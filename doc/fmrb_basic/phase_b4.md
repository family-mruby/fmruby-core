# Phase B4 指示書: 周辺・体験 (互換レベル L4)

前提: Phase B3 完了 (ターゲット作品が linux sim で動く)。B4 は互換の
すそ野 (POKE/PEEK、ON ERROR、ファイル) と「Family BASIC らしい体験」
(直接モードコンソール) を扱うフェーズ。**冒頭のユーザ判断で内容が
変わる**ため、T4-1 を最初に行うこと。

## タスク

### T4-1: 直接モードコンソールの要否判断 (ユーザ判断)

- 判断材料を整理してユーザに提示する:
  - fm-editor で .bas を編集 -> 実行、で足りているか (B3 までの運用実感)
  - 直接モード実装のコスト見積り (画面エディタ、LIST/AUTO/RENUM/DELETE/
    FIND、CONT の対話利用、エディタとインタプリタの状態共有)
- 「やる」となった場合のみ T4-6 を実施。「やらない」場合は行エディット
  系コマンド (B1 でトークンのみ定義済み) を「直接モード専用エラー」の
  文言に整えて終了。

### T4-2: 仮想 POKE / PEEK

- B0 T0-5 の棚卸しで判明した頻出アドレスを対象に、仮想メモリマップを
  実装する (compat_plan sec 5.6)。メモリマップの枠は core_spec sec 14 /
  v3_spec のマップに従い、エミュレート対象は代表領域 (画面 RAM、
  スプライト属性、乱数シード等、棚卸し結果で確定) のみ。
- 未対応アドレス: PEEK = 0、POKE = 無視。いずれも警告ログ (fmrb_log
  経由。BASIC 画面には出さない) を 1 アドレス 1 回に抑制して出す。
- 対応表 (アドレス範囲 -> 挙動) は report と doc 化する (ユーザが作品の
  非互換を判断する材料になる)。

### T4-3: ON ERROR / RESUME / ERROR

- ON ERROR GOTO / RESUME [行番号] / ERROR n (v3_spec の書式)。
  B1 で保持しているエラー種別・発生行を ERL / ERR 関数として公開し、
  捕捉 -> 復帰の制御フローを実行エンジンに足す。
- エラー処理中の再エラー、RESUME なしでの END 等の縁の挙動は spec に
  従い、不明点は疑義リストへ。

### T4-4: LOAD / SAVE / LOAD?

- littlefs (/home 以下) への読み書きに読み替える (compat_plan sec 5.7)。
  LOAD"名前" / SAVE"名前" のファイル名規則 (拡張子 .bas 補完、パスの
  扱い) を決めて report に記録。LOAD? はファイル内容比較。
- 実行中プログラムの置き換え (LOAD がプログラムを差し替えて停止する
  挙動) とアプリタスクのライフサイクルの整合に注意。

### T4-5: 残りの画面系 (BGGET / BGPUT / BACKUP / SCREEN / VIEW / FILTER)

- シャドウバッファ (B2) の退避・復元として実装する。書式・退避領域の
  個数は spec に従う。TRON / TROFF (トレース出力) もここで実装。

### T4-6: 直接モードコンソール (T4-1 で実施決定の場合のみ)

- BASIC コンソールアプリ: 起動するとタイトル + プロンプトの
  Family BASIC 画面になり、行入力 (行番号付き = プログラム編集、
  なし = 即時実行)、画面上のカーソル移動編集、LIST / AUTO / RENUM /
  DELETE / FIND、RUN / STOP / CONT、LOAD / SAVE を提供する。
- 実装は .bas アプリの一形態 (フルスクリーン) とし、インタプリタ状態を
  対話セッションとして保持する。
- キー入力 (カナモード含む) は B2 T2-3 の機構を使う。

## 受け入れ基準

1. 既存ゴールデン green 維持 + B4 機能のゴールデン追加
   (ON ERROR / POKE/PEEK / LOAD/SAVE をホスト or linux sim で)
2. 仮想メモリマップ対応表が文書化されている
3. ターゲット作品のうち POKE 依存作品の互換状況が更新されている
4. (実施時) 直接モードコンソールが headless 検証で操作できる
5. `reports/phase_b4_report.md` 完成
