# Phase B5 指示書: 実機調整・品質確定

前提: Phase B4 完了。B5 は実機 (Retro = ESP32-S3 / NARYAv3 を主対象、
Modern = ESP32-P4 / TAB5 でも動作確認) で速度・音・入力を仕上げ、
「ベーマガ作品の動作リスト」を公開できる品質に固めるフェーズ。
実機での操作・音・映像の官能確認はユーザが行う。実装担当はビルド・
計測・修正を受け持つ。

## タスク

### T5-1: 実機ビルドと基本動作 (S3 / NARYAv3)

- `rake build:esp32` (NARYAv3) でフラッシュし、L1-L4 の代表サンプルと
  ターゲット作品を実機で回す (フラッシュ・リセットはユーザ操作)。
- NTSC 出力 (WROVER 経由) での 224x192 画面の見え方 (にじみ・
  オーバースキャン) を確認し、必要なら枠色・配置を調整する。

### T5-2: 速度計測と調整

- 計測項目: インタプリタ実行速度 (ベンチ .bas: 空ループ、式評価、
  文字列操作の 3 種を test/samples/ に用意)、tick の実測周期と欠落率、
  スプライト同時表示数での フレーム維持。
- 「実機 Family BASIC 並み」を下回らないこと、および速すぎる場合の
  待ち合わせ (B3 T3-1 の方針) の実機挙動を確認する。
- ボトルネックが出たら計測 -> 修正のループを回し、計測値を before /
  after で report に残す (同一コミット同士で比較すること)。

### T5-3: サウンド実機確認

- PLAY / BEEP を S3 (WROVER APU) で確認 (音はユーザ官能確認)。
  テンポ精度 (T 指定と実測秒) は計測で確認する。
- P4 (TAB5) のローカル apu_emu 経路でも PLAY が鳴ることを確認する。

### T5-4: 入力実機確認

- USB ゲームパッドで STICK/STRIG (同時押し含む)、キーボード代替
  マップ、INKEY$ / カナ入力を実機で確認。
- パッドの抜き差し・未接続時の挙動 (エラーにしない) を確認。

### T5-5: P4 (TAB5) 動作確認

- `FMRB_HW_TARGET=TAB5` でビルドし、代表サンプル + 作品数本を確認。
  P4 は表示経路 (display_p4) と音声経路 (apu_emu ローカル) が S3 と
  異なるため、extension 層の分岐漏れを重点確認する。
- P4 固有の不具合は修正するが、性能調整の主対象はあくまで S3
  (P4 は性能余裕がある)。

### T5-6: 動作リストとドキュメント

- ターゲット作品の最終互換状況表 (動く / 制限付き (内容明記) /
  非対応 (理由: マシン語等)) を確定し、`doc/fmrb_basic/compat_list.md`
  として整備する (作品コード・出典の詳細は書かない。タイトルと
  互換状況のみ)。
- ユーザ向けの使い方文書 (.bas アプリの置き方、キーボード代替マップ、
  fmruby 独自拡張命令の一覧、Family BASIC との既知差分) を
  `doc/fmrb_basic/usage.md` に書く。
- spec の「資料待ち項目」「疑義リスト」の最終状態を整理し、実機挙動と
  照合できたものは spec を確定値に更新する。

## 受け入れ基準

1. S3 実機でターゲット作品が動作リストどおりに動く (ユーザ確認)
2. TAB5 で代表サンプルが動く
3. ベンチ計測値と tick 精度が report に記録されている
4. compat_list.md / usage.md が存在する
5. 全ゴールデンテスト green のままである
6. `reports/phase_b5_report.md` 完成

## 報告

`reports/phase_b5_report.md`。プロジェクト全体の残課題 (対象外とした
もの、既知差分) を総括し、以後のメンテナンス方針 (ゴールデンテストの
回し方) を明記して締める。
