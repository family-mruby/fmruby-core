# Family BASIC 言語仕様 (V2.1 / NS-HUBASIC V2.0A 基本命令)

- 表記: &Hxx は 16 進数。値域「a-b」は両端含む。[ ]=省略可、{ }=いずれか選択。
- 未確定だった項目は根拠のある暫定値を採用し「暫定確定」と明記した
  (採用根拠と残る資料待ち項目は末尾の一覧参照)。

## 1. 仕様水準

| 項目 | 内容 |
|---|---|
| 文字の種類 | 数字・英文字・カナ・記号 |
| 数の表現範囲 (整数) | 10進: -32768 - +32767 / 16進: &H0000 - &HFFFF / 文字列: 0-31文字 |
| 変数名 | 英字で始まる。先頭2文字を識別。長さ255文字まで |
| 行番号の範囲 | 0 - 65535 |
| テキスト行の最大桁 | 255桁 |
| 配列の大きさ | 2次元まで、要素数制限なし (メモリの範囲内) |
| マルチステートメント | 可能。「:」(コロン) で区切る |
| サブルーチン/ネスト | 制限なし (メモリの範囲内) |
| FOR NEXT ループ | 制限なし (メモリの範囲内) |
| 編集機能 | スクリーンエディタ |
| 画面モード | BG GRAPHIC面、スプライト面、バックグラウンド面、バックドロップ面 |
| グラフィック精度 | バックグラウンド面 28文字x24行 / スプライト面 256x240ドット / 1キャラクタ 8x8ドット |
| カラー | カラーゼネレータ 52色発生 |
| サウンド | 音階、テンポ、3重音、音色 |
| コントローラ入力 | 左・右コントローラ (方向入力、トリガー入力) |
| ファイル | カセットテープ (1200ボー) |
| 命令数 | 基本74 |
| アニメキャラクタ設定 | 既設16種類より選択 |

注記: -32768 - +32767 を超える数値を扱う演算結果は保証されない (オーバーフローの動作は未定義扱い)。

## 2. 数値・変数・文字列

| 項目 | 仕様 |
|---|---|
| 数値型 | 整数のみ。小数点を含む演算不可。除算は小数点以下切り捨て |
| 16進定数 | &H 前置 (&H2C = 44)。&H が付かなければ10進 |
| 数値変数 | 例 A, X。未定義参照時は 0 |
| 文字変数 | 名前 + $ (例 A$)。未定義参照時はヌルストリング。最大31文字 |
| 変数名 | 英字始まり、先頭2文字で識別、255文字まで記述可 |
| 型の混用 | 代入・SWAP とも両辺の型一致が必須 (数値と文字列の混用不可) |
| 真偽値 | 関係演算の結果: 真 = -1、偽 = 0 |

## 3. 演算子

| 種別 | 演算子 | 内容 |
|---|---|---|
| 算術 | + - * / MOD | / は整数除算 (切り捨て)。MOD は剰余。B<>0 が必要 |
| 関係 | = <> > < >= <= | =< / => / >< の書き方は不可 |
| 論理 | NOT AND OR XOR | 16bit ビット単位演算。変数と論理演算子を続けて書く場合は間にスペース必要 |

優先順位 (高い順): (1) 括弧 (2) 関数 (3) `* / MOD` (4) `+ -` (5) 関係演算子 (6) NOT (7) AND (8) OR (9) XOR

## 4. 特殊記号

| 記号 | 用途 |
|---|---|
| - | 行範囲指定 (LIST 10-100 等) |
| , | PRINT/INPUT/DATA 等のオペランド区切り (セパレータ) |
| : | マルチステートメント区切り、PLAY のチャンネルセパレータ |
| ; | PRINT 等の区切り (詰めて表示) |
| ? | PRINT の代用 |
| &H | 16進数プレフィクス |
| ' | REM の代用 (アポストロフィ) |

## 6. 一般ステートメント

| 文 | 書式 / 仕様 | 省略形 |
|---|---|---|
| 代入 | 変数 = 式。LET は存在しない (命令語なし)。両辺の型一致必須 | - |
| PRINT | PRINT 式[{;,}式...]。「;」は詰めて連結 (数値は前に符号分1桁、後にスペース1つ)。「,」は幅 8 桁のゾーン (開始桁 0/8/16/24 の 4 ブロック) の次ゾーン頭へタブ、最終ゾーンを超えたら次行 (仕様水準の「幅 8 文字 x 4 ブロック」の記述から暫定確定)。文末「;」で次の PRINT が継続。単独 PRINT は改行のみ。文字定数の閉じ「"」は後ろに区切り記号がなければ省略可 | ? / P. |
| INPUT | INPUT ["文字列"{;,}] 変数[,変数...]。「;」なら「?」表示、「,」なら「?」なし。複数変数はカンマ区切りで一度に入力。文字データに「,」を含めるには「"」で囲む。数値変数へ文字を入れると 0。空 RETURN で変数は 0/ヌルにクリア | I. |
| LINPUT | LINPUT ["文字列"{;,}] 文字変数。「,」もデータとして入力可。文字列のみ・変数1つのみ。31文字まで (表示メッセージ部を含めて31文字以内)。「?」は出ない | - |
| CLEAR (文形) | CLEAR。全変数・配列をクリア (数値=0、文字=ヌル) | CLE. |
| DIM | DIM 配列名(m1[,m2])[,配列名(n1[,n2])...]。2次元まで。数値・文字配列とも可。添字は 0 始まり。宣言時に 0/ヌルへ初期化 | D. |
| GOTO | GOTO 行番号。無条件ジャンプ。ダイレクト実行では変数を保持したまま実行開始できる | G. |
| GOSUB | GOSUB 行番号。ネスト可 (メモリ範囲内) | GOS. |
| RETURN | RETURN [行番号]。行番号指定でその行へ復帰、省略時は GOSUB の直後へ | RE. |
| IF-THEN | IF 式 THEN {行番号 | 文} / IF 式 GOTO 行番号 (THEN の後が GOTO の場合 THEN 省略可)。不成立時は次の行へ。IF のネスト可 | IF-T. |
| FOR-NEXT | FOR i=初期値 TO 終了値 [STEP s] ... NEXT。s は負数可、省略時 1。開始時点で条件を満たしていればループ本体は実行せず NEXT の次へ。NEXT の後ろにループ変数名を付けることは不可。対応 FOR がないと NF ERROR | F.-TO-ST. / N. |
| ON | ON 式 {GOTO|GOSUB|RETURN|RESTORE} 行番号[,行番号...]。式は 1 始まりの整数。式=1 で1番目、2 で2番目...。0 または個数超過なら次の文へ | - |
| STOP | 「BREAK IN 行番号」を表示して停止。変数保持、CONT で再開可 | STO. |
| END | 実行終了しコマンド待ちへ。最終行の END は省略可 | E. |
| SWAP | SWAP 変数1,変数2。同型必須 (SWAP A,B$ 不可。文字列同士は可) | SW. |
| REM | REM [コメント] (255文字まで)。「'」で代用可。GOSUB の飛び先行に置く場合は REM 不可、「'」を使用 | ' |
| READ | READ 変数[,変数...]。DATA 文と1対1対応、型一致必須。DATA 不足で OD ERROR | REA. |
| DATA | DATA 定数[,定数...]。数値定数 (-32768 - +32767) / 文字定数。1行255文字。文字列は「"」囲み省略可だが「,」「:」を含む場合は必須。プログラム中のどこでも可、行番号の若い順に先頭から読まれる | D. |
| RESTORE | RESTORE [行番号]。DATA ポインタを指定行 (省略時はプログラム先頭) へセット | RES. |
| CALL | CALL アドレス。マシン語サブルーチン呼び出し。アドレスは整数定数 (16進/10進)・変数・式。CLEAR で確保した領域以降に置く | CA. |
| POKE | POKE アドレス,データ[,データ...]。データは 0-255。複数指定で連続アドレスに書き込み。使用可能範囲 &H7040 - &H7FFF (&H7000 - &H703F はシステム使用のため禁止) | - |

## 7. 画面制御ステートメント

| 文 | 書式 / 仕様 | 省略形 |
|---|---|---|
| LOCATE | LOCATE X,Y。バックグラウンド面のカーソル位置。X=0-27 (水平カラム)、Y=0-23 (垂直行) | LOC. |
| COLOR | COLOR X,Y,n。X=0-27、Y=0-23、n=配色番号 0-3。指定位置を含む 2x2 キャラクタのエリア単位で配色番号を設定 (エリア開始座標は X,Y とも偶数)。CGSET でパレットを変えてもエリアの配色番号は有効のまま | COL. |
| CGEN | CGEN n (n=0-3)。キャラクタテーブル A (アニメキャラ) / B (文字・記号・カナ・背景パターン) を BG 面・スプライト面のどちらに割り当てるか選択。既定値 CGEN 2 (BG面=テーブルB、スプライト面=テーブルA)。CTRL+D で 2 に再設定。n=1: BG面=A、スプライト面=B。n=3: 両面=B。n=0: 両面=テーブル A (1=(BG:A,SP:B)、2=(BG:B,SP:A)、3=(両面B) の残余組合せとして確定) | CGE. |
| CLS | バックグラウンド面をクリア (コピーされた BG GRAPHIC も消える)。プログラム上で BG GRAPHIC を残したい場合は CLS の代わりに VIEW を使用 | - |
| CGSET | CGSET [m][,n]。m=バックグラウンド面用パレットコード 0-1、n=スプライト (アニメキャラクタ) 用パレットコード 0-2。既定値 m=1, n=1。BG 用 2 種 + スプライト用 3 種のカラーパレットがあり、各パレットは配色番号 0-3 の各グループに 3 色ずつ計 12 色の色コードを保持する。一度指定すると再指定または PALET で色コードを変えるまで有効。実行するとバックドロップ面の色は黒 (透明) になる。DEF SPRITE / DEF MOVE の配色番号は「CGSET で選んだスプライト用パレットの中の配色番号 0-3」を指す (BG 面の配色番号指定は COLOR 文)。VIEW で BG GRAPHIC 面をそのままの色でコピーするには BG 面パレットコード 1 (CGSET 1,1) を使う。CTR+D または BASIC 面へ入った時点では BG・スプライトとも BG 用パレットコード 1 の配色 | CG. |
| PALET B | PALET B n,C1,C2,C3,C4。BG 用。n=配色番号 0-3。C1=バックドロップ面の色 (n=0 のときのみ有効)。C2,C3,C4=配色番号内の左端・中央・右端の色。色コードは 52 色 (値 0-60) | PAL.B |
| PALET S | PALET S n,C1,C2,C3,C4。スプライト用。引数は PALET B と同じ。バックドロップ色は BG/スプライトのどちらで指定しても画面全体に反映 | PAL.S |

### 52 色の色コード表 (色コード値 0-60)

構造: 縦軸が色相 (灰/白、青系、赤系、緑系、クロ)、横軸が明度
(&H00 台=暗 -> &H30 台=明)。&H30 台にクロ系は存在しないため全 52 色。

| 色相 | 暗 (16進=10進) | | | 明 |
|---|---|---|---|---|
| 灰色~白色 | &H00=0 | &H10=16 | &H20=32 | &H30=48 |
| 青系 | &H01-&H04=1-4 | &H11-&H14=17-20 | &H21-&H24=33-36 | &H31-&H34=49-52 |
| 赤系 | &H05-&H08=5-8 | &H15-&H18=21-24 | &H25-&H28=37-40 | &H35-&H38=53-56 |
| 緑系 | &H09-&H0C=9-12 | &H19-&H1C=25-28 | &H29-&H2C=41-44 | &H39-&H3C=57-60 |
| クロ | &H0D-&H0F=13-15 | &H1D-&H1F=29-31 | &H2D-&H2F=45-47 | (なし) |

- PALET / PALET S / PALET B の C1-C4 にはこの値 (0-60) を使う。
- PALET はプログラム上では実行行番号の大きい指定が最終的に表示される。
  CGSET 文で決められたパレットに対して実行される。
- 初期状態のスプライト用パレットコード 0・配色番号 0 の 3 色は
  色コード 54, 22, 2。
- 例: `PALET S 0,1,48,25,18` = バックドロップ色を 1 にし、配色番号 0 の
  3 色 (54,22,2) をそれぞれ 48,25,18 に変更する。
- 例: `PALET S 3,&H0F,&H30,&H26,&H12` (色コードは 16 進でも指定可)。

## 8. スプライト制御

### DEF SPRITE

書式: `DEF SPRITE n,(A,B,C,D,E) = 文字式`

| 引数 | 意味 | 値域 |
|---|---|---|
| n | スプライト番号 | 0-7 (8個まで) |
| A | 配色番号 | 0-3 |
| B | キャラクタ合成型 | 0=8x8ドット (1文字)、1=16x16ドット (4文字) |
| C | 表示優先度 | 0=BG面より前のスプライト面、1=BG面より後ろのスプライト面 |
| D | X軸方向反転 | 0=そのまま、1=左右反転 |
| E | Y軸方向反転 | 0=そのまま、1=上下反転 |
| 文字式 | CHR$(N) の連結、文字列定数、文字変数のいずれも可 | N はキャラクタコード 0-255 (16進 &H 可) |

- B=1 (16x16) のときの4文字の並び: CHR$(n)+CHR$(n+1)+CHR$(n+2)+CHR$(n+3) = 左上・右上・左下・右下。
- MOVE コマンド系 (DEF MOVE) とは独立に使用できる。CGEN と組み合わせれば文字・記号もスプライトにできる (CGEN2 なら文字列 "DEF0" のような直接指定も可)。

### SPRITE / SPRITE ON / SPRITE OFF

| 文 | 仕様 | 省略形 |
|---|---|---|
| SPRITE n,x,y | 定義済みスプライトを表示。x=0-255、y=0-255 (有効範囲 X:0-240、Y:5-220。テレビにより表示範囲は異なる)。座標はキャラクタ左上端のスプライト面座標 | SP. |
| SPRITE n | 座標省略で該当スプライトのみ消去 | SP. |
| SPRITE ON | スプライト面の表示を有効化。DEF SPRITE / DEF MOVE の実行前に必要 | SP.O. |
| SPRITE OFF | スプライト面の表示を全て止める | SP.OF. |

- 同一座標に複数表示した場合、スプライト番号の小さいものが手前。
- 水平方向 (同一走査線上) には同時 4 個 (文字分) まで。超過分は見えなくなる。
- スプライト面座標 (x,y) と BG 文字座標の対応: 暫定確定: スプライト x = 8*X + 16、y = 8*Y + 24 (テキスト 28x24 は 32x30 タイル面の左右 2 タイル・上 3 タイル内側にあるという配置に基づく)。実ゲーム映像との比較で校正する。

## 9. MOVE コマンド (アニメキャラクタ)

### DEF MOVE

書式: `DEF MOVE(n) = SPRITE(A,B,C,D,E,F)`

| 引数 | 意味 | 値域 |
|---|---|---|
| n | 動作番号 | 0-7 (同時定義8個まで) |
| A | アニメキャラクタの種類 | 0-15 (16種類) |
| B | 動作の方向 | 0-8。0=停止。1-8 は時計回りの8方向: 1=上、2=右上、3=右、4=右下、5=下、6=左下、7=左、8=左上 |
| C | 動かす速さ | 1-255 (1=最高速、255=最低速。0 は 256 フレーム毎に動作)。2C フレーム (約 C/30 秒) 毎に 2 ドット移動 (ななめは X,Y 各 2 ドット)。速度 = 60/C ドット/秒 |
| D | 全移動量 | 1-255 (0 は表示されない)。全移動ドット数 = 2*D (ななめは X,Y 各 2D ドット) |
| E | 表示優先度 | 0=BG より前のスプライト面、1=BG より後ろのスプライト面 |
| F | 配色番号 | 0-3 |

- アニメキャラクタの種類 0-15 の割り当て: 0=マリオ、4=ペンペン は確定。
  残りは以下の暫定対応表を採用する (テーブル A の絵柄一覧と収録順、
  および確定 2 点との整合から構成。要資料確認):

  | 種類 | キャラクタ | 種類 | キャラクタ |
  |---|---|---|---|
  | 0 | マリオ (確定) | 8 | スターキラー |
  | 1 | レディ | 9 | スターシップ |
  | 2 | ファイターフライ | 10 | 爆発 |
  | 3 | アキレス | 11 | シェルクリーパー (カメ) |
  | 4 | ペンペン (確定) | 12 | サイドステッパー (カニ) |
  | 5 | ニタニタ | 13 | ニットピッカー (トリ) |
  | 6 | ファイアーボール | 14 | レーザー |
  | 7 | 車 | 15 | スピナー |


### MOVE / CUT / ERA / POSITION / 関数

| 文/関数 | 書式 / 仕様 | 省略形 |
|---|---|---|
| MOVE | MOVE n0[,n1,...,n7]。定義済み動作を開始。同時 8 個まで。BASIC の実行とは非同期に動き、プログラム終了後も定義された移動量が完了するまで動く。事前に SPRITE ON が必要 | M. |
| CUT | CUT n0[,n1,...,n7]。動作中のアニメキャラクタを停止 (表示は残る)。同時 8 個まで。再度 MOVE すると残りの移動量を止まった位置から続行 | CU. |
| ERA | ERA n0[,n1,...,n7]。停止させ、スプライト面から消去。同時 8 個まで。再度 MOVE すると残りの移動量を消えた位置から続行 | ER. |
| POSITION | POSITION n,X,Y。MOVE 開始前に初期座標を与える。X=0-255、Y=0-255 (有効範囲 X:0-240、Y:5-220)。値はキャラクタ左上端の座標。未指定時の既定値 X=120,Y=120。同じ動作番号を繰り返し MOVE すると前回完了位置が次の初期座標になる (RUN、POSITION 再指定、DEF MOVE 再定義まで保持) | POS. |
| XPOS(n) | 動作番号 n のキャラクタの現在水平座標を返す関数 | XP. |
| YPOS(n) | 動作番号 n のキャラクタの現在垂直座標を返す関数 | Y. (YP.?) |
| MOVE(n) | 関数。動作番号 n の動きが完了していれば 0、動作中なら -1 | M.(n) |

## 10. サウンド

### BEEP

「ピー」という音を出す。引数なし。省略形 B.

### PLAY

書式: `PLAY "ストリングデータ"` (省略形 PL.)。文字列変数も可。

3重音: 1本の文字列内をチャンネルセパレータ「:」(コロン) で区切る。
`PLAY "チャンネルA:チャンネルB:チャンネルC"` (例: `PLAY "O5C5:O4E5:O1G5"`)。
各チャンネルごとに音程・長さ・テンポ等のパラメータを指定する。チャンネル C (3番目) はエンベロープ・デューティの指定が効かない (ハードの三角波チャンネルに対応)。

| 要素 | 記法 | 値域 / 意味 |
|---|---|---|
| テンポ | Tn | 1-8。T1=速い、T8=遅い。既定 T4。各 T の絶対テンポ (BPM) は実装既定値を定め、実動作の録画・録音と聴感で校正する (暫定) |
| デューティ (音色) | Yn | Y0-Y3。Y0=12.5%、Y1=25.0%、Y2=50.0%、Y3=75.0%。M0/M1 指定を実行した後に有効 (M 指定後に Y を指定する) |
| エンベロープ | Mn | M0=エンベロープなし、M1=あり (余韻・切れた音・はねた音になる) |
| 音量 | Vn | M0 のとき V0-V15 で音量。M1 のとき V0-V15 はエンベロープの長さ (0=短い、15=長い。音量は V15 相当) |
| オクターブ | On | O0-O5。O0=低音、O5=高音。既定 O3 |
| 音程 | C D E F G A B と #前置 | C=ド 〜 B=シ。半音は # を音名の前に付ける (#C=ド#(レ♭)、#D、#F、#G、#A) |
| 休符 | Rn | R0-R9。n は長さ指定 (下表) |
| 長さ | 音程・休符の直後に 0-9 | 下表。省略時は直前に書かれた音と同じ長さ。既定 5 |

長さ 0-9 の対応 (32分音符から全音符まで、素の音符と付点が交互に並ぶ単調な系列として確定):

| n | 音価 |
|---|---|
| 0 | 32分音符 |
| 1 | 16分音符 |
| 2 | 付点16分音符 |
| 3 | 8分音符 |
| 4 | 付点8分音符 |
| 5 | 4分音符 (既定値) |
| 6 | 付点4分音符 |
| 7 | 2分音符 |
| 8 | 付点2分音符 |
| 9 | 全音符 |

- T, Y, M, V, O は一度指定すると再指定まで値を維持する (チャンネルごとに独立)。
- 既定値: T4、M0、V15、O3、音長・休符長 5。
- 例: `PLAY "T4Y2M1V15O3C5R5D5R5E5"`、`PLAY "C5:E5:G5"` (3音同時)。

## 14. メモリマップ

| 範囲 | 内容 |
|---|---|
| &H0000-&H07FF | 本体 RAM (使用) |
| &H7000-&H7FFF | ワーク RAM (BASIC カセット内、電池バックアップ) |
| &H7000-&H703F | システム使用 (POKE 禁止) |
| &H7040-&H7FFF | POKE 使用可能範囲。各ボードデータ / BASIC フリーエリア (内訳の境界は挙動に影響しないため互換実装では一様な RAM として扱う) |
| &H8000-&HFFFF | プログラム ROM |

CLEAR でユーザマシン語領域の最上位アドレスを指定し、CALL で呼び出す (例: CLEAR &H7600)。

互換実装では &H7040-&H7FFF を一様な RAM として扱えば十分 (内訳の境界は挙動に影響しない)。

## 17. 暫定確定値の採用状況と残る資料待ち項目

方針: 実機での確認が困難なため、未確定項目にはハードウェア仕様
(ファミコンの PPU/APU は完全に解析済み) とマニュアル内の整合性から
妥当性のある値を採用した。実装後は実ゲームの録画映像・録音との比較で
校正できる。
