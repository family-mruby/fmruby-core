## 2. T5-2: 速度計測

### 計測の仕組み

- ベンチは `components/basic/test/samples/bench_0*.bas` の 5 本。
  開始・終了マーカーを PRINT し、**ログのタイムスタンプ**から所要時間を取る。
  背景アプリ (画面なし) として起動するので PRINT がログに出る。
- ハーネスは `tool/basic/basic_bench.rb`。シミュレーションに対しては
  debugd 経由で起動し `docker logs` を読む。**実機では
  `--log <シリアルログ>` で同じ集計ができる**ので、ユーザが取った
  ログをそのまま渡せる。
- 素の実行速度を測るために **`_SPEED n`** を追加した (1 フレームあたりの
  実行文数、`0` で無制限)。`_` 始まりなので既存プログラムと衝突しない。
  これが B3 で入れたペーシング (60 文/フレーム) の校正ノブそのもの。

### 計測値

実機は ESP32-S3 (NARYAv3)、2026-07-29 に `b5d9ff5` のビルドで計測。
シミュレーションは x86 のネイティブビルドなので上限の目安であり、
実機の予測値ではない。

| ベンチ | 内容 | 実機 (S3) | シミュレーション |
|---|---|---|---|
| `bench_01_loop` | 空の FOR/NEXT 100,200 文 | 0.246 s / **407,317 文/s** | 0.008 s / 12,525,000 文/s |
| `bench_02_expr` | 式評価 80,000 文 | 0.878 s / **91,116 文/s** | 0.022 s / 3,636,364 文/s |
| `bench_03_string` | 文字列操作 40,000 文 | 0.724 s / **55,249 文/s** | 0.020 s / 2,000,000 文/s |
| `bench_04_tick` | `PAUSE 600` (= 10 秒のはず) | **10.070 s / 誤差 +0.7%** | 10.001 s / +0.0% |
| `bench_05_paced` | ペーシング有効の同じループ 2,040 文 | 0.517 s / **3,946 文/s** | 0.517 s / 3,946 文/s |

読み方:

- **ペーシングのノブは実機で完全に効いている**。設計値は 60 文 x 60 フレーム =
  3,600 文/s で、一番重い文字列処理でも素の速度が **15 倍** (空ループなら
  113 倍、式評価で 25 倍) ある。「素の速度が目標に届かず、ハードが
  ボトルネックになる」という T5-2 の懸念は起きていない。**速度を実機
  Family BASIC に合わせるのはノブの値だけの問題**であり、処理の高速化は要らない。
- **ペーシング実効値が実機とシミュレーションで完全に一致** (どちらも
  0.517 s / 3,946 文/s)。この値がクロック駆動でハード速度に依存しないことの
  裏付けで、設計どおり。設計値 3,600 との差はフレーム境界の刻み方による。
- **フレームクロックの誤差は +0.7%** (10 秒に対し +70 ms、実効 59.58 Hz 相当)。
  PAUSE・スプライト自動移動・PLAY の進行がすべてこのクロックに乗るので、
  ゲーム全体が一様に 0.7% 遅い。体感できる差ではない。
- 実機とシミュレーションの素の速度比は 31-40 倍。x86 との差としては妥当。

### メモリ (実機)

| 項目 | 値 |
|---|---|
| BASIC アプリのプール使用 | 27,784 / 508,708 バイト (5%) |
| BASIC アプリのタスクスタック | 16,384 バイト中 **13,768 バイト空き** (使用 2,616 バイト) |

スタックは明示スタック方式 (00_common のメモリ設計原則 1) が効いていて、
16KB のうち 2.6KB しか使っていない。プールも 5% で、大きなプログラムを
読み込む余裕が十分ある。

### 計測手順 (再現用)

ベンチはソースツリー (`components/basic/test/samples/`) にしか無いので、
そのままではデバイス上のエディタから開けない。**`rake basic:bench` で
`flash/home/bench/` へ入れてから焼く**。

1. `rake basic:bench` (ベンチ 5 本 + .toml を flash へ配置)
2. `rake build:esp32` して書き込み、リセット
3. シリアルログを取りながら、エディタで `/home/bench/bench_01_loop.bas` を
   開いて **F5**。5 本繰り返す
4. ログをファイルに保存して `ruby tool/basic/basic_bench.rb --log そのファイル`

`.toml` は **背景アプリ (画面なし)** として起動するよう書かれている。
画面を持つアプリの PRINT はログに出さない仕様なので (B5 のログ整理)、
マーカーをログで拾うにはこれが必要になる。

### 実機計測で見つかった別件 (BASIC 起因ではない)

B5 の範囲外だが、計測中のログに出ていたので記録する。

| 症状 | ログ | 見立て |
|---|---|---|
| 起動時のランチャースキャンが遅く、その間デスクトップのキューが溢れる | `msg_send TIMEOUT: dest=2, waiting=32` が多発、`hid_event slow: capture=102ms` | 35 アプリのスキャンに約 15 秒。各 `.toml` の読み込みが同期的。P4 で記録済みの「app スキャン 9.5 秒」と同種 |
| HID レイテンシ | `hid_lat: n=1000 sum_ms=13590 max_ms=103 ge1=987 ge5=156 ge10=136 gt25=135` | 平均 13.6 ms、最大 103 ms、25 ms 超が 1000 件中 135 件。上のキュー詰まりと同じ根 |
| エディタのタスクスタック残量が少ない | `FM-Editor 12288 564 IRAM` | 12,288 バイト中の最小空き 564 バイト。high-water なので増えはしないが余裕が薄い。ファイル選択ダイアログを通ると深くなる |

## 3. T5-3 / T5-4: 音と入力

### 計測で確認できたこと

- **テンポ精度**: B3 の時点で FMSQ を WAV に落として実測済み。
  `T4` の 4 分音符 = 0.500 秒ちょうど、`O3` の C = 261.35 Hz (C4 -1.8 cent)。
  変換は決定的なのでゴールデンでバイト列を固定してある。
- **フレームクロック**: 上記 `bench_04_tick` のとおり誤差 +0.0%。
  PLAY の進行もこのクロックに乗る。

### ユーザ官能確認をお願いしたいこと

| 項目 | 確認内容 |
|---|---|
| PLAY / BEEP (S3 / WROVER APU) | 3 声が鳴るか、テンポ・音程が実機 Family BASIC と比べて違和感がないか |
| PLAY (P4 / TAB5 ローカル apu_emu) | 同じプログラムが鳴るか |

### 残課題

すべて `known_differences.md` に区分つきで載っている。要約:

- **区分 3 (データ差し替え待ち)** が実質的な残作業。実配色、52 色表、
  MML の絶対テンポ/オクターブ、`$D000` の原点、文字コード表の未確定分。
  いずれもコードは完成しており、**表の値を書き換えるだけ**。
- **区分 4 (対象外)** は実装しない。マシン語 CALL、直接モードコンソール、
  LOAD/LOAD?、BACKUP、VIEW、BGTOOL、テープ入出力、命令単位のタイミング互換。
- ターゲット作品リストが未提供なので `compat_list.md` の本体が空。

### 以後のメンテナンス方針

1. **コアを触ったら `rake basic:test`**。ホスト g++ だけで走り、docker も
   実機も要らない。数秒で終わる。
2. **画面・スプライト・入力を触ったら `tool/basic/basic_screen_check.py`**。
   シミュレーションを立てて (`tools/dev_run_check.sh --keep`) 実際の描画経路を
   通す。ホストランナーでは通らない経路の回帰はここで捕まる。
3. **速度に関わる変更は `tool/basic/basic_bench.rb`** で before / after を取る。
   **同一コミット同士で比較する** (別日の記録と突き合わせない)。
4. 仕様の疑義が出たら spec を直す前に report に疑義として記録し、
   決着したら `known_differences.md` の区分へ移す。区分の無い疑義を
   残さないことが、この文書群の価値を保つ条件。
5. 絵柄を変えるときは `flash/usr/share/basic/*.bmp` を差し替える。
   生成器 (`tool/basic/gen_basic_*.rb`) は初期値を作るためのもので、
   手で描いたシートを上書きしないよう `rake basic:sheets` は既存ファイルを
   守る (`FORCE=1` が要る)。
