## 2. T4.5-1: FILTER の着色

- 実装場所はレンダラのパレット段: 色コード 0-60 -> `COLOR_RGB332` -> FILTER。
  `fmrb_basic_gfx.c` の **`FILTER_TINT` 表と `apply_filter()`** の 2 つだけが
  色に関わるので、実機映像が入ったらここを差し替える。
- 現在の色寄せは**対象色へ 1/4 の重みで混色**。spec が「フィルターをかけた
  ように淡く着色」と書いているので軽めにした。プレースホルダである。
- 対象は BG 面のみ。スプライトのパレットは `recompute_palette()` で
  FILTER を通さない (v3_spec が BG 面の効果としているため)。
- FILTER 変更時は `invalidate_glyphs` (グリフシートの色が変わる) と
  `invalidate_cells` (画面に出ている色も変わる) を両方行い、コアが
  `screen_refresh()` で塗り直す。
- 検証: golden `423` を FILTER 0-7 の全値 + 範囲外の IL に拡張。見た目は
  sim のスクリーンショットで FILTER 0/3/4 の差を確認した。

## 3. T4.5-2: 2bpp + パレット多色化

### 表現

内部表現を 2bpp に統一した。1 グリフ = 8 行 x 16bit で、行内は
**左端ピクセルが最上位のペア** (`index = (row >> (14 - 2*x)) & 3`)。
インデックス 0 は backdrop / 透明、1-3 が配色グループの 3 色。

読み出しは `basic_assets_glyph(table_a, code, out[8])` の 1 本にした。
呼ぶ側は元が何 bpp か気にしなくてよい:

| ソース | 格納 | 読み出し |
|---|---|---|
| フォント (表B) の埋め込み | 1bpp のまま rodata 2KB | 0 -> 0 / 1 -> 3 に昇格 |
| タイル (表A) の埋め込み | **2bpp** rodata 4KB | そのまま |
| BMP シート (1bpp) | 2bpp に展開 4KB | 0 -> 0 / 1 -> 3 |
| BMP シート (4/8bpp) | 同上 | パレットインデックスをそのまま (4 以上は 3 に丸め) |

フォントを 1bpp のまま残したのは、字形に多色が要らないため
(2bpp にすると rodata が 2KB 増える)。

### 3 経路

1. **グリフシート生成** (`ensure_glyph`): ランの判定を「同じインデックスが
   続く限り」に変更。シートは attr 別 4 枚のままでキャッシュ構造は不変。
2. **スプライト画像** (`draw_sprite_image`): ピクセルごとにインデックスを
   引き、**スプライトパレット**から色を取る。インデックス 0 は透明。
3. **アセット読み込み** (`basic_assets.c`): 上表のとおり。

### パレット

`PALET B` / `PALET S` の 3 色をすべて保持するようにした (従来は 3 番目だけ
使い、残り 2 つは捨てていた)。スプライト面は独自バンクなので
`sprite_palette` フックを新設し、`screen_send_palette()` が両方送る。
スプライト画像は色を焼き込んでいるので、パレット変更時は
`slot->repaint` を立てて描き直す。

### プレースホルダタイルの多色化

`tool/basic/gen_basic_tiles.rb` が **枠 = インデックス 1、本体 = 2、
四隅マーク = 3** で描くようにした。これで画面を見れば多色が効いているか
すぐ分かる。実アートに差し替えるときは BMP を置き換えるだけ。

検証: sim で 3 色同時表示を確認し、`PALET B 0,...` で 3 色が入れ替わることを
スクリーンショットで確認した。

## 4. T4.5-3: LIST / SAVE の原文忠実化

- **16 進の基数を保持**: トークン `number_hex` (0x06) を追加。ペイロードは
  `number` と同じ 2 バイトなので実行系は共用でき、判定は `is_number(tk)`
  ヘルパに集約した (呼び出し側 12 箇所を機械的に置換)。デクランチは
  `&H` + 大文字・前ゼロなしで書き戻す。
- **`LOAD?`**: `?` は PRINT の短縮形なので `LOAD PRINT` と展開されていた。
  デクランチで「LOAD の直後の PRINT トークン」を `?` として印字する特例を
  入れた。
- **省略形** (`P.` 等) は正式名で出力する。実機の LIST も同じなので変更しない。
- **roundtrip ゴールデン**: ランナーに `BASIC_ROUNDTRIP=1` を足した。
  プログラムを LIST し、その文字列を別のインタプリタに load し直して
  もう一度 LIST し、一致するかを出す。ハーネスは `*_roundtrip` という名前の
  ケースで自動的に有効にする。golden `450_list_roundtrip` が `&H` / `LOAD?` /
  省略形入りで **ROUNDTRIP|identical**。
