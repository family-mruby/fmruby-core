# 仮想メモリマップ (POKE / PEEK 対応表)

Family BASIC の POKE / PEEK は実機のアドレス空間を直接触る命令なので、
互換実装では「どのアドレスが何に化けるか」を決める必要がある。本書は
その対応表であり、作品の非互換を切り分ける材料になる。実装は
`components/basic/core/basic_exec.cpp` の `mem_cell()` / POKE 文と
`basic_expr.cpp` の PEEK。

アドレスは spec のメモリマップ (core_spec sec 14 / v3_spec) に従う。

## 対応表

| アドレス範囲 | 実機での意味 | 本実装の挙動 |
|---|---|---|
| `$0000-$07FF` | 本体 RAM | **ふつうの RAM** (2KB)。最初の POKE / PEEK で確保、初期値 0 |
| `$0800-$5FFF` | 未使用 / ROM | 未対応。PEEK=0、POKE 無視 (警告ログ) |
| `$6000-$6FFF` | ユーザー RAM 4KB (V3) | **ふつうの RAM**。`$6000-$7FFF` を 1 ブロック (8KB) として最初の POKE / PEEK で確保、初期値 0 |
| `$7000-$703F` | ワーク RAM のシステム領域 (POKE 禁止) | PEEK は読める (0)。**POKE は無視 + 警告** |
| `$7040-$7FFF` | ワーク RAM / BASIC フリーエリア | 上記 8KB ブロックの一部として RAM |
| `$8000-$CFFF` | プログラム ROM / BASIC インタプリタ | 未対応。PEEK=0、POKE 無視 (警告ログ) |
| `$D000-$D3BF` | BG 画面 (ネームテーブル 32 列) | **テキスト画面へマップ**。行 = (addr-$D000)/32、列 = 剰余。列 0-27 / 行 0-23 が 28x24 のセルに対応し、POKE は文字コードの書き込み (描画も走る)、PEEK はセルの文字コード |
| `$D3C0-$FFFF` | BG 属性 / GAME 領域 / システム | 未対応。PEEK=0、POKE 無視 (警告ログ) |

## 決めごと

- **ネームテーブルの原点**: `$D000` を行 0 列 0 とし、可視 28x24 を左上に
  取る。実機は 32x30 のうちどこを表示するかがテレビ依存なので、資料が
  出るまではこの単純対応とする (B4 report 疑義)。
- **32 列のうち列 28-31**: 画面外。POKE は無視 (警告)、PEEK は 0。
- **警告の抑制**: 同一 256 バイトページにつき 1 回だけ、`POKEW|unmapped $XXXX`
  / `PEEKW|unmapped $XXXX` を fmrb_log 経由で出す (BASIC 画面には出さない)。
  未対応アドレスへ書き続けるループでログが溢れないようにするため。
- **POKE のデータ範囲**: 0-255 以外は IL エラー。複数データは連続アドレスへ。
- **メモリコスト**: 触られたブロックだけ確保する (2KB + 8KB)。POKE / PEEK を
  使わない作品は 0 バイト。

## 未対応で困る場合

- スプライト属性 (OAM) を直接叩く作品: DEF SPRITE / POSITION 経由に
  読み替える必要がある (L5 相当、対象外)。
- 乱数シードの直接操作: RND の内部状態は本実装独自なので対応しない。
- BG 属性 (色) の直接操作: COLOR / PALET 経由に読み替える。
