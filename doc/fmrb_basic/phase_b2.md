# Phase B2 指示書: テキスト画面 (互換レベル L2)

前提: Phase B1 完了 (言語コアがホスト・ゴールデンテストで green、
fmruby 統合済み)。B2 は 28x24 のテキスト画面を実装し、画面系
ステートメント・関数と自作フォントを整備するフェーズ。
仕様の正は core_spec sec 7 (画面制御) / sec 12 (キャラクタコード) /
sec 13 (画面関連数値) / sec 16 (起動時デフォルト)。

## 設計方針

- テキスト画面はコア内部の **28x24 シャドウバッファ (文字コード +
  カラー属性)** が正であり、描画はその反映にすぎない (compat_plan
  sec 5.1)。SCR$ / スクロール / ダンプはシャドウバッファから答える。
- 画面レイアウト: 28x24 文字 x 8x8 px = 224x192 px を 320x240 の
  フレームバッファ中央に配置 (上下 24px / 左右 48px は枠色)。
- 描画反映はホストインタフェースに「セル更新通知 (x, y, 文字コード,
  カラー)」を追加し、fmruby 側 (extension/fmrb_basic_gfx.c 拡張) が
  変更セルのみ canvas へ再描画する。present のタイミングは tick 側で
  まとめる (毎ステートメントで present しない)。
- フォントは fmruby の既存フォントとは独立の BASIC 専用 8x8 とし、
  コード配置は core_spec sec 12 に従う (絵柄はオリジナル。カナ必須)。
  テーブル A (アニメキャラクタ絵柄) のタイルは B3 で使うが、コード枠と
  アセット形式はここで一緒に定義する。

## タスク

### T2-1: シャドウバッファと画面プリミティブ

- 28x24 シャドウバッファ (文字 + 色 0-3 の属性)、カーソル位置、
  画面スクロール (最下行改行時)、起動時デフォルト状態 (core_spec sec 16)。
- PRINT の出力先を B1 の 1 文字出力からシャドウバッファへ切り替える
  (ホスト出力コールバックはゴールデンテスト用に残し、ホスト実装で
  選択できるようにする)。
- CLS / LOCATE (0-27, 0-23、範囲外はエラー) / POS / CSRLIN / SCR$(x,y)。
- COLOR (位置指定の色属性。書式は core_spec sec 7)。

### T2-2: フォントと描画経路

- 8x8 フォントアセット: 形式はビットマップ配列の C ソース生成
  (`core/` 外。アセット置き場は `components/basic/assets/` を新設し、
  変換スクリプトがあれば `tools/` に置く)。英数・記号・カナを揃える。
  絵柄はプレースホルダ品質でよい (清書はユーザ判断。00_common 参照)。
- extension 側: セル更新通知を受けて fmrb_gfx canvas へ 8x8 タイルを
  描画する経路。B1 まで使っていた旧 basic_console の文字描画は
  この経路に置き換えて撤去する。
- PALET はここではテキスト 4 色 (色コードと RGB332 の対応表を
  core_spec sec 7 の 52 色表から作る) の範囲で実装し、スプライト系
  パレットは B3 で拡張する。

### T2-3: キー入力

- INKEY$ (1 文字キュー、押されていなければ空文字)、KEY / KEYLIST /
  CLICK (書式は core_spec sec 5-6。ファンクションキー割当の保持)。
- カナ入力モード: キーボードからのカナ入力トグルと配列 (かな配列は
  spec の文字コード表にあるカナが入力できれば方式は簡略でよい。
  report に方式を記録)。
- 入力はアプリタスクの HID イベントを fmrb_basic.c 側で受けて
  ホストインタフェースの入力キューに積む。

### T2-4: テキストダンプ debug 経路 (B0 設計の実装)

- B0 T0-3 で確定した方式でシャドウバッファのダンプ取得を実装する。
- ルートの headless ハーネスから「.bas を起動 -> 入力注入 -> ダンプ取得
  -> expected と diff」が 1 コマンドで回るスクリプトを用意する
  (family-mruby ルート tools/ か fmruby-core 内かは B0 の設計に従う)。
- 画面系ゴールデンテスト (linux sim 上) をこの経路で 10 ケース以上作る
  (PRINT ゾーン、スクロール、LOCATE/COLOR、SCR$、カナ表示)。

### T2-5: .bas アプリのフルスクリーン既定化

- ゲーム実行を想定し、.bas アプリの既定をフルスクリーン (BG 画面) に
  する (compat_plan sec 4.2)。ウィンドウ実行との切替は .app.toml の
  設定に従う。spawner / fmrb_app.c 側の変更は最小に。

## 受け入れ基準

1. `rake basic:test` (ホスト、B1 分) green を維持
2. linux sim 上の画面系ゴールデンテスト 10 ケース以上が green
3. カナを含む PRINT / INKEY$ / SCR$ が headless 検証で確認できる
4. basic.app.bas デモの挙動維持 (gfx 拡張と新描画経路の共存)
5. `reports/phase_b2_report.md` 完成

記載する。
