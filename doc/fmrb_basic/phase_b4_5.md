# Phase B4.5 指示書: 機能実装完了 (feature freeze)

前提: Phase B4 完了 (レビュー済み、実装は未コミット)。B5 (実機調整) の
前に、Family BASIC としての**機能実装をここで完了扱いにする**のが本
フェーズの目的。以後の B5 は「データ差し替え (実配色・テンポ)・実機計測・
品質確定」であり、新機能は足さない。

したがって B4.5 の成果物は 2 種類ある:

1. 残っていた機能そのもの (FILTER 着色、2bpp 多色化、LIST/SAVE 忠実化)
2. 「何が実装済みで、何が仕様との既知差異で、何が対象外か」を確定する
   文書 (これが無いと "完了" を宣言できない)

### T4.5-1: FILTER の着色実装 (B4 疑義 #30 のクローズ)

- 対象は BG 面のみ (テキスト + 絵柄タイル)。スプライトには効かせない。
- 実装はレンダラ側のパレット段で行う: 52 色コード -> RGB332 の変換後に
  FILTER 色 (1-7) による色寄せを掛ける。`FILTER 0` = 無着色。
- 色寄せの式/表はプレースホルダでよい (RGB332 空間で対象色相へ混色する
  程度)。実機映像が入手できたら表ごと差し替えられる形にし、表の位置を
  report に書く。
- FILTER 変更時は `invalidate_glyphs` + 全面 refresh (PALET と同じ経路)。
- 検証: golden は状態のみ (既存 423 拡張)、見た目は sim スクリーン
  ショットで FILTER 0 と 1-7 の差を確認。

### T4.5-2: 2bpp + パレット多色化

現状は 1bpp (点灯ピクセルに `attr_rgb[attr]` の 1 色)。これを
「2bit インデックス 0-3 を配色パレットで RGB332 に落とす」に拡張する。

- **内部表現を 2bpp に統一**する。既存の 1bpp ソース (埋め込みテーブル、
  1bpp BMP) は読み込み時に 0 -> 0 / 1 -> 3 へ昇格する (インデックス 3 =
  現行の前景色。`basic_console_set_palette` が受けて捨てている c1/c2 が
  インデックス 1/2 の色になる。0 は backdrop/透明)。
- 対象は 3 経路:
  1. グリフシート生成 (`ensure_glyph` のラン描画を 2bit 対応に。
     シートは attr 別 4 枚のままでキャッシュ構造は変えない)
  2. スプライト画像 (`draw_sprite_image`。色は `sprite_palette_` 系)
  3. アセット読み込み (`basic_assets`: BMP の 4bpp/8bpp はインデックス
     0-3 として読む。`rake basic:sheets` の書き出しも 2bpp 値を保つ)
- 埋め込みテーブル (rodata) は 2bpp 化すると 256 字 x 16B = 4KB/表。
  フォント (テキスト) は 1bpp のまま昇格読みで構わない (字形に多色は
  不要)。絵柄テーブル A のみ 2bpp を持つ。
- 検証: 配色 attr 0-3 で同じタイルの色が変わること、`PALET` で
  インデックス 1/2 の色が動くことを sim で確認。golden は SCR$ の
  配色読み等の既存挙動が変わらないこと。

### T4.5-3: LIST / SAVE の原文忠実化 (B4 疑義 #34 のクローズ)

- 16 進リテラルの基数を保持する: クランチに 16 進用の数値トークン
  (`token::number_hex` 相当) を 1 つ足し、デクランチで `&H` 表記に戻す。
  値の意味は 10 進と同一 (16bit 生パターン) なので実行系は共用できる。
- `LOAD?` のデクランチが `LOAD PRINT` になる件を直す (`LOAD` の直後の
  PRINT トークンは `?` として印字する特例)。
- 省略形 (`P.` 等) が正式名で出るのは実機の LIST と同じ挙動なので
  維持する (report にその旨を書く)。
- 検証: SAVE 出力を再クランチしてトークン列が一致する roundtrip
  ゴールデンを追加 (`&H` / `LOAD?` / 省略形入りのケース)。

### T4.5-4: 既知差異・対象外の確定文書

`doc/fmrb_basic/known_differences.md` を新設し、疑義リスト全件
(B0 sec 8.1 の 3 件 + #6-34) を棚卸しして全件の行き先を確定する。
区分は 4 つ:

1. **解決済み** (実装/裁可で決着。#29 LOAD、#30 FILTER、#31 JIS カナ、
   #34 LIST 忠実化はこのフェーズで移る)
2. **実装差として確定** (実機と違うがこの実装の仕様とするもの。
   例: #6 負数除算の丸め、#9 FOR 後の変数値、#11 文字列 31 字制限、
   #22 ひらがな畳み込み、#32 ERR=0、ローマ字カナ入力)
3. **データ差し替え待ち** (コードは完成、値だけ実機資料待ち。
   例: #16/#21 配色バンク実色、#33 $D000 原点、MML テンポ/オクターブ、
   52 色表の校正、文字コード表の未確定分)
4. **対象外** (CALL / マシン語、直接モードコンソール、LOAD/LOAD?、
   BACKUP、VIEW、GAME、実機タイミング互換 = L5)

各行に「根拠 (どの report のどの判断か)」と「影響する作品の種類」を
1 行で書く。**この文書の完成をもって機能実装完了と宣言する**。
以後、区分 3 の値更新と B5 の計測・調整だけが残る。
