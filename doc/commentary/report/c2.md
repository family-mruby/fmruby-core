## 2. コマンド

```
asterism-games commentate mahjong                                   # 既定: http://127.0.0.1:50021 の ずんだもん (ノーマル)
asterism-games commentate mahjong --voicevox http://127.0.0.1:50021 --speaker 四国めたん --style ノーマル
VOICEVOX_URL=http://127.0.0.1:50021 asterism-games commentate mahjong
asterism-games commentate voices --list                             # エンジンにあるキャラクターと声の調子 (番号つき)
asterism-games commentate voices --make                             # 決まり文句の WAV を今作る
```

- `--voicevox URL` (無ければ環境変数 `VOICEVOX_URL`、それも無ければ `http://127.0.0.1:50021`)、`--speaker`
  (既定 ずんだもん)、`--style` (既定 ノーマル)。`commentate --help` に声の節と `voices` の使い方を足した。
- 起動時に `GET /version` を聞く。答えが無ければ「`commentate: no VOICEVOX at <URL>: the browser's voice reads`」
  と出して C1 のブラウザの読み上げで続け、ページのバーに「VOICEVOX が見つからない: ブラウザの声で読む」と出す。
- 番号は `/speakers` から名前で引く (決め打ちしない)。キャラクターか声の調子が無ければ候補を並べて終わる
  (例「ずんだもん has no style "ふつう" (there are: ノーマル, あまあま, ツンツン, …)」、`voices --list` を案内)。
- `voices --list` の出力 (確認したエンジンで):


## 3. 声の作り

ファイル: `commentate/voicevox.rb` (エンジンの口)、`commentate/voice.rb` (決まり文句の WAV・その場の文・まとめ役)、
`commentate/mahjong_voice.yml` (決まり文句の一覧)。

### 3.1 エンジンの口 (`Voicevox`)

`version` (`GET /version`)、`speakers` (`GET /speakers`)、`style_id(名前, 調子)` (無ければ `NotFound` と候補)、
`synthesize(文, 番号)` (`POST /audio_query?text=&speaker=` → `POST /synthesis?speaker=`、WAV の中身を返す)。
`net/http` だけ。つなぐまで 2 秒、読むのは 60 秒で打ち切る。

### 3.2 決まり文句の WAV と置き場所 (`ClipBank`)

- 一覧 `mahjong_voice.yml`: 鍵 → `word` (その場の文がこの語で始まるときに抜く語) と、口調ごとの文の候補
  (`plain` と `zundamon`。候補が複数なら鳴らす時に乱数で選ぶ)。鍵は 32: `start` (実況を始めます)、`game_start`、
  `oorasu`、`round_east1`〜`round_west4` (12)、`riichi`、`chi`、`pon`、`kan`、`ron`、`tsumo`、`mangan`、`haneman`、
  `baiman`、`sanbaiman`、`yakuman`、`ryuukyoku`、`abort`、`lead_change`、`game_over`。ずんだもんでは 32 文
  (リーチと役満は 2 通り、ほかは 1 通り。plain のみの鍵は無い)。
- 置き場所: `$XDG_CACHE_HOME/asterism-games/voices/<speaker>-<style>/` (XDG_CACHE_HOME が無いか相対なら
  `~/.cache/…`、既定では `~/.cache/asterism-games/voices/ずんだもん-ノーマル/`)。名前の `/` などは `_` に置き換え、
  外へ出られないようにした。
- ファイル名は読みの文の SHA-256 の頭 16 桁 (`<digest>.wav`)。一覧を変えると、変わった文だけ作り直し、どの文も
  指さなくなったファイルは消す。同じ場所に `CREDITS.txt` (VOICEVOX:ずんだもん、この PC で作ったこと、再配布しないこと、
  消してよいこと) を置く。
- 作る時: `voices --make`、または実況の起動時に足りない分を別のスレッドで作る (その間も実況は始まる。まだ無い決まり文句は
  鳴らさずに飛ばし、その場の文から鳴らす)。書き込みは一時ファイル + rename。
- 確認したエンジンで 32 文を作るのに 18.8 秒 (1 文 0.6 秒ほど)、32 ファイルで 2.2 MB。2 回目は 0 作成・32 既存。
- 配るときに使う道は `/clip/<digest>.wav` だけで、一覧が指すファイルしか返さない。

### 3.3 その場の文の合成とキャッシュ (`LiveVoice`)

- ハブが行を作る時に、読みの文を登録して digest (32 桁) を得る。行には一時的な URL `/voice/<digest>.wav` が付く。
  登録と同時に合成の待ち行列に入れ、1 本のスレッドが順に合成する (prio の大きいものから。prio 2 未満で 30 秒放って
  おかれたものは後回しにし、頼まれた時に作る)。
- ページがその URL を頼むと、できるまで最長 30 秒待って返す。ページは行を待ち行列に入れた時点で取りに行くので、
  決まり文句が鳴っている間に合成が進む。
- 手牌を隠したときの文 (pspeech) が違う行は、その文も登録するが待ち行列には入れない (H を押したページが頼んだ時だけ
  合成する)。`--public` ではハブが最初から隠した文で作る。
- 同じ文 (同じキャラクター) は同じ digest で、キャッシュにある間は合成しない。上限は 200 文・64 MB で、最も長く
  使われていないものから WAV を捨てる (文は覚えているので、また頼まれれば作り直す)。覚える文は 2000 まで。
- ハブが登録していない digest は 404。ページから任意の文を合成させる道は無い。
- エンジンが失敗したら、その行は 404 になり、ページはその行だけブラウザの声で読む (日本語の声があれば)。

### 3.4 決まり文句とその場の文のつなぎ

- 出来事から決まり文句の鍵を出すのは `MahjongPhrases.clips(ev)` (純粋な関数)。局の始まりは局の名前 (対局の最初は
  `game_start`、オーラスは `oorasu`)、リーチ、チー・ポン・カン、和了はロン/ツモ (満貫以上はその段位も続ける)、流局、
  途中流局、逆転、終局。テンパイ (手牌に触れる)・打牌・残り枚数・新ドラは決まり文句なし。
- その場の文が決まり文句の語で始まるときは、その語を抜いて合成する (`Voice.after`。「ロン！」の後は
  「CPU1、タンヤオ。…」)。文の途中にある語は抜かない (「CPU1、リーチなのだ！ 待ちは…」は「リーチなのだ！」の後に
  そのまま言う)。

## 4. 待ち行列 (ページ)

- 1 本の待ち行列に、VOICEVOX でもブラウザの読み上げでも同じ形で入れる。1 行 = 決まり文句の WAV (0〜2 個) を順に →
  その場の文の WAV。VOICEVOX が無いか、その行の WAV が取れないときはブラウザの読み上げ。音は `Audio` でブラウザが
  鳴らす (PC 側で `paplay` / `afplay` は使わない)。
- 字幕は声の始まりと同時に出す。待ち行列に入らない行 (声が切・クリック前・声が無い・ページを開く前の行) はすぐ出す。
  飛ばした行も、飛ばした時点で字幕は出す。
- 追いつかない時の捨て方は C1 と同じ: prio 2 が来たら prio 0 を、prio 3 が来たら prio 1 以下を捨てる。待ちは 4 行まで、
  prio 2 未満は 20 秒で古いとみなす。捨てた行の WAV の取得は中止する。
- M で声を切る (鳴っている WAV と読み上げを止め、待ち行列を空にする。字幕は出続ける)。H は手牌を隠した文
  (`plive`) に切り替え、待ち行列を空にする。Space の一時停止は WAV も止める。
- クリックした時に `start` の決まり文句 (「実況を始めるのだ！」) を鳴らす (ブラウザの自動再生の決まりで、クリックの中で
  最初の音を出す)。
- 鳴らしたものは `window.commentate.played` に `{t, kind (clip / live / speech / drop / live-failed), id, prio, src}`
  で残し、コンソールにも出す (確認はこれを読んだ)。

## 5. 口調とクレジット

- 口調: `MahjongPhrases::TONES` に `plain` と `zundamon`。各口調が「どのキャラクターか」「言い回しの一覧」「AI に頼む
  ときの一文」(C3 用。ずんだもんは「語尾は〜なのだ・〜のだ、一人称はボク、明るく元気に、短く」) を持つ。ずんだもんの
  言い回し (`ZUNDAMON_PHRASES`) は全出来事について plain と同じ数だけ書き、同じ乱数で同じ番目を選ぶ。最初のあいさつ・
  流局のテンパイの一覧の語尾も口調に合わせた。ほかのキャラクターとブラウザの声は plain。
- 口調は字幕にも同じく出る (声と字幕を揃えた。`--json` の文も同じ)。例 (実際の卓): 「CPU2のロンなのだ！ 立直・平和・赤ドラ 1で
  30符 3翻 3900点なのだ。」「出たのだ、満貫！ CPU4のロン、断么九・ドラ 1・赤ドラ 2。4翻 8000点なのだ！」
  「オーラス続行なのだ、東4局。親はCPU4なのだ。」
- クレジット: VOICEVOX を使っている時だけ、ページの右下に「VOICEVOX:ずんだもん」を出す (`?obs=1` でも消さない)。
  バーの声の欄は「声: 入 (VOICEVOX ずんだもん (ノーマル))」。起動時の表示と `voices --make` の最後にも出す。
- README (英語): 「Commentary」に「The voice」の節を足した。エンジンの見つけ方、決まり文句と置き場所 (消してよい)、
  その場の文、エンジンに渡す読み、キャラクターの選び方と口調、ページで鳴らすこと・M・クレジット、VOICEVOX の
  入れ方 (Windows と WSL: mirrored なら 127.0.0.1、そうでなければ Windows 側の住所。macOS。docker の CPU 版)、
  規約の要点 (無料・クレジット必須・キャラクターごとの規約、配信の説明欄にもクレジット、生成した音声を渡す相手にも
  同じ条件 → MIT の中に混ぜられないので gem に音を入れない)。CHANGELOG の 0.19.0 にも書いた。

## 6. エンジンに渡す読み (親の追加指示への対応)

- エンジンに渡すのは常に読みの文 (C1 の speech: サンマン、リーチ、30フ 2ハン)。字幕の文は渡さない。決まり文句も読みに
  直してから合成し、digest も読みの文で取る。
- 確認したエンジン (0.25.0) で、言い回しと決まり文句に出る漢字の語を `audio_query` の kana で 1 つずつ確認し、誤読するもの
  を `MahjongPhrases::SPEECH_READ` で書き換えるようにした: 流局 (ナガレキョク) → リューキョク、途中流局 → 途中リューキョク、
  起家 (オコリカ) → チーチャ、跳満 (トベミツル) → ハネマン、三倍満 (サンバイミツル) → サンバイマン、東1局 → トン1局
  (対局開始の言い回しに字のまま入っていた)。役や牌に残りうる語 (立直・一発・裏ドラ・赤ドラ・符・翻・暗槓 …) も同じ表で
  読みにする。もし牌の名前 (3萬・赤5筒) が漏れても、`reading` が読み (サンマン・アカウーピン) に直す。
- 本場・供託・巡目・親番・終局・逆転は字のままで正しく読んだ (キョオタク、ホンバ、ジュンメ、オヤバン …) ので、字のままに
  した (カタカナにすると抑揚が悪くなった: 1ホンバ → イチホン/バ)。ユーザ辞書 (`/user_dict_word`) は使っていない。
- 試験: 記録した東風戦を ずんだもん と 四国めたん でハブに通し、全部の行のその場の文と決まり文句を偽のエンジンに合成
  させ、エンジンが受けた文のどれにも 萬・筒・索・流局・起家・跳満・三倍満・東n局・立直・一発・裏ドラ・符・翻 が無いことを
  見る (字幕には牌の名前があることも見る)。全部の役 (YAKU_READ の 41 と 役牌・自風・場風・ドラ) を入れた和了の文でも同じ。

## 7. 試験 (`test/test_commentate_voice.rb`、19 件)

試験の中で VOICEVOX を真似た小さなサーバ (`/version`、`/speakers`、`/audio_query`、`/synthesis`。合成した文を数える) を立てる。

- 名前から番号 (ずんだもん ノーマル 3・あまあま 1、四国めたん 2)、無い名前・調子で候補の一覧。合成。
- エンジンが無い: `version` が失敗、`Voice.connect` が nil、起動の表示、ハブの status が `{"engine":"browser","note":"missing"}`、
  行に voice が付かない、何も作らない。無いキャラクターで `voices --make` が候補を出して終わる。
- 決まり文句: 1 回だけ作る、名前は digest、口調の文が無い鍵は plain の文、2 回目は何も作らない、一覧の外のファイルは返さない。
  一覧が変わると変わった文だけ作り直し、古いファイルを消す。置き場所 (XDG_CACHE_HOME、相対は無視、`..` や `/` を含む名前)。
  gem の一覧に、行が使う鍵と全部の局の名前が両方の口調で揃い、ずんだもんの文がすべて「のだ」を含む。
- その場の文: 同じ文は同じ digest で 1 回だけ合成、上限 2 で最も古いものを捨て頼まれれば作り直す、待ち行列に入れない文は
  頼まれた時だけ合成、登録していない digest は合成しない。エンジンが落ちていれば nil。
- 決まり文句の語を抜く (先頭だけ、「なのだ」と句読点も)。
- 口調: ずんだもんの言い回しが全出来事で同じ数・すべて「のだ」入り、記録した東風戦の全部の行 (隠した文も) が「のだ」入り、
  plain には無い、リーチと満貫の和了の文、満貫の和了の決まり文句が `ron` + `mangan`。テンパイに決まり文句が無い。
- ハブ: 全行に voice、URL の形、テンパイの隠した文は無し、ロンで始まる行のその場の文がロンで始まらない。サーバ: `/clip/` と
  `/voice/` が audio/wav で返る、登録外・一覧外・`..` は 404、声の無いハブでは 404。起動時に足りない決まり文句を全部作る。
- エンジンに渡す読み (6 章)。オプション (`--voicevox`・`--speaker`・`--style`・`VOICEVOX_URL`)、`voices --list | --make`、
  引数なしは 2、エンジン無しは 1、`--help`。
- 既存の試験: `test_gem.rb` に一覧のファイルが gem に入ること・音が入らないことを足した。Rakefile の gem の試験に新しい
  ファイルを足した。C1 の `test_commentate.rb` は変えずに通った。

## 8. 確認の結果

構成 (どれも作業用の名前と番号で起こし、終わったら止めて消した。docker の prune はしていない):

- VOICEVOX: `docker run -d --name c2-voicevox -p 127.0.0.1:27521:50021 voicevox/voicevox_engine:cpu-0.25.0`
  (版を固定。イメージは残した。ユーザの Windows 側のエンジン 127.0.0.1:50021 には触れていない)。メモリは 816 MiB。
- zenohd: `docker run -d --name c2-commentate-zenohd -p 127.0.0.1:27571:7447 eclipse/zenoh:1.10.1`
- ゲームホスト: 作業コピーの `bin/asterism-games --config <scratch>/games.yml` (mahjong1、humans 0、cpu_ms 700、
  result_seconds 6、`rule: {game_type: tonpuu}`、`ANTHROPIC_API_KEY` は空で外の API は呼ばない)。
- 実況: `commentate mahjong --router tcp/127.0.0.1:27571 --port 27580 --no-open --json --voicevox http://127.0.0.1:27521`
  (`XDG_CACHE_HOME` は作業用の場所。空の場所から起動し、起動時に 32 文を作らせた)。
- ブラウザ: `mcr.microsoft.com/playwright:v1.56.0-noble` のコンテナ `c2-commentate-browser` (--rm) の headless Chromium
  (`--autoplay-policy=no-user-gesture-required`、それでも一度クリックする)。サーバは PC の 127.0.0.1 だけなので、C1 と同じく
  コンテナ内の中継から 127.0.0.1 で開いた。`HTMLMediaElement.play` に印を付け、各音の playing/ended と長さも記録した。
- `~/asterism_keys/` は使っていない。VPS にはつないでいない。後片付けはプロセスを pid で止め、コンテナを名前で stop / rm した。

### 8.1 1 文の合成の時間

エンジンが空いている時に、ずんだもんの実際の文 (出来事ごとに最も長いもの) を 3 回ずつ合成した
(WSL2 の docker、CPU 版、24 スレッドの PC):

| 出来事 | 読みの文の字数 | 合成 (3 回) | 音の長さ |
|---|---|---|---|
| wall | 9 | 0.43 / 0.41 / 0.40 秒 | 1.7 秒 |
| call | 18 | 0.69 / 0.70 / 0.69 秒 | 3.7 秒 |
| hello | 23 | 0.94 / 0.91 / 0.91 秒 | 5.3 秒 |
| tenpai | 32 | 0.92 / 0.95 / 0.96 秒 | 5.5 秒 |
| riichi | 34 | 1.08 / 1.06 / 1.14 秒 | 6.4 秒 |
| round_start (オーラス) | 36 | 1.13 / 1.17 / 1.18 秒 | 6.7 秒 |
| win (満貫) | 55 | 1.86 / 1.91 / 1.92 秒 | 11.7 秒 |
| game_over | 67 | 2.80 / 2.81 / 3.05 秒 | 18.8 秒 |

- ふつうの 1 文 (20〜35 字) は 0.7〜1.1 秒、和了で 2 秒前後、終局の順位で 3 秒。音の長さの 1/6 ほど。
- 決まり文句は 1.0〜1.8 秒鳴るので、その場の文の合成はその間に終わる (8.2 で、決まり文句の終わりから次の音まで隙間なし)。
  決まり文句の無い行 (テンパイ・打牌) は、行が来てから合成の分 (1 秒前後) 遅れて鳴る。

## 9. 決めたこと (指示書の範囲内の判断)

止まる条件 (1・2 章に無い仕様の選択) には当たらないと判断したが、聞こえ方に関わるので書いておく:

1. 決まり文句の後のその場の文は、行の全文から先頭の同じ語だけを抜いたもの。文の途中の語は抜かないので、「リーチなのだ！」→
   「CPU1、リーチなのだ！ 待ちは…」のように重なることがある。満貫以上の和了は「ロン」「満貫」の 2 つを鳴らしてから全文
   (満貫がもう一度出る)。
2. 口調は字幕にも出す (声と字幕を揃える)。ブラウザの声のときは plain。
3. 指定したキャラクター・調子が無いときは、候補を出して終わる (ブラウザの声には落とさない)。エンジンが無いときだけ落とす。
4. 字幕は声の始まりと同時 (指示書どおり)。そのため声が追いつかない間は字幕も遅れる (最大で待ち 4 行分)。

## 10. 確認してほしいこと

1. 実際の PC (WSL なら Windows の VOICEVOX アプリを起動、mirrored なら既定のまま) で `asterism-games commentate mahjong`
   を起動し、最初の起動で決まり文句が作られ (`~/.cache/asterism-games/voices/ずんだもん-ノーマル/`、30 秒ほど)、
   クリックで「実況を始めるのだ！」が鳴ること。
2. ずんだもんの声の聞こえ方: 決まり文句 (リーチなのだ！ ポンなのだ！ ロンなのだ！ トン1局なのだ。満貫なのだ！) と
   その場の文のつながり (間が空かないか、重なりが気にならないか。9 章の 1)、語尾「〜なのだ」の多さ (毎文 1〜2 回)。
3. 読み: 牌 (サンマン・アカウーピン・パーソー)、役 (タンヤオ・ジカゼ トン・アカドラ2)、点 (30フ 2ハン 3900点)、
   リューキョク・チーチャ・ハネマン・キョウタク・ホンバ・ジュンメが自然か。「CPU1」は「シーピーユーいち」と読まれる。
   「2位」が「にい」に聞こえる場合がある (kana がニイ)。
4. 決まり文句の無い行 (テンパイ・ドラの打牌) が 1 秒ほど遅れて鳴る感じ。字幕が声と一緒に出ること。
5. M で声が止まり、字幕は続くこと。H で手牌を隠すと、テンパイが言われず、リーチが待ちなしで言われること。
6. 右下の「VOICEVOX:ずんだもん」の大きさと位置 (配信の画面で読めるか)。OBS の Browser Source で WAV の音が配信に乗るか
   (Web Speech と違い Audio なので乗るはず。未確認)。
7. `--speaker 四国めたん` など別のキャラクターで、plain の口調・決まり文句の作り直し (別の置き場所) になること。
8. Windows の VOICEVOX アプリ (版が違う) で、6 章の誤読が無いこと (確認は docker のエンジン 0.25.0 だけで行った。親の

## 11. 気づき

- 合成は音の長さの 1/6 ほどで、CPU 版でも決まり文句 1 つの間に終わる。声づくりを網に置く C6 の目安になる。
- エンジンのメモリは起動後 816 MiB (実測)。参照資料の「1〜2GB」は多めの見積もりだった。
- VOICEVOX の誤読は文脈で変わる (流局は単独でも文の中でもナガレキョク、本場は文の中ならホンバ)。新しい言い回しを足す時は
  `audio_query` の kana で確認するのがよい (確認に使った小さなスクリプトは作業場所に置いただけで、リポジトリには入れていない)。
- Docker Desktop のコンテナから PC の 127.0.0.1 の Web サーバには直接届かず、C1 と同じくコンテナ内の中継が要った
  (`--network host` でも届かない)。ヘッドレスの Chromium でも `Audio` は実際の長さで再生され ended まで進む。
