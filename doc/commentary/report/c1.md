## 2. コマンドと画面

```
asterism-games commentate mahjong --router tcp/127.0.0.1:7447
asterism-games commentate mahjong --credentials viewer.tar                      # viewer か spectator の役割
asterism-games commentate mahjong --credentials viewer.tar --namespace room/01  # 部屋の卓 (room01-<卓>)
asterism-games commentate mahjong --public                                      # 配信用: 手牌をページに渡さない
asterism-games commentate mahjong --json | tee commentary.jsonl                 # 字幕を他の道具へ
```

- 入口は `bin/asterism-games commentate <game>` (play と並ぶ)。`--help` あり。ゲームは mahjong だけ。
- つなぎ方は play と同じ: `--router` / `--credentials`、どちらも無ければ `ASTERISM_ROUTER` / `ASTERISM_CREDENTIALS`
  (全部か無しか)、何も無ければ `tcp/127.0.0.1:7447`。`--node` (既定 `commentate-<host>-<pid>`)。
- 読むのは `asterism/*/spectate/*/state` の購読だけ。卓に join も call もしない。
- `--namespace room/01` は、観戦用のキーが部屋の外にある (0.18.0 の作り) ので、接続には namespace を付けず、
  卓の名前の頭 `room01-` で絞る形にした (つなぎ方を「play と同じ」に保ったまま、届く場所に合わせた解釈)。
- `--table` は `mahjong1` / `games/mahjong1` / `games/spectate/mahjong1` / play の `games/games/mahjong1` のどれでも。
  無ければ届いた卓を全部一覧にし、最初の卓を出す (複数あればバーで選ぶ)。
- `--port` (既定 7470、使用中なら次。20 番まで)、`--no-open`、`--public`、`--json`。
- 起動時にブラウザを開く: macOS `open`、WSL は `wslview`、無ければ `cmd.exe /c start` (C: で起動して UNC の警告を避ける)、
  ほかは `xdg-open`。開けなければ URL を出すだけ。

画面 (写しは 5 章):

- 上のバー: 卓の名前 (ホスト)、声の状態 (入/切/クリック待ち/日本語の声が無い)、遅れ (`delay_s`、0 なら「遅れなし」)、
  手牌の隠し方 (`--public` は「手牌非公開」、H は「手牌を隠す (H)」)、一時停止、ホスト不在・接続切れ。
- 自動再生の案内: 「画面をクリックすると実況の声が出ます」。クリックで消え、最初に「実況を始めます」を読む。
- canvas: 上の帯に局 (東1局)・本場・供託・残り (10 枚以下は赤)・ドラ表示牌、2 行目に結果 (ロン/ツモ・役・点、流局と
  テンパイ、終局の順位) か手番。4 席を同じ大きさで、広い窓は 2 列、狭い窓は 1 列。席ごとに風 (親は赤と「親」)、名前、
  CPU/AI、点数、リーチの札、左に河 (6 枚ずつ、リーチの牌は横、鳴かれた牌は薄く、直前の打牌は赤枠)、右に手牌
  (手牌のシートを 0.8 倍) とツモ牌、その下に鳴き (河のシート、暗槓は両端を裏)。手番の席は黄色の枠。
- 字幕: 時刻つき、新しいものが下 (下にいる時だけ自動で追う)。大きさは prio で 3 段 (2 は太字、3 は黄色で大きく)。
  ページを開く前の行は薄く出し、読まない。
- キー: Space 一時停止 (届いたものを溜め、戻すと最新の卓と溜めた字幕を出す。読むのは溜めた中の最後の大きい 1 つだけ)、
  M 声の切/入、H 手牌を隠す (裏で描き、手牌に触れる字幕を出さず読まない)。
- URL の引数 (OBS 用): `?obs=1` (バーと案内を消し背景を透明に)、`?hands=0`、`?voice=0`、`?table=<host>/<卓>`。

`mahjong_phrases.rb` の `MahjongPhrases.line(event, view, rng)`。どちらも入出力・時計・乱数を持たない純粋な関数
(乱数は引数で渡す)。memo はこの局で言ったテンパイの席・トップの席・局の識別だけ。ホストは変化のたびに様子を出すが、
間の手がまとまって届くこともあるので、河は 1 枚ずつ、鳴きは数と種類で比べる。

## 4. Web サーバの作り

- `lib/asterism_games/commentate/server.rb`。標準ライブラリの `socket` (`TCPServer.new("127.0.0.1", port)`) で
  HTTP/1.1 を最小限に書いた。gem は足していない (webrick なし)。接続ごとにスレッド、要求の頭は 8 KB・10 秒まで。
- 決まった道だけ返す: `/` (`/index.html`)、`/commentate.js`、`/commentate.css`、`/tiles_hand.bmp`、`/tiles_river.bmp`、
  `/TILES_LICENSE.txt`、`/events`。ファイル名で探さないので `..` は 404。GET と HEAD 以外は 405。Host が
  `127.0.0.1` / `localhost` 以外なら 403 (外の名前がこの機械を指しても入れない)。
- `/events` は Server-Sent Events: `status` (卓の一覧・不在・`public`)、`state` (卓の様子。`--public` では
  hand/drawn を抜く)、`line` (字幕)。開いた時に status・その卓の最新の様子・これまでの字幕 (old) を送る。
  15 秒ごとにコメント行で生存を見る。読まないページ (寝たタブ) は 2000 フレームで閉じ、ブラウザが開き直す。
- 卓と字幕は `MahjongHub` (同じく mahjong.rb) が持つ。網を待たないので試験から直接入れられる。ホストの
  `on_leave` / 15 秒の無音で「不在」、次の put で戻る。局・対局の切り替わりでも止まらない。
- 確認: `ss -ltnp` で `127.0.0.1:27480` / `127.0.0.1:27481` だけを listen していた。コンテナから
  `host.docker.internal` で入ると Host が違うので 403 になった (それでコンテナ内に中継を置いて 127.0.0.1 で開いた)。

ページ (`assets/`): `index.html` / `commentate.js` / `commentate.css`。外の CDN も外のフォントも使わない (gem の
試験が `http://` `https://` の無いことを見る)。牌はブラウザが BMP をそのまま読み、描く時に別の canvas で透明色
(RGB332 0xE3 = マゼンタ) の画素だけ透明にする。ファイルは変えない。牌 n は `x = (n % 10) * 幅`、`y = (n / 10) * 高さ`
(麻雀アプリの `mahjong.app.rb` 冒頭の説明と `load_sheet` に合わせた。手牌 42x56、河 24x32、37 が裏)。パレットが
RGB332 の色と一致していることも確認した (256 色すべて)。

## 5. 確認の結果 (写し)

手元の確認の構成 (どれも作業用の名前と番号で起こし、終わったら止めて消した。docker の prune はしていない):

- zenohd: `docker run -d --name c1-commentate-zenohd -p 127.0.0.1:27471:7447 eclipse/zenoh:1.10.1`
- ゲームホスト: 作業コピーの `bin/asterism-games --config <scratch>/games.yml` (mahjong1、humans 0、cpu_ms 700、
  遅れ 0、`ANTHROPIC_API_KEY` は空で外の API は呼ばない)。
- 実況: `commentate mahjong --router tcp/127.0.0.1:27471 --port 27480 --no-open --json` と、`--public` の 27481。
- ブラウザ: `mcr.microsoft.com/playwright:v1.56.0-noble` のコンテナ `c1-commentate-browser` (--rm) で headless Chromium。
- `~/asterism_keys/` は使っていない。VPS にはつないでいない。後片付けはプロセスを pid で止め、zenohd のコンテナを名前で
  stop / rm した。

写し (`doc/commentary/report/c1/`):

コンソールのエラーは 0。ヘッドレスの Chromium には声が無いので、バーは「日本語の声がありません」になった。
読み上げの流れは、`speechSynthesis` を差し替えた (日本語の声 1 つ、1 行 2.5 秒) ページで確認した: クリック前は
1 つも読まない (バー「クリック待ち」、案内が出る)、クリックで「実況を始めます」、以後 90 秒で 20 行を順に読んだ。
一回目は逆転 (prio 3) が待ち行列の先頭に割り込み、原因の和了より先に読まれたので、割り込みをやめて「prio 2 が来たら
prio 0 を、prio 3 が来たら prio 1 以下を待ち行列から捨てて後ろに並ぶ」形に直した。二回目は和了の後に逆転を読んだ。

止まらないことの確認: ホストを止めると (pid で kill) バーが不在になり (`status` の `gone: true`)、起こし直すと
`gone: false` に戻って字幕が続いた。終局のあと新しい状態のディレクトリでホストを起こし直すと、
「さあ始まりました。東1局、…」から続いた。実況のプロセスは一度も止まらなかった。

試験 (`test/test_commentate.rb`、22 件): 待ちの計算 (両面・三面張・七対子・国士 13 面・鳴きのある手・赤五)、
ドラ表示牌からドラ、手で作った様子からの各出来事と文 (局の開始、オーラスと続行、リーチと待ち、ポンと加槓、ドラと赤の
打牌、残り 10 枚、新ドラ、テンパイは 1 局 1 回、跳満のロンと逆転 (段位を 1 回だけ言う、放銃者)、流局、九種九牌、終局)、
読み (牌・役・点・局)、乱数で言い回しが変わる/同じ乱数なら同じ、記録した東風戦 (`test/fixtures/commentate_tonpuu.json.gz`、
CPU 4 人、383 の様子) を通して出来事が揃い全部の値が埋まること、手牌を隠すとテンパイと待ちと牌の名前が出ないこと、
ハブ (ページへのフレーム、`--public` で手牌が出ない、`--json`、後から開いたページ、ホストの不在と復帰、卓ごとの振り分け)、
サーバ (127.0.0.1 だけ、ページと牌のバイト一致、404/405/403、HEAD、イベントの流れ、使用中の番号は次へ)、オプション、
`--help`。卓のある `rake test` では、ここで CPU の 1 局を回してハブに通す。既存の試験も 2 つ直した
(`test_gem.rb`: gem に入るファイルとシートの SHA-256・注記・CDN 無し、`test_framework.rb`: commentate を play と同じ
「端末の道具」として枠の外に数える)。

## 6. 牌のシートの扱い

## 7. 確認してほしいこと

## 8. 気づき

- 観戦用の様子は変化のたびに出るので、CPU の速い卓 (cpu_ms 0) では 1 回の tick で 1 局が進み、間の出来事が飛ぶ。
  ふつうの卓 (cpu_ms 700) では手ごとに届いた。判定は河と鳴きを数で比べるので、まとまって届いても打牌と鳴きは拾える。
  結果の状態が丸ごと飛ぶと和了は言えない (C5 でホストが出来事を作れば消える)。
- 結果の時点の点数は、様子の点数が前と同じなら「前の点数 + changes」で数えた (ホストの点数が先に動いていても
  後でも同じになる)。
- 待ちの計算は gem の中で手牌から行った (riichi_engine に頼れない)。符・翻の見込みは出していない。
