## 3. 場面と間隔

ファイル: `lib/asterism_games/commentate/ai_comment.rb` (`AIComment`)。ハブ (`MahjongHub#update`) が様子ごとに、その様子が作った
決まりの行を渡す (`observe`)。実況の 2 秒ごとの見回りで `tick` (静かな時間)。

| 場面 | 元の行 | 格 (rank) |
|---|---|---|
| 終局 | game_over | 5 |
| 大きな和了 (満貫以上) / 逆転 | win (prio 3) / lead_change | 4 |
| 和了 / オーラス (続行も) | win (prio 2) / round_start (prio 3) | 3 |
| 流局 / 途中流局 | draw / abort | 2 |
| リーチ | riichi | 1 |
| 静かな時間 | 対局中に 60 秒どの行も出ない (AI の行も数える) | 0 |

- 同じ様子から出た行 (和了と逆転など) は 1 回の頼みにまとめ、全部を「直前の出来事」に入れる。
- **呼ぶ間隔の下限 20 秒**、同時に 1 つだけ。間に来た場面は待たせ (格の大きいものを 1 つ、同じ格なら新しいもの)、下限が明けたら
  呼ぶ。待つのは 15 秒まで。その間に局か段階 (対局中 → 結果) が変われば捨てる (結果 → 終局は同じ扱い: 最後の和了の文は終局の
  画面にも合う)。
- 静かな時間は 60 秒ごとに 1 回まで (前の静かな時間の頼みから 60 秒、かつ最後の行から 60 秒)。
- **ページが 1 つも開いていなければ呼ばない** (`--json` のときは最初の卓を見ている扱い)。見ている卓だけ。誰も見ていない卓に
  お金を使わないための判断 (指示書の範囲内と判断した)。
- 回数 (試験 `test_a_recorded_game_asks_a_few_times_a_round` と同じ記録 = C1 の東風戦、383 の様子、和了 4・流局 1 の 5 局):

| 様子の間隔 (仮定) | 対局の長さ | 呼んだ回数 | 内訳 |
|---|---|---|---|
| 1.0 秒 | 6.4 分 | 6 | リーチ 4、流局 1、オーラス 1 |
| 1.5 秒 | 9.6 分 | 6 | 同上 |
| 2.5 秒 | 16 分 | 11 | 静かな時間 5、リーチ 3、逆転 1、流局 1、和了 1 |

  実際の卓 (6 章の確認、CPU 4 人・cpu_ms 700・東風戦 5 局、約 3.5 分) では 5 回 (リーチ 3、和了 1、満貫の和了 1) と
  10 回 (別の対局: リーチ 5、逆転 1、和了 2、オーラス 1、終局 1)。**1 局 1〜2 回**に収まった。試験は「局の数以上、局の数の
  4 倍以下、間隔は 20 秒以上」を見る。
- 気づき: 和了の前 20 秒以内にリーチを呼んでいると、和了は下限で待たされ、結果の表示 (CPU の卓は 8 秒) が終わって次の局に
  なると捨てられる。記録の東風戦では和了 4 回のうち AI が言えたのは 0 回 (1.0・1.5 秒の場合)、実際の卓では 5 局のうち 2 回。
  7 章に選択肢を書いた。

## 4. 頼む文の形

`AI::Commentator` (`lib/asterism_games/ai.rb`、anthropic の gem はここで読む。commentate の下のファイルは gem の名前を require に
書かない決まり (`test_framework.rb`) があるので、枠のファイルに置いた):

```ruby
@client = ::Anthropic::Client.new(api_key: key, max_retries: 0)
@client.messages.create(
  model: :"claude-haiku-5-5", max_tokens: 1024,
  system_: [{ type: "text", text: SYSTEM, cache_control: { type: "ephemeral" } }],   # 固定の部分 (キャッシュ)
  output_config: { effort: :low },                                                  # thinking は既定 (adaptive) のまま
  messages: [{ role: "user", content: USER }],                                      # 変わる部分
  request_options: { timeout: 8 })
```

- claude-api の skill に合わせた: Ruby の SDK の `system_:` と `cache_control`、モデル名 `claude-haiku-5-5` (日付を付けない)、
  Haiku 5.5 は thinking を既定のまま effort で抑える (budget_tokens は使えない)、prefill は使わない、`stop_reason` の
  refusal と max_tokens を先に見る、型つきの例外 (`APIStatusError` / `APIConnectionError`、時間切れは `APITimeoutError`)。
- 再試行はしない (`max_retries: 0`)。遅れて来た文は価値が無い。

### 4.1 固定の部分 (system、キャッシュに乗る)

口調 (plain / zundamon) と手牌の扱い (見せる / 隠す) の 4 通り。どれも毎回同じバイト列 (一度作って凍結して使い回す。時刻や
番号を入れない)。長さは約 1,600 字 (日本語なので 1,000〜1,600 tokens と見積もる。Haiku 5.5 がキャッシュする下限は 512 tokens。
tokens を数える API も外の API なので呼んでいない。実際の API で 2 回目から `cache_read` が 0 でないことを確認してほしい: 8 章)。
中身 (要約。全文は `AIComment::Prompt::SYSTEM`):

1. 役: 麻雀の観戦実況の「ひとこと」係。決まりの実況の後に添える。同じ事実を繰り返さず、場面の意味・緊張感・見どころ・次の展開を
   観戦者に語りかける。
2. 答え方: 日本語で **40 字以内、1〜2 文**。答えは文だけ (前置き・説明・かぎかっこ・記号の飾り・絵文字・顔文字・改行・話し手の
   名前なし)。牌は「3萬」「赤5筒」「東」の形 (読み直しが効く形)。様子に無いことを言わない、点数・役・順位を推測しない、
   打ち手を馬鹿にしない、特定の打ち手を応援しすぎない。口調は `TONES` の一文 (ずんだもん: 「語尾は〜なのだ・〜のだ、一人称は
   ボク、明るく元気に、短く」)。
3. 手牌: 見せるとき「手牌と待ちに触れてよい (誰の待ちが山に残っていそうか…)。打ち手には見えていないことを忘れず」、隠すとき
   「手牌は見えない。手牌・待ち・聴牌しているかを推測で言わない。公開の情報だけで話す」。
4. 麻雀の要点 (11 行): 東風戦・半荘・連荘・本場、持ち点と順位と見どころ、和了の形・ロン・ツモ、聴牌と待ちの残り、リーチと
   オリ、鳴き、ドラ、翻と符と満貫〜役満、流局とノーテン罰符、河の読み方、1 局の流れ。
5. 様子の読み方: ユーザの文に何が書いてあるか、最近のひとことと同じ言い回しを避ける。

### 4.3 答えの後始末

- 字幕は文のまま。改行は空白に、かぎかっこ・記号の飾り (`*#_` など)・絵文字・「ずんだもん:」の頭を除く。60 字を超えたら
  60 字以内の最後の文末 (。！？) で切り、切れなければ捨てる。空なら捨てる。
- 声は決まりの行と同じく `MahjongPhrases.reading` を通す (`SPEECH_READ` と牌の読み)。AI が漢数字で牌を書く場合に備えて、
  `reading` に漢数字の牌 (三萬 → サンマン、九索 → キューソー、五筒 → ウーピン) を足した。VOICEVOX ではその場の文として合成する
  (決まり文句なし)。

## 5. 古い答えの扱いと費用

### 5.1 古い答え

- 頼んだ時に、その卓の局 (風・局・本場)・段階 (status)・sv と時刻を持つ。答えが来た時に (`AIComment.stale?`):
  - 頼んでから 15 秒より後 → 捨てる (late)
  - 局が変わった (本場も) → another round
  - 段階が変わった (対局中 → 結果、結果 → 次の対局。結果 → 終局は同じ扱い) → another phase
  - sv が頼んだ時より小さい (ホストが起動し直した) → the host started again
- 時間切れ 8 秒、失敗、断られた (refusal)、文にならない答えは、1 行のログで捨てる。再試行しない。ログにキーと文は出さない
  (出すのは場面・秒・tokens・費用・理由だけ)。例: `commentate: AI: win: a stale answer dropped (another phase)`。
- ページの待ち行列: AI の文はどの決まりの行よりも低い (ページの中では prio -1)。決まりの行の後ろに並ぶ (同じ場面の決まりの行は
  先に届いているので必ず先に読む)。新しい場面 (リーチ・和了・流局・逆転) が来たら捨てる、局の始まりは AI の文の後ろに並ぶ、
  あふれたら最初に捨てる、待ち 40 秒で捨てる。捨てた理由は `window.commentate.played` の drop の src に書く
  (big / win / scene / full / stale / cut)。

### 5.2 費用

- ゲームホストの `AI::Budget` をそのまま使う。種類は `commentary`、ファイルは
  `$XDG_STATE_HOME/asterism-games/commentary_ai_usage.json` (既定 `~/.local/state/…`、ディレクトリ 0700、ファイル 0600。
  中身は回数・tokens・ドルだけ)。日付は手元の日付で、日をまたげば 0 から (Budget が日ごとに持つ)。
- 1 回ごとに API が返した `input_tokens`・`output_tokens`・`cache_creation_input_tokens`・`cache_read_input_tokens` を、
  モデルの値段で数える。失敗で tokens が無いものは `failed` を数える。断られた・切れた答えは tokens を数える。
- 値段 (USD / 100 万 tokens、claude-api の skill の表 2026-10-06 版、キャッシュの書き込みは入力の 1.25 倍、読み込みは 0.1 倍):

| モデル | 入力 | 出力 | キャッシュ書き込み (5 分) | キャッシュ読み込み |
|---|---|---|---|---|
| claude-haiku-5-5 (既定) | 0.10 | 0.50 | 0.125 | 0.01 |
| claude-haiku-4-5 | 1.0 | 5.0 | 1.25 | 0.10 |
| claude-sonnet-5-5 | 2.0 | 10.0 | 2.5 | 0.20 |
| claude-opus-5-5 | 4.0 | 20.0 | 5.0 | 0.20 |
| 表に無いモデル | Fable 5.1 の値段 (10 / 50 / 12.5 / 0.25) で数える (上限が必ず効くように) | | | |

- 上限: 今日の合計が `--ai-daily-usd` (既定 3) に達したら呼ばない (バー「今日の上限に達した」)。呼んでいる途中の 1 回は上限を
  少し超えうる。
- 見積もり (Haiku 5.5): 固定の部分 1,000〜1,600 tokens をキャッシュから読み、変わる部分 400〜700 tokens、出力 50〜200 tokens
  (thinking を含む) とすると、1 回 0.0001〜0.0002 ドル、最初の 1 回だけキャッシュの書き込みで +0.0002 ドル。東風戦 1 回 (5〜10 回)
  で 0.001〜0.002 ドル。3 ドルは約 2 万回。
- 偽物の tokens (入力 300、出力 25、キャッシュ 1,500) での実際の記録: 1 回目 0.00023 ドル、2 回目から 0.00006 ドル。

### 6.2 確認の途中で直したこと (コミットに含む)

1. 最初の確認で、AI の文が 6 つともページで捨てられていた。原因は 2 つ: ページ側の「AI の文は 12 秒で古い」が、和了と逆転の声
   (合わせて 17 秒ほど) の後ろで待つ間に切れていた。リーチ (prio 2) が来たときに捨てる決まりにも当たっていた。サーバ側で sv と
   経過秒で古い答えを捨てているので、ページ側は「新しい場面が来たら捨てる・40 秒」に改めた。
2. 次の確認で、和了の AI の文が次の局の始まりの行で捨てられていた。局の始まりは AI の文の後ろに並ぶようにした (AI の文は先に
   届いているので先に読む)。
3. 最後の局の和了の答えが、結果からすぐ終局に変わったため「段階が変わった」で捨てられていた。結果 → 終局は同じ段階として扱う
   ようにした (試験も足した)。

## 7. 決めたこと・選んでほしいこと

指示書の範囲内で決めたこと (止まる条件には当たらないと判断した):

1. ページが開いていない (と `--json` でない) ときは呼ばない。見ている卓だけ。
2. H をサーバへ伝える道 (`/events?hide=1`) を足した。H のページが 1 つでもあれば AI に手牌を渡さない。
3. 偽物は `ASTERISM_GAMES_AI_FAKE=1` (ゲームホストと同じ)、費用は別のファイル。表に無いモデルは最も高い値段で数える。
4. thinking は既定 (adaptive) のまま effort low、max_tokens 1024。答えは 60 字までに整える。
5. 待たせる場面は 15 秒まで、答えの古さは 15 秒、ページの待ちは 40 秒。

**選んでほしいこと: 20 秒の下限と和了** (3 章の気づき)。リーチを呼んだ直後の和了は、下限で待つ間に結果の表示が終わって捨てられる
ことが多い (記録の東風戦で和了 4 回中 0 回、実際の卓で 5 局中 2 回)。

1. **(推奨) 前の頼みより格が上の場面 (和了・逆転・終局など) は、下限を短く (例 8 秒) する。** リーチの直後の和了も言える。
   1 局の回数は 1 回ほど増える (費用は東風戦 1 回で 0.001 ドルほど増える)。
2. 今のまま (20 秒の下限をすべての場面に)。和了を言い逃すことがある。
3. リーチは呼ばない (和了・流局・逆転・オーラス・終局・静かな時間だけ)。回数は減り、和了は言いやすくなるが、リーチ中の緊張の
   ひとことは無くなる。

## 9. 気づき

- 実況の速い卓 (CPU の東風戦は 3〜4 分) では、局が 40〜60 秒で進むので、20 秒の下限は 1 局 1〜2 回に相当する。人が打つ卓は

  skill の表では 0.20 ドル。今回の範囲外なので変えていない (実況の値段表は 0.20 にした)。

  前のタブ (H を押したまま) がサーバに残って結果に効く。次からは前のタブを閉じてから始める。
