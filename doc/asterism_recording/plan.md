# Asterism: アプリから頼むキーの記録

> 状態: 構想 | 更新: 2026-10-21 | console の記録 (V4、今は管理者が画面で手で始める) を、Asterism のオブジェクトとしてアプリから始め・止め・一覧できるようにする。誰が何を録れるか (権限) は未確定で、案を並べて決める

## 目的

- アプリが自分の出来事を、決まった権限のもとで録れるようにする。例:
  - お絵かき: 「録画」ボタンで描いた経過を残し、あとで描く様子を流し直す。
  - 麻雀・オセロ: 対局の始まりから終わりまでを自動で録り、実況アプリや console で見返す。
  - デモ: 画面の録画の前に網の流れを録っておき、画面の録画をやり直せるようにする。
- 録っていることが、その場にいる全員に分かるようにする (網の上の決まりとして)。
- console を各自が入れる OSS (console の方針) のまま、作者の環境を前提にしない。

## 今の形 (2026-10-21)

- console の `/recordings` (asterism-console の docs/v4.md): 管理者だけが画面で録るキーを選び、始めて止める。MCAP 1 ファイル (Asterism は MessagePack のまま)。見る・流し直すも console の画面で、網へ流し直すのは管理者だけ (確認つき、監査の記録あり)。
- 限度: 1 本 512 MB・3600 秒まで (既定 64 MB・300 秒)、同時に 2 本、全体で `ASTERISM_RECORDINGS_MAX_BYTES` (4 GB)、1 本にキー 16 個まで。
- console の bridge は網を見るだけで、Asterism のオブジェクトを出していない。部屋 (room) の中は録れない (console は部屋を購読しない)。
- お絵かきの記録の実例: `asterism/games/games/board1/strokes` を録ると、線・取り消し・全消しの知らせが順に残り、網へ流し直すと画面が同じ順に描き直す (docs/v4.md「Recording a drawing board」)。
- 呼んだ相手は分かる: protocol 1 の呼び出しのキーは `.../call/<呼んだ相手>` で、ルータの ACL (役割のひな形) が「自分の名前でしか呼べない」ことを保証する (G1.5)。受けた側は `Asterism.current_call` で読む。

## 方針 (案。権限以外は大筋で異論が出ていない形)

1. **録画機を Asterism のオブジェクトにする**: console の bridge がアプリ (例 `<console のノード>/console/recorder`) を出し、メソッドで頼む。console の画面の記録と同じ仕組み・同じファイル・同じ限度の勘定に載せる (別の録画機を作らない)。
   - `start(keys, max_s:, max_bytes:, label:)` → 記録の ID
   - `stop(id)`、`status(id)`、`list` (自分が頼んだもの)
   - 頼んだ相手 (ノード名) を記録に残し、console の一覧にも出す。
2. **録っていることを流す**: 録画機は今の記録の一覧を自分のキー (例 `.../console/recorder/active`) に置く (どのキーを、誰の頼みで、いつから)。画面のアプリはこれを見て「録画中」を出す。中身は録っているキーの名前までで、録った値は流さない。
3. **呼んだ相手は `current_call` で見る**: 権限の判断は、ACL が保証する呼んだ相手の名前に基づく。名前を引数で受けない。
4. **見る・流し直すの権限は、録る権限と分けて決める** (下の未確定事項)。
5. 部屋の中は対象にしない (今と同じ。部屋の名前空間は console が購読しない作り)。

## 権限 (未確定、議論する)

決めることは 4 つ。それぞれの案と、今の見立て (推奨ではなく、議論の出発点) を並べる。

### A. 頼んだ人が、どのキーを録れるか

録画機は広く読める権限で動いているので、頼まれたまま録ると、本来読めない人が録画機を通して読めてしまう (代理の悪用、confused deputy)。それを防ぐ線をどこに引くか。

| 案 | 中身 | 良い点 | 弱い点 |
|---|---|---|---|
| A1 自分のノードの下だけ | `asterism/<呼んだ相手>/**` に含まれるキーだけ | 判断が単純で、代理の悪用が起きない | お絵かきの参加者 (板のホストではない) は板のキーを録れない。ホストに頼む形 (A3) が要る |
| A2 自分の役割で読めるものだけ | console が役割のひな形から呼んだ相手の読める範囲を求め、頼まれたキーがその中に含まれるときだけ録る | 「読めるものは録れる」で筋が通る。参加者が直接録れる | キーの式どうしの「含まれる」の判定を console に書く (ワイルドカード)。ACL と判定が食い違うと穴になる。読めることと残してよいことは別、という反論がある |
| A3 キーの持ち主が許す | キーを出しているアプリ (例 板のホスト) が「このキーは参加者が録ってよい」と宣言するか、ホスト自身が参加者の頼みを受けて A1 で録る | 持ち主が決めるので、残されたくないものは残らない | アプリごとに作り込みが要る。持ち主のいないキー (端末のセンサ値) は決められない |
| A4 管理者の承認 | アプリの頼みは保留になり、管理者が console で認めたら始まる | 何でも録れて安全 | その場で録れない (デモ・対局の自動の記録に向かない) |

見立て: 最初は **A1 だけ**で作り、ゲームやお絵かきは**ホストが録る (A3 の後半)** 形で使う。A2 は判定の作りと試験の量を見てから。A4 は A1 の外を録りたいときの逃げ道として後で足せる。

### B. 誰が録画機を使えるか

| 案 | 中身 |
|---|---|
| B1 役割に「録ってよい」を足す | console の役割の設定に 1 項目足す。役割ごとに上限 (1 本の長さ・大きさ、ノードあたりの合計、同時の本数) も持たせる |
| B2 全員 (限度だけ) | 証明書があれば誰でも。限度はノードごと |
| B3 管理者が選んだノードだけ | 台帳の行ごとに許す |

見立て: **B1**。今の役割 (ひな形で ACL を作る) の作りに合う。部屋のページ (合言葉で入る人) は対象外。

### C. 録った記録を誰が見られる・流し直せるか

| 案 | 中身 |
|---|---|
| C1 頼んだノードと管理者だけ | 頼んだノードは `list` と、MCAP を受け取るメソッド (例 `fetch(id)`、分割して渡す) で手に入れる。console の画面は管理者のまま |
| C2 C1 + その場の参加者 | 録ったときの参加者 (板の参加者など) も見られる。参加者の名簿はアプリが渡す |
| C3 共有の印を付けたら誰でも | 頼んだノードが「公開」にした記録は、読み取りの役割を持つ人なら見られる |

網へ流し直すのは、今は管理者だけ (確認つき)。アプリから流し直すなら、流す先を**頼んだノード自身のキーに限る**などの線が要る (他人のキーに偽の値を流せてしまうため)。見立て: **C1**、流し直しは管理者のまま。アプリでの再生は、アプリが記録を受け取って自分の画面の中で流す (お絵かきの「再生」) 形で足りるかを先に見る。

### D. その場の人への知らせと同意

| 案 | 中身 |
|---|---|
| D1 知らせるだけ | 録画機の `active` を見て、アプリが「録画中」を出す。止める権利は頼んだ人と管理者 |
| D2 参加者が止められる | 録られているキーの持ち主か参加者が `stop` を呼べる (誰が参加者かはアプリが決める) |
| D3 参加者全員の同意で始まる | アプリが全員の同意を集めてから頼む (録画機は関与しない) |

見立て: 録画機としては **D1** を用意し、D2・D3 はアプリの決め (例 お絵かきは主だけが録画を始められる) に任せる。

## 段階 (案)

| 段 | 中身 | 受け入れ (案) |
|---|---|---|
| R0 | 権限の 4 点 (A-D) を決める。メソッドの形と、`active` のキーの形を決める | この plan の未確定事項が消える |
| R1 | console: bridge が録画機のオブジェクトを出す。`start`/`stop`/`status`/`list`、呼んだ相手の確認 (A の決めた形)、役割の「録ってよい」と上限 (B)、`active` の配信。console の記録の一覧に「頼んだノード」の列 | CRuby の試験のノードが自分のキーを録って止められる。他人のキーは断られる (理由つき)。限度で止まる。管理者の画面の記録と同じファイルになり、今の見る・流し直すがそのまま使える |
| R2 | 記録の受け渡し (C): `fetch` で MCAP を分割して渡す。asterism gem か asterism-games に、MCAP から Asterism のキーの値を順に読む小さな読み手 (console の Ruby の MCAP の読み手を参考にする) | CRuby が自分の記録を受け取り、値と時刻を順に読める |
| R3 | お絵かきで通す: 板のホストが録画を受け持ち (A1)、板の画面に「録画」(主だけ、または決めた人) と「録画中」の印。録画の再生は画面の中だけで流す | ブラウザ版 2 つで、描く → 録画 → 全消し → 再生で同じ順に描き直る。もう一方の画面に「録画中」が出る |
| R4 | 対局の自動の記録 (麻雀・オセロ): ゲームホストの設定で、対局の始まりに録り、終わりで止める。実況アプリや console で見返す | 1 局を録って、実況アプリで流し直せる (実況の側の作りは別に決める) |

## スコープ

- 入る: asterism-console (bridge の録画機・役割の設定・一覧の列)、asterism gem (呼ぶ側の小さな補助と MCAP の読み手、必要なら)、asterism-games (板・対局のホストが録る)、Family mruby の板の画面 (「録画」「録画中」)。
- 入らない: 部屋の中の記録、ROS 2 のトピックをアプリから録ること (今の画面の記録で足りる)、圧縮 (zstd)、他人のキーへの流し直し。
