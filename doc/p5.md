# P5 — Processing/p5.js 互換描画 API

family-mruby (fmruby-core) における Processing/p5.js 風の Ruby 描画 DSL を提供
するライブラリ。`mrblib/p5.rb` に定義されており、firmware に常時バンドルされる。

## ファイル

- 実装: [lib/add/picoruby-fmrb-app/mrblib/p5.rb](../lib/add/picoruby-fmrb-app/mrblib/p5.rb)
- 下層 API: [lib/add/picoruby-fmrb-app/mrblib/fmrb-gfx.rb](../lib/add/picoruby-fmrb-app/mrblib/fmrb-gfx.rb)
- 参照元: `tmp/harucom-os/rootfs/lib/p5.rb` および `tmp/harucom-os/doc/p5.md`

## 使い方

`FmrbApp` の `@gfx` を P5 でラップして使う。

```ruby
class MyApp < FmrbApp
  def on_create
    @p5 = P5.new(@gfx)
  end

  def on_update
    @p5.background(P5::BLACK)
    @p5.fill(P5::RED)
    @p5.no_stroke
    @p5.rect(10, 10, 60, 40)
    @p5.present
    33
  end
end
```

## Harucom-OS 版 P5 との差分

このセクションは Harucom-OS 版 (`tmp/harucom-os/rootfs/lib/p5.rb`) からの移植
時に意識すべき差分をまとめたものである。

### 構築方法

| 項目 | Harucom-OS | fmruby-core |
|---|---|---|
| 構築 | `p5 = P5.new` (DVI モード切替を内部で実施) | `p5 = P5.new(@gfx)` (FmrbApp の `@gfx` を渡す) |
| 描画下層 | `DVI::Graphics` クラスメソッド (シングルトン) | `FmrbGfx` インスタンスメソッド (canvas 毎) |
| バックエンド | RP2350 + DVI (HSTX) ローカル framebuffer | ESP32-S3 → ESP32-WROVER の SPI メッセージ + LovyanGFX |
| フレーム完了 | `commit` (VBlank 待ち & swap) | `present` (`commit` は alias) |

### API 単位の差分

下表で「同一」とあるものは引数・戻り値・効果が Harucom 版と等価。差分がある
項目のみ理由を補足する。

| API | 状態 | 差分・理由 |
|---|---|---|
| `width` / `height` | 同一 | 値は `@gfx.canvas_width/_height` から取得 |
| `background(color)` | 同一 | blend_mode が ADD/XOR のときは `FmrbGfx#blend_rect` 経由 |
| `commit` / `present` | 名称追加 | fmruby-core では `present` が正、`commit` は alias |
| `fill` / `no_fill` / `stroke` / `no_stroke` | 同一 | |
| `stroke_weight(w)` | 同一 (実装差) | `>1` の太線は `FmrbGfx#draw_thick_line` (法線方向に平行線を重ねる Ruby 実装)。Harucom は C 側の `draw_thick_line` 直呼び |
| `blend_mode(mode)` | **挙動差分** | サポート対象は `REPLACE` / `ADD` / `XOR` のみ。かつ `rect()` / `background()` (矩形塗り) でしか効かない。`SUBTRACT` / `MULTIPLY` / `SCREEN` は定数のみ提供し挙動は `REPLACE` と同じ。理由: LovyanGFX 側のグローバルブレンド設定パスが未実装で、FmrbGfx は `blend_rect` のみが ADD/XOR をサポート |
| `alpha(value)` | **未対応 (no-op)** | LovyanGFX 側にアルファ合成パスが無い |
| `text_font(font, wide_font = nil)` | **引数差分** | Harucom は `DVI::Graphics::FONT_8X8` 等の定数 ID。fmruby-core は `(:default)` または `(:ja, 8)` / `(:ja, 12)`。`wide_font` 引数は受けるが無視 |
| `text_color(color)` | 同一 | |
| `text_align(h, v = :top)` | 同一 | `:left/:center/:right` × `:top/:center/:bottom`。幅計測は固定幅前提 |
| `text_leading(pixels)` | 状態保持のみ | 行内 `\n` 解釈は未実装 |
| `text_width(str)` | 同一 (実装差) | `FmrbGfx#text_width` 経由。固定幅テーブルで計算 (`FmrbGfx::FONT_METRICS`) |
| `text(str, x, y)` | 同一 (実装差) | 呼び出し前に `@gfx.current_font` / `current_text_size` を保存し、描画後に元に戻す |
| `translate` / `rotate` / `scale` / `push_matrix` / `pop_matrix` / `reset_matrix` | **合成順を修正** | 2x3 アフィン行列スタックを post-multiply (`M' = M * op`) で更新する。Harucom の実装は pre-multiply (`M' = op * M`) で、`translate(160, 110); rotate(t); rect(-30,-20,60,40)` がワールド原点まわりの回転になってしまっていた。fmruby-core 版は p5.js / Processing と同じ「ローカル原点中心の回転」になる |
| `point(x, y)` | 同一 | |
| `line(x0, y0, x1, y1)` | 同一 (実装差) | `stroke_weight` に応じて `draw_line` / `draw_thick_line` に分岐 |
| `rect(x, y, w, h)` | 同一 | translate のみのとき高速パス。回転時は塗りを 2 三角形に分解 |
| `circle(cx, cy, r)` | 同一 | スケール時は `fill_ellipse` にフォールバック |
| `ellipse(cx, cy, rx, ry)` | 同一 | |
| `triangle(...)` | 同一 | |
| `arc(cx, cy, r, start, stop)` | **マッピング差分** | API は Harucom と同じく**ラジアン**で受けるが、`FmrbGfx#fill_arc` / `#draw_arc` は LovyanGFX 準拠で**度**を取るため、P5 内で radian → degree 変換してから渡す。塗りは `fill_arc(x, y, 0, r, ...)` (内側半径 0 = パイ)、ストロークは `draw_arc(x, y, r-1, r, ...)` (1 ピクセルの外周リング) にマップ。p5 の `OPEN`/`CHORD`/`PIE` モードはサポートしない (常にパイ) |
| `bezier(...)` | 同一 | 20 セグメントの直線分割 |
| `curve(...)` | 同一 | Catmull-Rom 20 セグメント |
| `image(...)` | **シグニチャ差分** | Harucom: `image(data, x, y, w, h)` (RGB332 生バッファ)。fmruby-core: `image(image_id, x, y, scale_x = 1.0, scale_y = 0.0)`。事前に `@gfx.create_image(path)` で取得した id を渡す。理由: 描画バックエンド (WROVER) は生バッファでなくファイルベース画像 API を持つ |
| `image_masked(image_id, mask_data, x, y, w, h)` | **シグニチャ差分** | Harucom: `image_masked(data, mask, x, y, w, h)` (RGB332 生バッファ + 1bpp マスク)。fmruby-core: 第 1 引数は SpriteImage の `image_id`、`mask_data` は 1bpp バイナリ文字列 (`ceil(w/8)*h` バイト、MSB-first)。理由: バックエンドは画像ソースを SpriteImage 経由で扱う。内部は `FmrbGfx#create_mask` で mask_id を取得し `draw_image_masked` を呼んだ後 `delete_mask` する。長寿命マスクが欲しい場合は `@gfx.create_mask` / `@gfx.draw_image_masked` を直接使う |
| `set_pixel(x, y, color)` | 同一 | 変換行列を介さない素の書き込み |
| `get_pixel(x, y)` | 対応 | `FmrbGfx#get_pixel` を経由。host_task の sync コマンドとして送られるため、直前までキューされた描画は自動で flush されてから読み取られる。範囲外座標は 0 を返す。SPI ラウンドトリップが入るのでループ内連呼は避ける |
| `color(r, g, b)` | 同一 (実装差) | `FmrbGfx.rgb_to_332(r, g, b)` を委譲呼び出し。Harucom はビット演算直書き |

### 色定数とブレンドモード定数

Harucom 版は色定数を `DVI::Graphics` 経由で扱うが、fmruby-core 版は P5 内で
独自定数を持つ (`FmrbGfx::COLOR_*` のミラー):

```
P5::BLACK / WHITE / RED / GREEN / BLUE / YELLOW / CYAN / MAGENTA / GRAY
P5::REPLACE / ADD / XOR / SUBTRACT / MULTIPLY / SCREEN
```

`SUBTRACT` / `MULTIPLY` / `SCREEN` は値だけ提供。実体は `REPLACE` と同じ動作。

### FmrbGfx に追加した補助メソッド

P5 から呼ぶ目的で、FmrbGfx 側 (`fmrb-gfx.rb`) に以下を追加している。P5 を
使わない場合でも FmrbGfx から直接呼べる:

- `FmrbGfx#text_width(str, family = nil, size = nil)` — 固定幅テーブルから
  ピクセル幅を計算
- `FmrbGfx#font_height(family = nil, size = nil)` — 行高さを返す
- `FmrbGfx#draw_thick_line(x0, y0, x1, y1, thickness, color)` — 法線方向に
  平行線を重ねた Ruby 実装の太線
- `FmrbGfx#canvas_width` / `FmrbGfx#canvas_height` — 構築時に渡された寸法を公開

固定幅テーブルは `FmrbGfx::FONT_METRICS` に定義 (`:default` / `[:ja, 8]` /
`[:ja, 12]`)。

## 移植時の注意

Harucom-OS 向けに書かれた p5 スケッチを fmruby-core で動かす際の修正手順:

1. `P5.new` → `P5.new(@gfx)` に書き換える (FmrbApp の `@gfx` を渡す)
2. `image(data, x, y, w, h)` を使っている場合は事前に
   `image_id = @gfx.create_image(path)` し、`image(image_id, x, y)` に変更
3. `image_masked` を使っている箇所は別実装に置き換え (`get_pixel` はそのまま動く)
4. `blend_mode(SUBTRACT/MULTIPLY/SCREEN)` を期待した見た目になっているかは
   `REPLACE` 動作になる前提で再調整
5. `alpha(value)` は no-op になるので、半透明前提の合成は別の方法で表現
6. `text_font(DVI::Graphics::FONT_8X8)` のような定数 ID は
   `text_font(:default)` 等に書き換え

## 既知の制限 (再掲)

- `image_masked` / `get_pixel` は対応済み (SpriteImage + 1bpp マスク。詳細は API 表参照)
- `blend_mode` のサポートは `REPLACE` / `ADD` / `XOR` のみ、かつ `rect` /
  `background` 限定
- `alpha` は no-op
- 太線 (`stroke_weight > 1`) は平行線重ね描画のソフト実装。鋭角ではジャギーや
  わずかな隙間が出ることがある
- テキストは fixed-pitch フォント前提で幅計測 (`FmrbGfx::FONT_METRICS`)。可変幅
  フォントが将来追加された場合は更新が必要
- `text_leading` は値を保持するのみで、改行込みの自動レイアウトは未実装
