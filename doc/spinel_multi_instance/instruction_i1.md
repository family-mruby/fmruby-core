# 作業指示書 I1: 調査 (同じ Spinel プログラムの複数インスタンス)

対象: 実装担当のサブエージェント。前提: plan.md (ユーザの決定を含む)、doc/app_exit/report/e1.md (E2 の節)、
e3.md。report は `report/i1.md` へ。**この段階は調査と見積もりだけで、コードは変えない** (計測のための一時的な
変更は可。コミットしない)。

## 目的

「根本対策 (状態をインスタンスごとに持たせる)」「一部だけ直す (例外まわりなど)」「同時起動の制約」を、ユーザが
選べるように、それぞれの難しさとトレードオフを数字で示す。

## T1: 何が共有されているか (全部の種類)

- エディタの生成 C (`main/prebuild_scripts/spinel/gen/` の editor の combined の C) と Spinel の実行時
  (components/fmrb_spinel_rt/spinel_rt/、フォーク kishima/spinel fmrb-ext の clone `/home/kishima/fmrb/wt/spinel-rebase`)
  を読み、ファイル単位の変数 (static、大域) を種類ごとに数える: 例外・catch・break のスタック、クラスの ivar
  (`civ_`)、定数 (`cst_`)、プールの数え、シンボル、凍結リテラル (const で書き込まないもの)、GC の根、
  `SP_MULTI_CTX` が既にインスタンスごとに持っているもの、など。
- それぞれ「書き込むか」「インスタンスの開始で `sp_reset_tu_statics` が戻すか」「GC の根か」を表にする。
- 実行時 (spinel_rt) の側の大域で、プログラムごと・インスタンスごとに分けるべきものも同じく。
- Spinel の gem (raycast、spinel_hello、fft) と、カーネル (1 つしか動かない) の扱いも書く。

## T2: 直し方の候補ごとの見積もり

候補ごとに、(1) 生成器 (codegen.c) と実行時の変更の範囲と行数の見込み、(2) 速さの費用、(3) 内蔵 RAM・PSRAM、
(4) 上流との乖離と保守の手間、(5) 危険 (見落とすと黙って壊れる箇所) を書く。

- **A. 全部をインスタンスごとに**: 書き込む変数を、インスタンスの文脈 (構造体) に移し、参照を 1 段間接にする。
  速さの費用は、**実際に試して測る** (例: エディタの生成 C の一部、または小さな Spinel のベンチを手で書き換えて、
  間接にした場合の速さを P4 実機か sim で比べる。コミットしない)。打鍵・描画・GC の時間への影響の見込み。
- **B. 一部だけ**: 例外・catch・break のスタックだけをインスタンスごと (または開始時に戻す) にした場合、E2 の
  症状のどれが消えて、どれが残るか (クラスの ivar・定数の上書きは残る、など)。
- **C. 同時起動の制約**: E2 で入れた形 (同じプログラムの 2 つ目を断る)。利用者から見た制約の内容と、gem への
  広げ方。
- 他に良い候補があれば加える (例: 2 つ目のインスタンスには、生成 C を別の名前で 2 本目としてリンクする、など。
  flash の増え方を書く)。

## T3: まとめ

- 候補の比較の表 (難しさ、速さ、RAM、flash、上流との乖離、危険) と、親への推奨 (理由つき)。ユーザが選ぶので、
  推奨は 1 つに決めつけず、選ぶための判断材料を中心に。

## 作業の決まり

- 作業ブランチ `feature/spinel-multi-instance` (親が develop から切った)。コミットするのは report (と必要なら
  plan の状態行は親が直すので触らない)。push とマージはしない。`.env` は書き換えない (scratchpad の
  env_before_multi.diff と一致)。
- フォークにも、試しの変更はコミットしない。sdkconfig、graphics-audio、submodule は変えない。
- 実機 P4-Nano (/dev/ttyACM1、192.0.2.15) は**ミュートのまま**。焼いた場合は最後に develop の版に戻す。
- **利用者から見た動きを変えることは何もしない**。
- report は日本語の常体。ユーザが選ぶための資料なので、表を中心に。
