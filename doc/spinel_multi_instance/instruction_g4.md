# 作業指示書 G4: エラーの窓の中のクリックでキー入力の行き先を動かさない

対象: 実装担当のサブエージェント。前提: plan.md、report/g1.md (G3、特に「止まった所」)。report は `report/g1.md` に
「G4」の節を足す。作業ブランチは `feature/spinel-gem-fallback`。

## 決定 (ユーザ、2026-10-04): 案 1

デスクトップのエラーの窓 (断る窓、ほかのエラーの窓すべて) の中をクリックしたときは、カーネルのクリックでキー入力の
行き先を移す規則 (クリックした窓のアプリへ) を適用せず、**キー入力の行き先を動かさない**。エラーの窓はキーを受けない
ので、キーを取る理由が無い。窓を閉じる動き (クリックで閉じる) はそのまま。

- エラーの窓以外 (デスクトップのほかの部分、メニュー、ほかのダイアログ、アプリの窓) のクリックの規則は変えない。
- エラーの窓かどうかの判定は、カーネルとデスクトップが既に持っている情報から選び、理由を report に書く (デスクトップの
  前面の重ね (overlay) の種類、窓の位置など)。

## 検証

- 実機 P4-Nano (ミュートのまま、動いているアプリは止めてよい): Mic Spectrum の 2 つ目 → 断る窓の**中**をクリックして閉じ、
  E キーが Mic Spectrum に届く。エディタの 2 つ目・spinel_hello の 2 つ目でも同じ。動いている最中のアプリのエラーの窓
  (G3 の report の compile_err など、エラーの窓を出す方法を探す) でも、窓の中のクリックで行き先が動かないこと。
  デスクトップの壁紙やメニューをクリックしたときは今までどおりデスクトップにキーが行くこと。
- sim (標準・互換)、`rake test`、ビルド (TAB5 / NARYAv4 / S3 / Linux の標準と互換 / wasm)。標準構成の sim ではエディタの
  起動と 1 打鍵も。静的な D/IRAM が develop (NARYAv4 125,612 B) を超えない。
