# NSF プレーヤの改修 (フォルダ・切り替え・曲の終わりで次へ)

> 状態: 進行中 | 更新: 2026-11-08 | N1・N2 実装済・develop に取り込み、GPD に入れて目視・耳の確認待ち (report/n1_n2.md)。 開くフォルダを選んで覚える、演奏中の別の曲は止めて鳴らす、曲の終わり (無音・ループを数周・時間の上限) で次へ。ループの検出は音源の側 (graphics-audio)

## 目的

- NSF プレーヤ (`flash/app/tool/nsf_player.app.rb`) を、手持ちの NSF を並べて聞き流せる道具にする。

## 今の形 (2026-11-08)

- フォルダは `/usr/share/sounds/nsf` の決め打ち。
- 曲 (ファイル) とトラックを選んで Play / Stop。曲が終わっても止まらず鳴り続ける
  (NSF には曲の長さの情報が無い)。
- 鳴らすのは graphics-audio の `audio_task_nsf_play` (前の曲を止めてから読み直す作り)。
  アプリへ「終わった」を知らせる道は無い。

## 方針 (2026-11-08 ユーザ決定)

1. **開くフォルダは、既存のファイル・フォルダを選ぶ画面で選ぶ** (無ければフォルダだけ
   選ぶ小さな画面を作る)。選んだフォルダを覚え、次に開いたときもそこを開く。
2. **演奏中に別の曲 (ファイル) を選んで再生したら、今の曲を止めて新しい曲を鳴らす**。
3. **曲の終わりを音源の側で見つけてアプリに知らせる**:
   - 無音が続いたら終わり。
   - **ループの検出**: APU のレジスタへの書き込みの流れを毎コマ記録し、同じ並びが繰り返し
     始めたら 1 周と数える。決めた周回でフェードアウトして終わり。
   - 検出できない曲は**時間の上限**でフェードアウトして終わり。
   - 無音の秒数・周回・時間の上限は既定値を持ち、決めた値を report に書く (後で画面から
     変えられるようにするかは、使ってから決める)。
4. **終わった後の進み方は画面で切り替える**: 「1 曲 (止まる)」「ファイルの中を順に」
   「フォルダの中を順に」などの繰り返しの範囲をボタンで選ぶ。選んだものも覚える。
5. Retro (WROVER) と Modern (同じ CPU の中の graphics-audio) とネイティブ版・sim・ブラウザ版の
   どれでも同じ動き。WROVER の CPU と内部 RAM の余裕を測ってから載せる。

## スコープ (段)

| 段 | 内容 | 状態 |
|---|---|---|
| N1 | アプリ側: フォルダを選んで覚える、演奏中の別の曲は止めて鳴らす、繰り返しの範囲のボタン | 実装済 |
| N2 | 音源の側: 無音・ループの検出・時間の上限とフェード、終わりをアプリへ知らせる道 (graphics-audio → core → アプリ)。アプリは知らせを受けて次へ | 実装済 |

## 受け入れ条件

- N1: フォルダを選ぶと一覧が変わり、アプリを閉じて開き直しても同じフォルダが開く。
  演奏中に別のファイルを選んで再生すると、前の曲が止まって新しい曲が鳴る (sim か
  ネイティブ版で、`fmrb_audio_probe` 等の数値で)。
- N2: 手持ちの NSF (`flash/usr/share/sounds/nsf/` の数曲) で、無音で終わる曲・ループする曲の
  それぞれが、決めた条件で次のトラックへ進むことをログと音の数値で示す。ループの検出が
  当たった曲・外れて時間の上限で進んだ曲を report に表で残す。WROVER の CPU の増分と
  内部 RAM の増分を report に (実機はユーザがつないだとき)。
- 最初の目視・耳での確認は GPD (ネイティブ版の .deb) で (2026-11-08 ユーザ)。検収と取り込みの後、親が .deb を作って GPD に入れる。
- どの段も `rake regress` が通る (graphics-audio 側も、その回帰の道具)。
