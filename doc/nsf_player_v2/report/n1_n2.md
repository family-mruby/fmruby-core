# N1・N2 の実装 (フォルダ・切り替え・繰り返しの範囲、曲の終わり)

> 状態: 実装済・親の検収待ち | 更新: 2026-11-08 | N1 (アプリ) と N2 (音源の側の終わりの検出と知らせ) を worktree (wt/nsf-player) で実装した。既定値、知らせの通り道、手持ちの NSF での検出の表、確認したことと残り

## 1. 何をしたか

### N1 (アプリ、`flash/app/tool/nsf_player.app.rb`)

- **フォルダ**: 「Open」ボタンでデスクトップの既存のファイル選択の画面 (`request_file_select("open")`) を開き、**選んだファイルのフォルダ**を開くフォルダにする (その画面はファイルしか選べない。フォルダを直接選ぶ形は作っていない。6 章)。選んだファイルが一覧で選択される。
- **覚える**: フォルダと繰り返しの範囲は `/home/nsf_player.toml` (`app_settings`) に `dir` と `repeat` で持つ。変えたときだけ書く。開くとそこを開く (無いフォルダなら既定の `/usr/share/sounds/nsf`)。
- **切り替え**: Play は常に「選んでいるもの」を鳴らす。演奏中に別のファイル (または別のファイルのトラック) を選ぶとボタンが Play に戻り、押すと今の曲を止めて新しい曲を鳴らす。鳴っているファイルには一覧で `>` が付く。鳴っているファイルのトラックを変えたときは今までどおりすぐ切り替わる。
- **繰り返しの範囲**: ボタン 1 つで `1 song` → `File` → `Folder` と巡る。既定は `Folder`。
  - `1 song`: 曲が終わったら止まる。
  - `File`: 同じファイルの次のトラックへ、最後のトラックの次は 1 番目へ。
  - `Folder`: 次のトラックへ、ファイルの最後のトラックの次は次のファイルの 1 番目のトラックへ、フォルダの最後の次は最初のファイルへ (読めないファイルは飛ばす)。曲が進むと選択も一緒に動く。
- ついで: 上下キーが効いていなかった (keycode で見ていた。sim では SDL の keysym なので KEY_UP と一致しない) のを scancode に直した。

### N2 (音源の側)

- 終わりの検出は **NSF プレーヤ自身** (`components/apu_emu/src/nsf_player.c`、graphics-audio と core で同一のファイル) に入れた。音源のタスク (graphics-audio の `main/tasks/audio_task.c`、core の `main/drivers/audio_p4/audio_p4_task.c`) は毎コマのミックスの後に `nsf_player_end_frame` を呼び、フェードを MAIN の音量に掛け、終わったら止める。Retro (WROVER)・sim (graphics-audio の Linux 版)・Modern・ネイティブ版・ブラウザ版のどれも同じコードが走る。
- **無音**: MAIN のそのコマの出力の振れ幅 (`apuif_main_level()`、新設。サンプルの変換のループで最小・最大を取るだけ) が小さいまま続いたら終わり。フェードなしですぐ止める。
- **ループ**: コマごとに APU のレジスタへの書き込み (アドレスと値の並び) を FNV-1a で 16 ビットの値にし、16384 コマ (4.5 分) の輪に置く。直近 32 コマの値の転がし指紋で、だいたい 16 コマに 1 つを「目印」にする (指紋自身のビットで選ぶので、どの周でも同じ場所が目印になる)。目印の表 (1024 個、直接写像) には、その指紋を見た最近の 3 か所と、輪に残っている最も古い 1 か所を持つ。前に見た目印から周期の候補が出たら、さかのぼって一番長く繰り返している候補を採り、以後はコマごとに 1 回比べる。
  - **前後 1 コマのずれを許す**: テンポをコマの端数で持つドライバは、周回ごとに音が 1 コマ早い・遅いところがあり、ぴったり一致するのは数周に 1 回になる (手持ちの曲の 1 つは、29.5 秒の曲が 88.6 秒ごとにしか一致しない)。比べる相手を 1 つ前・後のコマにも広げ、外れは 8 点、何かが変わったコマで当たれば 1 点戻し、64 点を超えたら候補を捨てる。何も変わらないコマ同士は数えない (新しい音のときだけ書くドライバは、そうしないとどの周期でも一致してしまう)。
  - 中の区間の繰り返しがループを隠さないよう、最も古い 1 か所を目印に残し、候補を追っている間もその 1 か所だけは試し、はっきり長く繰り返しているほうに乗り換える。
  - 周回: ループの最初の 1 周の後、さらに (周回 - 1) 周 = 既定で 1 周が繰り返したら終わり。15 秒より短い周期は 15 秒に届く整数倍を 1 周と数える (2 秒の音型の繰り返しで終わらないため)。
- **時間の上限**: ループが見つからない曲は 180 秒でフェードを始める。その時点でループを数えている (15 秒以上繰り返している) なら、その周の終わりまで 360 秒を上限に待つ。
- **フェード**: ループ・上限で終わるときは 5 秒で MAIN の音量を直線に 0 へ。SUB (効果音) と WAV には掛けない。
- 検出の記憶は `apuemu_malloc` (実機は PSRAM) で、曲を読み込んだときに取り、プレーヤを解放するときに返す: 輪 32 KB + 目印の指紋 4 KB + 場所 8 KB = 44 KB。取れなければループの検出だけが止まり、無音と上限は効く。

## 2. 「終わった」の通り道 (graphics-audio → core → アプリ)

graphics-audio と core の間の線は core が聞いて graphics-audio が答える形 (graphics-audio から勝手に送る道は無い) なので、**アプリが約 1 秒ごとに聞く**形にした。

1. アプリ: `FmrbAudio#nsf_status` (`lib/add/picoruby-fmrb-app/mrblib/fmrb-audio.rb`) → `FmrbApp#_audio_nsf_status` (C、`ports/esp32/app.c`) → `fmrb_app_audio_nsf_status` (`main/app/fmrb_app.c`)。
2. core: `fmrb_transport_send_sync(FMRB_LINK_TYPE_AUDIO, payload = [FMRB_AUDIO_CMD_NSF_STATUS (0x11)])`。画像の問い合わせと同じく、アプリのタスクから直に線へ出す (カーネルを通らない)。待ちは 500 ms。
3. 答える側:
   - Retro・sim: graphics-audio の `message_handler_task.c` が 0x11 を受けると `audio_task_nsf_status` で状態を作り、ACK に載せて返す。
   - Modern・ネイティブ版・ブラウザ版: core の `display_local_task.cpp` が `audio_p4_nsf_status` で同じものを ACK に載せる。
4. 答え (`fmrb_audio_nsf_status_t`、`audio_commands.h`、12 バイト): `state` (0 なし/止めた・1 演奏中・2 フェード中・3 自分で終わった)、`reason` (1 無音・2 ループ・3 上限)、`track`、`laps`、`gen`、`period_frames`、`frames`。
5. **gen**: 音源の側が受けた再生の数。問い合わせは再生の命令 (カーネル → host タスク経由) を追い越しうるので、アプリは再生を送る前に見た gen と違う gen が返ってくるまで、答えを前の曲のものとして扱わない (前の gen を知らないときは 1.5 秒待つ)。その後 gen が変わったら別のアプリが鳴らしたとみなして止める。
6. アプリは `state == 3` で繰り返しの範囲に従って次へ進む。`state == 0` (外から止められた・鳴らせなかった) なら演奏していない扱いに戻す。
7. 答えが無い (古い graphics-audio) ときは nil。2 回続いたら聞くのをやめ (1 回ごとに 500 ms 待つため)、今までどおり鳴らし続ける。

Spinel の FmrbApp (`fmrb_app_base_spinel.rb`) には nil を返す `_audio_nsf_status` だけを置いた (NSF を鳴らす Spinel のプログラムは無い)。

## 3. 既定値

| 項目 | 値 | 定数 (`nsf_player.h`) |
|---|---|---|
| 無音とみなす振れ幅 | 1 コマの振れ幅が 512 以下 (APU の 8 ビットで 2 段) | `NSF_END_SILENCE_LEVEL` |
| 無音の長さ | 3 秒 (180 コマ) | `NSF_END_SILENCE_FRAMES` |
| 周回 | 2 | `NSF_END_LAPS` |
| 1 周とみなす最短 | 15 秒 | `NSF_END_MIN_LOOP_FRAMES` |
| 時間の上限 (ループなし) | 180 秒 | `NSF_END_LIMIT_FRAMES` |
| 時間の上限 (ループを数えている) | 360 秒 | `NSF_END_HARD_LIMIT_FRAMES` |
| フェード | 5 秒 | `NSF_END_FADE_FRAMES` |
| 探せる周期の最長 | 約 4.5 分 (16384 コマの輪。2 周を聞くので実際は 3 分弱まで) | `NSF_END_HIST_FRAMES` |
| ずれの許し | 外れ 8 点、64 点で捨てる | `NSF_END_MISS_COST` / `_LIMIT` |
| アプリが聞く間隔 | 約 1 秒 (330 ms の更新の 3 回に 1 回) | アプリの `STATUS_EVERY` |

外れの点を 4 にすると見つかるループは増える (手持ちの曲で上限 44 → 26) が、短い音型の繰り返しを曲のループと取り違える例が出た (周期 51.2 秒の曲が 3.2 秒の繰り返しと取られて 56 秒で終わる、など) ので 8 にした。

## 5. 確認したこと

- `rake regress` (core worktree): host 22 suites (新しい `nsf:test` を含む) 通過、描画の記録 229 本通過。nsf_player の記録は 24 本が変わった・増えたので、中身を読んで更新した (Repeat と Open のボタンが増えた、上下キーが効くようになった、新しい場面 advance・switch・folder・remembered)。
- `rake nsf:test` (新設、`test/nsf_end/main.c`): 作り物のコマの流れで 21 項目。ぴったりのループ (2 周目の終わりでフェード、5 秒で 0)、無音 (3 秒、フェードなし)、ループなし (180 秒)、1 コマずれのループ、新しい音でだけ書くドライバ (誤検出しない)、12 秒の音型 (ループと取らない)、A A B A C の区間の繰り返し (全体の周期を取る)、記憶が取れないとき (上限は効く)。
- `rake regress:spinel`: 6 プログラム生成、失敗 0。
- ビルド: graphics-audio を linux と esp32 (WROVER) で、core のネイティブ版 (`rake native:core`) と S3・P4 (`rake regress:size`、5.4 節)。core の sim (linux) と graphics-audio の sim をつないだ通しは流していない。
- **ネイティブ版で通しで動かした** (worktree のビルド、`tools/fmrb_native.rb` を写して worktree を指す形、headless): `/home/nsf_player.toml` に置いたフォルダが開く → 手持ちの NSF の 1 曲目を鳴らす → 12.3 秒で `NSF ended: silence` → アプリが 2 曲目へ → 64.1 秒で `NSF ended: loop after 3846 frames (loop 1772 frames)` → 3 曲目へ。演奏中に別のファイルを選んで Enter で、`stop` の後に新しいファイルの `play` (画面も `>` と Stop が移る)。そのファイルが無音で終わると、フォルダを回って最初のファイルの 1 曲目へ。音の出力 (`audio`) にも音が出ている。

### 5.4 RAM と CPU

- WROVER (変更前のコミットと同じ設定で比べた): IRAM +0、DRAM の .bss +8 B (MAIN の振れ幅と再生の数)、flash のコード +1.9 KB。PSRAM は曲を読み込んでいる間 44 KB。
- core: 新しい static は `FMRB_EXT_RAM_BSS_ATTR` (MAIN の振れ幅、再生の数)。`rake regress:size` (NARYAv3・TAB5) は ok: 内蔵 RAM はどの種類も増えていない (基準 4e7e7e61 に対して DIRAM NARYAv3 -48、TAB5 -360、IRAM・その他 +0。差には基準以後のほかのコミットの分も入る)。
- CPU (ホストで、毎コマの `nsf_player_end_frame`): 平均 30-50 ns、最大 10-70 µs (候補を見つけたときのさかのぼり。最大で輪の長さ分の比較)。WROVER ではホストの 30-50 倍と見て、平均 2 µs 前後、さかのぼりの 1 回が数 ms。実機の数は実機をつないだときに測る。

## 6. 親が決めること・確かめること

- **フォルダの選び方**: 既存の画面はファイルしか選べないので「フォルダの中のファイルを 1 つ選ぶとそのフォルダ」にした。フォルダそのものを選ぶ形 (デスクトップの画面に folder の mode を足す、Spinel のデスクトップに触る) にするかは決めていない。
- **繰り返しの範囲の端**: File・Folder とも最後の次は最初へ戻る (止まらない) にした。止まるほうがよければ 1 行の直し。
- **フォルダの次のファイルは 1 番目のトラックから** (ヘッダの開始トラックではなく)。
- 既定値 (3 章)、とくに無音 3 秒・上限 180 秒・外れの点 8 は使ってから。
- graphics-audio の版 (FMRB_GA_VERSION / link) は上げていない。古い graphics-audio とでも壊れない (答えが無く、今までどおり鳴り続ける) が、リリースで揃えるかは親が決める。
- 検収: sim (Retro・Modern) で graphics-audio 経由の 0x11 の往復、`fmrb_audio_probe` でフェードと止まったことの数値、実機 (Retro の WROVER の CPU の増分・Tab5)、耳でのフェードと切り替え。ブラウザ版はまだ動かしていない。
