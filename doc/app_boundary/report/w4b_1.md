## 1. checkpoint への影響 (コードを読んだ結果)

### 1.1 端末の間でアプリを運ぶときの照合の仕組み

| 何を | どう照合するか | 合わないとき |
|---|---|---|
| 起動直後からある C の関数・クラス・mrblib の Proc | 名前 (`F:FmrbGfx#fill_rect`・`M:FmrbGfx#draw_text` など、`checkpoint_perm.c`)。プログラムのヒープがその物を指すときだけイメージに入る | 名前が読み手に無ければ理由つきで断る |
| mrblib のメソッドを実行中のフレーム | その irep の中身のハッシュ。読み手に同じ中身があればそれを使い、無ければ運んだ中身 (`GK_PERM_BODY`/`GR_PERM_CARRIED`) をそのまま動かす | 運んだ古い中身がそのまま動く |
| プログラムのコードが呼ぶメソッド名 | `SND0` (プログラムの irep の `OP_SEND` 系の名前のうち、書き手の基準のどれかのクラスにあるもの)。受け手の基準のどのクラスにも無い名前を数える | 断らない。ログと復元の返事の `missing` に出すだけ。断るのは `.app.toml` の `requires` に書いた名前だけ |
| 表の決まり | `TBL0` の版 (`MRB_CHECKPOINT_TABLE_VERSION`) | 違えば断る。ファームの版の照合は無い (名前で 1 つずつ結ぶ) |
| FmrbGfx の C のデータ | 埋め込み側の記録 (gfx.c の `gfx_ckpt_dump`、版 1: 役割と、追加の canvas の作り方) | 版が違えば「何にも描かない FmrbGfx」になる |

### 1.2 W4a の前後の版の間

- W4a で FmrbGfx から消えた C のメソッドは `_` で始まる内部用の 18 個 (`_draw_text`・`_draw_text_hybrid`・`_set_font`・
  `_set_text_size`・`_draw_image`・`_draw_tile`・`_draw_image_masked`・`_create_image_from_file`・`_create_mask`・
  `_delete_image`・`_delete_mask`・`_file_status`・`_get_pixel`・`_set_canvas_viewport`・`_set_composite_regions`・
  `_set_sprite_clip`・`_sync_file`・`_transfer_file`)。増えたのは `*_raw` の 10 個と、mrblib の素通しの包みが C に
  なった 10 個 (名前は同じ)。**公開の名前の集合は前後で同じ** (W4b-1 の後も同じ。`canvas_id` は mrblib の
  `attr_reader` から C のメソッドになっただけ)。
- アプリのコード (flash/・main/・lib/) で、消えた `_` の名前を呼ぶものは無い (`_sync_file` は FmrbApp の別のメソッド)。
  よって `SND0` の `missing` は空で、復元は通る。
- アプリの主の Task が止まるのは `_spin` から `main_loop` に戻った所 (fmrb_app_checkpoint.c の 3)。`fmrb-app.rb` は
  W4a・W4b-1 で変わっていないので、そのフレームは読み手の mrblib に結ばれる。
- **気づかれずに壊れうる経路が 1 つある**: アプリが自分で作った Task が、止めた瞬間に FmrbGfx の mrblib の包み
  (`draw_text` など) の中にいた場合、そのフレームは書き手の版の中身ごと運ばれる。古い版→新しい版なら運んだ
  `draw_text` が `_draw_text` を、新しい版→古い版なら `draw_text_raw` を呼び、復元の後でその Task が NoMethodError で
  落ちる。`SND0` は起動直後からある irep (運んだ mrblib の中身を含む) の呼び出しを数えないので、`missing` にも出ない。
  黙ってデータを壊すのではなく例外になるが、事前には分からない。今の movable のアプリ (11 本) で Task を持つ
  `ckpt_window`・`ckpt_full` の Task は描かない (ログと `sleep_ms` だけ) ので当たらない。
  直すなら mruby-checkpoint の側で、`SND0` に「運んだ mrblib のフレームの irep」の呼び出しも入れる (書き手の手元で
  分かる)。gem は固定した外の checkout (`rake checkpoint:setup`) で、この段の範囲 (worktree の fmruby-core) の外なので
  入れていない。仕様は変わらない直しだが、別のリポジトリの変更になるので親の判断に回す。
- 表 (`rake checkpoint:table`・ビルドごとの表) はビルドのたびに作り直されるので、同じ版の端末の間は名前が揃う。

## 3. FmrbGfx の状態を境界の下へ (決定 17)

### 3.1 形: 描き手 (drawer)

- `components/fmrb_common/include/fmrb_gfx_drawer.h`: どのエンジンの FmrbGfx も、C ではアプリの「描き手」1 つ。持つのは
  canvas・原点・区画の大きさ・スプライトの画像へ描いているか (12 バイト)。アプリの文脈
  (`fmrb_app_task_context_t.gfx_drawers[8]`、esp32 では PSRAM の `g_ctx_pool`) に 8 個。番号はアプリの中の 0〜7 で、
  ほかのアプリの番号は自分の表では意味を持たない。アプリの終わりに文脈ごと消える。
- **境界の FmrbGfx の関数の受け手の番号 = 描き手の番号**。平らな関数が原点を足す (スプライトの画像へ描いている間は
  足さない)。W4a の仮の形 (`fmrb_boundary_recv.h`、mruby・Lua が呼び出しのたびに原点を文脈に置く) は消した。
- 開く・閉じる・区画を決めるのは本体の内部の関数 (`fmrb_gfx_drawer_open`・`_close`・`_set_origin`・`_set_canvas`・
  `_set_to_image`・`_get`)。境界には載せない (sig では `_set_origin` が内部のまま)。
- 境界に載せた (印を外した): `canvas_id`・`origin_x`・`origin_y`・`area_width`・`area_height` (整数を返す)。
  全言語で状態を境界の関数で読める。ABI のハッシュは関数が 5 つ増えて `b2e857c4` になった。
- **sprite に描いている間の `set_sprite_clip` の原点 (決めた)**: スプライトの座標は、描く先がスプライトの画像でも
  いつも原点から (SpriteInstance#move と同じ座標)。`set_sprite_clip` も原点を足す。W4a の前の mruby・Spinel・記録係と
  同じで、W4a の mruby だけ足していなかったのが戻る。あわせて mruby の `SpriteInstance` の作成と `move` も、画像へ
  描いている間に原点を足すようにした (前は足していなかった。Spinel・記録係は前から足していた。画像へ描いている
  最中にスプライトを置く場面は見当たらない)。sig の説明に書いた。

### 3.2 状態の置き場 (前と後)

| 状態 | mruby (前 → 後) | Spinel (前 → 後) | Lua (前 → 後) | MicroPython (前 → 後) |
|---|---|---|---|---|
| canvas | C の構造体 + `@canvas_id` → **描き手** | `@canvas_id` → **描き手** | C の userdata → **描き手** | 属性 `canvas_id` → **描き手** (読むのは property) |
| 原点 | C の構造体 (呼ぶたびに文脈へ写す) → **描き手** | `@ox`・`@oy`・`@dx`・`@dy` (包みが足す) → **描き手** (C が足す) | C の userdata (呼ぶたびに写す) → **描き手** | 属性 `dx`・`dy`・`origin_*` (C のフックが読む) → **描き手** |
| 区画の大きさ | C の構造体 → **描き手** | `@aw`・`@ah` → **描き手** | 殻の layout (FmrbApp の関数) → 同じ + **描き手** | 属性 → **描き手** |
| 画像へ描いているか | C の構造体 → **描き手** | `@to_image` → **描き手** | (なし) | 属性 `to_image` → **描き手** |
| canvas 全体の大きさ | ivar (`@canvas_width`) → 同じ | ivar → 同じ | (なし) | 属性 → 同じ |
| 今のフォント・文字の倍率 | ivar (`@current_font`・`@asked_font`・`@current_text_size`) → 同じ | ivar → 同じ | (なし) | 属性 `current_font` → 同じ |
| エンジンのオブジェクトが持つもの | (C) 描き手の番号・持ち主の文脈・checkpoint の役割 | `@d` (描き手の番号) | 描き手の番号 | `_drawer` (描き手の番号) |

- 包みが足し算を持たない形になった: Spinel の `+ @dx`・`+ @ox` と MicroPython の `x + gfx.origin_x` は全部消えた。
  境界に載っていないスプライトと動画の関数 (Spinel の shim、MicroPython の `_fmrb.gfx_*sprite*`) も描き手の番号を
  受け取り、C が原点を足す形にした (次のまとまり「画像とスプライト」でそのまま境界に載せられる)。
- mruby の gem のつなぎ以外で `mrb_gfx_data` の並びを写していた `gfx_block.c` も直した (先頭の `ctx`・描き手の番号)。
- **フォントと文字の倍率は、この段では包みに残した** (次の段「文字」の仕事)。移すには次の 2 つを先に決める必要がある:
  - Spinel と mruby の `set_font` が違う。mruby は機種の持つ字へ置き換えて `[family, size]` を返し、`current_font` は
    置き換えた後のもの。Spinel は `self` を返し、大きさを省くと `current_font` が `[:ja]` (大きさなし) になって
    `text_width` が既定の字の幅で測り、`:ja_bold` を選ばない (FONT_METRICS に太字と 16 が無い)。C に移して揃えると
    Spinel の動き (返り値・測った幅) が変わる = 仕様の選択なので、ユーザが決める (止まる条件)。
  - mruby の checkpoint は今 ivar でフォントを運ぶ (`_checkpoint_font` が `@asked_font` から選び直す)。C に移すなら、
    `gfx_ckpt_dump` の版 1 のまま 10 バイト目の後ろに足す形にすれば古い読み手は無視できる (役割が追加の canvas
    以外のときは 2 バイト目以降を読まない、追加の canvas は 10 バイトまでしか読まない)。古いイメージは ivar から読む。
- canvas 全体の大きさ (`canvas_width`・`canvas_height`) は、境界の下で使わず、mruby の checkpoint の記録と古い版の
  復元が ivar を読むので、エンジンのオブジェクトに残した。

### 3.3 言語ごとに見える変化

- Ruby (mruby・Spinel): 書き方は変わらない。mruby の `origin_x` などは、`destroy` の後や復元で結び直せなかった
  FmrbGfx では 0 を返していたのが例外になる (描くメソッドと同じ扱い)。
- Lua: `gfx:canvas_id()`・`origin_x()`・`origin_y()`・`area_width()`・`area_height()` が増えた (README に書いた)。
- MicroPython: `canvas_id`・`origin_x`・`origin_y`・`area_width`・`area_height` は読み取り専用の property になった
  (読み方は同じ。書くアプリは無い)。`dx`・`dy`・`to_image` の属性は無くなった。`_fmrb` のスプライトの関数は
  FmrbGfx (か描き手の番号) を受け取る。`_fmrb.gfx_drawer_open`・`gfx_set_origin` を足し、`rake micropython:gen` で
  qstr の表を作り直した (8 増え 3 減った)。`doc/micropython/known_limitations.md` を直した。
- wasm (SDK): 関数が 5 つ増え、受け手の番号の説明を「描き手」に直した。殻がアプリに描き手の番号を渡すのは W1b。
- 描き手の上限 8 は今のアプリの最大 (gfx・window_gfx・壁紙・追加の canvas 2) の 5 に余裕を見た仮の値。9 個目は
  mruby・MicroPython では例外、Spinel では番号が -1 で何も描かない。上限を設けること自体が利用者から見た変化なので、
  値を含めて親とユーザに確認してほしい (今のアプリは当たらない)。

## 4. 計測 (mruby、最初のまとまりだけ)

### 4.1 測り方

- doc/reference/vm_speed_measurement.md の命令数 (valgrind callgrind、docker の `ghost-valgrind`、Ubuntu 22.04)。
- 本体の mruby (picoruby-mruby の手を入れた `vm.c`、picoruby の `mruby-compiler`) をホスト向けに `MRB_INT64`・
  `MRB_NO_BOXING`・`MRB_UTF8_STRING`・`-O2` で作り、FmrbGfx の C の側を生成したつなぎと同じ `mrb_get_args` の書式・
  受け手のフック・何もしない平らな関数にした gem で差し替えた。包みは今の `fmrb-gfx.rb` と W4a の前のものを写した。
  1 回あたり = (n = 20,000 の命令数 − n = 0 の命令数) / 20,000。空のループ 1 周が 135。
- Hash の数は GC を止めて `ObjectSpace.count_objects` を 1,000 回の前後で比べた。
- 道具は scratchpad に置いた (コミットしていない)。本体のビルドの `MRB_USE_DEBUG_HOOK`・`MRB_VM_SAFEPOINT_HOOK`・
  時分割は入れていないので、命令ごとの検査の分だけ本物より少ない。比べる相手どうしは同じ条件。

### 4.2 結果 (1 回の呼び出し、空のループ込み)

| 呼び方 | 命令数 | Hash / 回 |
|---|---|---|
| `fill_rect(x, y, w, h, c)` (包みなし、境界の関数そのもの) | 996 | 0 |
| `draw_text(x, y, s, c)` (今の包み → `draw_text_raw`) | 2,212 | **1** |
| `draw_text(x, y, s, c, bg)` | 2,197 | 1 |
| `draw_text(x, y, s, c, mixed: true)` | 3,034 | 1 |
| `draw_text_mixed(x, y, s, c)` (キーワードなしの包み) | 1,673 | 0 |
| `draw_text_raw(x, y, s, c, -1, false)` (境界の関数を直接) | **1,088** | 0 |
| W4a の前の `draw_text(x, y, s, c)` (→ `_draw_text`) | 2,186 | 1 |
| W4a の前の `draw_text(..., mixed: true)` | 3,020 | 1 |
| `present` (W4a からの包み → `present_raw`) | 1,326 | 0 |
| `present_raw(0, 0, false)` (境界の関数を直接) | 774 | 0 |
| W4a の前の `present` (C のメソッドそのもの、`\|ii`) | **620** | 0 |

- **境界の関数を直接呼ぶと**: `draw_text` は 2,212 → 1,088 (−51%) で、1 回ごとの Hash が無くなる。キーワード引数を
  持つメソッドは、キーワードを渡さなくても呼ぶたびに Hash を 1 つ作る (`draw_text(x, y, s, c)` でも 1)。
  `draw_text_mixed` (キーワードなしの包み) は 1,673 で Hash なし。
- **包みを通した `draw_text` は W4a の前と同じ** (2,186 → 2,212、+1%)。
- **`present` は W4a で 620 → 1,326 (+706、2.1 倍) に増えた**。1 フレームに 1 回なので絶対量は小さいが、計画の受け入れ
  条件「包みを通した呼び出しの mruby の命令数が今より増えていない」に当たる。直し方の案: (A) mruby だけ `present` を
  C のメソッド (省略できる引数を C で受ける、`present_raw` を呼ぶ) に戻す。Ruby から見た形は同じで、620 前後に戻る
  見込み。包みを mrblib に書く決まりからは外れる。(B) Ruby の包みのまま。この段では入れていない (親とユーザの判断)。
- デスクトップと標準アプリの `draw_text` を `draw_text_raw` に置き換えると、1 回あたり約 1,100 命令と Hash 1 つが
  減る。標準構成でデスクトップは mruby、エディタとカーネルは Spinel (Spinel の包みは Hash を作らず、段の差は
  C の関数呼び出し 1 つ)。

## 8. 取り込みの後に親が流すもの (sim・重い回帰)

原点の足し方がすべてのエンジンで変わった (C で足す) ので、画面の位置を見る所が中心。

| 対象 | 見る所 |

| `rake regress:screens` | 全部 (Retro・Modern・web・native)。エディタの 1 打鍵 (Spinel の標準の経路) を含む |

| mruby (sim) | デスクトップ (文字・時計・空きメモリ)、枠のあるアプリ (`pub_demo` のボタン = 原点 (1, タイトルの高さ))、枠 (window_gfx)、`rpg_demo` (`present(x, y)`・タイル)、`picoruby.app.rb` (スプライトの置き場所と `set_target` で画像へ描く `@badge`)、`walk_scroller` (追加の canvas と viewport) |
