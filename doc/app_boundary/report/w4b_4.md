- SDK (family-mruby-sdk) を作り直し、手元にコミットした (c265586)。TinyGo・Rust・Zig・C に新しい関数が生成で入った。

### 1.4 小さな違い (書き方は同じ)

- **動画の関数は受け手を取らないクラスの関数にした** (`FmrbGfx.video_control`)。再生機は 1 つで、`video_play.app.rb` の
  `on_destroy` が `@video.stop` を呼ぶ時には FmrbGfx はもう `destroy` されている (FmrbApp#destroy は `on_destroy` の前に
  `@gfx.destroy` する)。受け手を取ると mruby で例外になるため。
- **`SpriteImage#destroy`・`SpriteInstance#destroy` は RuntimeError を拾う**。shooter・flappy・デスクトップが `on_destroy`
  (FmrbGfx の destroy の後) でスプライトを消すので、前の「何もしない」を保つ。描画側の資源はアプリの canvas と一緒に消える。
- Spinel の `video_open` がネイティブ版・ブラウザ版でも動くようになった (前は P4 だけ。mruby に揃えた。sim と Retro は
  前と同じく nil)。Spinel に `export_frame` が入った。
- mruby: 壊した FmrbGfx への `move` など (`destroy` 以外) は、前は黙って何もしなかったのが例外になる (描くメソッドと同じ扱い。
  使っている所は無い)。パスが 120 バイト以上の `load_bmp`・`export_frame` は ArgumentError (前は切り詰め)。
- Lua・Python・wasm: 全部新しく使える (Lua は `gfx:create_sprite_image(...)` など、`gfx:video_open(path [, ...])` は前置きの
  包み。Python の `video_open` と `FmrbVideo` は prelude に足した)。Python の `FmrbGfx.delete_all_sprites` は生成になった
  (呼び方は同じ)。

## 5. 命令数 (mruby、ホスト)

W4b-3 と同じ測り方 (本体の mruby をホスト向けに `-O2`、何もしない平らな関数、callgrind の `ghost-valgrind`、1 回あたり =

- 生成したつなぎの増分は、`fmrb_gen_mrb_check` と受け手のフックが関数呼び出しのまま残っていたこと (逆アセンブルで確認)。
  直し: (1) 型紙で `if (ret < 0) fmrb_gen_mrb_check(...)` にし、check を cold に (全部の境界の関数で成功時の呼び出しが
  1 つ減る)、(2) `fmrb_mrb_recv_gfx` を inline にして例外を cold の関数へ、描き手の番号だけを見る (`ctx` と描き手は

- 残る +1 は測りの粒度の範囲と見る。Spinel は前も後も Ruby 1 段 + FFI で、測っていない。

## 7. W4b の締めと残り

- 7 つのまとまり (描画の基本図形・文字・画像とスプライト・アプリと Window・時刻とログとクリップボード・ファイル・音) が全部

  - MicroPython を殻に寄せるか、Ruby の基底の枠の描画を C へ差し替えるか。
- **取り込みの後に親が流すもの** (この段で流せなかったもの): `rake regress:screens` (sim の Retro・Modern。スプライトの
  デスクトップのアイコン・shooter などは描画の記録では通っている)、`rake regress:run` (VM プール: mruby の gem の FmrbGfx の
  メソッドの表は、`_` の 14 個が消えて公開の 14 個になったので数は同じ、`fmrb-sprite.rb` の rescue と `fmrb-gfx.rb` の
  `export_frame` の削除で mrblib は少し変わった)、`rake regress:checkpoint` (FmrbGfx の C のメソッドの名前が変わった。
  `SpriteInstance#move` などの mrblib の中で止まったフレームは版が違えば断られる (W4b-1b の決まり)。アプリが `_` の名前を
