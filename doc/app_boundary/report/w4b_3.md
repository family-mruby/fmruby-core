## 0. W4b-2 の後の決定を入れた

- **FmrbAudio は受け手の番号を取る形**に戻した (`NO_RECEIVER` は FmrbApp だけ)。本体 (`fmrb_boundary_audio.c`) は
  `int32_t audio` を受けて読まない。各エンジンは 0 を渡す (mruby `fmrb_mrb_recv_audio`、Lua `fmrb_lua_recv_audio`
  (FmrbAudio.new() の表か確かめるだけ)、MicroPython `fmrb_mp_recv_audio`、Spinel の基底は直に 0)。Lua の
  `audio:note_off(0)` などの書き方は同じ。
- FmrbApp にクラスの印を付け、道具の `STAGED` を消した。
- ABI のハッシュ: W4b-2 の `d34fea71` → この段の終わりで **`b7957f81`** (関数 122・記録 7 + フックの記録 1・フック 8)。
  `ruby tools/wamr_poc/run.rb boundary` の巡回の呼び出しは 23 → 33。

### 1.2 殻と基底クラスの重なり (report/w3.md 1.5 の一覧) をこの段でどこまで寄せたか

| 仕事 | この段 | 理由 |
|---|---|---|
| 区画の計算・Window の大きさ | **Lua・wasm は殻の値を境界の関数で読む** (`fmrb_app_shell_layout` を足し、Lua の手書きの registry の写しを消した)。Ruby・Python は基底のまま | Ruby の基底の ivar は checkpoint で運ばれ、Spinel の ivar の並びにも響く (doc/spinel_aot/reports/editor_ivar_layout_bug.md) |
| 枠の絵・枠のイベント・`_handle_system_control`・HID の解読・終わり | **寄せていない** (4 か所のまま) | 書き方は変わらないが、Ruby の main_loop を C に移すと checkpoint (Task のフレームを運ぶ) と Spinel の生成を作り直すことになり、段の大きさに合わない。移すなら別の段で、Ruby の基底の枠の描画を殻の C へ差し替えるかを先に決める (plan の未確定事項のまま) |
| カーネルへの頼み (メニュー・再読込・全画面・ファイル選択・起動) | **C に寄せた** (mruby・Spinel・Python・Lua・wasm が同じ C を呼ぶ)。Window のメニューの `movable` も C が決める | どの言語でも Hash を作らずに済み、mruby の命令数が減る (5 章) |

### 1.3 アプリの書き方が変わる所

**無かった** (止まらずに進めた)。Ruby (mruby・Spinel) のアプリは名前・引数・既定値が同じ。他の言語は足しただけ。
決めて入れた細部 (親が戻せる):

- **問いのメソッドの名前**: C と Lua・Python では `?` を落とす (`fmrb_file_exist`、Lua `FmrbApp.fullscreen()`、
  `FmrbFile.exist(path)`)。前例は Python の `ev_ctrl`。落とした名前がぶつかると道具が止まる。
- **Lua の FmrbApp のインスタンスメソッド**は `FmrbApp.` の関数 (W4a の `FmrbApp.user_area_width()` の形)。
- **Window の状態の読み手と `stop` など**: mruby は生成した C を登録し、gem の mrblib (後に読まれる) が同じ名前を
  Ruby で定義し直す。Ruby の基底は自分の ivar で答える (同じ名前の上書きなので、メソッドの表は大きくならない)。
- 戻り値の小さな違い: `request_reload` などの頼みは前は `send_message` の true/false、今は nil (sig は void。
  使っている所は無い)。`FmrbApp.language` は mruby でも実行時の設定を読む (前は VM の起動時の定数。Spinel と
  同じになった)。Spinel の `FmrbApp.crt_state` が本当の値になった (前は常に "")。

## 4. 各言語の変化

### 4.1 mruby

- gem の C (`app.c`) の手書きのクラスメソッド 16 個を消し、生成に替えた (`pid` `ps_gen` `script_path` `gfx_stats`
  `sys_pool_info` `battery_level` `battery_charging?` `linux_available?` `notify` (→ `notify_raw`) `crt_state`
  `set_text_cursor` `audio_muted?` `path_read_only?`・`free_bytes` (→ FmrbFile) `audio_volume` `wifi_connected?`)。
- mrblib: `request_reload`・`request_close_confirm`・`request_window_menu`・`_window_movable?`・`request_fullscreen` を
  消した (C)。`request_file_select`・`request_run`・`FmrbApp.notify`・`path_read_only?`・`free_bytes` は包み、
  `clear_user_area_raw` を足した。`FmrbApp.language` の Ruby の定義を消した (C)。`fmrb-file.rb` (新設) に `FmrbFile.list`。
- 書き方は変わらない。

### 4.2 Spinel

- 基底のクラスメソッドを生成の FFI に替え、手書きの FFI 15 個 (`fmrb_spx_app_pid` など、`fmrb_spx_app.c`・`.h`・
  `fmrb_app_ffi.rb`) を消した。頼みごとは生成の FFI を呼ぶ (Hash と MessagePack を作らない)。
- `FmrbFile` モジュールを基底に書いた。`read`・`list_raw` は 256 バイトを超えるので、クリップボードと同じく
  手書きの分割読み (`fmrb_spx_file_length`・`fmrb_spx_file_chunk`) で読む。
- 書き方は変わらない。

### 4.3 Lua

- `FmrbApp` の表の手書き (`user_area_width` など 4 つ・`stop`・`clear_user_area`・`draw_window_frame`) を生成に替えた。
  名前と呼び方は同じ (`clear_user_area([color])` は前置きの包み)。`FmrbApp.sleep(ms)` と定数 (`THEME_*`・`HEADLESS`) は
  手書きのまま (sig に無い)。区画の registry の写しを消し、殻の値を読む。
- 増えたもの: Window の状態・頼みごと・機械の様子 (1.1 の (a))、`FmrbFile` (`FmrbFile.list(dir)` は前置きの包み)。
  README (`components/lua/extension/README.md`) に書いた。

### 4.4 MicroPython

- 生成した `_FmrbAppBoundary`・`_FmrbFileBoundary` を継ぐ。prelude の頼みごと (`request_reload`・`request_fullscreen`)
  を消し、`request_run`・`request_file_select` は `_raw` の包み、`clear_user_area_raw`・`FmrbApp.notify` を足した。
  Python の FmrbApp の属性 (`self.window_width` など) は生成したメソッドより先に引かれる (前のまま)。
- **ファイル**: `_fmrb.read_file`・`file_size` を消し、`FmrbFile` に置き換えた (`FmrbFile.read(path)` は bytes か
  None)。`flash/app/python/python.app.py` の 1 か所を直した。`_fmrb.language` も生成の `_fmrb.app_language` に替えた
  (`language()` は前のまま)。
- **時計と長い整数**: `FmrbApp.uptime_ms()` を足し (境界、全言語)、`MICROPY_LONGINT_IMPL_LONGLONG` で 64 ビットの
  整数を有効にした (MPZ でなく LONGLONG: 境界の一番広い整数は 64 ビットで、小さい方)。sim で
  `uptime_us()`・`2**40 + 1` が正しく出た。ファームの増分は 7 章。
- qstr の表を作り直した (`rake micropython:gen`)。`doc/micropython/known_limitations.md` を直した。

### 4.5 wasm (C の SDK)

`sdk/c/fmrb_boundary.h`: 関数 +54、記録 +2、`FMRB_BOUNDARY_NONE`、結果の選択肢の定数、問いの名前の規則、終わりに
アプリが公開する関数 (フック 8) と `fmrb_app_event_t` (60 バイト) と `FMRB_APP_EVENT_TYPE_*`。

## 5. 命令数 (mruby、ホスト)

W4b-2 と同じ測り方 (本体の mruby をホスト向けに `-O2`、何もしない平らな関数、callgrind、`ghost-valgrind`、

| `FmrbApp.battery_level` (nil を返す) | 392 | 396 |

- **毎フレーム・毎イベントの道 (メッセージ待ち `_spin`・タイマー `_run_timers`・イベントの Hash と座標・main_loop) は
  この段で変えていない** (mruby の C と mrblib の該当部分に差分なし)。前後同じ。

  今は戻さなくてよいと考える。戻すなら `notify` を mruby だけ C の包み (`present` と同じ例外) に。親が決める。

## 6. FmrbFile

- `sig/fmrb_file.rbs` (新設): `read(path) -> bin?`・`write(path, data) -> bool`・`append`・`exist?`・`size -> int64?`・
  `delete` (ファイルか空のディレクトリ)・`mkdir` (あれば true)・`list(dir)` (包み、`Array[String]?`、ディレクトリは
  後ろに "/") と `list_raw(dir) -> String?` (名前を "\n" でつなぐ)・`path_read_only?`・`free_bytes -> int64?`。
- **`free_bytes` の「分からない」は nil** (C は `FMRB_BOUNDARY_NONE`)。nil の規則 (2 章) を足したので、負はエラーの
  規則と食い違わない。`read`・`size` の「無い」も同じ。
- パスで呼び、状態を持たない。読みは「呼ぶ側のバッファ、全体の長さ」の規則で、足りなければつなぎがファイルを
  頭から読み直す (同じ答えになる)。HAL を通るので読み書きできる場所は Ruby の File と同じ。Ruby の `File` は変えていない。
- 気付いたこと: `/tmp` (RAM のファイルシステム) では `mkdir` が false (下の HAL が作れない。Ruby の `Dir.mkdir` も同じ
  道)。`/home` では作れて消せる。

## 8. W4b の締めと wasm_apps の W1b への注意

### 8.1 VM プールの増分 (止まる条件に当たる 1 つ。親の判断が要る)

`rake regress:run` の増分を実験で分けた (Modern、`ONLY=modern` で 2 回ずつ):

| 実験 | アプリの VM (Kamon など) | Modern のデスクトップ |
|---|---|---|
| この段のまま | +632〜+720 | +1,920〜+1,952 |
| mruby の FmrbFile の登録と `fmrb-file.rb` を外す | 幅の中 (±0) | +1,568〜+1,584 (2 回とも同じ) |
| さらに mrblib (`fmrb-app.rb`) を W4b-2 の版に戻す | 幅の中 | +1,480 |

- **アプリの VM の +650 B 前後は FmrbFile** (モジュールとその特異クラス、11 個のメソッドの表、`FmrbFile.list` の
  irep)。どの mruby の VM にも乗る。説明できる大きさで、Services の +616 も同じもの。
- **Modern のデスクトップの残り +1.2〜1.5 KB は理由を突き止められていない**。Retro のデスクトップは FmrbFile の分
  (+744) だけで、同じ台本・同じ mrblib で Modern だけ多い。mrblib の変更ではない (戻しても +1,480)。gem の C の
  生成した登録 (FmrbApp の 49 個。うち Ruby が上書きするものは表の同じ場所) か、Modern の構成 (Wi-Fi のある端末) で
  デスクトップが通る道のどれかと考えるが、どれかは分けていない。決まった値 (2 回とも同じ) なので揺れではない。
- 基準は更新していない。受け入れるか、もう 1 段分けるか (gem の C の FmrbApp の登録を W4b-2 の 5 個に絞る実験。
  1 回 5 分ほど) は親が決める。

### 8.2 W4b の締め

W4b の 7 つのまとまりのうち、描画の基本図形・文字 (W4a・W4b-1)・時刻とログとクリップボード・音 (W4b-2)・アプリと

(W4b-1 で描き手の番号を受ける形にはしてあり、手書きのまま)。ライブラリと基底クラスの呼び出しを境界の関数へ

### 8.3 wasm_apps の W1b への注意

- C のヘッダ (`sdk/c/fmrb_boundary.h`、ABI のハッシュ `b7957f81`) の終わりに、アプリが公開する関数の形がある:
  `on_create` `on_update` (`int32_t`: 次までの ms、負で既定 330) `on_event(const fmrb_app_event_t *ev)` `on_destroy`
  `on_suspend` `on_resume` `on_resize(int32_t, int32_t)` `on_quit_request`。`FMRB_EXPORT(name)` は wasm では
  `export_name`。
- `fmrb_app_event_t` は 60 バイトの詰めた記録で、`type` は選択肢の番号 (`FMRB_APP_EVENT_TYPE_KEY_DOWN` = 0 …
  `KANA_MODE` = 9)。**殻の `fmrb_shell_event_t.kind` は HID のイベントの番号** (`FMRB_HID_EVENT_*`) なので、wasm の
  エンジンのつなぎ (殻の `call_event`) で番号を読み替え、アプリのメモリに記録を置いて渡す。並びは Lua のつなぎの
  `e_call_event` と同じ鍵。
- FmrbApp の関数は受け手の番号なし。Window の状態・`stop`・`draw_window_frame`・`clear_user_area_raw` の本体は
  殻の上で動く (`ctx->shell` が要る。殻の外では失敗を返す)。wasm のアプリは殻の上なのでそのまま使える。
- FmrbAudio の関数は受け手の番号を取る (今は 0 を渡せばよい)。
- nil があり得る結果は `FMRB_BOUNDARY_NONE` (-3) (`FmrbFile.read`・`size`・`free_bytes`、`FmrbApp.battery_level`)。
- 生成の WAMR のつなぎ (`fmrb_boundary_wasm.inc`) は 122 関数に増えた。登録の表が増える分は W1b で測る。

### 8.4 殻 (main/app/fmrb_app_shell.c) の変更

  `ax`・`ay`・`aw`・`ah`・`fullscreen` を写すだけ)。
- フックの名前・番号 (`fmrb_shell_hook_t`)・`fmrb_shell_engine_t`・`fmrb_app_shell_run` と既存の関数は変えていない。
