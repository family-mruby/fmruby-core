### 1.3 殻の置き場

- **`main/app/fmrb_app_shell.c` / `.h`** (新設)。殻はエンジンを知らない C で、`fmrb_app.c` の
  `execute_lua_script` が「Lua のつなぎ」を渡して呼ぶ。後で wasm (W1b の後) と、寄せるなら
  MicroPython も同じ口で乗る。
- **Lua のつなぎ** (フックの関数を `lua_pcall` で呼ぶ・イベントを Lua の表にする・原点を描き手に
  伝える) は `components/lua/` に置く (`fmrb_lua_shell.c`)。Lua の部品は殻のヘッダを読まず、
  整数とポインタだけの関数を出し、`fmrb_app.c` が殻の関数表 (下) に詰める。部品が main に
  依存しない今の向きを保つため。
- 殻が使う下の関数は今あるものだけ: `fmrb_app_canvas_init`・`fmrb_app_canvas_release_all`、
  `fmrb_msg_receive`・`fmrb_msg_send`・`fmrb_msg_delete_queue`、`fmrb_hid_event_decode`、
  `fmrb_gfx_cmd_*` + `fmrb_gfx_submit` (枠の図形と present)、`fmrb_gfx` の合成の区画の命令、
  テーマ (`fmrb_theme_get`)。msgpack は送る 2 種 (`exit`・`window_menu`) を固定の並びで組み、
  受ける制御は `cmd` と数個の整数の鍵だけを読む小さな読み手を殻に置く (Ruby の VM を通さない)。

殻の関数 (案):

```c
// What the shell asks of an engine. Every call runs app code; a non-zero
// return means the app raised, and the shell ends it as an error.
typedef struct {
    int  (*call_hook)(void *ud, fmrb_shell_hook_t hook);   // create/destroy/suspend/resume/quit_request
    int  (*call_update)(void *ud, int *next_ms);           // on_update; next_ms < 0 = not defined
    int  (*call_event)(void *ud, const fmrb_shell_event_t *ev);
    int  (*call_resize)(void *ud, int w, int h);
    void (*layout)(void *ud, const fmrb_shell_layout_t *l); // origin, area and window size changed
    bool (*has_hook)(void *ud, fmrb_shell_hook_t hook);
} fmrb_shell_engine_t;

fmrb_err_t fmrb_app_shell_run(fmrb_app_task_context_t *ctx,
                              const fmrb_shell_engine_t *eng, void *ud);
// Called from an engine's binding on behalf of the app:
void fmrb_app_shell_stop(fmrb_app_task_context_t *ctx);              // FmrbApp.stop
void fmrb_app_shell_draw_frame(fmrb_app_task_context_t *ctx);        // FmrbApp.draw_window_frame
void fmrb_app_shell_clear_user_area(fmrb_app_task_context_t *ctx, int color);
```

- 殻の状態 (区画・原点・中断・閉じるボタンの押し・止まる印・合成の区画の覚え) は
  `fmrb_app_shell_run` の中の自動変数 (アプリの task のスタック) に置き、`ctx` (PSRAM の
  `g_ctx_pool`) に指す先を 1 つ足して、つなぎから届くようにする。**静的な変数は足さない**
  (内蔵 RAM の増分 0)。
- `fmrb_app_shell_run` の流れ: canvas を作る → 区画を決めて `layout` → 枠を描いて present →
  `on_create` → ループ (中断中は 500 ms 待つだけ、そうでなければ `on_update` の ms だけ待ちながら
  メッセージを配る) → 止まる印で抜ける → カーネルへ `exit` → `on_destroy` → 後片付け。
  `on_update` が無いアプリは Ruby の既定と同じく 330 ms ごとに回る。
- 枠は Ruby の GfxBlock と同じ絵を 1 命令ずつ送る (Python と同じ形)。描くのは作ったとき、
  `clear_user_area`・`draw_window_frame` を頼まれたとき、大きさが変わったとき。

### 1.4 描画の原点

- **殻が区画を決め、Lua の描き手 (`lua_gfx_data`) が原点を持って C で足す** (T4 の `mrb_gfx_data` と
  同じ考え)。殻の `layout` を受けて Lua のつなぎが描き手の `ox, oy` を入れ直す。足すのは
  `fmrb_lua_gfx.c` の各描画 (fill_rect・draw_rect・round_rect 2 つ・draw_line・fill_circle・
  draw_text) で、`clear` と `present` は足さない (Ruby と同じ: clear は canvas 全体)。
- 区画の大きさ・原点の正は殻 (C) が持つ。W4b で Spinel・Python の原点を C の側へ移すときも、
  同じ殻の値を読む形にできる (plan の決定 17 の向き)。
- イベントの `x`・`y` は殻が区画の座標にし、`wx`・`wy` に Window の座標を入れる (Ruby と同じ)。

### 1.5 Ruby の基底との重複 (今回は Ruby の側を変えない)

殻を作ると、次の仕事が mruby・Spinel・Python・殻の 4 か所 (Python は一部) に並ぶ。
`_layout_user_area` (区画の計算)、枠の絵 (タイトルバー・3 本線・タイトル・閉じる丸・縁・
角の色の鍵・合成の区画・resize の印)、`_frame_event` (閉じるボタン・タイトルバーの右クリック・
枠なしの右クリック)、`_handle_system_control` (suspend・resume・stop・clear_and_stop・
quit_request・long_press)、`resize`・`moved` の扱い、HID の解読と原点の引き算、
`destroy` (exit の知らせ・後片付け)、`stop` と `expected_stop`。
加えて、カーネルの「mruby 以外のアプリの閉じるボタンで stop を送る」特別扱い
(`input_router.rb`) は、殻が閉じるボタンを持つと重なる (両方が stop。害は無いので残す。
BASIC はこれに頼っている)。

### 1.6 Lua のアプリの書き方が変わる所 (決めてほしいこと)

殻に乗せると、今の書き方 (トップレベルのループ・自分で canvas を作る・自分で枠を描く) は
成り立たない。変わる所と選択肢 (推奨を先頭):

| # | 変わる所 | 選択肢 (推奨が 1) |
|---|---|---|
| A | **アプリの形**: トップレベルのループをやめ、関数を公開する | 1. 大域の関数 `on_create()`・`on_update()` (次までの ms を返す)・`on_event(ev)`、任意で `on_destroy`・`on_suspend`・`on_resume`・`on_resize(w, h)`・`on_quit_request`。トップレベルは最初に 1 回走る (定義を置く所。Ruby のファイルの top level と同じ) 2. スクリプトが表を返す (`return { on_create = ..., }`) 3. 大域の表 `App` にメソッドとして書く (`function App:on_update()`) |
| B | **Window と描き手**: `FmrbApp.create_canvas`・`FmrbGfx.new(id)` をやめ、殻が作った描き手を渡す | 1. 大域の `gfx` (Ruby の `@gfx` と同じ名前。`on_create` の前に入っている) を置き、`create_canvas`・`FmrbGfx.new` は消す 2. `FmrbApp.gfx` 3. `on_create(gfx)` の引数 |
| C | **座標の原点**: 描画とイベントの (0, 0) が区画 (枠の内側) の左上になる。枠つきでは前より (1, 11) ずれる | 1. Ruby と同じにする (`gfx:clear` は canvas 全体のまま=枠ごと消える。区画だけ消す `FmrbApp.clear_user_area([色])` を足し、これが枠を描き直す) 2. Lua だけ `gfx:clear` を区画だけにする |
| D | **大きさ**: 区画の大きさが要る。今の `FmrbApp.WINDOW_WIDTH/HEIGHT` は起動のときの定数で、大きさが変わると古くなる | 1. `WINDOW_WIDTH/HEIGHT` は Window の大きさとして残し殻が大きさの変化で書き直す。区画の `FmrbApp.user_area_width`・`user_area_height` を足す 2. 区画の大きさだけを出す (`WINDOW_*` を消す) |
| E | **枠**: アプリは枠を描かない。タイトルは "Lua App" の直書きから、Ruby と同じくアプリの名前 (ctx の `app_name`) になる。閉じるボタンの押しの沈み・Window のメニュー・角の透明が Ruby と同じになる | 1. 区画の隅を塗った後に枠を描き直す口 `FmrbApp.draw_window_frame()` を出す (Ruby と同じ) 2. 出さない (殻が描くときだけ) |
| F | **イベント**: `on_event(ev)` の `ev` の形 | 1. Lua の表で、鍵と値の名前は Ruby と同じ (`ev.type` は `"mouse_down"`・`"key_down"` などの文字列、`button`・`x`・`y`・`wx`・`wy`・`keycode`・`scancode`・`modifier`・`character`・`delta`・`gamepad_id`・`axis`・`value`・`mode`) 2. `ev.type` を整数の定数 (`FmrbApp.EV_MOUSE_DOWN` など) |
| G | **終わり方**: アプリから終わる口が要る。関数を 1 つも定義しないスクリプト | 1. `FmrbApp.stop()` を足す。`on_create`・`on_update`・`on_event` のどれも無いスクリプトは、T3 の「No app class」と同じくエラーの Window とログ (`No on_create, on_update or on_event in <path>`) 2. 関数が無ければ今の形 (トップレベルだけ) で殻なしに走らせる (2 つの書き方が残る) |
| H | **`FmrbApp.sleep(ms)`** | 1. 残す (コールバックの中で寝るとその間イベントが届かないことを文書に書き、待ちは `on_update` の返り値を勧める) 2. 消す |
| I | **`busy.app.lua`** (kill の試験。わざと戻らない) | 1. `on_create` の中で `while true do end` (枠は殻が描く。試験の目的は同じ) |

書き方は変わらないが、決めた中身として伝えること:

- **長く戻らないコールバックの止め方**: 今のフックは 100 命令ごとに待ち行列を全部読み捨てる。
  殻の下でこれを続けると、ふつうの `on_update` の間に届いたマウス・キーが捨てられる。
  殻に乗ったアプリでは、フックは `should_exit` の印だけを見る。加えて、1 つのコールバックが
  長く (目安 1 秒) 戻らないときだけ今と同じく読み捨てて `stop` を拾う (busy の閉じるボタンは
  カーネルが送る `stop` のメッセージだけで、`should_exit` は立たないため)。kill は今も
  `should_exit` を立てるのでそのまま効く。
- checkpoint は対象外 (Lua のアプリは movable でない。`window_menu` の `movable` は false で送る)。
- 他のアプリとのメッセージ (`on_control`・topic) とタイマー (`set_timer`) は今回出さない
  (今の Lua に無い。W4a の生成で関数として足す範囲)。
- 引数の順 (Lua の `draw_text(text, x, y, color)` と Ruby の `draw_text(x, y, text, color)`) は
  今回変えない (plan の未確定事項、W4a で差を出す)。

**推奨のまとめ**: A1・B1・C1・D1・E1・F1・G1・H1・I1。Ruby のアプリと同じ名前・同じ座標・
同じ既定 (330 ms) にそろえ、2 つめの書き方を残さない。

推奨どおりなら `lua.app.lua` はこうなる (見本):

```lua
local seconds = 0

function on_create()
  FmrbApp.clear_user_area()
  gfx:draw_text("Hello from Lua!", 2, 2, FmrbApp.THEME_TEXT)
  gfx:draw_text(_VERSION, 2, 22, FmrbGfx.RED)
  gfx:present()
end

function on_update()
  seconds = seconds + 1
  gfx:fill_rect(0, 42, FmrbApp.user_area_width, 10, FmrbApp.THEME_WINDOW_BG)
  gfx:draw_text("Running: " .. seconds .. "s", 8, 42, FmrbApp.THEME_BORDER)
  gfx:present()
  return 1000
end

function on_event(ev)
  if ev.type == "key_down" and ev.character == string.byte("q") then
    FmrbApp.stop()
  end
end
```

### 1.7 確かめ方 (決まった後)

指示のとおり: `rake regress`、sim で Lua のアプリの枠・閉じるボタン・Window のメニュー・
ドラッグ・タイマー・終了を Ruby のアプリと並べて撮る、最後に `regress:screens` と
`regress:size` を 1 回ずつ。`regress:screens` に Lua の場面は無い (足すかは決まった後に
report へ)。描画の記録 (`tools/regress/run.rb`) は Ruby だけで、Lua は通らない。

| 同上: 制御の読み手 | msgpack の地図の上の段だけを読む小さな読み手 (`cmd`・`width`・`height`・`fullscreen`・`x`・`y`)。確保なし。`resize` (区画・塗り直し・枠・`on_resize`)、`suspend`・`resume`・`stop`・`clear_and_stop`・`quit_request` (`on_quit_request` が無ければ閉じる)・`long_press`。`moved` は何もしない (present が ctx の位置を読む)。topic などほかの制御は渡さない |
| 同上: 状態 | `shell_t` をアプリの task のスタックに置き、`ctx->shell` (足したポインタ 1 つ、PSRAM の `g_ctx_pool`) から届く。静的な変数なし。slot の使い回しで NULL に戻す |
| `components/lua/fmrb_lua_shell.c` (235 行) | Lua のつなぎ。大域の関数を `lua_pcall` (トレースバックつき) で呼ぶ、`ev` を表にする (鍵は Ruby と同じ、`type` は文字列)、`on_update` の返り値 (数でなければ既定 330)、止めのフックの印 (`__fmrb_close_requested__`) を「頼まれて終わった」と読む |
| `components/lua/extension/fmrb_lua_gfx.c` | 描き手 `lua_gfx_data` に `ox, oy` を足し、描く命令 (fill_rect・draw_rect・round_rect 2 つ・draw_line・fill_circle・draw_text) で C で足す (`GX`・`GY`、mruby の `mrb_gfx_data` と同じ形)。`clear`・`present` は足さない。`fmrb_lua_gfx_layout` が大域の `gfx` を作り・原点と `FmrbApp` の大きさを書き直す。`FmrbApp.stop`・`clear_user_area`・`draw_window_frame` を足し、`create_canvas`・`FmrbGfx.new` を消した |
| `main/app/fmrb_app.c` | `execute_lua_script` は compile の後に `fmrb_lua_shell_run`。エラー (関数が無い・Lua のエラー) は Ruby の例外と同じ口 (`set_last_error` + `notify_error_to_kernel` のエラーの Window)。止めのフックは `fmrb_app_shell_unwind_now` を読む |
| ビルドの一覧 | `main/CMakeLists.txt`・`components/lua/CMakeLists.txt`・`hosted/hosted.cmake` (ネイティブ版・ブラウザ版) |

止めのフック (1.6 で決めたとおり): 殻は呼び出しの間で止まる印を読むので、ふつうの呼び出しの最中に届いた入力は
捨てない。1 秒 (`FMRB_SHELL_LONG_CALL_MS`) 以上戻らない呼び出しだけ、前と同じく待ち行列を読み捨てて stop を拾い、
`should_exit` も読んで巻き戻す。

描画の原点: 区画の正は殻 (`layout`、Ruby の `_layout_user_area` と同じ計算)、足し算は Lua の描き手の中の C。
W4b で Spinel・Python の原点を C へ移すとき、殻の値を読む形にできる。

## 5. Ruby の基底との重複・W4a への注意

- 1.5 の重複は今そのまま 4 か所 (mruby・Spinel・Python・殻) にある。とくに**枠の絵と閉じるボタンの振る舞いは
  殻と Ruby の 2 か所を同時に直す**必要がある (殻のファイルの頭に書いた)。Ruby の基底の枠を殻の C に差し替えるかは
  plan の未確定事項のまま。
- カーネルの「mruby 以外のアプリの閉じるボタンで stop」(`input_router.rb`) は、殻と重なって stop が 2 回届く
  (害なし)。busy の閉じるボタンはこれに頼っている (殻は呼び出しの最中に枠のイベントを読めないため)。
- タイトルバーの押しもアプリに届く (`y` が負)。Ruby のアプリと同じ振る舞いで、見本は `ev.y >= 0` で区画の
  押しだけを数える。
- 殻が持たないもの: `on_control` (topic・run の結果)、`set_timer`、スプライトの区画のクリップ (Lua に
  スプライトが無い)、当たりの形、checkpoint、debug の `gc` の頼み (Lua は前から答えない)。W4a で関数を
  足すときに、殻か関数かを決める。
- W4a: Lua のつなぎは生成に替える対象。殻の口 (`fmrb_shell_engine_t`) とイベントの表の形は生成の外
  (plan のとおり)。`draw_text` の引数の順の差はそのまま (W4a の課題)。
