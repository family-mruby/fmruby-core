# Asterism V2.2 指示書: 網の図の色と、台帳の見え方

> 状態: 指示 | 更新: 2026-10-11 | asterism-console の網の図で、Asterism の 3 段 (ノード・アプリ・オブジェクト) が緑の濃淡で見分けにくいのを、色 1 つ + 形の違いに改める。台帳 (Relay registry) の表示を既定でオフにし、表示するときは隅に散らばらせず意味のある置き方にする

前提: plan.md の V の表 (V2.2 の行)、report/v2_1.md、asterism-console の docs/v2.md・v2_1.md、`app/javascript/controllers/console_controller.js` (色・形・凡例)、`lib/bridge/graph.rb` (台帳を重ねる部分)、W2 の台帳のモデル。

## 1. 決まっていること (2026-10-11 ユーザ)

- 図の色は「何の仲間か」だけを表す: 青=ルータ、紫=ROS 2、橙=トピック、**青緑=Asterism**。段の違いは色ではなく形で表す。
- Asterism の段:
  - ノード (機体・CRuby・console): 青緑の実線の枠、中は白。名前の前に種類の印 (機体・CRuby・console の区別。印の形は読みやすいものを選ぶ。絵文字は使わない)。
  - アプリ: 灰色の破線の枠 (色なし)。
  - オブジェクト: 青緑の小さな丸。
- 台帳 (Relay registry) の表示は**既定でオフ** (今の切り替えの既定を変える。ブラウザに覚えさせてよい)。
- 台帳を表示するとき:
  - つながっていない登録 (今の「Registered, not here」) は、「未接続 (台帳)」の名前付きの枠 1 つにまとめる。隅に散らばらせない。
  - つながるはずのルータが台帳から分かるもの (例: 中継の相手のルータ、そのルータ用の証明書を持つ機体) は、そのルータへ破線を引く。分からないものは枠の中に置くだけでよい。何が分かって何が分からないかを report に書く。
  - 今つながっているものの台帳の状態 (登録済み / 無効 / 未登録) は、今の色の輪をやめ、枠の角の小さな印で出す。凡例に印の意味を書く。
- 凡例も合わせて直す。記録の巻き戻しの図も同じ見え方にする。

## 2. 受け入れ条件

1. sim の Asterism のデモ・P4-Nano (または sim) の ROS 2 のアプリ・CRuby のノード・ROS 2 の台車がつながった状態で、Asterism の 3 段が色の濃淡に頼らず形で見分けられる。図の中の緑系の色が青緑 1 つになる。
2. 台帳の表示は既定でオフ。オンにすると「未接続 (台帳)」の枠にまとまり、分かるものはルータへ破線が出る。つながっているものに台帳の印が出る。
3. 巻き戻しの図も同じ。
4. 既存のテストが通る。組み立てを bridge 側で足すならテストを足す。
5. 変更前と変更後の写しを scratchpad に置き、report で比べる。

## 3. 範囲・決まり

- **触ってよいもの**: asterism-console (main にコミット・push してよい)、fmruby-core の `doc/ruby_asterism/report/v2_2.md` (develop にコミットのみ、push しない)。
- **触らないもの**: gem、ファーム、`.env`。台帳の DB の中身 (試しの登録) は消さない。
- **機体**: 親が渡す P4-Nano を使ってよい (ミュート中、`serial_start` は呼ばない)。
- **終わったら**: 自分で起動したものは止める。`fmruby-core/build/` は Linux の標準構成 (x86-64)。
- **止まる条件**: ここに書いていない見え方の選択が要るとき。案を写しつきで返す。
- **report**: Japanese plain style (常体)。書くこと: 色と形の割り当て、台帳から分かるつながり先の範囲、受け入れ条件の結果、残った課題。
