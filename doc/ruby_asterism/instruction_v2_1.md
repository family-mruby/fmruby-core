# Asterism V2.1 指示書: 網の図で、接続を点ではなく線として描く

> 状態: 指示 | 更新: 2026-10-11 | asterism-console の網の図で、Zenoh の Session (1 本の接続) を点として描くのをやめ、ノードをルータへ直接線でつなぎ、線に役 (client / peer) を書く。細かい情報はノードの詳細へ移す。今の描き方は切り替えで残す

前提: plan.md の V の表 (V2.1 の行)、asterism-console の docs/v2.md (図の作り)、`lib/bridge/graph.rb` (Session の組み立て、Zenoh の ID でノードと突き合わせる部分)、`app/javascript/controllers/console_controller.js` (描き方、層の切り替え)。

## 1. 決まっていること (2026-10-11 ユーザ)

- 図を見る人が知りたいのは「誰が (ノード)」で、「どの線で (Session)」は普段は要らない。点として挟まると分かりにくい。
- 既定の描き方を変える。今の描き方は、つながらない原因を探すときのために切り替えで残す。

## 2. 作るもの

1. **既定の描き方** (新しい層の切り替え、例: 「回線を点で表示」が外れている状態):
   - Session の点を描かない。その Session に結び付いたノード (Asterism のノード、ROS 2 のノード、console 自身) を、ルータへ直接線でつなぐ。
   - 線の脇に役 (`client` / `peer`) を小さく書く。
   - peer どうしがルータを通さずにつながっているときは、ノードとノードの間に線を引く。
   - 1 本の Session に複数のノードが乗る場合 (ROS 2 の 1 つのプロセスに複数のノード、など) は、それぞれのノードからルータへ線を引くか、まとめ方を決めて docs に書く。読みやすい方を選び、画面の写しで比べて決める。
   - どのノードにも結び付かない Session は、ルータのそばの「その他の接続 N 本」1 つにまとめる。クリックで中身 (役・ID・アドレス) の一覧を出す。
2. **ノードの詳細**: 結び付いた Session の Zenoh の ID、役、アドレス、通信の種類 (tcp など)、つながっているルータを出す。
3. **今の描き方**: 切り替え (「回線を点で表示」など) を入れると、今と同じに Session を点で描く。既存の「Routers and sessions」の切り替えとの関係を整理する (例: 「ルータ」と「回線を点で表示」に分ける)。切り替えの状態はブラウザに覚えさせてよい。
4. **記録の巻き戻し** (`recordings/structure`) の図も同じ描き方にする。
5. **docs**: console の docs に v2_1.md を足し、既定の描き方・切り替え・凡例を書く。凡例の文言も合わせて直す。

## 3. 受け入れ条件

1. sim (Linux) の機体・CRuby のノード・console を網につないだ状態で、既定の図に Session の点が出ず、各ノードがルータへ線でつながり、線に役が出る。ROS 2 の台車 (S1 の compose) を上げた状態でも同じ。
2. ノードの詳細に Session の情報が出る。
3. 切り替えで今の描き方に戻せる。巻き戻しの図も同じ。
4. 「その他の接続」が 1 つにまとまり、中身が見られる。
5. 既存のテストが通り、描き方の組み立て (bridge 側で作るなら) にテストを足す。
6. 変更前と変更後の図の写しを scratchpad に置く (report に比べた結果を書く)。

## 4. 範囲・決まり

- **触ってよいもの**: asterism-console (main にコミット・push してよい)、fmruby-core の `doc/ruby_asterism/report/v2_1.md` (コミットのみ、push しない)。
- **触らないもの**: asterism と asterism-zenoh の gem、fmruby-core のファーム、`.env`。
- **機体**: 要らない (sim と CRuby で足りる)。P4-Nano を使うなら、親が IP を渡す。
- **終わったら**: compose・sim・rails・bridge を止める。`fmruby-core/build/` は Linux の標準構成 (x86-64)。
- **止まる条件**: 既定の見え方で、ここに書いていない選択 (例: ノードを消す・まとめる) が要るとき。案を写しつきで書いて返す。
- **report**: Japanese plain style (常体)。書くこと: 描き方の組み立て (どこで何を作るか)、1 本の Session に複数のノードが乗る場合の決め方と理由、受け入れ条件の結果、残った課題。
