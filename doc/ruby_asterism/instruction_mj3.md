## 2. MJ3a: 部屋で遊ぶ・VPS 用の一式

1. **部屋の中の卓**: ゲームホストが枠の証明書 (`room-NN.tar`、`namespace` つき) で部屋の名前空間に入り、その部屋の中に卓 (待ち合わせから) を出す。部屋のリンクを開いたブラウザ版の卓のアプリが、そのまま待ち合わせに入れること。
   - どの枠に入るか・いつ卓を出すかの作りを決める (候補: 全部の枠に入っておき、部屋が使われている枠にだけ卓を出す / console が部屋を作るときに「麻雀の卓」を選べて、それをゲームホストが読む)。利用者から見た動き (部屋を作る人の操作) が増えるなら、増える操作が最小になる案を選び、理由を report に書く。
   - **枠の使い回しで前の部屋の卓が残らない**こと (部屋の ID が変わったら、前の卓の状態・席・合言葉を捨てる。保存した状態のファイルも)。
   - 部屋の外 (家の LAN の卓、今の `games/games/mahjong1` 形) も今どおり動くこと。
   - 部屋のリンクに開くアプリとして卓のアプリを指定できること (console の部屋の画面で、オセロと並べて選べる形)。
2. **VPS 用の一式** (asterism-games に置く): Dockerfile (image に riichi_engine の Fork を固定した版で入れる)、compose の service の例 (console の `deploy/vps` と並べて動かす形。状態の volume、再起動の方針)、`update.sh` (console と同じ流れ。対局の途中の更新を避ける「誰も座っていないときに反映」を選べる)、メモリの上限、ログ。console の毎日のバックアップに状態の volume を入れる方法 (console 側の変更が要るなら console に入れる)。
3. **見張り**: console の図にゲームホストが出て、死活と卓の数 (部屋ごと) が管理者の画面から見えること。足りないものは console に足す。
4. **手順書**: VPS に入れる手順 (ユーザが実行する。ssh で何を置き、何を起動するか) を asterism-games の docs と report に。実在の IP・ドメインは書かない (router.example.org、192.0.2.x)。

### MJ3a の受け入れ条件

1. 手元の構成 (console の `deploy/local`: nginx・door・signer・zenohd) で、管理者が部屋を作り、リンクを 4 つのブラウザ版で開いて、4 人 (または人 + CPU) で半荘を最後まで打てる。別の部屋からその卓は見えない・呼べない。
2. 部屋を閉じて同じ枠を別の部屋に使うと、新しい部屋の卓は空の待ち合わせから始まる。
3. ゲームホストの container を止めて起動し直すと、部屋の卓が同じ場面から続く。zenohd を起動し直しても数秒で戻る。
4. image を作って compose で起動でき、console の図に出る。メモリ (RSS) を 2 卓・4 人で測る。
5. asterism-games・console の試験、rubocop、fmruby-core の `rake test` と wasm のビルドが通る。今の家の LAN の卓 (`tools/mahjong_local.rb`) が今どおり動く。

## 3. MJ3b: ローカルルールの画面・観戦の仕上げ

1. **ローカルルールの設定の画面**: 卓の主が始める前に決め、待ち合わせの画面で全員に見せる。項目は riichi_engine が受けるルールの鍵から選ぶ (東風・半荘、喰いタン、赤ドラの枚数、ダブロン、三家和、ダブル役満、持ち時間、トビなど。エンジンが受けない項目は出さない)。既定は雀魂の既定 (ゲームホストの設定)。始まったあとは変えられない。保存した状態に入れる。
2. **観戦の仕上げ**: 観戦者に場だけを見せる (手牌は見せない) ことを試験で示す。数手遅らせて流す設定 (ゲームホストの設定、既定は report で決める)。観戦の画面 (1280x720 と 640x360) で、誰の手番か・点数・局の結果が見やすいこと。観戦の人数の上限 (部屋の 16 接続の内)。
3. **局の結果の画面**: 和了の役・符・翻・点数の移動、流局のテンパイの人が見やすいこと (1280x720 と 640x360)。

### MJ3b の受け入れ条件

1. ローカルルールを変えて始めた半荘が、その設定で進む (東風で終わる・喰いタンなしでタンヤオの鳴きが和了にならない、など) ことを試験と画面で示す。
2. 観戦の遅らせ・手牌の非表示の試験。観戦の画面の写し。
3. 画面の写しを report と `C:\Users\Public\asterism_deploy\screenshots\mj3\` に。
4. 1 通の最大が 3800 B 以下 (Web 版・端末の受けの上限 4096 B)。
5. MJ3a の 5 と同じ試験が通る。

## 4. 範囲・決まり

- **触ってよいもの**: asterism-games (main、コミットのみ)、asterism-console (main、コミットのみ。版は上げてよいが、タグは打たない)、fmruby-core (`feature/mj3`、develop から。コミットのみ)。
- **触らないもの**: riichi_engine の Fork (読むだけ。遊ぶ流れを止める誤りが出たら止まって返す)、asterism ほかのリポジトリ、VPS (ssh しない)、端末、sdkconfig、`.env`。
- push しない。`git commit -a` は使わない。公開の文書・コミットに実在の IP・ドメイン・端末 ID・鍵を書かない。
- ユーザに見せるファイルは `C:\Users\Public\asterism_deploy\` の下だけ (直下にフォルダを作らない)。
- **ユーザが使っているもの**: `tools/mahjong_local.rb up` で起動した zenohd (ws 7449)・ゲームホスト (asterism-games の `var/state`)・ページのサーバ (8006) は**止めない・作り直さない**。試しのゲームホストは別のポートと別の `state_dir` で動かす。卓 mahjong1 はユーザのもの (使ってよいが、終わったら待ち合わせの状態に戻す)。
- **終わったら**: 試しに起動したもの (deploy/local の構成、試しの image と volume、開発サーバ、sim) を止めて消す。fmruby-core の build/ は Linux の標準構成 (x86-64)、作業コピーは develop。
- **止まる条件**: 部屋・door・ACL の作り (G2) を変えないとできない。端末のファームの C や sdkconfig を変える必要が出た。VPS のメモリ (2 GB) に収まらない見込み。遊び方 (仕様) を決める選択で、1 章と 2-3 章から決めきれないもの (案を書いて返す)。
- **report** (`doc/ruby_asterism/report/mj3.md`、常体。MJ3a・MJ3b で章を分ける): 作り、決めた案と理由、受け入れ条件ごとの結果と数字、ユーザがすること (VPS への反映の手順)、残ったこと。
