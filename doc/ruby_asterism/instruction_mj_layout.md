# MJ-L 指示書: ふつうの麻雀ゲームの見た目の卓 (Web 版、高い解像度)

前提: game_rooms_comparison.md の 6 章 (「ふつうの麻雀ゲームの見た目の卓」の見本の形)、ユーザの見本の画像 `C:\Users\Public\asterism_deploy\screenshots\mj_design\table_layout_reference.png` (必ず見る)、report/mj1.md・report/mj2.md (今の卓・待ち合わせ・観戦・途切れの扱い、11 章の案 A)、asterism-games の README、`tools/mahjong_tilegen.rb` (牌の絵の生成)、wasm/web/main.js の解像度の選択 (`RESOLUTIONS`)。

言葉: 文書は常体、「端末」「確認」、作業の区切りは「Step」。技術の用語は例えにしない。

## 1. 決まっていること (2026-10-15 ユーザ)

- 端末を混ぜた確認と外への公開は後。今は、Web 版で、ふつうの麻雀ゲームの見た目の卓を作り、ユーザが自分と CPU 3 人で触って確かめる。
- 長く戻らない席は、mj2 の 11 章の案 A (途切れた席の待ち時間だけを短くする。CPU には替えない)。
- 見た目は見本の画像に合わせる: 4 人の河を中央の情報の板 (場風と局・本場・供託・ドラ・4 人の点数と風) のまわりに、それぞれの向きで並べる (左右の人は 90 度、向かいの人は 180 度回した牌)。他家の手牌は牌の裏の側面の列 (向かいは上の端、左右は縦の列)。鳴いた牌は右下に寄せ、横に倒した牌で誰から鳴いたかを示す。ボタン (ポン・ロン・スキップなど) は手牌の右上。自分の手牌は下の段に大きく、ツモの牌は少し離す。リーチの宣言牌は横に倒す。
- 牌の絵柄はユーザのもの (後で手で直す)。今の絵柄を元に、要る大きさ・向きを生成スクリプトで作る。シートは BMP (読み込みの上限は 2048 px)。

## 2. 作るもの

1. **解像度**: Web 版で使う大きさを決める。第一候補は 1280x720 (Web 版の解像度の選択肢に足す)。足すのが Web 版の作りの上で重い (描画の速さ、メモリ、ほかのアプリへの影響) なら、852x480 で作り、理由を report に書く。1280x720 を足す場合、ほかのアプリはその大きさで今どおり動けばよい (卓のアプリ以外の見た目の調整はしない)。
2. **牌の絵**: 選んだ大きさに合う、自分の手牌・河・他家の手牌の側面・鳴き用の横に倒した牌・左右と向かいの向き (90・180・270 度) の絵を、`tools/mahjong_tilegen.rb` に出力の形を足して作る (絵柄は変えない。拡大と回転)。シートの並びの表を README に。
3. **新しい卓の画面**: 今の卓のアプリの描き方の 1 つとして足す (画面の大きさで選ぶ。640x360 と小さい画面の今の描き方は残す)。待ち合わせ・観戦・結果の画面も同じ大きさで見やすく。打牌は手牌のクリック (とキー)、ボタンは手牌の右上。描画の量は画面に出る分に比例させる (毎回全部を描き直さず、変わったところだけ)。
4. **案 A**: 途切れた席は、その席の手番と鳴きの待ち時間を短くする (秒数は設定。既定は report で決める)。戻ったら元の待ち時間。
5. **ユーザが触るための手順**: Windows のブラウザで、自分 1 人と CPU 3 人の卓を開いて打てるまでの手順 (zenohd とゲームホストの起動、Web 版の開き方、解像度の選び方、卓の選び方)。できれば 1 つのコマンドか rake の task で全部が起きる形にする。手順は report と `C:\Users\Public\asterism_deploy\mj_layout\HOWTO.md` に置く。

## 3. 受け入れ条件

1. Web 版の選んだ解像度で、自分 1 人と CPU 3 人の半荘を最後まで打てる (エージェントは注入の操作で確かめる)。見本の画像の要素 (4 方向の河、中央の板、他家の手牌の側面、鳴きの横の牌、リーチの横の牌、右上のボタン) が出ている画面の写しを report と `C:\Users\Public\asterism_deploy\screenshots\mj_layout\` に。
2. 打牌から画面が描き終わるまでの時間 (中央値・95%) と、1 回の描画の時間を測り、Step 1 (640x360) と比べる。
3. 640x360 の今の卓、sim の卓、ほかのアプリ (エディタ・デスクトップ) が今どおり動く。Tab5・P4 の ESP32 のビルドが通る。
4. 案 A の試験 (途切れた席の待ち時間が短くなり、戻ると元に戻る)。
5. fmruby-core の `rake test`・wasm のビルド、asterism-games の試験が通る。
