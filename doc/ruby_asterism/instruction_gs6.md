# GS6 指示書: 共有のお絵かきボード (線の列、ボードごとの保存、console の MCAP で記録と再生)

> 状態: 指示 | 更新: 2026-10-18 | games_showcase.md の GS6。勝ち負けの無い「状態を共有して配る」例として、複数の端末とブラウザ版で同じボードに描けるお絵かきボードを、ゲームホストの枠組みの上に作る。描いていく様子は console の今の記録・再生 (V4、MCAP) で残して流せる

前提: games_showcase.md (GS6、3 章「共有のお絵かきボード」)、report/gs1.md〜gs5.md (枠組みの形、`Game` / `Remote` の子で書くもの、部屋の卓の選び方、居る・居ない、@status、meta の args / doc)、asterism-games の lib/asterism_games/ (othello を最小の見本として)、asterism-console の記録と再生 (V4: Recording / Playback、Bridge::Recorder / Player、docs の該当章)、卓のアプリ (fmruby-core flash/app/game/othello/ を見本に)、Family mruby のマウス入力とキャンバス描画 (fmrb-app-new の skill)。

言葉: 文書は常体。asterism-games・asterism-console の文書とコードのコメント、fmruby-core のコードのコメントは英語。

## 1. 決まっていること (2026-10-18 ユーザ、選択形式)

1. **絵は線の列で共有する**: 1 本の線 (色・太さ・点の列) を 1 つの単位にして配る。記録と再生で「描いていく様子」がそのまま再現でき、端末の低い解像度でも描ける。
2. **ボードごとに保存し、消すのは主**: ゲームホストがボードの絵を保存し、起こし直しても残る。全部消すのはボードの主 (最初に入った人、卓の主と同じ考え方)。各自は自分の最後の線を取り消せる。部屋のボードは部屋を閉じると消える (部屋の卓の保存と同じ)。
3. **記録と再生は console の今の記録機能 (V4)**: 管理者がボードの鍵を選んで記録し、再生すると端末やブラウザ版に描いていく様子が流れる。ボードの側に独自の履歴の再生は作らない。

ほか (前から決まっていること): 枠組みの上に、ほかのゲームと同じ書き方で書く。画面のアプリは fmruby-core。部屋の卓の選び方 (部屋が開くアプリからゲームを引く) と居る・居ない (アプリ `game` の印) はそのまま使う。

## 2. 作るもの

1. **ボードのゲーム** (asterism-games、例: `lib/asterism_games/board.rb` と `board/`): `Game` と `Remote` の子。
   - 呼び出し (名前・引数は任せる、meta に args / doc を書く): 入る・出る、線を足す (色・太さ・点の列。点は ボード座標の整数)、自分の最後の線を取り消す、全部消す (主だけ)、今の絵を取る (線の一覧、途中から取れる形)。
   - **配り方**: 受け付けた線を、ボードの鍵に put で配る (例: `asterism/<host>/games/<board>/strokes`。取り消し・全消しも同じ鍵に知らせとして流す)。端末はこれを購読して描く。console の記録はこの鍵を記録し、再生するとこの鍵に同じ put が流れて、端末が描いていく様子が再現されること。再生の put と本物の put を端末が同じように描けること (再生の間は、ボードの保存の絵と食い違ってよい。再生が終わったら端末は今の絵を取り直せる)。
   - ボード座標の大きさ (例: 640x360 か 320x180) と、色の数 (例: 16 色)、太さの段数、1 本の線の点の上限は任せる。**1 通は端末が受け取れる大きさ (Zenoh の頭を含め 4096 B) に収める** (長い線は分けて送る)。
   - 線の数の上限 (保存の大きさとメモリの上限) を設け、超えたら古い線から捨てるか断るかを決める (どちらにしたかを report に)。
   - 保存と再開、@status (線の数・人数)、部屋と常設と家の LAN。
   - 設定の例 (config/example.yml・rooms.yml) に `board1` を足す。
2. **ボードのアプリ** (fmruby-core、例: `flash/app/game/board/board.app.rb`、画面の名前「Board」/「お絵かき」など): ボードの一覧から入り、マウスで描く (押して動かして離すと 1 本)、色と太さを選ぶ、自分の最後の線を取り消す、主は全部消す。購読した線を描く。窓のアプリでよい。ブラウザ版 (1280x720・640x360) と sim (426x240) で崩れないこと。網のつなぎ方は卓のアプリと同じ (アプリ名 `game`)。描く処理は描いた分だけを描く (画面全体を毎回描き直さない)。
3. **console** (asterism-console): 記録・再生でボードの鍵を選べ、再生がボードの鍵に流れることを確かめる。今の作りで足りなければ直す (足りないものを report に)。部屋で開けるアプリにボードを足す設定の例 (docs)。
4. **試験**: ボードのゲームの試験 (線を足す・取り消す・主だけが全部消せる・保存と再開・1 通の大きさ・線の上限)。
5. **文書**: asterism-games の README (ボード)、console の docs (ボードの記録と再生の手順)。VERSION は asterism-games 0.11.0、console は変えたなら 0.3.5。

## 3. 受け入れ条件

1. asterism-games の `MJ_GAMES=8 bundle exec rake test`、asterism-console の試験と rubocop (触ったなら) が通る。
2. 家の LAN の網で、ブラウザ版 2 つと sim の端末が同じボードに描き、互いの線が出る (画面を写す。3 つの大きさで)。取り消しと主の全消しが全員に効く。ゲームホストを起こし直すと絵が戻る。
3. console の deploy/local で、ボードの鍵を記録し、白紙にしてから再生すると、ブラウザ版の画面に描いていく様子が流れる (途中と終わりを写す)。部屋のボード (部屋が開くアプリをボードにした部屋) で 2 つのページが描ける。
4. 数字: 線 1 本の 1 通の最大、線を 500 本描いたときのゲームホストの RSS と保存の大きさ、ボードのアプリの VM の使用量、描く処理の時間 (受け取ってから画面に出るまで)。
5. sim の標準構成で、エディタを 1 回起動して 1 打鍵する。

## 4. 範囲・決まり

- **触ってよいもの**: asterism-games (main)、asterism-console (main、記録・再生で要るなら)。fmruby-core はブランチ `feature/gs6` (develop から) で、ボードのアプリと、この Step の文書 (report)。asterism は読むだけ (足りなければ止まる)。
- **触らないもの**: riichi_engine の Fork、zenohd、VPS、実機の端末、sdkconfig、麻雀とオセロの見た目と動き。
- コミットのみ。push・タグはしない。`git commit -a` は使わない。コミットの末尾は `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。fmruby-core のコミットの件名は `<領域>: <要約>`、本文は英文。実在の値と鍵の検査をしてからコミットする。
- fmruby-core のビルドは本体の checkout で。ブラウザ版は `source ~/emsdk/emsdk_env.sh` のあと `rake spinel:gen wasm:mruby wasm:mrb wasm:web` で作り直す。終わったら build/ は Linux の標準構成 (x86-64) に戻し、`file build/fmruby-core.elf` で確かめる。
- 終わったら起こしたもの (zenohd、ゲームホスト、deploy/local、試しの image と volume、sim・web) を名前で止めて消す。前からある image は残す。docker の prune はしない。sim は音を出す前にミュート。家の LAN の zenohd は名前に `gs6` を入れ、ポートは sim の 7447 とぶつけない。
- **止まる条件**: asterism の変更が要る。console の記録・再生の作りを大きく変える必要がある。1 章に無い仕様の選択 (利用者から見た動き・既定値で 1 章を越えるもの) が要る。止まったら report に、ユーザが選べる形の選択肢 (推奨を先頭に、各選択肢で何が変わるか一言) を書いて返す。
- **report** (`doc/ruby_asterism/report/gs6.md`、常体): ボードの形 (呼び出し・鍵・1 通の形)、決めた大きさ・上限とその理由、記録と再生の確かめ、受け入れ条件ごとの結果と数字と画面、見立てと違った点、GS7 (gem と image) に向けて分かったこと、残ったこと。
