# GS9 指示書: 同じ招待リンクから作った部屋どうしで牌譜を見られる

> 状態: 指示 | 更新: 2026-10-18 | 部屋で打った牌譜は、今はその部屋が開いているあいだ、その部屋の中でしか一覧・振り返りに出ない。部屋は数時間で終わるので、同じ招待リンクから作った部屋どうしなら、前の部屋の牌譜も見られるようにする

前提: asterism-console 0.3.7 (招待リンク RoomInvite、部屋 Room の `room_invite` の参照、door 用の部屋のファイル `rooms.json` の書き出し (`{"slots": {"01": {"room", "until", "max", "app"}}}`)、docs/rooms.md)。asterism-games 0.15.0 (`lib/asterism_games/rooms.rb` が `rooms.json` を読んで部屋ごとのホストを起こす、記録 `RecordBook` (SQLite、`records_place` "room" と部屋の ID)、`records` / `record` は部屋のホストが自分の部屋の記録だけ出す、README「Game records」)。fmruby-core の麻雀アプリの「直近の結果」と振り返りは `records` / `record` を読むだけ (変えなくてよいはず。要るなら止まって返す)。

言葉: 文書は常体、「確かめ」ではなく「確認」。コードのコメントと両リポジトリの文書は英語。

## 1. 決まっていること (2026-10-18 ユーザ)

- **同じ招待リンクから作った部屋どうしなら、別の部屋でも牌譜が見られる** (一覧と振り返り)。
- 管理者が作った部屋 (招待リンクなし) は今どおり、その部屋の記録だけ。
- 常設の卓・LAN の卓からは今どおり見えない。成績の集計は今どおり。

## 2. 決めごと (親が決めた形。変えるなら止まって返す)

- **招待リンクの印**: console は招待リンクごとに、秘密と無関係な公開してよい印 (例 `group`: 招待の行ごとに作るランダムな文字列、または招待の ID から作る値) を持ち、`rooms.json` の部屋に `"group"` として書く。招待の秘密やそのハッシュは書かない。
- **記録に印**: ゲームホストは部屋の記録を書くときに、その部屋の印を残す (記録の表に欄を足す移行)。一覧と振り返りは「自分の部屋の記録 + 同じ印の記録」。印の無い部屋は今どおり。
- **これまでの記録は印を持たない**: さかのぼって付けない (今どおりその部屋だけ)。新しい版の後の対局から。
- **互換**: 新しいゲームホストと古い console (印を書かない) は今どおり。新しい console と古いゲームホスト (知らない欄を無視) も今どおり。
- 招待リンクを無効にした (Revoke) 後も、その招待の部屋が開いていれば、同じ招待の記録は見えてよい (印は消さない)。

## 3. 作るもの

### asterism-console (0.3.8)

1. 招待リンクの印 (移行。既存の招待にも作る)。`rooms.json` の部屋に `"group"`。招待のない部屋には書かない。
2. 試験: 招待の部屋に印が出る、管理者の部屋には出ない、秘密やハッシュが出ない。
3. 文書: docs/rooms.md (同じ招待の部屋どうしで牌譜が見える)、CHANGELOG 0.3.8、VERSION 0.3.8、install の 0.3.7 → 0.3.8 (更新は update.sh だけ、移行あり)。

### asterism-games (0.16.0)

1. `rooms.json` の `group` を読んで部屋のホストに渡す。記録に印 (移行)。`records` / `record` が同じ印の記録も出す (表の名前ごとに数える `records_kept` の決まりは今のまま)。
2. 試験: 同じ印の別の部屋の記録が一覧と `record` に出る、印の違う部屋・管理者の部屋・常設の卓からは出ない、印の無い記録は今どおり、古い `rooms.json` (印なし) で今どおり。
3. 文書: README「Game records」、CHANGELOG 0.16.0、VERSION 0.16.0、install の節。

## 4. 受け入れ条件

1. 両リポジトリの試験全部 (console は `bin/rails test` と rubocop、games は `MJ_GAMES=4 bundle exec rake test`) が通る。
2. 手元で: console の deploy/local と games の一式で、1 つの招待リンクから部屋 A を作って 1 局 (または半荘を短いルールで) 終局まで打ち、A を閉じる → 同じ招待から部屋 B を作って入り、「直近の結果」に A の対局が出て振り返れる。別の招待の部屋 C と管理者の部屋 D には出ない。画面か `records` の答えを report に写す。外の AI の API は呼ばない (CPU で)。手元で終局まで打つのが重すぎるなら、試験の層で同じことを確かめ、手元では `records` の答えだけで確認してよい (report に書く)。

## 5. 範囲・決まり

- **触ってよいもの**: asterism-console (main)、asterism-games (main)。fmruby-core は report だけ (ファイルとして書くだけ。git の操作はしない。親がコミットする)。
- **触らないもの**: asterism・riichi_engine・fmruby-core のコード、VPS、GitHub の設定、Tab5 (シリアル・WiFi)。
- 外の API を呼ばない。push・タグはしない。`git commit -a` は使わない。コミットの末尾は `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。実在の値の検査をしてからコミットする。
- 起こしたもの (deploy/local、games の一式、試しの image と volume、ブラウザ) は名前で止めて消す。前からある image は残す。docker の prune はしない。
- **止まる条件**: 1・2 章に無い仕様の選択が要る (例: 麻雀アプリの画面を変える必要がある、印の作り方に別の考えが要る)。止まったら report に、ユーザが選べる形の選択肢 (推奨を先頭に) を書いて返す。
- **report** (`doc/ruby_asterism/report/gs9.md`、常体): 印の形、`rooms.json` と記録の表の変更、受け入れ条件の結果、互換、VPS の更新に要ること。
