# Asterism G1.5b 指示書: ルータの起動し直しで困らないようにする、Apply の時を選ぶ、ブラウザのノード ID をハンドルから作る

> 状態: 指示 | 更新: 2026-10-13 | G1.5 で、動いている zenohd 1.10.1 の ACL は入れ替えられないと分かった (report/g1_5.md 3 章)。代わりの案のうち 1 (Apply の時を選ぶ) と 3 (切れても困らない) を入れる。あわせて、ブラウザのノード ID をメールアドレスからではなく、ユーザが決めるハンドルから作る

前提: report/g1_5.md (特に 3 章・7 章・ノード ID の決め方)、instruction_g1_5.md、plan.md の「決まっていること」の先頭 (console は OSS として各自が入れる)・G1.5・O1、asterism-console の `bin/ws_door`・`lib/relay/browser_node.rb`・Apply の画面、fmruby-core の `wasm/web/main.js`、`picoruby-asterism-zenoh/include/zenoh_generic_config.h` (`Z_FEATURE_AUTO_RECONNECT 0`)、asterism の gem (portable と CRuby) の接続の扱い。

言葉: 文書では、Family mruby の基板・sim・ブラウザ版を「端末」と呼ぶ (「機体」は使わない)。asterism-console の文書・画面は英語。

## 1. 決まっていること (2026-10-13 ユーザ: 「1+3 で。ハンドルから作る形がよい」)

- **案 3: 切れても困らないようにする** (本命)。クラウドのルータが起動し直しても (Apply・console の更新・回線の瞬断)、使う人からは数秒の途切れに見えるだけにする。
  - **ブラウザ**: 合言葉の扱いを「1 回の接続」から「**1 つの開いたページ、有効な間 (今の 4 時間まで)**」に変える (ユーザ決定)。同じページからのつなぎ直しは door が通す。別のページ・別のブラウザが同じ合言葉を使うことは今までどおり断る (ページごとの印を最初の接続で決め、つなぎ直しはそれを示す、など。どう結び付けるかは案を決めて report に書く)。合言葉はこれまでどおりフラグメントで渡し、サーバの記録に残さない。ページ (fmruby-core の wasm) は、切れたら自分でつなぎ直す (間隔を空けて何回か)。
  - **端末と CRuby**: つなぎ直したあと、生存の印・公開しているオブジェクト・購読が元どおりになる (つなぎ直したことをアプリが意識しなくてよい)。どの層でやるかは、測ってから選ぶ:
    - zenoh-pico の `Z_FEATURE_AUTO_RECONNECT` を入れる (宣言の付け直しも zenoh-pico がする)。**内蔵 RAM が増えるなら入れない** (増分 0 が最低線。PSRAM に回せるならその形で)。flash の増分も測る。
    - gem (portable の `Asterism.poll` など) が、セッションが閉じたことを見つけて開き直し、宣言を付け直す。
    - CRuby (zenoh-c) は、client の自動のつなぎ直しが宣言を戻すかをまず確かめる。
    - 選んだ層と理由・測った数字を report に書く。gem の本体を直してよい (asterism の main にコミット、**版は上げない・公開しない**。公開はユーザ)。
  - オセロは、途中でつなぎ直しが起きても対局が続く (相手が数秒見えなくなっても、すぐ「相手が抜けた」としない。待つ長さを決めて report に書く)。
- **案 1: Apply の時を選ぶ** (小さく)。Apply の確認の画面に、切れるもの (ブラウザの数・家のルータ・端末) を大きく出す。「今すぐ」に加えて「誰もつないでいないときに反映」と「時刻を決めて反映」を足す。後の 2 つは console が待ってから反映し、待っている間は台帳の画面に「反映待ち」と出す。取り消せる。
- **ブラウザのノード ID はハンドルから作る**: メールアドレスの一部は網の全員に見えてしまうので使わない。
  - ユーザがアカウントの画面でハンドル (短い名前) を決める。決めるまで「Open the browser build」は使えず、決めるよう促す。
  - 使える文字・長さ・ユーザどうしで重ならないこと (後から変えたときの扱い、空いた名前を他人がすぐ取れるか、を含めて決める)。ノード ID は `wasm-<ハンドル>`、同じユーザの 2 つ目のページは今の `_2` の形でよい。
  - 今のメールアドレスから作る決め方と、別のユーザと重なったときの `.<id>` は無くす。今いるユーザのハンドルは、移行で空にして、次に開くときに決めてもらう (メールから作った名前を残さない)。
- **OSS の方針** (plan.md「決まっていること」の先頭): 既定値・画面・文書に作者の環境を焼き込まない。

## 2. 作るもの

1. **asterism-console**: door の合言葉の扱い (1 つのページ・有効な間)、Apply の画面と待っての反映、ハンドル (アカウントの画面・検証・移行・`browser_node.rb`)、`docs/` に g1_5b.md、`deploy/vps/README.md` と g0_w4.md の合言葉の説明を直す。
2. **fmruby-core** (`feature/asterism-g1-5b`、develop から): ブラウザ版のつなぎ直し、端末のつなぎ直し (選んだ層による)、オセロの待つ長さ、`doc/ruby_asterism/report/g1_5b.md`。
3. **asterism / picoruby-asterism-zenoh / asterism-zenoh**: 選んだ層で要る直し (main にコミット、版は上げない)。

## 3. 受け入れ条件

1. 手元の構成 (deploy/vps と同じ docker、nginx・door を含む) で、オセロの対局中にクラウドのルータを起動し直しても (Apply の「今すぐ」と、`docker compose restart zenohd`)、ブラウザ版 (console から開いたもの)・家のルータの奥の sim・CRuby が数秒でつなぎ直し、対局が続く。console の図にも戻る。途切れの長さを測って書く。
2. 合言葉: 同じページのつなぎ直しは通り、別のページ・別のブラウザ・有効な間を過ぎたものは断られる。合言葉はサーバの記録に 0 回。
3. 端末 (P4-Nano) でも、つなぎ直しが効く (家のルータを起動し直す、で確かめてよい)。内蔵 RAM は増えていない (周期のダンプの値、同じコミットのビルドどうしで比べる)。焼き直しが要るなら、アプリの区画だけで済むか、全体かを先に書いて親に返す (焼くかはユーザ)。
4. Apply の「誰もつないでいないとき」「時刻を決めて」が働き、取り消せる。
5. ハンドル: 決めるまで開けない、重なりが断られる、ノード ID が `wasm-<ハンドル>`、メールアドレスの一部がどこにも出ない (図・記録・画面)。移行の上げ下げ。
6. console のテストと rubocop が通る。fmruby-core の wasm のビルドが通り、sim の標準構成も起動する (Linux の build/ は x86-64)。asterism の適合の試験 (CRuby と mruby) が通る。

## 4. 範囲・決まり

- **触ってよいもの**: asterism-console (main)、fmruby-core (`feature/asterism-g1-5b`)、asterism・asterism-zenoh・picoruby-asterism-zenoh (main)。すべてコミットのみ、push しない。**コミットは必ずファイルを指定する。`git commit -a` は使わない** (fmruby-core の `.env` にユーザの手元の変更がある)。
- **触らないもの**: `.env`、sdkconfig、fmruby-graphics-audio、公開済みの gem の版、**VPS (ssh で何かをすることは一切しない)**、家のルータの手元の設定 (`~/asterism-home/`)。
- **端末**: P4-Nano は 192.0.2.10 (tab5_* に ip を渡す。ミュート中)。焼き直しは親に返してから。
- **終わったら**: 起動したものを全部止める (compose、sim、ブラウザ、rails、zenohd、P4 のアプリ)。試し用の image は消す。`build/` は Linux の標準構成 (x86-64)。
- **止まる条件**:
  - 端末のつなぎ直しが、内蔵 RAM を増やさずにはできない (測った数字と案を書いて返す)。
  - ファームの C や sdkconfig を変えないとできない。
  - 合言葉の結び付け方で、1 章の決まりでは決めきれない選択が出た。
- **report** (`doc/ruby_asterism/report/g1_5b.md`、常体): つなぎ直しの層の選び方と測った数字、合言葉の結び付け方、Apply の待っての反映の作り、ハンドルの決まり、受け入れ条件ごとの結果、見立てと違った点、残った課題、VPS の更新の手順 (データベースの移行を含む、そのまま打てる形。本当のドメイン・IP は書かない)。
