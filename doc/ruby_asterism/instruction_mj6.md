# MJ6 指示書: 麻雀の画面の直し (発声・持ち時間) と、直近の結果の表・牌譜の振り返り

> 状態: 指示 | 更新: 2026-10-18 | 卓の麻雀のアプリで、リーチ・ポン・チー・カン・ロン・ツモの発声を宣言した人の席の近くに大きく出し、遅延 (ms) の表示を消し、持ち時間を目立つ形にする。ゲームホストが牌譜を保存して Asterism の公開メソッドで出し、アプリに直近の結果の表と牌譜の振り返りの画面を足す

前提: report/mj5.md (1280x720・640x360 の卓、観戦の 4 人の手牌、はみ出しの検査 `rake mahjong:overflow`)、gs5.md・gs5c.md (AI の席、待ち合わせ)、卓の麻雀のアプリ (fmruby-core flash/app/game/mahjong/ の mahjong.app.rb・mahjong_xl.rb・mahjong_panels.rb・mahjong_watch.rb)、asterism-games の app/asterism_games/mahjong/ (table.rb・remote.rb・readable.rb)、枠組み (lib/asterism_games/ の game.rb・store.rb の保存、@status)、asterism の README (meta の args / doc、@status)。

言葉: 文書は常体、「確かめ」ではなく「確認」。fmruby-core と asterism-games のコードのコメントは英語。

## 1. 決まっていること (2026-10-18 ユーザ、選択形式)

**A. 画面の直し**
1. **発声**: リーチ・ポン・チー・カン・ロン・ツモ (と流局の宣言があればそれも) を、**宣言した人の席の近く (その人の河の近く) に大きな文字で約 1 秒** 出す。誰が鳴いたかが場所で分かること。
2. **遅延 (ms) の表示は消す** (今の画面の応答時間の表示)。
3. **自分の持ち時間のカウントダウン**: 右側の引いた牌の表示の近くに、**大きな数字** で、今の手の時間と持ち越し (例「5」「+20」) を出す。**残り 5 秒で黄、一手の時間が尽きて持ち越しに入ったら赤**。
4. **鳴きの判断の持ち時間**: 鳴けるときに出るボタンの並びの近くに、同じ大きな数字と色で残りを出す。自分が鳴けるときだけ (ほかの人には誰が鳴けるかを見せない今の決まりのまま)。

**B. 直近の結果の表と牌譜**
5. **両方作る**: ゲームホストが対局ごとに牌譜 (配牌・ドラ表示・すべてのツモと打牌・鳴き・リーチ・和了と流局・点数の動き) を保存し、卓のアプリに「直近の結果」の表と、牌譜を 1 手ずつ進め戻しできる画面を足す。終局した対局は 4 人の手牌が全部見える。
6. **見られる人と残す数**: 卓に入れる人なら誰でも。常設の卓は卓ごとに直近 20 対局。部屋の牌譜は部屋を閉じると消える (部屋の卓の保存と同じ)。終局した対局だけを残す (対局中の牌譜は出さない)。
7. **Asterism の機能を生かす**: 牌譜はゲームホストの公開メソッド (例 `records` = 直近の対局の一覧、`record(id)` = 1 対局の牌譜) で、meta に引数名と説明 (args / doc) を付けて出す。卓のアプリ・CLI (`asterism call`)・MCP が同じものを読める。@status に直近の対局の結果の要約 (順位と点数) を足す。

ほか (前から): 効果音・BGM・WAV の再生は後の Step (この Step ではしない)。

## 2. 作るもの

1. **画面の直し** (fmruby-core の卓のアプリ、1280x720 と 640x360 の両方。426x240 は sim の開発用の簡易表示で、落ちない・続けられる程度): 1 章の 1-4。発声は、ゲームホストの見え方の中の最後の出来事 (今ある鍵で分かればそれを、無ければ足す) から出す。持ち時間の数字は今ある締め切り (`dl` など) から。`rake mahjong:overflow` のはみ出しの検査に新しい表示を足し、はみ出し 0 を保つ。
2. **牌譜の保存** (asterism-games): 対局中に出来事を記録し、終局で牌譜として卓の保存の場所 (常設は state の permanent の下、部屋は部屋の下) に書く。直近 20 を超えたら古いものから消す。牌譜の形 (鍵・牌の表し方) を決めて README に書く (AI や他の道具が読みやすいように、`look` と同じ牌の名前の表し方に揃える)。保存と再開をまたいでも記録が欠けないこと。
3. **公開メソッド**: `records` (直近の対局の一覧: いつ・ルール・4 人の名前と順位と点数) と `record(id)` (1 対局の牌譜)。1 通の大きさの上限 (端末は 4096 B) に収まらない牌譜は、局ごとなどに分けて取れる形にする (例 `record(id, round)`)。meta に args / doc。
4. **@status**: 直近の対局の結果の要約を足す (名前は載せてよい: 卓の会員の表示名は見え方ですでに出ている。ノード ID・token は載せない)。
5. **卓のアプリ**: 卓の一覧か待ち合わせから「直近の結果」を開き、表 (日時・順位・点数) から 1 対局を選んで振り返りの画面へ。振り返りは 1 手ずつ進む・戻る、局の頭へ跳ぶ、4 人の手牌・河・鳴き・ドラ・点数を出す。画面のファイルは、通常の対局で読み込まない別のファイルに分け (例 `mahjong_replay.rb`)、開いたときだけ読む (VM の使用量を対局中に増やさない)。1 つのアプリのファイルは 64 KB まで。
6. **試験**: 牌譜の記録 (配牌から終局まで欠けない、点数の動きが合う、再開をまたぐ)、直近 20 の上限、部屋を閉じると消える、公開メソッドの形と大きさ、@status の要約。
7. **文書**: asterism-games の README (牌譜の形、records / record、MCP で AI に牌譜を検討させる例)、CHANGELOG。asterism-games の VERSION は 0.13.0 (GS5c の 0.12.1 の分も含める)。

## 3. 受け入れ条件

1. asterism-games の `MJ_GAMES=8 bundle exec rake test` が通る (足した試験も)。fmruby-core の `rake mahjong:overflow` ではみ出し 0。
2. 家の LAN の卓 (CPU と偽物の AI でよい) で、発声が宣言した人の席の近くに出る、持ち時間の数字と色が変わる、鳴きの持ち時間が出る、遅延の表示が無いことを、1280x720・640x360 で写す。
3. 東風戦を 2 回終局まで打ち、直近の結果の表に 2 行出て、牌譜の振り返りで配牌から和了まで進め戻しでき、4 人の手牌が見えることを写す。
4. CLI (`asterism call` で records と record) と MCP (`asterism mcp --allow 'games/mahjong1.records' --allow 'games/mahjong1.record'` などの形) で同じ牌譜が読める。@status に直近の結果が出る (`asterism watch` か console の Details)。
5. 数字: 牌譜 1 対局の保存の大きさ、record の 1 通の最大、卓のアプリの VM の使用量 (対局中は MJ5 から増えないこと、振り返りを開いたとき)。
6. sim の標準構成で、エディタを 1 回起動して 1 打鍵する。

## 4. 範囲・決まり

- **触ってよいもの**: asterism-games (main)、fmruby-core はブランチ `feature/mj6` (develop から) で、卓の麻雀のアプリと report。asterism と asterism-console は読むだけ。
- **触らないもの**: riichi_engine の Fork (牌譜に要る情報がエンジンから取れなければ止まる)、オセロ・ボードのアプリ、zenohd、VPS、実機の端末、sdkconfig。
- コミットのみ。push・タグはしない。`git commit -a` は使わない。コミットの末尾は `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。fmruby-core のコミットの件名は `<領域>: <要約>`、本文は英文。鍵と実在の値の検査をしてからコミットする。
- fmruby-core のビルドは本体の checkout で。ブラウザ版は `source ~/emsdk/emsdk_env.sh` のあと `rake spinel:gen wasm:mruby wasm:mrb wasm:web` で作り直す。終わったら build/ は Linux の標準構成 (x86-64)、`file build/fmruby-core.elf` で確認する。
- 終わったら起こしたもの (zenohd、ゲームホスト、MCP サーバ、sim・web) を名前で止めて消す。家の LAN の zenohd は名前に `mj6` を入れ、ポートは sim の 7447 とぶつけない。sim は音を出す前にミュート。ゲームホストの状態の置き場所は作業用の場所にする (`var/state` を汚さない)。API の鍵は使わない (偽物のつなぎ `ASTERISM_GAMES_AI_FAKE=1`)。
- **止まる条件**: エンジンから牌譜に要る情報が取れない。1 章に無い仕様の選択 (利用者から見た動き・既定値) が要る。卓のアプリの VM が対局中に大きく増える (P4-Nano で large_memory でも足りなくなる恐れ)。止まったら report に、ユーザが選べる形の選択肢 (推奨を先頭に、各選択肢で何が変わるか一言) を書いて返す。
- **report** (`doc/ruby_asterism/report/mj6.md`、常体): 画面の前と後、牌譜の形と保存の場所、公開メソッドと @status、CLI と MCP での読み方の例、受け入れ条件ごとの結果と数字と画面、見立てと違った点、残ったこと (効果音・BGM の Step に向けて分かったことも)。
