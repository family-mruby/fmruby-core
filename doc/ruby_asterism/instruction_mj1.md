# MJ1 指示書: 麻雀の Step 1 (ゲームホストと CPU 3 人、牌の画像の卓)

> 状態: 指示 | 更新: 2026-10-15 | 自分 1 人と CPU 3 人で局が回るところまで作る。ゲームホスト (CRuby、riichi_engine を包む) は新しいリポジトリ asterism-games に、卓の画面 (640x360、牌は画像) は fmruby-core の flash/app/game/ に置く。部屋 (G2) に入れるのと人間 4 人は Step 2

前提: game_rooms_comparison.md (3〜6 章: 部屋の係、手牌の守り方、riichi_engine、ゲームホストの要件、麻雀の見込みと Step)、audio.md の「1 通の大きさの上限」(端末とブラウザ版が受け取れるのは 1 通 4096 B まで、超えると黙って捨てられる)、game.md と othello (flash/app/test/othello.app.rb、交互に指す遊びの作り・つなぎ直し)、asterism gem の README と protocol.md、fmrb-app-new の skill (端末のアプリの規約と picoruby の地雷)。

言葉: 文書は常体、「端末」「確認」、作業の区切りは「Step」。技術の用語は例えにしない。定着したカタカナ語はそのまま。卓の画面の文字は英語か日本語 (アプリの i18n の流儀に合わせる)。

## 1. 決まっていること (2026-10-15 ユーザ)

- 麻雀を先に進め、おおむねできてから外への公開 (G2 の残り) に進む。
- ゲームホストのコードは**新しいリポジトリ** `asterism-games` (親 family-mruby の下、ほかの asterism-* と並べる)。最初は手元だけ (GitHub に作らない)。将来は docker の image にして console と同じ update.sh で更新する形に育てる。麻雀以外のゲームホストも入れられる作りにする。
- 麻雀の処理は rubygems の `riichi_engine` (0.1.0 に固定)。山と乱数はゲームホストだけが持つ。プレイヤーから来た操作は、エンジンの「今できる操作の一覧」にあるものだけ受ける。
- 手牌は、座ったときにゲームホストが返す席の合言葉 (乱数) を添えた呼び出しにだけ返す。場 (河・鳴き・点数・手番・残り枚数) は全員に見せてよい。
- 卓は 640x360 を基準にする (P4 のアプリが使える最大。ブラウザ版も設定で 640x360 にできる)。牌は最初から画像で出す。画像はユーザが用意した生成スクリプト `mahjong_tilegen.rb` (純 Ruby、gem 不要、スクリプトも出力も CC0) で作る。手牌の大きさ 42x56 (640 px に 14+1 枚) と河の大きさ 24x32 の 2 種類、MPSZ の名前 (1m..9m・1p..9p・1s..9s・1z..7z、赤五の 0m・0p・0s、裏の back)。
- Step 1 は、自分 1 人と CPU 3 人。自分の手番の自摸・打牌・リーチ・自摸和了・暗槓、CPU の捨て牌へのロン・ポン・チー・明槓を、エンジンが出す一覧から選べる。手番の待ち時間を過ぎたら自動で打つ (既定の秒数は設定で変えられる)。人間 4 人の割り込みの調停・観戦・部屋は Step 2。

## 2. 作るもの

1. **asterism-games** (新しいリポジトリ、CRuby):
   - ゲームホストの土台 (Asterism のノードとして起き、ゲームごとのオブジェクトを公開する。設定はファイルと環境変数)。麻雀の卓のオブジェクト: 座る (席と合言葉を返す)・自分の見え方を取る・操作を送る・場の変化を配信する。CPU の席を riichi_engine の打ち手で埋める。局が終わったら次の局へ (半荘の終わりまで)。
   - **1 通の大きさ**: 端末とブラウザ版に渡す 1 通 (呼び出しの答え・配信) は、Zenoh と Asterism の包みを含めて 4096 B を超えない。席ごとの見え方は小さく符号化する (牌は 1 バイトの番号など)。大きさの上限を試験で確かめる。
   - 状態の書き出し: 変わるたびに局の状態をファイルに書き、起動し直したらそこから続ける。
   - 試験: CPU 4 人で局を多数 (少なくとも半荘 20 回) 回して例外が出ないこと、席ごとの見え方に他人の手牌が入らないこと、一覧にない操作を断ること、待ち時間の自動の打牌、書き出しと読み戻し。riichi_engine の誤りを見つけたら、こちらで回避するか止まって返す (作者への報告の下書きを report に書く)。
   - README (使い方・設定・試し方)。
2. **卓の画面** (fmruby-core の `flash/app/game/mahjong/` など、既存の game の置き方に合わせる): 640x360。自分の手牌・河 (4 人)・鳴き・点数・場風と局・ドラ表示・残り枚数・手番。操作は今できるものだけ押せるボタンと、手牌のクリックで打牌。待ち時間の残り。牌の画像は 1 枚の画像にまとめて小さく (Tab5 の flash の区画は残りが少ない。足す大きさを report に書く)。つなぎ直し (othello と同じ考え) で、戻ったら見え方を取り直す。
3. **牌の画像**: ユーザの生成スクリプト (Windows の Downloads の `mahjong_tilegen.rb`。親がこの指示書と一緒に渡す場所から読む) を fmruby-core の `tools/mahjong_tilegen.rb` に置き、出力をアプリの置き場に入れる。端末で読みやすい形 (1 枚の画像にまとめる、または必要な枚数だけ) と大きさ (Tab5 の区画の残り) を考えて、出力の形を足してよい。絵柄の直しが要ると思ったら、直さずに案を report に書く (絵柄はユーザのもの)。透明 (角の丸め) が P4・ブラウザ版・sim の画像の読み込みでどう出るかを確かめる。
4. **文書**: fmruby-core の `doc/ruby_asterism/report/mj1.md`、game_rooms_comparison.md の 6 章に結果の 1 行、plan.md の MJ の行。asterism-games の README。

## 3. 受け入れ条件

1. 手元の構成 (docker の zenohd、ゲームホスト、ブラウザ版を 640x360) で、自分 1 人と CPU 3 人の半荘を、ブラウザ版の操作 (web_input の注入) で最後まで打てる (自摸・打牌・少なくとも 1 回のポンかチー・リーチ・和了か流局を含む。和了が出ない場合は試験で形を作って画面を確かめてよい)。画面の写しを report に。
2. 端末とブラウザ版に渡す 1 通がすべて 4096 B 未満 (最大の値を report に)。
3. 席ごとの見え方に他人の手牌が入らない、合言葉の無い・違う呼び出しは断る、一覧にない操作は断る (試験)。
4. ゲームホストを途中で止めて起動し直すと、同じ局の同じ場面から続き、ブラウザ版はつなぎ直して見え方を取り直す。
5. sim (Linux の標準構成) でも卓の画面が描ける (ゲームホストに繋いで 1 局の途中まで)。
6. fmruby-core の `rake test`、wasm のビルド、asterism-games の試験が通る。Tab5 の区画に収まる (足した大きさ)。

## 4. 範囲・決まり

- **触ってよいもの**: 新しいリポジトリ `asterism-games` (git init、main、コミットのみ、GitHub に作らない・push しない)。fmruby-core (`feature/mj1-mahjong`、develop から、コミットのみ、push しない)。親リポジトリの `.gitignore` (asterism-games を無視に足すなら、ほかの asterism-* と同じ形で)。
- **触らないもの**: asterism・asterism-zenoh・picoruby-asterism-zenoh・asterism-console (読むだけ。直しが要るなら止まって返す)、VPS、端末 (焼かない)、sdkconfig、`.env`。
- `git commit -a` は使わない。コミットはファイルを指定する。英語のメッセージ。
- 公開される文書・コード・コミットに、実在の IP・ドメイン・SSID・端末 ID・鍵を書かない (例は 192.0.2.x、router.example.org、fmruby-aaaaaa)。
- ユーザに見せるファイルは `C:\Users\Public\asterism_deploy\` の下だけ (直下にフォルダを作らない)。
- **終わったら**: 起動したもの (zenohd・ゲームホスト・sim・web) を止める。fmruby-core の build/ は Linux の標準構成 (x86-64)、作業コピーは develop。
- **止まる条件**: 4096 B に収まらない。riichi_engine の誤りで先に進めない。asterism などほかのリポジトリを直す必要が出た。利用者から見た動き (仕様) を変える選択が要る。
- **report** (`doc/ruby_asterism/report/mj1.md`、常体): 作り (ゲームホストのオブジェクトと呼び出しの形、見え方の符号化、卓の画面の配置)、牌の画像の作り方 (生成スクリプトの使い方・出力の形・大きさ)、受け入れ条件ごとの結果と数字 (1 通の大きさの最大、操作から画面までの時間、メモリ、区画に足した大きさ)、riichi_engine で気づいたこと、見立てと違った点、Step 2 への申し送り。
