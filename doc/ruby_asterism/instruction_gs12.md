# GS12 指示書: `asterism-games play` を 1 キーで操作する

> 状態: 指示 | 更新: 2026-10-19 | GS11 の `play` は 1 行ずつ打つ形 (`pass` `pon` `d3` と打って Enter)。ユーザが試し、麻雀は鳴き・宣言を 1 キーで、オセロは十字キーで位置を動かして Enter で置きたいとのこと

前提: asterism-games main (未 push の 0.17.0、2bb409c)。`lib/asterism_games/play.rb` (入口、`--commands` の待ち行列、1 行ずつ読む loop)、`play/othello.rb`、`play/mahjong.rb` (`io/console` は読み込み済み)、`play/mahjong_screen.rb` / `mahjong_text.rb` (描画と牌の文字)。麻雀アプリ (fmruby-core `flash/app/game/mahjong/`) のキーの割り当てが手本 (読むだけ)。

言葉: 文書は常体、「確かめ」ではなく「確認」。コードのコメントと asterism-games の文書は英語。端末の表示は日本語。

## 1. 決まっていること (2026-10-19 ユーザ、選択形式)

- **麻雀は麻雀アプリと同じキー**: ←→ で手牌の牌を選び、Enter (か Space) で打つ。宣言は 1 キー: `R` リーチ、`T` ツモ/ロン、`P` ポン、`C`/`V`/`B` チー (候補ごと、アプリの CHI_KEYS と同じ順)、`K`/`L`/`J` カン (アプリの KAN_KEYS)、`N` 九種九牌 (アプリにあれば同じキー)、`Esc` パス、結果で `Enter` が OK。牌の文字 (a〜n) は使わない。画面の下の「今できること」は `[R]リーチ [T]ツモ` のように、キーを `[]` で囲んで出す (アプリの決まり)。
- **オセロは十字キーで位置を動かし、Enter で置く**: 盤上にカーソルを出す (置ける所の印と区別がつくように)。

## 2. 決めごと (親が決めた形。変えるなら止まって返す)

- **キーで読むのは標準入力が端末のときだけ**: `STDIN.tty?` のときは raw (`io/console` の `raw` / `getch` 相当) で 1 キーずつ読み、矢印などのエスケープ列を解釈する。パイプ・ファイル・試験のときは今の 1 行ずつの形のまま (自動入力の試験と `--commands` はそのまま動くこと)。`--commands` の待ち行列もキーの形と両立させる。
- **Esc と矢印の区別**: Esc 単独は少し (50 ms 程度) 待って後続が無ければ Esc とする。
- **待ち合わせ・終わり方も 1 キーに**: 座る・立つ・CPU で埋める・始める・抜けるを 1 キーにする (アプリの待ち合わせ画面にキーがあれば合わせる。無ければ頭文字で、画面に `[]` で出す)。`Ctrl+C` と `Q` (か `Ctrl+Q`、アプリの「閉じる」に合わせる) で抜ける。どの画面でも、今効くキーを下に出す。
- **打ち込みの形も残す**: `:` (か `/`) で 1 行打ち込む欄を開き、今の文字の命令 (`d3`、`6s`、`chi 2` など) をそのまま使えるようにする (逃げ道)。
- **端末を必ず戻す**: 例外・Ctrl+C・ホストの出入りで抜けても raw を解き、カーソルを表示に戻す (`ensure`)。描き直しのたびに画面が流れないよう、今の描き方 (消して描く) と合わせる。
- 依存は増やさない (標準ライブラリだけ)。

## 3. 作るもの

1. キーを読む層 (端末のときだけ raw、矢印・Esc・Enter・Space・Ctrl+C を名前に直す)。キー → 命令の変換を純粋な関数にし、単体試験できる形にする。
2. 麻雀: 選んでいる牌の印 (牌の下の `^^` など、幅の扱いは GS11 の並べ方に合わせる)、宣言のキー、鳴きの候補ごとのキー表示、結果の OK、待ち合わせのキー。
3. オセロ: カーソル (初期位置は置ける所の 1 つ、盤の端で止まる)、Enter で置く、置けない所は何もしない (か短い知らせ)、待ち合わせのキー。
4. 試験: キーの解釈 (エスケープ列、Esc 単独)、キー → 命令の変換 (麻雀の各場面、オセロのカーソルの動きと端)、端末でないときは今の形のまま。既存の試験は通ったまま。
5. 文書: README の play の節 (キーの一覧)、CHANGELOG の 0.17.0 に足す (版は 0.17.0 のまま)。

## 4. 受け入れ条件

1. `MJ_GAMES=4 bundle exec rake test` が通る。
2. 擬似端末 (`script` コマンドや Ruby の `PTY`) でキーを送り、手元の一式 (zenohd + ゲームホスト、CPU だけ) に対して: オセロをカーソルと Enter で 1 局終局まで、麻雀を 1 キーで東風戦の終局まで (鳴き・パス・結果の OK を含む) 打てる。画面の写しを report に貼る。
3. 抜けたあと端末が戻っている (`stty -a` が前と同じ) ことを確認する。
4. 実際の端末での打ち心地は親とユーザが確認する (report に「確認してほしいこと」を書く)。

## 5. 範囲・決まり

- **触ってよいもの**: asterism-games (main)。fmruby-core は report だけ (ファイルとして書くだけ、git の操作はしない)。
- **触らないもの**: asterism・asterism-console・riichi_engine・fmruby-core のコード、VPS、GitHub の設定、Tab5。
- 外の API を呼ばない。push・タグはしない。`git commit -a` は使わない。コミットの末尾は `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。実在の値の検査をしてからコミットする。
- 手元で親が動かしているもの (zenohd コンテナ `try-zenohd`、`/tmp/try-games` のゲームホスト) には触らない。自分の試験には別の名前・別のポートの zenohd とホストを起こし、終わったら名前で止めて消す。docker の prune はしない。
- **止まる条件**: 1・2 章に無い仕様の選択が要る。止まったら report に、ユーザが選べる形の選択肢 (推奨を先頭に) を書いて返す。
- **report** (`doc/ruby_asterism/report/gs12.md`、常体): キーの一覧 (麻雀・オセロ・待ち合わせ)、画面の写し、端末を戻す扱い、試験の結果、確認してほしいこと。
