# GS15 指示書: 観戦対局 (座らずに CPU・AI だけで始める)

> 状態: 指示 | 更新: 2026-10-20 | 麻雀の卓で、卓の主が自分は座らずに 4 席を CPU・AI で埋めて「観戦で始める」。AI 同士の対局を観戦し、PC の実況アプリ (doc/commentary/) で実況できるようにする。ゲームホスト・`play mahjong`・端末の麻雀アプリの 3 つ

前提:
- asterism-games main (0.19.1、bcb8607)。麻雀の卓 `app/asterism_games/mahjong/table.rb`: 卓の主は「座っている人の中で最初に座った人」(`pass_owner`)、`start(token)` は卓の主だけ、`cpu(token, seat, on)` で CPU・AI の席、`humans` の設定 (0 なら CPU だけで自動で回る常設の観戦卓)、離席の打ち切り (`abandon_ms`、人が全員離席で打ち切り)、終局 → 待ち合わせ、記録 (`records.rb`、成績 `stats`)、AI の席と 1 日の上限 (`lib/asterism_games/ai.rb`、`AI::GAME_KINDS`)、観戦者 (`spectators`、観戦の view)、観戦用の様子 (GS14)。`play mahjong` の待ち合わせのキー (GS12: 1〜4 座る、S 立つ、C CPU で埋める、Enter 始める)。
- fmruby-core develop。麻雀アプリ `flash/app/game/mahjong/` (待ち合わせ画面と席の選び方 `mahjong_panels.rb` の `["", "cpu"] + ai_kinds`、`ai_kinds` / `ai_label`、640x360 と 1280x720 の配置、はみ出しの検査 `rake mahjong:overflow`)。牌のシートはユーザの手描き: 触らない。

言葉: 文書は常体、「確かめ」ではなく「確認」。コードのコメントと asterism-games の文書は英語。画面の言葉は日本語。

## 1. 決まっていること (2026-10-20 ユーザ、選択形式)

1. **待ち合わせの操作として「観戦で始める」を足す** (別の設定ファイルの卓ではなく、ふつうの卓で選べる)。押せるのは**卓の主**。卓の主は座っていなくてよい (座らずに卓に入った最初の人が卓の主になれる)。空き席を CPU・AI で埋めるのも卓の主。
2. **終わり方は 1 回の対局**: 東風か半荘を 1 回打ったら待ち合わせに戻る。続けるならもう一度押す。見ている人 (卓の参加者) が全員去ったら、その時点でも止める。
3. **AI の席の上限: Claude は 1 席まで、Jev は 4 席まで** (観戦対局のとき)。費用はいまの 1 日の上限 (種類ごと) がそのまま効き、超えたら CPU が打つ。
4. **記録: 牌譜は残し、成績には数えない**。人の成績 (順位・平均) に混ぜない。CPU・AI ごとの成績には数える。記録の一覧で観戦対局と分かる印を付ける。

## 2. 決めごと (親が決めた形。変えるなら止まって返す)

- **ホスト**:
  - 卓の主: 座っていない参加者でも卓の主になれるようにする (卓に人が 1 人もいないときに入った人、または卓の主が去ったときの引き継ぎで座っていない人も対象)。今の「最初に座った人」の決まりとの関係を整理し、ふつうの対局の動きを変えない (人が座っているときは今まで通り)。
  - 新しいメソッド (例 `start_watch(token)`) か `start` の引数で、卓の主が「観戦で始める」。条件: 4 席がすべて CPU か AI (人が座っていない)、AI の席の上限を守る。違反は理由の文字列で断る。
  - 観戦対局の間: 人が座っていないので離席の打ち切りは効かせない。代わりに参加者が全員去ったら止める (途中の対局は記録しない、ふつうの打ち切りと同じ扱い)。結果の表示は CPU だけの卓と同じく自動で進む。1 回の対局で待ち合わせに戻る。
  - view と @status に観戦対局であることを出す (例 `wm: 1`、status の `watch: true`)。記録に印 (例 `watch: true`) を付け、人の成績から外す。
  - AI の席の上限は観戦対局の始めるときと、待ち合わせで AI を座らせるときの両方で守る (待ち合わせでは「観戦で始めるなら上限」の案内を出す程度でよい。ふつうの対局の AI の決まりは変えない)。
  - 観戦用の様子 (GS14) と実況アプリはそのまま働くこと (実況アプリのコードは変えない想定。変える必要があれば最小に)。
- **`play mahjong`**: 待ち合わせのキーに「観戦で始める」(例 `W`) を足す (卓の主で、全席が CPU・AI のときだけ案内に出す)。座らずに入った人が卓の主になれる流れ (座らずに CPU で埋めて W)。AI を座らせるキーは今のまま (無ければ、GS13 のオセロの A キーに合わせて席ごとに AI を選べるように)。
- **麻雀アプリ (fmruby-core)**: 待ち合わせ画面に「観戦で始める」のボタン (と既存のキーの決まりに合うキー) を足す。卓の主で全席が CPU・AI のときだけ出す。古いホスト (この機能が無い) では出さない (view の印か host の版で判断)。対局が始まったら、観戦者として 4 人の手牌が見える今の観戦画面になる。640x360 と 1280x720、Retro (320x240) で崩れないこと (`rake mahjong:overflow`)。内蔵 RAM を増やさない (アプリの Ruby だけの変更のはず)。
- **古いものとの組み合わせ**: 新しいアプリ × 今の VPS (0.18.0) のホスト、古いアプリ × 新しいホストで、今の遊び方が壊れない。
- 外の API を呼ばない (AI の席は Fake の decider)。

## 3. 作るもの

1. asterism-games: ホストの変更、`play mahjong` のキー、試験 (座らない卓の主、観戦で始める条件 (人がいる・AI の上限超え・卓の主でない は断る)、離席の打ち切りが効かない、全員去ったら止める、1 回で戻る、記録の印と成績から外す、ふつうの対局が変わらない)、README (観戦対局の節、メソッド、view・status の鍵)、CHANGELOG **0.20.0**、VERSION、docs/install.md (`.env` の変更の有無)。
2. fmruby-core: 麻雀アプリの待ち合わせの操作。
3. 確認: 手元の zenohd とゲームホスト (Fake の AI を Claude・Jev として出す) に対して、
   - `play mahjong` (擬似端末) で、座らずに入る → CPU・AI で埋める (Claude 1・Jev 2・CPU 1 など) → 観戦で始める → 終局 → 待ち合わせに戻る、まで。
   - Linux sim の麻雀アプリ (標準構成、fmrb MCP の sim_*) で、同じ流れを画面の写しで (待ち合わせの「観戦で始める」、対局中の観戦画面、終局)。エディタを 1 回起動して 1 打鍵する確認も含める。
   - PC の実況アプリ (`commentate mahjong`、`--ai off`、VOICEVOX なし) がその卓を実況できること (字幕が流れる)。
   - 写しを report に。
