# GS10 指示書: 部屋に入り直せる (同じブラウザは同じ人、卓の主の引き継ぎ)

> 状態: 指示 | 更新: 2026-10-18 | 部屋のリンクで麻雀を始め、タブを閉じて同じブラウザで開き直すと、別の人として観戦に入り、前の自分は「途切れ」のまま席と卓の主を持ち続ける。卓の主が途切れたままなので始めることもできず、どうしようもなくなる

前提:
- asterism-console 0.3.8: 部屋の門 (`bin/ws_door` の部屋の待ち受け、部屋の席 (`wasm-<slot><seat>` のノード ID と席ごとの証明書) を接続ごとに割り当てる、部屋のリンクの鍵で入る、docs/rooms.md)。
- asterism-games 0.16.1: 部屋ではノード ID で人を見分ける (`lib/asterism_games/game.rb` の join・`reused_seat` (`seat_reuse_ms` を過ぎた同じ席の番号は別のページ扱い)・away・`trusted_nodes`)、麻雀の卓の卓の主 (`@owner`、`app/asterism_games/mahjong/table.rb`)、README「Who is there」「Rooms」。
- fmruby-core のブラウザ版のページ (`wasm/web/index.html` が `#room=` を読む、`main.js` が `window.FMRB_ROOM` を渡す、ページの保存は localStorage、`?res=` など)。部屋への接続 (zenoh-pico の WebSocket で門へ) をどこで開いているかは読んで確かめる。

言葉: 文書は常体、「確かめ」ではなく「確認」。コードのコメントと asterism-* の文書は英語。

## 1. 決まっていること (2026-10-18 ユーザ、選択形式)

1. **同じブラウザなら同じ人に戻る**: ブラウザに部屋ごとの戻りの印を記憶し、同じ部屋のリンクを開き直したら、門が前と同じ席 (同じノード ID) を渡す。ゲームホストからは途切れた人が戻ったことになり、席・卓の主・対局の続き (手牌・点数) がそのまま戻る。
2. **途切れた卓の主を渡す**: 卓の主が一定時間 (既定 60 秒、設定で変えられる) 途切れたら、つながっている人間の参加者 (席に座っている人を優先、いなければ入った順) に卓の主を移す。前の卓の主が戻っても、取り返さない (移ったまま)。

## 2. 決めごと (親が決めた形。変えるなら止まって返す)

- **戻りの印は秘密**: ブラウザが部屋ごとに作るランダムな値 (または門が最初の接続で渡す値)。門は印と席の対応を部屋が開いているあいだだけ覚える (部屋が終われば消える)。印はリンクにもログにも出さない (部屋の鍵と同じ扱い: フラグメントか本文で運ぶ、nginx・門のログに残さない)。
- **前の接続が残っているとき**: 同じ印で新しい接続が来たら、前の接続 (閉じたタブの残り) を切って席を渡す (同じブラウザの 2 つ目のタブも同じ扱いでよい: 後から来た方が席を取る)。
- **席が別の人に渡っていたとき** (印を覚えていない、または門が再起動して対応を失った): 今どおり空いている席を渡す。落ちない。
- ゲームホストの `seat_reuse_ms` (同じ席の番号を別のページとみなすまでの時間) は、戻りの印がある前提で見直してよい (印で戻る限り同じ人)。変えるなら理由を report に書く。
- **互換**: 新しいページと古い門 (印を知らない)、古いページと新しい門 (印を送らない) は今どおり。新しいゲームホストと古い console も今どおり (卓の主の引き継ぎはゲームホストだけで動く)。

## 3. 作るもの

### asterism-console (0.3.9)

1. 門: 戻りの印を受け取り、部屋ごとに印→席を覚え、同じ印には同じ席を渡す (前の接続は切る)。印の長さ・形の検査、上限 (部屋の席の数を超えない)。部屋が閉じたら忘れる。
2. 試験、docs/rooms.md (入り直し)、CHANGELOG 0.3.9、VERSION、install の節。

### fmruby-core のブラウザ版のページ

1. 部屋ごとの戻りの印を localStorage に作って記憶し (部屋の ID か部屋の鍵のハッシュを索引に。鍵そのものは保存しない)、門への接続で渡す。部屋が終わった後の古い印は掃除する (例: 期限の過ぎたものを起動時に消す)。
2. `rake wasm:web` で作り直し、手元の一式で確かめる。

### asterism-games (0.16.2)

1. 卓の主の引き継ぎ (待ち合わせと対局中・結果・終局のどの状態でも)。設定 `owner_handover_seconds` (既定 60、0 で無効) を既存の設定の流儀で。log に一行。
2. 試験: 途切れて 60 秒で移る、座っている人を優先、誰もいなければ移らない、戻っても取り返さない、0 で無効。
3. README・CHANGELOG 0.16.2・VERSION・install。

## 4. 受け入れ条件

1. 3 つのリポジトリの試験 (console `bin/rails test`・rubocop、games `MJ_GAMES=4 bundle exec rake test`) が通る。fmruby-core の麻雀のはみ出し検査は触らないので今どおり。
2. 手元の一式 (console の deploy/local の門と部屋、games の一式、ブラウザ版 2 つ: 人間 2 + CPU 2) で:
   - 部屋で対局を始め、片方のタブを閉じ、同じブラウザ (同じプロファイル) で部屋のリンクを開き直すと、同じ席・同じ名前・(卓の主なら) 卓の主のまま、対局の続きに戻る。
   - 別のブラウザ (別のプロファイル) で開くと、今どおり別の人。
   - 卓の主のタブを閉じて開き直さないと、60 秒でもう一人に卓の主が移り、始める・CPU で埋めるができる。
   画面と log を report に写す。外の AI の API は呼ばない。

## 5. 範囲・決まり

- **触ってよいもの**: asterism-console (main)、asterism-games (main)、fmruby-core の `wasm/web/` と report。fmruby-core は develop に直接コミットしてよいが、**別のサブが同時に `flash/app/game/mahjong/` を編集している**ので、そこには触らず、コミットは自分のファイルだけを名前で指定する (`git add <path>`)。
- **触らないもの**: asterism・riichi_engine、fmruby-core のほかのコード (麻雀アプリを含む)、VPS、GitHub の設定、Tab5 (シリアル・WiFi)。
- 外の API を呼ばない。push・タグはしない。`git commit -a` は使わない。コミットの末尾は `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。実在の値の検査をしてからコミットする。
- 起こしたもの (deploy/local、games の一式、ブラウザ、試しの image と volume) は名前で止めて消す。前からある image は残す。docker の prune はしない。
- **止まる条件**: 1・2 章に無い仕様の選択が要る (例: 門の作りでは同じ席を渡せない、印をページから門へ渡す口が無い)。止まったら report に、ユーザが選べる形の選択肢 (推奨を先頭に) を書いて返す。
- **report** (`doc/ruby_asterism/report/gs10.md`、常体): 印の形と運び方、門の対応の持ち方、卓の主の引き継ぎ、受け入れ条件の結果と画面、互換、VPS の更新に要ること。
