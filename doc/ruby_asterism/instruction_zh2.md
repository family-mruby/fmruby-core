# ZH2 指示書: zenohd が新しいセッションを受けなくなったら console が起こし直す (console 0.3.2)

> 状態: 指示 | 更新: 2026-10-17 | zenohd 1.10.1 の行き詰まりへの、直った zenohd が入るまでのつなぎ (対策 3)。console が新しいセッションを開けるかを定期的に試し、開けなければ Apply と同じ道で zenohd を起こし直す。グラフの見え方は変えない

前提: report/zh1.md (bridge だけでは今と同じグラフが作れないと分かり止まった)、instruction_zh1.md 1 章 (行き詰まりの原因)、asterism-console の deploy/vps/zenohd/run.sh (`/generated/restart.request` が変わると zenohd を起こし直す)、bin/relay_restart_request と Apply の作り、lib/bridge/ (つなぎ直し、グラフ)、report/g1_5b.md (起こし直しで困らない作り: 端末・CRuby・ブラウザ版は数秒で戻る)。

言葉: 文書は常体。asterism-console の文書とコードのコメントは英語。

## 1. 決まっていること (2026-10-17 ユーザ)

- 根本の対策は zenohd の直し (上流への PR。取り込まれるまでは直した image)。別に進めている。
- bridge の問い合わせは今のまま (グラフの見え方は変えない)。
- それまでのつなぎとして、**新しいセッションが開けなくなったら zenohd を自動で起こし直す見張り**を console に入れる。

## 2. 作るもの

1. **見張り** (console の中。bridge の中の 1 つの仕事でも、別のプロセスでもよい。docker の権限は使わない):
   - 一定の間隔で、zenohd に **新しい** Zenoh のセッションを開いて閉じる (console の証明書で。今あるセッションを使い回すと行き詰まりを見逃す)。開くのに時間の上限を設ける。
   - 続けて決まった回数だけ失敗したら、Apply と同じ道 (`/generated/restart.request`) で zenohd を起こし直す。起こし直しの直後 (と console の Apply の直後、zenohd の起動を待っている間) は数えない。起こし直しが続くとき (例: 設定の誤りで zenohd が上がらない) は、間隔を広げて繰り返し要求しない。
   - 既定の値 (間隔・上限・回数) は、検出から起こし直しまでがおよそ 1 分以内になるように選ぶ (例: 30 秒ごと、上限 10 秒、2 回続けて失敗)。設定 (環境変数) で変えられ、0 で止められる。値は CHANGELOG と docs に書く。
   - 試しのセッションは、グラフにノードやセッションとして現れないようにする (bridge が自分のセッションを印で分けている作りに合わせる)。
   - 起こし直したときは、ログに理由 (失敗の回数と最後の誤り) を出し、Admin > Relay の画面に「最後に自動で起こし直した時刻と理由」を出す (画面の小さな追加。どの欄に出すかは任せる)。
2. **試験**: 失敗の数え方 (続けての回数、起動待ちを数えない、間隔の広げ方)、要求の書き方、設定 0 で止まること、を zenohd 無しで試す。
3. **文書**: CHANGELOG の 0.3.2 (zenohd 1.10.1 が止まる件の要点と、この見張り。VPS の更新は `./update.sh 0.3.2` だけ)、docs (install / relay のうち見張りに関わる所)。VERSION を 0.3.2 に。

## 3. 受け入れ条件

1. asterism-console の試験全部と rubocop が通る。
2. **起こし直しが効くこと**: 手元の構成 (deploy/local、zenohd は今の 1.10.1) で、bridge を動かしたまま接続・宣言・切断の負荷をかけて zenohd を行き詰まらせ (調べでは数分で止まる)、見張りが検出して起こし直し、新しいセッションがまた開けるようになることを、**少なくとも 3 回** 確かめる。止まってから戻るまでの時間を毎回出す。起こし直しのあと、ブラウザ版の部屋の席 (または CRuby の客) と bridge のグラフが戻ることも 1 回は確かめる。
3. **誤って起こし直さないこと**: 負荷なしで 30 分動かして自動の起こし直しが 0 回。console の Apply を 1 回して、その直後に見張りが余計な起こし直しをしない。
4. 試しのセッションがグラフに出ない (直す前と後で、負荷なしのグラフのノード・線の数が同じ)。
5. 移行が要らない (DB の変更なし)、`./update.sh 0.3.2` だけで上がる。
