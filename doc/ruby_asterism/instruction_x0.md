# Asterism X0 指示書: 言語によらない網の決まり (仕様の文書・決め直しの案・適合の試験)

> 状態: 指示 | 更新: 2026-10-12 | Asterism の網の決まり (キー・中身・例外・meta・生存の印・プロフィール) を、言語によらない仕様の文書に書き出す。Ruby に寄った形を洗い出し、決め直しの案を作る (決めるのはユーザ)。適合の試験の形を作る。この段では網の中身の形は変えない (決め直しは案まで)

前提: plan.md の「X0: 言語によらない網の決まり」と「Py」の節、asterism の README・docs/api_review.md・CHANGELOG・mrblib (asterism.rb・profile.rb など、決まりの実体)、lib/asterism/cruby/*、report/c8.md (1.0 に向けた API の残り)、report/v2_5.md (プロフィール)、report/g1b.md (`Asterism.session`)。

言葉: 文書では、Family mruby の基板・sim・ブラウザ版を「端末」と呼ぶ (「機体」は使わない)。仕様の文書は英語。

## 1. 作るもの

1. **仕様の文書** (asterism の `docs/protocol.md`、英語):
   - キーの形: `asterism/<ID>/<app>/<obj>/call|meta`、`@profile`、生存の印のキー、名前に使える文字と長さ。
   - 呼び出しと答えの中身: MessagePack の形 (今の実装が送っているものを、そのまま正確に書く)、引数・キーワード引数・戻り値、問い合わせの時間切れ、`depth` などの受け取りの扱い。
   - 例外の形 (今の `RemoteError` に渡っているもの)。
   - meta (公開しているメソッドの一覧) の形。
   - 生存の印 (ノード・アプリ・オブジェクト) の付け方と消え方。
   - プロフィール (V2.5) の形と上限 (PNG・8 KB・要約の計算)。
   - 使う Zenoh の機能の最低限 (query / queryable、liveliness の token と subscriber、put / subscribe) と Zenoh の版 (1.x)。
   - 書き方: 今の実装 (0.6.0) が実際にどうしているかを、実装を読み、網に流れる中身を実際に捕まえて確かめて書く (推測で書かない)。CRuby と mruby で違いがあれば書く。
2. **Ruby に寄った形の洗い出しと、決め直しの案** (同じ文書の付録か `docs/protocol_review.md`):
   - 位置の引数とキーワード引数の表し方、シンボルと文字列、Hash のキーの型、整数の範囲、小数と整数、時刻、nil・真偽・バイト列 (MessagePack の bin と str)、例外の種類の名前 (Ruby のクラス名) と詳細、メソッドの名前に使える文字 (`?` `!` `=` で終わる名前を他の言語でどう呼ぶか)。
   - それぞれ: 今の形、ほかの言語 (Python・TypeScript・C) で困ること、決め直しの案 (2 つ以上あれば並べる)、おすすめ、今の網 (0.x) との互換の扱い (両方を受ける期間など)。
   - **決まりの版**: meta かプロフィールに決まりの版を入れる案 (`protocol: 1` など)。違う版どうしの扱い。
   - **ここでは形を変えない**。案を書いて、ユーザが決めるのを待つ (決まった形の実装は次の段)。
3. **適合の試験** (asterism の `test/protocol/` などと、それを動かす rake の task):
   - 仕様の文書の各項目について、「この呼び出しをすると、網にこの中身が流れる」「この中身が来たら、こう答える」を、実装によらない形 (例: 期待する MessagePack のバイト列や、それを読んだ値を JSON などの言語によらない形で書いた見本の一覧) で持つ。
   - CRuby と mruby (今の `rake test:mruby` の仕組み) の両方で、その見本に沿っていることを確かめる。
   - ほかの言語の実装が、同じ見本で自分を確かめられる形にする (見本のファイルの形を docs に書く)。

## 2. 受け入れ条件

1. `docs/protocol.md` が、今の実装の網の決まりを漏れなく書いている (網に流れた中身と突き合わせた記録が report にある)。
2. Ruby に寄った形の一覧と、それぞれの決め直しの案とおすすめがある。ユーザが決めることの一覧がある。
3. 適合の試験が CRuby と mruby で通る。見本のファイルの形が docs にある。
4. asterism の既存のテスト (CRuby、`rake test:mruby`) が通る。網の中身の形は変わっていない (0.6.0 の端末・console と話せる)。

## 3. 範囲・決まり

- **asterism**: ブランチ `feature/protocol` にコミットのみ。push・タグ・gem の作成・公開はしない。版は上げない (形を変えないため)。
- **fmruby-core**: `doc/ruby_asterism/report/x0.md` だけ (develop にコミットのみ。**コミットは必ずファイルを指定する。`git commit -a` は使わない**)。
- **触らないもの**: asterism-zenoh・picoruby-asterism-zenoh (直しが要るなら差分を書いて返す)、console、端末、VPS。
- 網の中身を捕まえるのに zenohd や CRuby のノードを立ててよい。終わったら止める。
- **止まる条件**: 今の実装の決まりに、明らかな誤り (例: 実装どうしで食い違う、仕様として書けない振る舞い) が見つかったとき。直す前に案を書いて返す。
- **report**: Japanese plain style (常体)。書くこと: 仕様の文書の構成、捕まえた中身との突き合わせ、Ruby に寄った形の一覧と案 (要約)、ユーザが決めることの一覧、適合の試験の作り。
