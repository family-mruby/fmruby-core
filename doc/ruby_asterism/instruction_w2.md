> 状態: 指示 | 更新: 2026-10-09 | asterism-console にログインと呼べるメソッドの制限を足し (W2a)、その上にルータの台帳・証明書の発行・ACL の編集・クラウドの zenohd の設定の反映を作り、グラフに台帳を重ねる (W2b)

## W2a: 守り (先に)

1. **ログイン**:
   - Rails 8 の認証の生成 (`bin/rails generate authentication`) を基に、パスワードのログインを付ける。
   - 最初の管理者は `bin/rails` のタスクか seed で作る。パスワードはコマンドの引数でなく、入力か環境変数から受け取る。
   - 多要素 (TOTP) は、gem を 1 つ足すだけで済むなら入れる。重いなら W2 の後の課題として report に書く。
   - ログインしていない人には、グラフも値も操作も見せない (Action Cable も認証する)。
2. **呼べるメソッドの制限**: 画面から呼べるのは、許した組み合わせ (ノード/アプリ/オブジェクト/メソッドのパターン) だけにする。
   - 既定は「何も呼べない」。
   - 許すものは画面で編集できる (管理者のみ)。
   - 呼び出しの記録 (誰が、いつ、何を、結果) を残して見られるようにする。
3. **localhost 以外で待ち受けるときの扱い**:
   - 既定は 127.0.0.1 のまま。
   - 外で待ち受ける設定にしたときは、ログインが必須であることを確かめる (ログインを外す抜け道を作らない)。

## W2b: ルータの管理

1. **台帳**: ルータとクライアント (証明書の名前 = ACL の名前 = できればノードの ID) をモデルにする。
   - 種類 (router / client)、説明、許すキー (読み・書き)、管理用の空間の読み取りの可否、有効・無効、証明書の期限。
2. **証明書の発行**: W1 の `lib/relay/cert_authority.rb` を使う。
   - **CA の秘密鍵を Rails の中に置かない**: 署名だけを受け持つ別のプロセス (例: `bin/signer`。Unix ソケットか、手元の HTTP の 127.0.0.1 で、Rails からの署名の頼みだけを受ける) に分ける。CA の鍵はその置き場所だけにする (gitignore、0600)。
   - Rails が持つのは、発行の台帳 (名前、シリアル、期限、失効の印)。
   - 発行した証明書と鍵は、ダウンロードで一度だけ渡す (鍵を DB に残さない)。
3. **ACL と設定の生成**:
   - 台帳から、クラウドの zenohd の設定 (`cloud.json5` の ACL と TLS の部分) を作る。
   - 正は DB。手で書いたファイルとずれないよう、作ったファイルの先頭に「生成物」と書く。
4. **反映**:
   - 画面の「反映」で、設定を書き出して zenohd-cloud を起動し直す (docker compose の restart)。
   - 起動し直しの前後で何が切れるかを画面に出す。
   - 無効にした相手は ACL から外れ、期限 (と `close_link_on_expiration`) で切れる。1.10.1 に失効の一覧 (CRL) は無いので、この形でよい。
5. **グラフへの重ね合わせ**: 台帳の名前とグラフの点を照らし合わせ、色か印で分ける。
   - 登録済みでつながっている。
   - 登録済みだが来ていない。
   - 未登録。
   - 照らし合わせの鍵は、ノードの ID = 証明書の名前の決まりにそろえる (W1 の申し送り)。
6. **W1 で残ったこと**: クラウドを起動し直した後に、ROS 2 の生存のしるしが画面から消える件。
   - 原因を少し調べる。zenohd か rmw_zenoh の側なら、記録だけでよい。

## 受け入れ条件

1. ログインしないと何も見えず、何も呼べない (HTTP と Action Cable の両方)。試験がある。
2. 許していないメソッドは画面から呼べない。許したものは呼べる。呼び出しの記録が残る。試験がある。
3. 画面からクライアントを登録して証明書を発行し、その証明書で CRuby の examples/node.rb がクラウドにつながる。
   - 無効にして反映すると、つながれなくなる (または書けなくなる)。
4. 台帳とグラフの重ね合わせが、3 つの状態で正しく出る。headless のブラウザで撮って残す。
5. CA の秘密鍵が Rails のプロセスから読めない場所にある (signer だけが読む)。鍵や証明書がコミットされていない。
6. `bin/rails test` と rubocop が通る。README に、ログイン・signer・反映の使い方と、守りの前提を書く。

## 範囲・決まり

- **触ってよいもの**:
  - asterism-console (main にコミット、push してよい)。
  - 親リポジトリの `docker-compose.relay.yml` と `docker/zenoh-relay/` (生成の置き場の都合で要る変更だけ)。
  - fmruby-core の `doc/ruby_asterism/report/w2.md`。fmruby-core のブランチは develop から `feature/asterism-w2` を切る。
- **asterism / asterism-zenoh**: 直した場合は main にコミットしてよいが、push はしない。report に書く。
- **触らないもの**: 機体のファーム、fmruby-core のビルドの仕組み、`.env`、sdkconfig。
- **公開**: gem の公開はしない。
- **本当の値を書かない**: 本当の IP・機体の名前・MAC・鍵をコミットしない。
- **機体**: 機体は使わなくてもよい (CRuby と sim で足りる)。使う場合は P4-Nano (本当の IP は親が渡す)。
  - ミュート中。
  - 親のシリアルの capture が向いている (`serial_start` を呼ばない)。
- **終わったら**: 全部を止める。sim、zenohd、zenohd-cloud、ROS 2、Rails、bridge、signer。
- **止まる条件**:
  - 認証の仕組みで、Rails の標準の外の大きな依存が要るとき。
  - zenohd の設定の反映で、既存の compose の意味を変える必要があるとき。
- **report**: Japanese plain style (常体)。書くことは次のとおり。
  - 守りの作り (ログイン、制限、signer の分け方)。
  - 台帳と生成と反映の流れ。
  - 受け入れ条件の結果と画像のパス。
  - 残った課題 (多要素、動かしたままの反映など)。
