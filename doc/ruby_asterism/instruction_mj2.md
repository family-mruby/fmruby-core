# MJ2 指示書: 麻雀の Step 2 (人間 4 人の対局のデモ)

> 状態: 指示 | 更新: 2026-10-15 | 人間 4 人 (ブラウザ版と Tab5・P4-Nano を混ぜて) で 1 つの卓を囲み、半荘を打てるところまで作る。待ち合わせの画面、鳴きの割り込みの調停、途切れた人の扱いを足す。まずは家の LAN のルータで動かし、部屋 (G2) と VPS への配置は次のステップ

前提: report/mj1.md (Step 1 の作りと、9・10 章)、instruction_mj1.md、game_rooms_comparison.md の 3〜6 章 (部屋の係、手牌の守り方、ゲームホストの要件、卓のほかに要る画面)、asterism-games の README、game.md と othello (待ち合わせ・つなぎ直しの作り)。

言葉: 文書は常体、「端末」「確認」、作業の区切りは「Step」。技術の用語は例えにしない。

## 1. 決まっていること (2026-10-15 ユーザ)

- エンジンの細かいルールの問題で、遊ぶ流れに関わらないものは今は完全でなくてよい。4 人対戦のデモを早く動かすことを優先する。エンジンの品質向上は別の作業として後でやる (このステップでは、遊ぶ流れを止める誤りだけを直す)。
- 対象は Web 版 Family mruby・Tab5・P4-Nano (Retro は対象外)。卓は 640x360。
- 外への公開 (G2 の残り) は、麻雀がおおむねできてから。

## 2. 作るもの

1. **待ち合わせの画面** (卓のアプリの最初の画面): 卓に入っている人の一覧 (席・名前・つながっているか)、席に座る・立つ、空いた席を CPU で埋める (卓の主だけ)、始める (卓の主だけ、4 席がそろったら)。卓の主は最初に座った人 (ゲームホストが決める)。観戦は見えるだけの最小 (場だけ、手牌なし) でよい。ローカルルールの設定の画面は作らない (Step 3)。
2. **鳴きの割り込みの調停** (ゲームホスト): 捨て牌のあと、ロン・ポン・チー・明槓を選べる人間の席が複数あるとき、全員の答え (またはパス・時間切れ) を待ってから、優先順位 (ロン > ポン・槓 > チー、ロンが複数なら Step 1 で決めた頭はね) で決める。待ち時間は設定。人間に見せる選択肢は、エンジンが出す一覧のまま。
3. **途切れた人の扱い**: 途切れた席は、戻るまで待ち時間ごとに自動で打つ (ツモ切り・鳴きはパス)。戻ったら見え方を取り直して続ける。画面に「途切れている」印を出す。長く戻らない席を CPU に替える機能は入れない (仕様の選択なので、要るかは report に案として書く)。
4. **ゲームホスト**: 複数の卓 (少なくとも 2 卓同時) を持てる。終局で卓を待ち合わせに戻す (もう一回)。
5. 1 通の大きさ (4096 B 未満)、見え方の守り (他人の手牌が入らない)、起動し直して続けられることは Step 1 のまま守る。

## 3. 受け入れ条件

1. 家の LAN の構成 (手元の zenohd、ゲームホスト) で、人間 4 人が待ち合わせから座って始め、半荘を終局まで打てる。鳴きの割り込み (2 人以上が同時に選べる場面) を含む。エージェントの確認はブラウザ版 4 つでよい。Tab5 か P4-Nano を混ぜる確認はユーザに頼む手順を書く。画面の写しを report に。
2. 1 人が途中で切れても (ページを閉じる・ネットワークを切る) 卓は止まらず、戻ると続きから打てる。
3. 2 卓を同時に動かせる。ゲームホストの CPU とメモリを測る。
4. 1 通の最大バイト数、他人の手牌が入らないこと (4 人の人間で)、一覧にない操作を断ること、起動し直し (試験)。
5. fmruby-core の `rake test`・wasm のビルド・sim の標準構成の起動、asterism-games の試験が通る。

## 4. 範囲・決まり

- **触ってよいもの**: asterism-games (main、コミットのみ)、fmruby-core (`feature/mj2-mahjong`。MJ1 のブランチ `feature/mj1-mahjong` から作る。コミットのみ)、riichi_engine の手元の Fork (`fmrb` ブランチ。遊ぶ流れを止める誤りの直しだけ。push しない)。
- **触らないもの**: asterism・asterism-zenoh・picoruby-asterism-zenoh・asterism-console (読むだけ)、VPS、sdkconfig、`.env`。端末はアプリの区画を焼くか、遠隔の口でアプリのファイルを置くだけ (全体の焼き直しは /home を消すのでしない)。
- push しない。`git commit -a` は使わない。公開の文書・コミットに実在の IP・ドメイン・端末 ID・鍵を書かない (例は 192.0.2.x、fmruby-aaaaaa)。
- ユーザに見せるファイルは `C:\Users\Public\asterism_deploy\` の下だけ (直下にフォルダを作らない。画像は screenshots\mj2\)。
- **終わったら**: 起動したものを止める。fmruby-core の build/ は Linux の標準構成 (x86-64)、作業コピーは develop。
- **止まる条件**: 1 通が 4096 B に収まらない、ほかのリポジトリを直す必要が出た、遊び方 (仕様) を決める選択が要る。
- **report** (`doc/ruby_asterism/report/mj2.md`、常体): 作り (待ち合わせの呼び出しと配信、割り込みの調停の流れ、途切れの扱い)、受け入れ条件ごとの結果と数字、ユーザが端末で行う確認の手順、Step 3 (ローカルルールの設定・観戦の仕上げ・部屋と VPS への配置) への申し送り。
