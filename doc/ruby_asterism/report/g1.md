## 2. オセロの作り

### 2.1 オブジェクトとメソッド

- Asterism のアプリの名前は `game`、オブジェクトは `othello` (`asterism/<ノード>/game/othello`)。ほかのゲームも
  `game` の下に足せる。G0 の ACL の範囲 (`asterism/<ノード>/game/**`) に収まる。
- メソッド (game.md 1 章の表): `info`・`invite(from, name, gid)`・`answer(from, gid, accept, your_color, name)`・
  `cancel(from, gid)`・`move(from, gid, n, x, y)`・`resign(from, gid)`・`state`。呼ぶ側は最初の引数で自分の
  ノードの ID を渡す (gem は変えない。S4 の `from:` の件は未決のまま。こちらは位置引数にした)。
- 公開したメソッドは `Asterism.poll` (更新の 1 周) から呼ばれ、待たない。こちらから呼ぶものはすべて `async` で出し、
  次の周回以降で `done?` を見る。

### 2.2 待ち合わせ

- 生存の監視: `Asterism.on_join` / `on_leave` で印を付け、2 秒ごとと印が付いたときに `Asterism.each("*/game/othello")`
  で相手の一覧を作り直す。相手ごとの名前と様子は `info` を順に (1 つずつ、3 秒で一回り) 聞く。名前は profile の
  `name` があればそれ、無ければノードの ID。
- 誘う側が対局の ID (`<自分の ID>-<ミリ秒>`) を作って `invite`。相手は待っていれば `"asked"` を返して画面に出す。
  対局中・誘い中・答え待ちなら `"busy"`。受けると、受けた側が色を引き (黒が先)、`answer(..., true, 相手の色, 名前)`。
  誘った側は自分の誘いと合えば対局を始めて `true` を返し、受けた側はその `true` で始める。誘った側が取り消して
  いれば `false` (「誘いをやめていた」)。
- `answer` の答えが失われたとき (時間切れ) は、受けた側も始め、すぐ盤を合わせる (誘った側に対局が無ければ終わる)。
- 誘いの期限は 60 秒。誘った相手・誘ってきた相手が網から消えたら、その誘いは消える。

### 2.3 手の確かめ

`move(from, gid, n, x, y)` を受けた側は、次の順に確かめる。どれかに外れたら盤を変えずに理由を返す。

| 確かめ | 返す理由 |
|---|---|
| 対局の ID が今の対局か | `no game` |
| 呼んだのが今の相手か | `not your game` |
| 終わっていないか | `game over` |
| n (今までの手の数) が自分の数より小さい: 同じ位置の手が同じなら、答えの失われた再送として `ok` | `out of sync` |
| n が自分の数より大きい (自分が遅れている: 自分からも盤を合わせに行く) | `out of sync` |
| 相手の番か | `not your turn` |
| 置ける所か (パスは置ける所が無いときだけ) | `illegal` |

- 指す側も先に自分の盤で確かめ、置けない所は送らない (画面に「そこには置けない」)。手は相手が `ok` と答えて
  から自分の盤に置く。断られたか答えが無ければ、盤を合わせる (game.md 3.3)。
- PC から外れた手を送って確かめた (`fmrb_zenoh.rb call`): 相手の番の手は `not your turn`、関係ないノードからは
  `not your game`、違う対局は `no game`、置けない所は `illegal`、手の数の合わない手は `out of sync`。どれも盤は
  変わらなかった。画面からは、相手の番のクリックは何も起きず、埋まった升目は「そこには置けない」。

### 2.4 切れたとき

決め方は game.md 3.3 の表。待つのは 30 秒 (`GRACE_MS`)。相手の othello のオブジェクトが生存の一覧から消えたら
「相手が切れた」、自分の接続が切れたら 3 秒ごとにつなぎ直す。戻ったら `state` で手の並びを比べ、合えば続ける。
確かめたこと:

| 試し | 結果 |
|---|---|
| 対局中に zenohd を起動し直した (両方の接続が切れる) | sim は 3 秒後につなぎ直し、P4-Nano は「linux が戻った。盤を合わせる」。並びが同じで、そのまま 60 手まで指せた |
| 対局中に sim のアプリを止め、すぐ起動し直した | P4-Nano に「相手が切れた / あと 29 秒」。戻った sim には対局が無く、P4-Nano は「相手の対局が無くなったので終わり」(結果 `abandoned: linux lost the game`) |
| 対局中に P4-Nano のアプリを止め、そのまま | sim に 30 秒の数え下げ、31 秒後に「相手が戻らなかったので終わり」 |
| 対局中にブラウザ版のページを読み直した (同じ ID で、対局の無いアプリが戻る) | P4-Nano は「相手の対局が無くなったので終わり」 |
| 投了 (ブラウザ版 A で Esc → Enter) | 両方とも `white resigned`、相手の画面に「<名前> が投了した。あなたの勝ち」 |

### 2.5 状態の配信

手を指すたびに、対局の始めと終わりに、対局中は 10 秒ごとに、`asterism/<ノード>/game/othello/state` へ状態
(game.md 1 章) を MessagePack で `put` する。`state` の呼び出しも同じ Hash を返す。put には Asterism とは別の
Zenoh のセッションを使う (S4 と同じ。Asterism の公開の API に put が無いため)。

- ダークテーマ (ブラウザ版の束の既定) でも読めるよう、石の印の縁はテーマの枠の色にした。

## 6. ブラウザ版の合言葉

### 6.1 作り (fmruby-core)

- `wasm/web/index.html` の最初のスクリプトが、`#zenoh_pass=` (と古い形の `?zenoh_pass=`) を読み、すぐアドレスの
  欄から消す (`history.replaceState`。ほかの引数とフラグメントは残す)。値は `window.FMRB_ZENOH_PASS` に置き、
  `main.js` が取り込んで消す。`main.js` は `Module` (`moduleConfig.zenohPass`) に置き、起動の引数 (設定に
  持ち越されうる) には入れない。Network の枠に「pass: set for this visit (not kept, sent on wss:// only)」。
- 初めての訪問で coi-serviceworker がページを読み直すとき (公開の版、github.io)、`window.coi.doReload` を
  差し替えて、合言葉をフラグメントに戻してから読み直す。読み直したページがまた消す。
- `wasm/zenoh/zp_ws_emscripten.c` の `zp_ws_js_open`: `wss://` を選んだときだけ `?pass=<encodeURIComponent>` を足す。
  `ws://` (http のページ、ループバック) には付けない。URL は記録に出さない。
- `index.html` に `<meta name="referrer" content="strict-origin">`: 古い形 (`?zenoh_pass=`) で開いたとき、同じサーバ
  への後続の要求の Referer に合言葉が載っていた (確かめで見つけた) ので、Referer をオリジンだけにした。

### 6.2 途中で加わった決定 (2026-10-12 ユーザ) と asterism-console の直し

1. **フラグメント**: console の「Make a pass」のリンクを `...?zenoh=ws/<入口>#zenoh_pass=<合言葉>` にした
   (`PassLink.url`)。フラグメントはページを配るサーバに送られない。
2. **1 回きり**: 最初に通った `/passes/check` (204) が合言葉を使い終わりにする (`used_at`。「生きていて未使用」の行だけを
   書き換える UPDATE 1 つなので、同時の 2 つの確かめの片方だけが通る)。2 回目からは 401。期限・1 人 3 つまで・
   取り消しはそのまま。画面の様子は `used`。試験を足した (1 回目 204 と 2 回目 401、URI からの 2 回目、
   古い写しで競う 2 つ、使い終わりは「生きている数」に入らない、記録に合言葉が出ない)。
3. **接続の寿命**: nginx のプロキシの時間切れは「何も流れない時間」にしか効かず、Zenoh は数秒ごとに生存の
   知らせを流すので切れない。そこで入口と zenohd の間に小さな中継 `bin/ws_door` (サービス `door`、console の
   image の Ruby) を置き、接続ごとに `WS_DOOR_MAX_SECONDS` (既定 14400 = 4 時間) で両側を閉じる。zenohd の
   ws/ のポートは外 (ホスト) に出さず、`door` が nginx の向けるループバックのポートを持つ。長い対局は 4 時間で
   切れ、使う人は新しい合言葉で開き直す (手順書と docs/g0_w4.md に書いた)。
4. **入口で外す**: `asterism-router.conf` で、確かめの後 `rewrite ^ /? break;` で問い合わせの部分を落としてから
   渡す (確かめは書き換わらない `$request_uri` を読む)。`door` は受けた要求の行の道と「問い合わせが付いていたか」
   だけを記録する (問い合わせそのものは書かない)。

透過的に合言葉を取り直してつなぎ直す案 (作っていない): ページが console に「この接続の続き」を頼む口を持つ
(例: 使い終わった合言葉 + 短い期限の更新用の札を最初の 204 で返し、ページがそれで新しい合言葉を 1 つもらう)。
札を誰に渡すか (nginx の応答の頭か、console の別の口か) と、ログインしていないページに何を許すかが仕様の選択に
なるので、案に留めた。

## 7. 実時間の測り (G-RT、家の中)

### 7.1 作り

`flash/app/test/rt_probe.app.rb` (game.md 5 章)。自分の位置を毎秒 25 回 `put`、相手の点をそのまま描く。
往復は時計を比べずに測る (相手の送る位置に入った「最後に受けた自分の番号」と「受けてからの時間」を引く)。
1 秒ごとに数字を `asterism/<ノード>/game/rt/stats` へ配り、PC で集めた (スクラッチの道具) うえ、console でも
記録した。補間は 1 つだけ (`i` で、相手の点を 100 ms 遅らせて前後の 2 点の間に描く)。

- 測る前の版は、更新の毎周に `Asterism.poll` を呼んでいた。P4-Nano ではそれだけで 1 周 17 ms 前後かかり
  (8.2 節)、1 周が 42 ms、送れるのは毎秒 21 回だった。オブジェクトの層は stats の呼び出しに答えるだけなので、
  毎秒 10 回にした (流れのセッションは毎周)。下の数字はこの版。

## 8. 見立てと違った点・決めてほしいこと

### 8.1 1 回きりの合言葉と、2 つの接続を開くアプリ (決めてほしい)

ブラウザ版のアプリのうち、Asterism と別の Zenoh のセッションを持つもの (othello の状態の配信、rt_probe の流れ、
S4 の rover_pilot の ROS 2) は WebSocket を 2 つ開く。1 回きりの合言葉では 2 つ目が 401 になり、othello は
つながらない (通し稽古で確かめた: 1 つ目 101、2 つ目以降 401。アプリは 3 秒ごとにつなぎ直して 401 を重ねる)。
接続 1 つの asterism_demo は入れる。また、接続が切れたとき (4 時間、ルータの起動し直し、網の揺れ) のつなぎ直しも
すべて新しい合言葉が要る。案:

1. 合言葉を「最初に通ってから短い間 (例 30 秒)、同じ住所からなら何本でも」にする (console の確かめだけの直し)。
2. アプリを 1 つのセッションにする: gem の公開の API に put と subscribe を足す (例: `Asterism.session` を公開する。
   S4 でも挙がった件。公開済みの gem の直しになる)。
3. 1 つの合言葉で開ける数を決めて渡す (例: リンクに「2 本」と書き、console がその数まで通す)。

### 8.2 gem: `Asterism.poll` の重さ (端末で網が大きいと)

P4-Nano で測った (`Asterism.poll` と `Asterism.nodes` の時間、毎秒 20 回の平均): ノード 4・生きているオブジェクト 1 で
poll 6.6 ms (うち nodes 相当 2.8 ms)、ノード 5・オブジェクト 5 で poll 14.8 ms (nodes 7.9 ms)。`Asterism.poll` は毎回
`tell_nodes` で `nodes` を作り直し、`nodes` と `tell_nodes` は配列の `include?` を重ねて呼ぶ (PicoRuby では 1 回
1-2 ms)。生存の一覧が変わったときだけ作り直せば、変化の無い周回ではほぼ 0 になる見込み。差分の案 (gem は
変えていない):

```diff
   def self.tell_nodes
     known = @known
     return if known.nil?
+    # Nothing came on the liveliness watch since the last comparison.
+    return if @session && !@liveliness_changed
+    @liveliness_changed = false
     now = @session ? nodes : []
```

```diff
   def self.follow_liveliness
     w = @watch
     return unless w
     events = w.each_pending
+    @liveliness_changed = true if events.size > 0
```

(つないだとき・切れたときにも `@liveliness_changed = true` を立てる。`nodes` の中の `include?` を Hash に替えれば、
変化のあった周回も軽くなる。)

### 8.3 そのほか

- **合言葉の Referer**: 問い合わせの形で開くと、ページの後続の要求 (同じサーバ) の Referer に合言葉が載っていた。
  `strict-origin` で直した。フラグメントの形ならもともと載らない。
- **ページを配るサーバの記録**: 古い形 (`?zenoh_pass=`) は、そのサーバ (github.io なら GitHub) の要求の記録に残る。
  console のリンクはフラグメントの形にしたので、古い形は手で URL を作ったときだけ。
- **ブラウザの履歴**: アドレスの欄からは消えるが、ブラウザが「開いた URL」として履歴に残すのは開いたときの URL
  (フラグメントを含む)。合言葉は 1 回きりで 10 分の期限なので、残っても使えない。
- **ブラウザ版の WiFi の待ち**: 試しのアプリの「WiFi がつながるまで最大 20 秒待つ」は、ブラウザ版でも 20 秒待って
  いた (WiFi の情報が「つながっていない」を返す)。othello と rt_probe は端末 (esp32) のときだけ待つようにした。
  asterism_demo などは直していない (ブラウザ版で開いて 20 秒後につながる)。
- **AtomS3R の大きなアプリ**: 40 KB のソースは普通のプールでコンパイルできない。`large_memory = 1` で開けた。
- **ブラウザ版の束の ID**: MCP の web_down / web_up のたびにブラウザの保存領域が新しくなり、ノードの ID が変わった
  (`wasm-e7a00b` → `wasm-216cee` → `wasm-d62c3d`)。道具の使い方による。
- **P4-Nano のキーの注入**: 1 回、ロビーで Enter が 2 回届いたように見えた (誘いが出ていた)。再現しなかった。
