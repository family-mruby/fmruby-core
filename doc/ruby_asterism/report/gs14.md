## 2. キーと中身

### 2.1 キー

```
asterism/<host>/spectate/<卓>/state               常設の卓   (asterism/games/spectate/mahjong1/state)
asterism/<host>/spectate/room<slot>-<卓>/state    Room の卓  (asterism/games/spectate/room01-mahjong1/state)
```

- app の chunk を `spectate` にした (ホストの app `games` ではない)。プレーヤーの役割 `Read asterism/*/games/**` には当たらない。`match` の `asterism/*`・`asterism/*/game/**` にも当たらない。
- Room の卓は `room<slot>-<卓>` (1 chunk、protocol 2.1 の禁止文字なし)。常設の卓と Room の卓、Room 同士で重ならない。slot が別の Room に使われたら同じ名前になるが、前の Room のホストは止まっているので混ざらない。
- 値は MessagePack (state と同じ)。
- 流している間、ホストはその接続で liveliness token `asterism/<host>/spectate` を出す。CLI・MCP が「いるアプリの値」として扱う (MCP の `asterism_values` で `app: alive` を確認した)。

### 2.2 Room の卓は namespace の外へ (2 本目の接続)

Room のホストの接続は namespace `room/<slot>` 付きなので、その接続の put はすべて `room/<slot>/...` になり、Room の席に全部読まれる。そこで Room のホストは観戦用だけの 2 本目の接続を開く:

- `::Asterism::Zenoh.open(locator, credentials: <ホスト自身の .tar>)` (asterism 0.7.1 からある生の zenoh の接続。object 層の「1 プロセス 1 接続」とは別物)。namespace なしなので、キーは登録側に出る。
- 開くのはホスト自身の証明書のとき (`rooms.json` の `"hosts"` にホストがある、console 0.3.0 以降) だけ。`Rooms#child_config` が `spectate_outside` (= trust["own"]) と `spectate_label` (`room<slot>`) を渡す。slot の証明書 (console 0.3.0 より前) のときは開かず、何も put しない (その証明書は Room のもの)。
- 開くのはホストのループの、ロックの外 (`serve` の `open_spectate`)。失敗したら 30 秒ごとに試し直す。接続が切れたら (`down`) 閉じ、次の接続で開き直す。`spectate_view` を持つゲームが無い Room (オセロ・お絵かき) では開かない。
- 書く許可: 登録側での証明書 `games` の規則は役割 `games-host` のもの。今の `games-host` には `asterism/${node}/spectate/**` が無いので、手順書に 2 行 (`asterism/${node}/spectate`、`asterism/${node}/spectate/**`) を足した (console のコードの変更は要らない)。行が無いときはルータが put を捨てるだけで、ほかは何も変わらない (5.4 で確認)。

常設の卓 (と LAN のホスト) は今の接続 (`@net.session`) に put する。

### 2.3 麻雀の中身

`look` が席の無いメンバーに返す「言葉の卓」(`look_view(-1)`) から `you` と `moves` を除き、各席に `hand` (ツモ牌を除いた並べた手) と `drawn` (ツモ牌、無ければ null) を足し、`delay_s` を足したもの。手牌は観戦者メンバーの view の `sh` / `sd` と同じ (試験で一致を確認)。

- 入るもの: 席 (名前、種別 human/cpu/ai/empty、風、点数、立直、河、立直宣言牌の位置、鳴かれた牌の位置、鳴き、手牌の枚数、手牌、ツモ牌)、局 (場風、局、本場、供託、親、残り枚数、手番、局面)、めくれたドラ表示牌、最後の打牌、局の結果 (和了の役・翻・符・点・手)、終局の順位、ルール、`delay_s`。
- 入らないもの: 山の並び、裏ドラ表示牌、まだめくれていないドラ表示牌、メンバーの node ID・token、誰が鳴けるか (`dl` を含まない)、合法手。試験はキーの名前 (`token node wall yama ura uradora seed haipai rinshan ...`) と、token・node ID の文字列が無いことを見る。
- 形を「言葉の卓」にした理由: 卓アプリ用の短いキーと牌のバイト列 (`sh` は bin) は、CLI・MCP の JSON では `"(14 bytes)"` としか出ない。観戦用の読み手は管理者・観戦者・見るだけの AI なので、`look` と同じ読める形にした (範囲は今の観戦の view と同じ。2 章の「同じ範囲」に従い、形は report で決めた)。AI 席の考え中の状態は入れていない (入れてよいが要らなかった)。
- 局が終わったあとの結果の役には「裏ドラ 1」のように裏ドラの数が出る。これは和了のあと公開の state (`res` の `y`) にも出ている既存の公開情報で、裏ドラの表示牌そのものではない。

## 3. 遅れの扱い

**「ためて順に出す」にした。** 

- ホストは卓の state を put するとき (変化のあとと 5 秒ごと) に `spectate_view(now)` を取り、前と同じバイト列なら捨て、違えば `[時刻, バイト列]` を卓ごとの列に足す。
- 毎ステップ、列の先頭から「`now - 時刻 >= spectate_delay_ms`」のものを順に全部 put する。遅れ 0 ならその場で出る。最後に出したものは 5 秒ごとに出し直す (後から購読した人が 5 秒以内に受け取る)。
- 麻雀の `spectate_delay_ms` は卓の観戦の遅れ (`spectator_delay_ms`: 設定 `spectator_delay_minutes`、または持ち主がロビーで選んだ値。既定 0)。`spectate_view` 自体は「今」の様子 (遅らせない) で、遅らせるのはホストの列だけ。卓の中の観戦者の view (`@spec_hist` による遅れ) は変えていない。
- 漏れが起きない理由: 列を通らずに出る道が無い。局の区切りも、次の局の配牌も、同じ列に入り、遅れが経つまで出ない。遅れを短くすると (ロビーで選び直す) 古いものから今の遅れを満たした分がまとめて出る。長くすると出るのが止まる。どちらも「遅れより早く出る」ことは無い。
- ホストを起動し直すと列は空 (保存しない)。遅れの間は何も出ない。
- 列は卓ごとに 8 MB まで。超えたら古いものから捨てる (出さないだけで、早く出すことは無い)。遅れ 5 分・1 秒に 2 回の変化・1.4 KB で約 0.8 MB。

試験 (`test_the_delay`): 遅れ 3 秒・CPU 4 人の卓をホストで 60 秒回し、出た put のすべてが「その sv が卓に初めて現れてから 3 秒以上あと」、sv が昇順、局の結果 (`status: result`) も遅れて出る、最初の put は 3 秒より後、をすべて確認。遅れ 0 はその場で出る。

## 6. 役割の書き方 (console の手順書に載せたもの)

docs/rooms.md「Watching the tables from outside (asterism-games 0.18.0)」:

- `games-host` に Read and write の 2 行を足す: `asterism/${node}/spectate`、`asterism/${node}/spectate/**` (「A game host's permanent tables」の役割の囲みにも足した)。Room のホストも同じ行なので、Room の卓の分もこれで足りる。
- 観戦の役割 `spectator` (Admin > Members > Roles, "New role"):

  ```
  Read             asterism/*/spectate
                   asterism/*/spectate/**
  Watch            asterism/**
  Browsers have this role: no
  ```

  人ごとに行を作る (Register、kind `client`、名前は例えば `spectator-a`、"Issue a certificate"、"Save all (.tar)")、Apply。書けない・呼べない。**ブラウザには付けない** (ブラウザは 1 つの subject なので、パスを持つ全員、つまりプレーヤーにも手牌が見える)。プレーヤーの行にも付けない。
- viewer (docs/g1_5.md) は `asterism/**` を読むのでそのまま読める (CLI と MCP)。docs/g1_5.md に「viewer は観戦用のキーを読むので管理者だけに」と一行足した。ai-viewer (`read asterism/**`) も同じ。

## 8. 気づいたこと

- Room のホストは観戦用にルータへの接続を 1 本増やす (Room ごとに 1 本、麻雀の Room だけ)。console の `max_sessions` は 96 (G2)。Room 3 つで 3 本増える。
- 観戦用の接続は object 層の外 (生の zenoh) なので、console の図ではその接続に node の名前が付かない (liveliness token `asterism/games/spectate` が app `spectate` として出るはず。図は撮っていない)。
- console の作業コピーで `bin/rails test` を走らせると、隣の asterism の作業コピー (0.10.0) を見て `Gemfile.lock` が書き換わる。今回は戻してコミットに含めていない。

## 9. 後片付け

手元のホスト 2 つは pid で止めた (どちらも `stopped (state saved)` / 最後のログ)。CLI の echo はすべて `--duration` で終わった。console の deploy/local は `VOLUMES=1 rehearse down` で container・volume・network を消し、`deploy/local/.env` と `certs/` を消し、作った image `asterism-console-rehearsal:0.3.10` を消した。scratchpad の証明書 (.tar)・管理者のパスワード・卓の保存は消した。前からある image (`asterism-console-rehearsal:0.3.2`、`eclipse/zenoh:1.10.1`、nginx ほか) は残した。docker の prune はしていない。`~/asterism_keys/` は使っていない。VPS・GitHub の設定・Tab5・asterism / asterism-zenoh / riichi_engine / fmruby-core のコードには触っていない。外の AI の API は呼んでいない。
