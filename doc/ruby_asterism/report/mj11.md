## 2. 作り

- 音の部品は `mahjong_sound.rb` に置いた。本体 (`mahjong.app.rb`) は 64 KB の上限の近く (62,682 B → 62,943 B) なので、足したのは `on_create` の読み込みと開始、`save_assist` の 1 行、一覧と待ち合わせのボタンの呼び出しだけ。部品は本体のメソッドのいくつか (`take_view`・`round_tick`・`leave_table`・`on_update`・`lobby_key`・`list_key`・`run_button`・`stop`・`on_destroy`) を alias で包むので、クラスの本体の後 (`on_create`) で読む。振り返り (`mahjong_replay.rb`) は後から読まれて、包んだものをさらに包む (今までの順序のまま)。Retro の画面 (`@unsupported`) は読まない。
- 効果音・ジングルは `FmrbAudio#note_on` / `note_off` (APU の SUB: 矩形波 2 つ・三角波・ノイズ)。音を始めるのは出来事のときだけ (新しい view が前と違う、結果のカウントが 1 段進む)。2 つ目以降の音符は壁時計 (ms) の期限として持ち、`on_update` の最後 (描画の後) の `snd_tick` が期限の来たものを送る。待ちが空なら `snd_tick` は何もせず返る。鳴っている間は `on_update` の戻り値 (次の呼び出しまでの ms) を次の音符までに縮める (最短 5 ms)。最初の音符も描画の後に送るので、描画の長さで最初の音が伸びない (blockgame の流儀)。
- 重なったときの扱い: 音は使う通り道 (チャンネル) を取る。優先度 (1 打牌・ツモの短い音、2 自分の番・役のカウント、3 ジングル・局の始まり・点数、4 ファンファーレ) の高い音がまだ鳴っている通り道は取らない (その声部だけ省く)。同じ優先度なら新しい音が勝ち、世代番号で古い音の残りの音符を捨てる。
- ブラウザ版の最初の操作までの無音: アプリはふだんどおり送るだけ (ページが鳴らさない)。落ちる経路は無い。
- `FmrbMidi::MmlPlayer` は使っていない (SUB を使うので効果音とぶつかる)。

### 2.1 出来事との結び付け

| 出来事 | 見るもの | 音 |

- 卓に入った最初の view は数えない (古い出来事)。

周波数は Hz (ノイズは周期の番号 0-15)、長さは設計上の値 (ms)。P1/P2 は矩形波 (duty 1 = 25%、2 = 50%)、T は三角波、N はノイズ。

### 2.3 声 (WAV) への差し替えの口

- ジングルの名前 (`riichi` `pon` `chi` `kan` `ron` `tsumo` `kyuushu` `ryuukyoku`) ごとに WAV の場所を持てる。`VOICE` (定数、既定はすべて nil) か、`/home/mahjong.toml` の `voice_riichi = "/home/voice/riichi.wav"` など。
- 場所があれば `FmrbAudio#play_wav` を先に試し、鳴らせたらジングルは鳴らさない。Retro (play_wav が false) と失敗したときはジングルに戻る。WAV の形は play_wav の決まり (PCM 16bit・モノラル・8-48 kHz・2 MB まで、一度に 1 本)。

## 3. BGM の口

- 場面: `:lobby` (卓の一覧と待ち合わせ、アプリの開始時)、`:play` (対局中と結果)、`:tense` (任意: 誰かがリーチしている、または残り `TENSE_LEFT` = 10 枚以下。曲が無ければ `:play` の曲のまま)、`:none` (終局。ファンファーレだけを鳴らす。待ち合わせに戻ると `:lobby`)。
- 場面は view が変わったとき (`take_view`) と卓を出たとき (`leave_table`) に決め、変わったときだけ切り替える。同じ曲なら何もしない。
- 曲: `.nsf` は `FmrbAudio#play(path, track:)`、それ以外は FMSQ として `load_fmsq_file(slot)` + `play_slot(slot, instance: MAIN)`。どちらも先に `sync_file` で `/cache/app/mahjong/bgm_<場面>.<拡張子>` へ写す (sim・Retro は音の側が別のファイルシステム。blockgame と同じ)。FMSQ の枠は機械全体で共有なので 12・13・14 を使い (`BGM_SLOT`)、各枠は初めて使うときに 1 回だけ読む。
- 曲の置き場所と場面の対応:
  - アプリの定数 `BGM = { lobby: nil, play: nil, tense: nil }` に `["/usr/share/music/mj_lobby.fmsq", 0]` (NSF ならトラック番号) を書く (配布する曲を入れるとき)。
  - または `/home/mahjong.toml` に `bgm_lobby = "/home/music/lobby.fmsq"`、`bgm_play = "..."`、`bgm_tense = "..."`、NSF のトラックは `bgm_play_track = 2` (端末ごとの差し替え。定数より勝つ)。
- 曲が無い場面は鳴らさない (今の既定はすべて無音)。

## 4. 入り切り

- 卓の一覧: 上の行の「閉じる」の左に `BGM 入[B]` `効果音 入[E]` (名前のボタンはその分だけ縮む)。待ち合わせ: 640x360 と 1280x720 は名前の行の下の行、426x240 はアシストのボタンの右 (名前のボタンが縮む)。クリックか B・E キーで入⇔切。名前の入力中はキーを奪わない。ジングルは効果音に含む。
- 記憶: `/home/mahjong.toml` に `bgm = true|false`、`se = true|false` (既定は両方 true)。アシスト・名前と同じファイルで、`save_assist` が書く (アプリ側で設定した曲・声の行も書き戻して残す)。
- BGM を切ると曲を止め (`FmrbAudio#stop`)、入れると今の場面の曲から始める。効果音を切ると、待っている音符を捨てて 4 つの通り道を止め、WAV も止める。
- 閉じたとき: `stop` (閉じるボタン・Ctrl+Q・カーネルの stop はすべてここを通る) と `on_destroy` で BGM・効果音・WAV を止める。端末全体の音量・ミュートには触らない。

## 5. 受け入れ条件

### 5.1 はみ出し検査

`rake mahjong:overflow`: 225 drawings, 0 failed, 49 warnings (426x240 だけ)。足した場面は `lobby_owner/sound_off` (両方切)、`lobby_member/list_sound_off` (一覧、両方切)、`lobby_member/list_searching` (卓が見つからない一覧) の 3 つ x 3 解像度。警告が 1 つ増えたのは `lobby_owner/sound_off` が `lobby_owner` と同じ前からの警告 (426x240 のルールの 1 行) を持つため。検査は `mahjong_sound.rb` を本体の後に読み、FmrbApp の代わりに `stop` を足した。`rake test` も通った (golden 103 ほか)。

### 5.2 音の数値 (Linux の sim、標準構成 Modern、x86-64)

確認の経路: sim (`sim_up`) の卓のアプリを、手元のゲームホスト (`tools/mahjong_local.rb up`、作業用の設定: 東風、持ち時間 2 秒で銀行 0、鳴き 2 秒、CPU 400 ms、状態は作業用の場所) の卓に座らせ、CPU 3 人と対局させた (自分の席は時間切れで自動の打牌)。音は `tools/fmrb_audio_probe.rb --dump` で WAV に採り、作業用の Ruby (Goertzel で周波数ごとの強さ、1 次差分で高い音の立ち上がり) で読んだ。アプリのログには鳴らした音の名前を 1 行ずつ出している (`mahjong: sfx <名前>`、`mahjong: bgm <場面> <場所>`)。

BGM の試しには自作の仮の曲 (MML 3 行: 三角波で 1 音を 4 分音符で繰り返す。待ち合わせ 220 Hz、対局 277 Hz、緊張 349 Hz) を `tool/mml2fmsq.rb` で FMSQ にし、sim の `/home` (git の外) に置いて `/home/mahjong.toml` の `bgm_*` で指定した。曲は配布物に入れていない (確認の後に消し、sim の `/home/mahjong.toml` も元に戻した)。

| 確認 | 結果 |
|---|---|
| 待ち合わせの BGM | アプリの起動から 220 Hz の持続音 (peak 1,503、RMS 523) |
| BGM の場面の切替 | 240 秒の採録を 1 秒ごとに 220/277/349 Hz の強さで分けると「220 → 277 → 349 → 277 → 349 → 277」。ログの `bgm lobby → play → tense (リーチ) → play (次の局) → tense → play` と同じ順 |
| 効果音の数 | 同じ採録で、高い音の立ち上がり (20 ms 窓、BGM の床の +60) が 242 回。ログの音 336 回のうち、100 ms 以上離れた始まりの数は 239 (打牌・ツモ・自分の番がほぼ同時に重なるため)。数が合う |
| 局の始まり | ログの時刻のところで 523 Hz、続いて三角波 131 Hz・262 Hz が出る (RMS 523 → 870) |
| 打牌・ツモ・自分の番 | 最初の 3 つの打牌の時刻に 20-60 ms のノイズの山 (1 次差分 105 → 260)、自分の番の時刻に約 380 ms の山 (ツモ 70 + 遅れ + 自分の番 190) |
| ポン | 1568 Hz が 60 ms、休み、また 1568 Hz (その後に鳴いた人の番の 1047 → 1568) |
| 結果のカウント | ログで ロン → 1 秒後に yaku → 1 秒ごとに yaku → points (役 2 つ・3 つ・4 つの和了で各 1 回、計 11 回の yaku と 4 回の points)。採録の上でも point の時刻に 131 Hz の三角波が出る |
| 流局 | 三角波 131 → 98 Hz、最後に 523 Hz (約 0.9 秒) |
| 終局のファンファーレ (4 位) | 終局の view で BGM (349 Hz) が止まり、三角波 110 Hz、最後に 415 Hz の 0.5 秒、そのあと無音 (約 1.15 秒) |
| リーチ・チー・カン・ロン・ツモ・九種九牌 | ログに出た (リーチ 3、チー 3、カン 1、ロン 2+、ツモ 2)。九種九牌は対局では出なかったので CRuby の試し (5.3) で確認 |
| 振り返り | 一覧の「直近の結果」で 1 手ずつ 8 回進めて、打牌の 4 回だけ `sfx discard_other` |

- 注意: 採録 (probe の共有メモリの読み) は実時間より約 9% 長く溜まる (240 秒で 262.75 秒ぶん)。そのため 1 つ 1 つの音の時刻はずれて合わせにくく、上の照合は数と順と周波数で行った。
- 音量と官能 (うるさすぎないか、BGM との釣り合い) はユーザが確認する。

### 5.3 CRuby の試し (出来事 → 音の対応)

作業用のスクリプト (はみ出し検査の読み込みを使い、FmrbAudio を記録する代わりに差し替え、作り物の view を順に渡す) で、待ち合わせ → 配牌 (局の名前) → 自分の番 → 自分の打牌 → ほかの打牌 → ポン → リーチ (緊張の場面) → ツモと自分の番 → 自分のロンと役 3 つ (yaku 3 回・points 1 回) → 次の局 → 流局 → 九種九牌 → 終局 3 位 (fanfare3) → 待ち合わせ、を確認した。BGM は場面どおりに sync・load・play (NSF はトラック番号つき)。切替で `/home/mahjong.toml` に `bgm = false` / `se = false` と曲の行が書き戻され、効果音を切った後の打牌は鳴らず、`stop` で `stop` と 4 つの `note_off` を送る。

### 5.4 入り切りと停止 (sim)

| 確認 | 結果 |
|---|---|
| 一覧で B | BGM が止まる (peak 0)、ファイルに `bgm = false` |
| アプリを開き直す | ボタンが「BGM 切」のまま、無音のまま |
| ボタンのクリックで入 | 220 Hz が戻る |
| 効果音を切って対局 (25 秒) | 立ち上がり 0 回、ログに sfx 0 行、BGM (277 Hz) は鳴り続ける |
| 閉じる: Ctrl+Q / 閉じるボタン / カーネルの kill (`sim_app kill`) | どれも閉じる前は peak 1,183-1,274、閉じた後は peak 0 |

- 標準構成の決まりどおり、確認の最後にエディタを開いて 1 打鍵 (`Ln 1, Col 2 *`)。
- core のログの誤りは 1 件: 最初の起動の `bgm lobby: undefined method 'to_i' for NilClass` (picoruby の nil に to_i が無い)。直してから確認をやり直した (曲のトラックと、念のためリーチのビット・振り返りの手の番号の nil を型で見るようにした)。

## 6. 残ったこと・注意

- Tab5 の実機は触っていない (親が確認する)。実機ではスピーカーの小ささと音量の段 (audio_output.md) で聞こえ方が変わる。
- BGM の曲は未定。決まったら 3 章の手順で差し込む。配布する曲を入れるときは flash/ の決まり (追跡分 = 配布してよいもの) と ASSETS の流儀に従う。
- FMSQ の枠 12-14 は機械全体で共有。ほかのアプリが同じ番号を使うと、次に開いたとき読み直す (アプリの開始ごとに読む) ので困らないが、同時に使うとぶつかる。
- 打牌の音は view ごと: 1 回の view の間に 2 つ打牌があっても 1 回しか鳴らない (CPU が速いとき)。
- 持ち時間の警告は指示どおり入れていない。
