## 3. 0.4.0

### 3.1 3 つのリポジトリに共通の仕組み

- **非推奨の仕組み**: `Asterism.deprecated(old, instead, why)` が 1 つ。名前ごとに 1 回だけ警告する (CRuby は `warn`、機体は `warn` が無ければ `puts`。機体では VM ごとに 1 回)。`Asterism.deprecations = :warn / :raise / :silent`、環境変数 `ASTERISM_DEPRECATIONS`。`:raise` は `Asterism::DeprecationError` (`Asterism::Error` の下)。
- これは Zenoh の束ね (binding) の側に置いた。asterism-zenoh の `lib/asterism/zenoh/common.rb` と picoruby-asterism-zenoh の `mrblib/common.rb` は**同じファイル** (cmp で一致)。asterism は束ねに依存しているので、どちらの Ruby でもこれを使う。
- **時間の決まり**: 単位の無い名前は秒 (`timeout:`・`connect_timeout:`・`check_timeout:`)、それ以外は単位を名前に持つ (`timeout_ms:`)。時間を 2 回渡すと `ArgumentError`。共通の関数 `Asterism.time_ms` が、秒・ミリ秒・古い位置引数を 1 つのミリ秒にする。
- **試験**: 3 つとも試験は非推奨を例外にして回す (helper と CI の `ASTERISM_DEPRECATIONS: raise`)。古い形の試験だけ一時的に `:warn` にして、警告が 1 回出ることを見る。

直した不具合:

- **小数の時間制限の切り捨て**: 位置引数のミリ秒に Float が来ると、ミリ秒として切り捨てる旨 (`2.0 waits 2 ms`) と `timeout: (seconds)` を案内する警告を出す。値の扱いは今までどおり (壊さない)。
- **`ros2_talker.app.rb` の整数の割り算**: `every(PUBLISH_EVERY_MS / 1000)` を `every(ms: PUBLISH_EVERY_MS)` にした。
- **時間制限と同じ名前のフィールド**: `request:` キーワード (と、前からの Hash の位置引数) で要求を渡し、時間制限は `timeout:` で渡せる。ポーリングの層 (機体) で `timeout:` という名前のフィールドがあるときは、0.3.0 と同じくフィールドとして扱い、警告する (0.3.0 では機体の `timeout:` はフィールドだったので、そのまま時間制限にすると黙って意味が変わるため)。CRuby の層の `node.call` の `timeout:` は前から時間制限なので、そのまま時間制限。

### 3.3 定数の古い名前の扱い

`Asterism::Timeout` を定数の別名にすると、`module Asterism` の中で Ruby の `Timeout` を隠したまま (N8)、しかも警告できない。そこで定数を置かず、`Asterism.const_missing` (と `ROS.const_missing`) で `:Timeout` のときだけ警告して `TimeoutError` を返す形にした。`rescue Asterism::Timeout` は今までどおり捕まえる。`module Asterism` の中の `Timeout` は Ruby の `::Timeout` になる (CRuby の試験で確かめた)。機体の VM でも `const_missing` は効いた。P4-Nano で使い捨ての試し (コミットしていない。確かめた後に消した) を走らせ、`Asterism::Timeout == TimeoutError` と `ROS::Timeout == ROS::TimeoutError` が true、警告がそれぞれ 1 回、エラーの木 (`ROS::TimeoutError < TimeoutError`、`Zenoh::Error < Asterism::Error`、`ClosedError < Zenoh::Error`)、`BACKEND` が `zenoh_pico`・`VERSION` が `0.4.0`、`Session.open(config: {})` が説明つきの `ArgumentError` になることを見た。

### 3.4 0.4.0 に入れず 1.0 に回したもの (壊れるため)

- D7 (1 引数の `reply` をブロックの層と同じ意味に): 振る舞いが変わるので、0.4.0 は答えが変わる場合だけ警告する。queryable のキーにワイルドカードがあるときは変わらないので警告しない。
- R1 (`each { }` の戻り値): 文書に書いただけ (決定 6 のとおり警告も無し)。
- L4 (ROS が閉じたとき `Disconnected`): 0.4.0 は `Zenoh::ClosedError` (`Zenoh::Error` の下なので古い rescue も捕まえる)。
- U6 の機体側: zenoh-pico の接続の時間制限はビルド時の定数なので、機体は `connect_timeout:` を `ArgumentError` にした (黙って無視しない)。

- ROS の層が閉じたとき `Disconnected` を出す (L4)。
- `Asterism.each { }` / `net.each { }` の戻り値を Ruby の慣習に (R1)。
- 内部のメソッドを隠すか接頭辞を付ける (X2)。`ServiceFailed` を私的に。
- 要求のフィールドと時間のキーワードが重なるときの扱いを決める (`ArgumentError` にするか)。
- 1.0 の前に: YARD の reference の生成 (X3。今は注釈に単位を書いただけ)、fmruby-core の試しのアプリ以外の機体のアプリが古い形を使っていないかの確認、`zenoh_nodes.app.rb` の `peers` (警告の確かめ用にわざと残した) を直すこと。

## 8. 気づいたこと

- 機体の C で受け取る引数は今までどおり位置引数のままにし、キーワードは束ねの Ruby (`common.rb`) で受けて C に渡す形にした。両方の束ねで同じ Ruby のファイルになり、C の変更は小さく済んだ (エラーの系統、`code`、`connection_count`、query の queryable キー)。
- fmruby-core の `rake setup` は picoruby-asterism-zenoh の決まったファイルだけを写していたので、`mrblib/` を写す 1 行を足した (無い古い版でも動くようにしてある)。
- 機体のログでは、非推奨の警告は `puts` で出る (ESP のログの書式の外、`asterism: ...` の 1 行)。
- 互換構成と P4 を同じ日に比べるため、P4 は 2 回焼いた (基準と新しい版)。app_only の 1 回は 115200 baud で約 5 分 30 秒。
