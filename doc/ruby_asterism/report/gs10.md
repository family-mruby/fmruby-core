# GS10 報告: 部屋に入り直せる (同じブラウザは同じ人、卓の主の引き継ぎ、人のいない卓の対局を終える)

> 状態: 完了 (検収待ち) | 更新: 2026-10-19 | 同じブラウザで部屋のリンクを開き直すと、同じ席 (同じノード ID) に戻り、席・名前・卓の主・対局の続きがそのまま戻る。卓の主が 60 秒途切れると、つながっている人に卓の主が移る。追加 (2026-10-18 ユーザ決定) で、対局中に人間が全員いなくなった卓は 3 分で対局を捨てて待ち合わせに戻る (記録しない)。asterism-console 0.3.9 (ee7b432)、asterism-games 0.16.2 (eb66cc3)、fmruby-core のブラウザ版のページ (wasm/web/main.js)

## 1. 何が起きていたか

読んで分かったこと:

- 門 (console 0.3.0 から) は、ページの秘密 (32 桁 16 進) のハッシュから席を引く表をすでに持っていた。同じ秘密なら部屋が終わるまで同じ席を渡す。ページも秘密を localStorage に部屋の ID で保存していた。
- ただしページは、`/home` の錠を持つタブ (最初のタブ) だけが秘密を保存し、2 つ目のタブは保存しない使い捨ての秘密を作っていた。同じブラウザで 2 人目のタブを閉じて開き直すと、錠を持たないので新しい秘密になり、別の人 (別の席) として入る。前の席は「途切れ」のまま残る。報告された症状はこれで説明がつく。
- 門は同じ席に接続が 2 本あっても何もしなかった。閉じたタブの接続が残っていると (通信が途中で切れた場合など)、ゲームホストからは同じノードが 2 つ見え、古い方の lease が切れたときに戻った人まで「途切れ」になる。

## 2. 戻りの印の形と運び方

- **印 = 今ある部屋の秘密**。新しい値は作らない。16 バイトの乱数 (32 桁 16 進)、ブラウザが部屋ごとに作る。
- **保存**: localStorage の `fmrb_room_secret_<部屋の ID>` に `{"s": 秘密, "exp": 部屋の終わり (Unix 秒)}`。索引は部屋の ID (16 桁 16 進、rooms.json にも出る秘密でない値)。部屋の鍵は保存しない。**どのタブも同じ印を使う** (`/home` の錠と切り離した)。GS10 より前の形 (秘密だけの文字列) は、今の部屋のものは読んで新しい形に書き直す。
- **掃除**: ページの起動時に (部屋のリンクでなくても) `fmrb_room_secret_*` と `fmrb_room_holder_*` を見て、今の部屋以外で終わりが過ぎたもの・終わりの無いもの (GS10 より前の形) を消す。
- **運び方**: 今どおり、席の要求 `POST /room/seat` の本文と、WebSocket の最初の Text `{"s": ...}` だけ。URL・ヘッダ・ログには出ない (門のログはハッシュも出さない。試験で確認)。
- **後から開いたタブが席を取る**: タブごとの乱数の ID (秘密ではない) を、席を要求する**前に** `fmrb_room_holder_<部屋の ID>` に書く。古いタブは、門に 4403 で切られて席を取り直そうとしたとき (`reseat`) にここが自分の ID でなければ、つなぎ直しをやめて「the room was opened in another tab of this browser, which has this seat now. Reload this page to take it back.」と出す。取り返しはしない (再読み込みすれば取り返せる)。

## 3. 門の対応の持ち方 (console 0.3.9)

- 対応表は 0.3.0 からの席の表のまま: 部屋ごとに SHA-256("<部屋の ID>:<秘密>") → 席。部屋が開いているあいだだけ持ち、部屋が終われば 1 秒以内に消える。門の volume のファイルに書くので門の再起動では消えない (消えた場合は今どおり空いている席を渡す)。1 席に 1 件なので部屋の席の数を超えない。印の長さ・形の検査は 0.3.0 の `SECRET` (32 桁 16 進) のまま。
- **切る時点は「席の要求で同じ印が見つかったとき」にした**。最初は WebSocket が同じ席で開いたときに古い接続を切る形で書いたが、ページは 1 つの席に最大 4 本のセッション (docs/rooms.md「Seats」) を持ち、ルータの再起動後のつなぎ直しも席の要求なしで来るため、それだと自分のセッションどうしを切り合う。ページは起動時に 1 回だけ席を要求する (と、4403 を受けたときの取り直し) ので、「同じ印の席の要求 = 新しいページ」と見なせる。その席に残っている接続を全部切ってから答える。
- 切り方: zenohd 側の TLS をすぐ閉じる (zenohd に同じノードが 2 つ並ばない)。ページには close 4403 ("taken by a newer page") を送り、その後ページが送ってくるものは読み捨て、ページの close か最大 4 秒 (LINGER × 2) で閉じる。リセットにしないので nginx の error log に鍵が残らない (手元で error log の `room` 0 件を確認)。ログ: `seat 03: closing a connection from <addr> (a newer page took the seat with its secret)`。
- 席が別の人に渡っていたとき (印を覚えていない、seat_idle で別の印に渡った): 今どおり空いている席、それも無ければ 30 分接続の無い席、それも無ければ 409。

## 4. seat_reuse_ms の見直し

**変えない (30 分のまま)**。理由: 門は、席を別の印に渡すのを「誰も接続していない状態が `WS_DOOR_SEAT_IDLE` (30 分) 続いた席」に限っている。ゲームホストはノード ID しか見えず、席が別の人に渡ったかを知る手段が無いので、`seat_reuse_ms` が門の 30 分より長いと、新しい人が前の人の席と手牌を受け継いでしまう。印で戻る限り 30 分以内なら同じ人として戻れるので、戻りの印があっても短くする理由も長くする理由も無い。また、今回の卓の主の引き継ぎ (60 秒) と、人のいない卓の対局を捨てる (3 分) で、長く途切れた人が卓を止める問題は別の形で片付く。README「Who joins」、game.rb のコメント、CHANGELOG にこの理由を書いた。

## 5. 卓の主の引き継ぎ (games 0.16.2)

- 設定 `owner_handover_seconds` / `MAHJONG_OWNER_HANDOVER_SECONDS` (既定 60、0 で無効)。表の秒・環境の秒 → ms の既存の流儀 (`settings file:/env:`)。
- 卓の主が途切れて (ノードが網を出た、または `away_seconds` 呼ばない) から 60 秒たつと、**つながっている**人間の参加者に移す。席に座っている人を優先 (座った順)、いなければ入った順。誰もいなければ移さず、誰かがつながった時点で移す。待ち合わせ・対局中・結果・終局のどの状態でも同じ (tick で見る)。
- 前の卓の主が戻っても取り返さない。log: `the owner wasm-0102 was away for 60 s: wasm-0103 is the owner now`。
- 卓の主が抜けたとき (`leave`・`stand`) の既存の `pass_owner` (座っている人だけ) はそのまま。

## 6. 人のいない卓の対局を終える (games 0.16.2、追加の指示)

- 設定 `abandon_seconds` / `MAHJONG_ABANDON_SECONDS` (既定 180、0 で無効)。
- 対局中 (`play`・`result`) に、席の人間が誰も数えられなくなったら対局を捨てる。数えるのは: つながっている人、途切れて 180 秒未満の人。卓を出た人 (`leave`) はその時点で席が CPU になるので、すぐ数えない。
- 捨てると: 待ち合わせに戻る (終局のあとと同じ `to_lobby`)。CPU・AI の席は残し、途切れた人間は席から外す (参加者のまま観戦になり、また座れる)。卓の主はつながっていればそのまま、いなければ `pass_owner` (座っている人がいないので次に座った人)。途中の対局の記録は捨てる (`@rec = nil`。記録帳に入らないので成績にも出ない)。log: `game abandoned: no human there for 180 s (seats [1, 2] emptied; not recorded)`。
- `humans: 0` の卓 (CPU だけの常設の観戦卓) は対象外。3 分以内に 1 人でも戻れば対局は続く (他の途切れた席は今どおり代打ち)。

## 9. 互換

- **新しいページ + 古い門** (0.3.8 以前): 同じ印に同じ席を渡すのは 0.3.0 から同じなので、開き直すと同じ人に戻る。古い接続は切られず、自分で終わるのを待つ (閉じたタブなら普通はすぐ)。2 つ目のタブは同じ席で並び、古いタブは止まらない (今と同じく同じノードが 2 つ)。
- **古いページ + 新しい門**: 古いページは錠を持つタブだけが印を保存していたので、そのタブの開き直しは同じ席 (古い接続があれば切る)、2 つ目のタブは今どおり別の人。
- **移行の間の端**: 古いページのタブ (錠を持つ、印を保存) を開いたまま、同じブラウザで新しいページのタブを開くと、新しいタブは保存された印を読んで同じ席を取り、古いタブを切る。古いページは 4403 で席を取り直すので、互いに切り合うことがある (つなぎ直しの間隔で)。古いタブを閉じるか再読み込みすれば止まる。配布後に開きっぱなしの古いタブだけの話なので、作りは変えていない。
- **新しいゲームホスト + 古い console**: 卓の主の引き継ぎと対局を捨てるのはゲームホストだけで動く。常設の卓・LAN の卓でも同じ (`humans: 0` の観戦卓は対象外)。
- 新しい console + 古いゲームホスト: 開き直しは同じ席・同じノードなので、古いホストでも同じ参加者として戻る。

## 11. 範囲の外で気づいたこと

- 仕様の選択が要る点は無かった (止まる条件に当たらない)。切る時点を「WebSocket」ではなく「席の要求」にしたのは 2 章の「同じ印で新しい接続が来たら前の接続を切る」の実現の仕方で、1 ページが複数のセッションを持つ作りに合わせたもの (3 章)。
- 卓の主が観戦者に移ることがある (座っている人がいないとき、入った順)。待ち合わせなら座れば始められる。対局中の観戦者の卓の主はすることが無いが、終局の「次へ」は over_ms で自動で進むので止まらない。
