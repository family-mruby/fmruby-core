# V2.3 報告: ROS 2 のノードを機械ごとに畳む

> 状態: 完了 (検収待ち) | 更新: 2026-10-11 | instruction_v2_3.md の実装と確認の記録。asterism-console の網の図で、接続元の IP が同じ ROS 2 のノード (2 つ以上) を 1 つの点 (「ROS 2 machine」) に畳む。既定で畳み、詳細の欄の「Open / Fold」で開閉し、開閉の状態はブラウザに覚えさせる。名前は既定で IP、管理者が詳細の欄から名前を付けられ、名前は console の DB にメンバーのノード名の組と一緒に置く。巻き戻しの図も同じ畳み方で、名前は今の DB のものを使う。MuJoCo の台車・P4-Nano の ROS 2 のアプリ・sim の asterism_demo で確かめ、台車のコンテナを作り直して IP が変わっても名前が残ることを実際の IP を比べて確かめた。止まる条件には当たらなかった。asterism-console は main に push 済 (447eb7b)

## 1. 塊の組み立て (どこで何を作るか)

- **bridge の側で作る**。`lib/bridge/groups.rb` の `Bridge::Groups.apply(graph, names:)` が、to_h の形のグラフから塊の部品を足す純粋な関数。V2.1 の `Bridge::Connections` (ノードの `connections` を作る) の後、V2.2 の `Bridge::Marks` の前に置き、3 つを `Bridge::Graph.derive` でつないだ。`Graph#to_h` の最後と、巻き戻しの `RecordingsController#graph` がこれを呼ぶ。足したものを外してから足すので何度かけても同じで、V2.3 より前の記録も同じ畳み方になる。
- 塊の決め方:
  - ROS 2 のノードの Session のアドレス (`connections` の `address`、例 `tcp/[::ffff:172.20.0.3]:43764`) から IP を取り出す。IPv4 を写した IPv6 (`::ffff:`) は IPv4 にする。Session が複数あるノードは最初のものの IP。
  - 同じ IP の ROS 2 のノードが 2 つ以上あれば塊にする。1 つなら今のまま。Asterism のノードは対象外。
- 足す部品:

| 部品 | 中身 |
|---|---|
| `r_group` のノード | `r_group:<IP>`、層は `ros`。ラベル `<名前か IP> (N ROS 2 nodes)`。data: `ip`、`members` (ノードの ID)、`member_names` (ROS 2 のノード名)、名前が当たれば `name`・`name_id`・`named_members`、メンバーの `services`・`clients`・`unmatched` を合わせたもの (各項目に `node`)、`connections` (メンバーの Session を 1 つずつ)、`internal_topics` (塊の中どうしのトピック) |
| メンバーの data `group` | 塊の ID |
| 畳んだ写しの辺 | メンバーに触れる `topic_link`・`attach`・`publishes`・`subscribes`・`carries`・`peer_link` の辺の、メンバーを塊に置き換えた写し (`folded: true`)。塊どうしの辺は畳み方の組ごと (A だけ・B だけ・両方) に写しを作る。両端が同じ塊に入る写しは作らない。同じ両端の写しはまとめる (トピック、Session と役) |

- ページ (`console_controller.js`) は見せ方を選ぶだけ: 畳んだ塊は塊の点を、開いた塊はメンバーを見せる。辺は両端が見えているときだけ見える (V2.1 からの決まり) ので、正しい写しが自然に選ばれる。
- **塊の中どうしの矢印**: 畳んでいる間は描かない (指示書の 2 案のうち)。自己ループは「どこからどこへ」が読めず、台車では 12 本ほどが 1 つの点に重なる。中のトピックは詳細の「Topics inside」に出す。「Topics as nodes」でも、出す側と受ける側がすべて 1 つの畳んだ塊の中にあるトピックは描かない。
- 見た目: 塊はノードより大きな紫の角丸の四角に、外側にもう 1 本の紫の輪 (cytoscape の outline)。紫のままにしたのは ROS 2 の仲間だから (V2.2 の色の決まり)。数の印はメンバーのものを合算する (台車で services 95、相手のいないトピック 21)。
- 開くと、メンバーは V2.3 より前の描き方に戻り、箱で囲まない (V2.1 で箱は図を壊した)。初めて開くときはメンバーを塊のあった場所に輪に並べ、ほかを止めて短く配置し直す。それ以後は置いた場所を覚える。開閉の状態は `localStorage` (`asterism.console.openGroups`) に、名前があれば名前の ID、無ければ IP で覚える (名前があれば IP が変わっても開いたまま)。

## 2. 名前の照合の決め方

- 名前は console の DB (`MachineName`: `name`、`members` = ノード名の JSON 配列、`created_by`) に置き、利用者全員で共有する。IP には結び付けない。
- **付けられるのは管理者だけ**。W2 の作りでは、全員に効く設定 (呼べるメソッドの許可表、台帳) は管理者が変え、全員が読む。名前も全員の図に出るので同じにした (`MachineNamesController`、`require_admin`)。管理者でない利用者には「An admin can give this machine a name」と出す。
- 名前を付けると、そのときの塊のノード名の組を一緒に置く。付け直すと組も今のものに取り直す。消すと IP の表示に戻る。
- **重なりの決め方**: 塊のノード名の組を M、名前の組を N として、共通の数が大きい方の組の半分以上 (`2 * |M ∩ N| >= max(|M|, |N|)`) なら当たりとする。指示書の例「半分以上が一致」を、両方向で効くように「大きい方の半分」にした。ノードが大きく増えた塊 (別の機械と混ざった) も、名前のノードの多くが消えた塊も、名前を失って IP に戻る。
- 複数の名前と塊が当たりうるときは、重なりの近い組 (Jaccard、`|M ∩ N| / |M ∪ N|`) から順に決め、同点は新しい名前を先にする。1 つの名前は 1 つの塊にしか付けない (同じ台車を 2 台つないだら、片方は名前、もう片方は IP で出る)。1 つの塊にも名前は 1 つ。
- bridge は名前を管理空間と一緒に 2 秒ごとに読む。付けた名前は数秒で差分として全員の図に出る。

## 4. 残った課題

- **NAT の向こうは 1 台に見える**。Docker Desktop が公開した 7447 から入る LAN の機器は、どれも Docker の網のゲートウェイ (`172.20.0.1`) から来る。P4-Nano のほかに ROS 2 の機体が WiFi にあれば、2 台が 1 つの塊に畳まれる。console の bridge の Session も同じ IP から来るが、Asterism のノードなので対象外。ルータを host の網で動かすか、機体が自分の IP を名乗る仕組み (gem の範囲) が要る。
- 名前は管理者だけが付けられる。利用者ごとの呼び名 (ブラウザに置く) は作っていない。
- 塊の中の矢印は畳んでいる間は描かない。「中で何が流れているか」は詳細の「Topics inside」でしか分からない。
- 開いたときのメンバーの置き場所は、初めは塊の周りの輪から fcose で整える。台車のように線の多い塊では、開いた後の図は V2.2 と同じく込み合う (「Lay out again」で全体を置き直せる)。
- 写しを撮るため rails を一時的に `0.0.0.0` で上げ直した (headless の Chromium がコンテナから来るため)。終わりに 127.0.0.1:3000 に戻した。台車のコンテナは IP を変える確認のために作り直した (IP は `172.20.0.7` のまま動いている)。名前 `mujoco` は開発用 DB に残した。
