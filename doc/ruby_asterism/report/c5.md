## 2. API の一覧

どれも CRuby だけで、`require "asterism"` で入る。時間はこの層では秒で数える (ポーリングの API はミリ秒のまま)。

### 2.1 Zenoh (`Asterism::Zenoh`)

| 呼び出し | 内容 |
|---|---|
| `Asterism::Zenoh.open(locator, mode:, listen:, interval: 0.002) { \|s\| }` | `Session.open` を `Asterism::Zenoh::Connection` で包む。ブロックを抜けたら閉じ、ブロックの値を返す。ブロック無しなら Connection を返す |
| `Connection.new(session)` | ポーリングの API で開いたセッションを包む |
| `s.put(key, payload, attachment:)` | String でない payload は `to_s` で送る |
| `s.subscribe(key, depth: 16) { \|sample\| }` | 受け取りのスレッドで `Sample` を渡す |
| `s.subscribe(key)` (ブロック無し) | `each(timeout: nil)` が届くのを待つ Enumerator (Enumerable を持つ)、`each_pending` は今ある分を Sample で返す |
| `s.queryable(key) { \|q\| }` | ブロックを抜けたら問い合わせを終える。`q.reply(payload)` は queryable 自身の鍵 (ワイルドカードが無いとき) で答える。ブロック無しなら `each` |
| `s.get(key, timeout: 2.0, ...)` | 全部届くか時間切れまでの `Reply` の Enumerator (列挙のたびに送り直す)。ブロックありなら数を返す |
| `s.liveliness_watch(key) { \|key, alive\| }` / ブロック無しなら `each` が `Liveliness` | |
| `s.liveliness_get(key, timeout:)` | 今いる鍵の配列 |
| `s.start` / `stop` / `run` / `running?` / `on_error { \|e, where\| }` | `run` は呼んだスレッドで回し、`stop`・切断・Ctrl-C で戻る |

`Sample`・`Reply` (`key`、`payload`、`attachment`、`text`) と `Liveliness` (`key`、`alive?`) は `Data` なので、そのままパターンマッチできる。

```ruby
Asterism::Zenoh.open("tcp/192.0.2.2:7447") do |s|
  s.subscribe("home/**") { |sample| puts "#{sample.key} = #{sample.payload}" }
  s.queryable("home/pc/status") { |q| q.reply("ok") }
  s.get("home/**/status").each { |reply| p reply }
  s.subscribe("sensor/temp").each.lazy.map { _1.payload.to_f }.first(3)
  case sample
  in { key: %r{/temp\z}, payload: } then p payload.to_f
  end
  s.run
end
```

### 2.2 オブジェクトの網 (`Asterism`)

| 呼び出し | 内容 |
|---|---|
| `Asterism.connect(...) { \|net\| }` | `Asterism::Net` を渡し、抜けたら `Asterism.close`。ブロック無しは今どおり (`Asterism` を返す) |
| `Asterism.net` | ブロック無しで繋いだときの Net (つながっていなければ nil) |
| `net.expose` / `unexpose` / `exposed` | 公開したメソッドは受け取りのスレッド (または `run`、またはポーリングしている所) で動く |
| `net[path, timeout: nil]` (`proxy`) | 代理 (秒) |
| `net.each(pattern)` | 今いる代理の Enumerator (`net.each("*/demo/info").map(&:status)`) |
| `net.on_join { \|node\| }` / `net.on_leave { \|node\| }` | 機体が現れた / 去った。接続の直後は、すでにいる機体が最初の数回の tick で現れる。接続が切れたら、知っていた機体が全部去る |
| `net.start` / `stop` / `run` / `running?` / `on_error` / `nodes` / `connected?` / `close` | 公開したメソッドが raise したら、今どおり呼んだ側に RemoteError で返る (on_error には来ない) |

```ruby
Asterism.connect("tcp/192.0.2.2:7447", node: "mypc", app: "demo") do |net|
  net.expose("screen", Screen.new, methods: [:say])
  net.on_join { |node| puts "joined #{node}" }
  net.start
  net["fmruby-aaaaaa/demo/screen"].say("hello")
  net.run
end
```

### 2.3 ROS 2 (`Asterism::ROS`)

| 呼び出し | 内容 |
|---|---|
| `Asterism::ROS.connect(locator, domain: 0, type_path: nil, ...) { \|ros\| }` | `Asterism::ROS::Connection`。`type_path:` は `TYPE_PATH` に足す置き場所 |
| `ros.node(name, namespace:, enclave:)` | 共有の `Asterism::ROS::Node` に下の呼び出しを足したもの (Node の今の呼び出しはそのまま) |
| `node.subscribe(topic, type) { \|msg, info\| }` | 受け取りのスレッドで呼ぶ。ブロック無しなら `each` が待つ Enumerator |
| `node.topic(topic, type).each` | 列挙の間だけ購読し、終わったら取り下げる |
| `node.every(sec) { }` | タイマー。`Timer#cancel`・`fired`。周期を保ち、長く止まった後は取りこぼしをまとめて撃たず今から数え直す |
| `node.service(name, type) { \|req\| }` | 回している間に答える。ブロックが raise したら on_error に渡し、その要求には答えない |
| `node.call(name, type, timeout: 2.0, **fields)` | 答えを待つ。ほかのスレッドから呼んでもよい |
| `node.publisher(...)`、`pub << msg` | 発行は接続の錠を取る (タイマーとアプリが同時に出しても順番が乱れない) |
| `ros.spin` (`run`) / `start` / `stop` / `on_error` / `close` / `ros.zenoh` | `ros.zenoh` は下の Zenoh の Connection (同じ受け取りのスレッド) |

メッセージと `Attachment` に `deconstruct_keys` を足した (CRuby 専用のファイルで、共有のクラスの定義は書き換えていない)。

```ruby
Asterism::ROS.connect("tcp/192.0.2.2:7447") do |ros|
  node = ros.node("ruby_talker")
  chatter = node.publisher("/chatter", "std_msgs/msg/String")
  node.subscribe("/cmd_vel_in", "geometry_msgs/msg/Twist") do |msg|
    case msg
    in { linear: { x: }, angular: { z: } } then puts "forward #{x}, turn #{z}"
    end
  end
  node.every(1.0) { chatter << { data: Time.now.to_s } }
  node.service("/cruby/add_two_ints", "example_interfaces/srv/AddTwoInts") { |req| { sum: req.a + req.b } }
  p node.call("/add_two_ints", "example_interfaces/srv/AddTwoInts", a: 1, b: 2).sum
  ros.spin
end
```

同梱に無い型は `tools/asterism_msggen.rb -o DIR` で作り、`type_path: "DIR"` か `Asterism::ROS::TYPE_PATH << "DIR"` で置き場所を渡す (README に書いた)。

## 3. スレッドの形と錠

- **受け取りのループは `Asterism::Runner` 1 つにまとめた**。セッションごとに 1 つ。中身は「tick ごとに呼ぶ小さな proc (task)」の並び。task は今の `each_pending` / `poll` で取り出してアプリのブロックに渡す。zenoh-c のコールバックは今どおり Ruby に触らない (C1 の作りのまま)。
  - `start` は専用のスレッドを 1 本作る (使う人が呼んだときだけ)。`run` は呼んだスレッドで回す (Ctrl-C は Interrupt を受けて nil で戻る)。`stop` は今の tick が終わってから止め、ほかのスレッドから呼べばスレッドの終わりを `join` で待つ。受け取りのスレッドの中から呼べば印だけ付ける。
  - 何も届かなかった tick の後は 2 ms 眠る (`interval:`)。
  - セッションが閉じた (切断を含む) ら task が false を返し、ループが終わる。待っているスレッドを起こす。
- **錠**: Runner は `Monitor` を 1 つ持ち、tick はそれを握って回す。
  - オブジェクトの網は 1 プロセスに 1 接続で状態が `Asterism` モジュールにあるので、錠もプロセスに 1 つ (`Asterism::LOCK`)。`Asterism` の特異クラスに `prepend` した `Asterism::Locked` が、`poll`・`expose`・`unexpose`・`[]`・`call_async`・`meta`・`nodes`・`each`・`connected?`・`exposed`・`connect`・`close` をこの錠で包む。`each` は一覧を錠の中で作り、ブロックは錠の外で呼ぶ (ブロックの中で呼び出しができるように)。`Future#done?` も錠の中で見る。
  - ROS と Zenoh は接続ごとの錠。ROS ではノードを変える呼び出し (publisher・subscription・service・client・close) と発行が錠を取る。
  - **待つ呼び出し**: `Asterism.wait_until` (proxy の呼び出しの待ち) と `ROS::Client#wait_for` (サービスの待ち) を CRuby の層で包んだ。受け取りのスレッドが動いていて、呼んだのがそのスレッドでないときは、自分で poll せず Runner の条件変数で tick を待ち、tick のたびに錠の中で「答えが来たか」を見る。受け取りのスレッドの中 (ブロックが呼び出しをする場合) と、受け取りのスレッドが動いていないときは、今どおり自分で poll する (入れ子の数え方も今どおり)。待っている間に受け取りが止まったら、自分で poll する形に移る (切断ならそこで今どおりの例外になる)。
  - `close` は錠を取る前に受け取りのスレッドを止める (tick の中にいるスレッドを錠を持ったまま `join` すると止まり合うため)。
- **ROS のサービスを複数のスレッドから呼ぶ**: 共有の `Client#call_async` は `@sequence += 1` と、それを読んで要求に付け Call に覚えさせるまでの間に GVL が切り替わりうる。2 本のスレッドが同じ番号を付けて答えを取り違え、「nobody serves it」で落ちた (試験で見つけた)。CRuby の層で `call_async` を Mutex で包んだ。
- **ブロックの中で重い処理をすると、その接続のほかの受け取りが遅れる**。README の「Threads」に書いた (長い仕事は自分のスレッドか Queue に渡す)。
- Enumerator (`each`、`get`、`topic`) は、列挙するスレッドで待つ (受け取りのスレッドを要らない。zenoh-c が裏で受けているので、取り出すだけでよい)。

## 4. asterism-zenoh の修正 (小さいもの)

受け取りのスレッドとアプリのスレッドが同じセッションを使うと、閉じる瞬間に危ない所があった。

- 前: `close` (または切断の検出) は GVL を手放してから、op_lock の中で `open = false` にして zenoh-c のセッションを落としていた。その間に GVL を取ったほかのスレッドが、古い `open == true` を見て `z_info_routers_zid` などで落としかけのセッションに触れうる (解放後の使用)。
- 後: `open` (Ruby から見た状態) は GVL を握ったまま false にしてから GVL を手放す。GVL を手放して呼ぶ put・get は、別の印 `live` を op_lock の中で見る。これで、閉じ始めたら Ruby のほかのスレッドは必ず「閉じている」を見て `Asterism::Zenoh::Error` になる。
- 前の版で、5 本のスレッドから put・poll・liveliness・get・each_pending をしながら閉じる試しを 900 回回しても落ちなかった (窓が狭い)。理屈で直した。直した後の試験 `test_threads.rb` は 30 回 (相手を閉じる / 自分を閉じるを交互) と、1 つの購読を 2 本で取り合って 100 通がちょうど 1 回ずつ取れることを見る。
- Ruby の呼び出し・引数・戻り値は変えていない。README の「1 つのセッションは 1 本のスレッドから」を「複数のスレッドから使ってよい」に改めた。

## 7. 機体側 (mruby) に持っていける部分の提案

C5 では入れていない。

1. **`deconstruct_keys`** (Message、Attachment): メソッドを 1 つ足すだけなので、機体の VM (PicoRuby / mruby) で `case/in` が使えるなら共有の層にそのまま移せる。使えるかどうかは確かめていない (先に確かめる)。
2. **`node.every(sec) { }`** とタイマー: ブロックを持つが、呼ぶのは `node.poll` の中だけにすれば機体の「更新ごとに poll」の形に合う。時計は `Asterism.now_ms` を使う。
3. **ROS の `node.subscribe(topic, type) { }`**: 同じく `node.poll` の中で呼ぶ形なら機体でも成り立つ。ただし C から呼ぶブロックはスタックを食う (README の Stack の節) ので、Ruby の while で回す今の書き方を守る。
4. **on_join / on_leave**: 共有の層はすでに liveliness を `@nodes` / `@alive` に追っているので、`Asterism.poll` の中で差を取って呼ぶ形にできる。
5. **`Client#call_async` の番号の取り違え**: 機体は 1 本のスレッドなので起きないが、`@sequence` を一度だけ読んでローカルに持つ形に共有の層を直せば、CRuby の Mutex が要らなくなる (動きは変わらない)。
6. **`Asterism::Zenoh::Sample` のような値**: 機体には `Data` も `Struct` も無い (R3) ので、配列のままが軽い。持っていかないほうがよい。

受け取りのスレッド・条件変数・Enumerator は CRuby だけのままにする。

## 8. 見立てと違った点・踏んだ罠

- **名前がぶつかった**: 最初、包むほうのクラスを `Asterism::Zenoh::Queryable` と名付けたら、C 拡張の同じ名前のクラスを開き直してしまい、今の試験 (ROS のサービスの close) が落ちた。包むほうは `Connection::Subscription` / `Queryable` / `Watch` の入れ子にした。
- **`super(pattern)` もブロックを渡す**: `each` の上書きで引数を付けた `super` が暗にブロックを渡し、錠の中でブロックが走った。`super(pattern, &nil)` にした。
- **peer の接続では on_leave が来ない**: 相手が唯一の peer のとき、去ると自分のセッションも閉じるので、liveliness の「去った」は届かない。接続が切れたら知っていた機体を全部去らせることにした。
- **queryable の答えの鍵**: `q.reply("ok")` は問い合わせの鍵 (`c5/z/**` のようなワイルドカード) で答える (C 拡張のまま)。ブロックの API では queryable 自身の鍵で答えるようにした (ワイルドカードの無いとき)。ポーリングの API は今どおり。
- **共有の Client は複数スレッドを想定していない** (3 章)。
- Ruby のハッシュのパターンは Symbol の鍵だけなので、オブジェクトの網の戻り値 (MessagePack から来る String の鍵) には `in {"board" => ...}` が書けない。例では `values_at` の配列で受けた。
