## 2. つなぎ直しの層の選び方

指示書の 3 つの候補を順に調べた。

- **zenoh-pico の `Z_FEATURE_AUTO_RECONNECT`**: 1.10.1 では、ひとつのスレッドの実行器 (executor) の上でも働く。lease・keep-alive・読みの task が失敗すると `_zp_unicast_failed_result` が送り手の道を閉じ、つなぎ直しの task (`_z_client_reopen_task_fn`) を spawn する。つなぎ直しは 1 秒ごとに 1 回 `_z_open` を試し、通ったら宣言の控え (`_declaration_cache`: subscriber・queryable・liveliness の印と監視の interest) を全部送り直す。`Asterism::Zenoh` の Ruby のオブジェクトはそのまま使える。
  - ただし zenoh-pico の client の読みは「相手が閉じた」と「まだ何も無い」を区別しないので、そのままでは lease 切れ (10 秒) か keep-alive の失敗 (最大 3.3 秒) まで気づかない。gem はもともと poll のたびにソケットが閉じたかを見ている (`zp_tcp_socket_closed`) ので、閉じていたら閉じる代わりに `_zp_unicast_failed_result(&s->_tp._transport._unicast, &s->_runtime)` を呼び、すぐ zenoh-pico の失敗の道に渡すようにした。
- **gem (Ruby) でつなぎ直す**: Asterism の印・queryable・監視は付け直せるが、アプリが `Asterism.session` に宣言したもの (オセロの状態の配信、ROS 2 のノード) は付け直せず、「アプリが意識しなくてよい」にならない。
- **zenoh-c**: client は自分でつなぎ直し、宣言も戻る (2.2 で測った)。asterism-zenoh が「ルータが 0 になったら閉じる」をしていたのでやめた。

選んだ層: **Zenoh の部品の層** (zenoh-pico の機能と zenoh-c の素の振る舞い)。CRuby と mruby で同じ形 (セッションは閉じない、`reconnecting?` が真、終われば元どおり) になり、アプリが `Asterism.session` に宣言したものも戻る。

- 動いている間に増えるもの: 宣言の控え (宣言 1 つにつきメッセージの写し) と、つなぎ直しの task の handle。どちらも zenoh-pico の割り当て (`z_malloc`) で、ESP-IDF では gem の port が PSRAM から取る (`ports/esp32/zp_system_esp32.c`)。transport の構造体に増える task の handle 5 つもセッションの中 (PSRAM) にある。

- 周期のダンプ (`fmrb_task:` の stack high-water、`IRAM free:`) での確かめは、焼き直しが要るのでしていない (7 章)。

## 3. 合言葉の結び付け方

1 章の決まり (同じページは通す、別のページ・別のブラウザは断る) をそのまま形にした。ほかの選択は出なかった。

- ページは読み込んだときに印を作る (18 バイトの乱数、base64url 24 文字、`wasm/web/main.js`)。メモリにだけ置き、WebSocket を開くたびに合言葉の横に付ける (`?pass=<合言葉>&page=<印>`、`wasm/zenoh/zp_ws_emscripten.c`)。
- console の確かめ: 使われていない合言葉が初めて通ったとき、その印の SHA-256 (`page_digest`) と、閉じる時刻 (`open_until` = 最初の接続 + `ASTERISM_PASS_LIFETIME`、既定 4 時間) を 1 つの UPDATE で記録する (2 つのページが同時に来ても片方だけが取る)。開いている間、同じ合言葉と同じ印は何度でも通す (`uses` を数える)。別の印・印なし・閉じた・取り消した合言葉は 401。
- 通したとき、閉じる時刻を `X-Asterism-Until` で返す。nginx が `auth_request_set` で door に渡し、door はその時刻に接続を切る (`WS_DOOR_MAX_SECONDS` は上限として残る)。接続が合言葉より長生きしない。
- 印を送らない古いページは、今までどおり 1 回きり。
- 読み直したページは新しい印なので、新しい合言葉が要る (フラグメントはもう消えている)。

ブラウザ版のつなぎ直し: zenoh-pico の 1 秒ごとの試しに加え、ページの WebSocket が失敗の後の間隔を 1・2・4・8・16 秒、その後 30 秒ごとに空ける (その間の試しは WebSocket を作らずすぐ失敗)。合言葉のあるページは 10 回続けて失敗すると諦め、状態の行に「the pass may have closed」と出す。

## 4. Apply の待っての反映

- 確認の画面の上に、切れるもの (ブラウザのページの数・ルータの数・ノードの数と名前) を大きく出す。
- 「Write the configuration and restart the cloud router now」に加え、「Apply when nobody is connected」と「Apply at this time」(ブラウザの時刻、ページがずれ (`getTimezoneOffset`) を送り UTC で持つ)。後の 2 つは状態 `waiting` の RelayApply を作る。
- 「誰もつないでいない」の判定 (`Relay::Applier#idle?`): bridge が生きていてクラウドのルータが見え、ws のセッション (ブラウザ) が 0、console 以外のノードを運ぶ client のセッションが 0、console 以外の Asterism のノードが 0。ルータのリンクだけ (奥に誰もいない家のルータ) は数えない。bridge が見えないときは分からないので待つ。
- 待つ係 (`Relay::ApplyWaiter`): console のサーバの中の thread 1 本が 5 秒ごとに見る (`config/initializers/relay_apply_waiter.rb`、サーバのプロセスでだけ起動)。状態はデータベースにあるので、console が起動し直しても続きから待つ。
- 待っている間は、Relay の画面 (台帳・役割・Apply・Applies) の上に「waiting to apply」と取り消しのボタン。待っているのは 1 つだけで、新しい Apply を作ると待っているものは取り消す。待つ Apply は、走るときの台帳を反映する。
- 「走っている」の見張りは作った時刻でなく `started_at` で見る (待つ Apply は何時間も前に作られている)。

## 7. 見立てと違った点

### 7.1 nginx の error log に合言葉が残っていた (直した)

ルータが起動し直している間にブラウザが来ると、door は zenohd につなげず (あるいは zenohd が応える前に閉じ) 何も返さずに閉じていた。nginx はこれを「upstream prematurely closed connection」として、**リクエストの行 (`GET /?pass=...&page=...`) ごと error log に書く**。access log は query を落とす形 (`asterism_noquery`) だが、error log には効かない。G1 以来あった穴で、つなぎ直しで頻度が上がって見つかった。door が、zenohd につなげないとき・zenohd が何も返さずに閉じたときは自分で `503` を返すようにした (nginx は応えを受けたときは error log に書かない)。直した後の起動し直しでは error log が増えなかった。**VPS の `/var/log/nginx/asterism-router.error.log` には、これまでの起動し直しの分の合言葉が残っている可能性がある** (使い切り・期限切れなので今は使えないが、消すのがよい。8 章の手順に入れた)。

### 7.2 そのほか

- zenoh-pico 1.10.1 はひとつのスレッドの組み立てでもつなぎ直しが働いた (実行器の task として)。gem で付け直す層は要らなかった。
- zenoh-c は前からつなぎ直していて、閉じていたのは asterism-zenoh の側だった。
- つなぎ直しの間の `get` は例外でなく、誰にも届かず時間切れになる (zenoh-pico が送れなくても成功を返す)。
- 合言葉の確かめは、zenohd が戻る前の試し (502/503) でも通る (console の確かめは nginx が先にする)。`uses` はその分も数える。
- アカウントの画面のハンドルの欄の `pattern` が大文字を断っていた (保存のときに小文字にするのに)。大文字も通すようにした。
- 待っている Apply の取り消しのボタンが `<p>` の中の `<form>` で外に出ていた。`<div>` にした。

## 9. 残った課題・決めてほしいこと

- **P4-Nano での確かめ** (受け入れ条件 3): 焼き直しは**アプリの区画だけ** (`fmruby-core.bin`、`rake flash` でなく app-flash。区画の表・storage は変わらない) で足りる。ビルドは NARYAv4 で `ASTERISM_DIR=../asterism PICORUBY_ASTERISM_ZENOH_DIR=../picoruby-asterism-zenoh FMRB_HW_TARGET=NARYAv4 rake build:esp32` (ピンを上げた後なら env なし)。オセロの新しい版は `tab5_fs` で `/app/test/othello.app.rb` に送れば足りる。焼いた後: シリアルを開いたまま家のルータを起動し直し、`othello: the line dropped` → `connected again` の時刻と、周期のダンプ (`fmrb_task:` の Free、`IRAM free:`) を前の版と比べる。
- **ピンの更新**: asterism と picoruby-asterism-zenoh の main を push した後で、`lib/add/ASTERISM_PIN`・`PICORUBY_ASTERISM_ZENOH_PIN` を上げる。それまでは fmruby-core のこのブランチを既定のピンでビルドするとつなぎ直しが入らない (オセロは `reconnecting?` が無ければ今までどおり自分でつなぎ直す)。
- **公開**: asterism・asterism-zenoh・picoruby-asterism-zenoh の次の版 (CHANGELOG の Unreleased)。console の image は rubygems の asterism (0.7.0) を使うので、bridge は今までどおり自前で 3 s ごとにつなぎ直す。
- **待つ長さの見直し**: オセロの 60 s。ブラウザ版の試しの間隔は 30 s で頭打ちなので、ルータが 1 分以上止まると相手は抜けた扱いになる。
- **つなぎ直しの試しが poll を止める**: zenoh-pico の `_z_open` は poll の中で走り、届かない相手には `PICORUBY_ZENOH_CONNECT_TIMEOUT_MS` (3 s) まで止まる (ルータの PC が落ちて SYN が返らないとき)。拒まれる (ルータだけ止まる) ときはすぐ返る。端末の画面が 1 秒おきに 3 s 固まる形になりうる。必要なら gem で試しの間隔を空ける。
- **つなぎ直しの間の宣言**: 新しい宣言は例外になる (控えに入らないため)。取り消し (`close`) も送れずに控えに残り、戻った後に送り直される。今のアプリは困らないが、gem の課題に足す候補。
- 試しに使った Playwright の台本・CRuby の見張り (alice)・手の選び方の台本はスクラッチパッドに置いた (コミットしていない)。
