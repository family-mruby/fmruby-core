## 2. API (asterism 0.5.0)

### 2.1 形

portable API (端末と CRuby で同じ):

```ruby
Asterism.profile(name: "Rover", icon: png)     # 与えた項目だけ変え、プロフィールを返す
Asterism.profile                               # => {"kind" => "cruby", "name" => "Rover", "icon" => "...", "icon_hash" => "..."}
Asterism.profile_of("fmruby-aaaaaa")           # ほかのノードの。答えが無ければ nil
Asterism.profile_of("fmruby-aaaaaa", icon: false, timeout: 2.0)   # アイコンのバイト列なし
Asterism::Profile.png_info(bytes)              # => [幅, 高さ, icon_hash] か nil
```

CRuby API: `net.profile(**fields)` と `net.profile_of(node, icon:, timeout:)` (受信のスレッドが回っている間は、その刻みを待つ)。

- 設定の形は「キーワードで与えたものだけ変え、返り値は全体」。引数なしで読む。`nil` は `name` / `host` を外し、`kind` は既定に戻し、`icon` は「アイコンなし」。受け付けない値は `ArgumentError` (知らない項目、単語でない `kind`、PNG でない・8 KB を超える・256x256 を超えるアイコン)。
- 接続の前でも後でも呼べる。プロフィールはプロセス (端末では VM) のもので、`close` の後も残る。
- 読む側は `profile_of`。時間の単位は 0.4.0 の決まりどおり秒 (`timeout:`) か `timeout_ms:`。答えが無いことは異常ではないので、`TimeoutError` ではなく `nil` にした。自分のノードは網を通さずに返す。

### 2.2 キーと中身

- キー `asterism/<ID>/@profile`。接続した各アプリが queryable を 1 つ持つ (深さ 4)。`@` で始まる塊は Zenoh の verbatim chunk で、`asterism/**` には一致しない (CRuby で確かめた)。よって今の object 層の liveliness の監視・ワイルドカードの呼び出し・古い版の queryable (`asterism/<ID>/<app>/**`) には入り込まない。
- 答えは MessagePack の Hash: `kind`・`host`・`name`・`icon`・`icon_hash`。問い合わせの引数 `icon=0` でアイコンを抜く。
- 接続のときと、接続中の変更のたびに、アイコン抜きのプロフィールを同じキーへ put する (通知)。console はこれを購読して描き直す。
- 後のアプリ単位のプロフィールのため、キー `asterism/<ID>/<app>/@profile` (中身は同じ形) を空けた。0.5.0 では作っていない。

### 2.3 項目と制限

| 項目 | 値 | 制限 |
|---|---|---|
| `kind` | `family_mruby` / `picoruby` / `cruby` / `console`。ほかの単語も通す | 英小文字で始まり `a-z 0-9 _`、32 バイトまで |
| `host` | `atoms3r` / `tab5` / `p4nano` / `browser` / `sim` など | 32 バイトまで |
| `name` | 表示名 | 64 バイトまで |
| `icon` | PNG のバイト列 | 8 KB まで、256x256 まで、PNG だけ |
| `icon_hash` | Asterism が付ける (使う人は与えない) | 16 進 8 桁 |

- アイコンの確かめ (送る側・受ける側の両方、`Asterism::Profile.png_info`): PNG の先頭の 8 バイト、大きさ (8 KB)、塊 (chunk) が IHDR から IEND まで切れ目なく並ぶこと、IHDR の幅と高さ (1 から 256)。受ける側 (`Asterism::Profile.check`) は、通らないアイコンをその要約ごと捨てる。`kind` が無い・単語でない答えは丸ごと `nil`。知らない項目は落とす。SVG は受けない。
- `icon_hash` は PNG の各塊の CRC-32 の欄を順に並べたものの Adler-32 (16 進 8 桁)。CRC は各塊の中身の要約なので、絵が変われば必ずどれかが変わる。端末ではファイル全体を通さず、塊の数 x 4 バイトの小さい整数の足し算だけで済む (整数の幅に頼らない)。CRuby では `Zlib.adler32` と一致する (試験で確かめた)。

### 2.4 既定

| 処理系 | kind | host | アイコン | どこで決まるか |
|---|---|---|---|---|
| CRuby | `cruby` | なし | gem 同梱の `data/icon.png` (ルビーの絵、284 B) | gem の `lib/asterism/cruby.rb` |
| mruby / PicoRuby (Family mruby 以外) | `picoruby` | なし | `/usr/share/asterism/icon.png` があればそれ | gem の `mrblib/profile.rb` |
| Family mruby の端末・sim・ブラウザ版 | `family_mruby` | `FmrbConst::BOARD` から (`linux` は `sim`、`wasm` は `browser`、`naryav4` は `p4nano`、ほかは BOARD のまま) | `/usr/share/asterism/icon.png` (端末・sim は基板の絵、ブラウザ版は窓の絵) | fmruby-core の新しい gem `picoruby-fmrb-asterism` |
| console | `console` | なし | console の `app/assets/images/asterism_console.png` | console の bridge |

- アイコンのファイルは、プロフィールを最初に使うとき (接続のとき) に 1 回読む。アプリが `icon:` を与えたらファイルは読まない。
- 既定のアイコンの場所は `Asterism.default_icon_path`、既定の kind は `default_profile_kind` (どちらも CRuby の層が上書きする。`now_ms` などと同じ流儀)。

## 3. Family mruby の既定のプロフィール

### 3.1 どこで出すか

- 今の Asterism の取り込みは、アプリがそれぞれ `Asterism.connect` する形 (カーネルは Asterism を使わない)。そこで、アプリの VM が始まるときに既定を入れる形にした。
- 新しい mrbgem `lib/add/picoruby-fmrb-asterism` (純 Ruby、`picoruby-asterism` と `picoruby-fmrb-const` に依存)。mrblib は 1 行の要の `Asterism.profile(kind: :family_mruby, host: FmrbAsterism.host)` だけ。gem の mrblib は VM の初期化でアプリより先に走るので、アプリの `Asterism.profile(...)` がその上に重なる。
- Asterism を入れる構成 (Linux・P4・wasm、S3 は `FMRB_ASTERISM=1`) の 4 つのビルド設定に、`picoruby-asterism` の次の行として足した。`rakelib/setup.rake` が picoruby の木へ写す。Retro (`FMRB_ASTERISM=0`) には入らない。
- 公開の API (`Asterism.profile`) だけで書けたので、gem の側に Family mruby を知る仕組みは要らなかった。

### 3.2 アイコン

- `tools/asterism_icons.rb` (Ruby の zlib だけ) で 32x32 の RGBA の PNG を 5 枚描いた: 基板 (`family_mruby`、451 B)、ブラウザ (499 B)、ルビー (CRuby、284 B)、網 (console、373 B)、試しのアプリの絵 (591 B)。4 倍の超標本化でなめらかにした。同じ入力から同じバイト列ができる。
- 置き場所: `flash/usr/share/asterism/icon.png` (端末・sim)、`flash/usr/share/asterism/icon_browser.png`。ブラウザ版は `rake wasm:webflash` が束の `usr/share/asterism/icon.png` をブラウザの絵で置き換える (壁紙の `/data` と同じやり方)。アイコンは PSRAM の VM プールに読むか flash に置くだけで、内蔵 RAM は使わない。
- 使う人は自分の PNG に差し替えられる (8 KB・256x256 まで)。

### 3.3 試しのアプリ

- `asterism_demo` に、プロフィールを切り替える口を足した: キー `p` と、公開したメソッド `info.profile(name, own_icon)` (表示名と、アプリの絵 `/app/test/asterism_demo.png` か既定の絵)。キーボードの無い AtomS3R でも、PC や console から上書きを試せるようにするため。
- `ruby_profile` の試しのアプリは、画面と注釈の言葉だけ「Ruby features」「Ruby の対応表」に直した (ファイル名・ハンドル名は変えていない)。

### 3.4 PIN

`lib/add/ASTERISM_PIN` は asterism `feature/profile` の `5575401` を指す (未 push なので、ビルドは `ASTERISM_DIR=../asterism`)。PIN の注釈にそう書いた。main に入れた後に親が直す。

## 4. console (asterism-console、docs/v2_5.md)

- ノードが現れたら (`asterism/**` の liveliness の新しい名前)、bridge の専用のスレッドが 1 回問い合わせる: まずアイコン抜き (`profile_of(node, icon: false)`)、`icon_hash` が店に無いときだけアイコンつきでもう 1 回。アイコンは要約ごとに DB の表 `node_icons` に 1 行。同じアイコンのノードがいくつあっても、網を渡るのはアイコン 1 つにつき 1 回。
- 通知 (`asterism/*/@profile`) を購読し、知っていることを置き換える (同じ端末の複数のアプリが違う答えを出すときは最後の通知が勝つ)。アイコンが新しければ取りに行く。
- 答えが無いノード (古い版) は V2.2 の名前の決まりの印のまま。去るまで問い直さない。去ったノードは忘れ、戻れば問い直す。
- 印は処理系の名前にした: ▣ Family mruby、▤ PicoRuby、◈ CRuby、◎ console、◇ ほかの kind。凡例と詳細の言葉も `board` / `ruby` から処理系の名前に直した。詳細の「Runs on」に、プロフィールで名乗ったか名前から推したかを添え、`Name`・`Host`・アイコンを出す。
- アイコンは名前の前に描く (枠がアプリを抱えるときは枠の上、無いときは下の名前の前)。cytoscape の名前は絵を持てないので、名前の幅を測ってノードの背景の絵として置く。台帳の角の印も同じ配列に入れた。
- console 自身は `kind: console` と自分のアイコンを名乗り、自分のノードにもアイコンが出る。
- 記録と巻き戻し: 網の構造の記録は図の形をそのまま持つので、各ノードのプロフィール (アイコン抜き) が記録に入る。アイコンは「今の DB から引く」を選んだ (記録のファイルの形を変えず、アイコンを記録ごとに持たない。ほかの console で開くと印だけでアイコンは出ない)。

### 5.3 プロフィールを出さないノード・捨てるアイコン (条件 3)

- PNG でない・8 KB を超える・256x256 を超えるアイコンを捨てることは、asterism の試験で確かめた (CRuby で 2 プロセスの間、偽の答えを返すノードを相手に。送る側は `ArgumentError`)。console は受けたものを gem の `Asterism::Profile.check` に通してから使うので、同じ決まりで捨てる。

### 5.4 巻き戻し

構造の記録 (8 秒) の途中で sim のプロフィールを既定に戻した。巻き戻すと、始めは Name Sim Demo とアプリの絵、終わりは既定の絵になった。

## 7. 内蔵 RAM

- 静的 (esp_idf_size の D/IRAM): AtomS3R 111,279 B、Retro 126,259 B、Tab5 130,186 B。いずれも H3 の値と同じ。
- AtomS3R の実行時 (試しのアプリ `atoms3r_hello` + `asterism_demo` がつながった定常、`IRAM free:`): 焼く前 (H3 のファーム) 117,508-117,556 B、焼いた後 117,616-117,652 B。減っていない。プロフィールとアイコンは VM プール (PSRAM) にある。
- 新しい gem は純 Ruby で、バイトコードは flash、実行時の確保は VM プール。

## 8. 気づいたこと・残すこと

- **同じ端末の複数のアプリ**: アプリごとに queryable を持つので、`profile_of` は最初の答えを取る。console は通知の最後を取る。既定は全アプリで同じなので普段は問題ないが、1 つのアプリだけが上書きすると、`profile_of` はほかのアプリの既定を返しうる。アプリ単位のプロフィール (`asterism/<ID>/<app>/@profile`) を作るときに決め直す。
- **ノード名と表示名**: 図の名前はノードの ID のままにし、表示名は詳細だけに出した (呼び出し・許可・台帳が ID で引くため)。
- **公開の前に親がすること**: asterism の feature/profile を main へ入れ、CI (新しい mruby の job を含む) を見る。ASTERISM_PIN を main のコミットにし、`branch: main` に戻し、V2.5 の注釈を消す。console の feature/v2-5 を main へ入れる。gem の版は 0.5.0 (asterism だけ。asterism-zenoh は 0.4.0 のまま `~> 0.4.0`)。gem の作成と公開はユーザ。
- console の DB に `node_icons` が増えた (migration)。動いている console は `bin/rails db:migrate` が要る。
- 記録の巻き戻しのアイコンは今の DB から引くので、ほかの console で開くと出ない (docs/v2_5.md)。

## 9. 端末の状態

- AtomS3R (`/dev/ttyACM1`): このブランチのファーム (Spinel のカーネル、`FMRB_ASTERISM=1`、app の区画だけ焼いた)。`/usr/share/asterism/icon.png`・`/app/test/asterism_demo.app.rb`・`/app/test/asterism_demo.png` を devctl で置いた。startup_app は試しのアプリ `atoms3r_hello` のまま。`asterism_demo` は止めた。シリアルの記録は開いたまま。
- P4-Nano: 焼いていない。`asterism_demo` を 1 回起動して止めた。ファイルは送っていない。
- zenohd・console・bridge・CRuby のノード・sim・ブラウザは止めた。`build/` は Linux の標準構成 (x86-64)。ブラウザ版は作り直した。
