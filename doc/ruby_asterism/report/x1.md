## 2. protocol 1 の網の中身

仕様は asterism の `docs/protocol.md` (英語、規範)。protocol 0 は付録 A に「捨てた形」として短く残した。

| もの | protocol 0 | protocol 1 |
|---|---|---|
| 呼び出しのキー | `asterism/<ノード>/<アプリ>/<オブジェクト>/call` | `.../call/<呼んだノード>` (6 塊) |
| 呼び出しの中身 | `[method, args, kwargs]` (ちょうど 3 要素) | `{"method" => 名前, "args" => [...], "kwargs" => {...}}`。args と kwargs は空なら省いてよい。知らない欄は無視 |
| 答え | `["ok", 値]` / `["error", クラス, 文言]` | `{"value" => 値}` / `{"error" => {"kind", "class", "message"}}`。知らない欄は無視。error があれば value があっても例外 |
| 例外の種類 | 無い (クラス名だけ) | `raised`・`not_exposed`・`no_object`・`arguments`・`malformed`・`unsendable`・`nesting`・`protocol` |
| meta | `{"methods" => [[名前, 数]]}` | `{"methods" => [{"name" => 名前, "arity" => 数}]}` |
| プロフィール | 項目に版が無い。アイコンは str | `"protocol" => 1` が必ずある。アイコンは bin |
| バイト列 | 全部 str (CRuby は互換モード) | バイナリの文字列 (`String#b`) は bin、ほかは str |
| 生存の印 | `asterism/<ノード>` (アプリどうしで共有) と オブジェクト | `asterism/<ノード>/<アプリ>` (アプリごと) と オブジェクト。ノードだけの印は無い |
| 整数 | CRuby は uint64 も送る。端末は桁あふれで読む | 符号つき 64 ビットだけ。範囲外は送る前に `EncodeError`、受けたら malformed |
| 壊れた入力 | 端末は余分なバイトを無視、bin・ext を nil | 値はちょうど 1 つ。余分なバイト・ext・範囲外の整数は malformed |

決め直しの各項目は、おすすめのとおり入れた。互換のための形だった 3 つはきれいな形に置き換えた:

- R-1 (3 要素のまま 2 要素も受ける) → 名前つきの欄の map。キーワード引数の無い言語は `kwargs` を送らないだけで済み、
  あとで欄を足しても古い受け手が壊れない。
- R-9 (4 つ目の要素に kind) → 答えを map にして `error` の中に `kind`・`class`・`message`。決まりが作る例外の `class`
  は Ruby の名前のまま固定 (Ruby の呼び手が今までどおりの名前で受けられる)。
- R-16 (ノードの印に加えてアプリの印) → アプリの印だけ。ノードの印は「アプリが 1 つ閉じたらノードが消えて見える」
  原因そのものなので、残す理由が無くなった。

そのほか:

- R-11 (arity はそのまま) は値はそのままで、meta の 1 件を map にした (省略できる引数などを後で欄として足せる)。
- R-3 (移植できるキーは str と int) はおすすめ A のとおり「送り手はそうすべき (SHOULD)」で、gem は他の型を拒まない。
  キーワード引数の名前だけは str でなければ malformed。
- R-6 (時刻) は「1970 年からのナノ秒の整数」を慣習として書いた。ext は値ではない。
- protocol 0 の呼び出し (5 塊の `.../call`) の扱い: **断る** (答えない、ではなく)。中身にかかわらず種類 `protocol`
  の例外で答える。古い呼び手も、呼んだ相手の塊を付け忘れた新しい実装も、すぐに理由が分かるため。
- 呼んだ相手の塊が名前でないもの (`*`・`**`・`@` で始まる) の呼び出しには答えない。メソッドも走らせない。

## 3. 呼んだ相手 (R-14)

- キーの形: `asterism/<ノード>/<アプリ>/<オブジェクト>/call/<呼んだノード>`。gem が自分のノードの名前を付けて送る。
  答えも同じキーで返る。
- `Asterism.current_call`: 公開したメソッドが呼び出しのために走っている間だけ、`from` (呼んだノード)・`verified`
  (`:claimed`。同じアプリの中の呼び出しは網を通らないので `:local`)・`object`・`method` を持つ
  `Asterism::CurrentCall`。外では nil。待つ間に入ってきた呼び出しは上に積まれ、終われば戻る。CRuby はスレッドごと
  (受信のスレッドで答えているとき、ほかのスレッドから見ると nil)。
- `Asterism.expose(名前, obj, methods:, caller: :from)`: 各メソッドに `from:` を gem が入れる。呼び手が自分で
  `from:` を渡した呼び出しは種類 `arguments` で断る。台車の頭脳はこれに移した (`from: nil` の省略可能な引数を
  `from:` の必須に)。
- 段 2 (送り手の情報の突き合わせ) は入れていない。zenoh-pico の試験中の機能の大きさは 8 章。
- 「名前は名乗り」と仕様 (4.7) と README に書いた。ルータの ACL が名前とキーを結び付けたときだけ確かになる (7 章)。

## 4. 使う人から見える Ruby の API

足したのは次の 4 つで、どれも review のおすすめから出る。名前と引数の形を変えたものは無い。

| 追加 | 出どころ |
|---|---|
| `Asterism.current_call` (と CRuby の `net.current_call`)、`Asterism::CurrentCall` (`from`・`verified`・`object`・`method`) | R-14 の案 b (review が欄の名前まで書いている) |
| `expose(..., caller: :from)` (と `net.expose`) | R-14 の案 c |
| `proxy.asterism_call(名前, *args, **kw)` と `proxy.async.asterism_call` | R-10 (review が名前まで書いている) |
| `RemoteError#remote_kind` | R-9。review は Ruby の読み口の名前を書いていないので、既にある `remote_class`・`remote_message` に合わせた。**ユーザに名前の確認を求めたい唯一の点** |

ほかに `Asterism::PROTOCOL` (1) の定数。`verified` の値 `:local` は review の一覧 (nil・`:claimed`・`:consistent`・
`:router`) に無い値で、同じアプリの中の呼び出し (網を通らない) のために足した。

`Asterism.bytes` のような包みは要らなかった。mruby にも `String#b` (バイナリの印) があり、端末の MessagePack が
それで bin を選べる (5 章)。

## 5. 端末の MessagePack (lib/add/picoruby-fmrb-msgpack)

`ports/esp32/msgpack.c` (sim・ブラウザ版も同じファイル):

- 書く: バイナリの印の付いた String (`String#b`、mruby の `MRB_STR_BINARY`) は bin、ほかは str。
- 読む: bin はバイナリの印の付いた String。str は今までどおりの String。
- 値の後ろに余分なバイトがあれば失敗 (`msgpack_unpack_next` の off がちょうど終わりか確かめる)。
- ext (と知らない型) は失敗。nil にしない。
- 2^63-1 を超える uint は失敗 (桁あふれで負の数にしない)。int64 は全範囲そのまま。
- 失敗は `MessagePack.unpack` の RuntimeError になり、Asterism は malformed として答える。ログは警告 (W) に下げた。

確かめ (CRuby から素の Zenoh で、sim と AtomS3R の asterism_demo に送った。生データは scratchpad `x1/probe_*.txt`):
bin の引数は bin で返る、`-2^63` はそのまま、2^64-1・ext・余分なバイトは `malformed`、protocol 0 の呼び出しは
`protocol`、呼んだ相手が `*` には答えない、プロフィールのアイコンは bin (451 B)、印は `asterism/<ノード>/demo` と
オブジェクト 3 つで、ノードだけの印は無い。sim と AtomS3R で同じ答え。

## 7. ACL で「自分の名前でだけ呼べる」

手元に mTLS の zenohd (1.10.1) を 1 つ立てた (scratchpad `x1/acl/`。CA と証明書 3 枚 (router・alice・bob) を openssl
で作った)。ACL は既定で拒否、全員に生存の印・監視・queryable・答え・put・meta とプロフィールの問い合わせを許し、
呼び出しの問い合わせだけを証明書ごとに 1 行:

```
{ id: "alice_calls", permission: "allow", flows: ["ingress"], messages: ["query"],
  key_exprs: ["asterism/*/*/*/call/alice"] }
```

bob の証明書のノード `bob` が `who` (呼んだ相手を返す) を公開し、alice の証明書で 3 通りに名乗って呼んだ:

| alice の証明書で名乗った名前 | 結果 |
|---|---|
| `alice` | `"alice"` が返る |
| `carol` | `TimeoutError` (nobody answers、すぐ) |
| `bob2` | 同じ |

meta はどれでも読めた。キーの最後の塊がそのまま ACL の `key_exprs` に書けるので、G1.5 で台帳から「証明書の名前 =
呼んだ相手の塊」の規則を作れる。

## 11. 気づいたこと

- console の `Relay::CloudConfig` はプレイヤーの書いてよいキーに `asterism/<ノード>` を入れたままにした。protocol 1 では
  そこに何も出ないが、害は無い。アプリの印は `asterism/<ノード>/<game>/**` に入る。G1.5 で役割を書くときに外せる。
- CRuby では Zenoh から来た中身は ASCII-8BIT なので、それをそのまま渡すと bin になる。端末では Zenoh の中身は印の無い
  String なので str になる。どちらも受け手は String で受けるので困らないが、違いとして仕様の 9 章に書いた
  (picoruby-asterism-zenoh の中身に印を付けると、端末のアプリが文字として扱っている中身の長さなどが変わるので、
  やめた)。
- P4-Nano のプロフィールにアイコンが無い (アプリの区画だけを焼いてきたので `/usr/share/asterism/icon.png` が無い)。
  X1 とは関係ない。
- ブラウザ版の保存領域が前の版と別になり、ノードの名前が `wasm-` の別のものになった (web_up が作ったページ)。
