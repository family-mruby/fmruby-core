## 2. 役割の形とひな形の書き方

- 役割 = 名前 + ひな形の 4 つの欄。欄ごとに zenohd の規則の形が決まる (`lib/relay/cloud_config.rb` の `SECTION_RULES`)。

| 欄 | 規則 | 用途 |
|---|---|---|
| Read and write | 全 9 種、両方向 | 自分の場所 `asterism/${node}/<app>/**`、`asterism/${node}/@profile` |
| Read | 相手から declare_subscriber・liveliness_query、相手へ全 9 種 | 見てよいもの `asterism/*/<app>/**` |
| Ask | 相手から query | 呼び出しと meta (`asterism/*/<app>/*/call/${node}`、`.../meta`、`asterism/*/@profile`) |
| Watch | 相手から declare_liveliness_subscriber | gem が宣言する `asterism/**` の監視 |

- `${node}` は行の「Nodes it speaks for」(空なら行の名前) で広げる。`${node}` を含むひな形は行ごとの規則 (`<行>__<役割>_<欄>`)、含まないひな形は全行で共通の規則 1 つ (`role__<役割>_<欄>`)。ひな形にはアプリ名を書くので、全体で 1 つのゲーム用アプリという前提は無くなった (`ASTERISM_RELAY_GAME` は削除)。
- ほかに書けるのは `${node}` だけ。ひな形は `${node}` を入れるとキーの式になるものに限る (それ以外は保存で断る)。
- 台帳の行は役割を複数選べる (チェックボックス)。行ごとの「読み書きのキー / 読むだけのキー」は役割の外のものとして残し、新しく登録する行 (router も) の既定は空にした。
- 画面: Admin > Relay に Roles のタブ (一覧・作成・編集・削除)。役割のページに、その役割を持つ行ごと (とブラウザ) の広がった ACL のキーを出す。行のページに「What its roles allow」。
- ブラウザ (ws の subject) は、役割の「Browsers have this role」の印で役割を持つ。`${node}` は `ASTERISM_BROWSER_NODE_PREFIX` + `$*` (既定 `wasm-$*`)。別の行としてではなく役割の印にした (ブラウザは証明書の名前も行も持たないため)。
- 種の役割「match」(app `game`): G0 の Player と同じ意味に、呼び出しを自分の名前に絞った分だけを足したもの。G0 の `asterism/${node}` (protocol 0 のノードだけの印の名残) も同じ意味を保つため残した。新しい console では `db/seeds.rb` が (役割が 1 つも無いときだけ) 作る。

## 3. 止めずに入れ替える: zenohd 1.10.1 では効かない

### 3.1 実際に試した

手元に mTLS の zenohd 1.10.1 を 1 つ立て (`adminspace.permissions.write: true`、console 役の証明書に `@/**` の put を許す)、alice の put が bob に届く状態で、console 役から管理用の空間に alice を外した ACL を書いた。

| 書いたキー | zenohd の記録 | alice の put (同じセッション) | alice の put (つなぎ直した後) |
|---|---|---|---|
| `@/<zid>/router/config/access_control/policies` | `ERROR ... Error inserting conf value access_control/policies : updating config is only supported for keys starting with `plugins/`` | 届いた | 届いた |
| `@/<zid>/router/config/access_control` (丸ごと) | 同じ (`access_control`) | 届いた | 届いた |

### 3.2 ソースの根拠 (eclipse-zenoh/zenoh タグ 1.10.1)

- `zenoh/src/api/config.rs:179-188` `ensure_config_key_is_dynamically_writable`: キーが `plugins/` で始まらなければ上のエラー。`insert_json5` (`config.rs:258-266`) が必ずこれを通る。管理用の空間の put はこの `insert_json5` を呼ぶ (`zenoh/src/net/runtime/adminspace.rs:452-466`)。
- 仮に書けても効かない: ACL は割り込みの部品 (interceptor) として起動時に一度作られる (`zenoh/src/net/routing/interceptor/mod.rs:130-142`、`dispatcher/tables.rs:203`)。作り直す `TablesLock::update_config` (`dispatcher/tables.rs:525-546`、`#[allow(dead_code)]`) を呼ぶのは試験 (`zenoh/src/tests/interceptor_cache.rs`) だけ。設定の変化を待つのはプラグインの読み込みだけ (`adminspace.rs:249-262`、`plugins` で始まらない変更は飛ばす)。
- 2026-10-12 時点の main (版の表記は 1.10.1 のまま) も同じ。上の版に上げれば済む話ではない。

### 3.3 代わりの案

1. **起動し直しのまま、切れるものを先に見せ、時を選べるようにする**。Apply の確認の画面に、切れるブラウザの数 (合言葉を作り直す人) と、つなぎ直さないノードの数を大きく出す (今も一覧は出ている)。「誰もつないでいないときに反映」「時刻を決めて反映」を足す。手間は小さいが、切れることは変わらない。
2. **zenohd に小さな直しを当てた image を使う**。`access_control` を書き換えられるキーに加え、変更を受けたら `TablesLock::update_config` を呼ぶ (関数はあり、上流の試験で動いている)。動いているセッションの割り込みも作り直される (`set_interceptors_from_factories`)。自前の image を持つ手間がかかる。すでに通った宣言 (購読・queryable・印) は取り消されないので、行を Disable にしたときに何が残るかを試して決める必要がある。上流への PR の候補にもなる。
3. **切れても困らないようにする**。door が合言葉の有効な間 (4 時間) は同じブラウザのつなぎ直しを通す (合言葉を「1 回」から「1 つの開いたページ」にする)、アプリと gem がつなぎ直す (オセロは自分でつなぎ直す)。ルータは起動し直すが、使う人からは数秒の途切れに見える。

管理用の空間に書けるのは console だけにする件は、書き換え自体が効かないので手を入れていない (生成する設定は今も `write: false`)。

## 4. 移行のしかた

- `db/migrate/20261013100000_relay_roles.rb`: `relay_roles`・`relay_peer_roles` を作り、`player_nodes` を `nodes` に名前を変え、役割「match」を作る (`ASTERISM_RELAY_GAME` が置かれていればそのアプリ名、無ければ `game`)。Player の印のあった行を「match」に結び付け、`player` の列を消す。戻すとき (down) は「match」を持つ行に `player` を立て直す。
- 開発の DB で、Player の行 (`zenohd-home`、ノード 1 つ) を置いて上げ下げし、上げると match とノードの一覧が付き、下げると Player とノードが戻ることを確かめた。
- 罠: SQLite で列を消すと表を写し直す。最初は結び付けの表に `ON DELETE CASCADE` を付けていて、写し直しで結び付けが全部消えた (移行の中で `remove_column` を後に置いたら 0 件)。CASCADE をやめ (行と役割の削除はモデルで消す)、写し直しの後も結び付けが残ることを確かめた (`f9ba8c4`)。
- 同じ意味かの試験 (`test/lib/relay/role_migration_test.rb`): G0 の生成 (Player とブラウザの部分をそのまま写したもの) と、移行後の役割からの生成に、主体 4 つ (alice・家のルータ・ブラウザ・台帳に無い carol) × 9 種 × 2 方向 × キー 81 個を聞く (zenohd の `*`・`**`・`$*`・`@` の塊を読む小さな判定器で)。違いは「相手からの query」だけで、すべて新しい方が狭い。meta とプロフィール、自分の名前での呼び出しは変わらない。

## 5. 呼んだ相手の確かめ (段 3)

手元の構成 (6 章) で、bob (証明書 bob、mTLS 直結) が `who` (呼んだ相手を返す) を公開し、ほかが呼んだ。家のルータの行は役割 match、ノード `fmruby-aaaaaa`。

| つなぎ方 | 名乗ったノード | `who` | meta |
|---|---|---|---|
| alice の証明書で直結 | alice | `"alice"` | 読める |
| 同じ | carol | TimeoutError (nobody answers) | 読める |
| 同じ | bob2 | TimeoutError | 読める |
| 家のルータの奥 (tcp) | fmruby-aaaaaa | `"fmruby-aaaaaa"` | 読める |
| 同じ | fmruby-cccccc (行の一覧に無い) | TimeoutError | 読める |
| 同じ | alice (別の行の名前) | TimeoutError | 読める |

書き込み (`asterism/<自分>/game/x`・`asterism/fmruby-aaaaaa/game/x`・`asterism/alice/game/x` に put、bob が購読): bob に届いたのは、alice の証明書からは `asterism/alice/...` だけ、家のルータからは `asterism/fmruby-aaaaaa/...` だけ。`fmruby-cccccc` の場所への put は届かない。

ルータで見分けられない範囲: 家のルータの奥の端末どうしは同じ証明書なので、`fmruby-cccccc` を名乗る端末も `fmruby-aaaaaa` の場所に書け、その名前で呼べる (一覧のどれかの名前なら通る)。ブラウザどうしも同じ (どの `wasm-*` でも)。

asterism の docs/protocol.md 4.7 の「名前は名乗り」の後に、この 2 つの範囲と、meta・プロフィールは呼んだ相手を要らないことを一段落足した (gem の版と本体は変えていない)。

## 6. ブラウザ版の段 1

### 6.1 作り

- console: 設定 `ASTERISM_BROWSER_PAGE` (URL のひな形、`{router}`・`{pass}`・`{node}`・`{app}`、`{pass}` は `#` の後でなければ使わない) があるときだけ、Browser passes の画面に「Open the browser build」を出す。開くアプリは「Nothing (the page's own start)」と、役割の「Opens in a browser page」に書いたもの (match には `/app/test/othello.app.rb` を手で入れて試した。種の値は空)。押すと合言葉を作り、ノード ID を決め、新しいタブにページを開く。URL は保存されないページの本文 (meta refresh) で渡し、転送 (redirect) は使わない (Rails が転送先を記録に書くため)。
- ノード ID の決め方 (`lib/relay/browser_node.rb`): `wasm-<名前>`。名前はメールアドレスの `@` の前を小文字にし、a-z と 0-9 以外の並びを `-` 1 つにし、20 文字まで。何も残らなければ `user<id>`。別のユーザと同じ名前になったら、後から登録した方に `.<id>`。同じユーザが同時に 2 つ開くと `_2` … `_9` (図に今いる名前と、まだ使われていない・30 秒以内に使われた合言葉の名前を避ける)、それも埋まれば `_<16 進 3 桁>`。名前そのものに `.` と `_` は出ないので、付け足しが別のユーザの名前にならない。
- 合言葉の表に `node`・`app` の列を足し、自分の一覧と管理者の一覧にノードを出す。
- fmruby-core: ページの最初のスクリプトが、フラグメントの `zenoh_pass`・`zenoh_node`・`app` を読んでアドレスの欄から消す (coi-serviceworker の読み直しのときだけ戻す)。`main.js` はリンクのノード ID をその回だけ使い (どのタブでも。保存しない)、Network の枠に `(from the link, this visit)` と出す。`#app=` は `?app=` と同じ働き。今の `wasm-<16 進 6 桁>` の決め方 (localStorage・2 つ目のタブは使い捨て) は、リンクに ID が無いときにそのまま使う。
- `ASTERISM_STUDIO_URL` は、`ASTERISM_BROWSER_PAGE` が無いときのパスのリンクにだけ使う。既定のページは無くした。

## 7. ブラウザもルータで見分ける (段 2): 成り立つ

door が `ws/` の代わりに zenohd の `tls/` へユーザごとの証明書でつなぎ、流れを詰め替える案は成り立つ。ただし長さ 2 バイトを足し外すだけでは足りず、**最初の InitAck の batch_size を 2 減らす書き換えが要る**。調べは別の作業に任せ、zenoh 1.10.1 のソース (下の Z) と fmruby-core の zenoh-pico (P) を読み、手元で詰め替えを試した (コミットしていない)。

- ws のリンク: `is_streamed` は false (Z `io/zenoh-links/zenoh-link-ws/src/unicast.rs:227-229`)、MTU 65535。受けるのは Binary だけで、Ping・Pong・Text はリンクごと落とす (同 98-128)。送る `write` 1 回が WebSocket のメッセージ 1 通 (145-156)。転送層は非 streamed のリンクで `read` 1 回を 1 まとまり (batch) とする (Z `io/zenoh-transport/src/unicast/link.rs:292-306`)。よって **1 メッセージ = 1 まとまり**。
- tls のリンク: `is_streamed` は true (`zenoh-link-tls/src/unicast.rs:255-258`)。まとまりの前に 2 バイトのリトルエンディアンの長さ (書く側 Z `io/zenoh-transport/src/common/batch.rs:272-277, 311-322`、読む側 `unicast/link.rs:292-302`)。**最初の握手 (InitSyn/InitAck/OpenSyn/OpenAck) も同じ枠** (`unicast/establishment/open.rs:611-620`、`accept.rs:723-731`)。
- 握手にリンクの性質 (streamed か・MTU) を伝える欄は無い (Z `commons/zenoh-codec/src/transport/init.rs:309-348, 436-442`)。大きなメッセージの分割 (fragmentation) はリンクより上で行うので、かけらも普通のまとまりとして流れる。
- 2 バイトのずれ: tls の受け手のバッファは長さの 2 バイトを含めて MTU なので、受けられる本体は B-2 まで (`batch.rs:214-216`、`universal/link.rs:449-456`、`unicast/link.rs:299-302`)。ws の送り手は B まで送る。合わせないと `Invalid batch length or buffer size` でリンクが落ちる (試して再現)。zenoh-pico の既定 2048 を下げても、相手のバッファも同じだけ縮むので差は残る。door が InitAck の batch_size を B-2 に書き換えれば両向きとも収まる (cookie は暗号化されていて触らない)。
- zenoh-pico (ブラウザ版): ws は `Z_LINK_CAP_FLOW_DATAGRAM` (P `src/link/unicast/ws.c:84-95`)、1 まとまりを 1 回の `ws.send` (fmruby-core `wasm/zenoh/zp_ws_emscripten.c:186-215`)。読みは 1 メッセージ単位で、バッファより大きいものは捨てる (259-287)。
- ACL: tls の待ち受けはつなぐたびにクライアント証明書の CN を取り (`zenoh-link-tls/src/unicast.rs:530-536, 607-621, 677-680`)、ACL の `cert_common_names` で照らす (Z `zenoh/src/net/routing/interceptor/access_control.rs:733-752`)。
- 手元で試した結果 (zenohd 1.10.1、mTLS + ACL。door の試作は Ruby。ブラウザ役は zenoh-c の ws): 書き換えなしでは 200 KB の put でリンクが落ちた。書き換えあり (65160→65158) では、alice (door 経由、alice の証明書) の `t/alice/x` と 200 KB (分割あり) が bob に届き、`t/bob/x` は ACL で落ちた。bob からの 300 KB も door 経由の alice に届いた。25 秒置いても (lease 10 秒) 生き残った。
- door がやること: WebSocket の終わり (101・マスク外し・長さの拡張・continuation の連結)、Ping には自分で Pong、Text は異常、Close で両側を閉じる、上の詰め替えと InitAck の書き換え。
- 気をつけること: door が全ユーザの鍵を持つ (かその場で発行する) ので、door が信頼の要になる。zenohd から見たつなぎ元の住所は全員 door。
- 代わりの案: (B) zenoh-pico の ws を streamed 扱いにすれば door は中身を見ずに流すだけになるが、ブラウザ版の読みを部分読みに直す必要があり、zenohd の ws/ に直接はつなげなくなる。(C) ブラウザ専用の zenohd を door の後ろに置く案は、ルータどうしのつなぎが相手ごとに 1 本に束ねられ、全員が 1 つの CN に見えるので、1 ユーザ 1 zenohd になり勧めない。(D) ws のまま、利用者名とパスワード (zenoh-pico 側に資格情報を持たせる) か Zenoh の ID で見分ける。
- おすすめは本案 (door で詰め替え + InitAck の書き換え)。

## 11. VPS の更新の手順 (ユーザが行う)

VPS は今止めてある前提。名前・住所は仮名のまま書く。`<dir>` は VPS の asterism-console の checkout の `deploy/vps`。

```
# 0. 控え (止めたまま、console の DB と .env)
cd <dir>
docker compose run --rm --no-deps -T console tar -C /app -czf - storage > ~/console-storage-$(date +%F)-before-g15.tgz
cp .env ~/asterism-env-before-g15

# 1. 新しい版を取り、image を別の札で作る (今の札は戻し用に残る)
git pull
CONSOLE_IMAGE_TAG=g15 docker compose build
sed -i 's/^CONSOLE_IMAGE_TAG=.*/CONSOLE_IMAGE_TAG=g15/' .env   # 行が無ければ echo CONSOLE_IMAGE_TAG=g15 >> .env

# 2. .env: ブラウザ版を開くボタン (使うなら)
#    ASTERISM_BROWSER_PAGE=https://<ブラウザ版の置き場>/?zenoh={router}#zenoh_pass={pass}&zenoh_node={node}&app={app}
#    ASTERISM_RELAY_GAME は移行が一度読むので、移行の後で消す

# 3. 移行 (Player の行が役割 match に移る)
docker compose run --rm console bin/rails db:migrate
docker compose run --rm console bin/rails runner 'p RelayRole.pluck(:name); p RelayPeer.all.map { [_1.name, _1.roles.map(&:name), _1.speaks_for] }'
#    -> ["match"] と、Player だった行に ["match"] とノードの一覧が付いていること

# 4. nginx の snippet の名前を変える
sudo cp /etc/nginx/snippets/asterism-players-allow.conf /etc/nginx/snippets/asterism-door-allow.conf
sudo sed -i 's/asterism-players-allow\.conf/asterism-door-allow.conf/' /etc/nginx/sites-available/asterism-router.conf
sudo nginx -t && sudo systemctl reload nginx
sudo rm /etc/nginx/snippets/asterism-players-allow.conf

# 5. 起動 (systemd の雛形を使っている場合)
sudo systemctl enable --now docker-compose-service@<name>

# 6. console で: Admin > Relay > Roles で match を見る (Opens in a browser page にオセロのパスを書くなら書く)
#    -> Admin > Relay > Apply (呼び出しが自分の名前だけになる設定が書かれ、ルータが起動し直す)
#    -> .env から ASTERISM_RELAY_GAME を消す
```

戻し方:

```
sudo systemctl stop docker-compose-service@<name>
cp ~/asterism-env-before-g15 .env                     # 前の CONSOLE_IMAGE_TAG に戻る
docker compose run --rm --no-deps -T console sh -c 'rm -rf /app/storage/* && tar -C /app -xzf -' < ~/console-storage-<日付>-before-g15.tgz
sudo cp /etc/nginx/snippets/asterism-door-allow.conf /etc/nginx/snippets/asterism-players-allow.conf
sudo sed -i 's/asterism-door-allow\.conf/asterism-players-allow.conf/' /etc/nginx/sites-available/asterism-router.conf
sudo nginx -t && sudo systemctl reload nginx
sudo systemctl start docker-compose-service@<name>
# console の Apply を一度押すと、前の形の ACL が書き直される
```

(DB を控えから戻す代わりに `bin/rails db:rollback:primary STEP=2` でも戻る: match を持つ行に Player が立ち直る。)
