# GS11 報告: `asterism-games play` (端末でオセロと麻雀を遊ぶ)

> 状態: 完了 (検収待ち) | 更新: 2026-10-19 | `asterism-games play othello` / `play mahjong` を作った。オセロは今の othello-tty を play の下へ移し、`bin/othello-tty` は play othello を呼ぶだけの互換の入口にした。麻雀の端末版は新規 (卓の一覧 → 入る → 待ち合わせ → 対局 → 結果 → 終局、観戦、ホストの出入り)。牌は絵文字、`--tiles mpsz` で略号。`asterism-games --help` が使い方を出すようにした。asterism-games 0.17.0 (b9b7b27、main、push・タグなし)

## 1. コマンドの形

```
asterism-games play <game> [options]          # game: othello, mahjong
asterism-games play --help                    # ゲームの一覧と共通の指定
asterism-games play mahjong --help            # 共通の指定 + 麻雀の操作
asterism-games --help | help | -h             # ホストのコマンド全体の使い方 (ホストは起動しない)
bin/othello-tty [options]                     # = asterism-games play othello [options]
```

共通の指定 (othello-tty と同じ): `--router` `--credentials` `--namespace` `--table` `--name` `--node` `--commands "a,b,c"` `--until-over`。麻雀だけ `--tiles emoji|mpsz` (既定 emoji)。

- つなぎ先: `--router` も `--credentials` も無いときは `ASTERISM_ROUTER` / `ASTERISM_CREDENTIALS` を読む。gemspec の asterism (0.8.0) の Net にはこの決まりが無い (CLI の ca139a7 は未公開の main で、CLI の中だけの処理) ので、play 側 (`Play.network!`) で同じ決まり (どちらも無いときだけ、全部か無しか) を書いた。何も無ければ従来どおり `tcp/127.0.0.1:7447`。`.tar` だけなら locator は nil (.tar のルータ)。
- `--table` が無いとき: 名前が `mahjong` / `othello` で始まる卓を探す (ノードが加わるたびに探し直し、10 秒)。麻雀は複数あれば、端末なら一覧 (状態・席の名前・人数) を出して番号で選ぶ。パイプなら最初の卓。
- 置き場所: `lib/asterism_games/play.rb` (入口・指定・接続・入力の読み込み)、`play/othello.rb`、`play/mahjong.rb` (通信と描き直し)、`play/mahjong_text.rb` (牌の文字・幅・行・入力の読み取り。通信なし)、`play/mahjong_screen.rb` (view → 行)。どれも framework も riichi_engine も読まない (asterism と標準ライブラリだけ)。

**決めたこと (1・2 章に書かれていない形の選択)**: 麻雀の端末版を **gem に入れた**。gem は「麻雀を含まない」作りで、test_gem・test_framework が `mahjong` という名のファイルを gem に入れないことを確認していた。端末版は卓の実装 (app/、riichi_engine) を使わず asterism だけで動くので、`gem install asterism-games` の後に `asterism-games play mahjong` が動くほうが play の意味が通ると判断し、試験の決まりを「麻雀の卓は入れない、端末版 (`lib/asterism_games/play/mahjong*.rb`) は入れてよい、それも riichi_engine・framework を読まないこと」に直した。gem に入れない形 (app/ に置き、イメージと作業コピーだけで動く) に戻すのはファイルの移動と試験 2 か所で済む。

## 3. 操作の一覧

| 打つもの | |
|---|---|
| `a` .. `n` | 手牌のその牌を打つ (ツモ牌は最後の文字) |
| `6s` `0p` `東` (`1z`..`7z` も) | その牌を打つ。`0` は赤五。`5p` は手に普通の五が無く赤だけあるとき赤を打つ。絵文字 1 文字も牌として読む |
| `riichi` | 候補が 1 つならそれで。複数なら打牌の候補を出し、次の行 (文字か略号か番号) で選ぶ。`riichi e` / `riichi 6s` で一度に |
| `tsumo` `ron` | 和了 |
| `pon` `chi` `kan` | 鳴く。やり方が複数なら番号つきで出し、次の行で選ぶ (`2`、`3m4m`、`34m`、手牌の文字)。`chi 2`、`chi 3m4m` で一度に。赤の有無で分かれるポンは `pon 0p5p` / `pon 55p` |
| `pass` | 鳴かない |
| `kyuushu` | 九種九牌 |
| `ok` (結果のときは空の行も) | 結果の OK。終局では卓の主が待ち合わせに戻す |
| `sit [1-4]` `stand` | 座る (CPU の席にも座れる)・立つ |
| `cpu [1-4]` `nocpu 1-4` `ai 1-4 種類` | 卓の主: 空き席を CPU で埋める (席を指定すればその席)、CPU を外す、AI を座らせる (ロビーが出しているときだけ) |
| `tonpuu` `hanchan` `rule 項目 値` | 卓の主: 東風・半荘、ローカルルール一般 |
| `start` | 卓の主: 始める |
| `auto` | 代わりに打つ (和了は取る、鳴きは pass、ツモ切り、結果は OK)。もう一度で止める |
| `tables` `view` `help` `quit` | |

画面の最後の行が「今できること」: `自分の番: 打つ牌 (文字か 6s)、riichi、tsumo  あと 5+20秒`、`鳴ける (東 CPU1 の 🀙): pon、pass  あと 8秒`、`ほかの人の答えを待っています`、`南家 (CPU2) の番です`、`東1局 0本場 が始まります` (MJ9 の `in`)、`ok で次へ` と `OK を待っています (n/m)  あと N 秒` (MJ9 の `ok`)、`次へ: 卓の主が待ち合わせに戻す`。ホストの答えは麻雀アプリの言葉に直して出す (`今はできない`、`卓の主だけができる`、`画面が古い: 読み直し中` …)。リーチの待ちの手助け (assist 1 の `wt`) が来たときは `待ち: e→ 3m(2) 6m(3)` の行を出す。

## 4. 幅の扱い

- 実際の幅 (Unicode の East Asian Width): 麻雀牌は U+1F004 (🀄) だけが W (2 桁)、ほかは N (1 桁)。ただし字形は 1 桁より広く描かれやすい。手元にあるのは tmux だけで、実際の端末の字形は見られない (tmux は glibc の wcwidth どおり 🀄 を 2 桁、ほかを 1 桁として数えた)。
- 並べ方: 牌はどれも **2 桁の枠** (MPSZ は 3 桁) に入れ、牌の後ろの空きを広い字形のはみ出し用にする。手牌の下の文字も同じ枠で並べる。ツモ牌は 1 枠あけて最後。
- **端末 (tty) のとき**: 行の部品 (牌・文字・その後の文字列) を 1 つずつ **カーソルの桁指定 (CHA、`ESC [ n G`) で置く**。端末が 🀄 を 1 桁と数えても 2 桁と数えても、フォントが牌を広く描いても、次の牌と文字の位置は動かない。崩れるのは字形が 2 桁を超えて隣に重なる場合だけで、そのときは `--tiles mpsz`。
- **パイプ・ファイル (試験・写し)**: 上の幅の表で空白を詰める (🀄 は枠を埋めるので `🀄🀄` と隙間なく並ぶ。§2 の写しのとおり)。
- 赤五: 絵文字には赤五が無いので、端末では赤 (SGR 31) で描き、手牌の下に `赤: j` と文字を出す (パイプでは色なし)。
- リーチの牌は `[🀔 ]` と、角括弧の中にも 2 桁の枠を取った (指示書の見本は `[🀔]`。広い字形が `]` に重ならないようにした)。
- 名前は表示幅で揃える (漢字 2 桁)。長い名前は 10 桁で切る。
- 描き直しは view が変わったときだけ (残り時間の数字だけが変わったときは描かない)。打ちかけの行が画面ごと消されないようにするため。その代わり残り時間は描いた時点の値。
- 試験: `Row` の空白詰め (🀄 を含む行で各牌の始まりの桁が文字の桁と一致)、CHA の出力 (各部品の桁)、`width` (🀄 2・🀇 1・東 2・エスケープは 0)、`fit`。

### 9.2 `--commands "sit,cpu,start"` が効かなかった件

- 原因: 前の版は `--commands` を卓に入った直後に 1 回だけ、順に送っていた。そのとき卓が待ち合わせでないと (前の対局がまだ続いている、終局の画面が `over_seconds` (60 秒) 残っている、など)、`sit` は「待ち合わせ中ではない」で断られて捨てられる。続く `cpu` と `start` も席が無く卓の主でもないので断られる。さらに、ほかの人が卓の主だと `cpu` と `start` は「卓の主だけができる」になる。答えは注記の 1 行に出るだけで、次の描き直しで消える。手元の新しい卓 (待ち合わせ、誰もいない) では tmux でも通るので、ユーザの卓はこのどれかの状態だったと見ている (卓の状態は残っていないので断定はできない)。
- 直し: `--commands` を待ち行列にし、描き直しのたび (2 秒ごとの見直しを含む) にその時点で通るものから順に送る。待ち合わせの命令 (sit stand cpu nocpu ai start tonpuu hanchan rule) は待ち合わせを待つ。卓の主の命令は、席に着いて卓の主になるのを待つ。`start` はさらに 4 席がそろうのを待つ。待っている間は画面に `--commands: cpu (卓の主を待っています)` のように出す。断られた命令はやり直さない (同じ命令を送り続けないため)。
- 試験 `test/test_play_commands.rb` (3 件。卓は同じプロセスの中に置き、Asterism のオブジェクトの代わりに薄い代役を使う): ほかの人の対局が進んでいるところへ客が `sit,cpu,start` で入る → 待っていると画面に出る → その人が抜けて対局が捨てられ待ち合わせに戻る → 客が座り、CPU で埋め、卓の主として始める。卓の主でないときは `cpu` が卓の主を待ち、役が移ると始まる。新しい卓ではその場で順に通る。前の版の「すぐ送る」作りだと、1 件目は `sit` が「待ち合わせ中ではない」で消えるので落ちる。
- tmux (実際の tty) でも、`--table games/games/mahjong2 --tiles kanji --commands 'sit,cpu,start'` で座って始まり、自分の番まで進むことを確認した。

### 9.3 残り時間の表示

- 端末のときだけ、1 秒ごとの小さなスレッドで、最後に描いた view から描いてからの時間を引いて (`dl` の ms と `ok` の ms) 画面を計算し直す。行数が同じなら、変わった行だけをその位置で書き直す。書き直すのは最後の行の `あと 5+20秒` と、結果の `OK を待っています ... あと N 秒`。
- 書き方: `ESC 7` (カーソルを保存。入力中の `> ` の後ろ) → 各行を `ESC [行;1H ESC [2K` + 新しい行 → `ESC 8` (カーソルを戻す)。入力中の行には触れないので、端末の行編集 (エコー・消去はカーソルの位置で起きる) はそのまま使える。画面全体は消さない (ちらつかない)。端末の高さより画面が長くてスクロールしたときは、上に流れた行を書き直さない (`winsize` から行のずれを出す)。
- 持ち時間は、まず 1 手の時間が減り、それが尽きると銀行が減る (`あと 0+12秒`)。前の版にあった負の表示も直してある。
- パイプやファイルのときは今までどおり (スレッドを起こさない)。
