## 2. ホストの変更

### 2.1 卓の主 (決めた規則)

「人が座っているときは今まで通り」を崩さないため、**誰かが座っている間は卓の主は必ず座っている人**、誰も座っていない間だけ座っていない人が卓の主になれる、という形にした。

| 場面 | 規則 |
|---|---|
| join | 誰も座っておらず卓の主もいない卓に入った人が卓の主 (`join` の `"owner"` が true) |
| sit | 卓の主がいない、または卓の主が座っていないとき、座った人が卓の主になる (今の「最初に座った人」と同じ結果) |
| stand | 卓の主が立つ: ほかに座っている人がいればその中で最初に座った人 (今どおり)。誰も座っていなければ**立った人がそのまま卓の主** (座っていない卓の主) |
| leave / 忘れられる | 座っている人がいればその中で最初に座った人 (今どおり)。いなければ、残っている人のうち途切れていない人の中で最初に入った人 (全員途切れなら最初に入った人、誰もいなければ無し) |
| 途切れた卓の主の引き継ぎ (`owner_handover_ms`) | 変えていない (もともと座っていない人も対象) |

`pass_owner` に「座っている人がいないとき」の分岐を足し、`join` を上書きし、`sit` の `@owner ||= node` を上の条件に変えた。古い麻雀アプリは `"ow"` (卓の主の席) だけで卓の主を判断するので、座っていない卓の主は「卓の主がいない」ように見える。これは今の「誰も座っていない待ち合わせ」と同じ見え方で、誰かが座ればその人が卓の主になるので、古いアプリの遊び方は変わらない (5.3 で確認)。

### 2.2 メソッド

- `watch(token)` (Remote、引数 1)。中身は `Table#start_watch(token, now)`。
- 条件と断る理由: `"token"`、`"not waiting"`、`"not owner"`、`"seats"` (空き席がある)、`"human"` (人が座っている)、`"ai limit"` (AI の種類ごとの席数が上限を超える)。
- AI の上限は `Table::WATCH_AI_MAX = {"claude" => 1, "jev" => 4}` (ここに無い種類は 4)。観戦対局を始めるときだけ効く。ふつうの対局の AI の決まり (`cpu`) は変えていない。待ち合わせでは view の `"wc"` が 2 になり、画面が案内を出す。
- `start` は今のまま (人が 1 人もいなければ `"no human"`)。

### 2.3 観戦対局の間

- `@watch` を立てる。人が座っていないので `abandon_game` は `@watch` のとき何もしない。代わりに `stop_watch`: 卓の参加者が 0 人になったら (leave、または途切れて away_ms の 6 倍で忘れられた) 待ち合わせに戻す。途中の対局は記録しない (ログ `watch game stopped: nobody at the table (not recorded)`)。終局後の待ちの間に全員去った場合は、記録は残ったまま待ち合わせに戻る。
- 結果・終局の進み方は CPU だけの卓と同じ (人がいないので OK を待たず `result_ms`、終局は `over_ms` で待ち合わせへ)。配牌後の局名表示の待ちも無い (人がいない卓の今の動き)。
- 1 回で待ち合わせに戻り、`@watch` を下ろす。席 (CPU・AI) はそのまま残る。
- 保存・再開: 保存に `"watch"` を入れ、再起動しても観戦対局のまま続く (試験あり)。

### 2.4 view・status・記録の鍵

| 鍵 | どこ | 意味 |
|---|---|---|
| `mo` | 参加者自身の view だけ | 1: この人が卓の主 (座っていても、いなくても) |
| `wc` | 待ち合わせの view | 1: 観戦対局を始められる、2: 4 席とも CPU・AI だが AI の上限超え、0: 始められない。0.20.0 より前のホストには無い (画面はこれで新旧を見分ける) |
| `wm` | 対局中の view | 1: 観戦対局 |
| `@status` の卓の項目 | `status_extra` | 観戦対局中に `"watch" => true` (rooms の status ファイルは数だけのまま、`summary` には入れていない) |
| 記録 | `record_game_start` | `"watch" => true`。`records` の各項目と `record(id)` にも出す |
| 成績 | `record_summary` | 観戦対局の席は CPU・AI の種類ごとに数える。人の席はそもそも無いが、念のため `human` は `cpu` として数える (人の成績に混ざらない) |

`describe` の文 (AI への指示に使う) は変えていない (AI の手の判断には関係が無いため)。

## 3. `play mahjong` とアプリの操作

### 3.1 `play mahjong`

- `W`: 観戦で始める (卓の主、座っていても、いなくても)。`wc` が 1 のときだけ案内に出る。2 のときは「観戦対局の AI は Claude 1 席・Jev 4 席まで」、古いホストでは「このゲームホストは観戦対局ができない」。
- `A` のあと `1`〜`4`: その席を 空き→CPU→Claude→Jev→CPU と進める (ホストが出す種類だけ、ほかのキーでやめる)。今まで麻雀の `play` に AI を座らせるキーが無かったので、GS13 のオセロの A に合わせて足した (麻雀は 4 席あるので席の番号を続けて押す形)。コマンドの `ai 1-4 KIND` は今のまま。
- コマンド `watch`。卓の主のコマンド (`cpu`・`ai`・`watch`・`--commands`) は座っていない卓の主でも通る (卓の主の判定を `mo` か `ow == me` に)。
- 待ち合わせの観戦者の並びに `(卓の主)` を付け、座っていない卓の主には `(卓の主: 自分)` の行と `観戦中 (卓の主):` の案内。観戦対局の対局中は 1 行目に `観戦対局 (CPU と AI だけ)`、終局は「観戦対局: しばらくすると待ち合わせに戻る」。

### 3.2 麻雀アプリ (fmruby-core)

- 待ち合わせ: 卓の主で `wc` が 1 のとき `観戦で始める[W]` ボタンと `w` キー。`wc` が 2 のときはボタンの下に「観戦対局の AI は Claude 1 席・Jev 4 席まで」。`始める[Enter]` は人が座っているときだけ出す (座らずに全席 CPU のときに押しても `"no human"` で断られるだけなので)。
- 卓の主の判定 `owner?` は `mo == 1` か、今どおり `ow == 自分の席`。古いホストには `mo`・`wc` が無いので、今の画面のまま (ボタンは出ない)。
- 観戦者の並びで卓の主に `(卓の主)`。
- 対局中は今の観戦画面 (4 人の手牌)。終局の下の行を観戦対局では「観戦対局: しばらくすると待ち合わせに戻る」に。426x240 の小さい卓の案内行は「観戦対局」で始まる。
- 直近の結果の一覧: 観戦対局に `観` (640x360 以上、対局の形の後ろ)、小さい画面では時刻を水色に。
- 内蔵 RAM: アプリの Ruby だけの変更。VM プールは sim で 855-942 KB (27-30 %)、前回までの範囲と同程度。

## 6. VPS に出すとき要ること

- `./update.sh 0.20.0` (または `--when-idle 0.20.0`)。**`.env` の変更は無い** (docs/install.md に節を足した)。
