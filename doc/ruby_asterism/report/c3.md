## 2. zenoh-pico (picoruby-asterism-zenoh)

### 2.1 元にしたファイル 4 つ

対象: `src/zp_tcp_posix.c` (元 `src/link/transport/tcp/tcp_posix.c`)、`src/zp_network_posix.c` (元
`src/system/unix/network.c`)、`ports/esp32/zp_tcp_esp32.c` (元 `src/link/transport/tcp/tcp_esp32.c`)、
`include/zenoh_espidf_platform.h` (元 `include/zenoh-pico/system/platform/espidf.h`)。ほかに元にしたファイルは無い
(5 章の点検で確かめた)。

ヘッダを次の形にそろえた。

1. 元の著作権 (ZettaScale Technology、年は元のファイルどおり 2022 か 2026) と、こちらの変更の著作権。
2. 「zenoh-pico 1.10.1 のどのファイルから作ったか」と、元のファイルの表示をそのまま引用したもの (著作権、許諾の文、
   元の SPDX、Contributors)。元の表示は PIN の checkout (e1ab223a) から写した。
3. 「zenoh-pico の 2 つの許諾のうち Apache-2.0 を使う。変更したファイルで、MIT ではなく Apache-2.0 で配る」。
4. `SPDX-License-Identifier: Apache-2.0`。
5. その下に元からある「何を変えたか」の説明 (変更の表示)。「Based on that file (Copyright ..., EPL-2.0 OR
   Apache-2.0)」の重複は消した。zp_tcp_posix.c の「three changes」は実際は 5 つだったので「these changes」に直した。

引用した元の表示にも `SPDX-License-Identifier: EPL-2.0 OR Apache-2.0` の行が残るので、SPDX を機械で拾う道具は
2 つの行を見る。どちらでも Apache-2.0 で使えることに変わりはないので、元の表示を崩さない方を選んだ。

### 2.2 LICENSE-APACHE と NOTICE

- `LICENSE-APACHE`: Apache License 2.0 の全文。中身は `/usr/share/common-licenses/Apache-2.0` と同じもの
  (sha256 `cfc7749b...`、asterism の `data/msgs/LICENSE-Apache-2.0.txt` とも同じ)。
  - zenoh-pico と zenoh-c の LICENSE は 1 つのファイルに Apache-2.0 と EPL-2.0 を並べた形で、Apache-2.0 の部分は
    第 9 条で終わる (「END OF TERMS AND CONDITIONS」と付録が無い)。zenoh-c の Apache-2.0 の部分は、上の全文の
    第 1-9 条と空白を除いて一致した。
  - **zenoh-pico の LICENSE (PIN の e1ab223a) は本文が壊れている**: `purpose` が 7 か所 `pur_pose` になっている
    (上流で識別子を一括で置き換えたときの巻き添えと見られる)。zenoh-c の同じ部分は正しい。だから zenoh-pico の
    LICENSE を切り出さず、上の全文を置いた。
- `NOTICE`: 前半にこのリポジトリの事情 (どのファイルが Apache-2.0 か、zenoh-pico を Apache-2.0 で使うこと、
  zenoh-pico 本体はビルドのときに取ってくること)、後半に zenoh-pico 1.10.1 の `NOTICE.md` を 1 バイトも変えずに
  付けた (cmp で一致を確かめた)。Eclipse の商標の文もここに入る。

## 4. ROS 2 の型 (asterism)

### 4.1 表示の辿り方

- 型の置き場所 `data/msgs/` には `NOTICE` と `LICENSE-Apache-2.0.txt` がある (C2 から)。`NOTICE` に上流の
  リポジトリ 3 つの URL と、asterism のリポジトリの URL、定義の置き場所 (`tools/ros2_jazzy`) を足した。機体の
  storage には data/msgs だけが写るので、ここだけで出所が分かるようにした。
- 最上位の `NOTICE` から data/msgs、tools/ros2_jazzy、test/msgs の照合値の 3 つが辿れる (C2 から)。package.xml の
  写しを足したことを書き足した。README の License からも NOTICE と data/msgs/NOTICE を指す。

### 4.2 生成したファイルの先頭

前は「`geometry_msgs/msg/Twist` を Twist.msg から作った」だけで、パッケージ名は型の名前から読めるが、許諾は
書いていなかった。変換器 (`tools/asterism_msggen.rb`) を次のように直した。

```
# geometry_msgs/msg/Twist (ROS 2 jazzy), generated by asterism_msggen.rb from
# Twist.msg of the package geometry_msgs.
# License: Apache License 2.0, as the definition (package.xml of geometry_msgs).
# Do not edit; regenerate instead.
```

- 許諾は、定義を探す場所の `<pkg>/package.xml` の `<license>` から取る (ROS の並びそのものなので、
  `-I /opt/ros/jazzy/share` で使う人にもそのまま効く)。package.xml が無いパッケージ (試験用の
  asterism_test_msgs、利用者の自前の型) では License の行を出さない。思い込みで Apache-2.0 と書かないため。
- `tools/ros2_types.rb` は像から package.xml も取り、使ったパッケージ 6 つの分を `tools/ros2_jazzy/<pkg>/package.xml`
  に置く。docker の要らない試験 (test:msgs) も同じ package.xml を読んで同じ先頭を作る。6 つとも
  `<license>Apache License 2.0</license>` (C2 で確かめたものと同じ)。
- 型を作り直した: 親の像 `fmruby-ros2-jazzy-zenoh:local` で `ruby tools/ros2_types.rb --image ...`。
  型のハッシュ 153 件が像の JSON と一致、62 の型を書き直した。変わったのは先頭のコメントだけで (差分は
  ヘッダの行のみ)、定義と `type_hashes.txt` は 1 バイトも変わらなかった。
- 大きさ: 62 ファイルで 67,635 -> 74,265 バイト (+6,630)。4 KB の境を越えたファイルは無い。
- `test/test_layout.rb` に「同梱の型はすべて先頭にパッケージと許諾を書いている」試験を足した。package.xml が
  消えると変換器は黙って License の行を落とすので、それを捕まえるため。

### 4.3 gemspec、README

- gemspec: `s.license = "MIT"` (注釈で「後で決める」) を `s.licenses = ["MIT", "Apache-2.0"]` にした。gem に
  data/msgs (Apache-2.0) が入るので、MIT だけでは実態と合わない。RubyGems は SPDX の式 (`MIT AND Apache-2.0`) を
  受け付けないので配列で書き、「それぞれ自分のファイルに」と注釈にした。
- README の License: 生成した型は先頭に許諾を書くこと、gem は MIT と Apache-2.0 であること、依存 (CRuby の
  `msgpack` と `asterism-zenoh`、mruby の `picoruby-asterism-zenoh`) は同梱していないこと。
- mrbgem.rake の `license = 'MIT'` は実態どおり (mrbgem は mrblib だけで、型は含まない) なので変えていない。

## 8. 親が公開の前に見るべき点

1. **push の順番**: asterism (`95477ce`)、picoruby-asterism-zenoh (`44976fd`) を push してから fmruby-core。
   asterism-zenoh (`33b0fa7`) は PIN から参照されないので順は自由。
2. **取得の確認**: push の後、上書きの環境変数なしで `vendor/asterism` と `vendor/picoruby-asterism-zenoh` を消して
   `rake setup` を 1 度回し、PIN のコミットに着地することと、`components/picoruby-esp32/picoruby/mrbgems/
   picoruby-asterism-zenoh/` に LICENSE-APACHE と NOTICE があることを見る。
3. **URL の切り替えと一緒に直す注釈**: `lib/add/ASTERISM_PIN` (7-8 行目)、`lib/add/PICORUBY_ASTERISM_ZENOH_PIN`
   (8 行目)、fmruby-core の `Rakefile` (110 行目) に「private for now / ssh / CI は取れない」とある。
4. **GitHub の許諾の自動判定**: picoruby-asterism-zenoh の LICENSE は MIT の本文の後に節を足したので、GitHub
   (licensee) が「MIT」と判定しない (Other になる) かもしれない。公開後に表示を見て、気になるなら節を
   LICENSE から外して README と NOTICE だけに置く手がある (指示書は LICENSE に節を求めているので、今はこの形)。
5. **zenoh-pico の LICENSE の壊れた本文** (`pur_pose`): 上流への報告の候補。こちらの配布物は正しい全文を使って
   いるので実害は無い。fmruby-core の `rake setup` はビルドの木に zenoh-pico の LICENSE をそのまま写す (上流の
   ファイルなので手を入れない)。
6. **ビルド済みの gem を出すとき** (今は出していない): asterism-zenoh で zenoh-c を同梱するなら README の
   「配布の注意」の 3 つ、特に Rust の crate の表示の一覧が要る。今はまだ作っていない。
7. **履歴に残る機体の名前** (5.4): 公開済みの fmruby-core にもあるので問題は無いと見たが、気にするなら公開前が
   最後の機会 (公開後の履歴の書き換えは重い)。
8. mrblib などの注釈が `doc/ruby_asterism/design.md` (fmruby-core にある) を指している。許諾の話ではないが、
   asterism だけを見る人には辿れない。
