# MJ-L 報告: ふつうの麻雀ゲームの見た目の卓 (Web 版 1280x720)

> 状態: 完了 (検収待ち) | 更新: 2026-10-15 | instruction_mj_layout.md の実装と確認の記録。Web 版の解像度の選択肢に 1280x720 を足し、その大きさで見本の画像の形の卓 (4 方向の河と中央の板、他家の手牌の側面、鳴き・リーチの横の牌、手牌の右上のボタン) を卓のアプリの描き方の 1 つとして足した。牌の絵は今の 2 枚のシートを生成スクリプトで拡大・回転して作り、描画は変わった牌だけを描き直す。ゲームホストには途切れた席の待ち時間を短くする案 A を入れた。ブラウザ版で自分 1 人と CPU 3 人の半荘を注入の操作で 2 回最後まで打った。打牌から画面までは中央値 76 ms・95% 79 ms (640x360 の今の卓は 65 ms・72 ms)。zenohd・ゲームホスト・開発サーバは `rake mahjong:up` 1 つで起きる

## 2. 解像度: 1280x720

**1280x720 を選んだ**。Web 版に足すのは軽く、見本の配置がそのまま 2 倍で入る。

- 足したのはページの側の 2 行だけ (`wasm/web/main.js` の `RESOLUTIONS` と `index.html` の選択肢)。機械の側 (`wasm/backend/page_settings_wasm.c`) は前から 1920x1080 までの `--fmrb-res` を受けていて、`display_width`・`display_height` と窓の既定の大きさを書き換える。表示の作り (display_local の合成、RGBA への変換) は大きさに依らない。
- メモリ: 画面 1 枚 (RGB565) が 1.8 MB、全画面のアプリの canvas が作業用と確定用の 2 枚で 3.7 MB。wasm の初めのメモリ (256 MB、伸びる) に比べて小さい。卓のアプリの VM のプールは 574 KB (1,536 KB の 37%。640x360 のときは 468 KB・30%)。
- 速さ: 表示の側の 1 回の合成は、計装 (`render: ... avg max`、1 ms 単位) で 1280x720 でも avg・max とも 0 ms (1 ms 未満)。打牌から画面までの差は 4 章。
- ほかのアプリ: デスクトップもエディタも 1280x720 で動く (エディタは開いて 1 打鍵まで確かめた、`s5_web1280_editor_one_key.png`)。見た目は調整していない (指示どおり): 壁紙は 1280x720 の絵が無いので 426x240 の絵が左上に出る (`theme_wallpaper` の決まり: その大きさの絵が無ければ 426x240)、エディタの窓は小さいまま。
- 1280x720 のページでは `fullscreen_hires` は効かない (基本の大きさが 426x240 のページだけ)。卓は全画面で 1280x720 の canvas をそのまま使う。
- 852x480 は使わなかった: 1280x720 で困ることが無かった。

## 3. 牌の絵

### 3.1 作り方

- 新しいシートは描画のコードからではなく、**今の 2 枚のシート (`tiles_hand.bmp`・`tiles_river.bmp`) から作る**。シートが正 (mj1.md 3 章) なので、ユーザがシートを手で直したら `ruby tools/mahjong_tilegen.rb --layout-sheets flash/app/game/mahjong flash/app/game/mahjong/large` で作り直す。することは整数倍の拡大 (最近傍) と 90 度単位の回転だけで、絵柄は変えない。作り直すと上書きする (手で直すのは元の 2 枚)。
- 確かめ: 新しいシートの全部の牌を逆に回して元のシートと比べ、元の 293,664 画素がすべて一致した。今のファイルとスクリプトの出力はバイト単位で同じ。
- 他家の手牌の側面 (`tiles_side.bmp`) は元の絵に無いので、手牌のシートの裏の牌 (37) の縁・地・内側の線の 3 色を取って描いた (立てた牌の上端に内側の線の色を 4 px)。
- シートは BMP の上限 (2048 px) とスプライトのファイルの上限 (256 KB、display_local) の内に収める (超えればスクリプトが止まる)。手牌の 2 倍は 1 枚にすると 357 KB なので 2 枚に分けた。

### 3.2 大きさ・向き・シートの並び

回転は時計回り (r90 は絵の上が右を向く)。自分 r0、上家 (左) r90、対面 r180、下家 (右) r270。横に倒す牌 (リーチの宣言牌、鳴いた牌) は席の向きに 270 を足す。

| ファイル | 大きさ | 1 枚 | 元 | 倍 | 向き | 使うところ |
|---|---|---|---|---|---|---|
| `tiles_hand2_a.bmp` / `_b.bmp` | 840x224 ずつ | 84x112 | 手牌 | 2 | - | 自分の手牌 (a は牌 0-19、b は 20-37 を n-20 で) |
| `tiles_river2_r0.bmp` | 480x256 | 48x64 | 河 | 2 | 0 | 自分の河と鳴き、局の結果の手 |
| `tiles_river2_r90.bmp` | 640x192 | 64x48 | 河 | 2 | 90 | 上家の河、対面の横の牌 |
| `tiles_river2_r180.bmp` | 480x256 | 48x64 | 河 | 2 | 180 | 対面の河、下家の横の牌 |
| `tiles_river2_r270.bmp` | 640x192 | 64x48 | 河 | 2 | 270 | 下家の河、自分の横の牌 |
| `tiles_river_r90.bmp` ほか 2 枚 | 320x96 / 240x128 / 320x96 | 32x24 / 24x32 | 河 | 1 | 90 / 180 / 270 | 他家の鳴き (r0 は元の `tiles_river.bmp`) |
| `tiles_side.bmp` | 72x32 | 32x20 と 20x32 | 裏の色 | - | - | 他家の手牌 (対面・上家・下家の 3 枚) |

- 並びは元と同じ 10 列の格子 (牌 n は `src_x = (n % 10) * 幅`、`src_y = (n / 10) * 高さ`)、透明は RGB332 0xE3。表は `flash/app/game/mahjong/large/README.md` とスクリプトの先頭。
- 合わせて 976 KB。Tab5 と NARYAv4 (アプリが使えるのは 640x360 まで) のイメージからは `config/storage_exclude_tab5.txt`・`storage_exclude_naryav4.txt` で `app/game/mahjong/large` を外した (Retro は前から卓ごと外している)。sim とブラウザ版は flash/ の全部を持つ。
- 読み込み: 卓が 1280x720 になったときだけ 10 枚を読む (ブラウザ版で合わせて約 0.35 秒、1 枚 15-47 ms)。

### 4.2 描き直しの量

毎回全部を描き直さない。牌・裏・枠の 1 つずつを「部品」(位置・大きさ・シートの切り出し・印) にし、描くたびに河 4 つ・他家の列 3 つ・自分の手牌・自分の鳴きの部品の一覧を作って、前に描いた一覧と比べる。

1. 変わった部品は、前の位置を卓の緑で消して描き直す。
2. 消した矩形に触れる、変わっていない部品も描き直す (部品どうしは重ならないので、ふつうは無い)。
3. 文字の所 (中央の板、残り秒、ボタン) は中身の印 (signature) を持ち、変わったときだけその所を描き直す。ボタンは前のボタンの矩形だけを消す。
4. 画面が変わるとき (卓に着いた、局の結果が出た・消えた) だけ全部を描く。結果の箱は出ている間は描き直さない。

- 打牌 1 回で描くのは、自分の手牌のうち位置が変わった牌、河の 1 枚 (と前の最後の牌の枠)、板 (残り枚数が変わる)、ボタン。秒の表示は 1 秒ごとに左下の 470x56 だけ。
- 1 回の描画で描いた画素 (塗りと牌の和、2 回目の半荘 1,247 回): 中央値 71,168、95% 132,576。全部を描くとき (画面を消す 921,600 と牌) は約 135 万で、ふつうの描画はその約 5%。640x360 の今の卓は毎回全部を描く (消す 230,400 と牌で約 33 万)。
- 牌を描く `draw_tile` は 1 画素ずつ写す (mj1.md 3.1)。手牌の 1 枚が 9,408 画素なので、手牌の全部を描き直すと 13 万画素になる。打牌で牌が詰まる分だけ描くので、右側ほど描き直しが多い。

### 4.3 時間 (ブラウザ版、同じ PC、同じゲームホスト、CPU の間 400 ms)

アプリの「応答」(打牌の act を送ってから、その打牌が入った見え方を描き終えて present するまで) と、アプリが 1 回の描画の命令を出し終えるまで (draw_screen の時間) を、`/home/mahjong_perf.on` があるときアプリが `/home/mahjong_perf.txt` に書く形で測った。

| | 打牌から画面 (中央値 / 95% / 最大) | 1 回の描画 (中央値 / 95% / 最大) | 回数 |
|---|---|---|---|
| 1280x720 (新しい卓、変わった所だけ) | 76 / 79 / 94 ms | 7 / 16 / 29 ms | 打牌 179、描画 1,247 (半荘 1 回) |
| 640x360 (Step 1 の卓、毎回全部) | 65 / 72 / 79 ms | 5 / 9 / 15 ms | 打牌 154、描画 1,092 (同じ版のアプリ、半荘の途中まで 200 手) |

- 打牌から画面までは 11 ms 長い。中身は act の往復とゲームホストの処理 (両方で同じ、mj1 の CRuby からの往復 15 ms 前後) と、描画と、表示の側の合成と RGBA への変換 (画素が 4 倍)。1280x720 の描画は変わった所だけでも牌が大きい (手牌 1 枚が 4 倍の画素) ので、命令を出す時間は 640x360 の全部の描き直しより少し長い。
- パス (Esc) から画面までは両方とも約 490 ms (1280x720 で中央値 493、640x360 で 495)。誰も鳴かなかったときにゲームホストが CPU の間 (この確かめでは 400 ms) を置いてから進める作り (mj2.md 2.2 の 5) のためで、描画とは関係ない。鳴き・次へは 60-63 ms。
- 1 回目の半荘 (種類を分けずに測った版) も同じ形: 応答 292 回の中央値 77 ms、描画 1,728 回の中央値 8 ms・95% 17 ms。

## 5. 案 A (長く戻らない席)

- asterism-games の卓に `away_wait_ms` (設定 `away_wait_seconds`、環境 `MAHJONG_AWAY_WAIT_SECONDS`) を足した。**既定は 2 秒**。
- 途切れた席 (`away_seconds`、既定 10 秒、mj2.md 2.3) の手番は、待ち始めから 2 秒で自摸切りになる (20 秒でなく)。鳴きの待ちでは、途切れた席だけ待ち始めから 2 秒でパスになり、ほかの人は自分の締め切りまで待てる。見え方の `dl` は途切れた席の手番では短い方の残りを出す。
- 待ち始めた後に途切れたと分かった場合 (途切れの判定は 10 秒かかる)、そのときにもう 2 秒を過ぎていればすぐに打つ。
- 戻れば (卓を呼べば) 元の待ち時間に戻る。起動し直しても待ち始めからの経過を書き出しに残す (`wait_spent`)。
- 2 秒にした理由: CPU の間 (0.7 秒) より長く、他の 3 人に「途切れた人の番」と分かる長さで、半荘の中で何度来ても 1 回 2 秒で済む。0 にすると途切れた人の番が CPU と区別できない速さで過ぎる。
- 試験 (`test_mahjong_rules.rb`): 途切れる前は 20 秒・途切れた後は待ち始めから 2 秒で打つ・次の手番は最初から 2 秒・戻ると 20 秒に戻る、10 秒以内に戻った人は 20 秒のまま、鳴きでは途切れた人だけ先にパスしてほかの人は残り秒のまま、設定と環境変数。前からの試験 1 つ (局の途中の書き出しと読み戻し) は、元の卓の人を「今見た」にしてから比べる形に直した (直さないと元の卓だけその人が途切れ扱いになり、残り秒が違う)。

### 6.1 半荘

- 構成: 親リポジトリの zenohd (`docker-compose.yml` + `docker/asterism/docker-compose.zenoh-ws.yml`)、ゲームホスト (`config/example.yml`、`MAHJONG_CPU_MS=400`、状態は作業用の場所)、`rake wasm:serve` の開発サーバ、Windows の Chrome (headless) で `?w=1280&h=720&app=/app/game/mahjong/mahjong.app.rb`。
- 操作はページへの注入 (`tools/fmrb_web.rb`、web_input と同じ口) だけ。どれを押すかは、ゲームホストが書き出した状態からその席の一覧を計算して決める作業用のスクリプト (mj1 と同じ形、公開しない) に任せた: ツモ・ロンは必ず、リーチは出たら必ず、ポン・チーは 1 局の最初の 4 回、ほかはパス、打牌は手牌のツモの牌の**クリック**、結果は Enter。
- 1 回目: 15 局 (ロン 5・ツモ 2・流局 8)、自分の操作 296 回 (注入のクリック・キー)、自分の点が 0 未満になって (トビ) 終局。途中で 1 回ゲームホストを止めて起動し直した (鳴きの並びの直しを入れるため。同じ場面から続いた)。
- 2 回目: 終局の画面から待ち合わせに戻ってもう一度始め、終局まで (自分の操作 158 回、1 打目でのリーチを 1 回)。4.3 の数字はこの半荘。
- 3 回目: 見本の要素が 1 枚にそろう場面 (リーチの横の牌・鳴き・右上のボタン) の写しを取るために打った (写しが取れたところで止めた)。
- 1 通の最大はゲームホストのログで 524 B (見え方の答え、止めたときに出す値)。

## 8. ユーザが触る手順

`C:\Users\Public\asterism_deploy\mj_layout\HOWTO.md` に置いた。要点:

1. WSL の fmruby-core で `rake wasm:dist` (一度)、`rake mahjong:up` (同じもの `ruby tools/mahjong_local.rb up`)。zenohd (ws つき)・ゲームホスト・開発サーバのうち動いていないものを起こし、開く住所を出す。開発サーバは `wasm:dist` の自己完結の束 (`wasm/build/dist`、ページのコードと機械をその時点で写したもの) を出す (`rake wasm:serve DIST=1`)。開発の形 (`/wasm/web/`) だとページのコードが作業コピーから読まれ、develop に戻すと 1280x720 の選択肢が消えるため。
2. Windows の Chrome か Edge で `http://localhost:8006/index.html?w=1280&h=720&app=/app/game/mahjong/mahjong.app.rb`。`w=1280&h=720` が解像度 (ページの Resolution の 1280 x 720 と同じ)、`app=` で卓が開く。
3. 卓の一覧で mahjong1 を Enter、`1` で座る、`C` で CPU を入れる、Enter で始める。
4. 止めるのは `rake mahjong:down` (zenohd を残すなら `KEEP_ZENOHD=1`)。作業コピーが develop のときは `git show feature/mj-layout:tools/mahjong_local.rb | ruby - down` (fmruby-core で)。

- 届くこと: Windows の Chrome (WSL の外) から、WSL の localhost の開発サーバ (8006) と zenohd の ws (7449、docker が WSL の loopback に出している) の両方に届いた (6.1 の確かめはすべてこの形)。G2 Step 2 で中継が要ったのは Docker の container の中のブラウザだったため (mj2.md 5.1) で、Windows のブラウザでは要らない。
- 気をつけること: sim (sim_up / sim_down) は親の compose で zenohd も作り直し・片付けるので、ws の listener が消える。sim を使ったあとは `rake mahjong:up` で戻る (ws が無ければ起こし直す)。
