## 2. 途中で変わった仕様 (2026-10-12 ユーザ) と、作ったものへの影響

1. **サーバの console が唯一の console**。bin/signer もサーバに置く (計画の案 A)。CA の鍵は signer の container だけが
   mount する volume (`signer_ca`) に置き、signer は compose の中の internal な網 (`signer`、外へ出る道なし、入るのは
   console だけ) で待つ。手元の console は開発の道具として残るが、台帳と ACL の正はサーバのもの。
   - 先に作っていた「この console では発行しない」形 (証明書だけを持ち込む画面と `Relay::Importer`) は捨てた。
     `bin/rails relay:import` (W1 の証明書の取り込み) は残した。
2. **鍵はブラウザで作る**。発行の画面で Web Crypto が ECDSA P-256 の鍵の組を作り、公開鍵 (SPKI) だけを送る。signer は
   その公開鍵に、今までと同じ名前・SAN・拡張 (CN = 相手の名前、serverAuth と clientAuth) の証明書を署名する。画面は
   秘密鍵 (PKCS#8 PEM)・証明書・CA・設定の例を 1 度だけ出し、Copy と Save to file のボタンを付けた。ページを離れる
   ときは確かめのダイアログを出し、離れれば鍵は失われる (再表示なし。なくしたら失効して発行し直す)。
   - console は秘密鍵を受け取る場所を持たない。誤って秘密鍵を送ると断る。ページと答えは `Cache-Control: no-store`。
     公開鍵と PEM はログに出ない (`spki`・`pem` を filter に足し、実物のログで `[FILTERED]` と、PEM の行が 0 であることを
     確かめた)。https か localhost でないページでは、ボタンを止めてその旨を出す。
   - 以前の tar のダウンロードは無くした。道 (`POST /admin/relay/peers/:id/certificates`) は同じで、`{"spki": ...}` を
     受けて JSON を返す。tar に頼っていたものは無かった (W2 の headless の撮影の手順だけ)。
   - サーバ自身の身元 (ルータと bridge の証明書) は、鍵がどのみちサーバにあるので、`bin/rails relay:issue_local` が
     サーバの中で作る。
   - CSR と違い、公開鍵だけでは「秘密鍵を持っている」証明にならない。ただ証明書は秘密鍵なしでは使えず、頼めるのは
     管理者だけなので、要らないと判断した (docs/g0_w4.md に書いた)。
   - Chromium の Web Crypto が出した PKCS#8 の鍵を、zenohd 1.10.1 (rustls) がそのまま読めた (家のルータの
     `connect_private_key`、CRuby の zenoh-c の両方)。
3. CA の鍵をサーバの外へ控える手順を `deploy/vps/README.md` 9 章に書いた (`docker compose exec -T signer tar` を
   gpg で暗号化して家へ。手元の構成で tar の中身 (ca.pem・ca.key・issued.log、権限つき) を確かめた)。

## 3. サーバの一式 (`asterism-console/deploy/vps/`)

| サービス | 待ち受け (container の中) | サーバで公開 | 相手 |
|---|---|---|---|
| zenohd (eclipse/zenoh 1.10.1) | `tls/7448` (mTLS、自前の CA) | `${ROUTER_TLS_BIND}:${ROUTER_TLS_PORT}` (0.0.0.0:7448) | 家のルータ・端末・CRuby が直接 |
| | `ws/7449` (ブラウザ) | `127.0.0.1:${ROUTER_WS_PORT}` | nginx だけ (合言葉を確かめてから) |
| console (Rails、production) | 3000 | `127.0.0.1:${CONSOLE_PORT}` | nginx だけ |
| bridge | - | - | `tls/zenohd:7448` に console の証明書で |
| signer | 7450 | 無し | console だけ (internal な網) |

- 外に開けるのは 7448 (ルータの mTLS) と 7443 (nginx の wss://、仮の番号) だけ。3000 と 7449 はループバック。
- ルータの設定は console が台帳から作る (`generated` volume)。「Apply」は設定を書き、`bin/relay_restart_request` が
  要求のファイルを書く。zenohd の container の `zenohd/run.sh` (busybox の sh) がそれを見て zenohd を起動し直す。
  console は docker の権限を持たない (W2 の残りの課題「反映の権限」はこれで閉じた)。
- console は user 1000、signer は user 1001。秘密の値は `.env` (例は `env.example`、git に入れない)。
- image は 1 つ (`deploy/vps/Dockerfile`、ruby 3.2.6-slim の 2 段)。console・bridge・signer が同じ image を別の
  コマンドで動かす。console は起動のたびに `db:prepare` する。
- nginx (`deploy/vps/nginx/`): `asterism-http.conf` (http の中: map・limit・ログの形)、`asterism-upstreams.conf`
  (ループバックのポート)、`asterism-console.conf` (サブドメイン、80 は https へ、`/admin` は IP で絞る、`/session` と
  `/invitations/` に回数の上限、`/passes/check` は外から 404)、`asterism-router.conf` (wss:// の入口、
  `auth_request`)、snippets 5 つ (転送の header、管理者の IP、遊ぶ人の IP、証明書 2 つ)。名前はすべて `asterism_` で
  始め、ほかのサイトの設定とぶつからないようにした。

### 3.1 zenohd の設定 (1.10.1 で確かめた項目名)

W1 の TLS の部分 (`root_ca_certificate`・`listen_certificate`・`listen_private_key`・`enable_mtls: true`・
`close_link_on_expiration: true`) に、次を足した。

| 項目 | 値 | 確かめ |
|---|---|---|
| `listen/endpoints` | `tls/[::]:7448`、`ws/[::]:7449` | |
| `transport/unicast/max_sessions` | 64 (`ASTERISM_RELAY_MAX_SESSIONS`) | 4 にして ws で 6 本開くと、5 本目から `Unable to connect` |
| `transport/unicast/accept_pending` | 16 | 起動の `Initial conf` に出る |
| `transport/unicast/accept_timeout` | 5000 ms | 同上 |
| `transport/link/rx/max_message_size` | 4 MiB | 同上 |
| ACL の subject `link_protocols: ["ws"]` | ブラウザ (ws/ のセッション) をまとめて 1 つ | ws の CRuby がその規則で通った |
| ACL の key_exprs の `asterism/wasm-$*` | `wasm-` で始まる ID だけ | 起動でき、`wasm-abc123` が通り、`alice` は通らない |

`max_sessions` はルータに張られるセッションの総数 (家のルータ・bridge・ブラウザを含む)。

### 3.2 ACL (台帳から作る。`lib/relay/cloud_config.rb`)

台帳の相手に「Player」(遊ぶ人) の印と「代わりに話すノード」(空なら自分の名前。家のルータなら、その後ろの端末の
ID) を足した。遊ぶ人ごと・共通の規則は次のとおり。既定は拒否。

| 規則 | 種類 | 向き | キー |
|---|---|---|---|
| `<相手>_own` | 全 9 種 | 両方 | `asterism/<ノード>`、`asterism/<ノード>/game/**`、`asterism/<ノード>/@profile` |
| `game_in` (共通) | 購読・問い合わせ・生存の問い合わせ | 相手から | `asterism/*`、`asterism/*/game/**`、`asterism/*/@profile` |
| `game_out` (共通) | 全 9 種 | 相手へ | 同じ 3 つ |
| `game_watch` (共通) | 生存の購読の宣言 | 相手から | `asterism/**` |

- 自分のノードの場所にだけ書ける (値・queryable・生存のしるし)。ほかの人のノードの `game` は読めて呼べる
  (呼び出しは問い合わせ)。
- `game_watch` が要るのは、asterism の gem が `asterism/**` に生存の購読を 1 つ宣言するため (on_join / on_leave)。
  1.10.1 は許した範囲より広い宣言を丸ごと断る (W1 5 章)。届く中身は `game_out` で絞られるので、ほかのアプリ
  (家の `demo` など) のしるしは外に出ない。
- `demo`・`fmrb`・ROS 2・管理用の空間 `@/**` は、台帳で足さない限り通らない。
- ブラウザ (`ASTERISM_RELAY_BROWSERS` を置いたとき): ws/ のセッションは 1 つの subject で、`asterism/wasm-$*` を
  自分の場所とする同じ規則。ルータはブラウザどうしを見分けられない (証明書が無く、zenoh-pico に利用者名とパスワードの
  認証も無い) ので、あるブラウザがほかのブラウザの `wasm-*` に書けることは残る。遊ぶ人の場所には書けない。
- **キーの範囲は仮**。G1 の遊びが各ノードの `game` という 1 つのアプリだという前提。アプリ名が違えば
  `ASTERISM_RELAY_GAME` で変えられる。1 つのアプリに収まらないキー (待ち合わせの場所、共有の状態) が要るなら、規則を
  足す必要がある。G1 で決める。

### 3.3 ブラウザ版の合言葉

1. ログインした人が「Make a pass」を押す (Browser passes の画面)。console は合言葉の SHA-256 だけを、作った人・
   時刻・住所とともに残し、合言葉を 1 度だけ、ブラウザ版を開くリンクとともに出す
   (`?zenoh=ws/router.example.org:7443&zenoh_pass=<合言葉>`)。有効は 10 分 (`ASTERISM_PASS_TTL`)。1 人あたり有効な
   ものは 3 つまで (古いものから失効)。本人と管理者が取り消せる。管理者は全員の分を `/admin/passes` で見る。
2. ブラウザ版は `wss://router.example.org:7443/?pass=<合言葉>` につなぐ (下の案)。
3. nginx は WebSocket を開く前に `auth_request` で console に問う。副要求は元の URI を `X-Original-URI` で渡し、
   console は 204 (有効) か 401 (無い・知らない・期限切れ・取り消し) を返し、使った回数と断った回数を数える。
4. 確かめるのはつなぐときだけ。開いている接続は、合言葉が切れても取り消されても続く (ルータに後から問う手段が無い)。
   ページを閉じれば終わる。
5. 合言葉は URL に入るので、wss の入口のログは問い合わせの部分を出さない形 (`asterism_noquery`) にした。console の
   要求のログには `/passes/check` しか出ない (実物で、合言葉の文字列がログに 0 回であることを確かめた)。

**ブラウザ版の直しの案 (fmruby-core、この段では触っていない)**。今のページは WebSocket の URL を
`ws(s)://<host>:<port>/` と組み (wasm/zenoh/zp_ws_emscripten.c の `_z_ws_endpoint_init` と `zp_ws_js_open`)、
合言葉を載せる場所が無い。ロケータ (`ws/<host>:<port>`) にも載らない (ページの `ZENOH_RE` が通さない)。案:

- wasm/web/main.js: `?zenoh_pass=` を読み (その回だけ。保存しない、system_conf.toml にも入れない)、`Module` に置く。
  読んだら `history.replaceState` でアドレス欄から消す (履歴・画面の共有に残さない)。形は `[A-Za-z0-9_-]{20,100}`。
- wasm/zenoh/zp_ws_emscripten.c の `zp_ws_js_open`: `wss://` を選んだとき、`Module` に合言葉があれば URL に
  `?pass=<encodeURIComponent した合言葉>` を足す。ループバック (`ws://` のまま) には付けない。
- Network の枠に「pass: set (this visit)」を出す。ID (`wasm-<16 進 6 桁>`) と合言葉の持ち主は結び付けない (ルータが
  見分けられないため。上の 3.2)。
- 手元の確かめは、この直しの代わりに、試験のブラウザに WebSocket の URL へ `?pass=` を足す小さなスクリプトを
  先に入れて (Playwright の `addInitScript`) 行った。ブラウザ版の束 (B2 の写し) はそのまま。

## 4. console を Web に出す守り (W4)

- **招待制**: 登録の画面は無い。管理者が招待のリンクを作る (Admin > Users。1 度だけ、72 時間。SHA-256 だけを残す。
  管理者としての招待もできる)。開いた人がメールアドレスとパスワードを決めて利用者になる。同じリンクの 2 度目は 404。
- **総当たり**: Rails で住所ごとに 3 分 10 回、メールアドレスごとに 1 時間 20 回 (正しいパスワードも止まる)。nginx で
  住所ごとに 1 分 10 回 (余裕 5)。Rails の上限の店は production では cache の店 (solid_cache)、ほかでは専用の
  memory の店 (試験でも効く)。
- **管理者は TOTP 必須** (`CONSOLE_ADMIN_TOTP=required`、production の既定): 未設定の管理者はアカウントの画面
  (TOTP を有効にする) とログアウトしか使えず、管理者は TOTP を切れない。招待された管理者は登録の直後にその画面へ行く。
- **未ログインには何も見せない**: W2 のまま (HTML はログインの画面へ、JSON は 401、Action Cable は断る)。外に開く
  道は、ログイン・招待・`/up`・`/passes/check` (nginx が外から閉じる) だけ。経路の表を全部なめる試験に足した。
- **管理の画面の道は `/admin` の下に寄せた**: 台帳・証明書・反映 (`/admin/relay/...`)、呼び出しの許可
  (`/admin/call_permissions`)、利用者と招待 (`/admin/users`、`/admin/invitations`)、全員の合言葉 (`/admin/passes`)。
  nginx が `/admin` を IP で絞り、console も `CONSOLE_ADMIN_NETS` で絞る (2 重)。グラフの画面が使う「この
  オブジェクトに効く許可」は利用者向けに `/permissions` へ分けた。
- **記録は管理者だけ** (`/recordings`、`/playbacks`。役割で。`CONSOLE_ADMIN_NETS` も効く)。呼び出しの記録は、利用者は
  自分の分だけ、管理者は全員の分。
- **本番の設定**: HTTPS だけ (`force_ssl`、HSTS)。session の cookie は Secure・HttpOnly・SameSite=Lax。`CONSOLE_HOSTS`
  で Host を絞り、Action Cable の Origin も同じ。CSP (スクリプトは同じ origin と import map の nonce だけ、style は
  同じ origin と nonce と Turbo の進み具合の棒の hash、style 属性は許す、画像は同じ origin・data:・blob:、frame と
  plugin は無し)。ログから合言葉・鍵・証明書・コード・パスワードを除く。
- **重いトピック**: 眺める欄は 1 キーあたり毎秒 10 件 (W2 のまま) に加え、16 KB を超える値 (カメラの画像) は毎秒 2 件
  まで (`ASTERISM_WATCH_HEAVY_RATE`)。

## 6. 見立てと違った点・踏んだ罠

- **production の rake でも「公開して待ち受けるなら利用者が要る」の確かめが動いた**。`defined?(Puma::Server)` は
  bundle が puma を読むだけで真になる。サーバ (`bin/rails server` か puma) のときだけに絞った。
- **Applier は `ASTERISM_RELAY_COMPOSE_DIR` (既定は Rails の 1 つ上) で起動し直しのコマンドを走らせる**。container の
  中では `/` になり、相対の `bin/relay_restart_request` が見つからず、最初の反映が失敗した。compose で絶対の道を渡す。
- **auth_request の副要求は元の要求の引数を持たない**。`$arg_pass` は空になるので、`X-Original-URI $request_uri` を
  渡し、console の側で `pass` を読む。
- **Turbo の画面の移りと nonce**: Turbo は最初のページの CSP のまま次のページの nonce を使うので、進み具合の棒の
  `<style>` が断られた。棒の style の hash を許した。
- **Docker が公開したポートは ufw を素通りする**。7448 は ufw だけでは絞れない。手順書には DOCKER-USER の鎖の規則
  (ufw の after.rules) とさくらのパケットフィルタを書いた。DOCKER-USER の規則は手元では試していない (VPS で
  許す住所と断る住所から確かめる手順を書いた)。
- **compose の `env_file` は重ね合わせより先に読まれる**。サーバの compose の `.env` を手元の構成で差し替えられず、
  `ASTERISM_ENV_FILE` で道を変えられるようにした。
- **WSL2 の Windows のファイアウォール**: 家のルータを LAN の 17447 で出しても AtomS3R から届かなかった。W1 で使った
  7447 なら届いたので、手元の構成では 7447 で出した (`HOME_ROUTER_PORT`)。
- **家のルータの名前は図に出ない**。家のルータの管理用の空間はクラウドの ACL を通らない (台帳で「Admin space」を
  付けていない) ので、`router <zid>` と出る。台帳の印も名前で照らせない。

## 7. 残った課題・決めること

- **G1 のキーの範囲** (3.2): `asterism/<ノード>/game/**` は仮。G1 のアプリ名と、1 つのアプリに収まらないキーの有無で
  決める。
- **ブラウザ版の合言葉** (3.3 の案): fmruby-core の直しが要る。直すまでは、公開の版から wss:// の入口は使えない。
- **ブラウザどうしの見分け**: ルータは ws/ のセッションを 1 つにしか見ない。合言葉の持ち主とノードの ID を結ぶには、
  合言葉ごとに nginx がノードの ID を決めて渡す (ブラウザ版がその ID を使う) などの仕組みが要る。
- **wss:// の入口の番号と証明書**: 手順書は「サーバの今の名前の証明書で、専用の TLS のポート (7443 は仮)」とした
  (ほかのアプリと同じ流儀で、ポートごとに IP で絞れる)。サブドメインの 443 にする手もある。
- **7448 の IP の絞り込み**: DOCKER-USER の規則か、zenohd を host の網で動かすか。VPS で確かめて決める。
- **許す IP の一覧を台帳から作る** (plan の G0): 今回は作っていない。nginx の `asterism-players-allow.conf` と ufw・
  パケットフィルタは手で書く。台帳に「遊ぶ人の住所」を持たせて一覧を出すのは次の段。
- **反映でつながりが切れる** (W2 のまま): zenohd を起動し直すので、CRuby の Asterism のノードとブラウザ版は
  つなぎ直しが要る。
- **手元の console の役目**: 開発の道具 (fixture、手元の網) として残る。サーバの台帳を手元に写す仕組みは無い。
- **記録と `CONSOLE_ADMIN_NETS`**: 記録は管理者のものなので、その網の外にいる管理者は見られない。管理の網の外でも
  見たいなら、記録を `require_admin` の網の確かめから外す。
