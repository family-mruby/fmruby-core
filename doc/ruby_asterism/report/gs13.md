## 2. ホストの変更

- **ゲームごとの種類** (`lib/asterism_games/ai.rb`): `AI::GAME_KINDS = {"mahjong" => [claude, jev], "othello" => [jev]}` と `AI.kinds_for(game, kinds)`。Hub の `step` が各卓へ渡す種類をここで絞る (1 か所)。麻雀は今のまま claude・jev。ここに無いゲーム (board) は何も出さない。
- **オセロの卓** (`othello/table.rb`):
  - `cpu(token, seat, on)` の on に種類 (`"jev"`)。麻雀と同じ形: 空き席に Jev、CPU の席を Jev に (1 席を名指しのとき)、`true` で CPU に戻す、`false` で外す。出していない種類は `"no ai"` で席はそのまま。seat -1 は空き席だけを埋める。
  - view: `"ak"` (対局中でないとき、ホストが出せる種類があるときだけ。オセロは Jev の鍵があれば `["jev"]`)、`"ai"` (席ごとの種類、AI の席があるときだけ)。`"sk"` は AI の席も 2 のまま (古い画面には「Jev という名の CPU」に見える)。名前は `AI::LABELS` の `Jev` (2 席とも Jev なら Jev1・Jev2)。
  - @status (`summary`): `ais` を足した。
  - 問い合わせ: AI の席の番で、置ける升が 2 つ以上のとき `ai_requests` に出す。request は `"game" => "othello"`、`"instructions"` (オセロの決まりと view の読み方の英文、`Table::DESCRIPTION`)、`"view"` = `{"you" => "B"/"W", "board" => 8 行 (1 行目から、a-h), "discs", "n", "last", "moves" => [{"n", "square", "turns", "text"}]}`。答えの番号が範囲外・失敗・`ai_turn_ms` 内に来ないときは `Board::Cpu` が打つ。置ける升が 1 つなら問い合わせず CPU と同じく打つ (麻雀の「手が 1 つなら聞かない」と同じ)。
  - 待つ時間: 卓の設定 `ai_turn_seconds` (環境変数 `OTHELLO_AI_TURN_SECONDS`、既定 30 秒、麻雀の `ai_turn_seconds` と同じ)。この間 view の `dl` が残りを数える。
  - 上限: Budget は麻雀と共通 (同じ `ai_usage.json`、種類 jev で合算)。1 局あたり `calls_per_game` に達したら、その卓の AI の席を CPU に戻す (`ai_off!`)。1 日の上限に届いたら Hub が `ai_off!` を呼び、席は CPU になり `"ak"` から消える。
  - 保存: 席の `"ai"` は席ごと保存される。再起動で AI の番だったときは問い合わせをやり直す。
- **Remote** (`othello/remote.rb`): `cpu` の on に文字列を通す (麻雀の Remote と同じ)。メタの説明に `ai`・`ak` を足した。
- **鍵**: オセロ用の鍵や環境変数は足していない。麻雀の Jev と同じ `TYPESAFE_API_KEY`、同じ decider (`AI::Settings#deciders` の jev) を使う。

## 3. `play othello` の操作

- 待ち合わせ (と終局後) で卓の主が **`A`**: 相手の席 (空き・CPU) に Jev。もう一度 `A` で CPU に戻す。最後の行に `[A] Jev` / `[A] back to the CPU` が出る。`"ak"` が無い (鍵が無い・古いホスト) と出ない。`C` は空き席に CPU、Jev の席なら CPU に戻す。
- 1 行の命令: `ai [KIND]` (省略時は `ak` の先頭)、`cpu`。
- 席の表示は `Jev (AI)`、Jev の番の 1 行目は `move 1, last -, Jev is thinking, 30 s left`。案内は英語のまま。
- キー → 命令は純粋な関数 (`OthelloTty.key_command`、`ai_key_command`)。

## 4. 端末のオセロアプリの操作

- 待ち合わせで卓の主に、`CPU[C]` の上に **`Jev[A]`** (ボタンと A キー)。相手の席が空き・CPU のとき出る。Jev の席は `CPU[C]` (と C キー) で CPU に戻す。読み方は麻雀アプリと同じ `ai_kinds` / `ai_seat?` / `ai_label`。`"ak"` が無いホストでは今の画面のまま。
- 席の行に `Jev [AI]`。Jev の番は「Jev が考え中 (n 手目)」と「残り n 秒 (切れたら CPU が打つ)」。
- 断られたときの文言に `"no ai"` (「その AI は今は選べない」) を足した。
- アプリの Ruby だけの変更 (内蔵 RAM は変わらない)。VM プールは sim で対局中 540-549 KB (35 %)。

### 6.1 `play othello` (擬似端末)

Ruby の `PTY` で `asterism-games play othello` を起こし、キーだけを送った: `S` → `A` (Jev) → `A` (CPU に戻る) → `A` (Jev) → Enter → `:auto` で自分の手を打たせて終局まで。

```
  X seat1 Tester (you, owner)       0
  O seat2 (empty)                   0
  sit: ok
  [S] stand [C] CPU [A] Jev  [:] type a command  [Q] quit

  X seat1 Tester (you, owner)       0
  O seat2 Jev (AI)                  0
  ai jev: ok
  [S] stand [C] CPU [A] back to the CPU [Enter] start  [:] type a command  [Q] quit

  X seat1 Tester (you, owner)       0
  O seat2 CPU (CPU)                 0
  cpu: ok
  [S] stand [A] Jev [Enter] start  [:] type a command  [Q] quit

gs13games/games/othello1  move 1, last -, Jev is thinking, 30 s left
    a b c d e f g h
  ...
  4 . . . O X . . .
  5 . . . X O . . .
  ...
  X black Jev (AI)                  2 <
  O white Tester (you, owner)       2

gs13games/games/othello1  over: Tester (white) wins, 19-45
  X black Jev (AI)                 19
  O white Tester (you, owner)      45
```

ホストのログ: 20 回問い合わせ、18 回答え、2 回は Fake がわざと失敗 (`fake: failing on purpose (7); the CPU plays this move`) して CPU が打ち、終局まで進んだ (`game over (count, 19-45, seat 1 wins)`)。費用は `ai_usage.json` に jev として 18 回。

## 7. ユーザが選ぶこと: Retro でのオセロアプリの窓

1. **(推奨) 画面に合わせて窓を縮め、パネルを盤の右に詰める**: 窓を画面の幅に収め (320 幅なら盤の升を小さく、例えば 19 px)、ボタンを 2 列に並べ直す。Retro でもボタンと「考え中」が見える。アプリだけの変更。
2. 今のまま (窓 372x222): Retro はキーで遊ぶ前提とし、README に書く。
3. Retro だけ全画面の窓にする (`.app.toml` の設定で): 盤とパネルを 320x240 に配置し直す。

## 10. 追加: Retro で窓を画面に収める (ユーザの選択 1)

ユーザは 7 章の選択肢 1 (Retro では画面に合わせて盤を小さくし、パネルとボタンを切らさない。アプリだけの変更、Modern は今のまま) を選んだ。

コミット: fmruby-core `6a62938a` game: the othello table app takes the whole screen where its window does not fit (`othello.app.rb` のみ)。

### 10.1 やり方

- 窓の大きさは `.app.toml` の `default_window_width/height` だけで決まる。機種ごとに分ける書き方も、アプリが実行中に窓の大きさを変える手段も無い (`_set_window_param` は位置だけ)。toml を 320 幅以下にすると Modern の窓も変わる。
- そこで、画面が窓より狭いとき (`/etc/system_conf.toml` の `display_width` が窓の幅 372 未満) だけ、起動時に `request_fullscreen(true)` で画面全体をもらうことにした。前例は `flash/app/test/othello.app.rb` (128 幅の画面で同じことをする)。配置 (`layout`) はもともと利用領域から升の大きさを決めるので、320x240 では升が 21 px になり、盤 168 px の右にパネル (141 px) とボタン 2 列 (60 px × 2) が収まる。
- 画面全体だと窓枠の閉じるボタンが無いので、卓の一覧に「閉じる[Ctrl+Q]」ボタンを足した (画面全体のときだけ。Ctrl+Q でも閉じる)。卓の中からは Esc (出る) で一覧へ戻ってから閉じる。
- Modern (`display_width` 426) は何も変わらない。

### 10.3 A キーが反映されなかった件

sim で A キーを押すたびにアプリが受け取ったキーと命令をログに出す一時的な計装を入れ、15 回押した (クリックや間隔を変えて、写しも混ぜて)。結果は 15 回とも `key_down sc=4 ch=97` → `send_cmd ai cmd_f=nil` → 応答 `"ok"` (52-54 ms) で、取りこぼしは 0 だった。計装は外してからコミットした。

前回の 2 回は、どちらも「押したあとの写し」で判断していた。写しの並びを見直すと、毎回ちょうど 1 つ前の状態が写っていたと考えると全部つじつまが合う (卓の view をホストに問い合わせた結果は、つねに押した回数どおりに切り替わっていた)。1 枚の写しの中で席の表示とボタンが食い違っていたこともある (席は Jev、ボタンは Jev[A])。原因はアプリのキー処理ではなく、sim の写しが最後の描画を拾いきれていないことにある。GS5c の報告にある「呼び出しのあとの view が届くまで前の絵のことがある」と同じ現象。写しの側 (graphics-audio の共有メモリのダブルバッファの読み方) は今回の範囲の外なので追っていない。確認では、写しの代わりに卓の view を問い合わせて判断するのが確実。
