# MJ12 報告: BGM だけの音量、麻雀の BGM を 切/小/中/大

> 状態: 完了 (検収待ち) | 更新: 2026-10-19 | instruction_mj12.md の結果。APU の MAIN 側 (NSF と MAIN の FMSQ) にだけ掛ける音量を足し、アプリから `FmrbAudio#main_volume=` (百分率) で変えられるようにした。最後に下げたアプリが終わると kernel が 100 に戻す。Modern・ブラウザ版 (共通の C) と fmruby-graphics-audio (Retro・Linux sim) の両方に入れた。麻雀の BGM ボタンは 切→小→中→大 の巡回 (既定 小、仮の値 0/30/55/100%)。sim の音の数値で、段階どおりに BGM だけが下がり効果音の大きさは変わらないこと、閉じると 100% に戻ることを確認した

## 1. コミット

| リポジトリ | ブランチ | 中身 |
|---|---|---|
| fmruby-core | develop | 音声の C (apu_emu・audio_p4・audio_commands.h)、kernel の命令と後始末、`FmrbAudio#main_volume=`、sig、麻雀アプリ、はみ出し検査、`doc/reference/audio_output.md`、指示書とこの報告 |
| fmruby-graphics-audio | develop | apu_emu (apu_if.h・apu_if.cpp・apu_if_linux.c)、audio_task.c、音声の命令の受け口 2 つ (esp32・shm)、audio_commands.h |

push・タグはしていない。牌のシート (`tiles_hand.bmp` / `tiles_river.bmp`) は触っていない。

## 2. 口の形

- Ruby: `FmrbAudio#main_volume = percent` (0〜100、範囲外は詰める。既定 100 = 今までと同じ)。端末で 1 つの値。返す値は無い (読み出しの口は作っていない。FmrbAudio に ivar を足さないため)。
- kernel (`main/prebuild_scripts/kernel/fmrb_kernel/audio_handler.rb`): `"main_volume"` を `FMRB_AUDIO_CMD_SET_MAIN_VOLUME` (0x10) + percent 1 バイトにして音声側へ送る。100 以外を送ったアプリの pid を 1 つだけ覚え (最後に下げたアプリ)、そのアプリが終わると `restore_main_volume_for` が 100 を送る (`app_lifecycle.rb` の後始末、`stop_music_for` などと同じ並び)。正常終了・例外・kill のどれでも戻るので、アプリ側で戻すより安全な方として kernel 側を選んだ。アプリ自身が 100 を送ったら覚えた pid は消す (戻す物が無い)。
- 保存はしない。音声側の再起動でも 100 に戻る。古い音声側 (この命令を知らない) は未知の命令として 1 行ログを出し、MAIN は 100% のまま。

## 3. C の変更の場所

- `apuif_process_mix(buf, len, main_gain_q16)`: 引数を 1 つ足し、MAIN の 1 フレーム分のサンプルに Q16 の倍率 (`(s * g) >> 16`、`s_out_gain_q16` と同じ流儀) を掛けてから SUB と足す。倍率は 1 以下なのでサンプルは範囲を出ず、新しい飽和は起きない (足し算の後の切り詰めは今までどおり)。65536 以上なら何もしない (今と同じ経路)。
  - fmruby-core: `components/apu_emu/src/apu_if_p4.c` (Modern とブラウザ版が使う)、`components/apu_emu/include/apu_if.h`。
  - fmruby-graphics-audio: `components/apu_emu/src/apu_if.cpp` (WROVER)、`apu_if_linux.c` (sim)、`include/apu_if.h`。
- 値を持つ所:
  - Modern・ブラウザ版: `main/drivers/audio_p4/audio_p4_task.c` の `s_main_cut_q16` (`FMRB_EXT_RAM_BSS_ATTR` で PSRAM)。PSRAM の BSS は 0 で始まるので、「1 からの減り」(cut) で持って 0 = 100% にした。命令は `audio_p4_handler.c` の `FMRB_AUDIO_CMD_SET_MAIN_VOLUME` → `audio_p4_main_volume_set`。
  - Retro・sim: `main/tasks/audio_task.c` の `g_main_gain_q16` (初期値 65536)、`audio_task_set_main_volume`。命令は `main/audio/audio_handler_esp32.c` と `audio_handler_shm.c`。
- 命令の形: `components/fmrb_audio/audio_commands.h` と graphics-audio の `main/common/audio_commands.h` に `FMRB_AUDIO_CMD_SET_MAIN_VOLUME = 0x10` と `fmrb_audio_main_volume_cmd_t` (cmd_type + percent) を足した。2 つのファイルは冒頭の注記を除いて同じのまま。
- host_task の転送は命令の種類を見ずに送るので、変更は無い。

### 3.1 内蔵 RAM

- fmruby-core: 増分 0。新しい静的変数は `s_main_cut_q16` 1 つで PSRAM。kernel の pid の Hash は VM のヒープ (PSRAM)。`apuif_process_mix` の引数はスタックの 4 バイト (音声のタスクのスタックの中、既存の容量)。
- fmruby-graphics-audio (WROVER): `g_main_gain_q16` の 4 バイトが .data に増える。隣の `g_out_gain_q16` と同じ置き方で、WROVER は fmruby-core の内蔵 RAM の決まりの対象外 (別のチップ) と判断した。気になるなら PSRAM へ移せる (`EXT_RAM_BSS_ATTR` と CONFIG_SPIRAM_ALLOW_BSS_EXT_MEM の確認が要る)。

## 4. 段階の値 (仮)

`mahjong_sound.rb` の定数 `BGM_LEVELS = [0, 30, 55, 100]` (切・小・中・大)、`BGM_DEFAULT = 1` (小)。数は聞いて決める前提の仮の値。

- ボタン「BGM 小[B]」(切/小/中/大)。押すたび・B キーで 切→小→中→大→切。切は BGM を止めるだけで MAIN の音量は送らない (MAIN で鳴る物が無い)。切から小へ戻すと音量を送ってから曲を始める。
- `/home/mahjong.toml` には `bgm = 0..3` で書く (注記の行も直した)。読むときは `true` → 小 (1)、`false` → 切 (0)、`0..3` の数字はそのまま、それ以外は既定 (小)。前の `bgm = 1` (入) も小として読める。
- アプリの開始時 (`snd_start`) に段階の音量を送る。閉じたときの戻しは kernel に任せた (2 章)。

## 5. 受け入れ条件の結果

### 5.1 `rake test`・`rake mahjong:overflow`

- `rake test`: 通った (picoruby-ti・BASIC ゴールデン 103 件・MicroPython smoke。はみ出し検査も中で回る)。
- `rake mahjong:overflow`: 234 の描画で失敗 0 (警告 51 は 426x240 のもので、従来どおり警告だけ)。場面を 3 つ足した: 待ち合わせ (卓の主) の `bgm_mid`・`bgm_high`、卓の一覧の `list_bgm_high`。既存の `sound_off` / `list_sound_off` は `@snd_bgm = 0` に直した。「切/小/中/大」は同じ幅なのでボタンの幅は変わらない。
- 検査器はアプリの `snd_start` を通らないので `@snd_bgm` が nil のことがある。ラベルは nil を既定 (小) として描く。

### 5.2 Linux sim (標準構成、TAB5)

音は `ruby tools/fmrb_audio_probe.rb` で測った (graphics-audio が SHM のリングに書いた最終出力。sim の端末全体の音量は 7 のまま、どの測定も同じ条件)。

**測定用の小さなアプリ** (一時的に flash/app/test に置いて測り、消した。コミットしていない): spring_thing.nsf を MAIN で鳴らし、キーで `main_volume` を 100/55/30/0、SUB で 440 Hz の note_on (音量 10) を鳴らす。8 秒ずつ。曲の場所で値がぶれるので 2 回。

| MAIN の音量 | 1 回目 ピーク / RMS | 2 回目 ピーク / RMS |
|---|---|---|
| 100% | 2459 / 649.7 | 2185 / 349.3 |
| 55% | 1353 / 355.6 | 1376 / 270.1 |
| 30% | 793 / 199.3 | 825 / 199.7 |
| 0% | 456 / 8.6 | 547 / 10.0 |

ピークは 100% に対しておおむね 0.55〜0.63 倍・0.32〜0.38 倍で、段階どおりに下がる。0% の残り (RMS 10 前後) は 5.4 の既存の漏れ。

**効果音 (SUB) の大きさ**: 曲を止め、MAIN の音量だけを変えて同じ note_on を 3 秒ずつ測った。

| MAIN の音量 | ピーク / RMS |
|---|---|
| 100% | 456 / 425.0 |
| 55% | 434 / 424.3 |
| 30% | 442 / 424.3 |
| 0% | 456 / 424.7 |

効果音の RMS は変わらない (差 0.2% 以内)。曲と効果音を重ねると、MAIN 100%: 曲だけ 465.7 → 重ねて 647.9、30%: 140.7 → 460.5、0%: 10.5 → 424.9 (効果音だけと同じ)。

**麻雀アプリ** (待ち合わせの BGM after_the_rain.nsf、B キーで巡回、8 秒ずつ):

| 段階 | ピーク / RMS |
|---|---|
| 小 (起動時の既定) | 620 / 139.4 |
| 中 | 1052 / 282.5 |
| 大 | 2185 / 499.2 |
| 切 | 45 / 44.9 (曲は止まり、1 LSB の直流だけ) |
| 小 | 560 / 141.5 |
| 中 | 1152 / 249.2 |
| 大 | 2049 / 467.3 |

graphics-audio のログに `main volume: 30%` → 55% → 100% → (切は送らない) → 30% → 55% → 100% と出た。画面のボタンは「BGM 小[B]」で始まり、切のときは「BGM 切[B]」。保存は `bgm = 3` など。

**前の保存**: `bgm = true` の toml で起動すると小 (30%) で始まり、`bgm = false` で起動すると「BGM 切[B]」で曲は鳴らず、音量の命令も送らない (確認後、sim の /home/mahjong.toml は元に戻した)。

**閉じたときに戻る**:

- 測定用アプリを MAIN 0% のまま kill → kernel `Main volume back to 100 after pid=5`、graphics-audio `main volume: 100%`。
- 麻雀を中 (55%) にして Ctrl+Q → 同じく 100 に戻った。大 (100%) で閉じたときは戻す物が無いので何も送らない。
- その後に別のアプリ (測定用アプリ、音量に触らない) で NSF を鳴らすと ピーク 2367 / RMS 462.4、2732 / 460.9 で、100% の範囲 (上の表) と同じ。

**エディタ**: デスクトップからエディタを起動して `a` を 1 打鍵、画面に出た (Ln 1, Col 2)。

sim は sim_down で片付けた。

### 5.3 ブラウザ版 (`rake wasm:web`)

ビルドが通った (lib/add が新しいので wasm:mrb が libmruby を作り直した)。web_up でページが上がり、デスクトップから麻雀を開いて B を押し、Ctrl+Q で閉じてデスクトップに戻った (ルータが無いので待ち合わせの画面までは進まず「網から切れた」の表示。落ちてはいない)。ブラウザ版の音の数値は測る道具が無いので、同じ C の sim の結果で代える (Modern・ブラウザ版の C は `apu_if_p4.c` / `audio_p4_task.c` で、sim は graphics-audio 側の同じ形の実装。式は同じ)。web_down で片付けた。

### 5.4 気づいた既存の漏れ (直していない)

MAIN を 0% にしても、曲が鳴っていると RMS 10 前後の小さな音が残る (100% の 1.5% 程度、-36 dB くらい)。曲を止めると 0。WAV に落として見ると、8 ビットの 1〜6 段の小さな値がフレームごとに 1〜2 サンプルだけ出ている。原因は nofrendo の `nes_apu.c` の `apu_process` にある低域フィルタの `static int32 prev_sample` が 2 つの APU で共有されていること: MAIN の最後のサンプルが、続けて処理する SUB の最初のサンプルに混ざる。両リポジトリの `nes_apu.c` に同じ物がある。今回の MAIN の音量より前からある漏れで、範囲 (1・2 章) の外なので触っていない。直すなら次の形がある。

1. (推奨) `prev_sample` を `apu_t` (文脈) の中へ移す。両リポジトリの `nes_apu.c` / `nes_apu.h` の小さな変更で、文脈の入れ替えで一緒に入れ替わる。
2. そのままにする。0% は麻雀では使わない (切は曲を止める) ので、実害は小さい。

## 6. Retro の扱いとビルド

- Retro (fmruby-graphics-audio) にも同じ口を入れた (命令が届いて MAIN の音量が変わる)。Linux sim の音声も同じ audio_task.c なので、5.2 の数値はこの実装のもの。
- fmruby-graphics-audio の `rake build:esp32` (WROVER、`rake clean_all` の後): 通った (Xtensa の ELF)。
- fmruby-core の `rake build:esp32` (TAB5、`rake clean_all` の後): 通った (RISC-V の ELF)。`s_main_cut_q16` は `0x4800c928` (`.ext_ram.bss`、隣は `s_out_gain_q16`) で、内蔵 RAM ではないことを nm で確認した。

## 7. 親が焼くときの注意

- fmruby-core の build/ は TAB5 の esp32 のビルドのまま残した (`file build/fmruby-core.elf` で確認、UCB RISC-V)。sig と lib/add を直したので、型 db も新しい (clean_all から作った)。
- 焼くのは firmware だけでよい (storage の麻雀アプリも変わったので、app_only なら `tab5_fs` で `/app/game/mahjong/mahjong_sound.rb` を put する)。
- 実機で見るとよいこと: 麻雀の待ち合わせで B を押すと BGM だけが段階どおりに小さくなり、効果音 (打牌など) は変わらないこと、閉じた後に NSF Player が今までの大きさで鳴ること。段階の値 (30/55/100) が耳で合うかはユーザが決める。
- Retro の WROVER にも新しい firmware を入れないと、Retro では MAIN の音量は 100% のまま (未知の命令として 1 行ログ、落ちない)。
- fmruby-graphics-audio の build/ は、Retro のビルドを確認した後に `rake clean_all` + `rake build:linux` で作業前と同じ Linux のビルドに戻した (WROVER へ焼くなら build:esp32 をやり直す)。fmruby-core が esp32 なので、sim を使うときは fmruby-core の `rake clean_all` + `rake build:linux` が要る。
