## 2. 入れたもの・入れなかったもの

### 2.1 入れたもの

| 機能 | Ruby での形 | 備考 |
|---|---|---|
| セッションの設定 | `Session.open(loc, config: {"key/path" => 値})`、`config: "<JSON5 の文字列>"`、`config_file:` | Hash の値は Ruby の値を JSON にして入れる。優先順 (低い方から): zenoh の既定、gem の内部の設定 (スカウティング無し、接続と送信の時間制限、接続だけの peer は待ち受けない)、ファイルか文字列、引数 (locator・mode・listen・scouting・timestamping)、Hash。ファイルが既定と違う値にしたキーは、gem の内部の設定で上書きしない (既定の設定と読み比べて判断する) |

| 時刻の付与 | `Session.open(timestamping: true)` | 指示書には無いが、2.3 の理由で足した |

| delete | `session.delete(key, ...)` | 受け手には kind `:delete` の Sample が届く (`each_pending` では空の payload) |

| get の設定 | `get(..., encoding:, priority:, congestion_control:, express:, accept_replies:)` | |

| 時刻 (HLC) | `session.new_timestamp` → `Timestamp` (`ntp64`・`id`・`to_time`・比較できる) | |

### 2.2 入れなかったもの

| 機能 | 理由 |
|---|---|
| 共有メモリ | 同じ機械の中だけで、Ruby の String に写すので得が無い |
| 裏で動く宣言 (background) | オブジェクトの `close`・セッションの close・解放で閉じる今の形で足りる |
| 符号化の道具 (ze_serialize) | MessagePack と CDR がある。payload は String のまま |
| publication cache / querying subscriber | 高度な pub/sub の古い形。高度な pub/sub で足りる (ROS 2 Jazzy の rmw_zenoh 0.2.11 とも、高度な publisher でつながった) |
| get の取り消し、put の source info | 使う場面が少ない。get は時間制限で終わる |

指示書 1.2 の判断を変える事情は見つからなかった。

### 2.3 timestamping を足した理由

cache だけの高度な publisher (`cache: 2`) は宣言で失敗した (`-128`)。zenoh-c の文は「Sequencing::Timestamp のときは timestamping を有効にせよ」。cache と一緒に `sample_miss_detection: true` を付ければ番号で並べるので timestamping は要らない。両方を使えるように、`Session.open(timestamping: true)` を足し、`config: {"timestamping/enabled" => true}` と同じ意味にした。timestamping を有効にしたセッションの put には、送り手の zid の時刻が付く (試験で確かめた)。

### 2.4 Sample と Reply を asterism-zenoh に移した

asterism の CRuby の層は `Sample` / `Reply` を `Data.define(:key, :payload, :attachment)` で持っていた。同じ名前空間 (`Asterism::Zenoh`) なので、付加情報の付いた値を asterism-zenoh で作るには 1 つにまとめる必要があった。asterism-zenoh の `values.rb` で定義し、足した項目には既定値を与えたので、`Sample.new(key, payload, attachment)` は今どおり動く。asterism の層はその定義を消して使う形にした。

## 3. 作り

### 3.1 受け取りの形

- 今の FIFO (subscriber・queryable・get) はそのまま。新しく通知を受けるもの (受け手の有無、接続・リンク、取りこぼし、スカウティングの答え) は、小さな C の待ち行列 (`zevq`) にした。zenoh-c のコールバックは値を malloc した C の構造体に写して積むだけで、Ruby にも GVL にも触らない。いっぱいなら古いものを捨てて `dropped` に数える (今の FIFO と同じ決まり)。Ruby は `each_pending` で取り出す。
- `transports` / `links` / `peer_zids` のその場の一覧も同じ待ち行列に集めてから Ruby の値にする。
- 待つ呼び出し (publisher の put / delete、querier の get、scout) は GVL を手放す。publisher と querier は、閉じるときに session の op_lock を取る。これで、別のスレッドが GVL 無しで put している最中に close しても、put が終わってから閉じる。
- 新しいオブジェクトは session の 1 本のリストで持ち、session が閉じるときに順に閉じる (リスナー → publisher・querier → 今の queryable・token・subscriber → 宣言したキー)。

### 3.2 0.2.0 との互換

- 呼び方は変えていない。足したのはキーワード引数とメソッドとクラスだけ。
- 中で変えたのは 2 点。(1) get のエラーの答えは、前は数えて捨てていたが、今は待ち行列に入れる。`each_reply` はそれを取り出して捨てる (返さない) ので、見える動きは前と同じ (`errors` も同じ)。(2) put・get のキーに `KeyExpr` も受けるようにした。
- 今の試験 (asterism-zenoh の test_zenoh・test_threads、asterism の test:msgs・test:objects・test:api) は書き換えずに通る。

### 3.3 CRuby の層 (asterism `lib/asterism/cruby/zenoh.rb`)

| 足したもの | 中身 |
|---|---|
| `put(key, payload, **opts)`、`delete` | asterism-zenoh の設定をそのまま渡す |
| `publisher` / `advanced_publisher` → `Connection::Publisher` | `put` (String でなければ to_s)、`delete`、`matching?`、`on_matching { \|listening\| }` |
| `querier` → `Connection::Querier` | `get(params:, payload:, attachment:, encoding:, errors: false) { \|reply\| }` (ブロック無しは Enumerator)、`on_matching` |
| `advanced_subscriber(...) { \|sample\| }` → `AdvancedSubscription` | `Subscription` と同じ使い方に `on_publisher { \|key, alive\| }`、`on_miss { \|miss\| }` |
| `on_transport { \|ev\| }`、`on_link { \|ev\| }` → `Events` | `close` で止める |
| `get(..., errors: false, **opts)` | `errors: true` でエラーの答えも返す。既定は今どおり返さない |
| 購読のブロックと Enumerator | `each_sample` から作った Sample を渡す (kind や encoding が見える) |
| `QueryReply` | `reply_del` もキー無しなら queryable 自身のキーで答える |
| 情報 | `peer_zids`・`router_zids`・`transports`・`links`・`new_timestamp`・`declare_keyexpr` |

ブロックはすべて受け取りのスレッド (Runner の tick) から呼ぶ。リスナーごとに Runner の task を 1 つ足し、その task が `each_pending` で取り出して配る。

## 4. API の一覧 (短い例)

```ruby
Z = Asterism::Zenoh
# 設定 (TLS)、スカウティング、時刻
s = Z::Session.open("tls/localhost:7447",
                    config: { "transport/link/tls/root_ca_certificate" => "ca.pem" })
p2p = Z::Session.open(mode: :peer, scouting: true)          # locator 無し
Z.scout(what: :peer, timeout: 1.0)                           # => [#<Hello zid=.. whatami=:peer locators=[..]>]
ts = s.new_timestamp                                         # ts.to_time, ts.id

# put の設定と delete
s.put("demo/x", '{"a":1}', encoding: "application/json", priority: :data_high, timestamp: true)
s.delete("demo/x")

# 付加情報つきで受け取る
sub = s.subscribe("demo/**")
sub.each_sample { |sm| p [sm.kind, sm.encoding, sm.timestamp, sm.priority] }

# 宣言した publisher と受け手の有無
pub = s.publisher("demo/temp", encoding: "text/plain")
ml = pub.matching_listener
pub.matching?                                                # => false / true
ml.each_pending { |listening| }                              # 変わるたびに 1 つ

# querier と答えの種類
q = s.querier("demo/**", timeout_ms: 1500)
qa = s.queryable("demo/**")
qa.each_pending do |query|
  query.reply("demo/a", "[1]", encoding: "application/json")
  query.reply_del("demo/b")
  query.reply_err("no such thing")
end
q.get.each_result { |r| r.error? ? warn(r.payload) : p(r.payload) }

# キーの演算と宣言したキー
Z::KeyExpr.new("demo/*").includes?("demo/x")                 # => true
Z::KeyExpr.new("a/b").join("c").to_s                         # => "a/b/c"
k = s.declare_keyexpr("demo/declared"); s.put(k, "v")

# 高度な pub/sub (後から来た購読者が最後の値を受け取る)
adv = s.advanced_publisher("demo/mode", cache: 1, sample_miss_detection: true, publisher_detection: true)
adv.put("eco")
late = s.advanced_subscriber("demo/mode", history: true, recovery: true)
late.detect_publishers.each_pending { |key, alive| }
late.miss_listener.each_pending { |miss| }

# 接続・リンクの通知、ログ
ev = s.transport_events(history: true)
ev.each_pending { |e| p [e.kind, e.zid, e.whatami] }
Z.init_log("info")

# CRuby の層 (asterism)
Z.open("tcp/192.0.2.2:7447") do |c|
  c.publisher("demo/t").on_matching { |l| puts l }
  c.advanced_subscriber("demo/mode", history: true) { |sm| puts sm.payload }.on_publisher { |k, a| }
  c.on_transport { |e| puts "#{e.zid} #{e.kind}" }
  c.get("demo/**", errors: true).each { |r| p r }
  c.run
end
```

## 5. 試験と確かめ

構成: rbenv の Ruby 3.2.6、作業ツリーから。ルータは親の zenohd を LAN 用の重ね合わせで上げ、ROS 2 は `docker-compose.ros2.yml` (Jazzy、rmw_zenoh_cpp 0.2.11)。終わりに 3 つの compose を重ねて `down` した。

| test_features を 3 回、`rake test` を 3 回 | 全部 0 失敗 |
| ルータ経由 (`ASTERISM_TEST_ROUTER=tcp/127.0.0.1:7447`) | test_features 15 (153)、飛ばし 1 (接続の通知は peer のときだけ)。test_zenoh・test_threads も通る |
| asterism `test:msgs` | 2,396 項目 0 失敗、layout 4 (262) 0 失敗 |
| asterism `test:objects` | 6 (74) 0 失敗 |
| asterism `test:api` | test_api_objects 3 (45)、test_api_ros 6 (28)、test_api_zenoh 10 (45)、test_api_zenoh_features 6 (28)、0 失敗。5 回続けて 0 失敗。ルータ経由も通る |
| gem を作って入れる | `rake gem` で 2 つ作り、rbenv の Ruby に `gem install --local` して `require "asterism"`・KeyExpr・Timestamp が動く。その後 `gem uninstall` で 2 つとも消した |

test_features が見ていること:

- 付加情報: encoding・priority・congestion_control・express・reliability・timestamp (送った Timestamp と等しい)・attachment、delete の kind と時刻。`each_pending` と `each_sample` が同じ待ち行列から取る。パターンマッチ。
- put の引数の誤り (priority・congestion_control・reliability・allowed_destination・timestamp・delete の attachment)。
- 時刻: 続けて作ると大きくなる、id がセッションの zid、to_time が今に近い。
- publisher: 受け手がいない間は `matching?` が false、購読すると true になり `matching_listener` に true、購読を閉じると false。publisher の encoding と priority が受け手に届く、put ごとの encoding が勝つ、delete。閉じた後の put は Error。
- querier: `matching?`、params・payload・encoding が queryable に届く、答え・reply_del・reply_err の 3 種が `each_result` で区別できる、`replier_zid`、`each_reply` はエラーを返さず `errors` は 1。閉じた後は Error。
- キーの演算: intersects / includes / relation_to の 4 段階、join、concat、canonize、valid?、正しくないキーは ArgumentError、autocanonize。KeyExpr で購読、宣言したキーで put と publisher、undeclare の後もキーとして使える。
- 高度な pub/sub: cache 3 の publisher に 5 回 put した後に来た購読者が最後の 3 つを受け取り、その後の put も届く。`detect_publishers` が publisher の現れと去りを知らせる。miss_listener は作って閉じられる。閉じた購読者に miss_listener を頼むと Error。
- 接続・リンクの通知: 相手が来ると `:added`、去ると `:removed`、history: true なら今いる相手が先に来る。`peer_zids`・`transports`・`links` が相手の zid を返す。
- 設定: Hash で待ち受けの住所を渡す、Hash の `connect/timeout_ms` 300 で接続の失敗が 2 秒未満 (内部の 3 秒より Hash が勝つ)、知らないキーは ArgumentError。JSON5 の文字列とファイル。timestamping (cache だけの publisher は timestamping 無しで失敗し、文に timestamping が出る。有りなら put に送り手の時刻が付く)。
- TLS: 試験の中で自己署名の CA と localhost の証明書を作り、`tls/localhost:<port>` で待ち受ける peer と CA を渡した peer の間で put が届く。リンクの dst が `tls/`。CA 無しでは開けない。
- スカウティング: 待ち受ける peer を `scout(what: :peer)` が見つけ、locator に待ち受けの住所が入る。`scouting: true` で locator 無しに開いた peer が相手を見つける。手元 (WSL2) ではマルチキャストが通り、飛ばさずに通った。答えが無い環境では理由を出して飛ばす。
- ログ: 別プロセスで `init_log("debug")` すると標準出力に DEBUG と `zenoh::net::runtime` が出る。`init_log(nil)` で RUST_LOG が無ければ何も出ない。`RUST_LOG=error` なら DEBUG は出ない。
- test_threads: 複数スレッドで使いながら閉じる試しに、publisher の put (timestamp: true)、querier の get、delete を足した。30 回、0 失敗。

### 5.2 機体との往復 (P4-Nano)

機体は P4-Nano (192.0.2.15、ID `fmruby-aaaaaa`、焼き直していない、ミュートのまま)。tab5_app で `/app/test/asterism_demo.app.rb` を起動し、asterism 0.3.0 の `examples/node.rb` を回した。機体のファームとアプリは put / get の古い形のまま。

```

joined: fmruby-aaaaaa
fmruby-aaaaaa info.status -> {"name"=>"fmruby-aaaaaa", "board"=>"naryav4", ...} (223.0 ms)
fmruby-aaaaaa screen.say -> 24 (111.6 ms)
```

新しい呼び出しも機体に向けて確かめた:

- 宣言した querier (`<node>/demo/info/call`) は機体の queryable と `matching?` が true になり、`get(nil, 呼び出し, encoding: "application/msgpack")` に機体の zenoh-pico が `["ok", ...]` で答えた。`boom` (例外を出すメソッド) は `["error", "RuntimeError", ...]`。
- liveliness の監視で機体のトークン 4 つ (`asterism/fmruby-aaaaaa` と demo の 3 つ) が見えた。ルータの `router_zids` は 1 つ、`transports` は `:router`。

### 5.3 ROS 2 の transient local

rmw_zenoh の購読者を、値を出した後から起こして受け取れるかを見た。試しのスクリプト (コミットしていない) は次のとおり。

1. `Asterism::ROS` の node で `/c7_latched` (std_msgs/msg/String) の publisher を QoS `":1:,10:,:,:,,"` (durability = transient local) で作る。これで liveliness のトークンが transient local を名乗る。
2. 同じトピックのキーに `advanced_publisher(cache: 10, publisher_detection: true, sample_miss_detection: true)` を作り、rmw_zenoh の attachment (番号・時刻・gid) を付けて 3 回 put する。
3. その後で ROS 2 のコンテナで `ros2 topic echo --qos-durability transient_local --qos-reliability reliable /c7_latched` を起こす。

| 確かめ | 結果 |
|---|---|
| `ros2 topic info -v` | `Node name: c7_latch`、PUBLISHER、`Durability: TRANSIENT_LOCAL` |
| 後から起こした echo (高度な publisher) | `data: latched 0`、`latched 1`、`latched 2` の 3 つが届いた |
| 比べ: 同じ QoS のトークンで普通の put | 何も届かない (0 行) |

つまり、高度な publisher の cache が rmw_zenoh 0.2.11 の transient local の購読者に履歴として届く。`Asterism::ROS` の publisher (`mrblib/ros.rb`) はまだ普通の put なので、transient local を使うには、CRuby の層か共有の層で、QoS が transient local のときに高度な publisher で送る形を足す必要がある (C7 の範囲の外。`mrblib/` は触らない決まり)。

## 6. 機体側 (zenoh-pico) へ持っていける候補

| 候補 | 見立て |
|---|---|
| delete、put の encoding・priority・congestion control・express | zenoh-pico に同じ設定がある。payload を String のまま渡せるので、小さく足せる |
| 宣言した publisher | zenoh-pico に `z_declare_publisher` がある。キーを毎回送らずに済み、ROS 2 の発行の多い機体で効く |
| 値の付加情報 (kind・encoding) と `reply_err` / `reply_del` | zenoh-pico の sample と query から読める。共有の層の Sample を CRuby と同じ形にできる |
| キーの演算 (`intersects?`・`includes?`) | zenoh-pico にもある。共有の層でキーを照らし合わせる所に使える |
| 宣言した querier | zenoh-pico にある。サービスの呼び出しを繰り返す所に使える |
| 受け手の有無 (matching) | zenoh-pico ではビルドの設定で入る。RAM との兼ね合いを見る |
| 高度な pub/sub (transient local) | zenoh-pico にも advanced pub/sub があるが RAM を測ってから。機体が出す値を後から来た ROS 2 に届けたいときに要る |
| 時刻 | zenoh-pico は HLC を持たない形がある。付いてきた時刻を読むだけなら可能 |
| 接続・リンクの通知、ログ、TLS | 機体では見送り (zenoh-pico に無いか、ESP32 で TLS を使わない) |

## 7. 止まった所・気づいたこと

- 止まる条件には当たらなかった (コールバックの中で Ruby を呼ぶ必要は無く、今の API も変えずに済んだ)。
- zenoh-c の log は標準出力に書く (stderr ではない)。zenoh-c の振る舞いに合わせ、README と注釈に書いた。
- cache だけの高度な publisher には timestamping が要る (2.3)。
- `peers` は数のまま残したので、zid の配列は `peer_zids` / `router_zids` という名前にした (指示書の書き方と違う)。
- ルータ経由でも高度な pub/sub の履歴は届いた。
