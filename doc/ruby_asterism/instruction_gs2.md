# GS2 指示書: オセロの卓 (ホスト版) とその画面、CRuby のアスキーアートのクライアント

> 状態: 指示 | 更新: 2026-10-17 | games_showcase.md の GS2。最初に互換の部分を落とし、部屋の卓をアプリから選ぶ形にしてから、オセロの卓を枠組みの上に書く。画面は fmruby-core の新しいアプリ、Family mruby なしの例として CRuby の端末のクライアントを置く

前提: games_showcase.md (目的・方針・Step)、report/gs1.md (枠組みの形、6 章「GS2 に向けて分かったこと」と落とせる互換の表)、asterism-games の README とコード (lib/asterism_games/ の game.rb・remote.rb・rooms.rb・host.rb・store.rb、mahjong/、bin/、config/、deploy/vps/)、今の端末どうしのオセロ (fmruby-core flash/app/test/othello.app.rb)、卓の麻雀のアプリ (flash/app/game/mahjong/)、asterism の README (CRuby API の Net、`caller: :from`)。

言葉: 文書は常体、「端末」「確認」「Step」。技術の用語は例えにしない。asterism-games の文書とコードのコメント、fmruby-core のコードのコメントは英語。

## 1. 決まっていること (2026-10-16〜17 ユーザ)

- **互換の部分は GS2 の最初に 3 つまとめて落とす** (開発中なので古い卓のアプリとの互換は要らない。今の develop の卓のアプリとブラウザ版が動けばよい):
  1. `view` の引数 1 つの形 (assist なしを 1 とみなす分岐)。卓の麻雀のアプリ (mahjong.app.rb、gs1.md の時点で 546 行あたり) を常に 2 引数で呼ぶ形にそろえる。
  2. `join` / `mine` の秘密と `rooms.secret_ids` (席より前のブラウザ版のページの道)。ホスト側の分岐・設定・試験を消す。
  3. ルール項目の `ru` / `rx` / `ry` の分け方と `RULE_TURNS` (項目の少ない古いアプリ向け)。**今の卓のアプリ (端末・ブラウザ版) が読む鍵を先に確かめ、読んでいるものは残す**。
- **部屋の卓は、部屋が開くアプリからゲームを引いて、そのゲームの卓を出す**。部屋の設定は今の「開くアプリ」(`rooms.apps`) 1 つのまま。麻雀とオセロの両方を開く設定なら、部屋のリンクが開くアプリのゲームの卓だけをその部屋に出す (麻雀を開く部屋に麻雀の卓、オセロを開く部屋にオセロの卓)。対応は `Game.screens`。卓の一覧を書かないときの既定は、ゲームごとに最初の卓 1 つ。
- **卓の数は GS2 では網に載せない** (GS4 で読む側と一緒に `@status` を決める)。プロフィールは今のまま。
- **今の端末どうしのオセロは残し、名前で区別する**: 今のもの (flash/app/test/othello) の画面の名前を「Othello (direct)」/「オセロ (直接)」に、新しい卓のアプリを「Othello」/「オセロ (卓)」(英語の名前は任せる。2 つが区別できること) にする。今のものの動きは変えない。
- 席の管理 (座る・立つ・卓の主・CPU) を枠組みの基底 (例: `Seats`) に上げるかは、オセロが 2 つ目の使い手になった時点で判断してよい。上げるなら麻雀の見た目・動き・鍵は変えない。
- 手番の情報に隠すものが無いので、オセロは盤面を状態の put でも呼び出しの答えでも渡してよい。席だけの情報は無い。
- 部屋の守り (席の証明書、ゲームホスト自身の証明書 `games`)、常設の卓、家の LAN の卓は今どおり。

## 2. 作るもの

1. **互換を落とす** (1 章の 3 つ)。麻雀の試験・ボット・卓のアプリが今どおり動くこと。
2. **部屋の卓の選び方** (1 章)。rooms.rb の部屋ごとのホストに、その部屋のアプリのゲームの卓だけを渡す。`GET /status` と console の Rooms の画面が読む形 (`summary` の鍵) は変えない。
3. **オセロの卓** (asterism-games、`lib/asterism_games/othello.rb` と `othello/` など。名前は任せる): 枠組みの `Game` と `Remote` を継ぐ。gs1.md 6 章の「新しいゲームが書くもの」の形で、数百行を目安にする。
   - 2 席 + 観戦 (観戦の上限は麻雀と同じ考え方で設定できる)。卓の主が始める。空いた席に CPU を置ける。
   - ルール: 標準のオセロ (8x8、合法手、挟んだ石を返す、置けなければパス、両者置けなければ終局、石の数で勝敗)。手番の持ち時間は設定 `turn_seconds` (既定 0 = なし)。0 より大きくて切れたときは、その手を CPU が代わりに打つ。
   - CPU は小さくてよい (例: 位置の重みの表 + 返せる数)。強さの段階は要らない。
   - 保存と再開、途切れ (away)、見張りの `summary` は枠組みのまま使う。
   - 設定の例: config/example.yml の常設の卓・家の LAN の卓と、config/rooms.yml の部屋・常設に `othello1` (game: othello) を足す。
4. **オセロの卓のアプリ** (fmruby-core、例: `flash/app/game/othello/othello.app.rb` と `.app.toml`。置き場所と名前は任せる): 卓の一覧からオセロの卓を選んで、座る・観戦・CPU を置く・始める・打つ・投了・立つ。今の端末どうしのオセロの盤の描き方は写してよい (共通の部品に分けるなら、今のオセロの動きを変えないこと)。窓のアプリでよい。ブラウザ版 (1280x720・640x360) と sim (426x240) で崩れないこと。網のつなぎ方 (FmrbAsterism.settings、部屋の席の証明書) は卓の麻雀のアプリと同じ。メモリは小さいプールで足りるならそのまま、足りなければ `large_memory` (数字を report に)。
5. **CRuby の端末のクライアント** (asterism-games、例: `bin/othello-tty`。名前は任せる): アスキーアートで盤面を出して観戦する。席に座って座標 (例: `d3`) を打ち込んで打てる。CRuby と asterism gem だけで動く (Family mruby に依存しない)。平文のルータ (家の LAN) と、console の `.tar` (常設の卓) の両方で入れる。
6. **文書**: asterism-games の README に、オセロの卓と CRuby のクライアントの使い方、部屋の卓の選び方を書く。麻雀を例にした「新しいゲームの書き方」は、オセロを例にしたほうが短ければ差し替えてよい。

## 3. 受け入れ条件

1. asterism-games の `MJ_GAMES=8 bundle exec rake test` (今 145 件) が全部通る。足した試験も通る: オセロのルール (合法手・返す石・パス・終局・勝敗)、CPU が合法手だけを打つこと、持ち時間切れで CPU が代わりに打つこと、保存と再開、部屋の卓の選び方 (麻雀を開く部屋に麻雀の卓だけ、オセロを開く部屋にオセロの卓だけ、既定の卓)。落とした互換の分は試験も消す。
2. 互換を落とした後も、今の卓の麻雀のアプリ (この Step で 2 引数にそろえたもの) が家の LAN の卓で座って打てる (ブラウザ版の web_* で)。ボット (`bin/mahjong-bots`) が東風戦を最後まで打つ。
3. **同じオセロの卓で 3 種類の客が遊べる** (家の LAN の卓、平文の zenohd): ブラウザ版 (web_*) と sim の端末 (sim_*) が席に座って 1 局を終局まで打ち、CRuby のクライアントが観戦する。続けて CRuby のクライアントが座り、ブラウザ版か CPU と 1 局を終局まで打つ。画面を写して report に残す (3 つの大きさ: 1280x720・640x360・426x240)。
4. 部屋 (console の deploy/local、席の証明書): オセロを開く部屋のリンクで入ったブラウザ版 2 つが、オセロの卓で 1 局を終局まで打てる。麻雀を開く部屋にはオセロの卓が出ず、麻雀の卓で座れる。
5. 常設の卓: console の行と役割 games の `.tar` で、CRuby のクライアントが `othello1` に座り、CPU と 1 局を終局まで打つ。
6. 今の端末どうしのオセロが名前だけ変わって、今どおり動く (sim とブラウザ版で 1 局の途中まで打つ。画面の名前が区別できる)。
7. 数字: オセロの 1 通の最大、ゲームホストのメモリ (RSS、麻雀とオセロの卓を両方置いたとき)、卓のアプリの VM の使用量。麻雀の 1 通の最大と RSS が GS1 と同じくらい。
8. VPS 用の一式 (`deploy/vps/`) で image を作り、compose で起こして healthy になり、`status` に麻雀とオセロの卓が出る。

## 4. 範囲・決まり

- **触ってよいもの**: asterism-games (main)。fmruby-core はブランチ `feature/gs2` (develop から) で、オセロの卓のアプリ、今のオセロの画面の名前、mahjong.app.rb の `view` の呼び方、この Step の文書 (report)。asterism と asterism-console は読むだけ (console の変更が要ると分かったら止まって返す)。
- **触らないもの**: riichi_engine の Fork、VPS、実機の端末 (P4-Nano・Tab5・AtomS3R)。sdkconfig。
- コミットのみ。push・タグはしない。`git commit -a` は使わない。コミットの末尾は `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。fmruby-core のコミットの件名は `<領域>: <要約>`、本文は英文。
- 公開の文書・コミットに実在の IP・ドメイン・端末 ID・鍵を書かない。コミットの前に鍵 (`~/.openai_key`) と実在の値の検査をする (どちらも 0)。
- fmruby-core のビルドは本体の checkout で行う (worktree は sim で確かめられない)。ブラウザ版は `rake wasm:web` を作り直してから確かめる (生成物が古いままになる罠: spinel:gen / wasm:mrb)。終わったら build/ は Linux の標準構成 (x86-64) に戻し、`file build/fmruby-core.elf` で確かめる。
- 終わったら起こしたもの (deploy/local の一式、試しの image と volume、zenohd、ゲームホスト、開発サーバ、ブラウザ、sim) を名前で止めて消す。前からある image は残す。docker の prune はしない。sim は音を出す前に sim_audio でミュートし、終わったら戻す。
- **止まる条件**: 麻雀の見た目・動き・鍵を変えないとできない。互換を落とすと今の卓のアプリ (端末・ブラウザ版) が動かなくなる。部屋の卓の選び方に console の変更が要る。asterism の API が足りない。網の決まり (protocol.md) や ACL の規則の変更が要る。1 章に無い仕様の選択 (利用者から見た動きや既定値を決めるもの) が要る。止まったら report に状況を書いて返す。
- **report** (`doc/ruby_asterism/report/gs2.md`、常体): 落とした互換 (確かめた鍵、消したコードと試験)、部屋の卓の選び方の形、オセロの卓の形 (ゲームが書いたものの行数、枠組みに上げたもの)、卓のアプリと CRuby のクライアント、受け入れ条件ごとの結果と数字、写した画面、見立てと違った点・撤回した仮説、GS3 (on_join / on_leave、探し直し、case/in) に向けて分かったこと、残ったこと。
