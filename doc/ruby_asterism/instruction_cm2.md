# CM2 指示書: console に「部屋を作れる期限つきの招待リンク」

> 状態: 指示 | 更新: 2026-10-18 | 部屋を作れるのが管理者だけだと、管理者がいないとブラウザ版で遊べない。管理者が期限つきの招待リンクを作り、そのリンクを開いた人は「部屋を作るだけのページ」で部屋を作れるようにする

前提: asterism-console の部屋 (Admin > Rooms、Room・RoomPage・枠と席、部屋のリンク、`ASTERISM_ROOM_APPS`、部屋の数の上限)、認証 (ログイン・TOTP、管理者)、docs/rooms.md・install.md、CM1 (0.3.5、まだタグを打っていない)、door と nginx の部屋の道 (`/room` の接続元の制限があることに注意: VPS では `/room` は今は自宅からだけに絞っている)。

言葉: 文書は常体、「確かめ」ではなく「確認」。asterism-console の文書とコードのコメントは英語。

## 1. 決まっていること (2026-10-18 ユーザ、選択形式)

- **期限つきの招待リンク**: 管理者が期限 (例: 7 日) つきのリンクを作る。リンクを開いた人は、ログインせずに「部屋を作るだけのページ」で部屋を作れる (開くアプリを選ぶ、部屋の時間は 3 時間まで)。招待リンクごとに、同時に作れる部屋の数に上限。管理者はいつでもリンクを無効にできる。

## 2. 作るもの

1. **招待リンクの管理** (Admin > Rooms の中か隣): 作る (名前・期限・同時の部屋の上限・選べるアプリ (`ASTERISM_ROOM_APPS` の中から))、一覧 (期限・作られた部屋の数・今開いている部屋)、無効にする。リンクの秘密は推測できない長さで、DB には秘密そのものではなくハッシュを置く (部屋のリンクと同じ扱い)。作ったときに 1 回だけ全文を出す。
2. **部屋を作るだけのページ** (ログイン不要): 招待リンクの秘密で入る。名前 (任意)・開くアプリ・時間 (3 時間まで、既定 3 時間) を選んで部屋を作り、部屋のリンクを出す。そのページから、自分の招待で作った部屋の一覧と、閉じる操作ができる (ほかの招待や管理者の部屋は見えない)。期限切れ・無効・上限に届いたときは理由を出す。管理画面へは入れない。
3. **守り**: 招待のページは秘密の推測を防ぐ回数制限 (door や部屋の道の作りに合わせる)。招待で作った部屋も、部屋の数の全体の上限 (枠の数) を超えない。記録 (誰の招待で、いつ部屋が作られたか) を管理画面に出す。
4. **公開の範囲**: VPS の nginx は `/room` の接続元を絞っている。招待のページの道 (例 `/invite/...`) を nginx でどう出すか (部屋の道と同じ制限にするか、別にするか) は docs に書き、既定は「部屋の道と同じ扱い」とする。nginx の設定の変更が要るなら、docs と install の手順に書く (VPS の変更はユーザがする)。
5. **試験**: 招待の作成・期限・無効・上限・アプリの制限・ハッシュで保存・回数制限・自分の部屋だけ見える・管理画面に入れない。
6. **文書**: docs/rooms.md (招待リンク)、install.md (0.3.4 から 0.3.5 の手順に招待を足す、nginx の追記があれば)、CHANGELOG の **0.3.5 の中に足す** (CM1 と一緒に出す。0.3.5 はまだタグを打っていない)。

## 3. 受け入れ条件

1. console の試験全部と rubocop が通る。
2. deploy/local で: 管理者が招待リンクを作り、ログインしていないブラウザ (Playwright) でリンクを開いて部屋を作り、出た部屋のリンクでブラウザ版が部屋に入れる。上限に届くと断られる、無効にすると開けない、期限切れで開けない、を確認する (期限は試験用に短く)。
3. 招待のページから管理画面・ほかの部屋が見えない。

## 4. 範囲・決まり

- **触ってよいもの**: asterism-console (main)。fmruby-core は文書 (report) だけ: ほかの作業が fmruby-core のブランチを使っているので、report と画面は fmruby-core の作業コピーに**ファイルとして書くだけ**にし、fmruby-core の git 操作 (checkout・commit) はしない。親がコミットする。
- **触らないもの**: asterism・asterism-games・fmruby-core のコード、zenohd の設定の作り方 (ACL)、VPS。
- コミットのみ (asterism-console)。push・タグはしない。`git commit -a` は使わない。コミットの末尾は `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。実在の値の検査をしてからコミットする。
- 終わったら起こしたもの (deploy/local、試しの image と volume) を名前で止めて消す。前からある image は残す。docker の prune はしない。親が同時に Tab5 (シリアル /dev/ttyACM0、WiFi) と、別のエージェントが sim・web を使うので、触らない。
- **止まる条件**: ACL・ルータの設定の変更が要る。1 章に無い仕様の選択 (例: 招待で作った部屋に別の決まりが要る) が要る。止まったら report に、ユーザが選べる形の選択肢 (推奨を先頭に) を書いて返す。
- **report** (`doc/ruby_asterism/report/cm2.md`、常体): 画面、守りの形、nginx の扱い、受け入れ条件の結果と画面、残ったこと。
