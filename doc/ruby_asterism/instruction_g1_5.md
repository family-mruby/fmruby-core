# Asterism G1.5 指示書: 役割で書く ACL、止めずに入れ替える、呼んだ相手をルータで確かめる、ブラウザ版をユーザごとに開く

> 状態: 指示 | 更新: 2026-10-13 | console の台帳を「役割」で書く形にし、「Player」とゲーム固定の設定を役割に置き換える。ACL をルータを起動し直さずに入れ替えられるかを確かめて入れる。呼び出しのキーの呼んだ相手の塊を ACL で縛る (呼んだ相手の段 3)。ブラウザ版を console からユーザごとに開く (段 1) と、ブラウザもルータで見分ける案 (段 2) の調べ

前提: plan.md の G1.5 の行と「G1.5: 役割と部屋」の節、report/g0_w4.md・g1.md・g1b.md・x1.md (7 章: ACL で「自分の名前でだけ呼べる」)、asterism の `docs/protocol.md` (protocol 1、呼び出しのキー `asterism/<node>/<app>/<obj>/call/<caller>`)、asterism-console の `lib/relay/cloud_config.rb` (今の ACL の作り)・`docs/g0_w4.md`・`docs/v2_6.md`・`deploy/vps/`。

言葉: 文書では、Family mruby の基板・sim・ブラウザ版を「端末」と呼ぶ (「機体」は使わない)。asterism-console の文書・画面は英語。

## 1. 決まっていること (2026-10-12・10-13 ユーザ)

- **役割で書く**: 台帳に役割を置く。役割は「名前 + 許すキーのひな形」。ひな形の `${node}` は、その行が代わりに話すノードの ID の一覧で広げる (家のルータの行なら奥の端末の ID、端末が直接つなぐ行なら証明書の名前)。ひな形にはアプリ名を含めて書き、「全体で 1 つのゲーム用アプリ」という前提を無くす。台帳の各行は役割を選ぶ (複数可)。
- **「Player」を役割に置き換える**: 台帳の「Player」のチェックと、全体で 1 つの `ASTERISM_RELAY_GAME=game` を無くす。「対戦」(アプリ `game`) は最初から用意する役割の 1 つにする。今の台帳の Player の行は「対戦」の役割に移す (データベースの移行で)。画面と文書の、ゲームに寄った言葉 (Player・players-allow など) を一般の言葉に直す (nginx の snippet の名前も。ただし VPS に置いたファイルの名前が変わるので、移し方を手順に書く)。
- 台帳の「読み書きのキー / 読むだけのキー」(役割の外で直接書くキー) は残す (console 自身の `asterism/**` など、役割にならないもの)。ただし router を新しく登録するときの既定の `asterism/**` はやめる (2026-10-13 に、家のルータが何でも通せる形で登録されてしまった)。既定は空。
- **呼んだ相手をルータで確かめる (段 3)**: 役割のひな形で、呼び出しの問い合わせは `asterism/*/<app>/*/call/${node}` だけを許す (自分の名前でだけ呼べる)。meta とプロフィールの問い合わせは今までどおり。X1 の 7 章で手元の zenohd 1.10.1 に効くことは確かめてある。名前が ACL で結び付いたことを、asterism の `docs/protocol.md` の「名前は名乗り」(4.7) の近くに「ルータの ACL で確かになる場合」として一言足してよい (gem の版は上げない。gem の本体のコードは触らない)。
- **止めずに入れ替える**: Apply でクラウドのルータを起動し直さず、動いているルータの ACL だけを新しくする。zenohd 1.10.1 で、管理用の空間 (admin space) からの設定の書き換えが ACL に効くかを**最初に確かめる**。
  - 効くなら: Apply は「書き換え」を既定にし、起動し直しは「書き換えでは足りない変更」(listen・TLS の設定など) のときだけにする。管理用の空間に書けるのは console だけにする (ほかの相手に書く権利を渡さない)。
  - 効かない・一部しか効かないなら: その範囲を report に書き、代わりの案 (切れる人数の警告を Apply の画面に出す、空いている時間に反映、など) を 2-3 個書いて**止まる**。
- **ブラウザ版をユーザごとに開く (段 1)**: console に「Open the browser build」を置く。押すとその場でパスを作り、ブラウザ版を新しいタブで開く。最初に開くアプリは選べる (オセロ・何も開かないデスクトップ・ほか、台帳の役割のアプリから選べるとよい)。ノード ID はユーザに結び付ける (例: ユーザ名から作る `wasm-<ユーザ>`。使えない文字の扱い、同じユーザが 2 つ開いたときの名前の決め方は、案を決めて report に書く)。図にも誰のブラウザかが出る。固定の `ASTERISM_STUDIO_URL` は既定の値に下げる。今の Browser passes の画面 (パスだけ作る) は残してよい。
- **ブラウザもルータで見分ける (段 2)**: この段では**調べと案まで**。案: door はパスからユーザを知っているので、door から zenohd へはユーザごとの証明書の mTLS でつなぎ、ブラウザも証明書の名前で ACL に乗せる。door はブラウザの ws の流れを tls の流れに詰め替える必要がある。Zenoh 1.10.1 の ws のリンク (1 メッセージ = 1 まとまり) と tls のリンク (長さ付きの区切り) の対応、まとめ送り・分割・最初の握手の扱いを、zenoh のソースで確かめる。手元で小さな詰め替えを試してよい (コミットはしない)。成り立たなければ代わりの案 (ブラウザ専用の zenohd を door の後ろに置き、そこからクラウドへユーザごとの mTLS、など) を書く。

## 2. 作るもの

1. **asterism-console**
   - 役割: データベース (役割の表、台帳の行と役割の結び付け、移行で Player → 「対戦」)、画面 (役割の一覧・作成・編集、台帳の行で役割を選ぶ、役割から広がる ACL の中身の確かめ)、`Relay::CloudConfig` を役割から作る形に。ブラウザの ACL (ws の subject) も、役割「ブラウザ」として同じ形で書けるならそうする (今の `browsers_own` + game の規則)。
   - 呼んだ相手: 役割のひな形の `call/${node}`。
   - 止めずに入れ替える: 確かめの結果に合わせて Apply を直す (止まる条件は 1 章)。
   - ブラウザ版の段 1: 「Open the browser build」と、開くアプリとノード ID の受け渡し (パスと同じく fragment で渡す、など。サーバのログに残らない形)。
   - 文言: Player・players-allow などを一般の言葉に。`docs/` に g1_5.md を足し、g0_w4.md・deploy/vps/README.md を直す。
2. **fmruby-core**
   - ブラウザ版: console から渡すノード ID (と開くアプリ) を受け取る。今の `wasm-<16 進 6 桁>` の決め方がどこにあるかを読み、渡されたときだけそれを使う。ブランチは develop から `feature/asterism-g1-5`。
   - `doc/ruby_asterism/report/g1_5.md`。
3. **VPS の更新の手順** (VPS は今止めてある。操作はユーザ): image の入れ替え、データベースの移行 (Player の行が役割に移ること)、nginx の snippet の名前を変えるならその手順、戻し方。report の最後に、ユーザがそのまま打てる形で書く。本当のドメイン・IP は書かない (`router.example.org`、`192.0.2.x`)。

## 3. 受け入れ条件

1. 台帳で役割「対戦」を選んだ家のルータの行と、ブラウザで、オセロが手元の構成 (deploy/vps と同じ形の docker、nginx と door を含む) で指せる。家のルータの行の奥の端末は、自分のノードの場所にしか書けない (別のノード ID を名乗って `game` に書く・呼ぶと断られることを確かめる)。
2. 呼び出しは自分の名前でだけ通る: 端末・CRuby で、別の名前を名乗って呼ぶと答えが来ない (X1 の 7 章と同じ確かめを、役割から作った ACL で)。
3. 「Player」と `ASTERISM_RELAY_GAME` が画面・設定・文書から消え、今の台帳 (Player の行) が移行で「対戦」になる。移行の前と後で、作られる ACL が同じ意味になる (`call/${node}` の絞り込みが増える分を除く) ことをテストで確かめる。
4. 止めずに入れ替える: 効く場合は、Apply の前後でブラウザと家のルータが切れずに、ACL の変化 (行を Disable にする → その相手が書けなくなる) が効くこと。効かない場合は 1 章のとおり止まっている。
5. ブラウザ版の段 1: console から開いたブラウザ版が、ユーザに結び付いたノード ID で図に出て、選んだアプリが開く。パスはこれまでどおり使い切り・サーバのログに残らない。
6. 段 2 の調べと案が report にある (成り立つか、根拠のソースの場所、手元で試したならその結果)。
7. asterism-console のテストと rubocop が通る。fmruby-core の wasm のビルドが通り、sim の標準構成も今までどおり起動する (Linux の build/ は x86-64 のまま)。

## 4. 範囲・決まり

- **触ってよいもの**:
  - asterism-console: main にコミット。push しない。
  - fmruby-core: `feature/asterism-g1-5` にコミット (ブラウザ版のノード ID の受け取りと report)。push しない。**コミットは必ずファイルを指定する。`git commit -a` は使わない** (`.env` にユーザの手元の変更がある)。
  - asterism: `docs/protocol.md` に一言足すだけなら main にコミット (push しない)。gem の本体 (mrblib・lib) は触らない。直しが要るなら差分と理由を report に書いて返す。
- **触らないもの**: `.env`、sdkconfig、ファームの C、fmruby-graphics-audio、公開済みの gem、**VPS (ssh で何かを変えることは一切しない。読むのもしない)**、家のルータの手元の設定 (`~/asterism-home/`)。
- **端末**: 確かめは sim・ブラウザ版・CRuby・手元の docker で行う。P4-Nano は任意 (使うなら tab5_* に ip を渡す。ミュート中。焼き直しはしない)。
- **終わったら**: 起動したものを全部止める (compose、sim、ブラウザ、rails、bridge、zenohd、P4 のアプリ)。作った docker の image のうち試し用のものは消す。`build/` は Linux の標準構成 (x86-64)。
- **止まる条件**:
  - 止めずに入れ替えるのが zenohd 1.10.1 で効かない・一部しか効かない (1 章)。
  - 役割の形 (ひな形の書き方・台帳との結び付け) で、1 章の決まりでは決めきれない選択が出た。案を書いて返す。
  - gem の本体の直しが要る。
  - 端末のファームの C や sdkconfig を変えないとできない。
- **report** (`doc/ruby_asterism/report/g1_5.md`、常体): 役割の形とひな形の書き方、移行のしかた、止めずに入れ替えるの確かめの結果 (根拠つき)、呼んだ相手の確かめの結果、ブラウザ版の段 1 の作り (ノード ID の決め方)、段 2 の調べと案、受け入れ条件ごとの結果、見立てと違った点、残った課題、VPS の更新の手順。
