# Asterism G1 指示書: 家の中でオセロ (交互に指す対戦)、ブラウザ版の合言葉、実時間の測り (家の中)

> 状態: 指示 | 更新: 2026-10-12 | Family mruby の端末とブラウザ版で、家の中の網 (LAN) でオセロを対戦する。相手の一覧と待ち合わせ、手を呼び出しで送る、切れたときの扱い、console での観戦と記録。あわせて、ブラウザ版が合言葉を `wss://` に付ける直し (G0 の残り) と、実時間の測り (G-RT の家の中の分) を行う

前提: plan.md の G の節 (G0・G1・G1.5・G-RT、範囲は「多少の遅れを許す遊び」まで)、report/g0_w4.md (対戦用のキーの範囲 `asterism/<ノード>/game/**`、ブラウザ版の合言葉の案)、report/s4.md (端末どうしの呼び出しの往復、`from:` の件)、doc/ruby_asterism/browser.md、asterism の README (portable API: expose / 呼び出し / on_join / on_leave / every / subscribe / profile)、fmrb-app-new の skill (アプリの雛形と picoruby の地雷)。

言葉: 文書では、Family mruby の基板・sim・ブラウザ版を「端末」と呼ぶ (「機体」は使わない)。

## 1. 決まっていること

- 遊びはオセロ (8x8、交互に指す)。速い実時間の遊びは扱わない (2026-10-12 ユーザ)。
- **キーの範囲**: G0 の ACL に合わせ、Asterism のアプリの名前は **`game`**、オセロはその中のオブジェクト (例: `asterism/<ノード>/game/othello`)。ほかのゲームを足すときも `game` の下に置ける形にする。
- 各プレイヤーのゲームは自分のノードの下にオブジェクトを出し、相手のオブジェクトを呼ぶ (例: `opponent.invite`、`opponent.move(x, y)`)。どちらの側も盤を持ち、相手の手を自分の盤で確かめる (正しくない手は受けない)。
- 呼んだ相手は、引数で自分のノードの ID を渡して知らせる (gem の変更はしない。S4 の `from:` の件は未決のまま)。
- 家の中の網 (LAN、家のルータ = 親リポジトリの zenohd の LAN 向けの重ね合わせ) で遊ぶ。VPS は使わない。

## 2. 作るもの

1. **オセロのアプリ** (`flash/app/test/othello.app.rb` と `.app.toml`。アイコンも):
   - **待ち合わせ (ロビー)**: 生存の監視で、`game/othello` を出しているノードの一覧を出す (相手の名前は profile の `name` があればそれ)。相手を選んで「誘う」→ 相手の画面に「誰々から誘い。受ける / 断る」。受けたら先手・後手を決めて始める。
   - **対戦**: 盤、手番、石の数、相手の名前、最後の手。自分の手番でだけ置ける。置けないときはパス。終わったら結果。投了。
   - **切れたとき**: 相手が網から消えた (on_leave) ら、画面に出して一定時間待つ。戻ってきたら続けられるか (盤の状態を問い合わせて合わせる) を試み、戻らなければ終わりにする。決め方は docs に書く。
   - **入力**: キーボード (矢印・Enter・Esc) とマウス (クリック)。Tab5 の相対タッチでも遊べること (カーソル + タップ) を意識する。
   - **画面**: 426x240 (Modern・sim・ブラウザ版) を基本に、窓の大きさに合わせて盤を縮める。AtomS3R (128x128、ボタン 1 個) では観戦か「遊べない」表示でよい (無理に対応しない)。
   - 状態 (盤・手番・手の数) は `state` で問い合わせられ、手を指すたびに `put` で配る (console と観戦用)。
2. **ブラウザ版の合言葉** (G0 の残り、report/g0_w4.md の案のとおり):
   - `wasm/web/main.js`: `?zenoh_pass=` をその回だけ読み、保存せず、アドレスの欄から消す。
   - `wasm/zenoh/zp_ws_emscripten.c` (`zp_ws_js_open` か URL の組み立て): `wss://` を選んだときに `?pass=` を付ける。`ws://` (手元) では付けない。
   - 合言葉が URL・ログ・ブラウザの保存領域に残らないこと。
3. **実時間の測り (G-RT の家の中の分)**: 遊びではなく測るための最小の試し (`flash/app/test/rt_probe.app.rb` など)。自分の位置 (画面の中を動く点) を毎秒 20-30 回 `put` で配り、相手の点をそのまま描く。片道と往復の遅れ (時計のずれに頼らない測り方を選ぶ。往復を測って半分にする、など)、落ちる・順番が入れ替わる割合、毎秒の送る量、更新の 1 周の時間、内蔵 RAM を測り、console で記録 (MCAP) する。遅れを隠す工夫は試すとしても 1 つ (補間) まで。
4. **docs**: オセロの遊び方と、家の中での始め方 (zenohd の LAN 向けの起動、端末とブラウザ版の起動) を、親の `docker/` の README か doc に。G-RT の数字は report に。

## 3. 受け入れ条件

1. 次の組み合わせで、待ち合わせから終局まで遊べる: 端末 (P4-Nano) 対 ブラウザ版、sim 対 ブラウザ版、ブラウザ版 対 ブラウザ版 (別のプロファイル)。Tab5 は、つながっていれば。
2. 正しくない手 (相手の手番、置けない場所) は受けない。途中で片方のアプリを止めると、もう片方が「相手が切れた」を出し、決めた扱いになる。
3. asterism-console で、2 つのノードの `game/othello` と状態の配信が見え、記録して巻き戻すと盤の移り変わりが追える。
4. ブラウザ版の合言葉: G0 の手元の通し稽古の構成 (asterism-console の `deploy/local/rehearse`) で、ブラウザ版が `?zenoh_pass=` 付きの URL から `wss://` で入れる。合言葉が残らない。
5. G-RT: 組み合わせ (端末どうし、端末とブラウザ版、ブラウザ版どうし) ごとの遅れの分布と落ちる割合が report にある。見た目の確かめ (相手の点の遅れ・跳び) はユーザに頼む項目として書く。
6. 内蔵 RAM が増えない (アプリは VM の上なので、ファームの共通の部分を変えたときだけ確かめる)。`rake test`、sim の標準構成 (エディタの 1 打鍵)、ブラウザ版のビルドが通る。

## 4. 範囲・決まり

- **触ってよいもの**: fmruby-core の `flash/app/test/othello.*`・`rt_probe.*`、wasm 版のページと Zenoh のリンク (`wasm/`)、doc。ブランチは develop から `feature/asterism-g1`。コミットのみ、push しない。**コミットは必ずファイルを指定する。`git commit -a` は使わない** (`.env` は変えない)。親リポジトリ: docs の追記 (develop にコミットのみ)。asterism-console: 要る直しがあれば (観戦の見せ方など) ブランチ `feature/g1` にコミットのみ。
- **触らないもの**: 公開済みの gem (直しが要るなら差分を書いて返す)、ファームの C の振る舞い (wasm のリンクの直しは可)、sdkconfig、submodule、VPS。
- **端末**: P4-Nano (192.168.10.10、`/dev/ttyACM0`。アプリは tab5_fs で送る。焼き直しは要らない見込み)、AtomS3R (`/dev/ttyACM1`、WiFi)。どちらもミュート中。端末の IP・mDNS の名前・MAC はリポジトリに書かない。
- **終わったら**: 起動したものを全部止める。`build/` は Linux の標準構成 (x86-64)、ブラウザ版のビルドが通る状態。
- **止まる条件**: ここに無い仕様の選択 (使う人から見える遊び方・名前で、迷うもの)、公開済みの gem の直し、ACL のキーの範囲を変える必要。
- **report**: `doc/ruby_asterism/report/g1.md`、Japanese plain style (常体)。
