# W1 報告: 中核の配管とスクロールする 3 つの画面

> 状態: 完了 | 更新: 2026-08-31 | 端から端まで通った (browser / sim 両方で実測)。計画の「FmrbUI に入れれば 7 画面がただで動く」は外れ、`wheel_rows` に置き換え。sim では中継 (graphics-audio) の型ホワイトリストが 1 箇所抜けていた

計画は plan.md。検証はブラウザ経路 (W2 の前半を先に足した) で行った。

## 通した経路

```
ページの wheel / SDL_MOUSEWHEEL / fmrb_input.rb wheel
  → fmrb_host_send_mouse_wheel(x, y, notches)
  → host_task → HID_MSG_MOUSE_WHEEL (subtype 10)
  → input_router (フォーカスのある窓へ、窓相対座標で)
  → アプリ基底 (mruby は app.c、Spinel は _parse_hid_event)
  → { type: :mouse_wheel, delta:, x:, y: }
  → wheel_rows(ev) → アプリ自身のスクロール
```

触った継ぎ目は 16 ファイル。**既存のイベントには 1 バイトも触っていない**
(新しい型・新しい subtype・新しい関数を足しただけ)。

## 計画から変えたこと: FmrbUI ではなく `wheel_rows`

計画では「FmrbUI の scrollbar がホイールを拾えば、既に scrollbar を持つ
7 画面がただで動く」と書いた。**これは成り立たなかった**。

実際にはどの画面も**スクロール位置を自分で持ち、描画のたびに widget へ
書き込んでいる** (`@ui.set_value(:sb, @scroll)`)。widget の中の値を動かして
も次の描画で上書きされて消える。scrollbar は状態の持ち主ではなく、状態の
絵だった。

そこで**アプリ基底に `wheel_rows(ev)`** を置いた。ノッチ数 ×
`FmrbConst::WHEEL_LINES` を返し、ホイール以外なら nil。アプリ側は 4 行:

```ruby
rows = wheel_rows(ev)
if rows
  @scroll -= rows
  ... 端で止める ...
  redraw
end
```

「ただで 7 画面」は失ったが、**各画面が自分の刻み方を決められる**利点が
残った (log は行、ランチャーはアイコン行、shell は履歴行)。

## 入れた画面 (W1 の範囲)

| 画面 | ホイールの効き |
|---|---|
| Log Viewer | 行送り。回すと AUTO を降りる (ログ面のクリックと同じ) |
| Shell | 履歴の行送り。less モード中は無視 |
| デスクトップ | 開いている一覧 1 つ — ランチャー / ファイル選択 / ファイルマネージャ |

エディタ本文はこのあと足した (下記)。残りは nsf_player / smf_player。

## 決めたことの実装

- **1 ノッチ = `wheel_lines` 行**。`system_conf.toml` に既定 3 で追加
  (全 7 ファイル)、1-20 に丸める。カーネルが読んで
  `fmrb_wheel_lines_set()` へ渡し、**mruby には `FmrbConst::WHEEL_LINES`
  として、Spinel には `fmrb_spx_wheel_lines()` の FFI として**同じ値が入る
  (テーマ色が通っている道をなぞった)。起動ログに `wheel=3 rows` が出る。
- **向きは奥に回すと上**。ブラウザで実測して確認: `wheel 3` で一覧が前へ
  9 行戻り、`wheel -6` で 18 行進んだ。
- **配り先はフォーカス窓**。ルータはドラッグ中だけ `@capture_pid` を優先し、
  それ以外は鍵と同じ `@hid_target_pid` へ。
- **間引かない**。move の 33ms スロットルには乗せず、クリックと同じ
  「200ms 待って送る」経路。落ちたら警告を出す。

## ブラウザ側 (W2 の前半)

ページの `wheel` イベントを**ノッチに直してから**入力 ring (型 5) に積む。
ブラウザは端末によって px / 行 / ページで報告し、符号も逆なので、
その換算はページの中で済ませる (100px = 1 ノッチ、端数は溜める)。
`fmrb_web.rb wheel N` と MCP の `web_input` からも同じ形で出せる。

## 踏んだ罠

- **libmruby が古いまま**。`wheel_rows` をアプリ基底 (gem) に足したのに
  `rake wasm:web` はそれを作り直さず、デスクトップが最初のマウスイベントで
  NoMethodError で死んだ (画面は出るがクリックに無反応、という分かりにくい
  壊れ方)。**`rake wasm:mrb` に「lib/add が libmruby より新しければ
  wasm:mruby を先に呼ぶ」を足した** — 同じ形の罠を 2 度踏んだので、
  3 度目が無いようにした。
- ランチャーからの起動は**ダブルクリック**なので、一覧をホイールで動かした
  後に同じ座標を叩くと**別のアプリが起動する** (実際 RoboExplorer が
  立ち上がった)。駆動する側の注意。

## ユーザに触ってもらって直したこと (同日)

### ランチャーが進みすぎる → 単位が 2 種類あると分かった

「ちょっと回しただけで 2 行以上進む」。**`wheel_lines` は文字行の単位**で、
ランチャーが並べているのは文字 5 行分の高さのタイルだった。1 ノッチ =
3 タイル行では、3 行しか見えていない一覧が一飛びで端まで行く。

アプリ基底に **`wheel_notches(ev)`** (刻みそのもの) を足し、
**ランチャーだけがこちらを使う** (1 ノッチ = アイコン 1 行)。名前の一覧
(ファイル選択・ファイルマネージャ) は文字行なので `wheel_rows` のまま。

**教訓**: 「1 ノッチ = N 行」の N は設定できるが、**行の高さが画面ごとに
違う**。設定は「文字行」と決めておき、そうでない一覧は刻みで数える。

### エディタ本文も回せるように (W4 の主目的を前倒し)

`move_anchor(delta)` が既にあった — **画面行単位で、折返しを 1 セグメント
ずつ辿る**。ホイールはこれを呼ぶだけで済んだ (カーソルは動かさない。
動くのは見ている場所)。モーダル (メニュー・検索・色・終了確認・キー一覧)
が開いている間は無視する。

実測: 折返し ON で 2 ノッチ = 6 画面行 = 論理 3 行、戻すと折返しの途中の
セグメントから始まる。カーソルは Ln 1 Col 1 のまま。

## sim (SDL) で見つかった罠: **中継が型のホワイトリストだった**

sim で `wheel 3` を撃っても画面が動かなかった。**配線が 1 本足りて
いなかった**。

Linux の入力は 3 ホップある。

```
fmrb_input.rb / SDL
  → sdl2-display    (fmrb_inject で受け、そのまま横流し)
  → graphics-audio  (fmrb_input_socket の *サーバ*。ここが中継)
  → core            (usb_task_linux.c が受ける)
```

真ん中の **graphics-audio `main/input_linux/input_handler_ipc.c` が
型ごとの switch で、知らない型を捨てていた** (`default:` で
`Unknown event type` を出して終わり)。`case HID_EVENT_MOUSE_WHEEL:` を
button / key と並べて足したら、その場で通った。

つまり Linux 経路のリンク定義は **3 箇所**にある:
core `main/include/fmrb_hid_event.h`、graphics-audio の同名ヘッダ、そして
この中継の switch。**ヘッダを 2 つ直しても、switch を直さないと黙って
消える**。

### 切り分けでかかった時間の使い方 (次に同じことをしないために)

両端 (sdl2-display が送った / core が受けた) だけを見て、**中に 1 段ある
ことに気付くまでが長かった**。効いた手は 2 つ:

- **鎖の各段に 1 行ずつ probe を入れる**。「送った 8 バイト」と「受けた
  7 バイトだけ」が食い違った時点で、間に何かいると確定した。
- **型を変えた同じ長さの packet を撃つ**。0x11 で len=5 の 8 バイトは
  通り、0x12 で len=4 の 7 バイトは通らない — **落としているのは長さでは
  なく型**、と 1 回の実験で分かった。

**教訓**: 中継の `default:` はログを出していたのに、私はその中継のログ
(`docker logs fmruby_graphics_audio`) を最後まで見ていなかった。sim は
コンテナが 3 つあり、**ログも 3 つある**。

## sim での実測 (2026-08-31)

- Log Viewer: `wheel 3` で 9 行戻り (3 ノッチ x wheel_lines=3)、AUTO が
  外れて HOLD に。`wheel -2` で 6 行進む。
- ランチャー: `wheel -1` でアイコン 1 行ぶん進む (ノッチ単位。文字行では
  ないので進みすぎない)。
- ルータのログで `delta=3 target=4` (フォーカス窓の pid) を確認。
