# W3 報告: 実機の USB マウスからホイールを採る

> 状態: 完了 | 更新: 2026-09-01 | NARYA v4 + MOSART 2.4G コンボマウスで実機確認済。
> **記述子には頼らない**と決着 (SDK 側の問題、ユーザ判断)

## 決めた形 (計画どおり)

**設定ファイルに書いた機器だけがホイールを出す**。記述子解析は位置を
見つけたら記録するが、**それだけでは有効にならない**。
`/etc/hid_devices.toml` の `wheel = {...}` が唯一のスイッチで、書いて
いないマウスは 1 バイトも挙動が変わらない (回帰ゼロが W3 の本題)。

| 触ったところ | 中身 |
|---|---|
| `hid_report_parser` | Usage 0x38 (Wheel) を拾って位置と幅を記録・ログ。**有効化はしない** |
| `hid_device_config` | `wheel = {...}` で `wheel_enabled`。`protocol = "report"` も |
| `usb_task` | レポートからホイールを取り出して `fmrb_host_send_mouse_wheel` へ (±127 で頭打ち) |
| `hid_devices.toml` | 上記 2 つの書き方を先頭のコメントに |

書いていない機器には**1 回だけ**、そのまま貼れる形でログを出す:

```
usb_task: Mouse VID=0x.... PID=0x.... reports a wheel (offset=24 size=8);
  add wheel = { offset = 24, size = 8, ... } to /etc/hid_devices.toml to use it
```

## 実機で分かったこと (ここが本体)

### 1. Boot Interface のマウスは 3 バイトしか喋らない

繋がっていた MOSART 062A:4101 は Boot Interface のマウスで、レポートは
**3 バイト固定 (ボタン/X/Y)**。Boot Protocol の仕様どおりで、**ホイールの
バイトがそもそも存在しない**。どんな offset を書いても届かない。

しかも Boot デバイスは記述子解析の経路に入らない (決め打ち配置が当たる)
ので、**今回足した記述子側のホイール検出はそもそも走らない**。

そこで `[[mouse]]` に **`protocol = "report"`** を足した。**そこに書いた
機器だけ** SET_PROTOCOL(Report) を送り、機器自身の形式で喋らせる。

### 2. SET_PROTOCOL は timeout を返すが、機器は切り替わっている

`SET_PROTOCOL(Report) failed (0x107)` が出る。既存コメントが言うとおり
**ホストが STATUS の ACK を取りこぼしているだけ**で、機器は切り替わって
いた。証拠は**レポート長が 3 → 7 バイトに変わったこと**。
戻り値だけ見て諦めないこと。

### 3. 記述子は当てにならない (SDK 側、ユーザ判断で撤退)

「機器自身に配置を聞けばいい」と考えて `layout = "auto"` を実装したが、
**Boot subclass のインタフェースでは `hid_host_get_report_descriptor()` が
ゴミを返す** (168 バイトの中身がポインタらしき値 `24 D5 F4 4F ...`)。
解析は当然失敗し、**失敗すると「マウスではない」と判断して切断する**ので
マウスが一度死んだ。

**ユーザ判断: この機器に限らず記述子には頼らない**。実装した
`layout = "auto"` は撤去した。**設定ファイルにビットを書く**、当初の白名簿
だけを残す。

- 残る罠: 記述子解析の失敗は今も切断を招く。設定ファイルが名指しした機器
  でこれが起きるのは筋が悪いので、直すなら「名指しの機器は切断しない」。

### 4. 配置の測り方 (道具は揃っている)

HID Inspector の生バイト表示で測れる。**手順にコツが 2 つある**。

- **`report_len` を多め (8 など) に宣言しておく**。コピー長がこの値から
  決まるので、実際より短く宣言するとレポートの後ろが切れて見えない
  (最初 4 と書いていて、5 バイト目以降を見落とした)。
- **動かし続けたまま画面を撮る**。相対軸は手を止めると 0 に戻るので、
  止まった後の「最後のレポート」は全部ゼロで役に立たない。

右・下・ホイールの 3 つを 1 回ずつ撮れば決まる:

```
右:      03 00 01 00 00 00 00     <- raw index 2
下:      03 00 00 10 00 00 00     <- raw index 3、ただし 0x10
ホイール: 03 00 00 00 00 FF 00     <- raw index 5 = -1
```

**下に 1 動かして `0x01` ではなく `0x10` が出たのが決め手**。値が 4 ビット
上にずれている = Y は index 3 の上位ニブルから始まる = **軸は 12 ビット詰め**。
「左右が効かない・上下が動きすぎ」という症状はこれで説明がつく (8 ビットと
して読むと X は下位 8 ビットだけ、Y は X の上位 4 ビットを巻き込む)。

### 5. 測れた配置

```toml
[[mouse]]
vid = 0x062A
pid = 0x4101
name = "MOSART 2.4G Mouse"
protocol = "report"
report_id = 0x03
report_len = 6
buttons = { offset = 0, size = 8, min = 0, max = 1, relative = false }
x = { offset = 8, size = 12, min = -2048, max = 2047, relative = true }
y = { offset = 20, size = 12, min = -2048, max = 2047, relative = true }
wheel = { offset = 32, size = 8, min = -127, max = 127, relative = true }
```

既存の Logitech Unifying の項目と**同じ 12 ビット詰めの形**だった。

## 実機での結果

ユーザ確認: **ホイールでログビューアがスクロールし、カーソルの動きも自然**
(2026-09-01、NARYA v4)。

## 作業のやり方で効いたこと

`/etc` は遠隔ファイル転送の届かない場所 (許されるのは /app /home
/usr/share /mnt/sd)。だが**端末の上のアプリからは書ける** — HID Inspector
自身が同じことをしている。そこで `/etc/hid_devices.toml` を書き換える
使い捨てアプリを `/app/usr` に置いて起動する形にした。**焼き直し 5 分が
30 秒になり**、配置を 3 回変えて試せた。

## 残り

- **HID Inspector のウィザードにホイールの段がない**。今は生バイトを見て
  手で書く。「ホイールを回してください」の段を足して、生成する TOML に
  `wheel = ...` を混ぜるのが自然な次の一歩。
- ウィザードは 12 ビット詰めを X/Y については当てられるが、**Report ID の
  ある機器で `protocol = "report"` を書き出さない**。
