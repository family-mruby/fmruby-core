> ファイルマネージャー (起動のしかた・関連付け `config/associations.toml` と `/home/associations.toml`・右クリックの扱い)、

C3a の後にユーザが決めたこと (2026-11-21):

## 1. 絵のビューワーを新しく作り、PNG・BMP の標準にする

- ユーザの言葉: 「標準はビューワーアプリ、右クリックでスプライトエディタ。ビュワーは新規に作る」。
- **ビューワー** (新しいアプリ。置き場は `flash/app/tool/`、名前は任せるが report に書く): 絵のファイルを開いて見る。
  Window に収まる整数倍で出す (小さい絵は拡大、大きい絵は等倍でスクロールか縮小かを決めて report に)。
  ファイルの名前・大きさ (WxH) を出す。透明色 `0x01` の所は市松などで見分けられる。同じフォルダの前・次の絵へ送れる
  (キーの左右) と便利だが、重ければ入れなくてよい。「スプライトエディタで開く」をメニューに置く。
  Retro (320x240) でも動く大きさにする (絵は Retro でも使う)。
- **関連付け**: 既定で png・bmp = ビューワー。ダブルクリックでビューワーが開く。
- **右クリックでスプライトエディタ**: ファイルマネージャーで絵のファイルを右クリックしたときに「スプライトエディタで開く」を
  選べる。今のファイルマネージャーに右クリックのメニュー (ほかのアプリで開く) があるかを先に読む。
  - あるなら、そこに載る形にする。
  - **無いなら、作る前に止まって、案 (どんなメニューにするか・ほかの種類のファイルにも広げるか・タッチの端末での
    出し方) を選択肢にして返す**。ビューワーと残り (2・3) は先に進めてよい。

## 2. ファイルの画面に「最初に開くフォルダ」を渡せるようにする

- ユーザの決定: 名前の無い絵で「保存」を選んだら、テキストのエディタと同じくファイルの画面を開き、**最初に
  `/home/stamps/` が開いている**ようにする。
- デスクトップのファイルの画面 (開く・保存) に、呼ぶ側が最初のフォルダを渡せる引数を足す (渡さなければ今までどおり)。
  無いフォルダを渡されたときの扱い (作る・親へ戻る) を決めて report に書く。スプライトエディタは、保存と名前を付けて保存で
  `/home/stamps/` (無ければ作る) を渡す。開くでも同じにするかは、使い勝手で決めて report に書く。
- テキストのエディタの動きは変えない (渡さない)。

## 3. PNG の透明を、読み込みで透明色 0x01 にする

- ユーザの決定: 端末の PNG の読み込みを直し、透明な画素 (α が 0、tRNS で透明と指定された色) を `0x01` にする。
  半透明 (α が 0 でも 255 でもない) の扱いは、しきい値 (見立て: α < 128 を透明) を決めて report に書く。
- 絵を使うアプリ全部に効く直しなので、**今リポジトリにある絵 (flash/ の下の PNG) で、読んだ結果の画素が変わるものが
  あるかを全部調べる** (α つき・tRNS つきの絵の一覧と、変わる画素の数)。変わる絵があれば、どのアプリの見た目が
  どう変わるかを report に書く。**見た目が悪くなるもの (今まで色で出ていた所が抜けて困る) があれば、直さずに止まって返す**。
- 逆に、RGB で `0x01` に丸まる不透明な色 (紺色 (0,0,85) の近く) が透明と取り違えられる件は、今までと同じ扱いのまま
  (ここでは変えない)。事実だけ report に書く。
- sim・ブラウザ版・ネイティブ版・ESP32 で同じコードが使われるか (graphics-audio の側にも PNG の読み込みがあるか) を読む。
  **graphics-audio の直しが要るなら止まって返す** (別のリポジトリ)。

## 4. 受け入れ条件

1. sim の Modern: ファイルマネージャーで PNG をダブルクリックするとビューワーが開き、絵・名前・大きさが出る。
   BMP も同じ。ビューワーの「スプライトエディタで開く」で、同じ絵がスプライトエディタで開く。
2. スプライトエディタ: 新規 → 保存で、ファイルの画面が `/home/stamps/` で開き、名前を打って保存できる。
   テキストのエディタの開く・保存は今までどおりの場所で開く。
3. α つきの PNG (試験用に作る。置き場はスクラッチ) を端末に置いて、ビューワーとスプライトエディタで開くと、
   透明の所が透明色として出る。スプライトとして描くと抜ける。
4. 今ある絵の見た目が変わらない (3 章の調べ) か、変わるものの一覧がある。
5. ブラウザ版でも 1〜3 が通る (道具で確かめられる範囲)。Retro の sim でビューワーが開く。
6. `rake regress` が通る。最後に 1 回 `rake regress:screens`。ホストの試験に PNG の読み込みの試験があれば、透明の分を足す。
   内蔵 RAM・VM プールへの影響 (ビューワーの使用量、デスクトップの増分) を report に。デスクトップ (カーネルの側) を
   直すので、`rake regress:size` は親が最後に流す (流さなくてよい)。
7. `git status` に取りこぼしなし (前からある 3 つを除く)。起こしたものは止めてある。

## 5. 範囲と止まる条件

- 触ってよい所 (fmruby-core): 新しいビューワーのアプリ、`config/associations.toml`、スプライトエディタ、デスクトップの
  ファイルの画面 (最初のフォルダの引数だけ)、PNG の読み込み (透明の扱いだけ) とその試験、端末の案内、
  `tools/gen_picorabbit_sprites.rb` の古いコメント、`doc/asterism_chat/report/c3b.md`、`rake docs:index` の結果。
  Retro の storage の除外の一覧 (要るなら)。
- **触らない**: テキストのエディタの動き、チャットのアプリ、ほかのアプリの動き、回帰の道具の基準 (変わるなら、変化を
  report に書いて別コミットにし、親が検収する)、sdkconfig、submodule の中、graphics-audio、asterism-chat・tutor・console。
  **GPD・P4-Nano・VPS に触らない**。
- ブランチ `asterism-chat` の上にコミットする。1・2・3 は別々のコミットにする。push しない・develop へマージしない・
  `git add -A` を使わない。
- 止まる条件: 1 章と 3 章に書いた所。ユーザの作業が要る。範囲の外の変更が要る。利用者から見た動きを、この指示書に
  無い形で決める必要が出たとき (選ばずに、選択肢にして返す)。
- 内蔵 RAM を増やさない (デスクトップの直しは引数 1 つ。常に持つ領域を足さない)。
