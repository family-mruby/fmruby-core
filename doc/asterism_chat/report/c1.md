# C1 報告: チャットホストの gem の最小 (文字だけ)

> 状態: 完了 | 更新: 2026-11-21 | 新しいリポジトリ asterism-chat (ローカルの git だけ、GitHub なし・push なし) に、部屋・番号・知らせ・履歴の保存・表示名・1 日の上限・記録・`status`・SIGTERM を持つチャットホストの gem 0.1.0 を作った。ローカルの zenohd で、送り手 2 つが同じ部屋で話して互いの知らせから続きを取り、後から来た送り手が履歴を取り、起こし直しても履歴・番号・表示名が残ることを自動の試験で確かめた (`bundle exec rake test`: 部品 12 件・通し 5 件)。指示書は instruction_c0_c1.md

## 1. 作ったもの

置き場: `../asterism-chat/` (family-mruby の直下。直下のリポジトリからは追跡しない、asterism-tutor と同じ)。形は asterism-tutor に倣った。

| ファイル | 中身 |
|---|---|
| `lib/chat/config.rb` | 設定。引数 > 環境変数 `ASTERISM_CHAT_*` > ファイル > 既定。部屋は `[[rooms]]` (`id`・`title`) か `ASTERISM_CHAT_ROOMS=id:題,...`。部屋の id は `a-z 0-9 _ -` の 16 文字まで (履歴のファイル名にもなる)。起動のときに部屋の重なり・上限の値を検査 |
| `lib/chat/room.rb` | 公開するオブジェクト `room` (`hello`・`rooms`・`post`・`history`)。断りは `{"error", "message"}`。`cid` で送り直しを 1 回に数える。発言のたびに `news` に `{"room", "n"}` |
| `lib/chat/store.rb` | 部屋ごとの発言 (`state_dir/rooms/<id>.jsonl`、1 行 1 発言、追記) と表示名 (`names.json`)。残す数 (`history`) を 4 分の 1 (16 件以上) 超えたら残す分だけで書き直す (全部書いてから rename)。起動で読み戻し、途中で切れた行は飛ばす |
| `lib/chat/limits.rb` | 1 日の発言の数 (端末ごと)。起こし直したら記録の `post` から数え直す |
| `lib/chat/log.rb` | JSONL の記録 (1 日 1 ファイル)。発言は部屋・番号・文字数だけで、本文は入れない (c0 6 章 Q9 の推奨) |
| `lib/chat/status.rb`・`server.rb` | `status.json` を 2 秒ごと、`asterism-chat status` (0/1/2)。SIGTERM で新しい発言を `stopping` で断って終わる |
| `exe/asterism-chat` | 起動と `status` |
| `test/sender.rb` | 端末の代わり (CRuby)。`*/chat/room` を探し、`<host>/chat/news` を購読し、`catch_up` で「持っている最後より後」を全部取る。手で使う形 (標準入力の行を発言する) もある |
| `test/test_parts.rb`・`test/test_e2e.rb` | 部品の試験と、gem をプロセスで起こす通しの試験 |
| `config/chat.toml.example`・README.md・README.ja.md・CHANGELOG.md・LICENSE (MIT)・`.ruby-version` (3.4.13) | |

- 依存は asterism (>= 0.14)・msgpack・tomlrb だけ。rubocop の設定は asterism-tutor に無いので置いていない。
- 試験のルータは docker の `eclipse/zenoh:1.10.1` を 127.0.0.1:17530 に (sim の 7447・回帰の道具の 174xx・asterism-tutor の 17520 と別)。
  `rake e2e` が起こして止める。
- C2・C3 のために: スタンプは `post` の `req` にキーを足し、`Room::METHODS` にメソッドを足せば載る形にしてある。`deploy/vps/` は C4。

## 3. 気づいたこと

- 購読してすぐの発言は、publisher が購読者を知る前だと知らせが出ないことがある (design.md のとおり)。試験は購読の後に 1 秒置いて
  から話す。端末 (C2) は、開いたときに `hello` の `rooms` の `last` で追いつき、その後は知らせで取る形にすれば取りこぼさない。
- 知らせの購読の中 (受信のスレッド) で `history` を呼ぶと待つ呼び出しになる。`test/sender.rb` は知らせを Queue に積み、別の
  スレッドで取りに行く。端末では `proxy.async.history` の Future を `on_update` で見る (AI ヘルパーと同じ)。
- 呼び出しの中 (受信のスレッド) から `news` に put しても問題なかった。

## 4. 確認していないこと

- 端末 (mruby) からの呼び出し・購読 (C2)。mTLS のルータと console のロール (C4)。
- 長く動かしたときのファイルの書き直しの頻度と時間 (500 件で 125 発言ごとに 1 回、1 部屋最大 350 KB の書き直し。測っていない)。
- 同時に多くの端末が送ったときの順番 (呼び出しは受信のスレッドで 1 つずつ答えるので番号は重ならない。負荷はかけていない)。
