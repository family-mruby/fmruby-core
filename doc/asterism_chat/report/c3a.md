# C3a 報告: スプライトエディタを使いやすくする

> 状態: 完了 | 更新: 2026-11-21 | スプライトエディタ (`flash/app/tool/sprite_editor.app.rb` + `sprite_editor/screen.rb`) を、上にメニューバー・左に道具・中央に拡大した絵・右に 256 色と最近の色とタイルの一覧・下に状態の行、の形に作り直した。ペン (なぞれる)・消しゴム・塗りつぶし・色を拾う・取り消し (10 回)、新規 16/24/32/48、開く・保存・名前を付けて保存 (デスクトップのファイルの画面)、変更ありで閉じるときの確認、16x16 のタイルのシート、Window の大きさへの追従。sim の Modern (426x240・640x360、英語・日本語) とブラウザ版で受け入れ条件 1〜5 を確かめた。0x01 は PNG にパレットの色 (0,0,85) として書かれ、tRNS は付かない。透明として出すのは `use_transparent` のスプライトで。指示書は instruction_c3a.md

描画は、毎回多く描くものを描画側に 1 度だけ作って `draw_tile` で押す形にした: 256 色の升目 (1 枚のスプライトの絵) と、透明の市松模様の帯 (拡大した絵用とタイル一覧用)。透明の点の連なりは 1 回の押し、色の点の連なりは 1 つの `fill_rect`。最初に素直に書いた形 (透明 1 点に矩形 3 つ、色は 1 升ずつ) は、空の 32x32 で全体の描き直しが 306 ms (アプリの側の時間。描画側は 1 秒以上遅れて画面に出た、送るコマンドが 3,500 ほど) だったのが、この形で 7〜11 ms (タイルのシートで 40 ms) になった (sim)。1 点塗るのは矩形 1 つと一覧の 1 点。

## 4. 数字

- **VM プール (sim、64 ビット、debug server の gc の後)**: 48x48 の絵 (色の点だらけ)、256 色、取り消し 10 回分を持った状態で **624,968 B** / 1,572,864 B。取り消しを全部戻した後は 600,824 B で、**取り消し 10 回分は 24,144 B** (写し 2,304 B x 10 と配列の分)。見積もりどおり、絵の全体の写しを 10 個持つ形で足りる。コンパイル直後は used 472,480 B・peak 714,088 B (2 ファイルに分けた後の値)。タイルのシートは絵の全体 (例 64x32 = 2 KB) とタイル 1 枚分の写し (256 B) x 10。
- 描画側の資源: スプライトの絵を 3 枚 (升目、市松の帯 2 つ)。`create_image` (機械全体で 8 枚) は使わない。
- 全体の描き直し: 7〜11 ms (32x32・48x48)、40 ms (タイルのシート)。なぞりは 1 点ごとに矩形 1 つ + 一覧の 1 点 + 状態の行。
- `rake regress:screens`: 28 passed / 0 failed (modern 6/6・retro 6/6・web 5/5・native 6/6・native-keys 5/5、8.6 分)。

## 5. PNG と透明色 (C3 へ)

実物で確かめた (sim):

- `BMP332.save` (`encode_png`) は使われている色だけのパレットの PNG を書く。**0x01 はパレットの (0,0,85) という色として入り、tRNS (透明) は付かない**。PC の画像ソフトでは濃い紺に見える。
- 読み戻し (`BMP332.parse`・描画側の `load_bmp`) は (0,0,85) を 0x01 に戻すので、端末の中では透明の印が失われない (保存 → 開き直しで同じ絵)。
- 同じ PNG を端末に出すと:
  - `SpriteImage.new(..., transparent_color: 0x01, use_transparent: true)` + `load_bmp` + `draw_tile`: **0x01 の点は抜けて後ろが見える**。
  - 透明色なしの SpriteImage・`create_image` + `draw_image`: 紺 (0,0,85) で出る。
  - 枠のある Window の区画に `fill_rect(..., 0x01)` で描いても紺で出る (区画は透けない)。エディタが透明を市松で描くのはこのため。
- したがって **チャットの側 (C3) は、スタンプを `transparent_color: 0x01, use_transparent: true` のスプライトの絵に読んで `draw_tile` で出せば、透明として出せる** (c0.md 3.1 の「スプライトの絵を最大 8 枚程度持つ」形と同じ道)。今の端末の関数のままでよく、範囲の外の直しは要らない。
- 形式をまたぐ扱い (PC で描いた PNG の α・tRNS を 0x01 にするか、エディタの PNG に tRNS を付けるか) は、今回のエディタの中では選ぶ必要が出なかった。デコーダ (`png332.c`) は α と tRNS を読み捨てて色だけを取る、という事実だけ書いておく (6 章 Q3)。
