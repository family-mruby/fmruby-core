# C2 報告: 端末のチャットのアプリ (文字だけ)

> 状態: 完了 | 更新: 2026-11-21 | Modern の配布イメージに文字だけのチャットのアプリ (`flash/app/modern/chat.app.rb` + `chat/talk.rb`・`chat/screen.rb`) を作った。ローカルのルータ (sim の zenohd に WebSocket の口を足したもの) とチャットホストで、sim の Modern とブラウザ版が同じ部屋で互いの発言を知らせで受け、同じ順番で見た。日本語 (自前のかな入力・ブラウザの IME) が入る。履歴・さかのぼり・開き直した後の未読の数・幅で切り替わる画面・同じ表示名の見分け・ホストの断りの文・ホストを起こし直した後の続きを確かめた。VM プールは 50 件の部屋を出して +10〜57 KB (sim、64 ビット)。gem の直しは要らなかった。指示書は instruction_c2.md

### 1.1 動き

- **つなぐ**: `FmrbAsterism::Link` (アプリ名 `chat`、つなぎ直し 8 秒)。つながった直後の 3 秒は 0.3 秒ごとに `*/chat/room` を探し
  (網の liveliness が届くまでの間に「見つかりません」と出さないため)、その後は 3 秒ごと。状態の行の文は AI ヘルパーの流儀で、
  相手の呼び名は「チャットホスト」。
- **呼び出しの順** (1 つずつ): 探す → `hello` → 送る発言 → 開いた部屋の最新 → 続き (`after`) → さかのぼり (`before`) →
  部屋の一覧 (知らせの欠け・知らない部屋の知らせ・60 秒ごと) → ホストがまだいるか (3 秒ごと)。
- **新着**: `*/chat/news` を購読。知らせの `n` が開いている部屋の持っている最後より大きければ `history(after:)`、ほかの部屋なら
  その部屋の `last` を上げて一覧を描き直す。`info.lost > 0` か `restarted?` なら `rooms()` を取り直す。`hello` の答えの `rooms` でも
  追いつき、開いている部屋は続きを取る。
- **二重に出さない**: 発言は `history` の答えから、番号が持っている最後より大きいものだけを足す (知らせ・`post` の答え・追いつき
  のどれが先に来ても同じ)。`post` の答えは「続きを取る」きっかけにだけ使う。
- **送る**: 1 度に 1 つ。`cid` は `"<起動からの ms>-<連番>"`。答えが無ければ (時間切れ・ホストが消えた) 発言を持ったまま、
  次の `hello` の後に同じ `cid` で送り直す。断られたら (`too_long` など) 文を入力の行に戻す (行が空のとき)。
- **端末が持つ件数**: 開いている部屋の発言だけ、最大 50 件。開くと最新 20 件 (`fetch_max`)、上の端でさらに上へ行くと
  `before:` で 20 件ずつ。50 件を超えたら、足した側の反対の端から捨てる。新しい側を捨てた後は、下の端まで戻ると `after:` で取り直す。
  ほかの部屋の発言は持たない (一覧に戻ると捨てる)。
- **時刻**: 発言の `t` (ホストの時計) を `hello` の `tz` で `HH:MM` にする。

## 2. 自分で決めた細部

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 並べる幅 | 区画の幅 **380 px 以上**で左に一覧 (112 px)・右に会話。狭ければ切り替え | c0 の案は 560 px。426x240 の画面 (sim・ブラウザ版・Tab5) では Window をいっぱいに広げても 424 px なので、560 だと並ぶことが無い。380 なら画面いっぱいの Window で並び (会話の欄 約 300 px = 全角 25 字)、最初の大きさ (300) では切り替え。640x360 の P4-Nano は 380 以上ならいつでも並ぶ |
| 設定のファイル | `/home/chat/settings.toml`。`name = "..."` と `[seen]` の表 (`"<ホストのノード>/<部屋>" = 番号`) | ホストが変わっても番号が混ざらないようにノード名を鍵に入れた。書くのは見た番号が変わってから 5 秒後にまとめて 1 回と、アプリを閉じるとき (flash の書き込みを減らす) |
| 初めての部屋の未読 | 見たことの無い部屋は、`last` 全部を未読に数える。100 以上は `(99+)` | 「見ていない分」をそのまま数えた。ホストは最大 500 件持つので、新しい端末では大きな数になる (6 章 Q2) |
| 表示名 | 初めて開くと名前の面。8 文字 (`hello` の `name_max`) まで。端末に覚えて、次の `hello` で伝える (つながっていなくても決められる)。ホストが名前を持っていて端末に無いとき (設定が消えた) はホストの名前を使う。`bad_name` で断られたら名前の面に戻す | |
| 長さの上限 | 入力の行は `hello` の `text_max` 字で止まり「長すぎます (N 文字まで)。」。ホストの `too_long` も同じ形で出る | 打ち終わってから断られるより早く分かる |
| 発言の形 | `HH:MM 名前: 本文`。自分の発言は名前と本文をアクセントの色、時刻は薄い色。1 行目は「(abc)」の分を空けて折り返す (見分けの印が出ても折り返しが変わらない) | 印は画面に出ている発言で決まるので、スクロールのたびに折り返しが変わらないようにした |
| 同じ表示名 | 画面に出ている行の発言の中で、同じ名前が別のノードから来ているときだけ `名前(末尾 3 字)` | 決定 14 |
| スタンプ | 本文が空で `stamp` の鍵がある発言は「(スタンプ)」 | 指示書 |
| キー | 一覧 (狭いとき): 上下と Enter。会話: 上下・PageUp・PageDown・ホイール、Enter で送る、Esc で一覧へ (狭いとき)。名前の面: Esc で戻る (名前があるとき) | |
| 入力の行 | 部屋を替える・一覧に戻る・名前の面に行くと、打ちかけの文は消える | 部屋ごとに打ちかけを持つ作りは足していない |
| ホストを待つ間 | 送った発言は「チャットホストにつながっていません。つながったら送ります。」と出して持つ。アプリを閉じたら捨てる | |

## 3. 受け入れ条件

確認の環境: sim は `FMRB_HW_TARGET=TAB5 rake build:linux` (Modern の標準構成、426x240)。ルータは sim の zenohd を
`docker/asterism/docker-compose.zenoh-ws.yml` で起こし直し、tcp 7447 (sim と gem) と ws 7449 (ブラウザ版) の両方で聞かせた
(ブラウザ版は TCP を開けないので、gem の試験の 17530 のルータは使えない。起こし方はどちらも docker の `eclipse/zenoh:1.10.1`)。
チャットホストは `../asterism-chat` の `exe/asterism-chat` を部屋 3 つ (家族・ゲーム・ともだち) の設定で PC から起こした。
ブラウザ版は `rake wasm:web` → `web_up`。sim のノード名は `linux`、ブラウザ版は `wasm-a10ea0`。PC から CRuby の送り手
(`test/sender.rb` を使う小さなスクリプト、スクラッチ) で別のノード名の発言を足した。

ほかに確かめたこと:

- **cid の送り直し**: ホストを SIGSTOP で止めて sim から送ると 6 秒で時間切れ (`post: Asterism::TimeoutError`)、SIGCONT の後に
  `hello` → 同じ `cid` で送り直し。ホストの部屋のファイルにその発言は 1 つ、記録の `post` も 1 行で、画面にも 1 回だけ出た。
- **同じ表示名**: PC のノード `fmruby-pcabc` も「たろう」で話すと、ゲームの部屋で `たろう(nux)` (sim、ノード `linux`) と
  `たろう(abc)` が並んだ。片方だけが画面にあるときは名前だけ。
- **表示名を変える**: 一覧の「名前」→ `Taro` → ホストの `names.json` と端末の設定が `Taro` に。前の発言はそのときの名前のまま。
- **長い発言**: 200 文字の発言は 300 px の Window で 9 行に折り返り、スクロールの棒が出た。

  アクセントの色、`08:28 まま: きょうはこうえんにいくよ` が普通の色)。

## 4. VM プール

sim の Modern (64 ビット、アプリのプール 1.5 MB)。debug server の `gc` (全部のアプリで集めてから) の直後の `ps` の mem_used。
2 回ずつ測った。

| 状態 | mem_used | 差 |
|---|---|---|
| 開いてつながった、一覧の面 (部屋 3 つ) | 609,664 B / 608,664 B | — |
| ゲームの部屋で 50 件 (ほぼ 15〜20 字の発言) | 616,432 B / 622,480 B | +10 KB |
| ともだちの部屋で 50 件 (ほぼ全部が 200 字の日本語) | 665,152 B / 667,888 B | +57 KB |

- `gc` の前の山 (答えを解いている間を含む): 50 件の長い発言を `before:` で取り足した直後に 733,504 B (ログの `pool`)。
- AI ヘルパーの動いている間 (a3d・a3e) は 653〜671 KB で、短い発言の部屋はそれより小さく、長い発言ばかりの 50 件で同じくらい。
  c0 の見積もり (短い 50 件で 20 KB、200 字ばかりで 60 KB) とほぼ同じ (64 ビット。32 ビットの ESP32 では小さくなる見込み)。
- 50 件は減らさなくてよいと見る。減らすなら、長い発言 1 件 ≒ 1.1 KB (64 ビット) なので、30 件で長い発言ばかりの部屋が約 +34 KB。

## 7. 気づいたこと

- **この mruby には `NilClass#to_i` が無い** (`undefined method 'to_i' for NilClass`)。Hash に無い鍵の値に `.to_i` を付けた所で
  落ちた。アプリでは `int(x)` (Integer でなければ 0) を使った。AI ヘルパーの `.to_i` は nil にならない値にだけ付いている。
  memory の PicoRuby の罠の表に足す価値がある。
- sim の `sim_input` で注入した最初の打鍵が、エラーの窓を閉じた後にデスクトップへ行き、エディタが開いたことがあった
  (操作の手順の問題で、アプリの不具合ではない)。
