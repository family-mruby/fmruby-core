# C0 報告: チャットの線の形・上限・スタンプ・画面の割り振り

> 状態: 完了 | 更新: 2026-11-21 | チャットホストはアプリ `chat`・オブジェクト `room` (`hello`・`rooms`・`post`・`history`)・トピック `news`。新しい発言の知らせは**番号だけ** (`{"room", "n"}`、16 B) で、本文は端末が `history(after:)` で取る。上限の既定は 200 文字・500 件/部屋・1 回 20 件 (12,000 B まで)・表示名 8 文字・1 日 300 回。スタンプは 48x48 以下・8 KB 以下の PNG を 1 回の呼び出しで運べる (小分け不要)。App Store は今の端末のままで「絵だけのパック」を入れられ、ランチャーにも出ないが、一覧を作る family-mruby-apps の道具はスクリプトの無いアプリを断る。利用者から見た動きに関わる 9 件は 6 章に選択肢で返す。指示書は instruction_c0_c1.md

コードは C1 の gem (`asterism-chat/`) のほかは変えていない。数字のうち「実測」と書いたものは C1 の試験か、下に書いた既存の report のもの。

## 0. 要点

| 項目 | 決めたこと |
|---|---|
| 位置 | ホストのノード (既定 `chat`) のアプリ `chat`、オブジェクト `room`、トピック `news`。端末は `*/chat/room` を探す |
| 呼び出し | `hello(info)`・`rooms()`・`post(req)`・`history(req)`。全部 `caller: :from` で、断るときは例外でなく `{"error", "message"}` |
| 知らせ | `news` に `{"room" => id, "n" => 番号}` だけ。本文は載せない (1 章 1.3) |
| 番号 | 部屋ごとに 1 から。ホストが振る。全員が同じ順番で読む |
| 上限 | 200 文字、500 件/部屋、1 回 20 件かつ 12,000 B、表示名 8 文字、1 日 300 回/端末。端末は 1 部屋 50 件まで持つ (2 章) |
| スタンプ | PNG、48x48 以下、8 KB 以下。1 枚が 1 回の呼び出しに収まるので小分けにしない (3 章) |
| パック | `/app/usr/<id>/` に `<id>.app.toml` と PNG を平らに置く形なら、今の App Store で入り、ランチャーには出ない (3.4) |

## 1. 線の形

### 1.1 位置と `from`

- ホスト: ノード ID は設定 (既定 `chat`)、アプリ名 `chat`、オブジェクト `room`、トピック `news`。パスは `<host>/chat/room`。
- 端末のアプリ名も `chat` (端末のノードの下。`room` は公開しないので `*/chat/room` はホストだけに当たる)。
- `from` は asterism-tutor と同じ取り方: `net.expose("room", obj, caller: :from, methods: {...})` で、各メソッドが `from:` に
  呼んだノードの ID を受ける。素の TCP では名乗りにすぎず、VPS のルータでは console の証明書と ACL
  (`asterism/*/chat/room/call/${node}`) で拘束力が出る (ai_coding a0 2.1・2.4 と同じ)。表示名・発言・1 日の数はこの `from` ごと。

### 1.2 呼び出し

| メソッド | 引数 | 答え |
|---|---|---|
| `hello(info)` | `{"name" => 表示名 (省くとホストが持っている名前のまま), "fw", "lang", "host"}` | `{"ok" => true, "proto" => 1, "host" => ホストの名前, "name" => この端末の表示名 (まだ無ければ nil), "rooms" => rooms() と同じ配列, "text_max", "name_max", "fetch_max", "per_day", "used" => 今日送った数, "tz" => ホストの UTC からのずれ (秒)}` |
| `rooms()` | | `{"rooms" => [{"id", "title", "last" => その部屋の最新の番号 (空なら 0)}, ...]}` (設定の順) |
| `post(req)` | `{"room", "text", "cid" => 端末が付ける送信の印 (省略可、32 B まで)}` | `{"room", "n" => 振った番号, "t" => ホストの時刻}` |
| `history(req)` | `{"room", "after" => n}` (n より後、古い順) / `{"room", "before" => n}` (n の直前、さかのぼり) / `{"room"}` (最新)。`"max"` (fetch_max まで) | `{"room", "msgs" => [発言, ...] 古い順, "last" => 部屋の最新の番号, "first" => 残っている一番古い番号 (空なら nil), "more" => 頼んだ向きにまだあるか}` |

- 発言の形: `{"n" => 番号, "t" => ホストの時刻 (1970 からの秒), "node" => 発言した端末, "name" => そのときの表示名, "text" => 本文}`。
  時刻はホストのもの (端末の時計は合っていないことがある、design.md「時刻」)。表示は `hello` の `tz` で時分にする。
- `hello` が `rooms` を含むので、開いたときの呼び出しは `hello` 1 回で済む。
- `cid`: 端末が時間切れの後に同じ発言を送り直したとき、ホストは前に振った番号をそのまま返す (二重に載らない)。端末ごとに直近 32 個を
  メモリに覚える (再起動で忘れる)。端末は 1 発言ごとに `"<起動からの ms>-<連番>"` のような印を付ければよい。
- スタンプ (C3) は `post` の `req` に `"stamp" => sha256` を足し、絵の出し入れのメソッド (`stamp_has`・`stamp_put`・`stamp_get`) を足す
  (3.3)。今の 4 つの形は変えない。
- アプリの状態 (`@profile?status`) は `{"version", "rooms" => 部屋の数}` だけ。端末は使わない (console の一覧用)。
  gem の健全性は `asterism-chat status` (asterism-tutor と同じ status.json の形)。

### 1.3 誤りの形

`{"error" => 種類, "message" => 端末にそのまま出す日本語の文}`。

| 種類 | いつ |
|---|---|
| `not_allowed` | 受け付ける端末 (`devices`) に無い |
| `bad_request` | 形が違う (Hash でない、`after` が負、`cid` が長い) |
| `no_room` | 設定に無い部屋 |
| `empty` | 制御文字と前後の空白を除くと空 |
| `too_long` | `text_max` 文字を超える (文に上限の数が入る) |
| `bad_name` | 表示名が空か `name_max` 文字を超える |
| `no_name` | 表示名を決める前に発言した (端末は `hello` で名前を送ってから発言する) |
| `limit` | 1 日の数を使い切った |
| `stopping` | ホストが止まるところ (SIGTERM の後)。読むことはできる |

### 1.4 知らせに本文を載せるか (比べて決めた: 載せない)

| | 番号だけ `{"room", "n"}` (採用) | 本文も載せる |
|---|---|---|
| Zenoh の 1 つの値 | 16 B (実測、msgpack) | 200 文字の日本語で 668 B (実測)。端末の上限 16 KB には十分収まる。差は決め手にならない |
| 取りこぼし | トピックは届かなかった値を出し直さない。publisher が購読者を知る前の最初の数個も出ないことがある (design.md「通し番号の数え方」)。どちらの形でも、つなぎ直し・欠け (`info.lost > 0`・`restarted?`) の後は `history(after:)` で取り直す道が要る。番号だけなら**いつも同じ 1 本の道** (知らせ → `history(after: 持っている最後)`) で、欠けを特別に扱わない | 普段は知らせから、欠けたら呼び出しから、の 2 本の道になり、重なった分の重複を端末が捨てる |
| 順番 | ホストの番号の順に `history` で取るので、全員同じ | 知らせの届いた順と取り直した分を端末が並べ直す |
| 端末のメモリ | 部屋の一覧を見ている間も、開いていない部屋の知らせは 16 B。未読の数は `n` と覚えている番号の差 | 開いていない部屋の本文も毎回 VM に入り、捨てるだけの文字列が増える |
| 費用 | 開いている部屋の新しい発言 1 つにつき呼び出し 1 回 (LAN で数十 ms の見込み、VPS 経由は未実測) | 呼び出しなし |

- 決め手は取りこぼしと順番の扱いが 1 本になること。呼び出しが 1 回増える費用は、チャットの頻度なら問題にならない。
- トピックは 1 本 (`news`) で全部の部屋の知らせを流す。端末は購読 1 つ (`<host>/chat/news`)、欠けの数え方もトピック 1 本の通し番号で
  済む。欠けに気づいたら `rooms()` で全部の部屋の最新の番号を取り直す。
- 型はアプリ独自の `asterism-chat/news` (`[["room", "str"], ["n", "int"]]`) を宣言する (design.md「アプリ独自の型」)。

### 1.5 ACL の見込み (C4 で console のロールにする)

- **chat** (端末): `asterism/*/chat/room/call/${node}`・`asterism/*/chat/room/meta` の query、`asterism/*/chat/news` の subscription、
  ホストの `asterism/*/chat/@profile`・`@pubs` の読み (型を読むため)。
- **chat-host**: `asterism/${node}/chat/**` の queryable と reply、`asterism/${node}/chat/news` の put と publisher、自分の `@profile`・
  `@pubs`・`@status`。C3 のスタンプも同じ `room` の呼び出しに載せるので、行は増えない。

## 2. 上限の値

| 値 | 既定 (C1 の gem の設定) | 根拠 |
|---|---|---|
| 発言の長さ | 200 文字 (`text_max`) | plan の見立て。全角 12 px なので 426 幅の会話の欄 (約 400 px) で 1 行 33 文字、200 文字で 6〜7 行。msgpack で 668 B (実測) |
| 履歴の件数 | 500 件/部屋 (`history`) | plan の見立て。ホストのメモリとディスクは 1 部屋 500 件 x 最大 700 B で 350 KB 以下。ファイルは 125 件 (4 分の 1、16 件以上) 余計に溜まったら書き直す |
| 1 回に返す件数 | 20 件 (`fetch_max`)、かつ 12,000 B まで (`reply_bytes`) | 端末が受け取る答えは 16 KB まで (ai_coding a0 2.1。12,287 B の片が gem → 端末で通った実績、a2)。200 文字の発言ばかりなら 17 件で止まり、`more` が立つ。普段の短い発言 (30 文字で 109 B、実測) なら 20 件で 2〜3 KB |
| 端末が持つ件数 | 1 部屋 50 件 (C2 で守る) | 開くと最新 20 件、さかのぼるごとに 20 件。50 件を超えたら反対の端から捨て、戻ったら取り直す。短い発言なら 1 件 0.3〜0.4 KB 程度 (Hash と文字列 5 つ、32 ビットの見積もり) で 50 件 20 KB、200 文字ばかりでも 60 KB 程度。AI ヘルパーの動いている間の 645〜670 KB (sim、64 ビット、a2) と同じ大きさのアプリなら、1 MB のプール (Modern) に収まる見込み。12 KB の答えを解く間の一時の山は約 2 倍 (未実測) |
| 表示名の長さ | 8 文字 (`name_max`) | 毎行の頭に出るので、全角 8 文字 = 96 px (426 幅の 4 分の 1) に収める。6 章 Q1 |
| 1 日の発言の数 | 300 回/端末 (`posts_per_device_per_day`) | 子どもの連打で家族の部屋が流れない程度。AI ホストの 50 回 (LLM の費用) とは理由が違うので多め。6 章 Q3 |
| スタンプ 1 枚 | 48x48 以下、8 KB 以下の PNG | 3 章 |
| ホストが持つスタンプ | 2,000 枚・合わせて 16 MB まで、1 日に新しく受ける絵は 1 端末 30 枚 (C3 で設定に足す) | 1 枚 8 KB の上限で 2,000 枚 = 16 MB。VPS の volume に十分収まる |

- 文字数は Ruby の `String#length` (UTF-8 の文字数)。端末でも `String#length` は UTF-8 の文字数 (memory の罠の表) なので同じ数え方になる。
- ホストは本文の制御文字を除く (改行は残す。CR LF は LF に)。表示名は改行も除く。

## 3. スタンプ

### 3.1 端末で出せる形

| 道 | 読むもの | 数の限り | 出典 |
|---|---|---|---|
| `create_image` / `draw_image` (`load_image` はこれをまとめたもの) | PNG (描画側で解く) | **機械全体で 8 枚** (`MAX_IMAGE_STORE`、graphics-audio の `main/graphics/graphics_handler.cpp:157`)。App Store も「8 枚しかない」と注意している | `sig/fmrb_gfx.rbs:728-809`、`appstore.app.rb` の `release_images` |
| `SpriteImage#load_bmp` + 切り取って描く | PNG・8 ビット BMP を RGB332 のスプライトの絵に | 機械全体で 64 枚 (`SPRITE_MAX_IMAGES`、`sprite_manager.h:13`)。デスクトップ・ランチャーのアイコンと共有 | `sig/fmrb_gfx.rbs:811-835・1078-1121` |
| `BMP332.parse` (VM の中) | PNG (非インターレース、8 ビット。グレー・RGB・パレット・グレー+α・RGBA) と BMP を RGB332 の画素の文字列に。α は捨てる。2048 x 2048 まで | VM のプールだけ (48x48 で 2.3 KB) | `lib/gems/picoruby-fmrb-bmp332/ports/esp32/png332.c:325-480` |

- 画面は RGB332 (どの端末も)。PNG のどの色も描くときに RGB332 に落ちる (`to332`)。
- 会話の欄には複数のスタンプが同時に出るので、8 枚の `create_image` では足りない。**スプライトの絵 (64 枚の共有) を、アプリの中で
  最大 8 枚程度、最近使った順に持つ**形を C3 の案にする (それを超える種類が 1 画面に出るときは、古いものを消して作り直す)。
  1 画面に出るスタンプの種類が多いときの重さは C3 で測る。
- α は効かない。透明にするならスプライトの透明色 (`use_transparent`) だが、絵ごとに透明色を決める必要がある。6 章 Q8。

### 3.2 形式と大きさ (決めた)

- **PNG、48x48 以下、8 KB 以下**。色は落とさずに PNG のまま運ぶ (ホストは絵を作り直さない: sha256 が送り手と同じまま、gem に画像の
  ライブラリが要らない)。ホストの検査は先頭の印・IHDR の幅と高さ・色の形・インターレースなし・ファイルの大きさまで (PNG を解かない)。
- 8 KB にした理由: 端末 → gem の 8 KB の片と gem → 端末の 12 KB の片が通った実績がある (ai_coding a2)。**1 枚が 1 回の呼び出しに
  収まるので、plan 3.2 の `doc_begin`・`doc_piece` の小分けは要らない**。パレットの PNG の 32x32 の絵はふつう 1 KB 未満
  (`BMP332.encode_png` は使った色だけのパレットで書く)。
- 表示の大きさは会話の欄で 32x32 (16x16 の絵は 2 倍、48x48 は等倍か縮めずに 48)。
- 未確認: mruby の文字列 (バイナリ) を msgpack で送ったとき、CRuby の側で壊れずに届くか (str として届く見込み。C3 の最初に確かめる)。

### 3.3 運び方 (C3 の案)

```
送る端末: post({"room", "stamp" => sha}) が {"error" => "no_stamp"} なら stamp_put(sha, png) してから post し直す
受ける端末: 発言の "stamp" の sha が手元 (/home/stamps/.cache/<sha>.png、案) に無ければ stamp_get(sha) => {"png"}
ホスト: state_dir/stamps/<sha>.png。sha は受けた中身から計算し直して照らす
```

### 3.4 スプライトエディタの絵をそのまま使えるか

- スプライトエディタ (`flash/app/tool/sprite_editor.app.rb`) は 16x16 のタイルのシートを開いて直し、来た形のまま
  (`BMP332.save`: `.png` ならパレットの PNG、それ以外は 8 ビット BMP) 書き戻す。新しいシートは作れない (ファイル選択で開くだけ)。
- **16x16 のシート 1 枚のファイル (PNG) はそのまま 1 枚のスタンプにできる** (16x16 の PNG、2 倍で出す)。
- 複数のタイルのシートや BMP は、チャットのアプリが `BMP332.parse` で読んで 16x16 を切り出し、`BMP332.encode_png` で PNG にすれば
  スタンプになる (どちらも端末の VM にある関数。スプライトエディタの直しは要らない)。
- 白紙の 16x16 の PNG を 1 枚どこかに置かないと、スプライトエディタで描き始められない (パックかチャットのアプリに入れる案)。6 章 Q5。

### 3.5 App Store で「絵だけのパック」を入れられるか

**端末の側 (App Store と ランチャー): 今のままで入る**。

- 入れ方: 一覧 (`registry.tsv`) の `F` の行のファイルを全部取ってから、`/app/usr/<id>/` に**平らに**書く
  (`appstore.app.rb` の `finish_install`)。下のディレクトリは作らないので、`stamps/a.png` のような名前は書けない。
- 入っているかの印は `/app/usr/<id>/<id>.app.toml` があること (`installed_version`)。消すのも同じ所。
- ランチャーは `/app/usr/<id>/` まで見る (3 段目の走査) が、`.app.toml` の隣に**スクリプト (`<id>.app.rb` など) が無ければ載せない**
  (`launcher.rb` の `parse_app_entry` → `find_script_ext`)。`launcher_visible = false` でも載らない。
- よってパックは `<id>.app.toml` (印のキー、案 `stamp_pack = true`) と PNG を平らに置く形にすれば、端末は直さずに入り、
  ランチャーにも出ない。一覧の `env` は `modern,web` にする (Retro は対象外)。入れた後の文は「ランチャーを再走査」と出る (害はない)。

**一覧を作る側 (family-mruby-apps の `tools/`): 今のままでは断る**。

- `tools/validate.rb` の `check_files` は `<id>.app.<rb|lua|bas|py>` が無いと誤りにする。`tools/registry.rb` の `entry` は
  `File.basename(m[:script_path])` で、スクリプトが無いと例外になる。店に出す絵 (`<id>.png`) は要る (パックでも並べた絵を 1 枚置けばよい)。
- 直す大きさ: `.app.toml` に `stamp_pack = true` があるときはスクリプトを求めない、の 2 か所と試験で 10〜20 行 (直していない)。
- 直さずに済ませる形もある: 何もしない小さなスクリプトと `launcher_visible = false` をパックに入れる (6 章 Q7)。

**チャットのアプリがパックを見つける方法 (案)**: 起動のとき `/app/usr/*/` を見て、`<id>.app.toml` を `FmrbToml.parse` で読み
`stamp_pack` が真のものだけ、その中の `*.png` を一覧にする。自分の絵は `/home/stamps/*.png`。パックの数は多くないので、走査は開くとき 1 回。
ブラウザ版でも `/app/usr` は再読み込みの後に残る (appstore.app.rb 冒頭)。

## 4. 画面の割り振り (案)

AI ヘルパー (`flash/app/modern/ai_helper/screen.rb`) から流用する部品:
発言の折り返しと行の持ち方 (`add_text`・`wrap`・`rewrap`・`line_text`、全角 12 px・半角 6 px の `text_px`)、
スクロールの棒 (`draw_answers`)、入力の行と IME の位置 (`draw_input`・`tell_text_cursor`)、文字の入力 (`key`・`type_char`・`utf8_feed`)、
ボタンと当たり判定 (`button`・`@hits`)、メニューバー、状態の行、Link と Future の使い方 (`ai_helper.app.rb`)。行の高さ 13。

### 4.1 426x240 (Window 1 つで面を切り替える)

```
部屋の一覧                              会話
+--------------------------------------+ +--------------------------------------+
| [部屋]  なまえ: たろう      [名前]   | | [<] 家族                 たろう      |
|--------------------------------------| |--------------------------------------|
|  家族                          (3)   | | 10:02 ママ: きょうは公園に行くよ     |
|  ゲーム                              | | 10:03 たろう: やった!                |
|  ともだち                     (12)   | | 10:05 パパ: [stamp 32x32]            |
|                                      | | 10:06 ママ(a1b): おべんとうは...     |
|                                      | |   ...さかのぼると前の 20 件          |
|                                      | |--------------------------------------|
|--------------------------------------| | > 入力の行 (かな・IME)     [絵][送る]|
| つながっています (chat)               | | つながっています                     |
+--------------------------------------+ +--------------------------------------+
```

- 未読の数は `(n)`。会話の面の `[<]` で一覧に戻る。`[絵]` で入力の行の上にスタンプの一覧 (40 px の升目で横 10 個 x 2 段、
  パックごとのタブ) を開く。
- 表示名を決める所: 初めて開いたとき (ホストが `name` に nil を返したとき) は一覧の代わりに名前の入力の面を出す。後から `[名前]` で変える。

### 4.2 640x360 (広いときは並べる)

