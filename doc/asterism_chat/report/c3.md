### 1.1 動き

- **一覧**: 部屋の中で、入力の行の「スタンプ」(送信の左) を押すと、会話の欄が一覧になる。上にタブ: 「自分の絵」と、
  パックごと (`/app/usr/<id>/<id>.app.toml` を `FmrbToml.load` で読み `stamp_pack == true` のもの。名前は `app_screen_name_ja`、
  無ければ `app_screen_name`、無ければ id)。升目はタブの中の一番大きい絵に合わせる (32 px の絵なら 38 px の升)。
  自分の絵が無くパックがあるときは、最初にパックのタブを開く。どちらも無いときは案内の文 (写し `chat_sim_empty_hint.png`)。
- **送る**: 絵を押すとすぐ送り、一覧を閉じる。
  1. 開いたときに、タブの絵を 1 枚ずつ読む: ファイルが 64 KB を超えるもの・PNG の IHDR が 48 を超えるものは解かずに「大」の升。
     それ以外は `BMP332.parse` → `encode_png` (この PNG が送る中身)。8 KB を超えたら「大」。sha256 はこの PNG で取る。
  2. 表示用の絵 (下の 3) をまだ無ければ書く。
  3. 押すと `post({"room", "stamp" => sha, "cid"})`。`no_stamp` なら同じ絵を読み直し (sha が変わっていないか確かめて)
     `stamp_put({"sha", "png"})`、その後に同じ `cid` で `post`。断られたら (大きすぎ・1 日の上限・置き場が一杯) ホストの文を状態の行に。
- **出す**: スタンプの発言は「月/日 時:分 名前:」の行の下に、左を 12 px 下げて絵。絵の高さ + 2 px を 13 px の行に割った行数を使い、
  行ごとに絵の帯 (13 px) を `draw_tile` で押す (上の端で途中まで隠れた発言も、隠れた分の帯を飛ばすだけで済む)。
  大きさ: 1 辺 32 ÷ (長い辺) の整数倍、1 倍より小さくしない (16x16 → 32、8x8 → 32、24x24 → 24、32 → 32、48 → 48)。
- **受ける**: 持っている発言のうち、表示用の絵が無い sha を 1 つずつ `stamp_get({"sha", "as" => "bin"})` で取る (開いている部屋の
  ほかの呼び出しの後、部屋の一覧の前)。届いた PNG の sha256 を確かめ、読み直して表示用の絵を書き、行を割り付け直して描く
  (下の端を見ていたら下の端のまま)。取っている間は「(スタンプ)」、ホストに無い (`no_stamp`)・sha が合わない・読めないときは
  「(スタンプは取れませんでした)」。取れなかった sha は、その部屋を開いている間はもう取りに行かない (開き直すとまた 1 回)。
- **貯める所**: `/cache/app/chat/s/<sha の先頭 32 桁>.png` (表示用に拡大した絵)。自分の絵・パックの絵の表示用もここ。
  `/home/stamps/` には何も書かないので、自分の絵の一覧に貰った絵は混ざらない。名前を 32 桁にしたのは、esp_littlefs の
  パスの長さ (64 バイト) に収めるため (`/cache/app/chat/s/` + 32 + `.png` = 54)。
- **スプライトの絵**: `SpriteImage.new(width, height, transparent_color: 0x01, use_transparent: true)` + `sync_file` + `load_bmp`。
  sha ごとに 1 枚、最近使った順に 8 枚まで (9 枚目で一番古いものを `destroy`)。部屋を替える・一覧に戻る・閉じるときに全部離す。
  一覧の升目もこの 8 枚を使い回す (12 枚のパックも全部出た。描いた後に離しても画面の絵は残る)。

### 2.1 バイナリの渡し方 (実物で確かめた事実)

- **送る (`stamp_put`)**: 端末の `BMP332.encode_png` の結果 (`mrb_str_new`、バイナリの印なし) は MessagePack の **str** で届く。
  CRuby のホストでは `String`・`UTF-8` (差し込みの行 `class=String enc=UTF-8 bytes=148`)、中身は壊れず、ホストの sha256 の照合も通った
  (sim・ブラウザ版の両方)。ホストは `png.b` で受けるので問題ない。`String#b` を付けた bin にはしていない (要らなかった)。
- **受ける (`stamp_get`)**: `"as" => "bin"` (ホストの側は `ASCII-8BIT`) と `"as" => "str"` (`UTF-8`) の両方を試した。端末ではどちらも
  `String` で届き、sha256 が合い、`BMP332.parse` が読めた。**アプリは `"bin"` を頼む** (`STAMP_AS`。バイト列の意味どおりで、
  途中で UTF-8 として扱われる余地が無い)。ホストの既定 (`stamps.binary = "str"`) は変えなくてよい。
- sha256 は、ブラウザ版は `Digest::SHA256.hexdigest` (picoruby-fmrb-sha256)、sim・ESP32・ネイティブ版は `MbedTLS::Digest`
  (`transfer.rb` と同じ選び方)。どちらも無い端末では一覧の絵を送れない文を出す (今の端末には無い)。

## 4. 自分で決めた細部

| 項目 | 決めたこと | 理由 |
|---|---|---|
| ボタン | 入力の行の送信の左に「スタンプ」。押すと会話の欄が一覧に替わる (入力の行はそのまま)。もう一度押すか Esc で閉じる | c0 の画面の案 (`[絵][送る]`) の位置。「絵」1 字だと分かりにくいので「スタンプ」 |
| 送った後 | 一覧を閉じる | 一覧が会話の欄を覆うので、自分のスタンプが出るのを見せる |
| 一覧の並び | タブ: 自分の絵、パック (id の名前順)。中は名前順。1 つのタブで 96 枚まで | パックは多くない見込み |
| パックの店の絵 | `<id>.png` は一覧に出さない | c0 3.5 の「店に出す絵」。パックの作り手はスタンプの絵と別に 1 枚置く (見本のパックは星の写し) |
| 大きすぎる絵 | 升目に「大」(読めない絵は「?」) の枠を出し、押すと理由 | 一覧から消すと、なぜ出ないかが分からない |
| 表示の大きさ | 32 px に収まる整数倍 (1 倍より小さくしない)、48 は 48 | c0 の案。拡大は Ruby で画素を並べて PNG に書いた表示用の絵で (draw_tile に倍率が無い) |
| 置き場 | `/cache/app/chat/s/` (表示用の絵だけ。送るときは元の絵を読み直す) | `/home` を汚さず、自分の絵と混ざらない。`/cache` はほかのアプリも素材の一時置き場に使っている |
| 貰った絵の消し方 | 消さない (数の上限なし) | 1 枚 100〜300 B。下の Q3 |
| 取れなかった絵 | 部屋を開いている間は取りに行かない | 何度も聞かない。開き直せば 1 回 |
| 呼び出しの順 | 名乗り → 送る (put を含む) → 開いた部屋の最新・続き・さかのぼり → **スタンプを取る** → 部屋の一覧 → まだいるか | 文字が先に出て、絵は後から埋まる |
| 一覧の升の大きさ | タブの中の一番大きい絵の 1 辺 + 6 px | 16x16 だけのパックでも 2 倍の 32 で出るので、普通は 38 px |
| ログ | 絵を新しく読んだ描き直しだけ `chat: talk drawn, N stamp images loaded, M ms` | 種類の多い部屋の重さを後で見られるように |

## 6. 親 (ユーザ) に決めてほしいこと

各問いの先頭が推奨。

- **Q1 貰った絵を自分のスタンプとして使えるようにするか** (指示書 1 章 4。入れていない):
  (a) 入れない (推奨。描いた人の絵が知らないうちに広がらない。使いたい絵はパックで配る) /
  (b) 一覧に「もらった絵」のタブを足す (`/cache/app/chat/s/` の絵。ただし今は拡大した表示用の絵なので、元の大きさで送り直すには
  元の PNG も貯める形にする) / (c) 長押し・右クリックで「自分の絵に入れる」(`/home/stamps/` に写す。描いた人の許可は取れない)。
- **Q2 見本のパックをどこに残すか** (指示書 2 章): (a) family-mruby-apps に出す形の一式 (`apps/<id>/` に `.app.toml`・絵・店の絵) を、
  公開の前に置く非公開の場所 (例 `private-notes/` か asterism-chat の `examples/`) に置き、公開はユーザの許可の後
  (推奨。今のスクラッチの試験の絵は図形だけで見本としては弱い。見本の絵を誰が描くかは plan 6 章 1c のまま) /
  (b) family-mruby-apps の一覧の道具の直し (c0 Q7) と一緒に出す / (c) 当面は作らない。
- **Q3 貰った絵の貯め方**: (a) 消さない (推奨。1 枚 100〜300 B、ホストの上限 2,000 枚でも 600 KB 以下) /
  (b) 数の上限 (例 200 枚) を超えたら古いものから消す (アプリを開くときに数える分の時間がかかる)。
- **Q4 送った後の一覧**: (a) 閉じる (推奨、今の形) / (b) 開いたまま (続けて何枚も送る使い方)。

## 7. 気づいたこと

- **CRuby の道具 (`tools/rgb332_png.rb`) の PNG と、端末の `encode_png` の PNG はバイトが違う** (同じ絵のハートで 123 B と 121 B)。
  端末は送る前に必ず書き直すので、端末どうしでは同じ絵が同じ sha になる (太陽で確かめた) が、PC の送り手 (`test/sender.rb`) が
  パックのファイルをそのまま送ると、端末から見て別のスタンプになる (一度取りに行く)。困ることはない。
- ブラウザ版の App Store は、`/home/appstore_base.txt` に手元の HTTP の口 (CORS の応答ヘッダつき、スクラッチの小さな Python) を書いて、
  手書きの `registry.tsv` から試験のパックを入れられた (「installed (size checked only)」: ブラウザ版の App Store は mbedTLS が無く
  sha256 を照らさない。前からの作り)。入れた後、チャットの一覧にパックのタブが出て、そこから送れた。sim では試していない
  (コンテナから PC の口へのつなぎ方を足す必要がある)。
- ブラウザ版の関連付け: 束に `/etc/associations.toml` が入り、ファイルマネージャーで `/home/stamps/pc_alpha.png` をダブルクリックすると
  画像ビューワーが開いた (c3b Q2 の直し)。
- 汎用化の計画 (doc/pictures/plan.md) の P4 で、この stamps.rb の「読み直し・拡大した表示用の絵・スプライトの絵の持ち方」は
  共通の部品に移る見込み (3 章の +47 KB の多くはそこで減るはず)。

## 8. 確認していないこと

- ESP32 (P4-Nano・Tab5) とネイティブ版。32 ビットの VM プール、実機での読み直し・拡大・`load_bmp` の時間 (sim では 1 枚 10〜20 ms)。
- 640x360 の画面 (1 画面に 8 種類を超えるスタンプが出る形)。426x240 では 1 画面にスタンプは 3〜4 個までなので、8 枚の持ち方で
  画面の描き直しのたびに読み直すことは起きなかった。
- mTLS のルータと console の役割 (chat の行の `stamp_*` は `room/call` の同じ ACL に載る見込み)。
- 本物の PC の画像ソフトで描いた PNG (試験の α の絵はスクラッチの Ruby で作った)。
