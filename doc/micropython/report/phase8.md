## 入れたもの

### 音符の組み立てを 1 か所にまとめた (この段階で一番大きい変更)

音符メッセージの組み立ては Ruby の gem の中 (picoruby-fmrb-app の
ports/esp32/app.c) にあり、そこから MIDI スケジューラも呼んでいた。
Python から同じものを送るのに選べたのは 3 つ:

1. Python 側にもう一度書く → 同じ書式が 2 か所になる
2. Python から Ruby の gem を参照する → Python が Ruby に依存する
3. **どの言語からも使える場所へ移す**

3 を選び、`main/app/fmrb_app.c` へ移して `fmrb_app.h` で公開した
(`fmrb_app_build_audio_note_msg` / `fmrb_app_send_audio_note`)。
Ruby の binding と MIDI スケジューラと Python の binding が、同じ 1 つの
実装を呼ぶ。移動にあたって型を mruby のもの (`mrb_int`) から `int32_t` に
直しただけで、中身は変えていない。

**この移動が安全だったことは道具で確かめた**: MIDI Bench (Ruby) の
「組み立てたバイト列が MessagePack.pack と一致するか」の判定が
`audio wire matches MessagePack.pack: true (8 cases)` のまま通り、
Ruby 側の `audio note_on/off: 0 objects/200 calls` も変わらなかった。

### Python 側

- `_fmrb.audio_note(on, ch, freq, vol, duty, sweep)` (C 直行、辞書を作らない)。
- 共通層に `FmrbAudio` クラス: `play` / `stop` / `pause` / `resume` /
  `load_fmsq_file` / `play_slot` / `note_on` / `note_off`。
  定数 `MAIN` / `SUB`、`CH_PULSE1` / `CH_PULSE2` / `CH_TRIANGLE` / `CH_NOISE`。
- 検証用アプリ `flash/app/python/pysound.app.py` + toml。
  **(後日) `python.app.py` の Sound ページに畳んだ。**

## 実測

### 音階 (`1` キー、pulse1 に 150ms ずつ)

採った波形を 100ms ごとに自己相関にかけた結果。

| 指示 (Hz) | 262 | 294 | 330 | 349 | 392 | 440 | 494 | 523 |
|---|---|---|---|---|---|---|---|---|
| 実測 (Hz) | 262.0 | 291.1 / 296.6 | 327.5 / 334.5 | 349.3 | 393.0 | 436.7 / 449.1 | 491.2 | 524.0 |

ずれは測り方の分解能 (15,720 Hz の標本で 100ms 窓) と APU 側の周波数刻みに
よるもので、**指示どおりの高さが出ている**と言える。

### 主系と副系

| 状態 | 山の高さ | 実効値 | 鳴っていた窓 |
|---|---|---|---|
| 曲だけ (MAIN) | 12,032 | 4,380 | 79 / 79 |
| 曲 + 効果音 (SUB) | 13,568 | 4,074 | 73 / 80 |
| アプリを閉じた後 | 256 | 256 | **0 / 60** |

効果音を重ねると山が高くなり、曲は途切れない。閉じた後は無音になる。

### 音符の割り当て

`gc.mem_alloc()` を前後で比べて、**note_on / note_off 200 回で 0 バイト**。
辞書を作る道を通していれば 1 回につき数十バイト出ていた。

## 分かったこと

### 1. 音は「メッセージを送るだけ」で本当に足りた

計画どおり、曲の再生も停止も譜面の読み込みも `send_message` 一本で済み、
graphics-audio 側にも音声タスクにも手を入れていない。**phase5 で
メッセージ組み立てを直しておいたおかげ**で、辞書に文字列と整数を混ぜて
送るところは何も詰まらなかった。

### 2. 効果音の期限は実時間で持つしかない

`ticks_ms()` で「この音を止める時刻」を持ち、毎ターン期限の来たものだけを
止める形にした。フレーム数で数えると重い再描画のときに音が伸びる
(この企画で以前に踏んでいる)。Python でも同じ形がそのまま書ける。

### 3. 一度に鳴らせるのは 1 アプリ分ではない

音を出す口はアプリごとではなく機械に 1 つなので、Python アプリが曲を
流したまま Ruby アプリも鳴らせば混ざる。**アプリを閉じたら自分の音を
止める**のは書く側の責任になる (pysound は on_destroy で止めている)。

## やらなかったこと

- マイク入力 (Modern だけの機能で、ゲームに要らない)。
- 外部への MIDI 送出。
- `load_fmsq` (譜面をメッセージに直接詰める形)。1 メッセージ 176 バイトの
  制限に実用的な譜面は入らないので、経路指定の `load_fmsq_file` だけにした。
