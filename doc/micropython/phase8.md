# Phase 8: 音 (内蔵音源)

## 目的

Python アプリから内蔵音源を鳴らせるようにする。BGM (譜面データの再生) と
効果音 (音符の直接指定) の両方。

**仕組みの追加はほとんど要らない**。音は「カーネル宛に音声種別の
メッセージを送る」だけで鳴り、Python には既に `send_message` がある。
このフェーズの主な仕事は、Ruby 版の音声クラスを Python に写すことと、
毎フレーム飛ぶ音符メッセージを**ごみを出さない経路**に載せることである。

## やること

### 1. `FmrbAudio` の Python 版 (prelude)

Ruby 版と同名・同引数で写す。

| メソッド | 内容 |
|---|---|
| `play(path, track=0)` / `stop()` / `pause()` / `resume()` | 曲データの再生制御 |
| `load_fmsq_file(slot, path)` | 描画音声側にあるファイルから譜面をスロットへ読む |
| `play_slot(slot, instance=0)` | スロットの再生。0 = 主系、1 = 副系 |
| `note_on(ch, freq, vol=10, duty=2, sweep=0)` / `note_off(ch)` | 音符を直接鳴らす・止める |

**主系と副系の使い分けを守る**: 長い BGM は主系、短い効果音は副系。
これを守らないと効果音のたびに BGM が止まる。

`load_fmsq`(データを直接埋め込む方) は入れない。1 メッセージ 176 バイトに
実用的な譜面が入らないため、`load_fmsq_file` (経路指定) だけにする。

マイク入力は対象外 (Modern のみの機能であり、ゲームに要らない)。

### 2. 音符を送る速い経路 (C)

音符は数ミリ秒ごとに飛ぶことがあり、**ここで出たごみが音を途切れさせる**。
Ruby 側で、収集のたびにアプリが 100〜205 ミリ秒止まり、それが耳で分かる
という問題を踏んでいる。同じ轍を踏まないよう、Python も最初から専用経路に
する。

- `_fmrb.audio_note(on, ch, freq, vol, duty, sweep)` を追加する。
- 中身は `fmrb_app_send_audio_note()` を呼ぶだけ。メッセージの組み立ては
  C の中で終わり、Python 側では辞書もタプルも作らない。
- **その関数は Ruby の gem の中にあったので、どの言語からも使える場所
  (main/app/fmrb_app.c) へ移した**。Ruby の binding・MIDI スケジューラ・
  Python の binding が同じ 1 つの実装を呼ぶ。
- `FmrbAudio.note_on` / `note_off` はこの関数を直接呼ぶ。辞書を組んで
  送る道は残さない (使い分けの判断を書く側に押し付けないため)。

### 3. 効果音の予約 (アプリ側の書き方)

音符は自分では止まらないので、鳴らした後に消音を予約する必要がある。
Ruby のテトリスが持っている「予約表を実時間で処理する」形をそのまま
Python で書けることを、このフェーズで確かめる。

- 期限の管理は**フレーム数ではなく実時間** (`_fmrb.ticks_ms`) で行う。
  重い再描画のフレームで音が伸びるため。
- 予約は古い順に処理する。1 フレームに複数の期限が来たとき、順序を
  取り違えると「消音してから発音」になり、その音が鳴り続ける。
- 実装は phase9 のゲームに入れる。このフェーズでは動作を確かめる小さな
  アプリで足りる。

### 4. 検証用アプリ

`flash/app/python/pysound.app.py` (仮) を作る。

- 音階を順に鳴らす / 副系で効果音、主系で譜面を同時に鳴らす /
  全部止める、をボタンで選べるだけのもの。
- 譜面は既にある `usr/share/music/korobeiniki.fmsq` を使う。

## 検証方法 (ヘッドレスで数値で確かめる)

音は耳で聞かなくても確かめられる。リポジトリ直下の道具を使う。

- `ruby tools/fmrb_audio_probe.rb --duration 3 --dump out.wav`
  で合成後の波形を取り、山の高さと音のあった区間から「鳴っているか」
  「同時に複数鳴っているか」を判定する。落とした音声ファイルを周波数解析
  すれば音の高さまで測れる。
- 音の善し悪し (聞いた感じ) だけはユーザに確認してもらう。

## やらないこと

- マイク入力。
- 外部への MIDI 送出。Ruby 側には仕組みがあるが、Python から使う理由が
  今は無い。
- 効果音の共通ライブラリ化。まず 1 本のゲームで形にする。

## 確定した事項 (実装で決めた結果)

- 辞書経由の音符送出は**残さない**。note_on / note_off は C 直行だけ。
- `load_fmsq` (譜面をメッセージに直接詰める形) は**入れない**。
  1 メッセージ 176 バイトに実用的な譜面が入らないため、経路指定の
  `load_fmsq_file` だけにした。
- 音符の組み立ては main/app/fmrb_app.c に集約した (言語ごとの写しを作らない)。
- 効果音の期限は `ticks_ms()` の実時間で持つ。フレーム数で数えない。

## 完了条件

1. Python から音階が鳴り、波形の計測で音の高さが期待どおりであることが
   数値で確かめられている。
2. 主系の BGM を鳴らしたまま、副系の効果音が BGM を止めずに鳴る。
3. 音符 1 個の送出でごみが出ない (収集回数が増えないことを `gc` の値で確認)。
4. アプリ終了時に鳴りっぱなしの音が残らない。
