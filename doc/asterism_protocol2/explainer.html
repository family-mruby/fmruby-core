Asterism protocol 2

アプリが網に「流す値」の決まりを作る話です。今の決まり (protocol 1) で何が決まっていて何が決まっていないのか、protocol 2 で何をどう変えるのかを、順に説明します。

決定 (2026-11-13)・実装に着手 設計の正: fmruby-core doc/asterism_protocol2/design.md

まず、Asterism とは

Asterism は、Family mruby の端末 (ESP32 の基板・ブラウザ版・Linux のネイティブ版) や PC の Ruby が、網の上でおたがいのオブジェクトを使い合うための仕組みです。下では Zenoh という通信の仕組みを使っています。

網の上の住所は、ノード (端末) > アプリ > オブジェクト の 3 段です。Zenoh では、これを「キー」と呼ぶ文字列で表します。

決まった頭asterism
ノードfmruby-abc123
アプリmahjong
オブジェクトtable

キーは asterism/fmruby-abc123/mahjong/table のようにつなげて書きます。ルータの許可 (ACL) は、このキーを見て「だれが、どこに書いてよいか」を決めます。

今の決まり (protocol 1) で決まっていること

呼び出し

あるオブジェクトのメソッドを呼ぶ決まりです。キーの最後に「呼んだ相手の名前」を入れます。ルータは呼んだ相手を、キーで確かめます。

asterism/<相手>/<アプリ>/<オブジェクト>/call/<自分>

答えは {"value" => ...} か {"error" => ...} です。

自己紹介・状態・メタ

  • @profile: 端末の自己紹介 (名前・種類)
  • @status: アプリの今の状態
  • meta: オブジェクトが持つメソッドの一覧

console の図や anodes は、これを読んで出しています。

中身はどれも MessagePack の値 1 つです。Zenoh が持っている「形式の印 (encoding)」「添え書き (attachment)」「時刻 (タイムスタンプ)」は、使っていません。

今の決まりで、決まっていないこと

アプリが自分から流す値 (麻雀の卓の状態、お絵かきの線、センサの値、ログなど) は、「asterism/<ノード>/<アプリ>/... の下に MessagePack で置く」としか決まっていません。そのため、次のことが起きます。

  1. 何が流れているか、値が来るまで分からない。 網の上で「このアプリはどんな値を流しているか」を見つける方法がありません。
  2. 値の形が分からない。 受け手 (console の表示、記録、ほかのアプリ) は、届いた中身を見て、それが数なのか、座標なのか、画像なのかを推し量るしかありません。
  3. 抜けや順番が分からない。 通し番号が無いので、記録したときに取りこぼしを数えられません。いつ測った値なのかも分かりません。

protocol 2 の考え方

目的は上の 3 つを解くことです。ただし、端末 (メモリ・通信量が小さい ESP32) の負担は増やしません。そのための原則が 4 つあります。

原則どういうことか
許可で縛るものはキーに置くノード・アプリ・呼んだ相手はキーに置いたまま変えない。ルータの許可はキーしか見られないため。
値の説明は Zenoh の仕組みに載せる形式は encoding、通し番号と時刻は attachment に入れる。中身には値だけを入れる。
値ごとに送るものと、1 回だけ送るものを分ける型・単位・説明は「トピックの宣言」で 1 回だけ。値ごとには、通し番号と (MessagePack 以外のときだけ) 形式。
短くできるものは短く組み込みの型は番号。宣言のキーは 1〜2 文字。説明は省いてよい。

何を変えるか

新トピックを宣言する

アプリは、値を流す前に「この名前で、この型の値を流します」と宣言します。Ruby では次のような形を考えています。

pub = Asterism.publish("imu", type: :vector3, unit: "m/s2")
pub.put([0.1, 0.0, 9.8])

宣言の一覧は、アプリごとに 1 か所で答えます。後から網に来た人も、それを聞けば「何が流れているか」が分かります。

{"imu"            => {"t" => 2, "u" => "m/s2", "d" => "加速度"},
 "board1/strokes" => {"t" => "asterism-games/board.strokes"},
 "camera"         => {"t" => 4, "e" => 17}}
キー意味
t型。組み込みの型は番号、アプリ独自の型は名前空間つきの名前
e形式 (MessagePack 以外のとき。例: 17 は JPEG)
u単位
d説明 (人と道具が読む)
ts送り手の時刻を添えるか

新問い合わせの受付を増やさない

Zenoh では、問い合わせ (get) に答える側が、キーごとに queryable (問い合わせの受付) を立てます。1 つ立てるごとに、ESP32 では少しずつメモリを使います。

今のアプリは、呼び出しとメタに答える asterism/<ノード>/<アプリ>/** と、状態に答える @status の 2 つの queryable を持ちます。@ で始まるキーには ** のようなワイルドカードが掛からないので、@status は別に立てる必要があります。

protocol 2 では、トピックの宣言 (@pubs) と独自の型の定義 (@types) にも答えます。別々に立てると 4 つになりますが、状態・宣言・型の定義に答える queryable を 1 つ (@profile) にまとめ、問い合わせの引数で答えを分けます。名前は端末の自己紹介 asterism/<ノード>/@profile と同じ語で、「アプリの自己紹介」と読めるようにしています。

asterism/<ノード>/<アプリ>/@profile?status
asterism/<ノード>/<アプリ>/@profile?pubs
asterism/<ノード>/<アプリ>/@profile?types

変わったときの知らせ (put) は、今と同じく @status・@pubs・@types の別々のキーに出します。購読する側は、知りたいものだけを購読できます。これで、アプリごとの queryable は今と同じ 2 つのままです。

新組み込みの型 (番号)

番号型値の形
1number数
2vector3[x, y, z]
3pose位置と向き (配列)
4imageJPEG・PNG のバイト列 (形式は e)
5state場面・入/切などの文字列か整数
6logログの行
7text文字列

新値ごとに付けるもの

値そのものは今と同じ MessagePack です。添え書き (attachment) に、短い情報を足します。

キーasterism/…/imu
形式 (encoding)無し = MessagePack
attachment[通し番号] か [通し番号, 時刻]
中身[0.1, 0.0, 9.8]
  • 通し番号: トピックごとに 0 から 1 ずつ増えます。127 までは 1 バイトです。番号が飛べば取りこぼし、0 に戻ればつなぎ直しと分かります。
  • 送り手の時刻: 宣言で頼んだトピックだけ付けます。ふだんは付けず、ルータが付ける時刻で足りるかを先に確かめます。
  • 形式: MessagePack のときは何も付けません (0 バイト)。JPEG を MessagePack に包まず流すときは、Zenoh の決まった番号を付けます。

時刻は 3 つを使い分ける

時刻だれが付けるか使い道
送り手の時刻値を測った端末 (頼んだトピックだけ)同じトピックの中での間隔。グラフの横軸
ルータの時刻ルータ (zenohd) が通るときにいくつもの端末の値の順番
受け取った時刻受け手 (console)記録の時刻

そのまま変えないもの

  • 呼び出し・自己紹介・状態・メタの決まり (自己紹介の protocol の番号だけ 2 にする)
  • キーの形と、ルータの許可の考え方
  • ROS 2 とやりとりする部分 (ROS 2 の決まりのまま)

これで何ができるようになるか

  • console が、流れている値を型に合った形で描けます (座標なら軌跡、画像ならコマ送り、状態なら色の帯)。
  • 記録 (MCAP) に、型・通し番号・時刻がそのまま入ります。後から取りこぼしを数えられます。
  • 新しく網に来たアプリや道具が、「だれが何を流しているか」をすぐに知れます。

決定 (2026-11-13)

2026-11-12 の仮決定を、2026-11-13 に決定としました。この決まりで実装を進めます。
#問い答え
1宣言の一覧の問い合わせに答える queryable状態・宣言・型を 1 つの queryable @profile で答える (queryable の数は今と同じ)
2vector3 などの形配列 [x, y, z]
3アプリ独自の型の定義網で引けるようにする (@types)
4通し番号全部のトピックに付ける
5送り手の時刻の単位ミリ秒
6呼び出しの答えにも番号・時刻を付けるか付けない
7ROS 2 の側ROS 2 (rmw_zenoh) の決まりのまま
8宣言の名前に / を許すか許す (board1/strokes のような階層)
