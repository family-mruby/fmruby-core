# Asterism protocol 2: データの決まり (設計)

> 状態: 計画済 | 更新: 2026-11-13 | protocol 2 の今の設計を、決定 1〜33 を溶かし込んだ形で書く。身元・呼び出し・データの 3 層、接続 1 本がアプリ 1 つ (1 つのプログラムが複数持てる)、アプリの自己紹介 `@profile` (`?status`・`?pubs`・`?types`)、値ごとに送るのは encoding (MessagePack 以外のときだけ) と attachment の通し番号と回の識別子だけ、型はトピックの宣言に 1 回、持ち主の無いデータは共有の置き場 `@shared`。互換性は考えない (2026-10-21 ユーザ: 使っているのは作者だけ、あるべき姿を考える)。実装の段は plan.md、英語の決まりの正は asterism の docs/protocol.md、初心者向けの説明は explainer.html

この文書は**今の設計**を書く。どの問いをいつ決めたかは末尾の「決定の一覧」にあるが、本文はそれを読まなくても分かるように書いてある。
英語の決まり (asterism の `docs/protocol.md`) と食い違う所は、末尾の「文書どうしの食い違い」に挙げる。

## 目的

- アプリが流す値の**形式と型**を、受け手 (console の表示、記録、他のアプリ) が推し量らずに分かるようにする。
- 記録 (MCAP) に**通し番号と時刻**が素直に入り、取りこぼしが数えられるようにする。
- **何が流れているか**を網の上で見つけられるようにする (protocol 1 では値が来るまで分からなかった)。
- 持ち主が 1 つに決まらないデータ (観戦、網の参加者のお知らせ) の置き場を決める。
- 端末 (内蔵 RAM・flash・WiFi) の負担を増やさない: **値ごとに送るものは最小**にし、説明は 1 回だけ送る。

## 原則

1. **ACL で縛るものはキーに置く** (ノード・アプリ・呼んだ相手)。ルータの ACL はキーしか見られないため。
2. **値の説明は Zenoh の仕組みに載せ、中身には値だけを入れる**: 形式は encoding、通し番号・回の識別子・送り手の時刻は attachment。
3. **値ごとに送るものと、1 回だけ宣言するものを分ける**: 型・単位・説明は宣言に 1 回。値ごとには、形式 (MessagePack 以外のときだけ) と通し番号だけ。
4. **短くできるものは短く**: 組み込みの型は番号、宣言の map のキーは 1〜2 文字 (ゲームの状態の `"st"` `"mb"` と同じ流儀)、説明は省略できる。
5. **アプリの境界をきれいに保つ**: 接続 1 本が 1 つの本物のアプリ。アプリの名前空間には持ち主が 1 つのものだけを置き、持ち主の無いデータは共有の置き場に置く。
6. **入れ替えは一斉に**: protocol 1 との送り分けは作らない。ノードの自己紹介の `protocol` は 2。

## 3 つの層

Asterism の網はノード > アプリ > オブジェクトでできている。ノードは機械かプロセス (`fmruby-1a2b3c`・`linux`)、アプリはノードの上で動き
名前を持つ (`demo`)、オブジェクトはアプリが名前を付けて公開するもの (`apu`)。宛先は `<node>/<app>/<object>`。サーバは無く、どのアプリも
自分のオブジェクトへの問い合わせに自分で答える。ふつうは Zenoh のルータ (zenohd) がつなぎ、peer の直結でも同じに動く。

キーは全部 `asterism/` の下に置き、役目で 3 つの層に分かれる。

| 層 | 何を | キー (Zenoh の仕組み) |
|---|---|---|
| 身元 | だれがいるか、何者か | アプリの生存の印 `asterism/<node>/<app>` とオブジェクトの印 `asterism/<node>/<app>/<object>` (liveliness token)。ノードの自己紹介 `asterism/<node>/@profile` (queryable と put)。アプリの自己紹介 `asterism/<node>/<app>/@profile` (queryable) と、変わったときの `@status`・`@pubs` (put) |
| 呼び出し | オブジェクトのメソッドを呼ぶ | `asterism/<node>/<app>/<object>/call/<呼んだ相手>` と `.../meta` への get。アプリの queryable は `asterism/<node>/<app>/**` に 1 つ |
| データ | アプリが自分で流す値 | アプリのトピック `asterism/<node>/<app>/<トピック>`、ノードの共有の置き場 `asterism/<node>/@shared/<名前>`、網全体の共有の置き場 `asterism/@shared/<名前>` (publisher と put) |

- 身元と呼び出しは protocol 1 の形のまま (呼び出しの答えは `{"value"}` か `{"error" => {kind, class, message}}`、呼んだ相手をキーに置く)。
  protocol 2 が変えたのは、アプリの状態の問い合わせ先を `@status` から `@profile?status` にしたことだけ。
- 呼び出し・メタ・自己紹介・状態・宣言の値は MessagePack 1 つで、encoding・attachment・Zenoh のエラーの答え・タイムスタンプを使わない。
  encoding と attachment を使うのはデータの値だけ。**呼び出しの答えには通し番号も時刻も付けない**。
- `@` で始まる区切り (`@profile`・`@status`・`@pubs`・`@shared`) は Zenoh の verbatim の区切りで、`asterism/**` や
  `asterism/<node>/<app>/**` に掛からない。アプリ向けのワイルドカードやオブジェクトの層の見張りに混ざらず、ACL の規則も別に書ける。
  `asterism/` の下のほかの `@` の区切りは、この決まりのために取っておく。
- ノード・アプリ・オブジェクトの名前は Zenoh のキーの区切り 1 つ (空でない、`/` `*` `$` `?` `#` を含まない、`@` で始まらない)。
- ROS 2 の側 (`Asterism::ROS`) はこの決まりの外で、rmw_zenoh の決まりのまま変えない。

## 接続とアプリ

### 接続 1 本がアプリ 1 つ

- アプリは**接続 1 本** (Zenoh のセッション 1 つ) で、アプリのものを全部運ぶ: 生存の印、オブジェクト、アプリの自己紹介、状態、トピック、型、
  購読、ROS 2 のノード。1 つのノードに 2 つのアプリがあれば接続は 2 本で、ノードの ID を共有する。
- **1 つのプログラムが接続を複数持てる** (CRuby と端末の両方)。1 本ずつが 1 つの本物のアプリで、網の上では別のプログラムのアプリと区別が
  付かない (それぞれの印・queryable・キーを持ち、ルータとその ACL を通して呼び合う)。例: ゲームホストの常設のアプリ `games` と、
  ルームのプロセスのアプリ `room01`。
- 同じプログラムの接続どうしで共有するもの:
  - **ノードの自己紹介**: ノードのものなので、どの接続が `asterism/<node>/@profile` に答えても同じ中身になる。接続より前に置ける
    プログラムの既定 `Asterism.profile_defaults(kind:, name:, host:, icon:)` があり、ノードの項目 → プログラムの既定 → 組み込みの既定の順に重なる。
  - **待ち**: 呼び出しを待っている接続は、ほかの接続に来た呼び出しにも答える (一方が他方を呼んで待っても時間切れにならない)。
    入れ子の上限 (4) は全部の接続の待ちを合わせて数える。
  - **重複の確認**: 網の確認の前に、同じプログラムの接続と `node/app` が重なれば断る。
- 片方を閉じても他方は動き続ける。

### 端末での重さ

1 本ごとに、Zenoh のセッション (ルータへの TCP か TLS)、ルータの席 1 つ、呼び出しの queryable (深さ 32)、ノードの自己紹介の queryable、
(状態・トピック・型ができたら) アプリの自己紹介の queryable、生存の印の購読、アプリの印を使う。測った量は 1 本あたり、zenoh-pico に約 9 KB
(ESP-IDF では PSRAM)、TLS ならさらに約 21 KB (機種で PSRAM か内蔵の heap)、VM のプールに約 3 KB、内蔵 RAM に lwIP のソケット 1 つ分。
**端末では普通は 1 本**、2 本目は 2 つ目のアプリのときだけにする (同じアプリの別の用途のためには開かない)。ブラウザ版は、`wss://` の入口が
使い捨ての合言葉で 1 回だけ通す形なら 2 本目が通らないので、1 本に限る。同じプログラムの zenoh-pico のセッションどうしは peer で直結できず、
ルータを通してだけつながる。

### 接続はオブジェクト

- `net = Asterism.connect(node:, app:)` が接続 (`Asterism::Connection`) を返す。公開 (`expose`)・状態 (`status`)・`publish`・`subscribe`・
  `define_type`・`poll`・`on_join` などは**全部その接続のメソッド**で、アプリが使うモジュールの関数は無い。モジュールに残るのは
  `Asterism.connect`・`Asterism.connections`・`Asterism.poll_all`・`Asterism.profile_defaults` と、状態を持たない部品だけ。
- 状態・型・トピックは接続のもの。接続より前には置けず、つなぎ直しは新しい接続を作って置き直す (ノードの自己紹介だけは残る)。
- CRuby で素の Zenoh の包みが要るときは `net.zenoh`、素のセッションは両方で `net.session`。

### Family mruby のアプリ

- `FmrbAsterism::Link` が接続を持ち、`link.conn` でアプリに渡す。つなぐ・つなぎ直す係は Link のまま。
- つながるたびに `link_up(link)` が呼ばれ、アプリは `link.conn` に expose・publish・状態を置き直す。
- 1 つの VM でアプリ名を 2 つ名乗るなら Link を 2 つ作る (上の重さのとおり、普通はしない)。

## アプリの自己紹介 `@profile`

- **ノードの自己紹介** `asterism/<node>/@profile` は protocol 1 のまま (話す protocol (`2`)・何者か・名前・アイコン。queryable と、変わったときの put)。
- **アプリの自己紹介** `asterism/<node>/<app>/@profile` はアプリごとの queryable 1 つ (深さ 4) で、状態・トピックの宣言・独自の型の定義を
  問い合わせのパラメータで答え分ける。名前はノードの自己紹介と同じ語にし、「アプリの自己紹介」と読ませる。queryable はアプリが
  状態・トピック・型のどれかを初めて持ったときに立て、閉じるまで残す (何も持たないアプリは立てなくてよく、端末の RAM を使わない)。

### 問い合わせと答え

- パラメータは `;` で区切り、各部分の `=` の前を名前として読む。数えるのは `status`・`pubs`・`types` だけで、ほかは無視する。
- どれも無い (パラメータなし、ほかの名前だけ) ときは**既定の答え**: 状態と宣言 `{"status" => {...}, "pubs" => {...}}`。
- `?status`・`?pubs`・`?types` は、その部分だけを同じ形 (`{"types" => {...}}` など) で返す。2 つ書けば 2 つ返す。型は既定の答えに入らない。
- 持っていない部分は**省く** (nil や空の map にしない)。状態の無いアプリは `?status` に `{}` を返す。答えが無いのは「伝えることが無い」で、誤りではない。

```
get    asterism/games/games/@profile
reply  {"status" => {"mahjong1" => {"st" => "play", "members" => 4}},
        "pubs"   => {"mahjong1/state" => {"t" => "asterism-games/table.state"}}}
get    asterism/games/games/@profile?types
reply  {"types" => {"asterism-games/table.state" => {"f" => [["st", "str"], ["members", "int"]]}}}
```

### 変わったときの put

- 状態は `asterism/<node>/<app>/@status` に、接続のとき (状態があれば)・変わったとき・失った接続が戻ったときに put する。同じ状態を置き直しても put しない。
  `@status` への問い合わせには誰も答えない (状態は `@profile?status` で聞く)。
- 宣言は `asterism/<node>/<app>/@pubs` に、変わったとき (宣言・取り下げ) と、失った接続が戻ったときに map 全体を put する。
- 購読する側は知りたいものだけ (`asterism/*/*/@status`・`asterism/*/*/@pubs`) を購読し、`<node>/<app>` ごとに最後の put を持つ。
  新しく現れたアプリには `@profile` に 1 回だけ聞く (put は変わったときしか来ないため)。

### 状態

文字列のキーの map で、値は protocol の値、map の下 4 段まで、MessagePack で 1024 バイトまで。送り手は破るものを送る前に断る。中身は
アプリのもので、読み手は表示するだけ。数と状態を入れ、秘密 (メンバーの名前・ノードの ID・トークン) は入れない。

### 読み手の掃除と忘れ方

- 読み手は受け取ったものを掃除する (map でない答えは何も無い、1024 バイトを超える状態は無し、宣言と型はそれぞれの検査)。
- 消す put は無い。**アプリの生存の印が leave したら、読み手はそのアプリの状態・宣言・型・通し番号の記憶を全部捨てる** (次の「データの値」も参照)。

## データの値

アプリが自分のキーに流す値 (センサの値、卓の状態、カメラのコマ、お絵かきの線、ログ) は**トピック**として 1 回宣言し、値を 1 つずつ put する。

### 値ごとに送るもの

| 何を | どこに | 大きさ |
|---|---|---|
| 形式が MessagePack | **encoding を付けない**。「Asterism のデータで encoding が無ければ MessagePack」 | 0 バイト |
| 形式が MessagePack 以外 | Zenoh の決まった番号の encoding (`text/plain` 4、`application/cdr` 7、`image/png` 16、`image/jpeg` 17 など、Zenoh 1.x の 0〜52) | 1〜2 バイト |
| 型 | 値には載せない。トピックの宣言に 1 回 | 0 バイト |
| 通し番号と回の識別子 | attachment。**全部のトピックに付ける** | 配列の頭と通し番号で 2〜6 バイト、回の識別子 (16 ビット) で 1〜3 バイト |
| 送り手の時刻 | 宣言で `ts` を立てたトピックだけ attachment に足す | +9 バイト |
| 送り手 | 共有の置き場の値だけ attachment に足す | 送り手の文字列の分 |

- payload は MessagePack の値ちょうど 1 つ。encoding を宣言したトピックはその形式のバイト列そのもの (JPEG は MessagePack の bin に包まず、
  `image/jpeg` を付けて生で流す)。どの形式にも当たらないバイト列は MessagePack の bin で流す。
- MessagePack には Zenoh の決まった番号が無く、`application/msgpack` を文字列で付けると値ごとに 20〜30 バイト太るので付けない。
  独自の番号を名乗る案は Zenoh の道具で「不明」に見えるので採らない。送り手は `zenoh/bytes` をほかの意味で付けてはいけない。
- encoding の後ろの schema (`text/plain;charset=utf-8`) は値ごとに Zenoh が送るままで、宣言の `e` (番号) には入らない。
- トピックは Zenoh の **publisher** として宣言し、値はそこに put する。Zenoh はキーを番号に置き換えて送る。端末 (zenoh-pico) では素の put より
  値ごとのキーの分が軽くなる (実測で素の put 45 B → publisher 23 B、端末の 1 値は `[seq]` の attachment 込みで約 25 B の見積もり。回の識別子の分は測っていない)。CRuby (zenoh-c) は
  素の put でもキーを丸ごとは送らないので軽くならない。

### attachment の形

MessagePack の配列で、3 つの形がある。

| 形 | いつ |
|---|---|
| `[seq, id]` | アプリのトピックで、時刻を付けないとき |
| `[seq, id, ms]` | アプリのトピックで、宣言に `ts` があるとき |
| `[seq, id, ms または nil, "<node>/<app>"]` | 共有の置き場の値は**いつも 4 要素**。`ms` は `ts` のときだけ、それ以外は MessagePack の nil |

- `seq`: 整数。トピックの通し番号。0 から 1 ずつ増え、`2^31 - 1` の次は 0 に戻る (どの端末の整数でも扱える)。
- `id`: 整数。**回の識別子**。接続を開くたびに 16 ビットの乱数を決め、その接続の全部の値に載せる。送り手の再起動・つなぎ直しを
  番号の並びに頼らずに見分けるため。
- `ms`: 整数。送り手の時刻、1970-01-01 UTC からの**ミリ秒**。
- 送り手: 文字列 `"<node>/<app>"`。アプリの下のキーでは読み手は 3 つ目を読まない (キーが送り手を言う)。
- 読み手はこの後ろの要素を無視する (後で足せるように)。attachment が無い、または 0〜`2^31 - 1` の整数で始まる配列でない値は通し番号なし、
  整数でない時刻は時刻なし。

### 通し番号の数え方

- **番号は接続ごと**: 送り手はトピックごとに番号を持ち、接続を開いたら 0 から始める。**同じ接続で宣言し直しても 0 に戻さない**
  (前の番号を引き継ぐ)。新しい接続 (つなぎ直し・再起動) は 0 から。
- 共有の置き場では**キーと送り手の組ごと**に数える (送り手がそれぞれ 0 から番号を振る)。送り手が無い・`"node/app"` の形でない値はキーだけで数える。
- 読み手は最後の `id` と番号を覚える。**`id` が変わったら新しい回**として読む (`restarted?` true、`lost` は数えない)。
- `id` が同じときは、次を前への距離 `d = (seq - last) mod 2^31` で読む:
  - `0 < d < 2^30`: 前進。`d - 1` 個が**欠けた** (`lost`)。`2^31 - 1` から 0 は距離 1 で折り返し (前進、欠けなし)。
  - それ以外 (戻った、同じ、範囲の半分以上跳んだ): 送り手が**つなぎ直した** (`restarted?`)。`lost` はその回の番号 (新しい回で受け取れなかった数)。
  - 最初の値: `lost` 0 (遅れて購読した読み手は前の分を数えない)。publisher が購読者を知る前の最初の数個を Zenoh が送らないこともある。
- **アプリの生存の印の leave で、読み手はそのアプリの番号の記憶を捨てる** (共有の置き場では、送り手がそのアプリのもの)。次の値は最初の値として
  `lost` 0。これは記憶の掃除 (長く購読しても記憶が増え続けない) で、回の見分けは `id` が受け持つ。番号だけで見分けると、再起動の直後に前より
  大きい番号を最初に受けて「前進」と読み違え、読み手が leave を見る前に送り手が戻った場合は leave でも防げないため、`id` を足した。
- encoding が無いのに MessagePack 1 つとして解けない値は、ブロックに渡さず数える (`malformed`)。

### 受け手の Ruby の API

```ruby
net.subscribe("<node>/<app>/<topic>", depth: nil) do |v, info|
  v            # MessagePack は解いた後の値、encoding があれば String (バイト列)
  info.seq     # 通し番号 (無ければ nil)
  info.lost    # 前の値からの欠け
  info.restarted?
end
```

- `v` と `info` (`Asterism::SampleInfo`) の 2 つを渡す。`|v|` だけでも書ける。
- `info` の項目: `key`・`node`・`app`・`name`・`path` (`asterism/` の下のキー)・`seq`・`time` (送り手の ms、無ければ nil)・`encoding`
  (encoding が無い値は `"msgpack"`、MCAP の message_encoding と同じ語。部品は `"zenoh/bytes"` を返し、Asterism が読み替える)・`timestamp`
  (ルータの、無ければ nil)・`lost`・`restarted?`・`from` (送り手 `"<node>/<app>"`)・`shared` (nil・`:node`・`:global`)。
  共有の値の `node`・`app` は送り手のもの。
- 購読 (`Asterism::Subscription`) は `received`・`malformed`・`dropped` を数える。`depth:` は部品の購読の深さ (省略で 16)。
- ブロックは `net.poll` (全部の接続なら `Asterism.poll_all`) の中からだけ呼ばれ、待っている呼び出しの中では呼ばれない。
- アプリは自分が流した値を自分の購読で受け取らない (当てにしない)。同じプログラムのほかの接続は別のアプリなので受け取る。

## トピックの宣言

### 宣言する

```ruby
pub = net.publish("board1/strokes", type: "asterism-games/board.strokes")
pub.put(value)
imu = net.publish("imu", type: :vector3, unit: "m/s2", desc: "加速度", ts: true)
cam = net.publish("camera", type: :image, encoding: "image/jpeg")
```

- `net.publish(name, type:, unit:, desc:, ts:, encoding:, shared:)` が `Asterism::Topic` を返す。取り下げは `topic.close` か
  `net.unpublish(topic か名前)`、一覧は `net.published`。同じ名前でもう一度宣言すると置き換え (`@pubs` の並びは保ち、同じ宣言なら put しない)。
- 値のキーは `asterism/<node>/<app>/<名前>`。名前には `/` を許し (`board1/strokes`)、各区切りは名前の決まりに従う (`@` で始まらない)。
  オブジェクトの名前と最初の区切りが同じでもよい (印・呼び出しと put は出会わない) が、`x/meta`・`x/call/y` のような呼び出しの形は避ける。
- トピックは使い回す (毎回 `publish` しない。publisher 1 つで端末の PSRAM 約 0.7 KB)。

### 宣言の map

宣言は「項目名 => 宣言」の MessagePack の map で、各宣言は短いキーの map:

```
{"board1/strokes"         => {"t" => "asterism-games/board.strokes"},
 "imu"                    => {"t" => 2, "u" => "m/s2", "d" => "加速度", "ts" => true},
 "camera"                 => {"t" => 4, "e" => 17},
 "host/@shared/spectate/t1/state" => {"t" => "asterism-games/table"},
 "@shared/lobby"          => {"t" => 7}}
```

| キー | 意味 | 省略 |
|---|---|---|
| `t` | 型。組み込みは**番号**、アプリ独自は名前空間つきの文字列 | 型なし (読み手は値から推し量る) |
| `e` | encoding の番号 (MessagePack 以外のとき) | MessagePack |
| `u` | 単位 (64 バイトまで) | 単位なし |
| `d` | 説明 (人と道具が読む、2048 バイトまで) | 説明なし |
| `ts` | `true` なら値ごとに送り手の時刻を attachment に付ける | 付けない |

**項目名 (map のキー) の 3 つの形**:

| 形 | 値のキー |
|---|---|
| `<名前>` (`imu`、`board1/strokes`) | 自分のアプリのトピック `asterism/<node>/<app>/<名前>` |
| `<node>/@shared/<名前>` | ノードの共有の置き場 `asterism/<node>/@shared/<名前>` (`<node>` は宣言したアプリ自身のノード) |
| `@shared/<名前>` | 網全体の共有の置き場 `asterism/@shared/<名前>` |

共有の形は `asterism/` の下のキーそのものなので、読み手は `asterism/` を前に付ければ値のキーになる。トピックの名前の区切りは `@` で始まれないので、
取り違えは起きない。読み手はこの 3 つの形 (ノードの形では宣言したアプリのノードのもの) の項目だけを残し、各宣言では形の合うキーだけを残す。

### どこで伝えるか

- アプリの自己紹介の `pubs` (`asterism/<node>/<app>/@profile?pubs`) で答え、変わったら `@pubs` に put する (前の章)。最後のトピックを取り下げたら空の map を put する。
- **生存の印はトピックごとに立てない** (端末の資源を使うため)。トピックはアプリの生存の印と同じだけ生きる。宣言を知りたい人は
  `asterism/*/*/@pubs` を購読する。
- 読み手の道具: `net.pubs_of(node, app)` (宣言、答えが無ければ nil、部分が無ければ `{}`)、`net.types_of(node, app)`。

## 型

### 組み込みの型

宣言の `t` で番号で言う。値は下の形の MessagePack (数が並ぶものは**配列**)。

| 番号 | 名前 | 値 |
|---|---|---|
| 1 | number | 整数か浮動小数 |
| 2 | vector3 | `[x, y, z]` |
| 3 | pose | 平らな 7 要素 `[x, y, z, qx, qy, qz, qw]` (位置、続いて向きの四元数。ROS 2 の Pose と同じ順) |
| 4 | image | 画像のバイト列。形式はトピックの encoding (`image/jpeg`・`image/png` など) |
| 5 | state | 文字列か整数 (場面・モード・入/切) |
| 6 | log | map: `level` (`"debug"`〜`"fatal"`、または ROS 2 と同じ 10〜50)、`msg` (文字列)、`time` (**1970 年からの ms の整数**)。省略可: `name`・`file`・`line`・`function` |
| 7 | text | 文字列 |

番号は足すだけで変えない。知らない番号は型なしとして読む。

### アプリ独自の型

- 名前は定めた者の名前空間つきの文字列 (`asterism-games/board.strokes`)。定義は `net.define_type(name, fields, desc: nil)` で置き、
  アプリの自己紹介の `types` (`asterism/<node>/<app>/@profile?types`) で**網で引ける**。ROS 2 の `.msg` にあたる。型は接続のもの。
- 定義の形: 型の名前ごとに `{"f" => [[フィールド名, 型], ...], "d" => 説明}` (`d` は省略可)。

```
{"asterism-games/board.strokes" => {"f" => [["pts", "int[]"], ["color", "str"], ["at", "vector3"]],
                                    "d" => "1 枚の板の線"}}
```

- **フィールドの型は名前だけで書く** (番号は受け付けない):
  - 組み込みの型の名前: `number`・`vector3`・`pose`・`image`・`state`・`log`・`text`
  - 基本の型: `int`・`float`・`str`・`bin`・`bool`・`any` (`any` は形を決めない値。`[名前, 席, 印]` のような混ざった組など)
  - ほかの独自の型の名前
  - どれも末尾の `[]` で配列 (`vector3[]`・`int[]`・`asterism-games/point[]`)。重ねられる (`int[][]` は整数の配列の配列、`any[]`)。`[]` だけは型ではない。
- 宣言の `t` は今どおり番号 (組み込みのとき)。組み込みの型と基本の型の名前は、独自の型の名前に使えない。
- 独自の型の値は、フィールド名を文字列のキーにした **map**。値ごとの大きさは、フィールド名を 1〜2 文字にする作法で抑える
  (フィールド名なしで並べる配列の形は入れない)。
- **型は送り手のもの**: 型の名前は、そのトピックを宣言したアプリの定義の意味を持つ。共有の置き場では同じキーの送り手が同じ型の名前を
  違う定義にしてもよく、読み手は**値の送り手 (`info.from`) の宣言と型で読む** (`net.type_of(info)`・`net.declaration_of(info)`)。
- 受け付ける長さ: 型の名前・フィールド名 128 バイトまで、フィールド 64 個まで。読み手は名前が空でない文字列で、`f` が `[文字列, 空でない文字列]`
  の配列の定義だけを残す。

## 共有の置き場 `@shared`

### なぜ

アプリの名前空間 (`asterism/<node>/<app>/...`) は持ち主が 1 つ (オブジェクト・呼び出し・`@profile`・`@status`・`@pubs`・そのアプリだけの値)。
持ち主が 1 つに決まらないデータ (ノードが観戦者に見せる卓の様子は、どのプログラムが卓を回していても同じ場所に出したい。網の参加者の
お知らせ) をどれかのアプリの下に置くと、キーがたまたま送るプログラムに縛られる。そこで**データだけの置き場**を別に持つ。Zenoh・ROS 2 と
同じく「キーは共有の名前、宣言は送り手ごと」で、置き場は生存の印・オブジェクト・queryable・`@profile` を持たない。

### 2 つの置き場

| 置き場 | キー | 書くのは | 送り手の宣言の項目名 |
|---|---|---|---|
| ノードごと | `asterism/<node>/@shared/<名前>` | そのノードのアプリ | `<node>/@shared/<名前>` |
| 網全体 | `asterism/@shared/<名前>` | 網のロールが許したアプリ | `@shared/<名前>` |

- `<名前>` はトピックの名前と同じく `/` で区切った名前。アプリは自分のノードの置き場と網全体の置き場にだけ書く。
- 使い分けの目安:
  - **ノードごと**: そのノードが出すものの写し。卓が観戦者に見せるもの (`asterism/<node>/@shared/spectate/<卓>/...`)、そのノードの複数の
    プログラムが一緒に出す様子。読み手は 1 つのノード (`asterism/<node>/@shared/**`) か全部 (`asterism/*/@shared/**`) を購読する。
  - **網全体**: 網の取り決めの場。網の参加者が信頼できる前提での、データのやり取りと網の状態のお知らせ。Asterism の網は信頼できるメンバーだけの
    もので、ルータに届くだれにでも開いたものではない。
- `@shared` は verbatim なので `asterism/**` や `asterism/<node>/**` に掛からない。購読する側は `*/@shared/**` と `@shared/**` を別に書く。

### 書き方と読み方

```ruby
t = net.publish("spectate/t1/state", shared: :node, type: "asterism-games/table")  # asterism/<node>/@shared/spectate/t1/state
g = net.publish("lobby", shared: :global, type: :text)                             # asterism/@shared/lobby
t.put(state)                                   # attachment [seq, id, nil, "<node>/<app>"]

net.subscribe("*/@shared/spectate/**") do |v, info|
  info.from     # => "host/room01" (送り手)
  info.lost     # この送り手のこのキーの欠け
end
net.publishers_of("host/@shared/spectate/t1/state")  # => {"host/games" => {...}, "host/room01" => {...}}
net.type_of(info)                                    # 送り手の型: 番号か [名前, 送り手の定義]
```

- `shared:` は nil (既定、自分のアプリの下)・`:node`・`:global`。宣言は**送り手自身のアプリの `@pubs`** に完全な項目名で入り、型もそのアプリの定義。
  取り下げは `net.unpublish(topic)` か `net.unpublish(name, shared: :node)`。
- 値は普通のトピックの値と同じ (payload・encoding・publisher) で、attachment だけ送り手つきの 4 要素 (上の「attachment の形」)。
  送り手がキーに無いので attachment で言う。
- **同じキーに複数の送り手がいてよい**。それぞれ自分の宣言 (型・単位・encoding・`ts`) を持つ。キーの中身はそろえるのが望ましいが、そろわなくても
  読み手は送り手ごとに正しく読める。網の上で混ぜるものは無く、キーの最新の値は最後に put された値 (どの送り手でも)。
- 読み手は欠けを送り手ごとに数え、型を送り手から読む。だれが宣言しているかは `net.publishers_of(path)` (そのノードの、または `*` で全部の
  アプリの `@profile?pubs` に聞く)。
- 送り手は attachment で名乗るが、読み手はそこでは確かめられない。ノードの置き場ではルータの規則がキーとノードを結び付け、網全体の置き場では
  書けるロールを信頼する。

### 観戦 (ゲームホスト)

観戦の値は全部ノードの置き場 `asterism/<node>/@shared/spectate/<卓>/...` に置く。常設のホストは自分のアプリ (`games`) で宣言し、ルームの
プロセスも Asterism のアプリ (`room01` など) としてつないで宣言する。観戦する側 (実況・ブラウザ版) は `<ホストのノード>/@shared/spectate/<卓>/**`
か `*/@shared/spectate/**` を購読し、`info.from` で送り手 (ホストかルームか) を知る。ルームの出入りで送り手が変わっても、それぞれ別の番号の列として読める。

## 時刻

**時刻は全部、1970 年からの ms の整数**にそろえる (attachment の送り手の時刻、組み込みの log 型の `time`、決まりの文書の慣習)。長さは名前が言う単位
(`timeout_ms`・`period_s`)。ROS 層の `stamp_ns` は rmw_zenoh の側なので変えない。

3 つの時刻を使い分ける。

| 時刻 | どこから | 意味 | 使い道 |
|---|---|---|---|
| 送り手の時刻 | attachment (宣言で `ts` を立てたトピックだけ) | 値が測られた (送られた) 時刻、送り手の時計 | 同じトピックの中の間隔、グラフの横軸 |
| ルータのタイムスタンプ | zenohd が付ける (ルータは既定で timestamping が有効) | ルータを通った時刻 (HLC) | 複数のノードの値の順番 |
| 受け取った時刻 | 受け手 | 記録の時刻 | MCAP の log_time |

端末の時計は合っていないことがある (合っていないと 1970 年近くの値になる)。送り手の時刻は「同じトピックの中の間隔」として正しく、ルータの時刻は
「全体の順番」として正しい。普段は `ts` を付けず、ルータの時刻で足りるかを先に確かめる。peer の直結の値と、問い合わせの答えにはルータの時刻が付かない。

## 今の値

決まりは足さない。遅れて購読した読み手と、欠けに気づいた読み手は、次の値が来るまで今の値を持たない。**今の値が要るトピックは、アプリが
オブジェクトの呼び出しで答え**、読み手は最初と、`info.lost > 0` か `info.restarted?` のときに呼び出しで取り直す (ゲームの卓の状態・観戦の読み手)。
背景: 端末の購読の輪は深さ 16 で古い順に捨てる。欠けは数えられるが、取り戻す手段は値の流れの側には無い。

## 記録 (MCAP)

| MCAP | protocol 2 |
|---|---|
| channel の topic | キー |
| channel | アプリのキーはキーごとに 1 つ。**共有の置き場のキーは「キー + 送り手」ごとに 1 つ** (topic は同じキー、metadata の `asterism_from` に送り手、`asterism_declaration` にその送り手の宣言)。送り手の無い値はキーだけのチャンネル (型なし) |
| channel の message_encoding | encoding (無ければ `msgpack`) |
| schema | 宣言の `t` と独自の型の定義 (共有のキーでは送り手の宣言と型。同じ型の名前でも送り手ごとに別の schema になりうる) |
| message の sequence | attachment の通し番号 (取りこぼし・つなぎ直しが分かる。共有のキーでは送り手ごと) |
| message の publish_time | 送り手の時刻、無ければルータのタイムスタンプ |
| message の log_time | 受け取った時刻 |

- 共有の置き場は verbatim なので、`asterism/**` を記録するときは `asterism/*/@shared/**` と `asterism/@shared/**` も購読する。
- 再生は共有のキーのチャンネルを送り手つきの attachment で置き直す。
- 形に合わせた表示は `t` で描き方を選ぶ (2 は軌跡、4 はコマ送り、5 は色の帯、独自の型はその描き手)。

## 部品の対応

| | CRuby (asterism-zenoh、zenoh-c 1.10.1) | 端末・ブラウザ版 (picoruby-asterism-zenoh、zenoh-pico 1.10.1) |
|---|---|---|
| encoding を付ける・読む | `session.put(..., encoding:)`、受け取りの `Sample#encoding` | 同じ形の Ruby の API を足した (P1)。zenoh-pico の設定・sdkconfig の変更は要らない |
| attachment | ある | ある |
| publisher の宣言 | `session.publisher(key, encoding:)`、`pub.put`・`pub.close` | 同じ形の Ruby の API を足した (P1) |
| タイムスタンプを読む | `Sample#timestamp` | 足した (P1)。ルータを通った値にだけ付く |

encoding を付けない値を部品は `"zenoh/bytes"` と返し、Asterism の層が `"msgpack"` に読み替える。

## ACL とロールの要点

### 決まりとしての規則

- ACL で縛るものはキーにある。`@` の区切りは `asterism/**` 向けの規則に掛からないので、別に書く。
- アプリの自己紹介: 読み手は `asterism/*/*/@profile` の query と `asterism/*/*/@status`・`asterism/*/*/@pubs` の subscription。書き手 (アプリ) は
  `asterism/<node>/*/@profile` の queryable と reply、`asterism/<node>/*/@status`・`@pubs` の put。
- ノードの共有の置き場: 書き手は自分のノード (`asterism/${node}/@shared/**` の put と publisher の宣言、`${node}` は証明書の名前)。読み手は
  `asterism/*/@shared/**` の subscription。
- 網全体の共有の置き場: **既定ではだれも書けない**。管理者が `asterism/@shared/**` (かその一部、`asterism/@shared/lobby/**`) の put をロールで許す。
  読み手は `asterism/@shared/**` の subscription。

### console の既定

- 既定のロール `match` (メンバー): 自分のノードの `asterism/${node}/*/@profile`・`@status`・`@pubs` を読み書きでき、網全体の置き場 `asterism/@shared/**` を
  **読めるだけ**。観戦者など外向けのロールには網全体の置き場を読みも入れない。
- 文書の例のロール: viewer は両方の置き場を読む。games-host は自分のノードの置き場とルームのアプリ (`room$*`) を読み書きする。spectator は
  `<ノード>/@shared/spectate/**` と、送り手 (`games`・`room$*`) の `@profile`・`@pubs` を読み、`@profile` に聞ける (型を送り手から読むため)。
  ロールの行には Zenoh の `$*` を書ける (`room$*` のため)。
- 新しい console は最初からこの形のロールを作る。今の console は更新の migration で台帳を直す。

### migration は足すだけ

- 管理者の手直しと例を見分けられないので、全部のロールに同じ規則を当て、**行を足すだけ**にする。消すのは置き換えだけ:
  Ask の `<prefix>/*/@status` を `@profile` に置き換える (答えが届くよう Read にも `@profile` を足す)、spectator の古い `spectate` の行を
  `@shared/spectate/**` の行に置き換える。
- もう一度流しても何も変わらない。更新の setup がルータの設定を台帳から書いてルータを再起動するので、別の Apply は要らない。
- 自動の直しは一方通行なので、本番の console を更新する前に台帳の写しを取る。

## まだ決めていないこと

- `@pubs`・`@profile` の答えの全体の大きさの上限: 状態は 1024 バイトだが、宣言は件数に上限が無い。端末・ブラウザ版が受け取れる大きさを
  P3c で測り、その結果を見て上限を決まりに置くかを決める。

## 退けた案

- **アプリの自己紹介の名前を `@app` にする**: 語の重なりで退け、ノードの自己紹介と同じ語 `@profile` にした。
- **宣言の一覧に答える queryable を別に立てる・既存の `**` で答える**: `**` で答えると予約名が要り、`@pubs` 専用の queryable を足すと
  queryable が 1 つ増える。`@profile` 1 つにまとめた。
- **受け手のブロックに値の包み 1 つを渡す** (`{ |s| s.value; s.seq }`): 値と補足の 2 つ (`|v, info|`) にした。値だけ使うときに `|v|` と書ける。
- **1 本の接続で別のアプリ名も名乗る** (観戦の値をホストの接続から `spectate` の名前で流す): アプリの境界が濁るので取り下げ、1 本 = 1 アプリにした。
- **観戦を 2 本目の接続のアプリ `spectate` にする**: 観戦は持ち主の決まらないデータで、ルームのプロセスはその名前で宣言できない。
  ノードの共有の置き場 `@shared/spectate/...` に移し、ホストもルームもそれぞれ自分のアプリとして宣言する。
- **MessagePack を文字列の encoding か独自の番号で言う**: 値ごとに 20〜30 バイト太るか、Zenoh の道具で「不明」に見える。encoding なし = MessagePack にした。
- **共有の置き場の送り手をキーに置く・独自の型の値をフィールド名なしの配列にする**: どちらも採らず、送り手は attachment、値は map のまま。
