# M1・M2: Window のメニューと「送る」

> 状態: 報告 | 更新: 2026-11-11 | 枠つきの Window のタイトルバーの右クリックと、枠なしの Window の右クリック・長押しで、デスクトップの重ね表示に同じメニュー (送る ▸・読み直し・閉じる) を出す。今までの 1 回で効く動き (枠つきの右クリックの読み直し、枠なしの右クリックで閉じる、枠なしの長押しの「閉じますか?」) はやめてメニューの項目にした。receive.toml に送信有効のフラグ `send_enabled` (既定 false) を足し、Shell の `asend on|off` とアプリ「受け取り」で切り替える。どちらかのフラグが有効ならカーネルが転送のアプリを起こし、送信有効の間はそのアプリが網の上の端末の一覧を保つ。「送る ▸」はそれを読むだけで、選ぶと `amove` と同じ `FmrbApp.move` で移し、結果を板で短く出す。ネイティブ版 2 つ (使い捨ての zenohd) と sim の Retro で確かめた

計画は `../plan.md` (決定 2 つ)。前提は doc/frameless_window (W2・W3b・W3c の右クリックと長押し)、doc/asterism_file_transfer (T7 の `enabled`・アプリ「受け取り」・`areceive`)、doc/checkpoint (`amove`・`FmrbApp.move`)。

## 1. 決めた名前 (M2)

| もの | 名前 |
|---|---|
| receive.toml の送信有効のフラグ | `send_enabled` (最上位の鍵、`enabled` の隣。行が無い・`true` 以外は無効。既定の `/etc/asterism/receive.toml` は `send_enabled = false`) |
| Shell | `asend on` / `asend off` (切り替え)、`asend` (引数なし: 今の状態と使い方)。`areceive on|off` と同じ形。ファイルを送る `asend <node> <file>` は引数 2 つなのでぶつからない |
| アプリ「受け取り」 | 2 段目に「送信: 有効 / 無効」(Sending: on / off) のスイッチ。右に「Window のメニューの「送る」」の注記 |
| `FmrbReceiveConf` | `send_enabled?`・`set_send_enabled(on)`。`view` に `"send_enabled"`、`lines` の 2 行目に `sending: on|off` (`areceive`・`asend -l` に出る) |
| カーネル | `sending_enabled?`、共通の読み手 `transfer_conf_on?(key)` と `transfer_conf_path` (`receiving_enabled?` もこれを使う) |

## 2. 作り (M1)

### 2.1 流れ

1. アプリの基底 (mruby `fmrb-app.rb`・Spinel `fmrb_app_base_spinel.rb`)
   - 枠つき: タイトルバー (y < 11、全画面でない) の右ボタンの離しで `request_window_menu(x, y)`。前の `request_reload` 直呼びをやめた。
   - 枠なし: `on_frameless_right_click(ev)` の既定を `request_window_menu(ev[:x], ev[:y])` に (右クリックも長押しも同じ)。前の既定 (右クリック → `on_quit_request`、長押し → `request_close_confirm`) をやめた。
   - `request_window_menu` はカーネルへ APP_CONTROL `{"cmd" => "window_menu", "x", "y", "movable"}`。`movable` は mruby の基底では `@gfx._checkpoint_keep?` (`.app.toml` の `movable = true`、または image から起動したもの。C の `ask_move` と同じ判定の手前)。Spinel のプログラムは image にならないので常に false。
2. カーネル `open_window_menu(pid, data)` (`fmrb_kernel.rb`): Window の一覧から画面の座標を出し、名前 (40 バイトに切る)、読み直せるか (`load_mode == 1` で path がある。前の `reload_confirm` と同じ条件)、`movable`、送信の状態 `send` (0 無効、1 有効だが転送のアプリが網にいない、2 つながっている) と理由 (`@xfer_reason`) を付けてデスクトップへ `"window_menu"`。`send == 2` なら転送のアプリへ `{"cmd" => "peers_to", "pid" => デスクトップ, "for" => アプリ}`。有効なのに転送のアプリが動いていなければ、ここで `start_transfer` する (メニューは「接続中」)。
3. デスクトップ (`system_desktop/window_menu.rb`、新しい mixin `WindowMenuMixin`): 押した点にメニューを描き (画面の端で寄せる)、`notify_overlay_state` でカーネルの重ね表示の矩形 (メニューと一覧の外接矩形) にし、合成の区画を足す。外のクリックはカーネルが (0,0) の離しで知らせるので閉じる。Esc でも閉じる。ほかの重ね表示 (確認の画面など) が出ているときは開かない。

### 2.2 項目

| 項目 | 出る条件 | 動き |
|---|---|---|
| 送る > (Send to >) | `movable` のとき | 押すと右 (入らなければ左、どちらも入らなければメニューの下) に一覧。送信が無効・未接続なら項目を薄くし、一覧に理由を出す |
| 読み直し (Reload) | ファイルから起動したアプリ | デスクトップがカーネルへ `{"cmd" => "window_reload", "target" => pid}`、カーネルは前と同じ「Reload <app>?」の確認 (`reload_confirm` の中身を `ask_reload(pid)` にまとめ、両方から呼ぶ) |
| 閉じる (Close) | いつも | 長押しの問いの「はい」と同じ道: `{"cmd" => "close_confirmed", "close_pid", "close_name"}` → カーネルがアプリへ `quit_request` (`on_quit_request`、既定は閉じる。保存を尋ねるアプリはそこで止められる) |

前と同じ結果になること: 読み直しは同じ問いと同じ再起動 (`Reload: spawned PID 5`)。閉じるは、枠なしの右クリックの前の動き (`on_quit_request`) と同じ。枠つきの閉じるボタン (`stop` を直接) は変えていない。

### 2.3 上書きの口

- 枠なしのアプリは今どおり `on_frameless_right_click(ev)` を上書きすれば右クリックと長押しを自分で受ける。空ならメニューは出ない。メニューも出したいなら `super(ev)` を呼ぶ (`sig/fmrb_app.rbs`・`doc/app-distribution/spec.md` 3.4・skill に書いた)。右クリックは今どおり `on_event` にも届く。
- 枠つきのアプリには上書きの口を足していない (タイトルバーの右クリックは基底の `_frame_event` が受ける。`on_event` には今どおり届く)。要るなら、タイトルバーの右クリック用の hook を同じ形 (既定 `request_window_menu`) で足せる。今はタイトルバーの右クリックを自分で使っているアプリが無いので見送った。
- `request_window_menu(x, y)` は公開の口 (アプリが自分のボタンからメニューを出してもよい)。`request_reload`・`request_close_confirm` は残した (公開の口。基底からは呼ばなくなった)。

## 3. 作り (M2)

### 3.1 フラグと転送のアプリの起動

- カーネルは起動時に `receiving_enabled? || sending_enabled?` なら転送のアプリを起こす。ログは今までの行 `Transfer: receiving is on|off (<file>)` の次に `Transfer: sending is on|off (<file>)`。
- `FmrbReceiveConf.tell_transfer(app, on)` の `on` は「どちらかが有効」の意味にし、呼ぶ側 (`areceive on|off`・`asend on|off`・アプリ「受け取り」) が両方を見て渡す。片方を切ってももう片方が有効なら転送のアプリは残る。
- 転送のアプリ `check_receiving` は 2 つのフラグを読む。最後の 1 つが無効になったら、今までと同じく手が空いてから終わる (理由のログは `receiving is off` か `sending is off`。`regress:transfer:quick` の switch が見る `transfer: receiving is off; the transfer app ends` はそのまま)。受け取りを切っても送信が有効なら `new files are refused (sending keeps the app on the network)` で残る。
- Shell の `amove` と `asend <node> <file>` は今どおり、無効でもその場で転送のアプリを起こして送る。

### 3.2 送り先の一覧 (転送のアプリ)

送信有効でつながっている間、`on_update` で:

- `PEERS_MS` (2 秒) ごとに `Asterism.nodes` (anodes と同じ情報源) を見て一覧を追う。自分を除き、`PEER_MAX` (8) まで。消えた端末は外す。
- 新しい端末には profile を 1 回問う (`Asterism.profile_async`、icon なし、4 秒)。名前 (32 バイト) と host (無ければ kind、12 バイト)。
- 各端末に `PEER_CHECK_MS` (30 秒) ごとに、相手の `transfer/inbox` の `check("checkpoint", {names: [], requires: []})` を投げ、受け取りを許しているかを知る: 1 許す、2 受け取らない (`does not receive`、または誰も答えない = 転送のアプリが無い・時間切れ)、3 この端末からは受けない (一覧に無い)、4 アプリを動かせない。問う前は 0 (選べる)。
- どれも Future で投げっぱなしにし、`@link.update` の poll で進む。転送のアプリの受け取り・送信の仕事を待たせない。
- カーネルの `peers_to` には、その場で `"wm_peers" {for, n, seen, verified}` と `n` 個の `"wm_peer" {for, node, name, host, ok}` をデスクトップへ直接送る (1 通 150 バイトほどに収まるよう切った)。

### 3.3 メニューの「送る ▸」

- 一覧の行: 名前 (node ID)、右に host を薄く。名前が無ければ node ID だけ。ok が 2 以上の行は薄くし、押すと板に理由 (「今は受け取らない (受け取りが無効)」など)。
- 確認済みの名前の印: 行の左の小さな丸。この端末のつながりが tls/ のルータ (転送のアプリの `certified?`) のときに付ける。ルータの ACL が node ID を証明書に縛るので、そこに見える名前は名乗りでなく確かめられたもの、という読み。端末ごとに確かめる手段は無いので、つながり単位の印になる (同じ網なら全部の行に付くか、全部に付かないか)。
- 送信無効 (`send 0`): 「送る」を薄くし、一覧に「Sending is off / (asend on, or Receiving)」(日本語「送信が無効 / (asend on か「受け取り」で)」)。未接続 (`send 1`): 「Asterism に接続中...」と理由。一覧がまだ無い: 「端末を探しています...」。誰もいない: 「(ほかの端末が見えない)」。
- 選ぶとデスクトップが `FmrbApp.move(pid, node)` を呼ぶ (Shell の `amove` と同じ口、答えは `"checkpoint_result"` でデスクトップへ)。板 (メニューバーの下の中央、2 行) に「Sending Avatar to / Beta (wm-b)」、答えで「Avatar moved to / wm-b」か「Avatar not sent: / <理由>」を 5〜8 秒。`FmrbApp.move` がその場で断った理由も同じ板に出す。
- デスクトップの Spinel 版 (CI の全部 Spinel の構成) のために、Spinel の基底に `FmrbApp.move` を足した (`fmrb_spx_app_move`、C は mruby の binding と同じ `fmrb_app_checkpoint_move_from_app`。`FMRB_HAVE_CHECKPOINT` の無い build では理由を返すだけ)。手元の標準構成のデスクトップは mruby。

## 6. 見立てと違った点・仮決め

- Retro では一覧 (幅 110〜200 px) がメニューの左右に入らない。左に寄せるとメニューの「読み直し」「閉じる」を隠したので、左右に入らないときはメニューの下 (下にも入らなければ上) に出すようにした。
- 確認済みの名前の印は、つながり単位 (tls/ のルータか) で付ける読みにした (3.3)。端末ごとの確かめはできない。plan の「確認済みの名前かの印」をこの形で作った。
- 受け取りを許していない相手が分かるのは、相手に転送のアプリがあって `check` に答えたときと、答えが無い (受け取らない) とき。問う前 (最初の 0〜数秒) の行は選べる (選べば `amove` と同じく理由つきで断られる)。
- 「閉じる」は枠つきでも `on_quit_request` (終了の頼み) にした。閉じるボタン (`stop` 直) とは違い、保存を尋ねるアプリは問いを出せる。

## 7. 残り

- ESP32 の実機 (S3・Tab5) では見ていない。送信有効の S3 は転送のアプリの TLS の接続を 1 つ保つ (受け取り有効と同じ費用)。一覧の問い (profile・check) は 2 秒ごとの `Asterism.nodes` と 30 秒ごとの check。
- ブラウザ版では動かしていない (デスクトップと基底の Ruby は同じ)。
- 枠つきのタイトルバーの右クリックの上書きの口 (2.3)。
- keys のデスクトップはメニューを持たない (ポインタが無い構成)。
