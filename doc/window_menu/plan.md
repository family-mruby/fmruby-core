# Window のメニューと「送る」

> 状態: 計画済 | 更新: 2026-11-11 | Window のタイトルバーの右クリック (枠なしの Window は右クリックと長押し) でメニューを出し、「送る ▸」で網の上の端末を選んでアプリを移す (amove と同じ動き)。今の右クリックの動き (枠つきは読み直し、枠なしはすぐ閉じる、枠なしの長押しは閉じますかの問い) はメニューの項目にまとめる

## 目的

- アプリを直観的に別の端末へ移す最初の形 (コマンドの `amove` を知らなくても、どの運べるアプリでも使える)。
- 構想 (ドラッグして端に寄せると送り先の札が出る形など) は非公開のメモにある。その前段として、同じ送り先の一覧を
  メニューで出す。

## 決定 (2026-11-11 ユーザ)

- **右クリックはメニューにする**。右クリック 1 回で読み直す (枠つきのファイルのアプリ) 動きはやめ、「読み直し」は
  メニューの項目にする。枠なしの Window の右クリックで「すぐ閉じる」もやめ、「閉じる」はメニューの項目にする。
- **枠なしの Window の長押しも同じメニューにそろえる** (今の「閉じますか?」の問いはやめ、メニューの「閉じる」に)。
  タッチだけの端末でも送れる。
- **メニューの項目** (アプリの種類で出し分け):
  - 送る ▸ (運べるアプリ = `movable = true` のときだけ。見えている端末を名前・種類・確認済みの名前かの印つきで並べ、
    受け取りを許していない相手は薄く出す)
  - 読み直し (ファイルのアプリのとき)
  - 閉じる
- 選んだら amove と同じ動き (`FmrbApp.move`) で移し、結果を短く出す (移った・断られた理由)。

## 方針

- メニューはデスクトップの重ね表示に出す (確認の画面と同じ層。全画面のアプリには Window のタイトルバーが無いので対象外)。
- 送り先の一覧は待たせない: 網に常につながっている係 (転送のアプリ、または今の Asterism の接続を持つもの) が一覧を
  保ち、メニューを開いたときはそれを読むだけにする。一覧が無い (網につながっていない) ときは「送る」を薄くして理由を出す。
  `anodes` と同じ情報源。
- アプリは `on_frameless_right_click` を上書きしていれば今どおり自分で受け取れる (W2・W3c の口)。枠つきのアプリには
  上書きの口は今無い (足すかは report で見立て)。
- Retro (320x240) でも収まる大きさ。英日。

## 受け入れ条件

- 枠つき・枠なしのどちらでも、右クリック (枠なしは長押しも) でメニューが出て、読み直し・閉じるが今と同じ結果になる。
- 運べるアプリで「送る ▸」から端末を選ぶと、amove と同じに移る。運べないアプリでは「送る」が出ない。
- 網につながっていないときは理由が分かる。ESP32 でメニューを開いて一覧が出るまで待たない (前もって持っている)。
- 画面の基準の変化は、メニューが出る場面だけ (今の場面は変わらない見込み)。内蔵 RAM の増分 0。

## 決定 (2026-11-11 ユーザ、送り先の一覧を持つ係)

- **設定に「受け取り有効」と「送信有効」のフラグを別々に持たせ、どちらかが有効なら転送のサービス (転送のアプリ) を起こす**。
  送信有効の間は、そのサービスが網につながったまま送り先の一覧を持ち、メニューの「送る ▸」はそれを読む。
- 置き場所は receive.toml (今の `enabled` が受け取り有効。送信有効は新しいキー、例 `send_enabled`)。アプリ「受け取り」と
  Shell (`areceive` の隣、例 `asend on|off`) で切り替える。名前は M2 で決めて report に書く。
- 既定は親の仮決めで**送信も無効** (受け取りと同じく、出荷時は網につながらない)。送信が無効のとき、メニューの「送る」は
  薄く出して「送信が無効」と理由を出す。Shell の `amove`・`asend` は今どおり、その場で転送のアプリを起こして送れる。
