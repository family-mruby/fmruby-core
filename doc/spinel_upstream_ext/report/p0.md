## 変化点の要約 (先に読む)

1. **32bit は上流が本気で対応した**。`-m32` の CI レーン (`2d7e8c54`)、
   コンパイラが対象の整数幅を知る (`8350fef0`)、ランタイムの 64bit 前提の
   洗い出し (`6ffca36a`、bigint の境界を含む)、`sp_time.c` の `__int128`
   回避 (`a635431a`)。`lib/` の全 32 ファイルが `-m32` でコンパイルできる。
   フォークの `d9e363e` `1242ad3` は不要、`73a2083` (test32) も落とせる見込み。
   **ただし `53941f6` (FFI 可変長引数の幅) は未修正で、上流の -m32 で SIGSEGV
   を再現した**。上流は該当テストを `# spinel: int64` で 32bit から外している。
2. **ext 機構は変わっていない**。オプション名、生成ヘッダの形、`_try`、
   NUL を含む String、init 2 回、すべて前回と同じ結果。ext TU の外部シンボルは
   48 個 (エントリ 6 + init 2 + ランタイムのフック 40) で、**2 本リンクすると
   40 個が重複する**のも同じ。32bit でも ext のホスト呼び出しが通った。
3. **分類 6 (Ruby 穴埋め) は全部は落とせない**。フォークのテスト 6 本は
   64bit・32bit とも通るが、テストの無いコミットを小さな再現で当てると
   **3 群が上流で再現した**: sprintf の書式に GC ルートが要る呼び出し
   (`8a298cb` `286de9b`。**system_desktop の生成 C が上流ではコンパイルできない**)、
   大域変数・クラス変数への `+=` の右辺が poly (`9474d92`)、
   ivar の型が子だけ広がる件 (`ca0709c`。**editor で再現**、`622750c` の検査が止める)。
4. **組み込み向けに新しい論点が 2 つ増えた**。
   - **slab アロケータ** (`d43371a8`、2026-09-14): GC オブジェクトと文字列を
     mmap で確保した 16GB (32bit は 512MB) の予約領域から切り出す。既定で有効、
     切るのは環境変数 `SPINEL_GC_SLAB=0` だけで、コンパイル時の切替は無い。
     `sp_slab.c` は `sys/mman.h` を無条件に include する。
   - **文字列リテラルの凍結** (`e432b19b`、2026-07-24): リテラルは既定で凍結、
     オプトアウト無し。リテラルは生成 C の中で `static struct {...}` の
     書き換え可能なデータになり、**`.data` が kernel で 100B → 13.4KB、editor で
     796B → 24.6KB に増えた** (x86-64、-O1)。ESP32 では `.data` は内蔵 RAM に載る。
5. ランタイムの大域状態が大きく増えた。`libspinel_rt.a` の data/bss シンボルは
   基点 109 個 → 上流 377 個 (うち外部 50 → 194)。`SP_TLS` の使用は
   142 → 191。**多重インスタンス (`sp_ctx` へ移す対象) の棚卸しは 3 倍強に
   なる**。テキスト衝突の量より、こちらが P2 の本当の費用になる。

### 上流に「複数ランタイム」「差し替え口」は入ったか

入っていない。`sp_runtime_create` やアロケータ・I/O のフックに当たる API は無い
(`grep -rnE 'sp_runtime_(create|new)|alloc_hook|sp_vfs' lib` が 0 件)。

- slab アロケータ (`d43371a8`) とその並列 sweep、ワーカーごとの chunk 所有
  (`1fe20889` ほか)。
- `SP_THREADS` の M:N スケジューラの拡充。`SP_TLS` 付きの宣言が 142 → 191。
  例外スタックなどは今も `static SP_TLS` で、`SP_THREADS` 無しなら普通の
  TU ごとの static。
- `[package] allocator = "jemalloc"` はリンク入力の選択で、差し替え口ではない。

## P1 / P2 の指示書に入れるべきこと

### P1 (上流バイナリでの gem 試作)

- 上流の固定点は `01521b1e` を使う (P2 と揃える)。
- gem は `--ext-entry` で型付きエントリに書き換える前提で指示する。単に
  `--ext-init` に読み替えただけでは、呼ぶたびにトップレベルを走らせる今の
  使い方が成り立たない。raycast は本報告の形でヘッダまで出ることを確認済み。
- **文字列リテラルは凍結される**。gem の Ruby がリテラルを書き換えていないか
  (`buf = ""; buf << ...` の形) を先に grep する。書き換えるなら `+""` か
  `String.new` にする (mruby 側の `:ruby` バックエンドでも同じ意味になる)。
- ext TU は 1 本だけ載せる (40 個の重複は未解決)。ext ヘッダの include guard
  が固定名なので、ホスト側の .c も ext 1 本につき 1 ファイルにする。
- 上流ランタイムを sim (Linux) に載せるとき、slab は Linux では動くので
  そのままでよい。ESP32 に持っていく段 (P2 以降) では slab を切る口が要る。
- `.data` の増加 (凍結リテラル) を gem 単位で `size -A` で記録しておく。
