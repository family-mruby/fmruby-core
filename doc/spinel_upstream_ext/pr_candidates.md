# Spinel 上流への PR 候補台帳

上流 (matz/spinel) へ送る候補を 1 か所に集める台帳。**作業中に見つけた
上流の不具合・移植の穴はここに行を足す**。旧台帳
`doc/spinel_aot/reports/fork_pr_candidates.md` (2026-07〜08) の未処理分は
下に引き継いだ。旧台帳は経緯の記録として残し、以後は更新しない。

## 書き方の決まり

- 1 候補 1 行。ID は `U-連番` (上流不具合)、`P-連番` (移植・組み込み向け)、
  `F-連番` (機能・設計提案)。一度振った ID は変えない。
- **最小再現**は `repro/<ID>.rb` (必要なら `.c` や手順の `.md`) に置く。
  fmrb のコードに依存しない形にする。無い候補は状態を「候補」から進めない。
- **上流での確認**欄には、再現を確かめた上流 commit を書く。上流は変化が
  速いので、PR を準備する直前にもう一度 HEAD で確かめて更新する。
- 状態の流れ: `候補` → `再現済` (上流 HEAD で再現、repro あり) → `PR 準備`
  (修正ブランチあり、`make test` / `make bench` 通過) → `PR #番号` →
  `取り込み済` / `見送り`。上流で直っていたら `上流で解消 (commit)`。
- 提出は**ユーザの判断**。PR・Issue の作成は、明示の指示があるまでしない。
- 上流の作法 (焦点を絞った小さい PR、自己ホスト一致、`make test` /
  `make bench` 通過、`test/` への回帰テスト、既定の出力を変えない) に
  合わない候補は、見込み欄にその理由を書く。
- サブエージェントは台帳を直接編集せず、report の「PR 候補」節に書く。
  親が検収時にここへ移す (同じファイルを同時に書かないため)。
