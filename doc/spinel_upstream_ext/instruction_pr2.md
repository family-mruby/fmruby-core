## T1: pr/U-12 を広げる

- 対象の形:
  - 文の位置 (今の修正): `$g << "ab"`、`@@c.upcase!` など
  - **値の位置 (U-16)**: `x = ($g << "q")`、`puts($g << "x")`、メソッドの戻り値
    として `$g << "x"` を返す、など
  - **定数 (U-18)**: `S = +"a"; S << "d"`、`S.upcase!` (文と値の両方)
- 受け手の種類ごと (大域変数・クラス変数・定数) × 破壊メソッドの群ごと
  (`<<` とその連鎖、引数なしの `!` 系、`gsub!` 系、`replace` 系) に、
  回帰テストで押さえる。既存の `pr/U-12` のテストを広げる形でよい。
- 凍結された定数 (`S = "a".freeze` や凍結リテラル) に対しては FrozenError に
  なること (CRuby と同じ) も確かめる。
- U-17 の形 (`t = $g; $g << "x"; puts t`) は**直さない**。テストにも入れない。
- 修正が大きくなりすぎる (codegen の設計に踏み込む) と分かった形があれば、
  その形だけ外して、理由を report に書く (止まらずに残りを仕上げる)。
- `make test`、`make bench`、既定の出力が変わらない範囲の確認 (PR1 と同じく、
  全コーパスを基点と新しいコンパイラで C に変換して比べ、変わったテストを列挙)。

## T2: pr/P-3 の commit メッセージと PR 本文を書き直す

- コードは変えない。メッセージだけを書き直す (amend)。
- 骨子: 上流は `SP_GC_STACK_MAX` と `SP_DYN_SYMS_MAX` を `#ifndef` にしていて、
  ビルドする側が `-D` で決められる。同じ種類の容量の定数である
  `SP_EXC_STACK_MAX` / `SP_CATCH_STACK_MAX` / `SP_GC_MARK_STACK_MAX` だけが
  無条件で、`-D` を渡すと再定義の警告になる。3 つを同じ形に揃える。
  既定の出力は変わらない (確かめ方も書く)。段数を下げたときに安全に失敗する
  こと (境界検査) は一文で触れてよい。
- 書かないこと: マイコン、RAM の予算、.bss の削減量、fmrb。
- report/pr2.md に、新しい commit メッセージと PR 本文の下書き (英語) を載せる。
