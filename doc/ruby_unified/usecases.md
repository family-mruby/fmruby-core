# Asterism ユースケース集 (オブジェクトモデル視点)

記録: 2026-08-27。zenoh_idea.md 4 章の応用カタログが「通信できると何が
できるか」の目線なのに対し、ここは **「Ruby のオブジェクトとして見えると
何が面白くなるか」**、つまり Asterism ならではの目線で挙げる。

## 1. 家を each する

```ruby
Asterism["/devices/**"]
  .select { |d| d.respond_to?(:temperature) }
  .map(&:temperature).sum / n
```

発見 (liveliness) と introspection が Enumerable に化けると、「家じゅうの
温度の平均」が 1 行になる。`select` の条件に `respond_to?` が出てくること
自体が「オブジェクトの話」である証明になる。発表のつかみ向き。
最小実装で成立する。

## 2. エディタが網の中を補完する

Tab5 のエディタには picoruby-ti (型推論) と RBS の基盤が既にある。
$meta は「メソッド一覧 + 引数 + 型」なので、**接続中の実物から $meta を
引いてエディタが補完候補を出す**ことができる。`robot.` と打つと、いま網に
いる本物のロボットのメソッドが並ぶ — 静的な RBS でなく生きた機器が補完源に
なる開発体験は前例が見当たらない。機体上エディタ + ti という本プロジェクト
固有の資産が効く、一番「らしい」ユースケース。実装は重めだが
「ここにしか作れないもの」として本気度を示す一点になる。

## 3. 隣の機体の部品を借りる

```ruby
retro = Asterism["/machines/retro1"]
retro.apu.play("t120 o4 cdefg")   # 音は隣の機体から鳴る
```

Retro には APU、Tab5 には画面とエディタ、PC には GPU と API 鍵。
**ハードウェアの個性をオブジェクトとして貸し借りする**と、網全体が 1 台の
計算機になる。Plan 9 が「全部ファイル」でやったことを「全部 Ruby
オブジェクト」でやる、という整理は発表の柱になり得る。最小実装で成立する。

## 4. 実世界を RSpec する

```ruby
describe "our house" do
  it { expect(Asterism["/devices/entrance"].door).to be_closed }
  it { expect(Asterism["/robots/a2"].battery).to be > 20 }
end
```

朝の点呼・外出前の戸締まり確認・フリートの健全性チェックが**テスト
スイート**になる。CI が毎朝実世界に対して走り、赤くなったら通知。
「Ruby のテスト文化を物理世界に持ち込む」はネタとして笑えて、実用としても
成立する。

## 5. 時間を持つオブジェクト

```ruby
robot.pose                      # 今 (Zenoh)
robot.at(5.minutes.ago).pose    # 過去 (ストレージ / intdash)
```

`at` が返すのは「過去のその時点の読み取り専用プロキシ」。record & replay が
オブジェクトの意味論に溶けると、「昨日のプレイを再生」「障害発生時点の状態を
後から調べる」が同じ API で書ける。dRuby との差分を一番きれいに示せる拡張。

## 6. 家の中を歩き回る電子ペット

ペットの実体は 1 個の Ruby オブジェクトで、状態を持って機体から機体へ
引っ越す。Retro の画面の右端から歩いて消えると Tab5 の画面に現れ、夜は
PC のブラウザ (zenoh-ts) に移る。**「オブジェクトはどこに存在するのか」と
いう発表の問いを、そのまま目に見える形にしたデモ**。子どもが喜ぶ点で
Family mruby の名前にも合う。準備は重いが記憶に残る。
詳細設計 (V1 の引っ越し手順と V2-V4 の段階計画) は pet_design.md。

## 7. 分散インベントリの対戦・交換ゲーム

各プレイヤーの持ち物はその機体の上のオブジェクトとして存在し、交換は
`rival.offer(item)` というメソッド呼び出し。**アイテムの実体が 1 か所に
しかないので、複製チートが構造的に起きない** — 分散システムの一貫性の話が
遊びながら体感できる。教材としても面白い。

## 8. $meta を MCP に変換して AI に手足を渡す

$meta は「型・メソッド・引数の機械可読な記述」なので、**MCP のツール定義へ
ほぼ機械的に変換できる**。ブリッジを 1 本書けば、網に参加した機器は全部
AI エージェントから呼べる道具になる: 「ロボットを充電ステーションに戻して、
戻ったら教えて」を LLM が `robot.go_to` と `on(:arrived)` で実行する。
doc/ai/ideas.md の構想と合流する。時流への接続として最も刺さりやすい。

## 9. 会場全体をオーケストラにする (RubyKaigi の締め用)

聴衆がスマホのブラウザ (zenoh-ts、ファーム無改修) で参加すると、各ブラウザが
`beep` を持つ Resource として網に現れる。壇上から:

```ruby
audience = Asterism["/kaigi/audience/*"]
audience.each_slice(50).with_index { |grp, i| grp.each { |a| a.tone(scale[i]) } }
```

会場の数百台が和音を鳴らす。「Ruby のオブジェクト空間が会場そのものに
広がった」ことが音で証明される締めの一発。準備は重い (会場 WiFi・同時接続数
の下見が要る)。

## デモの費用対効果 (まとめ)

- **最小実装で成立**: 1 (each)、3 (部品の貸し借り)
- **中規模**: 4 (RSpec)、8 (MCP ブリッジ)、7 (ゲーム)
- **重いが記憶に残る**: 6 (ペット)、9 (会場オーケストラ)
- **重いが独自性最大**: 2 (エディタ補完)。5 (時間軸) はストレージ導入後の
  拡張として位置づける
