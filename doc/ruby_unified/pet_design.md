# 電子ペットの設計 (usecases.md 6 の詳細)

記録: 2026-08-28。状態: 構想 (実装未着手)。

基本方針: 「オブジェクトが移動する」のではなく**「状態が移動して、動かす
権利が移る」**。これなら v1 契約 (Proc 転送なし・分散 GC なし) の範囲で作れる。
同時に、後回しにした契約 (Security / Lifetime) を段階的に回収する
テストベッドとして位置づける (末尾の対応表)。

## V1: 状態の引っ越し

### 基本構造

- ペットは Resource `/pets/<名前>` として網に 1 匹だけ存在する。名前は不変で、
  どの機体にいるかは名前に含めない (「名前は資源を指し、機械を指さない」)。
- **クラス (振る舞いのコード) は全ての居住地に事前配布**する。Retro/Tab5 は
  habitat アプリ (.app.rb)、PC は worker、ブラウザは zenoh-ts のページ。
  移動するのは msgpack の状態スナップショット (名前・空腹度・機嫌・位置・
  世代番号。100 バイト程度) だけ。
- ある瞬間にペットを動かしている宿主は 1 つ。宿主は
  - liveliness token `/pets/<名前>/host` を掲げ、
  - 状態を publish し、
  - `feed` / `pat` 等の queryable を宣言する。
  他の機体からは普通の遠隔オブジェクトに見え、`Asterism["/pets/tama"].feed`
  はどこにいても同じコードで届く (経路は宿主の queryable に自動で向く)。

### 引っ越しの手順

```
[Retro (宿主)]                       [Tab5 (行き先)]
  ペットが画面右端へ歩く
  居住地一覧 (/habitats/* の liveliness) から隣を選ぶ
  -- adopt(state, 世代=n+1, 入場辺=左) -->
                                       クラスから実体を生成、入場アニメ開始
                                       host token を掲げ、queryable 宣言
  <---------------- ACK ----------------
  自分の実体を破棄、token を下ろす
```

- **世代番号が肝**。ACK が落ちて再送しても、宿主が二重になりかけても、
  大きい世代が常に勝つと決めておけば分裂しない。厳密な合意プロトコルは
  不要 (一瞬 2 匹に見えたら片方が消える、で許される題材)。
- `adopt` に「どの辺から入るか・速度」を載せ、右端に消えて左端から現れる。
  切り替わりの数百 ms の空白は「廊下を歩いている」で演出になる。

### 死と復活

- 宿主の電源断で liveliness token が消える。**実家ノード** (PC worker) が
  それを見張り、定期 checkpoint (宿主が数十秒ごとに状態を実家へ put) から
  復活させる。「機体を切るとペットが実家に帰る」挙動になる。
- ネットワーク分断中はペットは自分のいる側で生き続け、反対側からの
  `feed` は Timeout になるだけ。

### 位置づけ

Lifetime 契約 (寿命・移動・切断時の扱い) を、**保証が緩くても許される
デモで最初に踏む**。見た目はお遊びで、中身は契約の先行実装。

## V2: 振る舞いが一緒に旅をする (コード移動)

ペットが自分の振る舞いスクリプト (小さな Ruby ソース) を状態と一緒に
持ち歩き、移動先の sandbox で eval される。mruby-compiler と sandbox は
全ビルドに入っており、fmrb 側の土台は既にある。

- ここで**ペットが個体になる**。性格 = スクリプト。Modern は「作る機械」
  なので、**機体上のエディタで振る舞いを書く = 育てる**が成立する。
  「世話をする」が「コードを書く」に置き換わる教材。
- 強制される契約: **Security の実物化**。署名か発行元の信頼 (LAN 内前提の
  明文化)、スクリプトが触れる API の制限 (ペット用 DSL のハンドルだけ渡す
  capability 方式)、VM プールとスタックの上限。この「他所から来たコードを
  安全に走らせる枠」はフリート配布 (zenoh_idea.md 4.6) に流用できる。
- ブラウザ居住地は **ruby.wasm** にする。同じ Ruby ソースが mruby
  (マイコン)・CRuby (PC)・ruby.wasm (ブラウザ) の 3 処理系を渡り歩く。
  発表の「Ruby のオブジェクトはどこに存在するのか」への最大の答え。

## V3: 群れと生態系 (寿命と発見の契約)

複数のペットが同じ網に住み、同じ画面で出会って相互作用する。

- 挨拶・喧嘩・アイテム交換は**遠隔メソッド呼び出し同士の相互作用**。
  交配 = 2 匹のスクリプトとパラメータの組み合わせで子が生まれる、まで
  行くと遺伝的プログラミングの入り口。
- ヘッドレス子機 (R2P2 + LED) も居住地にする。**ペットがセンサノードに
  遊びに行くと LED で気配だけ見える**。画面の無いノードにも「居る」を
  表現でき、親機+子機構成 (zenoh_idea.md 4.9) のデモになる。
- 強制される契約: **Lifetime と Discovery の本番**。ペットの台帳、
  実家ノードの多重化、宿主が消えた孤児の回収 — 事実上の**分散 GC の
  最初の実装**。「誰のペットがどの機体に入ってよいか」で Security の
  ACL 側も進む。

## V4: 時間と外の世界

- **記録との統合**: ストレージ (Zenoh storage / intdash) に一生を自動記録し、
  `tama.at(3.days.ago)` で過去の姿を呼ぶ (usecases 5 の「時間を持つ
  オブジェクト」のペット版)。アルバム・成長グラフ・先代の再生。
- **帰省 (WAN 越え)**: 外部ルータ経由で遠隔地の機体へ引っ越す。NAT 越えと
  TLS/認証 (ルータ間) がここで本番になる。遠隔地の Ruby 世界が一つに
  なったことを、ペットの移動 1 つで示せる。
- **知能**: 頭脳として PC 側の ai サービス (doc/ai/ideas.md) を呼び、
  性格プロンプトをスクリプトと一緒に持ち歩く。居る機体の TTS で喋る。
  $meta→MCP ブリッジ (usecases 8) と逆向きの合流。

## 段階と契約の対応

| 段 | ペットに起きること | 成熟する契約 |
|---|---|---|
| V1 | 状態が引っ越す | 呼び出し・型・Error/Timeout |
| V2 | 振る舞いも旅をする (eval + ruby.wasm) | Security (署名・sandbox・capability) |
| V3 | 群れ・出会い・孤児の回収 | Lifetime (分散 GC)・Discovery |
| V4 | 記録・帰省・知能 | ストレージ統合・WAN/TLS |

v1 契約で捨てた項目 (Proc 転送、分散 GC) を捨てっぱなしにせず、
**回収する順番と動機がペットの成長物語として決まる**のがこの設計の利点。
