## 1. 道具に足したもの (`tools/ti/gen_site.rb`、`rake ti:site`)

| 項目 | 中身 |
|---|---|
| 載せない一覧 | `tools/ti/site_exclude.yml` (`classes:` の下に `クラス名: 理由`)。`Outer::*` で内側のクラスを全部。理由の無い行は止める。載せないクラスはページ・一覧の行・リンクのどれも作らない。今の中身は `Untyped` 1 つ (型エンジンの「型が分からない値」の呼び名で、アプリが名前で書けるクラスではない。5 章で確認を頼む) |
| 領域に無いファイル | `AREAS` に無い sig のファイルは「Other」(その他) に入れ、標準エラーに警告を出す。今の sig では 0 件 |
| 型の中のクラス名 | シグネチャを HTML のコードの塊 (`<pre class="fmrb-sig">`) で書き、中のクラス名を、ページのあるクラスだけリンクにする。名前は内側から解く (`FmrbUI::Button` の中の `Label` は `FmrbUI::Button::Label`→`FmrbUI::Label`→`Label` の順)。自分自身と、載せないクラスはリンクにしない。メソッド名 (`Kernel#Integer` など) はリンクにしない。href はサイトの `use_directory_urls` を読んで決める (既定は `../<クラス>/`) |
| 長いシグネチャ | 72 桁を超えるものは引数を 1 行に 1 つ (`name(` / `  引数,` / `) -> 戻り値`)。重ねた形 (`\|` の overload) は 1 つずつ行にし、折り返したものがあれば間に空行。1,484 のシグネチャのうち 112 を折り返した |
| 型の別名 | `type image_info = {...}` を「型」(Types) の表にした (前は出ていなかった。シグネチャの `-> image_info` が読めるように) |
| 話題のページとの相互リンク | 対応の表 `GUIDES` (話題のページ → 主なクラス、17 ページ) を道具に持つ。クラスのページの頭 (要約の次) に「使い方は ○○ のページにあります」(内側のクラスは外側のクラスの話題へ)。話題のページの末尾に `<!-- BEGIN class reference links ... -->` と `<!-- END ... -->` の間で「**クラスリファレンス:** …」の 1 行 (一覧の `index` は「すべてのクラス」へ)。印の外は触らない。名前を出すクラスが 0 になれば塊ごと消す |
| ナビゲーションの日本語 | `mkdocs.yml` の ja の `nav_translations` の末尾に、印の行の間で「Class Reference: クラスリファレンス」と領域の名前を足す。サイトが既に訳している名前 (Application・Drawing・Sound・Network・Overview) は書かず、そちらに合わせて `AREAS` の「音」を「音声」にした。訳が食い違えば警告 |
| 足元と断り書き | 各ページの足元に「fmruby-core <ブランチ>@<短いハッシュ> の sig から生成」。一覧 (`index.md`・`index.ja.md`) の頭に `!!! note` の断り書き (文は 5 章、仮) |
| 冪等 | 中身が変わったファイルだけ書く。書いたファイルの一覧を `docs/api/reference/.generated` に持ち、前回あって今回無いものだけ消す (道具が作っていない `docs/api/reference/` のファイルは消さない)。`FileUtils.rm_rf` で丸ごと消すのをやめた。実物で 2 回目は「0 files changed」 |
| クラスの説明の読み方 | sig のクラスのコメントは 3 つの形がある (要約に `<<en>>` / 1 行目は日本語だけで下に両言語 / 全部 1 言語で 1 行目は折り返した文の途中)。コメント全体から言語ごとの文を作り、一覧の「中身」は最初の段落の最初の文にした (前は 1 行目をそのまま出していて、英語の一覧が文の途中で切れていた: `load reads a file and parse a`) |
| 日本語の改行 | sig は F1 の 39 桁で折り返してあり、Markdown は段落の中の改行を空白にするので、日本語の文の途中に空白が出ていた (`呼べる。 メソッド`)。両側が全角の改行だけをつなぐ (コードの塊・リスト・見出し・表の行・ASCII の語の前後はそのまま) |
| 表の名前の列 | 狭い列でコードが語の途中で折れていた (`composite_re` / `gion`、`FmrbReceiveCon` / `f`)。名前の列を `<span class="fmrb-name">` で包み、サイトに CSS 1 つ (`docs/assets/class_reference.css`、`white-space: nowrap`) |

試験: `tools/ti/test_site/run.rb` (`rake ti:site:test`、`rake test` の並びに足した)。小さな sig (`fixture/sig`、領域に
無いファイル 1 つと載せないクラス 1 つを含む) と小さなサイト (`fixture/site`) を一時ディレクトリに作り、ページの形
(要約・長文・見出し・定数と型の表・例・足元)、日本語の改行のつなぎ方、シグネチャのリンク (内側の名前・引数・
載せないクラス・自分自身)・折り返し・overload、継承元のリンク、一覧 (領域・Other・断り書き・最初の文)、
mkdocs.yml (ナビの位置・訳の追加と既存の訳の扱い)、話題のページ (本文がそのまま・1 行・クラスのページから話題へ)、
2 回目で何も変わらないこと、絞った実行で道具の作ったページだけが消え手書きのファイルが残ることを見る。
34 項目すべて通る。`rake regress` も通った (ホスト 35 組・描画 310 件、ti:site:test を含む)。

## 4. sig の書き方が元で読みにくい所 (直す候補。sig は直していない)

1. **クラスのコメントが無い 23 クラス**: `FmrbApp`・`FmrbGfx`・`FmrbAudio`・`FmrbMidi`・`FmrbFile`・`P5`・`Fmrb`・`MIDI`
   と Ruby の基本クラス (`Array`・`Class`・`Enumerable`・`FalseClass`・`Float`・`Hash`・`Integer`・`Kernel`・
   `NilClass`・`Proc`・`Range`・`String`・`Symbol`・`TrueClass`) と `Untyped`。一覧の「中身」が空で、ページの頭に
   説明が無い。アプリが一番使う `FmrbApp`・`FmrbGfx` が空なのが目立つ。
2. **クラスのコメントが日本語だけの 35 クラス** (英語のページにも日本語が出る): Asterism の 15
   (`Asterism`・`Connection`・`Proxy`・`AsyncProxy`・`Future`・`Topic`・`Subscription`・`SampleInfo`・`CurrentCall`・
   `Error`・`RemoteError`・`TimeoutError`・`Disconnected`・`EncodeError`、`FmrbAsterism::Settings`)、音
   (`FmrbMic`・`NsfHeader`・`FmrbMidi::SmfPlayer`・`MmlPlayer`・`ApuTransport`・`MIDI::Device`)、絵
   (`SpriteImage`・`SpriteInstance`・`FmrbHitMask`・`GfxBlock`・`TileSheet`・`TileMap`・`TileRing`・`FmrbVideo`)、
   `File`・`Log`・`FmrbI18n`・`Digest`・`Module`・`Object`。S3 で数えた「英語の無い要約」はメソッドと定数の分で、
   クラスのコメントは数えていなかった。
3. **要約が日本語だけの定数 14**: `FmrbGfx::COLOR_*` 9 (英語のページで「黒 (RGB332)」)、`FmrbConst` 5。
4. **長文が日本語だけの 19 件**: `P5` 9、`GPIO` 2、`Asterism::ROS::*` 5、`FmrbAsterism`・`FmrbHw`・`Hash` 各 1。
5. **要約の無い定数 13**: `FmrbAssoc::RUN`・`EDIT`・`DEFAULT`・`SYS_PATH`・`USR_PATH`・`MAX_EXT_LEN`、
   `FmrbAudio::NSF_*` ほか。表の「中身」が空。

   ホバー (1 行目だけを持つ) では途中で切れて見えているはず。
8. 長文の中の「`{state:, shown:, dropped:}`」のような、コードを `` ` `` で囲まずに書いた所は普通の文として出る。

## 5. 親とユーザが決めること

1. **載せないクラス**。今は `Untyped` だけを入れた (一覧の雛形として。要らなければ行を消して作り直す)。候補と理由:
   - `FmrbMic`: 説明に「マイクの C 側の窓口。アプリはふつう FmrbAudio の mic_* を使う」とある内側の部品。
   - `Asterism::SharedSession`: 「各つながりのセッションに extend される」もので、アプリが名前で触らない。
   - `Object`: 説明が「Object 自身が受け手になる呼び方のための写し」で、型エンジンの都合のクラス。
   - 中身の無い名前空間 `Fmrb`・`MIDI`・`Digest` (メソッド 0)。ナビでは中のクラスの親として並ぶだけ。
   - 決定 10〜16 で「載せる」とした Asterism の細部 (`Pubs`・`Status`・`Sequences`・`Types`) と `FmrbUI::Widget` は
     そのまま載せた。
2. **断り書きの文** (今の仮の文):
   - 日本語: 「開発中の版から作っています — これらのページは、リリースの版ではなく、fmruby-core の開発中のブランチ
     (<ブランチ>@<ハッシュ>) の型定義から作っています。ここにあるメソッドが、お使いのファームウェアには無いことや、
     動きが違うことがあります。各リリースの中身はリリースノートにあります。」
   - 英語: "Made from the development version — These pages are generated from the API signatures on the
     development branch of fmruby-core (<branch>@<hash>), not from a release. A method listed here may be missing
     from, or work differently on, the firmware you have installed; the release notes say what each release contains."
3. **左のナビに全クラスを並べるか**。124 クラスが入るとサイトの全ページが約 45 KB 太り (サイト 31 → 62 MB の
   うちクラスのページ以外の分)、ナビも長い。代わりに「Class Reference」の下は Overview (一覧の表) と領域だけにし、
   クラスは一覧の表から辿る形にもできる (道具の `nav_lines` を変えるだけ)。利用者から見た動きが変わるので
   決めずに残した。
4. **公開の手順で気になる所**:
   - 生成物は今 `sig-s7@ea56c9e9` と名乗っている。`sig-s7` を develop に入れた後、develop で `rake ti:site` を
     流し直してからサイトの `api-reference` を main に入れる。
   - 足元にハッシュがあるので、**作り直すたびに 250 ファイルすべてが変わる** (sig が変わっていなくても)。
     サイトの履歴が太るのを嫌うなら、版は一覧のページだけに出す形にできる。
   - サイトの checkout の `site/` (gitignore) は試作のときに root で作られ、`build.sh` の `mkdocs build` が
     `PermissionError` で止まる。`sudo rm -rf site` が要る (触っていない)。
   - `api-reference` は `main` より後ろの `b39804a` から分かれている。main が進んでいれば取り込み時に確認が要る。
   - plan.md S7 の中身 5 (sig を直したらサイトも作り直す手順を release.md に足す) はまだ。
