## 3. 良くなった・変わらない・悪くなった頼み

### 良くなった

- **01 (キー)**: 前は scancode を数のまま (`when 79`・`80`・`82`・`81`)、後は `FmrbConst::KEY_LEFT` などの名前。どちらも
  数は合っている (HID の 79〜82) が、後は読める。`FmrbConst` は後の sig で足した (`sig/fmrb_const.rbs`)。04・07・08 の後も
  `FmrbConst::KEY_*` を使い、前の 03・04 は数のまま (`44`・`22`・`82`・`81`)。
- **08 (JSON)**: 前は束に `JSON` が無く、1 往復調べて `::JSON.parse` を見つけたが、**書く側は文字列を手で組み立てた**
  (`"{\"volume\": #{@volume}, \"on\": #{@on}}"`)。後は調べずに `JSON.generate` と `JSON.parse` (`sig/json.rbs`)。
  呼び出し 2 → 1、18.7 → 13.3 秒。
- **09 (乱数)**: 前は「乱数の `rand` はこの端末の Ruby では使えません」と説明し、`FmrbApp.uptime_ms % 6 + 1` で目を出した
  (乱数でない)。後は `RNG.random_int` (`sig/rng.rbs`)。説明の誤り (`rand` は使える。後の sig の `kernel.rbs` にある) も消えた。
- **06 (text_field)**: 後は `max: 20` を付けた (後の sig の `?max: Integer`)。前の sig の text_field にはキーワードが無かった。
- **10 (ほかの端末と)**: 前は 4 往復の上限まで調べ、expose / `conn.each` / `async.post` の形で作ったが、検査が 2 回落ちて
  (6 章 2)、7 回の呼び出し・39.4 秒。後は 2 往復で見本 talk_client を読み、`publish`・`subscribe`・`put`・`info.node` の形で
  一度で通った (3 回・17.1 秒、費用は 0.0106 → 0.0045)。どちらも型どおりで、形は a6b.md 5.2 とほぼ同じ。後は `text_field` に
  `max: 60`。`return if info.node == @link.node` が要らないのは a6b.md と同じ (害は無い)。

### 変わらない

- **02 (時計)**: どちらも `on_update` で 1000 を返す同じ形。`Machine` の時刻は前も後も使わなかった (頼みに要らない)。
- **05 (ボタン)**: どちらも `FmrbUI.new(self)`・`button`・`handle`・`flush`。label は前後とも使わず、数は `@gfx.draw_text`。
- **07 (ドレミ)**: どちらも `FmrbAudio#note_on` / `note_off` を `on_update` で順に鳴らす形。**`MmlPlayer` は前も後も使わなかった**
  (この頼みでは当てたい API に届いていない)。後は `note_on(0, f, 10, 2, 0)` と省略できる引数まで書いた (sig のとおり)。
- **04 (ファイル一覧)**: どちらも `FmrbFile.list("/home")`。**`Dir` は前も後も使わなかった**。

### 悪くなった (軽い)

- **03 (得点をファイルに)**: 前は `/home/score.txt` に `FmrbFile.write`・`read`・`exist?` で書いた (頼みどおり)。後は
  **`app_state` / `save_app_state` を使った** (後の sig で足した `sig/fmrb_app.rbs`)。これは `/tmp/<名前>.state.toml` で、
  **再起動で消える** (sig の長文にそう書いてあり、「ユーザの設定は `app_settings` に置く」ともある)。アプリを閉じて開き直す
  分には残るので頼みの文には一応応えているが、「ファイルに」の頼みからは外れ、説明にも再起動で消えることを書いていない。
  加えて得点のボタンを `fill_rect` で手描きにし、`draw_text` に背景色の 5 つ目の引数を渡した (5 章 1、形違い 1)。
- **04 (ファイル一覧)**: 後は `set_font(:ja, 12)` を呼ばず、見出しが英語 (`"/home  N files"`・`"(no files)"`) で、長い名前を
  `fit_text` で切らない。説明に「日本語の名前は正しく出ないかもしれません」と自分で書いている。sig とは関係が読めない
  (揺れの範囲と見る。1 回ずつしか流していない)。

## 5. sig の記述が元で LLM が間違えたと読める所 (直す候補。直していない)

1. **`FmrbGfx#draw_text` の sig が 4 引数** (`sig/fmrb_gfx.rbs` 638 行、`%a{fmrb.internal}`)。実装
   (`lib/gems/picoruby-fmrb-app/mrblib/fmrb-gfx.rb` 199 行・`main/ruby/spinel/fmrb_app_base_spinel.rb` 640 行) は
   `draw_text(x, y, str, color, bg_color = nil, mixed: false)`。後の 03 は `draw_text(x, y, "…", WHITE, BLUE)` と書いた
   (実装には合う)。sig/README.md の「引数は実装のとおりに書く」に照らすと、sig を `?Integer? bg_color, ?mixed: bool`
   まで書く方が正しい。今の形ではエディタの Ctrl+E がこの正しい呼び出しに「引数が多い」と出す見込み (確かめていない)。
2. **`FmrbGfx#fit_text` の sig が 2 引数** (`sig/fmrb_gfx.rbs` 60 行)。長文は 3〜5 つ目の引数 (印・印の幅・字の種類) を
   例つきで説明していて、実装 (`fmrb-text.rb` 34 行) も 5 引数。前後の 10 は `fit_text(s, w, "..")` (見本 talk_client と
   同じ)。シグネチャが長文と食い違っている。
3. **`app_state` の位置付け** (`sig/fmrb_app.rbs` 1288 行)。説明は正しい (再起動で消える、設定は `app_settings`) が、
   1 行目の要約だけ見ると「次に開くときのため覚える」場所に読める。後の 03 はファイルの頼みにこれを選んだ。要約に
   「再起動で消える」を入れるか、`app_settings` へ誘う余地がある。LLM の選び方の揺れかもしれない (1 回しか流していない)。

sig のせいではないが見つけたこと (範囲の外、変えていない):

- **asterism-tutor の検査が、sig と見本の正しい書き方を落とす**。前の 10 の 1 回目と 2 回目は
  `boards = @link.conn.each("*/#{APP}/board")` (sig の長文の例と見本 talk_board の書き方。sig にもブロック無しで Array を
  返す形がある) を、検査 `enumerator_next` ("external enumerator next / StopIteration (.each without a block)") が
  「端末の Ruby に無い」として落とした。LLM はブロックを付けて `boards << p` に書き換えて 3 回目で通った。往復の上限と
  答え直しで呼び出しが 7 回になったのはこのため。検査 (`lib/tutor/check.rb`) が `Asterism::Connection#each(pattern)` を
  外部イテレータと取り違えている。
- `MmlPlayer`・`Dir`・`Machine` は頼みの文が当てにいったが、LLM はより身近な `FmrbAudio`・`FmrbFile`・`on_update` で済ませた。
  これらの sig の良し悪しは今回の通しでは分からない (使われていない)。

## 6. 見立てと違った点・止まった所

1. **会話の続きが頼みに混ざった**。最初は全部の頼みを同じ端末 `fmruby-test01` から送ったため、`talk.turns = 4` で
   前の頼みのやり取りが次の頼みに付いた (記録の `history_turns` が 1, 2, 3, 4 と増えた)。比べる条件が揃わないので、02〜05 の
   前後 8 個を捨て (`scratchpad/s6/discarded/`)、頼みごとに端末の名前を変えて流し直した。01 は最初の 1 回目なので履歴が 0 で、
   そのまま使った。この捨てた分が 4 章の LLM の回数に入っている。
2. **後の 04 (1 回目、履歴つき) が LLM の時間切れ** (`the LLM did not answer in time`、tutor の `llm.timeout_s` 120 秒。
   `test/sender.rb` は 60 秒で先に諦めた)。記録に `llm` の行が無く、トークンと費用が分からない。流し直しの後の 04 は 11.1 秒で
   返った。原因 (API の遅れか、長い出力か) は確かめていない。これを受けて包みの待ちを 200 秒にした。
3. 前の 10 は 4 往復の上限まで使い、検査の答え直しでも呼び出しを重ねた (5 章の検査の取り違え)。
