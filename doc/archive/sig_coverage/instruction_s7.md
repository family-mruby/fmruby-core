# S7 指示書: クラスリファレンスを作る道具の仕上げと、全クラスの生成 (公開の手前まで)

> 2026-11-25 | 親セッションからサブへの指示。計画は plan.md の「S7 の中身」。試作は `tools/ti/gen_site.rb`
> (`rake ti:site`) と、サイトの checkout のブランチ `api-reference` (3 クラス分、`beda770`)。

## 目的

`sig/*.rbs` (125 クラス・1,470 メソッド) から、ドキュメントサイトの「Class Reference」を全クラス分作れる所まで
道具を仕上げ、サイトの手元のビルドとリンクの検査を通す。**push と公開はしない** (親とユーザが行う)。

## やること

1. **道具の仕上げ** (`tools/ti/gen_site.rb`、fmruby-core のブランチ `sig-s7`):
   - **載せないクラスの一覧**を設定ファイル (`tools/ti/site_exclude.yml`。クラス名と理由) から読む。今は空に近くてよい
     (どこまで出すかはユーザが決める。一覧を変えて作り直せば反映される形にする)。一覧にあるクラスへのリンクは
     張らない。
   - `AREAS` に無い sig のファイルがあったら、黙って落とさず「Other」に入れて警告を出す。
   - 型の中のクラス名 (`-> FmrbUI::Button`、引数の `Asterism::Proxy`) を、そのクラスのページへのリンクにする
     (載せているクラスだけ)。長いシグネチャは折り返して読める形にする (重ねた形 `|` は 1 つずつ行にする)。
   - 手で書いた話題のページ (`docs/api/*.md` の 17 ページ) との相互リンク: 対応の表を道具の中に持ち
     (話題のページ → 主なクラス)、クラスのページの頭に「使い方は ○○ のページ」、話題のページの末尾に
     「クラスリファレンス: ○○」の 1 行を、**印の行の間だけ**書き換える形で足す (手で書いた本文は変えない)。
   - ナビゲーションの日本語 (`mkdocs.yml` の `nav_translations`。領域の名前と「クラスリファレンス」)。
   - 各ページの足元に「fmruby-core の <ブランチ>@<短いハッシュ> の sig から生成」。一覧のページ (`index.md`) の頭に
     断り書き (開発中の版から作っていること、リリースの版と違う所があること。文は仮でよい。親が直す)。
   - 生成は冪等にする (2 回流して差が出ない)。前に生成して今は無いクラスのページは消す (生成物の一覧を
     `docs/api/reference/.generated` のような形で持ち、**道具が作ったファイルだけ**を消す)。
   - 道具の試験 (`rake ti:site:test` か、今ある試験の並びに足す。小さな sig の見本から作って、ページの形・
     載せない一覧・リンク・冪等を見る)。`rake test` に入れる。
2. **全クラスを生成する**: サイトの checkout `/home/kishima/fmrb/family-mruby/tmp/family-mruby.github.io` の
   ブランチ `api-reference` で `rake ti:site FMRB_SITE_DIR=...`。サイトの MkDocs のビルド (サイトの README か
   試作のときのやり方: plan.md の「試作で確かめたこと」と、サイトの `scripts/`) とリンクの検査を通す。
   警告 (切れたリンク・無い見出し) は 0 にする。ビルド時間とページの数・大きさを控える。
3. **目で見る**: 手元でサイトを開ける形にし (mkdocs serve か、ビルド結果)、日本語と英語のページを 5 つほど
   (`FmrbGfx`・`FmrbUI`・`Asterism::Connection`・`FmrbConst`・`String`) 画面で撮って、崩れ (表・コード・長い
   シグネチャ・見出しのリンク) を確かめる。撮った画像は scratchpad に置き、パスを報告に書く。
4. サイトの側はブランチ `api-reference` にコミットする (生成物と、`mkdocs.yml`・話題のページの印の行)。

## 報告 (fmruby-core の doc/archive/sig_coverage/report/s7.md)

1. 道具に足したもの (上の項目ごと) と試験。
2. 生成の結果: クラスの数・ページの数・大きさ、ビルド時間、リンクの検査の結果、警告。
3. 画面で見た結果 (崩れていた所と直した所、残った所)。画像のパス。
4. sig の書き方が元でページが読みにくい所 (直す候補。sig は直さない)。
5. 親とユーザが決めること (載せないクラスの候補と理由、断り書きの文、公開の手順で気になる所)。
6. 確かめていないこと。両リポジトリのコミットの一覧。

## 範囲と止まる条件

- 触ってよい: fmruby-core の `tools/ti/gen_site.rb`・`tools/ti/site_exclude.yml`・道具の試験・`rakelib/ti.rake`
  (と試験を並びに足す `rakelib/test.rake`)・`doc/archive/sig_coverage/report/s7.md`・`doc/README.md` (`rake docs:index`)。
  サイトの checkout のブランチ `api-reference` (`docs/api/reference/`・`mkdocs.yml`・話題のページの印の行の間・
  要れば CSS 1 つ)。
- 変えない: `sig/`・実装・ほかの道具・`gen_help.rb` (端末のヘルプ)・サイトの手で書いた本文・サイトの `main`。
- fmruby-core でビルドをしない (`rake build:*`・`rake clean*`)。流してよいのは `rake ti:site`・道具の試験・
  `rake regress`・`rake docs:index`。
- **push しない** (どちらのリポジトリも)。マージしない。公開の操作 (GitHub Pages・Actions) をしない。
- サイトに実在の値 (ドメイン・IP・ノード名・人の名前) が出ないこと (sig の例は仮の値のはずだが、生成物を
  grep して確かめ、見つけたら報告に書く。sig は直さない)。
- 外からのダウンロードは、サイトのビルドに要るパッケージ (試作のときに入れた物) の範囲だけ。新しく要るなら
  止まって報告する。ユーザに質問しない。コメントとコミットは英語、報告は日本語 (常体)。
  サイトのリポジトリは公開なので、コミットとコメントは ASCII だけ (日本語は `.ja.md` のページの中だけ)。
