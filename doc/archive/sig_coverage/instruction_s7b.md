# S7b 指示書: クラスと定数の説明の欠けを埋める (サイトに出す前の仕上げ)

> 2026-11-25 | 親セッションからサブ (Sonnet) への指示。元は report/s7.md の 4 章 (クラスリファレンスを全クラス
> 生成して見つかった、sig の説明の欠け)。書き方の正は `sig/README.md`。報告の形は report/s5a.md に合わせる。

## 目的

サイトのクラスリファレンス (と端末の F1・AI ホスト) で、クラスの説明が空・英語のページに日本語だけ、という所を
無くす。**メソッドの宣言 (シグネチャ) は変えない**。変えるのはコメントだけ。

## やること (fmruby-core、ブランチ `sig-s7b`)

report/s7.md の 4 章の 1〜5 と 7 を全部直す。一覧は道具で出し直す (4 章の数は S7 の時点の物。その後
`sig/exception.rbs` が増えた)。

1. **クラスのコメントが無いクラス** (`FmrbApp`・`FmrbGfx`・`FmrbAudio`・`FmrbMidi`・`FmrbFile`・`P5`・`Fmrb`・`MIDI`、
   Ruby の基本クラス 14): クラスの宣言の前に、`日本語の要約 <<en>> English summary` の 1 行 (111 バイトまで) と、
   長文 (日本語 → `<<en>>` → 英語) を書く。長文は「このクラスで何ができるか・アプリからどう手に入れるか
   (`@gfx` は `FmrbApp` が用意する、など)・最初に読むとよいメソッド 3〜5 個」を短く。Ruby の基本クラスは
   「CRuby との違い (この端末で使えるのは sig にあるメソッドだけ、など実装から言えること)」を 1〜3 行で。
   **実装とそのコメント・今ある sig のメソッドの説明に書いてあることだけを書く** (推測で書かない)。
   - `Untyped` は書かない (サイトに出さない)。
2. **クラスのコメントが日本語だけのクラス** (約 35): 同じ内容の英語を `<<en>>` の後に足す。1 行目が
   `日本語 <<en>> English` の形でなければ、その形に直す (日本語の意味は変えない)。
3. **クラスの 1 行目が文の途中で折り返している所** (`FmrbVideo`・`Asterism` ほか、道具で探す): 1 行目を
   111 バイトまでの完結した要約にし、続きは長文へ回す。
4. **要約が日本語だけの定数** (`FmrbGfx::COLOR_*`・`FmrbConst` ほか) に英語を足す。**要約の無い定数**
   (`FmrbAssoc::*`・`FmrbAudio::NSF_*` ほか) に要約を書く (実装の値とコメントを読んで)。
5. **長文が日本語だけのメソッド** (`P5` 9、`GPIO` 2、`Asterism::ROS::*` 5 ほか) に英語を足す。
6. 書き終えたら、欠けを数え直して 0 を確かめる。数え方は scratchpad に小さなスクリプトを書いてよい
   (`tools/ti/gen_site.rb` の読み方を借りる。道具そのものは変えない)。数えたスクリプトの場所を報告に書く。

## 確かめる

- `rake sig:coverage` (「3. doc gaps」は全部 0 のまま)、`rake ti:test`、`rake regress`、`rake ti:site:test`。
- `rake sig:coverage:update` は数が変わったときだけ、別コミット。
- 境界の検査が落ちたら `ruby tools/boundary/gen.rb` で SDK を作り直してコミットに入れる。
- ビルド・sim・サイトの生成はしない (親が行う)。

## 報告 (doc/archive/sig_coverage/report/s7b.md)

1. 直した数 (上の 1〜5 ごと、クラスの一覧)。
2. クラスのコメントを新しく書いた物について、根拠 (読んだ実装・sig の場所) の表。
3. 前後の欠けの数 (数えたスクリプトの場所)。確認の結果。
4. 直さなかった物と理由。**`String#__ljust_rjust_argcheck`** (report/s7.md 4 章の 6) は触らず、実装での
   使われ方 (アプリから呼ばれうるか、型エンジンの試験が前提にしているか) を調べて報告に書く。
5. 読んでいて見つけた、説明と実装の食い違い (直さずに書く)。確かめていないこと。

## 範囲と止まる条件

- 触ってよい: `sig/*.rbs` のコメント (上流由来のファイルも可。sig/README.md のとおり)、`sdk/` (境界の作り直しのとき)、
  `tools/sig_coverage/baseline.json`、`doc/archive/sig_coverage/report/s7b.md`、`doc/README.md` (`rake docs:index`)。
- 変えない: 宣言 (`def`・`class`・定数の型)、既にある要約の日本語の意味、実装、道具、型エンジンの試験の期待値
  (試験が落ちたら止まって報告)、`sig/README.md`、plan.md。
- ビルドをしない。push しない・マージしない。ユーザに質問しない。実在の値を書かない。
  コメントとコミットは英語 (sig の日本語の説明は除く)、報告は日本語 (常体)。
- 量が多ければ、まとまりごと (クラスのコメント / 英語の追加 / 定数) にコミットし、時間が足りなければ済んだ所までで返す。
