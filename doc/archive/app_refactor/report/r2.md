# R2 報告: TOML の読み書き FmrbToml と、ばらばらの読み手の載せ替え

> 状態: 完了 | 更新: 2026-10-25 | instruction_r2.md の記録。1 章の確認で一度止まり (Spinel から使えない、寛容な読み手が試験で決めてある)、ユーザが 3 点を決めた (誤りのあるファイルは無いものとして扱う、Spinel は対象外、麻雀の書き込みも update にする)。そのうえで FmrbToml を作り、mruby 側の読み手を載せ替えた。ホストの試験、sim (Modern と Retro)、ブラウザ版、3 機種の DIRAM の比較まで済んでいる

## 1. 結果の要約

- **FmrbToml** (picoruby-fmrb-app): `FmrbToml.parse(text)`・`FmrbToml.load(path)` は、ファームの tomlc99 で読んで Hash を返す。`FmrbToml.update(path, values)` は、渡した鍵の行だけを書き換える (Ruby)。値の書き方は `FmrbToml.dump_value` の 1 か所にまとめた。
- **FmrbApp (mruby)**: `app_settings`・`save_app_settings(values)` を足した (`/home/<app_handle_name>.toml`)。メソッドだけで、インスタンス変数は足していない。Spinel 版の FmrbApp は触っていない。
- **載せ替えた読み手 (mruby)**: FmrbColors、FmrbAssoc (mruby 側)、FmrbAsterism (config.toml・旧 asterism_profile.toml・system_conf)、SvcConf (サービスの一覧と状態のファイル)、step_sensor、オセロ (ゲームと test の写し)、asterism_demo、rt_probe、walk_scroller の台本、appstore、麻雀の設定 (読みと書き)。
- **残したもの**: Spinel 側の読み手 (5 章)。
- **試験**: `rake test` は全部通る。新しく `rake toml:test` を足した。sim の Modern と Retro、ブラウザ版の walk_scroller で確認した。
- **内蔵 RAM**: Tab5・Retro・StickS3 とも DIRAM は前後で同じ。ファームは +5,352 / +7,416 / +6,212 B。
- **コミット**: 6 つ (9 章)。push はしていない。

## 2. 1 章の確認結果 (止まる前に調べたこと)

| 確認 | 結果 |
|---|---|
| 1. ビルドの範囲 | ESP32 (Tab5・Retro・StickS3)・Linux の sim・ブラウザ版の全部で、fmrb_toml と tomlc99 がビルドに入っている。gem の `ports/esp32/*.c` は idf.py 側もブラウザ版も GLOB で拾われるので、足した C は手当てなしに 3 つ全部に入った (ブラウザ版のビルドの記録でも `toml.c.o`・`toml_walk.c.o` が作られている) |
| 2. 確保の領域 | tomlc99 の確保は全体で 1 組の関数 (`toml_set_memutil`) を通る。これまでは SYSTEM プール (`fmrb_sys_malloc`) で、ESP32 の全構成で PSRAM にある。今回、アプリの VM から読むときは VM のプールから取るようにした (3.3) |
| 3. Spinel | Spinel のプログラム (カーネル・デスクトップ・エディタ) は mrbgem の C メソッドを呼べない。C は `ffi_func` でしか呼べない。ユーザの判断で、R2 では Spinel を対象外にした |
| 4. 読み手の一覧 | 寛容な読み手が多い (行ごとに読み、読めない行だけ飛ばす)。SvcConf と FmrbAssoc は、その寛容さを試験で決めていた。ユーザの判断で、TOML の誤りが 1 つでもあるファイルは無いものとして扱い、理由を 1 行ログに出すことにした。引用の無い 1 語は、その文字列として読む |

## 3. FmrbToml と入口の形

### 3.1 読む

- `FmrbToml.parse(text)` は Hash を返す。TOML でなければ nil を返し、理由は `FmrbToml.error` に入る (例 `line 2: missing =`)。
- `FmrbToml.load(path)` は、ファイルが無ければ nil を返し、ログは出さない (設定を変えていない普通の状態だから)。TOML の誤りがあれば nil を返し、ログに 1 行出す (`toml: /home/colors.toml: line 3: missing =`)。空のファイルは `{}`。
- 値の対応:

| TOML | Ruby |
|---|---|
| 表 | Hash |
| 配列 | Array (種類が混ざってもよい) |
| 表の配列 (`[[mark]]`) | Array of Hash |
| 文字列 | String (エスケープを解く) |
| 整数 (`0x..`・`1_000` を含む) | Integer |
| 小数 | Float |
| 真偽 | true / false |
| 日時と引用の無い 1 語 (`bg = black`) | 書いてあるとおりの String |

- 鍵の順番: tomlc99 は値・配列・表を別々に持っている。そのため、Hash の鍵は種類ごとにファイルの順に並ぶ (値が先、配列、表の順)。サービスの一覧は表どうしなので、ファイルの順のまま。
- C の側 (`ports/esp32/toml.c`) は `FmrbToml._parse(text)` だけを持つ。Hash を返すか、TOML でないときは理由の String を返す。木をたどる部分 (`toml_walk.c`) は mruby を知らない素の C にした。こうしたので、ホストの試験 (`test/toml/dump.c`) が同じ C をホストの cc で動かせる。
- tomlc99 の癖: `\u` のエスケープは大文字の 16 進しか受け付けない (`"歩"` は読めるが、`"歩"` は `expect hex char` の誤りになる)。書くほう (`dump_value`) は大文字で書く。

### 3.2 書く

- `FmrbToml.update(path, values)` の `values` は `{ "rise_mg" => 130, "editor.bg" => ... }` の形。鍵は上の段、または `"section.key"`。
- 振る舞い:
  - 同じ表の、その鍵の行だけを書き換える。重複した行があれば消す。
  - 無い鍵は、その表の最後の行の後に足す。上の段の鍵は最初の表より前に置く。
  - 無い表は、末尾に空行を挟んで足す。
  - nil の鍵は行ごと消す。
  - ほかの行・コメント・ほかの表には触らない。
  - 書いたあと load し直して値を比べる。合えば読み直した Hash を返し、合わなければ nil を返す (理由は `FmrbToml.error`)。
  - ファイルがあって TOML でないときは書かずに nil を返す (人が書いた文章を壊さない)。
- 書き換える行にあった行末のコメントは消える (前の FmrbColors.set と save_tune と同じ)。
- `FmrbToml.dump_value`: 文字列は引用し、`\" \\ \n \t \r` と制御文字 (`\u00XX`) をエスケープする。整数・小数・真偽はそのまま、配列とハッシュは 1 行の形で書く。`FmrbToml.raw(text)` を渡すと引用しないで書く (色の名前に使う)。

### 3.3 確保

- `components/fmrb_toml` に、タスクごとの確保の口 (`fmrb_toml_set_task_allocator`) と、それに合わせた解放 (`fmrb_toml_xfree`) を足した。口が「引き受ける」と答えればそちらから取り、そうでなければ SYSTEM プールから取る。
- gem は口を 1 組登録する。今のタスクが mruby の VM で、そのアプリのスロットが `_parse` の中にいるときだけ、VM のプールから取る (`mrb_malloc_simple` / `mrb_free`)。スロットごとの印は確保と同じタスクから読むので、2 つの VM が同時に読んでもそれぞれのプールから取る。カーネル・起動・HID の表など、ほかの C の呼び手はこれまでどおり SYSTEM プール。
- `mrb_malloc_simple` は足りないと GC を走らせることがある。作りかけの Hash は arena で守っている。例外が出ても印と木を後始末してから投げ直す (`mrb_protect_error`)。
- 内蔵 RAM を使わないことの確認:
  - スロットの印 (`s_in_parse`、9 B) と口の 2 つのポインタは `.ext_ram.bss` (PSRAM) に置いた。StickS3 の ELF で確認した (`s_visitor` は `.flash.rodata`)。
  - DIRAM は 3 機種とも前後で同じ (8 章)。
- VM のプールから取っていることの確認 (sim):
  - 試験用のアプリが読んでいる最中に gdb を当てた。`toml_parse → CALLOC → toml_alloc_cb → vm_alloc → mrb_malloc_simple` で止まることを見た。
  - system_conf.toml を 50 回読んでも、SYSTEM プールの使用量は 2,592 B → 2,592 B で変わらなかった。

### 3.4 FmrbApp の入口 (mruby)

- `app_settings`: `FmrbToml.load(app_settings_path) || {}`。
- `save_app_settings(values)`: `FmrbToml.update(app_settings_path, values)`。
- `app_settings_path`: `"/home/" + app_handle_name + ".toml"`。
- `app_handle_name` を決める順:
  1. アプリの `.app.toml` の `app_handle_name`
  2. ファイル名から `.app.rb` を外したもの
  3. それも無ければ `name`
- 起動したファイルの場所は、新しい `FmrbApp.script_path` (C、`ctx->filepath`) で取る。
- インスタンス変数は足していない。Spinel 版の FmrbApp には入口を足していない (ユーザの判断)。

## 4. 載せ替えた読み手と、変わったところ

振る舞いが変わるのは、TOML として正しくないファイルだけにした。正しいファイルは前と同じに読める (下の「同じ」の確認)。

| 読み手 | 載せ替え | 変わった場合 |
|---|---|---|
| FmrbColors (`/home/colors.toml`) | `section` は load で読む。`set` は update で書き、色は名前か `0x..` のまま (`FmrbToml.raw`) | 誤りがあるとファイル全体を読まず、全アプリがテーマの色になる (前は読めない行だけ飛ばした)。誤りのあるファイルには set が書かない (前は行を書き換えた)。新しい鍵を足す位置は、表の最後の行の直後 (前は次の表の見出しの直前) |
| FmrbAssoc (mruby 側、`/etc`・`/home/associations.toml`) | `fmrb-assoc-file.rb` (load。鍵は小文字にし、空でない String の値だけ使う) | 誤りのある表は読まない。/home の表が壊れていれば /etc の表だけになる (前は読めない行だけ飛ばした)。整数などの String でない値は答えにしない |
| FmrbAsterism (`config.toml`、旧 `asterism_profile.toml`、system_conf の `zenoh_router`・`asterism_node`) | load の上の段の String。config.toml の書き方は前と同じ (全体を書き、見出しのコメントを付ける)。値は dump_value で書く | 同じ鍵が 2 回ある config.toml は読まない (前は先の値を取った)。表の中の行は設定として拾わない (前は拾った)。名前の中の制御文字は消さずにエスケープする |
| SvcConf (`/etc`・`/home/services.toml`、`services_state.toml`) | `SvcConf.from_toml(FmrbToml.load(...))`・`state_from_toml`。registry.rb は素の Ruby のまま | 誤りのある一覧は全体が無いことになる。もう 1 つの層は別のファイルなので残る (前は読めない行だけ飛ばした)。正しい TOML の値は型つきで届く (配列・小数・エスケープを解いた文字列。前は書いてある文字のまま渡した)。引用の無い 1 語は前と同じく文字列。見つからないファイルのログ (`services: no ...`) は出なくなった |
| step_sensor | 調整は app_settings / save_app_settings。display_width は system_conf を load して読む | 前方一致で鍵を拾うこと (`rise_mg2` など) は無くなった。整数でない値は無いものとして扱う |
| オセロ (ゲームと test)・asterism_demo・rt_probe の `conf_int` | system_conf を load して読む | system_conf が壊れているときは 0 (カーネルは factory に戻る) |
| walk_scroller の台本 | `FmrbToml.parse` | 誤りがあると台本全体を読まず、組み込みの台本 (`no script`) とログ 1 行になる。前も例外のときは同じだったが、読めない行は飛ばして続けていた |
| appstore の `value_of` | parse して文字列で返す | 入れた .app.toml が TOML でなければ版は `?` |
| 麻雀 (`/home/mahjong.toml`) | 読みは app_settings、書きは save_app_settings | 下の表 |

麻雀の設定のファイルの形:

| | 前 (全体を書き直す) | 後 (update) |
|---|---|---|
| 書く行 | 毎回、決まったコメント 3 行と `assist`・`name`・`bgm`・`se`・`voice`・`bgm_*`/`voice_*` | 渡した鍵の行だけを書き換え、無い鍵は末尾に足す |
| ユーザのコメント・知らない鍵 | 消える | 残る |
| 名前を消したとき | 行を書かない | 行を消す |
| 音の初期化に失敗したとき | 音の行を書かない (前の音の設定が消える) | 音の行には触らない (残る) |
| 新しいファイル | 上の形 | 3 行のコメント (中身の説明) と、鍵の行 |

- 前のコードが書いたファイルは、後のコードでそのまま読める。
  - `test/toml/run.rb` で、前の形のファイルを読み、書き直してコメントが残ることを確認した。
  - sim でも確認した。ユーザの手元の `flash/home/mahjong.toml` (前の形) で起動すると、名前「し」が出た。B で BGM を変えると、`bgm = 2`・`se`・`voice` の行が足され、コメント 2 行は残った。起動し直しても BGM は中のままだった。
  - 確認のあと、このファイルは元の内容に戻した。
- 名前に使える文字は `"` と `\` を含まない (`name_char_ok?`)。そのため、前のコードが書いた名前の行も TOML として正しい。

「同じ」の確認:

- walk_scroller: 前の `parse_toml` (HEAD から取り出した) と `FmrbToml.parse` の結果を CRuby で比べた。sample.toml とブラウザ版の /home にあった台本 (9 マーク) の両方で一致した。
- サービス: sim の一覧の起動ログが `3 running, 2 disabled` で、`flash/etc/services.toml` と合っている。

## 7. 試験

### 7.1 ホスト

- `rake test` は全部通る。

## 8. RAM とファームの大きさ

`idf.py size`。前 = 作業前の HEAD、後 = 載せ替えまで入れた作業ツリー。どちらも同じ手順 (`rake clean_all` → `FMRB_HW_TARGET=<機種> rake build:esp32`) で作った。

| 端末 | DIRAM 前 | DIRAM 後 | 像の大きさ 前 → 後 |
|---|---|---|---|
| Tab5 (P4) | 129,698 | 129,698 | 6,671,524 → 6,676,876 (+5,352) |
| Retro (NARYAv3) | 126,035 | 126,035 | 4,502,895 → 4,510,311 (+7,416) |
| StickS3 | 114,863 | 114,863 | 4,512,983 → 4,519,195 (+6,212) |

- Retro が一番大きく増えた。R1 の Link と違い、FmrbToml は Retro にも入る gem (picoruby-fmrb-app) に置いたため。tomlc99 自体は前から入っている。
- mrblib の Ruby は flash に bytecode として入る。各 VM の FmrbToml のクラス定義は VM のプール (PSRAM) に乗る。
- 作業のあと、build/ は Linux (TAB5、x86-64) に戻した。
