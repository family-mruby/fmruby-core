# M1 実施報告: ミュートと音量

> 状態: 完了 (親の検収待ち) | 更新: 2026-10-01 | ミュートと音量 (0-10) を出力の最後の段で効かせる。設定は system_conf に残り、起動音も従う。メニューバー・メニュー・Config・devctl・debugd・MCP から切り替えられる。上限・下限の既定は全機種 0 / -50 dB (1 段 5 dB、7 = -15 dB)。スピーカの印は時計のすぐ左。NARYAv4 の静的な D/IRAM は develop と同じ 125,524 バイト。実機 (P4-Nano) は親が書き込み、起動と動作を確認済み。7・8 章が実機確認後の変更 (8 章: 設定の保存をまとめて flash への書き込みを減らす)

指示書: ../instruction_m1.md / 計画: ../plan.md

## 1. 結果の要約

- 音源はすべて普段どおり動かし、書き出す直前のサンプルだけを変える (スピーカのミュートとつまみと同じ)。
  P4 とブラウザ版は core の audio_p4、Retro と sim は graphics-audio の最後の段。
- core からは新しい命令 `FMRB_AUDIO_CMD_SET_OUTPUT` (0x0F) を 1 つ送るだけ。中身はミュート・音量の段・
  その段の dB (0.1 dB 単位)。切り替えのたびと、接続 (INIT_DISPLAY) の直後に送る。
- 設定は system_conf の `audio_mute` / `audio_volume` (既定 7) と、設定ファイルだけの
  `audio_level_min` / `audio_level_max` (既定は全機種 -50 / 0 dB。7 章)。
- 静的な内蔵 RAM は増えていない (3 章)。

途中で設計が 2 回変わった。最初は host タスクで命令を種類ごとに捨てる作りで作り、sim で確かめたところで
親から「出力の段で止める」設計に変更の指示があった。そのあと音量が加わり、既定値が 2 回変わった (最終は 7)。
命令を捨てる作り (`fmrb_audio_cmd_allowed`、play / resume の止め、ミュートの瞬間の STOP) はコミットせずに消した。

## 2. 音の経路と止まる場所

すべての音は最後に 1 か所を通る。P4・ブラウザ版では audio_p4 のフレームループの `apuif_audio_write`、
Retro と sim では graphics-audio の `audio_out_write` (新設。`apuif_audio_write` の呼び出し 4 か所をここへ集めた)。

| 経路 | 通り道 | 最後の段を通るか |
|---|---|---|
| アプリの FmrbAudio (play / play_slot / load_fmsq / play_wav / note_on) | アプリ → kernel (msgpack を命令に直す) → host_task → transport → 音源 | 通る |
| note_on / note_off の C 経路 (`fmrb_app_send_audio_note`) | アプリ・MIDI スケジューラ → kernel → host → 音源 | 通る |
| MIDI の内蔵 APU (MmlPlayer / SmfPlayer) | fmrb_midi_sched → `fmrb_app_send_audio_note` → 上と同じ | 通る |
| BASIC の PLAY / BEEP | fmrb_basic.cpp → host に直接 (命令を自分で組む) → 音源 | 通る |
| MicroPython の audio_note | fmrb_bridge.c → `fmrb_app_send_audio_note` | 通る |
| Lua | 音の API が無い | ― |
| デスクトップの起動音 (ジングル) | system_desktop の FmrbAudio#note_on | 通る |
| P4 の起動の「ピコ」 | audio_p4 のタスクが自分で鳴らす (kernel より前) | 通る。設定はタスクが自分で先に読む |
| WROVER / sim の起動の「ピコ」 | graphics-audio の graphics_task が自分で鳴らす (core とつながる前) | 通る。最後の設定を graphics-audio が自分の flash に持つ |
| `fmrb_audio_play` など components/fmrb_audio の C API | transport に直接 | 呼び手が無い (使われていない) |
| 外部 MIDI 出力 (シリアル) | 本体の音ではない | 対象外 (止めない) |

ミュート中・音量 0 のときは最後の段が 0 を書く。再生中のものは止めないので、外すと曲の途中から鳴る
(sim でループ再生中に切り替えて確かめた)。

## 3. 作ったもの

### 3.1 命令と設定 (core)

- `audio_commands.h` (両リポジトリ同じ内容): `FMRB_AUDIO_CMD_SET_OUTPUT = 0x0F` と
  `fmrb_audio_output_cmd_t { cmd_type, muted, volume, level_db_x10 }` (5 バイト、packed)。
  古い WROVER は「Unknown audio command: 0x0f」を 1 行出して続ける (戻り値 -1 は message handler が
  警告を出すだけ)。そのときミュートも音量も効かず、今までどおり鳴る。
- `fmrb_audio` (component): ミュート・音量の段の記録と、段 → dB の計算 (`fmrb_audio_step_db_x10`)。
  記録は構造体の詰め物に置き、範囲 (min / max) は PSRAM。
- kernel: `read_system_config` が設定を読む (`apply_audio_conf`)。`fmrb_kernel_load_audio_conf` は
  audio_p4 のタスクが kernel より先に同じ読み方をするための口。保存は `fmrb_kernel_save_conf_value`
  (system_conf の最上位の 1 行を書き換え、無ければ最初の `[節]` の前に足す。一時ファイルに書いて rename)。
- host_task: `fmrb_host_set_audio_mute` / `fmrb_host_set_audio_volume` (状態を変え、SET_OUTPUT を
  host のキューに積み、変わったときだけ保存)。INIT_DISPLAY の直後に今の設定を送る。
- 段と dB: 段 n (1-10) は `min + (max - min) * n / 10` dB、0 は無音。既定の範囲は全機種
  -50 〜 0 dB で、1 段 5 dB (7 章で変更。最初の版は「ハードの最大・最小」で 1 = min だった)。

| 段 | 1 | 4 | 7 (既定) | 8 | 9 | 10 |
|---|---:|---:|---:|---:|---:|---:|
| dB (全機種) | -45 | -30 | **-15** | -10 | -5 | 0 |
| ES8311 (NARYAv4) の DAC レジスタ 0x32 | 0x65 | 0x83 | 0xA1 | 0xAB | 0xB5 | 0xBF |
| ES8388 (Tab5) の LDACVOL/RDACVOL | 0x5A | 0x3C | 0x1E | 0x14 | 0x0A | 0x00 |
| ソフトの倍率 (Retro・sim・ブラウザ版) | 0.0056 | 0.032 | 0.178 | 0.316 | 0.562 | 1.0 |

  ES8311 は 0x00 = -95.5 dB、0.5 dB 刻み (0xBF = 0 dB、0xFF = +32 dB)。ES8388 は 0x00 = 0 dB から
  0.5 dB 刻みで下がる。設定ファイルで動かせる範囲は出力ごとの限界まで (ES8311 -95.5〜+32、
  ES8388 -96〜0、ソフト -96〜0 dB)。今までの音量は P4 がチップで -11.4 dB (esp_codec_dev の 70/100 =
  -15 dB にドライバのハード利得の項 +3.6 dB)、ソフトは 0 dB。既定の 7 は P4 で約 3.6 dB 小さく、
  ソフトでは 15 dB 小さい。

- 下限 -50 dB の根拠 (M1 の最初の版でソフトの下限として測った値): sim で測ると APU の 1 声の山は
  3072 (約 -20 dBFS)。-50 dB では約 10 LSB で、小さいが曲と分かる。-60 dB で試した値は 4 LSB で、
  probe も「鳴っていない」と数えた。上限 0 dB はハードが持ち上げずに出せる最大 (ソフトは等倍)。

### 3.2 出力の段

- audio_p4 (P4・ブラウザ版): フレームループで、無音 (ミュートか音量 0) なら 0 を書く。ブラウザ版は
  Q16 の倍率を掛ける。P4 の実機は倍率を使わずコーデックの音量で絞る:
  - NARYAv4 (ES8311): コーデックドライバの `set_vol` を直接呼ぶ (`esp_codec_dev_set_out_vol` は
    0-100 を -50〜0 dB に写す曲線なので範囲が足りない)。ドライバが引くハード利得の項を足し戻して、
    チップに渡る dB を正確にした。ミュートは `esp_codec_dev_set_out_mute`。
  - Tab5 (ES8388): 表示ドライバの I2C 経由で LDACVOL/RDACVOL (0.5 dB 刻み、0〜0xC0) を書く。
    ミュートは DACControl3 の bit 2 (ドライバが開いたときの値を読んで 0x04 / 0x00 とした)。
  - 実機ではサンプルを 0 にするのに加えてコーデックもミュートする。
- 起動の「ピコ」より前に効くよう、audio_p4 のタスクは最初のフレームの前に system_conf を読む
  (サンプル側だけ。コーデックは host の最初の SET_OUTPUT で表示タスクの文脈から設定)。
- SET_VOLUME (0x06) は誰も送っていなかった。P4 では何もしない命令にし、backend 表の `set_volume`、
  ブラウザ版の `fmrb_wasm_audio_volume` とワークレットの倍率は消した (出力の段の倍率と二重になるため)。
- graphics-audio: `audio_out_write` で無音または倍率。最後の設定を
  `flash/etc/audio_output_{linux,esp32}.txt` に持ち (変わったときだけ書く)、audio タスクの開始時に読む。
  名前を機種で分けたのは、sim が書いたファイルが ESP32 の storage イメージに入って実機がそれで
  起動するのを避けるため (同じ flash/ から作られる)。

### 3.3 切り替えの口

| 口 | 内容 |
|---|---|
| メニューバー | 時計のすぐ左に スピーカ (7 章で移動。最初の版は状態のセルの一番左)。鳴る: 波、ミュート: 白地に × (反転)。クリックで切り替え。1 秒ごとに状態を読むので、遠隔の変更も 1 秒以内に出る |
| メニュー | 「消音 / Mute」「消音を解除 / Unmute」(状態で文言が変わる) |
| Config | 「音量 / Volume」0-10。矢印で動かしたその場で聞こえるが、保存は Save のときだけ (8 章)。表示は今の値 (ファイルに行が無い古い設定でも 0 にならない)。Config の保存は今のミュートの値を書く (開いた後に変わった値を古い値で上書きしない) |
| アプリ向け | `FmrbApp.set_audio_mute(bool)` / `audio_muted?` / `set_audio_volume(n)` / `audio_volume` (mruby と Spinel、sig にも追加) |
| devctl | `GET /audio/mute` `POST /audio/mute?on=0\|1` `GET /audio/volume` `POST /audio/volume?level=0..10`。答えは `{"ok","muted","volume"}`。自前サーバの経路の上限を 12 → 14 |
| debugd (sim 用) | `audio` 命令 (`on` / `volume` は省略可、`{muted, volume}` を返す) |
| MCP (親リポジトリ) | `tab5_audio(action: get\|mute\|unmute\|volume, level?)`、`sim_audio(同)`。selftest に追加 (全項目通過) |
| ブラウザ版のページ | `audio_mute` / `audio_volume` をページの設定の保存に加えた (再読み込みで残る) |

その他: `tools/fmrb_web.rb` は headless のブラウザを `--mute-audio` で起動するようにした。ブラウザが
Windows の Chrome の場合、headless でも出力はユーザのスピーカになるため。

  (サーバの再起動はしていないので、ツールとしての呼び出しは selftest で確認)。

## 5. 見立てと違った点

- 最初に「1 か所で止められる」場所として host タスクを選んだが、命令の種類で分ける作りは採用されな
  かった (1 章)。出力の段に移すには graphics-audio の変更が要った (親が許可)。
- 「起動音」は 3 種類あった。デスクトップのジングルのほかに、P4 の audio_p4 が自分で鳴らす「ピコ」と、
  WROVER / sim の graphics-audio が core とつながる前に鳴らす「ピコ」。後の 2 つは core の設定が届く
  前に鳴るので、それぞれ自分で設定を読むようにした。最初の試作の sim で「ミュートしたのに起動時に
  4 窓鳴った」のはこの graphics-audio のピコだった。
- core は WROVER の再接続を検出していない (起動時にリセットして INIT_DISPLAY で 1 回つなぐだけ)。
  「接続のたびに送る」は INIT_DISPLAY の直後の 1 回になる。WROVER が勝手に再起動した場合は、
  graphics-audio が自分のファイルの設定で動く。
- ブラウザ版の /etc はページの再読み込みで消える。ページの設定の保存に 2 つのキーを足して残した。
- `audio_level_max` の既定を最初「ハードの最大」とした結果、NARYAv4 は +32 dB (DAC のデジタル増幅)
  になり、実機で音量 10 がうるさすぎた。7 章で全機種 0 dB にそろえた。

## 6. 残件

- 青いちらつきの原因は flash への書き込みと分かった (8 章)。保存の回数は減らしたが、保存のたびに
  1 回は出る。flash の書き込みそのものでちらつく件は別に扱う。
- 実機の耳での確認: 段の聞こえ方 (5 dB 刻み)、既定の 7 (-15 dB)、コーデックのミュート。
- Tab5 と Retro 実機は未確認。WROVER のファームの焼き直しが要る (古い WROVER では効かず、今までどおり鳴る)。
- ブラウザ版でサンプルの値を直接見る確認はしていない。
- 通常の flash は system_conf を config/ の既定 (ミュートなし・音量 7) に戻す。ミュートを残すなら
  app_only で焼く。

## 7. 実機の確認を受けた変更 (2026-10-01)

親が NARYAv4 に M1 の版を書き込み、起動と動作を確認した。ユーザの確認を受けて 2 点を変えた。

### 7.1 上限・下限の既定を全機種 0 / -50 dB に

- 音量 10 (ES8311 で +32 dB) がうるさすぎた。既定を全機種 `audio_level_max = 0`、`audio_level_min = -50`
  にした (kernel の `AUDIO_LEVEL_DEFAULT_*`)。設定ファイルで動かせるのは同じ (出力ごとの限界で切る)。
- 段の割り当てを `min + (max - min) * n / 10` に変えた。1 段 5 dB、7 = -15 dB、10 = 0 dB
  (以前の式は 1 = min、10 = max の 9 等分だった)。
- 各コーデックへの写し方は 3.1 の表。ES8311 の 0 dB は 0xBF、ES8388 の 0 dB は 0x00 で、どちらも
  チップが持ち上げない最大。
- sim で確認 (MML、probe): 10 = peak 3072、7 = peak 547 (3072 x 0.178 = -15.0 dB)、
  1 = peak 18 (-44.6 dB)。graphics-audio のログは `output: volume 7, -150 dB/10`。
- NARYAv4 のビルドを作り直し、build/ に置いた。静的な D/IRAM は 125,524 (develop と同じ)。TAB5 と S3 は
  この変更では作り直していない (変えたのは定数と段の式だけ)。

### 7.2 スピーカの印を時計のすぐ左に

- 並びは左から RAM、かな、BLE、WiFi、スピーカ、時計。スピーカは `幅 - 90 - 4 - 10`、ほかのセルは
  `STATUS_RIGHT` (= 90 + 4 + 10) だけ右端から離れる。全体の幅は変わらず (一番左は今までどおり
  `幅 - 180`)、タスクバーの予約 (184) もそのまま。sim でクリックして切り替わることを確認した。

### 7.3 青いちらつき: 調べたこと (変更はしていない)

切り替え 1 回で起きることは 2 つある。

1. **設定の保存** (`fmrb_kernel_save_conf_value`): 呼んだタスク (メニューバーならデスクトップのアプリ
   タスク、devctl なら httpd、Config の矢印も 1 段ごとに) で、/etc/system_conf.toml (約 3.5 KB) を読み、
   `/etc/system_conf.toml.tmp` に書いて close、rename する。LittleFS への書き込みなので、内蔵 flash の
   消去・書き込みが 1 回の切り替えで数回起きる。値が変わったときだけ (同じ値なら書かない)。
2. **コーデックへの書き込み** (`apply_output`、表示タスクの文脈。host → transport → display_p4 の
   命令処理の中): NARYAv4 では
   - `audio_p4_hw_set_out_db`: ES8311 のドライバの `set_vol` → レジスタ 0x32 を 1 回書く。
   - `audio_p4_hw_set_out_mute`: `esp_codec_dev_set_out_mute` → レジスタ 0x31 を読んで書く (2 回)。
   - 切り替えのたびに両方を呼ぶ (計 3 トランザクション、100 kHz で数百 µs)。

I2C の直列化:
- ES8311 と LT8912B は同じ I2C_NUM_0 (表示が作ったバス、100 kHz) にいる。コーデックへの書き込みは
  esp_codec_dev の `audio_codec_new_i2c_ctrl` が同じバスの i2c_master ドライバで行う。**表示ドライバの
  `i2c_service_lock` (アプリの I2C と Tab5 用) は通らない**。ただ i2c_master ドライバ自身がバス単位で
  排他するので、同じバスの取引が電気的に混ざることはない。
- LT8912B に I2C で触るのは起動時の bring-up (`lgfx_naryav4.hpp` の `bring_up`) だけで、実行中に読み書き
  する箇所は見つからなかった (HPD の監視などは無い)。実行中の I2C の利用者は、コーデック、アプリの
  I2C (display_p4_i2c_*、mutex あり)、マイクの有効化。
- コーデックへの書き込みは表示タスクの中で走るので、その間 (数百 µs〜1 ms 程度) は描画が止まるが、
  表示は DSI の DMA が PSRAM のフレームバッファを読み続けるので、それだけで画面が乱れる理由は見えない。

見立て (未確認): 保存のほうが疑わしい。内蔵 flash の消去・書き込みの間は CPU のキャッシュが止まり、
PSRAM の帯域や DMA の進み方に影響しうる。以前の青いちらつき (FB の 4KB 揃え) と同じく DSI 側の
読み出しの乱れなら、flash の操作と重なって出る可能性がある。切り分けの案:
- ミュートの切り替えをせずに flash に書く操作だけをする (例: devctl の `/fs/put` で小さなファイルを
  /home に置く、エディタで保存する)。ちらつけば保存が原因。
- 逆に保存を伴わないコーデックへの書き込みだけ: 同じ値の SET_OUTPUT は保存しないので、
  `POST /audio/volume?level=<今と同じ値>` を送るとコーデックへの書き込み (表示タスク) だけが起きる。
  ちらつけば I2C 側。

## 8. 設定の保存をまとめる (2026-10-01)

ユーザがエディタの保存でも同じ青いちらつきを見て、原因は flash への書き込みと決まった。切り替えの
たびに system_conf を書いていたのをやめた。

### 8.1 Config の音量は Save のときだけ保存

- 矢印で動かすと `FmrbApp.preview_audio_volume` でその場で効くが、保存はしない。
- Save を押すと、今までどおり Config 自身が system_conf を書き (今のミュートと音量を含む)、
  `FmrbApp.audio_conf_saved` で「ファイルは今の値を持っている」と知らせる (待っている保存は取り消す)。
- Save せずに閉じると (Cancel・外側のクリック)、音量を開いたときの値 (Save した後ならその値) に戻す。
  ほかの行は値が画面の中にしか無く、閉じれば捨てられるだけなので、それに合わせて「保存していない変更は
  捨てる」を選んだ。Config にミュートの行は無い。

### 8.2 ほかの口はまとめて 1 回

- メニューバーのスピーカ・メニューの項目・devctl・debugd (`fmrb_host_set_audio_mute` /
  `fmrb_host_set_audio_volume`) は、その場で効かせて「保存が要る」と印を付けるだけ。host タスクの
  ループが、最後の変更から約 2 秒 (`AUDIO_SAVE_DELAY_MS`) たったときに、ファイルの値と違う
  キーだけを 1 回書く。表示タスクは書かない (P4 の表示は display_p4 のタスクで、host タスクとは別)。
- 状態は PSRAM に置いた (書くべき値・ファイルにある値・期限・排他の mutex)。
- `FmrbApp.reboot` (メニューの再起動・Config の Save & Reboot) は、待っている保存を先に書いてから
  再起動する (`fmrb_host_audio_flush_save`)。
- 起動時は今までどおり kernel が system_conf を読み、P4 の audio タスクも自分で読む。host タスクは
  読んだ値を「ファイルにある値」として持つ。
- **最後の変更から約 2 秒のうちに電源が切れると、その変更は保存されない** (再起動はメニューからなら
  保存される)。

### 8.3 sim での確認 (保存の回数を数えた)

- debugd で 6 回 (ミュート・音量を交互) + メニューバーのスピーカを 3 回、1.3 秒のうちに切り替え:
  `kernel: system_conf:` は **1 行** (音量だけ。ミュートは最後に元の値に戻ったので書かない)。
- 1 回だけ変えたとき: 2.0 秒後に 1 回書く。続けて変えたときは最後から 2〜3 秒 (host タスクの
  ループの都合で少し遅れることがある)。
- Config: 矢印 2 回 → Cancel で、プレビューの 2 回のあと元の値に戻り、保存は 0 回。矢印 3 回 → Save で、
  Config の保存が 1 回 (`Config: saved`)、host の保存は 0 回。閉じても戻らない。
- 再起動: Save した音量 9 が起動時に効く (`Audio output: volume 9 (-5.0 dB)`)。
- エディタを起動して 1 打鍵できた。`rake test` 通過。NARYAv4 を作り直して build/ に置いた
  (静的な D/IRAM 125,524、develop と同じ)。

### 8.4 残る flash への書き込み

- 保存 1 回ごとに system_conf の書き直し (一時ファイルに書いて rename) が 1 回。そのときのちらつきは残る。
- Retro では graphics-audio が SET_OUTPUT を受けるたびに、値が変われば WROVER の flash に自分の
  ファイルを書く。Config のプレビューも 1 段ごとに届くので、WROVER 側は 1 段ごとに書く。WROVER の
  映像 (NTSC) が flash の書き込みで乱れるかは未確認。乱れるなら graphics-audio 側も同じように
  まとめる必要がある。
