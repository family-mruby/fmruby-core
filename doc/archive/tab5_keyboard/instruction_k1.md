# 実装指示書 K1: Tab5 内蔵キーボードの刻印と入力の不一致修正

対象: 実装担当セッション。report は report/k1.md へ。
**T1 の実測は実機 (Tab5) とユーザの物理キー押下が必要** — 準備 (計測手段と
チェックリスト) までを先に作り、ユーザ実測を挟んで T2 に進む 2 段構え。

## 症状 (ユーザ報告 2026-08-11)

Tab5 内蔵キーボードで、**キーの刻印と実際の入力が一部一致しない (主に記号)**。

## 現状の構造と仮説

- ドライバ (main/drivers/tab5_keyboard/tab5_keyboard.c) は **HID モード**
  (レジスタ 0x30、modifier + keycode) で読み、keycode をそのまま
  scancode として host_task へ送る。文字化は host_task の 1 点で、
  **システム設定の keyboard_layout (既定 jp) の汎用フルキーボード表**
  (fmrb_keymap.c) が使われる。
- メーカ仕様の確認で以下が確定している (2026-08-11):
  1. **HID モードはデバイス内部で刻印 (Sym 層含む) を HID コードに解決
     済み**。Sym 押下中は右上刻印の文字に対応するコードが出る。
     「HID イベントを PC へ透過すればデバイスの記号どおりに打てる」と
     明記されており、これは **US 配列で解釈される前提**の変換である。
     → **jp 表で文字化しているのがズレの原因でほぼ確定** (us/jp の
     記号差分 @ ^ & ' ( ) = ~ : \ 等が症状と一致)。
  2. **Sym / Aa / Ctrl / Alt は単独では HID イベントを出さない**
     (他キーとの組み合わせでのみ効く)。→ Sym をかなトグルに使う案は
     不成立。T3 の Ctrl+Space 案で確定。
  3. **Aa の大小文字はデバイス内部処理** (単押し=次の 1 文字 / 長押し /
     二度押しロック、LED 表示付き)。firmware には Shift modifier として
     届くはずで通常処理と整合する見込み (T2 の確認項目)。
  4. release イベントは keycode=0 + modifier (現ドライバの扱いどおり)。

## T1: 確認テスト (ユーザ協力、短時間)

1. **1 分テスト**: 実機の設定で keyboard_layout を us に変えて再起動し、
   記号が刻印一致するかを確認してもらう。仕様どおりなら全一致するはず。
2. 全キー掃引は**最初からはやらない**。T2-A 適用後に不一致が残った
   キーだけを対象に、ドライバの Key DOWN ログ (既存 LOGD を INFO 化) で
   個別に採取する (残らなければ省略)。
3. Aa の各モード (単押し/長押し/ロック) で英字の大小が期待どおりかも
   1 のついでに確認してもらう。

## T2: 修正 (診断結果で分岐)

- **T2-A (本命)**: **ソース別レイアウト**を入れる。Tab5 内蔵キーボード
  由来のイベントは keyboard_layout 設定にかかわらず **US 表で文字化**
  する。実装は「イベントに layout ヒントを載せる」
  (fmrb_host_send_key_down の拡張 or 送出元登録) が素直。
  外付け USB/BLE キーボードは従来どおり設定に従う (JP キーボードを
  繋ぐユーザを壊さない)。sim には影響ゼロであること。
- **T2-B (T1/適用後確認で不一致キーが残った場合のみ)**: 残ったキーの
  実測から **FMRB_KEYMAP_LAYOUT_TAB5** (専用変換表) を fmrb_keymap に
  追加し、Tab5 内蔵キーボードだけこの表を使う (T2-A の機構に載せる)。
- **Character モードへの切替は採らない**。確定文字は刻印と一致するが、
  scancode が失われて矢印・ゲーム・ホットキー・かな合成層の前提が
  崩れるため。

## T3: Tab5 でのかなトグル (JA3 の持ち越し)

- Tab5 キーボードに半角/全角キーが無く、**Sym/Aa は単独でイベントを
  出さない仕様**なのでトグルに使えない。**Ctrl+Space を全キーボード
  共通の追加かなトグル**として fmrb_kana に足す (キーボード個体差に
  依存しない解。既存の 0x35 / Shift+0x35 / 0x88 はそのまま)。
- Ctrl+Space が既存機能と衝突しないことを確認 (エディタ・shell・
  デスクトップ。現状未使用のはず)。

## 受け入れ条件

- 実機: 全キー (素押し / Aa / Sym) で**刻印どおりの文字が入力される**
  (ユーザ確認。チェックリストを再利用)。
- 実機: エディタでかなモードが Ctrl+Space でトグルでき、ローマ字かな入力が
  内蔵キーボードで動く (JA3 の実機確認と統合)。
- 外付けキーボード (US/JP 設定) の従来動作に退行なし。sim に挙動変化なし。
- S3 ビルドにも影響なし (Tab5 ドライバは P4 限定のはず。確認)。

(T2-A/B) と根拠、かなトグルの最終仕様、ユーザ確認結果。
