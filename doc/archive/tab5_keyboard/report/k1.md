# K1 レポート: Tab5 内蔵キーボードの刻印/入力不一致の修正

instruction_k1.md への回答。方式は **T2-A(ソース別レイアウト)**、実機で確認済み。

## 診断 (T1)

内蔵キーボードで、記号キーの刻印と入力がズレる (英数字は一致) という症状。
仮説は「HID モードはデバイス内部で刻印を **US 前提の HID コード**に解決して
出すのに、host_task が全ソース共通で `keyboard_layout`(既定 jp)の表で
文字化しているためズレる」だった。

**1 分テスト**: 実機の `keyboard_layout` を `us` に変えて再起動 → 記号が
**刻印どおりに入力された**(ユーザ確認)。仮説が確定。全キー掃引 (T2-B) は
不要と判断。

## 修正 (T2-A)

イベントにレイアウトのヒントを載せ、**内蔵キーボード由来のイベントだけ
US 表で文字化**する。外付け USB/BLE キーボードは従来どおり `keyboard_layout`
設定に従うので、JP キーボードを繋ぐ利用者は壊れない。sim は内蔵ドライバを
使わないので影響ゼロ。

- `host_message_t` の key に `force_us` を追加 (既定 0 = 設定に従う。ゼロ
  初期化なので既存の送出元は無改修で従来動作)。
- `fmrb_host_send_key_down_us` / `fmrb_host_send_key_up_us` を新設
  (host_task.c / .h)。共通実装 `host_send_key` に集約。
- host_task の文字化を `force_us ? US : 設定` に分岐 (1 箇所)。
- `tab5_keyboard.c` の送出 (通常キー・修飾キーとも) を `_us` 版に切替。

Character モードへの切替は採らない (確定文字は刻印一致するが scancode が
失われ、矢印・ホットキー・ローマ字かな合成の前提が崩れるため。instruction
の判断どおり)。

## かなトグル (T3)

内蔵キーボードには半角/全角キーが無く、Sym/Aa は単独ではイベントを出さない
ため、**Ctrl+Space** を全キーボード共通のかなトグルとして使う。合成層側
(`fmrb_kana.c`) には JA3 の実装で既に入っており、K1 側の追加実装は不要
だった (二重実装を回避)。

## 実機確認 (ユーザ、TAB5)

- `keyboard_layout` は既定の **jp のまま**で、内蔵キーボードの記号が
  **すべて刻印どおり**に入力されることを確認 (Shift+数字段が US 刻印
  `@ # $ % ^ & * ( )` どおり)。残る不一致は無し → **T2-B の専用表は不要**。
- エディタでかなモードが Ctrl+Space でトグルできる (JA3 と統合)。

## 受け入れ条件の充足

- 実機: 全記号が刻印どおり (jp 設定のまま) ✅
- 外付けキーボード (US/JP 設定) の従来動作: 経路不変で退行なし ✅
- sim: 内蔵ドライバ非使用で挙動変化なし ✅
- S3: 内蔵ドライバは P4 限定。host_task の追加関数は S3 では未使用だが定義
  のみでビルドに影響なし (CI の NARYAv3 ビルドで確認)。
