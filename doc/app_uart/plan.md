# アプリから使える UART (doc/hw_resources の H5 を先に)

> 状態: 進行中 | 更新: 2026-11-26 | 上流の PicoRuby と同じ書き方の `UART` クラスを自前で持ち、ピンの台帳を通してアプリに開放する。ESP32 の全機種、実機の確認は Tab5 と P4-Nano。見本にシリアルのターミナルのアプリ。できたら 3.1.0 としてリリースする。段は U0〜U4、U0 (調査) に着手

## 1. 目的

- アプリから、端子につないだシリアルのモジュール (LoRa・GPS・ほかのマイコンなど) を使えるようにする。
- きっかけ: Tab5 に入れた利用者から、LoRa の無線 (Meshtastic) のアプリを作りたいという声があった (2026-11-26)。
  Meshtastic の基板は UART のテキストのモードを持ち、1 行を流せばメッセージになる。UART の API があれば、Ruby の
  アプリだけで書ける。
- doc/hw_resources の H5 (UART) を、H3 (名前での指定)・H4 (ADC・PWM) より先に切り出す (ユーザ 2026-11-26)。
  方針は hw_resources のまま: **クラスは自前で持ち、API は上流の PicoRuby に合わせる** (上流の gem `picoruby-uart` は
  ビルドに入れない。ピンの持ち主を見ないので、本体が使っている UART をアプリが開けてしまう)。

## 2. 今あるもの (2026-11-26)

| もの | 中身 |
|---|---|
| 上流の gem `picoruby-uart` | ソースはあるが、ビルドの設定でコメントアウト (`lib/upstream/family_mruby_esp32*.rb`)。型定義は gem の `sig/uart.rbs` |
| 本体の UART の HAL | `components/fmrb_hal/platform/esp32/fmrb_hal_uart_esp32.c` (シリアルの MIDI 出力などが使う)、描画側とのリンクの `fmrb_hal_link_uart_esp32.c` |
| ピンの台帳 | `fmrb_hal_pin_manager` (持ち主・使い方の種類。GPIO はシステムのピンを機種ごとの表で守る。doc/api_fixes の F6) |
| 開放できる端子 | Tab5 は Grove (G53・G54。シリアルの MIDI 出力と兼用)。ほかの機種は doc/hw_resources/report/h0.md の表 |
| 境界の定義 | アプリが呼ぶ API は `sig/*.rbs` に書き、境界の関数と各言語の SDK を生成する (doc/app_boundary) |

## 3. 方針 (決定 2026-11-26 ユーザ)

1. **対象は ESP32 の全機種。実機の確認は Tab5 と P4-Nano**。コードは機種を選ばない形にし、機種ごとには「アプリに開放して
   よいピン」の表だけを持つ。S3 の端末はビルドが通る所までで、実機はつないだときに確かめる。
2. **ピンは番号で指定する** (上流と同じ)。名前での指定 (`UART.new("grove")`) は hw_resources の H3 で足す。
3. **見本はシリアルのターミナル**。速さとピンを選び、届いた文字を出し、打った 1 行を送る汎用のアプリ。ソースが、
   アプリを書く人の手本になる。Meshtastic 専用のアプリは作らない (手元に基板が無く、確かめられない)。
4. **できたら 3.1.0 を全機種にリリースする**。出す前に、リリースのビルドを Tab5 と P4-Nano に焼いて、起動・WiFi・UART・
   主なアプリを確かめる。S3 の端末は CI のビルドと sim の回帰までで、実機は未確認とリリースノートに書く。

hw_resources から引き継ぐ決まり:

- クラス名・生成のしかた・主なメソッドと引数の形は上流と同じ。使用中のときのエラー・閉じる処理は自前の拡張として足す。
- 資源の管理は境界の下 (本体の C の 1 か所)。持ち主はアプリの単位で、アプリが終わったら本体が片付ける。
- 試験用の偽物は sim にだけ置く。ブラウザ版では「この環境では使えない」というエラーを返す。
- 内蔵 RAM を増やさない (受信のバッファは使うときだけ取り、PSRAM に置けるなら置く)。

## 4. 作る物の形 (U0 で確かめて決める)

```ruby
uart = UART.new(unit: 1, txd_pin: 53, rxd_pin: 54, baudrate: 115200)
uart.puts "hello"
line = uart.gets            # 1 行届いていなければ nil (待たない)
n = uart.bytes_available
uart.close                  # 自前の拡張。アプリが終われば本体も閉じる
```

- メソッドは上流に合わせる: `read`・`readpartial`・`getbyte`・`bytes_available`・`gets`・`puts`・`write`・`set_format`・
  `flush`・`clear_rx_buffer`・`clear_tx_buffer`・`break`。流れの制御 (`set_flow_control`) は U0 で要るか決める。
- 待たない読み方を基本にする (アプリの `on_update` の中で呼ぶため。長く待つ読み方はアプリを固める)。
- 開くとき: 本体が使っている UART の番号と、開放していないピンは理由つきの例外。ほかのアプリ (やシリアルの MIDI 出力)
  が使っているピンも例外。
- 境界の関数として `sig/` に書き、Ruby のほかの言語 (wasm・Lua・MicroPython) からも同じ管理を通る形にする
  (hw_resources の H6 を、UART の分だけ先に行う)。

## 6. 受け入れ条件

- U1: sim で、アプリが `UART.new` で開き、偽物を通して送った文字が読める。本体の番号・開放していないピン・使用中のピンは
  理由つきの例外。アプリを終えると閉じられ、次のアプリが同じピンを開ける。上流の gem の試験・使用例のうち、対象の
  メソッドの分が通る。`rake regress`、`rake sig:coverage` の doc gaps 0。内蔵 RAM の静的な増分 0。
- U2: ターミナルのアプリで、打った行が送られ、届いた行が出る (sim の偽物で)。
- U3: Tab5 と P4-Nano で、115200 と 9600 の送り受けが化けない。1 KB を続けて受けても落とさない。
- U4: リリースのビルドが Tab5 と P4-Nano で起動し、WiFi の設定の画面からつながり、ターミナルのアプリが動く。
