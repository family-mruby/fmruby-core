# Ctrl+Tab フォーカス切替 / フルスクリーン退避 - 実装と検証状況 (P1)

2026-08-07 時点。実装済み・sim 検証済み・実機で問題 5 件発見、うち 3 件に対策を
入れた状態 (対策は未検証)。この文書を見ながら続きをやる。

## 目的

- デモ用に、キー操作だけで前面アプリ (とキーボードフォーカス) を切り替える。
- 特に PicoRabbit のプレゼン中にフルスクリーンを抜け、別アプリを操作してから、
  同じスライドに戻れること。

## 設計の要点

- ホットキーは **Ctrl+Tab**。Alt は Linux sim で構造的に使えない
  (SDL の ALT bit 0x100 が 8bit modifier に入らない) ため Ctrl。
  host_task が routing 前に割り込むので、フルスクリーン中でも効く
  (Ctrl+Q と同じ経路、main/kernel/host/host_task.c)。
- フルスクリーン中の Ctrl+Tab = **退避 (park)**: アプリを suspend
  (on_suspend が canvas を透明クリア) し、デスクトップと他アプリを resume。
  アプリの状態はタスクごと保持される。exit_fullscreen (停止) とは別経路。
- 退避してよいアプリは **.app.toml の `fullscreen_switchable = 1` で自己申告**
  (on_suspend/on_resume の実装が前提)。未申告アプリはフルスクリーン中の
  Ctrl+Tab を無視する。すべてのアプリに resume 実装を求めない方針。
- 通常時の Ctrl+Tab = ウィンドウの round-robin (デスクトップ除外) +
  **キーボードフォーカス追従**。エディタ⇄アプリの往復が主用途。
- 巡回で退避アプリの番が来たら **復帰 (unpark)**: enter_fullscreen を再実行し
  resume (on_resume がスライドを全再描画)。タスクバーから退避アプリを
  クリックした場合も unpark 扱い (focus_app ハンドラ内)。

## 実装箇所

| ファイル | 内容 |
|---|---|
| main/kernel/host/host_task.c | Ctrl+Tab 検出 -> kernel へ {"cmd":"cycle_focus"} |
| fmrb_kernel/app_lifecycle.rb | handle_cycle_focus / park_fullscreen / unpark_fullscreen / cycle_front_app、終了時の @parked_fullscreen_pid クリア |
| fmrb_kernel.rb | cycle_focus ハンドラ、focus_app の parked 対応、@parked_fullscreen_pid |
| fmrb_kernel/window_manager.rb | find_window_at で parked canvas をヒットテスト除外 (対策1) |
| system_desktop/taskbar.rb | state 3 (SUSPENDED) もタスクバー表示 (対策4) |
| fmrb_app.h / fmrb_app.c / fmrb_app_spawner.c | fullscreen_switchable の toml 解析と配管 |
| lib/add/picoruby-fmrb-kernel/ports/esp32/kernel.c | mruby 版 _get_app_info に追加 |
| fmrb_spx.h / fmrb_spx_kernel.c / fmrb_kernel_base_spinel.rb | **Spinel 版 _get_app_info レコード 164->165 バイトに拡張** (offset 164 = fullscreen_switchable) |
| picorabbit.app.rb / .toml | on_suspend (clear 0x01) / on_resume (draw_current)、宣言フラグ |

罠: kernel は Spinel 構成 (FMRB_KERNEL_ENGINE=spinel) なので、mruby 側の
kernel.c だけ直しても効かない。_get_app_info は fmrb_spx_kernel.c の packed
record 経由。最初これで「not switchable」と誤判定された。

## sim で検証済み (2026-08-07、全て画面キャプチャで確認)

- Editor + GPIO Viewer の 2 ウィンドウで Ctrl+Tab 巡回 (z とフォーカス両方が
  移る。切替後の text 入力がエディタに入ることまで確認)。
- PicoRabbit フルスクリーン (debugd で spawn: `python3
  fmruby-core/tool/debug/fmrb_dbg_client.py localhost spawn
  path=/app/tool/picorabbit.app.rb`) -> スライド 3 まで進め Ctrl+Tab ->
  デスクトップ復帰 -> Ctrl+Tab -> **3/11 のまま全再描画**、その後の Right で
  wait ステップが進む (入力復帰も OK)。

## 実機 (Tab5) で発見した問題と状態

1. **マウス反応が不安定** -> 原因の見立て: 退避アプリの透明全画面 canvas が
   最前面 z のままヒットテストに掛かり、クリックが suspend 中のアプリの
   キューに溜まる。対策済 (find_window_at で除外)、**未検証**。
2. **Ctrl+Tab を2回押さないと戻らない** -> デスクトップにフォーカスがある
   状態からの巡回が candidates[0] 始まりだったため。対策済
   (デスクトップからは退避アプリ優先)、**未検証**。
3. **復帰後にスライドが勝手に進む** -> 1 で溜まった mouse_up が resume 時に
   一気に配送されるのが原因の見立て。1 の対策で解消するはず、**未検証**。
4. **タスクバーに退避アプリのアイコンが出ない** -> taskbar が state==RUNNING
   のみ表示だった。対策済 (SUSPENDED も表示)、**未検証**。
5. **PicoRabbit 終了後に画面が更新されず、最終的にリブート** ->
   **原因未特定**。シリアル未採取のため crash (Guru) か手動リブートかも不明。
   次回、(a) sim で Esc 終了経路 (特に park/unpark を経た後の終了) を再現、
   (b) 実機は `python3 ../tools/fmrb_serial_capture.py --no-reset -t 180 <log>`
   を回しながら再現してログを取る。

## 明日の手順

1. ビルド状態に注意: 中断時点で build/ は **Linux ターゲット** (バックグラウンド
   ビルドの完走を確認: `file build/fmruby-core.elf` が x86-64 なら OK)。
2. sim で対策 1-4 の検証 + 問題 5 の再現:
   - `tools/dev_run_check.sh --keep` で起動、debugd で PicoRabbit spawn
   - 退避 -> デスクトップで click 操作 (メニュー開閉など) が正常か (1)
   - タスクバーに P アイコンが出るか、クリックで復帰するか (4)
   - デスクトップから Ctrl+Tab 一発で復帰するか (2)
   - 退避中に画面のあちこちをクリック -> 復帰してもスライドが進まないか (3)
   - park/unpark を数回繰り返してから Esc で終了 -> デスクトップが戻るか (5)
   - 入力注入: `ruby tools/fmrb_input.rb key ctrl+tab` / `key esc` /
     `key right` / `click X Y`
3. 通ったら `rake clean_all` -> `rake build:esp32` -> `FLASH_BAUD=115200 rake
   flash` (ボタン不要)。実機検証はシリアル採取を回しながら。
4. 実機で 5 が再現したら Guru dump の MEPC を addr2line
   (docker 内 riscv32-esp-elf-addr2line -pfiaC -e build/fmruby-core.elf)。

## 既知の未解決・保留

- 問題 5 の原因特定 (最優先)。
- 退避中アプリの音は止まらない (park は silence_notes_for を通らない)。
  PicoRabbit は無音なので保留。音物アプリを switchable にする時に再考。

  依存しない汎用解)。P4 compositor には is_visible が既にあり、protocol と
  WROVER 側の追加が必要。第2段階。
- Ctrl+Tab の連打・長押し (key repeat) の挙動は未確認。
