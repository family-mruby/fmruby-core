## 成果

NARYAv4 は自分の sdkconfig / system_conf / ピン定義を持つようになった。
プレースホルダ警告は消えた。実機表示はまだ (P2)。

`ESP32P4_REV_MIN_FULL=301` / `REV_MAX_FULL=399` (`SELECTS_REV_LESS_V3` は

## 気づき・踏んだ罠

### 警告は fmrb_hw_defines.cmake ではなく main/CMakeLists.txt にあった

指示書は `components/fmrb_common/fmrb_hw_defines.cmake` の
`message(WARNING ...)` を消せと書いていたが、実物は
`main/CMakeLists.txt:353` にあった。fmrb_hw_defines.cmake 側にあるのは
同趣旨の**コメント**で、こちらも古くなっていたので両方直した。

### RESTRICTED_USB_DN / _DP の枠をコンソール UART に使った

ピン定義のマクロ名は Tab5 ブロックと同名で揃える必要がある一方、
P4-Nano のコンソールは USB-Serial-JTAG ではなく CH343P 経由の
UART0 (TX=37 / RX=38) で、対応するマクロが無い。この 2 枠の目的は
「USB-C のコンソール線をユーザアプリに取られてコンソールを殺されない
ようにする」ことなので、名前は据え置いて 37/38 を入れ、理由をコメントに
書いた。**名前と中身がずれている唯一の箇所**なので、基板確定時に
マクロ名ごと整理するのが望ましい。

### NARYAv4 ブロックは Tab5 の**上位集合**にした

Tab5 が定義するマクロ名は 1 つ残らず定義した上で、P0 で判明した
NARYAv4 固有のピンを追加した: `FMRB_PIN_I2S_MCLK/SCLK/LRCK/DOUT/DIN`、
`FMRB_PIN_AUDIO_AMP_EN` (NS4150B、GPIO53)、`FMRB_PIN_RADIO_EN`
(C6 EN、GPIO54)。**今は誰も消費していない** — audio_p4_hw.c は自前の
Tab5 定数のままで、これを使うのは P3。値をここに置いたのは、回路図を
読み直さずに済ませるため。

Grove の 53/54 が audio EN と C6 EN に化けている関係で、NARYAv4 の
`FMRB_PIN_I2C2_*` は NC。I2C は 7/8 の 1 本だけ (`FMRB_PIN_I2C1_*`)。

### set-target のログは NARYAv4 ビルドでも "HW target: TAB5" と出る

`rake build:esp32` は idf.py を 2 回呼ぶ。1 回目の `set-target` には
`-DFMRB_HW_TARGET` が付かないため、main/CMakeLists.txt の表示が既定側
(TAB5) に落ちる。2 回目の `build` は付けて呼び直し、cmake も再構成される
ので**成果物は正しい** (compile_commands.json で確認済み)。ログだけを見て
「Tab5 のバイナリができた」と誤読しないこと。P1 で入れた不具合ではなく
従来からの挙動なので、直すなら別件。

### まだ Tab5 のまま動くもの (P2/P3 の前提)

- `main/CMakeLists.txt` の P4 用ソース一覧はボード分岐が無く、NARYAv4
  ビルドにも `display_p4_task.cpp` / `touch_task.c` /
  `tab5_keyboard.c` / `audio_p4_hw.c` がそのまま入る。よってこの
  バイナリを P4-Nano で起動すると表示初期化 (PI4IO プローブ) は失敗する。
  P1 の想定どおり。
- `display_mode = "naryav4_hdmi"` は情報表示だけで、ドライバ選択には
  効いていない。
