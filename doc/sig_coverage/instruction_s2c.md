# S2c 指示書: File・Dir・Time・IO と、Class の残りを sig に書く

> 2026-11-25 | 親セッションからサブ (Sonnet) への指示。計画は plan.md (5 章の S2、7 章の決定)。書き方の正は
> `sig/README.md`。前の一括は report/s2a.md・s2b.md (同じ進め方。報告の形はこれに合わせる)。

## 目的

アプリがファイルと時刻を扱うときに使う API を sig に書く。S2 の最後の一括。

1. **`File`** (今の sig は `sig/fmrb_file.rbs` にある分だけ。実装にあるクラスメソッド `join`・`basename`・`dirname`・
   `extname`・`expand_path`・`exist?`・`open`・`read` など、インスタンスの `read`・`write`・`gets`・`each_line`・
   `close`・`seek` など、実際に定義されているもの)。
2. **`Dir`** (`exist?` 8 回・`open` 5 回・`mkdir`・一覧の読み方。C の実装に 25)。
3. **`Time`** (アプリが使っている呼び方と、実装にあるもの)。
4. **`IO`** (`puts`・`print`・`flush` など、アプリから使う分。`Kernel#puts` などとの関係も実装のとおりに)。
5. **`Class`・`Module` の残り**: `const_defined?`・`remove_method` (アプリが使っている。`sig/class.rbs`)。

## やること (fmruby-core、ブランチ `sig-s2c`)

1. `rake sig:coverage` を流し、`tmp/sig_coverage/report.md` から上の 1〜5 に当たる行を控える (前の数)。
   アプリでの実際の使い方 (`flash/app/`・`flash/lib/templates/`・`flash/usr/share/samples/`) を読む。
2. **実装を読む** (推測で書かない)。端末のビルドに入っている定義を突き止める。Family mruby は picoruby の
   ファイルの gem を差し替えている所がある (`lib/upstream/`・`lib/gems/`)。**どの実装がビルドに入るか**を build config と
   CMake で確かめてから読む。ファイルまわりは、つまずく所が多いので特に注意する:
   - **失敗のしかた**: ファイルが無い・ディレクトリが無い・書けない場所・既にある、のとき、例外 (名前も) か、nil か、
     false か。CRuby と違う所は必ず書く。
   - **書ける場所**: アプリが書いてよいのはどこか (`/home`・`/tmp` など)。読み取り専用の場所に書こうとしたときの
     振る舞い。実装か端末の案内 (`flash/usr/share/doc/`) に書いてあることだけを書く。
   - **閉じ忘れ**: ブロックを渡すと自動で閉じるか。開けたままにできる数に上限があるか (実装にあれば)。
   - **モードの文字** (`"r"`・`"w"`・`"a"`・`"rb"` など) のうち使えるもの。`File.binread` のように CRuby にあって
     端末に無いものは書かない (アプリが呼んでいて実装に無ければ、報告の「見つからなかったもの」に並べる)。
   - **機種ごとの違い** (ESP32 の flash・SD、sim、ブラウザ版、ネイティブ版) が実装から読める所は長文に書く。
     読めない所は書かずに、報告の「確かめていないこと」に書く。
   - `Time`: 端末に時計が無い・合っていないときの値、タイムゾーンの扱い、使えるメソッド。
3. **sig に書く**。`File` は既にある `sig/fmrb_file.rbs` に足す (既にある宣言と要約は変えない)。`Dir` は
   `sig/dir.rbs`、`Time` は `sig/time.rbs`、`IO` は `sig/io.rbs` (新しいファイル。既に宣言があればそこに足す)。
   `Class`・`Module` は `sig/class.rbs` に足す。
   - 要約は `日本語 <<en>> English` で 111 バイトまで。素直なものは「例だけ」、つまずくものは型紙の順
     (何をするか → 引数の意味 → 戻り値と失敗のしかた → 使う順番と前提 → 短い例)。
   - 省略できる引数は `?`、キーワードは `name:`、形が複数あるものは `|` で重ねて、実装のとおりに書く。
   - 例は同梱のアプリでの実際の使い方に合わせる (39 桁以内)。強調 `**` は 1 行の中で閉じる。
   - アプリが使っていないメソッドも、実装にあってアプリから使う想定のものは短く書く (前の一括の `Machine` と同じ)。
     内側のもの (ファイル記述子の番号を直接扱う、など) は書かずに、報告の「判断が要るもの」に並べる。
4. **確かめる**: `rake ti:test`、`rake regress`、`rake sig:coverage` (対象の「無い」が、書かなかった理由のあるもの
   だけになる)。`rake sig:coverage:update` で基準を更新し、別コミットにする。型データベースの各領域の大きさの
   前後を控える。**ビルドと sim の確認はしない** (親が検収で、sim のシェルで実際にファイルを読み書きして確かめる)。

## 報告に必ず書くこと (doc/sig_coverage/report/s2c.md)

1. **根拠の表**: 書いたメソッドごとに、読んだ実装のファイルと行 (`パス:行`)、どの gem・どのビルド設定に入っているか。
   **失敗のしかたを書いたものは、その根拠の行も** (例外を上げている行、nil を返している行)。
2. 書いた数、素直 / つまずくの内訳。
3. 実装にあるが書かなかったものと理由 / 判断が要るもの / **アプリが使っているのに実装に見つからなかったもの**。
4. 数える道具の前後の数、型データベースの大きさの前後。
5. **確かめていないこと** を、確かめたことと分けて書く。**親が sim のシェルで確かめるとよい項目を 10 個ほど**、
   打つ式と、sig に書いた期待の結果の形で並べる (例: `File.exist?("/nope")` → `false`)。1 行は 60 文字以内。
6. 読んでいて見つけた実装の不具合の疑い (前の一括の `Machine.delay_ms` のようなもの) があれば、直さずに書く。
7. 迷った所・型紙で足りなかった所。

## 範囲と止まる条件

- 触ってよい: `sig/fmrb_file.rbs`・`sig/class.rbs` への追加、`sig/dir.rbs`・`sig/time.rbs`・`sig/io.rbs` (新規)、
  上流由来の sig ファイルへの追加 (`kernel.rbs`・`object.rbs`。`puts` などが要るとき)、`sdk/` (境界の検査が落ちて
  作り直しが要るときだけ。`ruby tools/boundary/gen.rb`)、`tools/sig_coverage/baseline.json`、
  `doc/sig_coverage/report/s2c.md`、`rake docs:index` による `doc/README.md`。
- 実装・アプリ・sig の既にある宣言と要約・`sig/README.md`・plan.md・`tools/sig_coverage/` の道具と ignore.yml・
  型エンジンの試験の期待値は変えない (試験が落ちたら止まって報告)。
- ビルドをしない (sim・ESP32・ブラウザ版・ネイティブ版とも。`rake clean`・`rake build:*` を流さない)。
- 止まる条件: どの実装がビルドに入るか突き止められない / 型エンジンの試験が sig の追加で落ちる / 範囲の外の
  変更が要る。止まったら、そこまでをコミットして報告に書く。
- push しない・マージしない。ユーザに質問しない。実在の値 (ドメイン・IP・ノード名・鍵) を書かない。
  コメントとコミットは英語 (件名は `feat(sig): ...`・`test(sig_coverage): ...`・`docs(sig_coverage): ...`)、報告は日本語 (常体)。
