## 4. 例を書けなかったもの

| メソッド | 理由 |
|---|---|
| `FmrbApp#destroy` | `start` が最後に呼ぶもので、アプリが呼ぶ場面が無く (`grep` で `destroy` を呼ぶアプリ・テンプレートは無し)、実装から安全な呼び方が言えない |
| `FmrbApp#main_loop` | 同上 (`start` の中身。呼ぶと `on_update` のループが走り続ける) |

2 件とも `rake sig:coverage` の「例が無い」に残る。直すなら「内部用 (`%a{fmrb.internal}`) なので ignore.yml に入れる」か
「例を書かない決定をする」のどちらかだが、いずれも親の決定 (ignore.yml は触っていない)。

## 5. 長文を足した 3 件と、散文を足した 2 件

- 足した 3 件 (要約だけだったもの): `FmrbGfx#area_height` (`area_width` と対、`@user_area_height`)、`FmrbGfx#origin_y`
  (`origin_x` の縦の対)、`FmrbSystem.remote_access_paired` (守りが無いと 0、`revoke_remote_access` で 0)。
- 散文を足した 2 件 (実装を読んで、シグネチャに無い必須キーワードがあると分かったので、型紙の「引数の意味」に書いた。
  シグネチャと要約は変えていない): `TileMap#render` の `origin_x:`・`origin_y:` (必須)・`max_cols:`・`max_rows:`、
  `TileRing.new` の `tiles_w:`・`tiles_h:` (必須。「見える数 + 1 以上」は `fmrb-tilemap.rb:416` のコメントから)。

## 6. シグネチャ・要約が実装と食い違っているもの (直していない。親が確認する)

1. **`FmrbApp#publish`**: sig は `(String topic) -> void` だが、実装は `publish(topic, data = nil)` (`fmrb-app.rb:1187`)。
   アプリはどれも `publish(TOPIC, { ... })` と 2 引数で呼ぶ (`flash/lib/templates/worker.rb:39`、
   `flash/usr/share/transfer/fmrb_transfer.rb:105`)。型エンジンの Ctrl+E は今この呼び方に「引数が多い」と出るはず。
   例は 2 引数で書いた。直すなら `(String topic, ?untyped data)` (境界のメソッドでないので internal の扱いの確認が要る)。
2. **`TileMap#render`**: sig は `(TileSheet sheet)` だが、実装は `render(sheet, origin_x:, origin_y:, max_cols: nil, max_rows: nil)`
   (`fmrb-tilemap.rb:204`)。必須キーワードが 2 つあるので、sig どおりの呼び方は ArgumentError になる。
3. **`TileRing.new`**: sig は `(TileMap map, TileSheet sheet)` だが、実装は `initialize(map, sheet, tiles_w:, tiles_h:)`
   (`fmrb-tilemap.rb:420`。キーワード必須)。
4. **`FmrbUI#label`・`FmrbUI#button`**: sig に省略できるキーワードが無い。実装は
   `label(id, x, y, w, h, text, align: :left, text_size: nil)` (`fmrb-ui.rb:995`)・
   `button(id, x, y, w, h, text, text_size: nil, accent: nil)` (`:1005`)。長文には `align:`・`accent:`・`text_size:` が
   書いてあるのに、シグネチャに無いので、決定 22 の形 (`?align: Symbol` など) に直すと、まちがい探しが
   キーワードを検査できる。
5. 確認したいだけのもの: `FmrbApp#on_suspend` の要約・説明は「別のアプリが前に出たとき」だが、実装のコメント
   (`fmrb-app.rb:615-620`) は「fullscreen app taking over」「fullscreen app exited」と書く。ふつうの Window のアプリが
   前に出ても呼ばれるのかは読んでいない (例はどちらでも通る形にした)。

## 8. 確認していないこと・迷った所

- ビルドも sim も流していない (指示どおり)。例のコードは**どれも実行していない**。呼び方は実装の引数の形と、アプリの使い方に
  合わせた。F1 の画面での見え方 (強調の色の付き方、39 桁の折り返し) も見ていない。
- 例の桁数: 足した例は 39 桁 (全角 2 桁) に収めたが、既にあった例には 39 桁を超えるものが多数ある (数えていない。触っていない)。
- 強調の直しで、長い強調 (全角 100 桁超) を 2 つに分けた 3 か所は、F1 では強調が 2 つ並んで、間の 1 桁が空く。
- `` `*``*` `` (glob の `**` の書き換え) が F1 の markdown でどう見えるかは見ていない。コードの印が 2 つ並ぶはず。
- 「`Machine.exit`・`reboot`・`tud_*` ほかの機種差」は S2 の記述を信じ、今回は実装を読み直していない。
- `FmrbApp.script_path`・`FmrbGfx#transfer_file` は戻り値を書かなかった (言えなかった)。
- `FmrbApp#draw_window_frame` の例の `@gfx.clear(...)` が枠を消すことは、`clear_user_area` の sig の説明
  (「`gfx.clear` は canvas 全体を塗る」) からで、実機・sim では見ていない。
