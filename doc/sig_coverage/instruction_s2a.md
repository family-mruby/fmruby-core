# S2a 指示書: FmrbConst と Math を sig に書く

> 2026-11-24 | 親セッションからサブ (Sonnet) への指示。計画は plan.md (5 章の S2、7 章の決定)。書き方の正は
> `sig/README.md` (S1 で足した型紙と決まり)。S2 の最初の一括で、定型の作業を Sonnet に任せる試しでもある。

## 目的

同梱のアプリが一番多く使うのに sig に無い 2 つを埋める。

- `FmrbConst` の定数 (キーの番号・テーマの色・`BOARD` ほか。アプリで 273 回)。
- `Math` (`sin`・`cos`・`sqrt`・`atan2`・`PI` ほか。アプリで 41 回、C の実装に 26)。

## やること (fmruby-core、ブランチ `sig-s2a`)

1. **今の数を見る**: `rake sig:coverage` を流し、`tmp/sig_coverage/report.md` で `FmrbConst` と `Math` の行
   (アプリが使う定数・メソッドと、実装にあって sig に無いもの) を控える。
2. **実装を読む** (推測で書かない)。
   - `FmrbConst`: 定数がどこで定義されるか (C の定義、生成されるもの、機種やビルドで変わるもの) を突き止める。
     値が機種で変わる定数 (`BOARD`・画面の大きさなど) は、変わることを長文に書く。
   - `Math`: 端末のビルドに入っている実装 (mruby / picoruby の gem) を突き止め、**実際に定義されている関数と定数
     だけ**を書く。CRuby にあっても端末に無いものは書かない。引数の型 (Integer を渡せるか)、定義域の外での
     振る舞い (例外か NaN か) は、実装を読んで書く。
3. **sig に書く**。置き場: `FmrbConst` は `sig/fmrb_const.rbs` (新しいファイル)、`Math` は `sig/math.rbs`
   (新しいファイル)。既にどこかに宣言があればそこに足す。書き方は `sig/README.md` のとおり:
   - 要約は `日本語 <<en>> English` で 111 バイトまで。
   - 定数の書き方は既にある例に合わせる (`sig/fmrb_gfx.rbs` の `FmrbGfx::WHITE` など)。
   - 素直なものは「例だけ」(散文を書かない)。つまずくもの (README の目安に当たるもの) だけ型紙の順で長文を書く。
     `Math` の大半と、キーの番号の定数は素直な側のはず。
   - 定数が多い所は、**アプリが使っているもの (report.md に出るもの) を全部**と、同じ仲間で並びとして無いと
     不自然なもの (例: `KEY_A`〜`KEY_Z` の一部だけが使われているなら全部) を書く。内部用と分かるものは書かず、
     報告の「判断が要るもの」に並べる (勝手に ignore.yml に入れない)。
   - 例は同梱のアプリでの実際の使い方に合わせる (39 桁以内)。
   - 強調 `**` は 1 行の中で閉じる。
4. **確かめる**:
   - `rake ti:test`、`rake regress`、`rake sig:coverage` (`FmrbConst`・`Math` の「無い」が、書かなかった理由のある
     ものだけになる)。`rake sig:coverage:update` で基準を更新し、別コミットにする。
   - 型データベースの各領域の大きさ (名前・シグネチャ・要約) の前後を控える。
   - **ビルドと sim の確認はしない** (親が検収でまとめて行う)。

## 報告に必ず書くこと (doc/sig_coverage/report/s2a.md)

1. **根拠の表**: 書いた定数・メソッドの仲間ごとに、読んだ実装のファイルと行 (`パス:行`)。1 つずつでなくてよいが、
   どの定義を見て書いたかが後から追えること。値をそのまま sig に書いたものは、値の出どころも。
2. 書いた数 (定数・メソッド)、素直 / つまずくの内訳、つまずくと判断したものと理由。
3. 実装にあるが書かなかったものと理由 / 判断が要るもの。アプリが使っているのに実装に見つからなかったもの。
4. 数える道具の前後の数、型データベースの大きさの前後。
5. **確かめていないこと** (動かして確かめていない振る舞いなど) を、確かめたことと分けて書く。
6. 迷った所・型紙で足りなかった所。

## 範囲と止まる条件

- 触ってよい: `sig/fmrb_const.rbs`・`sig/math.rbs` (と、既に宣言があるファイルへの追加)・`sdk/` (境界の検査が
  落ちて作り直しが要るときだけ。`ruby tools/boundary/gen.rb`)・`tools/sig_coverage/baseline.json`・
  `doc/sig_coverage/report/s2a.md`・`rake docs:index` による `doc/README.md`。
- 実装・アプリ・ほかの sig の既にある宣言・`sig/README.md`・plan.md・`tools/sig_coverage/` の道具と ignore.yml は
  変えない。
- ビルドをしない (sim・ESP32・ブラウザ版・ネイティブ版とも。`rake clean`・`rake build:*` を流さない)。
- 止まる条件: 定数の定義が見つからない / 型エンジンの試験が sig の追加で落ちて原因が分からない / 生成器が定数の
  宣言を読めない / 範囲の外の変更が要る。止まったら、そこまでをコミットして報告に書く。
- push しない・マージしない。ユーザに質問しない。実在の値 (ドメイン・IP・ノード名・鍵) を書かない。
  コメントとコミットは英語、報告は日本語 (常体)。
