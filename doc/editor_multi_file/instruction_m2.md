## 1. この段で作るもの

M1 の土台 (`editor/docs.rb`、`EditorCore.doc_*`) の上に、利用者に見える形を作る。外から開く・外から
読む書く (plan 4.4・4.5) は M3。**この段では作らない**。

### 1.1 タブの行 (plan 3 章の 1、4.3)
- メニューの行の下に 1 行。**出すのは文書が 2 つ以上のときだけ**。1 つのときは今と同じ画面。
- 2 つ目ができたとき・1 つに戻ったときに、編集の行の数を計算し直して全体を描き直し、カーソルが画面の
  外に出ないようにスクロールを合わせる (全画面の切り替え・フォントの大きさの変更と同じ扱い)。
  行の数を使う所 (スクロール・折り返し・PageUp/Down・マウスの座標→行・補完やヘルプの位置・
  デバッグのペイン) が全部新しい数を見ること。
- タブ 1 つの表示: ファイル名 (パス無し)、無題は今のステータス行と同じ言葉、変更があれば後ろに `*`。
  今の文書は反転 (色はメニューの行・テーマの色から取る。カラーキーの 0x01 を使わない)。
- 幅に入らないとき: 名前を詰める (後ろを切る)。それでも入らなければ、今の文書が見える所から並べる。
- タブをクリックするとその文書に切り替わる。
- M1 の仮の印 (ステータス行の `[i/n]`) は消す。
- Retro (320x240)・Modern (426x240)・Modern の全画面 (640x360) で崩れないこと。

### 1.2 キー (決定、plan 3 章の 5)
- 次 `Alt+.`、前 `Alt+,`、番号で直接 `Alt+1`〜`Alt+5` (その番号の文書が無ければ何もしない)、
  閉じる `Ctrl+W`、新しい無題 `Ctrl+N`。
- `Ctrl+PageDown`・`Ctrl+PageUp` (M1 で足した、sim とネイティブ版は Alt を運べないため) は残す。
- キーの一覧 (Alt+K、`editor/keys.rb`) に載せる。i18n (ja・en) を足す。

### 1.3 File メニュー
- **Open は追加で開く** (plan 3 章の 3)。今の文書が「空で、変更が無く、無題」ならそこに開く。
  同じファイル (同じパス) がもう開いていれば、開かずにその文書へ切り替える。
- **New**: 無題の文書を足す (今ある New があれば、その動きを「足す」に変える。無ければ項目を足す)。
- **Close**: 今の文書を閉じる。変更があれば、今の終了の確認と同じ形のダイアログ (保存する・保存しない・
  やめる) を出す。M1 の「断る」はやめる。最後の 1 つを閉じたら空の無題になる (エディタは終わらない)。
- 上限 (5) を超える・領域が足りない (`EC_ERR_NOMEM`) ときは、開かずにステータス行で知らせ、今の文書を
  壊さない (M1 のまま。Open でも同じになること)。
- Template (File > Template) から作るときの動きは、今の文書が「空・変更なし・無題」ならそこへ、
  そうでなければ新しい文書へ (Open と同じ決まり)。

### 1.4 終了 (Ctrl+X など)
- **変更のある文書が 1 つでもあれば確認する**。変更のある文書ごとに順に、その文書へ切り替えて (中身が
  見える)、今の確認のダイアログを出す。「やめる」を選んだら終了をやめ、その文書に留まる。
  全部に答えたら終了する。
- 今は今の文書の変更しか見ず、ほかの文書の変更を黙って捨てて終わる (M1 の報告)。これを必ず直す。

### 1.5 案内と回帰
- エディタの案内の文書 (`flash/usr/share/doc/` の中のエディタの説明。ja・en。grep で探す) に、複数の
  ファイルの使い方を足す。
- **回帰の場面を 1 つ足す** (`test/regress/screens/`): エディタで 2 つ目の文書を作り (Ctrl+N)、打ち、
  Ctrl+PageUp で戻ると 1 つ目の中身の範囲に戻る、を「範囲が変わった・同じ回の写しと同じ」で判定する
  (全面の基準の PNG は置かない。書き方は doc/regression/usage.md 9 章と、今の `20_editor.rb`・
  `40_keys.rb`)。sim・ネイティブ版の構成に入れる (ブラウザ版に入れるかは、キーが届くかで決める)。

## 2. 受け入れ条件

標準構成 (Spinel) と全部 mruby の構成の両方、sim で確認する (Modern を主に、Retro と Modern の全画面は
標準構成で 1 回ずつ)。**判定はできるだけ中身 (保存したファイル) で**、見た目 (タブの行) は写しで。

1. 1 つのときはタブの行が無く、編集の行の数が今 (develop) と同じ。2 つ目を作るとタブの行が出て、
   1 つに戻ると消える。その前後でカーソルの行が画面の中にある (文書の最後の行にカーソルを置いて確認)。
2. タブのクリックと、Ctrl+PageDown/PageUp で切り替わる。今の文書が反転で分かり、変更の `*` が出る。
   5 つ開いて名前が長いときも崩れない (Retro で確認)。
3. File > Open: 追加で開く・空の無題に開く・同じファイルは切り替える、の 3 つとも。
4. Close: 変更なしは閉じる。変更ありは確認が出て、保存する・保存しない・やめる のどれも正しく動く
   (保存したファイルの中身で確認)。最後の 1 つを閉じると空の無題。
5. 終了: 変更のある文書が 2 つあるとき、2 回聞かれ、それぞれ保存を選ぶと 2 つとも保存されて終わる。
   途中で「やめる」を選ぶと終わらない。変更が無ければ聞かれずに終わる。終了後に文書の領域の使用量が 0。
6. タブの行が出ている状態で、マウスで行をクリックしたときのカーソルの位置、PageUp/Down、補完の候補・
   ヘルプ・検索のダイアログの位置がずれていない。
7. `rake regress` が通る。足した場面を含めて、段の最後に 1 回 `rake regress:screens FULL=1` が通る。
8. `git status` に取りこぼしが無い (前からある `m components/esp_littlefs`・
   `m components/picoruby-esp32/picoruby`・`?? wasm/vendor/`・`?? doc/ai_coding/` は除く。触らない)。

Alt のキー (Alt+. など) は sim で送れないので、コードを読んで Ctrl+PageDown と同じ所を呼んでいることを
確認すれば足りる (実機での確認は親が後で行う)。

確認の型: 直すたびに `rake regress` だけ。`regress:size`・`regress:run`・`regress:checkpoint`・
`regress:wl`・`regress:full` は流さない。ESP32 のビルドはしない。
