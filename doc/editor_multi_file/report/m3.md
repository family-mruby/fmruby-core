# M3 報告: 外から開く、外から読む・書く (AI 連携の口)

> 状態: 完了 | 更新: 2026-11-18 | エディタが動いているときにエディタを起こす頼みが来たら、カーネルは 2 つ目を起こさず、動いているエディタに `open_file` を送って前に出す。エディタは File > Open と同じ決まりで開き、ダイアログやメニューが出ている間は閉じるまで待つ。端末の中のアプリは `ai_read` で今の文書を `/tmp/ai_doc.rb` に書き出させ、`ai_replace` で版が同じときだけ入れ替えさせる。文書の版は C の通し番号。標準構成 (Spinel) と全部 mruby の構成の sim (Modern)、Retro の sim、ネイティブ版、ブラウザ版で確認した。指示書は instruction_m3.md

## 1. 起動の入口と、2 つ目が来たときの動き

### 1.1 入口の一覧

| 入口 | エディタを起こす経路 | 前 (M2 まで) | 後 (M3) |
|---|---|---|---|
| ファイルマネージャの関連付け (ダブルクリック・Enter、表が edit のとき) と右クリックの Edit | `spawn_app("default/editor", path)` → カーネルの `spawn` | Spinel: 2 つ目のタスクが `fmrb_app_spinel_claim` で断られ、「This app is already running.」のエラーのダイアログ。ファイルは開かれない。mruby: 2 つ目のエディタが起きる | 動いているエディタに `open_file` が届いてタブが足される (同じなら切り替え、6 つ目は「Max 5 files open」)。エディタが前に出る |

### 1.2 カーネル (main/ruby/kernel/)

- `fmrb_kernel.rb` の `spawn`: `return if hand_to_running_editor(app_name, pid, data["open_path"])` の 1 行。`focus_app` の中身は `focus_app_pid` に移した (動きは同じ)。
- `fmrb_kernel/app_lifecycle.rb`:
  - `@editor_pid` (初期値 -1)。`after_spawn` の中の `note_editor` が、名前 `FM-Editor` のアプリが起きたときに覚える (カーネルの spawn と C からの `spawned` の両方がここを通る)。`cleanup_terminated_app` が忘れる。使う前に `_get_app_info` で名前を照らす (`running_editor_pid`)。
  - `hand_to_running_editor`: 名前が `default/editor`・`default/editor_fs` で、動いているエディタがあれば、パスがあるとき `{"cmd" => "open_file", "path"}` を送り、`focus_app_pid` で前に出し、頼んだ側に `spawn_result` (pid はそのエディタ) を返す。
- 端末ごとの分岐は無い (sim・ネイティブ版・ブラウザ版・ESP32 で同じ Ruby)。

### 1.3 spawner (main/app/fmrb_app_spawner.c)

`spawn_builtin_app` の頭で、表の名前が `default/editor` で始まる項目 (窓と全画面の 2 つ) について、同じ名前 (`FM-Editor`) で止まりかけ (`PROC_STATE_STOPPING`) でない文脈を探す。あればその pid を答え、`{"cmd":"focus_app","pid":N}` をカーネルに送って `FMRB_OK` を返す (`spawned` は送らない)。ほかの組み込みアプリとファイルのアプリは素通り。カーネルの Ruby が先に受けるので、ここに来るのは C から直接呼ぶ口だけ。

## 2. エディタの側 (main/ruby/default_app/editor/remote.rb、新)

- `on_control` に `open_file`・`ai_read`・`ai_replace` を足した。`file_selected` は、mode が `open` でエディタ自身が Open を頼んでいない (`@pending_file_op != :open`) とき、外からの頼みとして `open_file` と同じに扱う。
- **待つ条件** (`remote_busy?`): 保存の確認 (`@quit_dialog_open`)、名前を待っている保存の確認 (`@after_save != 0`)、ファイルの窓の答え待ち (`@pending_file_op`)、メニュー、検索、色、キーの一覧、補完の候補、デバッガの選択。待っているファイルは 1 つ (`@open_waiting`、後から来たものが勝つ)。`on_update` が毎回見て、条件が外れたら `docs_open_path` で開く。ヘルプ (F1) は待つ条件に入れていない (`docs_open_path` がヘルプを閉じてから開く。M2 のまま)。
- ファイルの窓を Cancel したとき、`@pending_file_op` も消すようにした。今まで Cancel の後も `:save` が残り、次にエディタが頼まずに受けた `file_selected` (シェルの `edit`) を「名前を付けて保存」の答えと取り違える余地があった。これが残ると「答え待ち」で開くのが永久に待つので、この段で直した。
- 足した ivar は `EditorApp` の `@open_waiting` (文字列) 1 つ。基底には足していない。

## 3. 知らせの最終の形

すべて `send_message(pid, FmrbConst::MSG_TYPE_APP_CONTROL, hash)`、入れ子の無い Hash。

| 向き | cmd | 項目 |
|---|---|---|
| カーネル → エディタ | `open_file` | `path` |
| アプリ → エディタ | `ai_read` | `re` (答える pid、整数。無ければ答えずにログ)、`id` (整数。無ければ 0) |
| エディタ → アプリ | `ai_doc` | 成功: `id`・`ok` 1・`ver`・`n` (行の数)・`b` (バイト)・`y`・`x` (カーソル、行と文字の位置。0 始まり)・`sy`・`sx` (選択の起点、無ければ -1)・`m` (変更の印 1/0)・`f` (パス。無題は `""`、60 バイトを超えれば名前だけ)・`rp` (直前の F5 の pid、無ければ -1)。本文は `/tmp/ai_doc.rb`。失敗: `id`・`ok` 0・`why`・`ver` (今の版) |
| アプリ → エディタ | `ai_replace` | `re`・`id`・`ver` (読んだときの版)・`p` (入れ替える本文のファイル)・`y`・`x` (入れ替えた後のカーソル。範囲に収める) |
| エディタ → アプリ | `ai_done` | `id`・`ok`・`ver` (成功なら入れ替えた直後の版、失敗なら今の版)・`why` (失敗のとき) |

断る理由: `busy` (2 章の待つ条件のどれか)、`help` (F1 のヘルプが文書の代わりに出ている)、`ver` (版が違う。`ai_replace` だけ)、`io` (書けない・読めない、`p` が無い)、`nomem` (文書の領域が足りない)。

### 3.1 a0.md 3.2 から変えた所

1. **本文のファイルは `/tmp/ai_doc.rb` と、頼む側が決める `p`** (a0 は `/tmp/ai/doc.rb`・`/tmp/ai/new.rb`)。`/tmp` は平らで、サブディレクトリを作れない (`components/fmrb_hal/fmrb_tmpfs.h`「v1 is a flat directory」。sim の HAL も `/tmp holds files, not subdirectories` で断る)。最初の形で試すと `io` で断られて分かった。試験のアプリは `/tmp/ai_new.rb` を使う。
2. **失敗の `ai_doc` にも `ver`** を付けた (a0 は `ai_done` だけ)。断られたときに今の版が分かる。
3. **入れ替えは `load_file` でなく新しい `EditorCore.replace_file`**。`ec_load_file` は読み始めてから失敗すると文書を空にする (今のまま、File > Open の決まり)。AI の入れ替えで文書を失わないよう、新しい本文を別に読んで全部読めたときだけ差し替える口を足した (その間は新旧が両方領域にある)。見える動きは a0 のまま。

### 3.2 大きさの実測 (試験のアプリで `MessagePack.pack(msg).bytesize`)

- `ai_doc` 成功: 66 B (`f` が `/tmp/m3a.rb` の 11 バイト、版などが 1 バイトの整数)。`f` が上限の 60 バイトで 115 B、整数がすべて 5 バイトになっても 135 B 程度の見込みで、176 B に収まる。
- `ai_doc`・`ai_done` の断り: 32〜34 B。`ai_done` 成功: 26 B。
- `open_file`: 約 21 B + パスの長さ。パスが 150 バイトを超えると 176 B を超える (確認していない。そのときの `_send_raw_message` の動きも見ていない)。

### 3.3 文書の版 (lib/gems/picoruby-fmrb-editor-core)

- `editor_core.c`: `g_edit_seq` (PSRAM、`FMRB_EXT_RAM_BSS_ATTR`) と `ed_doc_t.ver` (`g_docs` は PSRAM)。`doc_touch` が `ver = ++g_edit_seq`。呼ぶのは `ec_reset`・`ec_insert_text`・`ec_split_line`・`ec_join_line`・`ec_delete_char` (消したときだけ)・`ec_delete_range`・`ec_insert_multiline`・`ec_paste_at`・`ec_load_file`・`ec_replace_file`。途中で失敗したものも、文書が変わりうるので進める。
- `ec_doc_version(slot)` は 31 ビットに丸めて返す。読み込みのループは `doc_read` に分けて `ec_load_file` と `ec_replace_file` で使う。
- `EditorCore.doc_version`・`EditorCore.replace_file` を Spinel の FFI (`fmrb_editor_ffi.rb`・`fmrb_spx_editor.c`) と mruby の束ね (`editor_core_mrb.c`) に足した。

## 6. カーネルの変更の大きさ

- Ruby: `spawn` に 1 行、`focus_app` を `focus_app_pid` に移し、`app_lifecycle.rb` に 5 つのメソッドと定数 1 つ、ivar `@editor_pid` 1 つ (VM のヒープ、整数)。`cleanup_terminated_app` に 1 行。
- スタック (ホストの x86-64、sim と同じフラグに `-fstack-usage` を足して、変更前と後の生成 C を比べた。ESP32 では測っていない): `handle_app_control` 2448 → 2416 B (-32)、`after_spawn` 512 → 544 B (+32、`note_editor` がインラインされた分)。`handle_app_control` から `after_spawn` を呼ぶ深さは 2960 B で同じ。`after_spawn` をほかから呼ぶ道 (チェックポイントの再開、Editor RUN の再起動) は 32 B 深い。最初の形 (`spawn` の中で pid を局所変数に取る) では `handle_app_control` が +16、`after_spawn` が +32 だったので、判定ごと 1 つのメソッドに移して減らした。
- 内蔵 RAM: 増やす静的な変数は無い。版の番号は PSRAM (`g_edit_seq` 4 B、`ed_doc_t` に 4 B × 5)。spawner の足し分は関数だけ (知らせは既存の `fmrb_msg_t` をスタックに 1 つ、`notify_kernel_app_spawned` と同じ形)。`rake regress:size` は流していない (指示どおり。親が後で行う)。
- ほかのアプリの起動は変えていない (エディタの 2 つの名前だけを見る)。

## 7. AI 連携アプリ (A2・A3) を作る人への引き継ぎ

```ruby
ed = FmrbApp.ps.find { |p| p[:name] == "FM-Editor" }      # 無ければエディタが動いていない
send_message(ed[:id], FmrbConst::MSG_TYPE_APP_CONTROL,
             { "cmd" => "ai_read", "re" => FmrbApp.pid, "id" => 1 })
# on_control で {"cmd"=>"ai_doc", "ok"=>1, "ver"=>v, ...} を受け、/tmp/ai_doc.rb を読む
File.open("/tmp/ai_new.rb", "w") { |f| f.write(new_text) }
send_message(ed[:id], FmrbConst::MSG_TYPE_APP_CONTROL,
             { "cmd" => "ai_replace", "re" => FmrbApp.pid, "id" => 2,
               "ver" => v, "p" => "/tmp/ai_new.rb", "y" => 0, "x" => 0 })
# {"cmd"=>"ai_done", "ok"=>1, "ver"=>新しい版} か {"ok"=>0, "why"=>"ver"|"busy"|"help"|"io"|"nomem"}
```

- `/tmp` にディレクトリは作れない。ファイル名で分ける (`/tmp/ai_*.rb`)。sim では mruby の `Dir.mkdir("/tmp/ai")` が通ってしまう (HAL の `mkdir` は断らない) が、そこへのファイルの書き込みは断られる。
- 本文の末尾の改行は残らない (エディタの文書は行の並び。26 B のファイルを開いて書き出すと 25 B)。`b` は書き出した大きさ。
- 版は全文書で 1 本の通し番号。読んだ後にタブを切り替えると、切り替え自体では変わらないが、相手が別の文書になるので `ver` で断られる。F1 のヘルプを開いて閉じると、ヘルプの頁の読み込みと文書の戻しで版が進む (ヘルプの前に読んだ版では断られる)。
- `busy` と `help` は待たずに返す。頼み直すのはアプリの側 (例: 1 秒後にもう一度)。
- `rp` は直前の F5 の pid。エラーの文は `FmrbApp._get_last_error` (a0.md 3.2 のまま)。
- 開くのは AI 用の口を作っていない。`spawn` の頼み (`{"cmd"=>"spawn","app_name"=>"default/editor","open_path"=>path}` をカーネルへ) で、動いていればタブに足される。
- Spinel のエディタの `on_control` は値を `is_a?(Integer)`・`is_a?(String)` で絞って読む。`re`・`id`・`ver`・`y`・`x` は整数、`p` は文字列で送ること (違う型は無いものとして扱う)。

## 10. 今の不具合 (この段では直していない)
