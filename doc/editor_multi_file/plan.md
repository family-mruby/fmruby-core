# エディタで複数のファイルを同時に開く

> 状態: 進行中 | 更新: 2026-11-18 | エディタは Spinel の制約 (同じプログラムは 1 つだけ) で同時に 2 つ起動できない。代わりに 1 つのエディタの中で 5 つまでのファイルを開き、タブの行で切り替える。外 (ファイルマネージャ・デスクトップ) から開いたファイルは、動いているエディタに渡して追加で開く。AI 連携 (doc/ai_coding) がエディタを外から読む・書く口も M3 で作る。M1〜M3 済 (ブランチ editor-multi-file、develop へは未取り込み。report/m1〜m3.md)。残り: ESP32 での確認、内蔵 RAM と VM プールの確認 (regress:size・run)、朝にユーザが仮決めを見る

## 1. 目的

- エディタ (標準構成は Spinel) は同時に 2 つ起動できない。Spinel の生成プログラムが状態をファイル単位の
  変数に持つためで、根本の対策は保留している (doc/spinel_multi_instance/plan.md の A2)。
- このため「見本を見ながら自分のファイルを書く」「2 つのファイルの間で写す」ができない。
- 1 つのエディタの中で複数のファイルを持てば、この制約に当たらずに同じことができる (2026-11-17 ユーザ)。

## 2. 分かっていること (2026-11-17、コードを読んだ範囲。試作はしていない)

- **本文は C 側にあり、もう複数持てる**: `lib/gems/picoruby-fmrb-editor-core/ports/esp32/editor_core.c` の
  `g_docs[ED_MAX_DOCS]` (`ED_MAX_DOCS` = `FMRB_USER_APP_COUNT` = 5)。`ec_*`・`et_*` (型支援) の全部の関数が
  slot の番号を取る。同時起動ができた頃の作り。
- **Ruby 側が持つのは表示の状態だけ**: `main/ruby/default_app/editor.app.rb` の `@cx`・`@cy`・`@scroll_y`・
  `@anchor_seg`・`@scroll_x`・`@wrap_on`・`@cur_line_segs`・`@modified`・`@current_file`・選択
  (`@sel_anchor_x/y`)・ハイライト (`@hl_enabled`・`@hl_manual`) など。本文の文字列は持たない。
- **slot はエディタ 1 つに 1 つと決め打ち**: Spinel 版は `main/app/fmrb_spx_editor.c` の `s_slot_plus1`
  (最初の `open_slot` が開き、以後は同じ番号を返す)、mruby 版は `editor_core_mrb.c` の `g_vm_slots`
  (`mrb_state` ごとに 1 つ)。Ruby 側の `EditorCore` (Spinel 版は `main/ruby/spinel/fmrb_editor_ffi.rb` の shim) は
  slot を引数に取らず、呼ぶたびに C に聞く。
- **クリップボードは端末の共有** (`ec_copy_range`・`ec_paste_at`)。ファイルの間の貼り付けはそのまま通る。
- **文書の領域は全部合わせて 1 MB** (`POOL_ID_EDITOR_DOC`、PSRAM)。型支援は文書を丸ごと写す作業の領域を
  同じ領域から取る (`et_serialize`)。
- **折り返しのキャッシュは slot をまたいで 1 つ** (`g_wrap`、鍵に slot が入っている)。
- **外からの知らせの経路がある**: エディタは `on_control(msg)` で `file_selected`・`run_result` を受けている。
- **2 つ目の起動を断る所**: `fmrb_app_spinel_claim` (main/app/fmrb_app.c)、呼び出しは
  `main/app/fmrb_app_spawner.c`。エディタは組み込みで、ランチャーの一覧には出ない。

## 3. 決めたこと (2026-11-17 ユーザ)

1. **表示はタブの行を 1 行足す**。メニューの行の下。Retro でも Modern でも同じ。
   **タブの行を出すのは 2 つ以上開いているときだけ**。1 つのときは今と同じ画面 (編集の行は減らない)。
   ```
   File Edit Run View
   [a.rb][main.app*][lib.rb]
   ------------------------------
    1 def hello
   ```
2. **上限は 5** (C 側の表のまま)。
3. **File > Open は追加で開く**。今の文書が空で変更の無い無題なら、そこに開く。同じファイルがもう開いて
   いれば、そこへ切り替える。閉じるのは File > Close。
4. **外から開いたファイルは、動いているエディタに渡して追加で開く**。最初に出す版から入れる
   (エディタの中だけを先に出すことはしない)。

5. **キー** (選択肢で回答): 次の文書 `Alt+.`、前の文書 `Alt+,`、番号で直接 `Alt+1`〜`Alt+5`、閉じる `Ctrl+W`。
6. **AI 連携アプリがエディタを外から操作する I/F を、この改修と一緒に作る** (M3。要件は doc/ai_coding/plan.md の 5 章)。

## 4. 方針

### 4.1 slot の切り替え (C の束ね)
- 束ねが「このエディタが持つ slot の組 (5 つまで) と、今の slot」を持つ。Ruby 側の `EditorCore` の呼び方
  (slot を渡さない) は変えない。足す口は「文書を足す」「今の文書を切り替える」「文書を閉じる」の 3 つ程度。
- Spinel 版 (`fmrb_spx_editor.c`) と mruby 版 (`editor_core_mrb.c`) を同じ形にする。エディタのソースは
  両方の構成で同じものを使う。
- エディタが終わった・殺されたときに、持っていた slot を全部返す (今の `fmrb_spx_ec_release_slot` と
  `slot_release` を組の分に広げる)。

### 4.2 ファイルごとの状態 (Ruby)
- 2 章の表示の状態を、文書ごとに保存して戻す。切り替えは「今の状態を保存 → slot を切り替え → 状態を戻す →
  全体を描き直す」。
- 持ち方は Spinel で型が絞れる形にする (整数の配列・文字列の配列を項目ごとに並べる、など。Hash に
  混ぜた型を入れない)。持ち方は最初の段でサブが試して決め、report に書く。
- 文書をまたいで 1 つでよいもの (メニュー・検索の語・フォントの大きさ・全画面・デバッグのペイン・実行中の
  pid) と、文書ごとのもの (カーソル・スクロール・選択・変更の印・ファイル名・ハイライト・折り返し・
  型支援の診断) を最初の段で仕分ける。

### 4.3 タブの行と操作
- タブの行は 1 行。名前はファイル名 (パス無し)、無題は今の無題の表示、変更があれば `*`。今の文書を
  反転で示す。幅に入らないときは名前を詰め、それでも入らなければ今の文書が見える所から並べる。
- クリックで切り替え。キーは 6 章の仮決め。
- 文書が 1 つのときはタブの行を出さない (3 章の 1)。2 つ目を開いたとき・1 つに戻ったときに編集の行が
  1 行増減するので、そのときは行の数を計算し直して全体を描き直し、カーソルが見える所に留まるように
  スクロールを合わせる (全画面の切り替え・フォントの大きさの変更と同じ扱い)。
- File メニュー: Open (追加)、New (無題を追加)、Close (今の文書。変更があれば今の「保存しますか」)。
  最後の 1 つを Close したら空の無題になる (エディタは終わらない)。
- 終了 (Ctrl+X): 変更のある文書が 1 つでもあれば確認する。文書ごとに順に聞く。
- 上限の 5 つを超えて開こうとしたら、開かずにステータス行で知らせる。領域が足りないとき
  (`EC_ERR_NOMEM`) も同じ。今の文書は壊さない。
- 実行 (F5) は今の文書を実行する (今の動きのまま)。

### 4.4 外から開く
- エディタが動いているときに、エディタでファイルを開く起動 (ファイルマネージャの関連付け、
  デスクトップからの起動) が来たら、カーネルが 2 つ目を起こさず、動いているエディタに
  `on_control` の知らせ (`cmd: "open_file"`, `path`) を送り、エディタを前に出す。
- パス無しの起動 (デスクトップのメニューからエディタ) は、動いているエディタを前に出すだけ。
- エディタはそれを 3 章の 3 と同じ決まりで開く (追加・同じファイルなら切り替え・上限なら知らせる)。
- sim・ネイティブ版・ブラウザ版・ESP32 で同じ経路にする (カーネルの Ruby と spawner の範囲で、
  端末ごとの分岐を作らない)。

### 4.5 外から読む・書く (AI 連携の I/F。M3)
- 4.4 と同じ知らせの経路 (`on_control`) に載せる。頼めるのは端末の中のアプリだけ。**本文を書き換えるのは
  エディタ自身だけ**で、外のアプリは頼むだけ。
- **読む**: 今の文書の中身・ファイル名・行の数、カーソルと選択の位置、変更の印、直前の実行 (F5) のエラー、
  **文書の版** (編集のたびに変わる番号。読んだ時点の中身と組で返す)。
- **書く**: 今の文書を丸ごと入れ替える。指定した行の上にコメントの行を入れる。決まった印で始まるコメントの
  行を数える・消す。**書く頼みには読んだときの版を付け、今の版と違えばエディタは入れずに断る** (断ったことと
  今の版を返す)。
- 文書が知らせ 1 つに載らないときは `/tmp` のファイルを介す。知らせと答えの形 (cmd の名前・項目) は
  doc/ai_coding/report/a0.md の案を元に M3 の指示書で決める。
- エディタがダイアログを出している最中の頼みは、断って理由を返す (待たせない)。

## 5. 段階

3 つの段に分けてサブに渡すが、**develop に入れるのは 3 つ揃ってから** (3 章の 4)。

| 段 | 中身 | 見るもの |
|---|---|---|
| M1 | slot の切り替え (4.1) と状態の出し入れ (4.2)。仮のキーで New・切り替え・Close ができる。タブの行はまだ無い | 2 つの文書の間で、本文・カーソル・スクロール・変更の印が混ざらない |
| M2 | タブの行、File メニュー、終了の確認、上限と領域切れの知らせ (4.3)。キーの一覧 (Alt+K)・i18n・案内の文書 | Retro・Modern・全画面で行の数と描き直しが合う。1 つ⇔2 つでタブの行が出入りしてもカーソルが画面の外に出ない |
| M3 | 外から開く (4.4)、外から読む・書く (4.5) | 動いているエディタに 2 つ目・同じファイル・6 つ目を渡したとき。試験用のアプリから読む・書く・版が違うと断る |

- **M2 済 (2026-11-18)**: report/m2.md。タブの行 (`editor/tabs.rb`、高さ 10 px、2 つ以上のときだけ)、File > New・Close、
  閉じる・終了の確認。File > Exit も変更があれば確認を通すようになった。回帰の場面 `editor_docs` を足した。
- **M3 済 (2026-11-18)**: report/m3.md。カーネルの `spawn` が動いているエディタに `open_file` を渡して前に出す
  (debug・遠隔操作の launch は今のエディタの pid を返す)。文書の版 (`EditorCore.doc_version`)、`ai_read`・
  `ai_replace` (本文は `/tmp/ai_doc.rb` と頼む側の決める `p`。`/tmp` は平らでサブディレクトリを作れない)。
  試験用のアプリ `flash/app/test/ai_editor_probe.app.rb`。
- **M1 済 (2026-11-17)**: report/m1.md。C 側は `ec_docset_t` (組と今の slot)、Ruby からは `EditorCore.doc_add`・
  `doc_switch`・`doc_close`・`doc_count`・`doc_index`。文書ごとの状態は整数の配列 `@doc_ints` と文字列の配列
  `@doc_files` (editor/docs.rb)。型支援の答えの表を、どのエディタも文書を持たなくなったら返すようにした
  (終了後の文書の領域の使用量が 0 に戻る)。領域切れは起こして確認していない。

## 6. 仮決め (親。違えば直す)

- キーは決定 (3 章の 5)。`Ctrl+Tab` はデスクトップのアプリの切り替えなので使わない。`Alt+W` (折り返し) は
  今のまま。新しい無題は `Ctrl+N` (M1 で足した)。
- **sim とネイティブ版は Alt を運べない**ので、同じ動きの `Ctrl+PageDown`・`Ctrl+PageUp` も残す (M1 で足した。
  それまで Ctrl+PageUp/Down は修飾なしの PageUp/Down と同じ動きだった)。
- 型支援の診断は文書ごとに持たず、切り替えで消す (M1 のまま)。
- デバッグを始めたときに仕掛けるブレークポイントは、今の文書のファイルの分だけ (今のまま。`@bp` は
  パスごとの表なので、名前のある文書ではファイルごとに分かれている)。
- タブの行の高さは文字 1 行分 (8 px + 余白)。色はメニューの行に合わせ、テーマの色から取る。
- 文書ごとの状態は VM のヒープに置く (5 つで数百バイト)。

## 7. 受け入れ条件

1. 5 つまで開けて、切り替えても本文・カーソル・スクロール・選択・変更の印・ファイル名・ハイライトが
   文書ごとに保たれる。標準構成 (Spinel) と全部 mruby の構成の両方。
2. 文書の間でコピー・貼り付けができる。
3. 6 つ目、領域切れ、同じファイルの 2 回目が 4.3 のとおりに動き、今の文書が壊れない。
4. エディタを終えた・殺した後に、文書の領域の使用量 (`ec_mem_used`) が起動前に戻る (slot の返し忘れが無い)。
5. 外から開く (4.4) が sim・ネイティブ版・ブラウザ版で動く。
6. 型支援 (F1・Ctrl+T・Ctrl+E)・検索・デバッグのペイン・実行 (F5) が、切り替えた後も今の文書に対して動く。
7. **内蔵 RAM が増えない** (`rake regress:size`)。VM プールの増え方は KB 未満 (`rake regress:run`)。
8. `rake regress` が通る。エディタの 1 打鍵の確認 (`rake regress:screens`) が通る。文書の切り替えの場面を
   回帰の道具に 1 つ足す。
9. ESP32 (Tab5 か P4-Nano) で、タブの表示・切り替え・外から開くをユーザが目視する。

## 8. 範囲の外

- 画面を分けて 2 つの文書を並べて見ること。
- 文書の領域 (1 MB) を増やすこと、文書ごとの上限。
- 開いていたファイルを次の起動で戻すこと。
- アンドゥ (今のエディタに無い)。
- Spinel の同時起動の根本の対策 (doc/spinel_multi_instance の A2)。
