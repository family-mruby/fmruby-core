# T1 レポート: イベント列テスト

段 3 の 1 段目。計画は `doc/ui_widgets/plan_s3.md` の T1、背景は
`issues_s3.md` の課題 C。

## やったこと

`test/fmrb_ui/run.rb` の events セクションの後に「event sequences」の節を
足した。既存の検査は 1 行も変えていない。

ヘルパは 3 つ。いずれもホストの CRuby で走るだけなので、実機側の書き方の
規則 (while のみ・ブロック禁止) の対象外。

```ruby
def feed(ui, seq)  = seq.map { |e| ui.handle(e) }   # nil も捨てずに並べる
def fires(ui, seq, id) = feed(ui, seq).count(id)    # 何回 act したか
def click_seq(x, y)  = [down(x,y), up(x,y)]
def cancel_seq(x, y) = [down(x,y), up(離れた所)]
```

**戻り値を 1 つ見るのでなく、列を流して発火回数を数える**形にした。課題 C の
2 段送り (症状 4) は「押下でも離しでも正しく見える」ので、回数でしか
捕まらない。

## 検査した内容

部品 7 種 (Button / Toggle / Stepper / Enum / TextField / Label / Scrollbar)
を 1 つの UI に並べ、それぞれに:

| 検査 | 期待 |
|---|---|
| 1 クリック (down + up) | id がちょうど 1 回 |
| down は部品内・up は部品外 | 0 回 (状態も変わらない) |
| 2 周 (down/up を 2 回) | 2 回。状態が残らない |
| Scrollbar (`fires_on_press?`) | down で 1 回、up で 0 回 |
| TextField | クリックは 0 回 (焦点を取るだけ)、Enter で 1 回 |
| Label | 何をしても 0 回 |

症状 4 の実列 (スクロールバー矢印の 1 クリック) はそのまま回帰にした。
値が 5 -> 6 と**1 段だけ**動くこと、2 クリックで 2 段動くこと、端では
両方の半分とも黙ること、を固定している。

## 壊れていたときに落ちるか

`handle` の

```ruby
on_press = w.fires_on_press?
fired = w.activate if on_press == false
```

を修正前の `fired = w.activate` に戻して走らせると **10 項目が FAIL** する
(うち回帰の 4 項目)。網として効いている。

## 結果

`ruby test/fmrb_ui/run.rb` -> 138 項目全通過 (既存 112 + 新規 26)。
既存項目に影響なし。
