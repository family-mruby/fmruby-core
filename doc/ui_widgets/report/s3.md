# S3 レポート: TextField

段 2 の 3 段目。計画は `doc/ui_widgets/plan_s2.md`。実装中の経緯も残す
(同じ間違いを繰り返さないため)。

## TextField

```ruby
@ui.text_field(:name, 46, 3, 120, 12, "song", max: 16)
@ui.field_text(:name)          # 打たれている文字
@ui.set_field_text(:name, "x") # 外から入れ直す
@ui.focus(:name)               # 焦点を当てる (nil で外す)
@ui.focused                    # 焦点のある部品の id か nil
```

- **クリックで焦点が移り、Enter で `handle` が id を返す**。Esc で焦点が外れる。
- **カーソルは点滅しない**。点滅は毎フレーム描くことになり、この部品群の
  絶対条件に反する。焦点がある間ずっと線が出ているだけ。
- **矢印キーも挿入位置も無い**。末尾に足し、末尾から消すだけ。欄が欲しかった
  2 箇所 (ファイル名、検索語) が実際にやっているのはこれ。編集カーソルは
  必要になってから。

### `handle` がキーを見るようになった

段 1 以来 `handle` は `:mouse_down` / `:mouse_up` 以外を即 nil で捨てていた。
入れ方はこうした:

```ruby
if t != :mouse_down && t != :mouse_up
  return nil if @focus.nil?      # 焦点が無ければ従来どおり即 nil
  return nil if t != :key_down
  return type_into_focus(ev)
end
```

**mouse_move の経路は比較 1 回だけ増える** (`@focus.nil?`)。「1 命令も
変わらない」と計画に書いたが正確ではないので、ここで訂正しておく。焦点が
無ければ部品には一切届かない、という保証はテストで縛った。

### 名前は `field_text`

`option_text` と同じ理由。`GfxBlock::Recorder` が `draw_text` の別名として
4 引数の `#text` を持つので、poly 受信の `text` を作らない。

## 実装中に直したこと (経緯)

### 1. 焦点を当てることと確定することが同じになっていた

最初の実装は `TextField#activate` が true を返していたため、**欄をクリック
しただけで `handle` が id を返していた**。アプリから見ると Enter と
区別できず、**打ちかけの値で動いてしまう**。

`activate` を false に変えた。焦点の移動は `handle` が hit 時に
`set_focus(w)` を呼ぶので、false でも問題なく移る。

**ホストのテストでは気づけなかった**。「クリックすると焦点が移る」ことは
`focused` で確認していたが、**戻り値を見ていなかった**。sim の一時アプリで
ログを出して初めて分かった。テストに
`check("clicking a field reports nothing", ..., nil)` を足した。

### 2. FakeGfx に `draw_line` が無かった

TextField のカーソルで初めて落ちた。**Scrollbar も `draw_line` を使うのに、
S2 のテストは一度も Scrollbar を flush していなかった** —
描画経路が丸ごと未検査だった。`draw_line` を足し、ついでに
「バーが矢印とつまみを描く」「収まるときは背景しか描かない」も足した。

教訓: **部品を足したら `flush` させるテストを 1 本は書く**。値と当たり判定
だけ試していると、描画側の穴に気づかない。

### 3. `rake clean` を忘れた

`lib/` の `fmrb-ui.rb` を直したあと `rake build:linux` だけ回し、
**古い `fmrb-ui.rb` がリンクされたまま** sim で確認して「直っていない」と
誤診しかけた。CLAUDE.md に明記されている罠をそのまま踏んだ。
lib/ を触ったら `rake clean` を挟む。

## file_selector の移植は S4 に送る

計画では S3 の確認先を `file_selector` の保存モードにしていたが、**S4 に
移す**。理由:

- `file_selector.rb` は `system_desktop` の mixin で、デスクトップはまだ
  FmrbUI を持っていない。1 つの欄のために `@ui` を持ち込むと、**ダイアログの
  座標系 (開くたびに位置が動く / fullscreen で user area 原点が (0,0))**
  という S4 の主題にそのまま当たる。
- そこを片付けるのは S4 の仕事で、**先に 1 箇所だけやると同じ作業を 2 回
  する**ことになる。

S3 では部品とテストを仕上げ、見た目と操作は一時アプリで確認した
(`flash/app/test/ui_field.app.*`、コミットしない)。

## 確認

| 項目 | 結果 |
|---|---|
| `rake ui:test` | **99 項目** (S2 の 73 + TextField 21 + 描画 5) |
| `rake test` 全体 | 通過 |
| sim: 焦点 | クリックで枠がハイライト、カーソル線が出る。別の欄をクリックすると移る |
| sim: 入力 | 文字が末尾に付く、Backspace で消える、max で止まる |
| sim: 確定 | **Enter でだけ id が返る** (クリックでも打鍵でも返らない) |
| sim: Esc | 焦点が外れ、以後のキーが届かない |
| sim: 焦点の解除 | スクロールバーをクリックすると `focus=nil` になる |
| 回帰 | logviewer / shell / kamon 従来どおり、例外 0 |

## S4 への申し送り

- デスクトップに FmrbUI を持ち込むときの順番: **座標系を最初に小さく試す**
  (fullscreen の user area 原点、ダイアログの `set_origin` + `move`)。
- `smf_player` のボタン 7 個 (S2 で見つけた積み残し) も、テンポの
  `< x1.0 >` が Enum に、Play/出力が Toggle になる。S4 のついでに。
- 基底の `draw_scrollbar` / `scrollbar_hit` の削除は S4 の最後。
