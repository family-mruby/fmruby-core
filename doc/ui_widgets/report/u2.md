# U2 レポート: midi_apu と Spinel

対象: doc/ui_widgets/instruction_u2_u3.md の U2 (T1 / T2 / T3)。

## 結論を先に

- **Spinel は基底型の変数経由の仮想ディスパッチを扱える**。U1 の申し送りで
  最大の懸念だった `@pressed.activate` は書き換え不要だった
  (`@pressed_kind` + case の逃げ道は使っていない)。生成 C の証拠は下記。
- ただし**別の落とし穴を踏んだ**: poly 受信のメソッド名は、同名メソッドを
  プログラム中から全部引きずり込む。`Widget#draw` を `#draw_widget` に
  改名して解決した (下記)。
- `FMRB_APP_ENGINE_DESKTOP=spinel` のビルドは **T1 の `_send_audio_note`
  だけでは通らなかった**。同種の欠落を 2 つ追加で埋めたが、最後に
  FmrbUI と無関係な**型推論の壁**が 1 つ残っている (下記 T1)。
- `rake spinel:doctor` の **fmrb-ui.rb に対する指摘は 0**。kernel と editor
  は clean、system_desktop の指摘 1 件は上記の残件。

## T1 (独立コミット): Spinel 基底の欠落メソッド

指示書は `_send_audio_note` 1 つと書いていたが、実際には**同じ性質の欠落が
3 つ**あった。いずれも「mruby では `respond_to?` や動的ディスパッチで済んで
いるが、Spinel は静的に解決するので呼び出しが必ず残る」もの。

| 追加したもの | なぜ要るか |
|---|---|
| `FmrbApp#_send_audio_note(on, ch, freq, vol, duty, sweep)` | `fmrb-audio.rb` が `respond_to?` の分岐から呼ぶ。C は `fmrb_spx_app_send_audio_note` を新設し、mruby と同じ `fmrb_app_send_audio_note()` を呼ぶので**バイト列は同一** |
| `FmrbApp#idle_gc=` / `#idle_gc` | `system_desktop.app.rb` が `self.idle_gc = true` を呼ぶ。Spinel の GC は incremental でも scheduler-driven でもないので**中身は no-op**、`idle_gc` は正直に false を返す |
| `FmrbApp#closable` (attr_accessor と `@closable = true`) | デスクトップが `self.closable = false` を呼ぶ。**同時に mruby 側で直した閉じるボタンのバグが Spinel 基底に残っていた**ので合わせて移植した (down を取り逃した時の保険が `!@fullscreen && @gfx` を見ておらず、フルスクリーンアプリの右上クリックで黙って停止しうる) |

C 側の追加は 1 対:
`main/app/fmrb_spx_app.h` / `.c` に `fmrb_spx_app_send_audio_note()`、
`main/prebuild_scripts/spinel/fmrb_app_ffi.rb` に `ffi_func` 宣言。

### 残件: desktop-Spinel を止めている最後の 1 件 (本計画の対象外)

```
spinel: system_desktop_combined.rb:7494: unsupported call:
  node 27314 (CallNode `[]`) recv=LocalVariableReadNode/ty17 argc=1 arg0ty6
```

`system_desktop.app.rb#load_shortcuts` の

```ruby
entries = FmrbApp.config("shortcuts")
e = entries[i]
key = e["key"]        # <- ここ
```

`config` が `tables = []` に `<<` で Hash を積んで返すため**要素型が確定
せず**、String キーの `[]` が出せない。`launcher.rb#launcher_exclude_dirs`
も同型。試したが効かなかったこと: `config` の戻りを `nil` ではなく常に
Array にする (nil 由来ではないので変わらない。**この変更は戻した**)。

**FmrbUI とも `_send_audio_note` とも無関係な既存の負債**なので、U2 では
ここで止めた。`doc/spinel_aot/ruby_writing_constraints.md` の B 表に
追記済み。これが取れれば desktop-Spinel は通る見込み (他の指摘は 0)。

## T2: midi_apu の書き換え

`BUTTONS` / `button_rect` / `button_at` / `draw` と独自パレット `COL_*` を
削除し、FmrbUI に置き換えた (434 行 -> 400 行)。

- **Scale / Chord / Drums は指示書の Button ではなく group 付き Toggle に
  した**。従来の `draw` は `@mode == BUTTONS[i][1]` で走行中のものを
  ハイライトしており、Button では状態を持てず**見た目が退化する**ため。
  指示書の「mode 表示の排他は group で」はこの形で満たしている。
  シーケンスが終わると `finish` -> `refresh` が `set_on(:scale, false)` で
  自動的に消える。
- BGM / SMF / Fast / Out は素の Toggle。Out だけ `on_text: "7 Out: serial"`。
- 状態行 `@status` は Label。`refresh` が `set_text` するだけなので、
  同じ文字列なら何も描かれない。
- 背景は `THEME_WINDOW_BG` に変えた (旧 `COL_BG = 0x00` の黒)。FmrbUI の
  Label / Toggle はテーマ色で描くので、黒地のままだと白い箱が浮く。
- **キー 1-7 とマウスが同じ経路に合流する**形は
  `refresh` で実現した: 各ハンドラは状態を変えるだけで、`refresh` が
  `set_on` / `set_text` で部品を状態に合わせる。**押したのに失敗した操作
  (.mid が無い / シリアルポートが無い) でトグルが勝手に戻る**のもこれ。

### sim での確認

| 見たこと | 結果 |
|---|---|
| 7 つのボタンとキー 1-7 | どちらも同じ動作。キー 6 で Fast、キー 7 で Out が点灯し、ラベルが `7 Out: serial` に変わる |
| 音 | `fmrb_audio_probe.rb`: 1 Scale で `peak=3072 avg_rms=1659.7 sounding_windows=39` |
| 走行中の表示 | 2 Chord クリック中のスナップで `chord playing` + 該当トグル点灯、終了後は自動で消灯 |
| SMF 再生 | `/usr/share/sounds/midi/joplin_entertainer.mid` を読み込んで再生、`events=22 fired=1 avg_late=85us` |
| **放置中の再描画** | GFX STATS が `1.0 presents/s` (= デスクトップの時計だけ) で 35 秒安定。**midi_apu からの present は 0** |
| ログの `[gc live=...]` | SMF 再生中のみ出る (従来どおり)。放置中は 1 行も出ないので、放置時の判定は上の presents/s で行った |

## T3: Spinel でコンパイルを通す

`tool/spinel/gen_app_combined.rb` の `system_desktop` と `editor` の `libs`
に `fmrb-ui.rb` を追加した。

### 仮想ディスパッチは通る (U1 の申し送りの答え)

`libs` に足すだけでは**使われていないので刈られてしまい**、editor の生成 C
には `FmrbUI_initialize` など数本しか出ない (確認済み)。そこで
**FmrbUI を実際に使う一時アプリ**を書き、base + i18n + sprite + audio +
fmrb-ui + そのアプリを結合して直接 spinel にかけた (コミットしない)。

結果、`FmrbUI#handle` の

```ruby
w = @pressed          # 基底 Widget 型
fired = w.activate    # サブクラスごとに実装が違う
```

は次の C になった:

```c
lv_fired = ({ sp_RbVal _t694 = lv_w; mrb_bool _t695 = 0;
  switch (_t694.cls_id) {
    case 20: _t695 = sp_Widget_activate((sp_Widget *)_t694.v.p); break;
    case 21: _t695 = sp_Button_activate((sp_Button *)_t694.v.p); break;
    case 22: _t695 = sp_Toggle_activate((sp_Toggle *)_t694.v.p); break;
    case 23: _t695 = sp_Stepper_activate((sp_Stepper *)_t694.v.p); break;
  } _t695; });
```

`press` / `release` / `group` / `set_on` / `draw_widget` も同じ形で
サブクラスごとの関数に分岐している。**素直な継承のままでよく、
`@pressed_kind` (整数) + case への書き換えは不要**。

### 踏んだ穴: poly 受信のメソッド名はプログラム全体で一意にする

最初の probe は `Widget#draw` のままで、こう落ちた:

```
unsupported hash literal (key/value type): node 5114 (KeywordHashNode)
  -> fmrb_app_base_spinel.rb の GfxBlock#draw(**kwargs)
```

**FmrbUI とは何の関係もない `GfxBlock#draw` が原因**だった。poly 受信の
`w.draw(@gfx)` は候補集合を**メソッド名で**引くので、プログラム中の `draw`
を全部生成対象に引き込む。`GfxBlock#draw` は `**kwargs` を取り Spinel が
扱えないため、**到達不能なのにビルドごと落ちる**。`fmrb-sprite.rb` の
`SpriteImage#draw` (`yield` を使う) も同じ集合に入る。

`FmrbUI::Widget#draw` を **`#draw_widget`** に改名して解決した
(`flush` の呼び出し 1 箇所とサブクラス 4 つ)。具体型受信なら候補が 1 つに
決まるので起きない。この 2 点は
`doc/spinel_aot/ruby_writing_constraints.md` の C 表に追記した。

- 改名の影響: 公開 API の `Widget#draw` が `#draw_widget` になった。
  `sig/fmrb_ui.rbs` は Widget の `draw` を書いていなかったので rbs の
  変更は不要。アプリは `draw_widget` を直接呼ばない (呼ぶのは `flush`)。

### 到達点

| 構成 | 結果 |
|---|---|
| `rake build:linux` (mruby app / spinel kernel) | 通る。sim で kamon / midi_apu / shell / editor / monitor / デスクトップの回帰 OK、例外 0 |
| `FMRB_APP_ENGINE_EDITOR=spinel` | 通る (fmrb-ui.rb を libs に足した状態で editor の生成・ビルド・起動を確認) |
| `FMRB_APP_ENGINE_DESKTOP=spinel` | **まだ通らない**。残り 1 件は上記 `load_shortcuts` の型推論 (FmrbUI とは無関係) |
| `rake spinel:doctor` | kernel clean / editor clean / system_desktop 指摘 1 件 (同上)。**fmrb-ui.rb に対する指摘は 0** |

Spinel で FmrbUI を**実際に動かす**確認は、FmrbUI を使う Spinel アプリが
まだ無いので U3 以降 (指示書のとおり)。コンパイルと生成 C の中身までは
上記で確認済み。

## U3 への申し送り

- monitor の Tasks ページを FmrbUI に載せるとき、`[X]` ボタンの
  `set_visible` の出し入れは U1 で実装済み (隠した領域は背景色で塗り直す)。
- **メソッド名の一意性**は U3 で足す部品にも効く。`update` / `run` /
  `draw` のような名前を Widget に足さないこと。
- `FMRB_APP_ENGINE_DESKTOP=spinel` を通したいなら、先に `load_shortcuts`
  の型推論 (B 表の新しい行) を片付ける必要がある。FmrbUI 側の作業ではない。
