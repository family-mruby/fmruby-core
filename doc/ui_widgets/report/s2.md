# S2 レポート: Scrollbar と 4 アプリの移植

段 2 の 2 段目。計画は `doc/ui_widgets/plan_s2.md`。

## Scrollbar

```ruby
@ui.scrollbar(:sb, @user_area_width - SB_W, LIST_Y, SB_W, list_h, total, visible)
@ui.set_range(:sb, total, visible)   # 行数が変わったとき
@ui.set_value(:sb, @scroll)          # アプリの位置を写す
@ui.value(:sb)                       # 押されたあとの位置
@ui.direction(:sb)                   # -1 / 0 / 1 (押しっぱなしの向き)
```

### 他の部品と違うところ 3 つ

1. **矩形は「バーそのもの」**。他の部品と同じく「置いた場所に描く」。旧
   `draw_scrollbar` は**一覧の矩形**を渡してバーを右端に押し込む形で、
   呼び出し側が渡す矩形の意味がバラバラだった (nsf/smf は幅 5 の矩形を
   渡していて、実際のバーは計算上その左 5px にずれて描かれていた)。
2. **押した瞬間に報告する**。ボタンは「離したら」だが、スクロールバーは
   押した瞬間に動いて押しっぱなしで動き続けるのが当たり前。基底に
   `fires_on_press?` (既定 false) を足し、`handle` の mouse_down 側で
   true の部品だけ `activate` を呼ぶようにした。**他の部品の経路は 1 命令も
   変わらない** (テストで確認)。
3. **要らないときは消える**。`total <= visible` なら描かず、`hit?` も false を
   返して**クリックが下の一覧へ抜ける**。アプリが `set_visible` を管理
   しなくてよい。

### `press(px)` -> `press(px, py)`

段 1 の API 変更。スクロールバーは押された **y** で上/下/つまみを判断する。
基底 + サブクラス 4 つ + `handle` の呼び出し 1 箇所の機械的な変更。

## 移植した 4 つ

| アプリ | 変わったこと |
|---|---|
| `nsf_player` | 一覧のバー。**以前はクリックできなかった** (描くだけで当たり判定が無かった) ので、機能が増えた |
| `smf_player` | 同上。こちらも以前は描くだけ |
| `logviewer` | バーのクリックと押しっぱなしの連続スクロール |
| `shell` | 履歴のバー。同上 |

### 「どちらへ」は部品、「どれだけ」はアプリ

移植中に気づいたこと: **スクロール量はアプリごとに違う**。logviewer は
半ページ (`visible_lines / 2`)、shell は 1 行かつ**最下段に着いたら
auto-scroll が復帰する**。部品の値で上書きすると挙動が変わってしまう。

そこで logviewer と shell では、部品からは `direction` だけ受け取り、
**アプリ自身の `scroll_up` / `scroll_down` を呼ぶ**形にした。部品の値は
次の再描画で `set_value` により `@scroll` から上書きされるので、ずれない。
nsf / smf は元々バーが押せなかったので、部品の値をそのまま使っている。

## 途中で見つけて直したこと

- **押下色が見えなかった**。押下時の塗りを `C_TEXT_LIGHT` にしていたが、
  アプリの背景は多くが `THEME_WINDOW_BG` で、**それが `C_TEXT_LIGHT` と
  同じ値** (0xFF)。白から白では何も変わらない。`C_HIGHLIGHT` に変更した。
  段 1 の「押下を枠色で表さない」(`THEME_BORDER == THEME_BUTTON`) と
  **同じ種類の間違い**を繰り返した。テーマの実値は 3 つが同じ値を持つ
  ことがある、と覚えておくこと。
- **mixin から包含クラスの定数は見えない**。`shell_scroll.rb` は
  `ShellScrollMixin` なので、`ShellApp` に置いた `SB_W` を裸で書くと
  `uninitialized constant ShellScrollMixin::SB_W` で落ちる。
  `ShellApp::SB_W` と明示した。sim で実際に落ちて気づいた。
- **`!bar.hit?(x, y)` を書いてしまった**。条件式で呼び出しを単項 `!` で
  否定するのは Spinel の codegen bug を踏む形
  (`ruby_writing_constraints.md` B 表)。ローカルに退避してから否定する形に
  直した。logviewer は今のところ mruby だけだが、規則は規則。

## 確認

| 項目 | 結果 |
|---|---|
| `rake ui:test` | **73 項目** (S1 の 51 + Scrollbar 22) |
| `rake test` 全体 | 通過 |
| logviewer | バーが出る / 上矢印で半ページ戻る / バー以外のクリックは auto-scroll の切替に抜ける |
| shell | `help` と `ls /app` を流してバーが出る、上矢印で履歴が戻る、例外 0 |
| nsf / smf | 起動と一覧表示に影響なし。**バーの見た目は sim で確認できていない** — 同梱の .nsf / .mid がどちらも一覧に収まる数しかなく、バーが出る条件にならない |

### 前の報告の訂正

U4 で「ツリーに自前の当たり判定はもう無い」と書いたのは**誤り**だった。
`smf_player.app.rb` に `hit_btn?` と 7 個のボタン (`@play_btn` /
`@slower_btn` / `@faster_btn` / `@out_btn` / 楽器行の 3 つ) が残っている。
移植した 5 本しか見ていなかった。**S2 ではスクロールバーだけを移し、
ボタンには手を付けていない**。nsf_player とほぼ同じ形なので移植は容易で、
テンポの `< x1.0 >` は S1 の Enum がそのまま使える (`TEMPO_STEPS` が表)。
S3 か S4 のついでに片付けるのが妥当。

## S3 への申し送り

- TextField で `handle` がキーを見るようになる。`fires_on_press?` と同じく
  **焦点が nil のときの経路を 1 命令も変えない**ことをテストで縛る。
- 押下や選択の色を決めるときは、**テーマの実値を確かめてから**にする
  (`window_bg = text_light = 0xFF`、`border = button = 0x60`)。
