# 報告: 出したことのない部品の「跡」を消していた

> 状態: 完了 | 更新: 2026-09-03 | 起動直後にメニューバーへ透明の穴が
> 開いていた。原因は FmrbUI、直したのも FmrbUI

ユーザ報告 (2026-09-02):「起動時に壁紙とタスクバーが出るとき、一瞬左上の
Family mruby の文字のところが透明で下が透けて見える」。

## 測ったこと

sim の起動を 1 フレームずつ 247 枚撮り、色で数えた。

- **(0,0)-(89,12) の 90×13 が、ちょうど 5 フレームだけ `0x01`**。1170 画素の
  完全な長方形で、欠けもにじみも無い。x=90 から先は正しくメニュー色。
- `0x01` は前景キャンバスの透明キー。画面には (0,0,85) の濃紺で出ていた。

## 因果

3 つが重なっていた。

**1. デスクトップは全部の部品を (0,0) に作って即座に隠す。**
`on_create` の `build_*_widgets` が 19 個の部品を `@ui.button(:id, 0, 0, w, h, ...)`
で作り、そのまま `set_visible(false)`。位置はダイアログを開くときに `move` で
入れる作りなので、それまでは全員が原点に重なっている。

**2. `set_visible(false)` は `dirty` も立てる** (fmrb-ui.rb)。

**3. `flush` の第 1 パスが「隠れていて dirty」な部品の地を塗り直す。**

```ruby
if w.dirty && w.visible == false
  p.paint_bg_rect(@gfx, w.x, w.y, w.w, w.h)
```

デスクトップの `paint_bg_rect` は壁紙を透かすために **`0x01` で塗る**。
つまり「一度も出ていない部品」の跡消しが、原点に透明の穴を開けていた。

`draw_foreground` の順番がとどめで、`draw_menu_bar` の**後**に `@ui.flush` が
走る。バーを描いた直後にその上へ穴が空く。

見えたのが 90×13 なのは、**塗られた矩形の和が一番幅の広い部品の幅** (90) で、
**メニューバーの領域だけが不透明合成**だから。バーの外にも同じ穴は開いていたが、
そこは透明合成なので `0x01` は見えない。5 フレームで消えるのは次の再描画で
バーが塗り直されるから。

## 直したもの

**跡が無いものに跡消しは要らない。** `Widget` に `shown` を足し、`flush` が
実際に描いたときだけ true にする。第 1 パスは `shown` の部品だけ地を塗り、
塗ったら false に戻す。

```ruby
if w.dirty && w.visible == false
  if w.shown
    ...paint...
    w.shown = false
  end
  w.dirty = false
end
```

デスクトップだけの回避 (画面外に作る、ラベルに背景色を渡す) ではなく
**FmrbUI 側を直した**。作って隠す部品はどのアプリでも書ける形で、同じ傷は
バーの外 (ダイアログの地の上など) にも出るため。

## 踏まなかった罠

基底クラス `Widget` に ivar を 1 つ足す変更なので、**Spinel の ivar レイアウト
食い違い** (doc/spinel_aot/reports/editor_ivar_layout_bug.md) の再来を疑う必要が
あった。あの穴はコンパイラ側で修正済み (fork `ca0709c`) だが、CLAUDE.md の
決まりどおり**標準構成でエディタを起動して 1 打鍵**するところまで確認した。
`@shown` は真偽値で型が広がる余地が無く、実際に問題は出ていない。

## 確かめたこと

- 起動 260 フレームを撮り直して、**バー内に `0x01` の画素は 0**。修正前は 5
  フレーム × 1170 画素。
- Spinel エディタ起動 + `gfx.fill_rect` を打鍵 (ivar レイアウトの回帰確認)。
- Config・エディタの保存確認・NSF プレイヤーを開いて閉じ、**本来の跡消しが
  効いていること**を確認 (閉じたあとデスクトップに矩形が残らない)。
