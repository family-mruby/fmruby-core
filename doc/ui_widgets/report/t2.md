## 入れたもの

### FmrbUI 側 (lib/add/picoruby-fmrb-app/mrblib/fmrb-ui.rb)

- `initialize(app, bg:, text_size:, bg_painter: nil)`。`flush` の非表示 dirty の
  分岐だけが変わる:

  ```ruby
  p = @bg_painter
  if p
    p.paint_bg_rect(@gfx, w.x, w.y, w.w, w.h)
  else
    @gfx.fill_rect(w.x, w.y, w.w, w.h, @bg)   # 従来と同値
  end
  ```

  既定 (nil) は 1 ビットも変わらないので、**monitor / shell / kamon /
  picoruby / nsf / smf / midi_apu / logviewer は無変更**。
- `bg:` の説明を狭めた。冒頭コメントと `Widget#bg` のコメントを
  「部品が自分の中を塗る色。**後ろにあるものの色ではない**」に書き直し、
  「消えた跡」の話は bg_painter 側へ移した。
- `paint_bg_rect` の契約 (描くだけ・present しない・確保しない・
  文字サイズやフォントを変えたら戻す・名前は固定) を `initialize` の
  コメントに書いた。名前を固定にする理由 (poly 受信) は `draw_widget` の
  注記を参照させている。

### デスクトップ (main/prebuild_scripts/kernel/system_desktop.app.rb)

- `@ui = FmrbUI.new(self, bg_painter: self)` (`set_origin(0, 0)` は従来どおり)。
- `paint_bg_rect` は**面ごとに塗り分ける**:
  - 既定は `FmrbApp::TRANSPARENT_COLOR` (= 0x01。既存の定数を使い、
    マジックナンバーは書いていない)。前面 canvas を透明に戻すと合成で
    背面の壁紙が出る。
  - **開いたままのパネルの内側**にある穴だけ `PANEL_BG`
    (= `FmrbConst::THEME_WINDOW_BG`。LAUNCHER_BG / CDLG_BG / FSEL_BG …が
    全部これ) で塗る。ここに透明キーを打つとパネルに穴が空く。
  - 判定は `hole_inside_open_panel?` (開いている 8 つのパネルの矩形と
    内包判定するだけ。整数比較のみ、確保なし)。部品を開いたまま隠す
    ことがないダイアログ (about / shortcuts / error / tbd) は載せていない
    (理由をコメントに明記)。
- 定数 `PANEL_BG` を 1 つ足した。

### ホストテスト

## 見つかったもの (T2 とは無関係、既存)

Storage の Yes/No から Clear/Close に戻すと、**戻ってきたボタンの一部が
白く欠ける** (「Clea□e」「□lose」)。原因は FmrbUI の描画順で、`flush` は
生成順に回るので、先に描かれた Clear/Close の上に、後から生成された
Yes/No の「穴」が塗られる。

これは painter とは無関係な既存の性質。painter 無しのホスト実行で再現する:

```ruby
ui.button(:early, 0, 0, 60, 16, "E")   # 先に生成
ui.button(:late, 20, 0, 60, 16, "L")   # 後に生成、重なる
# early を表示、late を非表示 dirty にして flush:
[[:fill, 1, 11, 60, 16, 96], [:rect, ...], [:text, ...],
 [:fill, 21, 11, 60, 16, 255],   # <- late の穴が early の上に乗る
 [:present]]
```

塗り色も従来と同値 (`@bg` = THEME_WINDOW_BG = 今回の PANEL_BG) なので、
**T2 の前後で画素は変わらない**。

直すなら `flush` を 2 周に分ける (**穴を全部塗ってから、表示中の部品を
描く**) だけで、費用は while の 1 周増しのみ。段 3 の範囲外なので**入れて
いない**。入れるかどうか指示をもらいたい。

## 追記: flush の 2 周化 (上の「見つかったもの」の修正)

ユーザ判断で入れた。**穴を全部塗ってから、表示中の部品を描く**。作者側に
回避策が無く (生成順を変えても逆向きの入替が壊れるだけ)、放置すると
「重なる部品の表示入替をしてはいけない」という新しい暗黙契約になるため。

- 1 周目は**非表示 dirty だけ** (`w.dirty && w.visible == false`) を塗って
  dirty を落とす。2 周目に残る dirty は表示中のものだけになる。
- `present` は従来どおり 1 回、`drawn` は両周の合算。確保はゼロのまま
  (while が 1 周増えるだけ)。

回帰テスト (run.rb「holes are painted before widgets」): 重なる 2 部品で
`set_visible(a,false)` + `set_visible(b,true)` を**両方向**行い、FakeGfx の
ログで穴の塗りが部品の描画より前に来ることを検査する。1 周版に戻すと
片方向が FAIL する (もう片方が通ってしまうのが「生成順では直せない」の
実物)。ホストテストは **150 項目全通過**。

## 追記: desktop=spinel での実行確認

ここまでの検収はすべて desktop=mruby だったので、**Spinel 側で実際に走る
経路**を確かめた。構成:

```
FMRB_KERNEL_ENGINE=spinel FMRB_APP_ENGINE_DESKTOP=spinel rake clean && rake build:linux
```

(`.env` は編集していない。CLI 上書き。x86-64 確認済み)

### 1. paint_bg_rect が Spinel で走る (ダイアログ開閉)

| 場面 | 走査結果 |
|---|---|
| Config 開 -> Cancel で閉 | 壁紙と `0 differing pixels` |
| Storage: Clear/Close -> Yes/No 確認画面 | ボタン行 y=155 のパネル内に壁紙色 0 画素 |
| Storage: 確認画面 -> Clear/Close に戻す | 開いた直後と `0 differing pixels` (欠け 0) |

透明キーの分岐 (壁紙の上) と PANEL_BG の分岐 (開いたままのパネルの内側) の
両方、および flush の 2 周化が、**Spinel でも mruby と同じ絵になる**。
`docker logs fmruby_core | grep -cE "^E \(|Exception|abort"` -> 0。

### 2. spinel_hello の枠

同じビルドで `run /app/debug/spinel_hello.app.rb`。窓 160x70 が開き、
左枠 (row 70 の x=60)・上枠 (col 62 の y=41)・**左下の角の丸み**が
そろっている。異常なし。

**ただしこれは mruby 基底の確認**である点を明記しておく:
spinel_hello.app.rb は Spinel 製の**gem を呼ぶ mruby アプリ**で、
アプリ本体は mruby VM で動く。`fmrb_app_base_spinel.rb` は通らない。

### 3. Spinel 基底の clear_user_area を実際に走らせた

上を踏まえて調べたところ、**Spinel でコンパイルされるプログラム
(kernel / desktop / editor) の中に `clear_user_area` の呼び出しは 1 つも
無い**。つまり T3 で Spinel 基底に足した分は、コンパイルはされるが
誰も呼んでいない (mruby 基底との等価性のために必要な実装)。

そこで**一時的にデスクトップの `on_create` に 1 行足して**呼ばせ、
実行を確認した (`clear_user_area(FmrbApp::TRANSPARENT_COLOR)` + 前後の
ログ。**確認後に削除済み、コミットしていない**)。

```
I (20:10:47.471) spx: TMP before clear_user_area
I (20:10:47.471) spx: TMP after clear_user_area
```

- 例外なく通る (Spinel で `draw_window_frame` のガードと
  `_invalidate_attached_uis` の while が走る)
- **壁紙の上にタイトルバーが出ない** = `@bg_canvas` ガードが Spinel でも
  効いている。呼んだあとのデスクトップは、呼ばない版と
  `0 differing pixels`
- そのあと Config を開閉しても `0 differing pixels` (部品の状態も壊れて
  いない)
- エラーログ 0
