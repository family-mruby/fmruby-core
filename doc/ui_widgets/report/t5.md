## doc/ui_widgets/verify.md

課題 E の「確認手順を定型化する」。**T2/T3 で実際に使った手つきだけ**を
書いた (使っていない手順は書いていない):

1. 撮る前にカーソルを毎回同じ座標へ戻す (カーソルは canvas に描かれる)。
   時計が動くメニューバーは比較範囲から外す
2. 「元に戻ったか」は差分の画素数で見る (`pngdiff.py`、合格は 0)
3. 枠と部品の境目は行/列の連長で読む (`pngscan.py`)
4. 角の丸みは操作の前後で同じ小矩形を突き合わせる
5. **検査が生きていることをわざと壊して確かめる** (ホストは実装を戻す、
   sim は `flash/app/` に壊した一時アプリを置く = 再ビルド不要)
6. 「自分の変更が原因か」は変更前の版を同じビルドに同梱して並べる。
   ホストで再現できるならそちらが速い
7. ログも見る (`^E \(` の数、`FmrbUI:` の警告)
8. 罠 (3 コンテナまとめて再起動 / stale build の偽グリーン / VM プール)

`pngdiff.py` / `pngscan.py` は**リポジトリルートの `tools/` に
`fmrb_pngdiff.py` / `fmrb_pngscan.py` として入れた** (ユーザ判断)。
verify.md は写経でなくツール参照 + 使用例に置き換えてある。画像処理なので
Python のまま (周辺ツールの Ruby 化の例外)。親リポジトリのコミットなので
fmruby-core とは別。
