| 対象 | 内容 |

## 座標系は杞憂だった

計画で「S4 で一番はまりそう」と書いた点は、実際には**楽な方**だった。

- **デスクトップは fullscreen なので user area 原点が (0, 0)**。部品の座標が
  そのままキャンバス座標になる。窓アプリより単純。
- **コンテナは 1 つで足りる**。ダイアログは同時に 2 つ開かないので部品を
  共有し `set_visible` で出し入れする。当たり判定は不可視を飛ばす。
- ダイアログは開くたび位置が変わるので、**開くときに `move` で貼り直す**。
- **閉じるときは隠してから `flush`**。逆にすると次の flush が背景を塗って
  下のアプリに穴が開く (U3 で踏んだのと同じ)。
- `draw_foreground` の末尾は `@gfx.present unless @ui.flush`。

## 移さなかったもの、とその理由

- **config の設定行 11 個**。行は「ラベル + 導出された値 + 左右の矢印」で、
  値は型付き (enum / bool / int / float)、表示は計算され一部は翻訳され、
  行そのものが選択ハイライトを持つ。部品にその意味は無く、Enum に
  やらせるには**表示文字から保存値へ戻す対応表**がアプリ側に要る。
  List を入れなかったのと同じ理由。
- **clock の日付フィールド 6 個**。矢印が縦に並び、フィールド同士で
  桁上がりを見て、値の行が選択も兼ねる。Stepper は横並びの `< n >` で、
  そのどれでもない。

**結果として、S1 で Enum を作った理由 (config_dialog) は外れた。**
Enum が実際に使われたのは smf_player のテンポで、`TEMPO_STEPS` が元から
表だったので素直に嵌まった。S1 の見積もりが甘かったということ。

### 数え方の誤り (訂正)

S1 で「storage 27 箇所 / config 18 箇所のボタン」と報告したが、これは
`fill_rect` を grep しただけで、**行やパネルの塗りを数えていた**。実際の
離散ボタンは 4 ダイアログ合わせて **12 個**だった。

## accent: を足した (ユーザ決定)

確認ダイアログの Yes が緑を失ったのを見て、**色そのものが意味を持つ数少ない
場合のための口**を開けた。生成時キーワードのみで、実行時の確保は増えない。

- Button の塗り、または Toggle の「入」の色を 1 色だけ置き換える。
- **accent の上の文字は明色**、テーマの淡い highlight は暗色のまま。
- 使ったのは 6 箇所: confirm の Yes、storage の Clear と Yes、clock の OK、
  smf の Stop と MIDI out / Own。いずれも「消す・止める・設定する」もの。

## 実装中に踏んだこと (経緯)

### 1 打鍵が 2 文字入った

保存ダイアログで `memo.rb` と打つと `mmeemmoo..rrbb` になった。原因は
**キーを 2 回処理していた**こと: S4 の最初のコミットで `on_event` の先頭に
置いた「まず FmrbUI に渡す」が key_down も渡しており、その後
file_selector 側の経路でもう一度渡していた。

**先頭のディスパッチはマウスだけにした。** キーにはこのアプリなりの順番が
あり (矢印と Enter が先に一覧を動かし、残りが欄に入る)、部品群がその順番の
前で奪うと順番を保てない。sim で打って初めて分かった。

### Spinel の確認

`FMRB_APP_ENGINE_DESKTOP=spinel rake build:linux` が**通る**。生成 C に
7 つの部品クラスの `draw_widget` が出そろい、`cls_id` の分岐が 233 箇所。
sim で起動し、storage ダイアログが開いて accent 付きのボタンが描かれ、
ボタンで閉じるところまで確認した。

**ただし Spinel デスクトップは i18n の文字列が生のキーのまま出る**
(`storage` / `clear_cache_target`)。これは本作業と無関係の既存の差で、
そのぶん**この構成での全ダイアログの操作確認は済んでいない**。
mruby 構成では 5 本すべて開閉と操作を確認した。

### ここで実バグが 1 つ見つかった: ボタンがダイアログの外へ

ユーザの指摘 (「ボタンが Window フレームからはみ出している」) で発覚。
**各ダイアログはキャンバス絶対座標を計算して `move()` に渡すが、FmrbUI は
そこに user area 原点を足す**。窓アプリでは正しいが、ここでは各ボタンが
`TITLE_BAR_H` 分だけ下へずれ、パネルの下辺からはみ出して壁紙の上に
描かれていた。

**間違いの元は「デスクトップは fullscreen」という思い込み**。実際には
`has_background_canvas` で枠の描画を抑えた**窓**で、`.fullscreen` は
立っていない。したがって user area は (0, 0) ではなく (1, 11) から始まる。
コンテナに `set_origin(0, 0)` を渡して、ダイアログの算術が元から前提に
していた座標系に合わせた。

**sim のスクリーンショットを 4 ダイアログ分見ておきながら気づかなかった。**
パネルの下辺に乗っているボタンは、指摘されるまで「パネルの上のボタン」に
見える。ずれが 11px で、パネルの縁と重なっていたため。
**寸法は目で見ずに数える** (この修正の確認は、パネルの下辺とボタンの下端の
y をピクセル走査で読んで行った)。
