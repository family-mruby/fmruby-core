# U3 レポート: monitor と大きさ変更、仕上げ

対象: doc/ui_widgets/instruction_u2_u3.md の U3 (T1 / T2 / T3)。

## FmrbUI 側の追加: `bg:`

ユーザ指摘のとおり、`set_visible(false)` の穴を `flush` が塗る色が
`THEME_WINDOW_BG` 固定では、monitor のような暗い背景のアプリに**白い穴**が
開く。生成時のキーワードで背景色を受けるようにした。

```ruby
@ui = FmrbUI.new(self, bg: COLOR_BG)
```

- `FmrbUI#add` が自分の `@bg` を各 Widget に配る (`Widget#bg`)。
- 使い道は 3 つ: Label の箱、Stepper の値の欄、隠した部品のあと。
  Button / Toggle は自分で全面を塗るので影響しない。
- 既定は `THEME_WINDOW_BG` なので kamon / midi_apu は無変更。

## T1: monitor の Tasks ページ

`main/prebuild_scripts/default_app/monitor.app.rb`。

- **`FMRB_MAX_APPS` 分 (9) の Button を `on_create` で作る**。Ruby からは
  この定数を引けないので `KILL_IDS` に 9 個の Symbol を並べた。窓の高さに
  入る行数のほうが少ないので、実際に作る数は `(msg_y - rows_y0) / ROW_H`
  との小さいほうになる (`@max_rows`)。**行ごとに部品を作らない**。
- 行が入れ替わったら `set_text` (`[X]` / `[?]`) → `move` → `set_visible(true)`。
  余った部品は `set_visible(false)` で、その跡は `COLOR_BG` で塗られる。
- **二段クリックは従来どおり**。`@kill_armed_pid` はアプリが持ち、部品は
  文字が変わるだけ (`[X]` -> `[?]` -> 送信)。色を変える口は FmrbUI に
  無いので、armed の赤 (`COLOR_USED`) は文字の変化に置き換えた。
- `handle_task_click` (座標での行探し) と `@kill_rows` は削除。当たり判定は
  FmrbUI が持つ。
- **ページ切替は部品を先に隠してから**。`turn_page` が
  `hide_kill_buttons` → `@ui.flush` → `draw_all` の順に呼ぶ。逆にすると、
  隠した部品の塗り直しが次の `flush` で新しいページの上に穴を開ける。

### 無変化なら描かない

指示書の条件「1 秒ごとの再描画で一覧に変化が無ければ present されない」を
満たすため、`draw_page_tasks` を `refresh_tasks` に作り替えた。

- 一覧を 1 本の文字列 (`task_signature`) に落として前回と比較する。
  pid / state / type / name に加えて **armed の行と kernel からの
  メッセージ**も含める (どちらも画面に出るため)。
- 一致したら `@ui.flush` を呼ぶだけ。dirty が無いので present も起きない。
- 変わったときだけ行の帯を 1 回 `fill_rect` で消して描き直す。
- `on_update` はページ 3 のときだけ `refresh_tasks`、1・2 ページ目は
  従来どおり毎秒 `draw_all` (時系列グラフなので毎秒変わる)。

**実測 (sim)**: page 3 を出したまま 35 秒放置して `GFX STATS` は
`1.0 presents/s` で一定。これはデスクトップの時計の分だけで、**monitor から
の present は 0**。

### sim での確認

| 見たこと | 結果 |
|---|---|
| 一覧表示 | `0 fmrb_kernel / 2 system_desktop / 4 Monitor / 5 FM-Shell` と表示、**[X] は FM-Shell の行だけ** (自分の行には出ない = kernel が拒否する相手に出さない従来仕様) |
| 押下表示 | `down` のままスナップして反転を確認 |
| 二段クリック | 1 回目で `[?]` + `click again to end PID 5`、2 回目で `Kill: quit request to built-in pid=5` |
| 終了後 | 行と部品が消え、**跡に白い穴は出ない** (`bg:` が効いている) |
| ページ切替 | 3 → 1 → 2 と回して、部品のあった場所に穴が出ないことを確認 |
| 複数行 | FM-Editor と Monitor の 2 行に同時に [X] が出る (行ごとに `move` される) |

## T2: 大きさ変更

kamon を**一時的に** resizable にして (`resizable = 1` を toml に、
`on_resize` を app に) 確認し、**両方とも元に戻した**
(`git checkout` 済み。作業ツリーに残っていない)。

手順は 4 手で、`plan.md` の「大きさ変更に追従する」に例として残した:

1. `@ui.set_origin(@user_area_x0, @user_area_y0)` — user area の原点が動く
2. 追従させる部品に `@ui.move(id, x, y, w, h)` (座標は user area 相対)
3. `clear_user_area` → `draw_window_frame` (resizable は毎 redraw 必要)
4. `@ui.invalidate_all` → 自分の絵 → `@ui.flush`

確認したこと: 300x210 から画面いっぱい (426x240 近く) までドラッグで広げ、
右列のパネルが右端に追従し、クレジット行が全幅に伸び、プレビューが崩れない。
**広げたあとにクリックしても当たり判定が新しい位置に付いてくる**
(菱を選択、count 5 → 6)。

落とし穴 2 つ (plan.md に明記):
- `set_origin` を忘れると `move` の相対座標が古い原点に足される。
- `invalidate_all` を忘れると `clear_user_area` で消えた部品が戻らない。
