## 1. NSF プレーヤ

`flash/app/tool/nsf_player.app.rb`。**残っていた最後の自前当たり判定**
(`hit_btn?`) と、`draw_ui` のたびに作り直していた 3 つの Hash
(`@prev_btn` / `@next_btn` / `@play_btn`) を削除した。

| 前 | 後 |
|---|---|
| `[<]` `1/5` `[>]` を 3 つの部品として手描き + Hash で矩形を保存 | `Stepper` 1 つ |
| Play/Stop を色違いの矩形 + 文字で手描き | `Toggle` (`on_text: "Stop"`) |
| `hit_btn?(@prev_btn, x, y)` を 3 回 | `@ui.handle(ev)` の戻り値を `case` |

ファイル一覧とスクロールバーは**手描きのまま**。FmrbUI にリスト部品が無い
(段 2 の候補)。移ったのは下段のトランスポートだけ。

### FmrbUI に足したもの

- **`Stepper#set_range(min, max)`** と `FmrbUI#set_range(id, min, max)`。
  曲数はファイルごとに変わるので、生成時に固定できない。値は新しい範囲へ
  引き込まれ、動いたときだけ文字を作り直す。
- `Stepper#suffix=` を同値なら no-op に (`"/5"` を毎回渡しても無駄が出ない)。
  併せて doc を「生成時に 1 回」から「データで変わるものも可」に直した。

### 色について (設計どおりの見た目の変化)

Play が緑・Stop が赤だったのを**テーマ色に寄せた** (off = `THEME_BUTTON`、
on = `THEME_HIGHLIGHT`)。plan.md の「部品ごとに色を持たせない」に従った
判断。状態の手掛かりは色とラベル (`Play` / `Stop`) の 2 つ残る。sim で
確認して読みづらくはなかったが、**意味を持った色に戻したいなら
`on_color:` を生成時キーワードとして足すのが素直** (要相談)。

## 2. 文字サイズ

**規則 (ユーザ決定)**: 部品を作ったときのサイズで固定する。指定が無ければ 1。

```ruby
@ui = FmrbUI.new(self, text_size: 2)          # この箱の既定
@ui.label(:title, 4, 2, 100, 20, "Title", text_size: 2)   # 部品ごとの上書き
```

なぜ「その時々のサイズに従わない」か: アプリは 2 回の flush の間に自分の絵の
ために `set_text_size` を変える (PicoRuby デモはページごとに 1〜4)。従うと
**測ったときと描くときで倍率が変わり、中央寄せも高さも崩れる**。

規則を成立させるのに要った 2 点:

1. **測定を現在のサイズから切り離す**。`FmrbGfx#text_width` は
   `@current_text_size` を掛けて返すので、
   `text_width(str, :default) / current_text_size * 自分のサイズ` で割り戻す
   (raw = base * size なので割り切れる)。これが無いと、アプリが size 3 の
   ときに作った size 1 の部品が 3 倍で測られる。
2. **`flush` がアプリのサイズを保存・復帰する**。入口で
   `current_text_size` を控え、部品ごとに違うときだけ `set_text_size` を
   出し、最後に戻す。`current_text_size` は Ruby 側の attr なので読むのは
   ただ。**全部が同じサイズならコマンドは 1 本も出ない**。

副次: Stepper の `< >` の幅も倍率に比例する (`STEP_W * ts`)。size 2 の
Stepper は幅を倍くらい取らないと値の欄が潰れる。

### ホスト harness (docker 不要、0.1 秒)

`fmrb-ui.rb` は純 Ruby で `FmrbGfx` の描画メソッドしか呼ばないので、
記録用の偽 gfx を与えればホストの ruby で直接動く。23 項目を書いて全部
通した。**ビルドを止められている間の検証はこれで足りた**。

確認した主なもの:

- 既定サイズが 1。**アプリが size 4 のときに作っても 1 で測り 1 で描く**。
- `flush` のあとアプリのサイズ (4) が戻っている。
- 部品ごとの上書きが効く。幅も高さも倍率どおり。
- **同じサイズしか無いときは `set_text_size` が 0 回**。
- `set_range` が値を引き込む / 端で `activate` が false を返す。
- `bg` が Label の箱にも隠した部品の穴にも使われる。

置き場所は scratchpad (`ui_harness.rb`)。**`rake test` に組み込めば
fmrb-ui.rb の回帰が docker 無しで回せる**が、指示外なのでコミットしていない。
要否はユーザ判断。

## 3. PicoRuby デモのナビバー

`draw_nav` と `_nav_click` を削除し、ナビバーを FmrbUI にした
(`_tab_w` / `_tabs_x0` は部品の配置計算として残る)。

- タブ 6 個 = group `:section` の Toggle (`SECTION_IDS` は固定表)。
- **`< 3/8 >` は Stepper ではなく Button 2 個 + Label**。理由:
  `_step_page` は**セクションの端で次のセクションへ回る** (クリックし続けると
  全ページを一周する) のに対し、Stepper は端で止まり、しかも**止まったことを
  何も返さない**ので、回り込みが実装できない。Button なら必ず id を返すので
  従来の挙動がそのまま残る。**部品の意味が合わないときは無理に使わない**
  という例。
- 背景は `bg: COLOR_NAV_BG`。ナビ独自だった `COLOR_NAV_FG` /
  `COLOR_TAB_ON` / `COLOR_TAB_ON_FG` は不要になり削除
  (アクティブタブの反転はテーマの `THEME_HIGHLIGHT` になる)。

### 文字サイズ (2) がここで効いた

このアプリはページごとに `set_text_size` を 1〜4 に変える。**`set_text_size
1-4` のページを表示したまま**ナビバーを見ると、部品はすべてサイズ 1 で
描かれている。(2) の「生成時に固定 + flush で復帰」が無ければ、ナビの文字が
ページの倍率を引きずって崩れていた。

### 毎フレームの再描画をやめた

従来の `draw_all` は**毎回 `draw_nav` を呼んでいた**。`:p5_transform` は
`DYNAMIC_PAGES` なので on_update から 15 Hz で `draw_all` が走り、ナビバー
(塗り + 文字 3 本 + タブ 6 個) をそのたびに描き直していた。

いまは `@nav_dirty` (ページ・セクションが動いたときだけ立つ) を見て
`refresh_nav` を呼ぶ。**アニメーション中はナビに 1 コマンドも出ない**。

- 実測 (sim、`:p5_transform` 表示中): `279 cmds/s / 16.0 presents/s`
  = **1 フレーム 17.4 コマンド**。ナビを毎フレーム描いていれば、塗り 1 +
  Label 2 + Button 3x2 + Toggle 3x6 = 約 27 コマンドが上乗せされる勘定。
- ページの絵は `fill_rect(..., uh, PAPER)` で **NAV_H を除いた高さ**しか
  消さないので、ナビの帯はページ側の再描画で壊れない。この前提があるので
  「動いたときだけ」で成立する。

### sim での確認 (ログ計装して確定させた)

スクリーンショットだけでは座標の読み違いで誤診しかけたので、
`on_event` と `_step_page` に一時ログを入れて確認した (ログは削除済み)。

| 見たこと | 結果 |
|---|---|
| `>` / `<` | 1 クリックにつき down 1 + up 1、`id=:next` / `:prev` で 1 ページだけ動く |
| セクションの回り込み | Shapes 3/3 で `>` -> `sec=1 pg=0` (Fonts 1/5)、そこで `<` -> `sec=0 pg=2` (Shapes 3/3) |
| タブ | Sound のタブで `id=:sec3`、ページが 1/1 になり、ハイライトが排他で移る |
| 押下表示 | `>` を押したままスナップして反転を確認 |
| キーボード Tab | セクションが進み、ナビの `1/5` とタブのハイライトが追従 |
| 絵のクリック | 従来どおり次のページへ (1/5 -> 2/5) |
| 終了 | 閉じるボタンで終了、例外 0 |

## 環境について (引き継ぎ)

- **`.env` の `FMRB_HW_TARGET` は `NARYAv3` のまま**。元は `TAB5` だったが、
  `rake build:linux` が NARYAv3 に書き換える既知の挙動で変わった。作業中に
  別セッションが `rake build:esp32` を実行して **S3 向けにビルド**しており、
  こちらで勝手に戻すと相手の意図を壊すので触っていない。Tab5 を焼くなら
  `FMRB_HW_TARGET=TAB5 rake build:esp32` か `.env` を戻すこと。
- `build/` は linux 成果物。
