## API (指示書からの差分)

指示書のシグネチャはそのまま実装した。追加・変更は次の 4 点。

1. **`Widget#press(px)` は x だけ受ける** (指示書は `press` の引数を規定して
   いない)。Stepper が左右どちらを押されたか決めるのに x だけが要るため。
2. **`Stepper#suffix=` を足した**。kamon の大きさ表示が `70%` なので、値の
   文字列に単位が要る。生成時に 1 回だけ呼ぶ前提 (`@size_st.suffix = "%"`)。
   これが無いと表示のたびにアプリ側で補間が必要になり、確保しない条件を
   破る。
3. **`FmrbUI#value(id)` / `set_value(id, v)` / `set_origin(x0, y0)` を足した**。
   前 2 つは Stepper を id 経由で読み書きするため (kamon は返り値の Widget を
   直接持つので使っていないが、部品を持ち回らないアプリ向け)。`set_origin` は
   U3 の `on_resize` -> `move` で user area の原点が動いたときに必要になる。
4. **文字幅は `text_width(str, :default)` で測る** (指示書は family 省略)。
   family 省略だと「アプリが直前に選んでいたフォント」で測ることになり、
   アプリが `set_font(:ja)` したまま部品を作ると幅がずれる。FmrbUI は常に
   `draw_text_mixed` (ASCII=Font0 6px / 多バイト=misaki_8 8px) で描くので、
   その換算をそのまま持つ `:default` を明示するのが正しい。

### 色の割り当て (指示書からの変更)

指示書は Button の文字を `THEME_TEXT`、Toggle の on を
`THEME_HIGHLIGHT` + `THEME_TEXT_LIGHT` としていたが、**既定テーマの実値では
どちらも読めない**ので入れ替えた。

- 既定テーマ (`lib/add/picoruby-fmrb-const/ports/esp32/const.c` の `g_theme`):
  `window_bg=0xFF` `text=0x00` `text_light=0xFF` `highlight=0xEE`
  `border=0x60` `button=0x60`。
- `THEME_BUTTON` は暗い赤なので、その上の文字は `THEME_TEXT` (黒) ではなく
  `THEME_TEXT_LIGHT` (白)。デスクトップの confirm_dialog も
  `fill(THEME_BUTTON)` + `draw_text(..., WHITE)` で同じ組にしている。
- `THEME_HIGHLIGHT` は明るいピンクなので、on の文字は `THEME_TEXT_LIGHT`
  (白) ではなく `THEME_TEXT` (黒)。
- **`THEME_BORDER == THEME_BUTTON == 0x60`**。そのため Toggle の押下表示に
  指示書どおり枠色の二重線を描くと**完全に見えない** (sim で確認)。押下中の
  内側の枠はラベル色で描くように変えた (off なら白、on なら黒)。

## T3: 確保と描画回数 (sim)

計測アプリ `flash/app/test/ui_probe.app.rb` (Button 3 / Toggle 4 (1 group) /
Stepper 2 / Label 2) で測定。**コミットしない**ので計測後に削除し、再ビルド
済み。手順は `on_update` で 1 秒ごとに `GC.start` -> `GC.stat[:live]` ->
ログ 1 行。ログ文字列は次の tick の `GC.start` で回収されるので、live 同士の
比較は GC 直後同士になる。

環境: Linux sim (docker、426x240、FMRB_HW_TARGET=TAB5 / kernel=spinel /
app=mruby)。

| 項目 | 手順 | live の変化 | present | 判定 |
|---|---|---|---|---|
| 無操作 68 秒 | 起動後放置、1 Hz サンプル 67 本 | **2366 -> 2366 (0)** | アプリ由来 0 (下記) | 合格 |
| Button クリック 100 回 | `down`/`up` を B1 の上で 100 回 (200 イベント) | **2366 -> 2366 (0)** | 200 (1 イベント 1 回) | 合格 |
| Stepper 100 回 | 右 50 回 -> 左 50 回 (200 イベント、値は 50->100->50) | **2366 -> 2366 (0)** | 200 | 合格 (文字列 100 本は回収済み) |
| 外れクリック 100 回 | 部品の無い場所で down/up (200 イベント) | **2366 -> 2366 (0)** | **0** | 合格 |
| mouse_move 200 件 x3 | 部品の上を掃くように移動 | 2366 -> 2367 -> 2367 -> 2367 | 0 | 合格 (下記) |

- **present の数え方**: `FmrbApp.gfx_stats[:presents]` は**ホスト側の全体
  カウンタ**でアプリ別ではない。デスクトップの時計が 1 秒に 1 回 present
  するので、無操作でも 1/s の底上げがある。上表の「アプリ由来」はこの底
  (経過秒数) を引いた値。外れクリックの区間は 21 秒で 20 増 = 底のみ、つまり
  **アプリからの present は 0**。
- **mouse_move の +1 について**: 1 回目の掃きで live が 1 増え、2 回目・
  3 回目では増えない。**初回だけ発生して以後定常**なので蓄積ではない
  (`:mouse_move` シンボル等の初回インターン)。`handle` は mouse_move を
  先頭の型判定で弾いており、確保も present もしない。
- **1 イベントの処理時間** (`handle` + `flush` を `Machine.board_millis` で
  挟んだ累計 / 件数。sim、ms 分解能):

  | 操作 | 件数 | 累計 | 平均 | 最大 |
  |---|---|---|---|---|
  | Button の down/up | 200 | 45 ms | 0.23 ms | 1 ms |
  | Stepper の down/up | 200 | 161 ms | 0.81 ms | 2 ms |
  | 外れクリック | 200 | 1 ms | 0.005 ms | 1 ms |

  Stepper が重いのは flush 1 回で矩形 6 + 文字 3 コマンド出るため。
  実機 (Tab5 / S3) の数字は未取得 — **ユーザ確認待ち**。

- **押下と離しで present が 2 回**になる (指示書の表は Stepper 100 回で
  present 100 回を期待していた)。押下表示を出す以上 down で 1 回描くのは
  避けられないので、1 操作 = 2 present が設計上の下限。押下表示が要らない
  部品を将来足すならそこだけ down を無描画にできる。

## U2 への申し送り

### 最重要: `@pressed` 経由の仮想ディスパッチ (T3 で最初に疑うところ)

**U2 T3 (`FMRB_APP_ENGINE_DESKTOP=spinel` でコンパイルを通す) で最初に
引っかかる候補はここ。** 通らなければ下記の逃げ道へ切り替える。

`FmrbUI#handle` は、押下中の部品を基底型の変数 `@pressed` (中身は
Button / Toggle / Stepper のいずれか) に持ち、そこから

```ruby
fired = w.activate     # Button/Toggle/Stepper でそれぞれ違う
w.release              # 同上
g = w.group            # Toggle だけが非 nil を返す
```

と呼んでいる。**サブクラスのオーバーライドを基底型の変数経由で解決する
= 仮想ディスパッチ**であり、mruby では当然動くが、**Spinel がこれをどう
扱うかは desktop / editor の移植ではまだ踏んでいないパターン**。
`@widgets` (サブクラス混在 Array) からの呼び出しも同じ形。

- 一応の予防として、`group` / `on?` / `set_on` / `value` / `set_value` /
  `press` / `release` / `activate` / `draw` / `set_text` / `relayout` は
  **すべて基底 Widget にも実装を置いてある** (nil / false を返すだけの
  ものを含む)。サブクラスにしか無いメソッドを増やすと Spinel の poly
  dispatch で穴になるので、増やすときは必ず基底にも置くこと。
- ただしこれは「メソッドが存在する」ことの保証でしかなく、**基底型の変数
  から呼んだときに実際にサブクラスの実装へ落ちるか**は別問題。コンパイルが
  通った場合も、U2 では sim で「Toggle を押して離すと排他が効く」
  「Stepper が値を動かす」まで**動作で**確認すること (基底の実装
  (`activate` -> false) に落ちていると、コンパイルは通るのに押しても
  何も起きない、という静かな壊れ方をする)。

**逃げ道 (コンパイルが通らない / 基底実装に落ちる場合)**: 部品の種類を
整数で持ち、`case` で分岐する形に落とす。

```ruby
KIND_LABEL = 0; KIND_BUTTON = 1; KIND_TOGGLE = 2; KIND_STEPPER = 3
# Widget#kind が上のいずれかを返す (各サブクラスの initialize で @kind に固定)
case w.kind
when KIND_BUTTON  then fired = true
when KIND_TOGGLE  then fired = toggle_activate(w)
when KIND_STEPPER then fired = stepper_activate(w)
end
```

`@pressed_kind` を `press` 時に控えておけば `w.kind` 呼び出しすら要らない。
分岐先を FmrbUI 側のメソッドにすれば仮想ディスパッチが 1 つも残らない。
mruby でも同義に動くので dual-safe。ただし可読性は落ちるので、**Spinel が
仮想ディスパッチを扱えると分かった場合は現状のままにする** (先回りして
`kind` 分岐にはしない)。

### その他

- **`each` / `times` / ブロック / `defined?` は fmrb-ui.rb に無い**
  (`grep -n "\.each\|\.times\|\.map\|\.select\|&blk\|yield\|defined?\|include?"`
  が空)。反復は全部 `while`。
- 条件式で呼び出しを単項 `!` で否定していない (fork の codegen bug 回避)。
  `fired == false` / `x.nil?` の形にしてある。
- `Log.*` はこのファイルに 1 つも無い (void 推論の罠を避けるため)。
  メソッド末尾は明示的に `nil` / 値を返している。
- 文字列を作るのは `Stepper#build_text` の補間 1 箇所だけ。
- `gen_app_combined.rb` の `libs` への `fmrb-ui.rb` 追加は U2 の作業。
- kamon はまだ `resizable` ではないので `move` / `invalidate_all` /
  `set_origin` の実地確認は U3 で行う。
