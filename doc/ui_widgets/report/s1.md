# S1 レポート: Enum とホストテスト

段 2 の 1 段目。計画は `doc/ui_widgets/plan_s2.md`。

## Enum

選択肢の配列を左右で送る部品。`config_dialog` が自前で持っている形
(`language: en/ja`、`theme: light/dark/classic`、`timezone` 6 択) を
部品にした。移植そのものは S4。

```ruby
THEMES = ["light", "dark", "classic"].freeze
@ui.enum(:theme, 70, 2, 100, 14, THEMES, index: 1)
@ui.value(:theme)        # -> 1  (添字)
@ui.option_text(:theme)  # -> "dark"
```

### Stepper の派生にした

`Enum < Stepper` で、違いは**表示する文字の作り方だけ** (`build_text` が
`options[@value]` を返す)。押下反転・矢印の幅・端で止まる挙動・`set_value` /
`set_range` はそのまま継承される。実装は 20 行ほど。

結果として **Stepper より軽い**。Stepper は値が動くたびに `"#{@value}"` を
作るが、Enum は**生成時に渡された Array の要素をそのまま指す**ので、
操作時の確保が 0 になる。テストでは `option_text.equal?(OPTS[2])` で
「表の中のオブジェクトそのもの」であることを確認している。

### 決めたこと

- **巡回しない**。端で止まり `handle` は nil を返す。言語やテーマが
  最後から最初へ回ると誤操作しやすく、取り消しも無いため。必要な用途が
  出たら `wrap: true` を足す。
- **`text` という名前を使わない**。`GfxBlock::Recorder` が `draw_text` の
  別名として 4 引数の `#text` を持っており、poly 受信の呼び出しは候補を
  **名前で**引くので、段 1 の `draw` と同じ罠になる。部品側は
  `option_text` にし、基底 `Widget` にも no-op を置いた。
- 空の配列を渡しても落ちない (`min = max = 0`、表示は空文字)。

## ホストテストを rake test に入れた

`test/fmrb_ui/run.rb` (+ `fake_gfx.rb`)。**51 項目**。`rake ui:test` 単体でも
`rake test` の一部としても回る (最初に走る = いちばん安いため)。

`fmrb-ui.rb` は純 Ruby で `FmrbGfx` の描画メソッドしか呼ばないので、
**実物の mrblib ファイルをそのまま `load` して**記録用の偽 gfx に対して
動かしている。docker もファームウェアも実機も要らず、0.1 秒で終わる。

覆っている範囲: 座標と文字サイズ (アプリの size に影響されないこと、flush が
戻すこと、同サイズならコマンド 0)、イベント (押下は報告しない / 外で離すと
報告しない / mouse_move は何も描かない / button 3 を無視)、group の排他、
Stepper の端と `set_range`、Enum、`bg` の伝播、無変化の flush が present
しないこと。

**見えないもの**: 見た目そのものと、グラフィックス側が本当にログどおり
描くか。そこは sim と実機に残る。

## S2 への申し送り

- Scrollbar も同じく **Widget の派生で書けるか**を最初に見る。Stepper とは
  違い「押した場所で上/下」なので `press(px)` ではなく `press` に y が要る。
  **`press(px)` の引数を (px, py) に広げる**必要がある — 基底とサブクラス
  4 つ + 呼び出し 1 箇所の変更で済むが、段 1 の API 変更になる。
- 移植先 7 箇所のうち S2 で触るのは軽い 4 つ (nsf_player / smf_player /
  logviewer / shell)。デスクトップ側 3 つは S4。
