# T4 レポート: 生成時の範囲警告

計画は `plan_s3.md` の T4、背景は `issues_s3.md` の課題 D
(座標系の間違いが静かにずれるだけで、例外も警告も出ない)。

## 入れたもの

`FmrbUI#initialize` で `@win_w = app.window_width` / `@win_h =
app.window_height` を控え、`add(w)` で窓の外にはみ出す部品を 1 行で報せる:

```ruby
if w.x < 0 || w.y < 0 || w.x + w.w > @win_w || w.y + w.h > @win_h
  Log.warn("FmrbUI: widget #{w.id} outside window (#{w.x},#{w.y},#{w.w},#{w.h})")
end
```

- **生成時だけ**。生成は `on_create` なので、この文字列補間は誰の定常経路
  にも乗らない。
- **`move` では警告しない**。monitor が実行時に行を並べ替えるので、
  ここに文字列生成を持ち込まない。この非対称は `add` のコメントに書いた。
- 明示 API (`origin:` 必須化) は採らない (plan_s3.md の判断どおり)。

ホストテスト側は `Log` を記録用のモジュールとして `fake_gfx.rb` に置いた
(warn を配列に貯めるだけ)。検査は 6 項目:

- 収まる部品は黙る
- 下にはみ出す / 右にはみ出す部品で 1 件ずつ出る
- 文言に部品 id と矩形 (`(1,51,40,16)`) が入る
- `move` では出ない

`ruby test/fmrb_ui/run.rb` -> **158 項目全通過**。
`rake spinel:doctor` は fmrb-ui.rb への指摘 0。

## sim: 本当に出るかの確認 (positive control)

「既存アプリで 0 件」だけだと検査が死んでいても同じ見え方になるので、
**わざとはみ出した部品を持つ一時アプリ**を作って sim で走らせた
(`flash/app/test/ui_warn.app.rb`。flash/ 以下は sim が実行時に読むので
再ビルド不要。**確認後に削除済み、コミットしていない**)。

窓 120x80 に、収まるボタンと y=200 のボタンを 1 つずつ:

```
W (19:37:54.814) UI Warn: FmrbUI: widget outside outside window (5,211,40,16)
```

はみ出した方だけが出て、収まる方は何も出さない。ログ 1 行で部品 id と
矩形が読める。

## sim: 既存アプリの起動ログ

FmrbUI を使う 9 本を起動して `docker logs fmruby_core | grep "FmrbUI:"`:

| アプリ | 起動方法 | warn |
|---|---|---|
| デスクトップ + 全ダイアログ | ブート (ダイアログの部品は `on_create` で全部作られるので、開かなくても検査される) | 0 |
| monitor | メニュー | 0 |
| logviewer | メニュー | 0 |
| shell | ランチャー | 0 |
| kamon | `run /app/demo/kamon.app.rb` | 0 |
| picoruby | `run /app/demo/picoruby.app.rb` | 0 |
| midi_apu | `run /app/demo/midi_apu.app.rb` | 0 |
| nsf_player | ランチャー | 0 |
| smf_player | `run /app/tool/smf_player.app.rb` | 0 |

**合計 0 件**。上の positive control を足したときだけ 1 件になる。
つまり**現状の座標にはみ出しは無い**ので、直すべきものの列挙も無い。

エラーログ (`grep -cE "^E \(|Exception|abort"`) は、VM プールを使い切った
ときの `No free context slots` (アプリを 6 本同時に開いた検証手順の都合)
以外は 0。この 2 件は T4 とは無関係で、アプリを kill してから起動し直すと
出ない。
