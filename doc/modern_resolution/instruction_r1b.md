# R1b 指示書: 640x360 のデスクトップで、古い全画面のアプリの間だけ 426x240 にする

> 2026-11-18 | 親セッションからサブ (Opus) への指示。計画の正は plan.md (2 章の 5、4.3)、作りの見立ては
> report/r0.md の 7 章 (全部読む)、今の高解像度モードの作りは doc/reference/fullscreen_hires.md と
> doc/fullscreen_hires/ (plan.md、report/h1〜h5)、R1a の結果は report/r1a.md。先に全部読む。

## 1. この段で作るもの

基本の画面が 640x360 のとき、**高解像度の属性の無い全画面のアプリが全画面の一番上にいる間だけ、
画面を 426x240 (3 倍) に切り替える** (ユーザの決定)。今の高解像度モード (基本が 426x240 のとき、属性の
あるアプリの間だけ 640x360) の逆向きで、同じ `SET_SCREEN_MODE` の道を一般化して作る (r0.md 7 章の 1〜3)。

- 基本が 426x240 のときの動きは、今と 1 つも変えない (高解像度モードはそのまま)。
- 基本が 640x360 のとき:
  - 属性のあるアプリ (`fullscreen_hires`。エディタ・麻雀など): 切り替えずに 640x360 の全画面 (R1a のまま)。
  - 属性の無いアプリ: 426x240 の canvas で作られ、前にいる間だけ画面が 426x240 になる。抜ける・隠れる・
    終わる・落ちるで 640x360 に戻る。入力の座標・ポインタ・遠隔の画面の写しと座標も追従する
    (今の高解像度モードと同じ守り: 待つ・打ち切る・遅れて出た絵を受ける)。
  - **どの大きさでも描けるアプリ** (領域の大きさから配置を決めるもの。r0.md 7 章の 4: shooter・welcome・
    picorabbit など) は切り替えず、640x360 の全画面で出す。そのための宣言を `.app.toml` に 1 つ足す
    (今ある `FMRB_FULLSCREEN_HIRES_ANY` を使う見立て)。**鍵の名前は親の仮決めで `fullscreen_any_size = true`**
    (もっと合う既存の名前・流儀があればそちらに合わせ、report に書く)。宣言の無いアプリは 426x240 に
    切り替える (これが既定)。
  - 組み込みのアプリと見本 (`flash/app/`、`main/ruby/default_app/`) の全画面のものを一通り見て、
    640x360 でそのまま正しく描けるものにだけ宣言を付ける (付けたものと、付けなかった理由を一覧に)。
    アプリの描き方は直さない (R2)。
- sim (graphics-audio) にも同じ一般化を入れ、sim の Modern (640x360) で確認できるようにする。
  ブラウザ版・ネイティブ版・Retro の動きは変えない。
- F11 で Window と全画面を行き来するアプリ、全画面のアプリの上にダイアログや別の全画面のアプリが
  重なったとき、全画面のアプリからデスクトップへ戻るとき、の出入りが正しいこと。
- チェックポイントで全画面のアプリを運ぶ場合 (r0.md 7 章の「難しい所」) は、**この段では作らない**。
  今より悪くならないこと (運んだ先で落ちない) だけ確認できる範囲で見て、残件として書く。

## 2. 受け入れ条件

1. sim の Modern (標準構成)、基本 640x360 で: 属性の無い全画面のアプリ (rpg_demo・raycaster・BASIC の
   全画面など、R0・R1a で崩れたもの) を開くと、画面が 426x240 になり、426x240 のときと同じ絵で出る
   (基本 426x240 のときの同じ場面の写しと画素で比べる)。閉じるとデスクトップが 640x360 で戻る。
   入力 (キー・クリックの位置) が正しい。宣言を付けたアプリは 640x360 のまま正しく出る。
   属性のあるアプリ (エディタの全画面) は 640x360 のまま。全部 mruby の構成でも 1 回。
2. sim の Modern、基本 426x240 で、今の高解像度モード (エディタの全画面の出入り、麻雀か hires_test) が
   変わらない。
3. P4-Nano (`app_sync` で焼く。ユーザの許可あり): Config で 640x360 にし、属性の無い全画面のアプリを
   開いて閉じる・エディタの全画面・宣言を付けたアプリを、遠隔の写し (大きさが 426x240 相当と 640x360 で
   切り替わること) と入力で確認する。切り替えのときのログ (`screen mode:` の行) に打ち切り・失敗が無い。
   **終わったら 426x240 に戻す**。端末の `/home` に触らない。
4. `rake regress` が通る。最後に 1 回 `rake regress:screens`・`rake regress:size` (内蔵 RAM が増えていない)。
   Tab5 のビルドが通る。
5. `git status` に取りこぼしが無い (各リポジトリ。前からあるものは除く)。sim・ネイティブ版・シリアルの
   capture は止めてある。`build-linux/` は両リポジトリとも Retro の標準構成。試験の設定は元に戻してある。

## 3. 範囲と止まる条件

- 触ってよい所: fmruby-core の表示 (`main/drivers/display_local/` の画面の切り替えの部分)、カーネル
  (C と Ruby。mruby 版と Spinel 版の両方)、`.app.toml` の読み取りと宣言を付けるアプリの `.app.toml`、
  `sig/` (要れば。直したら `rake clean`)、案内の文書 (`doc/reference/fullscreen_hires.md`、
  `flash/usr/share/doc/display*.md`、アプリの書き方の skill は直下なので report に直す所を書くだけ)、
  `doc/modern_resolution/report/r1b.md`、`rake docs:index` の結果。
  fmruby-graphics-audio は sim の同じ一般化に要る所だけ (`develop` からブランチ `modern-resolution` を
  切ってコミット)。
- **触らない**: `config/` の解像度の既定 (R2)、sdkconfig、合成の手当ての作り (R0b。切り替えの部分と
  重なる所は、絵が変わらないことを確かめながら最小限)、アプリの描き方、リンクのプロトコルの形
  (`SET_SCREEN_MODE` に項目を足す必要が出たら、**足す前に止まる**。今の項目で大きさを運べるなら
  そのまま使う)、submodule の中、回帰の基準、直下のリポジトリ、asterism-tutor。plan.md は親が直す。
- fmruby-core はブランチ `modern-resolution` に続けてコミットする (この指示書はコミット済み)。
  **どのリポジトリも push しない。develop へマージしない。** `git add -A` を使わない。
- P4-Nano: 焼くのは `app_sync` だけ (`FMRB_HW_TARGET=NARYAv4 FLASH_BAUD=115200 HOST=192.0.2.20 rake flash:app_sync`)。
  MCP の flash・tab5_*・sim_* は使わず CLI を使う。シリアルの detach・attach の繰り返しは 2 回まで。
- 止まる条件: ユーザの作業が要る。範囲の外の変更が要る。P4-Nano が起動しなくなった (426x240 で起動する
  所までは自分で戻す)。プロトコルに項目を足す必要がある。**利用者から見た動きを、plan・この指示書に
  無い形で変える必要が出たとき** (選ばずに止まる)。
- Spinel の罠 (doc/editor_multi_file/instruction_m1.md 4 章)。標準構成でエディタが開いて 1 打鍵できること。
  内蔵 RAM を増やさない。
