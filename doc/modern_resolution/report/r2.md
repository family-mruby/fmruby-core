## 2. 戻り道の直し (Shift の押しっぱなし)

### 2.1 原因

見立てどおり。キーボードは状態が変わったときにしか報告を送らない (HID の idle が 0)。電源を入れる前から
押している Shift は、キーボードが認識された後に変化が無いので報告が来ず、R1a の「キーの事象ごとに
Shift の状態を書く」形では拾えない。連打なら押した変化が報告になるので効いた。

### 2.2 作り

`main/drivers/usb/usb_task.c` (Modern だけ、`FMRB_MODERN_RESOLUTIONS`):

1. Boot のキーボードが `hid_host_device_start` まで済んだ所 (`Boot keyboard ready` の行) で、
   使い捨てのタスク `kbd_state` (スタック 3 KB、PSRAM、優先度 4) を作る。
2. そのタスクが HID の GET_REPORT (Input、ID 0、8 バイト) でキーボードの今の状態を読み、
   `Keyboard state at connect (slot N): modifier=0x..` を 1 行出す (0x02・0x20 が Shift)。
3. 修飾キーが押されていれば、修飾キーのバイトだけを入れた報告を、HID のタスクが報告を扱うのと同じ
   `process_keyboard_report` に、機器の錠を取って渡す。今までの「前の報告との差」の作りで、押された
   修飾キーが KEY_DOWN になり、`host_task.c` の `s_shift_down` が立つ。キーの配列は空にするので、
   起動のときに押していた文字は打ち込まれない。
4. タスクは終わると自分を消す (WithCaps で作ったものを `fmrb_task_delete` が正しく消すよう、
   ハンドルを登録して作る)。

連打の道は変えていない (押すたびの報告は今までどおり来る)。`host_task.c` は判定を変えておらず、
コメントだけを今の作りに合わせた。待ちは足していない: GET_REPORT は起動の道 (host タスクの
INIT_DISPLAY) と関係のないタスクで動き、host タスクは何も待たない。

### 2.3 3 回作った理由 (P4-Nano のシリアルで確かめた)

| 版 | 頼む所 | 結果 |
|---|---|---|
| 1 | HID ドライバの CONNECTED のコールバック (`hid_host_device_start` の前) | 5 秒で打ち切り (`Control transfer timeout`)。キーボードが使えるのが 1.6 秒 → 6.6 秒に遅れた |
| 2 | USB Host Library のタスク (start の後、`usb_host_lib_unblock` で起こす) | キーボードは 1.6 秒で使えるが、GET_REPORT は 5 秒で打ち切り |
| 3 | 使い捨てのタスク | 1.785 秒に `modifier=0x00` が返った。キーボードは 1.612 秒で使える (直す前と同じ) |

- 1 が止まる理由: コールバックは `hid_host_handle_events` (= `usb_host_client_handle_events`) の中で
  呼ばれ、転送の完了を知らせるのも同じ関数なので、自分で待っている間は完了が来ない。
- 2 が止まる理由: 転送の完了 (エンドポイントの事象) を処理するのは `usb_host_lib_handle_events` で、
  そのタスクが待っていると進まない。
- 3 は、HID のタスクも Library のタスクも空いているので進む。
- 3 の最初の版は、押された修飾キーを報告の待ち行列に入れていたが、HID のタスクは最大 100 ms の
  待ちの合間にしか行列を見ないので、画面の初期化 (約 0.1 秒後) に間に合わないおそれがあった。
  その場で扱う形 (2.2 の 3) に改めた。

ついでに分かったこと (直していない): 今の `usb_task.c` の、マウスへの SET_PROTOCOL を CONNECTED の
コールバックから出している所も、1 と同じ形なので、出せば 5 秒の打ち切りになる見立て。コメントには
「EP0 の取り合いで打ち切りになる」とあるが、同じ理由かもしれない。今の P4-Nano の機器 (Logitech の
受信機、設定ファイルで指定) はこの道を通らないので確かめていない。範囲の外。

### 2.4 時間とメモリ (P4-Nano、640x360 の既定の設定で起動)

| 行 | 時刻 |
|---|---|
| `Boot keyboard ready for slot 0` | 1.612 s |
| `Keyboard state at connect (slot 0): modifier=0x00` | 1.785 s |
| `host: Graphics transport initialized: 640x360` (Shift を見た直後) | 1.892 s |
| `display_local: Framebuffer allocated: 640x360` | 1.926 s |

- 答えが返るまで約 0.17 秒 (このキーボードは Logitech の Unifying の受信機)。画面の初期化までの余裕は
  約 0.1 秒。キーボードの認識や答えがこれより遅いキーボード (USB ハブ越しなど) では効かず、設定どおり
  上がる (連打なら効く)。案内の文書には書いていない (R1a の「キーボードは端末に直接つなぐ」のまま)。
- 内蔵 RAM: 静的な変数は PSRAM の `uint32_t` 4 個だけ。起動後の `IRAM free` は直す前のファームと同じ
  (215,480 / 215,488 B、10 秒周期の 1 回目)。`usb_host_lib`・`hid_host` のスタックの底も変わらない。
  使い捨てのタスクは PSRAM に作るので、内蔵 RAM は一時的にも使わない (WithCaps は TCB も PSRAM)。
- 起動の速さ: キーボードが使えるようになる時刻・画面の初期化の時刻とも、直す前と同じ。
