# R0b 指示書: 表示の合成の手当てと、測り直し (P4-Nano)

> 2026-11-18 | 親セッションからサブ (Opus) への指示。計画の正は plan.md、計測と見立ての正は
> report/r0.md (どちらも先に全部読む。特に 2 章の計装、4 章の表、5.2・5.3、5.4 の罠、9 章の再開の手順)。

## 1. この段でやること

**出る絵を変えずに**、表示の合成 (`main/drivers/display_local/`) を速くする。解像度の既定・設定の項目・
決め打ちの直しは R1・R2 (この段では触らない)。効果は 426x240 (Tab5 を含む) にも出る。

### 1.1 手当て (report/r0.md 5.3 の番号)
- **(1) clear を飛ばす**: 一番下の canvas が不透明で画面全体を覆っているとき、フレームバッファの
  clear をしない。条件が外れる場合 (壁紙が無い・canvas が画面より小さい・透過色を持つ・高解像度の
  全画面への切り替えの途中・起動の最初のフレームなど) を洗い、そのときは今のまま clear する。
- **(2) 前面の層の blend を絞る**: デスクトップの前面の層 (メニューバー・ランチャー・ドロップダウン・
  ファイルマネージャを描く、ほとんど透過色の全画面の canvas) を、中身のある範囲だけ blend する。
  範囲の持ち方 (描画コマンドから汚れた矩形を集める・アプリが範囲を知らせる・行ごとの有無など) は
  任せるが、**範囲の取りこぼしで絵が欠けないこと**を最優先にする。ほかの透過色を持つ canvas にも
  同じ仕組みが効くなら効かせてよい。
- **(4) present のたびの写し (commit の memcpy) を減らす**: 変わった行 (か矩形) だけ写す、など。
  working と committed の入れ替えは、アプリが前のフレームの絵を前提に描き足す使い方を壊すので、
  採るなら安全な条件を示す。**危ないと判断したら入れず、理由を report に書く**。
- (3) SRM の非 blocking と (5) 変わった所だけ合成は、**作らない**。(1)(2)(4) の後に残る時間の内訳から、
  要るかどうかの見立てだけ report に書く。
- 手当てはそれぞれ別のコミットにする (効き目を 1 つずつ言えるように。計測も、できれば 1 つずつ)。

### 1.2 PSRAM の写しの速さ (提案まで)
- 204 KB の memcpy に 6.3 ms (約 33 MB/s) だった理由を調べる: PSRAM の速度とモードの設定
  (`config/sdkconfig.defaults.naryav4`・`tab5` と、ビルドでできた sdkconfig を**読むだけ**)、キャッシュ
  (L2・行の大きさ)、写し元と写し先が両方 PSRAM であること、memcpy の実装 (語単位か)、ほかのコアとの
  取り合い。小さな計測 (起動時に 1 回だけの写しの速さの計測など) を入れて確かめてよいが、
  **計測のコードはコミットしない** (結果だけ report に)。
- **sdkconfig・sdkconfig.defaults は編集しない**。効きそうな設定があれば、手元だけで試して数字を取り
  (コミットしない)、提案として report に書く (何を、どの値に、効き目、副作用、Tab5 への影響)。
  コード側で直せるもの (写し方) があれば、それは (4) と一緒に入れてよい。

### 1.3 測り直し (P4-Nano)
- **シリアル (`/dev/ttyACM0`) は、ユーザが USB を差し直すまで無い**。始めに fmruby-core で `rake attach` を
  試し、出なければ、**先に 1.1・1.2 の実装とホストでの確認を済ませ**、その後にもう一度試す。それでも
  出なければ、計測を残して止まり、report に「計測待ち」と書いて返す (親がユーザに頼む)。
- 計測は R0 と同じ台本 (`tmp/modern_resolution/` の `scene.sh`・`agg.rb`・`robust.sh`。gitignore の下に
  残っている) で、**同じ場面 1〜6 を、426x240 と 640x360 の両方**。640x360 は R0 で測れなかった
  場面 3〜6 を含めて全部。主な場面は 2 回ずつ。
- R0 の罠 (5.4): MJPEG のクライアントをつないだ・切った直後、ホストが重いときに、シリアルの取り込みが
  止まった。**計測の間は sim のビルドなどホストの重い仕事を流さない**。遠隔の画面を使う場面 6 は
  最後に回す。取り込みが止まったら、まず端末が落ちていないか (`/app/list` の pid の並び) を見る。
  `rake detach`・`attach` の繰り返しは 2 回までにし、それで戻らなければ止まる (機器が消える)。
- 焼くのは `app_sync` だけ (`FMRB_HW_TARGET=NARYAv4 FLASH_BAUD=115200 HOST=192.0.2.20 rake flash:app_sync`)。
  解像度は R0 と同じやり方 (端末の `/etc/system_conf.toml` を退避 → 変えて put → 再起動 → 終わったら戻す)。
  **端末の `/home` (特に `/home/asterism/`) に触らない**。MCP の flash・tab5_* は使わない。
- 入力の遅れ: R0 では `hid_lat` が件数不足で出なかった。場面 2 で 1000 件を超えるまで打つか、
  今ある計装で取れる別の値で、426x240 と 640x360 を比べる。
- R0 で出た Interrupt WDT の panic (5.5) がまた出たら、時刻・場面・backtrace を記録する (直さない)。

## 2. 受け入れ条件

1. **絵が変わらない**: `rake regress` (描画の記録) が通る。sim とネイティブ版 (`native_*` か
   `tools/fmrb_native.rb`。display_local を通る方) で、デスクトップ・メニューを開いた状態・ランチャー・
   ファイルマネージャ・Window を重ねた状態・Window を動かした後・全画面のエディタの出入り・壁紙なしの
   設定、の写しが手当ての前後で同じ (画素の比較。比べ方を report に書く)。P4-Nano でも、同じ場面の
   遠隔の写しを手当ての前後で比べる (JPEG なので目で見て欠け・残りが無いこと)。
2. 手当てごとの効き目が、P4-Nano の `display_local: frame:` の行の区間の数字で言える。
3. 表: 場面 1〜6 × (426x240・640x360) × (手当ての前 = R0 の値・後)。既定にする線 (plan 2 章の 9:
   手当ての後の 640x360 が、場面 1〜4 で、手当ての前の 426x240 の実測より遅くならない) の判定。
4. 内蔵 RAM が増えていない (`rake regress:size` を最後に 1 回。足す静的な変数は PSRAM の属性)。
   PSRAM の増え方があれば書く。
5. `rake regress:screens` が通る (最後に 1 回。標準構成のエディタの 1 打鍵を含む)。
6. Tab5 のビルドが通る (`FMRB_HW_TARGET=TAB5 rake build:esp32`。焼かない。**終わったら NARYAv4 の
   ビルドに戻すか、どちらのビルドが `build/` に残っているかを report に書く**)。
7. コミットされているのは手当てと文書だけ。`config/`・sdkconfig・解像度に関わる動きは変わっていない。
   `git status` に取りこぼしが無い (前からある 3 つを除く)。
8. 終わったとき: P4-Nano は 426x240 の設定で、手当て入りのファームで起動している。sim・ネイティブ版・
   シリアルの capture は止めてある。`build-linux/` は Retro の標準構成。

## 3. 範囲と止まる条件

- 触ってよい所 (fmruby-core): `main/drivers/display_local/`、(2) の範囲の持ち方に要るなら描画コマンドを
  受ける側 (同じディレクトリ) まで。`doc/modern_resolution/report/r0b.md`、`rake docs:index` の結果。
- **触らない**: リンクのプロトコルの形 (`components/fmrb_wire/`。足す必要が出たら止まる)、デスクトップと
  アプリの Ruby (範囲を知らせるためにアプリを直す形は採らない。表示の側で分かる方法にする)、
  `config/`・sdkconfig、解像度の既定、submodule の中、graphics-audio (sim の合成は別物。直さない)、
  直下のリポジトリ、回帰の道具の本体と基準。plan.md は親が直す。
- 本体の checkout、ブランチ `modern-resolution` に続けてコミットする (この指示書はコミット済み)。
  コミットの書き方は fmruby-core/CLAUDE.md。**push しない。develop へマージしない。** `git add -A` を使わない。
- 止まる条件: ユーザの作業が要る (USB の差し直しは 1.3 のとおり)。P4-Nano が起動しなくなった
  (426x240 で起動する所までは自分で戻す)。絵が変わる形でしか速くできない。範囲の外の変更が要る。
  **利用者から見た動きが変わる** (例: ちらつき・tear が増える) 手当てしか無いとき。

## 4. report (doc/modern_resolution/report/r0b.md)

- 手当てごとの作り (条件、範囲の持ち方、守り)、効き目、入れなかったものと理由。
- 受け入れ条件 3 の表と判定。残った時間の内訳と、次に効く手の見立て ((3)・(5) が要るか)。
- PSRAM の写しの速さ: 分かった原因、試した設定と数字、提案。
- 絵が変わらないことの確認のやり方と結果。
- 踏んだ罠、確認していないこと、ユーザに決めてほしいこと、ユーザに見てほしいこと (HDMI)、コミットの一覧。
