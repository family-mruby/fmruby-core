# 3.1.0 の前の直し その 2 の結果 (F1 のヘルプを言語ごとに 1 つのファイルへ)

> 2026-11-27。指示は instruction_r2.md。本体の checkout (ブランチ app-uart) と sim (Retro) で確認した。
> ESP32 のビルド・実機・シリアルは触っていない。

## 1. 決めた形

`/help` は 5 ファイルにした。

| ファイル | 中身 |
|---|---|
| `ja.md`・`en.md` | その言語の全クラスのページを並べた物。1 ページは前の `<Class>.<lang>.md` とバイト単位で同じ |
| `ja.idx`・`en.idx` | 1 行 1 クラス、`<Class>\t<位置>\t<長さ>` (バイト) |
| `index.txt` | 前と同じ (`<名前>\t<Class>`) |

F1 の流れ: `index.txt` で名前からクラス (前と同じ) → 読む人の言語の `.idx` でクラスの行を探す → `EditorCore.load_range`
で `<lang>.md` のその範囲だけをエディタの文書に読む。本文の全部をメモリに載せることはない。

- **位置へ進む所は C に足した**。`FmrbFile` の sig には位置と長さで読む関数が無く、picoruby の IO にも seek が無い。
  エディタは前から文書を C (`ec_load_file`、ファイルを 2 KB ずつ文書の arena へ) で読んでいるので、その隣に
  `ec_load_range(slot, path, offset, length)` を足した (`fmrb_hal_file_seek` → 同じ読み込みを長さで止める)。
  mruby のバインディング (`editor_core_mrb.c`) と Spinel の FFI (`fmrb_spx_editor.c`・`fmrb_editor_ffi.rb`) の両方に出した。
  「数十 KB の塊に分けて数ファイル」の案は、塊ごとに複数クラスが入って表示が変わるか、ファイル数が戻るので採らなかった。
- **クラスの表は言語ごとに別ファイル** (`.idx`) にした。`index.txt` に混ぜると F1 のたびに読む量が両言語分 (約 6 KB) 増える。
  分ければ読むのは自分の言語の約 3 KB だけで、ファイルが 2 つ (2 ブロック) 増えるだけ。
- **表示は今と同じ**。ステータス行の名前は前のファイル名 (`[Help] Dir.en.md`) を仮の名前として `@current_file` に置く。
  中身・見出しへの飛び方・強調も同じ。
- ヘルプを開いている間に File > Save を選ぶと、前は `/help/<Class>.<lang>.md` を上書きしていた。今は仮の名前なので
  書くと迷子のファイルができる。`save_file` の頭で、ヘルプの間は「説明の画面です (書けません)」を出して止めた
  (Ctrl+S は前から止めていた)。
- 表 (`.idx`) にクラスが無いときは、前の「ヘルプがありません」と同じ扱い (編集中の文書は退避しない)。範囲が読めなかった
  ときだけは、退避した文書を戻して同じ表示を出す (前は空の文書が残り得た)。

古い形 (`/help/<Class>.<lang>.md`) が残った端末でも、新しいファームは新しい 5 ファイルだけを読む。古い物は app_sync の
`PRUNE=1` で消える。ブラウザ版・ネイティブ版は `flash/help` をフォルダごと写すので、そのまま新しい形になる。
WebConsole の `help.json` は `TiHelp.build` から直接作るので形は変わらない。サイトのクラスリファレンス (`rake ti:site`) も
sig から作るので変わらない (`ti:site:test` は通る)。

## 2. ファイル数と大きさ

ブロックは flash_layout.md 3.2 の数え方 (4 KB、512 B 以下は目録の中、フォルダの目録 2 ブロック、P4-Nano の実測に合わせて
1.10 倍) の見積もり。像は作っていない。

| | ファイル | 中身 | ブロック | 見積もり (1.10 倍) |
|---|---|---|---|---|
| 前 | 269 | 857,258 B | 318 | 約 1,400 KB |
| 後 | 5 | 863,759 B | 215 | 約 950 KB |

約 **0.45 MB** 空く見込み (中身は表の 6.5 KB だけ増える)。全機種同じ (StickS3・AtomS3R は前から `/help` を入れていない)。

## 3. F1 を開く速さとメモリ (sim、Retro、Spinel のエディタ)

同じ手順 (エディタを開き `FmrbFile.read`・`p.remote_methods`・`g.draw_text` の順に F1) を直す前と後で流した。
`help_lat` と、ページを読んだ直後の `edit_doc` の pool。

| ページ | help_lat 前 → 後 | pool 前 → 後 | arena (前後同じ) |
|---|---|---|---|
| Dir.en.md (306 行) | 0 → 0 ms | 18 → 18 % | 20,104 |
| Asterism__Proxy.en.md (89 行) | 0 → 0 ms | 31 → 32 % | 7,072 |
| FmrbGfx.en.md (1352 行) | 2 → 2 ms | 22 → 27 % | 97,144 |

pool の % は GC の時期で揺れる (同じ手順の退避の行でも 22〜33 % と動く)。コードの上での差は、F1 のたびに `.idx`
(約 3 KB) を 1 回読むことだけ (前と同じく `index.txt` 33.5 KB も読む)。文書の arena と行数は前と同じ。内蔵 RAM の
静的な変数は足していない (読み込みの 2 KB は前と同じく arena から取る)。

## 4. 確かめた事

- `rake regress`: ホスト 40 組・描画の記録 310 件すべて通る。
- 新しい試験 `rake ti:help:test` (`tools/ti/test_help/run.rb`、`rake test` に入れた): 5 ファイルができる、両言語で全クラスが
  表にある、ページが隙間なく並びファイルを覆う、各ページが生成器のクラスの文と同じ、`index.txt` のクラスに全部ページが
  ある。エディタ側は本物の `ti_ui.rb` を差し替えの部品の上で動かし、全クラス・両言語で `help_section` → `load_help_page`
  が正しいバイトを読むこと、ASCII のクラス (`Array`)・`::` のクラス (`Asterism::Proxy`)・メソッド名 (`draw_text`・`read`)・
  演算子 (`<<`)・無い名前・後ろが一致するだけの名前を確かめる。
- 生成した 268 ページを、直す前の `flash/help/<Class>.<lang>.md` とバイト単位で比べて全部一致、`index.txt` も一致。
- sim (Retro): 英語で 3 ページを直す前と後で撮り、時計の行より下が画素単位で一致。日本語でも `Array`・
  `p.remote_methods`・`g.draw_text` を開き、本文が `ja.md` の該当ページのとおり出ること、Esc で編集中の文書が戻ることを見た。

C の `ec_load_range` はホストの試験が無い (エディタの C を host で組む足場が無い)。sim の Spinel のエディタで動いている。
mruby のエディタのバインディング (`m_load_range`) はビルドが通ることまで。

## 5. 見立てと違った点

- 空く量は約 0.7 MB の見立てに対し、見積もりで約 0.45 MB。前の 269 ファイルのブロックは約 1.4 MB (1.5 MB ではない) で、
  まとめても中身の 844 KB 分のブロックは残る。実際の量は P4-Nano の像の実測で確かめてほしい。
- 前から有る食い違いを 2 つ見つけた (中身・引き方は変えない指示なので直していない)。
  - `::` のクラス (`Asterism::Proxy` など) のメソッドで F1 を押すと、ページの先頭が出て、そのメソッドの節へ飛ばない。
    `help_jump_to` が見出しを `# Asterism__Proxy#remote_methods` (表の綴り) で探すが、ページの見出しは
    `# Asterism::Proxy#remote_methods`。
  - `String#index` の節で、要約の行に `<<en>>` から後ろの英語が残る (日本語のページ)。生成器が、メソッドの節の
    ファイル名 `index.md` をクラスの説明の節と取り違え、頭の 2 行しか言語を分けない。メソッド名が `index` のクラスすべてに
    起きる。
  どちらも直すと表示が変わるので、直すかは親が決める。
