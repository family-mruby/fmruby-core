# 3.1.0 の前の直し その 1 の結果 (小さい物 5 つ)

> 2026-11-26。指示は instruction_r1.md。本体の checkout (ブランチ app-uart) と sim (Retro)・ネイティブ版で確認した。
> ESP32 のビルド・実機・シリアルは触っていない。5 の道具はリポジトリの直下 (tools/) にあり、そちらの develop にコミットした。

## 1. ls でフォルダに `/` が付かない (ESP32)

- 原因: `fmrb_hal_file_esp32.c` の `fmrb_hal_file_readdir` が `stat` を呼んでいるのに、大きさと時刻だけを写し、`mode` を 0 の
  ままにしていた。`fmrb_bnd_file_list_raw` は `FMRB_S_ISDIR(mode)` を見るので、全部ファイルになっていた。
- 直し: `stat` の `st_mode` を `mode` に入れる (`fmrb_hal_file_stat` と同じ)。`stat` が失敗したときは `d_type` から
  (`DT_DIR` → `FMRB_S_IFDIR`、`DT_REG` → `FMRB_S_IFREG`)。`is_dir` は `mode` から決め、2 つが食い違わないようにした
。POSIX の実装 (sim・ネイティブ版) は前から `mode` を埋めていて、触っていない。
- 確かめた事: sim (Retro) とネイティブ版のシェルで `ls /usr/share` がフォルダに `/` を付けて出る (今までどおり)。ESP32 は
  ビルドしていない (親が実機で見る)。

## 2. メニューバーの印「RS」を Modern とブラウザ版だけに

- 作り: デスクトップの既定は mruby のバイトコード (`FMRB_APP_ENGINE_DESKTOP` の既定は mruby。Spinel は選んだときだけ)。
  印の 3 つのメソッド (`rshell_pad`・`draw_rshell_icon`・`rshell_state_changed`) を `RshellMarkMixin`
  (`system_desktop/rshell_mark.rb`) に移し、Retro のビルドは代わりに何もしない同名の物 (`system_desktop_retro/rshell_mark.rb`)
  を使う。機種で分けるやり方は、サービスのホストを Retro から外す `fmrb_hw_family_is_modern` に倣い、
  `compile_ruby_to_bytecode.cmake` に `FMRB_MIXIN_EXCLUDE_<app>`・`FMRB_MIXIN_EXTRA_<app>` (部品を抜く・代わりを足す) を足した。
  ブラウザ版・ネイティブ版 (`rakelib/hosted.rake`) と Spinel のデスクトップは今までどおりフォルダを全部読むので印がある。
- 測った数 (`rake regress:run ONLY=retro`、system_desktop の idle):

  | 状態 | used |
  |---|---|
  | リモートシェルの前の基準 | 819,080 |
  | 印を入れた後の基準 | 823,776 (+4,696) |
  | 直す前 (このブランチ。UART で +1,608) | 825,384 |
  | 直した後 | **821,816** (-3,568) |
  | 元 + UART なら | 820,688 |

  4.7 KB のうち 3.6 KB が戻り、**1,128 B が残る**。ほかの点 (running ほか) も同じ差。基準の更新はしていない (UART の分
  と一緒に、重い回帰の時に人が確かめて更新する)。
- 見立てと違った点: 印のバイトコードは 0.7 KB (mrbc -g の .mrb の差) で、プールの 4.7 KB の大半はコードの大きさではなく、
  デスクトップのクラスのメソッドの表が 2 つ増えて大きくなった分と見ている (モジュールに出すと戻った)。同じメソッドを
  既にある `TaskbarMixin` に足す形も試したが、825,720 で逆に増えた (そちらの表が大きくなった)。残る 1.1 KB は代わりの
  モジュール・include・3 つのメソッドの分。これ以上減らすには、本体の呼び出し (メニューバー・メッセージ・タスクバー) ごと
  機種で分ける必要がある。
- 確かめた事: Retro のビルドの結合ファイルに代わりの物が入る (`build-linux/ruby_mrb/kernel/system_desktop_combined.rb`)。
  sim (Retro)・ネイティブ版でデスクトップが上がる。印が出る所の目視 (Modern でセッションを開く) はしていない。

## 3. シリアルの MIDI 出力を、開いたアプリが終わったら放す

- 原因: `fmrb_midi_serial.c` は一度開くと持ち主を持たず、再起動まで UART2 とピンを持っていた。
- 直し: 開いたアプリの task を記録する (`s_owners`、アプリ 1 つに 1 枠、PSRAM)。`fmrb_midi_serial_release_owner(task, app_id)`
  を `fmrb_app.c` の 2 つの片付けの経路 (普通の終わりは VM を閉じた後、kill は `force_release_resources`) で
  `fmrb_uart_release_owner` の隣に呼ぶ (sim でも走る)。最後の 1 つが終わったら閉じ、ピンを放す。閉じる前に、そのアプリが
  MIDI の待ち行列に残した物を落とす (`fmrb_midi_sched_clear_pid`。消えた音の all notes off が出る)。普通の終わりでは
  gem の final が先にこれをしているので何もしない。kill では VM の final が走らないので、ここで初めて出る。
- `app.c` の `_cleanup` (VM を閉じる前) には入れていない。そこで閉じると、final が出す all notes off が書けなくなる。
- 変えていない所: 鳴らしている間・出力先の切り替え、複数のアプリで共有、`close` (全員分を閉じる)、UART との取り合いの
  理由の文 (両方向)。
- 確かめた事 (sim Retro、MIDI の FIFO のモニタ `tools/fmrb_midi_monitor.rb --hex`):
  1. MIDI のアプリで「7 Out: serial」→「1 Scale」: モニタに note on/off が出る。
  2. そのままシリアルターミナルで Open: "UART: UART2 is used by the MIDI serial output" (今のまま)。
  3. MIDI のアプリを Window の閉じるボタンで閉じる: ログ "MIDI serial out closed"。ターミナルの Open で
     "Opened UART2 TX 47 RX 48 115200"。
  4. 「5 SMF」の演奏中に kill: 閉じた後にモニタに `control ch2 cc=123` (all notes off) が出て、ポートが閉じる。
     その後ターミナルが開ける。
  5. 試しのアプリ (残していない) が `FmrbMidi.serial_device` を開いて自分で終わる: "MIDI serial out closed"。

## 4. UART: 開き直した後の前のオブジェクト

- 直し: Ruby の包み (`fmrb-uart.rb`) が番号ごとの世代 (`UART::GENERATIONS`、アプリの VM ごと) を持ち、開けたら 1 進めて
  オブジェクトが覚える。世代が合わない物は `closed?` が true、呼ぶと IOError "UART: closed"、`close` は新しい方を閉じない。
  断られた開き直しは世代を進めない (C 側も前の物を開いたままにする)。境界の関数 (C・ほかの言語) は変えていない
  (オブジェクトを持つのは Ruby の包みだけ)。`sig/uart.rbs` の説明に足した。
- 確かめた事: `test/app_uart/run.rb` に 15 の確認を足した (110 checks 通過。直す前の包みでは 6 つ落ちる)。sim (Retro) の
  試しのアプリで、開き直した後の前の物が `closed?` true・write が IOError・close しても新しい方で `gets` が "hi\n"。

## 5. app_sync が消さない古い本体のファイル

- 直し: `tools/fmrb_rd_fs.rb` の `FmrbStorageSync` が、送った後に、本体の領域 (`/usr`・`/help`・`/etc`・`/lib`・`/boot`・`/bin`・
  `/cache` と、像にある `/app` のフォルダ) のうち像に無い物を選び、数・大きさの合計・先頭 8 行 (フォルダは 1 行) を出す。
  消すのは `--prune` のときだけ。`/home`・`/app/usr`・`/app/test`・`/mnt`・`/tmp`・`/var` は一覧にも出さない。それ以外の
  像に無い物 (例 `/data`、像に無い `/app` のフォルダ) は前と同じく「残した」一覧。
  - `rake flash:app_sync PRUNE=1`、`fmrb_flash_keep.rb sync --prune`、`fmrb_rd_fs.rb <IP> sync <root> --prune`、
    MCP の flash に `prune` (app_sync のときだけ。説明と README に書いた)。
  - **決定に足した物**: 端末が保存した設定 `/etc/system_conf.toml` は消さない (今の sync も「端末の設定」として送らずに残す。
    Retro の像には無いので、足さないと PRUNE=1 で消える)。
- 確かめた事: `tools/fmrb_rd_fs_sync_test.rb` に 6 つの試験 (選ぶ物・数と大きさ・行・prune が消す物とそれ以外・dry run・
  長い一覧)。14 runs 通過。`ruby tools/mcp/selftest.rb` 通過。端末での確認はしていない (親がする)。

## 7. 残り (親が実機で見る事)

- ESP32 のビルド (S3・P4) が通るか (`fmrb_hal_file_esp32.c`・`fmrb_midi_serial.c`・`fmrb_app.c` の ESP32 の道)。
  `regress:size` で内蔵 RAM が増えていないか。
- Tab5 / P4-Nano のシェルの `ls` でフォルダに `/` が付く。ファイルマネージャー・`Dir` の一覧も変わっていないか。
- Tab5 の Grove: MIDI で serial を選んで鳴らす → アプリを閉じる → ターミナルで UART2 (53/54) が開ける。逆に UART を開いた
  まま MIDI で serial を選ぶと断られる。演奏中に閉じて、外の音源の音が鳴り続けない。
- Modern でリモートシェルのセッションを開くと「RS」が出る (Retro の sim では出ない作り)。
- `rake flash:app_sync` を PRUNE 無しで流して一覧を見る。像に `/etc/wifi.toml` が無いビルドでは端末の `/etc/wifi.toml` が
  一覧に出て、PRUNE=1 で消える (端末の WiFi が /home/wifi.toml に無いと戻れなくなる)。守る物に足すかは親の判断。
  `tools/fmrb_rd_fs.rb install` で入れた追加のアプリ (walk_scroller) も一覧に出る。
