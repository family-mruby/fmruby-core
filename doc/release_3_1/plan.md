# 3.1.0 のリリース

> 状態: 進行中 | 更新: 2026-11-27 | 3.0.0 (2026-11-07) の後の develop 全体を 3.1.0 として全機種に出す。きっかけは、Tab5 に入れた利用者が WiFi の設定とアプリからの UART を求めたこと。出す前に入れる直しの一覧と、確認の順。発火はユーザの指示を待つ。小さい直し 5 つ (UART の開き直しを含む) は report/r1.md

## 1. 目的

- 3.0.0 には WiFi の設定の画面が無く、アプリから UART も使えない。develop にはその後の変更 (WiFi の画面、640x360、
  AI ヘルパー、チャット、API の直し、リモートシェル) が入っているので、UART (doc/app_uart) と下の直しを足して出す。
- Web インストーラから入れられるようにする。手順の正は family-mruby/doc/release.md。

## 2. 方針 (ユーザ決定 2026-11-26)

- develop 全体を全機種に出す。出す前に、リリースのビルドを Tab5 と P4-Nano に焼いて、起動・WiFi の設定の画面・UART・
  主なアプリを確かめる。S3 の端末 (NARYA v3・StickS3・AtomS3R) は CI のビルドと sim の回帰までで、実機は未確認と
  リリースノートに書く。
- 発火 (タグ・リリースの公開) はユーザの指示を待つ。

## 4. 確認の順

1. 上の物を develop に入れる。直しのたびは `rake regress`。
2. 重い回帰を 1 回 (`regress:run`・`regress:size`・`regress:screens`)。
3. リリースのビルドを Tab5 と P4-Nano に焼いて確かめる (起動、WiFi の画面からつなぐ、シリアルターミナル、主なアプリ、
   リモートシェル)。
4. リリースノート (3.0.0 からの変更、S3 の実機は未確認)。
5. ユーザの指示で発火。

## 4b. 途中で分かったこと (2026-11-27)

- 開発の端末を app_sync で上げるとき、新しいヘルプ (まとめた 2 つ、約 0.8 MB) を送る前に古いページ (268 ファイル) が
  消えないと、storage が溢れて送れない (P4-Nano で起きた。古い /help のページだけを手で消して送り直した)。
  インストーラの全部の書き込みでは起きない。app_sync で上げる端末は、先に `PRUNE=1` (/help の古いページも消える)。
- ヘルプのまとめで見つかった、前からある不具合 2 つ (report/r2.md): `::` のクラスのメソッドで F1 を押すとページの先頭が
  出る、日本語の `String#index` などの要約に英語が残る。直すかはユーザに聞く。
