## 方式 (指示どおり、実装で決めた点だけ)

- マーカー `<<en>>` は **要約はインライン / 長文は行**。sig の doc コメント
  1 か所に両言語が入り、db にも `.md` にもただの文字列として流れる。
- 切り分けるのは **ti_ui.rb だけ**。`ti_pick_lang` (要約) と
  `help_filter_language` (F1 のページ) の 2 つ。
- マーカーが無い doc は素通し。既存の日本語のみの sig は無改修で従来どおり。

### T3 で指示書と変えた点 (ページの実際の形に合わせた)

指示書は .md を「シグネチャ行 → 空行 → 日本語長文 → `<<en>>` 行 →
英語長文」としていたが、gen_help が実際に書く形は

```
# クラス#メソッド        <- 0
                         <- 1
シグネチャ               <- 2
                         <- 3
要約 (マーカーがインラインで入る)  <- 4
                         <- 5
長文                     <- 6 以降
```

で、**要約の行が header の中に居る**。指示書の手順 (先頭からの最初の空行の
次から `<<en>>` 行までを消す) をそのまま実装するとシグネチャごと消える。
また、要約はインラインのマーカーなので**行の削除では処理できない**
(ja のとき `黒 (RGB332) <<en>> black (RGB332)` がそのまま見えてしまう)。

そこで実装は次の 2 段にした。

1. **header (長文より上) にインラインのマーカーがある行は、その行を
   書き換える** (`ti_pick_lang` を通した結果で置換)。実際に該当するのは
   要約の 1 行だけ。
2. **`<<en>>` だけの行 M を境に行を消す**。ja なら M から末尾まで、
   en なら長文の先頭行から M まで。

長文の先頭行は gen_help の並びから決めている (メソッド 6 行目 /
クラスコメント 2 行目)。`.md` を書いているのは自分たちの gen_help なので、
形を決め打ちにして注釈で紐付けた。

load_file が失敗したときは**フィルタを走らせない**。失敗時は前の文書
(利用者の編集中バッファ) がそのまま残るため、そこへ行削除をかけると
文書を壊す。

## T1: 規約と見本

`sig/README.md` に追記した内容:

- マーカーの規約 (要約はインライン `ja <<en>> en`、長文は `<<en>>` 行、
  マーカー無しは片言語フォールバック)。
- **トーン**: 大人が読んでも普通の説明にする。「〜してみよう」のような
  子供向けの言い回しは使わない。P4 の「子供が最初に読む説明文」という
  記述もこれに合わせて直した。
- 英語を足すと**要約の分だけ db が増える** (長文は flash のファイルなので
  増えない) ことと、上限 65,535 バイト。

見本は 15 件:

| 場所 | 件数 | 長文も二言語 |
| --- | --- | --- |
| FmrbGfx の色定数 (BLACK..GRAY) | 9 | — |
| FmrbGfx::BLEND_ADD / BLEND_XOR | 2 | — |
| FmrbGfx#draw_text | 1 | あり |
| FmrbGfx#present | 1 | — |
| FmrbApp#on_update / #on_event | 2 | あり |

`COLOR_*` (同じ色の別名) は**わざと日本語のままにした**。フォールバックが
実機で効いていることを、同じ画面で確かめられるようにするため。

`present` を足したのは検証のため: 引数が無いのでシグネチャが短く、
Ctrl+T の 1 行 (`present: () -> FmrbGfx -- 説明`) がステータス行に収まる。
`draw_text` は説明まで届く前に幅で切れる。

## T4: 検証 (sim, 426x240, HW target TAB5)

### 標準構成 (Spinel カーネル + Spinel エディタ)

| 内容 | ja | en |
| --- | --- | --- |
| `FmrbGfx::B` + Tab の doc 行 (BLACK) | `黒 (RGB332)` | `black (RGB332)` |
| 同 (BLEND_ADD) | `色を加算で混ぜる (blend_rect 用)` | `additive blend (for blend_rect)` |
| Ctrl+T (`gfx.present`) | `present: () -> FmrbGfx -- 描いたものを…` | `present: () -> FmrbGfx -- show wha…` |
| F1 (draw_text) | 要約 `文字列を描く` + 日本語長文のみ (末尾は日本語の例で終わる。`<<en>>` 行も英語も無い) | 要約 `draw a string` + 英語長文のみ |
| フォールバック: `FmrbGfx::CO` + Tab (COLOR_BLACK) | `黒 (RGB332)` | `黒 (RGB332)` (日本語のまま出る) |
| フォールバック: F1 (draw_rect、日本語のみのページ) | 従来どおり | 従来どおり (英語構成でも日本語が出る) |

画面: `comp_en2.png` / `comp_en3.png` / `hover_en2.png` / `help_en.png` /
`fallback_en.png` / `help_fallback_en.png` / `comp_ja.png` /
`comp_ja2_status.png` / `hover_ja.png` / `help_ja.png` / `help_ja_end.png`。

言語の切り替えは `flash/etc/system_conf.toml` の `language` を書き替えて
スタックを再起動 (config は起動時読み。ビルドは 1 回で両言語が db と .md に
入っているので、**再ビルドは要らない**)。

### 全 mruby 構成

`FMRB_KERNEL_ENGINE=mruby FMRB_APP_ENGINE_EDITOR=mruby rake build:linux` で
ビルドし、同じ操作で **doc 行 (`black (RGB332)`) と F1 (英語長文) が同一**
であることを確認した (`comp_mrb.png` / `help_mrb.png`)。

ビルド通過だけでなく画面まで見たのは、`String#index` と `str[a, b]` の
文字/バイトの扱いがエンジンごとに違うと日本語の切り出しが壊れるため。
両方とも**文字単位**で一致していた (mruby は MRB_UTF8_STRING 有効、
Spinel は `sp_str_index` が UTF-8 を数えて文字位置を返す)。

`rake ti:test` は green。

## サイズ

同じ tidbgen で、**同一ツリーの P4.6 前後の sig** から生成して比べた:

| | document pool | 文字列数 |
| --- | --- | --- |
| P4.6 前 (日本語のみ) | 13,271 | 437 |
| P4.6 後 (見本 15 件が二言語) | **13,851** | 437 |

**+580 バイト / 15 件 = 1 件あたり約 39 バイト**。プールの上限は 65,535
バイトで、今は 21%。

**全 API を二言語にした場合の見積り**: プールの文字列 437 件のうち
まだ 422 件が片言語なので、`13,851 + 422 x 39 = 約 30,300 バイト`
(上限の **46%**)。指示書の「~1.8 倍」とほぼ同じで、余裕はある。
name (3,838) と signature (17,109) は sig の doc を触っても変わらない。

長文はいくら二言語にしても db は太らない (flash のファイル)。
flash/help は 7 ファイル / 中身 5,576 バイト (`du -sb` で 21,960。P4.5 の
20,309 との差 **+1,651** が draw_text と on_update / on_event の英語長文)。
littlefs のパーティションは固定なので、イメージの大きさは変わらない。

## 引っかかった点

- **sig を変えたら `rake clean` が要る**。`rake build:linux` は db の .c を
  作り直すが、picoruby 側のビルドが**古い .o を使い続ける**ので、
  ビルドは通るのに古い doc が焼かれる。最初これで「en なのに日本語が出る」
  という誤った症状を見た (実際には切り分けは動いていて、db が古かった)。
  判定は `strings build/fmruby-core.elf | grep '<<en>>'` が速い。
  CLAUDE.md の「lib/ を編集したら rake clean」と同じ罠。

## 将来 (P4.6 の範囲外)

- 3 言語目はこの方式では扱えない (マーカーは ja/en の 2 分割前提)。

  入っているので、サーバ側で `ti_pick_lang` 相当を通すだけでよい。
