`@gfx` の両方を書いた。**`gfx.dr` と `@gfx.dr` のどちらでも draw_* が出る**。

## 書かなかったもの (意図的)

- **`_` で始まる内部メソッド全部** (FmrbGfx の `_draw_text` 系、FmrbApp の
  `_send_message` / `_spin` など)。子供が呼ぶものではない。
- **定数** (`FmrbGfx::BLACK`、`P5::ADD`、`FmrbMidi::CH_PULSE1` など)。
  エンジンが定数の補完を持たないため (指示書の範囲外)。**これは実用上
  いちばん惜しい欠落**で、色を選ぶ場面で必ず当たる。上流への機能追加の
  相談事項として残す。
- **キーワード引数の正確な形**。必須引数だけの形で書いてあるので、
  `create_canvas_gfx(width:, height:)` は `(Integer width, Integer height)`、
  `SpriteImage.new(gfx, width:, height:)` は `(FmrbGfx gfx)` になっている。
  引数の名前と数はシグネチャの見た目としては正しくない。
- **GfxBlock のブロックの中身** (Recorder の DSL)。ブロック引数の型を
  エンジンが持たないので、`rec.` は補完できない。GfxBlock 自身の
  new/draw/destroy だけ書いた。
- **MIDI の内部クラス**: ApuTransport / SerialTransport / Sched /
  MIDI::MML::Sequence / 各 transport の register 周り。アプリが直接
  触るのは `FmrbMidi.device` が返す MIDI::Device と 2 つの Player なので、
  そこに絞った。
- **FmrbI18n の内部** (`half_kana?`)、**NsfHeader の `extract_string`**
  (どちらも実装の助け)。
- **picoruby の標準 gem 全般** (JSON / Time / Machine / GPIO 以外の
  ペリフェラル)。File だけ最小限入れた。使用頻度を見て次段で判断。

## 見つけた実装側の問題 (P4 の副産物)

- **`FmrbApp#set_timer` が mruby 版の基底では動かない**。
  `lib/add/picoruby-fmrb-app/mrblib/fmrb-app.rb` の実装は
  `def set_timer(interval, &blk); return timer_id; end` で、`timer_id` は
  どこにも無い (呼べば NameError)。Spinel 版の基底
  (`fmrb_app_base_spinel.rb`) には実装がある。sig には宣言を書いた
  (両基底に存在はする) ので、**補完から選べるのに mruby アプリでは
  落ちる**状態。実装側の別件として直すべき。

## エンジンの限界に当たった点

**引数の検査が親子関係を見ない**。`class MyApp < FmrbApp` の中で
`FmrbAudio.new(self)` と書くと、`self` は MyApp なので
`expected FmrbApp, but got MyApp` と誤って怒られた (sim で実際に赤くなった)。
アプリがまず書く行なので、**その手の引数は `untyped` にして回避**した:

- `FmrbAudio.new(untyped app)`
- `FmrbMidi.device(untyped app)`
- `SpriteInstance.new(FmrbGfx gfx, untyped images)` (一枚でも配列でも渡せる)

本物の型ちがい (`gfx.draw_text(1, 2, 3, 4)`、`a.note_on(0, "high")`) は
今も検出する。継承を見た検査は上流への相談事項。

**候補は 1 要求 64 件で頭打ち**。`gfx.` / `self.` / `p5.` を素で叩くと
64 件で切れる (Object や Kernel から継承した分も混ざるため)。1 文字打てば
絞れるので v1 は許容 (指示書どおり)。

## サイズ

### 生成 db の内訳 (ドメインごとの増分)

| 追加したファイル | db.c (バイト) | 増分 |
| --- | --- | --- |
| 基本型 15 + enumerable + gpio | 111,877 | — |
| + fmrb_gfx | 149,638 | +37,761 |
| + fmrb_app | 187,266 | +37,628 |
| + fmrb_sprite | 198,403 | +11,137 |
| + fmrb_tile | 215,652 | +17,249 |
| + fmrb_audio | 226,066 | +10,414 |
| + fmrb_midi | 256,453 | +30,387 |
| + fmrb_misc | 263,465 | +7,012 |
| + fmrb_p5 | 286,642 | +23,177 |

P3 (基本型 + P1 の下書き fmrb.rbs) は 159,881 バイト / メソッド 729 個
だったので、**db.c は 1.8 倍、メソッドは 1,344 個**になった。

### 文字列プールの残り (上限 65,535 バイト)

| プール | 使用 | 残り | 使用率 |
| --- | --- | --- | --- |
| name | 3,677 | 61,858 | 5.6% |
| signature | 16,846 | 48,689 | 25.7% |
| document | 13,058 | 52,477 | 19.9% |

**いちばん詰まっているシグネチャでも 26%**。今の 4 倍近く書けるので、
当面プールは制約にならない (tidbgen の改造は不要だった。生成 C が
`ti_builtin_*_pool_size` として使用量をそのまま出している)。

### S3 (NARYAv3)

| | P3 | P4 | 差 |
| --- | --- | --- | --- |
| bin | 0x3737c0 (3,618,752) | 0x37af40 (3,649,344) | **+30,592** |
| パーティション空き | 14% | 13% | |
| .bss (内蔵 RAM) | 51,112 | 51,112 | **±0** |

**内蔵 RAM は 1 バイトも増えない** (db は flash の rodata)。増えた 30.6KB は
そのまま「補完で出る API の量」の値段。残 13% (0x850c0 = 545KB) なので、
まだ余裕はあるが、**sig を増やすと flash だけが減る**関係ははっきりした。
