## 書いた範囲

73 メソッド中 **15**。**引数のとおりに動くものには何も書いていない**
(`window_width`、`pos_x`、`theme_*` など)。書いたのは、実装を読まないと
分からない振る舞いを持つものだけ。

| メソッド | 何が分からないか |
|---|---|
| `on_create` | ファイルのアプリは**末尾の起動 4 行**が無いと何も起きない |
| `on_destroy` | **例外で落ちたら呼ばれない**。保存を終わりに任せない |
| `on_suspend` / `on_resume` | 動いたまま画面だけ消える / 戻ると**中身は残っていない** |
| `on_resize` | **FmrbUI の部品は作った場所に貼り付く**ので作り直しが要る |
| `start` | これを呼ぶまで動かない |
| `draw_window_frame` | **描き直すたびに呼ぶ**。フォントは保存・復元される |
| `clear_user_area` | わくを描き直し、部品に印を付ける。`gfx.clear` との違い |
| `set_timer` | **一度きり**。刻みはループ周期。Spinel は外側のローカルを掴めない |
| `publish` | **1 通 176 バイト**。大きいものは `/tmp` に置いて場所を配る |
| `create_canvas_gfx` | **キーワード引数**。全画面のアプリ向け |
| `ev_ctrl?` | **`ev[:scancode]` で見る**。`keycode` は環境で変わる |
| `request_fullscreen` | すぐには変わらない。答えは `on_resize` |

## 分かったこと

### ヘルプ画面は markdown を解釈しない

`open_help` は `.md` を**エディタのバッファに読み込んで表示する** (強調表示は
切る)。整形はしないので、**`**強調**` はアスタリスクごと画面に出る**。
` ``` ` のコードフェンスも `#` の見出しも同じ。

既存のページは `**` を控えめにしか使っておらず (FmrbUI 19 中 2、
FmrbGfx 32 中 2)、今回書いたぶんはそれより多い。**直すなら表示側**で、
読み込んだ直後に `**` を落とす数行で済む (`help_filter_language` の隣)。
**エディタを触る話なので、この報告に留めて実施していない。**

### 例のコードは 39 桁

前回の報告 (help_fmrb_gfx.md) の指摘どおり。今回**既存のページも含めて**
折り返した — `on_update` と `on_event` の例は 47 桁あり、画面で割れていた。
`sig/fmrb_app.rbs` の例は全部 39 桁以内に収めてある。

### つまずきは「実装のコメントが弁解しているところ」にある

前回の見つけ方がそのまま効いた。`clear_user_area` の
「both players did exactly that」、`draw_window_frame` の
「used to leave it with no title bar」、`create_canvas_gfx` の
「the window manager does not track extra canvases」— **踏んだ人がいるから
書かれた注意書き**が、そのまま書くべき項目になっている。

`set_timer` は実装を読まないと**一度きり**と分からない。名前も
`set_timer` / `clear_time` と揃っていない (前者は timer、後者は time)。
**これは直す価値があるかもしれないが、既存のアプリが壊れるので触っていない。**

## sig と実装の食い違い (直さず報告)

1. **`create_canvas_gfx` はキーワード引数** (`width:`, `height:`)。sig は
   位置引数で書いてあり、これは規約どおり (型推論エンジンにキーワードが
   無い) だが、**シグネチャのとおりに呼ぶと `ArgumentError` になる**。
   長文に実際の呼び方を書いた。前回の報告の 3 番と同じ問題で、こちらは
   **省略可能ではなく必須**なので実害が大きい。
2. `set_timer` の戻り値を `clear_time` に渡す、という対応が名前から
   読み取れない (上記)。
