## 実装したもの

### T1: PIN 更新

`d40a9e6` (fork の hover 対応入り)。sig の変更なし、`rake ti:test` green。

### T4: ステータス行の整理 (先にやった)

**2 つの帯と、入口 1 つ**にした。

- **右端は常設バッジ専用**。かなモード `[A]/[あ]/[ア]` と、診断後の問題件数
  `[!N]`。**幅を先に測って最後に描く**ので、何があっても隠れない
  (P2 で候補の doc がかなバッジを塗り潰したのが直接の動機)。
- **左〜中央は一時メッセージ**。ホバー結果・診断サマリ・候補の doc・
  「大きすぎる」・「保存しました」まで全部ここ。`flash_status` が唯一の
  書き込み口で、バッジに届く長さは 1 文字ずつ切り詰める。消えるのは
  **次のキー** (それを出したキーの次) か **5 秒**のどちらか早いほう。
- 保存の緑フラッシュは右端バッジをやめ、このメッセージの「成功」表情に
  なった (色はそのまま)。

### T2/T3: ブリッジとバインディング

`et_hover` / `et_diagnose` を追加。P2 の足場 (ロック → 直列化 →
使い捨てヒープを借りて prism を向ける → 後片付け) を `et_begin` /
`et_end` に括り出し、3 つの入口で共有した。**setjmp は各入口に残す**
(アロケータが longjmp で戻る先のフレームに無ければならないため)。

診断のバイト位置は、**直列化バッファが生きているうちに** (行, 桁) へ
逆変換してからコピーする。桁は文字数 (エディタの座標系) に合わせてある。
message も次の ti 呼び出しで無効になるのでコピーする。

バインディングは P2 と同じ 3 点セット (mruby / Spinel FFI / EditorCore シム)。

### T5: ホバー (Ctrl+T)

- 変数: `@gfx : FmrbGfx` の形。
- メソッド: シグネチャそのまま。doc があり幅が許せば ` -- <doc>` を続ける。
- 見つからなければ「ここには型がありません」。モーダルにはしていない。

### T6: 診断 (Ctrl+E、保存時は自動)

- 実行は **Ctrl+E** と **保存成功直後** (Ruby ファイルのみ。判定は
  ハイライトと同じ `hl_default_for`)。
- 問題行は**行の背景を赤く**する。デバッガの停止行と同じ描画部品
  (`line_bg`) を使い、色で区別する。停止行が同じ行なら停止行が勝つ。
- ステータス行に `1 problem: <最初の message>` / `no problems`。
- **Ctrl+E 連打で次の問題行へジャンプ**し、その行の message を出す
  (末尾で先頭へ戻る)。
- **最初の編集でマーカーを全部消す** (`mark_edited` から)。位置が古くなる
  ため。次の保存か Ctrl+E で戻る。
- 32KB 超は「調べられませんでした」で、**0 件とは区別する**。

キーの衝突確認: Ctrl+T (0x17) / Ctrl+E (0x08) はどちらも未使用だった
(エディタは Ctrl+S/X/C/V/A/D、システムが Ctrl+Q / Ctrl+Tab / Ctrl+Space)。
代替を選ぶ必要はなかった。

ホバーと診断の所要時間は、この規模 (67-78 バイト) では `ti_lat` と同様に
0ms。**大きい文書での実測は P5 の実機測定とセットで取り直す** (ホストの
数字は P2 の report にある: 20.5KB で 34ms)。

### S3 (NARYAv3) のサイズ

| | P2 | P3 | 差 |
| --- | --- | --- | --- |
| bin | 0x370d70 (3,608,432) | 0x3737c0 (3,618,752) | **+10,320** |
| パーティション空き | 14% | 14% | |
| .bss (内蔵 RAM) | 50,680 | 51,112 | **+432** |
| DIRAM 空き | 174,921 | 174,489 | -432 |

ホバーと診断で増えたのは flash 10KB (エンジンの hover/diagnostic と
ブリッジ・UI) と内蔵 RAM 432B だけ。**診断の結果はエディタの文書プール
(PSRAM) に置く**ので、件数を増やしても内蔵 RAM は動かない。

## 途中で直したこと

- **「1 problems」**と出ていた。単数形を i18n に足して数で選ぶようにした
  (日本語は「件の問題」で共通)。
- 保存時の自動診断を最初は「問題なしのときは黙る」設計にしたが、指示書の
  受け入れ (`no problems` が出ること) と合わなかったので**常に答える**形に
  変えた。保存できたことは、ファイル名から `*` が消えることで分かる。

## 残した制限と申し送り

- **ブリッジが使い捨てヒープを作るたびに fmrb_alloc が info ログを 3 行出す**
  (`create_handle` / `Created pool` / `Destroyed pool`)。ホバーや補完のたびに
  出るので、実機のログが読みにくくなる。fmrb_alloc 側のログ水準の話なので
  P3 では触らず、記録だけ残す。
- 診断の範囲 (start_x..end_x) はブリッジまで来ているが、UI は行単位までしか
  使っていない (指示書どおり)。下線や波線は P4 以降の判断。
- ホバーは表示のみでモーダルではない。長いシグネチャはバッジ手前で切れる
  ので、全文を見せる手段は今のところ無い。
- 打鍵ごとの自動診断は入れていない (指示書の範囲外)。
