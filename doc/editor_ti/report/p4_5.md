## T1: fork 改修

### T1-0 (前段の 2 件を core 側に反映)

- **引数検査が継承をたどる**ようになったので、P4 で `untyped` に逃がした
  引数を本来の型に戻した (`FmrbAudio.new` / `FmrbMidi.device`)。
  `FmrbAudio.new(self)` は誤検知しなくなり、本物の型ちがいは今も出る。
  `SpriteInstance.new` の images だけは untyped のまま — こちらは
  「一枚でも配列でも渡せる」という実装どおりの意味で、回避ではない。
- **定数が db に入る**ようになったので、FmrbGfx の色を sig に書いた。
  C が定義する短い名前 (`BLACK`..`GRAY`) と mrblib の `COLOR_*`、
  それに `BLEND_ADD` / `BLEND_XOR`。`FmrbGfx::B` + Tab で
  BLACK / BLUE / BLEND_* が説明つきで出る。
- **エディタの Tab 文脈判定に `:` を足した**。これが無いと `FmrbGfx::` の
  直後で Tab がインデントになる。
- `sig/gpio.rbs` にエンジンのテストが前提にする宣言 (`attach`、定数) を
  足した。**これが無いと ti:test が落ちる** (fork のテストは fmruby-core の
  sig で走るため)。

### T1-1: db の document は先頭行だけ

`database_builder` が document pool に入れる文字列を最初の改行までに切った。
メソッドと定数の両方。上流にそのまま出せる説明にしてある
(「一覧に出せるのは 1 行、長文はプールを食う」)。

### T1-2: 呼び出し文脈 API

`ti_find_call_context(sources, cursor, out)` を新設 (`src/hover/`)。
返すのは、カーソルを含む**最内の呼び出し**のシグネチャ、カーソルが
**何番目の引数**か、その引数の名前と型。

実装で判断したこと 2 つ:

- **引数の位置はソースの文字を数えて決める**。書きかけの引数リストは
  構文木がまともに組み上がらないので、`(` からカーソルまでのカンマを、
  入れ子の括弧と引用符を飛ばしながら数える。
- **書きかけの呼び出しにも prism は閉じ括弧の位置を付ける**。それは
  「最後に見たもの」の位置なので、カンマの後に空白が 1 つあるだけで
  カーソルより前に来る。**本当に `)` がある場合だけ**引数リストの終わりと
  みなすようにした (これが無いと `draw_text(10, ` で何も出ない)。

引数の名前と型は**シグネチャ文字列から取り出す**。db の引数表を引き直す
必要がなく、ユーザ定義メソッド (名前だけ、型は無し) も同じ経路で扱える。

host_test に 5 本追加 (第 1 引数 / カンマ直後 / 入れ子の内側 /
ユーザ定義は名前だけ / 呼び出しの外では見つからない)。

## T2: ヘルプ生成

`tool/ti/gen_help.rb` (Ruby、rbs gem)。sig の doc コメントが 2 行以上の
メソッドについて `flash/help/<クラス>/<メソッド>.md` を書き出し、
`flash/help/index.txt` に「名前 → パス」を 1 行 1 件で並べる。
`rake ti:help` 単体でも走るが、**`rake setup` が毎回呼ぶ**ので、
ビルドすれば必ず最新になる (storage イメージは docker の中で flash/ を
写すので、その前に生成する必要がある)。生成物は gitignore。

見本の長文は 6 件: `FmrbGfx#draw_text` / `#draw_rect` / `#fill_rect`、
`FmrbApp#on_update` / `#on_event`、`SpriteInstance.new`。
「(x, y) は左上」「present を呼ぶまで画面に出ない」「動かすときは前の
場所を消す」など、**子供がつまずくところ**から書いた。

## T3: F1 ヘルプ

- **F1 (0x3A)** で、補完リストが開いていれば選択中の候補、開いていなければ
  カーソル下の語を index.txt から引いて開く。無ければ「まだ説明がありません」。
- ヘルプは**同じバッファに読み取り専用で開く**。編集キー (文字 / Enter /
  Backspace / Delete / Tab / Ctrl-S / Ctrl-V / Ctrl-X) は弾いて一言出し、
  移動キーは効く。ステータス行のファイル名に `[Help]` が付く。
- **編集中のバッファは /tmp に退避**してから開き、Esc か F1 で戻る。
  名前付きで未保存でも失われない (退避があるときは退避のほうを信じて戻す)。
  色分けの設定も退避して戻す (.md を開くと色分けが切れるため)。

## T4: signature help

- `(` と `,` を打った直後にだけ走る (打鍵ごとには走らない)。
- 表示は `draw_text(x, >>y: Integer<<, str, color)`。**印を付けた引数を
  前のほうに置く**ので、幅が足りずに末尾が切れても肝心の部分は残る。
- 所要時間は `sig_lat: N ms (arg K of <signature>)` として info で出す
  (ti_lat と同じ理由: debug はビルドから落ちている)。

## サイズ

### document pool: 先頭行だけにした効果

同じ sig (長文 6 件入り) で、db に入れる文字列を変えて比べた:

| | document pool | db.c |
| --- | --- | --- |
| コメント全文 (元の挙動) | 16,439 | 312,355 |
| 先頭行だけ (今) | **13,304** | 293,068 |

**長文 6 件で 3.1KB の差**。見本 6 件でこれなので、主要 API に書き足して
いけば全文方式は 65,535 バイトの上限にすぐ届く。先頭行だけにしたことで、
**長文をいくら書いてもファームウェアは太らない** (ヘルプは flash の
ファイルとして別に載る)。

参考: name 3,879 / signature 17,272 は P4 から定数の分だけ増えた。
一番詰まっている signature でも **26%**。

### flash/help と S3

| | P4 | P4.5 | 差 |
| --- | --- | --- | --- |
| bin | 0x37af40 (3,649,344) | 0x37f520 (3,668,768) | **+19,424** |
| パーティション空き | 13% | 13% | |
| flash/help | — | 7 ファイル / 20,309 バイト | |

storage.bin は littlefs のパーティションサイズ固定 (5MB) なので、
ヘルプが増えてもイメージのファイルサイズは変わらない。**中の空きが
20KB 減るだけ**で、当面は問題にならない。

bin の +19.4KB は定数の db と呼び出し文脈 API とエディタの追加分。

## 判断したこと・残したこと

- **ホバー (Ctrl+T) と signature help は分けたまま**にした。指示書では
  「呼び出し引数内なら Ctrl+T を signature help に回してもよい」とあったが、
  `(` と `,` で自動的に出るので、Ctrl+T は「今カーソルが乗っている物の型」
  という一貫した意味のままのほうが分かりやすい。
- 同名メソッドが複数クラスにある場合、index.txt には全部載るが**開くのは
  先頭**。今の見本 6 件では重複なし (`new` は SpriteInstance のみ)。
  重複が出たら「どのクラスか選ばせる」必要が出る。
- ヘルプからヘルプへは飛べない (v1)。退避が 1 枚だけなので、開いている
  最中の F1 は閉じる動作にした。
- **`/tmp` に退避する方式の限界**: 文書が /tmp の容量 (448KB) を超えると
  退避に失敗し、ヘルプを開かずに「保存できません」と出る。32KB を超える
  文書では補完も診断も動かないので、実用上は同じ範囲。
