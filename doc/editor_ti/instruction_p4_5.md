# 実装指示書 P4.5: ヘルプ段 (signature help / F1 ヘルプ)

対象: 実装担当セッション。**前提: P4 完了後** (sig/ に主要 API が
揃っていること。P4 未了ならこの指示書は保留)。plan.md と report/p4.md を
先に読むこと。

report は doc/editor_ti/report/p4_5.md へ。タスクごとにコミット。

## P4.5 のゴール

初心者 (子供) が関数名を選んだ後で迷わないための 2 機能:

1. **signature help**: 引数を打っている最中に「いま何番目の引数で、
   名前と型は何か」がステータス行に出る
2. **F1 ヘルプ**: 補完候補やカーソル下のメソッドから、長文の説明 +
   使用例をエディタ内で開ける

## 方針 (決定済み)

- **書く場所は sig/ の 1 箇所**。RBS の doc コメントを
  「**1 行目 = 一文** (db に入り、補完/ホバーの即時表示)、
  **2 行目以降 = 長文ヘルプ** (使用例の ```ruby コードブロック可。
  flash のヘルプファイルに生成)」という規約にする。
- db (tidbgen) には**先頭行しか入れない** (fork 改修 T1)。長文を db に
  入れると文字列プール 65535B 上限をすぐ食い潰すため。
- 長文ヘルプは**ビルド時に flash/help/ へ生成**するファイル。生成物は
  コミットしない (flash/etc/system_conf.toml と同じ扱い)。
- ヘルプの表示は**エディタの読み取り専用バッファ**で開く (新しい UI 部品を
  作らず、既存のファイル表示に乗る)。

## T1: fork 改修 (tmp/picoruby-ti、fmrb-dev へ)

1. **db の document は先頭行のみ**: database_builder が
   `collected_method.comment` を document pool に入れる箇所で、最初の
   改行までに切る (ivar には doc が無いので対象はメソッドのみ)。
   上流にもそのまま出せる説明 (「一覧表示用の要約は 1 行で足り、
   長文はプール上限を圧迫する」) をコミットメッセージに書く。
2. **呼び出し文脈 API**: `ti_find_call_context(sources, cursor_byte_offset,
   out)` を新設。カーソルを含む**最内の呼び出しノード**を見つけ、
   - メソッドのシグネチャ文字列 (既存の解決経路を流用。レシーバの型は
     eval で決める。suggest/hover と同じく外側クラスを context に設定)
   - **カーソルが何番目の引数位置にあるか** (0 始まり。引数リスト外なら -1)
   - その引数の名前と型 (TiBuiltinArgument から。ユーザ定義メソッドは
     define_arg_name_ids から名前のみ)
   を返す。host_test に最低 3 ケース (第 1 引数 / カンマ直後の第 2 引数 /
   入れ子呼び出しの内側) を追加。
3. push して lib/add/PICORUBY_TI_PIN を更新。rake ti:test green。

## T2: ヘルプ生成 (fmruby-core、fork 非依存)

- tool/ti/ に Ruby スクリプトを新設: sig/*.rbs を rbs gem でパースし、
  doc コメントが 2 行以上あるメソッドについて
  `flash/help/<クラス名>/<メソッド名>.md` を生成する。
  - 1 行目: シグネチャ (RBS から整形)、以降: コメントの 2 行目以降。
  - クラスコメント (class 直前) があれば `<クラス名>/index.md` に。
  - あわせて `flash/help/index.txt` (メソッド名 -> パスの一覧、1 行 1 件)
    を生成する。エディタの名前引きに使う。同名メソッドが複数クラスに
    あるときは全部載せる。
- rake に配線 (storage イメージを作る前に走ること)。生成先は
  gitignore に追加。
- sig/README.md に doc コメント規約 (1 行目 = 一文 / 2 行目以降 = 長文 +
  使用例) を追記する。P4 で書いた一文はそのまま 1 行目として有効。
- 題材として、まず **FmrbGfx の draw_text / draw_rect / fill_rect と
  FmrbApp のフック 2 つ**くらいに長文 + 使用例を書いて通す (全 API の
  長文化は P4.5 の範囲外。書き方の見本を作るのが目的)。

## T3: エディタ F1 ヘルプ

- **F1 (scancode 0x3A)** で発火 (未使用のはず。衝突したら代替を選んで
  report へ):
  - 補完リストが開いていれば選択中の候補名で
  - 開いていなければカーソル下の語 (ホバーと同じ対象の取り方) で
  - flash/help/index.txt から引いてヒットしたらそのファイルを開く。
    同名複数は先頭を採用 (v1。件数を report に記録)。ヒットしなければ
    一時メッセージ「ヘルプはまだ無い」。
- **読み取り専用バッファ**をエディタに新設: 編集キーを弾いて一時
  メッセージを出す。ステータス行のファイル名部に [Help] を付ける。
  閉じる (Ctrl+W 相当 or Esc) と元のバッファへ戻る。バッファ切替の
  既存機構があればそれに乗り、無ければ「1 枚だけ退避して戻れる」
  最小実装で良い (ヘルプからヘルプへは飛ばない)。

## T4: signature help

- 発火: 編集中に **`(` または `,` を打った直後** + 手動 (Ctrl+T の
  ホバーが呼び出し引数内なら signature help を優先、でも良い。判断して
  report へ)。et_* に T1-2 の呼び出し文脈 API を通すブリッジを足す
  (P2/P3 と同じ流儀: ロック + コピー + 両バインディング)。
- 表示: 一時メッセージ領域に
  `draw_text(x, >>y<<, text, color)` の形で現在引数を挟み込み表示 +
  可能なら「y: Integer」を続ける。幅が足りなければ現在引数の
  `>>y: Integer<<` だけでも良い。
- 打鍵のたびに走るものではない (`(` と `,` のときだけ)。ti_lat と同様に
  所要時間を DEBUG 相当のログで出す。

## T5: 検証とサイズ

1. sim (標準構成) 一巡、スクリーンショット付き:
   - `gfx.draw_text(10,` と打つ -> `>>y: Integer<<` が出る
   - 入れ子 `draw_text(1, rand(3` の内側で rand 側の表示になる
   - 補完リストから draw_text 選択中に F1 -> ヘルプが開く。編集キーが
     弾かれる。閉じると元のバッファ + カーソル位置に戻る
   - ヘルプの無いメソッドで F1 -> 「まだ無い」メッセージ
   - Tab 補完 / Ctrl+T / Ctrl+E / かなバッジの回帰
2. 全 mruby 構成で signature help と F1 の各 1 ケース。
3. rake ti:test green (T1 の新テスト込み)。
4. サイズ: document pool の使用量が**先頭行化でどれだけ減ったか**、
   storage.bin のヘルプ分の増分、S3 ビルド通過。

## 受け入れ条件

1. T5-1 が全て通る (スクリーンショット付き)。
2. rake ti:test green、S3 ビルド通過 + サイズ記録。
3. sig/README.md に規約が書かれ、見本の長文ヘルプが 5 件ある。
4. ヘルプ生成がビルドに配線され、素の clone + rake setup 系の手順だけで
   flash/help が埋まる。

## やらないこと (P4.5 の範囲外)

- 全 API の長文ヘルプ執筆 (見本 5 件まで。続きは P4 と同じ「書いた分だけ
  効く」性質なので、以後は API を触るときに書き足す運用)。
- 使用例をバッファに貼り込むボタン (次段候補。ヘルプが読めれば
  手で写せる)。
- 引数単位の説明フィールド (上流 db 拡張が要る。引数名を説明的に
  書くことで v1 は補う)。
- ヘルプの英語版。PC 側 LSP への長文ヘルプ接続 (P6)。
