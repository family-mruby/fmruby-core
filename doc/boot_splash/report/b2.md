# B2 報告: 起動の和音を FMSQ で作り直す (エンベロープと低音)

> 状態: 完了 | 更新: 2026-11-15 | 起動の和音を MAIN と SUB の 2 本の FMSQ (矩形波 4・三角波 2・ノイズ 2) にした。低音は 2 つの三角波を G2 で重ね (同じ位相で振れ幅 2 倍)、矩形波の音量は帯ごとの RMS を等ラウドネスで重み付けして決めた。デスクトップが送るメッセージは 27 通から 5 通。インラインの load_fmsq が mruby のカーネルで大きさを文字数で書く不具合も直した

開始 2026-11-15 12:31 (JST)、終了 2026-11-15 13:10 (JST)。

## 1. 作ったもの

- `tools/boot_chime.rb`: MAIN 用と SUB 用の FMSQ を作る (レジスタの直書きだけ。同じ値の書き込みは省く)。
  出力は `flash/boot/boot_chime_main.fmsq` (106 B) と `flash/boot/boot_chime_sub.fmsq` (133 B)。
  インラインで送れる上限 148 B (アプリのメッセージ 176 B から Hash の分 28 B を引いた数) を超えると書かずに止まる。
- `main/ruby/kernel/system_desktop.app.rb`: `BOOT_EVENTS` と `tick_boot_jingle` を消した。演出の始まり
  (`start_boot_animation`) で 2 本を読んで `load_fmsq`、線が出るコマ (最初の tick) で MAIN → SUB の順に
  `play_slot`、`finish_boot_animation` で `stop`。スロットは 200 と 201 (アプリは 0・4・12〜14 を使う)。
- 絵の段と時間は変えていない。graphics-audio と APU も変えていない。

### 1.1 声の割り振り

時刻は 60 Hz のコマ (FMSQ のコマ)。音量は 0〜15、デューティ比は 12.5 / 25 / 50%。

| 声 | 0 ms (コマ 0) | 267 ms (16) | 500 ms (30) 〜 | 止まる |
|---|---|---|---|---|
| MAIN 矩形 1 | G3 50% 音量 3→4、133 ms で 25% に (明るく) | D4 25% 4→5 | A4 50% 4→5→…→1 | 1183 ms |
| MAIN 矩形 2 | - | - | G4 50% 5→7→…→1 | 1183 ms |
| MAIN 三角 | G2 | (G2) | (G2) | 1100 ms |
| MAIN ノイズ | 長い周期 3、音量 3→2→1→0 (150 ms で消える。「すっ」) | - | - | |
| SUB 矩形 1 | G3 をタイマー 1 段ずらす (-3 cent)、50% 2、133 ms で 25% 3 | D4 (-5 cent) 25% 2→3 | D5 25% 5→7→…→1、浅いビブラート | 1183 ms |
| SUB 矩形 2 | - | - | G4 をタイマー 1 段ずらす (+6 cent)、12.5% 4→5→…→1 | 1183 ms |
| SUB 三角 | - | - | G2 (MAIN の G2 に重ねる) | 900 ms |
| SUB ノイズ | - | - | 短周期モード 周期 1、音量 4→2→1→0 (233 ms で消える。きらめき) | |

- **エンベロープ**: 和音は全部の矩形波が同じ形 (`CHORD_ENV`、満量で 10 → 14 → 13 → 11 → 9 → 8 → 7 → 6 → 5 → 4 →
  3 → 2、コマ 0・1・3・6・10・15・20・25・30・34・37・39) に声ごとの倍率 (`LEVEL`、16 分の n) を掛けた値。
  1 コマで立ち上がり、100 ms ほどで鳴りの高さに落ち、そのあと長く減衰して 1150 ms ごろに音量 1。
  前段の G3・D4 も 1 コマの立ち上がり (`LEAD_ENV`)。音量が整数なので、倍率の小さい声は 2→3 のように段が粗い。
- **デューティ比**: 前段の G3 は 50% で始めて、線が伸びる間 (133 ms) に 25% に変えて明るくする。和音は
  根音の G4 を 50% (丸い)、上の D5 を 25%、SUB の 2 つ目の G4 を 12.5% (細い) にして、同じ音でも色を変えた。
- **厚み**: MAIN と SUB の G3・D4・G4 は、タイマーを 1 段ずらしてわずかに違う高さにした (3〜6 cent。ゆっくり
  うなって 1 本より太く聞こえる)。
- **ビブラート**: SUB の D5 に、和音から 200 ms 後 (コマ 42) からタイマーを ±1 段 (±9 cent) 2〜3 コマごとに
  揺らす (約 6.5 Hz)。下位のタイマーだけを書くので波形はリセットされない。
- **三角波の止め方**: 三角波は音量で消せないので、SUB の G2 を 900 ms で止めて低音を半分にし、MAIN の G2 を
  1100 ms で止める。そのあと 83 ms は矩形波の余韻 (音量 1〜2) だけが鳴り、1183 ms でチャンネルを全部切る。
  WAV の 25 ms ごとの RMS (sim の Retro): 875 ms 1116 → 950 ms 567 (2 本 → 1 本)、1125 ms 541 → 1150 ms 262
  → 1175 ms 160 → 1200 ms 103 → 1225 ms 58 (ここから無音)。低音が 2 段で下がり、最後は矩形波が消えていく形で、
  ぶつ切りの段は 2 つとも矩形波の下にある。止める所は `FRAME_TRI_SUB_OFF`・`FRAME_TRI_MAIN_OFF` で変えられる。

### 1.2 2 つの三角波の位相

2 つの三角波は位相がそろったときだけ振れ幅が 2 倍になる。三角波は書き込みで位相が戻らないので、SUB の G2 は
MAIN の G2 の位相が一回りした所 (30 コマ = G2 の 48.97 周期) で始める。これは 2 本の再生がオーディオ側の
同じコマから始まるときに成り立つ。play_slot を続けて 2 通送るのはそのため。

ずれたときの低音 (音を出す側でずれを入れて描いた WAV、和音の 600〜880 ms の 200 Hz 未満の RMS。三角波 1 本は 2893):

| SUB の始まりの遅れ | 0 コマ | 1 コマ | 2 コマ | 3 コマ |
|---|---|---|---|---|
| 低音の RMS | 5778 (1 本の 2.00 倍) | 1947 (0.67 倍) | 4212 (1.46 倍) | 5342 (1.85 倍) |

**1 コマずれると 1 本より小さくなる**。sim では 2 通が同じミリ秒に届き、Retro・Modern・途中止めの 3 回とも
ずれなし (和音の低音が前段の 2.0 倍) だった。オーディオ側の 1 コマ (16.7 ms) の境目が 2 通の間 (1 ms 未満) に
入ったときだけずれるので、起こる率は数 % と見ている。実機 (S3 はリンク越し、P4 は同じチップの中) では測って
いない。気になるなら SUB の三角波を G2 以外にする (位相に関係なく足し算になる) 手があるが、決めた形
(両方 G2) を変えることになるので入れていない。

## 2. 釣り合い (帯ごとの RMS)

### 2.1 決め方

三角波の大きさは固定なので、釣り合いは矩形波の倍率 (`LEVEL`) で取る。数字は次の測り方で決めた。

- 道具: WAV を段ごとに切って FFT し、200 Hz 未満 (直流は除く) と以上に分けた RMS。生の値と、60 phon の
  等ラウドネス曲線 (ISO 226:2003 の近似。1 kHz を 0 dB とし、100 Hz は約 -19 dB、400 Hz は約 -3 dB、
  2〜4 kHz は +2〜4 dB) で重み付けした値の 2 つを出す。重み付けは「低い音は耳に小さく聞こえる」(指示書の
  理由の 3 つ目) を数にしたもの。三角波の固定の大きさと直流を除く処理 (理由の 1・2 つ目) は WAV にもう入っている。
  小さいスピーカーの低域の落ち方は機種で違うので入れていない (入れれば低音はさらに小さく聞こえる)。
- 段: 前段 G3 (0〜267 ms)、D4 (267〜500)、和音の頭 (500〜600)、鳴り (600〜900)、三角 1 本の尾 (900〜1100)、
  終わり (1100〜1190)。時間は音の出始めから。G3 (196 Hz) は 200 Hz 未満に入るので、G3 の段の「未満」は低音だけではない。
- 目安 (重み付けの 未満/以上): 鳴りで -6〜-8 dB (4 つの和音の声を足すと 1 声より 6 dB 大きいので、-6 dB で
  低音が和音の 1 声と同じ大きさ)。前段の D4 は旋律が前に出るよう -10 dB、和音の頭は明るい山なので -11 dB ほど。
- 1 回目 (倍率: 前段 16・10、和音 D5 12・G4 13・A4 10・G4' 9) は D4 -16.8、頭 -14.5、鳴り -11.2 dB で
  低音が足りなかった。矩形波を 4〜9 dB 下げた 2 回目 (前段 7・4、和音 8・8・6・6) が下の表で、目安に入った。

## 3. 音高 (sim の Retro の WAV。Modern も同じ値)

窓ごとの Goertzel で ±60 cent を 1 cent 刻みで探して一番強い周波数を取った (時間は音の出始めから)。

| 声 | 予定 | 予定 Hz | 測った Hz | ずれ | 測った区間 (ms) |
|---|---|---|---|---|---|
| 三角 (低音) | G2 | 98.00 | 97.83 | -3 cent | 30〜250 |
| 矩形 | G3 | 196.00 | 196.68 | +6 cent | 30〜250 |
| 矩形 | D4 | 293.66 | 293.33 | -2 cent | 300〜480 |
| 三角 2 本 | G2 | 98.00 | 97.94 | -1 cent | 560〜880 |
| 矩形 2 本 | G4 | 392.00 | 392.22 | +1 cent | 560〜880 |
| 矩形 | A4 | 440.00 | 440.51 | +2 cent | 560〜880 |
| 矩形 | D5 | 587.33 | 588.35 | +3 cent | 560〜880 |

G3・D4・G4 は MAIN と SUB を 1 段ずらしているので、測った値はその 2 本の強い方に寄る (分周の丸めと合わせて数 cent)。

### 3.1 絵との合わせ目

- 音の出始めは線の画面から -5 ms (Retro)・-12 ms (Modern) (サンプルを読んだ時刻で照らす。±1 コマの読み取りの粗さがある)。
- 和音の始まりはサンプルの数で音の出始めから 505 ms (30 コマ、予定 500)。
- 実時間では線の画面から +467 ms (Retro)・+468 ms (Modern) で、開ききる画面 (+497 ms、B1) より 30 ms 早い。
  **sim のオーディオの 1 コマが 16.04 ms (実時間で 16333 サンプル/秒、予定の 15720 より 3.9% 速い)** ためで、
  FMSQ はオーディオ側のコマで進むので sim では全体が 4% 縮む。実機のオーディオは 16667 us ごとのタイマーで
  回る (graphics-audio の ESP32 側・P4 の audio_p4_task) ので 500 ms に当たるはず (実機では測っていない)。
  B1 は音を実時間で送っていたので sim でも絵と合っていた。

## 4. 鳴らし方の確認

| 項目 | 結果 |
|---|---|
| インラインで足りるか | MAIN 106 B・SUB 133 B (上限 148 B)。カーネルが送るのは 115 B・142 B (上限 176 B) |
| 読み込みと再生 (sim のログ) | `Loaded music track 200 (106 bytes)`・`201 (133 bytes)`、`FMSQ play_slot: track 200 on MAIN`・`201 on SUB`。4 通が同じミリ秒 |
| 演出の終わり | 1.22 秒で `stop` (ログ `audio stop`) |
| 途中で止めたとき | `BOOT_END_MS` を一時的に 700 にした Modern の sim で、和音の途中の +715 ms (実時間) で `stop` が出て、次の 50 ms の窓から無音 (ビルドは戻した)。止めた所で三角波が切れるので 1 窓だけ広い帯のノイズが出る |
| `boot_splash = false` | sim (Modern、生成された flash/etc/system_conf.toml を一時的に書き換え) で、音のメッセージが 1 通も出ず、デスクトップが出て Boot complete (書き換えは戻した) |
| スロットの衝突 | アプリが使うのは 0 (blockgame・rpg_demo・midi_apu)・4 (picoruby)・12〜14 (mahjong)。BASIC の PLAY は C の側で送るのでスロットを持たない。200・201 は重ならない |

- オーディオ側の表は端末全体で 16 件 (`FMRB_MAX_MUSIC_TRACKS`) で、起動のたびに 2 件 (200・201) を使う (同じ番号を
  読み直すと上書き)。アプリの 5 件と合わせて 7 件。WROVER の graphics-audio は、表が 16 件埋まると既にある番号の
  読み直しも断る作りになっている (`process_load_command` が数の検査を先にする。直すのは graphics-audio)。
- `stop` は機械全体の止め (NSF と両方の FMSQ) だが、演出の終わりの時点では他に鳴っているものは無い。`stop` を
  送るのは、`play_slot` がデスクトップをカーネルの「音楽を鳴らしているアプリ」に入れるため: 残すと、終わらない
  デスクトップがいつまでも鳴らしていることになり、落ちたアプリの曲をカーネルが止めなくなる。

### 4.1 カーネルの直し (触ってよい範囲の外。別のコミット)

カーネルの load_fmsq (`main/ruby/kernel/fmrb_kernel/audio_handler.rb`) は LOAD_BINARY の大きさを
`String#length` で書いていた。FMSQ はバイナリで、mruby のカーネル (MRB_UTF8_STRING) は `C0 B5` のような
レジスタの書き込みを 1 文字と数えるので、大きさを実際より小さく書き、オーディオ側が「切れている」と断る。
Spinel のカーネル (標準) は不正な UTF-8 があるとバイト数を答えるので症状が出ない。インラインで FMSQ を送る
アプリがこれまで無かったので見つかっていなかった。`bytesize` にした。

- 確かめたのは標準 (Spinel のカーネル) の sim で動くことと、`rake regress`・`rake regress:spinel` が通ること。
  **mruby のカーネルで実際に断られることと、直して通ることは動かして確かめていない** (mruby の
  `mrb_utf8len` を読んだ判断)。全部 mruby の構成で確かめるならネイティブ版 (`rake native:mruby native:core`)
  だが、音が出るので流していない。

nes_apu.c・fmsq_player.c) で 2 つの instance に流して WAV にする小さな C、WAV を段と帯に分ける Ruby。sim の起動の
音と画面は B1 の取り方 (`--ipc host` の小さなコンテナで共有メモリを 3 ms ごとに読む) を写して使った。sim は
headless (SDL の dummy) で上げたので音は外に出ていない。`sim_audio` の mute は使っていない: mute は graphics-audio が
共有メモリのリングに書く前に 0 にするので、探りの WAV も無音になる。
