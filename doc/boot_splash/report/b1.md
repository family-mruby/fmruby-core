# B1 報告: 起動の演出の試作 (と、差し込みの直し 2 つ)

> 状態: 完了 | 更新: 2026-11-15 | ブラウン管の電源 ON (線 → 横に伸びる → 上下に開く → 白の山) と、G3→D4 の 5 度から G4・A4・D5 の和音へ。黒い画面からデスクトップまで 2.7 秒 → 1.26 秒。エディタの BS の跡と、cyberpunk の白い欄の文字色も直した

開始 2026-11-15 10:25 (JST)、終了 2026-11-15 11:30 (JST)。

## 1. 起動の演出

`main/ruby/kernel/system_desktop.app.rb` の `BOOT_*`・`start_boot_animation`・`tick_boot_animation`・
`tick_boot_jingle` を置き換えた。ロゴの画像と `boot_splash = false` の飛ばし方、`finish_boot_animation`
の後始末は変えていない。

### 作り

- 段の時刻も音の時刻も**最初の tick からの実時間 (ms)** で持つ (`Machine.board_millis`)。前の作りは
  tick の回数で数えていて、sim では 60 ms の tick が実際は 80 ms 前後かかり、ジングルが表の約 1.4 倍に
  伸びていた (変更前の WAV で拍の間隔が 180 ms のはずが約 250 ms)。重いフレームがあっても演出の長さと
  絵と音の合わせ目がずれない。
- 描くのは前のフレームから変わった帯だけ: 線は伸びた両端の 2 つ、開く段は上下に広がった 2 本の帯
  (透過色 0x01)、白の山はロゴの矩形 1 つ (白で塗る → 0x01 に戻す)。全画面を塗るのは最初の黒だけ
  (前と同じ)。整数の計算だけ (ease-out も整数)。
- `BOOT_FRAME_MS` は 60 → 33 (動きを滑らかにするため。描く量は段ごとに 0〜2 本の矩形)。
  `BOOT_HOLD_MS` (1 秒の待ち) は無くし、`BOOT_END_MS` = 1200 でデスクトップに替わる。

### 段と時間 (最初の tick からの ms)

| 段 | 予定 | sim の実測 Retro | sim の実測 Modern | 音 |
|---|---|---|---|---|
| 1. 黒の中央に短い線 (幅 = 画面の 1/8、高さ 2 px) | 0 | 0 | 0 | P1 G3 + 三角 G2 + ノイズの小さな音 |
| 2. 線が横に伸びる (ease-out) | 90〜260 | 98〜233 | 99〜230 | (G3 のまま) |
| 3. 上下に開く (ease-out) | 260〜500 | 263〜497 | 264〜494 | P1 D4 (5 度上へ) |
| 4. 開ききる → ロゴの矩形を白に (明るい山) | 500 | 497 | 494 | G4・A4・D5 + ノイズのきらめき |
| 5. ロゴが戻って落ち着く | 580 | 597 | 596 | 和音を音量の段で下げる |
| 6. デスクトップ | 1200 | 1255 | 1222 | 1190 で無音 |

実測は sim の共有メモリの画面を 3 ms ごとに読んで、変わった画面ごとに時刻を取ったもの (下の「測り方」)。

画面 (各段): `tmp/boot_splash/retro_1_0ms.png` 〜 `retro_8_1255ms.png` (Retro 320x240、8 枚)、
`tmp/boot_splash/modern_1_-34ms.png` 〜 `modern_9_1222ms.png` (Modern 426x240、9 枚。1 枚目は
演出の前の黒)。ファイル名の ms は線が出た画面からの時刻。

### 音 (予定の音高と WAV で測った値)

| 声 | 予定 | 予定 Hz | WAV で測った Hz | ずれ | 鳴る区間 (ms) |
|---|---|---|---|---|---|
| 三角 (低音) | G2 | 98.00 | 98.11 | +2 cent | 0〜500 |
| P1 | G3 | 196.00 | 196.22 | +2 cent | 0〜260 |
| P1 | D4 | 293.66 | 294.34 | +4 cent | 260〜500 |
| P2 | G4 | 392.00 | 392.22 | +1 cent | 500〜1190 (音量 12→1 を 8 段) |
| 三角 | A4 | 440.00 | 440.51 | +2 cent | 500〜820 |
| P1 | D5 | 587.33 | 590.73 | +10 cent | 500〜1190 (音量 10→1 を 7 段) |
| ノイズ | 小さな音 / きらめき | 周期 4 / 短周期モード 1 | (高域。音高なし) | - | 0〜40 / 500〜680 |

- WAV: `tmp/boot_splash/after_retro.wav`・`after_modern.wav` (演出の分だけ切り出した 15720 Hz モノラル)。
  比べる用に変更前の `before_retro.wav`・`before_modern.wav` も置いた。
- 測り方: 窓ごとの Goertzel で半音ごとの強さを見て段を分け、各音の区間で ±60 cent を 1 cent 刻みで
  探して一番強い周波数を取った。ずれは APU の分周の丸め (D5 は 587.3 Hz を頼んで 588.7 Hz になる) と
  測りの分解能の範囲。
- **3 つの音色しかない制約で 1 つ決めた**: APU の音の出る声は P1・P2・三角の 3 つで、和音の 3 音と G2 の
  低音を同時には鳴らせない。そこで低音 G2 は線の段 (G3・D4 の下) で鳴らし、和音になったら三角は A4
  (色の音) へ移る。音量を下げられるのは矩形波だけなので、和音の骨 (G4・D5) を P2・P1 が持って段で
  下げ、最後は空 5 度で消える。三角は音量が無いので 820 ms で抜ける (和音が大きいうちに抜けるので
  段差は目立ちにくい。WAV の RMS で 694 → 626 → 415)。和音の時に G2 も欲しい・三角の抜け方が
  気になる、ならユーザの判断で振り分けを変える。
- sim の WAV の時間軸について: graphics-audio は `note_on` のたびに 1 コマ分を余計に書く (遅延を減らす
  ため) ので、リングを並べた WAV は音の数だけ少し長い (1.2 秒の演出が約 1.5 秒)。合わせ目は
  書かれた時刻 (実時間) で照らし、D4 は線の画面から +233 ms (予定 260、tick の刻み 33 ms の内)、
  和音は +500 ms (予定 500) だった。

### 測り方 (道具は scratchpad、リポジトリには入れていない)

`--ipc host` の小さなコンテナを先に立てて共有メモリの出現を待ち、そのあと compose を上げて、画面の
完成した側と音のリングを 3 ms ごとに読み、変わった画面と音のサンプルを実時間つきで書き出した。
MCP の sim_up は起動を待ってから返るので、起動中の連続した画面はこの形でないと撮れない。

## 2. エディタ: 改行の後の BS でカーソルの反転が残る

- 再現: 標準の構成 (Spinel のエディタ) で `abc` → Enter 4 回 → BS 3 回。カーソルは 2 行目に戻るが、
  3〜5 行目にカーソルの黒い箱が残る (`tmp/boot_splash/editor_bs_before.png`)。
- 原因: 行の結合 (行頭の BS) は「この行から下」を描き直しに印を付けるが、`redraw_dirty`
  (editor/render.rb) は**本文の最後の行より下の画面の行を全部飛ばしていた**。結合で本文が 1 行縮むと、
  前の最後の行 (カーソルが描かれていた行) は本文の外になり、誰も消さない。複数行の選択の削除と、
  折り返しの行が短くなって行数が減るときも同じ穴だった。
- 直し: 前回の描画で文字のあった画面の行の数を `@drawn_rows` に覚え (全体の描画と差分の描画の
  両方で更新)、差分の描画では本文の外の行のうち前回まで文字があった行だけを消す。ふつうは結合 1 回で
  1 行。全体を描き直す直し方ではない。
- 確認: 同じ操作で残らない (`tmp/boot_splash/editor_bs_after.png`、cyberpunk でも
  `editor_bs_after_cyberpunk.png`)。3 行の選択を Shift+↑ で取って BS しても残らない。
- mruby のエディタ: Spinel と同じソース (main/ruby/default_app/editor/) から作るので同じ直しが入る。

## 3. Cyberpunk のテーマ: 白い欄の文字が黄緑

- 欄: デスクトップのファイル選択の保存の Name 欄 (エディタで Ctrl+S、パスを打つ所)。FmrbUI の
  TextField で、箱は `THEME_TEXT_LIGHT` (どのプリセットでも白 0xFF)、文字とキャレットは `THEME_TEXT`。
  cyberpunk の text は 0x1C (明るい緑) なので白の上で読みにくい (`tmp/boot_splash/cyberpunk_field_before.png`)。
  **dark でも同じ欄が白に白 (0xFF) で文字が見えなかった**。
- 色の決め方 (doc/app_theme/plan.md に沿う: テーマの項目は足さない、どのテーマでも自動で成り立つ規則):
  `THEME_TEXT` が暗い (エディタが暗い紙を見分けるのと同じ輝度、5/9/2 の重みで 45 未満) ときはそのまま、
  そうでなければ `THEME_BUTTON`。text_light は各テーマで「ボタンの色の上の文字」なので、
  ボタンの色は白の欄の上で必ず読める。FmrbUI は押されたボタンと Stepper の矢印でもう同じ組
  (text_light の地に button の文字) を使っている。

  | テーマ | 欄の地 | 文字 (前) | 文字 (後) |
  |---|---|---|---|
  | light | 0xFF | 0x00 黒 | 0x00 黒 (変わらない) |
  | dark | 0xFF | 0xFF 白 (見えない) | 0x49 濃い灰 |
  | cyberpunk | 0xFF | 0x1C 明るい緑 | 0x46 濃い紫 |

  後の画面: `tmp/boot_splash/cyberpunk_field_after.png`。
- ほかの白い地: FmrbUI の押されたボタン (文字はボタンの色)・Stepper の押された矢印 (C_BUTTON)・
  デスクトップのかなの指示器 (白い箱にメニューの色) は元から読める。白い地に `THEME_TEXT` を書いていたのは
  TextField だけだった。使っている所はファイル選択の Name 欄と、受け取りのアプリ
  (flash/app/tool/receiving.app.rb) の名前の欄の 2 つで、どちらもこの 1 か所の直しで直る。
  デモ類の白い画面 (i2c_kbd・encoder8 など) は自分の配色を持つので対象外。

### VM プール (rake regress:run)

同じ時点の木で、変更前 (この 3 つのファイルを 26c55373 に戻したもの) と後を Retro で比べた (byte):

| 点 | カーネル 前 | カーネル 後 | 差 | デスクトップ 前 | デスクトップ 後 | 差 |
|---|---|---|---|---|---|---|
| idle | 174904 | 179488 | +4584 | 817424 | 818984 | +1560 |
| running | 166016 | 170264 | +4248 | 818120 | 819632 | +1512 |
| closed | 182224 | 187240 | +5016 | 817424 | 818984 | +1560 |

- 基準 (test/regress/sim_baseline.json) とは、Retro でデスクトップ +1.3 KB (幅 512 を超える)・closed のカーネル
  +5.7 KB (幅 3% + 4 KB をわずかに超える) で落ちる。Modern はカーネル +6.6〜6.9 KB で落ち、デスクトップは
  逆に -4 KB。基準は更新していない。
- **デスクトップ +1.5 KB**: 演出のコードの大きさ (BOOT_EVENTS が 17 → 27 行、描画の段の 3 つのメソッド)。
  Modern では -4 KB と逆に動くので、GC の状態の揺れも混じる。
- **カーネル +4.5〜5 KB はデスクトップの変更から来る** (編集器と FmrbUI の直しだけを入れ、デスクトップを
  変更前に戻すと、カーネルは変更前と 1 byte も違わない 174904 / 166016 / 181528 に戻る)。演出の長さでは
  ない (BOOT_END_MS を 2700 にしても 179432 / 170264 / 187232 で同じ)。デスクトップは音を Hash の
  メッセージでカーネルに送るので、増えた音の数 (17 → 27 通) の分だけカーネルの起動直後のゴミの出方が
  変わり、GC の後に残るヒープの並びが変わったと見ている。**溜まり続ける増え方ではない**: sim で別のアプリから
  同じ形の note_on を 500 通送って GC の後に見ると、カーネルは 179448 → 162064 と減った。
  音の数を減らせばこの差は縮むが、消え方 (音量の段) と引き換えになるのでユーザの判断にする。
- 内蔵 RAM は増えていない (C の変更なし)。

- `boot_splash = false` の経路 (`:skip` → `finish_boot_animation`) はコードを変えていない。sim では
  流していない。
- 内蔵 RAM: C は触っていない (Ruby の定数の表が 1 つ入れ替わっただけ)。
