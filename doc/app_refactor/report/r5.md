# R5 報告: 画面の小物 (文字の幅・詰める・折り返す・ボタン) の共通化

> 状態: 完了 | 更新: 2026-10-25 | instruction_r5.md の記録。picoruby-fmrb-app の gem に `FmrbText` (FmrbGfx に混ぜる、幅に詰める・2 行に折る・複数行を描く) と `FmrbButtons` (押せる範囲の一覧と角丸のボタン) を足し、オセロの卓・お絵かきボード・麻雀・walk_scroller を載せ替えた。見た目は変わっていない (sim の Modern・Retro、ブラウザ版で前後の画素を比べた)。実機は使っていない。止まる条件には当たらなかった

## 1. 結果の要約

- **部品**: `lib/add/picoruby-fmrb-app/mrblib/fmrb-text.rb` (77 行、うちコメント 23 行) と `fmrb-buttons.rb` (55 行、うちコメント 17 行)。どちらも mruby の VM だけが読む。Spinel のプログラム (デスクトップ・エディタ) は自前の FmrbGfx を持ち、この 2 つのファイルも `fmrb-gfx.rb` も取り込まないので、Spinel 側の振る舞いは変わらない。既存のメソッドは 1 つも変えていない。
- **載せ替え**: 4 つのアプリから自前の小物を消した (4 章)。合わせて 216 行減、gem に 132 行。
- **見た目**: 前のファイルと新しいファイルを同じファームで順に動かし、画面の写しを画素で比べた。差は時計・マウスの矢印・残り秒数の数字だけ (5 章)。麻雀は検査の道具の記録 (210 の描画すべての図形と文字) が前後で完全に一致した。
- **試験**: `test/fmrb_text/run.rb` (42,008 項目、前のアプリの小物と答えを突き合わせる) を足し、`rake test` に入れた (`text:test`)。`rake test` は全部通る。`rake mahjong:overflow` は 0 failed / 55 warnings で前と同じ (出力も一字一句同じ)。
- **内蔵 RAM**: 6 章。
- **コミット**: 4 つ (8 章)。push はしていない。

## 2. 4 つのアプリの違い (載せ替えの前)

| 項目 | オセロの卓 | お絵かきボード | 麻雀 | walk_scroller |
|---|---|---|---|---|
| 文字の幅 | `text_w`: 多バイト 12 px、ASCII 6 px (efont 12 の固定) | 同じ `text_w` | `tw`: `@fw` (フォントの px × 倍率) で多バイト `@fw`、ASCII `@fw / 2` | 無し (文字数) |
| 幅に詰める | `fit(s, cols)`: 桁 (全角 2・半角 1) で数える、印なし | 同じ `fit` | `fit(s, w)`: px で測る、切ったら `..`、`..` の余地は倍率にかかわらず 12 px | `fit(t, n)`: 文字数で切る (6x8 の既定フォント) |
| 印つきで詰める | `fit_dots`: `…` を付ける、余地は 2 桁 (12 px)、桁が 2 未満なら空 | - | (上の `fit` が印つき) | - |
| 2 行に折る | `wrap2`: 1 行目の最後の空白で割って残りが 1 行に収まればそこで、だめなら桁で切り、2 行目は `fit_dots` | - | - | - |
| 複数行を描く | `text_lines`: `wrap2` の行を 15 px 間隔、次の y を返す | - | - | - |
| ボタンの形 | 角丸 (半径 3)、高さ 16、`theme_accent` の地に `theme_fg_light` の字、字は中央・2 px 下 | 角丸 (半径 3)、高さ 15、同じ色、字は 1 px 下 | 角丸 (半径 `u(4)`、1280 では 8)、幅は字から決まる、牌の絵を含む、色は種類で変わる (和了は赤、パスは灰) | - |
| 押せる範囲 | `[id, x, y, w, h]` の一覧、最初に当たったもの | 同じ | `[種類, x, y, w, h, 牌]` の一覧 (行の選択など絵でないものも入る)、最初に当たったもの | - |

- オセロの「桁」は efont 12 の px を 6 で割ったものと同じ。半角カナも efont では全角の箱で描かれ (FONT_METRICS の `kana_w` 12)、`text_w` の「多バイトは 12」と同じになる。`…` も多バイトとして 12 px に数える点で FmrbGfx#text_width と同じ (efont は半角で描くので、詰め方は短い側に 6 px 外れる。前からの形で、変えていない)。
- 麻雀の `tw` も、FONT_METRICS の `[:ja, 12]`・`[:ja, 16]` に倍率を掛けた FmrbGfx#text_width と同じ答えになる (麻雀は efont 12・16 だけを使う)。
- FmrbUI の Button は四角に枠線、mixed の 6x8/8x8 フォント、押している間は反転、離したときに働く、作ったら残る (retained) 部品。4 つのアプリのボタンは角丸・efont・押した時点で働く・毎回描き直す画面の一部で、形も押せる範囲の扱いも違う。指示 (違うならアプリの形のまま共通にする) に従い、FmrbUI には寄せていない。

## 3. 共通の口の設計

置き場は、幅の計算が描くフォントの状態 (FmrbGfx の `current_font`・`current_text_size`) に依るので FmrbGfx にした。ただし `fmrb-gfx.rb` に直接書かず、`FmrbText` というモジュールにして `class FmrbGfx; include FmrbText; end` で混ぜる。こうすると、`text_width` と `draw_text` を持つ別のもの (麻雀の検査の道具の記録係) にもそのまま混ぜられる。FmrbUI に置かなかったのは、`fmrb-ui.rb` が Spinel のデスクトップ・エディタにも取り込まれる (tool/spinel/gen_app_combined.rb) ため。

### 3.1 FmrbText (FmrbGfx のメソッド)

| メソッド | 中身 |
|---|---|
| `fit_text(str, width, mark = "", mark_w = nil)` | `str` が `width` px に収まればそのまま。収まらなければ 1 字ずつ足して、`使った幅 + 次の字 + mark_w` が `width` を超える手前で切り、`mark` を付ける。`mark_w` を省くと `text_width(mark)`。 |
| `wrap_text(str, width)` | 最大 2 行の配列。収まれば 1 行。1 行目 (`fit_text` の印なし) の最後の空白で割って残りが 1 行に収まればそこで割り、だめなら幅で切って 2 行目を `fit_text(残り, width, "…")`。 |
| `draw_text_lines(x, y, str, width, color, line_h)` | `wrap_text` の行を `line_h` 間隔で描き、最後の行の下の y を返す。 |

- 幅はすべて FmrbGfx#text_width (FONT_METRICS と今の倍率) で測る。字の区切りは getbyte・byteslice で UTF-8 を見る (Regexp を使わない、`String#[]` の頭からの数え直しを避ける)。
- 麻雀の `..` の余地は、載せ替えの時点では前と同じ 12 px 固定 (`mark_w` で 12) にした。ユーザの判断で、そのあと実際の幅で測る形に直した (10 章)。
- オセロの `fit_dots` の「桁が 2 未満なら空」は入れていない。オセロで最も狭いのは席の名前の欄で、Retro で約 10 桁 (60 px) あり、この条件に当たる場面が無いため。麻雀の `fit` (印だけを返す) と同じ形にそろえた。

### 3.2 FmrbButtons

| メソッド | 中身 |
|---|---|
| `FmrbButtons.new(gfx)` | アプリの `@gfx` を渡す。 |
| `clear` | 描き直しの前に一覧を空にする。 |
| `add(id, x, y, w, h, data = nil)` | 押せる範囲だけを足す (絵はアプリが描く)。 |
| `button(id, x, y, w, h, label, fill, fg, radius = 3)` | 角丸の地 (`fill_round_rect`) と中央の字 (`(w - text_width) / 2`、`(h - font_height) / 2`) を描き、範囲を足す。 |
| `at(x, y)` / `id_at(x, y)` | 当たった `[id, x, y, w, h, data]` / その id (無ければ nil)。前の判定と同じく最初に当たったもの。 |

- オセロ (高さ 16) とボードの (高さ 15) の字の位置 2 px 下・1 px 下は、`(h - font_height) / 2` で同じ値になる。
- 麻雀は `add` と `at` だけを使う (牌の絵を含む中身、種類ごとの色、1280 の半径 8 はアプリに残る)。

## 4. 載せ替え

| アプリ | 前 | 後 | 差 | 消えたもの |
|---|---|---|---|---|
| オセロの卓 (`flash/app/game/othello/othello.app.rb`) | 797 | 716 | -81 | text_w・fit・fit_dots・wrap2・text_lines・button_at、button は 1 行の包み (色と高さ) |
| お絵かきボード (`flash/app/game/board/board.app.rb`) | 1,209 | 1,171 | -38 | text_w・fit・button_at、button は 1 行の包み |
| 麻雀 (`flash/app/game/mahjong/*.rb` 9 ファイル) | 6,674 | 6,649 | -25 | fit の中身 (1 行の包みに)、2 か所の当たり判定の繰り返し、`@buttons` の配列 |
| walk_scroller (`flash/app/demo/walk_scroller.app.rb`) | 1,375 | 1,371 | -4 | fit |
| gem (`fmrb-text.rb`・`fmrb-buttons.rb`) | - | 132 | +132 | |

- 桁で数えていた所は px を渡す形にした (`cols = (幅) / 6` → 幅、`n = @pw / 6` → `@pw`)。efont 12 では字の幅がすべて 6 の倍数なので、`幅` と `幅 / 6 * 6` のどちらを渡しても切る位置は同じ。
- 麻雀の `fit` は呼ぶ所が 40 か所あまりあるので、名前は残して中身を `@gfx.fit_text(s, w, "..", 12)` にした (10 章の直しで `@gfx.fit_text(s, w, "..")`)。`tw` (幅) は麻雀のあらゆる描画が使い、FmrbGfx#text_width (呼ぶたびに `str.bytes` の配列を作る) より軽いので残した。
- walk_scroller の 2 行 (`TUNE <ノード>` と状態の行) は 6x8 の既定フォントで ASCII だけなので、`38 字` と `38 × 6 px` は同じ。
- 麻雀の検査の道具 (`tools/mahjong_overflow/check.rb`) は gem の 2 つのファイルを読み込み、記録係に `FmrbText` を混ぜ、`text_width`・`font_height` を足した。`@buttons` は FmrbButtons を置く。

## 6. RAM

`idf.py size` 相当 (`python -m esp_idf_size build/fmruby-core.map`、IDF のイメージの中で)。後 = コミットした作業ツリー、前 = 同じ作業ツリーから gem の 2 つのファイル (`fmrb-text.rb`・`fmrb-buttons.rb`) だけを外したもの (R4b のあとの gem と同じ)。どちらも `rake clean_all` → `FMRB_HW_TARGET=<機種> rake build:esp32` (ビルドの記録で、後には 2 つのファイルが入り、前には無いことを確認)。アプリのファイルはファームの像に入らない。

| 端末 | DIRAM 前 | DIRAM 後 | 像の大きさ 前 → 後 |
|---|---|---|---|
| Tab5 (P4) | 129,698 | 129,698 | 6,685,668 → 6,687,884 (+2,216) |
| Retro (NARYAv3) | 126,035 | 126,035 | 4,510,231 → 4,512,415 (+2,184) |
| StickS3 | 114,863 | 114,863 | 4,528,063 → 4,530,263 (+2,200) |

- DIRAM は 3 機種とも前後で同じ (R4a・R4b の値とも同じ)。mrblib の Ruby は flash に bytecode として入るだけで、静的な内蔵 RAM は増えない。picoruby-fmrb-app は Retro にも入るので、Retro の像も約 2 KB 増える。
- 2 つのクラス・モジュールは picoruby-fmrb-app を持つ VM ごとに定義され、VM のプール (PSRAM) に乗る。卓のアプリの VM プールは起動直後で同じか小さい (5.1)。
- 作業の後、build/ は Linux (TAB5、x86-64) に作り直した。TAB5 の esp32 ビルドは置き換わっているので、焼く前に `rake clean_all && rake build:esp32` が要る。ブラウザ版の束 (`wasm/build`) は新しい gem のもの。

## 7. 残件・気づいたこと

- **FONT_JA=0 の構成** (ユーザの判断: このままでよい) (AtomS3R・StickS3 の既定): 前のオセロ・ボードは efont 12 の決まった幅 (6/12) で数えていたが、新しい形は今のフォント (misaki 8 に落ちる: 4/8) で測る。この構成では、描かれる幅どおりに詰めるので切れる位置が前より後ろになる (ボタンの字の縦の位置も misaki の 8 px で中央になる)。卓のアプリは小さい端末では開かない (AtomS3R が映すのは別のアプリ「オセロ (直接)」) ので、確認した構成 (sim・ブラウザ版・Tab5 の想定) では差は無い。
- 麻雀の `..` の余地 (12 px 固定で、16 px のフォントと倍率 2 ではみ出していた) は直した (10 章)。
- ボードは Retro の 320 幅で右の欄が画面の外に出る (前から)。オセロのように画面全体を取る形にするなら別に決める。
- 麻雀の `tw` は FmrbGfx#text_width と同じ答えだが、軽さのため残した。text_width が `str.bytes` を作らない形 (getbyte) になれば寄せられる (既存の口の中身の変更になるので R5 ではしていない)。
- walk_scroller の `age.length * 6` (右寄せの幅) は文字数のまま (ASCII だけ)。
