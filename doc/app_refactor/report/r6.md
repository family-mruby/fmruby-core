# R6 報告: FmrbText・HitAreas を広げ、FmrbUI も FmrbText で詰める

> 状態: 完了 | 更新: 2026-10-25 | instruction_r6.md の記録。FmrbText を Spinel のデスクトップ・エディタに入れ、FmrbUI のラベル・ボタン・切り替え・値の欄が収まらない文字を `..` で詰めるようにした。FmrbButtons は FmrbUI::HitAreas (押せる範囲だけ) と FmrbGfx#draw_button (絵だけ) に分けて消した。5 つのアプリを載せ替えた (描画の記録は差 0)。使い分けを doc/reference/screen_helpers.md に書いた。止まる条件には当たらなかった。実機は使っていない

## 1. 結果の要約

- **Spinel**: `fmrb-text.rb` を `tool/spinel/gen_app_combined.rb` でデスクトップとエディタに足した。Spinel 版の FmrbGfx (text_width・FONT_METRICS は mruby 版と同じ) に混ざる。中の繰り返しは型の決まった C になる (2 章)。
- **FmrbUI**: 箱より広い文字だけを詰める。収まる文字の場面 (fmrbui_sheet の normal_en・normal_ja・operate、FmrbUI を使うほかのアプリの全場面) は描画の記録が差 0 (3 章)。
- **HitAreas**: `FmrbUI::HitAreas` (clear・add・at・id_at、描かない) と `FmrbGfx#draw_button` (角丸の地と中央の字、FmrbButtons#button と同じ呼び出し) に分け、`fmrb-buttons.rb` を消した。オセロの卓・ボード・麻雀を書き換えた。記録は差 0、麻雀の検査の道具の出力と `--dump` (210 の描画) も前と同じ。
- **5 アプリ**: 描画の記録は全場面で差 0。行数は 2,821 → 2,774 (4 章)。
- **内蔵 RAM**: `rake regress:size` は全 5 端末で内蔵 +0 (ok)。Spinel のエディタの TU の内蔵の分は 92 B のまま、増えた 2 つのプールの数えは PSRAM (+116 B、P4) に入った (5 章)。
- **regress:run**: gem に足した分で、起動したアプリの VM プールの使用量が 0.6〜2.2 KB 増えて落ちた (想定どおり、基準は更新していない。5.2)。
- **コミット**: 7 つ (8 章)。push はしていない。

## 2. FmrbText を Spinel で使えるようにした方法

### 2.1 取り込みの道筋

- Spinel のプログラムは `gen_app_combined.rb` が Ruby を 1 つにつないで作る。デスクトップ・エディタとも `fmrb-ui.rb` を取り込んでいて、FmrbGfx は `main/prebuild_scripts/spinel/fmrb_app_base_spinel.rb` の Spinel 版 (text_width・font_height・current_text_size・FONT_METRICS を持つ。mruby 版の `fmrb-gfx.rb` は取り込まない)。
- `fmrb-text.rb` を両方の libs の `fmrb-ui.rb` の前に足した。ファイルの最後の `class FmrbGfx; include FmrbText; end` が Spinel 版の FmrbGfx を開き直して混ぜる。CMake 側は生成済みの combined を読むだけなので直しは要らない。カーネルは FmrbUI を取り込まないので触っていない。

### 2.2 型

- 既存の FmrbUI は Spinel の中ではほぼ全部が型の決まらない値 (sp_RbVal) で動いている (前のコードの生成 C でも `sp_Widget_measure(self, sp_RbVal gfx, sp_RbVal str)`、`sp_FmrbGfx_text_width` の戻り値も sp_RbVal)。FmrbUI から渡す値は型が決まらない。
- そこで `fit_text` の頭で `str.to_s`・`width.to_i`、測った幅と `mark_w` に `.to_i` をかけた。生成 C では、中の局所変数がすべて `sp_int` / `const char *` / `sp_String *` になった (`lv_w`・`lv_mw`・`lv_used`・`lv_cw`・`lv_ch`・`lv_out`)。境の変換は `sp_poly_to_i_meth` (整数はそのまま返し、合わない物は NoMethodError。黙って 0 にはならない)。mruby でも同じ意味 (dual-safe)。
- 型の決まった呼び出し元から 3 つの口を呼ぶと、3 つとも型の決まった関数になることを、小さなプログラム (base + fmrb-text.rb + 3 行の呼び出し) を spinel にかけて確認した:
  - `const char * sp_FmrbGfx_fit_text(sp_FmrbGfx *, const char * str, sp_int width, const char * mark, sp_RbVal mark_w, sp_RbVal family)` (mark_w と family は nil との組なので sp_RbVal。どちらも text_width に渡すだけで、受け手にして呼ぶことはない)
  - `sp_StrArray * sp_FmrbGfx_wrap_text(sp_FmrbGfx *, const char *, sp_int)`
  - `sp_int sp_FmrbGfx_draw_text_lines(sp_FmrbGfx *, sp_int x, sp_int y, const char *, sp_int, sp_int, sp_int)`
- エディタ・デスクトップの中で使うのは `fit_text` だけ。`wrap_text`・`draw_text_lines` は呼ばれないので生成されない。
- `fit_text` に `family` を足した (5 番目、既定 nil = 今のフォント)。FmrbUI は今のフォントにかかわらず mixed の描き方 (ASCII は Font0 6 px、多バイトは misaki 8 px) で描くので `:default` を渡す。既存の呼び出し (麻雀・オセロの卓ほか) はそのまま。
- 文字列は `"".dup` から足す (Spinel では文字列リテラルが凍っている)。
- FmrbUI#move の中の `t.fit_widget_text(@gfx)` は基底型の受け手への呼び出し。名前はプログラムの中で一意にし、生成 C の分岐 (`sp_pd_16`) が Button → `sp_Button_fit_widget_text`、Scrollbar・TextField → 基底の何もしない版に落ちることを確認した (当たらない型は NoMethodError)。
- `rake spinel:doctor`: 前 (a5ac55cf、コードは R6 の直前と同じ) と後で、指摘は同じ 11 件・[ERR] 3 件 (どちらも許可済みの物)。行番号がずれただけで中身は同じ。結果は clean。

## 3. FmrbUI の詰め方

| 部品 | 詰める条件 | 詰める先 |
|---|---|---|
| Label | 文字の幅 > 幅 | 幅 |
| Button | 文字の幅 > 幅 | 幅 - 2 (枠線の内側) |
| Toggle | 2 つの文字 (off と on_text) それぞれ、幅 > 幅 | 幅 - 2 |
| Stepper・Enum | 値の文字の幅 > 値の欄 (幅 - 矢印 2 つ) | 値の欄 - 2 |
| TextField | 詰めない | - |
| Scrollbar | 文字が無い | - |

- 印は `..` (Font0 の 2 マス、倍率 1 で 12 px)。mixed の描き方で ASCII は Font0 なので、どの機種でも描ける。`…` (misaki の字) より幅は広いが、確実に描けることを優先した。sim の Modern で MIDI APU の `smf: Joplin_entertain..` が正しく描かれることを画面で確認した。
- 「箱より広いときだけ」詰めるので、箱に収まる文字 (枠線に触れるほどの物も含む) は前と同じ文字列を同じ位置に描く。
- 測り方は既存の `measure` と同じく「今の倍率で測って部品の倍率に直す」。詰める幅は `room / 部品の倍率 * 今の倍率` を渡す (FONT_METRICS の幅は倍率の整数倍なので割り算は切り捨てで同じ答え)。
- アプリが渡した文字は `@text` のまま持ち (`Label#text` などはそれを返す、`set_text` の同じかどうかの比較もそれ)、詰めた写しを `@show` に持つ。詰め直すのは文字を変えたとき (initialize・set_text・Stepper の値と suffix) と、`FmrbUI#move` で幅が変わったとき。デスクトップは窓のボタンを小さく作ってから move で置くので、作った時点で詰まっても move で元に戻る。flush では測らない。monitor が動作中に move を呼ぶので、幅が変わらない move では測らない (測ると割り当てが起きる)。
- TextField を詰めないのは、打っている末尾が見えなくなるため。長い名前を打つと欄からはみ出す件は前のまま (残件)。

### 3.1 描画の記録で差が出た場面 (基準を更新した物)

差が出たのは 14 の記録 (6 場面) の `textm` の行だけ (110 行。ほかの命令の行は 1 行も変わっていない)。

- `fmrbui_sheet/long_en`・`long_ja`・`operate_long_ja` (4 つの端末の組すべて): わざと長い文字の場面。
  - ラベル (160 px): `A label whose text is far longer than the widget it sits in` → `A label whose text is fa..`。中央寄せの方は前は窓の左外 (x -92) から描いていたのが x 7 から。日本語は `部品の幅よりずっと長い文字の見出しがここに入る` → `部品の幅よりずっと長い文字の見出しが..`。
  - 倍率 2 のラベル (100 px): `Much too big` → `Much t..`、`大きすぎる文字` → `大きすぎ..`。
  - ボタン (70 px、3 つ): `Apply the changes now` → `Apply the..`、`変更をすぐに反映する` → `変更をすぐに反..`。
  - 切り替え: `Background music and effects` (120 px) → `Background music ..`、on の文字 `背景の音楽と効果音を鳴らす: 入` → `背景の音楽と効果音を鳴らす..`。off の `背景の音楽と効果音を鳴らす` (104 px) は収まるので変わらない。組の切り替え (40 px): `The quietest setting` → `The ..`、`いちばん小さい音` → `いちば..` など。
  - 選択の値 (欄 92 px): `Somewhere in between` → `Somewhere in ..`。日本語の選択肢 (最長 64 px) は収まるので変わらない。
- `midi_apu/smf` (retro・modern): わざと長い場面ではないが、状態のラベル (142 px) に読み込んだファイル名 `smf: joplin_entertainer.mid` (162 px) が出て、ラベル自身の地の外まではみ出していた。`smf: joplin_entertain..` になった。収まらない文字の場面なので止まる条件には当たらないと判断し、同じコミットで基準を更新した。親の確認をお願いしたい。
- 基準の更新は `ca034797` (`test: regress baseline ...`) に分けた。収まる文字の場面、5 アプリ、オセロの卓・ボード・麻雀には差が出ていない。

## 9. 指示との違い・残件

- 基準の更新に `midi_apu/smf` (わざと長い場面ではないアプリの場面) を含めた (3.1)。収まらない文字の場面なので止まらなかった。
- 麻雀・オセロの卓・ボードの `@buttons` を `@hits` に改名した (HitAreas は描かないので、名前を範囲に合わせた)。StackChan Remote の `@buttons` (ボタンの定義の一覧) はそのまま。
- `draw_button` は mruby の FmrbGfx (`fmrb-gfx.rb`) だけに置いた (Spinel のプログラムは使わない)。
- 残件:
  - `rake regress:size:update` は不要 (内蔵 +0、flash の増えだけ)。`rake regress:run:update` は親の検収のあと。
  - FmrbUI の TextField は長い文字を詰めない (打っている末尾を見せる形は別の課題)。
