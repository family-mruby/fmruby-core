# B1 報告: 端末の証明書の束から G3 を外す

> 状態: 完了 | 更新: 2026-10-22 | `rake certs:bundle` で IDF の全部入りから emSign ECC Root CA - G3 を除いた `config/cacrt_fmrb.pem` (149 枚) を作り、Wi-Fi のある 4 機種の sdkconfig.defaults で使わせた。Tab5 向けのビルドで、生成された束が 149 枚・G3 なしであることを確認した。焼いていない (B2 で親)

## 1. 道具と rake

| コマンド | 中身 |
|---|---|
| `rake certs:bundle` | `tools/cacrt_bundle.rb --image <ビルド用 image>`。image の中の IDF から入力を docker でコピーし、`config/cacrt_exclude.txt` の名前を除いて `config/cacrt_fmrb.pem` を書く |
| `rake certs:test` | host の試験 (`test/ca_bundle/run.rb`)。`rake test` に入れた |
| `rake certs:check_build` | 直前の ESP32 ビルドが作った `build/esp-idf/mbedtls/x509_crt_bundle` を読み、`config/cacrt_fmrb.pem` と subject の集合が一致し、外した名前を含まないことを確認する |

道具のふるまい:

- IDF の `components/mbedtls/CMakeLists.txt` を読み、`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_DEFAULT_FULL` の枝が `cacrt_all.pem` + `cacrt_local.pem` を連ねる 1 行だけであることを確認してから作る。IDF の作りが変わったらエラーで止まる。
- 名前は PEM の上の名前の行 (下に `====` の行があるもの) と完全一致で照合する。外す名前が見つからない・2 つ以上当たるときはエラーで止まる。
- 各証明書は元のテキスト (名前の行・下線・PEM) をそのまま写す。時刻を書かないので同じ入力から同じ出力になる。
- 先頭の注記: IDF の版、入力 2 つの SHA-256、Mozilla の日付 (MPL-2.0)、枚数 (元・外した数・残り)、外した名前、作り方。
- image の起動時の案内表示は捨て、docker が失敗したときだけ出す。

外す一覧 `config/cacrt_exclude.txt` は 1 行 1 名、`#` から行末は注記。今は `emSign ECC Root CA - G3` だけで、理由を注記に書いた。

## 2. 元の束

- IDF v5.5.4 (ビルド用 image `ghcr.io/family-mruby/fmruby-esp32-build:v5.5.4`、`$IDF_PATH=/opt/esp/idf`)。版は `esp_idf_version.h` から読む。
- 全部入りの入力は CMakeLists のとおり `cacrt_all.pem` + `cacrt_local.pem` で、想定と同じだった。`cacrt_local.pem` は注記だけで証明書は 0 枚。
- `cacrt_all.pem`: 150 枚、SHA-256 `50a6277ec69113f00c5fd45f09e8b97a4b3e32daa35d3a95ab30137a55386cef`、Mozilla の日付 Tue Feb 25 04:12:03 2025 GMT。
- `cacrt_local.pem`: 0 枚、SHA-256 `98154a7a09134484dc889e725b95a030d423b7b09cb0b3d219ac3fcc8e07f29e`。

## 3. 自前の束

- `config/cacrt_fmrb.pem`: 149 枚、SHA-256 `e451c7b20371329de827f8f9e2b4d1f48d1ab0fe5145c471671c998bade6bf01`。
- `rake certs:bundle` を 3 回流し、3 回とも同じ SHA-256 (途中で下線を元の行から写すよう直したが、出力は変わらなかった)。
- 元の `cacrt_all.pem` の証明書部分と diff を取り、違いが G3 の 16 行 (名前・下線・PEM・空行) だけであることを確認した。emSign の G1・C1・C3 は残っている。

## 4. sdkconfig.defaults の 4 行

- `config/sdkconfig.defaults.p4`・`.naryav4`・`.atoms3r`・`.n16r8` の末尾に、空行 1 つと指示どおりの 4 行だけを足した (注記は付けていない)。
- パスの基準: IDF の CMakeLists が `get_filename_component(... ${CONFIG_MBEDTLS_CUSTOM_CERTIFICATE_BUNDLE_PATH} ABSOLUTE BASE_DIR "${project_dir}")` で解決する (Kconfig の help も "relative to the project root directory")。fmruby-core が project なので `config/cacrt_fmrb.pem` のままで正しい。書き換えは不要だった。
- `DEFAULT_NONE` のときは全部入りも `cacrt_deprecated.pem` も入らない (`DEPRECATED_LIST` は `!DEFAULT_NONE` が条件)。入力は自前の束 1 つだけになる。
- MAX_CERTS は既定の 200 のまま。149 枚で収まる。
- ルートの `sdkconfig` は編集していない (`rake clean_all` で消え、ビルドが作り直した)。

## 5. Tab5 向けのビルドでの確認

`.env` の `FMRB_HW_TARGET=TAB5` を確認し、`rake clean_all && rake build:esp32` が通った (app 0x65a2c0 バイト、空き 9%)。

- 生成された `sdkconfig` と `build/config/sdkconfig.h`: `CONFIG_MBEDTLS_CERTIFICATE_BUNDLE=y`、`DEFAULT_FULL` と `DEFAULT_CMN` は not set、`DEFAULT_NONE=y`、`CUSTOM_CERTIFICATE_BUNDLE=y`、`CUSTOM_CERTIFICATE_BUNDLE_PATH="config/cacrt_fmrb.pem"`、`MAX_CERTS=200`。
- `build/build.ninja` の束の生成コマンドは `gen_crt_bundle.py --input /project/config/cacrt_fmrb.pem -q --max-certs 200` (入力は自前の束だけ)。
- 生成物 `build/esp-idf/mbedtls/x509_crt_bundle` (68746 バイト): `rake certs:check_build` で 149 枚、subject の集合が `config/cacrt_fmrb.pem` と一致、外した名前なし。バイト列の grep でも "emSign ECC Root CA - G3" は 0 件、"emSign Root CA - G1" は 1 件。
- `file build/fmruby-core.elf`: ELF 32-bit LSB executable, UCB RISC-V (ESP32-P4)。
- build/ は残してある (B2 でそのまま焼ける)。焼き・シリアルには触れていない。

## 6. 試験

- `rake certs:test`: 全部通る。中身は、外す一覧の読み方、PEM の分け方と名前の取り方、名前の書き違いで止まること、閉じていない PEM で止まること、同じ入力で同じ出力、そして出荷する束について: 注記の枚数が一覧と合う、枚数 = 元 − 外した数 (150 − 1 = 149)、149 枚すべて OpenSSL::X509::Certificate で読める、G3 が名前でも subject の CN でも無い、200 以下。
- `rake test`: 全部通る (fmrb_ui・services・assoc・WAV・tts・secret_path・CA bundle・mahjong・voice・ti・BASIC golden 103・MicroPython smoke)。
