# P4 報告: 4 つのアプリを汎用の絵の部品に移す

> 状態: 完了 (検収待ち) | 更新: 2026-11-21 | チャットのスタンプ・画像ビューワー・スプライトエディタ・App Store を、P2 の `BMP332.to_png`・`info` と P3 の置き場 (`draw_picture`・`put_picture`・`draw_checker`) と `write_pixels`・`draw_tile(scale:)` に移した。置き場に「ファイルが 64 KB を超える絵は VM で読んで画素から置く」道を足した。移す前と後の画面は sim の Modern 19 場面・ブラウザ版 14 場面で比べ、App Store の店の絵の中の 163 点 (透明色 0x01 が透けるようになった) のほかは 0 点の差。スタンプの sha256 は変わらない。指示書は instruction_p4.md

## 0. 要点

- **置き場に足したもの** (`lib/gems/picoruby-fmrb-app/mrblib/fmrb-picture.rb`、+18 行): `:file_too_large` で断っていた絵 (点の数は 65,536 以内、ファイルが 65,536 B 超) を、置き場の中で `BMP332.load` で読んで `write_sprite_image` で置く (`_pic_read`)。アプリの側には書かない。`picture_error` の理由から `:file_too_large` が無くなった (sig・端末のヘルプも)。利用者から見た API の名前と引数は変えていない。
- **チャット**: 書き直しは `BMP332.to_png` (受けた絵は `to_png(data:)`)、大きさは `BMP332.info`、出すのは `draw_picture(path, x, y - sy, scale: k, clip: 行の帯)`。**拡大した絵を一時ファイルに書くのをやめた** (`scale_up`・`write_shown`・`png_size`・`stamp_sprite`・`release_sprites` を削除)。貯める場所と名前は今のまま (`/cache/app/chat/s/<sha の 32 桁>.png`)、中身が元の大きさの PNG になった。古い形 (拡大済み) の貯めた絵は、その大きさから倍率 1 が出るので今までどおりの大きさで出る。**sha256 は変わらない**。
- **画像ビューワー**: 絵を VM に読まない。`draw_picture(path, x, y, scale: 倍率 か -k, checker: true)`。開くときは空の切り抜き (`clip: [0, 0, 0, 0]`) で置き場に入れてみて、開けなければ前の絵を残す。前の絵は `release_picture`。市松の帯・色の連なりの描画・`MAX_PIXELS` を削除。
- **スプライトエディタ**: 256 色の升目を 16x16 の画素で置き場に 1 回 (`put_picture("pal", ...)`) 置いて `draw_picture(scale: 升の大きさ)` で押す (配置が変わるたびの 256 個の矩形が無くなった)。実寸の絵とタイルの一覧は、編集中の絵を 1 枚のスプライトの絵に持ち (`write_pixels`。別の絵なら全体、編集の後は今の範囲の行だけ)、`draw_checker` の上に `draw_tile(scale:)` で押す。拡大した編集の面 (升の中の 2x2 の市松と升目の線) は p0 8.3 のとおり移していない。
- **App Store**: 店の絵を `create_image` (4 枚まで自前の使い回し) から `draw_picture` に。`image_for`・`IMAGE_CACHE_MAX`・`stop` の上書き・`release_images` を削除。mruby で書かれている (`main/ruby/default_app`、Spinel ではない) ので、Spinel から置き場を呼ぶ例にはならなかった。
- **行数**: 4 つのアプリ (8 ファイル) で 4,726 → 4,469 行 (-257)。置き場は 412 → 430 行 (+18)。
- **VM プール** (sim の Modern、gc の直後 2 回): どのアプリも減るか同じ (チャット -4〜7 KB、ビューワー -5〜25 KB、App Store -1.5 KB、スプライトエディタ +1.4 KB)。2 章。
- **create_image を使うアプリ**は残る: `flash/` の PicoRuby の見本・Python の見本 (背景の 426x240 の絵)・`app/test/` の rover_cam・rover_pilot (JPEG のカメラの絵)、gem の picorabbit (スライドの絵)、デスクトップ (壁紙と起動の絵)、wasm の SDK の tour。4 章。

## 1. 移したもの

### 1.1 チャット (`flash/app/modern/chat/stamps.rb` ほか)

| 今まで | 替えた先 | 残したもの |
|---|---|---|

- **貯めるもの**: 一覧を開いたときに、パック・自分の絵を書き直した PNG を (無ければ) 貯める。これは今までと同じ時点 (前は拡大した絵を書いていた)。こうしておくと、同じパックの絵を他の端末が送ってきても取りに行かない (c3 の受け入れ条件 2 の後半)。受けた絵も `to_png(data:)` で確かめて書き直したものを貯める (端末が送った絵なら受けたバイト列と同じ)。
- **sha256**: 送る中身は `to_png` の結果。p2 で `parse` → `encode_png` と 1 バイトも違わないことを確かめてある。今回は、移す前の版が作った貯めた絵 16 枚の名前 (sha の先頭 32 桁) と、移した後に空の置き場から作り直した 16 枚の名前が同じ (パック 9 枚・自分の絵 2 枚・受けた絵) ことと、端末が書き直した絵 (パック・自分の絵) の中身の sha256 が名前と一致することを確かめた。PC の送り手 (CRuby の道具) がそのまま送った古い絵 5 枚は、端末で書き直すとバイトが変わる (c3 の 7 章の件。前からのこと) ので中身の sha は名前と違う。
- **古い形の貯めた絵**: 移す前の版で作った `/cache/app/chat/s/` (拡大済み) を残したまま、移した後の版で同じ場面を撮った: 4 場面とも差 0 点 (`after_old`)。

### 2.4 回帰 (条件 4・5)

- `rake regress`: 移した後、App Store の記録 8 つが変わった (1.4)。基準を更新して別のコミットにした後、host 33 suites・regress 310 runs 全部通った。

- `rake regress:run`: FAILED (基準は 2026-11-18 の 088cc852、更新していない)。差は P3 の報告 (p3.md 2.3) とほぼ同じ: デスクトップ +2,544〜+2,744、Kamon +520、MML +704、StackChan Remote +584、Spinel Hello +584 (P3 の後は +656・+704・+568・+536)、コンパイル直後 5 本 +1,432〜+1,520 (P3 の後と同じ範囲)。4 つのアプリは `regress:run` の対象に入っていない (2.3 の表が P4 の前後)。置き場に足した `_pic_read` の分は、絵を使わないアプリの揺れの中で見えなかった。

## 3. 自分で決めた細部

| 項目 | 決めたこと | 理由 |
|---|---|---|
| 置き場の大きいファイル | `BMP332.load` で読み `write_sprite_image` で置く。ファイルの大きさの上限は付けない | 前のビューワーが出せていた絵が出ること。上限は前のビューワーにも無かった |
| `:file_too_large` | `picture_error` の理由から消した (sig・ヘルプ) | もう起きない。`BMP332.to_png` の `:file_too_large` (`max_file_bytes:`) はそのまま |
| チャットの貯め方 | 一覧を開いたときにパック・自分の絵の書き直した PNG を貯める (前と同じ時点、中身だけ元の大きさに) | 他の端末が送った同じパックの絵を取りに行かない (c3 の条件 2) |
| 受けた絵 | `to_png(data:)` で確かめて書き直したものを貯める | 前と同じ確かめ方 (大きさ・読めるか)。端末が送った絵ならバイトは同じ |
| ビューワーの開き方 | 空の切り抜きで置き場に入れてから替える | 開けない絵で、前の絵が消えないように (前と同じふるまい) |
| スプライトエディタの色の升目 | 置き場の `put_picture` (16x16) | 置き場の数え (8 枚) に 1 枚。描画側の絵は 64 KB → 256 B |
| スプライトエディタの横の一覧 | 置き場でなく `SpriteImage` を直に持つ | 編集のたびに範囲の行だけ書き直すには、絵の番号が要る (置き場の `put_picture` は全体を書き直す) |

## 7. 選択肢 (親・ユーザに決めてほしいこと。先頭が推奨)

- **Q1 App Store の店の絵の 0x01**: (a) 受け入れる (推奨。スタンプのパックの店の絵は透明の地で描かれ、チャットの一覧と同じ見え方になる。普通の PNG は α・tRNS があれば抜け、無ければ (0,0,85) 近くの色だけが抜ける) / (b) 店の絵だけ透明なしのスプライトの絵にする (置き場に「透明なし」の引数が要る = 利用者から見た API を足す)。
- **Q2 置き場の大きいファイルの上限**: (a) 付けない (推奨。前のビューワーと同じ。VM プールが足りなければ `:unreadable`) / (b) 例えば 256 KB を超えるファイルは `:file_too_large` で断る (VM プールの山を抑える。前のビューワーで出せていた絵が出なくなることがある)。
- **Q3 スプライトエディタの全体の描き直しの初回**: (a) このまま (推奨。開いた直後に絵の全体と色の 256 点を送る分。なぞる間・なぞり終えは速くなった) / (b) 色の升目を前の作り (配置ごとに描画側で描く) に戻す。
