# P1 報告: 描画側と線の形 (透明・拡大と縮小・画素からスプライトの絵)

> 状態: 完了 (検収待ち) | 更新: 2026-11-21 | 2 つの描画側 (graphics-audio と display_local) で PNG の透明を 0x01 に、拡大と縮小して描く命令 `DRAW_TILE_SCALED`、画素からスプライトの絵を作る命令 `SPRITE_IMAGE_DATA`、境界 `draw_tile_scaled_raw`・`write_sprite_image`、包み `draw_tile(scale:)`・`SpriteImage#write_pixels`、sig。link 7・GA 3.2.0。内蔵 RAM の増分 0。Retro は S3 と WROVER の焼き直しが要る。指示書は instruction_p1.md

## 0. 要点

- **透明**: 2 つの描画側とも、スプライトの絵へ読む PNG を LovyanGFX の pngle に自前の受け口を渡して解き、α < 128 と tRNS を `0x01` にする。決まりは `fmrb_png332.h` の inline 関数 (`fmrb_png332_from_argb`) 1 つで、アプリの側の `png332.c` もそれを使う。pngle を回す所も 1 つのヘッダ (`fmrb_png332_pngle.h`、ヘッダだけ) で、graphics-audio は隣の fmruby-core の include を足して読む (写しなし)。
- **ホストの試験**: `rake png332:test` に描画側の読み手 (pngle + 決まり) を足した。flash/ の PNG 110 枚と α・tRNS の 5 枚 (RGBA・灰色+α・パレットの tRNS・灰色の tRNS・RGB の tRNS) の全部で、アプリの側の `BMP332.load` と 1 バイトも違わない (p0 10 章の「灰色・RGB の tRNS の点が α 0 で来るか」はこれで確かめた: 来る)。
- **拡大と縮小**: 新しい命令 `DRAW_TILE_SCALED` (0x8E)。scale 1〜32 は 1 点を scale x scale に、-2〜-32 は 1/|scale| (升の左上の 1 点)。切り抜きの矩形つき。行ごとの同じ色の連なりを 1 回の `fillRect` にし、透明色は飛ばす。今の `DRAW_TILE` と `draw_tile_raw` は変えていない。
- **画素から**: 新しい命令 `SPRITE_IMAGE_DATA` (0x42)。境界 `write_sprite_image` が 128 バイトずつに分け、**host の列を通す** (描く命令と順序が保たれる)。P4 系は 332 → 565 を `LOAD_SPRITE_IMAGE_BMP` の BMP と同じ `drawPixel` で変換。
- **版**: link 6 → 7、GA 3.1.0 → 3.2.0 (core の `fmrb.h`・`fmrb_link_version.h`、graphics-audio の `fmrb_ga_version.h`)。`rake wire:check` は通る。
- **sim の Modern・Retro、ブラウザ版、ネイティブ版で同じ絵**。graphics-audio の経路 (sim) と display_local の経路 (ネイティブ版・ブラウザ版) の画面の写しは、色の深さの違い (RGB332 と RGB565 の広げ方、1 チャンネル 3 段まで) を除いて 0 点の差。
- **内蔵 RAM は増えていない** (S3・P4・WROVER とも 0。同じ HEAD で変更の有無を作り比べた)。ファームは S3 +4,912 B、P4 (TAB5) +5,488 B、WROVER +1,548 B。

### 2.4 内蔵 RAM・ファームの大きさ・時間 (条件 4)

`rake regress:size` の基準 (4e7e7e61) は古く、差に P1 より前の変更が混ざるので、**同じ HEAD で変更を退避したビルドと比べた**。

|---|---|---|---|---|

- 実行時の山: PNG を読む間、pngle の作業領域 (44 KB、素の malloc なので内蔵 RAM) を取って返す。LovyanGFX の `drawPng` が持ち続ける同じ大きさの領域を先に `releasePngMemory()` で離すので、2 つ同時には持たない (山は今の `drawPng` と同じ)。スプライトの PNG を読んだ後は LovyanGFX の領域が離れたままになり、次の `drawPng` (`create_image`・起動画面) で作り直される。実機の `IRAM free:` では確かめていない。

## 4. p0 の案から変えた所

- **`SPRITE_IMAGE_DATA` は host の列を通す** (p0 4.2 の推奨どおり)。そのため 1 回の画素は p0 の 220 B ではなく **128 B** (列の 1 項 `gfx_cmd_t` を大きくしないため。文字の命令の 128 B と同じ枠に収め、assert で止める)。48x48 は 24 回 (幅 48 は 2 行ずつ)。Retro の UART では 1 回 140 B 前後なので 3.4 KB 前後 (p0 の見立て 2.3 KB より多い)。
- **scale は `int8`** (p0 の構造体は `uint8 scale` だった)。縮小を負の値で表すため (Q3 で縮小を入れると決まった)。縮小は升の左上の 1 点を取り、大きさは切り上げ (`ceil(w / |scale|)`)。0 と -1 は 1。範囲の外 (33 以上、-33 以下) は境界が ERR_ARG。
- **切り抜きの座標は原点から** (ほかの座標と同じ。描き手の原点を足して送る)。
- **包みの `draw_tile` には `scale:` だけ**を足した (`clip:` は無し。切り抜きは `draw_tile_scaled_raw` で。P3 の `draw_picture` もこちらを使う見込み)。
- **`picture_info` (境界) は入れていない**。p0 9.1 は P1 に数えていたが、指示書の作るものに無く、線の形も変えないので P2 (`BMP332.info` と同じ C) に回すのがよい (7 章)。
- PNG を解く所は p0 の「受け口を各描画側に 40〜50 行」ではなく、**ヘッダ 1 つ (`fmrb_png332_pngle.h`) を両方が読む**形にした (受け口の写しも作らないため。ホストの試験もそれを組む)。pngle の作業領域は呼ぶたびに取って返し、先に LovyanGFX の分を離す (2.4)。
- 描画側ごとの `DRAW_TILE` の違いをそのまま引き継いだ: display_local は描く先がスプライトの絵 (`set_target`) ならそこへ、graphics-audio は常に canvas へ描く。`DRAW_TILE_SCALED` も各描画側の `DRAW_TILE` と同じにした (7 章 Q3)。

## 5. 気づいたこと

- `FMRB_ABI_HASH` (SDK のヘッダ) は関数を足すたびに変わる。ファームは照らしていない (定義だけ) ので、今の C・wasm のアプリはそのまま動く。今までの足し方と同じ。
- graphics-audio の WROVER の storage の像に、sim の残り (`flash/cache`・`flash/home`) が入る (2.5)。ESP32 で作る前に除くか、像から外す仕組みがあるとよい (今回は触っていない)。
- 境界の道具・Spinel の FFI・MicroPython・Lua は、受け手 + 12 引数の関数を問題なく生成・ビルドできた (p0 10 章の疑問)。

## 6. 確認していないこと

- 実機 (Retro の S3+WROVER、P4)。焼いていない。WROVER の実時間、UART での `SPRITE_IMAGE_DATA` の時間、PNG を読むときの内蔵 RAM の空き (44 KB を取れるか。今の `drawPng` と同じ条件)。
- Spinel の基底の `draw_tile(scale:)`・`write_sprite_image` は**ビルドが通ったところまで** (Spinel で書いたアプリから呼んでいない)。Lua・MicroPython・wasm のアプリからも呼んでいない (生成されたつなぎがビルドに入ったところまで)。
- チャットのスタンプ・App Store・画像ビューワーの中身の画面 (2.2)。
- 古い graphics-audio と組み合わせて止まる所 (2.3、コードを読んだだけ)。
- インターレースの PNG (pngle は扱う。試験の絵には無い)。

## 7. 決めてほしいこと (先頭が推奨)

- **Q1 透明な点に書く値**: (a) いつも 0x01 (今の作り。アプリの側の `BMP332.load` と同じ) / (b) 絵が透明色を持っていれば (use_transparent) その色、無ければ 0x01 (`transparent_color: 0` の絵に α の PNG を読んでも抜ける。ただしアプリの側の読み方と食い違う)。
- **Q2 `picture_info` (境界)**: (a) P2 で `BMP332.info` と同じ C を使って足す / (b) P3 の置き場と一緒に。
- **Q3 `DRAW_TILE` の描く先の違い** (display_local は `set_target` の絵へ、graphics-audio は canvas へ): (a) 今は記録だけ (今のアプリに当たる所が無い) / (b) どちらかにそろえる (別の段で)。
- **Q4 `draw_tile` の包みの切り抜き**: (a) 足さない (`draw_tile_scaled_raw` で) / (b) `clip: [x, y, w, h]` を足す。
