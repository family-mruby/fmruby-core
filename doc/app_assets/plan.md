# アプリの asset を引き連れて運ぶ

> 状態: 構想 | 更新: 2026-11-10 | `.app.toml` に使う asset (画像・音など) を宣言すると、`amove` (checkpoint) のときにそれも相手へ運び、相手で同じ姿のまま続ける。運ぶのは doc/asterism_file_transfer の仕組み (片・再送・SHA-256)、許可は受け手の checkpoint の許可。着手はユーザの指示で

## 目的

- 動いているアプリを別の端末へ移すとき (doc/checkpoint、Shell の `amove`)、今は Ruby のヒープだけが運ばれ、
  画像・音などのファイルは相手に同じものがある前提になっている (doc/checkpoint/movable_apps.md)。
- アバターのような、自分の絵を持って端末の間を渡り歩くアプリを、相手に何も用意しなくても動かせるようにする。

## 方針

1. **宣言は `.app.toml`**: 例 `assets = ["avatar.bmp", "sounds/*.wav"]` (アプリの置き場所からの相対、型も可)。
2. **運ぶのは移す前**: `amove` のとき、VM のイメージを運ぶ前に、宣言された asset を同じ受け口 (種類 checkpoint の
   続き) で送る。どれかが届かなければ移すのを断り、アプリは元の端末で動き続ける (今の「断ったら続ける」と同じ)。
3. **同じものは送らない**: SHA-256 で比べ、相手が同じ中身を持っていれば送らない (2 回目からの移動を軽く)。
4. **アプリは置き場所を書かない**: `asset_path("avatar.bmp")` のような口で引く。元の端末ではアプリの横、
   移った先では受け手が決めた置き場所を返す。
5. **許可と上限は受け手が決める**: 受け手の checkpoint の許可 (receive.toml・console の一覧) をそのまま使う。
   大きさの上限と空きは T2・T3 の `begin` の断りと同じ形。

## 受け入れ条件

- 相手の端末に何も置いていない状態で、asset を持つアプリが `amove` で移り、同じ絵・音で続く (ネイティブ版どうし・ブラウザ版・ESP32)。
- asset のどれかが受け手に断られたら、アプリは移らず元の端末で続け、理由が返る。
- 同じアプリを 2 回目に移すとき、同じ中身の asset は送られない (ログで確認)。
- 内蔵 RAM の増分 0。

## 未確定事項

- 受け手の置き場所 (アプリごとの場所の名前、`/tmp` か `/home` か SD か) と、使い終わった asset をいつ消すか。
- 大きさの上限 (1 つ・全体)。相手の空きが足りないときの扱い。
- 宣言の無いアプリ (今のアプリ) の扱いは今のまま (asset を運ばない) でよいか。
- asset を宣言したアプリが元の端末に戻るとき、元の場所のファイルを使うか。
