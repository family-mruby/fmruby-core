# L4 指示書: キーボード専用のデスクトップ (320x170)

> 計画: doc/linux_native/plan.md (特に「キーボード専用のデスクトップ (keys)」
> 「全画面アプリの切り替え」「アプリの宣言」と、2026-10-26 のユーザ決定)。
> 前段の結果: report/l1.md 〜 l3c.md

## 目的

Cardputer Zero の本体の画面 (320x170) で、キーボードだけで使える
デスクトップを作る。開発と確認は WSL2 の SDL の窓 (320x170 を整数倍に拡大) で
行う。今の Modern・Retro のデスクトップ (mouse) の見た目と動きは変えない。

## ユーザの決定 (変えない)

- 画面の形: 上端に細い帯 (約 10px) を常に出し、今のアプリの名前・かなの
  状態・時計・電池を出す。残りの 320x160 をアプリに使う。アプリを選ぶ
  メニューも帯の下に全画面で出す。
- 切り替え: 決まったキーで切り替えの一覧を開く。動いているアプリと
  「アプリを起動」を並べ、矢印と Enter で選ぶ。終了もここからできる。
  キーの組は設定で変えられる (既定の組は下の「親の仮の決め」)。
- 最初に対応させるアプリ: エディタ・Shell・File Manager。

## 親の仮の決め (ユーザに確認中。変えやすく作る)

- 一覧を開くキーの既定: `Ctrl+Tab`。system_conf の項目で変えられる。
- Esc: 短押しはアプリへ渡す (アプリの「戻る」)。**長押し (約 1 秒) はデスク
  トップが受け、アプリの中ならそのアプリを閉じてメニューへ戻る。メニューで
  の長押しは Family mruby を終える** (APPLaunch へ戻る)。押した・離したで
  判断し、キーの繰り返しに頼らない。長押しの時間は設定で変えられる。
- 電池: native ではまだ値が無い (L6)。帯には値が無いときは何も出さない。

## 作業の内容

### 1. 画面の形 320x170

- native の基本の画面を、機種の定義の `screen.form` から 320x170 にできるようにする
  (display_local の画面の大きさ、kernel が知る画面の大きさ、入力の座標)。
  全画面の高解像度モード (640x360) は、基本の画面が 426x240 のときだけの
  ままにする。
- `cardputer_zero` の定義は 320x170 を断らなくする。開発用に
  `sdl_keys` (SDL・320x170・keys・倍率 4 など) の定義を足す。

### 2. デスクトップの作り分け

- system_desktop を、共通の部分 (i18n・設定とダイアログ・ファイル選択・
  ショートカット・テーマ・起動時のアプリ情報・かなの状態) と、作り分ける
  部分 (画面の枠・アプリの選び方・窓の扱い) に分ける。mouse は今の
  デスクトップそのもの、keys は新しく作る。
- どちらを使うかは機種の定義の `desktop.variant` で決まる。kernel・desktop に
  どう伝えるかは既存の設定の渡し方に合わせる。
- **mouse の見た目と動きは変えない** (回帰の画面が画素で同じであること)。
  共通化のために mouse の中を直すのはよいが、直した後も同じに動くこと。

### 3. keys のデスクトップ

- 上端の帯 (約 10px): 今のアプリの名前、かなの状態 (クリックで巡回する今の
  指示器と同じ状態を、キーで切り替えられる)、時計、電池 (値があれば)。
- メニュー (帯の下に全画面): 「320x170 に対応し、マウスの要らない」アプリと、
  File Manager を並べる。矢印・Enter で起動。
- File Manager は keys では帯の下に全画面で出す (今のデスクトップの部品を
  使う。キー操作は今のものを使う)。
- 切り替えの一覧 (上の決め)。
- アプリは常に全画面 (帯の下の 320x160) で起動する。

### 4. 全画面のアプリを複数持つ

- kernel の全画面のアプリは、今は退避できる枠が 1 つ
  (`@parked_fullscreen_pid`) と、入れ子の枠の積み重ね (`@fs_stack`)。keys では
  「全画面のアプリが複数動いていて、一覧から選んで前に出す」形が要る。
  退避の枠を一覧に広げるなど、kernel の作りを読んで形を決める。
- mouse での今の動き (Ctrl+Tab の退避と復帰、入れ子の全画面、
  `fullscreen_switchable` の制限) は**変えない**。keys のときだけ広がる形でもよい。
  どちらにしたかと理由を report に書く。
- kernel の Ruby を変えたら Spinel の生成物を作り直す (`rake spinel:gen` 相当)。
  標準の構成 (Spinel のカーネル) と全部 mruby の構成の両方で確かめる。

### 5. アプリの宣言とアプリの対応

- アプリが「320x170 に対応する」「マウスが要る」を宣言する欄を足す
  (flash のアプリは `.app.toml`、組み込みのアプリは今その属性を持っている所
  = spawner の表などに合わせる)。宣言の無いアプリは keys のメニューに出さない。
- エディタと Shell を 320x160 の全画面に対応させる (文字の大きさは、今の
  エディタのフォント 8/12/16 から選ぶ。日本語の表示を含めて読めること)。
  2 つの宣言を入れる。
- 既存のアプリの mouse での見た目と動きは変えない。

## 作業場所と git

- 本体の checkout、両リポジトリとも `feature/linux-native` に続けてコミット
  (規約は fmruby-core/CLAUDE.md、Co-Authored-By、`git add` は明示)。
  develop へのマージと push はしない。
- `build/` は ESP32-P4 のビルド。自分で `rake clean_all` はしない。kernel や
  default_app の生成物を作り直すのに必要なら、回帰の道具の作り直しの範囲で
  済むか確かめ、済まなければ止まる。

## 受け入れ条件

1. `--machine sdl_keys` でヘッドレス起動し、320x170 の画面に帯とメニューが出る。
2. メニューからエディタを起動すると、帯の下の 320x160 の全画面に出る。1 打鍵が
   出る。Shell も同じ。File Manager も帯の下の全画面に出て、キーで操作できる。
3. エディタと Shell を両方起動し、切り替えの一覧で行き来できる。一覧から
   片方を終えられる。
4. Esc の長押しで、アプリの中ではアプリが閉じてメニューへ、メニューでは
   Family mruby が終わる (プロセスが終わる)。短押しはアプリに届く。
5. かなの状態をキーで切り替えられ、帯に出る。
6. 標準の構成と全部 mruby の構成の両方で 1〜4 が通る。
7. 回帰: `rake regress`、`rake regress:screens` が通る (mouse の Modern・Retro・
   ブラウザ版・native の基準が変わらない)。keys の場面 (メニュー・エディタの
   1 打鍵・切り替えの一覧) を回帰の画面に足し、基準を作る (作ったことを
   report に書く)。`rake regress:size` で端末の内蔵 RAM が増えていない
   (kernel・desktop を触るので)。

## 大きすぎるときの分け方

L4a (1・2・3 と、kernel の全画面の一覧、エディタだけの対応) で一度 report を
書いて返してよい。その場合は Shell の対応と回帰の keys の場面を L4b とする。

## 止まる条件

- mouse・端末・sim・ブラウザ版の見た目や動きが変わる直し方を選ぶ必要が
  出たとき (回帰の基準の更新が要るとき)。
- kernel の全画面の作りが、keys の形を入れると mouse の動きを保てないと
  分かったとき。
- `rake clean_all` が要るとき、sudo が要るとき。
- 親の仮の決め (キーの既定・Esc の長押し) が、作りの上で成り立たないとき。
- 止まったら report に状況を書いて返す。

## report (doc/linux_native/report/l4.md、分けたら l4a.md・l4b.md) に書くこと

- デスクトップの分け方 (どのファイルが共通・mouse・keys か)
- 全画面のアプリの一覧の作り (kernel の変更と、mouse の動きを保った方法)
- 宣言の欄の名前と置き場所、対応させたアプリ
- 帯・メニュー・切り替えの一覧・Esc の長押しの作り、設定の項目名
- 受け入れ条件ごとの結果と、確かめたコマンド・数値 (内蔵 RAM の差を含む)
- 作った回帰の基準と場所
- 見立てと違った点、撤回した仮説、踏んだ罠、残件 (L5 へ渡すもの)
