# L9d 指示書: 画面を 2 倍で埋める、Linux の窓の角を透かす、Linux の印、配列を Linux に合わせる

> 計画: doc/linux_native/plan.md (段取りの L9、「後で直すもの」)。
> 前段の結果: report/l9a.md (代役と穴の作り、四隅の 3 画素の残件)、
> report/l9b.md (ランチャーの「Linux」の区分とアイコン)、report/l9c.md

## 経緯 (2026-10-27、ユーザの VirtualBox の Kubuntu 26.04 での確認から)

- 1280x800 の画面に 426x240 を 3 倍 (1278x720) で置き、上下に 40 画素ずつ黒い
  帯が出ている。
- 代役の枠の四隅の外側 (角丸の外) が透けず、壁紙の地の色で塗られている。
- 一覧の Linux のアプリの共通の印が「L」の字、「Linux」の区分の印が無地の
  四角で、寂しい。

## ユーザの決定 (2026-10-27、変えない)

- **画面**: コンポジタの機種 (`linux_pc_wl`) では、倍率を 2 にし、Family mruby の
  画面を「出力 ÷ 2」の大きさにして出力を埋める (1280x800 なら 640x400、
  1920x1080 なら 960x540)。黒い帯を無くす。倍率は設定で変えられる。
- **角丸**: Linux の窓の枠の四隅の外側も、普通の窓と同じく後ろが透けて見える。
- **キーボードの配列**: Linux の機種では、利用者が Family mruby の Config で
  配列を選んでいなければ、Linux の配列 (Kubuntu の設定) に自動で合わせる。
  jp なら jp、それ以外なら us。Config で選んだときはそれが勝つ。
- **印**: 「Linux」の区分の印は**自分で描いた小さなペンギン** (Tux の写しでは
  なく、Family mruby のほかの印と同じ筆致)。各 Linux のアプリの共通の印
  (アイコンが無いもの) は**窓の絵**にする。

## 作業の内容

### 1. 画面を出力 ÷ 倍率の大きさにする

- 機種の定義に、Family mruby の画面の大きさを「出力 ÷ 倍率」で決める指定を
  足す (例: `[screen] form = "output"`、`[display] scale = 2`)。`linux_pc_wl` を
  これにする。ほかの機種 (sdl・keys・cardputer・`linux_pc`) と端末・sim・
  ブラウザ版は今のまま。
- 出力の大きさが割り切れないときの余り (奇数の画素) は黒でよい。
- 先に読むこと: Family mruby の画面の大きさが 426x240 と 640x360 (高解像度の
  全画面) 以外になったとき、表示のタスク・kernel・デスクトップ・アプリが
  ついて来るか。デスクトップの並べ方 (メニューバー・タスクバー・アイコン・
  時計など) が広い画面で正しく並ぶか、大きさを決め打ちしている所が無いか。
  - 決め打ちを直すのに kernel・デスクトップの Ruby を変えてよい (標準と全部
    mruby の両方で確かめ、端末・sim・ブラウザ版の見た目が変わらないこと)。
  - 全画面のアプリ (426x240 の絵や 640x360 の高解像度) が上にいる間は、その
    絵を出力に収まる最大の整数倍で真ん中に置く (余りは黒)。
- 出力の大きさが変わるとき (入れ子の窓の大きさを変えた、`ROTATE` で縦長
  (例: 400x640) になった) にどうするかを決めて report に書く。縦長で
  デスクトップが崩れるなら、縦長のときは今の 426x240 に戻すなど、崩れない
  形にする (崩れずにできない場合は止まって返す)。
- Linux の窓の置き場所と大きさ (中身の矩形 × 倍率) は、倍率が 2 でも本来の
  画素の細かさのまま。ポインタの座標も同じ。

### 2. 代役の四隅を透かす

- 今は「代役の中身の矩形の中で 0x01 のまま残った画素を穴にする」作りで、
  代役の canvas をキーなしで作るので四隅が透けない (report/l9a.md の 2 章)。
- 四隅の外側が普通の窓と同じに透け、しかも前後関係 (Family mruby の窓・
  メニュー・ダイアログが上に重なれば Linux の窓が隠れる) が今どおりに保たれる
  作りを、表示の受け渡しの作りを読んで選び、report に理由を書く。
  候補の例: 代役の canvas もキーつきで作り、中身だけ別の決まった色で塗る
  (その色を見える色に使っていないかを確かめる)、表示の合成で canvas の一部
  (中身) だけキーを効かせない、など。
- 端末・sim・ブラウザ版の表示の動きと内蔵 RAM を変えない。表示のタスク
  (端末と共通) を変えないとできない場合は、止まって返す。

### 3. 印

- 「Linux」の区分の印: 小さなペンギン。ランチャーのほかの印の大きさ・色数・
  筆致に合わせる (今の印を見て合わせる)。
- アイコンの無い Linux のアプリの共通の印: 窓の絵 (題の帯と枠のある四角)。
- 置き場所: 配ってよい絵なので `flash/` の印の置き場所に BMP として置くか、
  L9b のように実行時に描くかを選び、report に書く。`flash/` に置くなら、
  native とコンテナの像に入ることを確かめる。

### 4. キーボードの配列を Linux の設定に合わせる

- Linux の配列は、システムの設定 (`/etc/default/keyboard` の `XKBLAYOUT`、
  `localectl` が書くもの。`dpkg-reconfigure keyboard-configuration` で変わる) を
  読む。Plasma の利用者ごとの配列の設定 (kxkbrc) も読むべきかを調べ、report に
  書く。
- 「利用者が選んでいない」をどう表すか (Config の `keyboard_layout` に `auto` を
  足して Linux の機種の既定にする、など) を作りを読んで選び、report に書く。
  端末・sim・ブラウザ版の Config の選択肢と既定は変えない (`auto` を出すのは
  Linux の機種だけ)。
- 合わせた結果は Family mruby のキーの表と、Linux の窓の keymap (L9a) の両方に
  効くこと。どの配列に決めたかをログに 1 行出す。

## 作業場所と git

- 本体の checkout、fmruby-core の `feature/linux-native` に続けてコミット
  (規約は fmruby-core/CLAUDE.md、Co-Authored-By、`git add` は明示)。
  develop へのマージと push はしない。
- `build/` は今 NARYAv4 (ESP32-P4) のビルド。自分で `rake clean_all` はしない。
- sudo は使わない。HOME・XDG_DATA_HOME は一時ディレクトリ。WSLg に窓を出し
  っぱなしにしない。開いたままのブラウザ (wasm の道具) は閉じない。
- kernel・デスクトップの Ruby を変えたら、標準 (Spinel のカーネル) と全部
  mruby の両方で確かめる。Spinel の罠 (型が絞れない呼び出しで黙って 0、
  mixin の素の定数) に注意。

## 受け入れ条件

1. `linux_pc_wl` を 1280x800 の出力 (headless) で起こすと、Family mruby の画面が
   640x400 で、2 倍で出力をちょうど埋める (grim の画面で黒い帯が無い)。
   1920x1080 では 960x540。デスクトップのメニューバー・タスクバー・アイコン・
   時計が広い画面で正しく並ぶ (画面を report に)。
2. エディタ・Shell・File Manager・ランチャーが 640x400 で開き、エディタは
   1 打鍵まで通る。全画面のアプリ (例: shooter) と高解像度の全画面のアプリは、
   出力に収まる最大の整数倍で真ん中に出る。
3. L9a・L9b・L9c の確認 (`rake regress:wl`) が、新しい大きさで通る (基準や
   座標の決め打ちを直す)。Linux の窓は本来の画素の細かさで出る。
4. 代役の四隅の外側に後ろの物 (壁紙・後ろの窓) が見え、前後の確認 (エディタ・
   メニュー・確認のダイアログを重ねたときに穴以外が絵と 0 画素差) が今どおり。
5. 「Linux」の区分にペンギンの印、アイコンの無い Linux のアプリに窓の印が出る
   (画面を report に)。
6. `rake regress`、`rake regress:screens`、`rake regress:size` (内蔵 RAM +0) が
   通る。端末・sim・ブラウザ版の画面の基準が変わらない (変わったら変化を
   report に書き、基準の更新は別のコミットに)。`rake native:test`、amd64 と
   arm64 の deb_check が通る。
7. 1・2・4 を標準と全部 mruby の両方で、pixman で。
8. 一時の場所に置いた偽の `/etc/default/keyboard` (`XKBLAYOUT="jp"`) で起こすと、
   Config で選んでいないとき Family mruby と Linux の窓 (foot) の配列が jp になる
   (jp の記号が配列どおりに入る)。`us` なら us。Config で us を選ぶと、Linux が
   jp でも us になる。端末・sim の Config の選択肢は今のまま。

## 止まる条件

- 上の決定と食い違う作りが要るとき。
- 表示のタスク (端末と共通) や端末・sim・ブラウザ版の動きを変えないと
  できないとき、内蔵 RAM が増える作りしか無いとき。
- 広い画面にデスクトップやアプリがついて来られず、直すと利用者から見た
  動きが端末で変わるとき。
- `rake clean_all` や sudo が要るとき。
- 止まったら report に状況を書いて返す。

- 印の描き方と置き場所
- 配列の読み方と「選んでいない」の表し方
- 受け入れ条件ごとの結果と、確かめたコマンド・数値 (内蔵 RAM・flash の差)、
  画面
