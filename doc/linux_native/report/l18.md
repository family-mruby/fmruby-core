## セッションの機種の見分け方

新しい設定項目は足していない。すでにある `FmrbApp.power_actions` に **`:power_off` が
あるか**で決める。

- Linux の `linux_power_actions` (native/sys/platform_sys_linux.c) は、機種の定義の
  `system.power` に `logind` があるときだけ Power off・Restart・Suspend を立てる。
  ESP32 の端末・sim・ブラウザ版は Power off を出さない。よって「Power off がある」=
  「logind の項目がある」= ログインのセッションとして動く機種。
- 今の機種の定義では `linux_pc`・`linux_pc_wl` (`["logind", "exit"]`) が該当。
  `linux_pc_drm` は `logind` だけで Exit が無いので、表示は変わらない (Exit の項目自体が無い)。
  `sdl`・`sdl_keys`・`cardputer_zero`・`cardputer_zero_hdmi` は `exit` だけで今のまま。
- アプリの側 (Ruby) で決めたので、C と FFI には手を入れていない。

## 変えた画面

| 所 | 変更 |
|---|---|
| `system_desktop.app.rb` | `login_session?(FmrbApp.power_actions)` で `POWER_EXIT_KEY` を `:power_logout` か `:power_exit` に。`POWER_KEYS` の exit がこれを使い、確認の文は `:"#{key}_confirm"` で `power_logout_confirm` になる。項目を押したときの分岐に `:power_logout` を足した (働きは `:power_exit` と同じ: 確認 → `do_power` の `exit`) |
| `system_desktop_keys.app.rb` | 同じ判定で `POWER_LABELS` の exit を `:power_logout` に。keys の Exit は今も確認なしですぐ終わる (L6 の決まりのまま)。よって keys では「ログアウト」の項目名だけが変わり、確認の文は出ない |
| `system_desktop/i18n.rb` | en `power_logout: "Log Out"`・`power_logout_confirm: "Log out?"`、ja 「ログアウト」・「ログアウトしますか?」 |

`login_session?` は `include?` を使わず while で回した (picoruby の `include?` の重さと、
Spinel で型の絞れない呼び出しを避けるため。起動時に 1 回だけ)。

## CRT の既定 (見た目は変わらない)

`native_machine_defaults` の 55・30・30・15・40・0・0・0 を、
`static const int crt_standard[8] = { CRT_PRESET_STANDARD };` から入れる形にした。
include は `"../../hosted/crt/crt_presets.h"` (相対)。`rake native:test` は
native_machine.c を hosted/crt を include の道に持たずにコンパイルするので、
rakelib を触らずに済むようにこの形にした。

## 確認

- `rake regress`: host 21/21、描画の記録 213/213。
- `rake regress:wl`: standard・mruby とも全部通過 (wl_check 27・apps 10・dialogs 11・keys 3・
  open 5・clip 5・ime 7・winops 11・settings 20・size 5・touch 7)。power_exit を押す場面は
  座標が同じなので試験は変えずに通った。`wl_settings_check` の「Exit がセッションを終える」も通過。
- `rake regress:screens`: 33/33 (retro 9、modern 11、web 6、native 3、native-keys 4)。
  **基準の更新なし** (どの場面も電源のメニューを撮っていない)。
- headless の目視 (撮った画を読んだ):
  - `linux_pc_wl` 英語 (wl_check の `exit_question.png`): 確認が "Log out?"。
  - `linux_pc_wl` 日本語 (wl_apps_check に足した `power_menu_ja.png`・`logout_question_ja.png`、
    撮影を足した後に `wl_apps_check` standard を単独でもう一度流して 10/10): メニューの先頭が
    「ログアウト」、続いて電源を切る・再起動・休止・ロック。確認が「ログアウトしますか?」。
  - `sdl` (tools/fmrb_native.rb、headless): 英語で項目 "Exit"・確認 "Exit Family mruby?"、
    日本語で「終了」・「Family mruby を終了しますか?」(今のまま)。
  - `sdl_keys` 英語: 一覧の最後が "Exit" (今のまま)。`sdl_keys` に
    `--set system.power=logind,exit --set system.power_log_only=true` で日本語: 一覧の最後が
    「ログアウト・電源を切る・再起動・休止」(keys の判定の確認。電源の項目は押していない)。
  - 英語のメニューの "Log Out" の項目そのものは撮っていない (確認の文が出るのは同じ鍵から)。

## ユーザに見てほしいこと (GPD、ログインし直してから)

1. 右上の電源ボタンのメニューの先頭が「ログアウト」(英語なら "Log Out") になっている。
2. 押すと「ログアウトしますか?」、はいでログイン画面に戻る (今までの Exit と同じ)。

## 残件・親の判断

- keys のデスクトップの Exit は確認なしで終わる (L6 の決まり)。セッションの機種で keys の
  形を使うと「ログアウト」も確認なしになる。今そういう機種の定義は無いので変えていない。
- `wasm/vendor/` が追跡外のまま残っている (10/29 の物、この作業のものではない。触っていない)。
