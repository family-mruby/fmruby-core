# L14 報告: 毎日使う環境 (3) 設定と丈夫さ

> 状態: 完了 (受け入れ 9 点。VirtualBox の Kubuntu での確認、ブラウザ版の画面の比較、arm64 の .deb の作り直しは残件) | 更新: 2026-10-28 | 指示書は instruction_l14.md。ブランチは fmruby-core の feature/linux-native (develop へは未マージ・未 push)

コミット: 1999c103 (コードと試験と usage.md の 11 章)。この報告は別のコミット。基準の絵は更新していない。

## 1. 全体の形

| 機能 | 受け持つ所 | 使う口 | 効く機種 |
|---|---|---|---|
| Wi-Fi の一覧・つなぐ・切る | `native/sys/linux_net.{h,c}` (専用のスレッド) と設定の窓 `native/apps/linux_settings.app.rb` | NetworkManager の D-Bus (system bus) と、秘密の代理人 (secret agent) | 機種の定義の新しい欄 `system.settings = true` (sdl・linux_pc・linux_pc_drm・linux_pc_wl) |
| Bluetooth の入り切り・既知の機器のつなぐ・切る | `native/sys/linux_bt.{h,c}` (専用のスレッド) と同じ設定の窓 | BlueZ の D-Bus (system bus、ObjectManager・Adapter1・Device1) | 同上 |
| 音量・ミュート | `native/sys/sys_linux_pw.c` (専用のスレッド) | `wpctl` (PipeWire)、無ければ `pactl` (PulseAudio と pipewire-pulse) | 同上。どちらも答えなければ今までどおり ALSA の mixer か中の音量 |
| 音量のキー | `native/backend/input_native.c` (ネイティブ版の入力の口) と `native/wlr/output_wlr.c` (コンポジタではいつも Family mruby へ) | HID の 0x7F・0x80・0x81 (KEY_MUTE・KEY_VOLUMEUP・KEY_VOLUMEDOWN) | ネイティブ版の全部の機種 (知らせは `system.settings` のときだけ) |
| 通知 | `native/sys/linux_notify.{h,c}` (知らせの置き場と、session bus の freedesktop の口) と、デスクトップの `system_desktop/notices.rb` | `org.freedesktop.Notifications` | `system.settings` の機種。名前を他のプログラムが持っていれば (GNOME の上の SDL の窓など) Linux の通知は受けず、Family mruby のアプリの知らせだけ出す |
| 画面の共有と録画 | コンポジタ (`ext-image-copy-capture-v1` を足した) と、包みの `family-mruby-portals.conf`・xdg-desktop-portal-wlr の設定、session の台本 | xdg-desktop-portal と xdg-desktop-portal-wlr | コンポジタ (`linux_pc_wl`) |
| 落ちたときの復帰 | `native/package/family-mruby-session` | 台本が子として起こして終わり方を見る | ログイン画面の入口 |

- 端末・sim・ブラウザ版: `fmrb_platform_sys` の表に 10 の口 (`wifi_list`・`wifi_connect`・`wifi_disconnect`・`bt_list`・`bt_power`・`bt_connect`・`notice_gen`・`notice_list`・`notice_post`・`notice_dismiss`) を足した。既定の表 (`static const`) では NULL なので、呼ぶ側の短い関数が -1・`FMRB_ERR_NOT_SUPPORTED` を返す (「使えない」)。表は flash に置かれ、内蔵 RAM は増えない。
- Ruby の口は `FmrbApp.wifi_networks`・`wifi_connect`・`wifi_disconnect`・`bt_devices`・`bt_power`・`bt_connect`・`notices_gen`・`notices`・`notice_dismiss`・`notify` (全部の機種にあり、端末では "" か false か -1)。設定の窓を開く `FmrbApp.linux_settings`・`settings_page` はネイティブ版にだけある (L9a の `wl_window` と同じ扱い)。sig には利用者のアプリが使う `FmrbApp.notify` だけ書いた。
- デスクトップの Ruby は、端末でも同じ bytecode が入る所なので、最初に 1 回だけ聞いて「無い」なら何もしない形にした: メニューの Bluetooth は `FmrbApp.bt_devices != ""` のときだけ、ネットワークのダイアログの「Wi-Fi の設定...」は `FmrbApp.wifi_networks != ""` のときだけ、知らせは起動の後の最初の更新で `notices_gen` が -1 なら以後は呼ばない。

### D-Bus の使い方と待たない作り

- sd-bus (libsystemd) を実行時に開く形は L6・L13 と同じ。呼ぶ関数を 1 か所にまとめた (`native/sys/linux_bus.{h,c}`: 44 の関数を `dlsym`)。ビルドに開発用のヘッダは要らない。
- NetworkManager・BlueZ・通知の口はそれぞれ自分のスレッドと自分の bus の接続を持つ (sd-bus の接続はスレッドをまたいで使えない)。スレッドは FreeRTOS の外で、bus の fd と起こし用の eventfd を `poll` で待つ (回り続けない)。
- FreeRTOS の側 (デスクトップ・設定の窓のタスク) が呼ぶ口は、錠を短く持って写すか頼みを積むだけで、待たない。協調の作り (L2n) なので、錠を持ったまま他のタスクに切り替わることはない。
- 一覧は「頼まれて、前に読んでから 3 秒 (Bluetooth は 2 秒) 経っていたら」読み直す。設定の窓は 1 秒ごとに文字列を読み、変わったときだけ描き直す。窓が閉じていればスレッドは眠ったまま。Wi-Fi と Bluetooth のスレッドは設定の窓 (かデスクトップの起動時の 1 回の問い) で初めて起きる。
- 音量はツールを動かすしかない (PipeWire・PulseAudio に音量の D-Bus の口が無く、ライブラリは 2 つの値のためには大きい) ので、ツールを走らせるのは専用のスレッドだけ。値は最後に分かったものを返し、2 秒より古ければ読み直しを頼む。変えた値はその場で返す値に入り、少し後にツールで OS に届く。起動の時だけ、どちらのツールが答えるかを 1 回走らせて決める (kernel が上がる前。サーバが固まっていてもツールごと 1.5 秒で切る)。

## 2. Wi-Fi

- ネットワークのダイアログ (L6 の表示だけのもの) に「Wi-Fi の設定...」のボタンを足し、押すと設定の窓の Wi-Fi の頁が開く。窓は 280x200 で、ネイティブ版の中に組み込んだアプリ (`native/apps/linux_settings.app.rb`、`rake native:mrb` が bytecode にし、ネイティブ版だけが持つ。端末・sim・ブラウザ版のファームには入らない)。
- 一覧: 最初の Wi-Fi の装置 (`GetDevices` の `DeviceType` が 2) の `GetAllAccessPoints`。同じ SSID は一番強いものだけ、隠れた (SSID の無い) ものは出さない。並びはつながっているもの、強さ、名前の順。強さは 4 本の棒、鍵の印、保存済みなら「保存」。「探す」で `RequestScan` を頼み、4 秒後に読み直す。
- つなぐ:
  - 保存済み (`Settings.ListConnections` の `GetSettings` で SSID が同じもの、30 秒ごとと試みの後に読み直す) は `ActivateConnection`。
  - 新しいものは `AddAndActivateConnection` に SSID とパスワード (`wpa-psk`、WPA3 だけのものは `sae`) を渡す。NetworkManager がそれを自分の道具で作ったものと同じように持つ。試みが失敗したら、その時に作った接続を消す (自分で作ったものだけ)。802.1X (会社の Wi-Fi) と WEP は作らず「Linux で設定してください」と出す。
  - 秘密の代理人 (SecretAgent): 保存済みでもパスワードを NetworkManager が持たないもの (Plasma が自分の財布に入れたもの、変わったもの) は NetworkManager が代理人に聞く。プログラムは `/org/freedesktop/NetworkManager/SecretAgent` で答え、今の試みに利用者が打ったパスワードがあればそれを、無ければ「無い」(NoSecrets) を返す。窓は「パスワードを入れてください」と出して欄を出す。
  - 状態は 0.4 秒ごとに `Connection.Active.State` を見る。2 (activated) でつながった、4 (deactivated) か 45 秒で失敗。失敗の理由は装置の `StateReason` (7 秘密が無い、8〜11 supplicant、53 SSID が無い) から「パスワードが要る」「パスワードが違うようです」「見つかりません」「つなげませんでした」に分ける。
- パスワード: 窓の欄は「*」で出す。「つなぐ」で C へ渡したら窓の変数から消す。C 側は試みが終わったら `explicit_bzero` で消す。ログには出さない (つなぐ頼みは「with a password」とだけ書く)。保存は NetworkManager だけがする。Ruby の文字列が GC されるまで VM のヒープに残るのは防げない (残件)。
- 切る: 装置の `Disconnect` (接続は保存されたまま)。
- 選択は名前で覚える (つながったものが一番上に移っても、選んだネットワークのまま)。

## 3. Bluetooth

- メニューの「Bluetooth」(端末・sim・ブラウザ版には出ない) で設定の窓の Bluetooth の頁が開く (開いていれば頁が変わって前に出る)。
- `ObjectManager.GetManagedObjects` で最初の adapter の `Powered` と、その adapter の機器のうち `Paired`・`Bonded`・`Trusted` のどれかが真のもの (既知の機器) を出す。つながっているものが上、印は塗った丸。
- 入り切りは `Adapter1.Powered` を書く。つなぐ・切るは `Device1.Connect`・`Disconnect` (数秒かかるので専用のスレッドが待つ。その間は「操作しています...」)。失敗は BlueZ の理由のまま出す (`org.bluez.Error.Failed: br-connection-page-timeout` など)。
- 新しい機器のペアリングはしない。窓の下に「新しい機器は Linux の bluetoothctl でペアリング」と 1 行。

## 4. 音量

- `system.settings` の機種では、起動の時に `wpctl get-volume @DEFAULT_AUDIO_SINK@`、だめなら `pactl get-sink-volume @DEFAULT_SINK@` を試し、答えた方で既定の出力の音量とミュートを動かす (`wpctl set-volume`・`set-mute`、`pactl set-sink-volume`・`set-sink-mute`)。音の出口 (SDL・ALSA) が何であっても OS の音量の方を動かす。
- どちらも答えなければ L6 のまま (ALSA の出力なら mixer、それ以外は中の音量)。ログに `native: volume: PipeWire (wpctl) on the default output` か `native: volume: no sound server (...)` が出る。
- 段は Family mruby の 0〜10。OS の 0.40 は 4 段。kernel から見ると L6 の mixer と同じ「OS が音量を持つ」形なので、デスクトップのミュートと Config の音量はそのまま OS の値を動かし、system_conf には書かない。
- 音量のキー: ネイティブ版の入力の口で受け、1 段上げ下げ・ミュートの切り替え (上げるとミュートも外す)。コンポジタでは Linux の窓がキーボードを持っていてもキーを Family mruby へ送る (Ctrl+Tab と同じ扱い)。PC では右上に「音量 70%」と棒の知らせを 2 秒出す (同じ知らせを差し替える)。

## 5. 通知

- `org.freedesktop.Notifications` を session bus で受け持つ (名前が空いているときだけ。`Notify`・`CloseNotification`・`GetCapabilities` は "body"・`GetServerInformation`・`NotificationClosed` の知らせ)。操作のボタン (actions) と hints は読み飛ばす。
- 知らせの置き場は C 側 (4 つまで、5 つ目で一番古いものが消える)。出す時間は、-1 (サーバ任せ) が 5 秒、0 (消さない) が 10 秒 (履歴を持たないので)、それ以外は 2〜10 秒に収める。
- デスクトップは 0.5 秒ごとの更新で置き場の世代を見て、変わったときだけ右上 (メニューバーの下) に新しいものを上にして描く。帯にアプリの名前、その下に要約、本文は 2 行まで (幅で折り返し、はみ出しは「..」)。デスクトップの前の層 (z=254) の合成の領域に足すので、アプリの窓の上に出る。コンポジタでは Linux の窓の上にも出る。
- Family mruby のアプリから: `FmrbApp.notify(summary, body)` (呼んだアプリの名前が帯に出る)。端末では false。

## 6. 画面の共有と録画 (portal)

- xdg-desktop-portal-wlr 0.8 は、出力の取り込みに `ext-image-copy-capture-v1` (と出力を源にする `ext-output-image-capture-source-v1`) か、wlr-screencopy と dmabuf を求める。pixman の描画 (VM) では dmabuf が無いので、コンポジタに前者を足した (wlroots 0.19 にある)。
- 包みに 2 つのファイルを足した: `/usr/share/xdg-desktop-portal/family-mruby-portals.conf` (ScreenCast と Screenshot は wlr、ほかは kde、無ければ gtk) と `/etc/xdg/xdg-desktop-portal-wlr/family-mruby` (`chooser_type=none`: 出力は 1 つなので聞かずにそれを渡す。slurp・wofi が要らない。conffile)。Recommends に xdg-desktop-portal-wlr を足した。
- session の環境: 台本が `XDG_CURRENT_DESKTOP=family-mruby` (ログイン画面が `.desktop` の DesktopNames から入れるもの。無ければ台本が入れる) と `XDG_SESSION_TYPE=wayland` を、起動の前に `dbus-update-activation-environment --systemd` で session のサービスに知らせる。コンポジタは Wayland の口ができてから `WAYLAND_DISPLAY` (と Xwayland の `DISPLAY`) を同じ道具で知らせる。これはコンソールの上 (ログイン画面の入口) で動くときだけ (他の机の中の入れ子では、その机の環境なので変えない)。確認では環境変数 `FMRB_COMPOSITOR_ACTIVATION_ENV=1` で動かす。
- 確かめた所: 入れ物の中で xdg-desktop-portal が D-Bus で起こされ、ScreenCast の CreateSession・SelectSources・Start・OpenPipeWireRemote が通り、PipeWire の流れ (1280x800) の番号と fd が返る (`clients/portal_cast.c`)。
- 確かめられない所 (理由): ブラウザの会議から実際に共有した絵が相手に届くこと (入れ物にブラウザも相手も無い)。Screenshot の portal は「問い」の実装 (Access) を KDE か GNOME の portal が持つので、入れ物では動かない (`The screenshot portal requires an access impl`)。Kubuntu には xdg-desktop-portal-kde があるので VM で確かめる。

## 7. 落ちたときの復帰

- 台本はプログラムを `exec` せず子として起こし、終わり方を見る:
  - 0 (Exit の項目、Config の Save & Reboot も同じ) なら台本も終わる (ログイン画面へ)。
  - SIGTERM・SIGHUP・SIGINT は「終えるよう頼まれた」(ログアウト、電源断、kill) として起こし直さない。台本自身が受けた SIGTERM などはプログラムに渡して、終わるのを待って終わる。
  - それ以外 (SIGSEGV・SIGABRT・SIGKILL・0 以外の終了) は異常な終わり。1 秒おいて起こし直し、`FMRB_SESSION_RESTARTED` に理由 (`SIGSEGV`、`status 3`) を入れる。直近 60 秒の異常な終わりが 4 回目になったら起こし直さず、台本は 1 で終わる (ログイン画面に戻る)。
  - ログ: `family-mruby-session: Family mruby ended by SIGSEGV; starting it again (1 of 3 within 60s)`、`... that is 4 abnormal ends within 60s: not starting it again (back to the login screen)`。
- 起こし直された Family mruby は `the session started Family mruby again (the last run ended abnormally: SIGSEGV)` をログに出し、デスクトップが最初に知らせを見た時から 10 秒「Family mruby を起こし直しました / 前回は異常終了しました (SIGSEGV)。」を右上に出す (起動の間に時間が切れないように、置き場への追加はデスクトップの最初の問いまで待つ)。
- **Linux のアプリはコンポジタと一緒に終わる。** Wayland の窓はそれを出しているコンポジタの持ち物で、コンポジタが落ちれば窓の相手が無くなり、ほとんどのアプリは接続が切れて終わる (保存していない作業は失われる)。L9b のとおり、プログラムが起こした Linux のプログラムは `PR_SET_PDEATHSIG` と終わりの片付けで終わる。起こし直した Family mruby はそれらを起こし直さない。fcitx5 (IME) と Xwayland はコンポジタが起こし直す (起動の時の手順)。

## 8. 仮決めに足した選択

| 選んだもの | 理由 | 別の案 |
|---|---|---|
| Wi-Fi と Bluetooth の操作をネットワークのダイアログの中でなく、ネイティブ版だけに組み込んだ「設定」の窓 (アプリ) にした。ダイアログには「Wi-Fi の設定...」のボタン、メニューに「Bluetooth」 | 一覧・選択・パスワードの入力は 240x104 のダイアログに入らない。デスクトップの Ruby は端末にも同じ bytecode が入るので、大きな画面を足すと端末の flash と VM の使用量が増える。窓なら動かせ、閉じられ、IME・キーの扱いも普通のアプリと同じ | ダイアログを PC で大きくして中に一覧を出す |
| nmcli は使わず D-Bus だけ | nmcli は同じ D-Bus の NetworkManager の道具なので、D-Bus に答えない時は nmcli も働かない。結果を文字で読むより確か | 指示書どおり D-Bus が無ければ nmcli を試す |
| 秘密の代理人になり、保存済みでパスワードを持たないネットワークでは利用者に聞く | Kubuntu の Plasma が作った接続はパスワードを KWallet に置く (代理人の持ち物) ことが多く、代理人がいないと Family mruby の session ではつながらない | 代理人にならず「Linux で設定してください」と出す |
| 新しい接続は `AddAndActivateConnection` で NetworkManager に保存させ、失敗したらその接続を消す | nmcli の `device wifi connect` と同じ振る舞い。違うパスワードの接続を残さない (利用者が作った接続は消さない) | 一時的な接続 (`persist: volatile`) にして保存しない |
| 802.1X・WEP は扱わない (「Linux で設定してください」) | 設定の項目が多く、L14 の範囲を超える | 項目を足す |
| 新しい secured のネットワークは WPA2 の `wpa-psk`、WPA3 だけのものは `sae` | NetworkManager の道具の既定と同じ | 常に `wpa-psk` |
| 機種の定義に `system.settings` (既定 true、Cardputer 2 つと sdl_keys は false) | 指示書の「PC だけ、sdl でも無理なくできる所まで」。組み込みの定義 = sdl.toml の決まりに合わせて既定を true (L13 の `window_ops` と同じ) | `system.services` に新しい値を足す |
| sdl の機種でも設定の窓・通知・PipeWire の音量を有効にした | どれも SDL の窓でも同じに働く (通知は名前が空いているときだけ)。portal と復帰はコンポジタだけ | sdl では切る |
| メニューの Bluetooth は BlueZ が無くても `system.settings` の機種では出す (開くと「装置がありません」) | 起動の時に BlueZ の有無はまだ分からない (スレッドが聞く前)。開けば理由が分かる | 有無が分かってからメニューを作り直す |
| 音量は wpctl → pactl の順、ツールを専用のスレッドで走らせる | PipeWire・PulseAudio に音量の D-Bus の口が無い。libpipewire・libpulse は依存が大きい | libpulse を実行時に開く |
| 音量のキーはネイティブ版の全部の機種で効かせ、知らせは PC だけ | Cardputer には音量のキーが無く害が無い。HID の口に置けば端末・sim・ブラウザ版のコードに触れない | PC の機種だけ |
| 音量の知らせは 2 秒、通知の 0 (消さない) は 10 秒、-1 は 5 秒、それ以外は 2〜10 秒 | 「数秒」の範囲。履歴を持たないので消さない通知も 10 秒で消える | 0 は押すまで出す |
| 知らせは押しても消えない (時間で消える) | デスクトップの前の層の押下を受けるには overlay の矩形 (ダイアログと 1 つを取り合う) が要る。時間で消えれば足りる | overlay にしてクリックで消す |
| 知らせは 4 つまで、デスクトップの更新 (0.5 秒) で見る | 画面の右上に収まる数。更新の間隔は今の 0.5 秒のまま | 専用の起こしで即時に描く |
| Screenshot の portal も wlr に向け、ほかは kde、gtk の順 | Kubuntu には kde の portal があり、ファイルを開くなどはそちら。Screenshot は wlr が画を取り、問いは kde が出す | ScreenCast だけ wlr |
| xdg-desktop-portal-wlr は `chooser_type=none` (出力を聞かずに渡す) | Family mruby は出力を 1 つしか使わない (L8)。選ぶ道具 (slurp など) を入れずに済む。共有するかどうかはブラウザが先に聞く | Family mruby の窓で出力を選ぶ道具を作る |
| 活性化の環境 (`dbus-update-activation-environment`) はコンソールの上だけで変える | 入れ子 (WSLg や他の机の中) では、その机の session の環境を書き換えてしまう | いつも変える |
| 復帰: SIGTERM・SIGHUP・SIGINT では起こし直さない。0 以外の終了は異常に数える | 頼まれて終わったものを起こし直さない。起動で断られた (DRM が無いなど) ものも 4 回で止まる | 0 以外の終了は起こし直さない |
| 起こし直しの間に 1 秒おく | 落ちてすぐの起動で同じ状態にぶつかるのを少し避ける。4 回でも 1 分に収まる | 待たない |
| 起こし直しの知らせは、置き場への追加をデスクトップの最初の問いまで遅らせ、10 秒出す | 起動 (入れ物では 8 秒ほど) の間に時間が切れて見えなかった | 時間を長くする |
| 確認では SIGSEGV のプログラムを `prlimit --core=1` で起こす | WSL ではコアは制限に関わらずホストの crash の取り込みへ渡される (1 だけが例外)。ホストの試験の台本はコアを残さない信号 (SIGKILL・SIGUSR1) を使う | そのまま |

## 10. VM で人が確かめる手順 (VirtualBox の Kubuntu 26.04)

1. 開発機で `.deb` を作る: `cd fmruby-core && rake native:deb ARCH=amd64` → `native/build-deb/family-mruby_<版>_amd64.deb`。VM へ写す。
2. VM の中で入れ直す: `sudo apt install ./family-mruby_<版>_amd64.deb`。Recommends の xdg-desktop-portal-wlr も入る (入らなければ `sudo apt install xdg-desktop-portal-wlr`)。
3. ログイン画面で「Family mruby」を選んでログイン。ログ (`~/.local/share/sddm/wayland-session.log`) に `native: volume: PipeWire (wpctl) on the default output`、`native: notifications: serving org.freedesktop.Notifications on the session bus`、`the session's activation environment: WAYLAND_DISPLAY and XDG_CURRENT_DESKTOP` が出ること。
4. **Wi-Fi**: 右上のネットワークの印 (かメニューの Network) → 「Wi-Fi の設定...」で設定の窓。VM の網は有線なので「Wi-Fi の装置がありません」と出るのが正しい (USB の Wi-Fi の子機を VM に渡せるなら、一覧・つなぐ・切る・パスワードを試す)。
5. **Bluetooth**: メニューの「Bluetooth」で同じ窓の Bluetooth の頁。VM に装置が無ければ「Bluetooth の装置がありません (BlueZ)」。USB の Bluetooth の子機を渡せるなら、入り切りと、Kubuntu の側で一度ペアリングした機器のつなぐ・切る。
6. **音量**: メニューの Mute で Plasma の音量の表示 (別の session にいるなら `wpctl get-volume @DEFAULT_AUDIO_SINK@` を Ctrl+Alt+F3 の文字の画面から) がミュートになり、もう一度で戻ること。VirtualBox がキーボードの音量のキーを渡すなら、押して右上に「音量 NN%」が出て、音の大きさが変わること。Konsole を前にしても同じであること。
7. **通知**: Linux の区分から Konsole を開き `notify-send "こんにちは" "通知の本文"` で右上に知らせが出て 5 秒ほどで消えること。`notify-send -t 0 ...` は 10 秒で消えること。
8. **画面の共有**: Firefox で共有を試すページ (たとえば会議のサービスの試験のページ) を開き、画面の共有を選ぶ。Firefox の問いのあと、Family mruby の画面全体が共有の絵に出ること。出ないときは `systemctl --user status xdg-desktop-portal xdg-desktop-portal-wlr` と、`~/.local/share/sddm/wayland-session.log` を見る (別の session の portal が古い環境で残っていれば `systemctl --user restart xdg-desktop-portal` してから試す)。
9. **復帰**: Konsole から `pkill -SEGV -f '/usr/bin/family-mruby --machine'`。画面が一度消え、Family mruby が起き直し、右上に「Family mruby を起こし直しました」と出ること (Konsole は消える)。1 分以内に 4 回続けるとログイン画面に戻ること。電源のメニューの「終了」では起こし直さずログイン画面に戻ること。

## 11. 撤回した見立て・踏んだ罠

- **xdg-desktop-portal-wlr が wlr-screencopy だけでは動かなかった**: 0.8 は wlr-screencopy を dmabuf と組でしか使わない (`Compositor supports neither ext_image_copy_capture or wlr_screencopy!`)。pixman では dmabuf が無いので、ext-image-copy-capture を足した (wlroots の見出しが protocol の server の見出しを要るので、CMake でそれも作る)。
- **選ぶ道具が無いと共有が断られた**: 既定の chooser は slurp・wofi などを順に試し、無ければ出力を選ばない (応答 1)。`chooser_type=none` の設定を包みに入れた。
- **portal は先に起こされると古い環境のまま**: 入れ物では PipeWire が portal を先に起こし、`XDG_CURRENT_DESKTOP` の無い環境で portal が残った。台本が起動の前に活性化の環境へ名前を知らせる形にした (Kubuntu では systemd の利用者の session で portal が起こされる。残件の手順 8)。
- **入れ物の WirePlumber は Dummy Output を作らなかった** (利用者が root でないとき): 確認の中で null sink を 1 つ作る。`wpctl get-volume` は失敗しても 0 で終わるので、出力の文字で判断する。
- **選んだ行が並び替えで別のネットワークに変わった**: つながったものが一番上に移ると、番号で覚えた選択が隣に移り、パスワードの欄が消えた。名前で覚えるようにした。
- **試みの後の一覧が 3 秒遅れた**: スレッドが自分で立てた「読み直し」をすぐに見ていなかった。試みの終わりにその場で読み直す。
- **確認だけの NetworkManager の接続の対象が見つからなかった**: sd-bus の fallback の vtable は、同じ道に普通の vtable もあると子の道を探さなかった。接続ごとに対象を置いた。
- **起こし直しの知らせが見えなかった**: 置き場に入れた時から 8 秒数えたので、入れ物の起動 (8 秒ほど) の間に消えた。デスクトップの最初の問いまで追加を遅らせた。
- **WSL でのコア**: 試験の台本で SIGSEGV・SIGABRT を使ったら、ホストの crash の取り込みが動いた。ホストの試験はコアを残さない信号に替え、入れ物の確認は `prlimit --core=1` にした。

## 12. 残件

- VirtualBox の Kubuntu での確認 (10 章)。実物の NetworkManager・BlueZ (polkit の許可。active な session の利用者は普通は許される)、Plasma の portal と一緒の Screenshot・ファイルを開く portal、ブラウザからの共有。
- パスワードは C 側では試みの後に消すが、Ruby の文字列 (窓の変数を空にしても、元の文字列) は GC されるまで VM のヒープに残る。
- 通知の操作のボタン (actions)、本文の markup、アイコンは扱わない。履歴は持たない (仮決めどおり)。
- 知らせは全画面のアプリの上には出ない (デスクトップの前の層に描くため)。
- 通知の名前を他のプログラムが持っている (Plasma の中の SDL の窓など) と、Linux の通知はそちらに行く (Family mruby のアプリの知らせは出る)。
- 端末の flash は L13 の時から NARYAv3 +7,328 B、TAB5 +7,392 B (デスクトップの知らせ・ボタン・メニューの bytecode と文字、アプリの gem の口)。内蔵 RAM は +0。
- ブラウザ版の画面 (`regress:screens` の web) は流していない (`tools/fmrb_web.rb` が開いたブラウザが開いたままで道具が止まるため。L9a からと同じ。閉じていない)。ブラウザ版に効く変更はデスクトップの Ruby の 3 か所 (どれも口が "" か -1 を返すので出ない) とアプリの gem の口だけ。描画の記録の比較 (`rake regress`) は 4 つの端末の組で全部通っている。
- arm64 の .deb は作り直していない (Cardputer は `system.settings = false` で、新しい口は何もしない)。
- Wi-Fi の無線の入り切り (`WirelessEnabled`) は出すだけで変えない (「Linux で入れる」と出す)。
