## コミット

| コミット | 中身 |
|---|---|

| 46310f17 | `native/sys/linux_apps.c` を 4 つのファイルと内部のヘッダに分ける |

## 分け方と理由

どちらも今ある節 (`/* ---- ... */`) の区切りでそのまま切った。節の中で関数の順番は変えていない。分けた先は名前どおりの節を、元の順番で並べている。

### output_wlr.c (3511 行)

| ファイル | 行数 | 中身 (元の節) |
|---|---|---|
| `output_wlr.c` | 874 | 頭の説明、state (状態の実体と now_ms など 4 つ)、output、the autostart、the output interface (`native_output_wlroots`) |
| `wl_window.c` | 517 | xdg and X11 windows alike、the focus、windows (xdg の窓・ポップアップ・枠の飾り) |
| `wl_picture.c` | 334 | the picture (絵の buffer、窓の置き方・切り抜き・ポップアップ) |
| `wl_xwayland.c` | 323 | X11 windows (全体が `#if WLR_HAS_XWAYLAND` のまま) |
| `wl_input.c` | 634 | keyboard、pointer |
| `wl_screen_lock.c` | 324 | the screen lock (L13) |
| `wl_tools.c` | 276 | the tools' devices (道具のキーボードとポインタ、`wlr_ctl`) |
| `output_wlr_internal.h` | 363 | include 一式、定数、型 (window_t など)、状態の構造体、ファイルをまたぐ関数の宣言 |

- 名前は同じ場所の `wl_clip.c`・`wl_ime.c` にそろえて `wl_*.c`。画面のロックは `test/native/wl/clients/wl_lock.c` (確認用のロックのプログラム) と紛れないように `wl_screen_lock.c` にした。
- 外への口 (`native_output_wlroots`、native_backends.h) は output_wlr.c のまま。
- 状態 `s` は無名の `static struct` だったので、ヘッダで共有するために構造体に名札 `struct output_wlr_state` を付け、`extern struct output_wlr_state s;` をヘッダに、実体を output_wlr.c に置いた。変数名 `s` は変えていない。
- ファイルをまたいで使う static の関数 49 個 (と `s_black`) は static を外し、ヘッダに宣言を置いた。1 つのファイルでしか使わないものは static のまま。元の前方宣言 (`lock_relayout`・`recheck_pointer`・`lock_start`・`begin_grab`・`lock_key`・`lock_motion`) はヘッダの宣言に置き換わったので消した。
- 外に出た名前が、つなぐライブラリ (wlroots・libc など) の出す名前と重ならないこと、プログラムの動的な記号表に出ないことを、組んだ後に nm で確認した (重なり 0)。

### linux_apps.c (2110 行)

| ファイル | 行数 | 中身 (元の節) |
|---|---|---|
| `linux_apps.c` | 1119 | 頭の説明、状態、reading the entries、the interface、opening files (L11)、starting and ending them |
| `linux_apps_util.c` | 145 | helpers |
| `linux_apps_exec.c` | 192 | the Exec field |
| `linux_apps_icons.c` | 624 | icons、the icon themes (L9e)、Qt's look (L9e) |
| `linux_apps_internal.h` | 99 | include 一式、`entry_t`、アイコンのテーマの構造体と大きさ、ファイルをまたぐ関数の宣言 |

- 名前は外への口 `linux_apps.h` にそろえて `linux_apps_*.c`。
- **linux_apps.c が 1000 行を超える理由**: 状態 `s` (static) を使う 4 つの節 (reading the entries・the interface・opening files・starting and ending) を 1 つのファイルに残したため。分けるには `s` を外に出す必要があるが、output_wlr.c の `s` も外に出したので、同じ名前の大域変数が 2 つになりリンクできない。名前を変えずに済む分け方はこれだけだった。名前を変えてよければ 4 つの節を分けられる (残件)。
- アイコンのテーマの構造体 (`struct linux_icon_themes`) は linux_apps.c の reader が `th->ndir` を読むので、その大きさの定数と一緒にヘッダへ移した。
- ファイルをまたいで使う static の関数 13 個は static を外してヘッダに宣言を置いた。`pathf` の printf 形式の属性つき宣言はヘッダへ移した。

### 名前で参照している所

- `native/CMakeLists.txt`: 分けた先のファイルを `NATIVE_WLR_SRCS`・`NATIVE_LINUX_APPS_SRCS` にまとめ、ソースの一覧と `set_source_files_properties` (wlroots の CFLAGS、`NATIVE_HAVE_PNG` と libpng) の両方でそれを使う。
- `rakelib/native.rake`: linux_apps のホスト試験に 4 つのファイルを並べた。.deb の Depends の説明 (librsvg) を `linux_apps_icons.c` に。
- コメント: `wl_ime.c` (`wl_ime_takes_keys` を聞くのは wl_input.c)、`test/native/apps.c` の頭、output_wlr.c の頭の説明の「below」(画面のロックは wl_screen_lock.c、wlr_ctl は wl_tools.c)。output_wlr.c と linux_apps.c の頭の説明の末尾に、ファイルの分担の段落を 1 つずつ足した。分けた先の各ファイルの頭には 1〜3 行の説明。
- 直さなかった参照: `comp_route.h`・`platform_sys_linux.c`・`linux_mime.h`・`main/prebuild_scripts/kernel/system_desktop/launcher.rb`・`desktop_icons.rb` の `output_wlr.c`・`linux_apps.c` は部品の名前として今も正しい (入口のファイル) のでそのまま。main/ の Ruby はバイトコードの作り直しを招くので触っていない。doc/linux_native/report の過去の報告もそのまま。

## 中身は移しただけ

- 元のファイルと分けた後のファイル一式を行の多重集合で比べた (行頭の `static ` / `extern ` は無視)。元にあって後に無い行は、output_wlr では頭の説明の 3 行 (above の参照を直した所) と `static struct {`・`} s;` の 2 行、linux_apps では `icon_for` の 2 行目 (`static` が取れて引数の行の字下げが 7 桁ずれたので合わせた) だけ。後にだけある行は、各ファイルの頭の説明・`#include`・ヘッダの宣言・空行。
- 関数の中身、コメント、節の順番は変えていない。

- 分ける前の regress:wl は流し直していない。この段の前のコードの変更は 2026-10-29 19:27 (c0cd675f) までで、その後は文書だけ。同じコードで 2026-10-29 20:23 に終わった regress:wl の結果 (tmp/wl_check の summary) が両エンジンとも全部通っていたので、それを分ける前の結果とした。
- 標準の wl_apps_check の 1 つ「the end」が 1 回落ちた。終わり方の流れ (3 つの窓に閉じるよう頼み、5 秒待ち、SIGTERM、SIGKILL、ランチャーから起こした 1 つを終える) とプログラムの exit=0 は分ける前と同じで、違いは終わった直後に撮る `ps` に Xwayland が 1 つ残っていたことだけ。`ps` はプログラムが終わった瞬間に撮るので、Xwayland が消える途中に当たったと見る (wlroots が Xwayland を止める所は移しただけで、中身は変えていない)。同じ確認だけを 2 回流し直して 2 回とも 10/10。揺れの候補として残件に書く。

## 気づいた点 (直さなかった候補)

- 大域変数の名前が `s` (output_wlr)。外に出たので、他の部品の大域の `s` とリンクで重なる。linux_apps.c の `s` を外に出せなかったのはこのため。`output_wlr_s` などへの改名の候補。
- 外に出た関数の名前が一般的 (`compose`・`relayout`・`new_input`・`cursor_motion`・`now_ms`・`dup_str`・`ms_now`・`sleep_ms`・`has_suffix` など)。今は重なりが無いが、`wl_`・`la_` などの前置きを付ける候補。
- `now_ms` (output_wlr) と `ms_now` (linux_apps) は同じ働き。`pathf` は linux_apps_util.c と linux_mime.c に同じものが 2 つ (後者は static)。共通化の候補。
- output_wlr_internal.h が wlroots のヘッダ一式を全部取り込むので、どのファイルも同じ include を持つ。ファイルごとに要るものだけにする整理の候補。

## 残件

- wl_apps_check の「the end」が、終わった直後の `ps` に消えかけの Xwayland を拾って落ちることがある (この段で 1 回、流し直し 2 回は通った)。確認の側で少し待つか、Xwayland が消えるのを待つ候補。
- linux_apps.c の 1119 行 (上の理由)。`s` の改名と合わせて、reading the entries と opening files を分けられる。
- 1500 行を超える `native/` の C ファイルは、この 2 つの他に無い (一番長いのは生成物の `native/apps/mrb/linux_settings.c` 1176 行、手で書いたものでは `wl_ime.c` 848 行)。
