## (a) タッチパッドのタップ

- コンポジタの `new_input` で、ポインタの装置が libinput のもの
  (`wlr_input_device_is_libinput`) で、タップに使える指の数が 1 以上なら、
  `wlr_libinput_get_device_handle` で libinput の装置を取り、
  - タップを入 (`libinput_device_config_tap_set_enabled`)
  - ボタンの割り当ては LRM (1 本指で左、2 本指で右、3 本指で中)
  - タップして動かすとドラッグ (`libinput_device_config_tap_set_drag_enabled`)
  にする。装置ごとにログへ 1 行 (`native: compositor: <名前>: tap to click on (N fingers)`)。
- 入れ子 (WSLg)・headless の装置は libinput でないので何もしない。
- 機種の定義に `[input] tap = true` (既定 true、`--set input.tap=false` で
  libinput の既定のまま) を足した。`linux_pc_wl.toml` に書き、機種の試験
  (`test/native/main.c`) に既定・false・不正な値を足した。安く済んだので入れた
  (指示どおり既定は入)。
- ビルド: libinput の関数を直接呼ぶので、CMake の `pkg_check_modules(WLROOTS ...)`
  に `libinput` を足した (image には wlroots の依存として入っている)。.deb の
  Depends は dpkg-shlibdeps が出す (libinput10 は wlroots の依存で元から入る)。

## (b) タッチの画面

### 決めたこと (wlroots・sway のやり方を読んで)

- **装置と回転**: タッチの装置を `wlr_cursor_attach_input_device` で cursor に
  つなぎ、`wlr_cursor_map_input_to_output` で出力に結びつける。wlroots の
  `wlr_cursor` (types/wlr_cursor.c の `handle_touch_down`・`handle_touch_motion`)
  は、出力に結びついた装置の 0..1 の座標に出力の transform をかけてから
  事象を出すので、ROTATE=270 は wlroots が回す (自分で式を書かない)。点は
  `wlr_cursor_absolute_to_layout_coords` で layout の座標にする。出力が後から
  来たときは `new_output` で結び直す。GPD の ILITEK は udev で
  `ID_INPUT_TOUCHSCREEN=1`、幅 90 mm・高さ 160 mm で、パネルの元の向き
  (縦長 1080x1920) の座標を出す。出力も同じパネルなので、出力の transform を
  かけるのが正しい。
  - ポインタの装置は結びつけない (入れ子の backend のポインタは絶対座標で、
    結びつけると回転がかかってしまう)。
- **CRT の曲がり**: `wl_crt.c` の `crt_pointer` を、任意の点を戻す `crt_point`
  とその上の `crt_pointer` に分けた。タッチの点は `crt_point` を通す。絵の外
  (曲がりの外の黒い所) に落ちたタッチは捨て、その指の移動と離しも捨てる
  (ポインタの押下と同じく `crt_dropped_press` に数える)。
- **届け方** (sway の `cursor.c` の `handle_touch_down` と同じ考え方。tinywl は
  タッチを扱わない):
  - 触った所が Linux の Window の surface で、その client が wl_touch を持つ
    (`wlr_surface_accepts_touch`) なら **wl_touch** で送る
    (`wlr_seat_touch_notify_down`・`_motion`・`_up`・`_frame`)。指を動かした間の
    座標は、触った surface の座標で送り続ける (surface の外へ出ても)。
    触ったときは、クリックと同じく Window を前に出してキーボードを渡し、
    Family mruby にも押下を渡す (Family mruby の Window の管理が代役を前に出す)。
    メニュー (popup) の上なら前後・フォーカスは変えない (クリックと同じ)。
  - それ以外 (Family mruby の絵、wl_touch を持たない client、画面ロックの間) は
    **ポインタの代わり**: ポインタを触った所へ動かし、左ボタンを押す。指を
    動かすとポインタが付いて動き (ドラッグ)、離すとボタンを離す。今のポインタの
    処理 (`process_motion`・`cursor_button`) をそのまま通すので、Family mruby の
    釦・タイトルの帯のドラッグ・File Manager のドラッグ・CRT の当たりは
    マウスと同じになる。
  - ポインタの代わりは 1 本の指だけ。その指が触れている間の別の指は捨てる。
    マウスのボタンを押している間・Window を動かしている間に触れた指も捨てる。
  - 同時に覚える指は 10 本まで。
- Window の上でタッチしたとき、Family mruby の矢印はそこへ描かず隠す (sway が
  タッチでカーソルを隠すのと同じ。マウスを動かすと戻る)。wlroots の矢印は
  動かさない。
- seat の capability に touch を出すのは、タッチの装置があるときだけ
  (無い機械で client が wl_touch を bind しない。Firefox などの振る舞いを
  変えないため)。

### 試験の口

- 制御のソケットに `comp touch` を足した (道具のタッチの装置。最初の
  `comp touch` で作り、cursor につなぎ、出力に結びつける。本物と同じ経路を通る):
  `comp touch` (状態と数: `devices down native emulated ignored`)、
  `comp touch down ID X Y`・`move ID X Y`・`up ID`・`tap X Y`。X, Y は見えている
  出力の画素で、道具が出力の transform の逆をかけて装置の 0..1 に戻す
  (wlroots が回し直す)。`comp stats` にも `touch_native`・`touch_emulated`・
  `touch_ignored` を足した。
- 試験の client `wl_dialog` に `touch` の引数を足した (wl_touch を bind して、
  down・motion・up をログに書く)。
- `test/native/wl/wl_touch_check.rb` (新規、`rake regress:wl` に入れた)。
  出力は GPD と同じ形 (1080x1920 を 270 回して 1920x1080、`display.scale=3`):
  1. タッチの装置ができると seat が touch を出し、touch の client だけ bind する
  2. touch の client を叩く: wl_touch の down・up が触った所 (surface 座標で
     1 画素以内)、キーボードがもう一方の Window から移る、ポインタのボタンは来ない
  3. 指を動かす: motion の座標が見た目どおりに動く (回転が 1 回だけかかる)
  4. wl_touch の無い client を叩く: ポインタの代わり (enter と左ボタンの down・up が触った所)
  5. Family mruby のタイトルの帯を指で動かす: Window が動く (90,36 出力画素 = 30,12 Family mruby 画素)
  6. その間の 2 本目の指は捨てる
- CRT は headless のコンテナ (pixman) では出ないので、GPD の GPU で確かめた (下)。

## (c) 2 本指のスクロール

- Linux の Window へは元から `wlr_seat_pointer_notify_axis` で届いている
  (Window 側が指のスクロールとして扱う)。Family mruby の絵の上では、
  `cursor_axis` が discrete の無い軸の事象を 1 つずつ 1 刻みにしていたので、
  細かい量が続けて来る指のスクロールは速すぎた。
- 事象の source が FINGER か CONTINUOUS のときは、縦の量を貯めて 15 ごとに
  1 刻み送り、余りは残す。15 は libinput のホイールの 1 刻みの角度
  (wlroots の libinput の backend はホイールで `delta` = 15・`delta_discrete` = 120
  を出す。指の `delta` も同じ単位)。止まったとき (量 0 の事象。libinput の
  scroll の止まり) に貯めた分を捨て、次の指は 0 から。向きが逆になったら
  逆向きの余りを捨てる。
- マウスのホイール (WHEEL・WHEEL_TILT) は今のまま (`delta_discrete` / 120、
  無ければ符号で 1 刻み)。
- タッチパッドの scroll の方法は、2 本指ができる装置なら 2 本指に決める
  (libinput の既定と同じだが念のため。`input.tap` に関係なく)。ナチュラル
  スクロールは触らない (libinput の既定のまま。wlroots が向きを
  `relative_direction` で伝える)。
- 試験の口: `comp scroll D` (道具のポインタの指のスクロール、D = 0 で止まり)、
  `comp stats` の `wheel_notches` (Family mruby に送った刻みの数)。
  `wl_touch_check` の 7 で、3 を 7 回 → 1 刻み、止めて 3 を 3 回 → 増えない
  (止まりで捨てた)、ホイール 1 → 1 刻み、-6 を 5 回 → 2 刻み、を確かめる。

- `rake regress`: host 21 本・描画の記録 213 本すべて通過 (a の後と最後の 2 回)。
  `native:test` の機種の試験は 559 項目通過 (`input.tap` の試験を含む)。
- `rake regress:wl`: standard・mruby とも全部通過 (wl_check・apps・dialogs・keys・open・
  clip・ime・winops・settings・size・touch)。新しい `wl_touch_check` は 7/7 ずつ。
  1 回目は (b) の binary の途中で試験に (c) の場面を足してしまい touch だけ落ちたので、
  (c) を入れて全部をもう一度流した (2 回目が上の結果)。
- 指示の「headless の backend でタッチを注入できるか」: wlroots の headless の
  backend にはタッチの装置が無い。そこで道具のタッチの装置 (`wlr_touch` を
  自分で init して cursor につなぐ) を作り、本物と同じ経路 (cursor の
  touch の事象・出力への結びつけ・回転) を通した。

### GPD の GPU で headless (ユーザの画面には出していない)

C4 と同じく、.deb を `/tmp/fmx` に展開だけして、`WLR_BACKENDS=headless
WLR_RENDERER=gles2`、1080x1920 を 270 回し、`display.scale=3`、
`display.look=crt`・`display.crt_curve=100` で動かした。

- `CRT look on OpenGL ES 3.2 Mesa ...`、道具のタッチの装置が出力に結びついた。
- 表示の左上 (5,5)・右下 (1915,1075) のタッチは絵の外として捨てた
  (`ignored=2`、CRT の `dropped=2`)。真ん中 (960,540) は Family mruby の
  デスクトップでポインタの代わり (`emulated=1`)。
- Konsole (Qt、wl_touch を持つ) をこのコンポジタで開き、その上のタップと
  指の移動が wl_touch で届いた (`native=2`)。
- 終わった後、テストのコンポジタと Konsole は止めた (ユーザのセッションの
  Konsole には触っていない)。

タッチパッド:
1. 1 本指で軽く叩く → 左クリック (Family mruby の釦・アイコン、Linux の Window)。
2. 2 本指で叩く → 右クリック (File Manager の右クリックのメニュー、Firefox の文脈メニュー)。
3. 叩いてすぐ指を置いたまま動かす → ドラッグ (Window のタイトルの帯、File Manager のファイル)。
4. 2 本指のスクロール: File Manager の長い一覧・ランチャー・エディタ (Family mruby) が
   ホイールくらいの速さで動くか (速すぎ・遅すぎ)。Firefox・Konsole (Linux の Window) も
   滑らかに動くか。向きはマウスのホイールと同じ感覚か (ナチュラルスクロールは libinput の既定のまま)。

タッチの画面:
5. Family mruby の釦・メニュー・アイコンを触る → その場所でクリック。
6. File Manager のファイルを触ったまま動かす → ドラッグ。Window のタイトルの帯を指で動かす。
7. Firefox などの Linux の Window: リンクを触る、指でページをスクロールする (wl_touch で
   渡すので、スクロールは Firefox 自身がする)。
8. 回転: 触った所と反応する所がずれないか (縦横・上下左右)。
9. CRT の曲がり (既定 15、設定で大きく): 触った所が見えている所に届くか。四隅の
   黒い所を触っても何も起きないか。
