## 1. 種類・既定・候補の読み方

### 置き場所

| 場所 | 中身 |
|---|---|
| `native/sys/linux_mime.{h,c}` (新) | ファイルの種類 (MIME)、種類の親 (別名・下位の種類)、`mimeapps.list` の読み方。POSIX だけで書き、FreeRTOS と fmrb の allocator を使わない (host の試験がそのまま動かす。L9b の `linux_apps` と同じ扱い)。データの場所の一覧 (`linux_xdg_data_dirs`) は `linux_apps.c` からここへ移し、両方で使う |
| `native/sys/linux_apps.{h,c}` | L9b の `.desktop` の読み方の隣に、ファイルを開く 2 つの口 (`linux_apps_handlers`・`linux_apps_open`) と、`Exec` にファイルを入れる分け方 (`linux_apps_split_exec_open`) を足した |
| `main/kernel/fmrb_platform_sys.{h,c}` | 関数の表に `apps_handlers`・`apps_open` の 2 項目と呼ぶ側の短い関数。既定の表は NULL のままで、端末・sim・ブラウザ版は「無い」(-1 / `FMRB_ERR_NOT_SUPPORTED`) を答える。表は `static const` |
| `native/sys/platform_sys_linux.c` | Linux の表に 2 項目 (`NATIVE_HAVE_WLROOTS` のビルドだけ)。仮想の場所を実体に直し、ファイルを読む仕事は待つ呼び出しの門 (gate) の助手のスレッドで |
| `lib/add/picoruby-fmrb-app/ports/esp32/app.c` | `FmrbApp.linux_handlers(path)` (候補の文字列、無い所では "")、`FmrbApp.linux_open(id, path)` (起こしたアプリの名前、起こせなければ "") |
| `main/prebuild_scripts/spinel/fmrb_app_base_spinel.rb` | Spinel の FmrbApp に同じ名前で「無い」を答えるもの (L9b と同じ理由) |

### 種類 (MIME) の判定

- shared-mime-info の `globs2` を、データの場所 (`$XDG_DATA_HOME`、無ければ `~/.local/share`、次に `$XDG_DATA_DIRS`、無ければ `/usr/local/share:/usr/share`) の順に `mime/globs2` から読む。各行は `重さ:種類:型[:印]`。
- 当たった型のうち重さの大きいもの、同じなら型の長いもの、同じなら `cs` の印のあるもの、それも同じなら先に読んだもの (大事な場所の方) を取る。
- 大文字小文字は xdgmime と同じ扱いにした: `cs` の印のある型はファイル名そのままと、印の無い型は小文字にしたファイル名と比べる。`globs2` は C++ の `*.C` を印つきと印なしの 2 行で持っていて、名前を大文字小文字を無視して比べると `x.c` が C++ になる (手元の Ubuntu 22.04 の `globs2` で実際にそうなった)。小文字の名前と比べると `*.C` (印なし) は `x.c` に当たらない。
- どの場所にも `globs2` が無いときだけ、拡張子の小さな表 (pdf・png・jpg・html・txt・mp3・mp4・zip・odt・docx など 35 個) を引く。何にも当たらなければ「分からない」(中身は見ない)。
- 種類の親: その種類、`mime/aliases` での正式な名前、`mime/subclasses` の親を幅優先で、`text/` で始まるものには最後に `text/plain`。12 個まで。`__NOGLOBS__` は扱っていない。
- 重さ (手元の Ubuntu 22.04、`globs2` 33 KB): 種類の判定 0.05-0.1 ms、親 0.03 ms、`mimeapps.list` 0.01 ms。

### 既定と候補 (`mimeapps.list` の決まりの順)

- 読むファイルの順: `$XDG_CONFIG_HOME` (無ければ `~/.config`)、`$XDG_CONFIG_DIRS` (無ければ `/etc/xdg`)、`$XDG_DATA_HOME/applications`、`$XDG_DATA_DIRS/applications`。それぞれで `family-mruby-mimeapps.list` (デスクトップの名前の小文字) を `mimeapps.list` の前に読む。最後にデータの場所の古い `defaults.list` (既定の組だけ)。Kubuntu の Dolphin の「Open With」の「覚える」は `~/.config/mimeapps.list` に書くので、それが一番前に来る。
- 毎回読み直す (小さいファイルで、Linux 側で変えた既定がすぐ効く)。
- 種類の親の 1 つずつについて、ファイルの順に:
  - `[Default Applications]` の行の中で入っている最初の項目が既定 (最初に見つかったものが勝つ。入っていない項目は飛ばす)。
  - `[Added Associations]` の項目を候補に足す。`[Removed Associations]` の項目は、それより後で足される候補から外す。
  - 続けて、`MimeType` にその種類を持つ `.desktop` を名前の順に足す。
- 既定の行が無ければ候補の最初が既定。同じ項目は 1 回だけ。候補は 64 個まで。
- **`NoDisplay=true` の `.desktop` も候補にする**。種類を開くためだけの項目 (Okular の `okularApplication_pdf.desktop` など) はたいてい `NoDisplay=true` で、L9b はこれをランチャーのために外していた。`MimeType` を持つものに限り、ランチャーの一覧には出さず開く用だけに残す (`OnlyShowIn`・`NotShowIn` で外れるものも同じ)。`Hidden=true` (消された項目) は今までどおり外す。こうして残したものはアイコンを作らない。ログの「`N entries of M desktop files`」の N はランチャーに出る数のままで、後ろに `K more to open files with` を足した。

### `Exec` にファイルを入れる

- L9b の分け方 (引用符、項目の符号) に、開くファイルを渡す形を足した (`linux_apps_split_exec_open`)。
- 引数まるごとの `%f %F %u %U` はファイルのパスになる。引数の途中 (`--file=%f`) でも同じ。ファイルは 1 つなので、最初の符号だけがパスになり、残りは消える。`%u %U` にもパスを渡す (決まりで許されている。`file://` の URL にはしない)。
- **項目の符号が 1 つも無いときは、パスを最後に足す** (GLib と KIO がそうする。決まりは決めていない)。
- `Terminal=true` はランチャーと同じく端末の中で起こす (`foot --`、無ければ `x-terminal-emulator -e`)。
- 起こすのは L9b の起動の口: 頼みを列に積み、コンポジタの主スレッドが fork と exec。終わり方 (Exit で閉じるよう頼み、残ったものに SIGTERM と SIGKILL) も同じ。窓の名前は起こした項目の名前になる。

## 2. パスの直し方

- File Manager は Family mruby の仮想の場所 (`/mnt/host/doc.pdf`) を渡す。`platform_sys_linux.c` が file HAL の振り分け (`fmrb_hal_file_resolve_path`) で実体の場所にし、`realpath` で辿った先が普通のファイルのときだけ渡す (`/mnt/host` は `$HOME`、`/mnt/root` は `/`、`/home` などの Family mruby の場所は利用者のディレクトリの下の実体)。
- 直せないもの (振り分けで答えが出ない、実体が無い、普通のファイルでない) は断り、ログに理由を出す。
- `realpath`・`stat`・`globs2` と `mimeapps.list` を読むのは門 (`fmrb_gate_call`) の助手のスレッド。協調の FreeRTOS では、タスクの中でファイルを読むと全部のタスクが止まるため (L2n)。

## 3. File Manager

### ダブルクリック・Enter

- 関連付けの表 (`FmrbAssoc.load_table`) にその拡張子があるかをまず見る。今までは `FmrbAssoc.resolve` が表に無いものに "edit" を返していたので、File Manager の中で「表に有るか」を直に見る形にした (`fmgr_assoc_listed`。`lib/add` の `FmrbAssoc` は変えていない)。
- 表にある種類 (`.rb`・`.txt`・`.md` など) は今までどおり。
- **表に無い種類 (拡張子の無いものを含む)** は、Linux のアプリのある機種 (コンポジタ) では Linux の既定で開く。**Linux の既定も無ければエディタで開く** (今までの「表に無いものはエディタ」と同じ)。下の「判断」を参照。
- 表の答えが `linux` か `linux:<id>` なら、その行き先で開く。起こせなければ知らせ (「Cannot open doc.pdf: no Linux app opens this kind of file.」など)。
- 起こしたら File Manager を閉じる (Family mruby のアプリで開いたときと同じ)。

### 右クリック「Linux のアプリで開く」

- ファイルの右クリックのメニューの最後に「Linux のアプリで開く」(英語は「Open in Linux app」) を足した。キーは L (メニューの右に `L`)。ディレクトリ、`special` のファイル (装置など)、「..」には出さない。Family mruby が開ける種類にも出す。メニューの幅は日本語の名前に合わせて広げる (90 から 130 ほど)。
- 選ぶと、そのファイルの候補の一覧を、メニューのあった所 (L キーなら選んだ行の下) に出す。先頭が既定で「(既定)」が付く。**6 個ずつ出し、まだあれば最後に「その他...」**。「その他...」で次の 6 個に替わる。
- 一覧はマウスで押すか、上下のキーで選んで Enter。Esc と Tab で閉じる。ほかのキーは一覧を閉じて下の行に効く (右クリックのメニューと同じ)。
- 候補が 1 つも無いときは知らせ (「No Linux app opens x.zzz (種類).」)。
- 項目と一覧は File Manager の矩形の中に収める (kernel が合成する重なりの矩形はそれ 1 つのため)。
- **Linux のアプリを起こせない機種では項目を出さず、動きは今と同じ**。File Manager を開くたびに `FmrbApp.linux_apps(2, lang)` (見出しだけ) を 1 回聞き、"" (端末・sim・ブラウザ版・コンポジタでないネイティブ版・Cardputer) なら項目も Linux の既定も使わない。keys のデスクトップ (Cardputer) は同じ mixin だが、Linux のアプリが無いので同じく出ない。

### 文字列

- i18n の表に `fmgr_open_linux` (Open in Linux app / Linux のアプリで開く)、`fmgr_linux_default` ((default) / (既定))、`fmgr_linux_other` (Other... / その他...) を足した。知らせは今の File Manager の知らせと同じく英語 (ダイアログが system のフォントだけで描くため)。

## 4. 関連付けの表の書き方

`config/associations.toml` (焼くときに `/etc/associations.toml` になる元。指示書の `flash/etc/associations.toml` はこれを写した生成物で git に無い) の説明に足した。

```
#   "linux"      Linux's default app for the file's kind (the PC only, below)
#   "linux:<id>" that Linux app: its desktop file id, ".desktop" optional
...
#   pdf  = "linux"                        # Linux's default PDF viewer
#   html = "linux:firefox"                # always Firefox
#   txt  = "linux:org.kde.kate.desktop"   # Kate rather than our editor
```

- 例は注釈だけで、出荷の表の行は変えていない。利用者は `/home/associations.toml` に書く。
- `linux` の行は、Linux のアプリが無い機種ではエディタで開く (表に無いものと同じ扱い。ログに 1 行)。

## 5. 判断したこと

- **Linux の既定が無いときはエディタ** (指示書の「Linux の既定も無ければ、今どおり『開けない』と出す」との違い): 今の動きは「表に無い種類はエディタ」で、「開けない」と出すのは特殊なファイル (L7d) だけ。「今どおり」を優先し、Linux も Family mruby の表も知らない種類 (拡張子の無い README など) は今と同じくエディタで開く形にした。「開けない」と出す形に変えるなら `fmgr_open_file` の 1 行 (`action = FmrbAssoc::EDIT` の代わりに知らせ)。ユーザの判断を仰ぎたい。
- **`.rb` は今どおり実行** (受け入れ条件 2 の「`.rb` は今どおりエディタで開く」との違い): 出荷の表は `rb = "run"` で、今の Enter は `.rb` を実行する。「今どおり」を守り、試験では `.rb` が実行されること、`.txt` (表で "edit") がエディタで開くことを見た。
- **`NoDisplay=true` の項目を開く用に残す** (上の 1 章)。外したままだと、Kubuntu の Okular など多くのアプリが候補に出ない。
- **符号の無い `Exec` にはパスを最後に足す** (上の 1 章)。
- File Manager が Linux のアプリを起こしたら閉じる (Family mruby のアプリで開いたときと同じ)。

## 7. VirtualBox の Kubuntu 26.04 で人が確かめる手順

1. 開発機で `.deb` を作る: `cd fmruby-core && rake native:deb ARCH=amd64` → `native/build-deb/family-mruby_<版>_amd64.deb`。VM へ写す (共有フォルダなど)。
2. VM の中で入れる: `sudo apt install ./family-mruby_<版>_amd64.deb`。ログイン画面で「Family mruby」を選んでログイン (L9b の手順と同じ。黒いときは `/etc/default/family-mruby-session` に `WLR_RENDERER=pixman`)。
3. 確かめるファイルを Kubuntu のホームに置く (Family mruby に入る前に Plasma で作るか、Family mruby の中の Konsole で): PDF (`~/doc.pdf`、何かの PDF)、画像 (`~/pic.png`)、文書 (`~/memo.txt`)、Ruby (`~/hello.rb`)。
4. Family mruby のメニューの「ファイル」(File Manager) → `mnt` → `host` で 3 のファイルが見える。
5. 確かめること:
   - `doc.pdf` をダブルクリック (か選んで Enter) → Kubuntu の既定の PDF のアプリ (Okular) が Family mruby の窓として開き、そのファイルを表示する。`pic.png` も既定の画像のアプリ (Gwenview) で開く。
   - `memo.txt` は今までどおり Family mruby のエディタで開く。`hello.rb` は今までどおり実行される。
   - `doc.pdf` を右クリック → 最後の「Linux のアプリで開く」→ PDF を開けるアプリの一覧 (先頭に「(既定)」) → 別のアプリ (Firefox など) を選ぶと、そのアプリで開く。キーボードでは、選んで L → 上下 → Enter。
   - 候補の多い種類 (`.txt` など。Kate・KWrite・Firefox…) では 6 個の後に「その他...」があり、押すと続きが出る。
   - Plasma の Dolphin で既定を変える (右クリック → 「Open With」→「Other Application」→ アプリを選び「Remember application association」) と、Family mruby の File Manager のダブルクリックもそのアプリになる (`~/.config/mimeapps.list` を毎回読む)。
   - `/home/associations.toml` (Family mruby のエディタで新規に作る) に `txt = "linux:org.kde.kate"` と書き、File Manager を開き直して `memo.txt` を開くと Kate で開く (表はデスクトップが起動したときに 1 度だけ読むので、書いた後は Exit してもう一度ログインする)。
   - 開いた Linux のアプリは題の帯の丸で閉じられ、電源のメニューの Exit でも閉じる。
6. ログ (`~/.local/share/sddm/wayland-session.log`): `File manager: open /mnt/host/doc.pdf in the Linux app ...`、`open ... (/home/<名前>/doc.pdf) in "...": asked to start`、`linux apps: started "..."`。開かないときは `linux apps for ...:` か `open ... in ...:` の行に理由が出る。

## 8. 撤回した見立て・踏んだ罠

- 最初は `globs2` の印なしの型を大文字小文字を無視して比べた。手元の `globs2` で測ると `x.c` が `text/x-c++src` になった (C++ の `*.C` が印つきと印なしの 2 行で載っているため)。xdgmime と同じく、印なしの型は小文字にした名前とそのまま比べる形に直し、host の試験に 2 行の組を足した。
- 根の一覧の並びは配布物の木とともに変わるので、試験は File Manager と同じ読み方をする小さなアプリ (`lister.app.rb`) を起こして並びを取り、行の場所を決めている。

## 9. 残件

- VirtualBox の Kubuntu での確認 (7 章)、人の手のキーボードとマウス、Okular など実際のアプリの窓。
- Shell の `open` は `linux` の行き先を知らない (範囲の外の `default_app/shell` にあるため)。表に `linux` を書いた種類を Shell の `open` で開くと、`spawn_app("linux", ...)` に行って起動に失敗する。File Manager と同じ扱い (Linux のアプリがあれば Linux、無ければエディタ) を足すとよい。
- 種類の判定はファイル名だけで、中身 (magic) は見ない。`__NOGLOBS__` は扱わない。`.desktop` の `MimeType` に書かれた別名は正式な名前に直さない (`mimeapps.list` の側は直して引く)。
- 候補の順は、既定・`Added Associations`・`MimeType` の名前の順。GLib の「最近使った」順は無い。
- 知らせは英語のまま (今の File Manager の知らせと同じ)。
- `FmrbAssoc.resolve` (lib/add) は "edit" を返したまま。File Manager 以外の使い手 (Shell の `open`、ほかのアプリ) は今までどおり。
