- よって二分探索はしていない。

## 原因

### apps の the end: Xwayland の終わりを待っていない

- wlroots は Xwayland を自前の fork を挟んで起こし、間の fork はすぐ終わる。入れ物の中で見ると Xwayland の親は docker-init (PID 1) で、fmruby-native ではない (`ps -o pid,ppid`: `102 1 Xwayland :0 -rootless ...`)。
- 終わるとき `wlr_xwayland_destroy` が接続を閉じ、Xwayland は自分で終わる (`(EE) failed to read Wayland events: Connection reset by peer`)。プログラムはそれを待たずにすぐ終わるので、Xwayland が終わり切る前に次のもの (確認では直後の `ps`、本物の PC ではセッションの台本の続き) が動くと、Xwayland がまだ見える。
- 確認の仕方: 確認の台本に一時的に「Exit の前に Xwayland を SIGSTOP する」を入れて流した (コミットしていない)。13e81d26 は `processes left: 95 Xwayland` (落ちた回と同じ形)、直した後は `Xwayland (pid 96) still there after 500 ms: SIGKILL (ended)`、`processes left: none`。

### fullscreen shooter: 撮る 2 つの間の 1 フレームのずれ

- 確認は Family mruby の絵 (`shot`) を撮ってから合成後の画面 (`grim`) を撮り、全画面の view の中を比べる。shot は約 50 ms、grim は約 140 ms かかる。合成後の画面は、先に撮った絵と同じフレームか、1 つ前のフレームになる (撮った後の絵の方が一致は悪い: 後 900,306、前 903,411)。
- shooter は敵が飛んでくる場面で、1 フレームのずれが view のちょうど 2% ほど。確認は view が出てから 1.5 秒の所で撮るので、ちょうどそこに当たる。同じ確認を 0.3 秒おきに 8 回撮ると、98.5% から 100% (全画素一致) まで動く (13e81d26 と 87e0ec97 で同じ並び: 906,138 / 912,060 / 911,232 / 918,918 / ... / 920,160)。
- 頭の説明には「両側で撮り近い方を数える」とあったが、作り (51982c6d、L9d) からずっと 1 回撮るだけだった。

## 直したこと

| ファイル | 中身 |
|---|---|
| `native/wlr/wl_xwayland.c`、`output_wlr.c`、`output_wlr_internal.h` | 終わり方の最後で `xwayland_end()`: `wlr_xwayland_destroy` の前に Xwayland の PID を見つけておき (`/proc` から、表示 `:N` を引数に持つ自分の利用者の Xwayland。表示ごとに X サーバは 1 つ)、終わる (または zombie になる) のを TERM_GRACE_MS (500 ms) まで待ち、残れば SIGKILL。ログに `Xwayland (pid N) ended in 5 ms` などを出す。接続の資格情報は使えない (Xwayland の接続は fork の前に作った socketpair なので、相手の PID がこのプログラム自身になる) |
| `test/native/wl/wl_check.rb` | view の確認を 1 回を「前に shot、grim、後に shot、近い方を数える」にし (頭の説明どおり)、通らなければ 0.3 秒おいて最大 3 回 (VIEW_TRIES)。置き方・周りの黒・98% の基準はそれぞれの回で今までどおり。結果の行に前と後の数と、3 つを撮るのにかかった時間を足した |

利用者から見た違い: Exit・セッションの終わりで、X11 のプログラムを使っていたときに最大 0.5 秒 (普段は数 ms) Xwayland の終わりを待つ。それ以外の動きは変わらない。

## 撤回した仮説

- **root の tools/fmrb_native.rb が遅くなって shot と grim の間が開いた**: 起動は 0.07 秒、shot は 50 ms。13e81d26 の後の root の変更 (app move まわり) は shot に関係しない。
- **11-04 以降のコアの変更 (S3 のプールの割り振り・mruby-checkpoint など) で shooter の進み方が変わった**: 13e81d26 と 87e0ec97 で撮れる数が 1 画素まで同じ。
- **合成が古いフレームを出し続けている (コンポジタの回帰)**: 0.3 秒おきの 8 回で 100% 一致も出る。ずれは高々 1 フレームで、13e81d26 と同じ。
- **fcitx5 (L12b の IME) が Xwayland の終わりを遅らせている**: 終わり方の流れのログは 13e81d26 と同じで、fcitx5 は SIGTERM で先に終わっている。残ったのは Xwayland だけ。
- **CPU の忙しさだけで再現できる**: 13e81d26 で 32 本の重しをかけて 6 回流しても再現しなかった。競争は Xwayland の終わる早さとプログラムの終わる早さの差なので、出るかどうかは機械の状態しだい。確実な再現は SIGSTOP で取った。
