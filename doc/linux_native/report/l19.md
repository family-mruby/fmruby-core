# L19 報告: ネイティブ版から証明書つき (mTLS) で Asterism のルータにつなぐ

> 状態: 実装済・検収待ち (GPD の実機と本物の console での確認はユーザ) | 更新: 2026-11-12 | ネイティブ版が ESP32 と同じ `tls/` の接続と console の `.tar` で、mTLS の zenohd に TLS 1.3 でつながる。Mbed TLS は**ネイティブ版にすでに入っているもの** (picoruby-mbedtls) を使い、設定に TLS 1.3 と PSA を足した。.deb の Depends は増えていない。TLS の口は gem (picoruby-asterism-zenoh) の `ports/posix/zp_tls_posix.c`。手元の mTLS + ACL の zenohd で、つながる・ノード ID が証明書に縛られる・anodes / asend / amove・console の一覧の受け取り・別の CA の証明書と .tar なしの拒否を確かめた。sim・ブラウザ版・ESP32 の中身は変わらない

計画は [../plan.md](../plan.md) の L19 の行。ESP32 の TLS の経緯は [../../ruby_asterism/report/g2a.md](../../ruby_asterism/report/g2a.md)、一覧の受け取りは [../../asterism_file_transfer/report/t6.md](../../asterism_file_transfer/report/t6.md)・[t8.md](../../asterism_file_transfer/report/t8.md)。

## 1. 結果の要約

- **Mbed TLS はネイティブ版の中のものを使う** (ホストの libmbedtls は使わない)。ネイティブ版の libmruby には picoruby-socket が連れてくる picoruby-mbedtls が Mbed TLS 3.6.2 を丸ごと組み込んでいる (SHA-256 の `MbedTLS::Digest` はこれ)。ただしその設定は TLS 1.2 だけで PSA が無い。zenohd 1.10.1 は mTLS のとき TLS 1.3 しか受けない (g2a 2.4) ので、設定に TLS 1.3 と PSA を足した (`native/net/mbedtls_tls13.h`)。
- **.deb の Depends は変わらない**: `rake native:deb ARCH=amd64` の Depends に mbedtls は無い (下の 5 章)。ホストの libmbedtls を足す案は、組み込みの Mbed TLS と同じ名前の関数がぶつかるので取らなかった (6 章)。
- **つながった**: `zenoh: TLS handshake with 127.0.0.1 (TLSv1.3) took 10 ms`。転送のアプリ・Shell の anodes・試しのアプリが、どれも同じ `.tar` で手元の zenohd (mTLS、ACL つき) につながった。
- **ノード ID は証明書の名前**: config.toml に `node = "imposter"` と書いても `asterism: the certificate's name gpd-l19 is the node ID (not imposter)` (これは ESP32 と同じ Ruby の層)。証明書 gpd-l19 の接続から他人の名前の鍵 (`asterism/mpc-l19/...`) へ put すると、ルータの ACL が捨てた (20 回出して 0 回届いた。自分の鍵は 20 回とも届いた)。
- **anodes・asend・amove**: 2 つのネイティブ版 (gpd-l19・mpc-l19) を同じ tls/ のルータにつなぎ、anodes で互いが見え、asend でファイルが相手の `/home/inbox/` に置かれ、amove で動いているアプリ (Ckpt Counter) が相手へ移って数え続けた。
- **console の一覧**: 転送のアプリの `certified?` はルータの文字列が `tls/` で始まるかで決めるので、ネイティブ版でも ESP32 と同じに働く。tls/ でつないだ mpc-l19 に、console 役 (`console = "pc-l19"`) から `policy_set` を呼ぶと受け取り、receive.toml の managed の部分に書いた。tcp では拒むこと (`regress:transfer:quick` の managed) は今までどおり。
- **拒否は 1 行で分かる**: 別の CA が署名した同じ名前の証明書では `TLS: alert 48 from the router: the router refused this machine's certificate (not signed by the router's CA?)`。`.tar` が無ければ `tls/127.0.0.1:7448 needs a credentials .tar in /home/asterism` (Shell の画面に出る)。
- **鍵の権限**: 起動のたびに `/home/asterism` を 0700、その中の `*.tar`・`*.key` を 0600 に締める (緩いときだけ。締めたら 1 行出す)。鍵の中身は出さない・読まない。

## 2. 設計

### 2.1 置き場所

| どこ | 何 |
|---|---|
| picoruby-asterism-zenoh (gem、別リポ) | `ports/posix/zp_tls_posix.c` (POSIX の TLS の口)。gem の TLS のリンク (`src/zp_tls_link.c`) と `tls_stream.h` を全部の platform で使い、zenoh-pico 自身の TLS のリンクと口は組まない。POSIX で TLS を入れるかは**組む側が決める** (`Z_FEATURE_LINK_TLS=1` と Mbed TLS の include を gem に渡す)。渡さなければ今までどおり (口は空、Mbed TLS のヘッダも読まない) |
| `lib/add/family_mruby_native.rb` | ネイティブ版だけ、gem に `Z_FEATURE_LINK_TLS=1`・picoruby-mbedtls の設定と include を渡す。libmruby 全体に `MBEDTLS_USER_CONFIG_FILE` |
| `native/net/mbedtls_tls13.h` | picoruby-mbedtls の設定に足す分 (TLS 1.3・PSA・HKDF・KEEP_PEER_CERTIFICATE・TLS 1.3 の ephemeral・互換モード・PKCS#1 v2.1) |
| `native/backend/main_native.c` | 起動時に `/home/asterism` の鍵のファイルの権限を締める |
| `lib/add/PICORUBY_ASTERISM_ZENOH_PIN` | gem の新しいコミット `15b0ff4` |

ESP32 は `ports/esp32/zp_tls_esp32.c` を ESP-IDF の部品が組み、POSIX は `ports/posix/zp_tls_posix.c` を gem の posix の port として mruby の rake が組む。ESP32 の組み方・設定・中身は変えていない。

### 2.2 口 (stream) の中身

ESP32 の口と同じ約束で書いた (g2a の 1〜7)。

- ソケットの読み書きは待たない (`MSG_DONTWAIT`)。待つのは握手 (10 秒)・握手中の読み・送りだけで、`select` で期限まで。ネイティブ版では `select` が待つ呼び出しの門 (`native/net/net_wrap.c`、L2n) を通るので、待つ間もほかのタスクが動く。
- 普段の読み (poll ごと) は待たない。「まだ無い」は SIZE_MAX、「切れた」は 0。
- Mbed TLS のエラーは「もう一度」以外すべて接続の終わり。ソケットを shutdown し、zenoh-pico のつなぎ直しに任せる。
- 証明書と鍵は base64 だけ (Ruby の層がそう渡す)。TLS で待ち受ける側 (peer) は断る。

ESP32 の口との違い:

| | ESP32 | POSIX |
|---|---|---|
| 乱数 | HMAC_DRBG | CTR_DRBG (どの Mbed TLS の設定にもある方) |
| 握手のログ | 時間と内蔵 RAM の最低値 | 時間と TLS の版 |
| ルータの alert | `TLS: the connection failed: -0x7780` | `TLS: alert 48 from the router: ...` と理由の見当 |
| つながらないとき | 何も出さない | `TLS: cannot connect to <host> (no router listening there?)` |
| EINTR | (lwIP には無い) | もう一度 |
| SIGPIPE | (無い) | `MSG_NOSIGNAL` |
| PSA | 必ず `psa_crypto_init()` | Mbed TLS に PSA があるときだけ |

TLS 1.3 のルータが送る NewSessionTicket は「もう一度」として読み捨てる (session を再開しないので)。

### 2.3 Mbed TLS の設定を足す方法

picoruby-mbedtls の `include/mbedtls_config.h` は submodule の中にあり、sim (Linux のビルド) も同じファイルを読む。ファイルは変えず、Mbed TLS の決まった口 `MBEDTLS_USER_CONFIG_FILE` (本体の設定の後に読まれる) で足した。定義はネイティブ版の libmruby の全体 (`conf.cc.defines`) に置いたので、Mbed TLS のライブラリと、それを読むすべての gem が同じ設定で組まれる (構造体の形がずれない)。CMake の側 (hosted.cmake) は Mbed TLS のヘッダを読むソースを組まない。

足したもののうち、既存の利用者に効くのは PSA だけ。digest・cipher は従来の (legacy) 実装が残っているので Mbed TLS はそちらを使い続け、`MbedTLS::Digest` は psa_crypto_init なしで動く (`regress:transfer:quick` の sha256 の照合が通る)。

### 2.4 鍵の権限

console の `.tar` には秘密鍵が入っている。ESP32 にはファイルの権限が無く、遠隔の道具 (devctl の `/fs/get`) が `/home/asterism` を読まないことで守っている (`fmrb_secret_path.h`)。ネイティブ版には遠隔のファイルの口が無いので、残るのは PC の上のほかの利用者。CRuby の Asterism は ssh のように「他人が読める」と警告する。ネイティブ版は警告でなく**締める**ことにした:

- 起動時 (ファイルの層の用意の直後、マシンが動く前) に、利用者の場所の `home/asterism` が他人に開いていれば 0700、その中の `*.tar`・`*.key` が開いていれば 0600 にする。締めたときだけ stderr に 1 行。
- 緩めることはしない。ディレクトリが無ければ作らない。中身は読まない。
- config.toml・receive.toml は鍵でないので触らない (転送のアプリは receive.toml を書き直すたびに 0644 で作るので、全部を締めると毎回 1 行出てしまう。最初の実装はそうなっていたので絞った)。

## 4. GPD に console の .tar を入れる手順 (ユーザ向け)

前提: GPD に L19 を含む .deb を入れる (`rake native:deb ARCH=amd64` で作る。L19 より前の .deb では `tls/` は「TLS is not built in」で止まる)。

1. **console で行を作る**: Admin > Members で、GPD の行を登録する (kind は `client`、名前は GPD のノード ID になる。例 `gpd-micropc2`)。役割 (role) は ESP32 の端末と同じもの。ファイルを受けるなら行の Edit で「Receives files from the console」、console へ送るなら「May send files to the console」に印を付ける。
2. **証明書を出す**: その行の「Issue a certificate」→「Save all (.tar)」。`.tar` は PC のブラウザの中で作られ、ダウンロードされる (例 `gpd-micropc2.tar`)。最後に **Apply** (ACL に入る。Apply の前はルータが何も通さない)。
3. **GPD へ運ぶ** (PC の端末から。ファイルは鍵なので他人の目に触れる場所を経由しない):
   ```
   scp gpd-micropc2.tar <user>@<GPD>:/tmp/
   ssh <user>@<GPD>
   install -D -m 600 /tmp/gpd-micropc2.tar ~/.local/share/family-mruby/home/asterism/gpd-micropc2.tar
   rm /tmp/gpd-micropc2.tar
   chmod 700 ~/.local/share/family-mruby/home/asterism
   ```
   置くのは 1 つだけ (2 つ以上あると名前順で最初のものを使い、その旨を 1 行出す)。権限を付け忘れても、Family mruby の起動時に 0600 / 0700 に締められる。開発用のビルド (`rake native:core`) なら場所は `~/.local/share/family-mruby-dev/home/asterism/`。
4. **ルータ**: パッケージ版は `zenoh_router` が空なので、`.tar` の中の `asterism.json` のルータ (`tls/<クラウドのルータ>:<port>`) がそのまま使われる。`~/.local/share/family-mruby/home/asterism/config.toml` に別の `router = "tcp/..."` を書いていたら消す (config.toml の router が先に効く)。名前 (`name = "..."`) は書いてよい。ノード ID は書いても証明書の名前が勝つ。
5. **確認**: Family mruby を起動し、Shell で `anodes`。1 行目に証明書の名前 (this machine) と、ほかの端末が出る。console の図にも GPD が出る。つながらないときは端末 (Konsole) から起動して stderr を見る: 証明書が別の CA なら `TLS: alert 48 from the router ...`、ルータに届かなければ `TLS: cannot connect to ...`、.tar が無ければ Shell に `needs a credentials .tar in /home/asterism`。
6. **console の受け相手の一覧を受ける** (T6・T7): Shell で `areceive on` (受け取りを有効にする)。console が一覧を送ると receive.toml の managed の部分に入り、`asend -l` で見える。tls/ でつないでいるときだけ受け取る (tcp のルータや peer では断る)。

### 5.2 手元の mTLS (scratchpad の使い捨ての鍵、確認後に全部消した)

- 鍵: console の `Relay::CertAuthority` (読むだけで使った) で CA・ルータ (`zenohd-l19`、SAN に localhost と 127.0.0.1)・端末 3 つ (`gpd-l19`・`mpc-l19`・`pc-l19`)、別の CA とそれが署名した `gpd-l19` を作った。`.tar` は console と同じ形 (`<name>.key`・`<name>.pem`・`ca.pem`・`asterism.json`)。
- ルータ: `eclipse/zenoh:1.10.1` を docker で、`tls/0.0.0.0:7448`、`enable_mtls`、ACL は既定 deny、端末ごとに「自分の名前の下だけ書ける、全部読める、呼ぶのは自分の名前で」(console の role の形を縮めたもの)。
- 端末: ネイティブ版を 2 つ (`fmrb_native.rb up --user-dir <scratchpad>/l19_home/a/user` と b)、利用者の場所は scratchpad の中だけ。`~/.local/share/family-mruby-dev` には触れていない。

| 確かめたこと | 結果 |
|---|---|
| つながる | `zenoh: TLS handshake with 127.0.0.1 (TLSv1.3) took 10 ms`、`Transfer app connected as mpc-l19`、`transfer: mpc-l19/transfer connected (tls/127.0.0.1:7448, 26 ms)` |
| 権限 | 0755 の dir と 0644 の .tar が `native: /home/asterism was open to others (0755); now 0700`、`.../gpd-l19.tar holds a key and was open to others (0644); now 0600` に |
| ノード ID | `asterism: the certificate's name gpd-l19 is the node ID (not imposter)`。試しのアプリが `asterism/gpd-l19/l19probe/own` と `asterism/mpc-l19/l19probe/forged` に 20 回ずつ put、CRuby の pc-l19 (同じルータに tls/、`asterism/*/l19probe/**` を購読) に届いたのは own の 20 回だけ |
| anodes | A の Shell に `anodes: 2 machine(s) on Asterism`、gpd-l19 (this machine) と mpc-l19 |
| asend | `asend mpc-l19 /home/l19note.txt` → `is in mpc-l19's /home/inbox as l19note.txt`、B の `home/inbox/l19note.txt` の中身が一致 |
| amove | `amove 6 mpc-l19` → A から Ckpt Counter が消え、B で `ckpt_counter: main=110` から数え続けた |
| console の一覧 | B の config.toml に `console = "pc-l19"`、CRuby の pc-l19 (tls/) から `policy_set` → `{"ok"=>true, "written"=>true, ...}`、B の receive.toml に `[managed] by = "pc-l19"` と file・checkpoint の一覧 |
| 別の CA の証明書 | `TLS: alert 48 from the router: the router refused this machine's certificate (not signed by the router's CA?)`、Shell は `could not connect to Asterism (cannot open a session to tls/127.0.0.1:7448 (-99))`。ルータ側は `invalid peer certificate: UnknownIssuer` |
| .tar なし | Shell に `not on Asterism: tls/127.0.0.1:7448 needs a credentials .tar in /home/asterism` |
| 証明書を出さない相手 (参考、openssl) | ルータは `alert certificate required` (116) で断る。ネイティブ版の口はこの alert を「the router wants a client certificate and got none」と読む |

TLS 1.3 では、端末の側の握手は相手が証明書を確かめる前に終わる。よって別の CA の場合も「handshake ... took 11 ms」の行が先に出て、その直後の最初の読みで alert 48 が来る (g2a 2.3 と同じ)。

### 5.3 sim・ブラウザ版

組み直しての確認はしていない。変わらない理由:

- sim (POSIX、TLS なし) とブラウザ版 (ZENOH_EMSCRIPTEN): gem の `tls_stream.h` は TLS なしでは zenoh-pico の元のものと同じ (どちらも include 2 つだけ)。zenoh-pico の `tls.c`・`tls_stream.c` は TLS なしでは空だったものを組まなくなっただけ。`ports/posix/zp_tls_posix.c` は TLS なしでは空。gem の host test (POSIX、TLS なし) は 130 checks 全部通過。
- Mbed TLS の設定に足したもの (`MBEDTLS_USER_CONFIG_FILE`) は `family_mruby_native.rb` の中だけ。sim の `family_mruby_linux.rb`・ブラウザ版の `family_mruby_wasm.rb` は変えていない。
- ESP32: gem の ESP-IDF 向けの出力は同じ (ガードの書き方が変わっただけ)。ESP-IDF の部品が組む `ports/esp32` の 3 本は変えていない。

## 6. 取り下げた仮説・案

- **ホストの libmbedtls を .deb の依存にする** (plan の案): 取らなかった。ネイティブ版の libmruby には picoruby-mbedtls が Mbed TLS 3.6.2 を組み込んでいて、ホストの libmbedtls (Ubuntu 26.04 の 3.6 系) を足すと `mbedtls_*` の同じ名前の関数が 2 組になる (どちらが結ばれるかがリンクの順で決まり、設定の違う構造体が混ざる)。名前を変えて逃がす手間に見合う利点が無く、組み込みの設定に足す方が依存も増えない。
- **組み込みの Mbed TLS の設定のままで足りる**: 足りない。TLS 1.2 だけで、zenohd は mTLS のとき TLS 1.3 だけを受ける (g2a で `SupportedVersionsExtensionRequired` を確認済)。
- **picoruby-mbedtls の `mbedtls_config.h` を lib/patch で差し替える**: sim も同じファイルを読むので、sim まで変わる。`MBEDTLS_USER_CONFIG_FILE` をネイティブ版だけに渡す形にした。
- **docker の zenohd を `--network host` で手元から見る**: WSL2 の docker では手元の 127.0.0.1 に出てこない (つながらない)。`-p 127.0.0.1:7448:7448` にした。この取り違えで「TLS open failed」とだけ出て理由が分からなかったので、口に `TLS: cannot connect to ...` の行を足した。
- **`/home/asterism` の config.toml 以外を全部締める**: 鍵の場所の決まり (`fmrb_secret_path.h`) には合うが、転送のアプリが receive.toml を 0644 で書き直すたびに起動時の行が出る。`*.tar`・`*.key` だけにした。

- **gem の push**: `15b0ff4` を GitHub に push してから fmruby-core を push する (3 章)。

- **2 つの口の重なり**: `zp_tls_posix.c` は `zp_tls_esp32.c` と 9 割同じ。alert の名指しと「つながらない」の行は POSIX だけなので、ESP32 にも入れるなら共通の部分を 1 つにまとめる機会。
- ~~**profile の host が「sim」**~~: 直した (2026-11-12、8 章)。
- **鍵の置き場所を選ぶ画面**: 今は手で `install` する。設定の画面から .tar を選んで置く口 (ESP32 の BLE の設定の Window に当たるもの) はネイティブ版に無い。

## 8. 追記: profile の host を「native」に (2026-11-12)

ネイティブ版は anodes・console の図の詳細・受け取りのアプリの近くの一覧・デスクトップの相手の一覧で「sim」と名乗っていた。BOARD がネイティブ版でも sim でも `linux` で (Linux の口を共有し、`BOARD == "linux"` で分けている所が 26 箇所ある)、`FmrbAsterism::HOSTS` がそれを sim と読んでいたため。

- **何と名乗るか: `native`**。host は「どこで動くか」(`atoms3r`・`tab5`・`p4nano`・`browser`・`sim`) で、sim・ブラウザ版は機種でなく作りの名を言っている。ネイティブ版もそれに揃えた。機種の定義の名 (`sdl`・`linux_pc_wl`) は描き方・入力の口の名で、相手から見て意味が薄い。長さも、受け取りのアプリの一覧が切る 12 バイトに収まる (`cardputer_zero_hdmi` は収まらない)。
- **見分け方**: `FmrbConst::NATIVE` を足した (const.c。`FMRB_PLATFORM_NATIVE` のある作り、つまりネイティブ版だけ true)。BOARD は `linux` のまま変えない。`FmrbAsterism.host` は NATIVE が真なら `native`、それ以外は今までどおり BOARD から (sim は `sim`、ブラウザ版は `browser`、ESP32 は機種の名)。NATIVE の無い古い作りや、FmrbConst を自前で用意する host の試験でも落ちないよう `const_defined?` を見る。
- **使う側**: host は表示に使うだけで、決まった値の一覧と照らす所は無い。console (読んだだけ、変えていない) は印 (▣) を kind (`family_mruby`) から決め、host は詳細の「Host」に文字のまま出すので、`native` と出る。受け取りのアプリの近くの一覧 (transfer.app.rb) とデスクトップの相手の一覧も文字のまま。avatar の訪問先は mDNS 名 (`FmrbAsterism.hostname`) で host は使っていない。
- **console に足すとよいもの (提案)**: 文書 docs/v2_5.md の ▣ の説明「a board, the Linux sim or the browser build」にネイティブ版を足す。asterism gem の README の host の例 (`atoms3r`、`tab5`、`p4nano`、`browser`、`sim`) にも `native` を足せる。どちらも動きには関わらない。

確認:

| 確かめたこと | 結果 |
|---|---|
| host の試験 (`rake asterism:config_test`、test/asterism/run.rb に 6 件) | sim・native・browser・p4nano・tab5・NATIVE の無い作り、全部通過。直す前の gem では「the native program says native: got "sim"」で落ちる |
| ネイティブ版 2 つ (手元の zenohd、sdl の機種) | CRuby の `asterism node info` が両方とも `kind=family_mruby ... host=native`。A の Shell の anodes が `rg-host-a  native, family_mruby (this machine)` と `rg-host-b  native, family_mruby` |
| `rake regress` 5 回、`rake regress:transfer:quick` | 全部通過 |

| sim (`rake clean` から組み直し、Retro) | Shell の anodes が `linux  sim, family_mruby (this machine)` |

ブラウザ版は組み直して見ていない。const.c の NATIVE は `FMRB_PLATFORM_NATIVE` が無ければ false で、それを定義するのは `family_mruby_native.rb` だけ (ブラウザ版の `family_mruby_wasm.rb` には無い)。host の試験が NATIVE が false のときの browser を押さえている。
