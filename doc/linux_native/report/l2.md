# L2 報告: 受け口の実装と機種の定義 (fbdev・DRM・evdev・ALSA)

> 状態: 完了 (受け入れ 6 点。装置を開く部分は WSL2 ではビルドと断りの確認まで、実機は L0・L3) | 更新: 2026-10-26 | 指示書は instruction_l2.md。ブランチは両リポジトリとも feature/linux-native (develop へは未マージ・未 push)

## 機種の定義

### 置き場所と選び方

- 正は `config/machines/<名前>.toml`。`rake native:etc` (native:core が先に流す) が
  `native/build/root/machines/` へ写す。system_conf と同じく config/ が正で、
  flash/ には置かない。
- 起動の引数で選ぶ: `--machine <名前またはパス>` (環境変数 `FMRB_NATIVE_MACHINE`)。
  `/` を含むか `.toml` で終わればパス、それ以外は `--machines-dir`
  (既定 `native/build/root/machines`、`FMRB_NATIVE_MACHINES_DIR`) の `<名前>.toml`。
  `--machine` を付けなければ `sdl`。`sdl.toml` が置かれていなければ、同じ中身の
  組み込みの定義で動く (L1 と同じ)。
- 定義の上に 1 項目ずつ重ねる: `--set 区画.項目=値` (何度でも)。L1 の
  `--scale` / `FMRB_NATIVE_SCALE` は `display.scale` を上書きする形で残した。
  順は「ファイル → `--set` → `--scale`」。
- 断るときは `native: refused: machine <名前>: <何で>: <理由>` を出して終了コード 3
  (引数の誤りは 2、動いてからの失敗は 1)。断りは機械 (FreeRTOS) を起こす前に
  すべて済ませる。
- 用意した定義: `sdl` (開発用、L1 と同じ)、`cardputer_zero` (fbdev・evdev・ALSA、
  320x170 なので起動時に断る)、`cardputer_zero_hdmi` (DRM 1280x720・evdev・ALSA)、
  `linux_pc_drm` (DRM 推奨モード・evdev・ALSA)。

### 項目名 (確定)

plan.md の例から変えたのは `[display]` の `mode` `rotate` `scale`、`[input]` の
`keymap_device`、`[audio]` の `device` `latency_ms` を足したこと。`[screen]` の
`form` と `[desktop]` の `variant`、`[system]` の 2 つは plan のまま。

| 区画 | 項目 | 値 | 既定 (sdl) |
|---|---|---|---|
| (頭) | `description` / `name` | 文字列。name を書かなければファイル名 | |
| `[screen]` | `form` | `"426x240"`。`"320x170"` は読めるが起動時に断る (L4) | 426x240 |
| `[display]` | `backend` | `sdl` / `fbdev` / `drm` (`wlr` は「L8」と断る) | sdl |
| | `device` | fbdev: `"auto"` (最初の fb)・`"auto:<名前>"` (/proc/fb の名前)・パス。drm: `"auto"` (card0..15 の最初の接続済み)・パス | auto |
| | `mode` | drm: `"auto"` (推奨モード)・`"WxH"`・`"WxH@Hz"`。無ければ推奨モードに落とす | auto |
| | `rotate` | 0 / 90 / 180 / 270 (時計回り) | 0 |
| | `scale` | `"auto"` か 1-16。sdl では窓の倍率 (auto = 3)、fbdev・drm では固定の倍率 (auto = 収まる最大の整数倍。固定が収まらなければ収まる最大へ) | auto |
| `[input]` | `backend` | `sdl` / `evdev` (`wlr` は「L8」と断る)。注入のソケットはどれでも常に付く | sdl |
| | `devices` | evdev: `["auto"]` か装置のパスの並び (by-path も可) | ["auto"] |
| | `keymap` | `""` か `"cardputer_zero"` | "" |
| | `keymap_device` | 追加の表を当てる装置の evdev の名前に含まれる文字列 | "" |
| `[audio]` | `backend` | `sdl` / `alsa` / `none` | sdl |
| | `device` | alsa: PCM の名前 | "default" |
| | `latency_ms` | alsa: 装置の溜め (10-2000) | 100 |
| `[desktop]` | `variant` | `mouse`。`keys` は「L4」と断る | mouse |
| `[system]` | `services` | `none` / `linux` (受け付けるだけ。L6) | none |
| | `exit_key` | `none` / `esc_long` (受け付けるだけ。L5) | none |

知らない区画・項目は、ファイル名と項目名を付けて断る (`display.flip` など)。

### 選ぶ所は 1 か所

`native/backend/native_backends.c` が定義を受け口に変える唯一の所。出力
(`native_output_t`: open / pump / present / close) と音 (`native_audio_sink_t`:
open / close) は表で引き、入力は機械の入力の源の表 (`fmrb_input_sources`) を
定義から組む (evdev か sdl、それに注入)。そのビルドに無い受け口
(libdrm・libasound 無しでビルドしたもの、後の段のもの) は理由を付けて断り、
SDL に替えることはしない。上の層 (display_backend_native・audio_backend_native・
入力の源の起動) は何が動いているかを知らない。

- `hosted/backend/input_source.h` の `fmrb_input_sources` を配列からポインタに
  した (native は起動時に組む)。wasm は 1 行の書き換えで、中身は同じ。
- 主スレッドの回り方は `main_native.c` の 1 つの輪に寄せた: 出力の `pump`
  (SDL のイベント、DRM の flip 完了を待つ)、新しい画面があれば `present`、
  制御のソケット、終了のシグナル (SDL 以外は自前の SIGINT/SIGTERM の旗)。
  L1 の host_sdl.c は `native/output/output_sdl.c` になり、SDL の音は
  `native/audio/audio_sdl.c` に分けた。
- 制御のソケットの `info` は機種の名前も返す (`OK w h seq pid machine`)。

## 受け口ごとの分け目 (中身の処理 / 装置を開く部分)

| 受け口 | 中身の処理 (host 試験あり) | 装置を開く部分 (ビルドと断りまで) |
|---|---|---|
| 拡大・黒帯・回転 | `native/present/fmrb_present.c`: 面 (`pixels`・幅・高さ・行のバイト数・形式・回転) を受けて置き場所を決め、描く。RGB565 と XRGB8888。回転は「物理の面の画素 → 見え方 → 画面」と逆にたどる。点の逆変換 (`to_frame`) も回転を考える | なし (各出力が自分の面を渡す) |
| fbdev | `native/output/fbdev_info.c`: /proc/fb の文字列から名前で番号を引く、`fb_var_screeninfo`/`fb_fix_screeninfo` から形式 (RGB565・XRGB8888 以外は理由つきで断る)・行の長さ・見えている所の位置 (xoffset/yoffset) を出す | `native/output/output_fbdev.c`: /proc/fb を読む、開く、ioctl 2 つ、mmap、変わった画面だけ描く |
| DRM | 描くのは present の共通部品 (XRGB8888) | `native/output/output_drm.c`: カードを探す、dumb buffer の有無、接続済みの出力、モード (定義 → 推奨 → 先頭)、CRTC、主導権 (`drmIsMaster`/`drmSetMaster`)、dumb buffer 2 枚、`drmModeSetCrtc`、page flip (完了は pump の poll で受ける)、終了時に元の CRTC へ戻す |
| キーの表 | `native/input/linux_keys.c` (KEY_* → HID、修飾の bit)、`native/input/keymap_cardputer_zero.c` (Sym の層、`keymap_extra.h` で名前から引く) | なし |
| evdev | `native/input/evdev_decode.c`: `struct input_event` の並び → キー (修飾は装置ごと、自動の繰り返しは捨てる)、相対移動 (USB マウスと同じ規則: 中央から、mouse_scale と端数の持ち越し、高解像度では画面比で拡大、端で止める)、ボタン・ホイール (1 つの報告の中では移動 → ボタン → ホイールの順)。非ブロッキングの fd から読む `evdev_drain_fd` もここ (パイプで試験できる) | `native/input/input_evdev.c`: /dev/input/event* を番号順に開いて EVIOCGBIT でキーボード (KEY_A と KEY_Z) とマウス (REL_X/Y と BTN_LEFT) を選ぶ、パス指定、EVIOCGNAME で追加の表を当てる装置を決める。FreeRTOS のタスクが 10 ms ごとに読む |
| ALSA | 試験は file プラグインを通した結合 (受け入れ 4) | `native/audio/audio_alsa.c`: `snd_pcm_open`・`snd_pcm_set_params` (15720 Hz・mono・S16、soft resample 可、latency_ms)、専用のスレッド (FreeRTOS の外) が L1 のリングから 256 標本ずつ取って `snd_pcm_writei`。詰まりは `snd_pcm_recover`。書き込みが待たない出口 (ファイル・null) でも走り過ぎないように壁時計で歩調を取る。機械の側は今までどおりリングに書くだけで、待たない |
| 機種の定義 | `native/machine/native_machine.c` (tomlc99 と libc だけ) | なし |

装置が無いときの断り (WSL2 で実際に出たもの):

| 何で | 理由 |
|---|---|
| fbdev | `no /proc/fb (No such file or directory): this system has no framebuffer` |
| DRM | `/dev/dri/card0 has no dumb buffers (not a display controller)` (WSL2 の card0 は描画用で KMS が無い) |
| evdev (auto) | `no evdev devices: /dev/input has no event* nodes (...)` |
| evdev (パス) | `input device /dev/input/mice: Permission denied (the user needs the input group, or root)` |
| ALSA | `cannot open the ALSA device "default": No such file or directory (no sound card, or the name is not in the ALSA configuration)` |
| 未対応の形 | `screen.form 320x170 is not supported yet (the 320x170 screen and the keyboard-only desktop come in L4); this build runs 426x240 only` |
| 後の段 | `display.backend "wlr": the wlroots output comes in L8` |

DRM の主導権が取れないときの文 (`cannot become the DRM master of ... another program -- a desktop, a compositor, X -- holds the display, or this session is not on the console`) は、WSL2 では KMS の無いカードで手前に止まるので出せていない。実機 (L3) で確かめる。

## Cardputer Zero のキーボードの表

- 元: M5Stack の m5stack-linux-dtoverlays (2026-09-23 のコミット 75518549) の
  `modules/CardputerZero/cardputerzero-v5-overlay.dts` (`linux,keymap` / `keymap1` /
  `keymap2`) と `modules/tca8418-1.0/tca8418_keypad_m5stack_keymap.map`。
  リポジトリの外 (scratchpad) に取得して読んだ。取得物はリポジトリに入れていない。
- 層はカーネルのドライバ (tca8418_keypad_m5stack) が切り替える。plain (`keymap`) と
  Fn (`keymap2`: F1-F12・矢印・Home/End/PgUp/PgDn・Insert・Delete・音量) は普通の
  キーコードで届くので Linux のキーコードの表で足りる。Sym (`keymap1`) だけが
  他のキーのキーコードを借りて届き (`!` が KEY_LEFTBRACE、`` ` `` が KEY_NUMLOCK、
  `-` が KEY_KP7 ...)、コンソールの表がそれを文字にしている。この 32 個を
  「US の HID usage と Shift の要否」の表にした (`keymap_cardputer_zero.c`)。
  Sym・Fn のキー自身 (KEY_CD 0x17f・KEY_DVD 0x185) は飲み込む。
- 表を当てる装置は、定義の `keymap_device` (cardputer の定義では `"tca8418"`) を
  evdev の名前に含むものだけ。HDMI の形で同時に挿す USB キーボードの `[` が `!` に
  ならないため。その装置のキーは全部 US として送る (`fmrb_host_send_key_*_us`、
  Tab5 の内蔵キーボードと同じ扱い)。記号が keyboard_layout (既定 jp) に左右されない。
- 試験は、コンソールの表の 32 行 (キーコードと文字) を試験の中に写し、表の
  usage と Shift をファームウェアの US の表 (`fmrb_keymap_scancode_to_char`) に
  通して同じ文字になることを見る。

## host 試験 (`rake native:test`、`rake test` に入れた)

`test/native/main.c` 1 本、383 項目。

- present: RGB565・XRGB8888 × 0/90/180/270 度 × 6 つの形 (1280x720 に 426x240 は 3 倍、
  640x360 は 2 倍、固定の倍率が収まる・収まらない、320x170 の等倍、面より大きい画面の
  切り取り)。行の終わりに余白のある面で、全画素を定義から計算した値と比べ、余白に
  書いていないことも見る。`to_frame` が描いた画素と同じ所を指すことも見る。
  置き場所の数値 (1280x720 で x=1、1920x1200 で 4 倍の (108,120)、縦の面を 90 度で
  1280x720 の見え方) も。
- Linux のキーコードの表: 英字・数字・記号の 48 キーを US の表に通して刻印と比べる、
  特殊キー・修飾・日本語のキー・F13-F24 の usage、HID の外のキーは 0、2 つのキーが
  同じ usage を持たない (半角/全角の 0x35 だけ例外)、修飾の bit。
- evdev: `test/native/evdev/*.ev` (1 行 1 イベントの文字の記録と、期待する呼び出しの並び)

  クリックの位置・右ボタン・ホイール・端・SYN_DROPPED)、hires (640x360 で画面比の拡大)、
  cardputer (plain・Sym・Fn と、Shift を押したままの `&`)。閉じたパイプが「装置が
  消えた」になることも。
- Cardputer の記号の層: 上の 32 行。
- fbdev: /proc/fb の名前引き、st7789v の RGB565 320x170、XRGB8888 で yoffset の
  ある面、BGR・24 bit・パレット・短いメモリを断る。
- 機種の定義: config/machines の 4 つを読み、`sdl.toml` が組み込みの既定と同じこと、
  cardputer_zero が 320x170 で断られること、`--set` の値の検査、知らない項目を

mouse.ev の期待を 1 行変えてその行が落ちることで確かめた (どちらも戻した)。

## 確認の道具

- `tools/fmrb_native.rb up` に `--machine`・`--set`・`--alsa-file` を足した。
  断られたときは、その 1 行 (`fmrb_native: refused: machine ...`) を出して終わる。
  `--alsa-file` は run dir に asoundrc (既定の PCM を file プラグイン + null、raw) を
  書いて `ALSA_CONFIG_PATH` で渡し、`--set audio.backend=alsa` を付ける。音は
  SDL の disk と同じ `<run>/audio.raw` に出るので `audio` でそのまま測れる。
  `status` は機種も出す。
- MCP: `native_up` (machine・engine・set・alsa_file・gui) / `native_down` /
  `native_screenshot` / `native_input` / `native_app` (tools/mcp/lib/native.rb、
  中身は fmrb_native.rb)。動いているものは再利用し、自分で起こしたものでなければ
  `native_down` は force を求める (sim と同じ決まり)。selftest に
  `selftest_native.rb` を足した (偽の fmrb_native.rb で 15 項目)。
  README とルートの CLAUDE.md の表に 1 行。
- 回帰: `rake regress:screens` に構成 `native` (標準構成、機種 `sdl`)。場面は
  `desktop` と `editor_type`。ビルドは sim・ブラウザ版の後に `rake native:mruby`・
  `native:core` (ブラウザ版を流さないときは `spinel:gen` も)。run dir
  `/tmp/fmrb-native-regress-<uid>`・debug の port 5575・利用者とキャッシュの場所は
  `tmp/regress/screens/native_home/` を毎回空から使うので、人のネイティブ版と並べて
  動く。`--attach native` は人が起こしたもの (`/tmp/fmrb-native-<uid>`) に流す。
  doc/regression/usage.md の 9 章に書いた。

## 実機で確かめる点 (L0・L3 へ)

- fb: Cardputer の /proc/fb に `fb_st7789v` の名前で出るか、番号。
  `FBIOGET_VSCREENINFO` の形式 (RGB565 で red 11/5・green 5/6・blue 0/5 か。BGR なら
  断るので表を足す)、`line_length`、xres/yres が 320x170 か (縦置きで 170x320 なら
  `rotate`)。fbtft の deferred I/O で、mmap への書き込みだけで LCD が更新されるか、
  更新の速さ。
- DRM: Cardputer の HDMI が `card0`/`card1` のどちらか (vc4 は card1 のことがある)、
  接続済みとして見えるか、1280x720 が出るか、`drmModeSetCrtc` が通るか、
  APPLaunch から起動したとき主導権が取れるか。page flip が使えるか (使えなければ
  SetCrtc に落とす作りにした)。終了後に元の画面に戻るか。
- コンソールの上で fbdev・DRM を使うとき、VT の文字の画面 (fbcon) とキー入力の
  扱い (KD_GRAPHICS・キーボードの mode) は何もしていない。打ったキーが VT にも
  届く・カーソルが上書きする、が起きたら L3 で足す。
- evdev: 内蔵キーボードの evdev の名前 (i2c のクライアント名、`tca8418` を含むか)、
  `/dev/input/cardputer-zero-internal` の udev の symlink と `ID_SEAT=seat-cardputer-zero`
  の意味 (別の seat にしてある。権限 `input` グループ・0660)。`auto` がキーボードと
  マウス以外 (電源ボタン・IMU) を拾わないか。APPLaunch が装置を開いたまま・掴んだ
  ままか (掴む `EVIOCGRAB` はしていない)。Sym 層の Shift の位置は KEY_KPPLUS を送り、
  コンソールの表に無いので、今はテンキーの `+` として届く。Sym を押したまま他の
  キーを押したときの順 (KEY_CD が先に届くか)。
- ALSA: ES8389 の PCM の名前 (`default` で鳴るか、`hw:` の番号)、15720 Hz を
  plug が変換するか、100 ms で詰まらないか、HDMI の音を選ぶ名前。

## 見立てと違った点・撤回した仮説・踏んだ罠

- WSL2 にも `/dev/dri/card0` はある (描画用の装置で KMS は無い)。DRM の「装置が
  無い」は「dumb buffer が無い」で断られる。主導権の断りは WSL2 では出せない。
  `/dev/input` には `mice` だけがあり (root 専用)、event* は無い。`/proc/fb` は無い。
- 切り替えの形 (Sym・Fn) はカーネルのドライバが持つと計画にあったとおり。
  ただし記号が「独自のキーコード」ではなく「他のキーのキーコードの借用」だった。
  そのため表は装置で絞らないと USB キーボードを壊す (`keymap_device` を足した)。
- 試験で、L1 の XRGB8888 の変換 (`*255/31`) を bit の複製に替えた (端の値は同じ、
  中間で 1 違うことがある)。L1 では XRGB8888 はどこも使っていなかった。
- 回帰の場面の helpers.rb は窓の題の色を sim の RGB332 の値で持っていた。ネイティブ版の
  写しは RGB565 そのものなので値が違い (sim [218,36,85]、native [222,36,82])、
  最初の流しでエディタの窓を見つけられなかった。`native?` で分けた。
- ALSA の file + null は書き込みで待たない。壁時計の歩調が無いとスレッドが CPU の
  速さでファイルを埋めるので、歩調を入れた (実装の時点で入れたので、無い場合は
  試していない)。

## 残件

- 抜き差し: evdev は起動時に見つけた装置だけ。抜けたら閉じてログに出す。
  挿したものを拾うのは後の段 (inotify か udev)。
- タッチパッド・タッチパネル (EV_ABS) は読んでいない。PC の (3) は libinput (wlroots)
  が受け持つ見込みなので、evdev で要るかは L3・L7 で決める。
- `[system]` の `services`・`exit_key` は受け付けて「未実装」とログに出すだけ (L5・L6)。
- DRM のハードウェアカーソルは使っていない (ポインタは機械が描く。今までどおり)。
- fbdev の縦横の入れ替えと 320x170 そのものの描画は L4・L5。
- ネットワーク (L2n) は手を付けていない。
