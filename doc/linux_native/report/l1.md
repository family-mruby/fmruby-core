# L1 報告: Linux ネイティブ版の土台 (x86_64・SDL・ファイルの振り分け)

> 状態: 完了 (受け入れ 8 点。7 の目視はユーザ) | 更新: 2026-10-26 | 指示書は instruction_l1.md。ブランチは両リポジトリとも feature/linux-native (develop へは未マージ・未 push)

## 何をどこに置いたか

### ディレクトリ

| 場所 | 中身 |
|---|---|
| `hosted/` (新設) | ブラウザ版とネイティブ版が共有するもの。「1 プロセス・ESP-IDF なし・Modern の表示タスクが同じプロセス」という形を hosted と呼ぶ |
| `hosted/hosted.cmake` | core の共通ソース一覧・インクルード・定義、FreeRTOS (`freertos_hosted`)、LovyanGFX (`lgfx_hosted`)、`fmrb_hosted_core_objs()` |
| `hosted/port/` | 協調 FreeRTOS port (wasm/port から移した)。時刻と眠りだけ `port_clock.h` の受け口に寄せ、`port_clock_wasm.c` / `port_clock_posix.c` を選ぶ |
| `hosted/stub/`, `hosted/vendor/freertos*` | wasm/ から移した (中身は同じ) |
| `hosted/backend/` | 共有の受け口の実装: ソフト MJPEG (`display_video_soft.c`)、JPEG エンコーダのスタブ、LovyanGFX の時計、入力の取り込み (`input_source.h` / `input_hosted.c`) |
| `hosted/vendor/m5gfx/` | LovyanGFX の取得先 (git 管理外)。旧 wasm/vendor/m5gfx は `rake hosted:m5gfx` が移す |
| `native/` (新設) | ネイティブ版。`CMakeLists.txt`、`backend/` (SDL・入力・音・制御ソケット・PNG・main)、`present/` (拡大・黒帯の共通部品) |
| `rakelib/hosted.rake` | 共有の rake 側: `hosted:m5gfx`、バイトコードの作り直し (`hosted_regen_mrb!`) |
| `rakelib/native.rake` | `native:mruby` / `native:mrb` / `native:etc` / `native:core` / `native:run` / `native:clean` |
| `lib/add/family_mruby_native.rb` | ネイティブ版の libmruby (host の gcc、64 bit、`MRB_TASK_TICK_SELF_SUPPLY`) |
| `lib/add/hal-dir-fmrb/` | 名前だけの gem。mruby-dir の posix port (平らな flash/ 前提) を外す |
| `config/system_conf_native.toml` | Modern。sim の Modern 用 (system_conf_linux_p4.toml) に `max_apps = 32` を足したもの |
| ルートの `tools/fmrb_native.rb` | 起動・停止・画面・入力・アプリ・音・ログ |

### 作り方と動かし方

```
# fmruby-core で
rake native:mruby                      # 1 回 (lib/ を触ったら作り直す)
rake native:core                       # 標準構成 -> native/build/fmruby-native
rake native:core NATIVE_ENGINE=mruby   # 全 mruby -> native/build-mruby/fmruby-native
rake native:run                        # 窓で起動 (WSLg)。ARGS="--scale 2" など

# ルートで (ヘッドレス)
ruby tools/fmrb_native.rb up [--engine mruby] [--gui] [--user-dir D] [--cache-dir D]
ruby tools/fmrb_native.rb shot out.png
ruby tools/fmrb_native.rb input click 30 5 sleep 600 click 30 31
ruby tools/fmrb_native.rb app ps | spawn /app/test/hires_test.app.rb | kill 6
ruby tools/fmrb_native.rb audio 2
ruby tools/fmrb_native.rb status | log | down
```

- 前提: `rake spinel:gen` の生成物 (main/prebuild_scripts/spinel/gen) と、
  mrbc (どれかのビルドが一度作るもの)。ninja は使わない (cmake の既定の Makefile)。
- `native:core` は `native:mrb` (古いバイトコードの作り直し、lib/add が新しければ
  libmruby も) と `native:etc` を先に流す。
- ヘッドレスは `SDL_VIDEODRIVER=dummy`、音は `SDL_AUDIODRIVER=disk` で
  `<run>/audio.raw` に出る (fmrb_native.rb up が設定する)。

### プログラムの形

- 主スレッド (FreeRTOS の外): SDL の窓・イベント・音の装置と制御ソケット。
  機械とは 3 つの口でだけ話す: `native_frame` (画面、mutex つきの RGB565)、
  `native_audio` (音、ロックなしの 1 対 1 のリング)、入力のリング。
  ブラウザ版のページと wasm の機械の関係と同じ。
- 機械: FreeRTOS のタスク全部。専用のスレッドから `vTaskStartScheduler` に入る。
  シグナルは使わない (SIGALRM なし)。SDL と同じプロセスで衝突は出ていない。
- 起動の引数・環境変数: `--scale` (既定 3)、`--user-dir`
  (既定 `$XDG_DATA_HOME/family-mruby-dev`、無ければ ~/.local/share/...)、
  `--cache-dir` (~/.cache/family-mruby-dev)、`--system-dir` (リポジトリの flash/)、
  `--etc-seed` (native/build/root/etc)、`--run-dir` (/tmp/fmrb-native-<uid>)。
  それぞれ `FMRB_NATIVE_*` の環境変数でも渡せる。
- run dir: `ctl` (制御ソケット: shot / info / quit)、`inject` (入力の注入)、
  `pid`、tools が置く `core.log` と `audio.raw`。
- debugd は TCP 5565 (sim は 5555)。`FMRB_DEBUG_TCP_PORT` で変えられる。
  `fmrb_dbg_client.py --json localhost:5565 ps` で使える。

## 共有化のために変えた所

### wasm

- wasm/port・wasm/stub・wasm/vendor/freertos* を hosted/ へ移し、
  wasm/CMakeLists.txt は hosted.cmake を include して自分の受け口 (main・page
  設定・RGBA 表示・音のリング・入力のリング・libc の補い・zenoh) だけを足す形にした。
  ソース一覧は 1 つ。
- port の Emscripten 依存は `emscripten_get_now` / `emscripten_thread_sleep` の
  2 つだけだった (見立てどおり)。`port_clock.h` に寄せた。タスクのスタックの
  下限・倍率は `portHOSTED_*` のマクロにし、native は 4 倍・下限 256 KB
  (wasm は従来どおり 1 倍・64 KB)。
- LovyanGFX の分岐名 `FMRB_LGFX_WASM` を `FMRB_LGFX_HOSTED` に。取得済みの
  clone は `hosted:m5gfx` が書き換える。
- `display_video_wasm.c` は wasm 固有の所が無かったので
  hosted/backend/display_video_soft.c に (ログのタグ `wasm_video` は `soft_video`)。
- エンジンの選択 (`FMRB_KERNEL_ENGINE` ほか) は CMake の変数だけで受ける。
  rake の環境には .env の端末向けの値が入っているので、環境変数を読むと
  ブラウザ版の中身が .env で変わってしまう。wasm は従来どおり常に標準構成。
- libmruby (family_mruby_wasm.rb) に `FMRB_PLATFORM_HOSTED=1` を足した。

### 定義の整理 (main・components)

`FMRB_PLATFORM_WASM` で分けていた所を読み直し、3 つに分けた。

| マクロ | 意味 | 使う所 |
|---|---|---|
| `FMRB_PLATFORM_HOSTED` | 1 プロセス・IDF なし (wasm と native) | host_task の表示経路、display_local の HW 部分、fmrb_app の画面モード、ログの port、fmrb_attr、local link の API、gfx.c の動画、boot の表示・音の初期化 |
| `FMRB_RTOS_COOPERATIVE` | 協調 port | sim_log_guard とシグナルの診断を飛ばす、debugd の TCP の待ち方 |
| `FMRB_PLATFORM_WASM` / `_NATIVE` | それぞれ固有 | 画面の受け口の選択、debugd を起動しない (wasm だけ)、起動ログの 1 行 |

sim と端末はどれも定義しないので、生成されるコードは変わらない。

### ファイル (posix の file HAL)

- `fmrb_hal_file_resolve_path` に振り分けの表を 1 つ置いた
  (`fmrb_hal_file_posix.c`)。表は 2 つあり、既定は「全部を書き込める flash/ へ」
  (sim とブラウザ版。出力は従来と 1 文字も変わらない)、native は
  `fmrb_hal_file_set_layout()` (fmrb_hal_file_layout.h) で層の表に切り替える。

  | 場所 | 実体 | 書き込み |
  |---|---|---|
  | `/app/usr`, `/home`, `/etc` | 利用者 | 可 |
  | `/var`, `/cache`, `/data`, `/tmp` | キャッシュ | 可 (`/tmp` は従来の容量の勘定つき) |
  | それ以外 (`/usr` `/lib` `/bin` `/boot` `/help` `/app` ...) | 配布物 (flash/) | 不可 |

- 層の表では仮想パスを正規化 (`.`・`..`・`//`) してから引く。`..` は根で止まる。
- 書き込み・消去・改名・mkdir・rmdir・utime・chmod は表を見て、配布物の側なら
  `FMRB_ERR_READ_ONLY` (fmrb_err.h に足した) を返す。利用者の側へは逃がさない。
- 「Linux の実ファイルへ素通し」は `ROOT_HOST` という種類だけ用意し、表には
  載せていない (L7)。
- `/etc` は初回に `native/build/root/etc` から写す (`native:etc` が
  config/system_conf_native.toml ほかを置く)。
- `/` と `/app` の一覧には利用者・キャッシュの側の名前を足す
  (`fmrb_hal_file_virtual_children`)。
- HAL を通らずに libc で開いていた所も表を通すようにした:
  `host_file_local.c` (hosted では resolver を使い、書き込み・消去は読み出し専用の
  判定を先に)、`audio_p4_*` (`audio_p4_resolve_path`)、tmpfs (自分の置き場を
  resolver に聞く)。読み出し専用の判定は `fmrb_hal_file_path_is_read_only()` として
  HAL の公開 API にし、ESP32 側は常に false を返す。
- mruby の Dir: mruby-dir の posix port は自前で "flash" を前に付ける。native は
  名前だけの gem `hal-dir-fmrb` でそれを外し、ESP32 と同じ
  lib/add/hal-esp32-dir/dir_hal.c (HAL の resolver と仮想の子を使う) を
  CMake でコンパイルする。dir_hal.c には `DIR_HAL_PATH_MAX` の上書きと
  mkdir/rmdir の読み出し専用の判定を足した。

### その他

- debugd の TCP: ポートを `#ifndef` にし (native は 5565)、協調 port では
  `select()` を待たずに見て、待ちは FreeRTOS の delay で行う
  (select で 50 ms 待つと、その間ほかのタスクが一切動かない)。
- `fmrb_mem_config.h` に `<stdint.h>` を足した (glibc では他の include が
  int8_t を連れてこない)。

## 入力の受け口

**hosted の 2 つ (wasm・native) は関数の表に直した。端末の USB は今の形のまま。**

- `hosted/backend/input_source.h`: `fmrb_input_source_t { name, start }` と、
  ビルドが並べる `fmrb_input_sources[]`。`input_hosted.c` が `usb_task_init()`
  (boot.c が全ターゲットで呼ぶ所) から順に起動し、usb_task の残りの API
  (機器一覧・生レポート) は「機器なし」を返す。
- wasm はページのリングを 1 つの source に (`fmrb_input_source_wasm`)、
  native は `sdl` (主スレッドが積むリング) と `inject` (Unix DGRAM) の 2 つ。
  L2 の evdev・wlr は source を足すだけになる。
- 端末 (usb_task.c、2200 行の USB host と機器の列挙) と sim (usb_task_linux.c)
  まで表に載せ替えるのはやめた。表にすると usb_task の「機器一覧」の API を
  入力の表から切り離す設計が要り、端末の動作確認 (実機) も要る。
  hosted 側の形が L2 で evdev を足して固まってから、端末側を寄せるかを決める方が安い。

キーの意味は wasm と同じ (key_code = scancode = HID usage、修飾は
FMRB_KEYMAP_MOD_*)。SDL の scancode はそのまま HID usage として渡す。
SDL の窓からは Alt も届く (sim は修飾の下位 8 bit しか運ばないので Alt が落ちる)。
半角/全角・カタカナの 2 キーは x11 のときだけ sim と同じ理由で捨てる。
注入のパケットは sim と同じ形 (修飾は SDL の下位 8 bit)、key code は使わず
scancode を両方に入れる。

## 見立てと違った点・踏んだ罠

- 協調 port の native 化は時刻と眠りの差し替えだけで済んだ (見立てどおり)。
  CPU 合成も wasm 前提は無かった。
- **/data は配布物ではなかった**。計画の表では `/data` は配布物 (読み出し専用) だが、
  flash/data に git 管理のファイルは無く、デスクトップが起動のたびに壁紙と
  ランチャーのアイコンを `/data` (と `/cache/launcher`) へ写している
  (graphics 側のための写し)。読み出し専用にすると壁紙が出ない。作り直せる写し
  なので、キャッシュの側に置いた。plan.md の表の直しは親に任せる。
- `/tmp/` で始まる WAV の再生は、端末では `/tmp` の mount、wasm では
  ホストの (MEMFS の) /tmp を見ていた。hosted は resolver を通るので、wasm でも
  HAL の /tmp (flash/tmp) を見るようになった。wasm では tts が無効で、
  /tmp の WAV を鳴らすアプリは無い。端末の `load_fmsq_file` も同じ関数を
  通るので `/tmp/...` の FMSQ が /tmp を見るようになった (以前は
  /flash/tmp/... を探して失敗していた)。
- GNU ld は使われない関数の参照も解決しようとする。Spinel の runtime が
  sp_net / sp_crypto (snapshot に無い) を、LovyanGFX のフォント表が
  コンパイルしていないフォントを参照していて、`-ffunction-sections
  -fdata-sections` と `--gc-sections` が要った (wasm-ld は黙って捨てていた)。
  IDF のビルドも同じ旗を使っている。
- mruby の名前だけの HAL gem (`hal-task-freertos`、今回の `hal-dir-fmrb`) は、
  実は libmruby.a から port のオブジェクトを外していない (archive に
  task_hal.o・dir_hal.o が残る)。CMake 側の定義が先にリンクされるので、GNU ld は
  archive の方を引かない。既存の sim も同じ状態で動いている。今回は
  リンクが通ることと Dir の一覧が層の表どおりになることで確かめた。
- Unix ソケットの path は 108 バイトまで。長い run dir では黙って切れたので、
  起動時に長さを見て止まるようにした。

## 残件

- MCP の道具 (native_up / native_shot ...) は足していない (指示書どおり)。
  fmrb_native.rb のサブコマンドがそのまま写せる形にしてある。
- `flash_local/` は重ねていない。配布物の層は flash/ (git 管理分 + 手元の
  生成物) だけ。手元専用の物を native で見せるかは、パッケージ化 (L3) で
  配布物の木を作るときに決める。
- 回帰の道具に native 版の起動と画面を足す (plan の共通の受け入れ条件)。
  fmrb_native.rb の up/shot/input で書ける。
- ネットワーク: native の libmruby にソケット系の gem と Zenoh を入れていない。
  ブロックするソケットは協調 port で全タスクを止めるので、非ブロックで
  poll する形にしてから入れる。サービスの一覧もブラウザ版と同じ
  (net・timesync なし)。
- `FmrbConst::BOARD` は sim と同じ "linux"。native を見分けたい所が出たら
  値を足す。
- L2 へ: 機種の定義の読み込み、fbdev・DRM (native/present の
  `fmrb_present_blit_xrgb8888` と配置の計算をそのまま使える)、evdev
  (input_source を足す)、ALSA (native_audio のリングを読む側を足す)、回転。
- `/etc` の更新で増えた項目を足す処理は L3。
- `fmrb_native.rb input` の配列は利用者の /etc の keyboard_layout を読む。

## 最後に残っているビルド

- `build/fmruby-core.elf`: `ELF 32-bit LSB executable, UCB RISC-V` (TAB5 / ESP32-P4。regress:screens・regress:size が退避して戻したもの)。
- `native/build/fmruby-native` (標準構成) と `native/build-mruby/fmruby-native` (全 mruby): x86_64。
- picoruby のビルドの木: regress:screens の clean_all の後、family-mruby-native を作り直した。wasm の libmruby は regress:screens が作ったもの。
- 利用者の既定の場所 (~/.local/share/family-mruby-dev、~/.cache/family-mruby-dev) は受け入れの確認で作られたまま残している (home/l1.rb、/etc はミュートを切った状態)。
