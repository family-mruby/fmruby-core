# L10 報告: Shell から Linux のコマンドを使う

> 状態: 完了 (受け入れ 8 点) | 更新: 2026-10-27 | 指示書は instruction_l10.md。ブランチは fmruby-core の feature/linux-native (develop へは未マージ・未 push)

## 1. C の口 (擬似端末の上の 1 つのプログラム)

### 形と置き場所

| 場所 | 中身 |
|---|---|
| `main/kernel/fmrb_platform_sys.h` | L6 の関数の表 `fmrb_platform_sys_t` に 7 項目を足した: `proc_start`・`proc_read`・`proc_write`・`proc_signal`・`proc_exited`・`proc_resize`・`proc_close`。起こす指定は `fmrb_sys_proc_spec_t` (コマンド・Family mruby の作業の場所・桁数・行数)、シグナルは `fmrb_sys_signal_t` (INT・TERM・KILL・HUP。Linux の番号は表の中で写す)。呼ぶ側の短い関数 `fmrb_platform_sys_proc_*()` と、使えるかを聞く `fmrb_platform_sys_proc_available()` も足した |
| `main/kernel/fmrb_platform_sys.c` | 既定の表には入れていない (NULL)。短い関数が「使えない」(`FMRB_ERR_NOT_SUPPORTED`・-1・「終わった」) を答える。端末・sim・ブラウザ版はこれで答える |
| `native/sys/linux_pty.{h,c}` | 中身。POSIX だけで書き、FreeRTOS・fmrb の allocator・ログを使わない (host の試験がそのまま動かすため) |
| `native/sys/platform_sys_linux.c` | L6 の linux の表に 7 項目をつないだ。作業の場所を file HAL の振り分け (`fmrb_hal_file_resolve_path`) で実体に直し、`realpath` が通らなければ断る。プログラムの持ち主は呼んだタスク (`xTaskGetCurrentTaskHandle`) |
| `hosted/gate/fmrb_gate.{h,c}` | タスクが消えたときに呼ぶ口 (L2n) を 1 つから 4 つまでに増やした (`fmrb_gate_add_task_deleted_listener`)。ソケットの台帳 (net_wrap.c) と、このプログラムの後始末の 2 つが使う |
| `native/backend/main_native.c` | 終わるときに `linux_pty_close_all()` (全部のセッションに SIGKILL) |

### 起こし方

- `posix_openpt` → `grantpt`・`unlockpt`・`ptsname_r` で端末の組を作り、子は
  `setsid()` → `TIOCSCTTY` で slave を制御端末にし、0・1・2 に `dup2`、
  ほかの fd を閉じ (`close_range`)、`chdir` してから `execve`。
  `!<コマンド>` は `/bin/sh -c <コマンド>`、`!` だけは `/bin/bash -i`
  (無ければ `/bin/sh -i`)。
- 子は自分のセッションの頭になる。Ctrl+C は端末の前面のプロセスの組へ、
  後始末はセッションの番号で全部を見つけられる。
- 子では、シグナルの扱いを全部既定に戻し、遮断を外す (機械のスレッドの
  遮断や無視が exec を越えて残らないように)。`PR_SET_PDEATHSIG` に SIGHUP
  (起こしたスレッド = Shell のタスクのスレッドが無くなったら、落ちたときも
  含めて端末が切れたのと同じになる)。
- 端末の設定は Linux の既定 (行単位の入力・エコー・ISIG・出力の `\n` は
  `\r\n`) に `IUTF8` を足した。`sh -c` には job control が無く、Ctrl+Z で
  止まると戻す手段が無いので、コマンドのときだけ `VSUSP` を無効にした。
- 環境は Family mruby の起動時のものを受け継ぎ、`TERM=dumb`・`COLUMNS`・
  `LINES` を Shell の窓の桁数・行数で上書きする (端末の大きさも
  `TIOCSWINSZ` で同じに。窓の大きさが変わったら `proc_resize`)。環境の
  並びは fork の前に親で作る (子では async-signal-safe な呼び出ししか
  しない)。
- 同時に 8 本まで (全部のアプリで)。手形は世代つきの番号で、閉じた手形を
  あとで使っても別のプログラムに当たらない。

### 待たない作り

- master は `O_NONBLOCK`。読むのは「今ある分」(無ければ 0、端末が閉じたら
  -1)、書くのは「今入る分」。
- 終わりは `waitpid(WNOHANG)` で知る (`proc_exited` のたびに)。
- 閉じるとき (`proc_close`) にまだ動いていれば、前面の組とセッションの組に
  SIGHUP・SIGCONT を送り、master を閉じ、**切り離したスレッド**
  (`end_session`) に後を任せて、呼んだタスクはすぐ戻る (host の試験で
  50 ms 未満)。そのスレッドは pid を値で受け取り、表には触れない:
  300 ms まで SIGHUP で終わるのを待ち、残っていればセッションの全部に
  SIGKILL (`/proc/*/stat` のセッションの欄で探す。背景に回したジョブも
  入る)、子を `waitpid` で刈り、最後にもう一度セッションの残りを SIGKILL。
  ゾンビも孤児も残らない。
- 持ち主のタスクが消えたとき (アプリが終わった・kill された・消された)、
  ゲートの delete hook から `linux_pty_close_owned(task)` が呼ばれる。
  Shell は自分でも閉じる (下) ので、ふつうはこちらには何も残っていない。
  `FMRB_NATIVE_GATE=off` (比べるための診断) では delete hook が入らないので、
  この後始末も働かない (Shell 自身の後始末と、終わるときの close_all は
  働く)。

## 2. Ruby の口

Shell は標準の構成 (Spinel のカーネル) でも全部 mruby の構成でも **mruby の
VM で動く** (`app ps` の `vm: 0`。カーネルだけが `vm: 3` = Spinel)。だから
mruby の gem (`lib/add/picoruby-fmrb-app/ports/esp32/app.c`) にだけ足した。
Spinel の FmrbApp には足していない (L6 の電池などと同じ扱い)。Spinel の
「型が絞れないと黙って 0」の罠には当たらない。

| 呼び名 | 返すもの |
|---|---|
| `FmrbApp.linux_available?` | このマシンで使えるか |
| `FmrbApp.linux_start(command, cwd, cols, rows)` | 手形 (Integer)。command が nil なら対話のシェル。cwd は Family mruby の場所。起こせなければ理由つきの RuntimeError |
| `FmrbApp.linux_read(h)` | 出てきた分の String (無ければ "")、もう出ない (端末が閉じた) なら nil。1 回 4 KB まで |
| `FmrbApp.linux_write(h, str)` | 受け取ったバイト数 (-1: もう受け取らない) |
| `FmrbApp.linux_signal(h, sym)` | `:int`・`:term`・`:kill`・`:hup` を前面の組へ。true/false |
| `FmrbApp.linux_exit_code(h)` | 動いている間は nil、終わったら Integer (シグナルなら 128 + 番号) |
| `FmrbApp.linux_resize(h, cols, rows)` | true/false |
| `FmrbApp.linux_close(h)` | nil。動いていれば終わらせる (待たない) |

端末・sim・ブラウザ版では `linux_available?` が false、`linux_start` は
「使えない」の例外、ほかは nil・-1・「終わった」を返す。読み取りの String は
その場で作り、static の領域は使わない (端末の内蔵 RAM を増やさないため)。

## 3. Shell

足したのは `shell/shell_linux.rb` (ShellLinuxMixin) と `shell/shell_term.rb`
(ShellTerm)。

- `handle_enter` で、IRB でなく行が `!` で始まれば `cmd_linux` に渡す。
  `!` の後ろが空なら対話のシェル。
- `cmd_linux` は shell_task の中で回る: 打鍵を送る → 4 KB ずつ最大 16 回
  読んで ShellTerm に食わせる → 済んだ行を履歴に足す → `linux_exit_code`
  を見る (終わっていたら残りを読み切って抜ける) → 出力があれば 1 ms、
  無ければ 10 ms 眠る。アプリが終わるとき (`running?` が false) も抜け、
  `ensure` で `linux_close`。最後の改行の無い行も足し、終了コードが 0 以外
  なら `[exit N]` を 1 行出す。
- 作業の場所は Shell の `@current_dir` をそのまま渡す。**引数の中の場所は
  直さない** (`!ls /mnt/host` は Linux の `/mnt/host` を見る)。

### 入力の渡し方とエコー

**打鍵ごとに送り、エコーは端末に任せた**。端末は行単位の入力 (ICANON) と
エコー (ECHO) を持っているので、打った字は端末が返してくる出力に入り、
バックスペースでの直し・Enter で行を渡す・Ctrl+C を SIGINT にする・
Ctrl+D を入力の終わりにする、を全部端末がやる。Shell が自分で行を組み立てて
エコーすると、`!` の対話のシェル (bash の readline は端末を行単位でない形に
切り替えて自分でエコーする) と食い違う。打鍵ごとに送れば、どちらの形でも
本物の端末と同じに見える。

| キー | 送るもの |
|---|---|
| 文字 (かなの UTF-8 のバイトも) | そのまま |
| Enter | `\r` (端末が `\n` に直す) |
| Backspace | DEL (0x7f。端末の消す字) |
| 矢印・Home・End・Delete | `ESC [ A` などの並び (bash の readline が解する) |
| Ctrl+英字 | その制御の字 (Ctrl+C は 3、Ctrl+D は 4)。Ctrl+C は端末の ISIG で前面の組に SIGINT になり、端末が `^C` をエコーする |
| Esc | ESC |
| PageUp・PageDown・ホイール | 送らない (Shell の履歴を戻る) |

Ctrl+C を `linux_signal(:int)` でなく 0x03 の書き込みにしたのは、こちらの
方が端末の決まりどおりになるから (読みかけの入力が捨てられ、`^C` が見え、
対話のシェルではシェルでなく走っているコマンドに届く)。

### 色と行の持ち方

- 履歴の 1 行は今までどおり String。色のある行だけ
  `{:type => :ansi, :text => 文字列, :spans => [[始まりの字, attr], ...]}`
  にした (ロゴの Hash と並ぶ 3 つ目の形)。attr は `(前景 + 1) | ((背景 + 1) << 5)`、
  0 は Shell の色。折り返し・スクロールの数え方は `:text` で、描くときは
  折り返した 1 行ごとに span の切れ目で `draw_text` を分ける。
- まだ改行の来ていない行 (bash のプロンプト、`!cat` で打っている途中) は
  入力の行の場所に、端末の今の桁にカーソルを置いて描く。
- 解釈するもの: `\n`、`\r` (行頭へ戻って上書き。進み具合の表示)、
  バックスペース (1 字戻る)、タブ (8 桁ごと)、SGR の 0・1・22・30-37・39・
  40-47・49・90-97・100-107・38/48;5;n (n < 16 だけ。256 色・24 bit 色は
  Shell の色のまま)。太字は明るい色で見せる (字の太さを持たないため)。
  ほかの CSI・OSC (題名)・文字集合の指定は読み捨てる。
- 読みの途中で切れた制御の並びや UTF-8 の字は、次の読みに持ち越す。

色の表 (RGB332)。Shell の地の色は theme で変わる (標準は白地) ので、地の
明るさで 2 組を使い分けた。暗い地では黒を暗い灰に、青を明るめにし
(多くの端末と同じ)、明るい地では黄と白を暗くした。どちらでも地に溶ける
色を作らない。背景の色は端末のふつうの色。0x01 (カラーキー) は使わない。

| SGR | 色 | 暗い地 | 明るい地 | 背景 |
|---|---|---|---|---|
| 30 / 40 | 黒 | 0x49 (暗い灰) | 0x00 | 0x00 |
| 31 / 41 | 赤 | 0xC0 | 0xA0 | 0xA0 |
| 32 / 42 | 緑 | 0x18 | 0x10 | 0x14 |
| 33 / 43 | 黄 | 0xD8 | 0x90 (暗い黄) | 0xB4 |
| 34 / 44 | 青 | 0x27 (明るめ) | 0x03 | 0x03 |
| 35 / 45 | 紫 | 0xC3 | 0x82 | 0xA2 |
| 36 / 46 | 水色 | 0x1B | 0x12 | 0x16 |
| 37 / 47 | 白 (明るい灰) | 0xB6 | 0x6D (灰) | 0xB6 |
| 90 / 100 | 明るい黒 (灰) | 0x92 | 0x49 | 0x49 |
| 91 / 101 | 明るい赤 | 0xE9 | 0xE0 | 0xE9 |
| 92 / 102 | 明るい緑 | 0x5D | 0x14 | 0x5D |
| 93 / 103 | 明るい黄 | 0xFD | 0xB4 | 0xFD |
| 94 / 104 | 明るい青 | 0x6F | 0x07 | 0x6F |
| 95 / 105 | 明るい紫 | 0xEB | 0xC3 | 0xEB |
| 96 / 106 | 明るい水色 | 0x5F | 0x16 | 0x5F |
| 97 / 107 | 明るい白 | 0xFF | 0x49 (暗い灰) | 0xFF |

地の明るさは RGB332 の 3 成分の重み付き (0.3・0.6・0.1 相当) で、半分より
明るければ「明るい地」。標準の白地と、`color bg black` で黒地にしたときの
両方を画面で確認した。

### 履歴の長さ

Linux のあるマシンでは履歴を 3000 行まで持つ (今までは窓の 3 ページ分
= 数十行)。`!seq 1 2000` の全部をスクロールで見られるようにするため。
端末・sim・ブラウザ版は今までどおり 3 ページ分 (`linux_available?` で分ける)。
`trim_history` にまとめ、`append_output`・`handle_enter` の 2 か所の同じ
処理をこれに替えた。

### help と「使えない」

- `help` には Linux のあるマシンでだけ 2 行を足す (`!<command>` と `!`)。
  Shell の help は英語だけで、en・ja の表は無い。端末・sim・ブラウザ版の
  help は変わらない。
- 端末・sim・ブラウザ版で `!` の行を打つと
  `!: Linux commands are not available on this machine` の 1 行。

## 4. 試験

- `test/native/pty.c` (`rake native:test` が `native_pty_test` を作って流す):
  52 項目。echo、終了コード (`false` 1・`exit 7`・自分を TERM で殺す 143・
  無いコマンド 127)、`cat` への書き込みと Ctrl+D、`read` とバックスペース、
  SIGINT (呼び出しと、端末への 0x03 の両方で 130、1 秒未満)、
  `seq 1 100000` (688,895 バイトを 52-59 ms で、全部の数を順に、`\r\n` つきで)、
  作業の場所 (一時のホームと `/etc`、無い場所は断る)、環境 (`dumb 80 24` と
  `stty size` の `24 80`)、対話のシェル (`cd /tmp; pwd` と `exit`)、
  動いている間に閉じたとき (`sleep 100 & sleep 100`。閉じる呼び出しは
  50 ms 未満で戻り、セッションの生きたプロセス 0・子の pid も消え (ゾンビ
  なし)・`waitpid(-1)` が ECHILD)、`close_owned`、閉じた手形。HOME は
  `/tmp` の下の自分の場所にして、終わりに消す。
- `test/native/shell_term_test.rb` (同じく `rake native:test` から。CRuby で
  Shell と同じファイルを読む): 17 項目。行、ls の色と元に戻す、8 色と明るい
  8 色、背景、256 色、太字、読みの途中で切れた並び、読み捨てる並び、`\r`、
  バックスペース、消すエコー (`\b \b`)、色を持ったままの上書き、タブ、
  途中で切れた UTF-8、途中の行とカーソル、2000 行。

## 5. 受け入れ条件

native は HOME・`XDG_DATA_HOME`・`XDG_CACHE_HOME` を一時の場所にし、
`--user-dir`・`--cache-dir` もその下、run dir は `/tmp/fmrb-l10-*`、debug の
port は 5595 で動かした (人のネイティブ版とぶつからないように)。

| 条件 | 結果 |
|---|---|
| 1. `!echo hello`・`!false` (`--machine sdl`) | `hello` が出て、`!false` で `[exit 1]` |
| 2. 作業の場所 | `cd /mnt/host` → `!pwd` が一時の HOME。`/mnt/root/etc` で `/etc`、`/mnt/host/src` で `<HOME>/src`、`/home` で利用者の場所の `home`。ログの `sys_linux: program N in <実体>` でも同じ |
| 3. 色と量 | `!ls --color=always` (ディレクトリが青、実行できるファイルが緑、リンクが水色) と `!printf` の 16 色・背景・太字が画面に出る (白地と黒地の両方)。`!seq 1 2000` はログが `exit 0, 2000 lines`、終わりまで 36 ms。irb で履歴を見て、2000 行が順に欠けずに入っている (`[2057, 40, 2000]` = 履歴の数・`"1"` の位置・合った行の数)。スクロールで戻れる |
| 4. 止める・入力・対話 | `!sleep 30` を 1.5 s 後に Ctrl+C: `^C` と `[exit 130]` (`exit 130`)。`!cat` に打った行が 2 回 (端末のエコーと cat) 出て、Ctrl+D で `exit 0`。`!` で bash に入り、`cd /tmp; pwd` が `/tmp`、`echo $TERM $COLUMNS $LINES` が `dumb 47 15` (窓の桁・行)、`exit` で Shell に戻る |
| 5. kill で何も残らない | `!sleep 301 & sleep 302` の間に `app kill` (頼んで終わらせる形): 1.5 s 後に `sleep 30[12]` も `sh` も無く、native の子も 0。止めに応じないアプリ (`linux_start` の後、イベントの輪に戻らない試験のアプリ。flash/ に入れず一時の `/home/l10/` に置いた) の kill は消す形になり、`sys_linux: ended 1 program(s) of a deleted task`、同じく何も残らない。プログラムが動いている間に native を `down` しても残らない |
| 6. keys の形 (`--machine sdl_keys`) | 1・4 が同じ結果 (標準・全部 mruby の両方、下) |
| 7. 標準と全部 mruby | `sdl`・`sdl_keys` × 標準・全部 mruby の 4 通りで、ログが `echo hello: exit 0, 1 lines` / `false: exit 1` / `sleep 30: exit 130` / `cat: exit 0, 2 lines` / `(shell): exit 0, 7 lines`、終わりに sleep の残り 0 |
| 8. sim と回帰 | sim (Modern) で `!ls` と `!` がどちらも `!: Linux commands are not available on this machine` の 1 行、`help` は今までどおり。`rake regress`: host 19/19、描画の記録 205/205。`rake regress:screens`: 26 passed / 0 failed (retro 8/8・modern 10/10・web 6/6・native 2/2) と、`ONLY=native` で native 2/2・native-keys 3/3 (下の罠)。画面の基準は変わらず、更新していない。`rake regress:size`: 内蔵 RAM は NARYAv3・TAB5 とも +0 |

### 大きさ (rake regress:size、基準 6f7b5848 との差)

| 端末 | DIRAM | IRAM | ほかの内蔵 | アプリの像 (flash) |
|---|---|---|---|---|
| NARYAv3 | 126,035 (+0) | 16,384 (+0) | 104 (+0) | 4,552,304 (+39,680) |
| TAB5 | 129,698 (+0) | - | 948 (+0) | 6,734,160 (+45,232) |

flash の差は基準のコミットからの全部で、L10 の分はその一部。L10 の分の
大半は Shell のバイトコード: 今の Shell を mrbc で作ると `-g` で 61,889 →
73,352 バイト (+11,463。デバッグ情報なしで 53,177 → 62,716)。ほかは
app.c の 8 つの束縛と表の短い関数 (libmruby の差 +4 KB 前後は L6 以降の
分を含む)。TAB5 の psram +216 も L10 以前の差を含む。

### VM プール (rake regress:run)

`rake regress:run` は **L10 の前 (HEAD) でも落ちる** (基準が app_refactor R6
の時点のまま。カーネルが +10 KB、デスクトップが +9 KB)。L10 を一時退避して
同じ道具で HEAD を測り、比べた: L10 の差はデスクトップの VM プールで
+48 バイト前後 (FmrbApp の 8 つのメソッドの表)、カーネルは揺れの範囲。
基準は更新していない。

## 6. 確認の手順

```
# fmruby-core で
rake native:test                       # pty 52 項目と ShellTerm 17 項目を含む
rake native:mrb && rake native:core && NATIVE_ENGINE=mruby rake native:core

# ルートで (HOME などを一時の場所にした環境で)
ruby tools/fmrb_native.rb up [--engine mruby] [--machine sdl_keys] \
     --user-dir <tmp>/user --cache-dir <tmp>/cache
ruby tools/fmrb_native.rb app spawn default/shell
ruby tools/fmrb_native.rb input text '!echo hello'; ruby tools/fmrb_native.rb input key enter
ruby tools/fmrb_native.rb input key ctrl+c        # ctrl+d も
ruby tools/fmrb_native.rb log 200 | grep "FM-Shell: linux:"   # 1 本ごとの終了コードと行数
```

Shell は 1 本ごとに `linux: <コマンド>: exit <N>, <行数> lines` をログに出す
(確認と、行の取りこぼしを数えるため)。

## 7. 見立てと違った点・罠・残件

- **Shell は Spinel では動いていない**: 標準の構成でも Shell は mruby の VM
  (カーネルとエディタだけが Spinel)。Ruby の口は mruby の gem だけで足りた。
- **Ctrl+C は信号の呼び出しでなく 0x03 の書き込みにした**。指示書の
  「Ctrl+C は SIGINT」は端末の ISIG で満たされる。`linux_signal` の口は
  残してあり、host の試験で両方を確認した。
- **Ctrl+英字はふだんの Shell では効いていない**: 道具の `key ctrl+l` を
  プロンプトで送ると `l` が入る (今までの動き)。実行中だけは
  `ev_ctrl?` (修飾キーの欄) か Ctrl の押下の記録で制御の字にする。
- **bash の行が窓より長いと横に送られる**: TERM=dumb の readline は長い行を
  `<` を付けて横に送って見せる (`</tmp$ echo ...`)。端末の決まりどおりで、
  直していない。
- **`/mnt` そのものは振り分けの表どおり配布物の `mnt`** (開発中は
  `flash/mnt`) が作業の場所になる。断るのは表で実体に直らない場所
  (`realpath` が通らない場所) だけ。
- **Linux のコマンドには Family mruby の「読むだけ」は効かない**: `/mnt/root`
  や配布物の木を作業の場所にしても、コマンドは OS の利用者の権限で書ける
  (開発中の配布物はリポジトリの flash/)。全部のアプリに許すという決定の
  とおりで、守りは OS の権限だけになる。引数の中の場所も直さない。
- **`regress:screens --keep` は native も起こしたまま残す**ので、続く
  native-keys が「もう動いている」で落ちる (道具の決まり)。sim に `!ls` を
  打つために `--keep` で流し、native だけを `ONLY=native` で流し直した。
- **一時の HOME では道具の python が msgpack を見失う** (利用者の
  site-packages が HOME の下にあるため)。`PYTHONUSERBASE` を元の
  `~/.local` にして使った。
- 端末・sim・ブラウザ版の動きは「使えない」の 1 行のほかは変えていない
  (help の 2 行は Linux のあるマシンだけ、履歴の長さも同じ)。
- 残件:
  - かなの入力は 1 バイトずつそのまま送る。端末の行の直し (IUTF8) で
    バックスペースは 1 字ずつ消える。実機のキーボードでの確認はまだ。
  - 256 色・24 bit 色は Shell の色のまま (先頭 16 色だけ写す)。
  - Cardputer Zero (root で動く) の実機での確認は実機が来てから。
