# L7b 報告: メニューバーの右上の電源ボタン

> 状態: 完了 (受け入れ 6 点。実機の目視は残件) | 更新: 2026-10-27 | 指示書は instruction_l7b.md。ブランチは fmruby-core の feature/linux-native (develop へは未マージ・未 push)

## 1. 作り

### 電源ボタン

- `system_desktop.app.rb` の `draw_power_icon`。メニューバーのいちばん右 (時計の右) に
  10x10 の枠で描く。絵は丸 (上が切れている) と縦線。色の決まりはスピーカーの枠と同じで、
  ふだんはバーの色の地に白、メニューが開いている間は反転 (白地にバーの色)。
- 電源の項目 (`POWER_ITEMS`、今どおり `FmrbApp.power_actions` から作る) が空なら描かず、
  `@power_icon_x` も nil のままなので押しても何も起きない。sim とブラウザ版がこれ。
- 左上の「Family mruby」のメニュー (`DROPDOWN_ITEMS`) から `POWER_ITEMS` を外した。

### 印の位置を 1 か所に

右からの引き算の連なりの起点を定数にまとめた。

| 定数 | 値 | 意味 |
|---|---|---|
| `POWER_CELL_W` | 10 | ボタンの幅 |
| `POWER_PAD` | ボタンがあれば 14 (10 + 間 4)、無ければ 0 | ボタンのぶん左へずれる量 |
| `CLOCK_RIGHT` | 90 + `POWER_PAD` | 時計の左端の右からの距離 (前は 90 の直書き) |
| `POWER_CELL_RIGHT` | 16 | ボタンの左端の右からの距離 (右の余白 6 は前の時計の右と同じ) |
| `STATUS_RIGHT` | `CLOCK_RIGHT` + 4 + 10 | 前と同じ式で、起点だけ `CLOCK_RIGHT` |

- 時計・スピーカーは `CLOCK_RIGHT` から、ほかの印は今どおり `STATUS_RIGHT` から引く。
  ボタンが無い所では `POWER_PAD` = 0 で、座標は前と 1 画素も変わらない (sim・ブラウザ版の
  画面の比較が通った)。
- タスクバーの取り置きの幅 (`taskbar.rb` の `clock_area` 184 と 170) にも
  `self.class::POWER_PAD` を足した (mixin なので bare 定数は使わない)。

### サブメニュー

- 左上のメニューの作りを 2 つのメニューで使い回す形にした。`@dropdown_menu` (`:main` か
  `:power`) を持ち、`dropdown_items`・`dropdown_x`・`dropdown_h` が開いている方を返す。
  `draw_dropdown`・`draw_dropdown_row`・`dropdown_item_at`・`hit_dropdown?`・
  `handle_dropdown_click`・合成の領域・kernel への overlay の矩形は全部これを通る。
- 電源のメニューは幅 80 (左上と同じ `DROPDOWN_W`)、行の高さ 12、ボタンの下に右揃え
  (メニューの右端 = ボタンの右端)。外を押せば閉じる (左上と同じ経路)。
- `run_dropdown_item` は番号でなく項目そのものを受け取るようにした (閉じる前に取る)。
  `:reset` と `:power_*` の扱い (確認のダイアログ) はそのまま。

### キーボードでの開き方

- **F10 で左上のメニューを開き、左右の矢印で電源のメニューへ移る** (戻るのも左右)。
  メニューが 2 つだけなので、どちらの矢印でももう一方へ行く。電源の項目が無い所では
  左右は何もしない (行き先が無い)。移った先は先頭の項目が選ばれた状態で開く。
- 理由: 開く口 (F10) は今のまま 1 つにでき、デスクトップの OS でメニューバーを左右で
  渡るのと同じ操作なので覚えることが増えない。電源専用のキーを足すと、ほかのアプリや
  ショートカットとの取り合いを調べる必要が出る。今の F10 の作りでは左右の矢印は
  使われていなかった。

- Retro の左端は「Family mruby」(2〜73) とタスクバー (82 から)。印同士・時計と重ならない

  (取り置きの幅がボタンのぶん広がるため)。印は消していないので止まる条件には当たらないと
  判断した。

## 4. 受け入れ条件

| 条件 | 結果 |
|---|---|
| 1. native の電源 | `fmrb_native.rb up --machine sdl`: 右上にボタン、押すと「Exit」だけのメニュー、Exit → 確認の Yes で `Desktop: do_power exit` → `power: ending the program` → プロセスが終わる。`--set system.power=logind --set system.power_log_only=true`: 「Power off / Restart / Suspend」の 3 つ、順に選んで Yes で `PowerOff(false)`・`Reboot(false)`・`Suspend(false)` (log only) がログに出て、プロセスは動き続ける。`--machine linux_pc --set system.power_log_only=true` (SDL はダミー): 「Exit / Power off / Restart / Suspend」の 4 つ、3 つは logind のログ、最後に Exit で終わる。左上のメニューの最後は About で電源の項目は無い。標準・全 mruby とも |
| 2. キーボードだけで | F10 → 右 → (下) → Enter で、電源のメニューが開き、項目が選ばれて確認のダイアログが出る (sdl の Exit、logind の Restart)。左で左上のメニューへ戻る。標準・全 mruby とも |

| 5. 両エンジン・regress | 1・2 は標準 (`rake native:core`) と全 mruby (`NATIVE_ENGINE=mruby`) で確認。`rake regress`: host 19/19、描画の記録 205/205 |

## 5. 見立てと違った点・罠・残件

- **撤回した見立て**: キーボードで確認のダイアログを出した直後の Yes のクリックが
  効いていないように見えたが、ログが書き出される前に grep していただけだった
  (少し待つと `do_power` が出ていた)。入力の取りこぼしは無い。
- **確認のダイアログはマウスだけ**: 確認のダイアログ (`confirm_dialog.rb`) はキーを受けない
  (Yes・No は FmrbUI のボタンで、デスクトップはキーを FmrbUI に渡していない)。よって
  「キーボードだけで項目を選ぶ」ところまではできるが、Yes を押すのはマウスかタッチになる。
  前からの作り (Reset の確認も同じ) で、確認のダイアログは削除などにも使われるため、
  Enter を Yes にするかどうかは仕様の判断と考えて変えていない。決めてもらう事項として残す
  (例: Enter = Yes / Esc = No、または Tab で選んで Enter)。
- タスクバーのアイコンの並べられる数が 1 つ減る (2 章)。
- 前からの食い違い (今回は変えていない): 電池の表示 (native で電池のある機種だけ) は
  空きメモリの左に置かれるが、タスクバーの取り置きの幅はそれを数えていないので、
  アプリを多く開くとアイコンが電池の表示に重なりうる。
- **残件 (実機の目視)**: Tab5 と S3 (Retro) で、右上に電源ボタンが出て、押すと「再起動」
  (en は Reset) だけのメニューが右揃えで開き、選ぶと確認を経て再起動すること。Retro の
  NTSC 出力で丸の絵がつぶれて見えないか。左上のメニューに再起動が無いこと。
