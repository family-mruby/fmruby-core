# L13 報告: 毎日使う環境 (2) 窓と画面

> 状態: 完了 (範囲を縮めた 3 機能。VirtualBox の Kubuntu での確認とブラウザ版の画面の比較は残件) | 更新: 2026-10-28 | 指示書は instruction_l13.md。ブランチは fmruby-core の feature/linux-native (develop へは未マージ・未 push)

コミット: 8558f302 (コードと試験と usage.md の 11 章)。この報告は別のコミット。基準の絵は更新していない。

## 0. 範囲の変更 (2026-10-28 ユーザ)

作業の途中で、ユーザの指示により L13 を次の 3 つだけにした。

- 残したもの: (1) 最大化 (題の帯のダブルクリック、Linux のアプリの最大化の頼み)、(2) Super + 矢印で並べる、(3) 画面ロック (ext-session-lock と swaylock、電源のメニューの「ロック」、logind の Lock)。
- 外したもの: Linux のアプリの全画面、2 つ目のモニタの鏡、明るさ。受け入れ条件 2・5・6 は無し。
- 外した 3 つは一度作って確かめ終えていたが (全画面は「代役を kernel の全画面のアプリにし、窓を絵の上の層に出力全体で置く」形、鏡は 2 つ目の出力を倍率で 1 つ目に合わせる形、明るさは sysfs で読み logind の SetBrightness で書く形。どれも wl_winops_check で通った)、残す 3 つには要らないのでコードから外した。全画面の頼みは L9a どおり「何も変えずに configure だけ返す」、2 つ目からの出力は L8 どおり使わない。
- 鏡の作りで入れた `wlr_cursor_map_to_output` が、回した出力 (display.rotate) で絶対座標の動きを回してしまい、wl_dialog_check のダイアログを押せなくなっていた (regress:wl で見つけた)。鏡と一緒に外したので今は起きない。後で鏡を作るときは `wlr_cursor_map_to_region` を使う。

## 1. 全体の形

| 機能 | 受け持つ所 | 効く機種 |
|---|---|---|
| 最大化・半分・戻す | `native/backend/native_winops.{h,c}` (FreeRTOS の側)、形の計算は `winops_geom.{h,c}` (host の試験の対象) | 機種の定義の新しい欄 `desktop.window_ops = true` (sdl・linux_pc・linux_pc_drm・linux_pc_wl)。Cardputer の 2 つと sdl_keys は false |
| Linux の窓の最大化の頼み | `native/wlr/output_wlr.c` (頼みを受けて知らせる、状態を窓に伝える)、`wl_bridge.c` (代役に効かせる) | コンポジタ (`linux_pc_wl`) |
| 画面ロック | `output_wlr.c` (ext-session-lock-v1)、`native/sys/linux_logind.c` (logind の知らせ)、電源のメニューは `platform_sys` の `FMRB_SYS_POWER_LOCK` | コンポジタ、`compositor.locker` (既定 `swaylock`) のプログラムがあるとき |

- kernel の Ruby は変えていない。窓の位置と大きさは、window manager のドラッグと同じ C の口 (`fmrb_app_update_window_position` / `_size`) で変える (L9a のブリッジと同じ道)。デスクトップの Ruby は電源のメニューに「ロック」を足しただけ (`power_actions` に `:lock` があるときだけ出る)。
- 端末・sim・ブラウザ版では新しい道は「無い」を答える: `platform_sys` の既定の表 (`static const`) は `:lock` を出さず、窓の操作はネイティブ版の入力の口にしか無い。

## 2. 最大化・半分・戻す

### 作り

- 作業領域は画面のメニューバー (13 画素) より下の全部 (タスクバーはメニューバーの中にある)。最大化はそこいっぱい、左右の半分は幅を 2 つに分ける (奇数の 1 画素は右)。
- **題の帯のダブルクリック**: ネイティブ版の入力の口 (SDL の窓の環、inject の口、evdev、コンポジタの環はどれもここを通る) で押下を見る。押した所の一番前の動いている窓 (デスクトップと全画面のアプリは除く、大きさを変えられるものだけ) の題の帯 (上 11 画素、左のメニューのボタンと右の閉じるボタンを除く) を、400 ms 以内・4 画素以内に 2 回押すとダブルクリック。最大化していれば戻し、それ以外は最大化する。2 回目の押下と離しは Family mruby に渡さない (window manager が 2 回目の押下で引きずりを始めると、最大化の直後の小さな動きで元の場所へ引き戻すため)。
- **Super + 矢印**: 前にある窓 (キーボードの持ち主、HID の行き先) に、左・右で半分、上で最大化、下で戻す。矢印の押下と離しは窓にもアプリにも渡さない。コンポジタでは Linux の窓がキーボードを持っていてもコンポジタが矢印を取る (Ctrl+Tab と同じ扱い)。SDL の窓と inject と evdev では入力の口が Super の押下を覚えて矢印を取る。
- **戻す**: 最初の操作の前の大きさと場所を窓ごとに覚え、戻すとそこへ。最大化から半分へ移っても覚えたものは最初のまま。操作の後で利用者が窓を動かすか大きさを変えたら (最後に置いた矩形と違えば)「利用者が置いたまま」とみなし、覚えたものは捨てる。アプリの文脈の世代 (gen) で、同じ番号の別のアプリと混ざらない。
- ログに 1 行: `winops: PID 5 'FM-Editor' maximized: 640x387 at (0,13) (a double-click on its title)`。

### Linux の窓

- 代役の窓を同じ口で動かすので、ブリッジの置き場所を通してコンポジタが Linux の窓の大きさを頼み直す (L9a のまま)。置き場所に「どう並べたか」(`comp_place_t.state`: 最大化・左・右・なし) を載せ、コンポジタは窓に伝える: xdg は maximized と tiled の辺 (tiled は版 2 以上)、X11 は `_NET_WM_STATE` の最大化。
- アプリの頼み (Firefox の □、xdg の set_maximized / unset_maximized、X11 の `_NET_WM_STATE`): コンポジタが知らせ (`COMP_NOTICE_MAXIMIZE`) をブリッジへ送り、ブリッジが代役が動き出してから代役の窓を最大化するか戻す。地図に出る前の頼み (最大化で始まるアプリ) は地図に出た時に読む。xdg の頼みには決まりどおりすぐ configure を返す。
- 窓の機能の知らせ (wm_capabilities) を「最大化あり」にした (L9a は空。全画面は無し)。
- 並べた窓は、アプリが自分の大きさ (foot の文字の格子) に落ち着いても代役を縮めない (L9b の FIT を無視)。余りは代役の枠の色 (L9b の下敷き)。縮めると「最後に置いた矩形」と違ってしまい、もう一度のダブルクリックで戻らなくなるため。

## 3. 画面ロック (ext-session-lock-v1)

- コンポジタが `ext-session-lock-v1` を出す (`wlr_session_lock_manager_v1`)。ロックのプログラム (機種の定義の新しい欄 `compositor.locker`、`linux_pc_wl` は `swaylock`、`/bin/sh -c` で起こす) が鍵をかけると、その場で画面全体を地の色 (暗い灰色) で覆い、プログラムの鍵の画面をその上に出す。鍵の画面が出たら `locked` を送り、キーボードとポインタを鍵の画面だけに渡す。
- ロック中は Family mruby にも Linux の窓にも入力を送らない (キー、押下、移動、ホイール、IME の掴みも通さない)。例外は仮想端末の切り替え (Ctrl+Alt+F1-F12)。Family mruby の絵と窓は下で動き続けるが見えない。
- 鍵を外すのはプログラム (パスワードの確認はプログラムがする。Family mruby はパスワードを扱わない)。外れたらキーボードを Family mruby の今の持ち主に戻し、ポインタの行き先を調べ直す。
- **プログラムが鍵を外さずに落ちたら開かない** (決まりどおり)。地の色で覆ったまま入力も止めたまま、ログに 1 行。新しいロックは受け付ける (鍵がある間の 2 つ目は断る)。
- 起こす口: (1) 電源のメニューの「ロック」(プログラムがあるときだけ出る。確かめの問いは出さない)、(2) logind の Session.Lock (`loginctl lock-session`、蓋を閉じて logind がロックする設定のとき)、(3) logind の Manager.PrepareForSleep(true) (休止の前)。logind は別のスレッド (`linux_logind.c`、libsystemd を実行時に開く、電源の項目と同じ扱い) で見る。休止の前に鍵が間に合うように、sleep の delay 抑止 (inhibitor) を持ち、鍵がかかったら (最長 3 秒) 放す。起きたら持ち直す。
- プログラムは自分のセッションで、プログラムの fd を受け継がず (3 以上を閉じる)、本体が落ちたら一緒に終わる (`PR_SET_PDEATHSIG`)。
- .deb の Recommends に swaylock を足した (`xwayland, swaylock`)。session の台本の頭の説明にロックを書いた。

## 4. 仮決めに足した選択

| 選んだもの | 理由 | 別の案 |
|---|---|---|
| 窓の操作を kernel の Ruby でなくネイティブ版の入力の口 (C) に置いた | kernel の Ruby は端末と共通で、Spinel と mruby の両方に C の口を足し、端末の flash も増える。入力の口なら端末・sim・ブラウザ版のコードに触れない。window manager と同じ C の口で動かすので結果は同じ | kernel の input_router に「ダブルクリック」を足し、機種の定義の口で端末では切る |
| ダブルクリックの 2 回目の押下と離しは Family mruby に渡さない | 渡すと window manager が引きずりを始め、少しでも動くと最大化した窓を元の場所へ動かす | 渡して、引きずりを止める変更を kernel に入れる |
| ダブルクリックは「最大化していれば戻す、それ以外 (半分を含む) は最大化」 | 題の帯のダブルクリックは最大化の切り替えというのが多くの机の決まり | 半分のときは戻す |
| 利用者が動かしたら「戻す」先を捨てる | 動かした後の「戻す」が離れた所へ跳ぶと驚く | 覚えたまま、Super + 下でいつでも戻す |
| 並べた Linux の窓はアプリの大きさに代役を縮めない | 縮めると最大化の判定が外れ、戻せなくなる。余りは枠の色 | 縮めて、判定に幅を持たせる |
| 窓の操作は機種の定義の新しい欄 `desktop.window_ops` (既定は true、Cardputer 2 つと sdl_keys は false) で切る | 指示書の「機種の定義か native の口で」。組み込みの定義 = sdl.toml の決まりに合わせて既定を true にした | 既定を false にして PC の定義だけ true |
| 電源のメニューの「ロック」は一番下、問いなし | 既存の確認 (deb_check・wl_check) が「終了」を 1 番目で押している。ロックは失うものが無い | 一番上に置き、確認の台本を直す |
| ロックのプログラムが落ちた後は、キー (2 秒に 1 回まで) でプログラムを起こし直す | 決まりどおり開かないまま、利用者が戻れる道を残す (他の仮想端末に移らずに済む) | 何もしない (sway と同じ。`loginctl lock-session` か他の端末から) |
| 休止の前は delay の抑止を持って、鍵がかかってから休止を進める | 起きたとき一瞬でも中身が見えないように (swayidle と同じ) | 知らせを受けて鍵をかけるだけ |
| 試験のために像に swaylock と libsystemd-dev を足した | swaylock で本物の確認、libsystemd-dev は確認だけの logind の代わり (C、sd-bus) を作るため | python3 の D-Bus で代わりを書く |

## 6. VM で人が確かめる手順 (VirtualBox の Kubuntu 26.04)

1. 開発機で `.deb` を作る: `cd fmruby-core && rake native:deb ARCH=amd64` → `native/build-deb/family-mruby_<版>_amd64.deb`。VM へ写す。
2. VM の中で入れ直す: `sudo apt install ./family-mruby_<版>_amd64.deb`。Recommends の swaylock も入る (入らなければ `sudo apt install swaylock`)。
3. ログイン画面で「Family mruby」を選んでログイン。ログ (`~/.local/share/sddm/wayland-session.log`) に `the screen lock: "swaylock" (ext-session-lock)` と `logind: watching /org/freedesktop/login1/session/... for Lock, and PrepareForSleep (a delay inhibitor held)`。
4. **最大化**: メニューからエディタを開き、題の帯 (題の文字の辺り) をダブルクリック。メニューバーより下いっぱいになり、もう一度で元の大きさと場所に戻ること。Linux の区分から Konsole を開き、同じく題の帯のダブルクリックで広がって戻ること。Firefox を開き、Firefox 自身の □ (最大化) を押すと広がり、もう一度で戻ること。
5. **Super + 矢印**: Konsole を前にして Windows キー + 左で左半分、+ 右で右半分、+ 上で最大化、+ 下で元に戻ること。Konsole に矢印の文字が入らないこと。エディタでも同じ。
6. **ロック**: 電源のメニュー (右上) の一番下「ロック」で swaylock の画面になり、パスワードで戻ること。ロック中にキーを打っても Family mruby や Konsole に入らないこと。Ctrl+Alt+F3 の文字の画面から `loginctl lock-session` でもロックすること。休止 (電源のメニュー) から戻ったときに swaylock の画面であること (VirtualBox で休止できない場合は省く)。
7. Firefox の F11 は全画面にならない (範囲の外、今までどおり)。

## 7. 撤回した見立て・踏んだ罠

- **ロックのプログラムを起こした後、道具の制御の口が答えなくなった**: キーで起こし直したとき、fork した子が制御の口の接続 (道具はサーバが閉じるまで読む) を受け継いでいた。子で 3 以上の fd を閉じ、シグナルを既定に戻し、`PR_SET_PDEATHSIG` を付けた (linux_apps の起こし方と同じ)。
- **鍵を外した後も `lock=locking` と出た**: 外した後も確認だけのロックのプログラムは動き続ける (swaylock は終わる)。「起こしたが鍵をまだ頼んでいない」を別に持つようにした。
- **電源のメニューに「ロック」を先頭で足すと、既存の確認が「終了」を押せなくなる**: 一番下にした (4 章)。
- **回した出力でポインタがずれた** (0 章): 外した鏡の作りの `wlr_cursor_map_to_output` のため。

## 8. 残件

- VirtualBox の Kubuntu での確認 (6 章)。実際の Firefox の □、Konsole・Kate、本物の logind の Lock と休止。GLES の描画。
