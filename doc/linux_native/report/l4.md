# L4 報告: キーボード専用のデスクトップ (320x170)

> 状態: 完了 (受け入れ 7 点。分けずに L4 全体) | 更新: 2026-10-26 | 指示書は instruction_l4.md。ブランチは両リポジトリとも feature/linux-native (develop へは未マージ・未 push)

## 画面の形 320x170

- 機種の定義の `screen.form` は `426x240` と `320x170` を受け付ける (それ以外は理由つきで断る)。
  `desktop.variant` は `mouse` と `keys`。どちらの組み合わせも断らない。
- 画面の大きさは kernel の設定の `display_width` / `display_height` が正で、display_local・
  入力の座標・SDL の窓はみなそれに従う (L1 から)。native はそこに機種の定義の形を
  上書きする: `main_native.c` が機械を起こす前に `fmrb_kernel_set_native_machine()` を呼び、
  `read_system_config()` が system_conf を読んだ後で置き換える
  (`kernel: Display 320x170 from the machine definition (system_conf says 426x240)`)。
  利用者の `/etc` は機種をまたいで同じものを使うので、画面は system_conf に書かせない。
  この口 (`fmrb_native_machine_conf_t`、fmrb_kernel.h) は `FMRB_PLATFORM_NATIVE` の中だけで、
  端末・sim・ブラウザ版には無い。
- 全画面の高解像度モード (640x360) は今までどおり基本の画面が 426x240 のときだけ
  (`fmrb_app_fullscreen_hires_size` の条件のまま)。
- `cardputer_zero` は形で断らなくなった (WSL2 では fbdev が無いので `display` で断る)。
  開発用に `config/machines/sdl_keys.toml` (SDL・320x170・keys・倍率 4・`exit_key = "esc_long"`)
  を足した。

## デスクトップの分け方

デスクトップは 2 つのプログラムにした。kernel・window manager から見ればどちらも
`system_desktop` という名前の同じアプリで、spawner が中身を選ぶ。

| ファイル | 種類 | 中身 |
|---|---|---|
| `kernel/system_desktop/desktop_common.rb` (新設) | 共通 | `DesktopCommonMixin`: 組み込みアプリの一覧と宣言 (`builtin_app_catalog`)、`spawn_app`、`read_conf_string` (どちらも mouse から移した) |
| `kernel/system_desktop/i18n.rb` | 共通 | 文字列 (変更なし) |
| `kernel/system_desktop/file_manager.rb`・`file_selector.rb` | 共通 | 大きさを定数から `fmgr_w`/`fmgr_h`・`fsel_w`/`fsel_h` のメソッドに替えた (既定は今の定数。keys は帯の下いっぱいを返す) |
| `kernel/system_desktop/error_dialog.rb` | 共通 | 変更なし |
| `kernel/system_desktop.app.rb` と残りの部品 (launcher・icons・taskbar・dialogs) | mouse | 今のデスクトップ。`DesktopCommonMixin` を include し、移した 2 つを消しただけ。launcher の `builtin_apps` は共通の一覧から作る (同じ 3 項目、同じ順) |
| `kernel/system_desktop_keys.app.rb` (新設) | keys | 帯・メニュー・切り替えの一覧・File Manager とファイル選択を帯の下に全画面 |

- 選び方: `fmrb_app_spawner.c` の `spawn_builtin_app` が、`system/desktop` を起動するときに
  `fmrb_kernel_native_machine()->keys_desktop` なら bytecode を `system_desktop_keys_irep` に替える
  (native だけ。mruby の VM で動かす。標準構成でもデスクトップは mruby)。
- keys のプログラムは native だけが持つ: `main/CMakeLists.txt` は端末・sim のビルドから
  外し (`REMOVE_ITEM`)、bytecode は `rakelib/hosted.rake` の `hosted_regen_mrb!` が作る。
  mixin を mouse の部品のディレクトリから借りるため、ファイルの頭の
  `# combine: system_desktop/i18n.rb ...` の行を読んで結合するようにした
  (この行の無い既存のプログラムは今までどおり)。
- keys の部品の文字列 (メニューの題など 4 つ) は keys のファイルの中で `FmrbI18n.add` する。
  mouse の文字列の表は変えていない。

## keys のデスクトップ

| 部分 | 作り |
|---|---|
| 帯 (10px) | 左に前にいるアプリの名前 (File Manager の間は "File Manager"、メニューでは "Family mruby")、右にかなの状態の枠と時計 (`draw_wallclock`)。電池は値が無いので何も出さない (L6)。前景の canvas の合成の領域は帯だけ (メニュー・パネルのときは全面) |
| メニュー | 帯の下に全画面。エディタ・Shell (組み込みの宣言から)・File Manager、続けて /app の宣言のあるアプリ。↑↓ PgUp PgDn と Enter。起動したら選択は先頭に戻る (Enter だけでエディタ) |
| File Manager・ファイル選択 | mouse と同じ部品を帯の下いっぱい (320x160) で。キー操作は今のまま (Esc で閉じてメニューへ) |
| 切り替えの一覧 | kernel の cycle_focus (下の切り替えのキー) で開く。動いているアプリ (FmrbApp.ps の、窓のあるアプリ) と「メニュー (アプリを起動)」。Enter で前へ、Delete/Backspace で終える、Esc で元に戻る |
| かな | 状態は今の host の通知 (kana_mode) をそのまま帯に出す。キーでの切り替えは今の Ctrl+Space (どの配列でも)・半角/全角・カタカナのキー。エディタでの日本語の入力と表示も確認 |
| 起動の絵 | 出さない (keys では起動の絵と音を省き、最初の描画で `boot_complete!`)。system_conf の `startup_app` は使える |

## 全画面のアプリを複数持つ (kernel)

**keys のときだけ広がる形にした** (`kernel/fmrb_kernel/keys_desktop.rb`、`KeysDesktopMixin`)。
mouse の全画面の積み重ね (`@fs_stack`)・退避の 1 枠 (`@parked_fullscreen_pid`)・
`fullscreen_switchable` の制限には手を入れていない。

- keys のデスクトップは起動時に `{"cmd":"desktop_keys", x, y, w, h}` (アプリを置く四角) を
  kernel に送る。kernel はこれを受けて初めて keys の動き (`@keys_mode`) になる。
  mouse のデスクトップは送らないので、keys の分岐はどれも最初の行で抜ける。
- アプリが canvas を持ったら (`on_app_started`)、宣言 (`.app.toml` の window_mode) に関係なく
  `_set_app_fullscreen(pid, true, 320, 160)` と `_update_window_position(pid, 0, 10)` で帯の下に置き、
  前に出す。前にいたアプリは suspend する (状態は残る)。デスクトップは suspend しない
  (帯を出し続け、メニュー・一覧・パネルはアプリの上の前景の canvas に描く)。
  全画面の積み重ねは使わないので、`@fullscreen_pid` は keys では常に nil。
- 前のアプリが終わったら (`cleanup_terminated_app` の後に `keys_after_exit`)、キーボードが
  渡った先 (F5 で起動した元のエディタなど) を前へ、無ければメニュー。
- デスクトップからの命令: `keys_show` (前へ)、`keys_menu` (メニューを前へ)、
  `keys_close` (前に出してから、ファイルのアプリには stop、組み込みには quit_request。
  エディタは未保存なら尋ねる)。
- `enter_fullscreen` / `exit_fullscreen` (エディタの F11) は keys では何もしない (常に全画面)。
- **理由**: mouse の積み重ねは「全画面のアプリが他を隠し、デスクトップも止める」形で、
  帯を出し続ける keys とは前提が違う。積み重ねを一覧に広げると、mouse の Ctrl+Tab の
  退避と入れ子の復帰を同じコードで保つ必要が出る。keys を別の小さな状態
  (前にいる pid 1 つと、suspend 済みの印) にすれば mouse の経路は 1 行も変わらない。

全部 mruby の構成のために、64 bit の Linux (sim・native) の kernel の VM プールを
500 KB → 1 MB にした (`components/fmrb_common/include/fmrb_mem_config.h`)。変更前から
mruby の kernel は起動直後に 506 KB / 500 KB (fmrb の pool の数え方で 512000 中 506248) で、
kernel に keys の mixin を足しただけで mouse の起動も `NoMemoryError` で止まった。
端末と wasm (32 bit) は 500 KB のまま (`UINTPTR_MAX` で分ける)。Spinel の kernel は 167 KB。
指示書の「触ってよい範囲」の外を 2 か所触った: このプールの定義
(`components/fmrb_common/`、64 bit の Linux だけ) と、keys のプログラムを端末・sim の
ビルドから外す `main/CMakeLists.txt` の 3 行。どちらも端末の出力を変えない
(regress:size の内蔵 RAM +0、retro・modern の画面は同じ)。

## アプリの宣言

| 欄 | 置き場所 | 意味 |
|---|---|---|
| `screens` | `.app.toml` (flash のアプリ)、`builtin_app_catalog` (組み込み、desktop_common.rb) | 描ける画面の形の並び。`["426x240", "320x170"]` |
| `needs_pointer` | 同上 | マウス・タッチが要るか。keys のメニューには `false` と明記したものだけ |

- 組み込みの宣言は spawner の表ではなく、デスクトップが持つ組み込みの一覧 (名前・アイコンと
  並べて) に置いた。読むのはデスクトップだけで、spawner の表に置くと Ruby から読む口
  (C の binding) と端末の構造体の欄が要るため。
- 対応させたアプリ: エディタ・Shell (宣言 2 つ)。File Manager はデスクトップの一部。
  flash/ の `.app.toml` には足していない (宣言の無いアプリは出ない、が確認できる)。
  keys のメニューは /app/<分類>/<名前>.toml と束 (/app/<分類>/<名前>/<名前>.toml) を読み、
  `launcher_exclude` に従う。
- エディタ・Shell は 320x160 の全画面でそのまま動いた (どちらも利用者の場所の大きさから
  配置を決める作り)。エディタは既定の 12 の字で 13 行、メニューの行も入る。Shell は 51 桁 13 行。
  コードの変更は要らなかった。

## キー (切り替え・Esc の長押し)

native の host_task (`main/kernel/host/host_task.c`、`FMRB_PLATFORM_NATIVE` の中だけ) で扱う。

| 設定 (system_conf) | 既定 | 意味 |
|---|---|---|
| `keys_switcher_key` | `"ctrl+tab"` | 切り替えの一覧を開くキー。修飾 (ctrl・shift・alt) と 1 つのキーを `+` でつなぐ (a-z・0-9・f1-f12・tab・space・comma など)。修飾なしは断って既定に戻す |
| `keys_esc_long_ms` | `1000` | Esc の長押しの時間 (300-5000) |

機種の定義 `system.exit_key = "esc_long"` が「デスクトップでの長押しで終える」を許す
(cardputer_zero と sdl_keys)。`none` なら長押しはアプリを閉じるだけ。

- 切り替えのキー: keys のときは今の Ctrl+Tab・Ctrl+カンマの固定の組の代わりに、設定のキーが
  kernel の cycle_focus を送る。kernel は keys なら一覧をデスクトップに頼む。
- Esc: 押した時点ではアプリへ送らない。設定の時間より前に離せば、押した・離したの 2 つを
  アプリへ送る (アプリの「戻る」)。時間に達したら、離すのを待たずに (host の輪が 10 ms ごとに
  見る): キーボードがアプリにあれば kernel に Ctrl+Q と同じ system_interrupt (ファイルの
  アプリは stop、組み込みは quit_request)、デスクトップにあれば (メニュー・一覧・File Manager)
  native の `fmrb_native_request_quit()` (制御のソケットの quit と同じ出口) で終える。
  キーの繰り返しは見ない (押したままの間の DOWN は捨てる)。
- 親の仮の決めはどちらも成り立った。変えるのは system_conf の 2 項目と機種の定義の 1 項目。

## 受け入れ条件

確かめた構成: 標準 (`rake native:core`、kernel と editor は Spinel、desktop は mruby) と
全 mruby (`rake native:core NATIVE_ENGINE=mruby`、`fmrb_native.rb up --engine mruby`)。

| 条件 | 結果 |
|---|---|
| 1. 帯とメニュー | `ruby tools/fmrb_native.rb up --machine sdl_keys` で `shot` が 320x170、帯 (Family mruby・かなの A・時計) とメニュー (Editor・Shell・File Manager)。ログに `Display 320x170 from the machine definition`、`Desktop: the keyboard-only variant`。Boot complete まで 0.2 s (起動の絵なし)。標準・全 mruby とも |
| 2. 帯の下の全画面 | メニューで Enter → `Keys desktop: PID 5 full screen at (0,10) 320x160`、エディタが帯の下に出て `a`・`abc` が出る。Shell も同じ (`ls` が出る)。File Manager は帯の下いっぱい、↑↓ Enter で /bin に入れる、Esc でメニュー。標準・全 mruby とも |
| 3. 切り替えの一覧 | エディタと Shell を起動し Ctrl+Tab で一覧 (FM-Editor・FM-Shell・メニュー)、↑ Enter でエディタへ (Shell は suspend、エディタは resume)。一覧で Shell を選んで Delete → Shell が終わり (ps から消える)、メニューへ。標準・全 mruby とも |
| 4. Esc | 短押しはアプリに届く (エディタの「保存しますか」の窓が Esc で閉じる)。アプリの中で 1.5 s 押すと `Esc held: closing the app in front` → エディタが未保存を尋ね、`n` で終わってメニューへ。メニューで 1.5 s 押すと `Esc held on the desktop: ending the program` → `native: quit asked for by the machine` でプロセスが終わる (kill -0 で確認)。標準・全 mruby とも |
| 5. かな | Ctrl+Space で帯の枠が A → あ、エディタで `nihongo` が「にほんご」と出る (日本語の表示も確認) |
| 6. 両方の構成 | 1-4 を標準と全 mruby の両方で確認 (上)。回帰の keys の場面は標準構成 |
| 7. 回帰 | `rake regress`: host 19/19 (native の host 試験 397 項目)、描画の記録 205/205。`rake regress:screens`: mouse は **26/26** (retro 8/8、modern 10/10、web 6/6、native 2/2。基準は更新していない)、keys は新しい基準で **native-keys 3/3**。全 mruby の sim: `FULL=1 ONLY=retro-mruby,modern-mruby rake regress:screens` は **4/4** (retro-mruby 2/2、modern-mruby 2/2。kernel のプールを替えた 64 bit の sim でも絵は同じ)。`rake regress:size`: **内蔵 RAM は NARYAv3・TAB5 とも DIRAM +0・IRAM +0・other +0** (Spinel の kernel の静的な内蔵 RAM も 128 B のまま)。flash は基準 6f7b5848 比 NARYAv3 +18,160 B (app の空き 28%)、TAB5 +20,464 B (空き 9%)。ほとんどが libmain.a (+13.6 KB / +15.7 KB: Spinel の kernel に足した keys の mixin、mouse のデスクトップの bytecode の共通化の分) と libmruby.a (+4 KB、基準が古い分) |

## 見立てと違った点・撤回した仮説・踏んだ罠

- **全 mruby の kernel のプールが元から溢れかけていた** (上)。kernel の Ruby を足したら mouse の
  起動ごと止まり、keys の変更の不具合に見えた。変更を外して測り直して、元の値 (506 KB) で
  分かった。
- アプリの置き場所は spawner (C) で決める見立てだったが、kernel が `on_app_started` で置き直す
  形で足りた (起動の途中の窓はメニューの下に隠れる)。spawner の変更はデスクトップの選択だけ。
- エディタ・Shell は変更なしで 320x160 に収まった。
- 一覧の初めの選択が、前にアプリがいないとき「メニュー」の行になり、Enter が何もしないように
  見えた。前のアプリがいるときだけ合わせるようにした。
- 回帰の後片付けは「デスクトップが起動直後と同じ」を見るので、メニューの選択が動いたままだと
  落ちる。起動したら選択を先頭に戻すことにした (操作としても Enter だけでエディタに戻れる)。
- 注入の修飾は SDL の下位 8 bit だけなので Alt が届かない (sim と同じ。L1 の報告どおり)。
  エディタの Alt-F などは道具からは試せない。

## 残件 (L5 へ)

- Cardputer の本体のキーボードで押せる切り替えのキーを実機で決める (Tab と Ctrl があるか、
  Fn の層)。`keys_switcher_key` を変えるだけ。
- APPLaunch の 320x170 の入口 (`.desktop` と起動用の実行ファイル) は足していない
  (`NATIVE_DEB_LAYOUT` に 1 行、L5)。
- Esc の長押しは、キーボードがデスクトップにあれば (File Manager・一覧を含む) 終了になる。
  File Manager はアプリのように見えるので、そこでの長押しは「閉じてメニューへ」の方が
  自然かもしれない (ユーザ確認)。
- 一覧から終えたアプリが前にいたときは、終わった後メニューに戻る (前にいた別のアプリには
  戻らない)。
- 実行中のアプリのエラーの窓 (error dialog) はデスクトップがキーボードを持たないと閉じられない
  (アプリが終われば閉じられる)。
- 起動の絵と音は keys では出していない。`boot_splash` に合わせて出すかは L5 で決める。
- `.app.toml` の 2 つの欄の説明 (fmrb-app-new などの手引き) はまだ書いていない。
- 電池は L6 (`fmrb_platform_sys`)。
