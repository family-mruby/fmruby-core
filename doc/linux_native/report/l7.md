## 0. 音源の二重解放

- 中身: `components/apu_emu/src/apu_if_p4.c` の `apuemu_free()` を `free()` から
  `heap_caps_free()` にした (1 行)。確保の `apuemu_malloc()` は `heap_caps_malloc()` なので、
  確保と解放が対になった。ESP-IDF では 2 つは同じ解放なので端末の動きは変わらない。
  `apu_if.h` の説明 (Linux では malloc/free、と古いことが書いてあった) も直した。
- ほかの食い違いを読んで探した結果、**見つからなかった**:
  - `apuemu_malloc()` の使い手 (NSF・FMSQ の再生器、`audio_p4_task.c` の WAV と再生器、
    `audio_p4_handler.c` の曲の置き場) は、どれも `apuemu_free()` で返している。
  - nofrendo の中 (`nes_apu.c`) は自分の `malloc` と `free` で対になっている。
  - hosted の土台の stub (`hosted/stub/heap_hosted.c`) は `heap_caps_free()` を持っていて、
    ブラウザ版の側 (wasm/) に heap_caps を直に解放する所は無い。
  - 共通のソースで `heap_caps_*alloc` を使う所 (`rd_stream.c`・`fmrb_msg.c`・
    `display_local_*`) は `heap_caps_free()` で返している。
- 確認:
  - 直す前の native は、rpg_demo を開いた最初の 1 つ目で落ちた (再現を確かめた)。
  - 直した後: native の標準と全部 mruby で、rpg_demo・blockgame・breakout を順に開いて
    閉じる (debug の spawn と kill) を 2 回ずつ。6 回とも本体は動き続け、曲は読み込まれている
    (`FMSQ play_slot: playing track ...`)。
  - ブラウザ版: `rake wasm:web` を作り直し、デスクトップの Breakout.py を開いて
    (曲が鳴る所まで進めて) 閉じる、をもう一度。デスクトップは動き続けた。
- コミットは別にした (34ae9a58)。

## 1. Linux のファイルを見せる

### 振り分けの表に足した種類

`components/fmrb_hal/platform/posix/fmrb_hal_file_posix.c` の表の 1 行に `host` という印を
足した。この印の行は「Linux の実ファイルへ素通し」で、実体の場所は「根 + 行の名前より後ろ」
(ほかの行は「根 + 仮想の場所の全部」)。

| Family mruby の場所 | 実体 | 書き込み |
|---|---|---|
| `/mnt/host` | 利用者のホーム (`$HOME`) | 可 (ホームの中だけ) |
| `/mnt/root` | Linux の `/` | 不可 (`FMRB_ERR_READ_ONLY`) |

- 表は 2 行を足しただけで、場所ごとの `if` は無い。sim とブラウザ版の表 (flat) は変えていない。
- 根を空にすると、その場所は出ない (名前は解決されず、一覧にも出ない)。
- 一覧: `/` に `mnt` が、`/mnt` に `host`・`root` が出る (仮の子の表)。どちらも出さない
  設定では `mnt` も出ない。

### 読むだけ・外へ書けないことの作り

書き込みの判定を 1 つの関数 (`check_write`) にまとめ、HAL の書く・消す・名前を変える・
ディレクトリを作る・消す・utime・chmod と、公開の `fmrb_hal_file_path_is_read_only()`
(ディレクトリの HAL と受け取りのファイル転送が先に聞くもの) がすべてこれを通る。

- `/mnt/root` は配布物の木と同じく、OS の権限と関係なく `FMRB_ERR_READ_ONLY`
  (Cardputer は root で動くので OS には止めてもらえない)。
- `/mnt/host` の下は、書く先の実際の場所 (`realpath`) がホームの実際の場所の中にあること
  を確かめる。
  - 書く・utime・chmod は、そのファイル自体 (シンボリックリンクなら指す先) を見る。
    外を指すリンク、どこも指さないリンクは断る。
  - 消す・名前を変える・ディレクトリを作るは、項目を持つディレクトリを見る (リンク自体を
    消すのはよい。指す先は消えない)。
  - まだ無い名前は、いちばん近い有る先祖で判断する (作られる親はその下にしかできない)。
  - `..` は仮想の場所を正規化した時点で畳まれるので、ここには来ない。
  - ホームそのものは消せず、名前も変えられない。
  - 読むのは制限しない (リンクの先が外でもよい。`/` はもともと読める)。
- 断ったときはログに理由を出す (`read-only (it would land outside the home directory)` など)。
- 判定と実際に開くまでの間にリンクを差し替えられる隙は残っている (下の残件)。

### 特殊なファイルの扱い

- `/mnt/host`・`/mnt/root` の下では、普通のファイルとディレクトリだけが解決される。
  装置・FIFO・ソケットは名前の解決で断る (`FMRB_ERR_NOT_SUPPORTED`)。開くと協調の
  機械全体が止まる (FIFO の読み) か、開くだけで何か起きる (シリアルの装置) ため。
- 開くときは `O_NONBLOCK`・`O_NOCTTY` で開き、開いた後に `fstat` で普通のファイルである
  ことをもう一度確かめる。`O_NONBLOCK` は、データを待つ procfs のファイル (kmsg) で
  止まらないためでもある。
- **一覧には出す**。一覧はディレクトリの HAL (lib/add の dir_hal.c、今回の範囲の外) が
  作っていて、範囲の中で隠すことはできない。出したうえで、File Manager では大きさ 0 の
  ファイルとして並び、開くと失敗する (エディタは「Load failed」)。`/dev` を開いて中が
  ほとんど空に見えるより、名前が見えて開けない方が読みやすいと判断した。
- `/proc`・`/sys` の大きさの合わないファイル: File Manager は `stat` で大きさを見るだけで
  中身を読まないので固まらない。`/mnt/root/proc` (数百の項目) も `/mnt/root/dev` も
  すぐ開けた。`/dev/core` (`/proc/kcore` へのリンク) は大きさが 128 TB と出て、表の桁から
  はみ出す (見た目だけ)。

### 設定の項目名

機種の定義に `[files]` を足した。既定はどの機種でも両方を見せる。

| 項目 | 値 | 既定 |
|---|---|---|
| `files.host` | `auto` (利用者のホーム: `$HOME`、無ければ passwd の項目) / ディレクトリ / `none` | `auto` |
| `files.root` | `auto` (`/`) / ディレクトリ / `none` | `auto` |

- `--set files.host=none` のように 1 つだけ変えられる。指したディレクトリが無いときは
  出さず、起動時に 1 行出す。
- 起動のログ: `file_posix: namespace: /mnt/host=<ホーム> /mnt/root=/ (read-only)`。
- Cardputer (root で動く) では `auto` のホームが `/root` になる。

## 2. Linux PC のログイン画面の入口 (cage)

### session の入口の中身

| 置き場所 (amd64 の .deb だけ) | 中身 |
|---|---|
| `/usr/share/wayland-sessions/family-mruby.desktop` | `Name=Family mruby`、`Exec`・`TryExec` は `/usr/bin/family-mruby-session` |
| `/usr/bin/family-mruby-session` | 起動用のシェルの台本 (`native/package/family-mruby-session`) |

- 台本は `cage -s -- /usr/bin/family-mruby --machine linux_pc` を起こす。
  - 環境変数: `SDL_VIDEODRIVER=wayland`、`SDL_VIDEO_WAYLAND_ALLOW_LIBDECOR=0`
    (下の罠)、`DISPLAY` は消す。
  - `-s` は VT の切り替えを許す (固まったときに Ctrl+Alt+F キーで逃げられる)。
  - Family mruby の「終了」でプログラムが終わると cage も終わり、ログイン画面に戻る。
- 設定は `/etc/default/family-mruby-session` (無くてよい。シェルの断片):
  `ROTATE=0|90|180|270` と `FMRB_ARGS="--set ..."`。試すときは `FMRB_SESSION_CONF` で
  別のファイルを指せる。
- cage は `Recommends`。無いとき、項目はログイン画面に出る (`TryExec` は台本の方) が、
  選ぶと台本が「cage is not installed ... install it with 'sudo apt install cage'」を出して
  終了コード 1 で終わる (ディスプレイマネージャはログイン画面に戻る。文はセッションの
  ログ: journal か `~/.local/share/sddm/wayland-session.log`)。
- arm64 の .deb には入れていない (deb_check が確かめる)。

### linux_pc の定義 (`config/machines/linux_pc.toml`)

| 項目 | 値 |
|---|---|
| 画面 | `426x240`、`display.backend = "sdl"`、`scale = "auto"`、`rotate = 0`、`fullscreen = true` (新しい項目) |
| 入力 | `sdl` (コンポジタのキーボード・タッチパッド・マウス) |
| 音 | `sdl` |
| デスクトップ | `mouse` |
| 電源 | `power = ["logind", "exit"]` |
| ファイル | `host = "auto"`、`root = "auto"` |

- `display.fullscreen` (sdl だけ): 窓を出力の全体に広げる。拡大は今の共通の部品のまま
  (整数倍の最大、余りは黒)。配置が変わるたびに
  `native: output 1280x720: frame 426x240 at 3x, 1278x720 at (1,0), black around` を出す。
- `system.power` は `exit`・`logind` の並びも受けるようにした (TOML の配列か
  `--set system.power=logind,exit`)。電源の項目は「終了」「電源を切る」「再起動」「休止」の
  4 つになる。`linux_pc_drm` は今のまま (`logind` だけ)。

### 回転の決め方

**コンポジタ (cage) で回す。Family mruby の `display.rotate` は 0 のまま。**

- 理由: cage の中の SDL の窓が受け取るのはコンポジタの座標のポインタで、タッチパッドの
  動きもコンポジタが出力の向きに合わせて回す。Family mruby の側で絵だけ回すと、
  タッチパッドで右に動かしたカーソルが画面では縦に動く。
- cage の版で回し方が違う。台本が見分ける:
  - cage 0.1 (Ubuntu 22.04 は 0.1.4、24.04 は 0.1.5): `-r` (90 度ごとに 1 つ)。
  - cage 0.2 (Debian trixie は 0.2.0): `-r` が無い。`wlr-randr` が入っていれば、cage の中で
    最初の出力を `--transform 90` などで回してから Family mruby になる。無ければ回さずに
    理由を 1 行出す。
- 書き方 (Chuwi MiniBook X のように液晶が縦向きに付いた機種):

  ```
  # /etc/default/family-mruby-session
  ROTATE=90      # 向きが逆なら 270
  ```

- `display.rotate` は cage を使わない形 (`linux_pc_drm`・fbdev) のためにそのまま残る。

### 音の扱い

SDL にした。デスクトップのログインでは PipeWire (か PulseAudio) が利用者ごとに動いていて、
SDL はそれを自分で見つける。音量は Family mruby の中の音量 (L6 の ALSA の mixer は
`audio.backend = "alsa"` のときだけ開くので、ここでは使わない)。ALSA の `default` は
PipeWire の環境で mixer の要素が揃う保証が無いので避けた。

## ユーザが VM (Kubuntu) で試す手順

1. `.deb` を入れる: `sudo apt install ./family-mruby_<版>_amd64.deb` (cage は Recommends
   なので一緒に入る。入らない設定なら `sudo apt install cage`)。
2. ログアウトし、ログイン画面 (SDDM) の左下のセッションの選択で「Family mruby」を選んで
   ログインする。
3. 画面いっぱいに Family mruby が出る (426x240 の整数倍、余りは黒)。
4. 確かめること:
   - キーボード・タッチパッド (マウス) で操作できる。
   - 音が出る (起動の音)。
   - File Manager の `/mnt/host` にホームが、`/mnt/root` に `/` が見え、`/mnt/host` に
     エディタで保存できる。`/mnt/root` には保存できない。
   - メニューの「Exit」でログイン画面に戻る。
   - 「Power off」「Restart」「Suspend」が本当に働く (polkit の許可。断られたら
     セッションのログに理由が出る)。
5. 縦向きの液晶: `/etc/default/family-mruby-session` に `ROTATE=90` (か 270) を書いて
   ログインし直す。cage 0.1 なら cage が、0.2 なら `wlr-randr` (`sudo apt install wlr-randr`)
   が回す。タッチパッドの向きが絵と合うことを見る。
6. うまく出ないときのログ: `~/.local/share/sddm/wayland-session.log`
   (GDM なら `journalctl --user -b`)。

## 見立てと違った点・撤回した仮説・踏んだ罠

- **cage 0.2 と SDL 2.32 の組で窓が出なかった**。Debian trixie の cage 0.2.0 の中で、
  SDL が `SDL_CreateWindow` の中 (`wl_display_dispatch_queue`) で待ったまま戻らない。
  libdecor の飾りの部品を入れても同じ。`SDL_VIDEO_WAYLAND_ALLOW_LIBDECOR=0` で libdecor を
  使わせないと、すぐ全画面で出た。cage は飾りを描かないので失うものは無い。台本で設定した
  (57083a67)。Ubuntu 22.04 の cage 0.1.4 と SDL 2.0.20 では起きない。
- WSL2 の cage 0.1.4 は `/usr/bin/Xwayland` が無いと起動を断る (Ubuntu 22.04 の cage は
  xwayland を必須にしていない)。24.04 と trixie の cage は xwayland を Depends に持つので、
  入れれば揃う。WSL2 では sudo を使わずに確かめるため、一時の名前空間 (unshare) の中で
  `/usr/bin` に代わりの Xwayland (起動されない) を見せ、`/tmp/.X11-unix` を自分の物にして
  cage を起こした (道具は作業用の一時の場所だけで、リポジトリには入れていない)。
  cage は root では動かない (root に戻れることを嫌う) ので、名前空間を 2 段にした。
- 回転は Family mruby の側 (`display.rotate`) で済むと思っていたが、ポインタの向きの
  ため cage の側にした (上)。そのうえ cage 0.2 では `-r` が無くなっていて、`wlr-randr` を
  使う道も要った。
- `fmrb_native.rb status` は、コンテナの中で動くプログラムの pid が手元に無いので
  「not running」と出る (shot と入力の注入は run dir のソケットで通る)。
- 試験のための確認で、WSLg の上に全画面の窓と cage の窓が数十秒ずつ出た
  (利用者の画面に出る)。
- エディタで `/mnt/host` のファイルを保存すると、末尾の改行が無い形で書かれた
  (標準・全部 mruby とも)。エディタの今の書き方で、`/mnt/host` に限らない。触っていない。

## 残件

- 書き込みの判定と実際に開くまでの間の隙: 判定の後にリンクを差し替えられると、外へ
  書けてしまう。同じ利用者のプログラムが狙ってやる場合に限られる。`openat` と
  `O_NOFOLLOW` で 1 段ずつ辿る形にすれば閉じられる。
- 一覧から特殊なファイルを隠すのは、lib/add の dir_hal.c を触ることになるので
  していない (開けないだけ)。
- `/proc/kcore` のような大きさの合わないファイルの大きさの表示がはみ出す。
- `Dir.getwd` (getcwd) は Linux の実際の場所を返す (今までどおり)。
- 開発中 (リポジトリの flash/) の `/mnt` には手元だけの `sd` も並ぶ。パッケージには無い。
- 実機・VM で確かめること: 上の手順の 4・5 (入力、音、logind、回転とタッチパッド)。
  `linux_pc_drm` は VM と実機でユーザが試す (WSL2 では断る) のは今のまま。
