# L12b 報告: PC では Linux の IME で日本語を打つ

> 状態: 完了 (受け入れ 7 点。ブラウザ版の画面の比較と VirtualBox の Kubuntu での確認は残件) | 更新: 2026-10-28 | 指示書は instruction_l12b.md。ブランチは fmruby-core の feature/linux-native (develop へは未マージ・未 push)

コミット: 7b60baa7 (コードと試験と usage.md の 11 章)。この報告は別のコミット。基準の絵は更新していない。

## 1. 全体の形

| 形 | IME の口 | Family mruby のアプリ | IME が無いとき |
|---|---|---|---|
| コンポジタ (`linux_pc_wl`) | コンポジタが input-method-v2・text-input-v3・virtual-keyboard-v1 を出す。fcitx5 をコンポジタが起こす | コンポジタ自身が text-input の側に立つ | 今のかな入力 |
| SDL の窓 (`sdl`) | SDL の text input (X11 では D-Bus の ibus・fcitx、Wayland では text-input-v3) | SDL_TEXTINPUT・SDL_TEXTEDITING を受ける | 今のかな入力 |
| cage (`linux_pc`)・Cardputer Zero・端末・sim・ブラウザ版 | 使わない | 今のかな入力のまま | — |

- 機種の定義に `input.ime` (`none` / `sdl` / `wayland`、既定は `none`) と `compositor.ime` (コンポジタが起こす IME のプログラム、既定 `""`) を足した。`linux_pc_wl` は `wayland` と `fcitx5`、`sdl` は `sdl`。cage の `linux_pc` と Cardputer の 2 つは `none` のまま。`input.ime = "sdl"` は display が sdl、`wayland` は wlroots のときだけ通る (`native_machine_check`)。
- 機械の側 (host_task.c) は「IME がいる」という 1 つの旗だけを見る。旗が立っている間、今のかな入力は止まる (後述)。旗はネイティブ版の主スレッド (コンポジタか SDL の窓) が立てる (`native/backend/native_ime.{h,c}`)。

## 2. コンポジタの形

### input-method と text-input のつなぎ方 (`native/wlr/wl_ime.c`)

- wlroots 0.19 の `wlr_input_method_manager_v2`・`wlr_text_input_manager_v3`・`wlr_virtual_keyboard_manager_v1` を作る (`input.ime = "wayland"` のときだけ)。IME は 1 つだけ。2 つ目には unavailable を返す。
- Linux の窓: どの wlroots の机にもある中継。キーボードのフォーカスのある窓のクライアントの text input に enter・leave を送り、それが enable したら IME を activate して内容の種類と周りの文字を渡す。IME の commit (変換中の文字、確定した文字、周りの削除) はそのまま text input へ送る。foot はこれで日本語が入る (受け入れ 1)。
- キー: IME が今のフォーカスの text input を受け持ち、キーボードを掴んで (keyboard grab) いる間は、キーボードのキーは IME へ行く。窓の切り替えのキー (Ctrl+Tab・Ctrl+,) はいつも Family mruby。IME が使わなかったキーは IME の仮想キーボードで戻ってきて、ふつうのキーと同じくフォーカスの所へ行く。キーは押した所で離す (キーボードごとに押した先を覚える。IME の仮想キーボードと実のキーボードが同じキーを押しても混ざらない)。
- IME の仮想キーボードは自分の配列 (keymap) を持つので、`keyboard_layout` に合わせて配列を上書きしない。

### Family mruby のアプリへの渡し方

- Family mruby がキーボードを持ち、前のアプリが「入力の位置」を知らせているとき (次節)、コンポジタが text input の代わりになって IME を activate する。内容の種類は普通の文字、周りの文字は渡さない。
- IME が確定した文字は、主スレッドから入力の輪 (`NATIVE_INPUT_TEXT`、1 件 12 バイト) で入力のタスクへ、そこから host_task の新しい知らせ (`HOST_MSG_HID_TEXT`、1 件 16 バイト) で前のアプリへ、**今のかな入力が確定したかなを送るのと同じ 1 バイトずつのキー** として届く。制御文字は送らない。アプリの側は何も変えていない (エディタも Shell も、かな入力の UTF-8 を組み立てる所でそのまま受ける)。
- 入力の位置を知らせていないアプリ (ゲーム) では IME を activate しない。キーは IME を通らずそのまま届く。

### 入力の位置の口

- `FmrbApp.set_text_cursor(x, y, h)`: canvas の座標 (行の左上) と行の高さ。`h = 0` で「今は文字を打たない」。mruby (`lib/add/picoruby-fmrb-app/ports/esp32/app.c`) と Spinel (`fmrb_spx_app_set_text_cursor`、`fmrb_app_base_spinel.rb`) の両方。`sig/fmrb_app.rbs` に足した (要約 105 バイト)。
- エディタは `draw_cursor` で、Shell はカーソルの下線を描く 2 か所で呼ぶ。エディタはカーソルが見えないときに `h = 0`。
- 端末・sim・ブラウザ版では C の本体が空 (何も覚えない)。覚える表 (アプリごとの位置) はネイティブ版のビルドにだけある。
- host_task が 20 ms ごとに、前のアプリの位置を窓の位置で足してフレームの座標にし、主スレッドへ渡す (変わったときだけ番号が進む)。コンポジタはそれを見せ方 (倍率、全画面のアプリの view) で出力の座標にする (`comp_route_from_frame`)。

### 候補の窓と preedit

- **調べたこと**: fcitx5 5.1 の input-method-v2 の口 (waylandim) は、相手が変換中の文字を出せるものとして決め打ちしている (能力の旗にいつも Preedit が立つ)。候補の窓 (input popup) には候補と注釈は出るが、変換中の文字そのものは出ない。fcitx5 の設定 (「アプリに preedit を出す」を切る) を変えれば候補の窓に出るが、利用者の設定を書き換えることになる。
- **決めたこと: preedit はコンポジタが描く**。アプリの中ではなく、コンポジタが Family mruby の字体 (efontJA 12・16、行が 12 未満なら misaki 8) で、アプリのカーソルの位置に、絵の倍率で重ねる (`native/backend/native_preedit.cpp`、LovyanGFX の sprite を自前の画素に)。白地に黒い字と下線、変換中の文節は青地に白、カーソルは縦の線。絵の矩形の中に収める (右へはみ出すなら左へずらす)。アプリは位置を知らせるだけで、変換中の文字を知らない。
  - 選ばなかった形: アプリの中に出す (エディタと Shell が変換中の文字を描く) のは、新しい知らせの種類と、エディタ (Spinel と mruby の両方) と Shell の描き方を変える大きな変更になる。今の形で「打っている所に文字が出る」は満たせ、アプリを変えずに済む。欠点は、変換中の文字がカーソルの右の文字の上に重なること (XIM の over-the-spot と同じ見え方)。
- 候補の窓は、変換中の文字の箱 (無ければカーソル) の下に、左を揃えて置く。下に入らなければ上、右にはみ出すなら左へずらす (`comp_ime_place`、host の試験あり)。どれも絵の矩形の中。IME にはその箱を `text_input_rectangle` で知らせる (変わったときだけ。毎回送ると IME が描き直して commit し、また送る、の繰り返しになるため)。
- Linux の窓では、窓の text input の cursor rectangle (面の座標) に窓の位置を足した所の下に置く。

### 切り替えのキーと表示

- 半角/全角・Ctrl+Space は IME に渡る (IME が文字を受け持っている間は全部のキーが IME へ行く)。IME が受け持っていないとき (ゲームの前、Linux の窓に text input が無いとき) は Family mruby に届くが、かな入力は止まっているので何も起きない。
- **かなの表示は PC では出さない (IME がいる間)**。input-method-v2 には IME の状態 (英字かかなか) を知る手段が無い。host_task が前のアプリとデスクトップに KANA_MODE の値 3 (`FMRB_KANA_MODE_IME`) を送り、メニューバーの指示器とエディタの状態の行の `[A]` を隠す。端末は 3 を送らない。
  - 前に出たアプリと、最初に入力の位置を知らせたアプリにも送る (起動の途中で送った値は、アプリが自分の初期値で上書きすることがあったため。エディタで実際に起きた)。
  - IME がいなくなると今のかなの状態を送り直し、表示は戻る。
  - 隠れた指示器は押せない。アプリが `set_kana_mode` を呼んでも、IME がいる間は断ってログに 1 行。
- IME がいる間、host_task は今のかな入力 (`fmrb_kana_feed`) を通さない。IME が来たときにかな入力の状態は切 (保留のローマ字も捨てる) にする。

### IME の起こし方と無いときの戻り方

- コンポジタが自分の Wayland の口を作った後に `compositor.ime` (既定 `fcitx5`) を `/bin/sh -c` で起こす。`DISPLAY` は外す (fcitx5 が X11 の口のために Xwayland を起こさないように。L9b の「最初の X11 のプログラムで Xwayland を起こす」を守る)。終わるときはコンポジタが止める。
- `PATH` に無ければ 1 行: `native: compositor: IME: fcitx5 is not installed: Family mruby keeps its own kana input`。かな入力は今のまま。
- fcitx5 が input-method-v2 につながると `native: IME: an IME (input-method-v2, pid N) types for the Family mruby apps; their own kana input steps aside`、host_task が `the PC's IME types for the apps: ...`。fcitx5 が終わると `no IME on the PC any more: Family mruby's kana input is back` で、かな入力が戻る。
- セッションの入口 (`family-mruby-session`) はそのまま (コンポジタが起こすので台本では起こさない)。頭の説明に、fcitx5 があれば使うこと、`FMRB_ARGS="--set compositor.ime="` で外せることを書いた。
- `.deb` は `Suggests: fcitx5, fcitx5-mozc` (amd64)。Depends・Recommends にはしない。入れるかは利用者が決める (Recommends だと入れたときに IME が入り、日本語を使わない人の PC でかな入力が止まるため)。

## 3. SDL の窓の形 (`native/output/output_sdl.c`)

- `input.ime = "sdl"` のときだけ。起動時は SDL の text input を止め、前のアプリが入力の位置を知らせている間だけ `SDL_StartTextInput` し、`SDL_SetTextInputRect` でその位置 (窓の座標) を IME に知らせる。ゲームのキーは IME を通らない。
- IME が使ったキーは SDL がキーの出来事にしない (X11 の D-Bus の IME でも Wayland の text-input-v3 でも)。確定した文字は `SDL_TEXTINPUT` で来て、コンポジタと同じ `native_ime_commit` でアプリへ行く。
- ふつうに打ったキーも `SDL_TEXTINPUT` を出す (キーは既に渡してある)。**キーを渡した直後、そのキーを離す前に来た TEXTINPUT はそのキーの文字として捨てる** (Ctrl・Alt・GUI 付きと文字の無いキーは数えない)。それ以外の TEXTINPUT が IME の確定。
- 変換中の文字 (`SDL_TEXTEDITING`、長いものは `SDL_TEXTEDITING_EXT`) は、コンポジタと同じ描き方で、絵の上のカーソルの位置に重ねる。
- SDL には IME の有無を聞けない。最初の変換中の文字か、キーに由来しない確定の文字が来た時点で「IME がいる」とし (`native: IME: the desktop's IME (SDL's text input) types ...`)、かな入力はそこから止まる。それまでは今のかな入力が働く (受け入れ 3 の形)。いなくなったことは分からないので、そのセッションの間は止まったまま。
- cage (`linux_pc`) は同じ SDL の窓だが `input.ime = "none"` なので、SDL の text の出来事は今どおり捨てる。

## 5. 判断したこと

- **preedit はコンポジタ (SDL の窓では出力) が Family mruby の字体でカーソルの位置に重ねて描く** (2 章)。代わりはアプリの中に描く形。
- **IME を受け持つのは、前のアプリが入力の位置を知らせているときだけ** (ゲームのキーは IME を通さない)。代わりは Family mruby がキーボードを持つ間はいつも受け持つ形 (IME が英字のときも全部のキーが IME を回る)。
- **IME がいる間はかなの表示を隠す** (KANA_MODE の値 3)。指示書の「分からなければ PC では出さない」に従った。IME がいないときは今どおり出る。
- **fcitx5 はコンポジタが起こす** (`compositor.ime`)。セッションの台本で起こさないのは、コンポジタの Wayland の口ができた後でないとつながれないため。`DISPLAY` を外して起こすので、X11 のプログラム (Xwayland) は fcitx5 の XIM を使えない (残件)。
- **`.deb` は Suggests** (2 章の末)。
- **Linux のアプリの環境変数 (`GTK_IM_MODULE`・`QT_IM_MODULE`) は触らない**。GTK と Qt 6 は Wayland では text-input を使う。利用者の環境に `GTK_IM_MODULE=fcitx` などがあれば、アプリは D-Bus で fcitx5 に直接つながる (それでも動く見込みだが、候補の窓の置き場所は fcitx5 次第)。
- **SDL の窓の IME は「IME の印を見たら」止める** (3 章)。SDL には有無を聞く口が無いため。
- wl_check (L9a からの確認) は IME なしで流す (4 章の 5)。

## 6. VirtualBox の Kubuntu 26.04 で人が確かめる手順

1. VM に fcitx5 と mozc を入れる: `sudo apt install fcitx5 fcitx5-mozc` (Kubuntu の日本語の設定で既に入っていれば不要)。Plasma で使っている人は、Plasma の「入力メソッド」の設定がそのまま使われる (設定は `~/.config/fcitx5/`)。初めてなら Plasma にログインして `fcitx5-configtool` (または システム設定 > 入力メソッド) で「Mozc」を足しておく。切り替えのキーは既定で Ctrl+Space と半角/全角。
2. 開発機で `.deb` を作って VM に写し、`sudo apt install ./fm.deb`。
3. ログイン画面で「Family mruby」を選んでログイン。`~/.local/share/sddm/wayland-session.log` に `native: compositor: IME: started "fcitx5"` と `native: IME: an IME (input-method-v2, pid N) types ...` が出ること。
4. Family mruby のメニューからエディタを開き、半角/全角 (か Ctrl+Space) で mozc に切り替えて「nihongo」と打つ。カーソルの位置に白地の「にほんご」が出て、Space で「日本語」に変わり、もう一度 Space で候補の窓がその下に出る。Enter で確定し、エディタに入ること。メニューバーのかなの指示器とエディタの右下の `[A]` が出ていないこと。
5. Shell (`!` の外のプロンプト) でも同じく打てること。ゲーム (shooter など) では mozc に切り替えていてもキーがそのまま効くこと。
6. Linux の区分から Konsole と Kate を開き、同じく日本語が打てること。候補の窓が打っている所の近くに出て、Family mruby の絵の外 (黒い帯) にはみ出さないこと。Firefox (Wayland) でも同じ。
7. fcitx5 を外して (`sudo apt remove fcitx5-mozc fcitx5` か、`/etc/default/family-mruby-session` に `FMRB_ARGS="--set compositor.ime="`) ログインし直すと、ログに `fcitx5 is not installed: Family mruby keeps its own kana input` (外した場合) が出て、エディタで Ctrl+Space の今のかな入力 (ローマ字 → かな) が働き、指示器が出ること。
8. 余力があれば SDL の窓の形: Plasma の中の端末から `family-mruby --machine sdl`。エディタで Plasma の IME (Ctrl+Space など) に切り替えて日本語が打てること、変換中の文字がカーソルの位置に出ること、候補の窓がその近くに出ること。
9. X11 のアプリ (`QT_QPA_PLATFORM=xcb kate` など) では IME は使えない見込み (残件)。

## 7. 撤回した見立て・踏んだ罠

- 変換中の文字が青と黒の縞になった: LovyanGFX は色の型で意味を変える (int は RGB888、uint8_t は RGB332、uint16_t は RGB565)。`#define` の色が int で渡り、8 ビットのつもりの sprite も 16 ビットだった。16 ビットの画素 (バイトが入れ替わった RGB565) を読む形にして色を uint16_t の定数にした。
- 前のアプリへ値 3 を送ってもエディタの `[A]` が残った: エディタが起動の途中 (アプリの文脈が RUNNING になった直後) に受け取り、その後の初期化で自分の値 0 に戻していた。最初に入力の位置を知らせたときにもう一度送るようにした。
- `comp ime` の答えに空白の入った項目を書き、道具の読み方 (空白で区切って `=` で分ける) が壊れた。
- 入れ子の SDL の窓の確認で、窓の上の端を押すと中の Family mruby のメニューバーを押してキーボードが Shell から外れた (確認の台本の誤り)。

## 8. 残件

- VirtualBox の Kubuntu での確認 (6 章)。実際の Plasma の設定の fcitx5、Konsole・Kate・Firefox、SDL の窓の形 (sdl2-compat の上の SDL3)。
- X11 のプログラム (Xwayland) の IME: fcitx5 を `DISPLAY` なしで起こすので XIM は無い。`GTK_IM_MODULE=fcitx` などの D-Bus の道なら使える見込み (未確認)。
- SDL の窓の X11 の D-Bus の道 (ibus・fcitx を SDL が直接使う形) は試していない。SDL の窓では IME がいなくなったことが分からない (そのセッションの間はかな入力が止まったまま)。
- 変換中の文字はカーソルの右の文字に重なる (over-the-spot)。アプリの中に差し込む形 (on-the-spot) にするかはユーザの判断。
- IME の状態 (英字・かな) は表示しない (分からない)。fcitx5 の小さな窓 (切り替えたときに出る「あ」など) はそのまま候補の窓の場所に出る。
- 押したままのキーの繰り返し: IME が受け持っている間、繰り返しは IME の側の速さになる見込み (確かめていない)。
- ブラウザ版の画面の比較 (開いたままのブラウザ)。
