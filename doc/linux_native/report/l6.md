# L6 報告: OS のサービス (電池・ネットワーク・音量・電源)

> 状態: 完了 (受け入れ 6 点) | 更新: 2026-10-27 | 指示書は instruction_l6.md。ブランチは fmruby-core の feature/linux-native (develop へは未マージ・未 push)

## 受け口の形と置き場所

- `main/kernel/fmrb_platform_sys.h` に関数の表 `fmrb_platform_sys_t` を置いた
  (display_backend_t・audio_backend_t と同じ形)。項目はネットワーク (`net_info`・
  `net_connected`)、電池 (`battery`)、OS の音量 (`volume_get`・`volume_set`・`mute_set`)、
  電源 (`power_actions`・`power`)。どれも NULL でよく、呼ぶ側の短い関数
  (`fmrb_platform_sys_net_info()` など) が NULL を「値なし」(false・0) にする。
- 既定の表 (`main/kernel/fmrb_platform_sys.c`) は、今までの答えをそのまま移したもの。
  端末・sim・ブラウザ版はこの表で答える。表を差し替える口 (`fmrb_platform_sys_install`) の
  ポインタは `FMRB_PLATFORM_NATIVE` の中だけにあり、端末では変数を 1 つも持たない。
- ソースの一覧: `main/CMakeLists.txt` (端末と sim) と `hosted/hosted.cmake` (ブラウザ版と
  native) に 1 行ずつ。

### 移した端末の実装

| 呼び名 (Ruby) | 前の置き場所 | 今 |
|---|---|---|
| `FmrbApp.wifi_info`・`wifi_connected?` (mruby) | `lib/add/picoruby-fmrb-app/ports/esp32/app.c` の中の `#if` 3 通り (WiFi のある端末・Linux のビルド・どちらでもない) | 既定の表の `net_info`・`net_connected` (同じ 3 通り) |
| 同 (Spinel) | `main/app/fmrb_spx_app.c` の中の同じ 3 通り (写し) | 同じ表を呼ぶ。写しが無くなった |
| `FmrbApp.reboot` (mruby・Spinel) | 2 か所に `esp_restart()` / `exit(0)` | 既定の表の `power(FMRB_SYS_POWER_RESET)` (中身は同じ) |
| 音量・ミュート (`fmrb_host_*`、host_task.c) | 中の音量だけ | 先に OS の音量を聞き、無ければ今までどおり中の音量 |
| 時計の設定 | (変えていない。下) | |

- 電池は今まで値を出す端末が無いので、既定の表では「値なし」。
- Ruby の呼び名は変えていない。足したのは `FmrbApp.power_actions` (電源の項目の
  Symbol の並び)、`FmrbApp.power(sym)`、`FmrbApp.battery_level` (0-100 か nil)、
  `FmrbApp.battery_charging?`。`wifi_info` の Hash には、OS が教えるときだけ `:signal` (0-100)
  が加わる。電池の 2 つは 1 秒ごとの描画のためにオブジェクトを作らない形にした。
  Spinel の FmrbApp には足していない (デスクトップはどちらの構成でも mruby)。
- `power_actions` は、端末では `[:reset]`、sim とブラウザ版では `[]`。mouse の
  デスクトップの「再起動」の項目は今まで `PLATFORM == "esp32"` で出していたが、
  これを `power_actions` から作るようにした。端末・sim・ブラウザ版で出る項目は同じ。

## linux の実装 (native/sys/)

機種の定義の `system.services = "linux"` のとき、`main_native.c` が音の出力を開いた後で
表を差し替える (`sys_linux_install`)。`sdl`・`sdl_keys` も `linux` にした (WSL2 でも
sysfs と procfs は読める。電池は無いので値なし)。

| 項目 | 読み取り先 | ファイル |
|---|---|---|
| 電池 | `/sys/class/power_supply/*` のうち `type` が `Battery` (`present` が 0 なら飛ばす) の最初のもの (名前の順)。`capacity`、無ければ `charge_now/charge_full`、`energy_now/energy_full`。`status` が `Charging` なら充電中 | sys_linux_read.c |
| つながっているか | `/proc/net/route` の既定の経路 (Destination 0、RTF_UP) の口が `/sys/class/net/<口>/operstate` で up (か unknown)。経路が無ければつながっていない | sys_linux_read.c |
| 電波の強さ | `/proc/net/wireless` のその口の link の値を 70 で割った % | sys_linux_read.c |
| SSID | `SIOCGIWESSID` の ioctl (無線の拡張の読み取り。cfg80211 が答える) | platform_sys_linux.c |
| IP・名前 | `getifaddrs` のその口の IPv4、`gethostname` | platform_sys_linux.c |
| 音量・ミュート | ALSA の simple mixer。要素は機種の定義の `audio.mixer` (`auto` は Master・PCM・Speaker・Headphone・Digital・DAC の順、無ければ再生の音量を持つ最初の要素)。ミュートは要素の再生のスイッチ、無ければ音量を最小にして戻す | sys_linux_mixer.c |
| 電源 | `exit`: `fmrb_native_request_quit()`。`logind`: system bus の `org.freedesktop.login1.Manager` の `PowerOff`・`Reboot`・`Suspend` (引数 interactive = false) | platform_sys_linux.c |

- **書き込みの呼び出しは入れていない** (接続・切断・設定の変更なし)。NetworkManager の
  D-Bus は使わず、ファイルと読み取りの ioctl だけで済ませた (ライブラリを増やさない)。
- D-Bus は libsystemd の sd-bus を**実行時に dlopen** で開く。ビルドに開発用の
  ヘッダが要らない (WSL2 の手元に libsystemd-dev が無く、入れるには sudo が要る)。
  `.deb` の Depends には `libsystemd0` を足した (dpkg-shlibdeps には見えないので
  native.rake で明示)。trixie の素のイメージに元から入っているので、依存の解決は増えない。
- logind の呼び出しは待つ (polkit の判断を待つ) ので、L2n の blocking-call gate の
  補助スレッドで行う。sysfs・procfs の読み取りは小さなファイルなので直接読む。
- mixer が開けるのは `audio.backend = "alsa"` のときだけ。開けたら、kernel が
  system_conf の `audio_volume`・`audio_mute` を中の音量に当てず (中は最大・ミュートなし)、
  デスクトップの音量とミュートの操作は mixer を動かし、system_conf には書かない
  (値は OS が持つ)。開けないとき (SDL の出力・WSL2・ALSA の null や file の装置) は
  今と同じ中の音量。起動のログに `native: volume: the mixer Master on default` か
  `native: volume: the internal volume (<理由>)` が出る。
- 試験のための差し替え: 環境変数 `FMRB_NATIVE_SYSFS`・`FMRB_NATIVE_PROCFS` で
  読む木を替えられる (host 試験と、偽の電池を画面で見るのに使った)。

### 足した機種の定義の項目

| 項目 | 値 | 既定 | 機種 |
|---|---|---|---|
| `audio.mixer` | `auto` / `none` / 要素の名前 | `auto` | ALSA の 3 機種に `auto` と明記 |
| `system.power` | `exit` / `logind` | `exit` | `cardputer_zero`・`cardputer_zero_hdmi`・`sdl`・`sdl_keys` は `exit`、`linux_pc_drm` は `logind` |
| `system.power_log_only` | `true` / `false` | `false` | (どの定義にも書かない。`--set` で使う) |

`system.services` の既定 (定義に書かないとき) も `linux` にした (`sdl.toml` と組み込みの
既定が同じであることを試験が見ている)。「L6 で実装」の起動時の注意の行は消した。

## 電源の形とログに出すだけの形

- `exit` の機種: デスクトップの電源の項目は「終了」だけ。選ぶとプログラムが終わる
  (Cardputer では APPLaunch に戻る)。`FmrbApp.reboot` (Config の Save & Reboot など、
  端末の再起動) も native では「終える」になる (PC の再起動にはしない)。
- `logind` の機種: 「電源を切る」「再起動」「休止」の 3 つ。
- **ログに出すだけ**: `--set system.power=logind --set system.power_log_only=true`。
  選ぶと `power: logind org.freedesktop.login1.Manager.PowerOff(false) (log only: system.power_log_only, not sent)`
  のように出て、D-Bus には何も送らない。試験は全部この形で流した。
- mouse のデスクトップ: メニューの最後に項目、選ぶと今の確認の窓 (「Family mruby を
  終了しますか?」など)、Yes で kernel へ `power` → kernel がデスクトップへ `do_power`
  (再起動の `reboot` → `do_reboot` と同じ往復) → `FmrbApp.power`。
- keys のデスクトップ: メニューの最後に項目。「終了」はすぐ終える (Esc の長押しと同じ)。
  3 つの項目は画面の下に「電源を切りますか? Enter:はい Esc:いいえ」の行を出して聞く。
  Esc の長押しはこの行も閉じる。
- 文字列は i18n の表に足した (en・ja、`power_exit` ほか 8 つと、keys の `keys_confirm_help`)。

## デスクトップ

- mouse: 電池は空きメモリの表示の左に、値があるときだけ (電池の形と「64%」、
  充電中は「64+」)。値が無い端末・sim・ブラウザ版では何も描かない (今の見た目のまま)。
  ネットワークの窓はもともと状態だけ (つながっているか・AP・IP・名前と、Refresh・Close) で、
  設定の操作は無い。OS が電波の強さを教えるときだけ AP の行に「(70%)」を足した。
- keys: 帯の右、かなの枠の左に電池 (値があるときだけ)。
- 時計の設定: sim と同じ扱いのまま (窓は出るが、Linux では時計を変えずログに出すだけ。
  `PLATFORM == "esp32"` のときだけ書く)。native も Linux の時計を変えない。

## L3b・L5b (実機) で確かめること

- 電池の sysfs の名前: Cardputer Zero の電池が `power_supply` に `type = Battery` で出るか、
  `capacity` を持つか (持たない、あるいは電池の IC のドライバが無い場合は値なしのまま)。
- mixer の要素: ES8389 の ALSA の simple mixer の要素の名前 (auto の候補に当たるか)、
  再生のスイッチの有無、音量の段の分かれ方。合わなければ `audio.mixer` に名前を書く。
  HDMI に出すとき (`cardputer_zero_hdmi`) の mixer。
- ネットワーク: Raspberry Pi OS の無線の口 (brcmfmac) が `/proc/net/wireless` と
  `SIOCGIWESSID` に答えるか (SSID が出るか)。NetworkManager の有無は今の作りでは問わない。
- APPLaunch から起動したとき (root) の「終了」で、画面と入力が APPLaunch に戻るか。
- PC (L7): logind の 3 つが本当に働くか (polkit の許可。interactive = false なので
  許可が無ければ断られ、ログに理由が出る)。

## 見立てと違った点・撤回した仮説・踏んだ罠

- NetworkManager の D-Bus を使う見立てだったが、SSID 以外は procfs・sysfs で足り、SSID も
  読み取りの ioctl で取れるので使わなかった。D-Bus は logind の電源だけ。
- sd-bus をリンクする見立てだったが、手元に開発用のヘッダが無く sudo が要るので、
  実行時に開く形にした。ビルドの像 (native/docker) も変えずに済んだ。
- mouse のデスクトップの「再起動」の項目の条件 (`PLATFORM == "esp32"`) を
  `power_actions` に置き換えると、sim とブラウザ版で項目が増えるのではと心配したが、
  既定の表が Linux のビルドでは空を返すので同じになった。
- host の C の試験は `-Werror` で、`snprintf` の切り詰めの警告で落ちた (native の本体の
  ビルドでは出ない)。道のつなぎを、長さを確かめる関数にまとめた。
- 偽の電池を画面で見るために、木の差し替えを環境変数でも効くようにした (試験の道具)。

## 残件

- Spinel の FmrbApp には `power_actions`・`power`・`battery_*` が無い (デスクトップは mruby)。
- 画面の明るさ (backlight) は計画の受け口の表にあるが、指示書の範囲外なので入れていない。
- 有線で IP が取れないとき、ネットワークの窓の IP の行が空になる (端末に合わせて「-」に
  するにはデスクトップの共通の部分を変えることになるので触っていない)。
- native のネットワークの窓の名前の行は OS のホスト名に `.local` を付けて出す
  (Raspberry Pi OS は avahi で引ける見込み。実機で確かめる)。
- L5a で見つけた FMSQ の曲で native が落ちる不具合は残っている (範囲外)。
