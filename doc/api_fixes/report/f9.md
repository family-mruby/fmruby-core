# F9 ESP32 のビルドの選択が前のビルドと違うときに止まる守りを、全部の選択に広げる

> 2026-11-26 | サブ (Opus) の報告。指示書は instruction_f9.md、計画は plan.md の決定 24。ブランチ `api-fixes-f9`。push していない。

## 1. 結果

- `rake build:esp32` は、ファームの中身を変える環境変数 13 個 (.env とボードの既定を足した後の値) を
  `build/fmrb_build_options.json` に書く。次の `build:esp32` と `rake flash`・`flash:app`・`flash:app_sync`・
  `flash:keep_home`・`flash:keep_home_serial` は、今の値と比べて違えば名前・前と今の値・直すコマンドを出して止まる。
  `build:esp32` は `setup` より前 (0.1 秒で止まり、ビルドは始まらない)、flash はポートに触る前に止まる。
- F8 の `build/fmrb_editor_option` だけの守りはこれに置き換えた (記録の無い build/ ではその値を読み、記録を書いたら消す)。
- 抜け道は `BUILD_OPTS_OK=1` (`STALE_OK=1` の流儀)。止まる文を warn に出して続ける。
- 中身は `rakelib/build_options.rb` (rake に依存しない Ruby のモジュール `FmrbBuildOptions`)。`rakelib/build.rake` の
  `build:esp32_options` (`build:esp32` の前提)、`rakelib/device.rake` の `flash_options` (flash の 5 つの前提) が呼ぶ。
- ビルドの既定の値・sdkconfig・CMake がソースを選ぶ条件・sim/ネイティブ版/ブラウザ版のビルドは変えていない。

## 2. 環境変数の表

「読む所」は ESP32 のファームのビルドで効く所。値は守りが比べる形 (`current`)。

### ファームの中身を変える (守りが比べる)

| 名前 | 比べる値 | 読む所 |
|---|---|---|
| `FMRB_HW_TARGET` | 文字列 (空 = ボード名なし: NARYAv3 の sdkconfig、ボードの既定なし) | Rakefile (`BOARD_BUILD_DEFAULTS`・`ESP_CHIP`)、build.rake (sdkconfig.defaults・system_conf・`-DFMRB_HW_TARGET`)、CMake の cache |
| `FMRB_KERNEL_ENGINE` | 空なら mruby | Rakefile → `ENGINE_ENV_OPTS` → main/CMakeLists.txt |
| `FMRB_APP_ENGINE_DESKTOP` | 同上 | 同上 |
| `FMRB_APP_ENGINE_EDITOR` | 同上。`FMRB_EDITOR=0` のときは none (main/CMakeLists.txt と同じ) | 同上 |
| `FMRB_FFT_SPINEL` | 0/1 (既定 1) | Rakefile (spinel:gen)、main/CMakeLists.txt |
| `FMRB_FONT_JA` | 0/1 (既定 1) | 直下 CMakeLists.txt (P4 のフォントの像)、fmrb_hw_defines.cmake (`FMRB_NO_FONT_JA`)、build.rake (font_ja:image) |
| `FMRB_ASTERISM` | 0/1。**P4 は常に 1** (P4 は変数によらず入る) | lib/upstream/family_mruby_esp32.rb、components/picoruby-esp32/CMakeLists.txt |
| `FMRB_IMU` | 0/1。**P4 は常に 1** | lib/upstream/family_mruby_esp32.rb |
| `FMRB_EDITOR` | 0/1 (既定 1) | family_mruby.gembox、components/picoruby-esp32/CMakeLists.txt、main/CMakeLists.txt、rakelib/checkpoint.rake |
| `FMRB_GC_PROFILE` | "1" か否か | family_mruby_esp32*.rb、mruby_abi_defines.cmake |
| `FMRB_TASK_SELF_TICK` | "1" か否か | family_mruby_esp32*.rb、components/picoruby-esp32/CMakeLists.txt |
| `FMRB_DISPLAY_BACKEND` | cpu か ppa (cpu 以外は同じ) | main/CMakeLists.txt |
| `DOCKER_IMAGE` (`ESP_IDF_VERSION` から) | Rakefile の `IMAGE` | 全部の idf.py (ツールチェーンと IDF そのもの) |

### 中身を変えるが、毎回渡るので食い違わない (比べない)

| 名前 | 理由 |
|---|---|
| `FMRB_RELEASE` | build.rake が `-DFMRB_DEV_REMOTE_CTL=ON/OFF` を毎回渡す (CMake が構成し直す) |
| `CMAKE_OPTS` | 毎回 idf.py の -D として渡る |
| `SPINEL_DIR`・`PICORUBY_TI_DIR`・`ASTERISM_DIR`・`PICORUBY_ASTERISM_ZENOH_DIR`・`ZENOH_PICO_DIR`・`MRUBY_CHECKPOINT_DIR` | 選択でなくソースの在りか。rake setup が中身の変わったファイルを写し、ninja が作り直す |

### 中身を変えない (比べない)

`PORT`・`FLASH_BAUD`・`READ_BAUD`・`BUSID`・`VIDPID`・`DEVICE_ARGS`・`HOST`/`IP`・`BACKUP`/`BACKUP_DIR`・`DEVICE`・
`CONF`・`STORAGE_ONLY`・`TERM` (書き込み・ポート・表示)、`JOBS`・`CC` (ホストの道具)、`FMRB_CKPT_TABLE_OF`
(checkpoint の表の中の受け渡し)、`FMRB_NATIVE_*`・`ZENOH_PICO_PLATFORM` (ネイティブ版・ブラウザ版だけ)。

### 読んでいるのに ESP32 では効いていない物 (見つけた不具合、直していない)

- `PICORB_DEBUG`: lib/upstream/family_mruby_esp32*.rb が読むが、`ENGINE_ENV_OPTS` に無いのでコンテナの中の libmruby の
  ビルドに届かない。ESP32 では常に無いのと同じ。
- `FMRB_HW_TARGET` (コンテナの中): family_mruby_esp32.rb の ATOM_DISPLAY を除く条件 (networking の gem) は
  `ENV['FMRB_HW_TARGET']` を読むが、同じ理由で届かない。ATOM はサポートを中断しているので今は害が無い
  (CMake 側は `-DFMRB_HW_TARGET` で正しく分かれている)。

## 3. 守りの作り

- 記録: `build/fmrb_build_options.json` (上の 13 個の名前と値の JSON)。`idf.py build` の直前 (set-target の後) に書く。
  build/ の中なので `rake clean_all` で一緒に消え、`regress:size` の退避でも一緒に動く。
- 比べる時機: build/ に `CMakeCache.txt` があるとき (構成済み) だけ。無ければ新しいビルドなので通る。
- 止まるときの文 (実例、P4-Nano の build/ に `FMRB_FONT_JA=0` で):

```
build:esp32: build/ was made with other build options than this run asks for:
  FMRB_FONT_JA  1 (build/) -> 0 (now)
CMake reads them only when it configures (a changed variable does not make it
configure again) and libmruby is rebuilt only when it is missing, so building on
would mix the two.
Start over: `rake clean_all` (it removes the ESP32 build only; the sim's build-linux/,
the native program and the browser build stay), then build again.
Or build with the options it was made with: FMRB_FONT_JA=1 rake <the same task>.
BUILD_OPTS_OK=1 goes on anyway (when you know CMake will configure again).
```

- flash の文 (P4-Nano の build/ に、.env の NARYAv3 のまま `rake flash` を流したとき):

```
flash: build/ was made with other build options than this run asks for:
  FMRB_HW_TARGET  NARYAv4 (build/) -> NARYAv3 (now)
  FMRB_IMU        1 (build/) -> 0 (now)
idf.py flash builds again first with this run's options, and build/ would be
flashed as a mix of the two (or as the firmware of another board).
Flash it with the options it was made with: FMRB_HW_TARGET=NARYAv4 FMRB_IMU=1 rake <the same task>,
or build what you asked for first: `rake clean_all`, then `rake build:esp32` with these options.
BUILD_OPTS_OK=1 goes on anyway (when you know CMake will configure again).
```

- flash は先にターゲットだけでなく全部の値を比べる。`idf.py flash` は焼く前に今の環境変数でビルドを確かめ直し、
  CMake が構成し直すとそのときの値のファームを作って焼く (Rakefile の `ENGINE_ENV_OPTS` の注にある事故) ため。
- `BUILD_OPTS_OK=1` のとき: build は止まる文の頭と違う行を warn に出して続け、記録は今の値で書き直す
  (`FMRB_DISPLAY_BACKEND` を変えて main/CMakeLists.txt を touch したときのように、構成し直すと分かっている場合の道)。
  Rakefile の `FMRB_DISPLAY_BACKEND` の注をこれに合わせて直した。

## 4. 記録の無い build/ の扱い、regress:size・flash との両立

- 記録の無い build/ (F9 より前に作った物): CMake の cache の `FMRB_HW_TARGET` (build.rake は名前のあるターゲットのときだけ
  -D で渡すので、無ければ「ボード名なし」) を、sdkconfig のチップと合うときだけ使う。`FMRB_EDITOR` は F8 の
  `build/fmrb_editor_option` (無ければ 1 = F8 より前はエディタ入り)。ほかは分からないので比べない。違わなければ通り、
  ビルドなら記録を書く (flash は書かない)。壊れた JSON の記録も同じ扱い。
- 今の build/ (P4-Nano、記録なし、cache は NARYAv4、F8 の記録は 1) は `FMRB_HW_TARGET=NARYAv4 rake build:esp32` で
  そのまま通り、記録が書かれ、F8 のファイルは消えた。
- `regress:size`・`regress:boot`: どちらも build/ ごと (sdkconfig・esp32/esp32p4 の libmruby・gen/esp32 も) 退避し、
  端末ごとに clean から `rake build:esp32` を流す (`tools/regress/build_tree.rb`)。cache の無い build/ なので守りは
  止まらず、その端末の値の記録を書く。終わりに退避した build/ を戻すので記録も元の物に戻る。`regress:boot` は
  同じ env で build と `flash:app` を流すので flash の守りも通る。tools/regress は変えていない。
- flash: 今までは何も確かめていなかった (`check-port` のチップの照合はポートの割り出しのときだけで、build/ との照合は無い)。

## 5. 試験と確認

- 足した試験: `test/build_options/run.rb` (`rake build_options:test`、`rake test` の並びに追加)。56 の確認:
  値の正規化 (unset と 1、P4 の Asterism・IMU、エディタなしのエンジン、ppa と unset)、同じ値で通る、1 つ違うと止まり
  名前と両側の値と clean_all と前の値のコマンドが出る、違う物だけが並ぶ、イメージ違い、flash の文、allow、壊れた記録、
  記録なし (cache なしは通る・同じボードは通る・違うボードは止まる・F8 のファイルを読む・記録が F8 のファイルを消す・
  cache とチップが食い違えば比べない・名前なしのボード)、タスクの前提 (build:esp32 は setup より前・flash の 5 つ)、
  比べる値が全部 Rakefile からコンテナへ渡っていること。
- `FMRB_HW_TARGET=NARYAv4 rake build:esp32` (今の build/、記録なし): 通った (2 分 6 秒、増分)。記録が書かれた。
- `FMRB_HW_TARGET=NARYAv4 FMRB_FONT_JA=0 rake build:esp32`: 0.1 秒で止まった (上の文)。
- `FMRB_HW_TARGET=NARYAv4 FMRB_KERNEL_ENGINE=mruby`: 止まった。`BUILD_OPTS_OK=1` を付けると warn を出して通った
  (`rake build:esp32_options` だけで確認。ビルドは流していない)。
- `FMRB_HW_TARGET=NARYAv4 FMRB_ASTERISM=0`: **止まらない** (指示書の確認の例は止まる想定)。NARYAv4 にはボードの既定が無く、
  .env にも無いので、普段の P4-Nano のビルドも `FMRB_ASTERISM` は 0 で、値は前と同じ。しかも P4 は変数によらず Asterism が
  入るので、比べる値は常に 1 にした (ここで止めると、中身が同じなのに clean_all を強いる)。止まる例には `FMRB_FONT_JA=0` を使った。
- flash (ドライラン: 前提のタスク `rake flash_options` だけを流し、ポートには触っていない): .env の NARYAv3 のままだと
  止まり、`FMRB_HW_TARGET=NARYAv4` なら通った。
- `rake regress:size ONLY=narya_v3`: 通った (3.9 分、`size: 1 boards vs baseline 4e7e7e61, ok`)。守りで止まらずに NARYAv3 を
  作り、終わりに `build/: NARYAv4 (esp32p4)` と戻した。戻った build/ の記録は NARYAv4 の物 (FMRB_HW_TARGET NARYAv4、
  cache も NARYAv4、sdkconfig も esp32p4)、退避の残り (`build.regress*`) なし。その後の
  `FMRB_HW_TARGET=NARYAv4 rake build:esp32_options` は通った。表の app image +815,488 は基準 (4e7e7e61) からの動きで、
  この変更 (rake の側だけ) によるものではない。
- `rake regress`: 通った (host 37 suites 全部、描画の記録 310 runs 全部)。

## 6. 確かめていないこと・気を付けること

- 実際の flash は流していない (守りの前提のタスクだけ)。
- **MCP の flash ツールへの影響**: ツールは `rake flash` / `flash:app` をサーバの環境のまま流す (FMRB_HW_TARGET は .env の
  物)。.env が NARYAv3 のまま P4-Nano 用の build/ を MCP で焼こうとすると、今後はここで止まる (前は idf.py が build/ の
  チップのまま焼けていた。ただし構成し直しが起きると NARYAv3 の値で作り直される危うさがあった)。P4-Nano を MCP で焼くときは
  .env の `FMRB_HW_TARGET` を合わせるか、サーバの環境に渡す必要がある。tools/mcp は範囲外なので触っていない。
- ESP32 用の libmruby (picoruby/build/esp32・esp32p4) は build/ の外にある。build/ だけを手で消して違う値で作ると、
  守りは新しいビルドとして通すが libmruby は古い値のまま (前からある穴。clean_all を使えば起きない)。
- S3 のターゲットの切り替え (NARYAv3 → ATOMS3R ほか) を実際に止める所は試験 (作った build/) だけで確かめた。
