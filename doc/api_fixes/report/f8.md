# F8 AtomS3R と StickS3 のビルドからエディタと型まわりを外す

> 2026-11-25 | サブ (Opus) の報告。指示書は instruction_f8.md、計画は plan.md の決定 23。ブランチ `mini-no-editor`。push していない。

## 1. 結果

ビルドの選択 `FMRB_EDITOR` (既定 1) を足し、`MINI_BUILD_DEFAULTS` (AtomS3R・StickS3) で 0 にした。2 つの端末のファームが
約 517 KB 小さくなり、app の区画の空きは StickS3 5,344 → 522,752 バイト、AtomS3R 20,128 → 537,552 バイトになった。
内蔵 RAM (DIRAM) は 96 バイト減り、IRAM は変わらない。NARYAv3・TAB5 のファームは大きさ・内蔵 RAM・部品ごとの大きさまで
変更前と同じ。区画表・sdkconfig は変えていない。ソースは消していない。

## 2. 今の作り (変更前)

### 2.1 ビルドに入る所

| もの | rake (libmruby) | CMake | 呼ぶ側 |
|---|---|---|---|
| エディタのアプリ (`main/ruby/default_app/editor.app.rb` + `editor/`) | なし | `main/CMakeLists.txt` の `DEFAULT_APP_RUBY_FILES` (glob)。`editor/*.rb` を前に連結して `editor_irep` にする (`compile_ruby_to_bytecode.cmake`)。Spinel のときは `editor_combined` と `app/fmrb_spx_editor.c` | `main/app/fmrb_app_spawner.c` の組み込みの表の `default/editor`・`default/editor_fs` |
| エディタの C の部品 `picoruby-fmrb-editor-core` (`EditorCore`) | `lib/upstream/family_mruby.gembox` (全構成) | port (`ports/esp32/editor_core*.c`・`editor_ti_bridge.c`) は `components/picoruby-esp32/CMakeLists.txt` の `PICORUBY_SRCS` (`FMRB_EDITOR_CORE_PORTS_SRCS`) | エディタだけ (mruby のエディタは gem、Spinel のエディタは `fmrb_spx_editor.c`) |
| 型エンジン `picoruby-ti` と型の db (sig 142 クラスから `rake setup` で生成) | gembox (全構成。C だけで Ruby のクラスは無い) | 公開ヘッダの include だけ | `editor_ti_bridge.c` (editor-core の port) だけ |
| 構文の色分け `picoruby-syntax-highlight` (`SyntaxHighlight`) | gembox | — | エディタ (editor-core の色分けの cache) と **picorabbit** (`picorabbit_renderer.rb` の `SyntaxHighlight.tokenize`) |
| デバッガの橋 `picoruby-fmrb-debug` (`FMRB::Debug`) | gembox | port `ports/esp32/debug.c` は `PICORUBY_SRCS` | エディタのデバッガの欄 (`editor/debug_pane.rb`) だけ。ほかは試験のアプリ `flash/app/test/dbg_e1_test.app.rb` (storage の像に入らない) |
| 遠隔のデバッガ (`main/drivers/debug/fmrb_debugd.c`) と VM の hook (`MRB_USE_DEBUG_HOOK`) | 定義は `family_mruby_esp32.rb` (ABI に関わる) | main | debugd (PC のデバッガ) |
| かな漢字変換 (`fmrb_kanji`・`main/drivers/usb/fmrb_kana.c`・`kernel/host/host_kanji.c`) | — | main | キー入力の層 (エディタ以外の入力でも使う) |

### 2.2 エディタを開く道

| 道 | 中身 | この 2 つの端末で通れるか |
|---|---|---|
| デスクトップのアイコン・メニュー (`desktop_common.rb`・`system_desktop.app.rb`)、ファイルマネージャの「編集」(`file_manager.rb`)、ランチャー | カーネルへ `spawn` を送る | デスクトップが起動しない (`boot_mode = "app"`) ので通らない。system_conf を `"desktop"` に書き換えたときだけ通る |
| 関連付け `FmrbAssoc::EDIT` (シェルの `open`)、シェルの `edit` | シェルがカーネルへ `spawn` | シェルは遠隔の起動 (devctl) でしか開けず、キーボードが無いので打てない。実際には通らない |
| カーネルの「エディタは 1 つ」(`app_lifecycle.rb` の `hand_to_running_editor`) | 動いているエディタへ渡す。無ければ普通の spawn | エディタが起動しないので常に普通の spawn に進む |
| 遠隔の操作 `POST /app/launch?path=default/editor` (devctl、WiFi) | `fmrb_app_spawn_app` を直に呼び、失敗はエラーの番号を JSON で返す | **通る** (開発の入口) |
| 単一アプリの起動 (`startup_app = "default/editor"`) | `spawn_single_app` | system_conf を書き換えれば通る |
| debugd (PC のデバッガ) の launch | `fmrb_app_spawn_app` を直に呼ぶ | BLE の設定のモードと別で、普段は通らない |

この 2 つの端末で起動するのは、カーネルと `startup_app` の 1 本 (既定は `/app/tool/welcome.app.rb`) だけ
(doc/headless_s3/plan.md の決定事項 2026-10-11 の 1)。

## 3. 外した物と残した物

| もの | 扱い | 理由 |
|---|---|---|
| エディタのアプリ (`editor_irep`、Spinel のエディタ) | 外した | エディタそのもの |
| `picoruby-fmrb-editor-core` とその port | 外した | エディタだけが使う |
| `picoruby-ti` と型の db | 外した | editor-core の port だけが使う。gem の依存も editor-core からだけ |
| `picoruby-fmrb-debug` (`FMRB::Debug`) とその port | 外した | エディタのデバッガの欄だけが使う。試験のアプリ `dbg_e1_test` はこの 2 つでは動かなくなる (storage の像に入っていない試験で、WiFi で送ったときだけの話) |
| `picoruby-syntax-highlight` | 残した | picorabbit (スライドの表示) が `SyntaxHighlight.tokenize` を使う |
| 遠隔のデバッガ (debugd) と `MRB_USE_DEBUG_HOOK` | 残した | エディタと別の道 (PC のデバッガ)。hook は `mrb_state` の形を変える (ABI) ので rake と CMake でそろえたまま |
| `TI_ARENA_INCLUDE` の定義 (`family_mruby_esp32*.rb`) | 残した | 定義だけで、ti が無ければ何も起きない。ABI に関わらない |
| かな漢字変換 | 残した | 入力の層の機能 |
| `/usr/share/template` | 残した | シェルの `create_app` が使う |
| `/usr/share/doc/editor.md`・`editor_ja.md` (storage) | 除外の一覧に足した | エディタの案内だけ。`home.md` からのリンクはこの 2 つでは切れる (デスクトップが無いので文書を開く道も無い) |
| `/help`・`/usr/share/samples` | 前から除外済み | — |

## 4. スイッチ

名前は `FMRB_EDITOR` (`FMRB_ASTERISM`・`FMRB_IMU` と同じ 0/1 の形)。既定 1、`MINI_BUILD_DEFAULTS` で 0。**ESP32 の
ファームだけ**が読む。sim・ネイティブ版・ブラウザ版は値によらず常にエディタが入る。

| 場所 | 見ている所 |
|---|---|
| Rakefile | `MINI_BUILD_DEFAULTS` に `"FMRB_EDITOR" => "0"`、定数 `FMRB_EDITOR`、`ENGINE_ENV_OPTS` の `-e FMRB_EDITOR=` (コンテナへ渡す) |
| rake (libmruby) | `lib/upstream/family_mruby.gembox`: ビルドの名前が `esp32*` か `ckpt-table-*` で `FMRB_EDITOR=0` のとき、editor-core・ti・debug の 3 つを入れない |
| CMake (部品) | `components/picoruby-esp32/CMakeLists.txt`: linux 以外で `$ENV{FMRB_EDITOR}` が 0 なら `PICORUBY_SRCS` から `FMRB_DEBUG_PORTS_SRCS`・`FMRB_EDITOR_CORE_PORTS_SRCS` を除く |
| CMake (main) | `main/CMakeLists.txt`: linux 以外で 0 なら `editor.app.rb` を `DEFAULT_APP_RUBY_FILES` から除き、`FMRB_APP_ENGINE_EDITOR` を `none` に (Spinel のエディタも作らない)、main に `FMRB_NO_EDITOR` を定義 |
| C | `main/app/fmrb_app_spawner.c`: `FMRB_NO_EDITOR` で組み込みの表から 2 つを外し、`fmrb_app_spawn_app` が 2 つの名前を `FMRB_ERR_NOT_SUPPORTED` で断る (ログ `default/editor: the editor is not in this build (FMRB_EDITOR=0)`) |
| checkpoint の表 | `rakelib/checkpoint.rake` が `-DFMRB_EDITOR=` を渡し、`tools/ckpt_table/CMakeLists.txt` が表を作る道具から 2 つの gem の port を除く (libmruby は同じ gembox を読むので gem の一覧は自動で合う) |
| 組み立ての守り | `rakelib/build.rake` の `build:esp32`: CMake は構成のときにしか環境変数を読まず、値を変えても構成し直さない。`build/fmrb_editor_option` に値を残し、違う値で作ろうとすると `rake clean_all` を求めて止まる (記録の無い古い `build/` は 1 とみなす) |
| 回帰 | `tools/regress/targets.rb`: `FIRMWARE_ENV` に `"FMRB_EDITOR" => "1"`、`MINI_BUILD` に `"0"` (Rakefile との照合は `regress:size` が行う) |
| storage | `config/storage_exclude_atoms3r.txt`・`_sticks3.txt` に `usr/share/doc/editor.md`・`editor_ja.md` |

rake と CMake は同じ 1 つの環境変数を読むので食い違わない。`MRB_*` の定義はどこも変えていない。

## 6. エディタを開く道の、外した後の動き

| 道 | 動き | 確かめ方 |
|---|---|---|
| デスクトップのアイコン・メニュー・ファイルマネージャ | エラーの窓「Failed to launch (error -4) / This machine cannot run this kind of app.」(日本語のときは「起動できません (エラー -4) / この端末では動かせない種類のアプリです。」)。新しい文は足していない | sim (下の注) で目視 |
| 遠隔の操作 `/app/launch?path=default/editor` | `500` と `{"ok":false,"err":-4}`、ログ `dev ctl: launch default/editor failed (-4)` | debugd の launch (同じ `fmrb_app_spawn_app`) で `{"error": -4}` を sim で確認。devctl は読みで |
| 単一アプリの起動 (`startup_app = "default/editor"`) | 決まった回数 (3 回) 起動し直してから止まり、画面に「default/editor failed 4 times. This machine cannot run this kind of app. / Reset to try again.」 | sim (下の注) で目視とログ |
| シェルの `edit`・`open` (関連付けの「編集」) | カーネルのログに断りが出る。シェルの画面には「Spawned: default/editor」が出たまま (失敗をシェルに返さないのは今までどの失敗でも同じ。この端末ではシェルを打てない) | 読みで |
| 落ちる・黙る | どちらも無い | — |

注: sim で確かめたのは、この作業の途中の版 (sim も `FMRB_EDITOR=0` を読んでいた版) を `FMRB_EDITOR=0 rake build:linux`
で作ったもの。断る C の道 (`fmrb_app_spawner.c`)・カーネル・デスクトップの文は今の版と同じコードだが、最後の版では
sim はこの選択を読まない (sim の構成は環境変数を変えても構成し直さないため。4 章の守り) ので、今の版のエディタの
無い sim は作れない。2 つの端末の実機では確かめていない (7 章)。

## 7. checkpoint の表

表 (`ckpt-table-esp32`、`tmp/ckpt_table/<端末>/`) はビルドごとに同じ gem から作る作りで、選択に自動で付いてくる。
外した後の表は AtomS3R が 4,542 → 4,462 の名前 (snapshot 1,317 → 1,308)、StickS3 が 4,566 → 4,486 (1,323 → 1,314)。
`EditorCore`・`FMRB::Debug` の名前が無くなった。NARYAv3 の表はバイト単位で変わっていない。

端末の間のアプリの移動は壊れないと判断した (止まる条件に当たらない):

- 表は「自分の表だけを持つ」作りで、イメージには名前の決まりの版 (`TBL0`) だけが入り、表のダイジェストは照らさない
  (doc/checkpoint/report/ff.md 5 章)。名前は 1 つずつ引き当てる。NARYAv3 と StickS3 の表はもとから違う
  (IMU の gem の有無で 4,542 と 4,566) まま移動が成り立っている。
- 表に無い名前は VM が自分で持ち、メソッドの無いクラスは受け手が理由つきで断る作り。`EditorCore`・`FMRB::Debug` を
  使うアプリ (エディタそのもの、デバッガの試験) だけがこの 2 つへ移せない。エディタは移動の対象のアプリではない。
- 移動の試験 (`rake regress:checkpoint`) は流していない。この 2 つの端末は実機でしか移動を試せない (回帰の道具は
  ネイティブ版・sim・ブラウザ版と、つないだ端末)。

## 8. 実機で確かめる手順 (親・ユーザ)

1. `FMRB_HW_TARGET=STICKS3 rake clean_all build:esp32` (AtomS3R は `ATOMS3R`)。`build/` にほかの値の構成が残っていると
   `rake clean_all` を求めて止まる。区画表は変えていないので、2026-11-07 より後の区画の端末には `app_sync` で焼ける。
2. 起動ログ: crash の印 (`Guru|abort`) が 0 件、`M1|` の行と周期の `IRAM free:` が前と同じ程度、
   `Single-app boot: /app/tool/welcome.app.rb` の後にアプリが上がる。checkpoint の表の行 (`table: ...`) が出る。
3. アプリを送って動かす: WiFi で `tab5_fs` (ip を渡す) か `fmrb_rd_fs.rb` で `.app.rb` を put → `/app/launch` で起動。
   Asterism の網に出ること (console の図)。
4. エディタを開こうとする: `curl -X POST "http://<IP>/app/launch?path=default/editor"` → `{"ok":false,"err":-4}`、
   シリアルに `default/editor: the editor is not in this build (FMRB_EDITOR=0)`。端末は落ちず、動いているアプリも続く。
5. 移動: ほかの端末 (NARYAv3・P4) から StickS3 へ、いつもの移動のアプリを送って動くこと。

## 9. 確かめていないこと・見つけたこと

- 2 つの端末の実機は無く、焼いていない。移動の試験も流していない (7 章)。
- `FMRB_APP_ENGINE_EDITOR=spinel` と `FMRB_EDITOR=0` を同時に指定したときは Spinel のエディタも作らない (CMake が
  そう告げる)。Spinel の生成 (`rake spinel:gen`) はエディタの .c を作ったままになる (使われないだけ)。
- 見つけたこと (直していない): 環境変数で選ぶビルドの選択 (`FMRB_ASTERISM`・`FMRB_FONT_JA`・`FMRB_IMU` など) は、
  同じ `build/` (sim なら `build-linux/`) で値を変えても CMake が構成し直さず、libmruby と部品の中身が食い違う
  (今回 sim で、gem はあるのに port の無いリンクの失敗として出た)。今は端末を変えるときに `clean_all` する習慣で
  避けている。今回は `FMRB_EDITOR` だけ 4 章の守りを足した。ほかの選択に広げるかは親の判断。
- 単一アプリの起動は、起動そのものができない失敗 (この場合は「入っていない」) でも 1 秒おきに起動し直してから止まる。
  前からの動きで、結果の画面は分かりやすいので変えていない。
