### B5

- 同梱のアプリ・カーネル・デスクトップ・sdk で `MSG_TASK_` を使う所は無い (grep。`.rb`・`.rbs`・`.c`・`.h`)。
- 定数は `kernel.c` の `mrb_fmrb_kernel_msg_init` で定義する。`src/` の方は本体のヘッダを見ないので、本体のヘッダを
  include している `ports/esp32/kernel.c` に移した。
- 受け付ける番号は 0 から `PROC_ID_MAX` (= `FMRB_MAX_APPS`) 未満。端末と sim は 9、ブラウザ版は 32
  (`lib/upstream/family_mruby_wasm.rb` の `FMRB_MAX_APPS=32`)。待ち行列の側 (`fmrb_msg.c`) と同じ上限なので、
  今まで「例外は出ないが false」だった 9〜15 は ArgumentError になる。

### B6

**調べて分かったこと**: C の待ち行列は前から**アプリごと**に分かれていた。`Sched._clear` は呼んだアプリの予約だけを
消す (`fmrb_midi_sched_clear_pid(current_pid())`)。s4b の「共有の待ち行列を空にする」は、アプリをまたぐ場合は当たらない
(読みで確認。2 つのアプリで同時に鳴らす形は sim で確かめていない)。当たるのは **1 つのアプリの中で 2 つのプレーヤーを
鳴らす**場合で、これを sim で再現した。`MmlPlayer` も同じ待ち行列を使い、同じく消し合う (再現は MmlPlayer 2 つ)。

**直し方**: 予約 1 件 (16 バイト) の中で、命令の種類 (2 ビット) とアプリの番号 (6 ビット) を 1 バイトにまとめ、空いた
1 バイトに持ち主 (プレーヤーの番号) を入れた。大きさは `_Static_assert` で 16 バイト・種類 4 未満・アプリ 64 未満を固定。

- プレーヤーは作るときに `FmrbMidi.next_owner` で 1〜255 の番号を取る (`@api private`)。0 はプレーヤー以外の予約。
- `defer_voices(due_us, owner)` で出力 (APU・シリアル) に渡し、出力は予約に付ける。`drop_queued` は `_clear(@owner)`。
- 引数なしの `_clear` と、アプリが終わるときの消去 (`mrb_fmrb_midi_sched_final`) は今までどおりアプリ全体。
- 持ち主ごとに消したときの消音: 消した予約が使っていた APU の声・シリアルのチャンネルだけを止める
  (アプリ全体のときは今までどおり 4 声・16 チャンネル全部)。もう片方のプレーヤーが別の声で鳴らしている音を止めないため。
- `_push_*` の持ち主の引数は省略できる (0)。`tools/midi/test` の `FakeSched` (2 つ) は新しい引数を受けるようにした。

### B7

型エンジン (fork `5c5a04c`) で:

- `rescue` の節を見たら、その変数 (ローカル・`@x`・`$x`) に、節が名前を挙げたクラスのインスタンスの型を付ける。
  入れ子 (`JSON::ParserError`、頭の `::`) も S8 の照合 (`ti_resolve_constant_class_id` として公開) で引く。
- `rescue A, B => e` は **union** (エンジンの union は 5 つまで。越えると型なし)。`rescue => e` は `StandardError`。
- データベースに無いクラス (ユーザのクラス)・`*ERRS`・式・無い定数が**1 つでも**混じると型なし (残りの型で付けると、
  ユーザのクラスにしか無いメソッドを誤って指摘するため)。
- 最上位の `begin/rescue` は、エンジンが木をたどって節に着いた所で変数を付ける。メソッドの中の `begin`・`v = begin ... end`・
  メソッドの本体の `rescue/else/ensure` は、節ごとに評価する (`ti_eval_begin`)。値は本体 (else があれば else) と
  各 rescue の値の union、ensure の値は捨てる。

**前の不具合 (ついでに直った物)**: メソッドの本体に `rescue`・`ensure` があると、本体は begin の節になるが、エンジンは
それを statements の節として読んでいた (`(const pm_statements_node_t *)def_node->body`)。begin の節の最初の欄は
`begin` の位置で、暗黙の begin では NULL なので「文が 0 個」と読まれ、**本体は評価されず、戻り値は nil** になっていた
(落ちはしない)。今は本体が評価され、戻り値も本体と rescue の値になる。

**sig の直し**: `JSON::ParserError` の補完に `message` が出なかった。tidbgen は親クラスの名前を最上位からしか引かず、
`module JSON` の中の `class ParserError < JSONError` の `JSONError` が見つからず、`StandardError`・`Exception` までの
つながりが切れていた。sig の親を `JSON::JSONError` と書いた (同じ形の物は sig 全体でこの 3 つだけ。上流由来の
`TrueClass < Bool` などは別)。

## 3. 動きが変わる所と同梱のアプリへの影響

- `Kernel::MSG_TASK_HOST` が 0 → 1、`MSG_TASK_SYSTEM` が 1 → 2、`MSG_TASK_KERNEL` (0) が増える。`Kernel.send_message`・
  `receive_message`・`message_queue_exists?` は 9 以上 (ブラウザ版は 32 以上) で ArgumentError (前は 16 以上)。
  同梱で使う物は無い。
- MIDI: 1 つのアプリで 2 つのプレーヤーを鳴らすと、片方の stop・pause・`device=`・`lookahead_us=` がもう片方の予約を
  消さない。プレーヤーが 1 つのときは前と同じく全部消える。止めたときに C が止める声・チャンネルが、全部から
  「消した予約が使っていた物」になる (鳴っている音はプレーヤーが続けて自分で止める。順番は前と同じ)。
  同梱のアプリはどれもプレーヤーを 1 つしか持たない (mml・midi_apu・midi_time・asterism_demo)。
- エディタ: `rescue ... => e` の後の `e` に補完と検査が効く。メソッドの本体に rescue/ensure がある物、メソッドの中の
  `begin`、`v = begin ... end` の中が検査されるようになり、今まで黙っていた行に (正しい) 指摘が出ることがある。
  rescue のあるメソッドの戻り値が nil でなくなる。
- sig: `FmrbGfx#current_font` の型を `Symbol` から `Array[untyped]` に、例を `set_font(*saved)` に直した (実装は
  `[family, size]` の配列を返す。前の例の `set_font(saved)` は配列を family に渡してしまう)。

### 解けるようになった形・解けないままの形

解ける: `rescue Foo => e`・`rescue A::B => e`・`rescue ::Foo => e`・`rescue => e` (StandardError)・`rescue A, B => e`
(union。Ctrl+T は `Union<ArgumentError RuntimeError>`)・`rescue => @err`・`rescue => $err`・メソッドの本体の rescue・
メソッドの中の begin・`ensure`/`else` つき・rescue を複数並べた形 (節ごとの変数)・閉じていない (打っている途中の) begin。

解けないまま:

- union の変数の引数の検査 (`rescue A, B => e` の `e.message(1)`): エンジンは union の受け手の引数を検査しない
  (前からの作り。補完と Ctrl+T は効く)。
- ユーザのクラス・`*ERRS`・それらが混じった並び: 型なし (指示書どおり)。
- ブロックの中の rescue (`each do ... rescue => e ... end`): エンジンはブロックの本体をもともと評価しない。指摘は出ない
  (落ちない)。
- `x rescue y` の値: 型を付けていない (前と同じ。落ちない)。
- `=> e` の `e` の上での Ctrl+T: hover は変数を読む所でしか出ない (前と同じ)。

## 6. 途中で見つけた別の不具合・確かめていないこと

見つけたもの (直していない):

- **MIDI の `_depth`・`_free` は待ち行列の全体を数える** (全アプリ・全プレーヤー)。プレーヤーは「曲を読み終えて
  `_depth` が 0 になったら終わり」と見る (`fmrb-smf.rb` の 442 行付近・`fmrb-mml.rb` の 515 行付近) ので、ほかの
  プレーヤー・ほかのアプリが鳴らしている間は `playing?` が true のまま残る見込み。「先に入れる前に空きが
  `QUEUE_MARGIN` あるか」も全体の空きで見る (読みだけ)。
- tidbgen は sig の親クラスの名前を最上位からしか引かない (`module A; class C < B` の `B` が `A::B` でも見つからない)。
  今は json.rbs の 3 つだけだったので sig で直した。
- プレーヤーの番号は 255 で一巡する。1 つのアプリが 255 個より多くプレーヤーを作り、古い物と新しい物が同じ番号で
  同時に鳴ると、また消し合う (読み)。
- 1 つのアプリの 2 つのプレーヤーが内蔵音源を使うと、もともと 4 つの声を取り合う (どちらも同じアプリの声)。持ち主ごとの
  消音でも、止めたプレーヤーが使っていた声で相手が鳴らしていれば、その音は止まる。

確かめていないこと:

- ESP32 のビルド・実機 (指示どおり作っていない)。`_Static_assert` は sim のビルドで通っただけ。
- 2 つのアプリで同時に MIDI を鳴らす形 (読みで「前からアプリごと」と判断した)。シリアルの MIDI の出力での 2 つのプレーヤー。
- Modern の sim・ブラウザ版・ネイティブ版。`rake regress:run`・`regress:size`・`regress:screens`。
- 音の聞こえ方 (止めたときの声)。
