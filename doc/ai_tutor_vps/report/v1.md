# V1 報告: asterism-tutor をコンテナで動く形にした

> 状態: 完了 | 更新: 2026-11-19 | asterism-tutor 0.2.0 (ブランチ vps-container、未 push・タグなし)。環境変数の設定、結果の volume、status、SIGTERM、deploy/vps 一式、イメージの CI を足し、手元の console の stack (rehearsal、mTLS のルータ) の隣でコンテナが healthy になり、役割の有無と devices で通る・届かない・断るが分かれることを確認した。ブラウザ版は役割を利用者ごとに付けられない (console の作り) ことが分かった

指示書は instruction_v1.md。計画の正は plan.md。

## 1. 作ったもの (asterism-tutor、ブランチ `vps-container`)

### 1.1 環境変数

優先は オプション > 環境変数 > ファイル > 既定 (`Tutor::Config.load(path, overrides, env:)`)。空の値は無いのと同じ
(例外は `ASTERISM_TUTOR_ROUTER` の空 = 証明書の中のルータ)。数・真偽が読めない値は変数名を出して止まる。

| 変数 | 設定の項目 |
|---|---|
| `ASTERISM_TUTOR_CONFIG` | 設定のファイル (`--config` が無いとき) |
| `ASTERISM_TUTOR_ROUTER` | `network.router` |
| `ASTERISM_TUTOR_CREDENTIALS` | `network.credentials` |
| `ASTERISM_TUTOR_NODE` | `network.node` |
| `ASTERISM_TUTOR_DEVICES` | `network.devices` (カンマか空白で区切る) |
| `ASTERISM_TUTOR_LLM` / `_MODEL` | `llm.provider` / `llm.model` |
| `ASTERISM_TUTOR_PER_DAY` / `_COST_PER_DAY` | `limits.per_device_per_day` / `limits.cost_per_day_usd` |
| `ASTERISM_TUTOR_LOG_DIR` / `_STATE_DIR` | `store.log_dir` / `store.state_dir` (新設) |
| `ASTERISM_TUTOR_MAKE` / `_FIX` | `modes.make` / `modes.fix` |
| `ASTERISM_TUTOR_STOP_GRACE` | `jobs.stop_grace_s` (新設、既定 8。指示書の対象外だが compose の `stop_grace_period` と組なので足した) |

LLM の鍵は今のまま `ANTHROPIC_API_KEY` だけ。起動時の 1 行 (モデルと上限) は今のまま出る (前の行に版を足した:
`asterism-tutor 0.2.0: tutor/tutor/helper on tls/zenohd:7448 (llm: fake)`)。

### 1.2 状態の置き場

今の gem が持っていたもの:

| もの | V1 の前 | V1 |
|---|---|---|
| 記録 (JSONL) | ファイル (`log_dir`) | そのまま |
| その日の回数と費用 | メモリ。起動時に記録 (`ask`・`llm` の行) から読み戻していた | そのまま (記録が volume にあれば残る) |
| 頼み (ticket) と結果 | メモリだけ | `<state_dir>/tickets/<id>.json` に変わるたびに丸ごと書く (一時ファイル → rename)。起動時に読み、`result_hours` を過ぎたものはファイルごと消す |
| 片で送っている途中の文書 | メモリ (1 時間) | メモリのまま (端末は送り直す) |
| 会話の続き | メモリ (30 分) | メモリのまま (指示書のとおり残さない) |

コンテナでは `log_dir=/state/log`、`state_dir=/state/store` で、volume `state` 1 つにまとまる。`status.json` も
`state_dir` に置く。

### 1.3 status

- 動いている gem が 2 秒ごとに `<state_dir>/status.json` を書く (`connected` = `net.connected? && !net.reconnecting?`、
  `exposed` = helper が `net.exposed` にある、`stopping`、進行中の数、その日の回数と費用、版)。
- `asterism-tutor status` はそれを読み、0 (つながり helper を公開している)・1 (ルータがいない、止まるところ)・
  2 (15 秒より古い = 動いていない・固まった) で終わる。port は開かない。
- asterism-games は supervisor の HTTP (7460) を同じコンテナの中から叩く形だが、tutor は 1 プロセスなので
  ファイルにした (外へ開かない点は同じ)。
- 受信は `net.run` から `net.start` (裏のスレッド) に替え、主スレッドは止める合図を `Queue#pop(timeout: 2)` で待ちながら
  状態を書く。接続が終わったら (`net.running?` が偽) 終了コード 1 で出る (docker が起こし直す)。

### 1.4 SIGTERM

親の見立てのとおりに作った。

1. TERM・INT の trap は `Queue` に積むだけ。主スレッドが受けて `stopping` を状態に書く。
2. 新しい `ask` は `{"error" => "stopping", "message" => "AI の係が止まるところです。少し待ってからもう一度送ってください。"}`
   (記録は `refused` の `why: stopping`)。status・result・pending はその間も答える。
3. 進行中と順番待ちの頼みを `jobs.stop_grace_s` (8 秒) まで待つ。
4. 残ったものは `failed`、`error: "stopped"`、文は「AI の係が止まったので、答えを作れませんでした。もう一度送ってください。」
   にして記録 (`failed` と `stop`) に残す。その後に動き終わった worker は何も書かない。
5. kill などで止まった gem が残した進行中の頼みは、次の起動で同じ失敗にする。

端末は gem が戻った後に `pending` → `result` でこの文を読む (ネイティブ版で確認、3.2)。止まった頼みも回数には数えている
(`ask` の時点で数える今の作りのまま)。

### 1.5 deploy/vps と CI

- `Dockerfile`: ruby 3.4.11-slim の 2 段 (build-essential で prism・msgpack・asterism-zenoh の拡張を作る)、
  uid 1000、`BUNDLE_WITHOUT=development:test` (rake と minitest は Gemfile の group へ移した)。`.dockerignore` で `.git`・
  `test`・`deploy/vps/.env`・`credentials` を外す。イメージは **227 MB**。
- `docker-compose.yml`: project `asterism-tutor`、`${ASTERISM_PROJECT}_router` に名前で入る、volume `state`、
  `./credentials:/credentials:ro`、`ASTERISM_TUTOR_ROUTER=${TUTOR_ROUTER:-tls/zenohd:7448}` (証明書の中のルータは
  公開の名前なので、console の網の中の zenohd を既定にした。console のルータの証明書は DNS 名 `zenohd` を持つ)、
  `mem_limit ${TUTOR_MEM_LIMIT:-256m}`、json-file 10m×5、healthcheck (`bundle exec exe/asterism-tutor status`、30 秒ごと、
  3 回)、`stop_grace_period: 15s`、`init: true`、`restart: unless-stopped`、`MALLOC_ARENA_MAX=2`。
- `docker-compose.build.yml`・`env.example`・`update.sh` (games の形。console の volume の確認を network だけにし、
  `--when-idle` は status の「0 working」を待つ。卓の写しの段は無い)・`README.md`・`credentials/.gitignore`。
  リポジトリ直下の `.gitignore` に `/deploy/vps/.env` を足した。
- `.github/workflows/image.yml`: タグ `v*` で amd64 だけを作り `ghcr.io/ruby-asterism/asterism-tutor` へ push
  (`<版>`・`<major>.<minor>`・`latest`)。版は `lib/tutor/version.rb` の `VERSION` と照合 (VERSION ファイルは作らなかった)。
  手で流すと作るだけ。ブランチの push で走るものは足していない。
- 版 0.2.0、CHANGELOG・README.md・README.ja.md・`docs/install.md` (英語) を合わせた。

### 1.6 mem_limit の根拠

コンテナの中の ruby の RSS (VmRSS / VmHWM)、偽物の LLM:

| 時点 | RSS |
|---|---|
| 起動直後 (つないで helper を公開) | 54.7 MB |
| 4 つの頼み × 4 回と 46 KB の文書のヒント・修正の後 (山) | 63.3 MB |
| `require "anthropic"` とクライアントを作る分 (別プロセスで測った差) | +48 MB |
| healthcheck の `status` コマンド (1 秒ほど) | 32.9 MB |

本物の LLM なら 63 + 48 ≒ 111 MB に応答の分が乗り、healthcheck の瞬間に +33 MB で 150 MB 前後の見込み。
256 MB にした。**本物の LLM を呼んだときの RSS は測っていない** (鍵を使わない決まり)。V2・V4 で `docker stats` を見る。

## 2. 役割 2 つ (console の画面に入れる形)

手元の rehearsal の console 0.4.1 に `bin/rails runner` で同じ行を作り (コードは変えていない)、mTLS のルータで確かめた。

**tutor-host** (係。台帳の行 `tutor`、kind client)

- Read and write:
  ```
  asterism/${node}
  asterism/${node}/tutor/**
  asterism/${node}/@profile
  asterism/${node}/tutor/@profile
  asterism/${node}/tutor/@status
  asterism/${node}/tutor/@pubs
  ```
- Read: なし / Ask: なし / Watch: `asterism/**` / 対ブラウザ: なし

**tutor** (使う端末)

- Read and write (端末の AI ヘルパー自身、アプリ名 `ai_helper`):
  ```
  asterism/${node}
  asterism/${node}/ai_helper/**
  asterism/${node}/@profile
  asterism/${node}/ai_helper/@profile
  asterism/${node}/ai_helper/@status
  asterism/${node}/ai_helper/@pubs
  ```
- Read:
  ```
  asterism/*/tutor/helper
  asterism/*/tutor/protocol/*
  asterism/*/tutor/helper/meta
  asterism/*/tutor/helper/call/${node}
  ```
- Ask:
  ```
  asterism/*/tutor/helper/meta
  asterism/*/tutor/helper/call/${node}
  ```
- Watch: `asterism/**` / 対ブラウザ: 4.2 を読んでから決める

洗った鍵 (Asterism protocol 2、asterism の mrblib の表と、gem・AI ヘルパーの呼び方から):

| 鍵 | 誰が | 何 |
|---|---|---|
| `asterism/<tutor>/tutor/protocol/2` | gem | アプリの liveliness (起動時の `already_there?` は `asterism/<tutor>/tutor/**` を liveliness_get) |
| `asterism/<tutor>/tutor/helper` | gem | 公開した helper の liveliness。端末の `conn.each("*/tutor/helper")` がこれを見る |
| `asterism/<tutor>/tutor/**` | gem | queryable (call・meta への返事) |
| `asterism/<tutor>/tutor/helper/call/<端末>` | 端末 → gem | 呼び出し (get)。返事は端末の egress でも照らされるので Read にも要る (console の cloud_config.rb の注記) |
| `asterism/<tutor>/tutor/helper/meta` | 端末 → gem | proxy が meta を問うとき用 (AI ヘルパーは今は問わないが、games の役割に合わせた) |
| `asterism/<node>/@profile`・`<node>/<app>/@profile`・`@status`・`@pubs` | 両方 | プロフィールと状態 (`**` は `@` で始まる塊に当たらないので 1 行ずつ) |
| `asterism/**` の liveliness watch | 両方 | 誰がいるか |

確認 (手元の stack、gem はコンテナ、端末の代わりは `test/sender.rb` 相当の CRuby。証明書は rehearsal の console で
`Relay::LocalIdentity.issue` で作り .tar にまとめた。画面の「Save all (.tar)」と同じ中身):

| 行 | 役割 | devices に | 結果 |
|---|---|---|---|
| fmruby-aaaaaa | tutor | ある | `*/tutor/helper` が見え、4 つの頼みが通った |
| fmruby-bbbbbb | match だけ | ある | helper が見えない、`hello` は「nobody answers」で時間切れ。gem の記録にも来ていない (ACL で届かない) |
| fmruby-cccccc | tutor | 無い | 見えるが gem が `not_allowed` で断った (記録に `refused`) |
| fmruby-dddddd | tutor と match | ある | 通った |
| aaaaaa の証明書で node を dddddd と名乗る | | | 呼び出しが時間切れ (`call/${node}` の名前の拘束) |

## 4. ブラウザ版・ネイティブ版の現状

### 4.1 ネイティブ版 (動く)

- アプリ: `/app` がリポジトリの `flash/` なので、AI ヘルパーは今の版がそのまま入る。`native_app spawn` で起動した。
- 素の TCP: `system_conf_native.toml` の `zenoh_router = "tcp/127.0.0.1:7447"` に、試験用の zenohd と PC の gem
  (fake) を置いた。ノード ID は PC のホスト名になる。質問・ヒント (エディタに 2 行入った)・作成 (「残しますか?」の問い →
  いいえで入れ替わった)・修正 (F5 で落としたエラー → 「修正してもらう」→ 入れ替えの問い) の 4 つが通った。
- mTLS: ネイティブ版の `/home/asterism/` に `config.toml` (`router = "tls/localhost:17448"`) と fmruby-aaaaaa の .tar を置くと、
  ノード ID が証明書の名前になり、rehearsal のルータ越しにコンテナの gem を見つけ、止まったときの `stopped` の結果を
  `pending` で拾って文を出し、質問 (文書つき) も通った。つまり**決定 9 (ネイティブ版も役割で VPS の係を呼べる) は今の端末のコードのままで足りる**。
  置いたファイルは試験の後に消した。
- 直しは要らない見立て。

### 4.2 ブラウザ版 (素の経路では動く、役割の付け方に console の制約)

- バンドル: `wasm/build` は 2026-11-18 18:08 の物で、AI ヘルパーの直し (メニューバーなど) より古い (web_up が stale と断った)。
  `allow_stale` で起こすと古い版の AI ヘルパーが入っていて起動した。今の版での確認は `rake wasm:web` の後に要る (作り直していない)。
- 経路: ページの既定 `ws/localhost:7449` に試験の zenohd を置くと、約 20 秒「Wi-Fi につながるのを待っています…」の後につながり、
  `*/tutor/helper` を見つけて質問が通った。エディタの口 (ヒントで 2 行入る、作成の問い) も動いた。
  - 20 秒待つのは、`FmrbAsterism::Link#wifi_ready?` が、`FmrbApp.wifi_info` が nil でなく未接続のとき `wifi_wait_ms` (20 秒)
    待つため。ブラウザ版の `wifi_info` が「WiFi あり・未接続」を返していると見る (確認していない)。直しの見立て:
    ブラウザ版の `wifi_info` を nil (WiFi の無い機械) にする、か Link が wasm では待たない。端末の側なので直していない。
- **役割 tutor を利用者ごとに付ける形 (決定 8) は、今の console では作れない**。console の `Relay::CloudConfig` では、
  「for browsers」の役割は、利用者の証明書を持つページ (`wasm-<handle>`) にも、パスで入る共有の `ws/` のページにも、
  全部に同じく付く (`browser_role_names` と `browser_cert_rules`)。利用者ごとに役割を選ぶ欄は無い。さらに共有の `ws/` の
  ページは `${node}` が `wasm-$*` に展開され、ほかのブラウザの名前で呼べる (cloud_config.rb の冒頭の注記のとおり)。
  - よって tutor に「for browsers」を付けると、パスを持つ全メンバーのブラウザが係を呼べ、gem の `devices` の
    `wasm-<handle>` は取り違え防止にしかならない。
  - 直しの見立て (console のコード、ユーザが決める): (a) 利用者 (handle) ごとに付ける役割を選べるようにし、
    `browser_cert_rules` が利用者の役割だけを展開する、(b) 役割に「証明書のあるブラウザだけ」の印を足し、共有の `ws/`
    には展開しない。どちらも console の変更なので止めた (指示書 2 章)。docs/install.md の 9 章にこの制約を書いた。
  - 利用者の証明書のブラウザで (door 経由の mTLS で) 通すことはしていない (rehearsal に PLAY_DIST と handle の設定が要る)。

## 5. 自分で決めた細部・見立てと違った点

- status はファイル (games の HTTP でなく)。1.3。
- 停止中の新しい頼みのエラーの種類は `stopping`。端末は `message` をそのまま出す作りなので、端末の直しは要らない。
- `ASTERISM_TUTOR_STOP_GRACE` を足した (1.1)。
- `TZ` は既定の UTC のまま (env.example にコメントで `TZ=Asia/Tokyo`)。UTC だと「1 日」の切り替わりは日本の 9 時になる。
- コンテナの既定のルータは `tls/zenohd:7448` (証明書の中の公開の名前でない)。
- イメージの版の照合は `lib/tutor/version.rb` (VERSION ファイルを作らなかった)。
- `test/sender.rb` の既定のアプリ名を `aihelp` から `ai_helper` (端末と同じ) にした。役割 tutor の rw 行に合わせるため。
- 役割 tutor に端末自身のアプリ (`ai_helper`) の rw 行を入れた。端末が match など別の役割を持たない場合も、この役割だけで
  AI ヘルパーが立つようにするため。
- 見立てと違った点: 手元の stack では最初 UnknownCA で入れなかった。原因は compose の `--env-file` が `${}` の展開にしか
  効かず、コンテナの環境 (`env_file: .env`) には入らないため (`.env` を deploy/vps に置いて解決)。手順書は `.env` を置く形なので問題ない。
