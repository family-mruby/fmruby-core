# Asterism でファイルを運ぶ汎用の仕組み (再送つき)

> 状態: 進行中 | 更新: 2026-11-08 | T0〜T3b 済 (report/t0〜t3.md)。ESP32 の実機の確認待ち。次は T4 (CRuby・console)。仕組みは asterism gem の data/transfer、ネイティブ版どうしの試験 `rake regress:transfer`、要点の試験 `rake regress:transfer:quick` (regress:full)、ESP32 は手順だけ)。 checkpoint の F5 で作った転送のアプリ (片に分けて運ぶ受け口) を、どんなファイルでも運べ、片の取りこぼし・重なり・接続の切れ目から続きを送り直せる汎用の仕組みに仕上げる。段は T0〜T5。仕組みは asterism gem の共通の部品に、再開は接続の切れ目まで、照合は全体の SHA-256、protocol 2 より先 (2026-11-06 決定)。未確定事項は 2026-11-08 に決定 (受け手の空き・相手 1 つ・/home/inbox/、同じ名前は送り手が上書きか名前を変えるかを選ぶ)

## 目的

- Asterism でつながった端末どうし (ESP32・ネイティブ版・sim・ブラウザ版・PC の CRuby) で、**どんなファイルでも**確実に運べるようにする。
- **再送**: 片が届かない・重なって届く・途中で接続が切れる・相手が一時的に答えない、のどれが起きても、最初からやり直さずに**続きから**送り直して完了する。届いたものが送ったものと同じであることを全体の照合で保証する。
- 使い道:
  - checkpoint のイメージ (今の使い道。F5)
  - ブラウザ版のアプリ (`.app.wasm`) のインストール (doc/wasm_apps/plan.md の 4)
  - 開発の手早い道: PC で作ったアプリ・画像・音を端末へ (Console のファイル転送、doc/wasm_apps/plan.md の 3)
  - 構想 (FmrbKernel と Asterism・checkpoint の統合) の土台: 「卵」(定期のイメージを別の端末に預ける) や大きなデータの受け渡し

## 今の形 (2026-11-06)

- 受け口: 転送のアプリ `/usr/share/transfer/transfer.app.rb` が `<ノード>/transfer/inbox` に `check` / `begin` / `chunk` / `commit` / `status` / `cancel` を出す (doc/checkpoint/report/f5.md の 2・11)。
- 片: 1 片 3,072 B。`chunk(id, pos, bytes)` は `pos` が受け手の `got` とちょうど同じときだけ受け取る (前の片の送り直し・抜けは失敗)。
- 上限: 1 MiB、同時に 1 つの相手だけ (ほかは busy)。10 秒片が来なければ捨てる (`.part` も消える)。
- 種類: `KINDS = ["checkpoint"]` だけ。種類の表で増やせる作り。
- 照合: 大きさだけ (`got == size`)。中身の照合 (ハッシュ) は無い。
- 送り手: 転送のアプリの送る側 (カーネルの頼みで、1 つの呼び出しの答えを待ってから次を投げる)。呼び出しの待ちは 10 秒。失敗したら移動ごと諦める。
- 許可: `/home/asterism/receive.toml` の `from = [...]` (種類を問わない)。
- 実測: 30 KB 前後のイメージで、ネイティブ版どうし 21〜35 ms、ネイティブ版 → ESP32 で 326〜488 ms、ESP32 → ネイティブ版で 526〜597 ms (毎秒 50〜100 KB 程度)。

## 方針

1. **今の転送のアプリを土台にし、中身は asterism gem の共通の部品にする**。受け口の名前 (`<ノード>/transfer/inbox`) と段取り (確認 → 始める → 片 → 確定 → 結果) は保ち、中身を汎用にする。checkpoint の移動 (F5・F6 の試験) はこの上でそのまま通ること。
2. **再送は「受け手が持っている位置」を正にする**:
   - 片は何度届いても同じ結果になる形にする。受け手は `pos` が手元の位置より前なら重なりとして読み捨て、今の位置を返す。先なら抜けとして今の位置を返す。送り手は返った位置から送り直す。
   - 送り手は呼び出しが期限切れ・失敗したら、受け手に今の位置を聞いて (`status` か `resume`) 続きから送る。回数と待ちの延び方に上限を持つ。
   - 途中で接続が切れたときは、`.part` と送り手・大きさ・照合の値を書いた控えを残し、同じ送り手から同じファイルの `begin` が期限内に来たら続きから受ける。
3. **全体の照合**: `begin` で送り手が全体のハッシュを宣言し、`commit` で受け手が照合する。合わなければ置かずに理由を返す。
4. **種類ごとの処理と許可**: 受け取った後の処理 (置き場所・起動・インストール) と、受けてよい相手は種類ごとに決める。今の `receive.toml` を種類ごとに書ける形に広げる (書いていない種類は受けない)。
5. **どの端末でも同じ決まり**: 受け口の段取りと値の形 (MessagePack) を文書に決め、ESP32 (picoruby)・ネイティブ版・ブラウザ版・CRuby が同じ決まりで送受する。
6. **費用は小さい端末に合わせる**: ESP32 の内蔵 RAM は増やさない。片の大きさ・同時に送る片の数・控えの大きさは、受け手が自分の空きから決めて送り手に伝える。

## 受け入れ条件

- T1: 試験の道具で起こした「片を 1 割落とす」「同じ片を 2 回送る」「順を入れ替える」「途中で接続を 2 回切る」「受け手の転送のアプリを途中で止めて起動し直す」のそれぞれで、ファイルが最後まで届き、全体のハッシュが一致する (ネイティブ版どうし・ネイティブ版 ⇔ ESP32)。途中で止めた分の送り直しは、止まった位置から (最初からではない) であることをログの位置で確認する。
- T1: 照合が合わないものは置かれず、送り手に理由が返る。期限を過ぎた `.part` は消える。
- T2: 許可していない種類・相手からのものは、受ける前に理由つきで断る。種類 `file` で置いたファイルが、受け手の許した場所にだけ現れる。
- T3: P4 へ 4 MB のファイルを運べる。S3 は置き場所の空きの範囲で運べ、入らないものは `begin` で断る (2026-11-08 ユーザ)。速さの数字 (片の大きさ・同時に送る片の数ごと) を report に残す。ESP32 の内蔵 RAM の増分 0 (`regress:size`)。
- T4: CRuby の送り手から ESP32 へ、ESP32 から CRuby の受け手へ、同じ試験が通る。
- T5: checkpoint の `regress:checkpoint` (ネイティブ版・sim・ブラウザ版・`BOARD=`) が新しい受け口の上で全部通る。
- どの段も `rake regress` が通る。

## 決まったこと (2026-11-06、ユーザが選択肢から選んだ)

- **仕組みの置き場所は asterism gem の共通の部品**: 送受の決まり・片の扱い・再送・照合を gem に置き、端末の転送のアプリと console (CRuby) はそれを使う。端末と PC で同じコードになり、送り手と受け手の食い違いが起きにくい。gem の版の管理 (Family mruby の pin) が増える。
- **再開は接続の切れ目まで**: 受け手が動いている間の切断・再接続から続きを受ける。途中のものは `/tmp` (PSRAM の tmpfs) に置き、flash を書き続けない。受け手の端末が再起動したら最初から。
- **照合は全体の SHA-256**: 片の破損は Zenoh (TCP / TLS) が守るので、片ごとの確認は省く。ESP32 での費用は T0 で測る。
- **protocol 2 より先にする**: 今の値の形 (MessagePack のバイト列) で作る。片はほとんどがバイト列なので、protocol 2 で値の形が変わっても影響は小さい。

## 決定事項 (2026-11-08 ユーザ)

- **上限は受け手の空きから**: 送る前に受け手が置き場所の空きを見て、入らなければ最初に断る。
  固定の上限は設けない。
- **同時に受けるのは 1 つの相手だけ**: 受けている間に来た別の相手には「使用中」で断り、
  相手が後で送り直す。
- **種類 `file` の置き場所は `/home/inbox/` の下だけ**。
- **同じ名前があるときは送り手が送るときに選ぶ**: 「上書き」か「名前を変える」
  (`foo(1).txt` のように変えて置き、元のファイルは残す)。指定がなければ名前を変える。
  ファイルの更新に使えるように (2026-11-08 ユーザ訂正)。

## 決定事項 (2026-11-08 ユーザ、T1 の後)

- **空きを知る口を T2 で足す**: 置き場所 (`/tmp`・`/home/inbox/`) の空きをアプリから
  知るメソッドを足し、`begin` で入らなければ断る (今は書けなくなった所で断る)。
- **push は asterism gem → fmruby-core の順** (fmruby-core の pin が gem の新しいコミットを指す)。
- **`regress:full` には 1 分ほどの要点の試験を入れる**: 今の `regress:transfer`
  (7 場面・2 構成で約 6 分) はそのまま残し、要点だけ (再送・続きから・照合) を
  1 分ほどで確かめる版を作って `regress:full` に入れる。
- **ブラウザ版の SHA-256 は C の実装にする** (T3 の数 MB を運ぶ前に)。

## 決定事項 (2026-11-08 ユーザ、T2 の後)

- **Shell のコマンドは `asend <ノード> <ファイル> [-o]`・`asend -c`** (Asterism の送信と
  分かる短い名前。T2 では send で作った)。
- **種類 file の名前の決まりは T2 のまま**: `.` で始まる名前は断る、48 バイトまで、日本語は通す。
- **種類 file の途中のファイルは置き場所の隣に直接書く** (T3): `/tmp` でなく
  `/home/inbox/` の隠しファイルに書き、受けられる大きさは storage の空きまで。
  commit での `/tmp` からの写しが要らなくなる。checkpoint は今のまま `/tmp`。

## 決定事項 (2026-11-08 ユーザ、T3 の後)

- **ESP32 へ 4 MB の受け入れ条件は P4 で**。S3 は置き場所の空きの範囲で運べ、入らなければ
  `begin` で断ること。
- **SD にも置ける**: 種類 file の置き場所に SD の inbox (`/sd/inbox/`) を足す。どちらに置くかは
  **送り手が送るときに選ぶ** (例: `asend --sd`)。指定がなければ `/home/inbox/`。SD の無い
  端末は `begin` で断る。
- **受け手の端末の再起動からは今のまま最初から** (控えは `/tmp`)。再起動の後に残った
  途中のファイルは転送のアプリの起動時に消す。
- **ブラウザ版の `/home` の空きはブラウザの保存の目安** (`navigator.storage.estimate`) から
  出し、入らなければ `begin` で断る (目安なので余裕を見る)。
- **同時に送る片の数は今の決め方** (プールの空き ÷ 片 4 つ分、最大 8、checkpoint は 4)。
  ESP32 で測ってから見直す。

## 決定事項 (2026-11-08 ユーザ、T3b の後)

- **ネイティブ版に `/sd` は足さない**: SD の inbox は ESP32 の実機でだけ確かめる。
- **Shell で SD を選ぶ指定は `-s` と `--sd` の両方** (PC の道具は `--sd`)。
- inbox の名前は `home`・`sd` だけを受け、ほかは断る (T3b の作りのまま)。
