# Asterism でファイルを運ぶ汎用の仕組み (再送つき)

> 状態: 計画済 | 更新: 2026-11-06 | checkpoint の F5 で作った転送のアプリ (片に分けて運ぶ受け口) を、どんなファイルでも運べ、片の取りこぼし・重なり・接続の切れ目から続きを送り直せる汎用の仕組みに仕上げる。段は T0〜T5、未確定事項 7 つ

## 目的

- Asterism でつながった端末どうし (ESP32・ネイティブ版・sim・ブラウザ版・PC の CRuby) で、**どんなファイルでも**確実に運べるようにする。
- **再送**: 片が届かない・重なって届く・途中で接続が切れる・相手が一時的に答えない、のどれが起きても、最初からやり直さずに**続きから**送り直して完了する。届いたものが送ったものと同じであることを全体の照合で保証する。
- 使い道:
  - checkpoint のイメージ (今の使い道。F5)
  - ブラウザ版のアプリ (`.app.wasm`) のインストール (doc/wasm_apps/plan.md の 4)
  - 開発の手早い道: PC で作ったアプリ・画像・音を端末へ (Console のファイル転送、doc/wasm_apps/plan.md の 3)
  - 構想 (FmrbKernel と Asterism・checkpoint の統合) の土台: 「卵」(定期のイメージを別の端末に預ける) や大きなデータの受け渡し

## 今の形 (2026-11-06)

- 受け口: 転送のアプリ `/usr/share/transfer/transfer.app.rb` が `<ノード>/transfer/inbox` に `check` / `begin` / `chunk` / `commit` / `status` / `cancel` を出す (doc/checkpoint/report/f5.md の 2・11)。
- 片: 1 片 3,072 B。`chunk(id, pos, bytes)` は `pos` が受け手の `got` とちょうど同じときだけ受け取る (前の片の送り直し・抜けは失敗)。
- 上限: 1 MiB、同時に 1 つの相手だけ (ほかは busy)。10 秒片が来なければ捨てる (`.part` も消える)。
- 種類: `KINDS = ["checkpoint"]` だけ。種類の表で増やせる作り。
- 照合: 大きさだけ (`got == size`)。中身の照合 (ハッシュ) は無い。
- 送り手: 転送のアプリの送る側 (カーネルの頼みで、1 つの呼び出しの答えを待ってから次を投げる)。呼び出しの待ちは 10 秒。失敗したら移動ごと諦める。
- 許可: `/home/asterism/receive.toml` の `from = [...]` (種類を問わない)。
- 実測: 30 KB 前後のイメージで、ネイティブ版どうし 21〜35 ms、ネイティブ版 → ESP32 で 326〜488 ms、ESP32 → ネイティブ版で 526〜597 ms (毎秒 50〜100 KB 程度)。

## 方針

1. **今の転送のアプリを土台にする**。受け口の名前 (`<ノード>/transfer/inbox`) と段取り (確認 → 始める → 片 → 確定 → 結果) は保ち、中身を汎用にする。checkpoint の移動 (F5・F6 の試験) はこの上でそのまま通ること。
2. **再送は「受け手が持っている位置」を正にする**:
   - 片は何度届いても同じ結果になる形にする。受け手は `pos` が手元の位置より前なら重なりとして読み捨て、今の位置を返す。先なら抜けとして今の位置を返す。送り手は返った位置から送り直す。
   - 送り手は呼び出しが期限切れ・失敗したら、受け手に今の位置を聞いて (`status` か `resume`) 続きから送る。回数と待ちの延び方に上限を持つ。
   - 途中で接続が切れたときは、`.part` と送り手・大きさ・照合の値を書いた控えを残し、同じ送り手から同じファイルの `begin` が期限内に来たら続きから受ける。
3. **全体の照合**: `begin` で送り手が全体のハッシュを宣言し、`commit` で受け手が照合する。合わなければ置かずに理由を返す。
4. **種類ごとの処理と許可**: 受け取った後の処理 (置き場所・起動・インストール) と、受けてよい相手は種類ごとに決める。今の `receive.toml` を種類ごとに書ける形に広げる (書いていない種類は受けない)。
5. **どの端末でも同じ決まり**: 受け口の段取りと値の形 (MessagePack) を文書に決め、ESP32 (picoruby)・ネイティブ版・ブラウザ版・CRuby が同じ決まりで送受する。
6. **費用は小さい端末に合わせる**: ESP32 の内蔵 RAM は増やさない。片の大きさ・同時に送る片の数・控えの大きさは、受け手が自分の空きから決めて送り手に伝える。

## 受け入れ条件

- T1: 試験の道具で起こした「片を 1 割落とす」「同じ片を 2 回送る」「順を入れ替える」「途中で接続を 2 回切る」「受け手の転送のアプリを途中で止めて起動し直す」のそれぞれで、ファイルが最後まで届き、全体のハッシュが一致する (ネイティブ版どうし・ネイティブ版 ⇔ ESP32)。途中で止めた分の送り直しは、止まった位置から (最初からではない) であることをログの位置で確認する。
- T1: 照合が合わないものは置かれず、送り手に理由が返る。期限を過ぎた `.part` は消える。
- T2: 許可していない種類・相手からのものは、受ける前に理由つきで断る。種類 `file` で置いたファイルが、受け手の許した場所にだけ現れる。
- T3: ESP32 へ 4 MB のファイルを運べる (受け手の空きがある範囲で)。速さの数字 (片の大きさ・同時に送る片の数ごと) を report に残す。ESP32 の内蔵 RAM の増分 0 (`regress:size`)。
- T4: CRuby の送り手から ESP32 へ、ESP32 から CRuby の受け手へ、同じ試験が通る。
- T5: checkpoint の `regress:checkpoint` (ネイティブ版・sim・ブラウザ版・`BOARD=`) が新しい受け口の上で全部通る。
- どの段も `rake regress` が通る。

## 未確定事項

1. **仕組みの置き場所**: (a) Family mruby の転送のアプリの中に置き、CRuby の側は後で同じ決まりを実装する (今の延長) / (b) 送受の決まりと片の扱いを asterism gem の共通の部品にし、転送のアプリと console はそれを使う (端末と PC で同じコード。gem の版の管理が増える)。
2. **再開の範囲**: 接続の切れ目だけでなく、受け手の端末の再起動をまたいでも続きから受けるか (`.part` と控えを flash に残す。flash の書き込み回数と、使う人のデータの置き場所 /home との関係を決める必要がある)。
3. **ハッシュの種類**: SHA-256 (確実、ESP32 では mbedtls で費用を測る) / CRC32 (軽いが偶然の一致がありうる) / 片ごとに CRC32 + 全体に SHA-256。
4. **上限**: 1 つのファイルの大きさの上限を固定にするか、受け手の空き (tmpfs・storage) から決めるか。置き場所 (`/tmp` は PSRAM の tmpfs、8 MB) で上限が変わる。
5. **同時に受ける数**: 今の「同時に 1 つの相手だけ」のままにするか、複数を並べるか。
6. **種類 `file` の置き場所と上書き**: 受け手が許す場所 (例: `/home/inbox/` だけ) と、同じ名前のファイルがあるとき (断る・名前を変える・上書き)。
7. **Asterism protocol 2 との関係**: protocol 2 (doc/ruby_asterism/protocol2_design.md、構想) で値の形を短くする計画と、どちらを先にするか。バイト列の運び方 (MessagePack の bin) を protocol 2 に合わせるか。
