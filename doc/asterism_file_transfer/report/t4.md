## 2. CRuby の受け手 (gem)

- `FileInbox.new(dir, work:, from:, max_bytes:, label:)`: 種類 `file` の受け手。端末の転送のアプリと同じ決まり。
  - 種類は `file` だけ (`<label> takes no checkpoint`)。送り手は `from` (ノード ID と `*` の型の配列) かブロックで許す (`<label> takes no file from <node>`)。
  - 名前は `Transfer.file_name?` (`/`・`\`・`..` なし、`.` で始まらない、48 バイトまで)。
  - 同じ名前: meta `"overwrite" => true` なら照合が合った後に置き換え、無ければ `name(1)` で横に置く。
  - 空き: `max_bytes` (置き場の合計) を超えるものは `begin` で断る (`N bytes do not fit (M bytes free)`)。CRuby の標準に statvfs が無いので、ディスクの空きは見ていない。
  - 片は置く先の隣の隠しファイル (`<dir>.<name>.file.part`)、commit は名前の付け替えだけ。控えは `work` (別のディレクトリ)。`start` で控えから続きを拾い、控えの無い隠しの片を消す (プログラムを起動し直しても続きから受ける。端末の「再起動したら最初から」は端末の `/tmp` の性質で、console では続ける方が自然なのでこうした)。
  - meta の `"inbox"` が `"sd"` なら「`<label> has no SD card to write to`」、ほかの値は「`has no inbox X (home only)`」で断る。
  - 相手 1 つ・再送・照合は `Inbox` のまま。
- `Endpoint.new(conn, inbox, node:, app: "transfer", object: "inbox").start`: Asterism の object layer は 1 プロセス 1 アプリ (bridge は `console/console`) なので、端末が送る先 `<node>/transfer/inbox` を出すために、Zenoh の接続に直に、アプリと object の liveliness token と queryable を置き、object layer と同じ符号 (`{"method","args"}` の map、答えは `{"value"}` / `{"error"}`) で `begin`・`chunk`・`commit`・`cancel` と meta に答える。呼び手のノード ID は鍵の最後の chunk から `from:` に渡す (`caller: :from` と同じ)。受け手の呼び出しは 1 つの錠の下で動く (受信のスレッドとプログラムの `tick`)。
- gem の試験 `rake test:transfer` は 26 件 (4 件足した)。`rake test` 全体では `test:cli` の `test_usage` が 1 件落ちるが、変更前 (stash して流した) も同じに落ちる (今回の変更と無関係)。

## 3. console のつくり

### ページ (`/files`、メニューの Watch に「Files」)

- **Send a file to a machine** (サインインした誰でも): ファイル、送り先のノード (今ネットワークにいて許可されたノードを候補に出す)、別の名前 (`As`)、「Overwrite」、「To the SD card」。送ると表に行ができ、1 秒ごとに「1.7 MB (4 %) of 40 MB」のように端末が持っている量が出て、自分の行には Cancel が出る。
- **Received** (管理者だけ): 受けたファイルの一覧 (名前・大きさ・着いた時刻)、名前をクリックでダウンロード、Delete。受けてよい相手 (`ASTERISM_TRANSFER_FROM`) と使っている量 / 上限も出す。
- **Record**: 新しい順に、いつ・sent to / from・ノード・ファイル名 (置かれた名前・overwrite・SD)・大きさ・SHA-256 (先頭 12 桁、全体は title)・結果 (done / failed / cancelled / denied、受けたもの: done / refused / dropped) と理由・かかった時間・だれ。一般の利用者は自分が送ったものだけ、管理者は全部 (受けたもの・断った相手も)。

### 送る (bridge)

- ページがアップロードを `storage/transfers/outbox/<ランダム 24 桁>` に置き、SHA-256 を計算して行 (`pending`) を書く。上限 `ASTERISM_TRANSFER_UPLOAD_MAX_BYTES` (256 MB)、空のファイルと名前の決まりに合わないものはここで断る。同時に待てるのは 8 つまで。
- bridge は 0.5 秒ごとに行を見て、`pending` を最大 2 つまで、ファイルごとのスレッドで `Asterism::Transfer::Sender` (`<node>/transfer/inbox`、種類 `file`、meta `overwrite`・`"inbox" => "sd"`) を 2 ms ごとに進める (bridge の本体の周期 0.1 秒で進めると 1 MiB に数秒かかるため)。進み具合 (`done_bytes`) を行に書き、ページの Cancel (`cancelling`) で `Sender#cancel` (端末は片を消す)。終わったら `done` (置かれた名前)・`failed` (端末の理由)・`cancelled`、アップロードは消す。
- bridge が送っている途中で止まったら行は `failed` (「the bridge stopped while it was sending」)。2 分取られなかった `pending` も `failed`。

### 受ける (bridge)

- bridge の Zenoh の接続 (読む側のセッション) に `Endpoint` を置き、`console/transfer/inbox` で答える。グラフでは console のノードの中にアプリ `console` と `transfer` (object `inbox`) が出る。
- 受けた結果は受信のスレッドからキューで本体に渡し、本体が行を書く (`begin` で `receiving`、`commit` で `done` (置いた名前) / `refused` (SHA-256 が合わない)、取りやめ・1 分片が来ない で `dropped`)。`begin` で断ったもの (許していない相手・名前・空き) も `refused` の行に残す (同じ相手・同じ理由は 1 分に 1 行)。
- bridge を起動し直したとき、控えから拾った途中のファイルは前の `receiving` の行につなぎ、ほかの `receiving` の行は `dropped` にする。
- `ASTERISM_TRANSFERS=0` で送受を丸ごと外せる。gem が古くて `FileInbox` が無いときは bridge は止まらず、「files: not started」とだけ出す。

## 4. 権限

- **送る (console の鍵)**: Call permissions の表に列 `kind` を足した (`call` / `file`)。管理者は Admin > Call permissions の「Allow sending files」でノードの型 (`fmruby-*` など) を足す。種類 `file` の行は app・object・method を `transfer`・`inbox`・`*` に固定し、**呼び出しは何も許さない** (`allows?` と `for_path` は `call` の行だけを見る)。逆に `call` の行 (`*/*/*` `*` でも) はファイルを送らせない。ページがアップロードを受けるときに確かめ (無ければ `denied` の行、アップロードは置かない)、bridge が送る直前にもう一度確かめる (その間に行が消されたら `denied`)。
- **送る (端末の鍵)**: 端末の `/home/asterism/receive.toml` の `[file] from = ["console"]` (T2 のまま)。無ければ端末が `begin` で断り、行に「`fmruby-xxxxxx takes no file from console (file from in /home/asterism/receive.toml)`」と出る。
- **受ける**: console の設定 `ASTERISM_TRANSFER_FROM` (カンマ区切り、`*` の型。空なら誰からも受けない)。受けたファイルの一覧・ダウンロード・削除と、受けた記録は管理者だけ (録画と同じ考え: 端末が送ってきたものなら何でも入っている)。
- 記録の作り: 今の console の「Call log」(`bridge_requests` が監査の記録) と「Recordings」(行が bridge への頼みを兼ねる) に合わせ、`file_transfers` の行が送る頼み・進み具合・監査の記録を兼ねる。既存の権限・記録の作りは変えていない (列 1 つと表 1 つを足しただけ)。

## 5. VPS へ配置するときに要るもの

1. **asterism gem の版**: console は `Asterism::Transfer::FileInbox`・`Endpoint` (gem の `56e25be`・`3366489`、0.11.0 より後) が要る。VPS の image は rubygems.org の gem を入れる (`ASTERISM_GEMS=rubygems`、Gemfile は `~> 0.8`) ので、**gem のリリース (0.12.0 など) と Gemfile のその行の版の更新が先**。古い gem のままでも console は動き、ファイルだけが動かない (bridge の log に「files: not started」)。
2. **migration** (console の起動時に流れる、2 つ): `call_permissions.kind` (既定 `"call"`、既存の行はそのまま呼び出しの行)、新しい表 `file_transfers`。消すものは無い。戻すときは更新前のバックアップ (いつもの手順)。
3. **`.env`** (env.example にコメントで足した):
   - `ASTERISM_TRANSFER_FROM` (端末から console へ送ってよいノード。設定しなければ受けない)
   - `ASTERISM_TRANSFER_INBOX_MAX_BYTES` (受けたファイルの合計、既定 1 GiB)、`ASTERISM_TRANSFER_UPLOAD_MAX_BYTES` (1 回のアップロード、既定 256 MiB)
   - 置き場は `storage` の volume の `storage/transfers/` (outbox・inbox・work)。日ごとのバックアップは DB だけで、このファイルは入らない (録画と同じ)。
4. **nginx**: 今の `client_max_body_size 300m` で 256 MiB のアップロードは通る。上限を上げるならここも。
5. **router の規則** (Admin > Members > Roles を作って Apply。console の証明書は既に `asterism/**` の rw がある):
   - 端末から console へ送る: ask に `asterism/console/transfer/inbox/call/${node}`。
   - console から端末へ送る: 端末が自分の `asterism/${node}/transfer`・`asterism/${node}/transfer/**` を rw で持つこと (受け口の token・queryable・答え)。今の role にあるかは公開の console で確かめる。
6. 公開の console の版 (VERSION・CHANGELOG の版名・install.md の「From 0.3.12 to ...」の節) は付けていない。CHANGELOG は `Unreleased` に「What an update needs」込みで書いた。リリースのときに版名と install.md の節を足す。

## 7. 気づき

- console の `bin/dev` は Ctrl-C (プロセスグループへの INT) で両方止まるが、`bin/dev` のプロセスだけに INT を送ると puma が残る (system() の子)。止めるときはグループに送る。既存の作り。
- ヘッドレスの Chromium (Docker Desktop の container) からは `--network host` では WSL のループバックに届かない。`host.docker.internal` と `CONSOLE_EXTRA_HOST=host.docker.internal` (README の道具の説明どおり) で届く。
- console の作業ツリーには、この作業の前から `Gemfile.lock` の変更 (asterism 0.8.0 → 0.11.0、asterism-zenoh 0.4.1 → 0.4.2。隣の checkout に合わせて Bundler が書いたもの) があった。コミットには入れていない。

## 8. 残件・親に決めてほしいこと

### 残件

- gem の push (`56e25be`・`3366489`) とリリース、console の Gemfile の rubygems の版。console の push。VPS への配置 (5 章)。
- ESP32 の端末との console の送受 (受け入れ条件「CRuby の送り手から ESP32 へ、ESP32 から CRuby の受け手へ」) は実機が要るので流していない。手順は (a)(b) と同じで、端末の `receive.toml` に `[file] from = ["console"]`、console の `ASTERISM_TRANSFER_FROM` に端末のノード。

### 親に決めてほしいこと

1. **受けたファイルと受けた記録は管理者だけ**にした (録画と同じ)。送るのは許可された誰でも、記録は自分の送ったものだけ。受けたファイルを一般の利用者にも見せるか。
2. **console は bridge を起動し直しても途中の受け取りを続ける** (控えを `storage/transfers/work/` に置く)。端末の「再起動したら最初から」とは違うが、console には `/tmp` の区別が無いのでこうした。
3. **console の置き場の空きはディスクを見ず、上限 (`ASTERISM_TRANSFER_INBOX_MAX_BYTES`、既定 1 GiB) だけで断る** (CRuby の標準に statvfs が無い)。既定の 1 GiB・アップロード 256 MiB・同時に送る 2 つ・待てる 8 つは仮決め。
4. **`console/transfer/inbox` は gem の `Endpoint` (object layer を通さず Zenoh に直に) で出した**。object layer を 1 プロセスで複数アプリにする作りは gem の大きな変更になるので選ばなかった。
5. 公開の console の版 (0.3.13 か 0.4.0) と、gem の版 (0.12.0)。

### 作り

- **印**: 台帳の表 `relay_peers` に列 2 つ、`files_to_console` (「May send files to the console」) と

- **bridge**: 受け手の許可は `RelayPeer.file_senders` を 2 秒ごとに読み直して `FileInbox#from` に入れる
  (動いている bridge に印の変更が効く、ログ「taking files from ...」)。送る前の確認は
  `RelayPeer.receives_files?`。`ASTERISM_TRANSFER_FROM` が残っていれば起動時に「読まない、.env から消して」と出す。
- **Files のページ**: 「On the network now and allowed」(候補) は受ける印の付いたノード、管理者の「Taken from」は
  送ってよい印の行 (表示名つき、家のルータなら「(for a, b)」)。誰にも印が無ければ「Admin > Members で印を」と出す。
- **Call permissions**: 種類 `file` の行と「Allow sending files」を消し、ページ・controller・試験は T4 の前に
  戻した (T4 だけが触っていた)。一文だけ「ファイルは Members の印」と足した。**列 `kind` は消した** (値が
  `call` だけになる列を残す意味が無い。SQLite は表を写し直すが、索引・外部キーは残ることを schema で確かめた)。

### 移行 (`db/migrate/20261108200000_member_file_marks.rb`)

1. 列 2 つを足す。
2. `call_permissions` の `kind = "file"` の行ごとに、その型 (`*` つき) に当たるノードを話す行に「受ける」の印、
   その行を消す。
3. `ASTERISM_TRANSFER_FROM` (VPS では console の container が `.env` を読むので、起動時の `db:prepare` で見える)
   の型ごとに、当たる行に「送ってよい」の印。
4. 当たる行が無い型は migration の出力 (console のログ) に
   「... no member row speaks for a node it matches; nothing marked (mark the rows in Admin > Members)」と出し、
   Rails のログにも書く。印は付かない。
5. 列 `kind` を消す。call の行はそのまま。
- down: 列 `kind` を戻し、受ける印の行のノードごとに file の行を作り、印の列を消す。
- 手元の開発用 DB (`storage/development.sqlite3`) に流した (file の行は無かった。列が増え `kind` が消えただけ、
  行数は同じ)。流す前の写しは scratchpad の `dbbak/`。

  `bin/rubocop` (変えたファイル) は指摘なし。
- 手元の通し (作業用の写しの console、DB は空から。zenohd 1.10.1 の container をループバックの空いたポートで):
  - 平の zenohd (ACL なし) と `bin/dev`。台帳: `fmrb-send` (送ってよい)、`home-a` (router、`fmruby-t4b1`・
    `fmruby-t4b2`、受ける)。`fmruby-core/tools/fmrb_send.rb console photo.bin --node ...` (300 KB):
    - `fmrb-send`: placed as photo.bin (88 ms)、SHA-256 一致。
    - `linux-x` (台帳に無い)・`fmruby-t4b1` (受けるだけ): 「console takes no file from ...」で begin で断る、`refused` の行。
    - 動いている bridge で `fmrb-send` の印を外し `home-a` に送ってよいを付けると、2 秒以内に
      「taking files from fmruby-t4b1 fmruby-t4b2」、`fmrb-send` は断られ `fmruby-t4b2` は photo(1).bin。
    - 印の無い `linux-x` への送る行は bridge が `denied` (「no member row lets the console send files to linux-x」)。
  - **生成した ACL で**: 行に仮の証明書の行を足して `Relay::Applier.config_for` の `cloud.json5` を書き、
    使い捨ての CA と証明書で zenohd をその設定 (mTLS、ACL 有効) のまま起動し、bridge を console の証明書で
    つないだ。CRuby の送り手 (fmrb_send.rb と同じ回し方で証明書を持つ小さな台本、scratchpad) で:
    - `fmrb-send` (送ってよいの印だけ、役割なし): placed。`linux-x` (台帳に無い): 答えが来ない (router が断る)。
    - console から `fmruby-t4b1` (`home-a` の証明書で CRuby の `FileInbox`+`Endpoint`、受けるの印だけ): done、
      SHA-256 一致。

    返らなかった (「nobody answers」)。zenohd 1.10.1 は答え (reply) を呼び手の egress の規則で見る。役割の ask
    の行はその役割の read の行 (egress 全部) で答えを通していたが、印には read の行が無い。同じ鍵に reply・egress
    を足した版で通ることを確かめてから、`_answer` の規則として生成に入れた (鍵は決定のまま、通すのはその呼び出しの
    答えだけ)。
- 起動したものは全部止めた (zenohd の container 3 つ、`bin/dev` の puma と bridge、stand-in の受け手)。

### 親に決めてほしいこと

1. **送ってよいの印に reply・egress の規則を足した** (上の「見つけたこと」)。鍵は決定のとおりで、これが無いと
   印だけでは動かない。仕様の変更ではないと判断して入れたが、確認してほしい。同じことは役割の ask の行にも
   言える (read の行の無い役割の ask は答えが返らない) が、役割の作りは変えていない。

   いない (ACL の側が見る。手元の ACL なしの router でも動くように)。
