## 2. 利用者ごとの鍵と証明書 (console)

- 名前は利用者のブラウザのノード ID そのもの (`wasm-<handle>`、`Relay::BrowserNode.base`)。証明書の CN = ノード ID なので、ACL の subject とページの名前が一致する。
- 置き場所は rooms の volume の `browsers/` (`wasm-alice.pem`・`wasm-alice.key` (0600)・`ca.pem`)。door は rooms の volume を既に読み取り専用でつないでいるので、compose の volume は増やしていない。
- 作るとき: 利用者が handle を決めたとき (アカウントの画面。signer が答えなければ作らずにログに残し、後で作る)、`bin/asterism setup` (更新の `setup --from-update` も。既にいる利用者の移行はこれ)、Members > Browsers の「Make the missing certificates」。期限は 365 日、残り 30 日を切ったら setup が作り直す (席と同じ `RoomCerts.ensure_one` を使う)。
- handle を変えたら古い名前のファイルを消し、door の一覧からもすぐ外す (Apply を待たずに古い名前は使われない)。利用者を消したときも消す。setup はどの利用者のものでもないファイルを消す。
- 利用者ごとに 1 つ。台帳の行は作らない (ファイルが記録)。台帳に同じ名前の行があれば ACL から外す (名前はブラウザのもの)。
- **ACL に載るのは Apply の後**: 次の設定に入るのは良い証明書を持つ利用者で、設定が変わるので Members の「Changes not yet applied」の帯が出る。Members > Browsers の表とアカウントの画面に「waiting to apply」、Apply の後は「in the ACL」・「yes」。Apply (と setup) が door の一覧 `browsers/browsers.json` (今の設定が入れている名前) を書く。

## 3. door

- pass の確認 (`/passes/check`) の答えに `X-Asterism-Browser: node=wasm-alice; pass=12; notice=1; until=...; mac=...` を足した。`node` は pass のノードがその利用者自身のノード (`wasm-<handle>`) のときだけ (2 つ目のページの `wasm-alice_2`・古い handle の pass は空)。`notice` はページが知らせを頼んだか (`door=1`)。
- **署名を付けた** (HMAC-SHA256、鍵は console が `browsers/door.key` に作る)。指示には無いが、nginx が新しい行を持つ前 (更新の途中) は、ブラウザが自分で送った同じ名前の頭が door まで素通りするので、署名なしでは他人の証明書を取れてしまう。door は署名が合わない頭を無視する (共有の接続へ)。
- nginx は `auth_request_set $asterism_browser ...` と `proxy_set_header X-Asterism-Browser ...` の 2 行 (Caddy は `copy_headers` に足す)。無ければ door には何も届かず、全部のページが今どおり共有の接続。
- 振り分け (`Relay::BrowserDoor`): 名前があり、`browsers.json` に載り、ファイルがあり、ほかの pass がその名前で今つながっていなければ、`tls/` へその証明書で。同じ pass の 2 つ目のセッション・つなぎ直しは同じ名前を取れる。それ以外は今の `ws/` へ。`tls/` 側は部屋の door と同じ詰め替え (1 メッセージ = 1 batch ⇔ 2 バイトの長さ、InitAck の batch の大きさを 2 減らす)。`tls/` へつなげなかったときも共有の接続へ落とす。
- 知らせ: `door=1` のページには Zenoh の最初の batch より前に Text を 1 通 (`{"door": {"verified": true, "node": "wasm-alice"}}`、共有なら `{"door": {"verified": false, "why": "..."}}`。共有のときは zenohd の 101 を通した後に door が挟む)。頼まないページ (古いブラウザ版) には送らない: 古いページは Text を長さ 0 の batch として受けてしまうため。
- ログ: `#3 open from ...: GET /, as wasm-alice with its certificate (pass 7), for 14400 s`、共有なら `(shared: <理由>)`。
- 部屋の door の動きは変えていない (`Relay::WsFrames` へ移しただけ。部屋の試験はそのまま通る)。

## 4. ACL (`Relay::CloudConfig`)

証明書のあるブラウザ `wasm-alice` (設定 `browser_certs`):

| subject | 規則 |
|---|---|
| `browser__wasm_alice` (CN だけ) | 「Browsers have this role」のロールを `${node}` = `wasm-alice` で、`asterism/*/*/*/call/**` の query を deny、受け手として一覧を選ばれたことがあれば自分の `asterism/wasm-alice/transfer`・`.../transfer/**` の rw |
| `browser__wasm_alice_calls` (CN + `link_protocols: ["tls"]`) | ロールの ask のうち呼び出しの行を、呼び手を自分の名前に直したもの (`asterism/*/game/*/call/wasm-alice`)、送り手として選ばれた受け口の ask と答え |

- 書けるのはロールの通り (`${node}` の行は自分の名前の下だけ)。呼べるのはロールの行の範囲で自分の名前だけ (ロールが `.../call/*` や `asterism/**` でも他人の名前では呼べない。`asterism/**` のような呼び出しでない ask だけのロールでは呼び出しは無くなる。席と同じ考え方)。
- 共有の `ws/` subject: ロールは今どおり (`wasm-$*`)、加えて `asterism/*/transfer`・`asterism/*/transfer/**` を全部の message・両方向で deny。
- T6 の一覧: ブラウザを台帳の行と同じ「当事者」として `sender_keys` に入れた。台帳の行の一覧で `wasm-alice` を選ぶ・`wasm-*`・`*` が当たる、ブラウザの一覧で台帳のノード・ほかのブラウザ・console を選ぶ、のどれも同じ形の行になる。自分は自分の送り手にならない。
- 試験 `test/lib/relay/browser_certs_acl_test.rb` (`AclEvaluator`): 自分の名前の下にだけ書ける、ほかのブラウザ・台帳の名前で呼べない、`tls` 以外の link では呼べない、共有の接続から転送の鍵が断られる (何でも許すロールでも)、台帳 → ブラウザ・ブラウザ → 台帳・ブラウザ → ブラウザの転送、選ばれていない者は呼べない、型がブラウザにも当たる、Apply 前 (設定に無い) は同じ名前の tls の相手が何もできない、台帳の同名の行が外れる、door の一覧。

## 5. 受け手としての利用者 (行の作り)

- Members に「Browsers」のタブを足した。handle を持つ利用者ごとに 1 行: ノード、証明書の期限、ACL (in the ACL / waiting to apply)、「Receives files from」「Receives apps (checkpoint) from」、ページに一覧が届いたか、今ネットワークにいるか、Edit。
- Edit は台帳の行の「Receives files from」と同じ欄 (同じ partial `relay/peers/_receivers_fields`)。候補は台帳の行のノード・証明書のあるブラウザ (`wasm-bob (a browser)`)・console、自分は外す。型も書ける。
- 中身は台帳の行と同じ列 (`receive_files_from`・`receive_checkpoints_from`・`receivers_changed_at`・`receivers_delivered`) を `users` に足し、選ぶ・変わった時刻・値の決まりは `ReceiverLists` の concern に移して `RelayPeer` と `User` で共有した。
- bridge の `Bridge::Receivers` は台帳の行に加えて利用者のブラウザのノードへも `policy_set` を送る。ログは `receivers: wasm-bob has the list of its user (written there)`。
- 台帳の行の Edit の候補にも証明書のあるブラウザが出る。
- 作りは Members に合わせた範囲で収まり、大きく変える必要は出なかった。T4b の印 (console の Files からブラウザへ送る、ブラウザの `asend console`) はブラウザには付けていない (残件)。

## 6. ブラウザ版 (fmruby-core)

- `zp_ws_emscripten.c`: pass のあるページは URL に `door=1` を付ける (pass・page の隣。nginx が query を落とし、console が X-Original-URI から読む)。`onmessage` で Text を受けたら rx の輪に入れず `Module.zenohDoor(slot, notice)` へ。閉じたら `Module.zenohDoor(slot, null)` (`zp_ws_js_close` は onclose を外すのでそこでも)。
- `main.js`: 開いている WebSocket の知らせが全部「verified かつ このページのノード」のときだけ確認済みとし、`/flash/tmp/.asterism_door` (端末の `/tmp/.asterism_door`) にノード ID を書く。そうでなくなったら消す。Network の欄に「the router checked this name (your certificate at the console's door): files can go」/「shared connection, the router does not check this name (<理由>): no files」/「the door connected this page as <名前>, not as this ID: no files」。
- 転送のアプリの `certified?`: `tls/` のとき、または `FmrbConst::BOARD == "wasm"` で `ws/` のルータかつ `/tmp/.asterism_door` の中身が自分のノード ID のとき。ページ全体で 1 つの印にしたのは、zenoh-pico のセッションと WebSocket の対応を Ruby から見られないため。安全の線はルータの側にある: 共有の接続では転送の受け口の宣言そのものが ACL で落ち、確認済みの接続では呼び手が証明書に縛られる。印は「受け入れてよいと言う」ためだけで、偽の印を書いても共有の接続では誰も受け口に届かない。断りの文言は `... over a connection without certificates (its router is not tls/, nor a page the door checked)`。

## 8. 見立てと違った点・撤回した仮説

- **署名が要った**: 指示の形 (nginx が console の答えを door へ渡す) だけでは、nginx の設定の更新が遅れた間、ブラウザが自分で付けた頭が door に素通りする (nginx は proxy_set_header の無い頭をそのまま渡す)。console の鍵での署名を足した。VPS の手順は「nginx に 2 行」のままで、順番を気にしなくてよい。
- **1 回目の通しで alice → bob が「the transfer app did not take it in 20 s」**: xfer_probe の `api` (アプリが FmrbTransfer で転送のアプリに頼む道) がブラウザ版で、カーネルの `spx: Failed to unpack msgpack data: integer overflow in <<` で毎回落ちていた。T8 とは関係のない既存の不具合 (ブラウザ版の `board_millis` が 32 ビットを超える値で、カーネル (Spinel) の msgpack の読みが溢れていると見ている。読み切っていない)。`regress:transfer:quick WEB=1` は PC からブラウザへ送る場面だけなので通っていた。2 回目は xfer_probe が自分で送る形 (種類 file、呼び手は同じ `wasm-alice`) にして通した。残件 1。
- 「door がページに知らせる」は WebSocket の Text 1 通にした。応答の頭や subprotocol はページの JavaScript から読めない・zenohd の `ws/` が subprotocol を返さない。古いページが Text を batch と取り違えるので、ページが頼んだときだけ送る形にした。
- ブラウザの呼び出しは「ロールの ask の呼び出しの行を自分の名前に直したもの」だけにした。席のように `asterism/*/*/*/call/<自分>` を丸ごと許すと、ロールが許していないアプリ (たとえば端末の別のアプリ) まで自分の名前で呼べてしまい、「ロールの中身は今どおり」から外れるため。

## 9. 残件

1. ブラウザ版のアプリから FmrbTransfer で送る道 (Shell の `asend`・xfer_probe の `api`) が、カーネルの msgpack の読みの溢れで動かない (8 章)。T8 の前からのもの。直すかは親が決める。 → 直した (`t8b.md`: 原因はブラウザ版の時計が Unix 時刻だったこと)。
2. T4b の印 (console の Files ページからブラウザへ送る、ブラウザの `asend console`) はブラウザには無い。
3. 同じ利用者の 2 つ目以降のページ・古いリンクは共有の接続のまま (決定どおり)。2 つ目のタブで送りたいときは最初のタブを閉じてから開き直す。
4. 確認済みかの印はページ全体で 1 つ (セッションごとではない)。安全はルータ側の ACL が持つ (6 章)。
5. 証明書の更新 (残り 30 日) は setup か Browsers の画面のボタンで。console が自分で周期的に作り直すことはしない (席と同じ)。
6. Network の欄の騙りの文言は通しの後に直した (ビルドと構文は確認、通しでの再確認はしていない)。

## 10. VPS の更新に要ること

- `./update.sh <版>` (版を付けるのは親)。migration 1 つ (`users` に列 4 つ、空)。compose の door に `WS_DOOR_BROWSERS_DIR` (既定と同じ値)。`.env`・ロールは変えない。

- ブラウザ版の配置 (このブラウザ版を公開する) は別。古いブラウザ版のページも証明書でつながるが、知らせを頼まないので Network の欄に出ず、一覧も受け入れない (今どおり)。
