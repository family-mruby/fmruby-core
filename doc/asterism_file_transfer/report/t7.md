### 1.1 置き場所と読む順

- 配布物 `flash/etc/asterism/receive.toml`: `enabled = false`、`[file] from = []`、`[checkpoint] from = []`、短い注釈 (何のファイルか、`/home` の写しが作られて以後そちらを読むこと、`*` の意味)。flash/etc の git 追跡分なので、ESP32 の storage・ネイティブ版の最初の /etc (`native:etc`)・ブラウザ版の束のどれにも入る。
- 読む順は `/home/asterism/receive.toml` があればそれ、無ければ `/etc/asterism/receive.toml` (WiFi の設定と同じ形)。`/home` のファイルがあれば `/etc` は見ない (`/home` に `enabled` が無ければ、`/etc` に何が書いてあっても無効)。
- 読む所は `FmrbReceiveConf` (`/usr/share/transfer/receive_conf.rb`) の 1 か所: 転送のアプリ、Shell の `areceive` と `asend -l`、アプリ「受け取り」がこれを使う。**カーネルだけは別に読む** (Spinel のプログラムで、この Ruby のファイルを読み込めない)。カーネルの `receiving_enabled?` は 1 行の規則 (最初の表より前の、鍵 `enabled`、`#` より前の値が `true`) だけを持ち、host の試験でカーネルのメソッドを本物のまま取り出して `FmrbReceiveConf.enabled?` と同じ答えを返すことを確かめる (10 のファイル: 無い・`/etc` だけ・行の無い `/home`・コメント付き・`"true"` (文字列)・表の中の `enabled`・console の分だけ・`/home` の off と `/etc` の on など)。
- 違いが出る所: 手書きの部分が TOML として壊れている (ほかの行が壊れている) とき、`FmrbReceiveConf` は無効と読み、カーネルは `enabled = true` の行を見て有効と読む。そのときカーネルは転送のアプリを起こすが、転送のアプリは全部の `begin` を断る (`does not receive`)。害は ESP32 の TLS の接続が 1 つ増えることだけなので、Spinel に TOML の読み手を足すことはしていない。

### 1.2 起動の条件 (カーネル)

`spawn_transfer_if_receiving` は「`receiving_enabled?` のとき」に変えた (ファイルの有無ではなく)。起動のたびに 1 行 `Transfer: receiving is on|off (<読んだファイル>)` を出す。

### 1.3 転送のアプリ: 断る・終わる

- `refused` (`begin` と `check` が呼ぶ) は最初に `enabled` を見る。無効なら `<node> does not receive (receiving is off there: areceive on)` で断る (送り手の Shell に出る 110 バイトほどに収まる)。`chunk` と `commit` は見ない。呼び出しのたびにファイルを読むのは T6 と同じ (`senders` の 1 回の読みに `enabled` も入れた)。
- 動いている転送のアプリは、`transfer/ctl` の `{"cmd" => "receive_conf"}` (保存の口が送る) と、10 秒ごとの読み直し (手で書き換えたとき) で `enabled` を見直す。有効 → 無効に変わったら `transfer: receiving is off; new files are refused, and the app ends when what is coming in is in` と出し、手が空いたら `stop` する。手が空いた = 自分の頼み (カーネルの移動・アプリの送信) が無く、最後の頼みの終わりから 3 秒、受け口への呼び出しが 3 秒無く、受けている途中のファイルが無い (片が `STALE_MS` 10 秒来ないものは止まったと見る)。
- **途中の受け取りは受け終えるまで待つ** (決めたこと)。指示の「新しい `begin` を断って終わる」の読みどおり、断るのは新しい `begin` だけで、受け始めたものは `chunk`・`commit` が通るので最後まで受けて置かれる。止まった (片が来ない) ものは待たずに終わり、片のファイルとメモは転送のアプリがほかの終わり方をしたときと同じく残る (60 秒で消える、次に有効で起動したときは続きから)。ただし続きの `begin` は無効の間は断られる。捨てる方 (すぐ `kill`) にしなかったのは、送り手から見て「送っている途中で理由なく切れる」になり、利用者が持ち主のスイッチを切った意図 (これから受けない) より強いため。
- 無効のまま起動した転送のアプリ (送るため・アプリを移すため) は今までどおり残る。終わるのは有効 → 無効の変化を見たときだけ (起動直後に終わると、`asend` や移動が使えなくなる)。
- 移動の途中で無効にすると: カーネルの頼みは `move_check` → `move_send` と順に来るので、その間に 3 秒の間が空けば転送のアプリが終わり、移動は「the transfer app ended」で失敗する。最後の頼みの終わりから 3 秒は待つので普段は起きない。

### 1.4 保存の口 (`FmrbReceiveConf`、画面と Shell で共通)

- `set_enabled(on)`、`allow(kind, node)`、`deny(kind, node)`: どれも書いたかどうか (true / false) を返し、理由のあるときは `ArgumentError`。
- 手書きの部分だけを**行で**変える: 鍵の行 (と、数行にわたる配列の続きの行) を 1 行に置き換えるか、無ければ足す (表の最後の鍵の後、表が無ければ末尾に表ごと、`enabled` が無ければ最初のコメントの塊の後・最初の表の前)。コメント・順序・知らない鍵はそのまま。`[managed]` の部分と印の行は文字のまま後ろに付け直す (触らない)。
- 変えた手書きの部分を TOML として読み直し、頼んだ値 (`enabled`、種類の一覧) になっていなければ書かない。手書きの部分がもともと TOML でなければ変えずに断る (人の書いたものを壊さない)。
- 書くのは中身が変わったときだけ: 同じ値なら書かない (`set_enabled(true)` が 2 回目は false)。`/home` に無いとき (初めて) は `/etc` の写しを手書きの部分として `/home/asterism/` に作る (ディレクトリも作る)。書き方は T6 と同じく `.receive.toml.new` に書いて置き換える。
- `deny` は手書きの一覧 (checkpoint は古い書き方の上の `from` からも) から外す。console の一覧にだけある相手は `... is in the list from console (file); it is changed there` で断る。
- 相手の名前の決まりは T6 と同じ (英数字と `.` `_` `-` `*`、64 バイトまで、1 つの種類に 64 まで)。
- `tell_transfer(app, on)`: 有効で転送のアプリが動いていなければ、カーネルに `spawn` を頼む (FmrbTransfer と同じ既存の口。カーネルは繋がったときに自分の転送のアプリとして引き取る)。動いていれば `transfer/ctl` に `receive_conf` を流す (無効なら上の 1.3 で終わる)。**止める口はカーネルの `kill` を使わず、この知らせにした** (`kill` は途中の受け取りを捨てるため)。新しい口は足していない (既存の Pub/Sub の topic に命令を 1 つ足しただけ)。
- T6 の `write_managed` も読む順に揃えた (`/home` に無ければ `/etc` の写しを手書きの部分にして作る)。console の一覧で `enabled` は変わらない (host の試験で確認)。

### 1.5 アプリ「受け取り」(`flash/app/tool/receiving.app.rb`)

- 名前: `receiving.app.rb` / `.app.toml` (既存の `gpio_viewer`・`nsf_player` に合わせた小文字の 1 語)。表示名 `Receiving` / `受け取り`、`launcher_visible = true`、`single_instance = true`、Window 300x204。
- 画面 (上から): スイッチ (「受け取り: 有効 / 無効」)、読んでいるファイル、種類の切り替え (「ファイル」「アプリ (checkpoint)」)、許す相手の一覧 (手書きの行は右に削除の「x」、console の分は `[console から]` を付けて灰色・読むだけ)、名前を打つ欄と「追加」「見える端末」、下に 2 行 (状態と最後の結果)。
- 「見える端末」: 押したときに初めて、このアプリ自身が Asterism につなぐ (`FmrbAsterism::Link`、アプリ名 `receiving`)。`Asterism.nodes` から自分と手書きで許した相手を除いて並べ、1 秒ごとに更新。押すとその相手を足す。一覧の最初は「誰でも (*)」。
- 「誰でも」(追加の決定 1・2): `*` は一覧で「誰でも (*)」と出す。足すとき (打っても、見える端末から選んでも) は確認を挟む: ファイルは「同じネットワークのだれからでも受け取ります。よいですか?」/ "Take files from anyone on the same network?"、checkpoint は赤で「だれでもこの端末でアプリを動かせるようになります。よいですか?」/ "Anyone could then run apps on this machine. Allow anyone?"。checkpoint に `*` があるとき (手書きでも console からでも) は、その行の頭に `!` を付けて赤で出し、下の状態の行に「! だれでもこの端末でアプリを動かせる設定です。」/ "! Anyone on the network can run apps here."。
- 無効のときは状態の行に「無効: 一覧にかかわらず何も受け取らない。」。
- receive.toml は 3 秒ごとに読み直す (console が一覧を書いたとき)。日本語と英語は `FmrbI18n` (language に従う)。
- 文字は 8 px の混在のフォント (`draw_text_mixed`、FmrbUI の部品と同じ) にした。skill の「`mixed: true` を使わない」は 12 px を選んだのに 8 px に落ちる話で、ここでは部品と同じ 8 px を意図して選んでいる (Retro の 320x240 に一覧が 9 行入る)。

### 1.6 Shell の `areceive` (`shell_commands.rb`、`asend` の隣)

```
> areceive
areceive: receiving: on (/home/asterism/receive.toml)
areceive: file:
areceive:   pc-desk  by hand
areceive:   *  by hand (anyone)
areceive:   fmruby-t7b  from console
areceive: ! checkpoint:
areceive: ! *  by hand (anyone)
areceive:   fmruby-t7c  from console
areceive: ! anyone on the network may run apps on this machine
areceive: managed by console, changed there at 2026-11-10T00:00:00Z
```

- `areceive on|off`: `receiving is on (written to /home/asterism/receive.toml)` か `(it was already)`、転送のアプリを起こした・終わる、を 1 行ずつ。
- `areceive allow|deny <file|checkpoint> <ノード>`: `'*'` と `"*"` は引用符を外す (Shell は引用符を解かない)。`*` は確認なしで通し (追加の決定 3)、出力に 1 行: checkpoint は `areceive: ! anyone on the network can now run apps on this machine`、file は `areceive: note: files are taken from anyone on the same network`。無効のときは最後に `receiving is off; areceive on to take anything`。
- `asend -l` も同じ行 (`FmrbReceiveConf.lines`) を出す (頭が `asend:`)。最初の行に有効・無効と読んだファイルが入った。
- help に 3 行。

## 4. 撤回した仮説

- 「保存の口が転送のアプリをカーネルの `kill` で止めればよい」: 途中の受け取りを捨てるので、知らせ (`receive_conf`) と手が空くのを待つ形にした。
- 「転送のアプリは無効なら起動直後に終わってよい」: 送るため・移すために起こされた転送のアプリまで終わり、`asend` と移動が使えなくなる。有効 → 無効の変化のときだけ終わる。

## 5. console (asterism-console、`f2c0040`)

- 無効の端末は転送のアプリが動いていないので、bridge は一覧を配れない。行のページの「The list on its machines」の「not sent yet」を `not sent yet: its transfer app is not on the network (receiving may be off on that machine; it is sent when the app appears)` にした。
