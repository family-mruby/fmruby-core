# T0・T1 指示書: 調べる・測る と、受け口の再送

> 状態: 実装中 | 更新: 2026-11-08 | 正は plan.md (方針・決まったこと・決定事項)。ここには範囲と進め方だけを書く

## 範囲

### T0 (調べる・測る)

plan.md の T0 の項目のうち、**実機なしでできるもの**を測る:
Zenoh の 1 回の呼び出しで運べる大きさの上限 (ネイティブ版・sim・ブラウザ版)、
片の大きさと速さの関係、同時に複数の片を投げたときの速さ、転送のアプリのメモリ、
抜け・重なり・順の入れ替え・切断を起こす試験の道具の作り方 (T1 の試験で使う)。
ESP32 での値 (呼び出しの上限・速さ・SHA-256 と CRC32 の費用) は**実機がつながったとき**に
測るので、測り方 (台本・コマンド) だけ用意して report に残す。

### T1 (受け口の再送)

plan.md の方針 2・3 と T1 の行のとおり:
- 何度届いても同じ結果になる片 (前なら重なりとして読み捨て、先なら抜け、どちらも
  受け手の今の位置を返す)。
- 送り手は期限切れ・失敗のとき受け手に位置を聞いて続きから。回数と待ちの延び方に上限。
- 接続の切れ目からの再開: `.part` と控え (送り手・大きさ・SHA-256) を `/tmp` に残し、
  同じ送り手から同じファイルの `begin` が期限内に来たら続きから受ける。受け手の端末が
  再起動したら最初から。
- 全体の照合: `begin` で送り手が SHA-256 を宣言、`commit` で受け手が照合、合わなければ
  置かずに理由を返す。期限を過ぎた `.part` は消える。
- 決定事項のうち T1 に効くもの: 同時に受けるのは 1 つの相手だけ (ほかは「使用中」)、
  受け手が空きを見て入らなければ `begin` で断る。
- 仕組みは asterism gem の共通の部品に置く (plan.md の「決まったこと」)。gem の置き場と
  Family mruby の pin の更新の仕方は今の形に合わせる。gem を公開リポジトリへ push する
  必要が出たら、そこで止まって返す (push はユーザの指示語のみ)。
- checkpoint の移動 (`regress:checkpoint` のネイティブ版・sim・ブラウザ版) が今のまま通ること。

種類 `file`・`receive.toml` の拡張・送り手の口・大きなファイルは T2・T3 (今回はしない)。

## 確認

- `rake regress`、`rake regress:checkpoint` (実機の `BOARD=` は除く)。ESP32 の内蔵 RAM に
  効く変更があれば `rake regress:size`。
- T1 の受け入れ条件 (plan.md) を**ネイティブ版どうし**で: 試験の道具で「片を 1 割落とす」
  「同じ片を 2 回送る」「順を入れ替える」「途中で接続を 2 回切る」「受け手の転送のアプリを
  途中で止めて起動し直す」を起こし、全部最後まで届いて SHA-256 が一致し、送り直しが
  止まった位置からであることをログの位置で示す。照合が合わないものは置かれず理由が返る。
  試験は回帰の道具から流せる形にする (`rake` のタスク。`regress:full` に入れるかは report で提案)。
- ネイティブ版 ⇔ ESP32 は実機がつながったときにユーザと行う。手順を report に書く。

## 触ってよい範囲

fmruby-core (転送のアプリ `flash/usr/share/transfer/`、checkpoint の送り手、関係する
試験・道具・rakelib、`doc/asterism_file_transfer/`)、asterism gem の作業用 checkout
(コミットまで)。それ以外が要るなら止まって返す。作業は本体 checkout で、終わったら
build/ を残さない。push はしない (コミットまで)。

## 止まる条件

- plan.md の方針・決定事項と違う動きが要る。利用者から見た動き (仕様) が変わる直し方を
  選ぶ必要が出た。
- 実機・sudo・公開リポジトリへの push が要る所まで来た。
- 測った値が方針を揺るがす (例: SHA-256 がネイティブ版で異常に重い、呼び出しの上限が片より小さい)。
