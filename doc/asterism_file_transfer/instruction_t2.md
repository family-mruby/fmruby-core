# T2 指示書: 種類 file・種類ごとの許可・送り手の口 (と T1 の後の決定)

> 状態: 実装中 | 更新: 2026-11-08 | 正は plan.md (方針・決まったこと・決定事項の 3 つの節)。ここには範囲と進め方だけを書く

## 範囲

1. **空きを知る口** (決定事項、T1 の後): 置き場所の空きをアプリから知るメソッドを足す
   (C に `fmrb_tmpfs_usage` がある。storage の空きも同じ口で)。`begin` で受け手が
   置き場所の空きを見て、入らなければ理由つきで断る。ESP32・ネイティブ版・sim・
   ブラウザ版のどれでも答えが出ること (出せない所は「分からない」を返し、今の
   「書けなくなった所で断る」に落ちる)。内蔵 RAM は増やさない。
2. **種類 `file`**: 受け手は `/home/inbox/` の下にだけ置く (無ければ作る。名前に `/`・`..`
   を許さない)。同じ名前があるときは**送り手が送るときに選ぶ**: 「上書き」か
   「名前を変える」(`foo(1).txt`、元は残す)。指定がなければ名前を変える。置いた名前を
   送り手に返す。上書きのときも、照合が合うまで元のファイルは消さない (`.part` から
   置き換える)。
3. **種類ごとの許可**: `/home/asterism/receive.toml` を種類ごとに書ける形に広げる
   (書いていない種類は受けない)。今の `from = [...]` の書き方は checkpoint の許可として
   読み続ける (今ある設定を壊さない。読み方を report に書く)。許していない種類・相手は
   `begin` で理由つきで断る。
4. **進み具合と取りやめ**: 送り手の口から進み具合 (送った量 / 全体) が見え、取りやめられる。
   取りやめたら受け手の `.part` と控えは消える。
5. **送り手の口**:
   - アプリの API (Ruby、端末のアプリから送る。進み具合と取りやめを含む)
   - Shell のコマンド (例: `send <ノード> <ファイル> [--overwrite]`。名前は既存のコマンドに
     合わせて決め、report に書く)
   - PC の道具 (`tools/` の Ruby。ネイティブ版・sim へ PC のファイルを送る)
6. **`regress:full` 用の 1 分ほどの要点の試験** (決定事項): 今の `regress:transfer` は残し、
   再送・続きから・照合・種類 `file` の置き場所と同じ名前の扱いを 1 分ほどで確かめる版を作り、
   `regress:full` に入れる。
7. **ブラウザ版の SHA-256 を C の実装に** (決定事項): ブラウザ版の受け手・送り手の SHA-256 を
   C で計算する (ほかの端末と同じ mbedTLS か、それが無理なら小さい C の実装)。1 MiB の
   計算の時間を前後で report に。

## 確認

- `rake regress`、`rake regress:transfer`、新しい要点の試験、`rake regress:checkpoint`
  (実機の `BOARD=` は除く)。main/ の C を変えたら `rake regress:size` (内蔵 RAM の増分 0)。
- plan.md の T2 の受け入れ条件 (許していない種類・相手は受ける前に断る、`file` は
  `/home/inbox/` にだけ現れる) と、同じ名前の 2 通り (上書き・名前を変える)、空きが
  足りないときに `begin` で断ることを、ネイティブ版どうしとブラウザ版で示す。
- Shell のコマンドを sim かネイティブ版で 1 回動かす (画面かログ)。

## 触ってよい範囲

fmruby-core (転送のアプリ・試験のアプリ・Shell のコマンド・アプリの API の Ruby 側、
空きを知る口のための main/ と native/・wasm/ の C、関係する試験・道具・rakelib、
`doc/asterism_file_transfer/`)、asterism gem の作業用 checkout (コミットまで)。
それ以外が要るなら止まって返す。作業は本体 checkout で、終わったら build/ を残さない。
push はしない (コミットまで。gem → fmruby-core の順で push するのはユーザの指示の後で親が行う)。
