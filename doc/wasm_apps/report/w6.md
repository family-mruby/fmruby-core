## 0. まとめ

- **線の上の形**: アプリ 1 本を tar (ustar) 1 つにまとめ、今の受け口 (`<ノード>/transfer/inbox`) に新しい種類
  `app` で送る。再送・続きから・全体の SHA-256・受け手が決める片の大きさは T1〜T3 のまま効く。ファイルの転送
  (種類 `file`) と checkpoint の移動 (種類 `checkpoint`) の動きは変えていない。
- **受け手**: tar を `/app/usr/.<名前>.new/` に開いて中を見る (プログラムが 1 つあるか、`.app.toml` が TOML か、
  wasm のアプリなら本体に無い関数を import していないか)。設定が「毎回確認する」(既定) なら所有者に Window で
  聞き、「入れる」で `/app/usr/<名前>/` に置く。設定が「自動」でも、聞かずに置くのは送り手が証明書つきの接続
  (`tls/`、T8 のブラウザの名乗り) で確かめられたときだけで、ほかは確認する。画面 (デスクトップ) の無い端末で
  確認が要るときは、すぐ理由つきで断る (7 章、ユーザの決定)。置いたらランチャーが `/app` を
  読み直す (開いていれば今、閉じていれば次に開いたとき)。
- **設定**: `receive.toml` の `[app]` に `from` (送ってよい相手) と `install = "ask" | "auto"`。T7 の受け取りの
  有効・無効がすべての前に効く。アプリ「受け取り」に「インストール」の一覧と「確認/自動」の切り替え、Shell に
  `areceive allow|deny app <ノード>`・`areceive install ask|auto`。
- **wasm の照合**: 起動のときに本体がする import の照合 (W5c) を、WAMR を起こさずにファイルから行う C の関数
  `fmrb_wasm_check_file` を足し、インストールの時点で同じ言葉 (関数の名前と SDK の版) で断る。
- **送り手**: PC は `tools/fmrb_send.rb <ノード> <フォルダ> --app [--overwrite]`、端末どうしは Shell の
  `asend -a <ノード> <アプリ> [-o]` とアプリの API `FmrbTransfer#send_app`。
- **確かめたこと**: 新しい場面 `rake regress:transfer:install` (ネイティブ版 2 つと PC、7 場面: 証明書の無い自動は
  確認になる・同じ名前・合わない wasm・一覧に無い相手・確認で「入れる」・確認で Esc・画面の無い端末で断る) が通った。`rake regress`・`regress:spinel`・
  `regress:transfer:quick`・`regress:checkpoint` も通った (5 章)。ESP32 の実機・sim・ブラウザ版のインストールは
  確かめていない。

## 1. 設計

### 1.1 線の上の「アプリの包み」

**1 つの tar (ustar) にする。** 中身はアプリのフォルダの中身で、`/app/usr/<名前>/` に置くときの名前のまま並ぶ。

| 入るもの | 決まり |
|---|---|
| `<名前>.app.<拡張子>` | プログラム。`rb` (Ruby)・`lua`・`py`・`bas`・`wasm` のどれか、ちょうど 1 つ |
| `<名前>.app.toml` | 属性。Ruby 以外は必須 (Ruby は `#---fmrb` の注釈で足りる) |
| ほか | アイコン (`.png`)・絵・音・データ。下のフォルダも可 |

- `<名前>` は英数字・`_`・`-` で 40 バイトまで (転送の `plain_name?` と同じ)。ランチャーは `.` を含むフォルダを
  見ないので、この名前ならフォルダとして必ず見える。
- 中の名前は、`/` 始まり・`..`・`.` 始まり (隠しファイル) を断る。1 つの部分は 48 バイトまで、パスは 96 バイトまで、
  ファイルは 64 個まで。リンクやデバイスは断る。他の道具が付ける pax の見出しは読み飛ばす。
- フォルダごと tar にしたもの (全部が `<名前>/` の下) も受ける (一段持ち上げる)。

**tar にした理由** (フォルダを 1 ファイルずつ送る形と比べた):

- 送る単位が 1 つになり、再送・続きから・全体の照合 (T1) がそのまま効く。届いたものは全部か何も無いかで、
  途中までのアプリが置かれることが無い。
- 標準の道具 (`tar`、CRuby の `Gem::Package::TarWriter`) で作れ、SDK の利用者が自分で包める。
- 端末の Ruby (picoruby) で先頭から順に読むだけで開ける (IO#seek が無くてよい)。見出しは 512 バイトで、
  検査和も見る。

### 1.2 インストールと普通のファイルの見分け

**種類 (`kind`) で分ける。** インストールは `app`、普通のファイルは今の `file` のまま。受けてよい相手も種類ごと
(`[app] from`) なので、「ファイルは受けるがアプリは入れさせない」が書ける。`begin` の `meta` は
`{"name" => <名前>, "size", "sha256", "app" => <名前>, "files" => 数, "overwrite" => true}` (`name` は転送の決まりの
ファイル名で、アプリの名前と同じ)。

### 1.3 置き場所と同じ名前

- 片は `/app/usr/.<名前>.app.part` に書く (`/app/usr` と同じファイルシステムに置き、開くときの写しを短くする)。
- 開くのは `/app/usr/.<名前>.new/`。中を見て、置くときはこのフォルダを `/app/usr/<名前>/` へ名前の付け替えで
  移す (付け替えのできないファイルシステムならファイルごとに移す)。途中で端末が止まって残った `.new` は、
  転送のアプリの起動時に消す。
- **同じ名前のアプリが入っているときは、送り手が上書きを頼んだときだけ置き換える。** 頼んでいなければ、
  `begin` で 1 バイトも送る前に理由つきで断る (`... is installed on <ノード> already (send with overwrite to
  replace it)`)。確認の Window には「同じ名前の入っているアプリを置き換える。」と出す。
  - 種類 `file` の既定 (名前を変えて両方残す、`foo(1).txt`) をアプリに使わない理由: ランチャーに同じ名前の
    アプリが 2 つ並び、アプリの名前 (`app_handle_name` やデータの置き場) もずれるため。
- 空きの検査: `begin` で `/app/usr` の空きの半分 (包みと開いたものが同時にあるため) より大きければ断る。
- 置いた後、ランチャーの索引の写し (`/var/cache/launcher_index`) を消す (店と同じ)。

### 1.4 受け手の確認の Window

新しいアプリ `/usr/share/transfer/install_ask.app.rb` (Window、270x134、ランチャーに出さない)。転送のアプリが
カーネルの `spawn` の `open_path` で札 (`/tmp/.install_ask`、1 行に `キー<TAB>値`) を渡して起こす。

- 出すもの: 送り手 (ノード ID)、アプリ (画面の名前と `/app/usr` の名前)、言語 (Ruby・Lua・Python・BASIC、wasm は
  `.app.toml` の `language` か言語のアイコンから `wasm (TinyGo)` など)、大きさとファイルの数、wasm の SDK の版、
  置き換えるかどうか、答えの残り時間。
- 「入れる」・「断る」。Esc と Window を閉じるのは「断る」。60 秒 (`ASK_MS`) 答えが無ければ断る (転送のアプリが
  Window を止める)。
- 答えは Pub/Sub (`transfer/ctl` に `{"cmd" => "install_answer", "id", "yes"}`) で返し、転送のアプリは自分が起こした
  Window の PID (カーネルの `spawn_result`) からの答えだけを受ける。
- 画面は scratchpad の `w6/ask_yes.png` (TinyGo の hello、端末 A から)・`w6/ask_no.png` (Lua、PC から)・
  `w6/ask_from_shell.png`。

### 1.5 設定 (決定 25)

`receive.toml` (T7 の置き場所: `/home/asterism/receive.toml`、無ければ `/etc/asterism/receive.toml`) に:

```toml
enabled = true          # T7: 受け取り全体のスイッチ (これが無効なら何も受けない)

[app]
from = ["pc-desk"]      # アプリを入れてよい相手 (ノード ID・パターン、"*" はネットワークの全員)
install = "ask"         # "ask": 毎回確認する (既定。行が無い・ほかの値も ask)、"auto": 確認せずに入れる
```

- 配布の `/etc/asterism/receive.toml` に `[app] from = []`・`install = "ask"` を足した。
- 変え方は T7 と同じ (手書きの部分を行ごとに直し、console の部分と印はそのまま): `FmrbReceiveConf.allow/deny`
  が `app` を受け、`set_install_mode("ask"|"auto")` と `install_mode` を足した。
- アプリ「受け取り」: 種類の切り替えに「インストール」を足し、その一覧のときだけ下の行の右に「確認/自動」の
  切り替えを出す。注記の行に「インストール: 毎回確認する。/ 確認せずに入れる。」(画面は `w6/receiving_*.png`)。
- Shell: `areceive allow|deny app <ノード>`、`areceive install ask|auto` (auto にすると注意を 1 行)、`areceive` と
  `asend -l` の表示に app の一覧と入れ方。
- **console の一覧 (T6 の `[managed]`) には app を入れていない。** console が配る種類は今の `file`・`checkpoint` の
  まま (`FmrbReceiveConf::KINDS`)。手書きの種類だけ `HAND_KINDS` で app を足した。console の Members の行で app を
  選べるようにするかは 6 章。

### 1.6 合わない wasm のアプリをインストールの前に断る

- W5c の照合 (読み込みの後に WAMR の import の結び付きを見る) は WAMR を起こす (共有のプール 256 KB を取る) ので、
  受け手の転送のアプリからは使わない。代わりに `components/fmrb_wamr/fmrb_wasm.c` に
  `fmrb_wasm_check_file(path, ...)` を足した: ファイルを小さな窓で読み、型と import の section だけを
  呼び手の領域 (転送のアプリの VM のプール) に読み、関数の import を境界の関数表 (`k_natives`) と WAMR と同じ規則
  (名前、先頭の `_` を外した名前、`(ii)i` の形と `*`・`~`・`$`) で突き合わせる。custom section `fmrb.sdk` の版も読む。
- 断るときの言葉は起動時と同じ関数 (`refuse_imports` に切り出した) で作る:
  `w6bad.app.wasm: imports fmrb.gfx_draw_hologram, which this firmware does not have: the app was built with
  SDK 9.1.0, newer than this firmware; update the firmware`。
- Ruby からは `FmrbApp._wasm_check(path) -> [ok, sdk_version, reason]`。checkpoint の受け手のメソッド
  (`_checkpoint_has_method` など、`main/app/fmrb_app_checkpoint.c`) と同じ所で、checkpoint 用に用意する VM
  (転送のアプリは `movable = true`) にだけ定義する。ほかのアプリの VM は増えない。
- 照合が通ったアプリは、起動のときにもう一度本物の照合 (W5c) を通る。

### 1.7 ランチャー

- 転送のアプリが置いた後、カーネルに `apps_installed {name}` を送り、カーネルがデスクトップへ渡す。
- デスクトップのランチャーは、開いていれば今読み直し (Reload と同じ)、閉じていれば印を付けて次に開いたときに
  読み直す (読み直しは題の帯に描くので、閉じているときは走らせない)。ログに `Launcher: <名前> was installed; ...`。
- 画面は `w6/launcher_after_install.png` (届いた W6 Ruby がアイコンつきで並ぶ)。

### 1.8 今の動きを変えた所・変えなかった所

- 変えなかった: 種類 `file`・`checkpoint` の受け方と許可、console の `policy_set` と `[managed]` の中身、
  checkpoint の片の窓 (4)、T7 のスイッチの読み方。転送の gem (asterism) と console には触っていない。
- 変えた: 配布の `receive.toml` に `[app]` 節 (受け取りは今までどおり無効、`from = []`)。`areceive` の表示に app の
  行が増えた。転送のアプリが起動時に `/app/usr/.*.new` を掃除する。

## 6. ユーザに決めてほしいこと

1. (後で、と決定) **console の Members の行でアプリのインストールの相手を選べるようにするか。** 今は手書き (`[app] from`) だけで、
   console が配る一覧 (`policy_set`、`[managed]`) は `file`・`checkpoint` のまま。足すなら console (asterism-console)
   の変更と、`FmrbReceiveConf::KINDS` に `app` を足すこと (console が送らない種類は空の一覧として書かれる) が要る。
2. (7 章で決定・実装済) **「自動」を証明書つきの接続 (`tls/`) のときだけ効かせるか。** 家のルータや P2P では相手のノード ID は名乗り
   だけなので、`[app] from` の名前を名乗った誰でも、確認なしにアプリを置けてしまう。今は接続の種類を見ていない
   (ファイルの受け取りと同じ)。「確認する」なら所有者が Window で送り手を見て断れる。案: tls/ でない接続では
   `auto` でも確認する。
3. (7 章で決定・実装済) **画面の無い端末 (StickS3 などのヘッドレスの S3) で「確認する」のとき。** Window を出せないので 60 秒後に
   「答えが無い」で断る。案: 画面の無い端末では確認の代わりにすぐ理由つきで断る (「この端末では install = auto に」)。
4. (今のまま、と決定) **答えを待つ時間 (60 秒) と、Enter で「入れる」にしないこと。** 誤って入れないよう、キーは Esc (断る) だけに
   した。
5. **店 (App Store) の「入っているもの」との関係。** 店は自分の一覧にあるアプリだけを出すので、Asterism で入れた
   アプリは店の画面に出ない。消す口は今はファイルマネージャだけ。
6. **ブラウザ版の空き**: ブラウザ版は `/app/usr` の空きを知る口が無い (`/home` だけ見積もりがある) ので、
   `begin` での空きの検査が効かず、書けなくなった所で断る形になる。

## 7. ユーザの決定の後で足したこと (2026-11-16)

親を通したユーザの決定 (6 章の 1〜4):

1. **「自動」は証明書つきの相手だけ**: 送り手が証明書つきの接続で確かめられたとき (`TransferApp#certified?`:
   `tls/` のルータ、またはブラウザ版で door が利用者の証明書でつないだページ) だけ確認なしに置く。ほかは設定が
   auto でも確認の Window を出す (ログ `install: ask (auto, but the sender is not checked by a certificate)`)。決め方は
   `FmrbAppPackage.install_how(mode, certified, can_ask)` に切り出し、host の試験で組み合わせを全部見る。
2. **確認の Window は今のまま** (クリックで入れる、Esc・閉じるは断る、60 秒、Enter は割り当てない)。
3. **画面の無い端末**: デスクトップ (`system_desktop`) が動いていない端末 (画面の無い端末、単一のアプリで起動した
   端末) で確認が要るときは、すぐに断り、送り手に `<ノード>: this board has no screen to ask; set it to auto with a
   certificate or allow the sender` を返す。
4. console の Members の行での選択は後で (今回は変えない)。

あわせて、4 章で見つけた `app kill` の穴を直した (family-mruby の develop、tools/ の別コミット):
`tools/fmrb_native.rb app kill` は PID 0・1・2 と、ps の名前が `fmrb_kernel`・`system_desktop` のものを理由つきで
断る。MCP の `sim_app` の kill も PID 0・1・2 を断る (sim の debug サーバも止めてしまうため)。ブラウザ版
(`fmrb_web.rb`・`web_app`) には kill の口が無い。Tab5 の `tab5_app` は以前から本体 (devctl) が断る。debug サーバ
(fmruby-core の `debugd`・`fmrb_dbg_client.py`) 自身は今も止めるので、本体の側で断るのが根本 (今回は道具だけ)。

試験の場面は auto を「証明書の無い auto は確認になり、クリックで入る」に変え、again の上書きも確認を通すようにし、
no_screen (B を `boot_mode = "app"` で起こし直し、PC のアプリがすぐ断られる、1 秒以内) を足した。7/7 (24 秒)。
証明書つきの auto (確認なしに置く) は、回帰の道具に `tls/` のルータが無いので host の試験 (`install_how`) だけ。
