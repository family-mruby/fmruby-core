  `tools/gen_bindings.rb` がそれから言語ごとのつなぎを型紙で生成する。TinyGo は `tinygo/fmrb/raw` (122 関数・

## 1. 生成の道具の置き場と型紙

**決めたこと: 境界の読み取り (RBS → 表) は fmruby-core、言語のつなぎの型紙は SDK。** 間をつなぐのは
`boundary.json` 1 つ。

| 場所 | 役目 |
|---|---|
| fmruby-core `tools/boundary/gen.rb` | `sig/*.rbs` から表を作る (今まで通り)。新たに `sdk/boundary.json` を書く (コミットする生成物、`--check` で照合)。`--sdk DIR` (`rake boundary:sdk SDK=DIR`) で SDK の checkout に `boundary/boundary.json` と `c/fmrb_boundary.h` (英語だけ) を書く |
| fmruby-core `tools/boundary/templates/sdk_c.h.erb` | C のヘッダの型紙 (1 つ)。`ja:` で説明文の日本語の行を出すか決める。本体の `sdk/c/fmrb_boundary.h` は 2 か国語、SDK の写しは英語だけ |
| SDK `tools/lib/boundary.rb` | `boundary.json` を読む・型紙を描く・名前と型の変換 (`Go` モジュール)。`OUTPUTS` に型紙 → 生成物を並べる |
| SDK `tools/templates/tinygo/raw.go.erb`・`types.go.erb` | `tinygo/fmrb/raw/raw.go` (`//go:wasmimport` の宣言 122 個)・`types.go` (版・ABI のハッシュ・結果の定数・イベントの置き場の大きさ・選択肢の定数・記録の型) |
| SDK `tools/templates/c/fmrb_sdk_version.h.erb` | `c/fmrb_sdk_version.h` (版の 3 つの番号・文字列・ABI のハッシュ) |
| SDK `tools/gen_bindings.rb` | 変わったものだけ書く |
| SDK `tools/check_bindings.rb` | (1) 生成物が今の `boundary.json` と `VERSION` から作ったものと同じ (2) `c/fmrb_boundary.h` の関数とフックの wasm の型・ABI のハッシュが `boundary.json` と同じ (3) 渡した `.wasm` の import とフックが境界と合う (`--against vX.Y.Z` か `--against file.json` で古い版の境界と) |

この形にした理由:

- SDK の利用者は fmruby-core 無しで使える (生成物はすべて SDK にコミット)。生成をやり直すのも SDK の中で
  済む (`boundary.json` があれば足りる)。
- 言語を足す人が触るのは SDK だけ。fmruby-core の生成は RBS の規則だけを受け持つ。
- 版の判定も `boundary.json` 同士の比較で SDK の中で閉じる。
- C のヘッダだけ fmruby-core の型紙にしたのは、本体の側でも基準の資料として使っている (c_check、決定 12) ため。
  型紙を 2 つにしない。英語だけの版は同じ型紙を `ja: false` で描く (日本語の行を消して写すのではない)。

`boundary.json` (117 KB、ASCII。`JSON.pretty_generate(ascii_only: true)`) の中身: `abi_hash`、`import_module`、
結果の定数、`event_buffer` (export の名前と大きさ)、`records` (C の名前・クラス・大きさ・フックだけが受けるか・
欄の名前と C の型とオフセットと選択肢)、`functions` (import の名前・C の名前・Ruby の形・英語の説明・受け手・
Ruby の引数 (`args`: 種類・選択肢・記録) と C の引数 (`params`: C の型・wasm の型・役割 value/pointer/length/count/
out/out_size)・結果 (種類・C と wasm の型・選択肢・記録・nil になるか))、`hooks` (export の名前・引数・結果)。
ABI のハッシュは変わらない (`0x922a7dad`)。

### 1.1 TinyGo の生成物の形

| 境界 | Go |
|---|---|
| 関数 `gfx_fill_rect` | `raw.GfxFillRect(gfx int32, x int32, ...) int32` (exported。`id`・`wx`・`wy` は `ID`・`WX`・`WY`) |
| ポインタ | `unsafe.Pointer`。int32 以外は uint32_t → `uint32`、64 ビット → `int64`/`uint64`、小数 → `float64`/`float32` |
| 選択肢 | `raw.GfxSetFontRawFamilyJa int32 = 1`、イベントは `raw.AppEventTypeKeyDown` … |
| 記録 (並びが Go の struct と同じもの) | struct (`raw.AppEventRecord`・`AppSysPoolInfoRecord`・`GfxImageInfoRecord`・`AudioNsfStatusRecord`・`AppGfxStatsRecord`) |
| 記録 (packed で並びが違うもの) | `[N]byte` と欄ごとの getter・setter (`AppWallclockRecord`・`GfxCompositeRegionRecord`・`GfxFileInfoRecord`) |

記録の型の名前に `Record` を付けたのは、記録を埋める関数 (`raw.AppWallclock`) と名前がぶつかるため。

手書きの `tinygo/fmrb/fmrb.go` は `raw` を呼ぶ形に置き換えた (48 か所、機械的)。`fmrb.Event` は
`raw.AppEventRecord` の別名、`fmrb.KeyDown` などは `raw` の定数の別名、置き場は `[raw.EventBufferSize / 8]uint64`。
tour のために包みを足した (`SetFont`・`DrawTextMixed`・`DrawEllipse`/`FillEllipse`・`DrawTriangle`・`SyncFile`・
`CreateImage`/`DrawImage`/`DeleteImage`・`Wallclock`・`MemoryFree`・`App.ScriptPath`)。

大きさ: bounce 9,285 → 9,340 B、hello 7,507 → 7,538 B。コードの節は同じで、増えたのは wasm の `name` の節
(関数の名前にパッケージの path `fmrb/raw` が入った分) だけ (節ごとの大きさを比べた)。背景の色の変更で数バイト動いた。

## 2. 版の照合 (決定 13・14)

### 2.1 本体

`components/fmrb_wamr/fmrb_wasm.c` の `check_imports` を、`wasm_runtime_load` の直後 (インスタンスを作る前) に
呼ぶ。

- `wasm_runtime_get_import_count`・`wasm_runtime_get_import_type` で import を順に見て、関数の import で
  `linked` でないものを数える。WAMR は名前と型の文字列 (raw の登録の signature) が合ったときだけ import を
  つなぎ、つながらないものは呼んだときにトラップする (既定の設定では読み込みもインスタンスも通る)。
  だから「無い関数」と「形が違う関数」の両方がここで分かる。関数以外の import は WAMR に任せる。
- 理由 (256 バイトの err に収まる。最初の 1 つと残りの数):
  - `imports fmrb.gfx_draw_hologram, which this firmware does not have: the app was built with SDK 9.1.0, newer than this firmware; update the firmware`
  - `imports fmrb.gfx_fill_rect, in another shape than this firmware's: the app was built with a newer SDK; update the firmware` (`sdk_version` が無いとき)
  - `imports wasi_snapshot_preview1.fd_write, but the firmware gives only "fmrb" functions: build the app without WASI or libc's I/O`
  - 2 つ以上あると ` (and N more)`
- 「無い」か「形が違う」かは、生成の表 (`k_natives`) に名前があるかで分ける。
- `sdk_version` は**断るときだけ**、`.app.wasm` の隣の `.app.toml` を読んで探す (アプリのプールから一時的に確保。
  起動の道は何も増えない。`ctx` に欄を足していないので内蔵 RAM も増えない)。
- 本体は版の番号を比べない (決めたこと)。import の照合で必要十分で、番号の比較は「同じ番号なのに中身が違う」
  開発中の版で誤る。本体が自分の版の番号を持つ必要も無くなった (C のヘッダの `FMRB_ABI_VERSION_MAJOR/MINOR` の
  固定値 0・1 は消し、版は SDK の `VERSION` と `c/fmrb_sdk_version.h` に置いた)。

### 2.2 `.app.toml`

- `sdk_version = "0.1.0"` (作った SDK の版)。`tinygo/build.rb`・`c/build.rb` が書く: 出力先に `.app.toml` が
  無ければサンプルのものを写してから、あれば `sdk_version` の行だけを書き換える (ほかの行はそのまま。
  fmruby-core の bounce の日本語の名前などを残すため)。
- 指示の「使う関数の一覧か、その版で足りるか」: **一覧は書かない**。`.wasm` の import の節がその一覧そのもので、
  本体はそれを直接読む。二重に持つと食い違う。「その版で足りるか」は道具で答える
  (`check_bindings.rb --against vX.Y.Z app.wasm`)。

### 2.3 版の付け方 (SDK `tools/version.rb`)

前回のリリース (最新の `vX.Y.Z` のタグの `boundary/boundary.json`。`--base` でタグかファイル、ファイルなら
`--from` でその版) と今の `boundary.json` を比べる:

| 判定 | 中身 |
|---|---|
| MAJOR | 関数が消えた・C の引数や結果の型が変わった (wasm の型が同じでも、int32 が uint8 になれば意味が変わる)、記録の欄の名前・型・並びが変わった・記録が消えた、選択肢の番号が変わった・消えた、フックが消えた・変わった、イベントの置き場の大きさが変わった |
| MINOR | 足しただけ (関数・記録・フック・選択肢の後ろへの追加) |
| PATCH | 境界が同じ。ABI のハッシュが変わったのに差が見つからないときは安全側で MINOR |

`--write` で `VERSION` を書き換えて生成し直す。タグが無い今は「最初のリリースは VERSION のとおり (0.1.0)」と
答える。偽の古い境界 (関数を 1 つ消したもの → minor、引数を変えたもの → major、選択肢を足したもの → minor) で
判定を確かめた。

## 3. 配り方 (SDK の README)

| 言語 | ディレクトリ | 出し方 (予定) |
|---|---|---|
| C | `c/` | ヘッダを写すか git で取る |
| TinyGo | `tinygo/` | Go のモジュール `github.com/family-mruby/family-mruby-sdk/tinygo` (今の go.mod のまま) |
| Rust | `rust/` | crate |
| Zig | `zig/` | パッケージ (`build.zig.zon`) |

- タグ: `vX.Y.Z` と、Go のサブディレクトリのモジュールのために同じコミットに `tinygo/vX.Y.Z`。
- MAJOR が 2 以上になると Go はモジュールの path に `/v2` を要る。module の行と import が変わる (README に書いた)。
- リリースの手順 (書くだけ、タグは打っていない): `rake boundary:sdk` → `gen_bindings.rb` → `version.rb [--write]`
  → サンプルのビルドと `check_bindings.rb` → コミット・タグ 2 つ・push。

## 8. Rust・Zig を足すとき

1. SDK に `rust/` (Cargo の crate) か `zig/` (`build.zig`・`build.zig.zon`) を作る。
2. 型紙を `tools/templates/rust/*.erb` (`zig/*.erb`) に置き、`tools/lib/boundary.rb` の `OUTPUTS` に
   「型紙 → 生成物」を足す。名前と型の変換は `Go` と同じ形のモジュール (`Rust`・`Zig`) を足し、`render_all` の
   `result_with_hash` に渡す。中身は TinyGo と同じ 2 つ: import の宣言 (Rust は `#[link(wasm_import_module = "fmrb")]
   extern "C"`、Zig は `extern "fmrb" fn`) と、定数・記録の型 (`#[repr(C, packed)]` / `extern struct` か `packed struct`。
   並びは `boundary.json` のオフセットのとおり)。
3. 手書きの包み (フックの export と `fmrb_event_buffer`、Window・App・Audio・File) を生成物の上に書く。
   フックの形は `boundary.json` の `hooks`、置き場の大きさは `event_buffer.size`。
4. ビルドのスクリプト (`rust/build.rb`・`zig/build.rb`) を TinyGo・C と同じ形で: 決まりの設定 (Rust はスタックの大きさ、
   決定 1)、`.app.toml` の `sdk_version`。
5. `docs/tour.md` のとおりに `examples/tour` を書き、`check_bindings.rb` で照合し、ネイティブ版・ブラウザ版で TinyGo・C と
   同じ画面になることを見る。`check_bindings.rb` は生成物の照合を `OUTPUTS` から自動で行う。
