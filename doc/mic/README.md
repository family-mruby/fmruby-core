# Family mruby マイク入力 検討メモ

Tab5 (Modern) が積んでいるマイク配列を Ruby から使えるようにするための検討。
実装計画ではなく、どの道を通るか・何を先に潰すかを決めるための文書。

最終更新: 2026-08-09 (配線と初期化手順の確認、周波数の制約の洗い出し)

先に入れた 6 軸センサ ([../imu/report/p1.md](../imu/report/p1.md)) と違い、
**純 Ruby では届かない**。I2S を触る必要があるため C の追加が要る。

## 0. 前提

| 項目 | 内容 |
|---|---|
| 対象ボード | **Tab5 (P4) のみ**。Retro にマイクは無い |
| 目的 | 未使用の内蔵機能を使えるようにする。音量に反応するアプリが Ruby で書けること |
| 優先度 | 「鳴らす」側は既に動いている。こちらは追加であって置き換えではない |

## 1. ハードウェアの実際

| 項目 | 値 | 確認元 |
|---|---|---|
| コーデック | ES7210 (4ch 入力、マイクは 2 本、エコー消去用の参照入力を持つ) | 公式仕様 |
| 制御 | I2C `0x40`、内部バス (GPIO31/32) | M5Unified |
| I2S | MCLK 30 / BCLK 27 / WS 29 / **DIN 28** | M5Unified |
| 初期化 | レジスタ 30 個の並び (リセット / マイクバイアス / ゲイン 0x1B / HPF) | M5Unified に完全な表がある |
| ドライバ | `esp_codec_dev` の es7210 | 既に依存にある |

**決定的なのは、スピーカーと同じ MCLK/BCLK/WS を共有し、データ線だけが
別 (出力 26 / 入力 28) だということ**。クロック線を 2 つの I2S が同時に
駆動することはできないので、いま出力に使っている I2S_NUM_1 を全二重にする
以外の形は取れない。

## 2. 標本化周波数 (2026-08-09 改訂: 縛りは「同時にやる場合」だけ)

### 2.0 M5 公式実装の確認

`M5Tab5-UserDemo` の `hal_audio.cpp` を読んだ結果:

- **I2S は 1 ポートで全二重**。こちらの構造分析と一致
- **録音も再生も 48kHz**。`i2s_reconfig_clk_fn(48000, 16, I2S_SLOT_MODE_STEREO)`
  で**動作ごとにクロックを設定し直している**
- **録音と再生を同時にはやっていない**。再生中は再生要求を弾き、録音は
  塞いで待つ作り

つまりクロックは実行時に変えられる。当初「全二重だから APU の 47160Hz に
固定される」と書いたが、これは**鳴らしながら録る場合に限った話**だった。

| やりたいこと | 標本化周波数 |
|---|---|
| 録るときは鳴らさない (M5 と同じ) | **48000 など標準の値を選べる** |
| 鳴らしながら録る | 47160Hz に固定 (クロックを共有するため) |

IDF で clock を変えるにはチャネルを一度止める必要がある
(`i2s_channel_disable` -> `i2s_channel_reconfig_std_clock` -> `enable`)ので、
**録音の間は APU の出力が止まる**。M5 も同じ制約の中にいる。

ES7210 と ES8388 はどちらも従属側なので、与えたクロックに追従する。ただし
ES7210 のレジスタ設定は MCLK/fs = 256 を前提にした値なので、その比は保つ。

### 2.1 47160Hz を使う場合に何が起きるか

「鳴らしながら録る」を選んだときだけ関係する話。この値は APU 由来で、
NTSC の 262 走査線 x 60Hz = 15720Hz を 3 倍したものである。

素因数分解すると `47160 = 2^3 x 3^2 x 5 x 131`。**131 が構造的に居座る**
(262 = 2 x 131 が出どころ)。これが以下を決める。

### 問題にならないもの

- **帯域**: 半分の 23580Hz まで扱える。44.1kHz より広く、失うものは無い
- **周波数の測定**: 解析式に 47160 を入れるだけで、音高も倍音も正しく出る
- **WAV での持ち出し**: WAV のヘッダは任意の周波数を書けるので、47160Hz の
  まま記録して PC で再生できる。再生側が勝手に合わせる
- **クロックの精度**: この周波数は今スピーカーが鳴っている実績値であって、
  マイクのために新しく作る値ではない。誤差があるなら既に出力側で出ている

### 問題になるもの

- **標準の周波数への変換が整数比にならない**。44100 との比は 262:245、
  16000 との比は 1179:400。131 が約分で消えないため、単純な間引きでは
  作れず、任意比の再標本化が要る
- **標準の周波数を前提にする相手**に渡せない。音声認識 (16k)、MP3/AAC の
  符号化 (44.1k/48k)、外部の解析ライブラリはたいてい決め打ちで、上の変換を
  挟まないと使えない
- **ミリ秒が整数の標本数にならない**。10ms = 471.6 標本。窓の長さを整数に
  丸めると少しずつずれるので、時間の計算は「標本数」を正として扱う必要がある

### 逃げ道

1. **録るときは鳴らさない** (推奨。M5 と同じ)。録音の間だけクロックを
   48000 に張り替え、終わったら 47160 に戻す。上の面倒は全部消える
2. 鳴らしながら録りたい場合に標準の周波数が要るなら、APU が 15720Hz で
   吐くのを再標本化してから I2S に載せる形になる。音の出方そのものに触る
   変更なので、マイクのついでにやることではない

## 3. 実装の形

1. `audio_p4_hw_init` で送受信チャネルを同時に確保する
   (`i2s_new_channel(&cfg, &tx, &rx)`)。**今動いている音の経路に手を入れる
   唯一の箇所**で、危険はここに集中している
2. ES7210 を初期化し、受信は開かれるまで無効のままにする。使わない人の
   負担をゼロにする
3. 受信タスクが環状バッファに貯め、二乗平均とピークを更新し続ける
4. Ruby へは新しい gem (`picoruby-fmrb-mic`) で公開する。
   `Mic.open` / `Mic.level` / `Mic.close`、生の標本が要るなら `Mic.read(n)`
5. 見本アプリは音量計 (棒とピーク保持)。動いていることが一目で分かる

所有は 1 本のアプリに限る (ピン管理や hw_proxy と同じ考え方)。

## 4. 段階

| 段 | 内容 | 意図 |
|---|---|---|
| M1 | 全二重化のみ。マイクは触らない | **今までどおり音が鳴ることだけを確かめる**。壊す可能性のある変更を単独で切り分ける |
| M2 | ES7210 の立ち上げ + 音量の取得 + 音量計アプリ。録音中はクロックを 48000 に張り替え、APU の出力を止める | 山を越える。無音で低く、拍手で跳ねることを実機で見る |
| M3 | 生の標本を Ruby へ。録音と周波数解析 | 既知の周波数を鳴らして解析値と突き合わせる。48000 なので外の道具にもそのまま渡せる |
| M4 | 鳴らしながら録る (47160 共有 + エコー消去の参照チャネル) | ここまでは当面やらない。M5 もやっていない |

M1 を単独で通すのが要点。ここで音が出なくなったら、原因は全二重化以外に
ありえない状態にしておく。

## 5. 検証の見通し (6 軸センサとの違い)

6 軸センサは I2C の手順を偽のセンサで再現できたので、実機に触る前に 26 項目
の検査を通せた。**マイクではこの手が効きにくい**。相手が I2S のタイミングと
実際の音で、シミュレータにマイクは無い。

したがって検証は実機中心になり、しかも**音を出す人が要る**。

| 見るもの | 方法 |
|---|---|
| 無音で低い値 | 静かな状態で音量を読む |
| 音に反応する | 拍手や声で跳ねることを画面で見る |
| 値が正しい | 既知の周波数を鳴らし、解析した音高と突き合わせる (M3) |

画面の取得と操作はリモートデスクトップでこちらから行えるので、依頼するのは
「音を出す」ところだけになる。

なお **鳴らしながら録ると自分のスピーカーが回り込む**。M3 までは「録るときは
鳴らさない」で進め、回り込みの除去は M4 の主題とする。
