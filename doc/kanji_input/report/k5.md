### `asend --sd` で届く場所

Shell の `asend <ノード> <ファイル> --sd` (と `-s`)・PC の `tools/fmrb_send.rb --sd`・console のページの SD の指定は、
どれも受け手の `/sd/inbox/` に置く (doc/asterism_file_transfer の T3b の決定。置き場所は `home`・`sd` の inbox だけ)。
辞書の場所へ直接は置けないので、案内には受け手の Shell で

```
mkdir /sd/dict
mv /sd/inbox/fmrb_kanji.dic /sd/dict/
```

と書いた。Shell の `mv` は `File.rename` で、同じ SD の中なので写しにならない。inbox に同じ名前があると
`fmrb_kanji(1).dic` になる (送るときの `-o` で上書き) ことも書いた。

### 検査 (`kanji:place`・`kanji:check`)

K2b の残件「`fmrb_kanji_verify` (CRC) を呼ぶ道は無い」には、端末でなく PC の側で答えた。端末は今までどおり開くときに
頭と大きさだけを見る (1 MB の crc32 を起動のたびに計算しない)。壊れた写しは PC で写した後と、落とした後に見つける。

| 試したこと | 結果 |
|---|---|
| `rake kanji:place DEST=<scratchpad>/card` | `card/dict/` に 2 つ。`ok, 1048576 bytes, 80192 words, 66407 readings, sha256 a2f6e08d…` |
| `rake kanji:check FILE=` (写した物) | 同じ行 |
| 先頭 100,000 バイトだけの写し | `file size 100000 != header 1048576`、終了コード 1 |
| 中の 1 バイトを変えた写し | `crc32 mismatch (a broken or partial copy)`、終了コード 1 |
| 生成物が無い所を `--from` で指す | `not there (rake kanji:dict makes it)`、終了コード 1 |

sim・ネイティブ版で試すときは、`DEST` に `/home` になる場所 (ネイティブ版なら `--user-dir` の下) を渡し、
`kanji_dict = "/home/dict/fmrb_kanji.dic"` を指す (sim・ネイティブ版には `/sd` が無い。K2b の試し方を道具にしただけ)。

## リリースのときにユーザがすること

doc/release.md の 2 の後 (CI の github-release ジョブが終わってから):

1. fmruby-core で `rake kanji:dict`、`rake kanji:place DEST=<作業の場所>`。sha256 を控える。
2. 直下で `gh release upload <ver> <作業の場所>/dict/fmrb_kanji.dic <作業の場所>/dict/fmrb_kanji_LICENSE.txt --clobber`。
3. リリースノートに 1 行 (置き場所・案内の場所・sha256。例は release.md)。
4. 落として `rake kanji:check FILE=` で ok。

## CI について (提案、変えていない)

今、リリースの添付は `.github/workflows/release-installer.yml` の github-release ジョブが `.deb` を付ける形。辞書も
そこで作れば手順が 1 つ減るが、変えなかった。

- 作るには元データ (約 75 MB、外の 2 か所) をリリースのたびに取りに行くことになり、取れなければリリースの CI ごと落ちる。
- plan の仮決めは「次のリリースで添付する (ユーザの指示で)」で、毎回の自動にするかは決まっていない。
- 作業ブランチに CI を足さない方針。

CI に入れるなら、linux-deb と並ぶジョブを 1 つ足し (ruby の用意 → `rake kanji:dict` → `rake kanji:place DEST=kanji` →
`actions/upload-artifact` で `kanji/dict/*`)、github-release の `needs` に足して、`debs/*.deb` と一緒に
`gh release upload`/`create` へ渡す。ノートの文にも 1 行。元データの取得を `actions/cache` に載せれば取りに行くのは
版を変えたときだけになる。入れるかはユーザが決める。
