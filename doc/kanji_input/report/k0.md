# K0 報告: 調べる・測る

> 状態: 完了 | 更新: 2026-11-11 | 基準のフォントは misaki 8 (漢字 6358 字 = JIS 第 1・第 2 水準 + 々〆仝)。元データは mozc の辞書 (IPAdic 系の条件 + BSD) と 1 字の表、足りない 65 字は Unihan。1 MB で約 5.7 万語 (1 字の表込み)。画面の下の 1 行をデスクトップが描く案は、全画面のアプリで出ない

ビルド・sim・ネイティブ版・ブラウザ版は動かしていない。ソースを読み、ホストの Ruby で数え、元データを
scratchpad に取って調べた。数える道具は `tools/kanji/` に置いた (標準ライブラリだけ)。

| 道具 | すること |
|---|---|
| `tools/kanji/font_charset.rb` | bdfconv が出した C の配列 (u8g2 の形) を読み、収録の Unicode の字を数える・一覧に出す |
| `tools/kanji/mozc_estimate.rb` | mozc の辞書の元データを、フォントで描ける語に絞り、頻度の上位から大きさの上限まで入れたら何語か、1 字の表が漢字を覆うかを数える |

## 3. 見積もり (mozc_estimate.rb、基準のフォント = misaki 8)

### 絞り込み

| | 行・語 |
|---|---|
| mozc の辞書の行 | 1,289,076 |
| 読みがひらがなだけでない (数字・記号入り) | 3,489 |
| 表記が読みと同じ (変換しても変わらない) | 93,525 |
| 表記に misaki で描けない字がある | 3,016 |
| 残った (読み, 表記) の組 | 1,003,189 (うちカタカナだけの表記 213,682) |

### 大きさの形 2 つ

- **utf8**: 読みも表記も UTF-8。
- **packed**: かな (ひらがな・カタカナ・ー) を 1 バイト、それ以外の字を 2 バイト (辞書の頭に置く字の表の番号) にする。
  字の表は使う字だけ (最大 7065 字 × 3 バイト = 約 21 KB)。端末での戻しは表を引くだけ。
- どちらも、読みごとに索引 4 バイト + 読みの長さと候補の数、候補ごとに長さ 1 バイトで数えた。

| 形 | 全部 | 1 MB に入る語 (読み) | 2 MB に入る語 |
|---|---|---|---|
| utf8 | 32.6 MB | 35,879 (30,232) | 70,024 |
| **packed** | **16.4 MB** | **65,613 (53,906)** | **132,827** |

- 1 字の表 (6358 字ぶん) は packed で約 102 KB (utf8 で約 146 KB)。**1 字の表と字の表を 1 MB の中に入れると、語は約 57,500**。
- 1 MB の境目のコストは 5214。境目のあたりの語は 中庭・被爆・未遂・ベストセラー・ブライダル 程度で、日常の語は入る。
  試した 31 語 (漢字・変換・日本語・学校・先生・友達・明日・プログラム・鉛筆・誕生日・郵便局・放課後・遊園地・算数 …) のうち
  入らなかったのは 連絡帳 (コスト 6257) だけ (固有名詞を外した版では 東京 も落ちる。上の理由で外さない)。
- **SD の大きさから見ると 1 MB はかなり控えめ**: 全部入れても packed で 16 MB。1 MB の目安は plan の仮決めのまま残し、
  K1 の道具の上限で増やせるようにする。

### 打てない読み

今のかなの合成 (fmrb_kana.c) が出せない並びを含む読みは、1 MB の語の 3.6% (2,370)。

- 1,653 は語幹が っ で終わる形 (言っ・良かっ・終わっ)。っ は次の子音を待つので、読みの末尾には来ない。
  **読みの先頭から最も長く一致する所で引く (いった → 言っ + た)** なら、この形はそのまま役に立つ。文節に区切る IME ではなく、
  単語の変換の範囲の工夫で済む。
- 残り約 700 は てぃ でぃ ふぁ ふぉ ふぃ ふぇ うぇ うぃ うぉ ゔ など。合成に `x`/`l` の小書き (xa・ltu)、`fa`・`thi`・`dhi`・
  `wi`・`we`・`va` などを足せば打てる。足さないなら K1 で外す。

### 辞書のファイルの形の案

読みの順 (packed のバイト順 = ひらがなの Unicode 順 = 五十音順) に並べた本体を **4 KB の塊** に切り、頭に「各塊の最初の読み」の
小さな表を置く。

```
頭       魔法の数・版・数・各部の位置・ライセンスの名前
字の表   packed の 2 バイトの番号 -> UTF-8 (約 21 KB)
塊の索引 塊ごとの最初の読み (約 250 個、約 3 KB)
本体     4 KB の塊の列。塊の中は [読みの長さ][読み][候補の数]([長さ][表記])... を読みの順に
         (1 字の表の漢字は語の後ろに続ける。読みは塊をまたがない)
```

- 引き方: 塊の索引で二分探索 (開くときに PSRAM へ読む、約 3 KB。内蔵 RAM は使わない) → 塊を 1 つ読む (4 KB、連続 8 セクタ) →
  塊の中を前から見る。**SD を読むのは 1 回の変換で 1 回**。
- 純粋な二分探索 (読みごとの 4 バイトの索引) なら 16 回前後の探りで、索引と本体を交互に読むので 30 回前後のランダムな読みに
  なる。下の見込みでは S3 でも数十ミリ秒で、どちらでも体感の範囲だが、塊の形のほうが一桁速く、字の表と同じく頭で済む。
  plan 方針 6 の「索引から二分探索」の範囲に入る。

## 4. 端末の SD

| | P4 (Tab5・NARYAv4) | S3 (NARYAv3) |
|---|---|---|
| つなぎ方 | SDMMC slot 0、4 bit (だめなら 1 bit)、IO 電圧は内蔵 LDO 4 | SDSPI、SPI3 (CS 15・MOSI 16・SCLK 17・MISO 18・挿入検出 38)。子マイコンへの SPI2 とは別のバス |
| クロック | `SDMMC_FREQ_HIGHSPEED` = 40 MHz | `SDSPI_HOST_DEFAULT` の 20 MHz |
| 線の上の速さ | 20 MB/s (4 bit) | 2.5 MB/s |
| 512 B のランダムな読み (見込み) | 0.1〜0.3 ms (カードの応答が大半) | 0.5〜1.5 ms |
| 4 KB の塊を 1 つ (見込み) | 0.3〜0.5 ms | 2〜5 ms |
| 二分探索 30 回 (見込み) | 5〜10 ms | 15〜45 ms |

- マウントは `/sd`、FAT (長いファイル名あり、`CONFIG_FATFS_LFN_HEAP`)。読み取り専用で開くファイルは newlib の既定の
  バッファのまま (fmrb_hal_file_esp32.c)。
- 確認すること (K2): FatFs のファイルごとのキャッシュ (512 B) の置き場所 (`CONFIG_FATFS_ALLOC_PREFER_EXTRAM` で PSRAM に
  なるか)。ファイルを開いたままにすると、その分が常に取られる。
- **実測の手順** (実機が要るので K2 で): 1 MB の試験ファイルを `/sd/dict/` に置き、(1) ランダムな位置の 512 B 読みを 200 回、
  (2) 4 KB 境界の 4 KB 読みを 200 回、(3) 開く・閉じるを 50 回、それぞれ fmrb_hal_time の µs で平均と最大を出す小さな
  試験 (C の関数をアプリから呼ぶか、mruby の File で同じことをする) を、Tab5 は tab5_app で起動して tab5 の画面かシリアルで、
  NARYAv3 はシリアルのログで読む。カードは 2 種類以上 (遅いものを含む) で測る。目安: 1 回の変換で SD に 10 ms 以内。

## 5. かなの合成の場所と、preedit・候補を描く場所

### 合成の場所

- `main/kernel/host/host_task.c` の `fmrb_keymap_scancode_to_char()` の直後で `fmrb_kana_feed()` を呼ぶ 1 か所が、全部の入力
  (USB・Tab5 内蔵・I2C・遠隔・SDL) の合流点。確定したかなは `host_send_kana_byte()` で 1 バイト 1 イベントとして送る。
- **preedit はここに持たせる**: 辞書があって変換が有効なら、確定したかなを送らずに C の preedit のバッファ (fmrb_kana の隣に
  新しい部品) へためる。preedit がある間だけ スペース・変換・Enter・Esc・BS・数字 を消費する (今の BS の扱いと同じ形)。
  確定は今と同じ `host_send_kana_byte()` の連打で送れるので、受け側 (エディタの UTF-8 の組み立て) は変えなくてよい。
  ネイティブ版で PC の IME の確定を流す `HOST_MSG_HID_TEXT` も同じ送り方。
- **引くのは host task ではない所で**: host task は優先度 10 で、入力・描画・音の唯一のポンプ (送り先が詰まったら 200 ms で
  諦める作り)。SD を読む仕事を置けない。引き手は低い優先度の別の所に置き、結果を host task へ返す形になる (案: 優先度の低い
  C のタスクを 1 つ、スタックは PSRAM。SD の読みはフラッシュのキャッシュを止めないので PSRAM のスタックで動くはず。K2 で
  確認する)。

### 画面の下の 1 行 (仮決め) について

- 「デスクトップの重ね表示」はデスクトップの前景の Canvas (z=254、メニューバー・ドロップダウン・ランチャーを描く所)。
- **全画面のアプリが上にいる間はデスクトップが止まり、この Canvas は画面に出ない** (window_manager.rb の find_window_at の
  注記、fmrb_kernel.rb の全画面の扱い)。全画面のエディタ (Modern の 640x360 を含む) は日本語を書く主な場所なので、
  **デスクトップが描く形だと、そこで preedit と候補が見えない**。また、デスクトップに描かせると、変換のたびに host task →
  カーネル → デスクトップの往復になる。
- 代わりの形: **システムが持つ 1 行の Canvas** を、全 Canvas より上の z で、必要なときだけ作る (下端、高さ 10 px 前後、
  幅は今の画面の幅 320 / 426 / 640。全画面の高解像度の切り替えで作り直す)。描くのは preedit の持ち主 (C の側) が gfx の
  コマンドで。Canvas は z の順に重ねる作りなので (display_local_task.cpp・graphics_handler.cpp とも)、Retro (子マイコンが
  合成) でも Modern でも同じ命令で出せる。Retro の 320 幅は misaki 8 で全角 40 字。preedit 10 字 + 「1漢字 2感じ 3幹事 …」で
  1 ページ 4〜6 候補。
- これは仮決めの「システムが画面の下に出す 1 行。どのアプリでも同じ場所」はそのまま守り、**描き手がデスクトップでなくなる**
  という違い。親の判断を待つ (plan は変えていない)。
- ほかに使える既存の仕組み: アプリは `FmrbApp.set_text_cursor(x, y, h)` で文字のカーソルの位置を言う (L12b で入った。
  エディタ・Shell は呼んでいる)。今はネイティブ版でだけ値を使う。将来、候補をカーソルの近くに出すならこれを使える。
- ネイティブ版は PC の IME の未確定の文字を Family mruby のフォントで描いている (`native/backend/native_preedit.cpp`。
  efontJA 16 / 12 / misaki 8 を行の高さで選ぶ)。端末の 1 行の描き方の手本になる。

## 6. ブラウザ版の IME (K4) の見立て

- 今のページ (`wasm/web/main.js`) は `<canvas>` の keydown / keyup を HID の scancode に直して入力のリング
  (`pushInput`、1 件 5 語) へ積む。テキストを流す道は無い。
- 貼り付け (L12a) は **クリップボードの差し替え** で、テキストを打つ道ではない (Ctrl+V の paste イベントの文字を
  `clip_wasm.c` の in の枠に書き、アプリがクリップボードを読んだときに渡る)。K4 にはそのまま使えない。
- 使えるのはネイティブ版の道: `fmrb_host_send_text()` → `HOST_MSG_HID_TEXT` → 1 バイト 1 イベント。今は
  `FMRB_PLATFORM_NATIVE` の中だけにある。IME がある間に自前のかな入力を止める・指示器を隠す (`FMRB_KANA_MODE_IME`)・
  `set_text_cursor` の位置を外へ出す、もネイティブ版の中にある。K4 はこの囲いをブラウザ版にも開け、
  - 入力のリングに「テキスト」の種類を足す (ネイティブ版の `NATIVE_INPUT_TEXT` と同じ、1 件に 12 バイトまで。
    `wasm/backend/input_wasm.c` の switch に 1 つ)、
  - ページに見えない `<textarea>` を置いて焦点をそこへ移し、keydown は今の変換を通す。ただし `isComposing` の間
    (と keyCode 229) は HID へ送らない。`compositionend` の確定の文字をテキストの種類で流す、
  - 見えない入力欄をアプリの文字カーソルの位置へ動かす (ブラウザの候補の Window がそこに出る) — 位置は set_text_cursor の値を
    フレームの番号と同じように共有メモリで渡す、
  という形になる。

## 撤回した仮説

- 「misaki は第 1 水準だけ」: misaki の COPYRIGHT.txt (core と graphics-audio の両方) の Coverage 行に「JIS L1 kanji」と
  あるが、数えると第 1・第 2 水準の全部 (6355 字) が入っている。説明の行が誤り (直すのは別の機会。K0 では触っていない)。

- 「Retro と Modern で efont の版が違うかもしれない」: 4 か所とも同じ中身だった。

## 親の仮決めに対して

- **崩れるもの**: 「preedit と候補はデスクトップの重ね表示に出す」。全画面のアプリの上では出ない。1 行は守ったまま、描き手を
  システム (C の側) の Canvas にする案を上に書いた。判断待ち。
- **補足が要るもの**: 辞書の大きさ 1 MB は約 5.7 万語 (1 字の表込み)。全部でも 16 MB で SD には余裕がある。目安は仮決めのまま。
- **そのままでよいもの**: SD に置く、生成物をリポジトリに入れない、学習しない、頻度順 (mozc のコスト)、`/sd/dict/`
  (長いファイル名が使える)、単語ごとの変換 (最長一致を足せば語幹の形も使える)。
