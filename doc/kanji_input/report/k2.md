### API (`fmrb_kanji.h`)

```c
fmrb_err_t fmrb_kanji_open(const char *path, fmrb_kanji_dict_t **out);
void       fmrb_kanji_close(fmrb_kanji_dict_t *dict);
void       fmrb_kanji_get_info(const fmrb_kanji_dict_t *dict, fmrb_kanji_info_t *out);
uint32_t   fmrb_kanji_block_reads(const fmrb_kanji_dict_t *dict);
fmrb_err_t fmrb_kanji_lookup(fmrb_kanji_dict_t *dict, const char *reading, size_t len,
                             uint8_t *block, fmrb_kanji_result_t *out);
fmrb_err_t fmrb_kanji_longest_prefix(fmrb_kanji_dict_t *dict, const char *reading, size_t len,
                                     uint8_t *block, fmrb_kanji_result_t *out);
fmrb_err_t fmrb_kanji_candidate(fmrb_kanji_result_t *result, uint16_t index,
                                char *utf8, size_t cap, size_t *out_len);
fmrb_err_t fmrb_kanji_verify(fmrb_kanji_dict_t *dict, uint8_t *block);
```

- **開く**: 頭 64 バイトを読み、dict_format.md の印 (magic・version・file_size・index_offset・index_offset + index_size <=
  body_offset・body_offset + 塊の数 x 4096 = file_size・block_size) を確かめ、字の表と塊の索引 (隣り合っているので 1 回の
  読み) を `fmrb_sys_malloc` の 1 つの確保に読む。ほかに、塊の索引の中の位置がすべて索引の中にあること、key の長さが
  1..127、key が厳密に増えることも確かめる。ファイルは開いたまま持つ。
  - 戻り値: 開けない `NOT_FOUND`、版違い `NOT_SUPPORTED`、辞書でない・壊れている `INVALID_STATE`、`NO_MEMORY`、
    読みの失敗 `FAILED`。**どれも「辞書は無い」として扱えばよい** (かな入力は今のまま)。
  - 表が 128 KB を超える頭は壊れているとみなす (1 MB の辞書で 15.5 KB。壊れた頭で大きな確保をしないため)。
  - CRC は開くときに見ない (dict_format.md のとおり)。`fmrb_kanji_verify` が頭より後ろ全部を 4 KB ずつ読んで確かめる。
    表は 4 ビットずつの 16 個 (64 バイト、const)。コピーした後の確認用。
- **引く**: 読み (UTF-8、NUL 終端でなくてよい) を 1 バイトのかなに詰め、塊の索引を二分探索し、塊を 1 つだけ呼び手の
  4 KB に読んで前から見る。かな (ひらがな・カタカナ・ー) 以外の字を含む読みは `NOT_FOUND` (Ruby の Reader も空を返す)。
- **最長一致**: 読みの先頭のかなだけを詰め (かなでない字の手前まで、127 字まで)、全体から 1 字ずつ短くして引く。
  **すでにバッファにある塊は読み直さない** (dict_format.md で許した工夫)。`matched_bytes` が一致した UTF-8 のバイト数
  (かなは 1 字 3 バイト)。残りは呼び手が次の変換に回す。
- **候補**: 結果 (`fmrb_kanji_result_t`) は呼び手のバッファと辞書の表を指す (バッファを使い回すか閉じるまで有効)。
  `fmrb_kanji_candidate` が i 番目を NUL 終端の UTF-8 にする。前から順に読めば追加の手間はなく、戻ると先頭から数え直す。
  `FMRB_KANJI_CAND_UTF8_MAX` (766) あれば必ず収まる。足りなければ `INVALID_PARAM`。
- **壊れた塊**: 長さ・数・字の表の番号をすべて 4096 と字の数で抑え、合わなければ `INVALID_STATE`。塊の外は読まない。
- 1 つの辞書は 1 つのタスクが開いて引く (排他は持たない)。

### 試験の数 (`rake kanji:test`、約 3 秒)

c_lookup.rb は 72 の確認。

1. **作り物の辞書** (fixtures.rb。1 塊と 2 塊、2 塊の方は候補 200 の読みで 2 バイトの数を通る): 全部の読みの完全一致、
   読み + た・読み + んじ・読みの末尾を削ったものの最長一致、乱数のかな 3000 件の外れ、変わった入力 (空・ASCII・カタカナ・
   漢字まじり・130 字・壊れた UTF-8)。C の答えの行と、Ruby の Reader から作った答えの行が全部一致。Ruby 側の答えは
   each_entry の表から作るので、その表が Reader#lookup / #longest_prefix と同じことも抜き取りで確かめた。
   **辞書が無い環境 (CI) でもここまでは走る**。
2. **壊れたファイル** (作り物の 2 塊の辞書を書き換える): 無いファイル・magic・版 2・途中までのコピー・10 バイト・空・
   index_offset・block_size・header_size・塊の数・巨大な index_size・索引の位置が範囲外・索引の key が増えない、の 13 通りを
   開くときに断る (版 2 は `NOT_SUPPORTED`、無いファイルは `NOT_FOUND`、ほかは `INVALID_STATE`)。どれも閉じた後プールに
   残りなし。本体の 1 バイトを変えたものは開けるが verify で断る。本体を壊したもの 7 通り (全部 0xFF・乱数・長さの上げ・
   数を 0 に・詰め物の 0 を 0x03 / 0x05 / 0x7F に) で全部の読みを引き、答えは見つかった・無い・壊れている のどれかで、
   塊の外を読まない (AddressSanitizer)。読みの失敗 (開くとき・引くとき) は `FAILED` で、その後また引ける。
   候補を後ろから読んでも前からと同じ。小さすぎるバッファは断る。
   - 詰め物の 3 通りは、`skip_candidates` の範囲の確認を抜いた版で AddressSanitizer が塊の外の読みを捕まえることを
     確かめてから入れた (ほかの壊し方では、その確認が無くても先の確認で止まり、捕まらなかった)。
3. **生成した辞書** (`tools/kanji/work/out/fmrb_kanji.dic`、1 MB、あれば。無ければ理由を出して飛ばす):

| | 件数 | 塊の読み | ホストで 1 件 |
|---|---|---|---|
| 完全一致 (読み 66,407 + 外れ 3000 + 変わった入力) | 69,418 | 69,410 | 2.6 us |
| 最長一致 (読み + た・+ んじ・末尾を削る・外れ) | 135,494 | 214,679 (1 件 1.58) | 4.9 us |

- 全部の行が Ruby と一致。ホストの時間は SD と関係がないので目安にもならない (端末の測定は K2b)。
- 読みの読み直しをしない工夫: 読み + た の 66,407 件では、毎回引くやり方 (Ruby の Reader) が 1 件 2.0 回引く。C は同じ塊を
  読み直さない。いった は 2 回 → 1 回、れんらくちょう は 4 回 → 1 回 (Reader の reads と C の block_reads で数えた)。

## 撤回した仮説

- 「本体を乱数や 0xFF で壊せば、塊の外を読む誤りは試験で捕まる」: 捕まらなかった。そういう壊し方は最初の項目の長さや
  数の確認で止まり、候補を飛ばすところの範囲の確認まで行かない。塊の終わりの詰め物 (0) を小さな値に変えて、正しい形の
  項目が塊の終わりを越えて続くようにすると捕まる。その 3 通りを足した。
- 「試験の答えは lookup.rb を読みごとに呼んで作る」: Ruby の Reader は 1 回の引きで塊を丸ごと配列にするので、13 万件の
  最長一致では遅い。each_entry の表から答えを作り、その表と Reader の答えが同じことを抜き取りで確かめる形にした。

## K2b に要るもの

- **組み込み**: `components/fmrb_kanji/CMakeLists.txt` (`REQUIRES fmrb_hal fmrb_mem fmrb_common` 相当) を足す。
  ESP32・sim の CMake と、ネイティブ版・ブラウザ版のソースの一覧 (native / wasm の rake) にも足す。ビルドが要るので K2a では
  していない。**ファームのビルドで通るかは未確認** (ホストの gcc では -Wall -Wextra -Werror で通る)。
- **引くタスク**: 優先度の低い C のタスクが辞書を開いて持ち、4 KB のバッファ (PSRAM) を持つ。host task では引かない。
  かなの合成 (K3) からの頼みと答えの受け渡し (キュー) を決める。結果は塊のバッファを指すので、答えを渡すときは候補を
  UTF-8 に書き出してから渡す。
- **置き場所の設定**: 既定 `/sd/dict/fmrb_kanji.dic`、sim は別の場所 (system_conf)。開けなければ辞書なしで動く。
- **端末での速さの測定**: S3 (SPI の SD) と P4 (SDMMC) で、開く時間 (16 KB の読み)、1 回の引き (4 KB の読み + 塊の中の
  走査)、最長一致の最悪 (いった・れんらくちょう など)、verify (1 MB を読む) を測る。`fmrb_kanji_block_reads` で読みの回数を
  数えられる。実機が要るので K3 と一緒にする。
- fmrb_hal_file_seek は `int32_t` の位置を取る。辞書は 2 GB を超えないので困らないが、版を上げるときに覚えておく。
- 内蔵 RAM の増分 0 の確認 (`rake regress:size`) は組み込んだ後。
