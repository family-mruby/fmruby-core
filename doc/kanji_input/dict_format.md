# 漢字の辞書のファイルの形 (fmrb_kanji.dic)

> 状態: 版 1 | 更新: 2026-11-11 | 企画の中の仕様 (K1 で決めた形)。生成は `tools/kanji/make_dict.rb` (`rake kanji:dict`)、引く側の基準は `tools/kanji/lookup.rb` (Ruby)。K2 の C の実装はこの文書と lookup.rb と同じ答えを出す

## 全体

1 ファイル。数はすべてリトルエンディアン。

```
0          頭 (64 バイト)
64         字の表        char_count 個 x 2 バイト
index_off  塊の索引      index_size バイト
(0 で埋める)             body_offset まで (body_offset は 4096 の倍数)
body_off   本体          block_count 個の 4 KB の塊
file_size  = body_offset + block_count x block_size
```

- 頭・字の表・塊の索引は開くときに一度に読む (1 MB の辞書で 16 KB。塊の索引だけなら約 2.5 KB)。
- 本体は 4 KB の塊。1 回の引きで SD を読むのは 1 塊 (連続 8 セクタ)。本体の始まりを 4096 の倍数にしてあるので、
  FAT のクラスタ (4 KB 以上) の境目と塊の境目がそろう。

## 頭 (64 バイト)

| 位置 | 型 | 名前 | 中身 |
|---|---|---|---|
| 0 | char[4] | magic | `FMKD` |
| 4 | u16 | version | 形の版。今は 1。引く側は知らない版を開かない |
| 6 | u16 | header_size | 64 |
| 8 | u32 | file_size | ファイルの大きさ。実際の大きさと違えば壊れている (途中までのコピー) |
| 12 | u32 | chars_offset | 字の表の位置 (64) |
| 16 | u16 | char_count | 字の表の数 (16384 まで) |
| 18 | u16 | flags | 0 (予約) |
| 20 | u32 | index_offset | 塊の索引の位置 (= chars_offset + char_count x 2) |
| 24 | u32 | index_size | 塊の索引のバイト数 |
| 28 | u32 | block_count | 塊の数 |
| 32 | u32 | body_offset | 本体の位置 (4096 の倍数) |
| 36 | u32 | block_size | 塊の大きさ (4096) |
| 40 | u32 | reading_count | 読みの数 |
| 44 | u32 | word_count | 語の辞書から入れた語の数 (1 字の表を除く) |
| 48 | u32 | single_count | 1 字の表の (読み, 漢字) の組の数 |
| 52 | u32 | crc32 | 頭の後ろ全部 (64 バイト目からファイルの終わりまで) の CRC-32 (zlib と同じ多項式)。配った物の確認用。端末は開くたびに確かめなくてよい |
| 56 | u32 | reserved0 | 0 |
| 60 | u32 | reserved1 | 0 |

引く側が開くときに確かめる印: magic、version、file_size、index_offset = chars_offset + char_count x 2、
index_offset + index_size <= body_offset、body_offset + block_count x block_size = file_size、block_size = 4096。
どれかが合わなければ辞書は無いものとして扱う (かな入力は今のまま)。

## 字の番号付け (packed)

読みも候補も、1 字を 1 バイトか 2 バイトで書く。

| バイト | 字 |
|---|---|
| 0x00 | 使わない (塊の終わりの印) |
| 0x01-0x56 | ひらがな U+3041-U+3096 (0x01 + (字 - 0x3041)) |
| 0x57-0xB0 | カタカナ U+30A1-U+30FA (0x57 + (字 - 0x30A1)) |
| 0xB1 | 長音 ー U+30FC |
| 0xB2-0xBF | 使わない |
| 0xC0-0xFF + 1 バイト | 字の表の番号 ((先頭 - 0xC0) x 256 + 2 バイト目)。0..16383 |

- 字の表は u16 の Unicode の番号 (BMP だけ) を番号の順に並べたもの。字の表は小さい順に並べてある (二分探索で
  逆引きもできる)。辞書に出てくる、かな以外の字 (漢字・記号・英数字・・ ヽ ヾ など) だけが入る。
- UTF-8 への戻しは、1 バイトのかなは計算で、2 バイトは表を引いて 3 バイト以下の UTF-8 にする。
- **読みはひらがなと ー だけ** なので、読みはすべて 1 バイトの字で書かれ、**バイトの順 = Unicode の順 = 五十音の順**になる。
  打った読みを packed にするのに表は要らない (ひらがな・ー 以外の字を含む読みは辞書に無い)。

## 塊の索引

```
u32 offset[block_count]     各塊の最初の読みの位置 (塊の索引の先頭から)
key[block_count]            [長さ u8][読み (packed)]
```

- key[i] は塊 i の最初の読み。key は厳密に増える順。
- 読み k を引くには、key[i] <= k となる最後の i を二分探索で探す (key[0] > k なら辞書に無い)。比べ方は memcmp で、
  共通の部分が同じなら短いほうが小さい。

## 塊 (4096 バイト)

塊の中は項目を読みの順に詰め、残りを 0 で埋める。項目は塊をまたがない。

```
項目 = [読みの長さ u8 (1..127)][読み (packed)]
       [候補の数: 0x00-0x7F なら 1 バイト、それ以上は 2 バイト (0x80 | 上位 7 ビット, 下位 8 ビット)]
       候補 x 数: [長さ u8 (1..255)][表記 (packed)]
```

- 読みの長さが 0 のところ (か塊の終わり) で塊は終わる。
- 1 つの読みは辞書全体で 1 回だけ出る。候補が最も多い読みは こう の 320 (1 MB の辞書で)。1 項目は必ず 4096 バイトに収まる
  (生成の道具が確かめる)。
- 引き方: 塊を前から見て、読みが k と同じなら候補を返す。k より大きい読みが出たら、辞書に無い。

## 候補の順

1. 語の辞書の語: mozc のコストの小さい順 (よく使う順)。同じ読み・表記の行が品詞違いで複数あるときは最小のコスト。
   コストが同じなら読み・表記の順。
2. 1 字の表の漢字: 上で出ていない字だけを、元の表の並び (single_kanji.tsv の読みごとの並び) で後ろに続ける。

学習はしない (最初の版)。端末は候補をこの順に出す。

## 中身の約束 (生成の道具が確かめる)

- 候補のすべての字は基準の字の集合 (misaki 8 と efontJA 12・12 太字・16 の共通部分、7065 字) にある。
  どの構成の端末でも描ける。
- 基準の字の集合の漢字 6358 字は、どれもどこかの読みの候補に 1 字で出る (漏れ 0)。
- 読みは今のかなの合成 (ローマ字) で打てるものだけ。ただし最後の字が っ の読み (語幹の 言っ・良かっ) は入っている。
  これは読みの先頭からの最長一致で引く (下)。
- 表記が読みと同じ語 (変換しても変わらない) は入れない。カタカナの表記 (読みをカタカナにしただけのものを含む) は入れる。

## 最長一致

打った読み r に完全に一致する項目が無いとき、r の先頭から最も長く一致する読みを探す (r の長さから 1 字ずつ短くして
引く)。見つかった読み p の候補を出し、残り (r の p より後ろ) は次の変換に回す。

例: いった は項目が無い → いっ (言っ 行っ 一 …)、残り た。

lookup.rb の `longest_prefix` がこの基準。短くするたびに 1 回引くので、SD の読みは最大で r の字数ぶん。K2 で、同じ塊に
入る読みは塊を読み直さずに済ませてよい (答えは変わらない)。

## 版を上げるとき

項目や頭の意味を変えたら version を上げる。古い引く側は新しい版を開かない (辞書が無いのと同じ動き)。頭の予約の 0 の欄に
意味を足すだけで、古い引く側がそのまま正しく引けるなら版はそのままでよい。
