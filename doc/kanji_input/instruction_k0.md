# K0 指示書: 調べる・測る (ビルドと sim を使わない)

> 状態: 実装中 | 更新: 2026-11-11 | 正は plan.md (方針・親の仮決め)

ほかのサブが同じ checkout でビルド・sim・ブラウザ版を使っているので、K0 は**ビルド・sim・ネイティブ版・ブラウザ版を
動かさない**。ソースを読み、ホストの Ruby で数え、ネットから元データを取って調べるだけ。

## 調べること

1. **フォントの字の集合**: 配る全部の構成で描ける漢字の集合。
   - misaki 8 (fmruby-core/main/drivers/display_local/fonts/misaki/ と、graphics-audio 側で使う LovyanGFX の misaki)、
     efontJA 12/16 (LovyanGFX)。どの構成でどのフォントが入るか (FMRB_NO_FONT_JA、Retro の子マイコン側、Modern、
     ブラウザ版、ネイティブ版)。
   - フォントの元データ (C の配列) から、収録の Unicode の字を数える道具を Ruby で書き、集合の大きさと共通部分を出す
     (道具は tools/kanji/ に置いてよい。生成物の表は scratchpad に)。
2. **辞書の元データ**: mozc の辞書の元データ (dictionary_oss) の形・ライセンス (BSD 系と ICOT の条項、IPAdic の条件)・
   大きさ・頻度 (cost) の持ち方、1 字の漢字の読みの表 (single_kanji など) の有無とライセンス。取るのは版を固定した
   ものにする (コミットのハッシュ)。元データはリポジトリに入れない (scratchpad に取る)。
   ほかに配りやすい候補 (KANJIDIC など) があれば比べる。
3. **見積もり**: 1 と 2 から、「基準のフォントで描ける語だけ」「頻度の上位から 1 MB まで」で何語入るか、基準のフォントの
   漢字が 1 字の表で全部覆えるか (覆えない字の数と例)。辞書のファイルの形の案 (読みの順の索引 + 本体、二分探索) と大きさ。
4. **端末の SD**: P4 (SDMMC)・S3 (SPI) の SD の読みの速さの見込み (ソースの設定・クロックから。実測は実機が要るので
   手順だけ書く)。二分探索 1 回 (20 回前後の読み) の時間の見込み。
5. **今のかなの合成の場所と、候補・preedit を描く場所**: かなの合成 (doc/editor_ja の合成層、host_task の文字変換点) の
   コードを読み、preedit を持たせる所と、画面の下の 1 行 (デスクトップの重ね表示) を出す所の見立て。Retro・Modern・
   ブラウザ版・ネイティブ版での違い (ブラウザ版とネイティブ版は自前の変換を使わない)。
6. **ブラウザ版の IME (K4)**: wasm/web の入力の扱いを読み、見えない入力欄で compositionend を受けて確定の文字を端末へ
   流す道の見立て (貼り付けの道が既にある)。
