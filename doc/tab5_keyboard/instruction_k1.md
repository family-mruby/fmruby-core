# 実装指示書 K1: Tab5 内蔵キーボードの刻印と入力の不一致修正

対象: 実装担当セッション。report は report/k1.md へ。
**T1 の実測は実機 (Tab5) とユーザの物理キー押下が必要** — 準備 (計測手段と
チェックリスト) までを先に作り、ユーザ実測を挟んで T2 に進む 2 段構え。

## 症状 (ユーザ報告 2026-08-11)

Tab5 内蔵キーボードで、**キーの刻印と実際の入力が一部一致しない (主に記号)**。

## 現状の構造と仮説

- ドライバ (main/drivers/tab5_keyboard/tab5_keyboard.c) は **HID モード**
  (レジスタ 0x30、modifier + keycode) で読み、keycode をそのまま
  scancode として host_task へ送る。文字化は host_task の 1 点で、
  **システム設定の keyboard_layout (既定 jp) の汎用フルキーボード表**
  (fmrb_keymap.c) が使われる。
- 公式仕様: 14x5 の 70 キー、**Sym キー / Aa キー**を持つ独自コンパクト
  配列。Character モード (0x50) では Sym/Aa をキーボード側ファームが解決
  して確定文字列を返すが、HID モードでの Sym 層の keycode 対応は非公開。
- **仮説 (本命)**: 刻印は US 系の記号配置で、jp 表で変換するため
  us/jp の記号差分 (@ ^ & ' ( ) = ~ : \ など) がそのままズレている。
  Sym 層が素直に「US 配列でその記号を出す keycode + Shift」を返して
  いるなら、これで全部説明がつく。

## T1: 診断 (準備は実装セッション、実測はユーザ)

1. **1 分テストの依頼**: 実機の設定で keyboard_layout を us に変えて
   再起動し、記号の刻印一致がどう変わるかをユーザに確認してもらう。
   全一致するなら仮説確定で T2-A へ。
2. **キー掃引の準備**: ドライバの Key DOWN ログ (既存 LOGD) を一時的に
   INFO へ上げるか debugd 経由で取れるようにし、**14x5 の全キーを
   素押し / Aa(Shift?) / Sym の 3 状態で押してもらうチェックリスト**
   (刻印を書き込む表) を report に用意する。ログは fmrb_serial_capture
   で採取。modifier キー自体 (Ctrl/Alt/Sym/Aa) が何を出すかも記録
   (かなトグル候補の調査を兼ねる)。
3. 実測結果 (keycode 表) を report/k1.md に貼ってから T2 の方式を確定する。

## T2: 修正 (診断結果で分岐)

- **T2-A (仮説どおり = US 配列で一致する場合)**: **ソース別レイアウト**を
  入れる。Tab5 内蔵キーボード由来のイベントは keyboard_layout 設定に
  かかわらず **US 表で文字化**する。実装は「イベントに layout ヒントを
  載せる」(fmrb_host_send_key_down の拡張 or 送出元登録) が素直。
  外付け USB/BLE キーボードは従来どおり設定に従う (JP キーボードを
  繋ぐユーザを壊さない)。sim には影響ゼロであること。
- **T2-B (Sym 層が独自 keycode を出す場合)**: 実測表から
  **FMRB_KEYMAP_LAYOUT_TAB5** (専用変換表) を fmrb_keymap に追加し、
  Tab5 内蔵キーボードのイベントだけこの表を使う (T2-A の機構に載せる)。
- **Character モードへの切替は採らない** (最後の手段)。確定文字は刻印と
  一致するが、scancode が失われて矢印・ゲーム・ホットキー・かな合成層の
  前提が崩れるため。検討したら理由ごと report に。

## T3: Tab5 でのかなトグル (JA3 の持ち越し)

- Tab5 キーボードに半角/全角キーが無い。**Ctrl+Space を全キーボード共通の
  追加かなトグル**として fmrb_kana に足す (キーボード個体差に依存しない
  解。既存の 0x35 / Shift+0x35 / 0x88 はそのまま)。
- Ctrl+Space が既存機能と衝突しないことを確認 (エディタ・shell・
  デスクトップ。現状未使用のはず)。
- T1 の実測で Sym/Aa が独自 keycode を出すと分かった場合、それを
  トグルに使う案も report で比較する (採否はユーザ判断)。

## 受け入れ条件

- 実機: 全キー (素押し / Aa / Sym) で**刻印どおりの文字が入力される**
  (ユーザ確認。チェックリストを再利用)。
- 実機: エディタでかなモードが Ctrl+Space でトグルでき、ローマ字かな入力が
  内蔵キーボードで動く (JA3 の実機確認と統合)。
- 外付けキーボード (US/JP 設定) の従来動作に退行なし。sim に挙動変化なし。
- S3 ビルドにも影響なし (Tab5 ドライバは P4 限定のはず。確認)。

## 完了報告

report/k1.md に: 実測 keycode 表 (チェックリスト込み)、採った方式
(T2-A/B) と根拠、かなトグルの最終仕様、ユーザ確認結果。
