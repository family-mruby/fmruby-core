# 基準の表を flash に置く (F6 の前の段)

> 状態: 計画済 | 更新: 2026-11-03 | 基準の表 (起動直後の VM のものの名前と付属物) のうち、ファームで決まる部分をファームを作るときに作って flash に置き、VM ごとには番号 → ポインタの小さな表だけを持つ。F1b の結果を見て案を選ぶ

計画全体は `plan.md`。決定 D12 の (c) (mruby-checkpoint の `doc/plan.md`)。ユーザの決定 (2026-11-03): 基準の費用は
「まず gem の表を小さくし (F1b)、実機 (F6) の前に名前の表をファームごとに flash に置く形も作る」。

## 目的

- 申告したアプリの VM が払う基準の費用を、端末の VM のプール (S3 で約 500 KB) に無理なく収まる大きさに下げる。
- 内蔵 RAM は +0 のまま (表は flash、VM ごとの残りは PSRAM のプール)。

## 表の中身と置き場所の見込み

基準の表の中身 (F1 の内訳は `report/f1.md` §3.1、F1b の後は `report/f1b.md`) を、ファームで決まるものと
VM ごとに変わるものに分ける。

| 中身 | 端末ごと・VM ごとに変わるか | 置き場所 |
|---|---|---|
| 名前の文字列 (Family mruby のアプリの VM で 4,041 個) | 同じファームなら同じ | flash (順に並べ、二分探索で引く) |
| C の関数 → 名前 | 関数の番地はファームで決まる | flash |
| mrblib の irep → 名前 | irep はファームの定数 (rodata) | flash |
| クラスの写し (起動直後のメソッドと ivar。アプリが変えた差分を見つけるため) | 同じファームなら同じ | flash。または ROM のメソッド表と比べて作る |
| ヒープにできるオブジェクト (クラスなど) のポインタ | VM ごとに違う (プールの番地) | VM ごとに残る: 番号 → ポインタの配列 (32 bit で 4 B × 約 4,000 = 約 16 KB) と逆引き |

見込み: VM ごとの費用は数十 KB (F1 の 64 bit で約 1 MB、F1b の後で約 355 KB)。

## Family mruby の側で要る仕組み

1. **ファームを作るときに表を作る**: 名前と順番はビルドで決まる (`checkpoint_perm.c` の名前の付け方は記号の名前の
   順で、同じビルドなら同じ)。表を C のソースとして書き出し、ファームに一緒にリンクする。C の関数は関数への参照で
   書けば番地はリンカが埋める (リンクの後で書き換えない)。
2. **構成ごとに作る**: sim・ネイティブ版・S3・P4 で入る gem が違うので、表は構成ごとに作る。表を作るには、その
   構成の mruby を一度起動して名前を集める必要がある。ESP32 の構成の名前をどう集めるかが一番の課題:
   - **案 A (ホストで作る)**: ESP32 と同じ gem の組み合わせで、ホスト用の mruby を作って名前を集め、C のソースに
     する。ESP32 にしか無い gem (ハードウェアの port) の扱いが要る (名前だけを持つ代わりのもので足りるか)。
   - **案 B (端末の最初の起動で作る)**: 端末で最初に起動したときに表を作って flash の領域 (専用の区画か
     ファイル) に保存し、2 回目からは読むだけ (ESP32 なら区画を mmap して RAM を使わずに読む)。ファームの版の
     印で古い表を見分けて作り直す。最初の起動だけ時間がかかる。
3. **食い違いを断る**: 表とファームが食い違うと名前の引き当てを誤る。イメージにファームの版の印 (表の版) を
   入れ、違えば断る。
4. **gem の側**: 表を「外から渡された固定のデータ」と「VM ごとの番号 → ポインタ」に分けて読める入口
   (F1b で flash に移りやすい形にしてある前提)。

## 段の位置

- F1b の後、F6 (実機) の前。F2〜F5 (ネイティブ版・sim での受け渡し、窓、端末の間、Asterism) と並べて進めてよい。
- 選ぶこと: 案 A か案 B か (F1b の結果を見て、ユーザが選ぶ)。

## 受け入れ条件 (案)

- ネイティブ版と端末 (P4・S3) で、申告したアプリの VM が払う基準の費用が数十 KB に収まる (32 bit で測る)。
- 内蔵 RAM +0 (`rake regress:size`)。
- 表を flash に置いた形でも、`rake regress:checkpoint` と mruby-checkpoint の試験が通る。
- 表とファームが食い違うイメージは、理由つきで断られる。
