# F4 指示書: 日本語フォントを専用の区画 (1.3 MB) へ移す

> 親: plan.md の段 F4 と未確定事項 4 (1.3 MB に決まった)。前段は report/f01.md (P4 の storage の使用は 6.41 → 4.65 MB)。
> 時間の目安は doc/regression/usage.md 0 章。

## やること

1. **区画の表**: `config/partitions_p4_common.csv` に、フォントの区画 (data、独自の subtype、1.3 MB) を足し、storage を
   その分縮める (8 MB → 約 6.7 MB)。ファームの区画 (0x7F0000) はそのまま。Tab5 と NARYAv4 の両方 (16 MB)。
2. **フォントの像**: 今ファームに入っている日本語フォント (efont 日本語 16 px・12 px・12 px 太字、美咲 8 px。
   `lgfx_efont_ja_*`・`lgfx_misaki_8`) を、ビルドのときに 1 つの像 (版と目次つきの簡単な形式) にまとめる道具を作り、
   区画に書く (rake の flash の対象に加える。ふだんの app_sync では書かない。像が変わったときだけ書く)。
3. **読み方 (P4)**: 起動時に `esp_partition_mmap` でフォントの区画を映し、目次から各フォントのデータの番地を
   LovyanGFX のフォントの構造に渡す (RAM に写さない)。区画が無い・版が合わないときは、分かる言葉でログに出し、
   日本語は美咲など残す最小のもの (ファームに残すかを決めて書く) に落ちる。黙って何も出ない形にしない。
   ファームの中のフォントのデータを外し、ファームの大きさの減りを測る。
4. **sim・ネイティブ版・ブラウザ版**: 同じ像をファイル (ビルドが置く) から読むか、今のままファームに入れておくかを
   決める (sim 系は大きさの制約が無いので、今のままでもよい。P4 との差が出ないことを優先して決め、書く)。
5. **焼き方**: 区画の表が変わるので、最初は全体を焼く (`rake flash:keep_home` で /home を残す)。`flash:app_sync` が、
   区画の表とフォントの区画が端末と合っているかを確かめ、合わなければ止まって keep_home を案内する。

## 確かめること

- `rake regress`・`rake regress:screens` (日本語の出る場面が同じ)・`rake regress:size ALL=1` (P4 のファームの大きさと
  空き、内蔵 RAM の静的な増分 0)。回線は戻っている。
- P4-Nano (親が焼く。シリアル・flash は親): 日本語が出ること (エディタ・デスクトップの日本語・TinyGo の tour の日本語)、
  起動ログのフォントの区画の行。
- 小さな差は理由を書けば止まらない (ユーザ)。

## 触ってよい範囲

- fmruby-core (develop)。graphics-audio は変えない (Retro のフォントは対象外)。sdkconfig を変える必要があれば、変えずに
  提案して止まる。既存の未コミット (components/ のサブモジュール 2 つ、wasm/vendor/) には触らない。シリアル・flash・
  /dev/tty* は使わない。
- コミットは件名 `<種類>(<場所>): <要約>`、英語、Co-Authored-By、pathspec を明示。push しない。基準の更新はしない。

## 止まる条件

- sdkconfig の変更が要る。内蔵 RAM の増分。仕様が変わる選択 (日本語の出方が変わる)。ユーザの作業が要るとき。

## report (report/f4.md)

区画の表、像の形式と道具、読み方、sim 系の扱い、大きさの前後 (ファーム・空き・storage)、焼き方、確かめた結果、
親が P4-Nano で見るログの行。開始と終了の時刻は `date` で書く。終わったら NARYAv4 のビルドを build/ に残す。
