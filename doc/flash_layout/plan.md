# storage を減らし、日本語フォントを専用の区画へ移す計画

> 状態: 計画済 | 更新: 2026-11-16 | P4 の 16 MB はファームの区画 (7.94 MB、空き 8%) と storage (8 MB、使用 6.3 MB) で埋まっている。試験用のアプリを storage に入れず WiFi で送る形にし (F1)、画像と音を小さくし (F2・F3)、空いた分で storage を縮めて日本語フォントの専用の区画を作る (F4)。ファームから約 1.2 MB が抜け、焼く時間とファームの区画の空きが良くなる

## 目的

- 焼く時間を縮める (P4-Nano は CH343・115200 bps で、ファームの区画だけでも約 6 分。P4-Nano には P4 自身の USB の
  口が出ていない)。
- ファームの区画の空き (今 8%) を増やし、WAMR などを足す余地を作る。
- storage の無駄 (試験用のアプリ、圧縮していない画像) を減らす。
- 2026-11-16 ユーザ: 「Test は原則書き込まず、テストで使うときだけ WiFi で転送」「画像と音が思ったより大きい」
  「ファイルシステムを削って、その分をフォントに割り当てる」。

## 今の状態 (2026-11-16 の実測、P4)

| 項目 | 値 |
|---|---|
| ファーム | 7.63 MB / 区画 7.94 MB (空き 8.3%) |
| うち日本語フォント | efont 日本語 16 px 456 KB・12 px 301 KB・12 px 太字 301 KB・美咲 8 px 114 KB (計 約 1.2 MB) |
| storage の像 | 698 ファイル・97 ディレクトリ、データ 4.1 MB、littlefs での使用 約 6.3 MB (4 KB 未満のファイル 483 個が 1 区画ずつ使う) |
| 画像 (`flash/` の下) | BMP 126 個 2,021 KB、PNG 16 個 223 KB、MJPG 113 KB |
| 音 | WAV 8 個 177 KB (16 kHz・16 bit の PCM)、MIDI 58 KB、NSF 49 KB |
| 試験用のアプリ (`app/test`) | 142 ファイル 337 KB |
| littlefs の inline | 既に 512 B まで有効。4 KB の区画では規則で 512 B が上限 (広げると内蔵 RAM が増える) |

- Retro (S3) の画面は子マイコン (WROVER) が描くので、日本語フォントは graphics-audio の側にある。この計画のフォントの
  話は P4 (Tab5・P4-Nano) と sim・ネイティブ版・ブラウザ版。

## 段

| 段 | 内容 | 状態 |
|---|---|---|
| F1 | **試験用のアプリを storage に入れない**: `app/test` を全端末の storage の像から外す (sim・ネイティブ版・ブラウザ版は今の作りを確かめて決める)。回帰の道具と MCP は、実機で要るときだけ WiFi で送る (doc/remote_guard の G0 の `push`・`sync`。開発のビルドは読み書き自由)。送った試験のアプリを後で消すか残すか (未確定事項 1) | 未着手 |
| F2 | **画像を小さくする**: BMP を読む所 (FmrbGfx の `create_image`・`load_image`、スプライト、タイル、graphics-audio への転送) を調べ、PNG に替えるか、圧縮した自前の形式 (RGB332 + 単純な圧縮など) を作るかを決める (未確定事項 2)。読み込みの速さ (麻雀の牌などは起動時にまとめて読む) と内蔵 RAM の増分 0 を守る | 未着手 |
| F3 | **音を小さくする**: 試験用の WAV を F1 で外す。声などの WAV を ADPCM などにするか、標本化の速さを下げるかを、再生の作り (graphics-audio の WAV 再生) を見て決める (未確定事項 3) | 未着手 |
| F4 | **フォントの専用の区画**: F1〜F3 で空いた分で storage を縮め (8 MB → 約 6.7 MB)、その分をフォントの区画 (約 1.3 MB) にする。フォントはファームから外し、`esp_partition_mmap` で映して LovyanGFX にそのまま渡す (RAM を使わない)。sim・ネイティブ版・ブラウザ版はファイルから読む。区画の表 (`config/partitions_p4_common.csv`) が変わるので、最初の 1 回は全体を焼く (doc/remote_guard の `keep_home` で /home を残す)。ふだんの焼き込み (app_sync) はフォントの区画を書かない。フォントの区画の版を確かめ、合わなければ分かる言葉でログに出す (日本語が出ないまま黙って動かない) | 未着手 |

順番は F1 → F2・F3 → F4。F4 は storage を縮めるので、F1〜F3 で使用が十分減ってから。

## 受け入れ条件

- F1: 実機の storage の像に `app/test` が無い。回帰の道具 (`regress:boot` など実機を使うもの) と MCP が、要る試験のアプリを
  WiFi で送ってから使う。sim の回帰 (screens・run・checkpoint・live) は今までどおり通る。
- F2・F3: 同じ見た目・同じ音で、大きさが減る。読み込みの時間が増えない (起動ログで比べる)。
- F4: P4 のファームの区画の空きが 2 割前後になる。日本語が今までどおり出る (sim・ブラウザ版・P4)。app_sync で焼く時間が
  縮む。内蔵 RAM の静的な増分 0。
- どの段も `rake regress`・`regress:screens`・`regress:size` (回線が戻ってから)。
