## 2. 入れる道

### walk_scroller

App Store には今は載せられない。理由: (1) App Store は `/app/usr/<id>/` に入れるが、walk_scroller は絵を
`/usr/share/sprites/walk_scroller` の決まったパスから読む (アプリの直しが要る)、(2) 載せるには別のリポジトリ
(family-mruby-apps) への push が要る。よって WiFi の道具で入れる:

```
ruby tools/fmrb_rd_fs.rb <IP> extra walk_scroller            # 入れる (無いか大きさの違うものだけ、23 ファイル 717 KB)
ruby tools/fmrb_rd_fs.rb <IP> extra walk_scroller --remove   # 消す
MCP: tab5_fs action: "extra" / "extra_remove", names: ["walk_scroller"]
```

ランチャーの一覧には右クリックで読み直した後に出る。`extra` は `flash/` の下のパスも取る (`extra usr/share/...`)。

### 試験のアプリ (F1)

```
ruby tools/fmrb_rd_fs.rb <IP> tests push [名前...] [--reserve KB] [--flash DIR]
ruby tools/fmrb_rd_fs.rb <IP> tests ls
ruby tools/fmrb_rd_fs.rb <IP> tests clean
ruby tools/fmrb_rd_fs.rb <IP> df [path]
MCP: tab5_fs action: "tests_push" (names) / "tests_clean" / "tests_ls" / "df"
```

- 名前は `.app.rb` の前の部分 (`ckpt_counter` は `ckpt_counter.app.rb`・`.app.toml` とその名前の付いた物全部)。
  省くと `flash/app/test` 全部。送るのは無いか大きさの違うものだけ。
- 未確定事項 1 の決定どおり: 続けて試験する間は残し、まとまりの終わりに `tests clean` が `/app/test` ごと消す
  (像に無いので、そこにあるのは全部送った物)。送ると空きが 512 KB (`--reserve`) を切るときは、先に今回要らない
  試験のファイルを送った時刻の古い順に消す (端末の `/app/test/.pushed.json` に時刻を残す)。それでも足りなければ
  送らずに止まる。
- 空きは新しい口 **`GET /fs/df?path=`** (`{"ok":true,"total":N,"free":N}`、devctl_http.c。`fmrb_hal_file_statfs`
  = `esp_littlefs_info`) で見る。この口の無いファーム (今の P4-Nano を含む) では「空きを見ない」と 1 行出して送る。
  口の数: Modern の rd_http は 25 / 28、Retro の devctl_task は 17・20 (checkpoint あり) に上げた。

## 4. 減った量

端末ごとの storage の像。CMake の staging と同じ手順 (`flash/` の写し、var/cache・tmp の始末、Retro の services と声の
除外、除外の一覧) を scratchpad の台本で作り、ビルドと同じ `littlefs-python create --block-size=4096 --name-max=64` で
区画の大きさの像にして、使用ブロック数を数えた。`flash_local/` (手元の私物の重ね) は入れていない
(手元の実際の P4 のビルドは前で 698 ファイル・4.25 MB・6.41 MB 使用。差は flash_local の NSF と声 18 ファイル)。

| 端末 (区画) | ファイル 前 → 後 | データ 前 → 後 | littlefs の使用 前 → 後 | 減った使用 |
|---|---|---|---|---|
| Tab5・NARYAv4 (8 MB) | 680 → 504 | 3.77 MB → 2.38 MB | 5.87 MB (70%) → 4.10 MB (49%) | -1.76 MB |
| NARYAv3 (5 MB)・Atom Display (4.9 MB) | 621 → 468 | 2.41 MB → 1.72 MB | 4.30 MB (82% / 86%) → 3.32 MB (63% / 66%) | -0.98 MB |
| StickS3・AtomS3R (2496 KB) | 356 → 214 | 1.08 MB → 0.73 MB | 2.31 MB (91%) → 1.72 MB (67%) | -0.59 MB |

(MB は 1,000,000 B ではなく 1,048,576 B。小さい端末の差は `app/test` と試験の音だけ。)

## 6. 実機 (P4-Nano) の通し

WiFi の道具だけで行った (シリアル・flash は使っていない。/home には触っていない)。端末は焼き直していない
(G0 のファーム。`/fs/df` は無い)。音は先に mute。

1. `tests clean`: 古い像が入れていた `/app/test` (144 項目) を消した (17 秒)。F1 の像と同じ状態にするため。
2. `tests push ckpt_counter step_sensor`: 「/fs/df が無いので空きを見ない」と出て 4 ファイル 19 KB を送った (1 秒)。
   2 回目は送る物 0。
3. `tab5_app launch /app/test/step_sensor.app.rb` → 画面に Step Sensor の Window (WiFi ok・AST ok・0 歩・no IMU) →
   kill。
4. `tests clean`: 6 項目を消し、`/app` に `test` が無いことを確かめた。
5. `extra walk_scroller`: 古い像が入れていたので送る物 0 (23 ファイル一致)。消していない。

**今の P4-Nano には `/app/test` が無い** (F1 の像を焼いた後と同じ)。試験のアプリが要るときは `tests push`。

## 7. ESP32 のビルド

`FMRB_HW_TARGET=NARYAv4` で `rake clean_all` → docker の `idf.py set-target esp32p4` → littlefs の venv を写す →
`rake build:esp32` (3 分ほど)。**本体の checkout の `build/` に残した** (焼くのは親)。`.env` は触っていない。

| 項目 | 値 |
|---|---|
| `file build/fmruby-core.elf` | ELF 32-bit RISC-V |
| DIRAM (内蔵 RAM の静的な使用) | **124,876 B** (G0 と同じ。増分 0) |
| `fmruby-core.bin` | 7,632,256 B (G0 の 7,629,952 B から +2,304 B。`/fs/df` と、G0 の後に入った W1c の変更の合計で、分けていない) |
| storage の像 (`build/storage_root`、flash_local を含む) | 698 → **524 ファイル**、データ 4.25 MB → 2.86 MB、littlefs の使用 6.41 MB → **4.65 MB** (8 MB の 55%) |
| 像の中身 | `app/` に `test` 無し、背景は 426x240・640x360 の 2 種だけ、`sounds/` に sine440 無し、`sprites/walk_scroller` 無し |
| 新しい警告 | devctl・rd_http に無し |

- 焼くなら app と storage の両方が変わっている。`flash:keep_home` (WiFi で /home を退避) が使える。全体を焼いた後、
  `/fs/df` が答えること (`ruby tools/fmrb_rd_fs.rb <IP> df`) と、`tests push` で「空きを見ない」が出ないことを見る。
- 残した小さな試験の物: `usr/share/sprites/test/tilesheet.bmp` (3 KB、`app/test/draw_tile_test` だけが使う)。
  `tests push` は `app/test` だけを送るので、外すと draw_tile_test が実機で動かなくなる。小さいので残した。
