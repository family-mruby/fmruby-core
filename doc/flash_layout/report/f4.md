# F4 報告: 日本語フォントを専用の区画へ移す

> 開始 2026-11-16 11:21 (JST) / 終了 2026-11-16 12:01 | 指示書: ../instruction_f4.md | 親: ../plan.md の F4 (未確定事項 4 の決定: 1.3 MB)

## 0. 要約

- P4 (Tab5・NARYAv4) の efont 日本語 3 本 (16 px・12 px・12 px 太字、計 1,083,758 B) をファームから外し、新しい区画
  **font_ja (data・subtype 0x40・0x150000 = 1.3125 MB、flash の最後)** に置いた。storage は同じ番地のまま 8M → **0x6B0000 (6.69 MB)**。
- **ファーム 7,636,432 B → 6,555,904 B (-1,080,528 B)。app の区画の空き 8% → 21%** (受け入れ条件の「2 割前後」)。
- 起動時に区画を `esp_partition_mmap` で映し、目次から各フォントの番地を `lgfx::U8g2font` に渡す (RAM に写さない)。
  **内蔵 RAM の静的な使用は 124,876 B のまま (増分 0)**。置き場の変数はすべて PSRAM の bss。
- **美咲 8 px はファームに残した** (区画が使えないときの落ち先。2 章)。区画が無い・版が違う・目次が壊れているときは
  理由と直し方 (keep_home) をログに出し、日本語は全部の大きさを美咲 8 で描く。
- sim・ネイティブ版・ブラウザ版・S3 の自前の画面の端末は、今までどおりフォントをプログラムに入れる (4 章)。
- `flash:app_sync` (rake・MCP) は焼く前に端末の区画の表とフォントの像をビルドと比べ、違えば何も焼かずに keep_home を
  案内して止まる。**今の P4-Nano は F4 の前のファームなので、最初は keep_home で全体を焼く**。

## 1. 区画の表 (`config/partitions_p4_common.csv`、Tab5・NARYAv4 共通)

| 名前 | 種類 | 番地 | 大きさ | 前 |
|---|---|---|---|---|
| nvs | data/nvs | 0x9000 | 24K | 同じ |
| phy_init | data/phy | 0xF000 | 4K | 同じ |
| factory | app | 0x10000 | 0x7F0000 | 同じ |
| storage | data/littlefs | 0x800000 | **0x6B0000** (7,012,352 B) | 8M |
| **font_ja** | data/**0x40** | **0xEB0000** | **0x150000** (1,376,256 B) | (無し) |

- storage は番地を変えず後ろを削った。font_ja を後ろに置いたので、古い表のまま新しいファームを app だけ焼いた場合も
  storage はそのまま読め、フォントは「区画が無い」で美咲 8 に落ちる (壊れない)。
- 区画の大きさは決定どおり 1.3 MB に近い 64 KB の倍数にした。像は 1,083,882 B で、292,374 B (約 285 KB) 余る
  (美咲 8 を入れても 117 KB で収まる)。

## 2. 像の形式と道具

道具は **`tools/font_ja/font_ja_image.rb`** (標準ライブラリだけ)。M5GFX の `lgfx_efont_ja.c` の配列 (C の文字列リテラルと
8 進のエスケープ) を読み、宣言の大きさ (末尾の NUL を含む) のまま並べる。

```
0   char[8]  "FMRBFONT"
8   u16      形式の版 (1)
10  u16      フォントの数
12  u32      像の大きさ
16  u32      CRC-32 (24 バイト目から像の終わりまで)
20  u32      0
24  数 x { char 名前[24] (NUL 埋め), u32 番地, u32 大きさ }
..  フォント (4 の倍数の番地)
```

| 名前 | 番地 | 大きさ |
|---|---|---|
| efont_ja_16 | 120 | 467,155 B |
| efont_ja_12 | 467,276 | 308,265 B |
| efont_ja_12_b | 775,544 | 308,338 B |

- 像の CRC は 073960f8。**F3 のファーム (efont を含む ELF) の `.flash.rodata` から取り出した 3 本と、像の 3 本がバイト単位で同じ**
  ことを確かめた。
- 元の C は `main/idf_component.yml` が固定する M5GFX の版 (0.2.36) のもの。`managed_components/` がその版ならそれを、
  無ければ GitHub から `tmp/font_ja/src/` へ 1 度取る。
- `rake font_ja:image` が `tmp/font_ja/font_ja.bin` を作る (中身が同じなら書かない、0.5 秒)。`rake build:esp32` は P4 で
  `FMRB_FONT_JA` が 0 でないとき、configure の前にこれを呼ぶ (ビルドのコンテナに Ruby が無いため。checkpoint の表と同じ形)。
- トップの `CMakeLists.txt` が像を `build/font_ja.bin` へ写し、`esptool_py_flash_target_image(flash font_ja ...)` で
  **`idf.py flash` (全体) にだけ** 加える。app-flash には入らない。`build/flash_args`・`flasher_args.json` に
  `0xeb0000 font_ja.bin` が載るので、`flash:keep_home`・`keep_home_serial` (flash_args を使う) も書く。
  像が無い・区画より大きい・区画が無いときは configure で止まる。
- `rake font_ja:test` (`rake test` に入れた): ファームの読み手 (`font_ja_image.c`) をホストの cc で作り、道具が作った像で
  開く・引く・壊れた像 (消去済みの区画、版違い、区画より大きい、目次が外を指す、名前の NUL が無い) を確かめる。手元に
  本物の像があればそれも引いて道具の答えと比べる。C のリテラルの読み (8 進は 3 桁まで、宣言の大きさまで NUL 埋め) も。

## 3. 読み方 (P4)

`main/drivers/display_local/fonts/font_ja/`:

| ファイル | 役 |
|---|---|
| `font_ja.h` | `font_ja_init()`・`font_ja_get(id)` (C++)・`font_ja_flash_status()` |
| `font_ja_image.{h,c}` | 像の頭と目次の検査・名前で引く (素の C、ホストの試験と同じもの) |
| `font_ja_partition.cpp` | P4: 区画を探して `esp_partition_mmap` (区画全体、DATA)、目次を検査、3 本を `U8g2font` にする |
| `font_ja_builtin.cpp` | それ以外: M5GFX の `fonts::efontJA_*` を返す (`FMRB_FONT_JA=0` なら何も返さない) |

- `display_local_task_init()` の頭で `font_ja_init()` を呼ぶ (表示のタスクが最初の SET_FONT を受ける前)。
- 起動時に CRC は回さない (1 MB を flash のキャッシュ越しに読むと起動が遅れる)。魔法の語・版・大きさ・目次の範囲だけを見る。
  CRC は `/status` で報告し、app_sync が比べる。
- `U8g2font` の置き場 (3 個) とポインタ・状態は `FMRB_EXT_RAM_BSS_ATTR` (PSRAM)。フォントの本体は映した flash を直接読む
  (前もファームの rodata を flash のキャッシュ越しに読んでいたので、描く速さの差は無い見込み)。
- 表示のタスクの SET_FONT は `font_ja_get()` が nullptr なら美咲 8 (`FMRB_NO_FONT_JA` の枝はこの形にまとめた。挙動は同じ)。

### 区画が使えないとき

| 場合 | ログ (TAG font_ja、E) |
|---|---|
| 区画が無い (古い表) | `no font_ja partition (an older partition table): Japanese is drawn in misaki 8 only. Flash the whole image once (rake flash:keep_home).` |
| 魔法の語が無い (消去済み・書いていない) | `no font image in the partition: Japanese is drawn in misaki 8 only. Flash the whole image (rake flash:keep_home).` |
| 版が違う | `the font image is another format version (vN, this firmware reads v1): ...` |
| 目次が壊れている・区画より大きい | `the font image's directory is broken: ...` など |
| 目次に名前が無い | `the font image has no efont_ja_16: that size is drawn in misaki 8.` (その大きさだけ) |

- **決めたこと (仕様は変えていない)**: 落ちたときは表示の側だけが美咲 8 にし、Ruby の側 (`FmrbConst::FONT_JA`・`set_font` の答え) は
  今の true のまま。`FONT_JA` は Spinel では生成時の定数で、起動時の状態に合わせるにはカーネル・デスクトップ・エディタの
  参照を呼び出しに直す必要があり、焼き損ないの時だけの経路にしては大きいため。結果、落ちたときの日本語は 12・16 px の
  桁に 8 px の美咲で描かれ (字間が空く)、黙って何も出ない形にはならない。直し方はログと app_sync が言う。
- 美咲 8 はシステムの UI (ハイブリッドの 8 px) が常に使うので、ファームに残すのが自然と判断した。

## 4. sim・ネイティブ版・ブラウザ版

**今のままプログラムに入れる** (`font_ja_builtin.cpp`)。理由:

- sim の画面は graphics-audio が描く (フォントは graphics-audio の側にあり、この段では触らない)。
- ネイティブ版・ブラウザ版は大きさの制約が無い。ブラウザ版で像をファイルから読むには束に 1 MB を足して起動時に読む
  経路が要り、差を生む場所が増える。
- P4 との差が出ないこと: 像のフォントは M5GFX の配列とバイト単位で同じ (2 章で確かめた) で、LovyanGFX に渡す型
  (`U8g2font`) も同じなので、描かれる字は同じ。読み手の検査・引き方はホストの試験 (`font_ja:test`) で回る。
  表示のタスクの選び方 (`font_ja_get` → 無ければ美咲) は全端末で同じコード。
- S3 の自前の画面の端末 (AtomS3R・StickS3) も同じ builtin (既定で `FMRB_FONT_JA=0`、区画は無い)。

## 5. 大きさの前後

| 項目 | 前 (F3 のビルド) | 後 |
|---|---|---|
| `fmruby-core.bin` | 7,636,432 B | **6,555,904 B** (-1,080,528) |
| app の区画 (0x7F0000) の空き | 8% | **21%** (0x1AF700 = 1,767,168 B) |
| DIRAM (内蔵 RAM の静的な使用) | 124,876 B | **124,876 B** |
| storage の区画 | 8,388,608 B | 7,012,352 B |
| storage の littlefs の使用 (この PC の像、flash_local を含む) | 1,021 区画 = 4.18 MB (49.9%) | 1,021 区画 = 4.18 MB (**59.6%**)、空き 2.83 MB |
| font_ja の区画 | 無し | 1,376,256 B に像 1,083,882 B |

- map で efont の 3 本 (`.rodata.lgfx_efont_ja_*`) は捨てられた節 (番地 0) になり、美咲 8 (`lgfx_misaki_8`、117,554 B) は残っている。
- storage の使用は `build/storage.bin` を littlefs-python で開いて数えた (538 ファイル、2.87 MB のデータ)。

`rake regress:size ALL=1` (基準 4e7e7e61 との比較、13.9 分、ok):

| 端末 | DIRAM | app の像 | app の区画の空き |
|---|---|---|---|
| NARYAv3 | 125,395 B (-64) | 5,560,496 B (+346,624) | 730,960 B (12%) |
| TAB5 | 129,394 B (-304) | 6,578,736 B (-110,192) | 1,744,336 B (**21%**) |
| NARYAv4 | 124,876 B (-320) | 6,555,904 B (-110,160) | 1,767,168 B (**21%**) |
| STICKS3 | 114,463 B (-64) | 5,318,656 B (+295,248) | 448,512 B (8%) |
| ATOMS3R | 114,099 B (-64) | 5,304,048 B (+295,408) | 463,120 B (8%) |

- 内蔵 RAM はどの端末も基準より増えていない。基準 (4e7e7e61) はこの段より前のもので、P4 の app の像の「-110 KB」は
  efont の -1.08 MB とその間の他の段の増分 (libmruby +152 KB ほか) の合計。S3 の増分はこの段とは関係ない (NARYAv3 は
  この段のコードを含まない。StickS3・AtomS3R は `font_ja_builtin.cpp` が入るだけで、FMRB_FONT_JA=0 なので efont を参照しない)。
  基準は更新していない。

## 6. 焼き方

区画の表が変わったので、**最初の 1 回は全体を焼く** (`/home` は WiFi で退避して戻す):

```
cd fmruby-core
FMRB_HW_TARGET=NARYAv4 rake flash:keep_home HOST=<P4-Nano の IP>   # または MCP flash の keep_home: true
```

- 全体の焼き込みは bootloader・表・app・storage・**font_ja** を書く (`build/flash_args` に 5 つ)。
- その後のふだんの `flash:app_sync` (rake・MCP) は焼く前に `tools/fmrb_flash_keep.rb layout` を呼び、端末の `/status` の
  `layout` と `font_ja` をビルドの `partition-table.bin`・`font_ja.bin` と比べる。違えば (または F4 の前のファームで
  `layout` が無ければ) 終了コード 4 で止まり、keep_home を案内する。S3 のビルド (font_ja の区画が無い) は比べない。
- 今の P4-Nano (F3 のファーム) に対して `layout` を流した結果 (読むだけ): 「the board's firmware does not say its flash
  layout (it predates the font partition) ... Flash the whole image once, keeping /home」で exit 4 (期待どおり)。
- 焼いた後の `/status` に出るはずの値: `"layout":"storage@0x800000+0x6b0000,font_ja@0xeb0000+0x150000","font_ja":"v1 crc=073960f8"`。
- 焼く時間: app は 1.08 MB 減ったので、CH343・115200 bps の app だけの焼き込みは前 (約 6 分) の 86% ほどになる見込み (測っていない)。
  フォントの区画はふだんは書かない。

## 8. P4-Nano で親が見ること

1. 上の keep_home で全体を焼く。
2. 起動ログに `font_ja: partition at 0xeb0000 (1344 KB): image v1, 3 fonts, 1083882 bytes, crc 073960f8` (I)。
   `Japanese is drawn in misaki 8 only` (E) が出ないこと。
3. 日本語が今までどおり出ること: デスクトップのメニュー・ランチャーの日本語、エディタ (日本語の 12・16 px)、TinyGo の tour の
   日本語。字が 8 px の美咲に変わっていたら区画が読めていない (ログの E の行を見る)。
4. `ruby tools/fmrb_flash_keep.rb layout <IP> --build fmruby-core/build` (family-mruby で) が
   `layout: the board's partitions and font image are this build's (v1 crc=073960f8)` を出すこと (以後 app_sync が通る)。
5. `M1|` の行・`IRAM free:` が F3 と同じ程度であること (内蔵 RAM は静的に増えていない。映す処理のハンドルは起動時に少しだけ heap を使う)。

## 9. 残り・決めること

1. **リリースの installer**: 全体の焼き込みに `font_ja.bin` (0xEB0000) が要る。family-mruby の
   `.github/scripts/stash-core-build.sh` は `fmruby-core.bin`・`storage.bin` と `flasher_args.json` を写すが `font_ja.bin` を写さない。
   installer の staging (このリポジトリに無い) が `flasher_args.json` の全部を焼く作りか確かめ、P4 の束に `font_ja.bin` を
   足す必要がある。触っていない (リリースの手順はユーザの判断)。
2. 区画が使えないときの Ruby 側 (`FmrbConst::FONT_JA`) を起動時の状態に合わせるか (3 章の決めたこと)。今は表示だけが美咲に落ちる。
3. 実機での確認 (8 章)。
4. sdkconfig は変えていない。
