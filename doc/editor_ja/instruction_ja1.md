# 実装指示書 JA1: エディタ日本語対応 (J1 メニュー i18n + J2 日本語表示)

対象: 実装担当セッション。前提: エディタ P1-P5 完了。plan.md (このディレクトリ)
を先に読むこと。report は report/ja1.md へ。タスクごとにコミット。
J3 (折り返し) と J4 (かな入力) は本指示書の範囲外 (次フェーズ)。

## 進め方の約束

- エディタ P1-P5 と同じ (doc/editor_serious_mode/instruction_p1.md 冒頭 +
  p2 の Spinel カーネル注意)。
- エディタは単一ソース二重バックエンド。**標準構成 (Spinel editor) と
  互換構成 (mruby editor) の両方で各タスクを検証**する。
- 言語切替のテスト: config/system_conf_linux*.toml の `language = "ja"` を
  一時的に変えて sim を再起動する (設定ダイアログ経由でも可)。en/ja 両方の
  スクリーンショットを report に。
- 新しく Ruby ファイルをエディタの連結対象に足す場合は、**mruby 側の
  バイトコード連結 (gen_combined_rb 経路) と Spinel 側の
  gen_app_combined.rb の両方**に入れること (debug_pane の除外と混同しない)。

## T1 (= J1): メニューの i18n 化

### 実装

1. エディタ用の翻訳テーブルを追加する (en/ja)。キーの目安:
   file / edit / search / run / hilight / debug / full /
   open / save / save_as / template / exit / find / find_next /
   quit_confirm 系のダイアログ文言。既存の system_desktop/i18n.rb と
   重複するキー (save / cancel / close 等) は流用して良いが、エディタ VM の
   テーブルは別登録が必要 (FmrbI18n.add。テーブルは VM ごと)。
2. メニューバーの固定配置 (`x += N*CHAR_W`) を
   `w = FmrbI18n.text_width(label)` ベースの累積配置に変え、各項目の
   x と幅を ivar に保存。マウスヒットテスト・ドロップダウンの原点
   (menu_origin)・ドロップダウン幅 (MENU_*_W 固定値と menu_width) を
   保存した幅から算出する形に置換する。
3. ラベル描画を `mixed: true` 化。アクセラレータ表示は現在の
   「先頭 1 文字を色分け」(draw_menu_item の "F"+"ile" 分割) が日本語で
   成立しないため、**「ファイル(F)」形式** (ラベル + 括弧付きキー文字) へ
   変更する。en でも同形式 ("File(F)") に統一して良い (実装が単純になる)。
   ホットキー自体はスキャンコード表 (MENU_*_HOTKEYS) なので**無改修**。
4. ドロップダウン項目・検索ダイアログ・終了確認ダイアログ・ステータス行の
   固定文言も i18n キー化する (このタスクではラベル置換のみ。編集領域には
   触らない)。

### 受け入れ条件

- language=en / ja でメニューバー・ドロップダウン・ダイアログが切り替わる
  (両言語のスクリーンショット)。
- ja 表示でメニューのクリック位置が正しい (ヒットテストが幅に追随)。
- Alt ホットキー・スキャンコードホットキーが両言語で従来どおり効く
  (Alt は sim で死んでいるので、その分は実機確認待ちに明記)。
- editor_fs (全画面) でも同様に動く。両エンジン、S3/P4 ビルド通過。

## T2 (= J2): 日本語表示 — 2 セルモデル

### 前段: gfx 基盤の既存バグ 3 件を先に直す (別コミット)

1. **draw_text の 127 バイト無言切り捨て**: FMRB_GFX_MAX_TEXT_LEN を
   128 → 256 に (components/fmrb_gfx/fmrb_gfx.h)。リンク層は 255 まで
   許容するのでプロトコル変更は不要。gfx_cmd_t が太る分のキューメモリ増
   (深さ x 128B) を report に記録。併せて cmd_copy_bytes
   (fmrb_gfx_cmd.c) の切り捨てを **UTF-8 境界で切る**よう修正 (壊れた
   マルチバイト末尾を送らない)。
2. **FONT_METRICS の幅誤り** (lib/add/picoruby-fmrb-app/mrblib/fmrb-gfx.rb):
   [:ja,8] / [:ja,12] は「半角幅 / 全角幅」のデュアル幅である事実を
   モデル化する (half_w フィールド追加等)。実測: misaki = 半4/全8、
   efont = 半6/全12。text_width も半角/全角で正しく数える。
3. **FmrbI18n.text_width の半角カナ誤り**: U+FF61-FF9F は 4px (hybrid 時)。

この 3 件は desktop 等の既存利用者に影響し得るので、デスクトップの
メニュー/ランチャー表示に退行が無いことを必ず確認する。

### editor-core: セル幅マップ API の追加

- `ec_render_width(y, col0, max_cols)` を追加: ec_render_hl と同じ
  「1 文字 1 バイト」形式で、各文字のセル幅 (1 or 2) を返す。
- 判定はコードポイント範囲で East Asian Wide 相当を 2 セルとする。
  最低限: U+1100-115F / U+2E80-A4CF / U+AC00-D7A3 / U+F900-FAFF /
  U+FF00-FF60 / U+FFE0-FFE6 → 2、**U+FF61-FF9F (半角カナ) → 1**、
  それ以外 → 1。採用した範囲表を report に記す (完全な Unicode 準拠は
  不要。表示に使うフォントが持つ範囲で正しければ良い)。
- mruby / Spinel 両バインディングに追加 (P5 のスロット化 3 層構成に従う。
  EditorCore の FFI 宣言は専用ファイルへ — 共有 FFI に入れるとリンクが
  壊れる件は report/p5.md 参照)。

### エディタ本体: 2 セルモデル化

- 編集領域 + ステータス行を `set_font(:ja, 12)` 固定にする。
  セル幅 CELL_W=6、行高 LINE_H=12。**半角 = 1 セル、全角 = 2 セル**
  (efont は厳密な 6px/12px なのでピクセルずれ無し)。表示行数の減少
  (Retro 全画面 27→18 行) は許容 (plan.md 3.1 の決定)。メニューバーは
  T1 の 8px hybrid のままで良い (混在レイアウトの整理は実装判断。
  recompute_layout に一元化すること)。
- **二重座標系の分離**: @cx / EditorCore は文字インデックスのまま
  (無改修)。エディタ側だけが ec_render_width の接頭和で cell ↔ char
  変換を行う。対象: カーソル描画位置と幅 (全角上は 2 セル幅)、選択矩形、
  マウスクリック → 文字位置 (行内走査で良い。行は高々百数十文字)、
  水平スクロール (@scroll_x は「左端の文字インデックス」のまま、描画時に
  セル換算。左端で全角が半分欠ける場合は 1 文字送るか空白で埋める —
  どちらにしたか report に)。
- 描画: 編集領域の draw_text を :ja フォント下で行う (ハイライトの
  色区間分割 draw_highlighted_line も同様)。**1 回の draw_text が
  255 バイトを超えないよう分割する** — 半角カナは 1 セル 3 バイトなので、
  106 セル行が最悪 318 バイトになり新上限 256 でも溢れる。色区間分割が
  既にあるので、その中で長さ上限も見る形が素直。
- ハイライト: トークナイザ (Prism) は UTF-8 を通るので、日本語コメント/
  文字列を含む .rb で色と桁がずれないことを確認する。

### 受け入れ条件

- 日本語 (漢字/かな/半角カナ/ASCII 混在) のサンプル .rb を開いて:
  正しく表示・カーソル移動 (全角上で 2 セル幅)・選択・コピー/ペースト・
  検索 (日本語クエリ)・保存 → 再読込で内容不変。スクリーンショット。
- **長い日本語行 (全角 60 文字以上) が行末まで描かれる** (127B バグ修正の
  実証)。
- 横スクロールで全角混在行の桁がずれない。
- 英語のみのファイルで従来表示 (可読性・列数) と操作に退行がないこと。
  edit_lat: の退行が無いこと (ja 表示時の数値も report に)。
- デスクトップ表示 (前段修正の影響範囲) に退行なし。
- 両エンジン、Linux/S3/P4 ビルド通過。実機の見え方はユーザ確認待ち。
