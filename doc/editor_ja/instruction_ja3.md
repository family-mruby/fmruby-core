# 実装指示書 JA3: かな入力 (J4)

対象: 実装担当セッション。前提: JA1/JA2 完了 + stale statics 根本修正済み。
設計の根拠は plan.md 3.3。report は report/ja3.md へ。タスクごとにコミット。

## 方針 (決定済み)

- **入力はかなのみ** (ひらがな/カタカナ)。漢字変換 (辞書 IME) は作らない。
- 出力は**全角かなのみ** (半角カナは出さない。ユーザ決定 2026-08-11)。
- **ローマ字 2 打変換**。かな刻印の JIS かな配列直接入力はやらない (v1)。
- character フィールド (1 バイト) は変えず、**確定かなを UTF-8 バイト列に
  分解して複数のキーイベントとして送る** (案 A)。

## T1: かな合成層 (host_task)

### 置き場所と有効条件

- **host_task の文字変換点 (fmrb_keymap_scancode_to_char 呼び出しの直後)**
  に合成層を挿す。全入力デバイス (USB / Tab5 内蔵 / I2C / remote desktop /
  SDL) が一括で対象になる合流点はここだけ。
- 有効条件: keyboard_layout が jp のときのみ合成層が動く (us では完全に
  素通し)。かなモード自体は下記トグルで on/off。

### トグルキー

- **半角/全角キー (scancode 0x35) でかなモード on/off**。現在キーマップで
  {0,0} と捨てられている空き枠 (fmrb_keymap.c:117 付近)。
- かなモード中の**カタカナ ⇔ ひらがな切替はカタカナひらがなキー
  (scancode 0x88)**。無いキーボード向けの代替 (例: Shift+半角/全角) を
  1 つ決めて report に記す。
- トグルキー自体のイベントはアプリへ流さない (合成層で消費)。

### ローマ字変換

- BASIC の実装 (components/basic/core/basic_screen.cpp の kana_translate
  一族) を**仕様の出発点**として移植し、出力を Unicode コードポイント
  (ひらがな U+3041〜 / カタカナは +0x60) に差し替える。
- 最低限サポートする組: 五十音 (あ〜ん)、**濁音・半濁音は合成済み
  コードポイント** (が = U+304C。結合文字は使わない)、拗音 (きゃ 等 =
  子音+y+母音)、促音 (っ = 子音重ね)、ん (nn および n+子音)、長音 (-)、
  BASIC 準拠の補正 (J→Z 行、F→H 行)。BASIC に無い組を足した/落とした
  場合は差分を report に一覧すること。
- 句読点・記号: かなモード中の `,` `.` は 、 。 を出す。それ以外の記号は
  ASCII のまま (v1)。
- **未確定の子音はバッファ 1 文字だけ** (2 打で確定するのが基本)。
  画面フィードバック (preedit 表示) は v1 ではやらない (plan 3.3)。
  Esc またはモード off で保留子音は破棄。

### イベントの出し方 (ここが要)

- **scancode / keycode は常に素通しする**。合成層が触るのは character の
  生成だけ。ゲーム類はスキャンコードで読むので、かなモード中でも
  矢印・WASD 等が従来どおり動くこと (これを受け入れ条件にする)。
- かなモード中、ローマ字に使ったキーの **ASCII の character は出さない**
  (a を押しても 'a' は流れない)。かなが確定した時点で、その UTF-8
  バイト列 (3 バイト) を**バイトごとに key イベントとして連続送出**する
  (scancode/keycode は 0 で良い。既存アプリは 32..126 で弾くため無害)。
- Enter / BS / Tab / 矢印等の制御キーはかなモードでも従来どおり。
  BS は「保留子音があればそれを消す、無ければ普通に BS を流す」。

## T2: エディタ側の受け (UTF-8 アキュムレータ)

- on_event の key_down 処理で、character >= 0x80 のバイトを UTF-8
  アキュムレータに溜め、1 文字完成した時点で EditorCore.insert_text へ
  渡す (JA2 の引継ぎどおり、表示・カーソル・折り返しは無改修で受かる)。
  不完全なまま別種イベントが来たら破棄 (壊れた文字を入れない)。
- **検索ダイアログにも同じ受けを入れる** — これで JA1 から持ち越しの
  「日本語クエリでの検索」が初めて検証可能になる。
- 共通化: アキュムレータは 1 実装を handle_key 系と検索入力の両方から
  使う形にする。
- **かなモードの状態表示**: 子供が今どのモードか分かるよう、エディタの
  ステータス行に [A] / [あ] / [ア] を表示する。モード変化の伝達方法は
  実装に任せる (案: 合成層がモード変化時に専用 subtype の HID イベントを
  HID target へ送り、アプリが ivar に持つ。既存アプリは未知 subtype を
  無視するので無害)。採った方式を report に。

## T3: 検証ツールの追随

- sim の注入ツール (tools/fmrb_input.rb) にトグルキーの名前 (例:
  `key zenkaku` / `key katakana`) を追加し、**かな入力の自動検証を
  スクリプトで再現できる**ようにする (`text "ka"` → か、の類)。
- ルートの CLAUDE.md のキー一覧に追記。

## 受け入れ条件 (すべて sim、標準構成 + 互換構成)

1. 半角/全角でかなモード on/off、ステータス行の表示が追随する。
2. `ka ki ku ke ko` → かきくけこ。`ga`→が、`kya`→きゃ、`kka`→っか、
   `nn`→ん、`n`+子音→ん+子音、`,` `.`→、。カタカナモードで同様。
3. 入力したかなが折り返し・カーソル・選択・保存/再読込で正しく扱われる
   (JA2 の表示基盤に乗ることの確認)。
4. **日本語クエリの検索が動く** (かなで打って検索、混在行でヒット位置が
   正しい。JA1 持ち越しの解消)。
5. かなモード中でもゲーム (raycaster 等、スキャンコード読み) の操作が
   従来どおり効く。shell 等の ASCII 前提アプリは、かなモード off なら
   完全に従来どおり (on のまま shell に切り替えた場合の挙動も確認し、
   困る点があれば report に)。
6. us レイアウト設定では合成層が完全に素通し (一切の挙動変化なし)。
7. 両エンジン、Linux/S3/P4 ビルド通過。実機 (実キーボードの半角/全角キー、
   Tab5 内蔵キーボード) はユーザ確認待ちに明記。

## 範囲外

- 50 音タッチパレット (将来候補のまま)。
- BASIC 内蔵のかな入力 (別系統のまま触らない)。
