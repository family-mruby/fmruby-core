## T1: かな合成層

### 置き場所

`main/kernel/host/host_task.c` の `fmrb_keymap_scancode_to_char()` 呼び出し
直後、`fmrb_msg_send` でアプリへ送る前。合成の本体は
`main/drivers/usb/fmrb_kana.c` (キーマップの隣) に分けた。

ここが**全入力デバイスの唯一の合流点**なので、USB / Tab5 内蔵 / I2C /
remote desktop / SDL のどれも自動的に対象になる。有効条件は
`fmrb_keymap_get_layout() == JP` の 1 行だけで、us レイアウトでは合成層を
そもそも呼ばない。

### トグル

| 操作 | scancode | 動作 | 使える環境 |
|---|---|---|---|
| **Ctrl+Space** | 0x2C+Ctrl | かなモード on/off | **どこでも** |
| 半角/全角 | 0x35 | かなモード on/off | **jp 配列のときだけ** |
| カタカナひらがな | 0x88 | ひらがな ⇔ カタカナ (かなモード中) | JIS キーボード |
| **指示器のクリック** | - | A → あ → ア → A の巡回 | **どこでも** (タッチ含む) |

半角/全角と Ctrl+Space は**修飾キーを一切見ない**。半角/全角を jp 配列に
限るのは、US キーボードではその scancode が `` ` `` の実キーだからで、
奪うと文字が打てなくなる。

当初は「Shift+半角/全角 でひらがな⇔カタカナ」をカタカナキーの無い
キーボード向けの代替として入れていたが、**off に戻れなくなる罠**だったので
撤去した (下記「修正: 半角/全角が効かなくなる」)。その代わりが
Ctrl+Space とクリックで、こちらは下記「US キーボード対応」。

0x35 は JP キーマップで `{0, 0}` (文字なし) として捨てられていた枠なので
衝突しない。0x88 はキーマップ上は `]` になっているが、**かなモード中だけ**
奪うので、モード off のときの `]` は従来どおり。どちらもトグルとして
消費し、アプリへは流さない。

### 変換表の最終仕様と BASIC との差分

出発点は `components/basic/core/basic_screen.cpp` の `kana_translate` 一族。
**BASIC 側は一切触っていない** (別系統のまま)。

BASIC から引き継いだ規則:

- 子音は母音が来るまで保留、五十音 13 行 (清音 + 濁音 + 半濁音) と
  や行 / わ行の欠けた枠。
- `nn` → ん。
- **J → Z 行 / F → H 行**の読み替え (`ji`=じ, `fu`=ふ)。
- 保留中に母音以外が来たら保留を捨ててそのキーを解釈し直す。

**追加したもの** (BASIC に無い):

| 追加 | 例 | 理由 |
|---|---|---|
| 出力が Unicode | あ=U+3042 | BASIC は自前の画面文字コード。濁音・半濁音は**合成済みコードポイント** (が=U+304C。結合文字は使わない) |
| カタカナモード | `ka`→カ | ひらがな U+3041-U+3096 に +0x60。長音・句読点は変換しない |
| 拗音 | `kya`→きゃ | イ段 + 小書き (ゃぃゅぇょ) |
| 促音 | `kka`→っか | 同じ子音の連打で っ を確定し、子音は保留したまま |
| ん + 子音 | `kanji`→かんじ | BASIC は保留 n を**捨てて**いた。エディタでは落とせない |
| 長音 | `-`→ー | |
| 句読点 | `,`→、 `.`→。 | それ以外の記号は ASCII のまま (v1) |
| ヘボン式の二重字 | `shi chi tsu ja` | 下記 |
| 半角カナ | 出さない | ユーザ決定 (2026-08-11)。全角かなのみ |

**ヘボン式の二重字について**: 学校で習う訓令式 (`si ti tu sya zya hu`) は
BASIC の表だけで全部通る。一方キーボードで実際に打たれるヘボン式は
2 打規則のままだと誤変換になる (`sha`→さ、`ja`→ざ、`tsu`→す) ので、
**`sh` / `ch` / `ts` / `j` の 4 つだけ**を二文字子音として足した:

```
sha shi shu she sho -> しゃ し しゅ しぇ しょ
cha chi chu che cho -> ちゃ ち ちゅ ちぇ ちょ
tsu                 -> つ        (tsa 等は無効)
ja  ji  ju  je  jo  -> じゃ じ じゅ じぇ じょ
cya                 -> ちゃ
```

`shi` / `chi` / `ji` はイ段そのもの (小書きを付けない) という例外つき。
`ca` のような組は音節が無いので**何も出さない**。

**落としたもの**: なし。

**保留バッファ**: 指示書は「1 文字だけ」だったが、拗音 (`kya`) と上記の
二重字 (`shi`) はどちらも**子音 2 文字**を保留しないと成立しないので、
**子音 1 文字 + 二文字目 (`y`/`h`/`s`) の 2 枠**にした。3 文字以上は無い。
Esc とモード切替で破棄、BS は「二文字目があればそれだけ、無ければ子音を
消す」(下記)。preedit 表示は v1 では出さない (plan どおり)。

### イベントの出し方

- **scancode / keycode は常に素通し**。合成層が触るのは `character` だけ。
- かなモード中、ローマ字に使ったキー (a-z と `,` `.` `-`) は
  `character = 0` にして送る。キーイベント自体は消さないので、
  スキャンコードで読むアプリからは何も変わらない。
- かなが確定したら、その UTF-8 3 バイトを **1 バイト 1 イベント**で、
  scancode = keycode = 0 のキー押下として先に送る。**確定分を先に**送るのは、
  「n の保留を確定させつつそのキー自身も意味を持つ」場合
  (`kanji` の後のスペース) に順序が逆にならないため。
- Ctrl / Alt が押されている組み合わせは合成層を通さない
  (Ctrl+S 等がかなモード中も従来どおり効く)。
- BS は**保留があればそれを消してイベントを消費**、無ければ素通し。
  Esc は保留を捨てて素通し。

### モード変化の伝達方式

**専用の HID subtype を足した** (`HID_MSG_KANA_MODE = 9`,
`fmrb_hid_kana_mode_event_t {subtype, mode}`)。合成層がモードを変えた
ときだけ HID target へ 1 通送る。

- 共通デコーダ `fmrb_hid_event.c` に 1 ケース追加し、mruby (`app.c`) /
  Spinel (`fmrb_app_base_spinel.rb`) / MicroPython (`fmrb_module.c`) の
  3 バインディングが同じように `{type: :kana_mode, mode: n}` を作る。
- **既存アプリは未知の type として素通しする**ので影響なし。
- ポーリングを足さずに済み、アプリ側は ivar 1 個で状態を持てる。

**デスクトップにも届ける** (ユーザ指示 2026-08-11): かなモードは
「フォーカス中のアプリ」ではなく**機械全体の状態**なので、どこからでも
見えないと意味がない。host_task はモード変化を HID target と**カーネル
(PID 0) の両方**へ送り、カーネルは HID target でない場合にかぎり
デスクトップへ転送する (`input_router.rb`。2 バイトなのでマウス前提の
サイズ検査より手前で捌く)。宛先を知っているのはカーネルなので、
host_task はデスクトップの PID を知らずに済む。

短所: **フォーカスが移ったアプリは現在のモードを知らない** (次のトグルまで
アプリ側のバッジが出ない)。ただしメニューバーの表示は常に正しいので、
実害は「エディタを開いた直後、まだステータス行に出ない」だけになった。

## T2: エディタ側の受け

- `utf8_feed(byte)` / `utf8_reset` の 1 実装を、**本文入力 (`handle_key`) と
  検索ダイアログ (`handle_search_dialog_key`) の両方**から使う。
  0x80 以上のバイトを溜め、1 文字揃った時点で String を返す。
  key_down 以外のイベントが割り込んだら破棄する (壊れた文字を入れない)。
- 表示・カーソル・折り返し・選択・保存は JA2 の基盤に**無改修で乗った**
  (EditorCore は文字単位・UTF-8 対応済み)。
- 検索ダイアログはクエリを `mixed: true` で描き、キャレット位置を
  文字数ではなく**ピクセル幅** (`FmrbI18n.text_width`) で置くようにした。
  これで JA1 から持ち越しの「日本語クエリでの検索」が初めて成立する。
- ステータス行の右端に `[A]` / `[あ]` / `[ア]`。**右詰め**にしたのは、
  240px 幅の窓では左から積むと画面外に出て見えなかったため。
  ホストからモードを 1 度も聞いていない間 (us キーボード) は**出さない**。

### デスクトップのメニューバー表示 (ユーザ指示による追加)

かなモードは全体状態なので、**エディタの外にいる間も見えるように**
メニューバー右側 (空きメモリ表示の左) に指示器を置いた。BLE 表示と同じ
作りで、灰箱 + 白 `A` = ASCII、白箱 + 反転かな = かな入力中。
ホストがモードを 1 度も言ってこない間 (us レイアウト) は何も描かない。

これが無いと**モードが on であることに気づく手段がエディタ内にしか無く**、
実際に検証中、エディタを閉じた後デスクトップで `e` を押しても反応せず
(かなモードが on のままで `e` が「え」に食われていた) 原因究明に時間を
使った。子供にはまず分からない。

### かなモード中の他アプリへの影響

当初、**かなモード on のままだとエディタの「Unsaved changes [Y]es [N]o」に
`n` が届かなかった** (`n` は保留子音になる)。**ユーザ指示により、エディタの
モーダルは character ではなく scancode で判定するようにした** (追加コミット。
0x1C=Y / 0x11=N / 0x06=C / 0x29=Esc)。合成層は scancode を素通しするので、
これでかなモード中でも Y/N/C が従来どおり効く。

副産物として **Esc でのキャンセルが初めて効くようになった**。キーマップは
Esc に文字を割り当てていないので、旧コードの `when 27` (character) は
Linux でも実機でも一度も発火していなかった。

エディタの他のモーダルは元から scancode 判定だった (ドロップダウンの
頭文字ホットキー `menu_hotkeys`、検索ダイアログの Enter/ESC、
デバッガの attach ピッカー)。**検索ダイアログの文字入力だけは character の
ままで正しい** (そこは打った文字そのものが要る)。

残る影響:

| 読み方 | かなモード on での挙動 |
|---|---|
| scancode で読む (ゲーム全般、エディタのモーダル・メニュー) | **影響なし** |
| `character` の英字で読む | 届かない。**該当は system_desktop の 1 文字ショートカット** (`handle_shortcut`: デスクトップで `e` を押すとエディタ、等) と shell の入力。**モードはメニューバーに出ているので、気づけないことはなくなった** |
| 数字・記号・Space・Enter・BS・矢印・Ctrl 系 | 従来どおり |
| `character` >= 0x80 | 従来 0 件。エディタだけが解釈する |

デスクトップのショートカットは「メニュー項目名の頭文字」を動的に引く作り
なので、scancode 化には文字→scancode の逆引き表が要る。かなモードを切って
から押す / アイコンをクリックする、で回避できるため今回は触っていない
(**ユーザ判断待ち**)。アプリ切替で自動的にかなモードを off にする案も
あるが、「エディタに戻ったら消えている」ほうが煩わしいので採らなかった。

## 修正: 半角/全角で off に戻れなくなる (ユーザ報告 2026-08-11)

**症状**: 半角/全角 → ひらがな、かなキー → カタカナ、のあと
**半角/全角を押しても A に戻らず、かなキーでもひらがなに戻らない**。

**原因**: 初版は Shift+半角/全角 をひらがな⇔カタカナの切替に割り当てて
いた。JIS キーボードの**カタカナは かなキーの上段 (Shift 側) の刻印**なので、
Shift を押しながらカタカナにした流れでそのまま半角/全角を叩くと、
`0x35 + Shift` = script 切替になり、**かな/カナを往復するだけで off に
到達できない**。かなキーもその往復に噛み合うので、両方効かないように見える。

sim で再現・修正後を実測 (エディタのステータス行):

| 操作 | 修正前 | 修正後 |
|---|---|---|
| 半角/全角 → かなキー | あ → ア | あ → ア |
| **Shift+半角/全角** | **あ** (off に行かない) | **A** |
| さらに かなキー | ア (往復) | (off なので無反応) |

**修正**: **半角/全角は修飾キーを一切見ない**。かな入力を切るキーは、
何が一緒に押されていようが、どの状態からでも切れなければならない。

あわせて、モード変化時に **`kana mode=N (sc=.. mod=..)` を INFO ログに
出す**ようにした。「トグルキーが効かない」という報告は、合成層が実際に
何を受け取ったか (修飾キー込み) が分からないと切り分けられないため。

**副作用**: カタカナひらがなキー (0x88) を持たないキーボード
(US 配列を jp 設定で使う等) は、ひらがな⇔カタカナの切替手段が無くなった。
キーボード非依存のトグルは `doc/tab5_keyboard/instruction_k1.md` (Ctrl+Space)
の担当なので、そちらで script 切替も一緒に決めるのが筋。

## US キーボード対応 (ユーザ指示 2026-08-11)

### 問題

かな合成層は `keyboard_layout == jp` のときだけ動いていた。US キーボードの
人が日本語を打つには設定を jp にするしかなく、そうすると**記号のキートップ
が全部ずれる** (`[` を押すと `@`、Shift+2 が `"` …)。カタカナ切替が無い
ことより、こちらのほうが実害が大きい。

一方で**ローマ字入力自体は US 配列で何も問題ない**: a-z と `,` `.` は
US/JP で scancode も文字も同一だからである。jp 設定にする必要は本来ない。

### 直した形

**「配列設定 = 記号表」「かな入力の可否 = トグルキーが押されたか」に分けた**。

1. 合成層は**レイアウトに関係なく動く**。かなモードが off の間は全キーが
   素通しなので、us 配列の挙動は従来どおり (受け入れ条件 6 は維持)。
2. **半角/全角 (0x35) を奪うのは jp 配列のときだけ**。US 配列では
   `` ` `` の実キーなので触らない。
3. **Ctrl+Space をどの配列でも効く on/off に追加**。US キーボードでも
   Tab5 内蔵キーボード (半角/全角キーが無い) でも、これ 1 つで入れる。
   合成層の Ctrl 除外 (Ctrl+S 等を守るための素通し) **より手前**で判定する。
4. **モード指示器を押せるようにした**。エディタのステータス行の
   `[A]/[あ]/[ア]` と、デスクトップのメニューバーの指示器を、どちらも
   クリックで A→あ→ア→A と巡回させる。キーの暗記が要らず、**Tab5 の
   タッチでも使える**。0x88 を持たないキーボードのひら⇔カナ切替はこれ。

指示器は **language=ja なら起動時から表示**する (押せることが分からないと
入口にならないため)。en では従来どおり、かなモードを一度使うまで出ない。

### モードを外から設定する経路

`fmrb_host_set_kana_mode(mode)` (host_task.h) を新設。合成層のモードを
設定し、フォーカス中のアプリとカーネル (→デスクトップ) に通知する。
アプリからは `FmrbApp.set_kana_mode(n)` で、**mruby (app.c) と
Spinel (fmrb_spx_app.c + ffi) の両方に足した**。標準構成は
デスクトップ=mruby / エディタ=Spinel なので、**この構成 1 つで両方の
バインディングが実際に使われる**。

## 修正: sim で半角/全角が 1 回おきにしか効かない (ユーザ報告 2026-08-11)

**症状**: Linux sim で半角/全角を押すとかなになるが、もう一度押しても戻らない。
かなキーも同様。「中途半端に効いている」。Ctrl+Space とクリックは正常。

**原因**: 追加した診断ログ (0x35/0x88 の全イベント) が一発で答えを出した:

```
20:14:09.559 host: kana key sc=0x35 down mod=0x00 -> mode=1
20:14:13.692 host: kana key sc=0x35 up   mod=0x00 -> mode=1
```

**down と up が 4.1 秒離れており、その間に何も無い**。つまりこれは 1 回の
押下ではなく、**押下 1 回目 = KEYDOWN、押下 2 回目 = KEYUP**。X11 はこの
2 キーを**ロックキー**として扱い、1 回の押下につき 1 イベントしか出さない
(型が交互に変わる)。ファームは USB の流儀 (1 押下 = 1 key_down) なので、
2 回に 1 回が丸ごと無視されていた。

**修正場所は sim (sdl2-display)**。理由:

- **実機の USB キーボードは普通に down/up 対を出す**。ファーム側の規則は
  正しく、X11 の癖をファームに持ち込むべきではない。
- **注入ツールの経路 (drain_inject_events) は down/up 対**なので、ファームで
  「両エッジで 1 回」にすると自動検証が二重トグルで壊れる。sim の SDL
  イベント経路だけを直せば両方成立する。

`process_sdl_events` の 0x35 / 0x88 だけ、単発イベントを**完全な 1 押下
(down+up)** に組み立て直す。正常な down/up 対とロックキーの 2 押下は
**イベント列としては区別できない**ので、判定は down からの経過時間
(400ms) で行う。400ms 以上押しっぱなしにすると押下が 2 回になるが、
対象はこの 2 キーだけで、2 回トグルは打ち消し合うだけ。

修正コミット: fmruby-graphics-audio `49d5514`。
**適用には `docker compose build sdl2-display` が要る**。

診断ログ (`kana key sc=.. down/up mod=.. -> mode=..`) は残した。今回これが
無ければ「届いていない」のか「届いて無視された」のか切り分けられなかった。

## 日本語対応 (J1-J4) の総括

| 段階 | 内容 | commit |
|---|---|---|
| J1 | メニューの i18n | JA1 `0692956` |
| J2 | 日本語表示: efontJA_12 + 「1 文字 = 1 または 2 セル」 + 既存バグ 3 件 | JA1 `ff51e9d` `7c84a1e` |
| J3 | 行の折り返し + クリックでカーソル + 漢字語彙 | JA2 `b9c53f8` |
| J4 | かな入力 | JA3 `c6584dc` `84fe2bd` |

**結果**: エディタは日本語を打てて、正しい幅で表示して、折り返して、
クリックで位置を合わせて、日本語で検索できる。UI は en/ja 両方。

**効いた設計判断**:

1. **「1 文字 = 1 または 2 セル」を EditorCore (C) 側に置いた**。
   幅の判定が 1 箇所なので、折り返し・クリック・選択・カーソルが
   全部同じ答えを見る。表示だけ後から直す形にしていたら破綻していた。
2. **character フィールドを広げなかった**。1 バイトのまま複数イベントに
   割ったので、HID を読む既存 20 箇所と 3 バインディングが無改修で済んだ。
3. **合成層を host_task の 1 点に置いた**。入力経路が 5 つあるのに、
   実装も有効条件 (jp レイアウト) も 1 箇所で済んでいる。
4. **scancode を触らないと決めた**。これでゲームがかなモードの影響を
   受けないことが設計として保証され、受け入れ条件にもできた。

**途中で分かった地雷** (他の作業でも刺さるもの):

- efontJA_12 には**半角カナの字形が無い** (12px で描かれて桁がずれる)。
  JA2 で `cp_cells` を 2 に直した。今回「全角かなのみ出す」と決めたのは
  この実測が根拠。
- `FmrbI18n.add("en" => {...})` は Spinel では kwargs になって届かない。
  **波括弧を明示**する (JA1)。
- 同じ Spinel プログラムを 2 回目に起動すると SEGV する生成器のバグを
  JA2 で踏み、`stale_statics` で根本修正した (fork `c7de66c`)。
  エディタは「繰り返し起動される唯一の Spinel プログラム」なので、
  日本語対応をやらなければ当分見つからなかった。
