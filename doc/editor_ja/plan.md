# エディタ日本語対応計画: 子供が使える編集環境

作成: 2026-08-11。状態: 計画 (実装未着手)。
関連: doc/editor_serious_mode/plan.md (P1-P5 完了済みの土台の上に載る)。

## 1. 目的とスコープ

エディタを子供にも使ってもらえるようにする:

- **入力はひらがな / カタカナのみ** (ローマ字 2 打)。**漢字変換 (辞書 IME) は
  持たない** — 表示は漢字も出るが、入力はかなに限る、という線引き。
- **表示は漢字を含む日本語全般** (大人が用意したサンプル・テンプレート・
  コメントを読める)。
- **メニュー等の UI はシステム言語設定 (en/ja) に追従**。
- **行の折り返し** (長い行を横スクロールではなく画面内に畳む)。

## 2. 現状調査の結果 (2026-08-11。詳細な file:line は調査時の記録参照)

### 揃っているもの

- **日本語フォントは 3 ターゲット (Modern/Retro/sim) 完備で描画経路も同一**:
  misaki 8x8 (半角 4px / 全角 8px) と efontJA_12 (半角 6px / 全角 12px)。
  どちらも半角・全角のデュアル幅。デスクトップのメニュー/ランチャー/
  設定ダイアログは既に日本語表示で動いている (mixed: true 描画 26 箇所、
  表示デモ flash/app/demo/ja_text.app.rb あり)。
- **i18n 機構は既存**: FmrbI18n.t(key) + en/ja テーブル
  (system_desktop/i18n.rb)、言語は system_conf の language (設定ダイアログ
  から変更、再起動で反映)。picoruby-fmrb-app 同梱なのでエディタ VM から
  追加ロード無しで使える。editor: キーは登録済み。
- **editor-core (P4) は最初から UTF-8 文字単位**で、文書モデルは無改修で
  日本語対応済み。MRB_UTF8_STRING も全ビルド有効。
- **かな変換の前例**: Family BASIC 内にローマ字 2 打→かな変換表が実装済み
  (basic_screen.cpp。出力が BASIC 内部コードなので表の移植が必要)。

### ギャップ

1. エディタのメニューは英語ハードコード + 固定ピクセル位置。
2. エディタの編集領域が「1 文字 = CHAR_W(6px) 1 セル」前提で、日本語は
   文字化け (mixed: 未指定) + 桁ズレする。折り返しも無い (横スクロールのみ)。
3. かな入力の仕組みが (BASIC 内部を除き) 存在しない。character は
   1 バイト固定。

### 調査で見つかった既存バグ (J2 で直す)

- **draw_text の 127 バイト上限で無言切り捨て** (FMRB_GFX_MAX_TEXT_LEN=128、
  cmd_copy_bytes が UTF-8 境界を見ずに切る)。全角 42 文字で行が切れる。
- fmrb-gfx.rb の FONT_METRICS が [:ja,8] の ASCII を 8px と誤申告
  (実測 4px)。text_width が倍になる。
- FmrbI18n.text_width が半角カナ (U+FF61-FF9F、実測 4px) を 8px 扱い。

## 3. 設計

### 3.1 表示: efontJA_12 + 「1 文字 = 1 または 2 セル」モデル (J2)

エディタの編集領域を `set_font(:ja, 12)` 固定にし、セル幅 6px で
**半角 = 1 セル、全角 = 2 セル**の古典端末モデルにする。

- efont は半角ちょうど 6px / 全角ちょうど 12px の**厳密な 1:2 整数比**。
  既存の CHAR_W=6 グリッドがそのまま生きる。misaki 案 (4px セル) は ASCII の
  可読性が悪く、混合プロポーショナル案はカーソル/選択/マウス→桁の全計算が
  前方走査になるため採らない。
- 漢字 12x12 は子供の読みやすさの点でも望ましい。代償は行高 8→12px で
  表示行数 2/3 (Retro 全画面 27→18 行)。**段階 5 の 640x360 と好相性**
  (106 セル x 30 行) なので、実機が戻ったら統合を検討。
- **二重座標系を明示的に分離する**: EditorCore は文字インデックスのまま
  (無改修)、エディタ側だけが cell ↔ char 変換を持つ。
  - editor-core に **`ec_render_width` (1 文字 1 バイトのセル幅マップ)** を
    追加する。既存 ec_render_hl と同じ形。判定はコードポイントの
    East Asian Wide 範囲 + 半角カナは 1 セル。
- カーソルは全角上で 2 セル幅。選択矩形・マウス→桁・水平スクロールは
  セル幅マップの接頭和で計算。
- 付随修正: FMRB_GFX_MAX_TEXT_LEN を 256 へ (リンク層は 255 まで許容する
  のでプロトコル変更不要。gfx_cmd_t が 128B 太る分のキューメモリ増は許容)、
  cmd_copy_bytes を UTF-8 境界で切る、FONT_METRICS / FmrbI18n.text_width の
  幅バグ修正、編集領域の draw_text を mixed または :ja 固定で統一。

### 3.2 行の折り返し (J3)

**成立する。難しさの正体は「全行の画面行数を大域的に数えようとすると全文
再計算になる」ことで、これは以下の 2 点で回避する**:

1. **折り返し計算は行単位で editor-core (C) に置く**。
   `ec_wrap_segments(y, view_cells)` = その行をセル幅 view_cells で折った
   ときの区切り (文字インデックス列) を返す。計算は 3.1 のセル幅マップの
   接頭和で、C なら 1 行あたり数 µs。行ごとにキャッシュし、編集・
   リサイズ・フォント変更で無効化。2 セル文字を行末で割らない。
2. **スクロールをアンカー基準にする**: 画面の先頭を「絶対画面行番号」では
   なく **(論理行, 区分番号) のアンカー**で持つ。描画は アンカーから
   画面行数ぶんだけ順に区分を消費すれば良く、**全文の画面行数合計は
   一切必要ない**。カーソル上下・PageUp/Down・ensure_cursor_visible も
   アンカーからの相対で閉じる。スクロールバー等で全体比率が欲しい場合は
   論理行ベースの近似で足りる (v1 はそれで良い)。

- dirty 管理は既存の mark_dirty_from と同型:「行の区分数が変わったら
  その行以下を再描画」。1 行編集で区分数が不変なら、その行の区分だけの
  再描画で済む。
- 行番号ガター: 論理行番号を先頭区分にだけ表示 (継続区分は空白または
  折返し記号)。
- **折り返しは ON/OFF 切替** (メニュー)。OFF = 従来の横スクロール。
  既定は ON (子供向けの主目的)。
- v1 では単純な文字単位折り返し。単語境界折返し・禁則処理 (行頭の
  「。」等) はやらない (将来、ec_wrap_segments 内の判定追加で対応可能な
  設計にしておく)。

### 3.3 かな入力 (J4)

- **合成層は host_task の文字変換点 (全入力デバイスの合流点、1 箇所) の
  直後に置く**。USB / Tab5 内蔵 / I2C / remote desktop / SDL が一括対応。
- **トグルは半角/全角キー (scancode 0x35)**。現在キーマップで意図的に
  捨てられている空き枠で、衝突しない。かなモード中の Shift 等の扱いは
  実装時に決める。ひらがな ⇔ カタカナの切替キーも用意する
  (カタカナひらがなキー scancode 0x88 が候補)。
- **ローマ字 2 打変換**: BASIC の変換表を移植し、出力を Unicode
  コードポイントへ差し替える。「n の後に子音 → ん」「っ (子音重ね)」
  「ゃゅょ」も BASIC 実装に準拠。
- **1 バイト固定の character フィールドは変えない**。確定したかなを
  UTF-8 バイト列に分解し、**1 バイトずつ複数のキーイベントとして送る**
  (案 A)。既存の consumer 20 箇所は 32..126 で弾いているため全部無改修で
  安全。受け側はエディタだけが >= 0x80 のバイトを UTF-8 アキュムレータで
  組み立てて EditorCore.insert_text へ渡す。
- 未確定ローマ字の画面フィードバック (k を打った時点の表示) は v1 では
  やらない (2 打で確定するので実害が小さい)。将来: preedit イベント種別の
  追加、または Tab5 タッチ向けの 50 音パレット (キーマップ非依存、
  Ruby のみで完結) を検討。

### 3.4 メニューの i18n (J1)

- editor 用の翻訳テーブルを追加登録 (FmrbI18n.add。VM ごとのテーブル
  なので desktop 分とは別に要る): file / edit / search / run / hilight /
  debug / full / open / save / save_as / template / exit 等。
- メニューバーの固定配置 (x += N*CHAR_W) を text_width ベースの累積配置に
  変え、幅を保存してヒットテスト・ドロップダウン配置・幅計算に流用。
  描画は mixed: true 化。
- アクセラレータ表示は「F」+「ile」分割方式が日本語で成立しないため
  「ファイル(F)」形式へ。**ホットキーはスキャンコード表でラベルと独立
  しているため無改修**。
- 言語切替は現行仕様どおり再起動で反映。

## 4. 段階計画 (指示書は段階ごとに逐次発行)

| 段階 | 内容 | 依存 | 備考 |
|---|---|---|---|

- 全段階 Linux sim で完結 (実機不要)。エディタは単一ソース二重バックエンド

  検証**する。
- 検証素材: flash/app/demo/ja_text.app.rb (表示)、日本語コメント入りの
  サンプル .rb、かな入力は sim のキー注入 (fmrb_input.rb) で自動化できる。

## 5. 範囲外

- 漢字変換 (辞書 IME)。方針として持たない。
- 単語境界の折り返し・禁則処理 (v1 は文字単位)。
- Family BASIC の文字コード系 (独自キャラジェネ) との統合。
- 言語のランタイム切替 (現行の再起動反映のまま)。
- 50 音タッチパレット (将来候補として記録のみ)。
