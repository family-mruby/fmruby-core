### games の 1 件の失敗 (3.4 と無関係)

`TestMahjongGames#test_four_human_hanchans` の `assert_operator sum["multi_human_calls"], :>, 0` (Expected 0 to be > 0)。人 4 人の半荘を 1 回 (`MJ_HUMAN_GAMES` の既定 1) 打ち、2 人以上が同時に鳴ける場面が 1 度も無いと落ちる。牌山と席が `SecureRandom` 由来で seed では再現しない (同じ seed で 3.4.11・3.2.6 とも通った)。この試験だけを 20 回ずつ流すと、3.2.6 も 3.4.11 も 0 は出ず、値の分布 (4〜26) も同じ。まれな「1 局も重ならない」引きで、Ruby の版と関係しない。直していない (直すなら `MJ_HUMAN_GAMES` を増やすか、0 のとき打ち直すかで、試験の意図に関わるので親とユーザの判断)。

### 3.4 の変更点で引っかかったもの

- **Hash#inspect の形・エラーの文の引用符**: どの試験も落ちなかった (asterism の決まりは自前の文、各試験も inspect の文字列を比べていない)。
- **bundled gem への移動**: `require "base64"` は root の tools/ (fmrb_web.rb・fmrb_zenoh.rb・MCP サーバほか) と console の `lib/relay/room_token.rb`・`room_door.rb` にある。bundler の外 (tools/、console の signer と ws_door) では同梱の base64 が読め、bundler の下 (Rails) では Gemfile.lock に base64 がある (Rails 経由)。どれも問題なし。
- **image の土台が Debian 13**: asterism-zenoh の拡張の組み立て、sqlite3 (games 2.10.0 / SQLite 3.54.0、console 2.9.6 / SQLite 3.53.2) とも通った。
- **RubyGems 3.6 の bundler の自動切り替え** (下の 4 章): console の image が起動しなくなった。3.4 で壊れたのはこれだけ。

## 4. 直したもの

### console の image が起動しない (Errno::EACCES on Gemfile.lock)

- 症状: 3.4.11 で作った image で `bin/rails db:prepare` が `Bundler::PermissionError` (`/app/Gemfile.lock` の `File.utime` で EACCES) で落ちる。`bin/rails server`・`bin/bridge`・`bin/asterism` (config/boot を読むもの) が全部同じ。
- 原因: Ruby 3.4 の RubyGems 3.6 は Gemfile.lock の `BUNDLED WITH` (4.0.6) の bundler に自動で切り替える。3.2.6 の image では image 同梱の bundler 2.4.19 がそのまま動いていた (0.3.10 の image で `bundle -v` → 2.4.19 を確認)。bundler 4.0.6 は frozen でない bundle では、lock の中身が同じでも `bundler/setup` のたびに lock を touch する (`Definition#write_lock`)。lock は root の持ち物で、rails (1000) は touch できない。
- frozen (`BUNDLE_FROZEN`) にする手は使えなかった: image の中で `ASTERISM_GEMS=rubygems` として解き直した lock は asterism・asterism-zenoh の CHECKSUMS が空で、frozen だと `Bundler::ProductionError` になる。
- 直し方: `deploy/vps/Dockerfile` の最後の `RUN` で `chown rails:rails Gemfile.lock` を足した (理由のコメントつき)。振る舞いは変わらない (3.2.6 の image と同じく起動するだけ)。signer (1001) と ws_door は bundler を読まないので関係しない。
- 確認: 作り直した image で `bin/rails db:prepare` → 使い捨ての利用者を作成 → `bin/rails server -b 0.0.0.0`。`/up` 200、`/` 401 (未ログイン)、`/session/new` 200。中で `bin/rails runner` から asterism 0.8.0 を読み、zenoh の peer セッションが開けた。`ruby bin/signer`・`ruby bin/ws_door` も起動した (base64 込み)。

ほかのリポジトリの試験は 3.4 で 1 件も落ちず、コードの直しは無い。
