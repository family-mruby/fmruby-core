## T1: コメント埋め込み toml

### 実装形

`main/app/fmrb_app_spawner.c` に `load_inline_toml()` を追加し、
`spawn_user_app()` のサイドカー読み込みの**後段**に置いた。

1. 対象は `.rb` のみ (拡張子で判定)。
2. `fmrb_hal_file_read` で先頭 512 バイトだけ読む。作業用の 512B x2 は
   `fmrb_sys_malloc` から取る (この関数はカーネルの深い呼び出しの先で
   動くので、既存コードと同じくスタックに置かない)。
3. 行単位で走査する。フェンス開始前は空行とコメント行だけ許し、
   **最初の非コメント行に当たったら探索を打ち切る**。
   `#---fmrb` 行 (以降は空白のみ) で本文に入り、`#---` 行で閉じる。
4. 本文の各行は行頭の `#` と続く空白 1 個を剥いで別バッファに積み、
   最後に **既存の `toml_parse()` にそのまま渡す**。新しい文法は無い。
5. 512 バイト窓の途中で行が切れた場合はそこで打ち切る (推測しない)。

`spawn_user_app()` 側は `config` の入手元が `.toml` か
コメントかを `config_from_comment` で覚えているだけで、**属性反映の
コードは 1 本のまま共用**している。したがって窓モード / large_memory /
task_stack_kb / resizable / fullscreen 等は `.toml` と同じキーが同じに効く。

例外は `app_screen_name` で、コメント側にあっても警告して無視する
(ランチャー表示系は `.toml` 限定という線引き。起動時スキャンが全 `.rb` を
開く事態を避けるため)。

### shell の `run` も直した (指示書に無い必要な追随)

`shell_commands.rb` の `detect_run_mode` は「`.toml` サイドカーがあれば
spawn、無ければ sandbox 実行」だった。このままではフェンス付きファイルが
**shell の VM 内で実行され、属性が一切効かない**。フェンスが開いている
`.rb` も spawn 扱いにする判定を足した (spawner と同じ 512 バイト窓・
同じ「最初の非コメント行で打ち切り」規則)。

### 事前確認の結果 (指示書の宿題)

**`.toml` 無しの `.app.rb` はランチャーに出ない**。
`system_desktop/launcher.rb` の `scan_app_dir` は `.toml` ファイルを
列挙して、そこから対応する script 名を導く作りで、`.rb` 単独は
走査対象に入らない (`launcher.rb:366` 付近)。

これは M1 の「ランチャー表示系メタデータは `.toml` 限定」という方針と
整合しているので**そのままにした**。フェンスだけのアプリの入口は
shell の `run`、ファイル管理、エディタの F5 になる。ランチャーにも
出したいならサイドカーを置く (フェンスと併用した場合はサイドカーが勝つ)。

## T3: /tmp RAM FS

### 構成

| 面 | 実体 |
|---|---|
| esp32 | `components/fmrb_hal/platform/esp32/fmrb_tmpfs_esp32.c` — POOL_ID_TMPFS を裏に持つ RAM FS を `esp_vfs_register("/tmp", ...)` で登録 |
| posix | `components/fmrb_hal/platform/posix/fmrb_tmpfs_posix.c` — `flash/tmp` に割り当て、起動時に空にする + 同じ容量上限を課す |
| 共通 | `components/fmrb_hal/fmrb_tmpfs.h` (`fmrb_tmpfs_init` / `fmrb_tmpfs_usage`)。両方とも `fmrb_hal_file_init()` から呼ぶ |

esp32 側で esp_vfs にしたのは、**この機械でファイルに触る経路が全部
libc 越しだから**。Ruby の File/IO と Dir、spawner、エディタ
(EditorCore の load/save)、transfer_file が、`/tmp` の存在を知らないまま
そのまま動く。`fmrb_hal_file_esp32.c` 側の変更は 3 行だけ:

- `s_path_aliases` に `{ "/tmp", "/tmp" }` (flash の下に畳まれないように)
- `/` の仮想 children に `"tmp"` を追加 (`ls /` に出る)
- `fmrb_hal_file_init` から `fmrb_tmpfs_init()` を呼ぶ

VFS 実装は open/close/read/write/lseek/fstat/stat/unlink/rename/
truncate/ftruncate/fsync/access/opendir/readdir(_r)/telldir/seekdir/
closedir を持つ。`mkdir`/`rmdir` は `ENOTSUP` を返す (下記)。

### プールサイズの根拠

```
FMRB_MEM_POOL_SIZE_TMPFS  = 512KB   (POOL_ID_TMPFS、PSRAM)
FMRB_TMPFS_CAPACITY_BYTES = 448KB   (ファイル内容として配る量)
```

- 専用プールにした理由は editor-core (P4) と同じ。アプリの mruby プール
  (500KB) に置くと**そのアプリの終了で消える**うえファイルサイズの上限に
  なり、SYSTEM 500KB は各種ドライバの共有財布なので大物を置けない。
- 512KB は **S3 基準**。S3 の PSRAM 残は 3.2MB で、うち 1MB は
  editor_doc が取っている。P4 は 20MB 以上空いているので、定数は
  ターゲット別に上げられるよう `FMRB_MEM_POOL_SIZE_TMPFS` 単独で持たせた。
- 配る量を 448KB に絞ったのは、割り当てヘッダと各ファイルの伸長余白
  (512B 単位) を吸わせるため。**書き込みの途中で確保に失敗するより、
  書く前に「満杯」を返すほうがアプリ側で受け止めやすい**。

### 意図的に付けた制約: /tmp は平ら (サブディレクトリ無し)

RAM FS 側を 1 段の名前表だけにしたので `/tmp/a/b.txt` は作れない。
posix 側にも同じ拒否を入れてある (`fmrb_tmpfs_path_too_deep`) ので、
**sim で通ったものが実機で通らない、という穴は開けていない**。

### 容量計上 (posix 側)

sim でも「満杯」を再現するため、`flash/tmp` 配下の書き込みバイト数を
数えている。ハンドルごとに「この文字列のうち既に計上済みのバイト数」を
持ち、書き込み位置がそれを超える分だけ課金する。truncate (`"w"` で開く)
と削除で返却する。**同一ファイルを 2 つのハンドルで同時に伸ばすと
二重計上になりうる**が、sim の近似としては許容した (実機側は RAM FS の
実配分なので正確)。

### 確認したこと (sim)

`flash/app/test/tmp_smoke.app.rb` (headless、フェンス付き) の実行ログ:

```
TMP: ok   exist / size / read / append size / append read / truncate size
TMP: ok   list has smoke1 / list has smoke2
TMP: ok   root has tmp / tmp is a dir
TMP: ok   renamed gone / renamed here / deleted
TMP: ok   flat mount            (サブディレクトリ作成が失敗すること)
TMP: refused at 454656 bytes (RuntimeError: write failed)
TMP: ok   full is reported      (アプリは生存して後始末まで走った)
```

454656B で拒否されたのは、直前に別ファイルが 3B 使っていたためで、
上限 458752B (=448KB) にちょうど一致する。

| 確認項目 | 結果 | 画面 |
|---|---|---|
| アプリ A が /tmp に書き、アプリ B が読む (pub/sub でパス通知) | OK。427B を受け渡し。`tmp_writer` "sent 1 (427B)" / `tmp_reader` "got 1 427B" | `handoff.png` (h5) |

## T2: エディタのテンプレート挿入

### 実装形

- テンプレートは `flash/lib/templates/*.rb` (実機では `/lib/templates`)。
  ファーム埋め込みにしていないので、ユーザが自分のものを置けば一覧に出る。
- エディタ側は `File` メニューに `Template` を追加 (項目は
  Open / Save / Save as / **Template** / Exit)。一覧は
  **既存のメニュー drop-down をそのまま使う** (`@active_menu = :template`)。
  上下キー・Enter・ESC・クリックの処理は元からあるものが効く。
- 挿入は `EditorCore.insert_multiline(@cy, @cx, body)`。貼り付けと同じ形で、
  選択があれば消してから入れ、戻り値から新カーソル位置を取る。
- 一覧はメニューを開くたびに読み直すので、**エディタを動かしたまま
  テンプレートを追加しても再起動なしで出る**。
- クラス名の置換は v1 ではやらない (指示どおり)。

### 同梱した 3 種

| ファイル | 内容 |
|---|---|
| `window.rb` | 窓アプリ。on_create / draw / on_event / on_update / on_destroy、`draw_window_frame` を毎回呼ぶ形 |
| `fullscreen.rb` | 全画面 + ゲームループ。`fullscreen_switchable` 付き、`on_resume` あり、矢印キーの例 (scancode を使う) |
| `worker.rb` | headless。処理を細切れにして `on_update` から戻る形 + /tmp へ結果 + publish で通知 |

**3 つとも末尾に起動トレーラ** (`begin / MyApp.new.start / rescue`) を
持ち、なぜ必要かをコメントで書いてある。

### 統合デモ (T1 + T3 + T2 が 1 本で成立することの確認)

手順 (sim、マウスとキーボードのみ):

1. デスクトップで `e` → エディタ起動
2. `File > Template > worker` → 雛形が挿入される (`t3.png`)
3. `File > Save as` → `/app/test/` へ `my_worker.app.rb` で保存
   (**サイドカー `.toml` は作らない**) (`t12.png`)
4. あらかじめ `worker_watch.app.rb` (topic "worker" の購読側) を起動しておく
5. エディタで **F5**

結果 (`t19.png`):

```
fmrb_default_apps: Loaded comment toml from /app/test/my_worker.app.rb   <- T1
app_canvas: [my_worker] Headless: no canvas allocated                    <- T1 (background)
my_worker: worker: wrote /tmp/worker_result.txt (total=29994)            <- T3
WorkerWatch: WATCH: /tmp/worker_result.txt -> total=29994                <- publish 通知
```

WorkerWatch の窓に "results: 1 / total=29994" が出る。

window / fullscreen の雛形も同じ手順で保存 → F5 し、
窓アプリは クリック数が増えること (`t25.png`)、
全画面アプリは全面で四角が動くこと (`t30.png`) を確認した。

## 後追い修正: F5 の起動場所制限を外した (2026-08-10)

M1 の後にユーザが踏んだ症状: **エディタで Template を挿入 → F5 →
保存先を聞かれて `/tmp` に保存 → 何も起動しない**。

原因は `run` 要求のパス許可リストが `/app/` と `/home/` だけだったこと
(`app_lifecycle.rb` の `run_path_allowed?`、エディタ側にも同じ判定の
`runnable_path?`)。/tmp が増えて保存ダイアログに `[tmp]` が出るように
なったので、この制限が表に出た。しかも**カーネルの `"spawn"` ハンドラ
(shell とランチャーが使う) には制限が無く**、同じファイルが
`run /tmp/foo.app.rb` では起動し、F5 では起動しないという食い違いに
なっていた。拒否の通知もステータス行右端の 2 秒バッジだけで気付けない。

判定を **「絶対パスならよい」** に変えた (ユーザ判断 2026-08-10)。

- 場所の制限は無くなり、/tmp でも SD でもどこでも F5 で起動する。
- 組み込み名 (`default/editor` 等) は `/` で始まらないので従来どおり
  弾かれる。これが元々の制限の趣旨だった (「デスクトップが spawn する
  ものを run で呼ばせない」)。
- 同じ述語を使う他の 2 箇所 (前回起動分を停止するか / Ctrl+Q で "stop" を
  送るか) は「そのアプリはファイル起動か」を訊いている。組み込みは
  `:path` を持たない (`""`) ので答えは以前と同じ。
  むしろ**副作用として直った**: 以前は /tmp のアプリを F5 で連打すると
  前の instance が停止されずスロットを食い潰していた。

確認 (sim): /tmp 保存 → F5 で起動 (`f1.png`)、再 F5 で前を停止して起動し直す
(`Run: stopping PID 5 first`)、Ctrl+Q で正常終了、/home と /app の F5 も従来
どおり。S3/P4 ビルド通過。

## 見つけた既存の不具合 (今回は直していない)

**デスクトップのファイル選択で `[..]` を 1 階層目から押すと壊れる。**

`system_desktop/file_selector.rb` の親移動:

```ruby
parts = @file_selector_dir.split("/")
parts.pop
@file_selector_dir = parts.empty? ? "/" : parts.join("/")
```

`"/app".split("/")` は `["", "app"]` なので pop 後は `[""]`、
`empty?` は偽、`join("/")` は `""` になる。`""` は HAL の解決で
`flash/` に落ちるため、**中身は `/` なのに `[..]` 行が付いた一覧**が
出て、以降の位置がずれる。`/app/game` など 2 階層目からの `[..]` は
正常。修正は join 結果が空なら `"/"` にする 1 行。

なお同じ画面で「ディレクトリに入るのは**シングルクリック**」である点も
注意 (二度押すと入った先の先頭 = `[..]` を押したことになる)。
