# 次期基板 HDMI 映像出力方式 検討資料

2026-07-08 作成。ステータス: 検討中 (案A が最有力)。
量産目標: **~10枚、JLCPCB で製造・実装** (入手性・実装可否を判断基準に含む)。

## 背景と目的

- 次期基板は **ESP32-P4 + ESP32-C6** の構成 (Tab5 と同じ) を維持しつつ、
  映像出力を内蔵パネル (MIPI-DSI) から **HDMI コネクタ出力**に変更したい
- ESP32-P4 は DVI/HDMI の TMDS 信号を直接生成できないため、
  変換手段の選定が必要
- 本資料は候補方式の洗い出しと比較、推奨案の整理を目的とする

## 前提

### ESP32-P4 の映像出力能力 (IDF 5.5 soc_caps / Tab5 実績)

| インタフェース | 仕様 | 備考 |
|---|---|---|
| MIPI-DSI TX | 2レーン、最大 1.5Gbps/lane | Tab5 で 900Mbps/lane・720x1280 RGB565 実績あり。専用ピン (GPIO を消費しない) |
| パラレル RGB (LCD_CAM) | 最大 24bit データ + HSYNC/VSYNC/DE/PCLK | `SOC_LCDCAM_RGB_LCD_SUPPORTED`。PCLK 上限と PSRAM 帯域は要実測 (S3 世代は実用 ~40MHz) |
| i80 (8080) | 24bit | 動画向きではない (フレームメモリ内蔵パネル用) |

- TMDS (DVI/HDMI 物理層) は生成不可 → **外部変換が必須**
- 現行 Modern パイプライン: 426x240 RGB565 合成 (PPA Blend) →
  **PPA SRM で 3x 拡大 + 回転して DSI フレームバッファ (720x1280) へ**
  → esp_lcd_mipi_dsi が DPI ストリーム送出
- HDMI 化しても fmruby の内部解像度は 426x240 のまま。
  1280x720 出力なら**ちょうど 3x** (1278x720 + 黒縁 1px) で現行 PPA
  パスがそのまま使える

### 要件 (整理)

| 項目 | 要求 |
|---|---|
| 出力解像度 | 640x480@60 以上、できれば 1280x720@60 |
| 音声 | 要検討: HDMI 音声に載せるか、現行同様ローカル DAC/スピーカか |
| GPIO 予算 | C6 (SDIO 6本) / USB / SD / I2C ほか現行機能と共存できること |
| ソフト変更量 | display_p4 パイプラインの流用度が高いほど良い |
| ライセンス | ホビー用途。"HDMI" を名乗らず DVI 信号を HDMI コネクタに出す形なら
  HDMI アダプタ契約は不要 (製品化時は再検討) |

## 候補方式

### 案A: MIPI-DSI → HDMI ブリッジ IC (推奨第一候補)

```
[P4] --MIPI-DSI 2lane--> [ブリッジIC] --TMDS--> [HDMIコネクタ]
        (専用ピン)          ^I2C設定 (P4から)
                            ^I2S audio (任意)
```

Tab5 と同じ DSI 出力をそのままブリッジ IC に入れる。P4 から見ると
「パネルがブリッジに変わっただけ」で、**現行 display_p4 の
PPA 合成 → DSI フレームバッファのパイプラインがほぼ無変更で流用できる**
(パネル初期化コードを ILI9881C からブリッジの I2C 設定に差し替え、
解像度/タイミングを 1280x720 等に変更するだけ)。

候補 IC:

| IC | 入力 | 出力 | 音声 | 参考価格 | 備考 |
|---|---|---|---|---|---|
| Lontium LT8912B | DSI 1-4lane | HDMI1.4 (~1080p) + LVDS | I2S入力可 | ~$3-5 (LCSC) | 中華SBCのDSI-HDMIアダプタで多用。正式データシートは出回らないが Linux DRM ドライバ (lontium-lt8912b.c) に初期化シーケンスがある |
| Lontium LT9611 | DSI 4lane x1-2port | HDMI1.4 1080p60 | I2S入力可 | ~$6-9 | Linux ドライバあり (lontium-lt9611.c)。2lane 入力での動作可否は要確認 |
| ADI ADV7533/7535 | DSI 1-4lane | HDMI1.4 | I2S/SPDIF | ~$10-15 | ドキュメント/プログラミングガイドが最も整っている。高め |

**LT8912B は Espressif 公式サポートあり (2026-07 調査で確認)**:

- **公式ドライバ**: ESP Component Registry に `espressif/esp_lcd_lt8912b`
  (esp-bsp 内、I2C 設定の esp_lcd パネルドライバ) が存在
- **公式 BSP 実績**: `esp32_p4_function_ev_board` BSP が LT8912B 経由の
  HDMI をサポート。**800x600@60 / 1280x720@60 / 1280x800@60 /
  1920x1080@30** (RGB888 のみ)
- **参照回路**: Olimex が ESP32-P4-Devkit 用 LT8912B MIPI-HDMI
  アダプタ (14.95EUR) をオープンハードウェアで公開 (KiCad 回路図が
  GitHub にある)。プロトタイプはこれを購入すれば基板を起こす前に
  ソフト検証まで完了できる
- 注意: ESP-FAQ に「HDMI 利用時は IDF 5.4 以前を推奨」の記述あり。
  本プロジェクトは IDF 5.5.1 のため動作可否の確認が必要 (要検証)

検証項目: 2レーン DSI 入力対応 (LT8912B は 1-4lane 可)、720p60 時の
レーン速度 (RGB888 24bpp で ~1.0Gbps/lane、Tab5 の 900Mbps 実績に近い)、
EDID/ホットプラグ処理、IDF 5.5 での esp_lcd_lt8912b 動作。

- 長所: GPIO 消費ゼロ (DSI 専用ピン)、ソフト変更最小、追加ファーム不要、
  遅延ゼロ、HDMI 音声対応可、**公式ドライバ + オープンハード参照回路が
  揃っており当初懸念 (Lontium 資料非公開) はほぼ解消**
- 短所: RGB888 のみ (現行 DSI FB は RGB565 → FB を RGB888 化するか
  PPA 出力形式の変更が必要、PSRAM 使用量 720p で 2.7MB)、QFN-64 実装、
  モニタ相性試験は必要

### 案B: パラレル RGB (DPI) → DVI/HDMI トランスミッタ IC (ユーザ案1)

```
[P4] --RGB24/RGB565 + HS/VS/DE/PCLK--> [TX IC] --TMDS--> [HDMI]
        (GPIO 19~28本)                    ^I2C設定
```

候補 IC:

| IC | 入力 | 音声 | 参考価格 | 備考 |
|---|---|---|---|---|
| TI TFP410 | RGB24 (12bit DDR可) | なし (DVI) | ~$5-8 | データシート完全公開、設定ほぼ不要 (ピンストラップ可) で最も枯れている |
| Lontium LT8618SX | RGB24 | I2S可 | ~$2-4 | Rockchip 系ボードで実績多数。ドライバソースは BSP に散在 |
| ITE IT66121 | RGB24 | I2S可 | ~$3-5 | オープンハード採用例あり (データシートは要 NDA 部分あり) |
| Chrontel CH7035B | RGB | あり | ~$4-6 | スケーラ内蔵 (低解像度入力を 1080p 出力可) が特徴 |

- P4 の RGB LCD は最大 24bit。RGB565 (16+4=20本) か RGB666 で
  ピン数を削れるが、それでも **GPIO を 19~28 本消費**する
- PCLK 上限が実質的な解像度上限: 640x480@60 (25.175MHz) は確実、
  **720p60 (74.25MHz) は P4 の RGB ペリフェラルと PSRAM 帯域的に
  おそらく困難** (要実測)。720p を狙うなら CH7035B のような
  スケーラ内蔵 TX で 640x480→720p アップスケールする手はある
- 長所: TFP410 なら資料が完璧で電気的リスクが最小。DSI と独立なので
  DSI をデバッグ用パネルに残す構成も可能
- 短所: GPIO 大量消費が現行機能 (C6 SDIO / USB / SD / I2C / PWM 等) と
  衝突する可能性大。基板配線も等長制約が増える。
  esp_lcd ドライバを RGB 用に書き換え (PPA 合成部は流用可)

### 案C: RasPi Pico (RP2350) SPI→DVI コンパニオン (ユーザ案2)

```
[P4] --SPI(QSPI) フレーム転送--> [RP2350] --HSTX DVI--> [HDMI]
                                    ^ スケーラ/フレームバッファ/(音声?)
```

- **Retro 構成 (S3 + WROVER SPI グラフィックスボード) と同型**の
  アーキテクチャ。fmruby には既に「子マイコンに描画を委譲する」
  IPC の設計資産がある
- RP2350 の **HSTX ペリフェラルはオーバークロック無しで
  DVI 640x480@60 を出せる** (RP2040+PicoDVI はオーバークロック前提
  なので RP2350 を推奨)。854x480 や 720x480 などのモードも工夫次第
- 帯域試算: 426x240 RGB565 x 30fps = 49Mbps → SPI 80MHz シングルで可、
  QSPI なら余裕。RP2350 内蔵 SRAM 520KB に 426x240 RGB565 (204KB) を
  置き、スキャンライン毎に 640x480 へ拡大しながら送出する構成が現実的
- 長所: 部品が安価で入手容易 ($1.5~)、TMDS は Pico 側で完結、
  スケーリング/パレット/レトロエフェクトを Pico に持たせられる
  (「自作グラフィックチップ」的な拡張余地)。DVI 信号なので
  ライセンス面もクリーン
- 短所: **もう1つのファームウェアを開発・保守**することになる
  (転送プロトコル、フロー制御、アップデート手段)。
  HDMI 音声はデータアイランド生成が必要で PicoDVI 系では実験的
  (音声はローカル DAC 継続が無難)。表示遅延 +1 フレーム程度

### 案D: 小型 FPGA ブリッジ (参考)

- Gowin GW1NR-9 (Tang Nano 9K 相当、PSRAM 内蔵、~$5-10) や
  Lattice ECP5 で SPI または RGB 入力 → TMDS 出力を自作する
- 長所: 究極の柔軟性 (スプライト/パレット等を「本物のレトロ GPU」として
  実装できる)、720p も可
- 短所: HDL 開発・検証コストが最も大きい。本プロジェクトの主目的から
  逸れるため、趣味的拡張フェーズ向け

### 案E: 検討したが除外

| 方式 | 除外理由 |
|---|---|
| USB-HDMI (DisplayLink 等) | プロトコル非公開、P4 側ドライバ実現性なし |
| コンポジット/VGA 出力 | HDMI 要件を満たさない (VGA は RGB+抵抗DACで安価に併設は可能) |
| SDI/その他 | 用途外 |

## JLCPCB 量産性の評価 (10枚目標、2026-07 調査)

| 部品 | JLCPCB/LCSC 取扱 | 実装 | 備考 |
|---|---|---|---|
| LT8912B (案A) | あり: LCSC **C2892102** (QFN-64) | **Economic/Standard 両対応** | 価格/在庫はカートで要確認 (相場 $3-6)。Lontium は在庫変動があるため、基板発注前に JLCPCB パーツライブラリへ先行購入して確保するのが安全 |
| TFP410PAP (案B) | あり: LCSC **C1543847** | 可 (HTQFP-64) | **$2.59、在庫 298個** (調査時点)。TI 品で供給安定 |
| RP2350A/B (案C) | あり: C42411118 / C42415655 ほか | 可 (JLCPCB は RasPi **公式 PCBA パートナー**) | **$1.25 前後、在庫あり** (数千→数百に変動する時期あり)。クリスタルは ABM8-272-T3 指定、SMPS 用インダクタ指定あり |
| ADV7535 (案A代替) | 在庫薄/高価になりがち | BGA (49ball) | 10枚規模では優先度低 → 保険候補から外す |
| HDMI コネクタ/ESD | 汎用品多数 | 可 | 問題なし |

- 3案とも JLCPCB での 10枚実装は**可能**。差は IC 確保の安定性のみで、
  少量なら「発注前にパーツライブラリへ先行確保」で全て回避できる
- QFN-64 (LT8912B) は Economic 実装対象なので実装費も安い

## 推奨

1. **第一候補: 案A (DSI→HDMI ブリッジ、LT8912B) — 確度高**
   - **Espressif 公式ドライバ (esp_lcd_lt8912b) + 公式 EV ボード BSP の
     HDMI 実績 (720p60/1080p30) + Olimex のオープンハード参照回路**が
     揃っており、当初の最大懸念 (Lontium 資料非公開) は解消
   - 現行 Modern の描画パイプライン (PPA 合成 → DSI) が
     ほぼ流用でき、426x240 → 1278x720 の 3x 整数スケールが
     現行の Tab5 (3x + 回転) と同じ PPA パスで済む
     (FB の RGB888 化のみ差分)
   - GPIO を消費しないため、C6/USB/SD 等の現行ピンアサインを
     ほぼ維持して基板設計できる
   - JLCPCB: C2892102 (QFN-64) が Economic 実装対象。発注前に
     パーツライブラリへ先行確保
2. **保険/併設: 案B の TFP410 (DVI, 音声なし)**
   - 案A のブリッジがどうしても動かない場合の枯れた逃げ道
     (LCSC $2.59・在庫あり)。ただし GPIO 消費が大きく、載せるなら
     RGB565 (20本) 構成でピンアサイン設計時に両立可否を先に確認する
3. **案C は「Retro 的な拡張」として魅力はある**が、次期基板の
   主目的 (HDMI 化) に対してファーム開発・保守コストが割高。
   将来「HDMI 版グラフィックスボード」を作る話になったら再浮上させる
   (RP2350 は JLCPCB 公式 PCBA パートナーで実装容易という追い風はある)

## プロトタイプ計画 (案A)

1. 部材: **Olimex LT8912B MIPI-HDMI アダプタ (14.95EUR)** +
   標準 MIPI ピンアウトの P4 開発ボード (Olimex/Waveshare/DFRobot/
   Espressif。Tab5 は DSI がパネル直結のため不可) + 15pin FPC ケーブル
2. ステップ:
   1. `esp_lcd_lt8912b` + `esp32_p4_function_ev_board` BSP の HDMI
      サンプルを IDF 5.5.1 でビルド・動作確認 (FAQ の
      「IDF 5.4 以前推奨」記述の実態確認)
   2. 1280x720@60 RGB888 で表示確認 (BSP 実績解像度)
   3. display_p4 パイプラインを接続: DSI FB を RGB888 720p 化し、
      PPA 3x スケール (回転なし) で 426x240 → 1278x720
   4. モニタ数機種で EDID/HPD/相性確認
   5. 基板設計: Olimex の KiCad 回路図を参照して P4+C6+LT8912B を
      1枚に統合。JLCPCB へ LT8912B を先行確保してから発注
3. 判断基準: 720p60 が安定しない場合は 800x600@60 / 640x480@60 へ
   フォールバック (BSP 実績あり)。案A 全滅時のみ案B に切替

## 音声の扱い (未決定)

- 現行 Modern は ES8388 コーデックでローカル出力 (47160Hz)
- 選択肢:
  1. 現行踏襲: 基板にアンプ+ジャック or スピーカ (HDMI 音声なし)
  2. ブリッジの I2S 入力へ APU 出力を分配し HDMI 音声化
     (テレビ利用を想定するなら価値が大きい。ブリッジ側の
     対応サンプルレート 44.1k/48k と APU の 47160Hz の
     リサンプル要否を確認すること)
  3. 両対応 (I2S を両方に配線しておく)
- 基板設計としては 3 (両配線) にしておき、ソフトで選べるようにするのが
  安全
