# ユーザによるシステム拡張の余地 (構想の棚卸し)

カーネルと Spinel 化した部分は性能のために固定であり、コードの差し替えに
よる拡張はできない。それでもこの OS には**動的な媒体が 3 つ**残っている。

- **(a) 設定ファイル (toml)** — 実行時に読まれる
- **(b) 実行時に読まれる Ruby** — アプリと、その VM に require されるもの
- **(c) メッセージ** — Pub/Sub と kernel へのメッセージ

ユーザ拡張の余地はすべてこの 3 つの組み合わせで作れる。既にある実例:
hid_devices.toml (HID Inspector が書く)、theme、壁紙、app.toml、
shortcuts。本書はこのパターンを広げる案の一覧。優先順は末尾。

## 1. シェル: 外部コマンド

- shell が未知のコマンドを `/home/bin/<名前>.rb` から探して実行する
  (PATH 方式)。shell 本体は固定のまま、コマンド語彙が増やせる。
  費用が小さく効果が大きい筆頭。
- 実行は shell 自身の VM での eval (irb が同じ機構の実証)。ファイルは
  `def main(args)` を定義する約束。重い/危ない物はアプリ spawn に逃がす。
  単発の居場所の整理は services/plan.md の「単発 (一回きり) の扱い」。
- エイリアスやプロンプトを `/home/.shellrc` から読む。

## 2. 起動時サービス (常駐の userland) — 計画済み (services/plan.md、システム/ユーザの二層)

- headless アプリは既にあるので、`/etc/autostart.toml` (または
  `/home/autostart/`) に列挙したアプリをブート時に kernel が spawn する
  だけで「ユーザのデーモン」になる。時報、MIDI ルータ、ネットワーク通知、
  クリップボード履歴など。
- 併せて cron 風の予定表 (`/home/schedule.toml` → 時刻でアプリ起動)。
  RTC が動くようになったので成立する。

## 3. ファイルの関連付け (open の一般化) — 実装済み (assoc/report/a1.md)

- `/etc/associations.toml` に拡張子 → アプリの対応表を持ち、file manager
  のダブルクリックと shell の `open` がそれに従う。ユーザは
  `/home/associations.toml` で拡張子ごとに上書きできる。解決は
  **`FmrbAssoc.resolve(path)`** (gem。`"run"` / `"edit"` / アプリのパスを返す)。
- 前提の**アプリへの引数渡し**は既にあった (kernel の spawn 要求の
  `open_path`)。本件はそれを契約として公式化した仕事で、新しい配管は
  足していない。

### 契約: 関連付けで起動されたアプリ

**関連付けで起動されたアプリには、起動直後に `file_selected` が届く。**

```ruby
def on_control(msg)
  return unless msg["cmd"] == "file_selected"
  open_it(msg["path"])
end
```

- 受けたければ `on_control` で拾う。**受けなければ何も起きない** —
  アプリはただ起動するだけで、それで良い (対応は任意)。
- 届くのはアプリが受け取れるようになってから (kernel が繰り延べる)。
- 実例は PicoRabbit (メニューを飛ばして渡されたデッキを開く)。

## 4. ユーザライブラリ (`require` の載る場所)

- `/home/lib/*.rb` をアプリの require パスに入れる。ユーザが書いた部品
  (自作 UI 部品、ゲームのユーティリティ) をアプリ間で共有できる。
- mruby はバイトコード (.mrb) の動的ロードができるので、大きいものは
  PC で mrbc に通して置く形も取れる。
- 「OS の拡張」ではなく「アプリの土壌を厚くする」方向だが、体感は
  いちばん OS らしくなる。

## 5. デスクトップの差し込み口

デスクトップ本体は固定のまま、内容だけユーザから来る場所を作る。

- メニュー項目の追加 (`/home/menu.toml`: 表示名 + 起動パス)
- メニューバーの小さな表示枠 — かな指示器や空きメモリと同列の
  「ウィジェット枠」を 1〜2 個開け、登録したアプリが Pub/Sub で文字列
  (や小さな絵) を送ると表示される。時計の隣に天気や CPU 温度、が定番
- ライブ壁紙 — 背面 canvas に描く権利を 1 アプリに貸す (ブート画面と
  同じ経路)
- グローバルショートカット (`Ctrl+数字` → 指定アプリ起動、toml)

## 6. Pub/Sub の「契約」の公開

チャネル名と payload を文書化して安定させるだけで拡張点になる:
アプリ起動/終了、キー、ネットワーク状態、電源、時刻。ユーザの常駐アプリが
これを聞いて反応する (5 のウィジェットもこの上に乗る)。逆向きに
「システムに頼む」チャネル (画面ロック、音量、起動) を足せば、リモコンや
自動化がユーザのアプリとして書ける。

## 7. エディタ・道具側の拡張 (Spinel でも可能な形)

エディタは Spinel なのでプラグインは載らないが:

- 設定・スニペット・色テーマ・キーバインドを toml から
- 「現在のファイルを実行/整形/検査」フック: エディタは固定の作法で
  `/home/hooks/<名前>.rb` を spawn して結果を受けるだけ。中身はユーザの
  Ruby。オンデバイスデバッガと同じ「別 VM に逃がす」構図
- picoruby-ti の型 DB にユーザ RBS (`/home/sig/`) を足し、自作ライブラリ
  でも補完が効くようにする

## 8. 音・見た目のテーマパック

- theme を色だけでなく一式 (`/home/themes/<名前>/`: 色 + 壁紙 + 起動音 +
  効果音) にする。システム効果音を FMSQ ファイルの差し替えで変えられる
  ように。
- APU の音色プリセット、MIDI のルーティング表も toml で。

## 9. 言語の入口を増やす

BASIC / Lua / MicroPython は既にあるので、1 と 3 の仕組みに乗せるだけで
「拡張に使える言語」が 4 つになる (シェルコマンドを BASIC で書く、.py を
ダブルクリックで実行する)。

## 10. ネットワーク側 (Modern)

- `/home/www/` を rd_http が静的配信 — ユーザが端末のウェブページを持てる
- ユーザアプリに HTTP の口を持たせるのは大ごとなので、代わりに
  **Pub/Sub と HTTP の橋** (`/user/<チャネル>` への POST がそのまま
  チャネルへ流れる) が安くて強い。スマホから自作アプリを叩ける
- 外部通信を Zenoh へ寄せる方向とも矛盾しない

## 11. PC で AOT してから持ち込む経路 (上級者向け)

動的ロードは無理でも、拡張の単位をアプリに切ってあれば、性能が欲しい
ユーザは PC で Spinel / ネイティブ gem 化して firmware を焼き直す道が残る。
WiFi のファイル転送 (put → launch) がそのまま配布の形になる (アプリなら
焼き直し不要)。

## 12. 声の通知 (WAV 再生 + ネットワーク TTS + カレンダー) — 計画済み (voice/plan.md)

任意波形 (PCM/WAV) を鳴らす口を 1 つ足し (効果音テーマにも効く汎用投資)、
その上に tts サービス (キャッシュ / ローカル VOICEVOX / クラウド WAV 系) と
カレンダー読み上げ (Google の iCal 非公開 URL、OAuth 不要) を積む。

## 優先順

1. **3 (関連付け + 引数渡し)** — 他の多く (1, 9, PicoRabbit のデッキ指定)
   の土台になるので最初。
2. **2 (autostart)** と **4 (/home/lib)** — 「固定のシステム + 生きている
   userland」という OS の形がこの 3 つでははっきりする。
3. 5 と 6 は見栄えの割に設計 (契約の安定化) が要るので、その次。

着手するときは案ごとに doc/<機能>/plan.md へ切り出し、本書には確定した
結果 (やった / やらないと決めた) だけを反映する。
