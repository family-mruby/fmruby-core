# 作業指示書 E3: Spinel アプリの同時起動の制限を外す

対象: 実装担当のサブエージェント。前提: plan.md、report/e1.md (E2 の節)。report は `report/e3.md` へ。

## 経緯と決定 (ユーザ、2026-10-03)

E2 で入れた「同じ Spinel のプログラムは 1 つしか起動できない」(`fmrb_app_spinel_claim` / `release`、2 つ目は
「すでに起動しています」) は、ユーザに確認せずに入れた**仕様の変更 (退行)** だった。親の指示書の誤り。
ユーザの決定: **制限を外し、ほかの修正は残す。根本の直し (Spinel の変数をインスタンスごとに持たせる) は別に計画する**。

## T1: 制限を外す

- commit a1b2ee50 のうち、同時起動を断る部分を外す: `fmrb_app_spinel_claim` / `fmrb_app_spinel_release`、
  `ctx->spinel_program`、spawner の断りと「すでに起動しています」の表示、`destroy_vm` での claim の解放。
  変更前 (develop) と同じく、エディタを 2 つ同時に開ける状態に戻す。
- **残すもの**: E1 (c8e3e181、`mrb_close`)、競合の修正 (42494d08、`parked`)、エディタの文書の枠の返し忘れの修正
  (a1b2ee50 の `fmrb_spx_editor.c` の部分と `fmrb_app_run_spinel_vm` の `after` の口)。文書の枠の修正が、2 つの
  エディタが同時に開いているときも正しく動くか (それぞれが自分の枠を返す、kill されたエディタの枠を次が回収する
  ときに、生きているもう 1 つの枠を取らない) を確かめる。制限があることを前提に書いた所があれば直す。
- 外したあとの動きは**元に戻るだけ** (2 つ同時に動かすと、まれに落ちる・状態が混ざる。根本の直しは別の計画)。
  これを report に書く。新しい手当て (別の制限、警告の表示など) は**入れない**。

## 検証

- 実機 P4-Nano: エディタを 2 つ同時に開けること。1 つずつの起動と終了をくり返しても「Doc full」が出ないこと。
  2 つ開いて閉じる手順を数回 (落ちることがあっても、それは元からの症状として記録する。新しい落ち方が無いか)。
  全アプリの起動と終了を数周、Guru が新しく出ないこと。ミュートのまま。
- sim (標準・互換)、ブラウザ版、`rake test`、ビルド (TAB5 / NARYAv4 / S3 / Linux / wasm)。静的な D/IRAM が develop を
  超えない。
