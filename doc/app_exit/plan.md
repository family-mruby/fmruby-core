# アプリの終了の後始末 (mrb_close と、同じ Spinel アプリの同時起動)

> 状態: 進行中 | 更新: 2026-10-03 | E1 (mrb_close) と終了時の競合の修正は完了。E2 で入れた同じ Spinel アプリの同時起動の制限は、ユーザ未確認の仕様の変更 (退行) だったので E3 で外す。根本の直し (Spinel の変数をインスタンスごとに) は doc/spinel_multi_instance で計画

## 目的

アプリの終了で VM を上流と同じ順番 (`mrb_close` → `mrc_ccontext_free`) で片付け、同じアプリを 2 つ同時に
動かしても壊れないようにする。

## 分かっていること (doc/shell_input_lag/report/s2c.md)

- `mrb_close` を呼ばなかったのは、先に `mrc_irep_free` で irep を解放していたため (二重解放)。S2c でその解放を
  やめた後は、`mrb_close` を呼んでも落ちず、不正な解放も 0 回だった (6 本の mruby アプリ、コミットはしていない)。
  かかった時間は点検ありの版で Shell 1.5 秒、BlockGame 0.57 秒、MML・Monitor 約 0.27 秒、ほか約 0.15 秒
  (点検を外した今の版では短くなる見込み、未測定)。
- 強制終了 (kill の強制経路) では、錠を持ったままタスクを消す作りなので (doc/archive の fs_kill_hang)、
  後始末を走らせない。Lua の `lua_close` も強制終了では呼ばない (K2)。
- エディタ (Spinel) を 2 つ同時に開き、両方閉じてから 3 つ目を開くと、`FmrbColors.read` の `File.open` の
  `Errno::ENOENT` が `rescue` をすり抜けて abort した (長く動かした計測ビルドで 2/2、焼き直した直後と sim では
  0/3)。3 つ目のエディタの ExcHW が 6/0 (1 つだけなら 3/0) で、前のエディタの状態が残っていた。
  見立て (未確認): Spinel の生成 C の翻訳単位ごとの static (例外の深さなど) を、同じプログラムの 2 つの
  インスタンスが共有している。これまで `ESTALLOC_DEBUG` の `est_cleanup` がプールを 0 で埋めていて隠れていた
  可能性。同じアプリの多重起動を止める仕組みは、Python のアプリ以外に無い。

## 方針

- E1: 正常な終了でだけ `mrb_close` を呼ぶ。強制終了では呼ばない (錠の扱いと同じ理由)。終了にかかる時間と、
  プールの戻り、不正な解放 (点検を一時的に戻して) を測る。
- E2: 推論で直さない。再現の条件を固め、何が共有されているか (生成 C の static、`SP_MULTI_CTX` の
  インスタンスごとの領域の作り) を確かめてから直し方を選ぶ。候補: (1) 同じ Spinel アプリの同時起動を止める、
  (2) Spinel 側でインスタンスごとに持つように直す (フォークの変更)、(3) 終了時の後始末で状態を戻す。
  根本 (2) が大きければ、(1) を先に入れて (2) を案として返す。

## 段階

| 段階 | 内容 | 状態 |

| E2 | Spinel アプリの同時起動の abort (instruction_e1.md の後半) | **原因は確定、直し方は差し戻し** (report/e1.md)。同じプログラムの 2 つのインスタンスがファイル単位の変数 (例外の深さ・jmp_buf・クラスの ivar・定数・プール) を共有する。同時起動を断る制限を入れたが、ユーザ未確認の仕様の変更だった。エディタの文書の枠の返し忘れ (6 回目で Doc full) も見つけて直した |
| E3 | 同時起動の制限を外し、ほかの修正を残す (instruction_e3.md、ユーザ決定 2026-10-03) | 着手 |

## 受け入れ条件

- E1: 6 本以上の mruby アプリの起動と終了をくり返して、落ちない・不正な解放 0・プールが戻る。終了の時間を前後で示す。
- E2: 「エディタを 2 つ開く → 両方閉じる → 3 つ目を開く」を、長く動かした後も含めて何度くり返しても落ちない。

## ユーザの決定 (2026-10-03)

同じ Spinel アプリの同時起動を断る制限は退行。外して (E3)、根本の直し (Spinel の生成 C のファイル単位の変数をインスタンスごとに持たせる) を別に計画する (doc/spinel_multi_instance)。仕様が変わる直し方はユーザだけが決める (fmrb-dev-flow 4 章に反映)。
