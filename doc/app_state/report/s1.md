## 一度止まった理由 (見立てと違った点)

最初の置き場所 `/tmp/.state/<名前>.toml` は作れなかった。/tmp は設計として
平ら (ファイルだけ) で、components/fmrb_hal/fmrb_tmpfs.h に「両方の HAL が
守る」と書いてある。実機の tmpfs (platform/esp32/fmrb_tmpfs_esp32.c の
`tmpfs_name`) は名前に `/` を含むパスを断り、POSIX の HAL (sim・ネイティブ版・
ブラウザ版) も mkdir と 2 段目の open・rename を断る。ユーザの決定 (2026-10-29)
で平らな名前 `/tmp/<app_handle_name>.state.toml` にした。C は触っていない。

## API の形

mruby の基底 (lib/add/picoruby-fmrb-app/mrblib/fmrb-app.rb) と Spinel の基底
(main/prebuild_scripts/spinel/fmrb_app_base_spinel.rb) の FmrbApp に、同じ
3 つのメソッドを足した。

```ruby
st = app_state                          # {} when nothing is remembered
save_app_state({ "dir" => "/home" })    # writes only when a value changed
app_state_path                          # "/tmp/<app_handle_name>.state.toml"
# File Manager (a part of the desktop with its own name):
app_state("file_manager")
save_app_state({ "dir" => @file_manager_dir }, "file_manager")
```

- 既存の `app_settings` / `save_app_settings` / `app_settings_path`
  (/home/<名前>.toml、利用者の設定) と並べた名前と形にした。置き場所と寿命が
  違う (設定は /home で消えない、状態は /tmp で再起動で消える) ので、名前で
  分けた。
- 値は文字列・整数・真偽だけ。表は平ら (節は持たない)。ほかの型は読むときも
  書くときも黙って捨てる。
- 名前は省略すると app_handle_name。File Manager はデスクトップの一部なので
  固定の `file_manager` を渡す (ユーザ決定。マウスのデスクトップと keys の
  デスクトップで同じファイルを使う)。Spinel の基底には app_handle_name が
  無かったので、カーネルから受け取る名前 (`@_name`) を返すものを足した。
- **基底にはメソッドだけ足し、ivar は足さない**。Spinel で基底に ivar を
  足すと親子の ivar の並びがずれた前例がある (fmrb-app.rb の app_settings も
  同じ理由でメソッドだけ)。このため「閉じるとき自動で書く」は基底では
  しない。アプリが閉じるところで `save_app_state` を呼ぶ。中身が今と同じなら
  書かないので、毎回呼んでよい。
- 読めない・壊れている・無いときは {}。保存するときは表をまるごと書き直す
  (状態のファイルはこの API だけが書くので、手書きの行を残す
  FmrbToml.update の流儀は要らない。壊れたファイルも次の保存で直る)。
- mruby 側は FmrbToml.load で読み、FmrbToml.dump_key / dump_value で書く
  (既存の道具)。Spinel 側には FmrbToml の束縛が無い (FmrbColors・
  fmrb_assoc_spinel.rb と同じ事情) ので、`key = value` の行だけを読む小さな
  読み書きを FmrbApp のメソッドとして書いた (`_state_int?`・
  `_state_unquote`・`_state_quote`)。内蔵 RAM のため、新しい定数・module は
  足していない。文字列の `\"` `\\` `\n` `\t` はどちらも同じに読み書きする
  (mruby 側が書く `\u00XX` は Spinel 側では読まない。制御文字を含む値は
  想定していない)。
- Spinel では文字列キーの Hash を引数に渡すとき波括弧を明示する
  (`save_app_state({ ... })`)。

## 置き場所と寿命

どの端末も `/tmp/<名前>.state.toml`。端末ごとの切り分けは無い。

| 端末 | /tmp の実体 | 覚えている間 |
|---|---|---|
| 実機 (S3・P4) | PSRAM の tmpfs (fmrb_tmpfs_esp32.c) | 電源を切る・再起動するまで |
| sim | コンテナの中の flash/tmp。core の起動時に空にする | core を再起動するまで |
| ネイティブ版 | キャッシュの根の下の tmp。起動時に空にする | プログラムを終えるまで |
| ブラウザ版 | ページの中の flash/tmp。起動時に空にする | ページを再読み込みするまで |

POSIX の側は fmrb_tmpfs_posix.c が起動時に中身を消す (実機の再起動と同じ
意味に揃えるため)。ネイティブ版の再起動・ブラウザ版の再読み込みで消える
ことは下の確認で見た。実機の /tmp には数の上限 (Retro 24・Modern 64) と
名前の長さ (63 バイト) があり、1 アプリが 1 枠使う。実機の経路はコードで
示すだけで、動かしていない (S1 の決まり)。

## File Manager

main/prebuild_scripts/kernel/system_desktop/file_manager.rb の 1 か所で、
マウスと keys の両方のデスクトップに効く。

- `open_file_manager` は `"/"` の代わりに `fmgr_remembered_dir` から始める。
  覚えたものが無い・文字列でない・`/` で始まらない・Dir.open できないときは
  `"/"` (今の初期フォルダ)。
- `close_file_manager` で `save_app_state({ "dir" => ... }, "file_manager")`。
- 標準構成のデスクトップは mruby なので、実際に動くのは mruby の基底の側。
  Spinel のデスクトップ (FMRB_APP_ENGINE_DESKTOP=spinel) は、この変更の前から
  `rake spinel:gen` が 9 件の NoMethodError (battery_level・power・
  linux_settings ほか、L 段の FmrbApp のクラスメソッド) で通らない
  (変更を外しても同じ 9 件)。Spinel の基底の 3 メソッドは、同じ形の小さな
  プログラムを Spinel で作って走らせ、読み書き・逃がし文字・壊れたファイル・
  整数と真偽を確かめた。エディタ (Spinel) は通る。

## 確認

- `rake regress`: host 19/19、描画の記録 205/205。
- `rake regress:size`: NARYAv3・TAB5 とも DIRAM・IRAM・other **+0**。
  flash は基準 (6f7b5848) から NARYAv3 +72,928 / TAB5 +79,024 (L15 の時点が
  +70,960 / +77,040 なので、この変更で約 2 KB)。
- `ONLY=retro,modern,native rake regress:screens`: 既存の 23 場面は基準どおり。
  場面を 2 つ足した (test/regress/screens/50_file_manager.rb):
  - `fmgr_remember` (retro・modern・native): File Manager を開き、"/" の最初の
    フォルダ (app) に入って閉じ、もう一度開いた画面。題が `File: /app` で
    始まることを写しで見てから基準にした。sim の受け入れ (1 回の起動の中で
    閉じて開き直す) はこれで見ている。
  - `keys_fmgr_remember` (native-keys): keys のデスクトップで同じこと。
  - 新しい 4 枚 (どれも題が /app) を見てから `regress:screens:update` で
    基準にした。web は 8016 で人のブラウザが動いているので
    regress:screens では流さず、下で手で見た。
- ネイティブ版 (tools/fmrb_native.rb、利用者とキャッシュの場所は作業用の
  ディレクトリ):
  - 覚えたフォルダ `/home/gone` (無い) → "/" で始まり、閉じると "/" を書く。
  - 壊れたファイル (`dir = [[[`) → "/" で始まり (ログに toml の警告)、閉じると
    正しいファイルに書き直す。
  - `/mnt/host/x` を覚えさせて開く → そこから始まる。中の `sub` に入って閉じ、
    開き直すと `/mnt/host/x/sub`。`sub` を消してから開くと "/"。
  - プログラムを終えて起こし直すと /tmp は空 (覚えたものは消える)。
- ブラウザ版 (このブランチで `spinel:gen`・`wasm:mruby`・`wasm:web` を作り直し、
  port 8016 の開いていたページを reload。ページは閉じていない):
  - 開いて /app に入って閉じ、開き直すと /app (/flash/tmp/file_manager.state.toml
    に `dir = "/app"`)。
  - 無いフォルダ・壊れたファイルはネイティブ版と同じく "/" で始まり、次に
    閉じたときに書き直す。
  - 再読み込みの後は /tmp が空で、"/" から始まる。
- wl の一式のうち File Manager に関係するもの: `wl_open_check.rb`
  (L11、File Manager から Linux のアプリで開く) を標準と全部 mruby で。
  最初は両方 1/5 で落ちた。台本が File Manager を開くたびに "/" から
  /mnt/host へ歩く作りで、2 回目からは覚えた /mnt/host で開くようになったため
  (意図した変化)。台本の `to_host` を、最初の 1 回だけ歩くよう直して
  標準・全部 mruby とも 5/5。File Manager を使う確認はほかの wl・sdl の台本と
  live には無い。

## 残件

- 壊れたファイルのとき、toml の警告がログに 2 回出る (開くときと、閉じる
  ときの比べるための読み直し)。害は無い。
- 他のアプリの移し替え (エディタの /home/editor.toml などは設定なので移さない
  方がよいものも多い) は、別に決める (plan.md の決定どおり)。
- sig/ には足していない (app_settings も sig に無い)。エディタの型の助けに
  出すなら、sig を足して `rake clean` が要る。
- Spinel のデスクトップが通らないのはこの段と関係ない既存の問題。
