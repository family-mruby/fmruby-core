# 作業指示書 H3: エディタのフォントの選択

対象: 実装担当のサブエージェント。前提: plan.md の「確定した設計」7、
report/h0.md 5 章 (フォント) と 8.6、report/h2.md。report は `report/h3.md` へ。

## ゴール

エディタのフォントを **ja12 (既定) / ja16 / misaki 8** から選べ、選んだものが
`/home/editor.toml` に残り、再起動後も効く。窓と全画面 (640x360) で共通。

## やること

1. **文字の大きさを変数にする**: `EDIT_FONT_SIZE` と、それに依存する行の高さ・
   1 文字の幅 (`LINE_H` / `CELL_W` などの定数と、その値を前提にした計算) を、
   選んだフォントから決まる値にする (H0 の見立てで 87 か所)。
   - 配置の計算 (`recompute_layout` など) を、フォントが変わったときにも
     やり直す。桁数・行数・折り返し・カーソル位置・スクロール・選択範囲・
     行番号の幅・ステータス行・メニュー・検索・デバッガの下分割・型支援の
     表示 (ti_ui) など、文字の大きさを使う所を全部。
   - 日本語 (かな入力、漢字の表示、全角の幅 2) の扱いが崩れないこと。
     misaki 8 は半角 4px 相当になるので、半角と全角の幅の関係を確かめる。
2. **選ぶ口**: エディタのメニュー (View など、既存のメニューの形に揃える) で
   3 つから選ぶ。選ぶと即座に描き直す。
3. **保存**: `/home/editor.toml` (新設) に保存し、起動時に読む。ファイルが無い・
   壊れているときは ja12。既存の `/home/colors.toml [editor]` (配色) とは別の
   ファイルにする (plan の決定)。
4. **mruby 版と Spinel 版の両方** (標準構成はエディタが Spinel、互換構成は mruby)。
   Spinel の書き方の制約 (flash/app のアプリの規約、spinel の注意) に気をつける。
5. i18n (英語・日本語) のメニューの文言を足す。

## 検証

- sim (標準構成と互換構成): 3 つのフォントを切り替えて打鍵・日本語入力・
  スクロール・検索・F11 の往復。再起動後に選んだフォントが残る。
  エディタの起動・打鍵・閉じる・再起動・打鍵 (標準手順)。
- 実機 (P4-Nano、つながっていれば Tab5): 全画面 640x360 で 3 つのフォントの見え方。
  最後に止まって、ユーザに 1 回だけ目視を依頼する (時刻の照合は求めない)。
  見てほしい点: 3 つのフォントが崩れずに読めるか、桁数・行数の感触、日本語の表示。
- ブラウザ版 (web_*): 同じ操作。
- ビルド: TAB5 / NARYAv4 / S3 / Linux / wasm。静的な D/IRAM が H2 の値
  (TAB5 183,008、NARYAv4 178,410、S3 146,995) を超えない。
  Tab5 のアプリの区画の空きも記録する。

## 作業の決まり

- 作業ブランチ `feature/fullscreen-hires`。コミットは 2-3 本、自分が変えた
  ファイルだけをパスで指定。push とマージはしない。
- .env は書き換えずコミットしない。最後に `git diff .env` が
  scratchpad の env_before_hires.diff と一致することを確かめる。
- sdkconfig と graphics-audio は変えない。内蔵 RAM を増やさない。新しいフォントは足さない。
- report は日本語の常体。コードのコメントと commit メッセージは英語。

- 選んだフォントが /home/editor.toml に残り、再起動後も効く
- mruby 版と Spinel 版の両方で動く
- ユーザの目視で合格
- 静的な D/IRAM が H2 の値を超えない
