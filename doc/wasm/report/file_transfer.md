# 報告: ブラウザ版へのファイルの持ち込み (F1-F4)

> 状態: 完了 | 更新: 2026-09-03 | 放り込み・フォルダ結び付け・追随・書き戻し
> まで実装し、ユーザ確認済み。設計は file_transfer.md

計画どおり F1 から F4 まで入れた。ここには**書いてみて初めて見えたもの**と、
**誰が何を確かめたか**を残す。

## 計画に無かった判断 3 つ

いずれも「動きはするが費用が見合わない」形で、実装するまで見えなかった。

**1. 取った時刻の表を handle と一緒に IndexedDB へ残す。** handle だけ覚えても、
再訪のたびに作業場を丸ごと読み直す。素材が主用途で 1 枚数十 KB なので、
これは毎回の待ちになる。表があれば 1 ファイル 1 stat で済む。

**2. 書き出した直後に、その時刻を表へ書く。** 書かないと次の巡回が
「外の方が新しい」と見て、たった今出した中身を全部写し戻す。

**3. 再接続用に横取りした click は名前付きにする。** 無名の包みで
`addEventListener` すると `removeEventListener` が効かず、**ボタンが
その訪問の間ずっと乗っ取られたまま**になる。再接続の後に普通の選択が
できなくなる。

## 誰が何を確かめたか

**Claude が確かめられたもの**

- 行き先の規則 9 件。`folderTarget` と `writeInto` を**実ソースから取り出して**
  node で実行した (写しではないので、ソースが変われば試験も変わる)。
  `settings.toml` を持つ画像フォルダが `/home` 行きになること、`..` と
  絶対パスが剥がれて 2 つの store の外に出ないことを含む。
- ページが例外なく起動すること (機械が上がることで分かる)。
- `flappy` 改名後にランチャーが FlappyDemo を出し、素材ごと動くこと。

**Claude には動かせなかったもの (ユーザ確認)**

- 放り込みとファイル選択。
- `showDirectoryPicker` と許可の付与。
- 書き戻し。

**注入はキャンバスの入力に入る経路**で、ページの DOM に drop や file dialog を
起こせない。音の官能評価や実タッチと同じ区分。ユーザが 2026-09-03 に
「フォルダ選択して、ローカルで作成したファイルが Family mruby 側でも見えている」
「back するとFamily mruby側の編集がローカルに反映される」を確認して閉じた。

## 判定の規則が `flappy` を直させた

フォルダがアプリかどうかは **`*.app.toml`** で見る。ランチャー自身は `.toml`
なら何でもよいが、あれは `/app` の中を歩いていて、そこにある物は構造上すべて
アプリなので緩くて済む。外から来るフォルダには文脈が無い。

この規則を書く段になって、梱包の中に `flappy.toml` / `flappy.rb` という
**唯一の例外**があることが問題になった (他は 71 本すべて `*.app.toml`)。
規約に例外が 1 つあると規則の方が間違って見えるので、改名した (a3c30809)。

## 残っている疑問

**`/app/usr` のファイルが再読み込みで消えた例がある。** 別セッションが
作っていた `/app/usr/paint_pad/paint_pad.app.rb` が、再読み込み後に
**フォルダだけ残ってファイルが無い**状態になっていた。/app/usr は IDBFS で
永続のはずの場所である。

- この持ち込みの実装が原因ではない (追加した経路は放り込みか選択でしか
  動かず、そのとき一度も走っていない)。
- 疑うのは 2 つ。**autoPersist が書き戻る前にページが消えた**か、
  **2 枚目のタブとして使い捨ての /home を掴んでいた**か。
- 再現の条件が分かっていないので追えていない。**機械が書いた直後に
  リロードする**手順で再現を試すのが次の一手。

作業場を結び付けている間は、書いたものが外にも出せるので傷は浅くなった
(それがこの機能の副産物でもある)。
