# T3・T4 報告: 記憶域の見せ方と、/home の持ち出し

> 状態: 完了 | 更新: 2026-08-31 | 恒久化要求・使用量・一台だけが書く規則・tar の書き出し / 取り込み / 消去。すべてページ側だけ

指示書は instruction_storage.md。T2 (report/storage_t2.md) の続き。

## T3: ページが状態を言う

`wasm/web/index.html` に 1 行足した (`Your files (/home): ...` と 3 つのボタン)。

- **恒久化の要求**: `navigator.storage.persisted()` → 偽なら `persist()`。
  結果を文言に混ぜる。headless Chrome では拒否される (利用実績がないため)
  ので、実測でも「kept in this browser, but the browser may reclaim it」に
  なる。**拒否されても動作は変わらない** — 消えやすいかどうかだけが変わる。
- **使用量**: `navigator.storage.estimate()` の `usage` を KB で出す。
  出所は同一オリジン全体なので /home だけの量ではない。今は 1 KB 台。
- **一台だけが書く規則**: Web Lock `fmrb-home` を `ifAvailable: true` で
  取り、取れたタブだけが割り当てを行う。取れなかったタブは**割り当てず**、
  揮発の /home で動く。二つの機械が同じ IndexedDB を最後に書いた方で
  丸ごと上書きする事故を、これで構造的に避ける。

### 実測

同じページを iframe で二枚目として読み込み、その文言を親から読んだ:

```
FSPROBE lock: second tab says "another tab has them open -- changes here are NOT saved"
```

二枚目は起動前 (機械を立ち上げる前) にこう言う。**先に言う**ことに意味が
あるので、鍵が取れなかった時点で表示を更新している。

## T4: 書き出し / 取り込み / 消去

`/home` をまるごと **tar** にする。zip でなく tar なのは、書くのも読むのも
数十行で済み、端末側も同じ形式を知っているため。実装はページの JS だけ
(機械の microtar は使わない)。

- **書き出し**: `/home` を再帰的に歩いて ustar のヘッダを組み、Blob を
  ダウンロードさせる。ファイル名は `fmrb-home-YYYYMMDD.tar`。
- **取り込み**: ヘッダを読み、**名前は必ず組み直す** —
  `split('/')` して `''` `.` `..` を捨ててから `/home` の下に繋ぐ。
  取り込み後に `syncfs(false)`。
- **消去**: `/home` の中身を子から順に消して `syncfs(false)`。
  **/home は空で出荷される (T1) ので、これがそのまま出荷状態**である。
  確認の問いを一度挟む。

### 実測 (ブラウザ内で往復させた)

`?fsprobe=1` に自己検査を仕込んで測った:

```
FSPROBE t4: after erase /home holds [".",".."]
FSPROBE t4: restored 3 file(s), /home holds [".","..","t4.txt","sub","escaped.txt"]
             sub=[".","..","deep.txt"] deep=nested
FSPROBE t4: escaped out of /home = no, landed as [".","..","t4.txt","sub","escaped.txt"]
```

- 入れ子のディレクトリごと往復した (`sub/deep.txt` の中身も一致)。
- 消去は本当に空にする。
- **`../escaped.txt` という細工した名前は外に出られない**。`/flash/escaped.txt`
  は作られず、`/home/escaped.txt` として着地した。

### 書き出した tar を GNU tar に読ませた

検証のあいだだけ probe に base64 の吐き出しを足し、出てきたファイルを
ホストの `tar` にかけた (吐き出しは検証後に外した):

```
-rw-r--r-- 0/0    5 2026-08-31 09:07 t4.txt
drwxr-xr-x 0/0    0 2026-08-31 09:07 sub/
-rw-r--r-- 0/0    6 2026-08-31 09:07 sub/deep.txt
```

展開しても中身が一致した (`sub/deep.txt` = "nested")。**ヘッダの検算・
ディレクトリ項目・パディングとも正しい**。ついでに、細工した
`../escaped.txt` は GNU tar 自身も拒む (`Member name contains '..'`)。

## 気づき

- **T1 (/home を空にする) がここでも効いた**。「消去 = 出荷状態」が
  「中身を全部消す」で書ける。手本が /home に居たら、消去のたびに
  手本を配り直す仕掛けが要り、その版をどう決めるかの問題が戻ってくる。
- 取り込みは「PC のファイルを /home に入れる」導線も兼ねる。これまで
  ブラウザ版には外から物を入れる道が無かった。
- 取り込みと消去の後は**リロードを勧める文言**にした。機械は起動時に
  一覧を作る場所があり (ランチャーの索引など)、走っている最中に足元の
  ファイルが変わったことを知らせる手段が無いため。
- `persist()` が拒否されるのは headless では正常。実ブラウザで人が触った
  ページでは通ることが多い。**通らなくても壊れない**作りにしてある。

## 実ブラウザで見つかった穴 (2026-08-31、ユーザ報告)

**3 つのボタンがどれも無反応だった**。ボタンは disabled で出荷し、機械が
上がったら有効にする作りなのに、その「有効にする」呼び出しが**取り込みの
処理の中に紛れ込んでいた** — 取り込みでしか有効にならず、その取り込みは
ボタンが無効で始められない。無効なボタンはクリックを黙って飲むので、
処理が繋がっていないように見える。

書き換えを機械任せ (最初に一致した箇所を置換) にしたのが原因で、
headless の検査は tar の往復を関数呼び出しで直接試していたため、
**ボタン経由の経路だけが誰にも通られていなかった**。
[[新しい構成は無言の穴を持つ]] の実例がまた 1 つ。

対処: `?fsprobe=1` に**3 つのボタンが有効かどうか**を出させた。実ブラウザで
「3 つとも有効」「Download のクリックで処理が本当に走る
(`wrote N entries to a .tar`)」を確認済み。

ページの文言も 2 か所古かった。「リロードすると書いたものは消える」は
/home について嘘になっていたので、**何が残り何が残らないか** (とくに /tmp)
に書き換えた。「網には一切繋がらない」はユーザの指示で削除 — 外向きの
通信はこれから増える予定で、**古びて嘘になる約束は書かない方がよい**。

## 残り

- エディタで書いて保存 → リロードの実操作 (ブラウザ側に UI 自動操作の
  道具が無い。経路は T2 で確認済みだが、人の手で一度確かめたい)。
- 恒久化が通った場合の表示 (headless では常に拒否されるため未確認)。
