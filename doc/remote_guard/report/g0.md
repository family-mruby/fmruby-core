# G0 報告: 開発のビルドで読み書きを自由にし、/home を WiFi で退避・書き戻す

> 開始 2026-11-15 23:42 (JST) / 終了 2026-11-16 00:03 | 指示書: ../instruction_g0.md | 決まりの正: doc/dev_remote_ctl/plan.md の「開発のビルドの決まり」

## 1. 変えた所

### ファーム (fmruby-core)

- `main/drivers/devctl/devctl_http.c`・`.h`
  - **`devctl_fs_unrestricted()`** を足した (「開発のビルドだけ自由」を表す 1 か所)。`FMRB_DEV_REMOTE_CTL` で true。
    true のとき `/fs/*` は `/` の下を全部 (4 つの根の制限なし)、`/fs/get` は鍵 (FMRB_PATH_SECRET)・パスワード
    (FMRB_PATH_PASSWORD) も渡す。false のときは前の決まりのまま (G1・G2 の足場)。`..` は常に断る。
  - **`GET /fs/md5?path=`**: ファイルの MD5 と大きさ (ROM の `esp_rom_md5`、4 KB の既存の buffer で読む)。
    app_sync と退避の照合に使う。restricted なら鍵は get と同じく断る。
  - **`POST /sys/reboot`**: 答えてから 300 ms 後に `fmrb_platform_sys_power(FMRB_SYS_POWER_RESET)`
    (FmrbSystem.reboot と同じ。保存待ちの音量・ミュートを先に書く)。
  - **`devctl_status_ident()`**: `/status` に `"board"` (FmrbConst::BOARD の綴り) と `"host"` (mDNS 名
    fmruby-XXXXXX) を足す。退避の置き場の名前に使う。
- `main/drivers/remote_desktop/rd_http.c`: `/status` に上の 2 つ (開発のビルドだけ。リリースの `/status` は今のまま)。
  `max_uri_handlers` 24 → 28 (使うのは 24)。
- `main/drivers/devctl/devctl_task.c` (Retro): `/status` に同じ 2 つ、`max_uri_handlers` 14/17 → 16/19。
- コメントだけ: `main/kernel/fmrb_secret_path.h` (devctl は restricted のときだけこの決まりに従う)、
  `main/CMakeLists.txt`、`test/secret_path/main.c`。**BLE の console の決まり (`fmrb_secret_path.c`) は変えていない。**
- リリースのビルド: devctl は入らない (`FMRB_DEV_REMOTE_CTL=OFF`) ので動きは変わらない。rd_http の追加は
  `#ifdef FMRB_DEV_REMOTE_CTL` の中だけ。

### rake (fmruby-core rakelib/device.rake)

- **CH34x は最初から 115200 bps**: `rake flash`・`flash:app` (と下の新しい task) は、ポートの USB vendor が 1a86
  (sysfs) なら `-b 115200`。sysfs が読めなければ FMRB_HW_TARGET が NARYAv3・NARYAv4 のとき。`FLASH_BAUD=` が勝つ。
  ほかの端末は今までどおり idf.py の既定 (460800)。
- **`rake flash:keep_home HOST=`**: (a) 新しい像の `/etc/wifi.toml` で WiFi が上がるか確かめる (無い・`enable = false`・
  ssid 無しなら**焼かずに止まり**「keep_home_serial を使う」と返す) → /home を WiFi で退避 → (b) `rake flash`
  → (c) WiFi に戻るのを待つ (240 s。IP が変われば mDNS 名で引き直す。戻らなければ exit 3 で
  `rake flash:keep_home_serial BACKUP=<dir> STORAGE_ONLY=1` を案内) → (d) 書き戻す → (e) `/sys/reboot` して待つ。
- **`rake flash:app_sync HOST=`**: `rake flash:app` → 起動を待つ → `build/storage_root` と端末の差を送る。
- **`rake flash:keep_home_serial`** (今の手順を道具にした予備): esptool の read_flash で storage を読み
  (`READ_BAUD` 既定 460800)、ビルドの venv の littlefs-python で開き、その /home を `build/storage_root` に重ねた像を
  作り、`build/flash_args` の storage.bin を差し替えて全体を書く。`BACKUP=<dir>` なら読まずに WiFi の退避の /home を使う、
  `STORAGE_ONLY=1` は storage の区画だけ。置き場は `BACKUP_DIR=`、`DEVICE=<機種>-<MAC 下 3>`、または HOST の /status から。
  終わったら置き場を `chmod -R go-rwx`。

### 道具 (family-mruby tools/)

- `tools/fmrb_rd_fs.rb`: `backup [dir]`・`restore <dir>`・`sync <storage_root>`・`wait`・`reboot` を足した。
  `.local` の名前は WSL では Windows の resolver で引く。本体はファイルの末尾で `$PROGRAM_NAME == __FILE__` の
  ときだけ動く (下の道具がクラスを読むため)。
- `tools/fmrb_flash_keep.rb` (新規): 焼く前後の WiFi の半分 (`prepare`・`finish`・`name`・`sync`)。rake と MCP が共有する。
- MCP (`tools/mcp/fmrb_mcp_server.rb`): flash に **`keep_home: true`**・**`app_sync: true`**・`ip` を足した。
  焼くのはサーバ自身の flash (capture の退避と再開) で、その前後で `fmrb_flash_keep.rb` を呼ぶので、書き戻しと
  再起動のログも capture に残る。prepare が断ったら何も焼かない。焼くのに失敗したら退避の場所を返す。
  tab5_fs の説明 (場所の制限、鍵の扱い) と 400 のときの案内を直した。

## 2. 道具の使い方と退避の置き場

```
ruby tools/fmrb_rd_fs.rb <IP> backup                 # ~/asterism_keys/devices/<機種>-<MAC下3>/home_backup_<YYYYmmdd-HHMMSS>/
ruby tools/fmrb_rd_fs.rb <IP> backup <dir>           # 途中で切れたら同じ dir でもう一度 (合っている物は取り直さない)
ruby tools/fmrb_rd_fs.rb <IP> restore <dir> [--force]
ruby tools/fmrb_rd_fs.rb <IP> sync fmruby-core/build/storage_root [--dry-run] [--conf]
cd fmruby-core && rake flash:keep_home HOST=<IP|fmruby-xxxxxx.local> [BACKUP_DIR=]
cd fmruby-core && rake flash:app_sync  HOST=<IP|fmruby-xxxxxx.local> [CONF=1]
cd fmruby-core && rake flash:keep_home_serial DEVICE=p4nano-xxxxxx [BACKUP=<dir>] [STORAGE_ONLY=1]
MCP: flash(keep_home: true) / flash(app_sync: true)
```

- 退避の中身: `home/` (端末の /home の写し、空のディレクトリも)、`manifest.json` (全ファイルの大きさと MD5、
  ディレクトリ、board・host・ip・時刻、`complete`)。ディレクトリ 700、ファイル 600 (umask 077 で作る)。
- 機種の名前: `/status` の board から (naryav4 → `p4nano`、narya_v3 → `naryav3`、ほかはそのまま)、MAC は host の
  末尾 6 桁 (WiFi の MAC。既存の `p4nano-xxxxxx` の形)。取れなければ `--machine`・`--mac`。
- 標準出力に出すのはファイルの名前と大きさだけ。中身は出さない。
- 退避は各ファイルを端末の MD5 と照合し `.part` → 名前付けで書く。書き戻しは送ったファイルをもう一度 MD5 で確かめる。
  端末にあって退避に無い物は一覧に出すだけで消さない。`complete: false` の退避からは戻さない。
- 属性: LittleFS は所有者・権限・日時を持たないので、保つのは名前・中身・ディレクトリ。

## 3. app_sync の差の取り方 (決めたこと)

- 端末の一覧の大きさと比べて違えば送る、同じなら `/fs/md5` で中身を比べる。日時は使わない (littlefs-python の像も
  devctl の put も mtime を持たない)。ハッシュの計算は端末側 (ROM の MD5) で、ファイルを PC に引かない。
- 送らない所: `/home`・`/tmp`・`/mnt`・`/var/cache`、それと **`/etc/system_conf.toml`** (端末が保存した設定。
  音量・ミュートもここ。違えば「保った」と一覧に出し、`CONF=1` / `--conf` で送る)。仕様の選択に当たるかもしれない
  ので親に見てほしい (全体 flash はこれも出荷の状態に戻す)。
- 端末にあってビルドに無い物は消さずに一覧だけ。
- storage の木は最後のビルドが残した `build/storage_root` (焼く前に `rake build:esp32`)。

未測定。

## 5. 確かめた結果

- **`rake regress`**: host 29 suites 全部通過 (secret_path を含む)、描画の記録 229 runs 全部通過。
- **ESP32 (NARYAv4) のビルド**: 通った (`file build/fmruby-core.elf` は RISC-V)。devctl・rd_http に新しい警告なし。
  **DIRAM 124,876 B** (W1b・W1b-2 の報告と同じ値で、内蔵 RAM の静的な増分 0)、image 7,629,952 B。
  `build/` に残した (焼くのは親)。`.env` は NARYAv4 にして作り、終わってから戻した。
- **devctl の sim・ネイティブ版での確認**: できない。devctl は ESP32 だけ (sim・ネイティブ版・ブラウザ版に同じ口は
  無い。main/CMakeLists.txt で esp32 のときだけ入る)。
- **道具**: devctl と同じ答え方の偽の端末 (Ruby の小さな HTTP サーバ、scratchpad) で確かめた。
  - backup: 既定の置き場の名前 (`p4nano-abcdef/home_backup_<日時>`)、700/600、空のディレクトリ、MD5 の照合。
  - 途中から: 1 ファイルを切り詰めて同じ dir で流す → 1 つだけ取り直し、2 つは保った。
  - restore: /home を空にした端末へ戻す → `diff -r` で一致、空のディレクトリも戻る、退避に無いファイルは一覧だけ。
    2 回目は送る物 0。`complete: false` の退避は断る (exit 1)。
  - sync: 同じ大きさで中身の違うファイルを MD5 で見つけて送る、新しいファイル・空のディレクトリを作る、
    /home と /var/cache に触らない、system_conf.toml は保って一覧、ビルドに無いファイルは一覧だけ、2 回目は送る物 0、
    `--dry-run` は何も書かない。
  - fmrb_flash_keep.rb: prepare (WiFi の確かめ。`enable = false` で exit 3、焼く前に止まる)、finish (待つ → 戻す →
    reboot → 待つ)、答えない端末で exit 3 と serial の案内、name、sync。
  - keep_home_serial の像の部分: `build/storage_root` に退避の /home を重ねた木から littlefs-python (コンテナ) で
    8 MB の像を作り、開き直して `diff -r` で一致 (空のディレクトリも残る)。read_flash と書き込みは実機が要るので未実行。
  - MCP: `ruby tools/mcp/selftest.rb` 全部通過。keep_home・app_sync の通しは実機が要るので未実行。
- **実機 (P4-Nano)**: 未 (親が焼く)。下の 6 章。

## 6. 親が P4-Nano で流すこと

今の P4-Nano のファームは G0 より前なので、WiFi では鍵を渡さず `/status` に board・host も無い。**最初の 1 回は
serial で /home を残して焼く**。シリアルは親の MCP の capture が掴んでいるので、rake で焼くときは先に serial_stop。
`.env` は NARYAv3 のままなので、rake には `FMRB_HW_TARGET=NARYAv4` を前に付ける (ビルドは esp32p4 で、焼くのは
`build/` の物)。

1. 最初の書き込み (今の手順を道具で):
   ```
   (MCP) serial_stop
   cd /home/kishima/fmrb/family-mruby/fmruby-core
   FMRB_HW_TARGET=NARYAv4 rake flash:keep_home_serial DEVICE=p4nano-xxxxxx
   (MCP) serial_start
   ```
   置き場は `~/asterism_keys/devices/p4nano-xxxxxx/home_backup_serial_<日時>/` (storage.bin・extract・merged_root・
   storage_keep_home.bin・flash_args_keep_home)。手でやる従来の形でもよい。
2. 起動の後: `curl -s http://<IP>/status` に `"board":"naryav4","host":"fmruby-xxxxxx"` があること。ログに
   `the file endpoints reach every path, keys included` の行。
3. WiFi の退避と中身の確認 (大きさだけ):
   ```
   cd /home/kishima/fmrb/family-mruby
   ruby tools/fmrb_rd_fs.rb <IP> backup        # 最後の行 backup=<dir>
   ls -l <dir>/home/asterism <dir>/home/wifi.toml   # .tar があること (中身は開かない)
   ```
4. 小さなファイルを足して戻す:
   ```
   echo g0 > <dir>/home/g0_restore_test.txt
   ruby tools/fmrb_rd_fs.rb <IP> restore <dir>     # g0_restore_test.txt だけ送られる
   ruby tools/fmrb_rd_fs.rb <IP> ls /home          # 出てくること
   ruby tools/fmrb_rd_fs.rb <IP> del /home/g0_restore_test.txt
   ```
5. 通し: MCP の `flash(keep_home: true)` (または `FMRB_HW_TARGET=NARYAv4 rake flash:keep_home HOST=<IP>`、
   rake のときは serial_stop を先に)。退避 → 焼く → 書き戻し → 再起動の後、/home・WiFi・Asterism の鍵が残って
   いること、所要時間 (rake は最後に段ごとの秒数を出す)。
6. (任意) MCP の `flash(app_sync: true)`: 送られたファイルの数、所要時間、system_conf.toml の扱い。
