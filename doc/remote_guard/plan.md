# WiFi の遠隔操作に制約を付ける計画

> 状態: 計画済 | 更新: 2026-11-15 | 開発用の遠隔操作 (アプリの起動・終了、ファイルの読み書き、画面と入力) は今は無認証で、同じ LAN の誰でも使える。開発のビルドは読み書きを自由のままにし (鍵の読み出しも許して /home の退避を WiFi でできるように)、リリースのビルドでは書ける場所を絞り (G1)、端末の上で許可したときだけ開く (G2)。正式な経路は Asterism の認証に寄せる (G3)。SDK の利用者がリリースのファームでも端末で許可すれば wasm のアプリを送って試せる形にする

## 目的

- 同じ LAN にいるだけで、端末のアプリの起動・終了・ファイルの書き換え・画面の閲覧と入力ができる状態をやめる。
- そのうえで、put → launch の開発ループ (Tab5 の自律操作、wasm の SDK の手順書の「実機に送る」) は使い続けられる
  ようにする。開発の速さを落とさない。
- 2026-11-15 ユーザ: 「WiFi のシステム操作系は今後制約を考えたい」→ 親の案 (G1 → G2 → G3) で計画する。

## 今の状態 (2026-11-15)

| 口 | 中身 | 今の制約 |
|---|---|---|
| devctl (`main/drivers/devctl/devctl_http.c`) | `/app/launch`・`/app/kill`・`/app/list`・`/app/checkpoint`・`/app/move`、`/fs/list`・`/fs/get`・`/fs/put`・`/fs/del`・`/fs/mkdir`、`/audio/*` | `FMRB_DEV_REMOTE_CTL` (開発のビルドで ON、リリースで OFF)。無認証。鍵 (secrets.toml・wifi.toml・/home/asterism の .tar) は get で読めない。put・del はどこでも |
| リモートデスクトップ (`main/drivers/remote_desktop/rd_http.c`) | `/stream`・`/ws_video` (画面)、`/ws` (キーとマウスの入力)、`/status` | 無認証。入力を注入できるので、ランチャー経由で何でも起動できる |
| BLE (debugd) | Retro のデバッグ | この計画の対象外 (BLE の接続の作法で別) |

## 方針

- **開発のビルドとリリースのビルドで分ける (2026-11-15 ユーザ)**: 開発のビルド (`FMRB_DEV_REMOTE_CTL` が ON) では
  読み書きを自由にする。場所の制限も許可の手順も付けない。鍵 (secrets.toml・wifi.toml・/home/asterism) の読み出しも
  許し、/home の退避を WiFi でできるようにする (今は 8 MB の storage をシリアルで読み出している。doc/reference/TODO.md
  の「/home を残したまま焼く」)。G1・G2 の制約はリリースのビルド (と、開発のビルドから外したいときの選択肢) に
  かける。

- 軽い順に入れる。G1 と G2 で「LAN の誰でも」をなくし、G3 で正式な経路を作る。
- 「信頼できるメンバーだけの網」(Asterism の前提) と揃える。素の HTTP は開発の補助として残す。
- 開発のループ (Claude の MCP の tab5_* と fmrb_rd_*.rb、SDK の手順書) は、許可の手順を 1 回踏めば今と同じ速さで
  回ること。道具の側は合言葉 (トークン) を覚えて毎回付ける。
- 実機の確認はユーザがつないだときだけ (Tab5・P4-Nano)。sim・ネイティブ版での確認を先に。

## 段

| 段 | 内容 | 状態 |
|---|---|---|
| G0 | **開発のビルドで鍵も読めるように**: 開発のビルドでは `/fs/get` の鍵の除外を外し、/home を鍵ごと WiFi で退避・書き戻しできる道具 (`fmrb_rd_fs.rb` の pull/push と、焼く前後の退避・書き戻しを rake と MCP の flash の選択肢に) を作る。リリースのビルドでは鍵は読めないまま | 未着手 |
| G1 | **(リリースのビルド) 書ける場所を絞る**: `/fs/put`・`/fs/del`・`/fs/mkdir` を `/home` と `/app` の下だけにし、ほか (`/usr`・`/etc`・`/boot` など本体の領域) は理由つきで断る (HTTP 403)。`/fs/get`・`/fs/list` の鍵の扱いは今のまま。道具 (fmrb_rd_fs.rb・MCP の tab5_fs) が本体の領域へ put している所を洗い出し、置き場を直すか、開発のビルドだけの別の許可にする (未確定事項 1)。sim・ネイティブ版・ブラウザ版に同じ口があれば揃える | 未着手 |
| G2 | **(リリースのビルド) 端末の上で許可する**: Config に「開発用の遠隔操作」を足す (既定 OFF)。ON にすると一定時間 (既定 30 分、未確定事項 2) だけ開き、画面に短い合言葉 (数字 6 桁など) を出す。PC は最初に合言葉を送ってトークンを受け取り、以後の要求にトークンを付ける (ヘッダ)。トークンが無い・切れた要求は 401。対象は devctl の全部と、リモートデスクトップの入力 (`/ws`) と画面 (`/stream`・`/ws_video`、未確定事項 3)。`/status` は開いたまま (道具の端末の見分けに使う)。道具 (fmrb_rd_*.rb・MCP の tab5_* と tab5_ip) はトークンを `~/.config/fmrb/` に端末ごとに覚えて付け、401 なら「端末で許可して合言葉を」と分かる言葉で返す。リリースのファームにもこの口を入れる (既定 OFF なので、許可しない限り閉じている) | 未着手 |
| G3 | **Asterism に寄せる**: 遠隔の操作 (アプリの起動・終了・ファイルの転送) の正式な経路を Asterism の認証 (利用者ごとの証明書、doc/asterism_file_transfer の T8) の上に置く。ファイルの転送は既にある。素の HTTP の口は開発の補助に格下げし、既定で入れないビルドも選べるようにする | 未着手 (G1・G2 の後。計画を別に立てる) |

## 受け入れ条件

- G1: 本体の領域への put・del が理由つきで断られ、`/home`・`/app` は今までどおり。Claude の開発ループ (put → launch) が
  回る。`rake regress` と、devctl の試験 (sim かネイティブ版)。
- G2: 端末で許可していないとき、devctl とリモートデスクトップの入力が 401。許可して合言葉を入れると今と同じに使え、
  時間が過ぎると閉じる。Config の表示と、合言葉が画面に出ること。MCP の tab5_* が 401 を分かる言葉で返す。
  内蔵 RAM の静的な増分 0。
- どの段も、SDK の手順書 (family-mruby-sdk の docs/getting_started) の「実機に送る」節を合わせて直す。

## 未確定事項

1. ~~本体の領域への put を開発のビルドで許すか~~ → 開発のビルドは読み書き自由 (2026-11-15 ユーザ)。
2. リリースのビルドで開いておく時間 (30 分・再起動まで・明示的に閉じるまで)。開発のビルドは許可の手順なし。
3. 画面の閲覧 (`/stream`) も許可の対象にするか。見るだけでも中身が見える (プライバシー)。
4. トークンの置き場 (端末: NVS か `/etc` のファイル。checkpoint の対象外にする) と、複数の PC を許すか。
5. HTTPS にはしない前提 (端末の負担と証明書の配り方)。LAN の盗み見は G3 (Asterism の TLS) で扱う。
