# C6 指示書: NTSC の色のにじみ、時間で動く効果、既定の強さ (ブラウザ版の C2 と共通)

> 状態: 実装中 | 更新: 2026-11-08 | plan.md の C6 (ネイティブ版) とブラウザ版の C2 を一緒に。シェーダーは共通なので、効果は両方に入る

正は plan.md (決定事項・方針)。ここには C6 の範囲と進め方だけを書く。

## 範囲

1. **NTSC の色のにじみ**: 色の解像度を横に落とす (輝度はそのまま、色差を横にぼかす)。
   Retro の実機 (WROVER の NTSC 出力を家庭のテレビに出す) の見え方に寄せる。
   強さ 0〜100、0 は計算しない。
2. **時間で動く効果**: ちらつき (明るさのゆらぎ) とノイズ (粒)。強さ 0〜100、
   **既定は 0** (決定事項: 入れると毎コマ描くことになる)。0 より大きいときだけ、
   画面が変わらなくても一定の間隔 (30 コマ/秒を目安、決めたら report に) で描く。
   0 なら今どおり「画面が変わったときだけ描く」を保つ。
3. 2 つの効果を、シェーダー (`hosted/crt/`) と、強さの設定の全部の口に足す:
   - ネイティブ版: 機種の定義の `crt_ntsc`・`crt_flicker`・`crt_noise` (名前は合わせて
     決めてよい)、`--set`、利用者の `[crt]`、PC の設定の Window の「画面」のページの
     stepper、「既定に戻す」。
   - ブラウザ版: ページの Display の欄の調整と、保存 (`writeSetting`)、`?look=crt`。
4. **既定の強さの詰め** (未確定事項 1): 今の既定 (走査線 55・格子 30・にじみ 30・
   曲がり 15・四隅 40) と、新しい効果の既定の案を、GPD の実画面で見比べられるように
   する。**見て決めるのはユーザ**。いくつかの組 (たとえば「控えめ」「今の既定」
   「強め」と、NTSC のにじみの有無) を、ユーザが設定の画面か `comp crt ...` で
   切り替えて見比べられる形で用意し、親に返す。決まった値を既定にするのは、
   ユーザの決定を受けてから。

## 確認

- `rake webcrt:test` (JS と C の曲がりの式・シェーダーの写しが古くない)、
  `rake regress`、`rake regress:wl`、`rake regress:screens` (web を含む。既定の見た目、
  つまり CRT 切のときは変わらない。CRT 入の既定の見た目は、新しい効果が既定 0 なら
  変わらないはず)。
- ネイティブ版: GPD (ssh、鍵。`.deb` は `~/fm-deb/fm.deb` に送り
  `sudo -n apt install -y /home/kishima/fm-deb/fm.deb`、ログインし直しはユーザ)。
  時間で動く効果を入れたときの重さ (1 コマの CRT の描画、何コマ/秒描いたか) を
  ログで測り、効果を 0 に戻したら描画が「変わったときだけ」に戻ることを確かめる。
  画面写しは GPD の `grim` (`WAYLAND_DISPLAY=wayland-0 XDG_RUNTIME_DIR=/run/user/1000`)。
- ブラウザ版: headless の Chromium で、新しい効果を 0 にしたときの絵が今と同じ
  (バイトまで) であること。
