# C5 指示書: ネイティブ版の CRT の選び口 (設定の画面)

> 状態: 計画済 (未確定事項 1 つ、ユーザの決定待ち) | 更新: 2026-11-07 | plan.md の「ネイティブ版のコンポジタ (C4〜C6)」の C5。設定の画面で CRT の入り切りと効果ごとの強さを変え、すぐ効かせ、次のセッションでも覚えている

正は plan.md の「ネイティブ版のコンポジタ」の節 (決定事項・方針・受け入れ条件)。
ここには C5 の範囲と進め方だけを書く。下回り (コンポジタの `crt_set`) は C4 で済んでいる。

## 範囲

1. **置き場所**: PC の設定の Window (`native/apps/linux_settings.app.rb`、ネイティブ版だけに
   ある。今は Wi-Fi・Bluetooth の 2 ページ) に 3 つ目のページ「画面」/ "Display" を足す。
   デスクトップのメニューに「画面...」/ "Display..." を足し、このページで開く
   (`FmrbApp.linux_settings("display")`。ページの番号は今の 1 ビットを 2 ビットに広げる)。
2. **中身**: CRT の入り切り (Sharp / CRT の 2 つの toggle)、5 つの強さ (走査線・格子・
   にじみ・曲がり・四隅の暗さ、0〜100、FmrbUI の stepper、5 刻み)、「既定に戻す」
   (5 つの強さをブラウザ版の既定 55・30・30・15・40 に戻す。入り切りはそのまま。ブラウザ版の
   Defaults と同じ)。日本語と英語の文言。
3. **すぐ効く**: 変えるたびに、コンポジタの `crt_set` を呼ぶ (Family mruby の task から
   wlroots の main thread へ渡す。`comp_link` と同じく eventfd で起こす)。
4. **覚える**: 下の「未確定事項」で決める置き場所に書き、次のセッションの起動で読む。
5. **無い端末**: CRT を出せない所では、メニューの「画面...」とページの tab を**出さない**
   (Bluetooth の項目が BlueZ の無い所で出ないのと同じ扱い)。ESP32・sim・ブラウザ版は
   設定の Window 自体が無い。ネイティブ版で出さないのは、コンポジタでない (sdl・drm の
   backend) とき、描画器が GLES でない (pixman など) とき。判定は `FmrbApp.crt_state`
   (新規、ネイティブ版だけ。出せないときは "") で。
6. ブラウザ版のページの Display の欄は今のまま (統合しない)。

## 未確定事項 (ユーザに聞く)

利用者が設定の画面で選んだ値と、`/etc/default/family-mruby-session` の `FMRB_ARGS`
(`--set display.look=crt` など) のどちらが勝つか。

- **案 A (推奨)**: 設定の画面の値が勝つ。画面で一度でも変えたら、Family mruby の
  `/etc/system_conf.toml` (利用者の etc、`~/.local/share/family-mruby/etc/`) の `[crt]` の表に
  書き、起動のときにそれで機種の定義と `--set` を上書きする。`/etc/default` の指定は
  「まだ選んでいない人の既定」になる。sudo の要らない所だけで完結する。
- 案 B: `--set` が勝つ。`/etc/default` に書いた項目は、画面で変えてもそのセッションの間
  だけで、次のログインで戻る (書いていない項目は保存した値が効く)。管理者が固定できるが、
  画面の変更が「覚えない」ように見える。

## 確認

- `rake regress` (ホストの試験と描画の記録。sim の画面が変わるならその基準の更新は
  別コミット)、`rake regress:wl` (コンポジタ。pixman で「画面...」が出ないこと、sharp の既定で
  今と変わらないこと)。
- GPD: パスワード無しの apt (`sudo -n apt install -y /home/kishima/fm-deb/fm.deb`) で入れ、
  制御のソケット (`comp crt`) で値が変わったこと、保存した値がセッションをやり直しても
  残ることを確かめる。ログインし直しと見た目はユーザ。
