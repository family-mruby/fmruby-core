# 報告 C1: CRT 風の表示の下回りと主な効果

> 状態: 完了 | 更新: 2026-10-29 | WebGL2 の表示用 canvas を #screen に重ね、走査線・格子・にじみ・曲がり・四隅の暗さを自前のシェーダーで描く。座標は同じ式で戻す。既定の見た目は変わらない

指示書は [../instruction_c1.md](../instruction_c1.md)、計画は [../plan.md](../plan.md)。

### 重ね方

`#crt-view` は `#screen` の上に絶対配置で重ね、`pointer-events: none` で
イベントを素通しにした。`#screen` は CSS で隠さず、上から覆われるだけになる。
これで**マウス・タッチ・キーのフォーカスは今までどおり `#screen` が受ける**
ので、入力の扱いは何も変えていない。CRT を切ると `#crt-view` は `hidden` に
なり、ページは元の形そのもの (`#screen` の pixelated の拡大) に戻る。

表示用 canvas の画素は `#screen` の表示の大きさ × `devicePixelRatio`。
applyZoom の最後で位置と大きさを合わせるので、Zoom の切り替え、窓の大きさ、
全画面、ブラウザの拡大 (resize として届く) に追従する。高解像度の 640x360 との
行き来は、枠 (426x240 の基準の大きさ) が変わらないので表示の canvas は
そのままで、テクスチャの大きさだけが変わる。

### 描く回数

paint は今までどおり絵の通し番号が変わったときだけ `imageData` を作り直し、
その同じ `imageData.data` をテクスチャに送る (SharedArrayBuffer の view は
渡さない)。通し番号が同じ rAF では `flush()` を呼ぶだけで、大きさか設定が
変わったときしか描かない。

### シェーダー

自前で書いた (外のシェーダーは見ていないし入れていない)。計算はすべて元の
画素が単位。

- 走査線: 元の 1 行に 1 本のガウスの光線。明るさで幅 (σ 0.20〜0.38) が
  変わるので、明るい文字は詰まり、暗い行は隙間が開く。暗くなる分は利得で
  一部を戻す。
- 格子: アパーチャーグリル (元の 1 画素に R・G・B の縦縞 3 本)。
- にじみ・光り: 横の隣と混ぜる + 周り 10 画素の明るさの 2 乗を後から足す
  (走査線と格子の隙間が光で埋まる)。
- 曲がり: `d' = d * (1 + c|d|^2)` (d は -1..1)。c は 0〜0.25 (スライダ 100 で
  0.25)。
- 四隅の暗さ: `16 x y (1-x)(1-y)` のべき。
- 強さ 0 の効果は uniform の分岐で飛ばす。
- 倍率による自動の弱め (どの解像度でも同じ式): 表示の画素 / 元の画素を
  `scale` として、走査線は 1.5〜3 倍、格子は 2〜3 倍で smoothstep で 0→1。
  426x240 を 3 倍で出すと両方とも全量、640x360 を同じ枠 (約 2 倍) に出すと
  走査線は約 0.26、格子は 0 になる。

## 格子をアパーチャーグリルにした理由

- 3 倍 (1 元画素 = 3 表示画素) のときに縦縞 3 本がちょうど 1 表示画素ずつに
  乗る。シャドウマスクは点を互い違いに並べるので縦にも 2 段が要り、3 倍では
  1 段が 1.5 表示画素になって縞がにじむ。6〜8 倍くらいないと形にならない。
- 縦縞は走査線 (横縞) と直交するので、合わせても網目になるだけで
  文字の形を崩さない。426x240 の 6px の英字がこれで読めた (下の画像)。
- Retro の実機の出力先は家庭のテレビ (多くはシャドウマスク) なので、
  雰囲気としてはシャドウマスクのほうが近い。高い倍率のときだけシャドウ
  マスクを選べるようにするかは C2 でユーザと決める。

## 確認

### 回帰

- `rake regress`: host 19 本すべて通過、描画の記録 205 本すべて通過。
  `rake webcrt:test` (曲がりの往復) は 55 項目すべて通過。
- `rake regress:screens ONLY=retro` 8/8、`ONLY=modern` 10/10 通過。
- ブラウザ版の画面: 本体の checkout で tools/fmrb_web.rb のブラウザが開いて
  いると `regress:screens` の web は始まらない (既存の守り)。閉じてはいけない
  ので、`ruby tools/regress/screens.rb --only web --attach web --port <その
  ページのポート>` でそのページに対して流した。既定の見た目で 6/6 通過、
  **CRT を入れたままでも 6/6 通過** (画面写しは `#screen` を読むので変わらない)。

### 撮った画面

ブラウザ (dpr 1) で 3 倍、CRT 既定の強さ。`fmrb_web.rb view` で撮った表示用
canvas そのもの (1278x720)。

- [c1_modern_desktop_crt.png](c1_modern_desktop_crt.png): Modern 426x240 のデスクトップ
- [c1_editor_hires_crt.png](c1_editor_hires_crt.png): エディタを F11 で全画面 (640x360) にして 1 行打った所
- [c1_curve_strong.png](c1_curve_strong.png): 曲がり 100 (c = 0.25)

### 座標 (曲がり 100)

表示の画像から位置を読み、`fmrb_web.rb dom click X Y` で本物の DOM の
mousemove・mousedown・mouseup を `#screen` に送った (canvasPos を通る)。

| 押した所 (表示の CSS 画素) | 機械に届いた座標 | 結果 |
|---|---|---|
| メニューバー右のかな指示器 (818,70) | 283,5 | A → あ に変わった。さらに 2 回押して ア → A へ戻した |
| 左上の Family mruby (220,85) | 37,5 | メニューが開いた |
| 開いたメニューの Editor (170,142) | 21,30 | エディタが開いた |
| 表示の左上の角 (5,5)・右下の角 (1270,715) | — | 絵の外として捨てた |

また、曲がりを入れた画像に描かれた機械のマウスカーソルが、送った位置の
アイコンの上に出ていた。

### WebGL2 が無いとき

ヘッドレスの Chromium (別のブラウザ、開発サーバは同じ) で確認した。

- `getContext('webgl2')` が null を返すようにして `?look=crt` を開く →
  `fmrb: CRT look unavailable: no WebGL2` の 1 行、Look は Sharp pixels で
  選べなくなり、`#crt-view` は隠れたまま、`#screen` は pixelated のまま。
- 確認用の `?webgl=0` でも同じ形に戻る (ログは `turned off by ?webgl=0`)。
- `?look=crt` だけ: CRT が入り、`fmrb_web_look` は保存されない。
- 指定なし: 今までどおり。

### 描画の回数と重さ

- デスクトップで何も触らずに 10 秒: 機械の絵の通し番号が 10 進み (時計の
  1 秒ごとの更新)、テクスチャの送りが 10 回、描画が 10 回。rAF の約 600 回
  のうち描いたのは絵が変わった回だけ。
- 1 回の描画は 1278x720 で約 2.7 ms (60 回描いて毎回 1 画素の読み戻しで
  GPU を待たせた平均。`crt bench=60`。Windows の Chrome、WSL 経由の
  開発サーバ)。読み戻しの待ちを含むので実際の 1 回はこれより軽い。
- テクスチャは 426x240 で約 400 KB、640x360 で約 900 KB を絵が変わるたびに送る。
- dpr 2 のヘッドレス (1400x1000) で、3 倍・2 倍・Fit の各場合に表示用 canvas が
  `#screen` と同じ位置・大きさに重なり、画素が 2 倍 (2556x1440 など) に
  なることを確認した。

## 見立てと違った点

- **曲がりの式の向き**: 指示書は「絵→表示の写しを JS とシェーダーで同じ式に
  し、canvasPos はその逆」としていたが、断片シェーダーは表示の 1 点ごとに
  絵のどこを読むかを計算するので、自然に書けるのは表示→絵のほう。そこで
  **表示→絵 (`warpToSource`) を JS とシェーダーで同じ式**にし、canvasPos は
  これをそのまま使う (反復なし、描いた画素と押した画素が必ず一致する)。
  絵→表示 (`warpToDisplay`) はその逆で、ニュートン法で解く。試験は
  絵→表示→絵の往復で、426x240 と 640x360 の全画素が元の画素へ戻ることを見る。
- **`#screen` を隠す方法**: CSS で隠すと入力とフォーカスの受け手が変わるので、
  上から覆うだけにした。止まる条件の「重ねるとタッチ・フォーカスが崩れる」は
  起きていない。
- **regress:screens の web**: 開いている駆動のブラウザがあると始まらない
  (既存の守り)。上の `--attach` で代えた。

## 撤回した仮説

- 曲がりを「辺の中点が表示の辺に来る」ように正規化する案。中央は拡大されて
  見栄えはよいが、四隅が絵の外へ押し出され、左上のメニュー (Family mruby) や
  右上の時計が押せなくなる。正規化しない式にして、**絵全体が必ず表示の中に
  残り、外になるのは周りの黒い所だけ**にした。
- CRT を切ったら GL の文脈を捨てる案。同じ canvas からは失った文脈を取り直せ
  ないので、一度作った表示は隠して取っておき、次に入れたときに使い回す。

## 決めたこと (小さなもの)

- 曲がりの外で押したボタンを離したときは、最後に機械へ送った位置で離す
  (押したままにならないように)。ホイールも外では最後の位置で送る。押下と
  移動は捨てる。pushInput の形は変えていない。
- `?look=crt` の訪問中はスライダを動かしても保存しない (`?res=` と同じ扱い)。
  `?look=flat` も受ける。
- Erase は Look と強さも消す。Download / Restore にも載せた。

## 残件

- ブラウザの全画面は道具からは入れない (ユーザの操作が要る)。位置合わせは
  applyZoom を通るので同じ経路だが、実際の全画面での見た目と座標は人の目で
  確認したい。スマホの実タッチも同じ。
- 見た目の善し悪しと既定の強さは C2 でユーザと詰める (Retro の実機の写真と
  見比べる)。シャドウマスクを高倍率で選べるようにするかもそこで。
- NTSC の色のにじみと時間で動く効果は C2。
- Safari は未確認 (WebGL2 はあるはず)。
- 確認のため、駆動のページの Zoom を 3 倍にして撮り、終わってから 1 倍へ
  戻した。始める前に Zoom が保存されていたかは確かめておらず、今は "1" が
  保存されている。
