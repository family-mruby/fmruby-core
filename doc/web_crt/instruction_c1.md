# 実装指示書 C1: CRT 風の表示の下回りと主な効果

計画は doc/web_crt/plan.md (決定事項の節が正)。この段では C1 の行の中身を作る。

作業ブランチ: fmruby-core で develop から `feature/web-crt` を切る (feature/linux-native
とは混ぜない)。本体 checkout で直列。

## 作るもの

1. **重ねる canvas**: `wasm/web/index.html` と `main.js` に、WebGL2 で描く表示用の
   canvas を足す。元の `#screen` (2D) は絵の正としてそのまま残し、今までどおり
   `paint()` が書く。CRT が入っている間だけ表示用の canvas を見せ、`#screen` は
   見えなくする (画面写しと回帰はこれまでどおり `#screen` を読む)。
   - 表示用の canvas の画素は CSS の大きさ × `devicePixelRatio`。`applyZoom()`・
     全画面・高解像度の 640x360 との行き来に追従する。
   - テクスチャの更新と描画は、絵の通し番号が変わったときと大きさ・設定が
     変わったときだけ。SharedArrayBuffer の view を WebGL に直接渡さず、今の
     `imageData.data` を使い回す。
   - WebGL2 が取れない・シェーダーの組み立てに失敗したときは、ログを 1 行出して
     今の pixelated の表示に戻す (CRT の選び口は無効にする)。
2. **シェーダー** (自前で書く。外のシェーダーの写しや GPL のコードは入れない):
   走査線 (明るい画素ほど線が太る)、蛍光体の格子 (アパーチャーグリルかシャドウ
   マスク。どちらにするかは作って見て決め、report に理由)、にじみ・光り、画面の
   曲がり、四隅の暗さ。計算は元の画素を単位にし、拡大の倍率が小さいときは走査線と
   格子を自動で弱めてモアレを抑える (どの解像度でも同じ式)。強さ 0 の効果は計算
   しない (uniform で分岐するか、組み合わせごとに組み直すかは任せる)。
3. **座標の戻し**: 曲がりは、元の画素の座標 → 表示の座標の写しを 1 つの純粋な
   関数 (JS) とシェーダーで同じ式にし、`canvasPos()` とタッチの座標の割り戻しは
   その逆で元の画素へ戻す。逆は解析的でも数回の反復でもよい。曲がりで絵の外に
   なった所の押下・移動は捨てる (ホイールは今の位置のまま)。
   - この写しと逆の往復を node で試す小さな試験を足す (置き場所は既存の試験の
     流儀に合わせる。`rake test` に載せられるなら載せる)。
4. **選び口**: Display の欄に CRT の入り切りと、効果ごとの強さ (走査線・格子・
   にじみ・曲がり・四隅の暗さ) のスライダ、「既定に戻す」。`writeSetting` で覚える。
   `?look=crt` で CRT を既定の強さで入れる (覚えている設定より優先、ただし書き
   換えない。今の `?res=` と同じ扱い)。NTSC の色のにじみと時間で動く効果は C2
   なので、この段では欄を作らない。
   - 既定の強さは仮でよい (C2 でユーザと詰める)。3 倍の拡大で 426x240 の 6px の
     英字が読めることを目安にする。

## 確認

- `rake regress` と `rake regress:screens` (ブラウザ版の画面を含む。既定の見た目では
  1 画素も変わらないこと)。
- ブラウザ版は `ruby tools/fmrb_web.rb` で動かす (使い方は `--help`、経緯は
  doc/wasm/report/drive_tool.md)。`screenshot` は `#screen` (絵の正) を返すので、
  **CRT の見た目を撮る手段が要るなら、ページ側の命令 (例: 表示用の canvas を返す
  命令) を足してよい**。足したら `--help` にも書く。
- 撮って report に添える (画像は doc/web_crt/report/ に置いてよい):
  - Modern 426x240 のデスクトップ、3 倍相当、CRT 既定の強さ。
  - 高解像度の全画面のエディタ (640x360) で同じ設定。
  - 曲がりを強めにした画面。
- 座標: 曲がりを入れた状態で、表示の上の決めた点 (例: 四隅に近いアイコン、
  メニューバーの項目) に本物の DOM のマウスイベントを送り (ページの中で
  `dispatchEvent` する命令を足してよい)、狙った物が押されることを確かめる。
  `click` 命令は座標を直接リングに入れるので、この確認には使えない。
- WebGL2 を使わせない状態 (例: `getContext('webgl2')` が null を返すようにした
  確認用の URL の指定) で、今の表示に戻ること。
- 絵が変わらない間に WebGL の描画が走っていないこと (数え上げで示す)。

## 触ってよい範囲

- `wasm/web/` (index.html・main.js、必要なら新しい js ファイル)、`tools/fmrb_web.rb`
  (命令を足す場合)、試験の置き場所、doc/web_crt/。
- wasm の C・ファームウェア・sim・ネイティブ版は触らない。

## 止まる条件

- 既定の見た目の画面写しや回帰の比較が変わってしまうと分かったとき。
- 座標の戻しで、今の入力の流れ (pushInput の形) を変える必要が出たとき。
- 見立てと違う事実 (例: 表示用の canvas を重ねるとタッチ・フォーカスの扱いが
  崩れる) が出たとき。

## 守ること

- `rake clean_all` はしない (wasm の生成物が消える)。sudo しない。本当の HOME・
  /etc・/usr に書かない。
- tools/fmrb_web.rb が開いているブラウザ (pid 551298 前後) は閉じない (`down` も
  しない)。そのページを `reload` で動かすのはよい。終わったら CRT を切った既定の
  設定に戻しておく。
- 公開のブラウザ版への配置はしない。
- 終わったら `feature/web-crt` にコミット (領域名は `wasm`、英文、Co-Authored-By
  を付ける)。push はしない。文書に手元の絶対パスやユーザ名を書かない。
- report は `doc/web_crt/report/c1.md`: 選んだ格子と理由、既定の強さの仮の値、
  描画の回数・重さ、見立てと違った点、撤回した仮説、残件。
