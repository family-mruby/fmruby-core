# P7.5 報告書: APU 再生の「外れた音」を直す

対象: `doc/midi/work_order_p7_5.md`。
前提: [p7.md](p7.md)、[p6.md](p6.md)。

指示書の 2 件を直した。**主犯 (和音の戻り発音)** は「同じ瞬間のメッセージを
まとめ、声ごとに 1 回だけ確定する」段を transport に足して消し、
**低音のクランプ**はオクターブ折り返しに変えた。どちらも割り当てゼロ
(P6/P7 の成果) を維持している。

## 0. 結論だけ先に

| | 変更前 | 変更後 |
|---|---|---|
| The Entertainer 1 曲で APU に送る声の書き換え | **1517 回** | **500 回** (-67%) |
| うち「どの瞬間も最後に鳴る音」 | - | **500 の瞬間すべてで変更前と一致** |
| sim の音 (13 秒) の音高変化 | 12.1 回/秒 | 10.5 回/秒 (-14%、3 章) |
| sim のリンクメッセージ (再生中) | 27 /秒 | 16 /秒 |
| A1 より低い音 (パルス) | **全部 55 Hz** | 音名を保って 1 オクターブ上げ |
| レガートの戻り発音 | あり | **あり (維持)** |
| 単発発音の即時性 | 即時 | **即時 (維持)** |
| 1 イベントあたりの割り当て | 0 個 | **0 個 (維持)** |

## 1. タスク B: 同じ瞬間のメッセージをまとめる (主犯)

### 1.1 何が起きていたか

APU の 1 声は単音・後着優先なので、1 チャンネルに書かれた和音 C-E-G は
G だけが鳴る。ここまでは仕方がない。問題は**離鍵**で、G の note off が来ると
`note_off` の fallback が **held に残る E へ戻り発音**し、続く E off で C へ
戻り、最後に C off で無音になる。**楽譜に無い音が 2 つ、拍からずれて鳴る**。

fallback 自体は正しい。**別の瞬間にまたがる重なり (レガート) を繋ぐ**ための
ものだからである。誤っていたのは、それが**同じ瞬間の中でも働いていた**こと
だった。

### 1.2 直し方: 瞬間の区切りを transport に教える

`ApuTransport` に 2 つのメソッドを足した。

```ruby
transport.defer_voices   # ここから
...  note_on / note_off  # 声の状態は更新するが、何も送らない
transport.flush_voices   # 触られた声に、最終状態を 1 回ずつ送る
```

- **グループの外では今までどおり即時**。アプリの打鍵やドラムパッドが
  境界を待たされることは無い (指示書 2.3)。
- `SmfPlayer#tick` が 1 回の呼び出しで配る分をこれで囲む。tick は
  複数の出口 (`return`) を持っていたので、**配る処理を `run_due` に
  切り出し**、`tick` は「開いて、配って、閉じる」の 3 行にした。
  どの経路で抜けても閉じる。
- 確定の規則 (`resolve_voice`):
  - held が空 → 無音を 1 回。
  - そうでなければ最新の held が声を取り、**そのグループがその音を
    始めたとき**か**今鳴っている音と違うとき**に発音する。
    前者が和音の打鍵と同音連打、後者がレガートの受け渡しである。
    **グループの中で始まって終わった短い音は、下で鳴り続けている
    長い音に触らない** (従来は戻り発音で叩き直していた)。
- **serial は対象外**。実音源はポリフォニックなので、この問題が無い
  (`SmfPlayer` は出力が `flush_voices` を持つときだけグループを開く)。

### 1.3 「同じ瞬間」の定義

実装上のグループは「**1 回の `tick` で配った分**」である。楽譜上の tick と
厳密に一対一ではなく、同時に期限が来た数 tick 分が入ることがある。
これは意図的で、数 ms 以内に配られるイベントは**まとめたほうが正しい**
(APU では中間状態が「鳴ってしまう」だけだから)。まとめ過ぎる心配は
`due > now` で即座に返る作りと `STALL_MS` の追いつき抑制が抑えている。

### 1.4 割り当てゼロの維持

グループ用の作業領域 (`@touched` / `@grouped_on`) は初期化時に確保した
4 要素の配列で、中身は Integer と真偽値だけ。bench アプリで実測:

```
alloc apu grouped chord (6 events): 16 objects/100 calls
```

25 回の反復 (= 150 イベント) で 4 個、これは測定枠そのものの分である。
**1 イベントあたり 0 個**を維持している。P6/P7 の他の数字も変わっていない
(`play: 0 objects/10 events`、`play: gc=0`)。

## 2. タスク A: 低音のオクターブ折り返し

### 2.1 変えたこと

`PULSE_FREQ` はノート 0〜32 が全部 55 Hz (A1) に張り付いていた。11 ビットの
タイマーで出せる最低音がそこだからである。**バスが 1 つの高さに潰れる**ので、
リズムだけ残って和声が消える。

範囲外の音は**クランプではなく +12 ずつ上げて範囲に入れる**ようにした
(`tool/midi/gen_apu_note_table.rb` の `playable_note`)。音名が保たれるので、
バスは 1 オクターブ上で同じ和音を綴る。

| | 最低音 | 折り返す音 |
|---|---|---|
| パルス (16 分周) | MIDI 33 (A1, 55 Hz) | 0〜32 |
| 三角波 (32 分周) | MIDI 21 (A0, 28 Hz) | 0〜20 |

### 2.2 上端は触らない (指示書 1 の判断)

**上端はクランプされていなかった**。127 まで、どの音も丸めた結果が
タイマーの下限 (パルス 8 / 三角 2) を下回らない — 測って確認した。
残っているのは**タイマーの分解能**で、ノート 126 と 127 が同じタイマー 8
(約 12.4 kHz) を共有する。ここを -12 で折り返すと、半音の誤差を直すために
**わざとオクターブずらす**ことになり、しかも対象は 10 kHz 超で音高の
知覚がほぼ効かない領域である。**触らないほうが良い**と判断した。

### 2.3 横断一致 (P5-sim の検証項目)

**`tool/midi/smf2fmsq.rb` にも同じ折り返しを入れた**。事前変換とリアルタイムで
同じ音高になることは P5-sim からの約束で、片方だけ直すとそこが壊れる。
ホストテストに「折り返した音でも両経路のタイマーが一致する」を追加した
(最悪 10.1 セント。これは低音域の整数 Hz 分解能そのもので、折り返し前から
ある値)。

生成器の出力形式も、gem のファイルにそのまま貼れる形に揃えた
(インデントと `.freeze` の有無)。再生成しても差分が出ない。

## 3. 検証

### 3.1 ホストテスト (決定的なほう)

`transport_test.rb` に 8 項目、`smf_player_test.rb` に 4 項目を追加した。
とくに後者は、**問題が報告された曲そのもの (The Entertainer) を 2 回再生**して
比べる:

```
every instant ends on the same note it used to (0 of 500 instants differ)
the writes it drops are the ones nobody could hear (1517 writes to the APU became 500 (-1017))
almost every instant still writes something (0 of 500 instants write nothing)
```

比較の相手は「グループを提供しない出力」でラップした同じプレーヤで、
**変更前の挙動をそのまま再現している**。ここで効いているのは 2 つ目ではなく
**1 つ目**である: 書き込みを 3 分の 1 に減らしても、**どの瞬間も最後に
鳴っている音は 1 つも変わらない**。減ったのは中間状態だけ、と言い切れる。

レガートと単発の維持も項目にした:

```
legato across two instants still falls back to the held note
a note struck and released inside one instant leaves a longer one alone
a note repeated inside one instant is struck again
outside a group a note sounds immediately
```

### 3.2 sim の音 (指示書 3.2)

変更前後で同じ曲を APU で 13 秒ずつ録り (`tools/fmrb_audio_probe.rb --dump`)、
`tool/midi/wav_segments.rb` (新規) で**音高が変わった回数**を数えた。
波形を目で見る代わりに数える道具で、APU の声は周期波なので
「周期が変わった回数 = 鳴った音の数」になる。

```
p75_before.wav  13.9 s  sounding 13.4 s  pitch changes 163  (12.1/s)
p75_after.wav   13.5 s  sounding 13.1 s  pitch changes 137  (10.5/s)
```

**14% 減**。書き込みが 67% 減ったのに音の変化が 14% しか減らないのは、
**sim では中間状態のほとんどが音にならないから**である。同じ tick の
メッセージは Ruby の数十マイクロ秒差で連続して届き、15.7 kHz の出力では
1 周期にも満たない。

**これは「sim では過小に出る」ことの説明でもある**。実機ではメッセージが
kernel -> リンク -> WROVER と渡るぶん、隣り合う書き込みの間隔が桁違いに
広がり、中間状態が音として何周期も鳴る。P4/P5-sim でこの不具合を
捕まえられなかった理由も同じで、**耳で分かるようになるのは実機**である。
リンクの負荷としては sim でもはっきり見える:

```
再生中の tx_msg   変更前 27/s -> 変更後 16/s
```

### 3.3 単発の即時性 (指示書 2.3)

デモの「1 Scale」(8 音、200 ms 音 + 60 ms 休み) を録って数えた:

```
p75_scale.wav  3.3 s  sounding 1.8 s  pitch changes 8
```

**8 音がそのまま 8 回**。遅れも取りこぼしも無い (1.8 s = 8 x 200 ms + 端数)。

### 3.4 sim のアプリ

`midi_apu` (SMF 再生・音が出る)、`smf_player` (一覧・選曲・再生)、
bench (割り当てとバイト列) を起動して確認した。P7 で見つけた
`tetris` の起動不能 (P7.5 とも無関係、p7.md 5 章) はそのままである。

## 4. 実機での確認手順

**聴くのはユーザ**。焼き方は p7.md 6.1 と同じ (計測ビルドである必要は無い。
GC は今回関係しない)。

### 4.1 主犯が消えたか

1. SMF プレーヤ (`/app/tool/smf_player.app.rb`) で **The Entertainer** を
   APU 出力で再生する。
2. 聴くのは**和音の切れ目**。変更前は和音を離すたびに、内声が短く
   ぽろぽろと鳴っていた (拍とずれた「外れた音」)。**それが無いこと**。
3. 同じ曲を「MIDI out」(Unit MIDI) に切り替えて聴き比べる。
   **APU 側が外部音源と同じ和声進行に聞こえれば成功**である
   (声の数は違うので、和音の一番上の音だけが鳴る)。

### 4.2 レガートが残っているか

つながった旋律 (bach_sheep_bwv208.mid など) で、**音が途切れずに
繋がって聞こえること**。ここが途切れるなら確定処理が効きすぎている。

### 4.3 低音

**bach_polonaise_bwv117a.mid** など低音のある曲で、バスが 1 つの音に
潰れず動いて聞こえること。変更前は A1 より下が全部同じ高さだった。

### 4.4 単発

MIDI APU デモの「1 Scale」「3 Drums」を押して、**押した瞬間に鳴る**こと。
piano アプリの打鍵でも同じ (piano は `FmrbAudio` を直接使うので、
この変更の影響を受けないことの確認になる)。

### 4.5 横断一致

`tool/midi/smf2fmsq.rb` で同じ曲を FMSQ に変換して再生し、**リアルタイム
再生と同じ高さに聞こえること**。低音の折り返しは両経路に入れてあるので、
ここがずれたら片方の再生成漏れである。

## 5. やらなかったこと

- **4 声への圧縮そのもの** (指示書 0-3)。物理限界なので対象外。
  メロディ系は忙しい順に 3 チャンネルまで、4 つ目以降は無音のまま。
- voice-stealing の方針 (後着優先) は変えていない。
- serial 経路、受信、`picoruby-midi` は無改変 (md5 一致を維持)。
