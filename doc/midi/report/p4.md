# P4 報告書: 実時間 SMF プレーヤ

対象: `doc/midi/work_order_p4.md`。
前提: [README.md](../README.md)、[p1.md](p1.md)、[p2.md](p2.md)。

アプリから .mid を読んで再生・停止でき、曲中のテンポ変更に追従し、
再生しながらテンポを変えられる状態になった。sim で確認済み。

## 1. 作ったもの

| 位置 | 中身 |
|---|---|
| `lib/add/picoruby-fmrb-midi/mrblib/fmrb-smf.rb` | `FmrbMidi::SmfPlayer` (SMF の逐次パーサ + スケジューラ) |
| `lib/add/picoruby-fmrb-midi/mrblib/fmrb-midi.rb` | `ApuTransport#auto_map` を追加 (曲が使う ch から声を割り当てる) |
| `flash/app/demo/midi_apu.app.rb` | デモに「5 SMF」「6 Fast」を追加 |
| `flash/data/midi/scale.mid`, `tempo_change.mid` | デモ用の .mid (自前生成なので権利関係なし) |
| `tool/midi/test/smf_player_test.rb` | ホストで走る単体テスト (24 項目) |
| `tool/midi/test/sim_play/crash_note.app.rb` | 6 章の検証用 (flash には入れない) |
| kernel の `audio_handler.rb` / `app_lifecycle.rb` | 異常終了したアプリの音を止める (下記 6) |

使い方:

```ruby
player = FmrbMidi::SmfPlayer.new(FmrbMidi.device(self))
player.load("/data/midi/song.mid")
device.transport.auto_map(player.channel_usage)   # 曲に合わせて声を割り当て
player.start

def on_update            # FmrbApp の中で
  player.next_delay(100) # 期限の来たイベントを送り、次までの待ち時間を返す
end

player.tempo_scale = 1.5
player.pause / player.resume / player.stop
player.transpose = 12
```

## 2. 置き場所とメモリ (指示書 2 章の判断)

**(a) Ruby で `picoruby-fmrb-midi` に置いた**。ただし「曲を読み込んで
イベント列を作る」形は採らず、**ファイルのバイト列を 1 本の String で持ったまま、
期限が来たイベントだけをその場で復号する**形にした。

### なぜイベント列にしなかったか (先に見積もった)

イベント 1 個を Ruby の Array (tick, status, data1, data2) で持つと、
mrb_value 16 バイト x 4 + オブジェクトヘッダで **1 イベント約 100 バイト**。
P1 で扱ったバッハの曲は 1284 音 = note on/off で 2568 イベントあり、
**約 257 KB**。アプリの VM プールは 512 KB でアプリの他の用途と共有なので、
曲 1 本で半分を持っていかれる。採れない。

### 逐次方式の実測

デモアプリで `FmrbApp.ps` の `mem_used` を読み、`GC.start` を挟んで
読み込み前後を測った (sim):

| 曲 | ファイル | プール増分 |
|---|---:|---:|
| `scale.mid` (自前生成、8 音) | 105 B | **+216 B** |
| `Sheep.mid` (BWV 208、4 トラック、892 音) | 10,217 B | **+10,680 B** |

**増えるのはほぼファイルサイズそのもの** (差分はトラックカーソルと文字列の
ヘッダ)。892 音の曲で 10 KB なら、512 KB のプールに対して 2% であり、
イベント列方式の 250 KB 級とは比較にならない。

構造としては、トラックごとに [読み位置, 終端, 次イベントの絶対 tick,
ランニングステータス, 終了フラグ] の 5 要素だけを持ち、毎回いちばん早い
トラックを選んで 1 イベント進める。**曲の長さに比例して増えるものが無い**。

## 3. 時間の設計 (指示書 3 章)

P2 の教訓 (Ruby で予約を持つと叩く間隔が精度になる / 早起きで曲が進むと
速くなる) をそのまま引き継いだ。

### 時刻の権威は 1 つ

`Machine.board_millis` だけを基準にする。プレーヤは経過時間を足し込まず、
**「次のイベントが鳴るべき絶対時刻」を毎回計算する**。計算は 2 段構え:

1. tick -> 曲中の経過マイクロ秒 (`ticks_to_us`)。テンポ (`us_per_quarter`) と
   分解能から求める。
2. 曲中時刻 -> 実時刻。`tempo_scale` を千分率で掛ける。

`tick` は「今より前のイベントをすべて送る」だけで、呼ばれた回数や間隔に
依存しない。**アプリが 10ms ごとに叩こうが 200ms ごとに叩こうが、曲の
テンポは変わらない**(ホストテストで確認)。

### 32bit で溢れないようにした

ESP32 の mruby は整数が 32bit の構成があるため、`tick * us_per_quarter` を
そのまま計算すると簡単に溢れる (4800 tick x 500000 = 2.4e9)。商と剰余に
分けて `(ticks * (us/div)) + (ticks * (us%div)) / div` と計算し、
**途中の値を小さく保ったまま誤差 1us 未満**にしてある。

### テンポは 2 系統、どちらも「今から先」だけに効く

| 系統 | 出どころ | 効き方 |
|---|---|---|
| Set Tempo | ファイル (曲中のテンポ変更) | イベントを処理した時点で切り替え |
| `tempo_scale` | ユーザ (実時間操作) | 呼ばれた時点で切り替え |

**優先関係は無く、掛け算で合成する**。ファイルが 240 BPM に変わったうえで
`tempo_scale = 1.5` なら 360 BPM 相当になる。どちらも変更前に
「今の位置」で時刻の基準を貼り直すので、**すでに鳴った音の間隔は動かない**
(ホストテストで確認)。

### 溜まったときは捨てずにずらす

アプリが長く止まって大量のイベントが期限を過ぎた場合、**200ms 以上遅れて
いたらスケジュール全体を遅れた分だけ後ろにずらす**。つまり曲が一瞬止まって
続きから再開する。

- 全部送ると、止まっていた間の音が一気に鳴って潰れる。
- 古いものを捨てると note_off を落とす危険がある (指示書 3 章の注意)。
- ずらす方式なら**何も捨てない**。曲が遅れるだけで、音は正しい順序で鳴る。

1 回の `tick` で処理するイベント数には 256 の上限を置いた。同一 tick に
イベントが極端に多い壊れたファイルでアプリのタスクを占有しないため。

## 4. 出力先 (指示書 4 章)

プレーヤは `MIDI::Device` にしか触らない。**送り先が APU か外部音源かを
知らない**。ドラムの解釈も 4 声への押し込みも transport の仕事のままで、
プレーヤは間引きを一切しない。

1 つだけ足したのが `ApuTransport#auto_map(usage)` である。実在の .mid は
チャンネル 1/2/3/10 を使うとは限らず (試した PD 曲は ch1-4 と ch1-5)、
既定の割り当てのままだと**音が 1 つも出ない**。プレーヤは
`channel_usage` (曲が使う ch と音数・平均音高) を返すだけで、
**それをどう声に割り当てるかは transport が決める**という分担にした。
規則は `tool/midi/smf2fmsq.rb --auto` と同じ (ch10 は打楽器、残りは音数の
多い順に 3 つ選び、平均音高の高い順に矩形波1/矩形波2/三角波)。

実際、BWV 208 で両者が同じ 3 チャンネル (ch0/ch1/ch3) を選び、
**鳴った音数も 892 で一致した**。

## 5. 検証

### 5.1 ホストの単体テスト (24 項目、すべて成功)

`ruby tool/midi/test/smf_player_test.rb`。時計を差し替えられるので、
**曲を一瞬で通して発音時刻を厳密に検査できる** (sim では測れない精度)。

| 見ているもの | 結果 |
|---|---|
| 120 BPM の 4 分音符 | 8 音がすべて **500ms 間隔ちょうど** |
| 音高 | 8 音とも P2 の音高テーブルの値と一致 |
| 曲中のテンポ変更 (`tempo_change.mid`) | 前半 500ms、後半 **250ms** に切り替わる |
| `tempo_scale = 2.0` | 全音が **250ms 間隔** |
| 再生中のテンポ変更 | 既に鳴った音の時刻は変わらず、以降だけ速くなる |
| 停止・一時停止 | 鳴っている音が必ず note_off される |
| 5 秒の一時停止からの再開 | 続きから、間隔 500ms のまま |
| 移調 (+12) | 1 オクターブ上の周波数になる |
| 複数トラック (`chord.mid`) | 3 トラックが同時に 3 声を鳴らす |
| 打楽器 (`drums.mid`) | ch9 がノイズ声に行く |
| 3 秒のストール | 1 回の tick で溜まった分を吐き出さない / 曲は最後まで鳴る |

デモアプリの「5 SMF」で `/data/midi/scale.mid` を再生し、共有メモリから
波形を採って測った。

**音高は P1 の事前変換と一致** (完了条件 4):

| 音 | P1: FMSQ 経路 | P4: SMF 実時間 |
|---|---:|---:|
| C4 | 261.35 Hz | 261.31 Hz |
| D4 | 293.58 | 293.58 |
| E4 | 330.15 | 330.81 |
| F4 | 349.62 | 349.62 |
| G4 | 392.35 | 392.35 |
| A4 | 440.63 | 440.63 |
| B4 | 494.91 | 494.91 |
| C5 | 522.69 | 522.73 |

**`tempo_scale` が実際に効く** (完了条件 3): 同じ曲・同じ計測経路で

| 設定 | 実測の平均間隔 |
|---|---:|
| x1.0 | 541 ms |
| x1.5 | 364 ms |

比は 1.49 で、指定どおり。10 KB の曲 (BWV 208) も 3 声で鳴ることを確認した

541ms に見える)。共有メモリのリングが埋まるとサンプルが落ちるためで、
プレーヤの精度ではない。**厳密な時刻はホストテストのほうが正しい**
(そちらは 500ms ちょうど)。比較には同じ経路で採った相対値を使った。

## 6. アプリ終了時に音が残る問題 (P2 の申し送り、直した)

**直した**。kernel 側で、**note を鳴らしたことのあるアプリが終了したら
その声を止める**ようにした。

- `fmrb_kernel/audio_handler.rb`: `note_on` を送ってきた pid を覚える。
- `fmrb_kernel/app_lifecycle.rb`: `cleanup_terminated_app` から
  `silence_notes_for(pid)` を呼び、4 声に note_off を送る。

置き場所を kernel にしたのは、**異常終了ではアプリ側のコードが一切走らない**
から。`cleanup_terminated_app` は正常終了・強制終了のどちらも通る。

「note_on を送ったことがある pid だけ」に限定したのは、**無関係なアプリの
終了で演奏中の音を切らないため**である (SUB は共有なので、無条件に消すと
別アプリの演奏が止まる)。

検証: 音を鳴らした直後に例外で落ちるアプリ
(`tool/midi/test/sim_play/crash_note.app.rb`) を sim で走らせた。

```
E AA Crash Note: Exception: RuntimeError: intentional crash while a note is sounding
I fmrb_kernel: Silenced note voices left by pid=5
```

直後の波形はピーク 0 (無音)。P2 では同じ状況で D4 が鳴り続けていた。

## 7. 申し送り

- **プレーヤの精度はアプリが `tick` を呼ぶ間隔で決まる**。`next_delay` を
  `on_update` の戻り値に使えば期限に合わせて起きるが、アプリが重い処理を
  していれば遅れる。遅れは 200ms を超えるとスケジュールごと後ろにずれる
  (音は落とさない)。厳密なタイミングが要る用途は事前変換 (FMSQ) のほうが
  適している、という P1/P4 の使い分けは変わらない。
- **ピッチベンドとアフタータッチは読み飛ばす**。APU に対応する概念が無く、
  `MIDI::Device#pitch_bend` 自体もこのビルドでは動かない (p2.md 3 章)。
- **SMF format 2 は非対応**。エラーを返して読み込みを失敗させる。
- **曲の途中への seek は未実装**。実装するなら、途中までのイベントを
  「音を出さずに」流してテンポと状態を再現する必要がある (テンポマップは
  逐次方式では前から辿るしかないため)。
- **デモに同梱した .mid は自前生成のもの**だけである
  (`tool/midi/test/make_test_midi.rb` の出力)。音楽として聴ける曲を入れる
  場合は、ライセンスをファイル単位で確認したものを `flash/data/midi/song.mid`
  として置けば、デモが自動でそちらを選ぶ。Mutopia の Public Domain 表記の
  ファイル (BWV Anh.117a、BWV 208 など) は変換・再生とも確認済み。
- **P4 は sim だけで確認した**。実機 (S3 / P4 ボード) は未接続。
