# P7.7 報告書: Ruby アプリの MML

対象: `doc/midi/work_order_p7_7.md`。
前提: [p7_6.md](p7_6.md) (キューの使い方)、[p7_5.md](p7_5.md) (声グループ)。

Ruby アプリから MML で演奏できるようになった。**パーサは Midori から
無改変で輸入**し、**プレーヤは P7.6 のキューに乗る形で新しく書いた**。
sim の実測で、`l4` @ 120 BPM が線上で **500.1 ms 間隔 (sd 0.59 ms)**、
APU の音高は**平均律から最大 7 セント**である。

## 0. 結論だけ先に

```ruby
player = FmrbMidi::MmlPlayer.new(FmrbMidi.device(self))  # APU でも serial でも
player.load_string("o4 l8 crdrerfrgrarbr>cr")
player.add_string("o3 l2 c g", channel: 1)               # 2 声目
player.bpm = 120
player.loop = true
player.start
```

| 確認したこと | 結果 |
|---|---|
| 音符間隔 (serial、モニタ実測) | **500.1 ms / sd 0.59 ms / 最悪 +1.0 ms** (`l4` @ 120 BPM) |
| C 側の発射遅れ (同じ再生) | avg 24〜609us / max 1.0 ms、under 0、drop 0 |
| APU の音高 (録音から実測) | C4〜C5 が **最大 7 セント**の誤差 |
| 再生中の割り当て | **0 個/イベント** (bench 実測、64 イベントで 4 個 = 測定枠の分) |
| 輸入ファイル | **md5 一致** (`mrblib/midi_mml.rb`, `mrbgem.rake`) |
| テスト | 143 -> **174 項目**、全通過 (MML の 31 項目を追加) |

## 1. 輸入したもの / しなかったもの

`lib/add/picoruby-midi-mml/` として gem ごと輸入した。詳細は同ディレクトリの
`FAMILY_MRUBY_PORT.md` (picoruby-midi と同じ体裁)。

| ファイル | 扱い |
|---|---|
| `mrblib/midi_mml.rb` (`MIDI::MML::Sequence`) | **無改変**。依存は picoruby-midi だけで、それは既にある |
| `mrbgem.rake` | **無改変** |
| `mrblib/midi_mml_player.rb` (`Player` / `CombinedPlayer`) | **輸入しない** (下記) |
| `example/`, `sig/`, `README.md` | 輸入しない。example の MML 文字列はホストテストの題材として使った |

**プレーヤを輸入しなかった理由**: Midori の `Player#tick(clock)` は
`MIDI.start!` の bpm ループから呼ばれる形で、**音はそのループが回った
ときに出る**。P7.6 で Family mruby はその逆に進んだ — プレーヤは時刻つき
コマンドを C のキューに預け、タイマーが送る — ので、これを輸入すると
bpm ループごと持ち込むことになり、キューの存在理由である精度を捨てる
ことになる。`FmrbMidi::MmlPlayer` が代わりを務める。

md5 での確認:

```
md5sum lib/add/picoruby-midi-mml/mrblib/midi_mml.rb \
       ../tmp/midori/mrbgems/picoruby-midi-mml/mrblib/midi_mml.rb
```

## 2. `FmrbMidi::MmlPlayer`

`SmfPlayer` と**同じ顔**にした (`load` / `start` / `stop` / `playing?` /
`tempo_scale=` / `tick` / `next_delay`)。アプリから見て .mid と MML が
入れ替え可能で、実装としても P7.6 のキューと P7.5 の声グループを
同じ形で通す。

### 2.1 クロックから時刻へ

`Sequence` は 4 分音符 = 24 クロックで事象を並べる。μs への変換は
プレーヤの仕事である (パーサにテンポの命令が無い。`t120` は黙って
無視されるので、`MmlPlayer#bpm=` が唯一のテンポ源)。

**1 イベントずつ足し込まない**: 120 BPM の 4 分音符は 500000/24 =
20833.3us で、毎回丸めると 1 小節ごとに 0.3 ms ずれる。掛けてから割る
形にして、テンポが変わったときだけ基準を置き直す。

```ruby
song_us(clock) = tempo_base_us + ((clock - tempo_base_clock) * 60_000_000) / (bpm * 24)
```

### 2.2 割り当て 0 のための表現

`Sequence#events` は Hash の配列で、パース時にはそれでよい。**再生中は
1 個も作らない**ので、load の時点で packed Integer に変換して持つ
(P6 の流儀):

```
bits  0-6   note      bits 7-13  velocity    bits 14-17 channel
bit  18     1 = note on           bits 19-   clock
```

クロックを上位に置いてあるので、**素の数値ソートが「クロック順、同じ
クロックでは note off が先」に並ぶ**。同時刻では離鍵が先に来てほしい
(単音の声を次の音に渡すため) ので、この並びがそのまま欲しい順序になる。

bench 実測:

```
mml: 64 events parsed
mml: 0 objects/10 events (4 over 64)
```

### 2.3 複数パートは 1 つのプレーヤで合成する

`add_string` で 2 声目・3 声目を足せる。**別々のプレーヤを 2 つ動かす
形にはしなかった**: C のキューは「1 つの生産者が時刻順に積む」前提の
FIFO で、2 つのプレーヤが交互に積むと順序が崩れる (先頭が遠い未来の
コマンドだと、後ろの近い未来がその後ろで待たされる)。load の時点で
マージして 1 本のソート済み列にすれば、この問題は起きない。

Midori の `CombinedPlayer` が実行時にやっていたことを、こちらは
**読み込み時にやる**という違いである。

### 2.4 ループ

`player.loop = true` で、末尾まで積んだら `loop_base_clock` を曲の長さ
だけ進めて先頭に戻る。**末尾の note off も 1 つのイベントとして積まれた
後で**折り返すので、ループ境界で音が残らない。sim で確認した (4.4)。

### 2.5 停止・出力先変更

`SmfPlayer` と同じ: **先にキューを捨て、後から note off** (逆だと捨て
損ねた note on が後に来て鳴りっぱなしになる。p7_6.md 4.4 の教訓)。

## 3. デモ (指示書 1.3 の判断)

**専用の小さなアプリ `flash/app/demo/mml.app.rb` を作った**。midi_apu
デモに足さなかった理由は 2 つ:

- midi_apu は既にボタンが 7 つあり、あれは「transport のデモ」である。
  MML は曲の書き方のデモで、見せたいものが違う。
- P6 で分かったとおり、**アプリのソースの大きさがそのまま VM プールを
  食う** (500 KB のうち 300 KB 強がコンパイルで消える)。既存アプリを
  太らせるより、小さいアプリを 1 つ足すほうが安い。

4 つの曲 (単声 1、2 声 3)、出力先の切り替え (`o`)、ループ (`l`)、停止。
**同じ MML が APU でも Unit MIDI でも鳴る**ことが 1 つのボタンで
見えるようにしてある。

曲の 1 つ目 (Scale) は `o4 l8 crdrerfrgrarbr>cr` と**スタッカートで
書いた**。単音の声でレガートの音階を鳴らすと音符が切れ目なく繋がって
しまい、耳でも録音でも 1 音ずつ確かめられないためである (4.2 で効いた)。

## 4. 検証

### 4.1 パーサ (指示書 2-1)

`tool/midi/test/mml_test.rb` に 31 項目。Midori の example の MML 文字列
(`play_scale.rb` / `two_part.rb`) を題材に、**この方言が何を意味するかを
固定**した。輸入ファイルは無改変なので、これは自分のコードのテストでは
なく**上流が変わったら気付くための記録**である。

固定したもの: 音名とオクターブ (`o4 c` = MIDI 60)、`>` `<` が 12 動く
こと、`+` `-` `#`、`l4` = 24 クロック、付点 (`c2.` = 72 クロック)、
タイ (`c4&8` = 36 クロック)、ループ (`[cd]3` = 6 音)、休符、`v`、
そして **`t120` は解釈されない**こと。

記録として面白かったもの: `o4 l4 cdefgab>cba<gfedc` は**上りと下りが
対称でない**。`>` でオクターブが 5 に上がったまま `ba` を弾くので、
下りの最初の 2 音は上りより 1 オクターブ高い。Midori の example の
ままの挙動で、直していない (テストにその旨を書いた)。

### 4.2 音高と間隔 (指示書 2-3, 2-4)

**serial (線の上)**: モニタのタイムスタンプで実測。

```
run 1: 15 notes  gap 500.1 ms  error mean +0.06 ms  sd 0.59 ms  worst +1.00 ms
  0.621  note on ch1 C4 vel=100 [90 3C 64]
  1.122  note on ch1 D4 vel=100 [90 3E 64]
  1.621  note on ch1 E4 ...
```

`l4` @ 120 BPM = 500 ms がそのまま出ている。音名も MML のとおり。

**APU (音そのもの)**: 録音を `tool/midi/wav_pitch.rb` で解析。

```
  0     0.190   0.280     261.35  C4      -1.8
  1     0.719   0.300     293.58  D4      -0.5
  2     1.258   0.290     330.95  E4      +6.9
  ...   3.955   0.280     522.73  C5      -1.7
```

**8 音すべてが正しい音名で、誤差は最大 7 セント** (APU のタイマーが
整数なので、この程度は原理的に残る。transport_test が offline 変換との
一致として別途固定している値と同じ性質)。

**注意 (sim の癖)**: この録音の音符間隔は 529〜550 ms に見えるが、
これは**シミュレータの音声パイプラインが実時間ちょうどのサンプルレート
で回っていない**ためで、演奏の遅れではない。同じ再生の serial 側は
500.1 ms である (時刻は同じキューが決めている)。音高は
「波形の周期 / サンプルレート」の比なので、この癖の影響を受けない。
実機の APU は水晶で駆動されるのでこの話自体が無い。

### 4.3 割り当て (指示書 2-2)

2.2 のとおり **0 個/イベント**。bench アプリに MML の測定を足してある
(`bench_mml`)。

### 4.4 sim のアプリ

| 操作 | 結果 |
|---|---|
| Scale を APU で | 8 音が正しい音高で鳴る (4.2) |
| Scale を serial で | モニタに正しい音名と 500.1 ms 間隔 (4.2) |
| Round (2 声) を APU で | 2 つの声が同時に鳴る (`peak=5632`)、ホストテストでも両パートが別の声に載ることを固定 |
| ループ再生 | 曲の長さ (4 秒) を越えて鳴り続ける。C 統計は `avg_late=24us` |
| 停止 | `peak=0`、音が残らない |

## 5. 実機での確認手順

**聴くのはユーザ**。MML は P7.6 のキューに乗るので、時刻の正確さは
P7.6 で実機確認済み (定常 avg 183〜931us) のものがそのまま効く。

1. `rm -rf build && rake clean_all && rake build:esp32` して焼く
   (計測ビルドである必要は無い。C 統計を見るなら `FMRB_GC_PROFILE=1`)。
2. ランチャーから **MML** を起動。
3. `1` (Scale) を押す。**APU でハ長調の音階が 1 音ずつ**鳴る。
4. `o` で出力先を Unit MIDI に変えて、もう一度 `1`。**同じ音階が
   外部音源で**鳴る。曲は同じ、音源だけが違う。
5. `2` (Round) で 2 声。APU は 2 つの矩形波に載る。
6. `l` でループを入れて `2`。**境目で音が途切れたり重なったりしない**こと。
7. `space` で停止。**音が残らない**こと。
8. ログを見るなら:

   ```
   grep "MmlDemo" play.log
   MmlDemo: events=30 fired=17 avg_late=24us max_late=203us under=0 q=0/2 drop=0/0
   ```

   読み方は p7_6.md 5.1 と同じ。

## 6. 残っていること

- **MML の方言は Midori のもののみ** (指示書 3 のとおり拡張しない)。
  テンポ命令が無いこと、`>` `<` がオクターブを持ち越すことは 4.1 の
  記録のとおり。
- BASIC の MML とは独立のまま (確定方針)。
- 同時に走らせられるプレーヤは 1 つ (2.3)。2 声以上は `add_string` で
  1 つのプレーヤにまとめる。
