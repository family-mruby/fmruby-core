# MIDI 対応 作業指示書 (P7.5: APU 再生の「外れた音」を直す)

対象: 実装セッション (Opus)
ブランチ: `feature/midi`
前提: [report/p7.md](report/p7.md)、[report/p6.md](report/p6.md)。
対象コードは `lib/add/picoruby-fmrb-midi/mrblib/fmrb-midi.rb` の
`ApuTransport` と `tool/midi/gen_apu_note_table.rb`。

## 0. 症状と原因 (特定済み)

実機の APU 再生で「音の一部が外れて変な音階になる」。原因は 3 つ特定済みで、
このうち 2 つを直す (3 つ目は APU の物理限界なので対象外):

1. **主犯: 和音の戻り発音アルペジオ**。1 声は単音・後着優先なので、
   同時和音 C-E-G は G だけ鳴る。ここまでは仕方ないが、和音の離鍵で
   G の note_off が来ると **held に残る E へ「戻り発音」**し、直後の
   E off で C へ、と**和音の内声が逆順に一瞬ずつ鳴る** (`fmrb-midi.rb`
   `note_off` の fallback)。レガート用の正しい仕様が、同時離鍵の和音で
   誤動作する。楽譜に無い音が拍とずれて鳴るので「外れた音」に聞こえる。
2. **低音のクランプ**。`PULSE_FREQ` はノート 0〜33 が全部 55 Hz (A1、
   タイマーの床) に張り付く。A1 より低い音は**全部 A1 で鳴る**。
3. (対象外) 4 声への圧縮そのもの: メロディ系は忙しい順 3 チャンネル
   まで、4 つ目以降は無音。物理限界。

Unit MIDI (16ch/64 音ポリ) では同じ曲が正しく聞こえることは実機で確認
済み。曲データは正しく、APU への押し込みで起きている。

## 1. タスク A: 低音のオクターブ折り返し (簡単な方)

`tool/midi/gen_apu_note_table.rb` を直して再生成する。

- 範囲外の低音は**クランプではなく +12 (1 オクターブ) ずつ上げて範囲に
  入れる** (チップチューンの定石。音名が保たれるので和声が壊れない)。
  パルスと三角波それぞれの床で折り返すこと。
- **上端の扱いは判断して報告に書く** (同じ原理なら -12 折り返しだが、
  高音側は現状でも音名は合っている。触らない判断でもよい)。
- **横断一致を壊さないこと**: 「同じ曲が FMSQ 事前変換でもリアルタイム
  でも同じ音高になる」は P5-sim の検証項目である。`smf2fmsq.rb` 側の
  変換と折り返し規則を一致させ、既存の横断テストが通ることを確認する。
- テスト: 折り返し境界 (ノート 33/34 前後、三角波の床前後) のケースを
  `tool/midi/test/` に足す。

## 2. タスク B: tick 単位の声の整理 (主犯の方)

### 2.1 目標の挙動

- **同一 tick 内**で複数のイベントが同じ声に触れた場合、中間状態を
  鳴らさず、**tick の最後に声ごとの「あるべき音」を 1 回だけ送る**。
  和音の同時離鍵では戻り発音の瞬きが出ない (最終的に held が空なら
  silence 1 回だけ)。
- **異なる tick にまたがる重なり (レガート) の戻り発音は今まで通り**。
  この区別が本質: 同時離鍵 = 同 tick、レガート = 別 tick。

### 2.2 設計の指針 (判断は任せる)

- transport に「ためて、tick の終わりで確定する」段を足す。確定の
  呼び出し点は `FmrbMidi.tick` / `SmfPlayer#tick` が既に境界を持っている
  (`NoteScheduler` と同じ場所に住める)。
- **`MIDI::Device` の見た目は変えない**。`lib/add/picoruby-midi/` は
  無改変 (md5 一致) のまま。
- **割り当てゼロを維持する** (P6/P7 の成果)。held は packed Integer の
  まま、確定処理で新しいオブジェクトを作らないこと。tick ごとの
  作業領域が要るなら初期化時に確保して使い回す。
- serial transport は対象外 (実音源側がポリフォニックなので、この
  問題自体が無い)。ApuTransport に閉じること。

### 2.3 直後に確かめること

- **リアルタイム演奏 (音符が 1 個ずつ来る) が遅れないこと**。確定を
  tick 境界に置くと、`trigger` 系の単発発音が次の tick まで待たされる
  作りになりやすい。単発は即時、同 tick 束のみ整理、が正しい。
  (デモの 1 Scale / piano アプリの打鍵で確認できる)

## 3. 検証

1. ホストテスト: `transport_test.rb` に「同時和音の on/off で声が
   瞬かない」「レガートの戻り発音は残る」のシナリオを追加。
   既存 122 項目を壊さない。
2. sim: 同じ曲 (The Entertainer) を APU で再生し、
   `tools/fmrb_audio_probe.rb --dump` の波形で離鍵瞬間の
   短い異音が消えていることを確認 (変更前後の WAV 比較)。
3. 横断一致: FMSQ 経由とリアルタイムで同じ音高 (P5-sim の項目) が
   タスク A 後も成立。
4. 実機手順を報告書に書く (焼いて聴くのはユーザ)。

## 6. 完了の条件

1. 和音の離鍵で内声が瞬かない (ホストテスト + sim 波形で確認)。
2. レガートの戻り発音が残っている (ホストテスト)。
3. A1 より低い音が音名を保って鳴る (折り返しテスト + FMSQ 横断一致)。
4. リアルタイム単発の発音が遅れていない (2.3)。
5. 割り当て 0 個/イベントが維持されている (bench の alloc 計測)。
6. 実機での確認手順が報告書にある。
