## 1. 作るもの

端末 (Modern) の AI 連携アプリ。mruby のアプリ (Spinel にしない。Asterism を使うため)。
a0.md 10 章の A2 の 1〜6 と A3 の 2〜4 (A3 の 1 と 2 = エディタ側は M3 で済み。m3.md の形を使う)。

### 段 A2 (先に作り、コミットする): 質問だけ
- アプリの置き場と Retro の扱いは a0.md 9 章。名前は仮に「AI ヘルパー」/ `ai_helper`。
- Asterism で `*/tutor/helper` を探してつなぎ、`hello`。画面は上に答え (スクロール、日本語、漢字)、
  下に入力の行 (かな漢字の入力が使えること)、状態の行、使い方の切り替え、「新しい話」「やめる」。
- 質問: `ask` → 1 秒ごとの `status` → `result` (片) → 表示 → `ack`。起動時に `pending`。
- つながらない (ルータに届かない・gem がいない・上限・止められた使い方・受け付けない端末) ときに、
  固まらず、理由を普通の日本語で出す。
- 片の大きさの実測 (端末 → gem 8 KB、gem → 端末 12 KB。通らなければ 3072 B に下げ、gem の設定も合わせる)。

### 段 A3: エディタとつなぐ
- **ヒント**: `ai_read` → 文書を gem に送る (`hint`) → 結果の文書を `/tmp/ai_new.rb` に組み立て →
  `ai_replace` (読んだときの版つき)。カーソルは上に入った行の数だけずらす。
- **作る**・**直してもらう**: 「今の中身を残しますか?」→ はい なら同じディレクトリに `.bakN` で退避
  (plan 2 章 7b: 5 個まで、`.bak1` はいつも残し、2 番目に古いものから消す。無題の文書は退避できないので、
  「退避できません。上書きしますか?」と聞く = 親の仮決め) → `ai_replace`。空の無題なら聞かない。
  `ai_done` が失敗なら、いま作った退避を消す。
- **直して**: `FmrbApp._get_last_error` を読み、エディタの実行したアプリのものと合うときだけ付ける。
  毎回「ヒントをもらう」か「直してもらう」を選ぶ (plan 2 章 7c)。gem が `fix` を止めていれば選べない。
- **AI のコメントを消す**: `ai_read` → `# AI: ` で始まる行 (頭の空白は許す) を数えて「N 行消します」と
  確認 → 消した文書で `ai_replace`。
- **版違い** (a0.md 4 章): ヒントは `ai_read` し直して `rebase`。作る・直してもらうは「待っている間に
  書いた分があります」と出して聞き直す。
- **エディタが動いていない**・`busy`・`help` で断られたときは、理由を出す (「エディタのダイアログを
  閉じてからもう一度」など)。エディタを勝手に起こさない・閉じない。
- 「質問」で今の文書を付けるかは、画面の切り替えで選べる (既定は付けない = 親の仮決め)。

### M3 で決まったエディタの口 (a0.md と違う所。m3.md が正)
- `/tmp` は平らでサブディレクトリを作れない。エディタが書き出す本文は **`/tmp/ai_doc.rb`**、入れ替える
  本文は頼む側が `p` で渡す (**`/tmp/ai_new.rb`** を使う)。この指示書と a0.md の `/tmp/ai/...` は全部
  この 2 つに読み替える。
- 入れ替えの後の文書は末尾の改行が残らない。読んだ後に F1 のヘルプを開いて閉じると版が進む。
  `busy` は待たずに返るので、頼み直すのはアプリの側。知らせの整数と文字列の型を正しく送る。
- 使い方の見本は `flash/app/test/ai_editor_probe.app.rb`。

### 守ること
- 鍵は端末に置かない。端末のアプリは LLM の提供元と直接話さない (gem とだけ)。
- AI 連携アプリが書くのは `/tmp/ai_new.rb` (と、要れば `/tmp/ai_` で始まる作業のファイル) と、退避の `.bakN` (文書と同じディレクトリ) だけ。
- Retro の storage と内蔵 RAM を増やさない (a0.md 9 章の除外)。使っていないときに常駐しない。
- PicoRuby の罠 (Regexp 無し、`Array#pack` 無し、ブロックは重い、`sleep_ms` でなく `Machine.delay_ms`、
  配列要素への多重代入、`String#length` は文字数) と、アプリの書き方 (skill
  `.claude/skills/fmrb-app-new/SKILL.md`) を守る。
- VM プールを使い切らない (`.app.toml` のプールの大きさ。8 KB の片と数十 KB の文書を扱うので、
  文書は VM の文字列に丸ごと持たず、`/tmp` のファイルと片で流す)。

## 2. 確認の環境

- sim (Modern のビルド) の中の zenohd に、ホストから gem をつなぐ:
  `cd fmrb-tutor && bundle exec exe/fmrb-tutor --router tcp/127.0.0.1:7447 --llm fake`
  (形は a1.md の引き継ぎ。sim の中の端末からは `tcp/zenohd:7447`)。端末側の Asterism の設定
  (`/home/asterism` など) の置き方は、今ある Asterism を使うアプリ・回帰の道具 (`tools/regress/live.rb` の
  卓のゲームホスト) を参考にする。**ユーザの設定・鍵 (`~/asterism_keys/`、端末の /home の中身) を
  書き換えない**。sim の flash/home に置く設定は試験の間だけにし、終わったら元に戻す。
- **本物の LLM は全部で 15 回まで** (A2 で 3 回、A3 で 12 回が目安)。それ以外は `--llm fake`
  (`[[slow]]` などの印は a1.md)。鍵は `~/.config/fmrb/anthropic_api_key`。**中身を表示しない・ログや
  ファイルやコミットに入れない**。gem を起こすプロセスの環境変数に渡すだけ
  (`ANTHROPIC_API_KEY="$(cat ~/.config/fmrb/anthropic_api_key)" bundle exec exe/fmrb-tutor ... --llm anthropic`、
  `set -x` を使わない)。認証・残高・レート制限で通らなければ、繰り返さず fake で仕上げて report に書く。
- 画面の日本語の入力は、sim の `key ctrl+space` でかなモードにして `text "..."` (直下の CLAUDE.md)。

## 3. 受け入れ条件

sim の Modern、標準構成 (エディタは Spinel) で確認する。エディタが全部 mruby の構成でも 2〜4 を 1 回。

1. (A2) アプリを開き、質問を打つと、進み具合が出て、答えが日本語で出る (fake と、本物で 1 回以上)。
   「新しい話」で会話の続きが消える。gem を止める・ルータに届かないとき、理由が出て固まらず、
   gem を起こし直すとまた使える。答えを待っている間にアプリを殺して起動し直すと、答えを受け取り直す。
2. (A3 ヒント) エディタで文書を開いてヒントを頼むと、`# AI: ` のコメントが入り、コメントを除くと元と
   バイト単位で同じ (エディタで保存したファイルと、元のファイルで確認)。変更の印が付く。
   ヒアドキュメントのある文書で、中に入らない。
3. (A3 作る) 中身のある文書で作るを頼むと、確認が出て、はい で `.bak1` ができ (元の中身と同じ)、
   文書が入れ替わる。続けて作ると `.bak2` ができ、`.bak1` は最初の中身のまま。7 回続けても退避は
   5 個を超えず、`.bak1` が残る。いいえ なら退避せずに上書き。やめる なら何も変わらない。
4. (A3 版違い) 頼んでから結果が来るまでの間 (fake の `[[slow]]`) にエディタで 1 行足すと、ヒントは
   合わせ直されて正しい行に入る (か、入れなかったと出る)。作るは聞き直す。黙って上書きしない。
5. (A3) 直して: わざと落ちるアプリを F5 で実行した後、エラーが付いて頼める。ヒントと直してもらうを
   選べる。AI のコメントを消す: 数が出て、確認の後に消える。
6. エディタが動いていない・ダイアログ中のとき、理由が出る。エディタは壊れない (その後も打てて保存できる)。
7. 本物の LLM で、ヒント・作る・直してもらうが 1 回ずつ以上、端末からエディタまで通る。**作るの答えを
   エディタで F5 で実行して動くか**を 2 回以上見て、結果 (動いた・落ちた、エラーの文) を report に書く。
8. `rake regress` が通る。段の最後に 1 回 `rake regress:screens ONLY=modern` が通る。Retro のビルドの
   storage にアプリが入っていない (除外の確認。ビルドし直さずに確認できる方法で)。
9. `git status` に取りこぼしが無い (前からある `m components/esp_littlefs`・
   `m components/picoruby-esp32/picoruby`・`?? wasm/vendor/` は除く)。sim の flash/home などに置いた
   試験の設定を元に戻してある。鍵がどこにも残っていない。

`regress:size`・`regress:run`・`regress:checkpoint`・`regress:wl`・`regress:full` は流さない。
ESP32 のビルドはしない (親が後で行う)。

## 4. 範囲と止まる条件

### 触ってよい所
- fmruby-core: AI 連携アプリのファイル (a0.md 9 章の置き場)、Retro の storage の除外の一覧、
  端末の案内の文書 (`flash/usr/share/doc/`) に AI ヘルパーの説明、`doc/ai_coding/report/a2.md`・`a3.md`、
  `rake docs:index` の結果。
- エディタ・カーネル・C は**直さない**。M3 の口に不具合・足りない所があれば、再現の手順を report に書いて、
  その機能だけ後回しにしてほかを進める。小さな直し (数行、動きの決まりを変えないもの) だけは直してよい
  (別のコミットにし、report に書く)。
- fmrb-tutor (`fmrb-tutor/`): 端末とつないで分かった不具合の直しと、
  片の大きさなどの設定の既定。変えたら `bundle exec rake test` を通し、そこでコミットする。
- **触らない**: 回帰の道具の本体、sdkconfig、submodule の中、graphics-audio、直下 (family-mruby) の
  リポジトリ、asterism の gem、`wasm/vendor/`。plan.md は親が直す。P4-Nano (`/dev/ttyACM0`)。

### 作業場所と git
- fmruby-core の本体の checkout、今いるブランチ `editor-multi-file` の上に続けてコミットする (この指示書を
  最初のコミットに入れる)。**A2 が通った時点で 1 回コミットしてから A3 に進む。**
  **push しない。develop へマージしない。どこにも公開しない。** `git add -A` を使わない。
- 終わったら sim・gem・ルータ・ブラウザ・ネイティブ版を止める。

### 止まる条件 (止まったら report に状況を書いて返す)
- ユーザの作業が要る (sudo・機器・公開)。触ってよい範囲の外の変更が要る。
- 端末の Asterism から gem を呼べない (設定・証明書・ファームの機能の都合)。原因を調べて report に書く。
  A2 がここで止まるなら、A3 は「エディタとの口だけを fake の結果で試す」所まで進めてよい。
- **利用者から見た動きを、plan・この指示書に無い形で変える必要が出たとき**。選ばずに止まる
  (画面の並び・言葉・色などの細部は任せる。report に書く)。

## 5. report に書くこと (doc/ai_coding/report/a2.md と a3.md。1 つにまとめてもよい)

- アプリの作り (ファイル、画面、状態の持ち方、VM プール・スタックの設定と実測)。
- 受け入れ条件 1〜9 の結果と根拠 (打ったキーの列、写しの場所、保存されたファイルの中身、gem の記録)。
- 片の大きさの実測、`status` を 1 秒ごとに呼ぶときの様子。
- 本物の LLM: 回数、usage、答えの例、**作ったアプリを実行した結果**、見えた問題。
- a0.md・a1.md・m3.md の形から変えた所と理由。gem を直した所。
- 自分で決めた言葉・画面の形。親の仮決め (無題の退避、質問に文書を付ける既定) で困った所。
- ESP32 (P4-Nano) で確認する人への引き継ぎ: 端末の設定で要るもの、起こし方、見る所。
- 残件、未確認のこと、ユーザに決めてほしいこと。コミットの一覧 (リポジトリごと)。
