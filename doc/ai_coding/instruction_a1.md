## 3. 受け入れ条件

1. `bundle exec rake test` (か相当のコマンド 1 つ) で、ローカルのルータを立て、`fake` の LLM で、試験の
   送り手 (端末の代わりの CRuby) から次が全部自動で通る: 質問・ヒント・作る・直してもらう、8 KB の片に
   分けた文書、落ちた後の受け取り直し (`pending`)、版違いの `rebase`、会話の続きと「新しい話」、
   1 日の上限、受け付けない端末、止めた使い方。
2. ヒントの検査: ヒアドキュメント・複数行の文字列・`%w[]`・行末 `\` の継続の中にコメントが入らない
   (a0.md 5.2 の見本 20 件を試験にする)。コードの行が 1 文字も変わらない。
3. PicoRuby に無い書き方 (Regexp など) を使う `fake` の答えは、直させる流れに入り、直らなければ端末に
   届かない (理由が返る)。
4. 知識の束 `bundles/3.1.0/` がスクリプトで作れる (fmruby-core の sig・skill・見本から。fmruby-core は
   読むだけ)。大きさ (バイトと、分かればトークン数) を report に書く。
5. 記録 (JSONL) に頼み・送った文書・答え・usage・検査の結果が残り、鍵は入っていない
   (`grep -r "sk-ant" .` が 0 件。リポジトリ・記録・ログの全部で)。
6. 本物の LLM で、質問・ヒント・作るが 1 回ずつ以上通る (2 章の範囲で)。作るの答えが、Family mruby の
   アプリの形 (束の雛形) になっていて、構文と PicoRuby の検査を通る。**作ったアプリを sim で動かす確認は
   しない** (fmruby-core の sim は別のサブが使っている)。答えの例を report に貼る。
7. README (日本語と英語のどちらか 1 つでよい。公開しないので) に、起こし方、設定、LLM の提供元に送るもの、
   端末は鍵を持たないこと、未確認のことを書く。
