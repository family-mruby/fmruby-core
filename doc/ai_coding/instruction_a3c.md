## 1. 直すもの (利用者から見た動きは、ここに書いたとおりがユーザの決定)

### 1.1 Window の大きさを変えられるようにする
- AI ヘルパーの Window を、利用者が大きさを変えられるようにする (ほかの大きさを変えられるアプリと同じ流儀)。
- 大きさが変わったら、答えの欄の折り返し・スクロールの位置・各段の位置を組み直す。答えの中身と
  入力の行に打ちかけた文は失わない。最小の大きさを決める (今の大きさで全部のボタンが入ること。
  それより小さくはできない)。全画面にはしない。
- 426x240 と 640x360 の両方で崩れないこと。最初の大きさと位置は今のまま。

### 1.2 ボタンの名前

| 今 | 新しい名前 |
|---|---|
| 送る | 送信 |
| 作る | 作成 |
| やめる (答えを待っている間・送っている間) | 中断 |
| やめる (確認の問いを取りやめる) | キャンセル |
| 新しい話 | 会話リセット |
| 直して | 修正 |
| AIの行を消す | AIコメント削除 |
| (「直して」の後の問い) ヒントをもらう / 直してもらう | ヒント / 修正してもらう |

- 質問・ヒント・はい・いいえ・上書きする・消す・もう一度・文書も送る/文書は送らない は今のまま。
- 状態の行・答えの欄の案内の文・入力の行の薄い案内・エラーの文の中で、古い名前を言っている所
  (「『送る』を押してください」「新しい話にしました」など) を新しい名前に合わせる。
  英語の表示 (language=en) があるなら同じように合わせる (言葉は任せる。report に書く)。

### 1.3 並び
- **上の段はメニューバーのように見せる**: 四角い枠のボタンをやめ、下の答えの欄とはっきり分かれた
  1 本の帯 (メニューバーと同じ見た目の流儀。色はテーマから。カラーキーの 0x01 を使わない) に、
  字だけを並べる。

  ```
   質問  ヒント  作成 | 修正  編集▼
  ```

  - 質問・ヒント・作成は「今選んでいるもの」が分かるように、選んだものを反転で示す (押しても何も
    起きず、次に送るものの種類を選ぶだけ、という今の動きのまま)。
  - 区切りを入れて、修正 (押すとすぐ動く) と 編集 (プルダウン) を並べる。
  - 使えないとき (親が「修正してもらう」を止めている、など) の見せ方は今の流儀のまま (薄くする)。
- **編集のプルダウン**: 「編集」を押すと下に項目が出て、選ぶ。項目は次の 2 つ (今後の追加に備えて
  プルダウンにする、がユーザの決定)。プルダウンの外を押す・Esc で閉じる。
  - **AIコメント削除** (今の「AIの行を消す」と同じ動き)。
  - **バックアップから戻す** (1.4)。
- **下の段**: 送信・中断 (か、問いのボタン) は左から今の並び。**会話リセットは右寄せ**。
  「文書も送る/文書は送らない」の切り替えは、今の所 (質問を選んでいるときだけ) に残し、
  会話リセットと重ならないように置く (幅が足りないときの詰め方は任せる)。
- 状態の行の文字色は、ほかと同じ文字色にする (もう直してあり、未コミットの変更として木に入っている。
  そのまま最初のコミットに入れる)。

### 1.4 バックアップから戻す (新しい機能)
エディタの今の文書を、AI ヘルパーが作った退避 (`同じ場所の <名前>.bak1`〜`.bak5`) の中身に戻す。
動きの細部は親の仮決め (report に「仮決め」として書く。ユーザが後で見る):
- 今の文書に退避が 1 つも無い (無題の文書・退避したことが無い) ときは、その旨を出して終わる。
- 退避があれば一覧を出して選ぶ: 番号と、分かる範囲の手掛かり (大きさ・先頭の行など。任せる)。
  `.bak1` は「最初の中身」、番号が大きいほど新しい、が分かるようにする。
- 選んだら、「作成」と同じ確認を通す: 今の文書に中身があれば「今の中身を残しますか?」
  (はい = 退避してから入れ替え、いいえ = 退避せずに入れ替え、キャンセル = 何もしない)。
  **はい のときの退避で、戻そうとしている退避そのものが消える・番号が変わることがある**
  (5 個まで・`.bak1` は残す・2 番目に古いものから消す・番号を詰める、の決まりのため)。選んだ中身を
  先に読んでから退避するなど、選んだものと違う中身に戻らないようにする。
- 入れ替えはエディタの口 (`ai_read`・`ai_replace`、版つき) を使う。版違い・`busy`・`help`・エディタが
  動いていないときの扱いは「作成」と同じ。戻した後の退避のファイルは消さない。
- gem (AI ホスト) とつながっていなくても使える (LLM を使わないので)。AIコメント削除も同じ扱いにできるなら
  そうする (今どうなっているかを確認し、変えるなら report に書く)。

## 2. 受け入れ条件

sim の Modern、標準構成 (エディタは Spinel) で確認し、640x360 でも 1 回 (R1a の手順。
doc/modern_resolution/report/r1a.md)。全部 mruby の構成で 1 回 (起動・質問・編集のプルダウン)。

1. Window の大きさを変えると、段の位置と答えの折り返しが組み直され、答えと打ちかけの文が残る。
   最小より小さくならない。写しを 3 つの大きさで。
2. ボタンの名前が 1.2 の表のとおり。古い名前が画面のどこにも残っていない (ソースを grep して、
   画面に出る文に古い名前が無いこと)。
3. 上の段がメニューバーの見た目で、選んだ種類が反転で分かる。編集のプルダウンが開いて閉じる
   (項目を選ぶ・外を押す・Esc)。会話リセットが右寄せ。写しを付ける。
4. 質問・ヒント・作成・修正・AIコメント削除が、今までどおり通る (偽物の LLM で 1 回ずつ。
   a2.md の受け入れ条件の主なもの: ヒントのコメントが入る、作成で `.bak1` ができる、修正でエラーが付く)。
5. バックアップから戻す: 作成を 2 回して `.bak1`・`.bak2` がある状態で、`.bak1` を選んで はい →
   文書が最初の中身になり (エディタで保存したファイルで確認)、今の中身が退避されている。いいえ・
   キャンセル・退避が無いとき・無題の文書・エディタが動いていないとき、もそれぞれ確認する。
   退避が 5 個ある状態で `.bak2` を選んで はい にしても、選んだ中身に戻る。
6. `rake regress` が通る。最後に 1 回 `rake regress:screens ONLY=modern`。VM プール: AI ヘルパーの
   起動後とひととおり使った後の VM プールの使用量を、直す前と比べて report に書く (KB 単位で
   増えるなら理由を書く。プールを使い切らないこと)。
7. `git status` に取りこぼしが無い (前からある `m components/esp_littlefs`・
   `m components/picoruby-esp32/picoruby`・`?? wasm/vendor/` は除く)。sim・gem・ルータを止めてある。
   sim の flash/home の試験の設定を元に戻してある。
