## 1. やること

**コードを変えない。ビルドしない。sim・ブラウザ版・ネイティブ版を起こさない** (別のサブが同じ checkout で

調べて、**試作 (A1〜A3) がそのまま始められる形で案を 1 つに絞って**書く。選択肢が残るものは、推奨と理由を

### 1.1 Asterism に載せる形 (plan 6.2)
- 読むもの: `asterism` (CRuby の gem。README・lib・doc)、
  `fmruby-core/doc/asterism_protocol2/design.md`、`fmruby-core/doc/asterism_file_transfer/plan.md`、
  端末のアプリから Asterism を使っている例 (`fmruby-core/flash/` の中で `Asterism`・`link.conn` を grep。
  麻雀・transfer のアプリなど)、`asterism-console`、
  `picoruby-asterism-zenoh`、ローカルのルータの立て方 (zenohd。回帰の道具 `tools/regress/checkpoint*.rb`・
  `transfer*.rb` が自前のルータを立てている)。
- 決めること: AI の gem が公開するオブジェクトとメソッドの名前・引数・返り値の形、進み具合のトピック、
  結果の返し方 (端末が取りに行く呼び出しか、トピックか、ファイル転送か)。呼び出し 1 つの大きさと時間の
  上限 (実測値か、コードの上限の定数) を調べ、文書 (数 KB〜数十 KB) と結果が載るかを判断する。
  端末は 50 ms ほどの周期でポーリングする前提。受け付けの番号、端末宛ての未受け取りの結果、会話の続き
  (plan 6.2 の 5・6) を含める。
- 端末の mruby のアプリから呼ぶときの書き方 (同期か、コールバックか) と、CRuby の側の書き方の見本を
  数行ずつ。
- 権限: 親が「受け付ける端末」を決める方法 (Asterism の身元・証明書・console の呼び出しの権限) の今の仕組み。

### 1.2 エディタとの知らせの形 (plan 5)
- 読むもの: `main/ruby/default_app/editor.app.rb` の `on_control`、カーネルの知らせの送り方
  (`main/ruby/kernel/`、`file_selected`・`run_result` がどう届くか)、アプリからアプリへ知らせを送る口が
  あるか (Pub/Sub、`FmrbApp` の API、`sig/*.rbs`)、知らせ 1 つの大きさの上限 (msgpack・キュー)。
  `doc/editor_multi_file/plan.md` と、ブランチ `editor-multi-file` の今のコード (読むだけ)。
- 決めること: AI 連携アプリ → エディタの頼みと、エディタ → AI 連携アプリの答えの形 (cmd の名前・項目)。
  読む (中身・ファイル名・行の数・カーソル・選択・変更の印・直前のエラー・文書の版)、書く (丸ごと入れ替え・
  行の上にコメントを入れる・印の付いたコメントを数える/消す。版が違えば断る)、開く。
  文書が知らせ 1 つに載らないときの渡し方 (`/tmp` のファイルを介すのが見立て。tmpfs は Modern で 8 MB)。
  直前の実行 (F5) のエラーをエディタが今持っているか、持っていなければどこから取れるか。
  文書の版の番号を C 側のどこで数えるのがよいか (`editor_core.c`。今ある `g_wrap_stamp` は全文書で 1 つ)。
- エディタが Spinel であることの制約 (型が絞れる形、文字列の扱い) を踏まえた形にする。

### 1.4 検査 (plan 6.4)
- Family mruby のビルドが Ruby をどのコンパイラで読んでいるか (picoruby-prism か mruby-compiler か。
  `lib/upstream/`・build config・`components/picoruby-esp32/picoruby/mrbgems/` を読む)。
- **CRuby の prism gem で試す** (スクラッチの場所で。この PC に prism 1.9.0 がある): コメントを入れる前後で
  「コメントを除いたトークンの並びが同じか」を比べる小さなスクリプトを書き、次の見本で、差し込んでよい行と
  いけない行を正しく見分けることを確認する: 普通の行の上、ヒアドキュメントの中、複数行の文字列の中、
  `%w[]` の中、`=begin`〜`=end` の中、行末が `\` の継続の間、メソッドチェーンの途中 (行頭が `.` の行の上)、
  `__END__` の後。結果の表とスクリプトを report に貼る。
- CRuby の Prism は通すが PicoRuby は通さない書き方 (分かる範囲で。Regexp リテラルなど、実行時に無いものは
  別枠)。
- 型の診断 (picoruby-ti、`rake ti:test`、`lib/gems/` の型エンジン) を gem からどう使えるか: ホストで
  単体のコマンドとして動くか、型のデータ (rbs から作る db) を束に入れられるか。最初の版に入れるかの推奨。
