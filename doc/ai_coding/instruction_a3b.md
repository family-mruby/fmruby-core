# A3b 指示書: 仮決めの見直しで決まった直し (タブの行の色、実行したアプリの名前、質問に文書を付ける既定)

> report/m2.md・m3.md、doc/ai_coding/plan.md と report/a2.md。ユーザが朝に仮決めを見直して決めた分。

## 1. 直すもの (3 つ。利用者から見た動きはここに書いたとおりで、ユーザの決定)

### 1.1 エディタ: タブの行の地の色を変える
- 今: 今の文書だけ反転、ほかのタブは字だけで、メニューの行と 1 つの帯に見える (m2.md 9 章の 1)。
- 直し: **タブの行全体の地の色を、メニューの行とも編集の領域とも違う色にする**。今の文書の反転はそのまま
  (地の色を変えた後も、今の文書がはっきり見分けられること)。区切りの線は足さない。
- 色はテーマから取るか、テーマの色から作る (全部のテーマで見分けが付くこと。カラーキーの 0x01 を使わない)。
  どの色にしたかは任せる (report に書く)。Retro・Modern・Modern の全画面で確認する。

### 1.2 エディタ: 読む口 (`ai_doc`) で、最後に F5 で実行したアプリの名前を返す
- 今: AI ヘルパーの「直して」は、直前のエラー (`FmrbApp._get_last_error`) のアプリの名前を、文書の
  ファイル名から作った名前と比べている。文書の中で別の `app_screen_name` を書いたアプリでは合わず、
  エラーが付かない見込み (a2.md 8 章の 2)。
- 直し: エディタが、今の文書を最後に実行したとき (F5) のアプリの名前 (カーネルが直前のエラーに付ける
  名前と同じもの) を覚え、`ai_doc` の答えに 1 項目足して返す。AI ヘルパーはそれと直前のエラーの名前を
  比べる。まだ実行していない文書では空 (エラーを付けない)。
- 覚えるのは文書ごと (切り替えで混ざらない)。知らせの大きさの上限 (176 B) を超えないこと
  (名前が長いときの扱いを決めて report に書く)。項目の名前は任せる。
- まず「別の `app_screen_name` を書いたアプリで、今はエラーが付かない」ことを再現してから直す。
  見立てが違った (今でも付く) なら、その事実を report に書き、直しは要る分だけにする。

### 1.3 AI ヘルパー: 「質問」に文書を付ける既定
- 今: 既定は「文書は送らない」。画面の切り替えで「文書も送る」にできる。
- 直し: **エディタが動いていて、今の文書に中身があれば、既定で付ける**。エディタが動いていない・
  文書が空のときは付けずに質問だけ送る (断らない)。切り替えは残す (送らないを選べる)。
  付けたか付けなかったかが、状態の行などで分かること。
- エディタが `busy`・`help` で読めないときの動きは、質問を止めない方を選ぶ (付けずに送り、付けなかった
  ことを知らせる)。

### 1.4 文書
- 端末の案内 (`flash/usr/share/doc/ai_helper(_ja).md`・`editor(_ja).md`) を動きに合わせる。
- `doc/reference/TODO.md` に課題を 1 つ足す: ルータに届かない間、Asterism の Link の `connect` が
  アプリを約 4 秒止める (AI ヘルパーで見えた。ほかの Asterism を使うアプリにも関わる。a2.md 8 章)。
  ユーザの決定は「後回しにして課題に記録」。

## 2. 受け入れ条件

sim の Modern、標準構成 (エディタは Spinel) で確認し、1.1 と 1.2 は全部 mruby の構成でも 1 回。

1. タブの行: 2 つ以上のとき、タブの行がメニューの行と別の帯に見え、今の文書が分かる。写しを
   Retro・Modern・Modern の全画面で 1 枚ずつ。テーマを 2 つ以上替えて見分けが付く。
2. 別の `app_screen_name` を書いたわざと落ちるアプリを F5 で実行した後、AI ヘルパーの「直して」に
   エラーが付く (gem の記録 JSONL で、頼みにエラーの文が入っていることを確認)。実行していない文書・
   別の文書に切り替えた後では付かない。
3. 質問: エディタに中身のある文書があるとき、何も切り替えずに質問すると文書が付く (gem の記録で確認)。
   エディタが動いていないとき・文書が空のとき、質問だけが通る。「送らない」に切り替えると付かない。
4. `rake regress` が通る。最後に 1 回 `rake regress:screens ONLY=modern` が通る。
5. `git status` に取りこぼしが無い (前からある `m components/esp_littlefs`・
   `m components/picoruby-esp32/picoruby`・`?? wasm/vendor/` は除く)。試験の設定を元に戻してある。

`regress:size`・`regress:run`・`regress:full` などは流さない。ESP32 のビルドはしない。

## 3. 確認の環境

- gem は `--llm fake` だけ (**本物の LLM は使わない**。鍵のファイルに触らない)。
  `cd fmrb-tutor && bundle exec exe/fmrb-tutor --config <スクラッチの toml>`。
  **既定のモデルが Sonnet になり、偽物の LLM でも費用の見積もりが 9 回ほどで 1 日の上限 (1 ドル) に
  当たる**。試験の設定 (スクラッチの場所に置く toml) で `[limits] cost_per_day_usd = 1000` にする
  (書き方は gem の `test/test_e2e.rb` の設定と `config/tutor.toml.example`)。
- sim の端末側の Asterism の設定の置き方は a2.md の手順のとおり。**ユーザの設定・鍵
  (`~/asterism_keys/`、端末の /home) を書き換えない**。sim の flash/home に置いたものは終わったら戻す。
- **親が同じ時間に、P4-Nano (`/dev/ttyACM0`、WiFi) で別の確認をしている**。P4-Nano・シリアル・
  ESP32 の `build/` に触らない。親は自分のルータを別の port (7460) で立て、gem を別の記録の場所で
  動かす。sim の 7447 はサブが使ってよい。`pkill -f` で gem を止めない (親の gem も止まる。自分が
  起こしたプロセスの pid で止める)。
