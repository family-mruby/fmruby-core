# 端末だけで AI と一緒にアプリを作る (AI 連携)

> 状態: 計画済 | 更新: 2026-11-17 | P4-Nano・Tab5 だけを持つ人 (子どもなど) が、端末の AI 連携アプリから AI に質問し、ヒントをコメントでもらい、丸ごと作ってもらえるようにする。AI は親が外に用意した独立した gem の Ruby アプリで、Asterism のルータ経由で端末と話す。未着手 (実装の指示はまだ無い)

## 1. 目的

- 作者は AI (Claude Code) で Family mruby のアプリを作っている。同じことを、**端末だけを持つ人** (子どもなど) が
  できるようにしたい (2026-11-17 ユーザ)。
- Claude Code を自分で動かせる人は自分でできるので、対象にしない。
- AI の鍵・知識・検査は端末に置かず、親が外に用意する環境に置く。端末とは Asterism でつなぐ。

### 1.1 一番の価値 (2026-11-17 ユーザ)

**子どもにタブレットやブラウザを渡さなくてよい**。

- タブレットやブラウザには、動画・ゲーム・通知・検索・何でも答えるチャットの AI が付いてくる。親はそれを
  止める設定と戦うことになる。専用の端末は、最初から「作ること」と「作ることについて AI に聞くこと」しか
  できない。
- **AI の届く範囲を親が決められる**。AI 連携アプリができるのはエディタの文書の読み書きだけで、AI への
  指示の中身は親の gem の側で決まる。「AI には触れさせたいが、何でも聞ける AI は渡したくない」に答える。
- 子どもにとっては、借りた物ではなく自分のコンピュータで自分のアプリを作ることになる。

この価値を守るために、設計で言い切れるようにしておくこと:
- AI とのやり取りの出口は AI 連携アプリの 1 本だけで、その先は親の gem だけ (端末は LLM の提供元と直接
  話さない。鍵も持たない)。README と案内にそう書けること。
- AI は端末を勝手に操作しない (10 章)。
- 端末にはほかにも外とつながる機能がある (WiFi の設定、Asterism のほかのアプリ、Weather など)。
  「子どもの端末が外と何をやり取りできるか」を親が一覧で見て止められる仕組みは、この計画の外だが、
  この価値を前に出すなら要る (11 章)。

## 2. 決めたこと (2026-11-17 ユーザ)

1. **対象の人**: P4-Nano・Tab5 だけを持つ人。親が外に環境を用意するのはあり。
2. **対象の端末**: Modern だけ。**Retro は対象外**。
3. **言語**: Ruby (もしくは Python) だけ。wasm の SDK (TinyGo・Rust・Zig) は対象外。
4. **端末側は AI 連携用の独立したアプリ**。エディタの中の機能にはしない。エディタの情報を読み、書き換え、
   外から操作する。使い方は 3 つ:
   - **質問する**: エディタに触らない。
   - **ヒントをもらう**: エディタの文書に注釈を入れてもらう。
   - **丸ごと作ってもらう**: エディタの文書を書く。
5. **教える寄り (ヒント・説明) を最初から入れる**。
6. **注釈はコメントとしてファイルに書き込む**。AI のコメントには印を付ける。
7. **丸ごとのときは、古いデータを退避するか確認した上で上書きする**。退避のファイルは同じディレクトリに置く。
7b. **退避のファイルは番号つきで 5 個まで** (`game.app.rb` → `game.app.rb.bak1`、次は `.bak2`)。上限に達したら、
    **最初の 1 つ (`.bak1`、子どもが自分で書いた元のコード) はいつも残し、2 番目に古いものから自動で消す**
    (2026-11-17 ユーザ)。`.app.rb` で終わる名前にしないのは、ランチャーにアプリとして出てしまうため。
7c. **「直して」は、毎回子どもが「ヒントをもらう」か「直してもらう」を選ぶ**。親の設定で「直してもらう」を
    止められる (2026-11-17 ユーザ)。
8. **親の環境は、gem として独立した Ruby アプリ**。Asterism のルータ経由で Family mruby と通信する。
9. **ルータ**: 開発時はローカルで立てて試す。将来は VPS のルータ。親の環境は console の中でも動くようにする。
10. **エディタの外からの操作 I/F は、エディタの改修 (doc/editor_multi_file) と一緒に作る**。
11. **子ども向けだが、日本語は普通に漢字を使ってよい**。

## 3. 全体の形

```
端末 (P4-Nano / Tab5)                                親の環境
+----------+  読む・書く・コメント  +--------------+  Asterism   +------------------+
| エディタ | <------------------- | AI 連携アプリ | -- ルータ -> | AI の gem (Ruby) | -> LLM の API
| (Spinel) |   端末の中の知らせ    | (mruby)      |             | 鍵・知識・検査    |
+----------+                      +--------------+             | 記録・上限        |
                                                               +------------------+
```

- **エディタは Spinel なので Asterism を直接使えない** (Asterism のユーザ向けの層は mruby の VM だけ)。
  AI 連携アプリ (mruby のアプリ) が Asterism で親の環境と話し、エディタとは端末の中の知らせで話す。
- **本文を書き換えるのはエディタ自身だけ**。AI 連携アプリは頼むだけ (2 つのタスクが同じ文書に触らない)。
- 鍵・知識・検査・記録・上限は全部 AI の gem の側。端末には置かない。
- 1 つの AI の gem が複数の端末を受け持てる (きょうだい、ワークショップ)。

## 4. 端末の AI 連携アプリ

### 4.1 画面と入力
- 独立した Window。Modern (426x240、全画面のエディタは 640x360) でエディタと並べて、または重ねて使う。
- 上に AI の答え (スクロールできる)、下に入力の行。日本語は今のかな漢字の入力で打つ。
- 使い方の切り替え (質問・ヒント・作る) と、「直して」(直前の実行のエラーを付けて頼む)。
- 待っている間は進み具合を出す (受け付けた・考えている・検査している)。途中でやめられる。
- つながっていない (ルータに届かない・AI の gem がいない・上限に達した) ときは、理由を子どもに分かる言葉で出す。

### 4.2 3 つの使い方
| 使い方 | AI に送るもの | エディタにすること |
|---|---|---|
| 質問 | 質問の文 (と、選べば今の文書) | 何もしない。答えは AI 連携アプリの中だけ |
| ヒント | 質問の文、今の文書、カーソルの行、直前のエラー | AI のコメント (印つき) を行の上に入れる。コードは変えない |
| 作る | 頼みの文、今の文書、直前のエラー | 退避するか確認 → 文書を丸ごと入れ替える |

- **ヒント**: AI は「何行目に何と書くか」の組を返し、エディタがコメントとして入れる。コードの行は 1 文字も
  変えない。確かめ方は 6.4 (行の比較ではなく、構文解析して、コメントを除いたトークンの並びが前後で同じか)。
- **AI のコメントの印**: 行の頭に決まった印 (7 章の仮決め)。AI 連携アプリから「AI のコメントを消す」ができる。
  消す前に、何行消すかを見せて確認する (子どもが自分で同じ印を書いた行・AI のコメントを書き直した行も
  消えるため)。Ruby も Python もコメントは `#` なので同じ形。
- **作る**: 「今の中身を残しますか?」を聞き、はい なら同じディレクトリに退避してから上書きする。
  無題で空の文書なら聞かない。上書きの後、文書は「変更あり」のまま (保存は子どもがする)。
- **待っている間に文書が変わったとき** (LLM の待ちは数十秒ある): 頼みに文書の版 (5 章) を付け、結果を
  入れるときに今の版と比べる。
  - ヒント: 違っていたら、そのままの行番号では入れない。行の中身で合わせ直せるか (送ったときの行の文が
    今もあればその行の上に入れる) は A0 で決め、合わせられない分は入れずに「書きかえたので入れなかった」と
    出す。
  - 作る: 違っていたら黙って上書きしない。「待っている間に書いた分があります」と出して、退避と上書きを
    聞き直す。
- どの使い方でも、AI の答えには短い説明が付く (何をしたか・なぜか)。

### 4.3 教える寄り
- 既定の使い方は「ヒント」。「作る」は選べば使える。親の設定で「作る」を止められる。
- **日本語は普通に漢字を使う** (2026-11-17 ユーザ)。画面の言葉も AI の答えも、ひらがなに開かない。漢字の量を選ぶ設定は作らない。説明は短く、専門の言葉には一言の説明を付ける。
- 「作る」のときも、作ったコードの要所に AI のコメントで説明を入れる (切れる)。
- エラーの「直して」は、その場で子どもが選ぶ: 「ヒントをもらう」(どの行の何が違うかを AI のコメントで。
  コードは変えない) か、「直してもらう」(退避の確認の後、直した文書で上書き。「作る」と同じ扱い)。

## 5. エディタの外からの操作 I/F (正は doc/editor_multi_file)

エディタの改修の M3 (外からファイルを開く) を広げて、同じ経路に載せる。ここには AI 連携が要るものだけ書く。

- **読む**: 今の文書の中身・ファイル名・行の数、カーソルと選択の位置、変更の印、直前の実行 (F5) のエラー、
  **文書の版** (編集のたびに変わる番号。読んだ時点の中身と組で返す)。
- **書く**: 今の文書を丸ごと入れ替える。指定した行の上にコメントの行を入れる。印の付いたコメントの行を消す
  (消す前に数を返す口も)。**書く頼みには読んだときの版を付け、今の版と違えばエディタは入れずに断る**
  (断ったことと今の版を返す)。
- **開く・前に出す**: ファイルを追加で開く (もとの M3)。
- 文書が大きいときの渡し方 (知らせ 1 つに載らない) は、エディタの側で決める (`/tmp` のファイルを介す、など)。
- エディタがダイアログを出している最中・実行中の扱いも、エディタの側で決める。
- 頼めるのは端末の中のアプリだけ。網の外から直接エディタを操作する口は作らない。

## 6. 親の環境 (AI の gem)

### 6.1 形
- CRuby の gem。`gem install` して、設定 (ルータの場所・LLM の鍵・受け付ける端末) を渡して起こすと、
  Asterism の 1 つのアプリとして網に入る。
- **単体で起こせるコマンド**と、**console から呼べるライブラリ**の両方の形にする (2 章の 9)。
- LLM の API の提供元とモデルは設定で選ぶ (最初は 1 つ)。鍵は環境変数か設定のファイル。リポジトリに入れない。

### 6.2 頼みの流れ
1. 端末が「頼み」を出す (使い方、文、文書、カーソル、エラー、ファームの版、言語)。
2. gem は受け付けの番号をすぐ返す。生成は数十秒かかるので、呼び出しの中では待たない。
3. gem は進み具合を知らせ、LLM を呼び、検査し、結果 (説明と、コメントの組 か 文書) を返す。
4. 端末の AI 連携アプリが結果を受け、エディタに頼む。
5. **結果は gem が受け付けの番号ごとに一定の時間持つ**。端末が再起動した・アプリが落ちたときは、AI 連携
   アプリが起動のときに「この端末宛ての、まだ受け取っていない結果」を聞いて受け取れる (端末には何も
   保存しない)。
6. **会話の続き**: gem が端末ごとに直前の数回 (頼みと答え) を持ち、次の頼みに付ける (「それってどういう
   こと?」と聞き返せるように)。AI 連携アプリの「新しい話」で消す。A2 から入れる。

- 呼び出し・トピック・ファイル転送のどれに何を載せるか (文書と結果の大きさ、時間の上限) は A0 で決める。
  見立て: 頼みと結果は 1 つの呼び出しに載る大きさ (数十 KB まで) なら呼び出しで、超えるならファイル転送。

### 6.3 知識
- LLM への指示に入れるもの: アプリの書き方 (今の skill `fmrb-app-new` の中身)、API の型 (`sig/*.rbs`)、
  PicoRuby の罠、短い見本。
- これらはファームの版ごとに違うので、**版ごとの束**にする。最初は gem に同梱し、ファームの版との対応表を
  gem が持つ (端末が自分の版を送り、合う束が無ければ近い古い版の束を使ってそのことを記録する)。
  fmruby-core のリリースに束を付ける形は、版が増えてから考える。束の作り方 (sig・skill・見本から) は A0。
- 子ども向けの決まり (言葉づかい、危ない頼みを断る、分からないことは分からないと言う) も指示に入れる。

### 6.4 検査
- 返す前に、gem の側で構文と型の診断を通し、落ちたら LLM に直させる (回数の上限つき)。
- **構文の検査は CRuby の prism gem を使う見立て** (picoruby に picoruby-prism の gem がある。Family mruby の
  ビルドが実際に Prism で読んでいるか、CRuby の Prism が通して PicoRuby が通さない書き方が何かは A0 で確認)。
- **ヒントが「コメント以外を変えていない」ことの確かめ**: コメントを入れた後の文書と元の文書を構文解析し、
  コメントを除いたトークンの並びが同じかを比べる。`#` で始まる行でも、ヒアドキュメント・複数行の文字列・
  `%w[]` の中ではコードの一部で、そこに行を差し込むとプログラムが変わるため、行の比較では足りない。
  同じでなければ、そのコメントは入れない (別の行に寄せるか、答えの文の中だけで伝える)。
  Python は別の解析が要る (A0。Python を入れる段で)。
- 型の診断は fmruby-core の型エンジン (picoruby-ti) を使いたいが、gem からどう使うか (ホストのコマンドに
  するか、型のデータを束に入れるか) は A0 で調べる。最初の版は構文だけでもよい。
- 実際に動かしての確認 (ヘッドレスのネイティブ版) は後の段 (8 章)。

### 6.5 親ができること
- 受け付ける端末 (Asterism の身元) を決める。
- 1 日の回数・費用の上限。達したら端末に理由を返す。
- やり取りの記録 (頼み・送った文書・答え・かかった量) を全部残し、読める。
- 使い方の制限 (「作る」「直してもらう」を止める)。
- 何が LLM の提供元に送られるか (子どもの打った文と文書) は、gem の README に明記する。

## 7. 仮決め (親セッション。違えば直す)

- AI のコメントの印: `# AI: ` で始まる行。
- gem の名前・端末のアプリの名前と置き場は未定 (11 章)。
- 最初の言語は Ruby。Python は A0 で、Family mruby の MicroPython から使える API の範囲を調べてから段に入れる。

| A4 | 教える寄りの仕上げ (説明の書き方、使い方の制限)、検査 (構文と型)、知識の束を版ごとに | 罠 (Regexp など) を使ったコードが子どもに届かない |

AI が端末の画面やログを見る、作ったアプリを Asterism で人に渡す。

## 9. 受け入れ条件 (A5 まで)

1. Tab5 か P4-Nano と、親の PC で起こした gem だけで、子どもが端末から質問・ヒント・作るを使える。
2. ヒントはコードの行を変えない。AI のコメントは印で見分けられ、まとめて消せる。
3. 作るは、確認の後に退避してから上書きする。退避したファイルは元の中身と同じ。何回続けて作っても、
   最初の退避 (`.bak1`) が残っている。退避は 5 個を超えない。
3b. 待っている間に文書を書き換えた場合、ヒントは違う行に入らず、作るは黙って上書きしない。
3c. ヒアドキュメント・複数行の文字列の中にコメントが差し込まれない。
4. LLM の鍵は端末のどこにも無い。
5. 上限に達した・つながらないときに、端末が固まらず、理由が出る。
6. やり取りの記録が gem の側に残り、親が読める。
7. 端末のアプリは Modern だけに入る (Retro の storage と内蔵 RAM を増やさない)。
8. AI 連携アプリを使っていないとき、エディタと端末の動き・メモリは今と同じ。

## 10. 範囲の外

- Retro。wasm の SDK の言語。
- Claude Code などを自分で動かせる人向けの道具 (MCP・skill の配布)。
- 端末から LLM の API を直接呼ぶ形 (鍵を端末に置く形)。
- AI が勝手に端末を操作すること (アプリの起動・ファイルの削除など)。頼めるのはエディタの文書の読み書きだけ。

- LLM の提供元とモデルの既定、費用の目安 (A0 で見積もる)。

- 文書の大きさの上限 (大きいファイルを丸ごと送るか、カーソルの周りだけ送るか)。
