# A3c 報告: AI ヘルパーの画面の直し (大きさの変更、ボタンの名前と並び、編集のプルダウン、バックアップから戻す)

> 状態: 完了 | 更新: 2026-11-18 | AI ヘルパーの上の段をメニューバーの見た目にし (選んだ使い方は反転、区切りの後に「修正」と「編集▼」)、「編集」のプルダウンに「AIコメント削除」と「バックアップから戻す」を置いた。ボタンの名前を表のとおりに変え、会話リセットを右寄せにし、Window の大きさを変えられるようにした (最小は最初の大きさ 300x222)。描画と入力を `ai_helper/screen.rb` に分け、本体のコンパイルの山は 928 KB から 740 KB に下がった。sim の Modern (標準構成・640x360・全部 mruby) で確認した。指示書は instruction_a3c.md

## 1. 画面の作り

### 1.1 段の並び (上から)

```
+--------------------------------------------+
| 質問 [ヒント] 作成 | 修正  編集▼            |  メニューバーの帯 (高さ 15)。選んだ使い方は反転
| AI: ...答え (スクロール、右端に位置の棒)    |  答えの欄
|--------------------------------------------|
| 状態の行 (2 行まで。問いのときは問いの文)   |
| [入力の行]                                  |
| [送信][中断][文書も送る]       [会話リセット]|  会話リセットは右寄せ (右下の角を空ける)
+--------------------------------------------+
```

- **メニューバー**: 帯の色はエディタのメニューの行と同じ作り (`FmrbColors.shade(THEME_MENU_BG, theme_bg)`。
  Window の題の帯から 1 段ずらした色で、カラーキーの 0x01 にはならない)。字は `theme_fg_light`。
  選んだ使い方は、字の色の四角の上に帯の色の字 (反転)。使えないもの (親が「作成」を止めている) は、
  字の色を帯の色の側へ 1 段ずらした薄い色。区切りは同じ薄い色の縦線。「編集」の後ろに小さな三角を描いた
  (書体の ▼ に頼らない)。帯と答えの欄の間は 3 px の地の色。
- **答えの欄**: 前のとおり。行の間に余白が無くなって最後の行が状態の行の線に接したので、欄の上を 1 px 下げた
  (300x222 で 9 行)。
- **下の段**: 送信・中断は左から今の並び (幅 40)。「文書も送る / 文書は送らない」は「質問」のときだけ、中断と
  会話リセットの間に置く (幅が足りないときは間に収まる幅に縮め、20 px 未満なら出さない。最小の大きさでは
  縮まない)。会話リセットは右端から `resize_corner` (大きさを変える角) を空けて置く。
- **問いのボタン** (はい・いいえ・キャンセル、ヒント・修正してもらう・キャンセル、バックアップの番号など) は
  前のとおり下の段を丸ごと置き換える (会話リセットも、問いの間は出ない。問いの間は押しても断られるため)。

### 1.2 最小の大きさ・大きさの変更

- `.app.toml` に `resizable = 1`、`min_window_width = 300`、`min_window_height = 222` (最初の大きさと同じ)。
  最初の大きさと位置は変えていない。全画面にはしない (`fullscreen_switchable` は書いていない)。
- カーネルは角を離したときに 1 回だけ大きさを変える (動かしている間は枠の線だけ)。`on_resize(w, h)` で
  段の位置を組み直し、幅が変わったときだけ答えを折り返し直す (1 回の大きさの変更で 1 回)。
- 答えの持ち方を変えた: 前は折り返した後の行の文字列を持っていたが、今は**話 (メッセージ) をまるごと**
  `@msgs` に持ち、行は「話の番号・バイトの位置・長さ」の 3 つの整数の配列で持つ。描くときに見える行だけ
  `byteslice` する。上限は前と同じ 400 行 (超えたら古い話から捨てる)。折り返し直した後は、上に見えていた
  行 (話と位置) が上に来るように戻す。
- 入力の行に打ちかけた文は `@input` のままで、新しい幅で末尾が見えるように描き直すだけ。
- 前からあった `on_resize` は引数を取らない形で、大きさを変えられない Window なので呼ばれていなかった。
  大きさを変えたら `ArgumentError` で落ちたので、`on_resize(w, h)` に直した。

### 1.3 編集のプルダウン

- FmrbUI にプルダウンの部品は無い (Label・Button・Toggle・Stepper・Enum・Scrollbar・TextField) ので、
  AI ヘルパーの中で描いた。「編集」の下 (帯のすぐ下) に、地 `theme_bg`・枠 `theme_border`・字 `theme_fg`、
  項目の間に薄い線。1 項目 15 px。右にはみ出すときは区画の中に寄せる (300 幅では右に寄り、640x360 で広げた
  Window では「編集」の真下)。
- 開いている間は、次の押下・ホイール・キーをプルダウンが受ける: 項目の上の押下はその項目を実行、それ以外の
  押下・ホイール・Esc は閉じるだけ (「編集」をもう一度押しても閉じる)。Esc 以外のキーは閉じた後にいつもどおり
  効く (打った文字は入る)。開いている間に答えが届いて答えの欄を描き直しても、プルダウンは上に描き直す。
  大きさを変えると閉じる。
- 「AIコメント削除」は前の「AIの行を消す」と同じ動き。「バックアップから戻す」は 2 章。

## 2. バックアップから戻す

### 2.1 動き

1. 「編集」→「バックアップから戻す」。前の頼みが終わっていなければ「前の頼みがまだ終わっていません。」
2. エディタの文書を読む (`ai_read`)。エディタが動いていない・`busy`・`help` は「作成」と同じ文で止まる。
3. 名前の無い文書は「今の文書には名前が無いので、バックアップはありません。」、`<名前>.bak1`〜`.bak9`
   が 1 つも無ければ「<名前> のバックアップはありません。」で終わる。
4. 答えの欄に一覧を出す:
   ```
   AI: aitest.app.rb のバックアップ (1 が最初の中身、番号が大きいほど新しい):
   1 (最初の中身): 386 バイト「class AitestApp < FmrbApp」
   2: 45 バイト「class Bak2App < FmrbApp」
   ...
   5 (いちばん新しい): 45 バイト「class Bak5App < FmrbApp」
   ```
   手掛かりは大きさと、頭の 512 バイトの中の最初のコードの行 (`#` で始まらない空でない行。無ければ最初の
   空でない行) を 150 px に切ったもの。状態の行に「どのバックアップに戻しますか? 番号を選んでください。」、
   下の段に番号のボタン [1]〜[5] と [キャンセル]。
5. 番号を選ぶと、**選んだ退避をまず `/tmp/ai_new.rb` に写す**。その後は「作成」と同じ `ask_overwrite`:
   今の中身を残しますか? [はい][いいえ][キャンセル] (名前があって中身が空の文書でも聞くのは「作成」と同じ)。
6. はい: 今の中身を次の番号に退避してから `ai_replace` (版つき)。成功したら退避の数を 5 個に詰める
   (前のとおり `.bak1` を残し 2 番目から消して番号を詰める)。いいえ: 退避せずに入れ替える。
   キャンセル: 何もしない (「キャンセルしました。エディタの文書はそのままです。」)。
7. 終わると「aitest.app.rb.bak1 の中身に戻しました。前の中身は aitest.app.rb.bak3 に残しました。」
   (番号は詰めた後の番号)。戻した後も退避のファイルは消さない (はい のときの詰める決まりで消えるものを除く)。

- 版違い (選んでから はい までにエディタで書いた): エディタが `ver` で断る → 作った退避を消し、読み直して
  「待っている間に書いた分があります。今の中身を残しますか?」をもう一度聞く (「作成」と同じ)。読み直したときに
  エディタの文書が別のファイルに切り替わっていたら、「エディタの文書が切りかわったので、戻しませんでした。」で
  やめる (別の文書に戻すことはしない)。
- `busy`・`help` で入れられなかったときは「もう一度」「キャンセル」(「作成」と同じ)。
- gem (AI ホスト) につながっていなくても使える。「AIコメント削除」も前から gem を見ていない (`press_erase` は
  `@hello` を確かめない)。どちらも変えていない。

### 2.2 仮決めで困った所

- **はい のときに選んだものが消える**: 5 個ある状態で `.bak2` を選んで はい にすると、今の中身が `.bak6` に退避され、
  5 個に詰める決まりで `.bak2` (選んだもの) が消え、`.bak3`〜`.bak6` が `.bak2`〜`.bak5` になる。中身は先に
  写してあるので戻るのは選んだ中身だが、**戻した中身の元の退避はもう無い** (文書がそれと同じ中身になっただけ)。
  指示書の想定どおりだが、子どもから見ると「戻したら一覧から 1 つ消えた」ように見える。詰める決まりを戻すときだけ
  変えるかはユーザに決めてほしい (6 章)。
- 一覧の手掛かりに時刻を出せない (PicoRuby の `File` で更新の時刻を取れない)。大きさと最初の行だけ。
  fake の LLM は毎回同じ中身を返すので、試験では同じ大きさ・同じ行が並んだ (本物では違う中身になる見込み)。
- 番号のボタンは数字だけ。説明は答えの欄の一覧に出す (下の段の幅に [1]〜[5] と [キャンセル] が収まるように)。
- 状態の行の「戻しました」は、gem が見つからない間は 2 秒以内に「AI ホストが見つかりません。…」で上書きされる
  (前からの、見つからない間 2 秒ごとに状態を出す作りのため。答えの欄の一覧は残る)。

### 3.4 今までの動き (fake の LLM)

標準構成 (426x240、Spinel のエディタ):
- ヒント: 「ヒントを 2 個入れました。」(`ai_done ok=1`)、エディタに `# AI: ` の 2 行。
- 作成: はい → `aitest.app.rb.bak1` ができ、入れ替わった。続けてもう 1 回で `.bak2`。
- 修正: `crash.app.rb` (`@gfx.drw_text`) を F5 → エラーの窓を閉じて「修正」→「このエラーについて頼めます」と
  [ヒント][修正してもらう][キャンセル] → 修正してもらう → はい で `crash.app.rb.bak1`、入れ替わった。gem の記録の
  `ask` が `"mode":"fix"` で `"error":"undefined method 'drw_text' for FmrbGfx (NoMethodError)..."`。
- AIコメント削除 (プルダウンから): 「2 行消します」→ 消す で `ai_done ok=1`。
- 質問: 「(質問 + 文書 crash.app.rb) nani」→ 答え。「文書は送らない」に切り替えた後は「(質問、文書なし)」。
- 中断: `[[wait 6]]` の途中で「中断」→「中断しています…」→「中断しました。」。640x360 で Esc でも同じ。
- 会話リセット: 「会話をリセットしました。前のやり取りは AI に送りません。」、答えの欄が空になった。

全部 mruby の構成 (426x240): 起動、質問 (文書つき、答えが出た)、編集のプルダウン (バックアップの一覧 → 1 を はい で
戻した、AIコメント削除) が通った。

### 3.5 バックアップから戻す

標準構成 (426x240)。エディタで保存したファイルを `cmp`/md5 で比べた。

- `.bak1`・`.bak2` がある状態で `.bak1` を選んで はい → 「aitest.app.rb.bak1 の中身に戻しました。前の中身は
  aitest.app.rb.bak3 に残しました。」。Ctrl+S で保存したファイルが `.bak1` とバイト単位で同じ。今の中身は `.bak3` に
  退避された (413 B。fake の作成の結果)。
- いいえ (`.bak2` を選んだ): 退避が増えずに入れ替わった (版 11 → 12、`copied` の行は選んだ退避の写しだけ)。
- キャンセル: `ai_replace` を送らない (`ai_done` が出ない)、「キャンセルしました。エディタの文書はそのままです。」
- 退避が 5 個 (中身を別々にした `.bak1`〜`.bak5`) で `.bak2` を選んで はい → ログ `copied .bak2 -> /tmp/ai_new.rb`、
  `copied /tmp/ai_doc.rb -> .bak6`、`ai_done ok=1`、`removed .bak2`。保存したファイルが**元の `.bak2` の写しと同じ**
  (選んだ中身)。退避は `.bak1`〜`.bak5` (元の 1・3・4・5 と今の中身)。
- 退避が無い (`nobak.app.rb`): 「nobak.app.rb のバックアップはありません。」
- 無題の文書 (Ctrl+N): 「今の文書には名前が無いので、バックアップはありません。」
- エディタが動いていない: 「エディタが動いていません。エディタで文書を開いてから、もう一度押してください。」
- gem を止めた状態: 一覧 → 1 → はい で戻った (`crash.app.rb.bak1` → 文書、今の中身は `.bak2`)。AIコメント削除も
  gem 無しで動いた (「AI のコメント … はありません。」)。

### 3.6 回帰と VM プール

- `rake regress`: host 33 suites・regress 310 runs、全部通った (直した後に 2 回)。
- `rake regress:screens ONLY=modern`: `screens: 6 passed / 0 failed (modern 6/6; 2.0 min)`。
- VM プール (sim、64 ビット、プール 1.5 MB、標準構成)。同じ手順 (エディタで同じ文書、AI ヘルパーを起動 → ヒント →
  作成 はい → 質問 → 削除) で、直す前 (この段の HEAD と状態の行の色の変更) と直した後を比べた。

| | 直す前 | 直した後 | 差 |
|---|---|---|---|
| 本体のコンパイルの後 (used / peak) | 517,328 B / 928,032 B (59%) | 480,168 B / 739,896 B (47%) | 山 -188 KB |
| 起動後 (`ps` の mem_used) | 660,664 B | 664,808 B | +4.1 KB |
| 結果を受けたとき (`pool_used`、3 回) | 660,640 / 673,552 / 661,824 B | 660,248 / 670,960 / 684,640 B | 揺れの中 |
| ひととおり使った後 (`ps`) | 647,512 B | 656,552 B | +9.0 KB |

  - 増えた分の理由: コードが増えた (メニューバー・プルダウン・折り返し直し・戻すで、3 つのファイルの合計は 51.2 KB
    から 61.9 KB。命令列と文字列の定数は VM に残る) と、答えを話ごとに持つ (話の文字列 + 行ごとの整数 3 つ。前は
    行ごとの文字列)。GC の時期で 10〜20 KB は揺れるので、+4〜9 KB は揺れと同じ程度。プールの 7 割 (1.1 MB) まで
    余裕がある。ほかに、大きさの変更や長い質問をくり返した回では 693,680 B の時もあった (同じく GC の時期と

## 4. 自分で決めた言葉・細部

- 状態の文: 「中断しています…」「中断しました。」「キャンセルしました。」「キャンセルしました。エディタの文書は
  そのままです。」「会話をリセットしました。」、修正の問い「「ヒント」か「修正してもらう」を選んでください。」
  (止められているとき「「ヒント」を選んでください (「修正してもらう」は親の設定で止められています)。」)。
- 戻すの文: 一覧の頭「<名前> のバックアップ (1 が最初の中身、番号が大きいほど新しい):」、印「(最初の中身)」
  「(いちばん新しい)」、問い「どのバックアップに戻しますか? 番号を選んでください。」、終わり「<名前>.bakN の中身に
  戻しました。前の中身は <名前>.bakM に残しました。」、無いとき「今の文書には名前が無いので、バックアップはありません。」
  「<名前> のバックアップはありません。」、切り替わったとき「エディタの文書が切りかわったので、戻しませんでした。」
- 一覧は「AI:」の行として答えの欄に出す (前からアプリ自身の案内も「AI:」で出していたのに合わせた)。
- メニューバーの薄い色・区切りの線・三角は自分で描いた。プルダウンの項目の間に線を入れた。
- Esc を scancode (0x29) でも受けるようにした。sim では文字の値で受ける前の形では Esc が効かなかった
  (確認の問いのキャンセルが起きなかった)。エディタと同じく scancode で読む形。
- 最小の大きさ = 最初の大きさ (300x222)。「今の大きさで全部のボタンが入ること。それより小さくはできない」を、
  最初の大きさを下限とする意味に読んだ。
- 問いの間は会話リセットを出さない (前のとおり、問いのボタンが下の段を置き換える)。
- 答えの上限 400 行は前のとおり。超えたら古い話から捨てる (前は古い行から 1 行ずつ)。
