## 2. Asterism に載せる形 (plan 6.2)

### 2.1 分かったこと

- **1 通の大きさ**: 端末の zenoh-pico は断片を組み直す領域が `Z_FRAG_MAX_SIZE` 16384
  (`picoruby-asterism-zenoh/include/zenoh_generic_config.h:44-53`。fmruby-core の写しも同じ。どのビルドも上書きしていない)。
  これを超える答えは「だれも答えなかった」ように捨てられる (`host_test/cruby_check.rb:38-55` で 12,000 B は通り 20,000 B は捨てられる)。
  README の Transfer の節の「1 回 4 KB」(4,044 B は通り 4,048 B は通らない) は 4096 だった頃の値で、今は古い。
  **端末が受け取る答えは 16 KB (msgpack の包みを含む) まで**。端末から送る側の上限は実測が無い (未確認。送る側は断片に分けて出すので
  受け手 = CRuby の zenoh-c の上限が効くはずだが、測っていない)。
- **時間**: 呼び出しの既定の時間切れは 2 秒 (`net[path, timeout:]` で変える)。待つ呼び出しはアプリの描画と入力も止める。
  端末では `proxy.async.<method>` の `Future` を `on_update` で `done?` を見るのが決まり (README「How waiting works」「Stack」)。
- **値**: msgpack の nil・真偽・整数・小数・文字列・配列・Hash だけ。Symbol は文字列で届く。入れ子は 16 段まで。
- **だれが呼んだか**: `expose(..., caller: :from)` で `from:` に呼んだノードの ID が入る。素の TCP では名乗りにすぎない。
  mTLS のルータの ACL で、証明書ごとに `asterism/*/<app>/*/call/${node}` だけ query を許すと拘束力が出る
  (README「Who called」、console のロール `ask` の行: `asterism-console/docs/g1_5.md:21,60`)。
- **端末の接続**: `FmrbAsterism::Link.new(self, app)` が WiFi 待ち・接続・つなぎ直しを持ち、つながるたびに `link_up(link)` が
  呼ばれる。ルータ・ノード ID・証明書は `/home/asterism/config.toml` と `<name>.tar` (`FmrbAsterism.settings`)。
  1 本の接続で zenoh-pico 約 9 KB (PSRAM)・VM プール約 3 KB (`asterism_protocol2/design.md`「端末での重さ」)。
- **ローカルのルータ**: sim の stack に `fmruby_zenohd` (eclipse/zenoh:1.10.1) があり、sim の中から `tcp/zenohd:7447`、
  PC から `tcp/127.0.0.1:7447`。gem はそのまま PC 側でつなげる。sim なしで試すときは回帰の道具と同じく
  `docker run eclipse/zenoh:1.10.1 --no-multicast-scouting --listen tcp/0.0.0.0:7447` を別のポートで立てる
  (`tools/regress/checkpoint_asterism.rb:71-94`)。
- **CRuby の側**: `Asterism.connect(...) { |net| net.expose(...); net.run }`。公開したメソッドは受信のスレッドで 1 つずつ走るので、
  **長い仕事 (LLM) は自分のスレッドへ渡す** (README「Threads」)。この PC に asterism 0.14.0・asterism-zenoh 0.4.2・msgpack 1.8.5・
  anthropic 1.80.0・prism 1.9.0 が入っている。
- **Asterism::Transfer** (再送つきのファイル転送) もあるが、受け手に Inbox を公開し、片 3,072 B・SHA-256 の確認・
  受け取りの設定 (`/etc/asterism/receive.toml`) が絡む。gem → 端末の向きでは端末にも Inbox が要る。試作には重い。

### 2.2 試作で使う形

gem の位置: ノード ID は設定 (既定 `tutor`)、アプリ名 `tutor`、オブジェクト `helper`。パスは `<gem-node>/tutor/helper`。
全部のメソッドは `caller: :from` で `from:` を受け、受け付ける端末の一覧 (設定) に無ければ `{"error" => "not_allowed"}` を返す。
**例外でなく Hash の `"error"` で返す** (端末で例外の型を分けるより、子ども向けの文に変えやすい)。

| メソッド | 引数 | 返り値 |
|---|---|---|
| `hello(info)` | `{"fw" => FmrbConst::OS_VERSION, "lang" => "ja", "host" => "tab5"}` | `{"ok" => true, "modes" => ["ask","hint","make","fix"], "piece" => 8192, "doc_max" => 65536, "used" => n, "max" => m, "name" => "親の名前"}`。止められた使い方は `modes` に入らない |
| `doc_begin(bytes)` | 文書のバイト数 | `{"doc" => "d17"}` (`doc_max` を超えれば `{"error" => "too_large"}`) |
| `doc_piece(doc, i, text)` | 片の番号 (0 から)・片 (8 KB まで。行の境で切る) | `{"have" => 受け取ったバイト数}`。同じ番号は上書き (やり直してよい) |
| `ask(req)` | 下の Hash | `{"ticket" => "t42"}` か `{"error" => "limit" / "busy" / "bad_request", "message" => "..."}` |
| `status(ticket)` | | `{"state" => "queued" / "thinking" / "checking" / "done" / "failed" / "cancelled", "message" => "表示用の短い文"}` |
| `result(ticket)` | | `{"kind" => "answer" / "hint" / "doc", "explain" => 説明 (4 KB まで), "hints" => [[行, その行の文, コメント], ...], "doc_bytes" => n, "pieces" => k, "base_ver" => 頼んだときの版}` |
| `result_piece(ticket, i)` | | `{"i" => i, "text" => 片}` (`kind` が hint・doc のとき、入れ替える文書全体) |
| `rebase(ticket, doc)` | 版が違ったときに送り直した今の文書 | `{"ticket" => 新しい番号}` (LLM を呼ばずに合わせ直す。4 章) |
| `cancel(ticket)` | | `{"ok" => true}` |
| `pending()` | | この端末宛てでまだ `ack` していない番号の配列 `[["t42", "done"], ...]` |
| `ack(ticket)` | | `{"ok" => true}` (gem は結果を忘れてよい) |
| `new_talk()` | | `{"ok" => true}` (この端末の会話の続きを消す) |

`ask` の `req`:

```ruby
{ "mode" => "ask",            # "ask" / "hint" / "make" / "fix_hint" / "fix_make"
  "text" => "子どもの文",
  "doc" => "d17",             # doc_begin の番号。8 KB までなら "doc_text" に直接入れてよい
  "doc_text" => nil,
  "file" => "/home/game.app.rb", "ver" => 1234,   # 版は結果にそのまま返る
  "cy" => 12, "cx" => 4,      # カーソル (0 から)
  "error" => "最後のエラーの文 (1 KB まで)",
  "fw" => "3.1.0", "lang" => "ja" }
```

- **結果は端末が取りに行く** (トピックにしない)。理由: トピックは届かなかった値を出し直さない (README「The present value」)。
  落ちた後の受け取り直し (`pending`) にはどのみち呼び出しが要るので、1 本にまとめる。進み具合も `status` で 1 秒ごと。
  1 秒ごとの小さな呼び出しは LAN で数十 ms の見込み (未実測)。50 ms ごとの `on_update` では `Future#done?` を見るだけ。
- **片の大きさは 8 KB** (16 KB の半分。msgpack の包みと日本語の説明の分の余裕)。端末 → gem の片の上限は未実測なので、
  A2 で 8 KB が通るかを最初に確かめ、通らなければ 3,072 B (Transfer の実績値) に下げる。
- **結果を持つ時間**: 24 時間 (設定)。gem の再起動で消えてよい (A1)。記録 (8.5) はファイルに残る。
- **会話の続き**: gem が端末ごとに直前 4 往復を持ち、30 分使われなければ忘れる (仮。決めてほしいこと)。

### 2.3 書き方の見本

端末 (mruby):

```ruby
def on_create
  @link = FmrbAsterism::Link.new(self, "aihelp", tag: "ai_helper")
end

def link_up(link)
  found = link.conn.each("*/tutor/helper")          # discover the parent's gem
  @ai = found.size > 0 ? link.conn[found[0].asterism_path, timeout: 5.0] : nil
end

def on_update
  return unless @link.update
  if @f && @f.done?
    begin
      take(@f.value)                                  # a Hash from the gem
    rescue ::Asterism::Error => e
      show_problem(e)                                  # timeout / disconnected / remote error
    end
    @f = nil
  end
  if @ticket && @f.nil? && Machine.board_millis >= @next_poll
    @f = @ai.async.status(@ticket)
    @next_poll = Machine.board_millis + 1000
  end
end
```

gem (CRuby):

```ruby
Asterism.connect(cfg.router, node: cfg.node, app: "tutor", config: cfg.tls) do |net|
  net.expose("helper", Tutor::Helper.new(store, jobs, cfg), caller: :from,
             doc: "Family mruby AI helper",
             methods: { hello: 1, doc_begin: 1, doc_piece: 3, ask: 1, status: 1, result: 1,
                        result_piece: 2, rebase: 2, cancel: 1, pending: 0, ack: 1, new_talk: 0 })
  net.run                       # Helper methods only touch the store; jobs run on worker threads
end
```

`Helper` のメソッドは `Store` (Mutex で守る) を読み書きして即座に返し、`ask` は `Jobs` (Queue と数本の Thread) に積むだけ。
worker は LLM を呼び、検査し、`Store` に状態と結果を書く。worker は `net` に触らない。

### 2.4 受け付ける端末 (権限)

- 開発時 (素の TCP のローカルのルータ): gem の設定の `devices: ["fmruby-abc123", ...]` と `from` を照らす。名乗りなので取り違え防止にすぎない。
- VPS のルータ (A5): console が配る証明書 (mTLS) と、ルータの ACL のロールで、子どもの端末の証明書に
  `asterism/*/tutor/*/call/${node}`・`asterism/*/tutor/*/meta` の query だけを許す (今の `ask` ロールの形を `game` から `tutor` へ)。
  これで `from` が拘束力を持つ。gem の証明書には `asterism/<gem-node>/tutor/**` の queryable が要る。
- console の「Call permissions」は console の Web から呼ぶ人の権限で、端末と gem の間の呼び出しには効かない (別物)。

## 3. エディタとの知らせの形 (plan 5)

### 3.1 分かったこと

- **知らせ 1 通は 176 B まで** (`FMRB_MAX_MSG_PAYLOAD_SIZE`、`components/fmrb_msg/fmrb_msg.h:28`。msgpack にした後の大きさ)。
  大きいものは `/tmp` に書いてパスだけ送るのが決まり (`sig/fmrb_app.rbs` の `publish`、見本 `flash/app/test/tmp_writer.app.rb`)。
- **送り方は 2 つ**: `publish(topic, data)` はカーネルが `{"cmd" => "topic_data", "topic", "data", "src_pid"}` に包んで配る
  (`fmrb_kernel.rb:686-700`、`data` が入れ子)。`send_message(pid, MSG_TYPE_APP_CONTROL, hash)` は相手の `on_control(hash)` に
  そのまま届く (送り手の pid は付かない。Spinel の `_dispatch_control` は `MessagePack.unpack` して `cmd` が文字列なら `on_control`)。
  **Spinel のエディタに入れ子の Hash を読ませない**ため、平らな `send_message` を使う。返す先の pid は頼みに `"re"` で入れる。
- **エディタを見つける**: `FmrbApp.ps` が `[{id:, name:, ...}]` を返す。エディタは Spinel 版も全画面版も名前 `FM-Editor`
  (`main/app/fmrb_app_spawner.c:207-250`。シェルとデスクトップの「エディタで開く」も名前で探している)。
- **本文は C にあり、ファイルとの出し入れも C**: `EditorCore.save_file(path)`・`load_file(path)` (`ec_save_file`・`ec_load_file`)。
  エディタの VM に本文の文字列を作らずに `/tmp` へ書き出し・読み込みができる。
- **今の on_control** は `file_selected` と `run_result` だけ (`editor.app.rb:494-516`)。M1 で `editor/docs.rb` (文書ごとの状態) が
  入っている途中。
- **直前の実行 (F5) のエラーはエディタが持っていない**。エディタが持つのは `@run_pid` だけ。エラーはアプリが落ちたときに
  C の 1 つの領域 (`fmrb_app.c:636-760`、名前 32 B + 本文とバックトレース 1024 B、**全アプリで最後の 1 つ**) に入り、
  `FmrbApp._get_last_error` (`{name:, error:}`) で mruby のアプリからも読める (`lib/gems/picoruby-fmrb-app/ports/esp32/app.c:1071`)。
  カーネルは `app_error` で受けてデスクトップのダイアログに出す。
- **版の番号**: `g_wrap_stamp` (`editor_core.c:115`) は全文書で 1 つで、ハイライトの作り直し (`line_drop_hl`) でも増えるので
  版には使えない。

### 3.2 試作で使う形

C (`editor_core.c`): 全体の通し番号 `g_edit_seq` を 1 本持ち、`ed_doc_t` に `uint32_t ver` を足す。本文を変える公開の口
(`ec_reset`・`ec_insert_text`・`ec_split_line`・`ec_join_line`・`ec_delete_char`・`ec_delete_range`・`ec_insert_multiline`・
`ec_paste_at`・`ec_load_file`) の成功のたびに `d->ver = ++g_edit_seq`。`ec_doc_version(slot)` を足し、Spinel の FFI と mruby の束ねに
`EditorCore.doc_version` を出す。通し番号から取るので、別の文書の版と同じ値にならない (タブを切り替えられても取り違えない)。
**内蔵 RAM は増えない** (`g_docs` は PSRAM、番号は 4 B)。

知らせ (全部 `send_message(pid, FmrbConst::MSG_TYPE_APP_CONTROL, hash)`、176 B に収まる平らな Hash):

| 向き | cmd | 項目 | 中身 |
|---|---|---|---|
| AI → エディタ | `ai_read` | `re` (自分の pid)、`id` (頼みの番号) | 今の文書を `/tmp/ai/doc.rb` に書き出してと頼む |
| エディタ → AI | `ai_doc` | `id`、`ok` (1/0)、`why` (`busy` / `help` / `io` / `nomem`)、`ver`、`n` (行の数)、`b` (バイト)、`y`・`x` (カーソル)、`sy`・`sx` (選択の起点、無ければ -1)、`m` (変更の印 1/0)、`f` (ファイルのパス、無題は `""`、60 B を超えれば名前だけ)、`rp` (`@run_pid`、無ければ -1) | 書き出した後に答える。本文は `/tmp/ai/doc.rb` |
| AI → エディタ | `ai_replace` | `re`、`id`、`ver` (読んだときの版)、`p` (`/tmp/ai/new.rb`)、`y`・`x` (入れ替えた後のカーソル) | 版が今と同じなら `p` を今の文書に読み込む。ファイル名はそのまま、変更の印を付ける、診断を消す、全体を描き直す |
| エディタ → AI | `ai_done` | `id`、`ok`、`why` (`ver` / `busy` / `help` / `io` / `nomem`)、`ver` (今の版) | 断ったときは今の版を返す |

- **断る (`busy`)**: ダイアログ・メニュー・検索・補完・キー一覧・色・保存の確認・ファイル選択の待ちが開いているとき。
  **F1 のヘルプを開いている間 (`@help_open`) は `help` で断る** (そのとき今の文書はヘルプの頁で、子どもの文書は `/tmp` に退避中)。
- **ヒントも作るも、エディタの口は `ai_replace` 1 つ**。ヒントは gem がコメントを入れた文書全体を作って検査済みで返すので、
  エディタに「行の上に差し込む」口を作らない。カーソルは AI 連携アプリが、上に入った行の数だけずらした `y` を渡す。
- **AI のコメントを消す** も AI 連携アプリの側: `ai_read` → `/tmp/ai/doc.rb` から `# AI: ` で始まる行 (頭の空白は許す) を数えて
  子どもに確認 → 消した文書を `/tmp/ai/new.rb` に書いて `ai_replace`。端末に Prism の口が無いので、ヒアドキュメントの中に
  子どもが同じ形の行を書いた場合も消える (確認の画面でそう言う。plan 4.2 のとおり)。
- **退避** (作る・直してもらう): AI 連携アプリが `ai_replace` を送る**前**に `/tmp/ai/doc.rb` (読んだ版の中身) を
  `<ファイル>.bakN` に写す。`ai_done` が `ok` 0 で返ったら、いま作った退避を消す。番号の決まりは plan 2 章 7b
  (`.bak1` は残し、5 つを超えたら 2 番目に古いものから消す)。無題の文書の退避先は決めてほしいこと。
- **直前のエラー**: AI 連携アプリが `FmrbApp._get_last_error` を読み、その `name` がエディタの実行したアプリの名前と合うときだけ
  「このエラーを付けて聞く」を出す (エディタの改修は要らない)。全アプリで最後の 1 つなので、合わないときは付けない。
- **開く** (M3): `doc/editor_multi_file` の M3 の `open_file` (カーネルが動いているエディタに `{"cmd" => "open_file", "path"}`)
  をそのまま使う。AI 連携に固有の口は足さない。
- **Spinel の制約**: エディタの `on_control` では `msg["ver"].is_a?(Integer)` で型を絞ってから使う (`_dispatch_control` と同じ書き方)。
  入れ子の Hash・配列を知らせに入れない。エディタが書くファイルは C の `save_file` だけで、Ruby で本文の文字列を作らない。
- 文書の大きさ: エディタの文書の領域は全部で 1 MB、`/tmp` は Modern で 8 MB。AI に送る上限は gem の `doc_max` (既定 64 KB) で決める。

## 4. 待っている間に文書が変わったとき (plan 4.2)

- 頼みの `ver` と `ai_replace` の `ver` をエディタが比べるので、黙って上書きすることは無い (3.2)。
- **作る・直してもらう**: `ai_done` が `why: "ver"` なら「待っている間に書いた分があります」と出し、もう一度 `ai_read` して退避と
  上書きを聞き直す (入れ替える中身は gem の結果のまま)。
- **ヒント**: `why: "ver"` なら AI 連携アプリが `ai_read` し直し、今の文書を gem に送って `rebase(ticket, doc)`。gem は
  LLM を呼ばずに次の手順で合わせ直し、5 章の検査をやり直して新しい結果を作る。
  1. ヒントの組 `[行, その行の文, コメント]` ごとに、今の文書で**その行の文と同じ行** (行末の空白を除いて完全一致) を探す。
  2. 1 つだけならそこ。複数なら、元の行の番号に一番近いもの。近さが同じ候補が 2 つあれば入れない。
  3. 見つからなければ入れない。空の行・`end` だけの行のように、同じ文が多い行に付いたヒントは、上の行の文も
     合わせて (2 行の並びで) 探す。
  4. 入れなかった分は結果の `explain` の後ろに「書きかえたので入れなかったヒント」として文で付ける (答えの欄には出る)。
- **どこで行うか: gem**。端末には Prism の口が無く、合わせ直した後の安全確認 (5 章) ができないため。費用は文書を送り直す通信だけ。

### 5.2 Prism での「コメント以外を変えていない」の確認 (実測)

最初は「コメントを除いたトークン列が同じ」だけで判定した。**それでは足りない例が 1 つ見つかった**:
行末が `\` の継続の後ろにコメントの行を入れると、Prism の COMMENT トークンが文を終える改行を飲み込むので、トークン列は
同じに見えるが、CRuby で実行すると文が 2 つに分かれる (`puts "a" \` / `# AI: hint` / `"b"` は `a` だけを出す)。
そこで次の 4 つを全部満たすときだけ差し込んでよいとした:

1. 差し込んだ後の構文の誤りが、前より増えていない。
2. COMMENT・EMBDOC_*・IGNORED_NEWLINE を除いたトークン列 (種類と文字) が同じ (NEWLINE は文を終えるので残す)。
3. 位置を除いた構文木 (ノードの種類と、位置以外の項目を再帰で並べたもの) が同じ。`__END__` の後ろのデータも同じ。
4. 差し込んだ行が、それだけで 1 つの COMMENT トークンになっている (`=begin`〜`=end` の中では EMBDOC_LINE になるので断る)。

結果 (prism 1.9.0、Ruby 3.4.11。「入れてよい」= その行の上に `# AI: hint` を同じ字下げで差し込める):

| 見本 | 行 | 正解 | 判定 | 理由 |
|---|---|---|---|---|
| 普通の行 | 2 | 可 | 可 | ok |
| ヒアドキュメントの中 | 3 | 不可 | 不可 | tokens differ |
| ヒアドキュメントの終わりの印の上 | 3 | 不可 | 不可 | tokens differ |
| ヒアドキュメントの次の行 | 4 | 可 | 可 | ok |
| 複数行の文字列 | 2 | 不可 | 不可 | tokens differ |
| `%w[]` が複数行 | 3 | 不可 | 不可 | tokens differ |
| 配列の `[...]` が複数行 | 3 | 可 | 可 | ok |
| `=begin`〜`=end` の中 | 3 | 不可 | 不可 | 差し込んだ行が EMBDOC_LINE |
| 行末 `\`、演算子が前の行 (`1 + \`) | 2 | 可 | 可 | ok (1 つの式のまま) |
| 行末 `\`、演算子が次の行 (`+ 2`) | 2 | 不可 | 不可 | tokens differ |
| 行末 `\`、文字列の連結 (`"a" \` `"b"`) | 2 | 不可 | 不可 | tree differs (トークンでは見逃す) |
| メソッドチェーン (行頭が `.`) の上 | 2 | 可 | 可 | ok |
| 2 つ目の `.` の上 | 3 | 可 | 可 | ok |
| `__END__` の後ろ | 3 | 不可 | 不可 | tokens differ |
| `__END__` の上 | 2 | 可 | 可 | ok |
| `%q{}` が複数行 | 2 | 不可 | 不可 | tokens differ |
| ブロックの中の普通の行 | 3 | 可 | 可 | ok |
| すでにコメントの行の上 | 2 | 可 | 可 | ok |
| 複数行の正規表現 `/.../x` | 2 | 不可 | 不可 | tokens differ |
| `<<~` の字下げ (浅い行の上) | 2 | 不可 | 不可 | tokens differ |

20 件すべて正しく見分けた。混ぜた見本 (クラス・ヒアドキュメント・`\` の継続・`%w[]`・複数行の文字列・`__END__`) でも、
入れてよい行は `[1, 2, 5, 6, 7, 8, 11, 13, 14, 15]` (16 行中) で、ヒアドキュメントの本文・`%w[]` の中身・文字列の 2 行目・
`__END__` の後ろを正しく外した。速さ: 45 KB・1,395 行のアプリ (`walk_scroller.app.rb`) で 1 回の判定が平均 91 ms。
gem はヒントの数 (数個) だけ判定するので足りる。

判定の中身 (スクラッチで流したスクリプトの関数の部分。見本の表は上):

```ruby
require "prism"

MARK = "# AI: "
SKIP = %i[COMMENT EMBDOC_BEGIN EMBDOC_LINE EMBDOC_END IGNORED_NEWLINE EOF]

def code_tokens(src)
  r = Prism.lex(src)
  toks = r.value.map(&:first).reject { |t| SKIP.include?(t.type) }
  [toks.map { |t| [t.type, t.value] }, r]
end

# The syntax tree without positions. Catches what the tokens miss (a COMMENT
# token swallows the newline that ends a statement after a backslash).
def shape(v)
  case v
  when Prism::Node
    h = v.deconstruct_keys(nil).reject { |k, x| k == :location || k == :node_id || x.is_a?(Prism::Location) }
    [v.class.name.split("::").last] + h.sort_by { |k, _| k.to_s }.map { |k, x| [k, shape(x)] }
  when Array then v.map { |x| shape(x) }
  when Prism::Location then nil
  else v
  end
end

def data_after_end(src) = Prism.parse(src).data_loc&.slice

def insert_comment(src, n, text = "hint")   # above line n (1-based), same indent
  lines = src.lines
  indent = (lines[n - 1] || "")[/\A[ \t]*/]
  lines.insert(n - 1, "#{indent}#{MARK}#{text}\n")
  lines.join
end

def insertable?(src, n)
  before_toks, = code_tokens(src)
  after = insert_comment(src, n)
  after_toks, after_r = code_tokens(after)
  return [false, "parse errors grew"] if Prism.parse(after).errors.size > Prism.parse(src).errors.size
  return [false, "tokens differ"] if before_toks != after_toks
  return [false, "tree differs"] if shape(Prism.parse(src).value) != shape(Prism.parse(after).value)
  return [false, "__END__ data differs"] if data_after_end(src) != data_after_end(after)
  on_line = after_r.value.map(&:first).select { |t| t.location.start_line == n && !%i[IGNORED_NEWLINE NEWLINE].include?(t.type) }
  return [false, "inserted line is not a comment"] unless on_line.size == 1 && on_line[0].type == :COMMENT
  [true, "ok"]
end
```

gem ではコメントを 1 つずつ下の行から順に入れ、入れるたびに判定する (入れた後の文書を次の判定の元にする)。
不可のコメントは「1 つ上の行に寄せて判定し直す (3 行まで)」→ それでも不可なら答えの文にだけ入れる。

### 5.3 PicoRuby に無い書き方の検出

gem は Prism の木を歩いて警告を作り、LLM に直させる (回数の上限 2):
`RegularExpressionNode`・`InterpolatedRegularExpressionNode`・`MatchLastLineNode` (Regexp)、`RationalNode`・`ImaginaryNode`、
`DefinedNode`、定数 `Struct`・`Data`・`Set`・`Fiber`・`Thread`・`Mutex`、呼び出し名の表 (`each_slice`・`sort_by`・`tap`・`binread`・
`pack`・`force_encoding` など 5.1 の表から)、配列要素を左辺に持つ多重代入 (`MultiWriteNode` の中の `IndexTargetNode`)、
`ForwardingSuperNode` ほかコード生成が断る形。名前の表は**束 (6 章) に入れてファームの版ごとに持つ** (`ruby_features.md` の表の
「app VM std」列から作る)。自分で定義したメソッドの名前と重なると誤検出になるので、エラーにせず警告として LLM に返す。

### 5.4 型の診断 (picoruby-ti)

- 型エンジンはホストで動く: `rake ti:test` は `vendor/picoruby-ti` を Prism と一緒に gcc でビルドして試験を流し、
  `rake ti:probe` は `tools/ti/ti_probe.c` から単体のコマンドを作る。型の db は `sig/*.rbs` から生成する C (`picoruby_ti_builtin_database.c`、

- ブラウザ版のために emscripten でビルドした `tools/web/wasm/ti.js`・`ti.wasm` (422 KB) があり、`tw_diagnose(src, len)` を出している
  (`-sENVIRONMENT=web,node` なので Node から呼べる見込み。この PC に Node 22 がある)。ただし今の `ti.wasm` は 8 月 13 日のビルドで、
  今の sig の db ではない (作り直しは `rake ti:wasm`、emsdk が要る)。
- **推奨: 最初の版 (A1〜A3) は構文 (5.2・5.3) だけ**。A4 で次のどちらか: (a) fmruby-core に「診断だけをする単体のコマンド」
  (`ti_probe.c` の隣に `ti_check.c`、`rake ti:check_cli`) を足し、版ごとの束にバイナリを入れる、(b) 束に `ti.wasm` を入れて gem が
  Node で呼ぶ。(b) は親の PC に Node が要る。(a) を推奨 (親の PC は CRuby と gcc があればよい、とは言えないので、束にビルド済みの
  x86_64・arm64 を入れる)。どちらもコードの変更とビルドが要るので、この調査ではしていない。

### 7.2 キャッシュ

## 8. Python (plan 7 章の仮決め)

サブの調査 (`components/micropython/`・`doc/micropython/known_limitations.md`・`phase6〜8.md`・`rakelib/micropython.rake`):

- MicroPython v1.28.0 が全端末 (S3・P4・sim・ネイティブ版・ブラウザ版) に入っている。境界は `sig/*.rbs` から生成するので、
  Window・描画 (`FmrbGfx`、日本語、画像、スプライト)・キーとマウス・音・ファイル (`FmrbFile`)・アプリ間の Pub/Sub と `send_message`・
  タイマ・通知は Ruby とほぼ同じ形で使える。
- **ネットワークと Asterism は Python から使えない** (方針として持ち込まない)。だから AI 連携アプリ自体は Ruby (mruby) で書く。
- 欠け: GfxBlock、動画、マイク、MIDI 送出、`json`・`re`・`time`・`os`。Python のアプリは同時に 1 本。
- 構文の検査は既製のコマンドが無い (`micropython:smoke` はホストのスモーク試験)。`mpy-cross` か、`mp_embed` をホストでビルドした
  「コンパイルだけ」のコマンドが要る。
- **推奨**: Python は A4 の後の段。条件は Ruby 版の流れ (束・検査・エディタの知らせ) が落ち着くこと、と Python の構文の検査を作ること。

## 11. 見立て (plan.md) と違った点

1. **呼び出し 1 つは「数十 KB まで」ではなく 16 KB まで** (端末の `Z_FRAG_MAX_SIZE`)。文書と結果は 8 KB の片に分ける。
   Asterism の README の Transfer の節の「4 KB」は古い値 (今は 16 KB)。
2. **端末のコンパイラは picoruby-prism の gem ではなく、Prism 1.9.0 を中に持つ mruby-compiler**。CRuby の prism 1.9.0 と同じ版なので、
   構文の判定は一致する。違いはコード生成と実行時のライブラリ (5.1)。
3. **トークン列の比較だけでは足りない** (行末 `\` の後ろのコメントが文の終わりの改行を飲み込む)。構文木の比較を足した (5.2)。
4. **ヒントの「行の上に入れる」口をエディタに作らない**。gem がコメントを入れた文書全体を検査して返し、エディタは丸ごと入れ替えるだけ。
   エディタ (Spinel) の改修は版の番号と 2 つの cmd で済む。
5. **直前の実行のエラーはエディタに無い**。全アプリで最後の 1 つの領域 (`FmrbApp._get_last_error`) を AI 連携アプリが読む。
6. **アプリ間の知らせは publish でなく send_message にする** (publish は `data` が入れ子になり、Spinel のエディタで扱いにくい)。
7. 版の番号は今の `g_wrap_stamp` を使えない (ハイライトでも増え、全文書で 1 つ)。文書ごとの番号を足す。
8. 型の診断はブラウザ版の wasm (`ti.js`) がもうあるが、版ごとの db が焼き込まれる形なので、束にバイナリを入れる形になる。
9. 知識の束は「全部入れる」と 20 万トークンを超える。Haiku 5.5 は 10 万トークンを超えると全部の区分が高い価格になるので、絞るのが前提。
10. `/app/modern` は Retro で一覧から隠れるだけで、storage には入っている。
