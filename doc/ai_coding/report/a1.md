## 4. a0.md の形から変えた所

1. **束の `api.rbs` で `%a{fmrb.internal}` のメソッドを落とさない**。a0 (6.2) はこの印を「アプリ向けでない」と読んで落としたが、
   sig/README.md では「境界に載せない (Ruby で書いた包み・省略できる引数を持つ包み)」の印で、`draw_text`・`set_font`・`present`・
   `clear_user_area`・`set_timer`・`publish`・`Log.info` など、アプリが一番使うものに付いている。落とした束で本物の LLM に
   聞くと `draw_text` が束に無い状態で答えていた (たまたま見本と雛形から書けていた)。残すと `api.rbs` は 53 KB → 61 KB。
2. **罠の表 (`pitfalls.tsv`) に、probe が app VM で出したエラーの文を 4 列目に足した**。表の行は「`rand(10)` と `Random.new(1)`」の
   ように 2 つを 1 行で試していて、本物の LLM が「乱数は使えない」と答えた (実際に無いのは定数 `Random` だけ。flappy は `rand` を使う)。
   エラーの文 (`NameError: uninitialized constant Random`) を付けると何が無いかが分かる。
3. **検査に「ブロック無しの繰り返し」(`each_with_index.map` など) を足した**。端末に Enumerator が無い (表の `enumerator_new`・
   `range_step` のエラー「fiber required for enumerator」)。`step` もブロック付きなら当てない。fmruby-core の
   `flash/app/{demo,game,tool}` の 31 本に検査をかけて、当たるものは 0 件 (誤検出なし)。
4. **使い方の名前は指示書の `ask`・`hint`・`make`・`fix`**。a0 の `fix_hint` / `fix_make` はやめ、「直して」でヒントを選んだときは
   `hint` に `error` を付ける (指示書 1 章)。
5. **`rebase(ticket, doc)` の `doc` は Hash** (`{"doc" => doc_begin の番号}` か `{"doc_text" => 文書}`、と `"ver"`)。a0 は文書を
   そのまま渡す形だったが、8 KB を超える文書は片で送るので、`ask` と同じ選び方にした。結果の `base_ver` は新しい `ver`。
   元の番号は `ack` 済みになる。
6. **`result` の `hints` の行番号は 1 から**、送った文書の行 (コメントを入れる行) の番号。`[行, その行の文, コメント]` は a0 のまま。
   ほかに `left_out` (入れられなかった数) と `bundle` (使った束の版) を足した。失敗は `{"error" => "check" / "llm" / "llm_setup" /
   "internal", "message"}`、やめたら `{"error" => "cancelled"}`、まだなら `{"error" => "not_ready", "state"}`。
7. **ヒントの文は 2 行・120 字まで** (それぞれ `# AI: ` で始まる行)。入れられない行は 3 行上まで寄せ、それでも駄目なら
   説明の後ろに「入れられなかったヒント」として付ける (a0 のまま)。全部入れた後に文書全体でも同じ比較をする。
8. **会話の続き** には、子どもの文の短い形 (`(使い方) 文 [文書 N 行を付けた]`) と答えの説明だけを入れ、前の文書とコードは入れない
   (費用を抑えるため)。
9. **上限の費用は全端末の合計**、回数は端末ごと (指示書の「1 日 1 ドル相当」をどちらで数えるかが書いていなかったので合計にした。
   設定で変える項目は無い)。gem を起こし直すと、その日の記録から数え直す。
10. **sender は `net.poll` してから `net.each` で探す**。CRuby で受信のスレッドを起こしていない接続は、poll するまで相手が見えない
    (端末は `FmrbAsterism::Link` が回すので同じことは要らない)。

## 7. A2 (端末のアプリ) への引き継ぎ

### 7.1 呼ぶメソッドと項目 (最終の形。`README.md` の表と同じ)

パス `<gem のノード ID>/tutor/helper` (既定 `tutor/tutor/helper`)。端末は `link.conn.each("*/tutor/helper")` で探す。
全部 `caller: :from`。断りは例外でなく `{"error" => 種類, "message" => 子ども向けの文}`。種類: `not_allowed`・`bad_request`・
`too_large`・`busy`・`limit`・`mode_off`・`not_found`・`not_ready`・`check`・`llm`・`llm_setup`・`internal`・`cancelled`。

| メソッド | 引数 | 返り値 |
|---|---|---|
| `hello(info)` | `{"fw" => FmrbConst::OS_VERSION, "lang" => "ja", "host"}` | `{"ok", "modes" (止められたものは入らない), "piece" => 8192, "doc_max" => 65536, "used", "max", "name"}` |
| `doc_begin(bytes)` | | `{"doc" => "d…"}` |
| `doc_piece(doc, i, text)` | i は 0 から、片は 8 KB (8192 バイト) まで。同じ番号は上書き | `{"have" => バイト}` |
| `ask(req)` | 下 | `{"ticket" => "t…"}` |
| `status(ticket)` | | `{"state", "message"}` |
| `result(ticket)` | | `{"kind", "explain" (4 KB まで), "hints" => [[行, 文, コメント]], "left_out", "doc_bytes", "pieces", "base_ver", "bundle"}` |
| `result_piece(ticket, i)` | | `{"i", "text"}` |
| `rebase(ticket, doc)` | `{"doc" => id}` か `{"doc_text"}` と `"ver"` | `{"ticket"}` (すぐ `done`) |
| `cancel(ticket)` / `ack(ticket)` / `new_talk()` | | `{"ok" => true}` |
| `pending()` | | `[[ticket, state], ...]` |

`req` = `{"mode" => "ask" / "hint" / "make" / "fix", "text" (2 KB まで。ask と make は空不可), "doc" => id または "doc_text" (8 KB まで),
"file", "ver" (整数。結果の base_ver に返る), "cy", "cx" (0 から), "error" (1 KB で切る), "fw", "lang"}`。
hint と fix は文書が要る。端末 1 台につき動いている頼みは 1 つ (2 つ目は `busy`)。結果は 24 時間、gem が動いている間だけ持つ。

### 7.2 ルータと gem の起こし方 (sim につなぐ)

- sim を `sim_up` で起こすと stack に `fmruby_zenohd` (7447) がある。gem は PC の側から
  `bundle exec exe/fmrb-tutor --router tcp/127.0.0.1:7447 --llm fake` でそこにつなぐ (sim の中の端末からは `tcp/zenohd:7447`)。
  sim の端末のノード ID が分からないうちは `devices = ["*"]` (既定) のままにする。
- sim なしで試すときは `bundle exec rake router:up` (127.0.0.1:17520) と `ruby test/sender.rb ...`。
- 本物の LLM は `--llm anthropic` と環境変数 `ANTHROPIC_API_KEY`。偽物の LLM は印 (`[[slow]]` で 1.5 秒待つ、`[[regexp]]` など。
  `lib/tutor/llm.rb` の `Fake` の説明) で、待ち・失敗の表示を端末の側で試せる。

### 7.3 片の大きさ

- gem の側は 8 KB の片で受け、8 KB の片で返す (行の境で切る。1 行が 8 KB を超えるときは文字の境で切る)。
  `hello` の `piece` で端末に知らせるので、端末 → gem の 8 KB が通らなかったら gem の設定 `store.piece` を 3072 にする。
- 端末が受け取る最大は `result` の答え (説明 4 KB + 項目) と `result_piece` (8 KB + 包み)。どちらも 16 KB の手前。
  端末で通るかは確認していない (a0 の未確認のまま)。
