### 1.1 ソースを持つ (`lib/tutor/sources.rb`)

- 取る元 (設定 `sources.core`・`sources.asterism`): 公開の fmruby-core と asterism。**直下のリポジトリ (family-mruby) は取らない**:
  アプリの書き方の skill `.claude/skills/fmrb-app-new` は直下の `.gitignore` に入っていて GitHub に無い (5.1)。束のその部分は
  gem の写し `data/app_guide.md` を使う (`tools/make_bundle.rb --root` で手元の checkout から作り直せる)。
- 取り方: `git clone --depth 1 --filter=blob:none --no-checkout --single-branch --no-tags --branch <ref>` の後、非 cone の
  sparse-checkout で要るパスだけを出す (`read-tree -mu HEAD`)。submodule は取らない (`--recurse-submodules` を付けない)。
  出すパスは束が読む分 (`sig/`・`flash/lib/templates/`・`flash/app/demo/`・`fmrb.h`) と検索の範囲から作り、外す型
  (`flash/app/test/`・`flash/app/game/mahjong/`) は `!` で出さない。asterism は `docs/ruby_features.md` だけ。
- 版の選び方: 端末の `fw` は `FmrbConst::OS_VERSION` で、元は `fmrb.h` の `FMRB_OS_VERSION` (今の develop は `"3.1.0"`)。
  開発中の版も枝番は付かず、タグと同じ形。fmruby-core のタグの一覧 (`git ls-remote --tags`) に `fw` と同じ名前があれば
  そのタグ、無ければ `sources.branch` (develop)。`fw` は `[0-9A-Za-z][0-9A-Za-z._-]{0,31}` の形でなければ develop
  (`/` を含むタグや `-` で始まる文字は git の引数に届かない)。タグの一覧が取れていないときは、手元にそのタグの写しが
  あればタグ、無ければ develop。
- 置き場: `sources.dir` (既定は `store.state_dir` の隣の `sources`、コンテナは volume `sources` の `/sources`)。
  `core/<ref>@<commit>/`・`asterism/main@<commit>/`・`bundles/<ref>@<core>-<asterism>/`・`state.json` (各 ref の今の写し・
  タグの一覧・最後の失敗)。**版ごとに別の写し**なので、3.0.0 の端末と develop の端末が同時に来ても混ざらない。
- 更新: `ls-remote` でコミットを見て、変わっていなければ clone しない (時刻だけ更新)。変わっていれば隣に clone して
  束を作り、できてから差し替える。頼みは `acquire` した写しを `release` まで持ち、古い写しは使う頼みが無くなってから消す
  (試験 `test_a_request_keeps_its_snapshot_through_an_update`)。取りに行くのは 1 度に 1 つ (直列)。
- いつ: AI ホストの起動のとき (裏のスレッド、ルータへの参加を待たせない)、その後 `sources.refresh_hours` (24) ごと、
  端末がまだ写しの無い版 (タグ) で来たとき (その頼みの中で取る)。起動直後の最初の取得が終わる前に来た頼みで、手元に
  写しが無い版は、その場で取りに行く。
- 取れないとき: 手元の写しを使い続ける (再起動しても `state.json` から読む)。それも無ければ gem に同梱の束 (道具なし)。
  タグの写しが無く取れないときは、develop の写しに寄せずに同梱の束にした (版の違う写しで答えないため)。
- git には端末も資格情報も渡さない (`GIT_TERMINAL_PROMPT=0`・`credential.helper=`)。失敗は git の `fatal:` の行を
  理由として記録 (`sources` の記録、`status`)。URL に利用者名・トークンが入っていても記録には出さない。
- 試験のための鍵: 環境変数 `ASTERISM_TUTOR_SOURCES_LOCAL_ONLY` があると `file://` とパス以外の URL を断る。
  `test/test_helper.rb` が立てるので、単体の試験も通しの試験 (起こした gem に継がれる) も GitHub に出ていかない。

### 1.3 調べる道具 (`lib/tutor/lookup.rb`)

| 道具 | 引数 | 返すもの | 上限 |
|---|---|---|---|
| `search_source` | `pattern` (必須)、`regexp` (既定 false)、`ignore_case`、`path` (この文字で始まるファイルだけ) | 1 行目に件数 (`N matches, the first 30:`)、続けて `パス:行番号: 行` | 30 行 (`lookup.hits`)、1 行 200 文字、型は 200 文字まで、正規表現は 1 行 0.5 秒・1 回の検索 3 秒 |
| `read_source` | `path` (必須)、`from`・`to` | 1 行目に `パス lines A-B of N`、続けて `番号| 行` | 120 行 (`lookup.lines`)、1 行 400 文字 |

- 範囲 (`sources.search`): `sig/**/*`・`flash/app/**/*`・`lib/gems/*/mrblib/**/*`・`flash/usr/share/doc/**/*`・`doc/reference/**/*`。
  外す型 (`sources.exclude`): `flash/app/test/**/*`・`flash/app/game/mahjong/**/*` (親の追加の指示)。
  `.rb` の大きさの上限 (`sources.rb_max_kb`): **32 KB** (1.4)。512 KB を超えるファイルと、NUL を含むファイル (wasm・画像) も外す。
- **範囲の外を読めない**: 範囲の中の普通のファイルの一覧を、シンボリックリンクをたどらずに歩いて作り (lstat)、道具の
  パスはその一覧で引く。`..`・絶対パス・ファイルへのリンク・ディレクトリへのリンク・範囲の外の実在のファイル
  (`components/...`)・外す型のファイルを、全部「no such file in scope」で断ることを試験にした。検索も Ruby の中だけで
  (`Regexp.new(..., timeout:)`)、LLM の文字列を外部のコマンドに渡さない。
- 往復 (`lookup.rounds`、既定 4): LLM が道具を呼んだら結果を返して続ける。4 往復目の結果に「調べ物の上限に達した…ここまでの
  材料で答えて」を付け、次の呼び出しは `tool_choice: none` (道具の定義は残す。前の往復を送り直せるように) で答えさせる。
  0 にすると道具を渡さない。
- 時間: 今の `llm.timeout_s` (120 秒) を、**1 つの答え (その調べ物を含む)** の上限にした (0.2.2 は 1 回の呼び出しの上限)。
  各呼び出しの待ちは残りの時間。残りが 3 分の 1 を切ったら、それ以上は調べさせない (「時間が足りないので…」を付ける)。
- 検査に落ちて答え直させるときも道具は使える。ただし往復の数は頼み全体で数える (答え直しで 4 往復増えない)。
- 記録: `llm` に `round`・`tool_calls` (2 往復目からは `prompt` を空にし、道具の結果は `tool` の方に)、`tool` に道具の名前・
  引数・結果の情報 (件数・読んだ範囲)・バイト数・返した文、`knowledge` に頼みの元 (ref・コミット・取った時刻、同梱の束なら
  その理由)、`result` に `used` (往復・呼び出しの数・トークンの合計・費用)。往復ごとの費用を 1 日の上限に足す (試験済み)。
- キャッシュ: 道具があるときは上の段のキャッシュ (`cache_control` を要求の上に) も付け、往復の途中の分も次の往復で読めるようにした。
- 端末に見える状態は今のまま (`thinking` の間に調べる)。端末のアプリは変えていない。
- 偽の LLM: 子どもの文の `[[search 語]]`・`[[read パス]]`・`[[lookup_loop]]` (毎回調べる) で道具を呼ぶ。調べた後の答えの説明に
  各結果の 1 行目を付ける (試験で中身が届いたかを見る)。

型 (sig) で足りない所: 端末どうしの通信 (`FmrbAsterism`・`FmrbAsterism::Link` の公開の呼び出し) の型。これがあれば 1 往復目の

## 5. 決めた細部の一覧

1. 直下のリポジトリは取らず、アプリの書き方は gem の写し `data/app_guide.md` (5.1)。
2. 写しは版 (ref) ごとに別の置き場。差し替えは隣に作ってから、古いものは使う頼みが無くなってから消す。取得は直列。
3. タグの写しが取れないときは develop に寄せず同梱の束。
4. `fw` が版の形でなければ develop。タグの一覧が取れていなければ手元にあるタグの写し。
5. 道具の名前・引数・上限は 1.3 の表 (30 行・120 行・200 文字・型 200 文字・正規表現 0.5 秒・検索 3 秒・ファイル 512 KB)。
6. `.rb` の上限 32 KB を、指示どおり範囲の全部の `.rb` に効かせた (mrblib の 3 つも外れる)。
7. 外す型は sparse-checkout からも外す (ディスクも減る)。束が読むパスは外さない。
8. `llm.timeout_s` を「1 つの答えとその調べ物」の上限にし、残り 3 分の 1 で調べ物を止める。
9. 往復の数は頼み全体 (答え直しを含む) で数える。答え直しのときも道具は使える。
10. 道具の結果は記録の `tool` に全文を残す (親が読めるように。1 回最大 10 KB 前後)。
11. 端末の状態の名前は増やさない (調べている間も `thinking`)。
12. 束の文にコミットを入れない。ref が版と違うときだけ「ソースは develop」を付ける。
13. 道具の決まりは束の後ろに足す別の文 (`data/tools_ja.md`)。道具が無いとき (同梱の束・往復 0) は付けない。
14. **使ってよい API を「型 (`sig/`) にあるもの」から「型にあるもの + 見本のアプリと端末の案内がアプリから使っているもの」に
    広げた** (6.1。7 章 1 で確かめてほしい)。
15. 道具の決まりに「束に無い話題 (ほかの端末とのやり取りなど) は答える前に調べる。束の Pub/Sub は同じ端末の中の話」を足した (6.1)。

## 6. 見立てと違った点

### 6.1 Haiku は束の似た API で済ませて調べなかった

(c) の 1 回目、LLM は「束で足りる」と判断して調べず、ほかの端末に届かない Pub/Sub で作った。指示書の決まり (土台で足りるときは
調べない) と、束に Pub/Sub の節があることが重なった。決まりに「束に無い話題は調べる、Pub/Sub は端末の中」を足すと、2 回とも
2 往復で調べた (5 の 15)。

もう 1 つ、指示書の「アプリから使えるのは型 (`sig/`) にあるものだけ」をそのまま書くと、型の無い `FmrbAsterism` は見本で見つけても
使えず、(c) は原理的に「見本を元に答える」にならない。ここは指示書の範囲の細部と見て、「見本と案内がアプリから使っているもの」
まで広げた (5 の 14)。それでも (c) は 3.2 の理由 (型が無い・短い見本が範囲の外) で届かなかった。

### 6.2 開発中の版はタグと同じ文字

`FMRB_OS_VERSION` は develop で `"3.1.0"`、リリースのタグも `3.1.0` の形。**3.1.0 のタグを打った後、develop の版の文字を上げるまでの
間は、develop を焼いた端末もタグの写しで答える**。枝番の無い今の形では見分けられない。

### 6.3 その他

- skill は GitHub に無かった (直下の `.gitignore` に `.claude/`)。
- fmruby-core のタグには版でない名前のものもある (`/` を含む)。版の形で弾くので選ばれない。
- 束は約 110 KB の見立てどおり (develop 113 KB)。道具の分のトークンは +6.6% で済んだ。
- 道具があると、往復のたびに束をキャッシュから読む (1 往復 約 4.7 万トークンの読み)。Haiku の単価では (c) で 0.0022 → 0.0043 ドル
  (キャッシュが温まっているとき)、待ちは +3 秒ほど (16.2 → 19.4 秒)。調べない頼みは今と同じか速い。

## 7. 親・ユーザに決めてほしいこと

1. **使ってよい API の範囲**: 「型だけ」(指示書) か、「型 + 見本と案内が使っているもの」(今の実装) か。後者は `data/tools_ja.md` の 1 行。
2. **32 KB の上限が mrblib にも効く件**: `fmrb-app.rb`・`fmrb-ui.rb`・`picorabbit_renderer.rb` が検索から外れる。今の決まりでは mrblib は
   答えに使わないので害は小さいが、flash/app だけに効かせる形もできる。
