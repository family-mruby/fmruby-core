# A2・A3 報告: 端末の AI 連携アプリ (質問 → エディタとつなぐ)

> 状態: 完了 | 更新: 2026-11-18 | Modern だけの mruby アプリ「AI ヘルパー」(`flash/app/modern/ai_helper.app.rb` + `ai_helper/editor.rb`) を作った。sim (Modern) の zenohd に親の PC から fmrb-tutor をつなぎ、質問・ヒント・作る・直して・AI の行を消すが通る。8 KB の片は両向き、12 KB の片は gem → 端末で通った。本物の LLM は 7 回 (0.0174 ドル)、作ったアプリ 3 本を F5 で実行して 3 本とも動いた。gem はヒントが末尾の改行の無い文書 (エディタが渡す形) に入らない不具合を直した。A3 の結果もこの文書に書く (a3.md は作っていない)。指示書は instruction_a2.md

### 1.2 画面 (Modern、窓 300x222)

```
+-------------------------------------------+
|[質問][ヒント][作る]  [直して][AIの行を消す] |  使い方 (選んだものが塗りつぶし) と 2 つの動作
| AI: ...答え (スクロール、右端に位置の棒)   |  「あなた: (使い方) 文」と「AI: 答え」
| あなた: (ヒント) ...                       |
|-------------------------------------------|
| 状態の行 (2 行まで。問いのときは問いの文)  |
| [ヒント: どこが分からないか (空でもよい)]  |  入力の行 (空のときは使い方の案内を薄く)
|[送る][やめる][新しい話][文書は送らない]    |  問いのときは選択肢のボタンに替わる
+-------------------------------------------+
```

- 答えは 12px の日本語の書体。幅は ASCII 6・それ以外 12 の固定幅で自前で折り返す (1 文字ずつ `text_width` を
  呼ばない)。最大 400 行、新しい答えはその頭を見せる。ホイール・上下・PageUp/Down で読む。
- 入力はかなの UTF-8 を 1 バイトずつ組み立てる (シェルと同じ形)。Enter で送る、BS で 1 文字消す、Esc は「やめる」
  (問いのときは最後の選択肢)。200 文字まで。
- 「文書は送らない / 文書も送る」は「質問」のときだけ出る (既定は送らない = 親の仮決め)。
- 既定の使い方は「ヒント」(plan 4.3)。gem が `make` を止めていれば「作る」は薄く、押すと理由が出る。
- 実際の画面の写し (sim): 会話の場所のスクラッチ `shots/` に 16 枚 (a2_ask_fake・a2_limit・a2_not_allowed・
  a2_gem_gone・a2_pending_after_kill・a3_make_ver・a3_busy・a3_real_make1_run ほか)。スクラッチは消える。

### 1.3 状態の持ち方

- 接続は `FmrbAsterism::Link.new(self, "ai_helper", retry_ms: 8000)`。つながると `*/tutor/helper` を
  `conn.each` で探し (送信なし)、`conn[path, timeout: 6.0]` の proxy を持つ。`hello` → `pending`。
  頼んでいない間は 2 秒ごとに `conn.each` で gem がまだいるかを見る。
- gem への呼び出しは `proxy.async.asterism_call(名前, ...)` の Future を 1 つだけ持ち、`on_update` で `done?` を見る。
  失敗 (`Asterism::Error`) なら proxy を捨てて探し直し、`hello` の後の `pending` で続きを拾う。
- 頼みの段階は `@phase` 1 本: `idle`・`ed_read`・`doc_begin`・`doc_piece`・`asking`・`poll`・`result`・`pieces`・
  `rebasing`・`ed_replace`・`choice`・`ack`。gem を待つ段階 (`net_phase?`) とエディタ・子どもを待つ段階を分け、
  接続が切れたときは gem を待つ段階だけを `idle` に戻す (番号は持ったまま、つながったら `pending` で続ける)。
- エディタへの知らせは `send_message` で、番号 `id` を付けて 1 つずつ。3 秒返事が無ければ理由を出す。
- 文書は VM に丸ごと持たない: 送るときは `/tmp/ai_doc.rb` を `read(n)` で片ごとに読み (改行の後ろで切る、無ければ
  文字の境で切る)、受け取った片は `/tmp/ai_new.rb` に開いたまま書き足す。消すときも 4 KB ずつ行に分けて読む。
  例外は 1 片 (8 KB) 以下の文書で、`doc_text` として `ask` に入れる。
- 端末には何も保存しない (会話の続きも結果も gem が持つ)。

### 3.1 (A2) 質問

- fake: `key ctrl+space` → `text "hennsuutteenani?"` → Enter で「へんすうってえなに?」を送り、「受け付けました。」→
  答え「(会話の続き: 0 往復) これは偽物の AI の答えです。…」。続けて質問すると「1 往復」、「新しい話」の後は「0 往復」。
- 本物 (1 回): 「がめんにもじをだすには?」→ 3 秒で答え (`@gfx.draw_text`・`set_font(:ja, 12)`・`present` の説明、漢字まじり)。
- **gem を止めた** (待っていないとき): 2 秒以内に「AI ホストが見つかりません。親の PC で AI ホストが動いているか確かめてください。」
  起こし直すと 10 秒ほどで「つながりました (AI helper)。今日 5 / 50 回。」
- **gem を止めた** (答えを待っている間、`[[wait 30]]`): `status` が「nobody answers」で失敗し「AI ホストから返事がありません。
  つながったら答えを受け取りに行きます。」→ 見つからない表示。起こし直した gem はその頼みを持っていない (記憶は
  プロセスの中だけ) ので「前の頼みの答えは、AI ホストが持っていませんでした。もう一度送ってください。」
- **ルータを止めた** (`docker stop fmruby_zenohd`): 「ネットワーク (ルータ) につながりません。少し待ってからもう一度つなぎます。」
  `docker start` の後、自動でつながり直して `hello` まで通った。
- **アプリを殺して起動し直す**: `[[wait 25]]` の質問の途中で `sim_app kill` → `spawn`。起動のログ `pending 1` →
  「前に頼んだ答えを受け取ります。」→ 17 秒後に答えが出た。
- **上限**: `per_device_per_day = 5` の gem で「今日使える回数 (5 回) を使い切りました。また明日使えます。」(答えの欄と状態の行)。
- **受け付けない端末**: `devices = ["fmruby-other"]` の gem で「この端末は、この AI を使えるように登録されていません。」
  (端末の名前を付け足すようにした: 「(この端末の名前: linux)」。親が `devices` に書くため)。
- **止めた使い方**: `make = false, fix = false` の gem で、「作る」を押すと「「作る」は、親の設定で止められています。」、
  「直して」の選択肢から「直してもらう」が消える。
- **やめる**: `[[wait 15]]` の途中で「やめる」→「やめています… (5 秒)」→ gem の側が終わったところで「やめました。」
  (偽物の LLM は待ちの途中では止まらないので、gem が終わるまで状態は「やめています」)。
- 固まらないこと: 上の全部で、ほかのボタン・入力・スクロールは効いた。**ただしルータに届かない間は、つなぎ直しの
  1 回ごとに Link の `connect` が約 4 秒アプリを止める** (`cannot open a session ... (-128)` まで 4 秒)。その間の
  キーは失われず、後でまとめて入る。再試行の間を 8 秒にして (Link の既定は 3 秒)、止まっている時間を半分以下にした。

### 3.2 (A3) ヒント

- `/home/aitest.app.rb` (ヒアドキュメントのある 25 行・369 B) をシェルの `edit` で開き、ヒントのまま Enter。
  fake の答えは「カーソルの行」と「1 行目」の 2 つ。2 行がエディタに入り (25 → 27 行、`*` が付く)、Ctrl+S で保存した
  ファイルから `# AI: ` の行を除いたものが元のファイルとバイト単位で同じ (`cmp`)。
  - 保存したファイルは末尾の改行が無い (エディタの決まり、m3.md)。`grep -v` が最後の行に改行を足すので、比べた結果は
    「元のファイル (末尾の改行あり) と同じ」。厳密には「元のファイルから末尾の改行を除いたもの + AI の行」。
- `[[heredoc]]` (ヒアドキュメントの中の行を指す答え): gem がその上の `MSG = <<~TXT` の上に寄せて入れた (`"at":4`)。
  ヒアドキュメントの中には入らず、コードは同じ。本物の LLM のヒント (4 章) でも同じ確認をした。
- **最初は 2 つとも入らなかった** (`left_out: tokens differ`)。gem の `insert_comment` が、末尾に改行の無い文書に
  改行を足してから比べていたため。エディタが渡す文書はいつも末尾の改行が無いので、gem を直した (5 章)。
- 大きい文書: `walk_scroller.app.rb` の写し (45,168 B、1,395 行) で、端末 → gem の片 6 つ (8 KB 前後、1 回 50 ms)、
  gem → 端末の片 6 つ (8,179〜8,187 B、1 回 100 ms)。行数 1,395 → 1,397。

### 3.3 (A3) 作る

- `/home/mk.app.rb` (6 行、120 B) で「click counter」を作る → 「今の中身を残しますか? (mk.app.rb.bak に退避します)」
  [はい][いいえ][やめる]。はい で `mk.app.rb.bak1` ができ、md5 が元のファイルと同じ (変更の無い文書なので、保存された

- いいえ: 退避を作らずに入れ替わった (版 25 → 26)。やめる: `ai_replace` を送らない (版 25 のまま)、

- 無題の文書 (Ctrl+N で `puts 1`): 「今の文書には名前が無いので、退避できません。上書きしますか?」[上書きする][やめる]。

### 3.4 (A3) 版違い

- ヒント: `[[wait 10]]` で頼み、待っている間にエディタの 3 行目に `# new` の行を足した。結果が来たとき `ai_read` で
  版 5 → 15 を見て `rebase 1 (sent ver 5, now 15)`。gem に今の文書を送り直し、新しい番号の結果を受け取って入れた。
  送ったときカーソルのあった `@count = 0` の上に、1 行ずれた正しい行に入った (保存したファイルの 16 行目の上)。
  コードは `# new` の 1 行のほかは同じ。
- 作る: `[[wait 8]]` で頼み、待っている間にエディタで `zz` を打った → 「待っている間に書いた分があります。今の中身を
  残しますか?」。そこでさらに `yy` を打ってから はい → エディタが `ver` で断り、作ったばかりの `.bak6` を消し
  (`ls` に無い)、読み直して同じ問いをもう一度出した。2 回目の はい で、`yyzz` を含む中身が退避され、入れ替わった。
  黙って上書きしたことは無い。

### 3.5 (A3) 直して・AI の行を消す

- `/home/crash.app.rb` (`@gfx.drw_text`) を F5 → エラーの窓 `undefined method 'drw_text' for FmrbGfx` を閉じて「直して」。
  `FmrbApp._get_last_error` の名前は `crash` (ファイル名の頭) で、エディタの `rp` (8) と組で合うので、エラーの頭 3 行を
  答えの欄に出し、「ヒントをもらいますか、直してもらいますか?」[ヒントをもらう][直してもらう][やめる]。
  - ヒントをもらう: `mode: "hint"` に `error` を付けて送った (gem の記録の `req`)。コメントが入った。
  - 直してもらう: `mode: "fix"`、退避の問い → はい で `crash.app.rb.bak1`、入れ替わった。
  - エラーが別のアプリのもの (aitest を F5 して落ちなかった後): 「エディタで実行 (F5) したアプリのエラーが見つかりません。
    F5 で実行して落ちた後に押してください。」
- AI の行を消す: 「AI のコメント (# AI: で始まる行) を 2 行消します。自分で同じ形に書いた行も消えます。」[消す][やめる] →
  消す で 25 → 23 行。保存したファイルに `AI:` が 0 行。

### 3.6 エディタが動いていない・ダイアログ中

- 保存の確認 (Ctrl+W) を出したままヒント: 「エディタでダイアログやメニューが開いています。閉じてから、もう一度押して
  ください。」(`ai_read` が `busy`)。
- F1 のヘルプ (`draw_text` の頁) を開いたままヒント: 「エディタでヘルプ (F1) が開いています。閉じてから、もう一度押して
  ください。」(`help`)。
- エディタを kill してからヒント・直して・消す: 「エディタが動いていません。エディタで文書を開いてから、もう一度押して
  ください。」エディタを勝手に起こしていない。
- その後もエディタは打てて保存できた (保存の確認を閉じた後に打って Ctrl+S、ファイルに反映)。結果を入れる段階で
  `busy`・`help` になったときは「もう一度」「やめる」を出す (コードの経路。sim では起こしていない)。

### 3.7 全部 mruby の構成 (2〜4 を 1 回)

エディタ・カーネル・デスクトップを mruby にした Modern の sim で: ヒント (`[[heredoc]]`、保存して AI の行を除くと元と
同じ)、作る 2 回 (`.bak1` が元の md5、`.bak2` ができる)、作るの版違い (「待っている間に書いた分があります」)、
ヒントの版違い (`rebase 1 (sent ver 9, now 13)` の後に入った)。2 ファイルに分けた後の本体でも、ここでヒントを 1 回
通した。**分けた後の形は標準構成 (Spinel のエディタ) では動かしていない** (分ける前の 1 ファイルで 3.1〜3.6 を通した。
分けたのはアプリの中だけで、エディタとの知らせは同じ)。

残件・気づいたこと:
