# A6 指示書: AI ホストが知識をソースから取り、LLM が調べられるようにする

> 2026-11-22 | 親セッションからサブ (Opus) への指示。先に読むもの: doc/ai_coding/plan.md (全部。特に 6.3・7c)、
> report の a0・a1 (束の作り方・上限・LLM の呼び方)、隣の `../asterism-tutor` の全部 (`lib/tutor/` の bundle・jobs・
> llm・prompt・check・config・status・log、`tools/make_bundle.rb`、`bundles/3.1.0/`、`test/`、`deploy/vps/`、
> `docs/install.md`、README、CHANGELOG)、Anthropic の Ruby の SDK での道具 (tool use) の使い方 (gem の中の文書と型)。

## 1. 起きていること

AI ホスト (asterism-tutor) の知識は、gem に同梱した束 1 つ (2026-11-17 に作った 3.1.0) だけ。それ以降に足した API
(絵: `draw_picture`・`picture_size` ほか) が無く、Asterism の通信と `FmrbNet` の型は元から入っていない。LLM は束だけで
一度に答え、分からない所を調べる手段が無い。束を足すたびに gem を出し直すことになる。

## 2. 決まっている形 (plan.md 7c。2026-11-22 ユーザ)

1. AI ホストが Family mruby のソースを GitHub から clone して持ち、束はそこから作る。
2. LLM に、検索する・ファイルの一部を読む、の 2 つの道具を渡す (読むだけ)。
3. 検索の範囲の既定: `sig/`、`flash/app/`、`lib/gems/` の mrblib、`flash/usr/share/doc/`、`doc/reference/`。設定で変えられる。
4. 調べ物は 1 回の頼みで 4 回まで。達したら、そこまでの材料で答えさせる。
5. 版: 端末の版のリリースのタグがあればそれ、無ければ develop の先頭。
6. 更新: 起動のときと、その後は 1 日 1 回。取れないときは手元のものを使い続ける。

## 3. 作るもの (asterism-tutor)

### 3.1 ソースを持つ
- 取りに行く先は設定 (既定は公開の fmruby-core の URL と、束の残りの元になる 2 つ: アプリの書き方の skill がある
  直下のリポジトリ、罠の表の元がある asterism。今の `tools/make_bundle.rb` が何をどこから読むかを見て、要るものだけ)。
  置き場は設定 (コンテナでは volume。gem の中に書かない)。submodule は取らない。浅く取る (履歴は要らない)。
  `components/` などの大きい所を取らずに済む方法 (sparse・部分 clone) があれば使い、ディスクと時間を測って report に。
- 版の選び方: 端末が送る `fw` (実物が何を送るかを `FmrbConst::OS_VERSION` の作り方から確かめる。開発中の版は
  タグと同じ文字になるのか、枝番が付くのか)。タグがあればそのタグ、無ければ develop の先頭。版ごとに持つか、
  1 つの置き場で切り替えるかは決めてよい (同時に 2 つの版の端末が来ても壊れないこと)。
- 束 (LLM に毎回渡す土台) は、取ったソースから作る。今の `make_bundle.rb` の中身を gem の中から使える形にする。
  **束の文は、ソースが変わらない間は 1 バイトも変わらないこと** (LLM の側のキャッシュが効くように)。
- 検査の型 (`checks.json`) も同じ所から。
- 取れないとき (ネットが無い・GitHub が落ちている・タグが無い) は、手元の前回のもの、それも無ければ gem に同梱の
  束で答える。記録と `status` に、どの元 (コミット) を使っているか、最後に取れた時刻、失敗の理由を出す。
- 更新は起動のときと 1 日 1 回。頼みを処理している最中に、足元のファイルが入れ替わらないこと。
- 既存の設定 `bundle.dir` (親が自分の束を使う道) は残す。

### 3.2 調べる道具
- LLM に渡す道具は 2 つ: 検索 (文字列か正規表現、範囲の中、結果は「パス:行番号: 行」で件数と 1 行の長さに上限)、
  読む (パスと行の範囲、行数に上限)。名前・引数・上限の値は決めてよい (report に並べる)。
- **範囲の外を読めないこと**: 設定の範囲 (パスの型) に合うファイルだけ。`..`・絶対パス・シンボリックリンクで外へ
  出られない。外部のコマンドに LLM の文字列を渡さない (Ruby の中で検索する。範囲は 5 MB 前後)。
- 往復の上限 (既定 4。設定で変えられる)。達したら道具なしで答えさせる。全体の時間の上限 (今の `timeout_s`) は守る。
- 土台の文に、道具の使い方の決まりを足す: 土台で足りるときは調べない。アプリから使えるのは型 (`sig/`) にあるもの
  だけで、検索で見つけた内側の呼び出しを答えに使わない。調べた中身をそのまま子どもに見せない (答え方の決まりは同じ)。
- 既にある「検査で落ちたら答え直させる」の道と一緒に動くこと (答え直しのときも道具を使えるか、は決めてよい)。
- 記録 (JSONL) に、道具の呼び出し (何を検索・どこを読んだ・何件返した) と、往復の数、増えた量 (トークン) を残す。
  費用の上限 (1 日) の数え方に、往復の分が入ること。
- 偽の LLM (`--llm fake`) でも、道具を呼ぶ流れを試験できるようにする。

### 3.3 配る形
- `deploy/vps/` のイメージに git を入れる・置き場の volume を足す。`docs/install.md`・README (英語と日本語)・
  `env.example`・CHANGELOG を合わせる。版を上げる (0.3.0)。**タグを打たない・push しない・リリースしない**。
- gem に同梱の束は、保険として残す (今の fmruby-core の develop から作り直す)。

## 4. 受け入れ条件

1. 自動の試験 (`bundle exec rake test`) が通る。新しく入れるもの: 範囲の外を読めない (`..`・絶対パス・リンク)、
   上限 (件数・行数・往復)、取れないときの戻り方、版の選び方、束の文が同じソースから 2 回作って同じ、偽の LLM での
   道具の往復。**試験は GitHub に出ていかない** (ローカルに作った git のリポジトリを元にする)。
2. 手元で 1 回だけ、本物の GitHub から取って束を作り、時間・ディスクの量・束の大きさ (バイトと見積もりのトークン) を
   report に書く。束に絵の API (`draw_picture`) が入っていること。
3. 本物の LLM での通し (鍵は親が渡した環境変数。**値を表示・記録・コミットしない**)。ローカルのルータと試験用の送り手で、
   次の 3 つの頼みを流し、記録から、調べたか・何回か・かかった時間と量・答えの中身を report に書く:
   (a) 土台で足りる簡単な質問 (調べずに答える)、(b) 絵を出すアプリを作る (`draw_picture` を正しく使う)、
   (c) 土台に無いことを聞く (例: ほかの端末と文をやり取りするアプリの作り方。検索して、ある見本を元に答える)。
   返ったコードが今の検査を通っていること。回数は最小限にする (費用)。
4. 道具なしの今の答え (0.2.2) と比べた、待ち時間と費用の変化を、(a)〜(c) の実測で report に書く。
5. `git status` に取りこぼしなし。起こしたもの (ルータ・コンテナ) は止めてある。

## 5. 範囲と止まる条件

- 触ってよい所: `../asterism-tutor` の全部 (作業ブランチ `sources` を切ってコミット)、fmruby-core の
  `doc/ai_coding/report/a6.md` と `rake docs:index` の結果 (develop からブランチ `ai-sources` を切ってコミット)。
- **触らない**: fmruby-core のコード・flash・回帰の道具 (束を作る道具を fmruby-core に移す案が良いと分かったら、
  移さずに report に案を書く)、端末のアプリ、asterism 本体・console・games・chat、graphics-audio、直下のリポジトリ、
  **VPS・端末 (P4-Nano・GPD・Tab5・Cardputer Zero)・gmktec**。fmruby-core でビルドしない (`build/` に触らない)。
- push しない・マージしない・タグを打たない・`git add -A` を使わない。コミットの書き方は fmruby-core/CLAUDE.md。
  コードのコメントは ASCII だけ (公開のリポジトリ)。実在のドメイン・IP・端末の名前・ローカルの絶対パスを書かない。
- 止まる条件: ユーザの作業が要る。範囲の外の変更が要る。**利用者から見た動きを、この指示書に無い形で決める必要が出た**
  (例: 待ち時間が大きく延びて、往復の上限や範囲を変えないと使えない。選ばずに、実測と選択肢を report に書いて返す)。
  本物の LLM の費用が、通しの確認で 2 ドルを超えそうなとき。
- 呼び名: 「AI ホスト」「端末」「Window」。
