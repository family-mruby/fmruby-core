# ミュート (音を出さない設定)

> 状態: 進行中 | 更新: 2026-10-01 | 本体の音を一括で消す設定。音源は動かしたまま出力の最後の段で無音にする (P4 は audio_p4、Retro と sim は graphics-audio)。再起動しても残り、メニューバーと遠隔から切り替えられる。M1 で作る

## 目的

通話中など音を出したくないときに、アプリの起動・ゲーム・起動音を含めて、本体の音を一括で止められるようにする。
開発の検証 (サブエージェントが実機でアプリを起動する) の前に、遠隔から止めておけるようにする。

## 分かっていること

- 音の出口: P4 (Tab5 / NARYAv4) は core の audio_p4 (APU のエミュレーションから I2S)。コーデックに音量と
  ミュートの口がある (`audio_p4_hw_set_volume`、0 でミュート)。Retro (S3) は WROVER の graphics-audio が鳴らし、
  core から音の命令を送る。WROVER 側の音量の命令は今は何もしない (スタブ)。sim は graphics-audio の SDL、
  ブラウザ版は audio_p4 から AudioWorklet。
- 起動音 (ジングル) はデスクトップが鳴らす。`boot_splash = false` でロゴごと消せるが、ミュートとは別の設定。
- 外部 MIDI 出力 (シリアル) は本体の音ではない。

## 方針

**ユーザ決定 (2026-10-01)**: メッセージ単位で止めない。命令の種類で鳴らす・鳴らさないを分けると、抜けと状態の
食い違い (演奏中のつもりが止まっている、ノートオフだけ届く、外したときに鳴らない) が生まれる。**音源は普段どおり
全部動かし、出力の最後の段で無音にする** (スピーカのミュートと同じ考え)。Retro と sim も同じ形にする
(graphics-audio も変える、ユーザ選択 1)。

- **P4・ブラウザ版**: core の audio_p4 で、I2S (ブラウザ版は AudioWorklet) に書き出す直前にサンプルを 0 にする。
  加えて P4 はコーデックのミュートも使う (無音を確実にする)。APU の合成・WAV の重ね合わせ・状態は変えない。
- **Retro (WROVER)・sim**: graphics-audio の出力の最後の段 (ESP32 は I2S、Linux は SDL / SHM のリングへの書き出し)
  で同じく 0 にする。core からはミュートの命令を 1 つ送るだけ (新しい命令を足すか、既存の命令に意味を持たせるかは
  M1 で決める。古い WROVER のファームが知らない命令を受けたときに困らないこと、両リポジトリの
  audio_commands.h / fmrb_link_protocol.h をそろえることに注意)。WROVER は接続のたび (起動・再接続) に
  core から今の状態を送り直す。
- **設定として残す**: system_conf の `audio_mute` (既定 false)。起動時に読み、起動音より前に効く。切り替えたら保存する。
- **切り替えの口**: デスクトップのメニューバーの指示器 (クリックで切り替え) とメニューの項目・設定画面、遠隔
  (devctl の `/audio/mute`、sim は debugd)、MCP の fmrb サーバ。アプリ向けの `FmrbApp.set_audio_mute` /
  `audio_muted?` はこれらが使う口として残してよい。
- アプリは鳴らすつもりで普段どおり動き、ミュートを知らない。外部 MIDI 出力は止めない。内蔵 RAM を増やさない。

## 受け入れ条件

- ミュート中は、起動音・アプリの音 (MML、ゲーム、BASIC の PLAY など) が鳴らない。外す と鳴る。
- 再起動してもミュートが残る (起動音も鳴らない)。
- メニューバーと遠隔の両方から切り替えられ、状態が一致する。
- P4 (P4-Nano)・sim・ブラウザ版で確認。Retro はビルドと sim、実機はつないだときに。
