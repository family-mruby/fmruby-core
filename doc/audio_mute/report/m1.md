# M1 実施報告: ミュートと音量

> 状態: 完了 (親の検収待ち、実機は未書き込み) | 更新: 2026-10-01 | ミュートと音量 (0-10) を出力の最後の段で効かせる。設定は system_conf に残り、起動音も従う。メニューバー・メニュー・Config・devctl・debugd・MCP から切り替えられる。sim と ブラウザ版と 4 構成のビルドで確認。NARYAv4 の静的な D/IRAM は develop と同じ 125,524 バイト。**最初の書き込みの前で止まっている**

指示書: ../instruction_m1.md / 計画: ../plan.md

## 1. 結果の要約

- 音源はすべて普段どおり動かし、書き出す直前のサンプルだけを変える (スピーカのミュートとつまみと同じ)。
  P4 とブラウザ版は core の audio_p4、Retro と sim は graphics-audio の最後の段。
- core からは新しい命令 `FMRB_AUDIO_CMD_SET_OUTPUT` (0x0F) を 1 つ送るだけ。中身はミュート・音量の段・
  その段の dB (0.1 dB 単位)。切り替えのたびと、接続 (INIT_DISPLAY) の直後に送る。
- 設定は system_conf の `audio_mute` / `audio_volume` (既定 7) と、設定ファイルだけの
  `audio_level_min` / `audio_level_max` (既定はその出力でできる最大と最小)。
- 静的な内蔵 RAM は増えていない (3 章)。

途中で設計が 2 回変わった。最初は host タスクで命令を種類ごとに捨てる作りで作り、sim で確かめたところで
親から「出力の段で止める」設計に変更の指示があった。そのあと音量が加わり、既定値が 2 回変わった (最終は 7)。
命令を捨てる作り (`fmrb_audio_cmd_allowed`、play / resume の止め、ミュートの瞬間の STOP) はコミットせずに消した。

## 2. 音の経路と止まる場所

すべての音は最後に 1 か所を通る。P4・ブラウザ版では audio_p4 のフレームループの `apuif_audio_write`、
Retro と sim では graphics-audio の `audio_out_write` (新設。`apuif_audio_write` の呼び出し 4 か所をここへ集めた)。

| 経路 | 通り道 | 最後の段を通るか |
|---|---|---|
| アプリの FmrbAudio (play / play_slot / load_fmsq / play_wav / note_on) | アプリ → kernel (msgpack を命令に直す) → host_task → transport → 音源 | 通る |
| note_on / note_off の C 経路 (`fmrb_app_send_audio_note`) | アプリ・MIDI スケジューラ → kernel → host → 音源 | 通る |
| MIDI の内蔵 APU (MmlPlayer / SmfPlayer) | fmrb_midi_sched → `fmrb_app_send_audio_note` → 上と同じ | 通る |
| BASIC の PLAY / BEEP | fmrb_basic.cpp → host に直接 (命令を自分で組む) → 音源 | 通る |
| MicroPython の audio_note | fmrb_bridge.c → `fmrb_app_send_audio_note` | 通る |
| Lua | 音の API が無い | ― |
| デスクトップの起動音 (ジングル) | system_desktop の FmrbAudio#note_on | 通る |
| P4 の起動の「ピコ」 | audio_p4 のタスクが自分で鳴らす (kernel より前) | 通る。設定はタスクが自分で先に読む |
| WROVER / sim の起動の「ピコ」 | graphics-audio の graphics_task が自分で鳴らす (core とつながる前) | 通る。最後の設定を graphics-audio が自分の flash に持つ |
| `fmrb_audio_play` など components/fmrb_audio の C API | transport に直接 | 呼び手が無い (使われていない) |
| 外部 MIDI 出力 (シリアル) | 本体の音ではない | 対象外 (止めない) |

ミュート中・音量 0 のときは最後の段が 0 を書く。再生中のものは止めないので、外すと曲の途中から鳴る
(sim でループ再生中に切り替えて確かめた)。

## 3. 作ったもの

### 3.1 命令と設定 (core)

- `audio_commands.h` (両リポジトリ同じ内容): `FMRB_AUDIO_CMD_SET_OUTPUT = 0x0F` と
  `fmrb_audio_output_cmd_t { cmd_type, muted, volume, level_db_x10 }` (5 バイト、packed)。
  古い WROVER は「Unknown audio command: 0x0f」を 1 行出して続ける (戻り値 -1 は message handler が
  警告を出すだけ)。そのときミュートも音量も効かず、今までどおり鳴る。
- `fmrb_audio` (component): ミュート・音量の段の記録と、段 → dB の計算 (`fmrb_audio_step_db_x10`)。
  記録は構造体の詰め物に置き、範囲 (min / max) は PSRAM。
- kernel: `read_system_config` が設定を読む (`apply_audio_conf`)。`fmrb_kernel_load_audio_conf` は
  audio_p4 のタスクが kernel より先に同じ読み方をするための口。保存は `fmrb_kernel_save_conf_value`
  (system_conf の最上位の 1 行を書き換え、無ければ最初の `[節]` の前に足す。一時ファイルに書いて rename)。
- host_task: `fmrb_host_set_audio_mute` / `fmrb_host_set_audio_volume` (状態を変え、SET_OUTPUT を
  host のキューに積み、変わったときだけ保存)。INIT_DISPLAY の直後に今の設定を送る。
- 段と dB: 1-10 を下限から上限の間に dB で等間隔、0 は無音。既定の範囲と各段の値:

| 出力 | 範囲 | 1 | 4 | 7 (既定) | 8 | 10 |
|---|---|---:|---:|---:|---:|---:|
| NARYAv4 (ES8311 の DAC) | -95.5 〜 +32 dB | -95.5 | -53.0 | **-10.5** | +3.7 | +32.0 |
| Tab5 (ES8388 の DAC) | -96 〜 0 dB | -96.0 | -64.0 | **-32.0** | -21.3 | 0.0 |
| Retro・sim・ブラウザ版 (ソフトの倍率) | -50 〜 0 dB | -50.0 | -33.3 | **-16.7** | -11.1 | 0.0 |

  今までの音量は、P4 がコーデック 70/100 (esp_codec_dev の曲線で -15 dB、ドライバのハード利得の項
  +3.6 dB を足してチップで -11.4 dB)、ソフトは等倍 (0 dB)。既定の 7 では NARYAv4 はほぼ同じ
  (-10.5 dB)、Tab5 は約 21 dB 小さく、Retro・sim・ブラウザ版は約 17 dB 小さくなる。

- ソフトの下限を -50 dB にした理由: sim で測ると APU の 1 声の山は 3072 (約 -20 dBFS)。-50 dB では
  約 10 LSB で、小さいが曲と分かる。-60 dB で試した値は 4 LSB で、probe も「鳴っていない」と数えた
  (量子化の雑音のほうが大きい)。上限は等倍 (1 を超える倍率は割れるだけ)。

### 3.2 出力の段

- audio_p4 (P4・ブラウザ版): フレームループで、無音 (ミュートか音量 0) なら 0 を書く。ブラウザ版は
  Q16 の倍率を掛ける。P4 の実機は倍率を使わずコーデックの音量で絞る:
  - NARYAv4 (ES8311): コーデックドライバの `set_vol` を直接呼ぶ (`esp_codec_dev_set_out_vol` は
    0-100 を -50〜0 dB に写す曲線なので範囲が足りない)。ドライバが引くハード利得の項を足し戻して、
    チップに渡る dB を正確にした。ミュートは `esp_codec_dev_set_out_mute`。
  - Tab5 (ES8388): 表示ドライバの I2C 経由で LDACVOL/RDACVOL (0.5 dB 刻み、0〜0xC0) を書く。
    ミュートは DACControl3 の bit 2 (ドライバが開いたときの値を読んで 0x04 / 0x00 とした)。
  - 実機ではサンプルを 0 にするのに加えてコーデックもミュートする。
- 起動の「ピコ」より前に効くよう、audio_p4 のタスクは最初のフレームの前に system_conf を読む
  (サンプル側だけ。コーデックは host の最初の SET_OUTPUT で表示タスクの文脈から設定)。
- SET_VOLUME (0x06) は誰も送っていなかった。P4 では何もしない命令にし、backend 表の `set_volume`、
  ブラウザ版の `fmrb_wasm_audio_volume` とワークレットの倍率は消した (出力の段の倍率と二重になるため)。
- graphics-audio: `audio_out_write` で無音または倍率。最後の設定を
  `flash/etc/audio_output_{linux,esp32}.txt` に持ち (変わったときだけ書く)、audio タスクの開始時に読む。
  名前を機種で分けたのは、sim が書いたファイルが ESP32 の storage イメージに入って実機がそれで
  起動するのを避けるため (同じ flash/ から作られる)。

### 3.3 切り替えの口

| 口 | 内容 |
|---|---|
| メニューバー | 状態のセルの一番左に スピーカ。鳴る: 波、ミュート: 白地に × (反転)。クリックで切り替え。1 秒ごとに状態を読むので、遠隔の変更も 1 秒以内に出る |
| メニュー | 「消音 / Mute」「消音を解除 / Unmute」(状態で文言が変わる) |
| Config | 「音量 / Volume」0-10。矢印で動かしたその場で効き、保存もされる (つまみと同じ)。表示は今の値 (ファイルに行が無い古い設定でも 0 にならない)。Config の保存は今のミュートの値を書く (開いた後に変わった値を古い値で上書きしない) |
| アプリ向け | `FmrbApp.set_audio_mute(bool)` / `audio_muted?` / `set_audio_volume(n)` / `audio_volume` (mruby と Spinel、sig にも追加) |
| devctl | `GET /audio/mute` `POST /audio/mute?on=0\|1` `GET /audio/volume` `POST /audio/volume?level=0..10`。答えは `{"ok","muted","volume"}`。自前サーバの経路の上限を 12 → 14 |
| debugd (sim 用) | `audio` 命令 (`on` / `volume` は省略可、`{muted, volume}` を返す) |
| MCP (親リポジトリ) | `tab5_audio(action: get\|mute\|unmute\|volume, level?)`、`sim_audio(同)`。selftest に追加 (全項目通過) |
| ブラウザ版のページ | `audio_mute` / `audio_volume` をページの設定の保存に加えた (再読み込みで残る) |

その他: `tools/fmrb_web.rb` は headless のブラウザを `--mute-audio` で起動するようにした。ブラウザが
Windows の Chrome の場合、headless でも出力はユーザのスピーカになるため。

## 4. 確認の結果

### sim (TAB5 の sim、426x240)

`tools/fmrb_audio_probe.rb` で graphics-audio の SHM リングを数値で見た。MML デモ (`/app/demo/mml.app.rb`)。

| 条件 | peak | 鳴った窓 |
|---|---:|---:|
| 音量 10 (0 dB) | 3072 | 38 |
| 音量 7 (-20 dB の版で測定) | 308 (= 3072 x 0.1) | 36 |
| 音量 7 (-16.7 dB、最終版、all-mruby 構成) | 450 | 25 |
| 音量 1 (-60 dB の版) | 4 | 0 |
| 音量 0 | 0 | 0 |
| ミュート (メニューバー) / debugd | 0 | 0 |
| ループ再生中にミュート → 解除 | 5632 → 0 → 5632 | 曲は止まっていない |
| ミュートのまま sim を再起動 (起動のピコ + ジングルの区間、20 秒) | 0 | 0 |
| ミュートなしで再起動 (同じ区間、音量 9) | 5911 | 25 |

- 再起動で残る: core は system_conf、graphics-audio は自分のファイル。graphics-audio のログで
  「output (saved): ... muted」が「Play boot beep」より前に出ることを確かめた。probe は起動のピコより
  前から動いていた。
- 構成: 標準 (Spinel カーネル + Spinel エディタ、デスクトップは mruby)、Spinel デスクトップ
  (`FMRB_APP_ENGINE_DESKTOP=spinel`)、互換 (全部 mruby) の 3 つ。どれもメニューバーと Config で
  切り替えでき、エディタを起動して 1 打鍵できた。
- MCP の `sim_audio` のライブラリを動いている sim に当てて、mute / volume / get が通ることを確かめた
  (サーバの再起動はしていないので、ツールとしての呼び出しは selftest で確認)。

### ブラウザ版

- メニューバーのクリックで system_conf の `audio_mute = true` になり、再読み込みしても残る
  (ページの設定の保存に加えた後)。
- node 版 (`rake wasm:run`) のログで、host の「Audio output: volume 7 (-16.7 dB)」と audio_p4 の
  「output: volume 7, -16.7 dB」を確認。ブラウザ版のサンプルの値そのものは見ていない (リングを
  読む道具が無い)。倍率の計算は graphics-audio と同じ式。

## 5. 見立てと違った点

- 最初に「1 か所で止められる」場所として host タスクを選んだが、命令の種類で分ける作りは採用されな
  かった (1 章)。出力の段に移すには graphics-audio の変更が要った (親が許可)。
- 「起動音」は 3 種類あった。デスクトップのジングルのほかに、P4 の audio_p4 が自分で鳴らす「ピコ」と、
  WROVER / sim の graphics-audio が core とつながる前に鳴らす「ピコ」。後の 2 つは core の設定が届く
  前に鳴るので、それぞれ自分で設定を読むようにした。最初の試作の sim で「ミュートしたのに起動時に
  4 窓鳴った」のはこの graphics-audio のピコだった。
- core は WROVER の再接続を検出していない (起動時にリセットして INIT_DISPLAY で 1 回つなぐだけ)。
  「接続のたびに送る」は INIT_DISPLAY の直後の 1 回になる。WROVER が勝手に再起動した場合は、
  graphics-audio が自分のファイルの設定で動く。
- ブラウザ版の /etc はページの再読み込みで消える。ページの設定の保存に 2 つのキーを足して残した。
- `audio_level_max` の既定を「ハードの最大」とした結果、NARYAv4 は +32 dB (DAC のデジタル増幅)。
  APU の音は -15〜-20 dBFS ほどなので、段 8 (+3.7 dB) あたりから先は大きな音で割れる。段 10 は
  今までより約 43 dB 大きい。

## 6. 残件

- **実機 (P4-Nano / NARYAv4) への最初の書き込み** (ここで止まっている)。ビルドは
  `FMRB_HW_TARGET=NARYAv4` で build/ に置いてある。
  - 通常の flash は storage を書き直し、system_conf は config/ の既定 (ミュートなし・音量 7) になる。
    **最初の起動ではピコとジングルが鳴る** (NARYAv4 の段 7 は -10.5 dB で、今までとほぼ同じ大きさ)。
    app_only でも、今入っている試験ファームの system_conf にはこのキーが無いので同じく鳴る。
  - 最初から鳴らしたくない場合の案: 書き込みの前に `flash_local/etc/system_conf.toml` に
    `audio_mute = true` の入った system_conf を置く (storage は flash/ と flash_local/ の合成なので、
    それが入る)。手元だけの変更で、コミットには入らない。
  - 一度 M1 が入れば、`tab5_audio` (ip 192.168.10.15) でミュートしてから再起動・app_only の flash を
    すれば鳴らない。通常の flash はまた既定に戻る。
- 実機での確認 (親・ユーザ):
  - ミュートにして MML を起動し無音 (シリアルで「audio_p4: output: ... muted」と「level ... dB」)。
  - 耳での確認: ミュートを外すと鳴る、音量の段の聞こえ方、**NARYAv4 の段 8 以上の割れと大きさ**、
    Tab5 の段 7 (-32 dB) が小さすぎないか。上限・下限・既定の見直しはここで決める。
  - コーデックのミュート (ES8311 の `set_out_mute`、ES8388 の DACControl3) が実機で効くか。
- Retro 実機 (S3 + WROVER) は未確認 (つながっていない)。WROVER のファームも焼き直しが要る
  (古い WROVER では効かず、今までどおり鳴る)。
- ブラウザ版でサンプルの値を直接見る確認はしていない。
- MCP の新しいツールはサーバの再起動後に見える。
