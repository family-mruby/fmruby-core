# W3b 指示書: 当たり判定を専用の定義に置き換える・長押しで閉じる

> 状態: 実装中 | 更新: 2026-11-11 | 正は plan.md の「決定 (2026-11-11 ユーザ、W3 の後)」と、タッチの閉じ方の決定

## やること

1. **画素の問い合わせ (W3) をやめる**: カーネルの `_window_see_through?` の画素の問い合わせと、そのための C の口
   (`fmrb_app_window_see_through_at` など) を外す。W3 で直した display_local の `GET_PIXEL` の色の直しは残す
   (アプリの `get_pixel` のための正しい直し)。
2. **アプリが申告する当たりの形**: 枠なしの Window だけが対象。申告が無ければ Window の四角で当たる。
   - 基底 (mruby の fmrb-app.rb と Spinel の基底) に手伝いを 3 つ:
     - 矩形の一覧: `set_hit_shape([[x, y, w, h], ...])` (Window の中の座標)。`clear_hit_shape` で四角に戻す。
     - ビットのマスク: 画素単位の形 (行ごとのビット列など、形は report で決める)。ドット絵の文字列から作る手伝い
       (透ける文字を指定、拡大率も)。
     - スプライトの当たりの印: 印を付けたスプライトの矩形 (できればマスク) が、スプライトの位置に合わせて当たりに入る。
       基底がスプライトの位置を管理しているので、アプリは印を付けるだけ。
   - 形は矩形・マスク・スプライトの和。カーネルに申告し、カーネルは押した点が和に入るかだけを見る (描画側へ往復しない)。
   - 形はアプリの状態として checkpoint で運ばれ、移った先で基底が申告し直す。
   - 内蔵 RAM は増やさない (形は PSRAM か、アプリの VM の中)。
3. **長押しで閉じる (タッチだけの端末のため)**: 枠なしの Window を動かさずに 1 秒押し続けると、`on_frameless_right_click`
   と同じ口が呼ばれ、既定は「閉じますか」の問い (今の右クリックの既定と同じ on_quit_request)。アプリが上書きできる。
   W2 の押下の預かりとの関係 (1 秒の間に 4 px 動いたらドラッグ、動かずに 1 秒ならこの口、すぐ離せばクリック) を整える。
4. **見本のアバター (flash/app/demo/avatar.app.rb)**: 絵の文字列から形を作って申告する (コマが替わったら形も)。
   吹き出しを押したときはなでたことにせず、吹き出しを閉じる (W4 の残件)。
5. 文書: spec.md 3.4、sig、movable_apps.md (形が運ばれること)。

## 確認

`rake regress`、`rake regress:screens`、`rake regress:checkpoint` (BOARD= なし)、`rake regress:size` (内蔵 RAM の増分 0)、
`rake regress:spinel`。ネイティブ版・ブラウザ版・sim の Retro で: 矩形・マスク・スプライトの印のそれぞれで、形の外を押すと
後ろへ、内を押すとアプリへ届く (スプライトの上がすり抜けない)。長押しで問いが出る。`amove` の後も同じ形で当たる。
枠つきのアプリの当たり判定は変わらない。

## 触ってよい範囲

fmruby-core の基底・カーネル・C の口・見本のアバター・文書・sig。graphics-audio は触らない (要るなら止まって返す)。
lib/ を触ったら `rake clean`。コミットまで (develop)。push しない (親がする)。
