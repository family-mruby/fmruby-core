# W1・W2: 枠なしのフラグと、カーネルが持つドラッグ

> 状態: 報告 | 更新: 2026-11-11 | `.app.toml` の `window_frame = "none"` で、枠・タイトルバー・閉じるボタンの無い、地の透けた Window になる (基底が描かず、Window 全体を透ける区画にし、移った後も掛け直す)。`window_drag = "title" | "anywhere" | "none"` (枠なしの既定は anywhere) で、カーネルが押下を 4 px まで預かってドラッグとクリックを見分ける。アプリの `set_window_position` でカーネルの一覧が古くなる不具合と、カーネルのドラッグの後に `pos_x` / `pos_y` が古い不具合も直した。ネイティブ版・ブラウザ版・sim の Retro で確かめ、回帰の道具 (regress・screens・checkpoint・size) は全部通った。内蔵 RAM は増えていない

指示書は `doc/frameless_window/instruction_w1_w2.md`、計画は `plan.md`、見立ては `report/w0.md` の 4 章。

### 1.2 基底 (mruby の `fmrb-app.rb` と Spinel の `fmrb_app_base_spinel.rb`、同じ形)

- `frameless?`。
- `_layout_user_area` (Spinel は initialize と resize の中の同じ分岐): 枠なしなら user area は `(0,0)-(w,h)`。
- initialize: 枠なしなら枠の GfxBlock を作らず (Spinel は `draw_window_frame` を呼ばず)、`@gfx.clear(TRANSPARENT_COLOR)` と区画の掛け。
- `draw_window_frame`: 枠なしなら区画を保つだけで何も描かない。
- `clear_user_area(color = (@_frameless ? TRANSPARENT_COLOR : THEME_WINDOW_BG))`: 枠なしの既定は透ける色。枠は描き直さない。Spinel がこの既定の式 (ivar を読む) を通すことは小さな試験で確かめた (scratchpad の `spt/t.rb`)。
- `_apply_rounded_corner_regions`: 枠なしなら Window 全体 1 つの透ける区画 (大きさで控える今の仕組みのまま。resize・復元でも掛け直る)。`rounded_corners = 0` でも枠なしなら掛ける。
- `_frame_event`: 枠なしなら閉じるボタンと右クリックの読み直しを見ず、右ボタンの離しで `on_frameless_right_click(ev)` を呼ぶ。既定は `on_quit_request` (既定は閉じる。保存を尋ねるアプリはそこで止められる)。右ボタンを使うアプリはこの hook を空で上書きする。クリックは `on_event` にも届く。
- `_checkpoint_restored` (mruby): `_build_frame_block unless @_fullscreen || @_frameless`。後の `clear_user_area` が地を透ける色にし、区画を掛け直すので、`on_restore` で絵を描くだけで透けたまま着く。
- Spinel の `_dispatch_control` に `"moved"`。Spinel の `_set_window_param` は `@pos_x` / `@pos_y` を更新していなかったので、mruby に合わせて更新するようにした。

Spinel の ivar の並び: 足したのは bool の `@_frameless` 1 個。生成 C で `sp_EditorApp`・`sp_SystemDesktopApp` が `sp_FmrbApp` の先頭一致を保つことを全部 Spinel の構成 (`rake regress:spinel`) と標準構成の両方で確かめた (32 フィールド、一致)。エディタの 1 打鍵は `regress:screens` の台本が含む。

### 1.3 カーネル (`input_router.rb`・`window_manager.rb`・`fmrb_kernel.rb`)

- mouse_down: 上 11 行のタイトルバーのドラッグは `!frameless && drag == title` のときだけ。mouse_up の閉じるボタンの判定 (mruby 以外の VM 向け) も枠なしではしない。
- `window_drag = "anywhere"` で左の押下: `@capture_mode = :press` にし、押下をアプリへ送らずに `@press_data` に取っておく。
  - mouse_move: 押した点から 4 px より遠く (距離の 2 乗 > 16) なったら `:grab` にし、以後は今のドラッグと同じ式 (`x - offset`、絶対) で動かす。`:press` と `:grab` の間は move をアプリへ送らない。
  - mouse_up: `:press` のままなら、取っておいた押下と離しを続けてアプリへ送る (クリック)。`:grab` なら何も送らない。
  - 右ボタンなどは預からずにそのまま送る。左を押している間に別のボタンを離したときは、そのまま送って預かりを続ける。
- ドラッグの終わり (タイトルバーのドラッグも anywhere も、実際に動いたとき): `notify_moved` が APP_CONTROL `{"cmd" => "moved", "x", "y"}` をアプリへ送る。基底だけが受ける (hook なし) ので、mruby と Spinel (native) のアプリだけに送る (Lua・BASIC・MicroPython には送らない)。
- `update_window_list`: dirty の印に加えて、C の世代の数が変わっていたら読み直す。mouse_move の転送 (タイトルバーのドラッグ中を除く) と mouse_up の前に呼ぶ。これでアプリが `set_window_position` で自分を動かしても、相対座標の基準がその場で新しくなる。
- 新しい ivar: `@drag_moved` (bool)、`@press_x` / `@press_y` (int)、`@press_data` (String)、`@window_list_gen` (int)。`tool/spinel_poc/harness_input_router.rb` にも足した (CRuby で流れることを確かめた)。

## 3. W0 の見立てと違った所

- **`fmrb_window_info_t` が内蔵 RAM に static で 1 つある** (`main/kernel/host/host_task.c` の `ime_focused_cursor`)。見立ては「ctx に 1 bit」だけだったが、一覧の構造体にフィールドを足すと 50 → 52 バイト × 7 になる。足す 2 つを元の詰め物の位置に置き、50 バイトのままにした。ctx は PSRAM の `g_ctx_pool` なので増えても内蔵は増えない。世代の数も PSRAM に置いた。
- **枠なしは `rounded_corners` と独立に透ける色が要る**。キャンバスの透ける色は `!fullscreen && rounded_corners` で決まっていたので、`rounded_corners = 0` の枠なしは透けなかった。条件に frameless を足した。
- **Spinel の `set_window_position` は `@pos_x` / `@pos_y` を更新していなかった** (mruby の binding だけがしていた)。合わせた。
- **ネイティブ版のウインドウ操作** (タイトルのダブルクリックで最大化) も上 11 行を見ていた (resizable のときだけ)。見立てに無かったので足した。
- `pos_x` / `pos_y` の直し方は、W0 の見立ての「読むときに ctx から取る口」ではなく、カーネルがドラッグの終わりに `"moved"` を送る形にした。アプリは `@pos_x` を直接読むので、読み口を変えても ivar は古いまま残るため。

## 4. 取り下げた見込み・仮決め

- 仮決め: 預かりの距離は 4 px (距離の 2 乗で比べる)。Retro のタッチやマウスの揺れでは測っていない。
- 仮決め: 右クリックの口は「離したとき」に `on_frameless_right_click` → `on_quit_request`。新しいメニューは作らない (plan の決定どおり)。
- 仮決め: 枠つきのアプリにも `window_drag` を書ける (anywhere・none)。枠つきの既定 (title) は今の動きのまま。
- `"moved"` は枠つきのアプリにも、タイトルバーのドラッグで実際に動いたときに 1 回届く (C と Spinel の基底が ivar を直すだけで、hook は呼ばない)。画面の動きは変わらないが、ドラッグの後に `@pos_x` が正しくなる点は変わる。
- mouse_move の相対座標は、何かの Window が動いた (世代が変わった) ときに一覧を読み直してから作る。枠つきのアプリでも、タイトルバーのドラッグの直後から周期の点検までの間の move は、前は古い位置からの相対座標、今は正しい位置からの相対座標になる。タイトルバーのドラッグ中は今までどおり (読み直さない)。

## 5. 残件

- **タッチだけの構成の閉じ方**: 枠なしの Window はキーボードがあれば Ctrl+Q・Shell の kill、マウスがあれば右クリックで閉じられる。タッチだけ (Tab5 を指だけで使う) では右クリックが出せず、閉じる口は遠隔 (tab5_app の kill) しか無い。長押しを閉じる口にする案は、`"anywhere"` の預かりと時間で区別する必要があり、決定の範囲を出るので入れていない。ユーザの判断が要る。
- **押下が届くのは離したとき**: `"anywhere"` のアプリでは押している間の反応 (ボタンの凹み) と長押しが作れない (spec.md 3.4 に書いた)。要るアプリは `"none"`。
- **アプリ自身のドラッグの残り**: 一覧の基準は新しくなったが、カーネルが move を作る時点とアプリがそれを処理する時点の間にアプリが自分を動かしていると、相対座標の基準が 1 手ずれる (遅いアプリで行き過ぎる)。ついてくるドラッグはカーネルに任せる (`"anywhere"`) のが正。
- **ネイティブ版のウインドウ操作 (Super+矢印) で動いた後の `pos_x`**: `"moved"` はカーネルのドラッグの終わりだけが送る。ウインドウ操作 (C) で動いたときは送らない (世代は進むのでカーネルの一覧は正しい)。
- **透けている所のクリックを後ろへ** (W3) は未着手。当たり判定は Window の四角のまま。
- Tab5・S3 の実機では確かめていない (sim の Retro・ネイティブ版・ブラウザ版だけ)。
