# W4: 見本のアバターのアプリ

> 状態: 報告 | 更新: 2026-11-11 | `flash/app/demo/avatar.app.rb` (表示名 Avatar / アバター)。枠なし・movable の小さなキャラクター「Moku」(芽の生えた丸い餅のような子、オリジナル)。絵は 16x16 の文字列 (3 倍で 48x48) をアプリの中に持ち、芽の揺れ・まばたき・クリックの笑顔を、画面と違う行だけ描き直す。状態 (名前・なでられた回数・訪れた端末の一覧) を持ち、`on_restore` で着いた端末のノード ID を足して「2 か所目だよ」と吹き出しで言う。ネイティブ版 2 つの間、ネイティブ版 ⇔ ブラウザ版 (Asterism)、sim の Retro で確かめた。基底・カーネルは変えていない

指示書は `doc/frameless_window/instruction_w4.md`、計画は `plan.md`、前段は `report/w1_w2.md`・`report/w3.md`。

### 1.1 絵

- 16x16 の文字列の配列 (1 文字 1 色: `K` 輪郭・`B` 体・`E` 目・`P` 頬・`M` 口・`G` 芽・`.` 透ける) を 3 倍で描く。上 3 行 (芽) は 2 通り (右へ傾く・左へ傾く)、7〜10 行 (顔) は 3 通り (ふつう・まばたき・笑顔)、ほかの行は 1 通り。行ごとに組み合わせて 1 枚にする。
- 外部のファイルを読まないので、doc/app_assets や BMP の無い端末へ移っても同じ姿になる。
- 色は RGB332 の固定値 (作品としての色。透ける色の 0x01 は使わない)。吹き出しは白地に輪郭の色、字は黒。

### 1.2 描画の費用

描くのは画面に出ている行と違う行だけ (`@shown` に今出ている 16 行の文字列を控え、組み直した行と比べる)。1 行は「その帯を透ける色で塗る + 同じ色の続きごとに `fill_rect` 1 個」。

| 変化 | 描き直す行 | `fill_rect` の数 |
|---|---|---|
| 全部 (起動・`on_restore`) | 16 | 63 |
| 芽の揺れ (0.9 秒ごと) | 2 | 4 |
| まばたき (閉じる・開ける、各 160 ms) | 2 | 12 |
| 笑顔になる・戻る | 4 | 36 |
| 吹き出しを出す | 上の 38 行の帯 | 消す 1 + 角丸 2・三角 1・線 2・字 1〜2 行 |
| 吹き出しを消す | 上の 38 行の帯 | 1 |

`present` は何か描いたときだけ。`on_update` は次に絵が変わる時刻 (揺れ・まばたきの始まりと終わり・笑顔の終わり・吹き出しの終わりの一番近いもの) までの ms を返す (最短 20 ms)。時刻は `Machine.board_millis` で数えるので、移った後も続きから数える (movable_apps.md の D9)。まばたきの間隔は 5 つの値を順に使う (乱数は使っていない)。

### 1.3 ふるまい

- 起動: 吹き出しで「こんにちは / Moku だよ」(en: Hello, / I'm Moku)。3 秒で消える。
- クリック (W2 の預かりで、押して離した。`mouse_up` の左だけを見る): なでられた回数を 1 つ足し、1.5 秒笑顔 (目が ^ ^、頬、赤い口) と吹き出し「えへへ / なでなで N 回目」(en: Hehe! / Pats: N)。5 回ごとに「N か所めぐったよ / w4-a>w4-b」(en: Been to N: ...) で訪れた端末の一覧を出す。
- ドラッグ: カーネルが動かす (既定の `window_drag = "anywhere"`)。アプリは何もしない。
- 透けている所の押下は後ろへ抜ける (W3)。吹き出しを出している間は吹き出しも当たりになる。
- 右クリック: W2 の既定のまま閉じる (`on_frameless_right_click` を上書きしていない)。
- 移る: `on_checkpoint` はログだけ。`on_restore` で今の端末の名前を一覧に足し、全部の行を描き直し、「N か所目だよ / <端末の名前>」(en: Stop N: / <name>)。
- 言葉は描くたびに `FmrbApp.language` を読む (着いた側の言語になる)。en から ja の端末へ移したら、着いた側で日本語の吹き出しになった。

### 1.4 端末の名前

`place_here` が、FmrbAsterism が選ぶのと同じ順で**読むだけで**求める: `/home/asterism/config.toml` の `node`、無ければ mDNS の名前 (`FmrbAsterism.hostname`)、無ければ system_conf の `asterism_node` (ブラウザ版の wasm-XXXXXX)、無ければ `FmrbConst::BOARD` (sim は `linux`)。`FmrbAsterism.settings` を呼ばないのは、そちらが古い設定のファイルを config.toml へ移す (書く) ことがあり、見本のアプリが起動のたびにファイルを書き換えるのは避けたいため。ファイルは開いて読んで閉じるだけなので、チェックポイントで断られる理由 (開いたままのファイル) にはならない。FmrbAsterism の無いビルドに備えて `Object.const_defined?` と `rescue` で包んだ。

## 3. 回帰の道具への影響と、場面に足すかの見立て

### 3.1 アプリが増えたことによる変化

- **web の launcher**: ブラウザ版のランチャーに「Avatar」の札が App Store の次に入り、後ろの札が 1 つずつずれた (3,827 px)。意図した変化。**基準の更新 (`rake regress:screens:update ONLY=web SCENE=launcher`) は親に任せる**。diff は `ONLY=web SCENE=launcher` で流すと `tmp/regress/screens/diff/web/launcher.png` に出る (今は後の Retro・Modern の実行で消えている)。
- **web の kamon**: 場面はランチャーで右へ 11 回送って Kamon を開いていたので、札が 1 つずれて別のアプリが開いた。送る回数を 12 にした (`test/regress/screens/30_apps.rb`、別のコミット)。直した後は通る。
- sim の Retro・Modern の launcher は変わらなかった (どちらも 1/1)。

### 3.2 回帰の場面に足すか (見立て)

足さないでよいと見る。

- 画面の場面 (`regress:screens`) に足すと、芽の揺れ (0.9 秒) とまばたき (間隔 0.9〜5.2 秒) が時刻で絵を変えるので、撮る瞬間によって画素が変わる。揺れの無い瞬間を待つ仕掛けを足すか、アプリに試験用の止める口を作ることになり、見本のアプリとしては余計。
- 移る・透ける・掴む・クリックの仕組みは、既にある場面が受け持っている: `regress:checkpoint` (ckpt_window の Window ごとの移動、Asterism、ブラウザ版との往復)、W1〜W3 で足した枠なしの扱いは基底とカーネルの側の試験。アバターが足すのは「見本が壊れていないか」だけ。
- 足すなら、`regress:checkpoint` のネイティブ版の場面に 1 つ (avatar を起動 → 1 回クリック → 移す → 着いた側のログの `avatar: arrived at <node> (...), pats=1` を読む) が安い。画素を比べずに状態が続いたことを確かめられる。別のコミットで足せる。


## 4. 仮決め・見送ったもの

- 名前は「Moku」で固定 (ivar に持ち、運ばれる)。名前を変える口は作っていない。
- まばたきの間隔は決まった 5 つの値を順に使う。乱数 (`rand`) は使っていない (端末ごとに乱数の gem の有無を気にしなくてよい)。
- 訪れた端末の一覧は、同じ端末に戻っても足す (w4-a > w4-b > w4-a)。「N か所目」は着いた回数 + 1 (起動した所を含む)。
- 吹き出しの字は efont 12 (無い端末では misaki 8 になり、行の高さも `FONT_METRICS` から取る)。幅が 110 px を超える行は `fit_text` で `..` に詰める (経路が長いとき)。
- 当たり判定は W3 のまま (描いた所が当たり)。吹き出しが出ている間は吹き出しも当たりになり、そこを押してもなでたことになる。
- タッチだけの端末 (Tab5 を指だけ) では閉じられない (W1/W2 の残件のまま)。
