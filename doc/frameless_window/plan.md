# 枠なしの GUI アプリ (アバターのような形のある Window)

> 状態: 進行中 | 更新: 2026-11-10 | W0 済、次は W1 (ユーザ: 指示なしで行けるところまで。未確定事項は親の仮決めで進め、後でユーザが見直す)。 枠とタイトルバーを持たず、透ける地の上に絵だけを見せるアプリを、FmrbApp の決まった口で書けるようにする。カーネルの「上の 11 行はタイトルバー」の扱いを toml のフラグで変え、どこを掴んでも動かせるドラッグをカーネルが受け持つ。着手はユーザの指示で

## 目的

- アバター・マスコットのような、四角い Window に見えないアプリを作れるようにする。
- doc/checkpoint の `amove` と doc/app_assets と合わせ、「自分の絵を持って端末の間を渡り歩くアプリ」のデモにする。

## 今の作りで分かっていること (2026-11-10、コードを読み、W0 で動かして確かめた。report/w0.md)

- 枠は FmrbApp の基底が描く (`draw_window_frame`。`clear_user_area` の中でも描き直す)。アプリが
  `@gfx.clear(TRANSPARENT_COLOR)` で地を塗り、`@gfx.set_composite_regions` で Window 全体を `transparent: true`
  にすれば、透ける地の上に絵だけを見せられる見込み (角の丸みと同じ合成の仕組み)。
- 閉じるボタンは見えなくても当たり判定が残る。`self.closable = false` で消せる。
- カーネル (input_router) は、全画面でない Window の上 11 行を押すとドラッグを始め、右クリックは読み直し。
  枠の無いアプリでは、絵の頭の辺りが勝手に取っ手になる。
- クリックの当たり判定は Window の四角。透けている所を押しても後ろの Window には届かない。
- アプリは `set_window_position(x, y)` で自分を動かせ、カーネルの Window の一覧にも載る。動かすたびに出ていた INFO の
  ログ 2 行は DEBUG に下げ済み (16825033)。アプリが自分でドラッグを作っても、move は焦点のある Window に送られ続ける
  ので、カーソルが外へ出ても途切れない (W0)。ただし、外へ出た負の座標は 16 bit の符号なし (65446 など) で届き、
  相対座標の基準 (カーネルの一覧の位置) はアプリの `set_window_position` では更新されず、押下後に 1 回だけ黙って
  読み直される。このため、ついてくるドラッグはアプリ側では正しく書けない (絵が戻る・止まる。report/w0.md 2.3)。
- checkpoint で移った後は基底が角の丸みの区画を掛け直すので、`on_restore` で全体の透けを掛け直す必要がある。

## 方針

1. **toml のフラグで枠なしにする**: 例 `window_frame = "none"`。基底は枠・タイトルバー・閉じるボタンを描かず、
   地を透ける色にし、Window 全体を透ける区画にする (移った後も基底が掛け直す)。アプリは描くだけでよい。
2. **上 11 行の扱いをフラグで変える**: 枠なしの Window では、カーネルは上 11 行をタイトルバーとして扱わない
   (ドラッグ・読み直し・閉じるボタンの当たり判定をしない)。
3. **どこを掴んでも動かせるドラッグはカーネルが受け持つ**: 例 `window_drag = "anywhere"` (と `"none"`、
   アプリが決めた区画だけの形)。カーネルが掴んで捕まえるので、カーソルが外へ出ても途切れず、アプリはドラッグを
   書かなくてよい。クリックとドラッグの見分け (動いた距離) もカーネルで。
4. **透けている所のクリックは後ろへ** (できれば): 当たり判定で、押した点が透ける色なら次の Window へ回す。
   費用 (画素を読む) と Retro での可否を調べて決める。
5. 閉じ方: 枠が無いので、右クリックのメニューやキーで閉じる口を基底に用意する。

## 決定 (2026-11-10。親の仮決めをユーザが同意)

ユーザの判断を待たずに進めるため、未確定事項を次のように仮に決める。どれも後から変えやすい形にし、report に
「仮決め」と書く。

- フラグの名前: `window_frame = "none"` (既定 `"normal"`)、`window_drag = "title" | "anywhere" | "none"`
  (既定は枠つきなら `"title"`、枠なしなら `"anywhere"`)。
- 枠なしのアプリの閉じ方: 既にある口だけで閉じられるようにする (Ctrl+Q の終了の頼み、Shell の kill、
  ランチャーの右クリックなど、今あるもの)。新しいメニューは作らない。どれも効かない形が見つかったら、
  基底の右クリックで閉じる口を 1 つ足す (アプリが右クリックを使うなら上書きできる)。
- 透けている所のクリックを後ろへ回す (W3): W0・W2 で費用を測り、Modern で安くできるなら入れる。高ければ
  見送って report に書く。
- Retro (S3) も対象にする。W0 で Window 全体を透けさせる合成が遅すぎると分かったら、Retro では透けを
  四角の枠なしに落とす (絵は出る、地が透けない) 形を検討して止まって返す。
- 見本のアプリ (W4) は `flash/app/demo/` に置き、`movable = true`。絵は Ruby の文字列としてアプリの中に持つ
  (doc/app_assets が無くても移った先で同じ姿になる)。

## 決定 (2026-11-11 ユーザ、W3 の後: 当たり判定は専用の定義)

- **当たり判定は、画素の問い合わせ (W3) をやめ、アプリが申告する専用の定義に置き換える**。スプライトをすり抜ける・
  描きかけを読む・押すたびに描画側へ往復する (約 10 ms) を解消し、見た目と当たりを分けられるようにする。
- 申告の無い枠なしのアプリは Window の四角で当たる (W3 の前と同じ)。
- 基底に用意する手伝いは 3 つ: **矩形の一覧** (`set_hit_shape([[x, y, w, h], ...])` のような形)、**ビットのマスク**
  (画素単位の形。ドット絵の文字列から作る手伝いも)、**スプライトの当たりの印** (印を付けたスプライトの矩形かマスクが、
  動きに合わせて自動で当たりに入る)。
- 形はアプリの状態として `amove` で運ばれ、移った先で基底がカーネルへ申告し直す。
- 段は W3b として W4 の後に行い、W4 の見本のアバターに形の申告を足す。
- **(2026-11-11 ユーザ) タッチだけの端末の閉じ方**: 動かさずに 1 秒押し続けると「閉じますか」の問いを出す (右クリックと
  同じ口 `on_frameless_right_click` の既定。アプリが上書きできる)。W3b で入れる。

## 受け入れ条件

- toml のフラグだけで、枠・タイトルバー・閉じるボタンの無い、地の透けたアプリが書ける。`amove` の後も透けたまま。
- 枠なしの Window の上 11 行を押しても、カーネルのタイトルバーの動き (ドラッグ・読み直し・閉じる) が起きない。
- `window_drag = "anywhere"` のアプリは、どこを掴んでも動かせ、速く動かしても途切れない。押しただけ (動かさない)
  ならアプリにクリックとして届く。
- 今の枠つきのアプリの動きは変わらない (回帰の道具の画面の基準が変わらない)。
- 内蔵 RAM の増分 0。
