## 2. メタデータの鍵 (両形式と優先)

書き方は 2 つ。鍵の名前・型・意味はどちらも同じで、読み手は `fmrb_app_meta.c` の 1 つ。

| 形 | 置き場 | 読まれる条件 |
|---|---|---|
| `.app.toml` | 本体の最後の拡張子を `.toml` にしたもの (`foo.app.rb` → `foo.app.toml`) | どの言語のアプリでも |
| `#---fmrb` 囲み | `.rb` の先頭。`#---fmrb` の行から `#---` の行まで、各行の `# ` を外して toml | `.rb` だけ。先頭 512 バイトの中で、最初のコードの行より前。閉じていない・toml として読めないときは WARN を出して囲みを使わない (アプリであることには変わらない) |

**優先: 鍵ごとに合わせ、両方にある鍵は `.app.toml` が勝つ。** 片方にしか無い鍵はそちらの値。

| 鍵 | 読む所 | 囲みで | 備考 |
|---|---|---|---|
| `app_screen_name` / `app_screen_name_<言語>` | spawner (名前)・ランチャー・desktop・keys desktop | 書ける (**今回から**。前は WARN を出して無視) | 言語別は鍵ごとに合わせたあとで `_<言語>` → 無印 → ファイル名 |
| `icon` | ランチャー・アイコン | 書ける (今回から) | |
| `launcher_visible` | ランチャー | 書ける (今回から) | `false` か `0` で出さない |
| `default_window_mode`・`default_window_{width,height,pos_x,pos_y}`・`min_window_{width,height}`・`resizable`・`rounded_corners`・`window_frame`・`window_drag`・`fullscreen_switchable`・`fullscreen_hires`・`large_memory`・`single_instance`・`exclusive_group`・`movable`・`task_stack_kb` | spawner (`default_window_mode` は desktop の起動アプリも) | 書ける (前から。ただし前は `.app.toml` があると囲みを丸ごと無視) | 型の読み方は前と同じ (`fullscreen_hires`・`single_instance`・`movable` は `true` か `1`) |
| `requires` | checkpoint | 書ける (今回から) | 画像の `.toml` も同じ読み手 |
| `screens`・`needs_pointer` | keys desktop | 書ける (今回から) | `screens` は配列。`app_meta` では空白でつないだ文字列 |
| `app_id`・`app_version` ほか配布の鍵 | App Store (`appstore.app.rb` が自分で読む) | — | 導入の記録。配布には `.app.toml` が要る (spec 3.3) |

## 3. 確かめた結果

- ビルド: `rake clean` → `rake build:linux` (標準構成: Spinel のカーネルとエディタ、mruby のデスクトップ)。`build/fmruby-core.elf` は x86-64。新しい警告なし。
- `rake regress`: host 26 suites 全部通過、描画 229 runs 全部通過。
- `rake regress:spinel`: 6 programs 全部生成 (Spinel のデスクトップの `launcher.rb` と `FmrbApp.app_meta` の包みを含む)。
- `rake regress:screens`: 1 回目は 31 通過 / 2 落ち (Retro と Modern の `launcher`)。差は一覧に Avatar が出たことだけ。原因はコードではなく、sim が共有する `flash/var/cache/launcher_index` (git の外) を私が sim で Reload して作り直したこと: 基準 (10/26) は Avatar (11/11 に足された) が入る前のキャッシュで撮られていた。キャッシュを前の中身 (Avatar の無い 33 本) に戻して `ONLY=retro SCENE=launcher` を流し直して通過。web・native・native-keys は 1 回目から全部通過。
- `rake regress:checkpoint`: standard・mruby・web とも ok (requires の運び・断りを含む、6.6 分)。
- `rake regress:size`: ok。内蔵 RAM の静的な増分なし (NARYAv3 DIRAM 125,403 -56・IRAM +0、TAB5 DIRAM 129,338 -360。比べた基準は 4e7e7e61 で、差には T1 より前のコミットの分も入る)。Spinel の箱 (`fmrb_spx_app_meta` の 2 KB) は PSRAM。
- sim (Retro 320x240、標準構成) で手で見たもの:
  - 試験の 8 本を一時的に `/app/usr/` に写し (`/app/test` は launcher_exclude で出ない)、ランチャーの Reload で作り直した。一覧は 36 → 44 (囲みだけ 7 本+ meta_merge、それと古かったキャッシュに無かった Avatar)。囲みだけの 7 本は名前の無いものはファイル名 (`fence_bg.app` など) と Ruby の絵で出た。`fence_win` は `.app.toml` の `launcher_visible = false` で出ない (前と同じ)。ほかの 34 本の名前と絵は、作り直したキャッシュを前の読み方 (行ごとの `key = value`) で `.app.toml` から出したものと突き合わせて全部一致 (en)。
  - `meta_merge` はランチャーで「MetaMerge」(`.app.toml`) とオセロの絵 (囲みだけの `icon`) で出て、ダブルクリックで起動し `window=200x120 at 60,30` (大きさは囲み、位置は `.app.toml` が勝った)。
  - パスで起動: `fence_win` は 180x90 の Window (`.app.toml` の window が囲みの fullscreen に勝つ)、`fence_bg`・`tmp_smoke` は headless でスタック 32 KB、`fence_fs`・`ja_width` は全画面、`fence_bad` は閉じていない囲みの WARN を出して既定の Window、`fence_bad2` は既定の Window。
  - Shell: `run /app/test/fence_bg.app.rb` は spawn、`run /app/test/require_test.rb` (囲みも `.app.toml` も無い) は sandbox で走った。
  - `timer_test`: TIMER1 +500ms、TIMER2 +1500ms、`clear_timer` した TIMER3 は来ない。
  - エディタを起動して 1 打鍵 (`x`) まで。
  - 終わったあと `/app/usr/` の写しを消し、sim のランチャーのキャッシュ (`flash/var/cache/launcher_index`、git の外) から `/app/usr/` の行を消した。

## 4. 見立てと違った点

- `super(ev)` の実コードは T0 の 3 か所のほかに `tool/midi/test/sim_play/` の 2 本にもあった (T0 は `tool/` を数えていなかった)。同じ契約なので消した。
- skill は root のリポジトリではなく、`.claude/` が独立した git リポジトリで、root からは無視されている。そこの `fmrb-app-new/SKILL.md` には別の未コミットの直し (枠なしの Window・HitAreas・single_instance など) が既にあったので、HEAD に自分の直しだけを当てたものを index に載せてコミットした。作業ツリーには両方が残っている。
- ランチャーが囲みだけのアプリを拾うために `.rb` を開くのは、`.app.toml` の無い `*.app.rb` だけにした。アプリの横の補助の `.rb` (例 `require_test.rb`) は開かない。ブートはキャッシュを使うので、読みが増えるのは作り直しのときだけ。
- spawner は前は `.app.toml` があれば `.rb` を開かなかったが、今は合わせるために毎回先頭 512 バイトを読む (起動ごとに 1 回の短い読み)。
- 囲みが壊れているアプリ (`fence_bad`) も「アプリ」として扱う (ランチャーに出る、Shell は spawn)。前の Shell も囲みの開きの行だけで判断していたので同じ。

## 5. 基準の更新が要る変化

- コードの変化で基準を変える必要があるものは無い。
- ただし `regress:screens` の `launcher` (Retro・Modern) の基準は、手元のランチャーのキャッシュが古い (Avatar が無い) ことに乗っている。キャッシュが作り直されると (Reload・右クリック・キャッシュの無い checkout) Avatar が出て落ちる。道具が場面の前にキャッシュを決まった中身にするか、Avatar 入りで基準を撮り直すかは親の判断。

## 6. T3 以降への注意

- T3 (自動起動): 囲みの鍵に `class =` を足すなら `fmrb_app_meta_table` で引けば両形式で効く。テンプレート 3 本と試験アプリは末尾の起動コードを持ったまま。
- `tools/regress/run.rb` (描画の記録) は spawner の Window を `.app.toml` だけから作っている (MiniToml)。今の場面のアプリはどれも `.app.toml` を持つので差は出ないが、囲みで Window を決めるアプリを場面に足すときは合わせる必要がある。
- `appstore.app.rb` は導入の記録 (`app_id`・`app_version`) を自分で `.app.toml` から読んでいる。配布の記録なので今回は寄せていない。寄せるなら `FmrbApp.app_meta` で足りる。
- `doc/multivm_app/plan.md` 3.2 の「ランチャーの鍵は sidecar だけ (ブートの走査で全部の .rb を開かないため)」は今回の決定で変わった。経緯の文書なので直していない。
