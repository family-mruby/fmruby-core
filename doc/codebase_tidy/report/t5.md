# T5 FmrbApp のクラスメソッドの分割 (FmrbSystem)

> 状態: 済 (VM プールの 1 点が未説明、6 章) | 更新: 2026-11-14 | 端末の設定とサービスを変える 34 本を `FmrbSystem` へ移し、mruby と Spinel のずれを揃え、sig の欠けを埋めた。古い呼び出しは `rake system:check` (`rake test` の中) が止める。コミットは core d5ad62df、skill 8143bca (`.claude`)

## 1. 移した名前 (34 本)

`FmrbApp.<名前>` から `FmrbSystem.<名前>` へ。古い名前は残していない。

| 分野 | メソッド |
|---|---|
| 時計・電源 | set_wallclock、reboot、power_actions、power |
| PC のアプリ | linux_apps、linux_launch、linux_handlers、linux_open |
| Wi-Fi | wifi_networks、wifi_connect、wifi_disconnect、wifi_forget |
| Bluetooth (PC) | bt_devices、bt_power、bt_connect |
| PC の知らせ | notices_gen、notices、notice_dismiss |
| ネイティブ版だけ (`#if defined(FMRB_PLATFORM_NATIVE)`) | wl_window、wl_close、wl_key、linux_keyboard、linux_settings、settings_page、crt_set |
| BLE | ble_start、ble_state、ble_settings_window、ble_settings_left |
| 音の設定 | set_audio_mute、set_audio_volume、preview_audio_volume、audio_conf_saved |
| 遠隔の画面 | rd_stream_state |

`FmrbApp` に残したもの: 状態を読むもの (wifi_info・wifi_connected?・battery_level・battery_charging?・audio_volume・audio_muted?・crt_state・sys_pool_info・usb_devices)、プロセス (ps・ps_gen・pid・checkpoint・move)、IME (set_kana_mode・set_text_cursor)、端末の linux_* 8 本、hid_raw_*、config、一般用 (language・clipboard・wallclock・notify ほか)。

- mruby: `lib/gems/picoruby-fmrb-app/ports/esp32/app.c` で `mrb_define_module(mrb, "FmrbSystem")` に `mrb_define_class_method` で登録 (モジュールの特異メソッドだけ。`module_function` にしないので表は増えない)。C の関数名 (`mrb_fmrb_app_s_*`) はそのまま。
- Spinel: `main/ruby/spinel/fmrb_app_base_spinel.rb` に `module FmrbSystem` を作り、あった 24 本を移した。`POWER_ACTION_NAMES` も移した。
- MicroPython: `FmrbApp` にクラスメソッドが無い (Log だけ) ので移すものは無い。
- 呼び出し元: カーネル・デスクトップ (`system_desktop*`)・組み込みアプリ (wifi)・`linux_window`・ネイティブ版の設定アプリ・サービス (timesync)・試験アプリ (ckpt_calls・ckpt_requires)・回帰の stand-in (`tools/regress/stand_ins.rb` に `module FmrbSystem`)。コメントの `FmrbApp.<名前>` も直した (C・Ruby で 160 か所)。
- 生きている文書 (doc/reference/audio_output.md、doc/checkpoint/movable_apps.md、doc/regression/usage.md、doc/linux_native/plan.md、doc/wifi_settings/plan.md) の 7 か所も直した。過去の report・instruction は当時の名前のまま。

## 2. mruby と Spinel のずれ

Spinel に足したもの (FFI の受け皿を `main/app/fmrb_spx_app.c` に、本体は mruby の binding と同じ呼び出し):

| 置き場 | 足したもの |
|---|---|
| FmrbApp | pid、script_path、uptime_us、checkpoint(pid, restart:)、free_bytes、notify、linux_available?・linux_start・linux_read・linux_write・linux_signal・linux_exit_code・linux_resize・linux_close、move の `hold:` |
| FmrbSystem | wifi_connect、wifi_disconnect、wifi_forget (今まで常に false の仮置き)、bt_power、bt_connect |

- 戻りの領域 (linux_read の 4 KB、linux_start のコマンド 1 KB、free_bytes の 8 B、理由の 160 B) は `FMRB_SPX_BSS_ATTR` (実機では PSRAM) に置いた。内蔵 RAM の静的な増分は無い (int 1 つ、`s_linux_read_ended` の 4 B だけ BSS)。
- free_bytes は 4 GB を超えうるので 8 バイトの :binstr (下位・上位の u32) で渡す。linux_exit_code の「動いている」は `FMRB_SPX_APP_LINUX_RUNNING` (-1000000)。
- mruby に足したもの: `FmrbApp.gc` (`GC.start`)。
- 揃えなかったもの (理由つき):
  - ネイティブ版だけの 6 本 (wl_window・wl_close・wl_key・linux_keyboard・settings_page・crt_set): mruby でもネイティブ版のビルドにしか無い。ネイティブ版のデスクトップは mruby で、Spinel の desktop が `respond_to?(:linux_keyboard)` で「無い」と見て keyboard_layout の auto を出さない作りなので、Spinel に置くと端末で auto が出てしまう。checkpoint の試験 (ckpt_calls・ckpt_requires) も「sim には linux_settings が無い」ことを前提にしている。`rake system:check` はこの 7 本 (linux_settings を含む) を Spinel との突き合わせから外す。linux_settings は以前から Spinel に仮置き (false) があり、network_dialog がそれを呼ぶのでそのまま。
  - `_set_hit_shape` (内部): Spinel は枠なしの当たり判定をインスタンスの側で持つ (別の作り)。

## 3. sig

- `sig/fmrb_system.rbs` を新しく作った (34 本。fmrb_app.rbs から移した 11 本と、無かった 23 本)。ネイティブ版だけのものは要約か本文に「ネイティブ版だけ」と書いた。
- `sig/fmrb_app.rbs` に無かった 14 本を足した (pid・script_path・gc・battery_level・battery_charging?・crt_state・linux_* 8 本)。t0 の数えた 37 本 = 23 + 14。
- 要約は 112 バイト以内 (新しく書いた行は全部)。既にあった `set_text_cursor` の要約が 113 バイトで 1 バイト超えている (今回は触っていない、残件)。
- help は `tools/ti/gen_help.rb` が module も拾うので `flash/help/FmrbSystem/` ができる。sig を直したので、次のビルドの前に `rake clean` (済)。

## 4. 古い呼び出しの検査 (`rake system:check`)

`rakelib/fmrb_system.rake`、`rake test` の依存に入れた (よって `rake regress` でも走る)。

- 名前の正は C の登録 (`mrb_define_class_method(mrb, sys_module, "...")`)。あとで移す名前が増えても検査は直さなくてよい。
- `git ls-files` の flash・main・lib・tools・native・test・sig の .rb・.c・.h・.rbs・.py・.toml・.cmake・.txt に `FmrbApp.<名前>` と `FmrbApp.respond_to?(:<名前>)` が 1 つでもあれば落ちる (コメントも数える)。
- Spinel の `module FmrbSystem` の名前と `sig/fmrb_system.rbs` の名前が C と同じかも見る (ネイティブ版だけのものは Spinel の側で除く)。
- 最初に流したとき sig の例文 8 か所を見つけた (直した)。今: `system:check: 34 FmrbSystem methods, no FmrbApp.<name> calls left`。
