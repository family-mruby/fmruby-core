# T3 アプリの自動起動

> 親: plan.md の T3、指示: instruction_t3.md | 2026-11-14 | fmruby-core develop、skill (`.claude` リポジトリ)。

## 1. 入れた場所

| 場所 | 中身 |
|---|---|
| mruby の Ruby (`lib/add/picoruby-fmrb-app/mrblib/fmrb-app.rb`) | `FmrbApp.inherited` が子を `FmrbApp` のクラスの ivar `@_app_classes` に覚える (孫も基底の `inherited` を継いで覚えられる)。`_autostart_task(name)` は `Task.new(name:) { FmrbApp._autostart }` を返す。`_autostart` は `_app_class_to_start` の結果が文字列 (起動できない理由) ならそれを返し、クラスなら `new.start` して nil。選び方: 覚えた子から「ほかの子の親になっているもの」を除き、残りが 1 つならそれ (メタデータは読まない)。0 か 2 つ以上なら `FmrbApp.app_meta(script_path)["class"]` を見て、覚えた子 (親も含む) から名前の一致を探す |
| C (`main/app/fmrb_app.c`) | `execute_mruby_script` の `mrb_task_run` の後、`report_mruby_result` (bool を返すように) で例外が無ければ `autostart_mruby_app`。旗が立っている・`expected_stop`・`FmrbApp` が無い、のどれかなら何もしない。`FmrbApp._autostart_task` を `mrb_funcall` で呼び、その Task を checkpoint の host task に付け替えてから `mrb_task_run`。終わったら例外は `report_mruby_result` (ダイアログ+ログ)、Task の値が文字列なら `set_last_error` + `notify_error_to_kernel` (今の異常終了と同じ口、ログは `Not started: ...`) |
| C の旗 | `fmrb_app_task_context_t.app_instance_made` (`components/fmrb_common/include/fmrb_app.h`、ctx は `g_ctx_pool` = PSRAM)。`FmrbApp#_init` (`ports/esp32/app.c`) で立て、`reset_ctx_run_state` で下ろす。headless のアプリも `_init` を通る。`started_notified` の隣の bool なので構造体の詰め物に入る |
| checkpoint | 復元 (`execute_mruby_checkpoint`) は自動起動を通らない。自動起動の Task が host task になるので、イメージの中で走っているのはその Task で、復元後の結果の報告も同じ口 |
| Spinel (`tool/spinel/gen_app_combined.rb`) | 生成のときに mixin と本体から `^class X < FmrbApp` を拾い、1 つならそれ、`.app.toml` の `class =` (無ければ本体の先頭 512 バイトの `# class = "..."`) があればそれ。名前が子に無い・子が無い・2 つ以上で名指し無しなら生成を止める。結合の末尾に `begin / app = X.new / app.start / rescue => e / Log.error(...) / end` を足す。本体に `X.new` が段下げ 2 以下で残っていれば足さずに WARN (二重起動の防ぎ)。今これを通るのは editor と system_desktop |
| 描画の記録 (`tools/regress/run.rb`) | `load_app` が末尾の起動コードの無いファイルを読めるように。クラスは場面の `klass`、残っていれば末尾、どちらも無ければ `app_class_in` (ランタイムと同じ選び方: `class =`、無ければ親になっていない子が 1 つ) |

起動の失敗の見せ方 (sim で見た文言):

| 場合 | エラーの Window の文 |
|---|---|
| 子が無い | `No app class in /app/test/autostart_none.app.rb.` / `Define one: class MyApp < FmrbApp` |
| 子が 2 つ以上で `class =` 無し | `2 app classes in /app/test/autostart_two.app.rb: LeftApp, RightApp.` / `Name the one to start: class = "LeftApp" in its .app.toml.` |
| `class =` の名前が無い | `class = "MissingApp" is not an app class in /app/test/autostart_bad_name.app.rb.` / `App classes: UpApp, DownApp.` |
| `new`・`on_create`・実行中の例外 | 今までの捕まえられなかった例外と同じ (例外の文とバックトレース) |

## 2. 消した末尾の起動コード

127 ファイル。flash/app 106 (t0 の 107 のうち `debug/compile_err` はクラスが無いので元から無い)、`flash/usr/share/transfer/transfer.app.rb` 1 (t0 の数に入っていなかった)、組み込み 11 (`default_app` 8・`kernel` 3)、`native/apps/linux_settings.app.rb` 1、`test/native/net/net_l2n.app.rb` 1、`tool/midi/test/sim_play/` 3、テンプレート 3 (`flash/lib/templates/`) と Shell の `new` の雛形 `flash/usr/share/template/app.rb.template` (`{{class}}.new.start`)。

形ごと (雛形を除く 126 本。消す前に、末尾が下の文だけでできていることを道具で確かめてから消した):

| 形 | 本数 |
|---|---|
| `begin; app = X.new; app.start; rescue => e; Log.error(...); end` | 39 |
| 同じで rescue が `puts` | 20 |
| `begin; X.new.start; rescue; Log.error` (`ruby_profile` の変数名違いを含む) | 17 |
| rescue に backtrace を足したもの | 14 |
| 前後に `Log.info`、rescue に 2〜4 行の `Log.error` (`rescue Exception` 3 本を含む、12 種の変形) | 30 |
| `app = X.new; app.start` (rescue なし) | 6 |

**rescue の中でログ以外のことをしているものは 0 本**。後始末・再試行・画面への表示をしているものは無かった。

消して変わること (仕様の範囲と判断した点):

- 前は rescue が例外を飲んでログに書き、アプリは黙って消えていた。今は捕まえないので、`exception.app.rb` (前から rescue が無い) と同じくエラーの Window とログに出る。決定の「黙って何も起きない、を無くす」「起動で例外のときはダイアログ」と同じ向きで、今の異常終了の見せ方そのもの。基底で rescue してログだけにまとめる形は採らなかった (それでは起動の例外もまた黙る)。
- `Log.info("XApp.new")`・`"Script ended"` などの起動の前後のログ行が無くなった。これを grep する道具・試験は無かった (tools・test・rakelib を探した)。
- MIDI の sim の試験 `crash_note.app.rb` (わざと落ちる) は、落ちたときにエラーの Window が出るようになる。回帰の道具からは使われていない。

消さずに残したもの: Python (`.app.py`) 5 本 (指示どおり)、試験の中で作るアプリ (`test/native/{sdl,wl}/*_check.rb` が文字列で書く `X.new.start`。末尾が残っていても二重にならないので動きは同じ)、`lib/add/picoruby-fmrb-app/example/user-app-sample.rb` (`if __FILE__ == $0` の古い見本で、端末で動く形ではない)。

## 6. 見立てと違った点・T4 以降への注意

- 自動起動を C で文を compile して走らせる案 (t0 の候補 A) ではなく、Ruby の `_autostart_task` が返す `Task.new` を C が走らせる形にした。compile が要らず、組み込みの bytecode でも同じ。
- `report_mruby_result` の後に `expected_stop` も見る (top level の間に kill されたファイルを起動しない)。
- 子が 1 つのときは `class =` を読まない (t0 の案どおり。1 つなのに違う名前を書いても黙って 1 つを起動する)。
- 基底を共有するアプリ (今は 0 本) のため、「ほかの子の親になっている子」は数えないことにした。決定の「子を 1 つ見つける」の読み方として入れたが、利用者から見える選び方なので、親に確認してほしい。
- Spinel の生成の末尾の rescue は前の editor・desktop の末尾と同じく**ログだけ** (Spinel には今エラーの Window へ出す口が無い)。子が無い・名指しの誤りは生成のときに止まるので、実行時に黙ることは無い。
- `flash/usr/share/transfer/transfer.app.rb` は t0 の数 (flash/app) の外にあった。
- **mruby アプリの VM プールが +2〜4 KB** (4 章)。止まる条件の「内蔵 RAM の増分」ではない (PSRAM のプール) が、`regress:run` の基準を更新するときはこの分が入る。減らすかどうかは親の判断。
- T4: 全アプリの末尾が消えたので、座標の入れ替えでアプリの最後の行を触る差分はクラスの `end` までで済む。テンプレート 3 本と雛形も末尾が無くなった。

## 7. 基準の更新が要るもの

- `regress:run` (前から古い。更新するなら mruby アプリの +2〜4 KB が入る)。
- ほかの道具 (screens・live・checkpoint・size・spinel・描画の記録) は基準を変えずに通った。
