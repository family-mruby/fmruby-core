## 1. 入れた場所

| 場所 | 中身 |
|---|---|
| mruby の Ruby (`lib/add/picoruby-fmrb-app/mrblib/fmrb-app.rb`) | `FmrbApp.inherited` が子を `FmrbApp` のクラスの ivar `@_app_classes` に覚える (孫も基底の `inherited` を継いで覚えられる)。`_autostart_task(name)` は `Task.new(name:) { FmrbApp._autostart }` を返す。`_autostart` は `_app_class_to_start` の結果が文字列 (起動できない理由) ならそれを返し、クラスなら `new.start` して nil。選び方: 覚えた子から「ほかの子の親になっているもの」を除き、残りが 1 つならそれ (メタデータは読まない)。0 か 2 つ以上なら `FmrbApp.app_meta(script_path)["class"]` を見て、覚えた子 (親も含む) から名前の一致を探す |
| C (`main/app/fmrb_app.c`) | `execute_mruby_script` の `mrb_task_run` の後、`report_mruby_result` (bool を返すように) で例外が無ければ `autostart_mruby_app`。旗が立っている・`expected_stop`・`FmrbApp` が無い、のどれかなら何もしない。`FmrbApp._autostart_task` を `mrb_funcall` で呼び、その Task を checkpoint の host task に付け替えてから `mrb_task_run`。終わったら例外は `report_mruby_result` (ダイアログ+ログ)、Task の値が文字列なら `set_last_error` + `notify_error_to_kernel` (今の異常終了と同じ口、ログは `Not started: ...`) |

| checkpoint | 復元 (`execute_mruby_checkpoint`) は自動起動を通らない。自動起動の Task が host task になるので、イメージの中で走っているのはその Task で、復元後の結果の報告も同じ口 |

## 6. 見立てと違った点・T4 以降への注意

- 自動起動を C で文を compile して走らせる案 (t0 の候補 A) ではなく、Ruby の `_autostart_task` が返す `Task.new` を C が走らせる形にした。compile が要らず、組み込みの bytecode でも同じ。
- `report_mruby_result` の後に `expected_stop` も見る (top level の間に kill されたファイルを起動しない)。
- 子が 1 つのときは `class =` を読まない (t0 の案どおり。1 つなのに違う名前を書いても黙って 1 つを起動する)。
- 基底を共有するアプリ (今は 0 本) のため、「ほかの子の親になっている子」は数えないことにした。決定の「子を 1 つ見つける」の読み方として入れたが、利用者から見える選び方なので、親に確認してほしい。
- Spinel の生成の末尾の rescue は前の editor・desktop の末尾と同じく**ログだけ** (Spinel には今エラーの Window へ出す口が無い)。子が無い・名指しの誤りは生成のときに止まるので、実行時に黙ることは無い。
- `flash/usr/share/transfer/transfer.app.rb` は t0 の数 (flash/app) の外にあった。
- **mruby アプリの VM プールが +2〜4 KB** (4 章)。止まる条件の「内蔵 RAM の増分」ではない (PSRAM のプール) が、`regress:run` の基準を更新するときはこの分が入る。減らすかどうかは親の判断。
- T4: 全アプリの末尾が消えたので、座標の入れ替えでアプリの最後の行を触る差分はクラスの `end` までで済む。テンプレート 3 本と雛形も末尾が無くなった。

## 9. 追記: 起動を同じ Task に入れ直した (親の検収の後)

親の指摘 2 点への対応 (2026-11-14)。

### 9.1 VM プールの増分を無くした

1 章の形 (ファイルの top level の後に 2 つめの Task を作る) は、終わった最初の Task が DORMANT のまま残り (`mrb_gc_register` されスタックを持ったまま)、アプリ全体の下に `_autostart` のフレームが 1 段増えて VM のスタックが伸びるため、mruby のアプリごとに +2〜4 KB (Modern の desktop は +7.9 KB) かかっていた。

今の形: 起動のコードをファイルの後ろに足し、ファイルと同じ Task の中、前の末尾の起動コードと同じ深さで走らせる。

```ruby
(__fmrb_app = FmrbApp._app_to_start).is_a?(Class) ? __fmrb_app.new.start : __fmrb_app
```

| 場所 | 中身 |
|---|---|
| ファイルのアプリ | `fmrb_app.c` の `load_script_file` が後ろに場所を空け、`execute_mruby_script` が compile の前に足す (`AUTOSTART_CALL`)。checkpoint には足す前の、書かれたままのファイルを渡す (表示用) |
| 組み込み (bytecode) | `main/prebuild_scripts/autostart.rb` を `*.app.rb` の後ろにつないで組む。CMake (`compile_ruby_to_bytecode.cmake`)、ネイティブ版・ブラウザ版 (`rakelib/hosted.rake`)、ネイティブ版だけのアプリ (`rakelib/native.rake`) の 3 か所 |
| Ruby | `_autostart` と `_autostart_task` をやめ、`_app_to_start` (旗が立っていれば nil、クラス、または起動できない理由の文字列) にした。旗は C の `FmrbApp._app_instance_made?` で読む |
| C | 2 つめの Task と host task の付け替えをやめた (host task は前と同じプログラムの Task)。起動できない理由はプログラムの最後の値として返り、`report_autostart_refusal` が前と同じ口 (ログとエラーの Window) に出す |

旗・エラーの出し方・checkpoint の扱いは前と同じ。試しに `Task.new` の代わりに同じ Task で `_autostart` を呼ぶ形 (フレームが 1 段深い) も測ったが、ファイルのアプリで +400〜900 B 残ったので、前の末尾と同じ深さで `new.start` を呼ぶ今の形にした。

`regress:run` の差 (VM プールの used、後 − 前。前は 156c042d のファームの分のファイルに戻した木、同じ道具・同じ日):

| modern system_desktop (idle / running / closed) | +7,960 / +7,968 / +7,816 | +248 / +240 / +64 |
| modern Services (idle / running / closed) | +2,120 / +2,536 / +2,536 | -96 / +320 / +320 |
| Kamon | -4,896 | -6,240 |
| MML | +1,840 | -1,464 |
| StackChan Remote | +3,992 | +696 |

- 組み込み (desktop・Services) は +64〜+320 B で幅 (アプリ 512 B) の中。中身は FmrbApp の子の一覧 (クラスの ivar の配列) とクラスメソッドの表の分と見る。
- ファイルのアプリは -6,240〜+696 B で、増えたのは StackChan Remote の +696 B だけ (幅を 184 B 超える)。同じ木を流し直したときのずれは 56 B (校正) だが、プログラムが変わると GC の後に残るヒープのページの切れ目が動き、Kamon・MML・Spinel Hello は逆に 1.4〜6.2 KB 減っている。固定でかかる分は desktop と同じく数百 B と見ており、StackChan の +696 はこの切れ目の動きと判断した (起動のコードは前の末尾と同じ形・同じ深さ)。
- スタックの空きの差は -180〜+24 B (幅 512 B の中)。kernel は T3 で変えていない Spinel のプログラムで、modern の差は前から (1 章の形と同じ値)。

### 9.2 `class =` は常に優先

- メタデータに `class =` があれば、子が 1 つでもそれを起動する。名前が無ければ、ほかの場合と同じくエラーの Window とログ。無いときは前のとおり (ほかの子の親になっている子を除いて、ちょうど 1 つ残ればそれ)。
- 鍵 1 つだけを C で読む `FmrbApp._start_class_name` を足した (メタデータは system のヒープに読んで放す。VM には文字列 1 つだけ)。前の形は子が 2 つ以上のときに `FmrbApp.app_meta` で Hash ごと作っていた。
- 試験用に `flash/app/test/autostart_one_bad.app.rb` (子 1 つ、囲みの `class = "OtherApp"`) を足した。
- Spinel の生成 (`gen_app_combined.rb`) と描画の記録 (`run.rb`) は前から `class =` を先に見ていたので変えていない。
- 文書: spec 3.1 の `class` の行、sig の `start` の help、skill (`.claude` 8ec36a4)。
