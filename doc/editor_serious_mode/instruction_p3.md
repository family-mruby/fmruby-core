# 実装指示書 P3: ハイライト既定のファイル種別化 + 窓フレーム欠けの修正

対象: 実装担当セッション。前提: P2 完了 (report/p2.md)。
report は report/p3.md へ (小タスクなので簡潔で良い)。

## T0 (バグ、先にやる): 全画面起動 → 窓化で窓フレームが描かれない

### 症状 (ユーザ報告 2026-08-10)

**最初から全画面で起動した**エディタ (edit -f / editor_fs) を F11 等で
窓モードに戻すと、**窓フレーム (タイトルバー・枠) が描画されない**。
窓モードで起動して F11 往復した場合は問題ない (P2 検証済み) ため、
「全画面 spawn からの初窓化」だけで通る経路に穴がある。

### 見立て (要検証)

候補は 2 つ。原因を確定してから直すこと:

1. 全画面 spawn のアプリは Ruby 側 @fullscreen が true で初期化され、
   実行時トグルの exit 側でこのフラグが更新されない経路がある
   → draw_window_frame の「fullscreen なら描かない」早期 return に
   落ち続けている。
2. resize 制御メッセージの処理順で、フレーム描画が resize 適用前に走って
   その後の再描画で消えている (resizable アプリは毎 redraw で
   draw_window_frame を呼ぶ必要がある、という既知の規律との絡み)。

窓モード起動 → F11 往復との差分 (何が違うのか) を先に特定すると早い。
editor_fs 固有ではなく「全画面 spawn したアプリ全般」の問題なら
基底クラス側で直す。

### 受け入れ条件

- edit -f (全画面起動) → F11 で窓化 → **フレーム・タイトルバー・
  閉じるボタンが正しく描かれる**。ドラッグ移動・リサイズも効く。
- 窓起動 → F11 往復の従来動作に退行なし。
- 全画面 spawn する他アプリ (editor_fs 以外に該当があれば) でも確認。

## 決定事項 (ユーザ決定 2026-08-10)

- HL_AUTO_LIMIT (サイズによる自動オフ) は**撤廃のまま**。復活させない。
- ハイライトの ON/OFF 機能は**維持する** (エディタは Ruby 以外も扱うため)。
- **既定値をファイル種別で決める**: Ruby は ON、それ以外は OFF。
  現状トークナイザ (picoruby-syntax-highlight) は Ruby 専用であり、
  他言語ファイルに Ruby の色付けが当たるのを防ぐ意味もある。

## 仕様

1. ファイルを開いた時 (Open ダイアログ / edit・edit -f / spawn open_path /
   F5 前の再読み込み等、全経路) にハイライト既定を決める:
   - 拡張子 .rb (末尾一致。.app.rb を含む) → ON
   - それ以外 (.bas / .lua / .py / .toml / .json / .txt / 無拡張など) → OFF
2. 手動トグル (メニューの Hilight) は従来どおりいつでも有効で、
   既定より優先する。ただしトグル状態は**バッファ単位**で持ち、
   別ファイルを開いたら既定判定をやり直す (前のファイルの手動状態を
   引きずらない)。
3. 新規の無名バッファは ON (このシステムの主用途は Ruby)。
   Save as で名前が付いた時に拡張子で再判定する (手動トグル済みなら
   その状態を尊重)。
4. メニューの Hilight 表記が現在状態を反映していること (既存挙動の確認)。

## 受け入れ条件

- .rb を開くと色付き、.bas / .toml を開くと色なし (sim スクリーンショット)。
- .bas を開いて手動 ON → 色が付く (誤った色でも動作としては可)。
  その後 .rb を開き直すと既定 ON に戻る。
- 新規バッファ ON → .bas 名で保存 → OFF に切り替わる。
- 大きい .rb (20KB 級) が引き続き HL ON で開ける (撤廃の退行なし)。
- 窓/全画面の両モードで動く。esp32 (S3/P4) ビルド通過。

## 範囲外

- Ruby 以外のトークナイザ追加 (BASIC/Lua 等の色付けは将来別件)。
- 段階 4 (editor-gem 分割) 以降の項目。
