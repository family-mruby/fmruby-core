# P2 実施報告: 全画面モードの GUI 統合

指示書: ../instruction_p2.md / P1 の報告: p1.md

## T3: 全画面まわりの 3 症状

### 原因 (確定) — 見立てとの差分

3 症状の**共通根は指示書の見立てどおり**「全画面状態が単一スロットで、
全画面中の spawn / 終了の意味論が未定義」だった。ただし症状 3 の機序は
見立てと違った。

- 症状 1 (入れ子復帰でタスクバー): `enter_fullscreen` は
  `@fullscreen_pid` を上書きし、**suspend リスト `@suspended_pids` も
  作り直す**。エディタ(全画面) → RPG(全画面) の順に起動すると RPG の
  リストは `[エディタ, デスクトップ]` になり、RPG 終了時の cleanup が
  それを**全部 resume** する。よってデスクトップが復帰してタスクバーを
  描き、`@fullscreen_pid` は nil に戻る。
- 症状 3 (Ctrl+Q が効かない): **P1 の on_event 直接処理は無関係**だった。
  Ctrl+Q は host_task が横取りしてカーネルに system_interrupt を送る形で、
  アプリのイベント経路には最初から流れていない。カーネル側は
  「パスを持つアプリ (= /app, /home) なら stop、そうでなければ
  `elsif @fullscreen_pid` で全画面解除」しかなく、
  - 症状 1 で `@fullscreen_pid` が nil になっていると**何も起きない**
  - **窓モードの組み込みアプリ (エディタ等) は元から Ctrl+Q で閉じられない**
    (コメントに「エディタは未保存ダイアログを持つので勝手に止めない」と
    明記されており、意図的にそうなっていた)
- 症状 2 (全画面中の窓アプリ): カーネルにこの組合せの意味論が無い。
  デスクトップは suspend のまま、入力ルーティングは
  `if @fullscreen_pid` で全画面アプリに固定 (=クリックは窓ではなく下の
  全画面アプリに配られる)、z-order だけ窓が上。実測では窓は
  **一度も見えなかった** (ユーザ報告の「重なって表示され、クリックで消える」は
  同じ状態の別の見え方)。

### 修正: 全画面状態をスタックにした

`@fs_stack = [{ pid:, suspended: [...] }, ...]` (内側が末尾)。

- **フレームは「自分が suspend したアプリ」だけを記録する**。
  内側フレームを pop すると外側の全画面アプリだけが resume され、
  デスクトップは suspend のまま残る。
- `@fullscreen_pid` はスタック先頭のミラー (既存コードが多数参照するため
  残した)。`@suspended_pids` はフレームの和集合 (`app_suspended?` 用)。
- **1 段記憶ではなくスタックにした理由**: 深さは「エディタ → 全画面アプリ」の
  2 段で足りるが、park (Ctrl+Tab) と組み合わせると *どのフレームを戻すか* の
  判断が必要になり、フレームに suspend リストを持たせる形が結局いちばん
  単純だった。1 段記憶だと「誰を resume すべきか」を別に持つことになる。
- `exit_fullscreen` は**停止要求だけ**に変えた。復帰は
  `cleanup_terminated_app` (アプリの exit 通知) 側に一本化。従来は両方で
  resume していて、アプリがまだ画面に出ているのに「全画面ではない」状態を
  作っていた。

### 修正: 全画面中に窓アプリが spawn されたら park する

`after_spawn` で「新アプリが窓モード かつ 現在全画面」なら
`park_fullscreen` する (指示書の仕様どおり)。park は
`fullscreen_switchable` のアプリだけ (エディタは宣言済み)。
窓アプリ終了時は `@run_parent` が指す親が park 中なら **unpark** して
全画面へ戻す。これで「F5 で窓アプリを試して閉じたら編集に戻る」が成立する。

park は 1 個だけ (単一スロット)。**入れ子で park 済みのときに Ctrl+Tab を
押したら、park を拒否するのではなく `cycle_front_app` に落として park 中の
アプリを unpark する**ようにした (拒否だけだと park 中のアプリに二度と
到達できない = 詰み状態になる)。

### 修正: Ctrl+Q は組み込みアプリに `quit_request` を送る

パスを持たないアプリには `{"cmd"=>"quit_request"}` を送り、アプリが決める:

- `FmrbApp#on_quit_request` の既定は `stop` (状態を持たない組み込みアプリは
  そのまま閉じる)。
- エディタは override し、未保存なら Ctrl-X と同じ確認ダイアログを出す。
- デスクトップには送らない。`elsif @fullscreen_pid` の全画面解除は
  最後の保険として残した。

C 側 (`lib/add/picoruby-fmrb-app/ports/esp32/app.c`) の制御コマンド振り分けは
コマンド名の明示リストなので `quit_request` を追加した (これを忘れると
`on_control` に流れて無反応になる)。

### ついでに直した既存バグ 2 件

いずれも T3 の受け入れ条件を満たすのに必要だった。

1. **spawn 直後の HID target が消える競合**: `check_terminated_apps` は
   「窓リストに居ないアプリ」の HID target を捨てるが、窓リストは
   RUNNING のアプリだけで、spawn 直後の INIT 状態のアプリは入っていない。
   結果、キーボードを渡した直後に取り上げてしまい **Ctrl+Q が時々
   完全に無反応**になっていた (ログは
   `HID target app 6 no longer exists`)。`_get_app_info` は INIT でも
   情報を返すので、それも見るようにした。
2. **終了処理中のアプリを suspend してデスクトップ全体が停止**:
   unpark を cleanup の中で即実行すると、まだ窓リストに残っている
   「終了中のアプリ」を `enter_fullscreen` が suspend してしまい、
   そのタスクは二度と終了できず (reaper が待ち続け) システムが固まった。
   unpark は **相手のスロットが解放されるまで tick_process で待つ**
   形にした (`@pending_unpark`)。

### 範囲外として残した既知の問題

- 全画面エディタから 14KB 級の窓アプリ (tetris) を F5 すると
  `Out of memory (NoMemoryError)` で**プロセス全体が落ちる**ことがある。
  エディタ (バッファ) + 窓アプリ (14KB スクリプトの実行時コンパイル) +
  全画面 canvas が同時に載るとメモリが足りない。T3 の状態管理とは別問題で、
  p1.md の「50KB でエディタ VM が死ぬ」と同じ根 (段階 4 の editor-gem 分割)。
  小さい窓アプリ (draw_tile_test, 2KB) では再現しない。
