# P5 実施報告: エディタ全体の Spinel 化 (段階 6)

指示書: ../instruction_p5.md / 前段: report/p1.md - p4.md

**到達点**: `FMRB_APP_ENGINE_EDITOR=spinel` でエディタが Spinel プログラムとして
動作する。ソースは 1 本のまま (単一ソース二重バックエンド)、未設定なら従来の
mruby バイトコード。.env の既定は mruby のまま変えていない。

## T1: デバッガ部の分離

- `main/prebuild_scripts/default_app/editor/debug_pane.rb` に
  `module EditorDebugPane` として移動 (ペイン描画、ブレークポイント、
  attach ピッカー、FMRB::Debug 呼び出し 19 箇所すべて)。
- Spinel ビルドは代わりに `main/prebuild_scripts/spinel/editor_debug_stub.rb`
  (同名の no-op モジュール) を連結する。**エディタ本体には分岐も defined? も
  無い** — 連結するファイルが違うだけ。
- 本体との接点は 16 個の `dbg_*` フック
  (init / active? / pane_h / gutter_w / draw_pane / modal? / draw_modal /
  handle_modal_key / handle_key / menu_visible? / menu_label / menu_width /
  menu_items / activate_item / line_background / draw_gutter / poll / shutdown)。
- 定数の切り分け: ガター寸法と F キーのスキャンコードは EditorApp に残した
  (F5 は Run、F11 は全画面でエディタ本体が使う)。デバッガ固有の色と ps
  フィルタ値はモジュールへ。モジュールから包含クラスの定数を見るには
  `self.class::NAME` が要る (picoruby は bare 定数を解決しない)。
- mruby ビルドでデバッガの退行が無いことを確認してから次へ進んだ
  (attach → 下分割ペイン → F9 ブレークポイント)。

## T3: editor-core のスロット化

P4 の gem は文書スロットを **mrb_state キー**で持っていた。Spinel に
mrb_state は無いので、次の 2 層に割った:

- `ports/esp32/editor_core.c`: **mruby を一切含まない純 C** (`ec_*(int slot,…)`)。
  文字列は「ポインタ + out 長さ」で返す。これは mruby (`mrb_str_new`) と
  Spinel (`:binstr` = ポインタ + `sp_net_bin_len`) の**両方が包める形**。
- `ports/esp32/editor_core_mrb.c`: mrb_state → スロット解決と String 化だけ。
- `main/app/fmrb_spx_editor.c`: Spinel FFI シム (同じ ec_* を呼び、
  `sp_net_bin_len` を publish するだけ)。
- `include/editor_core_api.h` が両者の唯一の契約。

外部挙動は不変 (gem のスモークテスト 44 項目が変更前と同じく全通過)。

## T2: ビルド配線

desktop の型をなぞった:

- `FMRB_APP_ENGINE_EDITOR` (既定 mruby) を Rakefile / DOCKER 環境変数 /
  CMake に追加。`spinel:gen` に editor 分 (entry `editor_entry`)。
- `tool/spinel/gen_app_combined.rb` の APPS に `"editor"` を追加。連結順は
  fmrb_app_ffi.rb → 生成 consts → msgpack_pure.rb → fmrb_app_base_spinel.rb →
  **fmrb_editor_ffi.rb** → **editor_debug_stub.rb** → editor.app.rb。
- **EditorCore の FFI 宣言は別ファイル (fmrb_editor_ffi.rb) に置いた**。
  fmrb_app_ffi.rb に入れると、Spinel が全 ffi_func に extern を出す性質上、
  「エディタは mruby・デスクトップは Spinel」構成でリンクが壊れる。
- spawner: `default/editor` と `default/editor_fs` を `#ifdef` で
  NATIVE + `spinel_editor_native` に切替。**窓属性 (fullscreen /
  fullscreen_switchable / resizable / min_window_*) は #ifdef の外**に
  あるので両エンジンで同一。

## T4: 基底クラスの追随と書き方制約

### fmrb_app_base_spinel.rb に足した API (mruby FmrbApp との差分)

| API | 由来 |
|---|---|
| `on_quit_request` + `quit_request` 制御メッセージ | P2 (Ctrl+Q) |
| `request_run(path, prev_pid)` | 既存 (エディタの F5) |
| `request_fullscreen(on)` / `toggle_fullscreen` | P2 (F11) |
| resize 制御での `fullscreen` フィールド対応 (user_area の全画面/窓切替) | P2 |
| `Machine.uptime_us` (+ `fmrb_spx_board_micros`) | P1 の edit_lat 計測 |
| `FmrbApp.pool_usage` (+ `fmrb_spx_app_pool_usage`) | P4 の edit_doc 計測 |

`draw_window_frame` の frame block 遅延生成 (P3) は Spinel 基底が
`_paint_frame` を毎回描く実装なので該当なし。

### エディタ本体で書き換えたもの (制約適合)

**1 件だけ**だった: `Integer#chr` (2 箇所) が Spinel ランタイムに無い。
`ASCII_PRINTABLE[code - 32, 1]` のテーブル引きに変更 (両エンジンで同じ動作)。

frozen リテラル / escaping proc / symbol キー Hash の poly-dispatch は
**引っかからなかった**。P1-P4 で入れ替えてきた過程 (差分描画・C 文書モデル・
デバッガ分離) が、結果的に Spinel が苦手な書き方をあらかた落としていたため。

`rake spinel:doctor` は kernel / system_desktop / editor の 3 プログラムとも
**clean** (unsupported / unresolved ゼロ)。

### 性能比較 (同一 sim・同一ファイル・110 打鍵 @70ms・全画面・HL ON)

| ファイル | mruby editor | **Spinel editor** |
|---|---|---|
| 384B (24 行) | mean 1.83ms / max 7.6ms | **mean 1.65ms / max 7.9ms** |
| 10.9KB (719 行) | mean 1.97ms / max 6.0ms | **mean 1.55ms / max 7.6ms** |
| 200KB (12590 行) | mean 1.80ms / max 8.1ms | **mean 1.52ms / max 8.5ms** |
| 53.4KB (3419 行) | - | mean 1.54ms |

いずれも 25ms 超ゼロ、p99 <= 10ms。**遅延の改善は 10-20% と小さい**が、
これは指示書の想定どおり: P4 で描画と文書操作は既に C 側にあり、Spinel 化で
速くなるのは残った UI 層の解釈だけ。退行は無い。

**大きい差は遅延ではなくメモリ**:

| | mruby editor | Spinel editor |
|---|---|---|
| VM プール使用率 (どのファイルでも一定) | **68%** | **15%** |

同じ 500KB のアプリプールで、Spinel 版は 1/4 しか使わない。GC の余裕が
増え、P4 で残った「アプリプールの天井」への距離が大きくなった。

### ビルド (6 通り)

| ターゲット | editor=mruby | editor=spinel |
|---|---|---|
| Linux | OK | OK |
| S3 (NARYAv3) | OK / bin 0x3267e0 (**21% free**) | OK / bin 0x34dd50 (**17% free**) |
| P4 (TAB5) | OK | OK |

S3 の flash 残量は Spinel 化で 21% → 17% (約 160KB 増)。エディタの
Spinel 生成 C は mruby バイトコードより大きい方向に出る、という予想どおり。
**両方入っている**ことに注意 (mruby 版 irep も同時にリンクされる構成では
ない — editor engine は排他)。

- **実機確認はユーザ確認待ち** (実機無しの前提で sim のみ実施)。

## デバッガの将来形への引継ぎ

T1 の分離境界 (`dbg_*` フック 16 個) は、そのまま**別アプリ化の下地になる**:

- エディタ側が握っているのは「ペインの高さ」「ガター幅」「行の背景色」
  「キーの消費」だけで、デバッガの状態はモジュール内に閉じている。
- 別アプリにする場合、この 16 フックを「エディタ ⇔ デバッガアプリ」の
  メッセージ (窓の分割要求 / 行装飾の要求 / キーの委譲) に置き換える形になる。
  現在の同期呼び出しが非同期メッセージに変わる点だけが設計課題。
- v1 の Spinel エディタはデバッガ無しで完結しているので、
  **デバッグ時は .env で `FMRB_APP_ENGINE_EDITOR` を外して mruby 版を使う**
  (互換構成は全機能維持)。
