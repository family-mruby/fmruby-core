# P3 実施報告: ハイライト既定のファイル種別化 + 窓フレーム欠けの修正

指示書: ../instruction_p3.md / 前段: report/p2.md

## T0: 全画面起動 → 窓化で窓フレームが描かれない

### 原因 (確定)

見立ての候補 1 に近いが、**フラグではなく GfxBlock が原因**だった。
`FmrbApp#initialize` は

```ruby
unless @fullscreen
  _build_frame_block
  _apply_rounded_corner_regions
end
```

となっており、**全画面で spawn したアプリは `@frame_block` を一度も作らない**
(全画面には枠が無いので当然)。P2 の実行時トグルで窓モードになると
`@fullscreen` は正しく false に更新される (resize メッセージの
`fullscreen` フィールド経由) が、`draw_window_frame` の

```ruby
if @frame_block
  @frame_block.draw(...)
end
```

が nil で素通りするため、タイトルバー・枠・閉じるボタンが一切描かれない。
窓起動 → F11 往復では初期化時に block ができているので問題が出なかった。

### 修正

`draw_window_frame` で **必要になった時に遅延生成**する
(`_build_frame_block if @gfx && !@frame_block`)。基底クラス側の修正なので、
全画面 spawn する他のアプリが後から窓モードになる場合も同じく直る。

併せて **editor_fs エントリに `resizable` / `min_window_*` を追加**した。
`default/editor` にはあるが全画面版には無く、F11 で窓化した後に
角ドラッグのリサイズが `fmrb_app_update_window_size` の resizable チェックで
弾かれていた (同じアプリなので窓としての性質は揃えるべき)。

## ハイライト既定のファイル種別化

### 実装 (editor.app.rb)

- `hl_default_for(path)`: `.rb` で終わるパス → ON、それ以外 → OFF。
  **無名バッファ (path が nil) は ON** (このシステムの主用途は Ruby)。
- `@hl_manual`: 手動トグルしたかどうか。トグルは既定より優先するが
  **バッファ単位**で、`load_file` で false に戻す (前のファイルの手動状態を
  引きずらない)。
- `load_file` は全経路 (Open ダイアログ / edit / edit -f / spawn open_path /
  デバッガの source_file 追従) が通るので、ここで既定を決めれば十分だった。
- `save_file_as` で名前が付いた/変わった時に再判定 (手動トグル済みなら尊重)。
- HL_AUTO_LIMIT (サイズによる自動オフ) は決定どおり**撤廃のまま**。

### 検証 (Linux sim 320x240、窓 / 全画面 両モード)

| ケース | 結果 | 画面 |
|---|---|---|

| `.toml` で手動 ON → 色が付く (Ruby の色が当たるのは仕様どおり許容) | OK | x3_manual.png |

## 補足 (P1 の宿題について)

ハイライトを行単位 tokenize にした代償として、**全面再描画時は可視行ぶん
tokenize する**ため、ハイライト有効の全面再描画は sim で 12-16ms かかる
(p1.md の T4 節)。今回のファイル種別化で **Ruby 以外は既定 OFF になった**ので、
その負荷を踏むのは Ruby ファイルを開いている時だけになった。
行単位キャッシュ (未実装) は依然として実機で効く見込みの改善案として残る。
