# アプリ配布プラットフォーム 計画

> 状態: 進行中 | 更新: 2026-09-02 | **P1 / P2 完了**。P2 でブラウザの店ができた (一覧・写し・判定・導入・更新、report/p2.md)。`?app=` は起動の受け皿がファームに無く別フェーズへ。次は P2b (startup_app) か P3。 

配布物の形式・置き場所・判定規則は `spec.md` が正。この文書は**いつ何を
作るか**だけを持つ。元の構想は `family-mruby-app-distribution-design.md`。

## 目的

Ruby (および Lua / BASIC / MicroPython) で書いたアプリを、GitHub に置くだけで
公開でき、ブラウザ版でそのまま試せ、実機へ入れられるようにする。

> Ruby で書く → GitHub に出す → Web で動く → 実機に入る

この 4 つの距離を短くすることが目的であり、店の見栄えや品揃えは後でよい。

## 方針

### 新しいものを作らない

配布のために増やすのは**一覧 (`registry.json`) と取得の手順だけ**にする。
アプリ記述は既存の `.app.toml`、置き場は既存の `/app/usr/`、束は既存の
3 階層走査、実機の取得は既存の `Net::HTTP` を使う。理由と根拠は spec.md。

**P3 までファームウェアを変更しない**のを制約として持つ。配布用の鍵は
導入のときに既存の鍵へ翻訳する (spec.md 8.4)。ファームの版と配布物の版が
連動し始めると、店に出すたびに実機を焼き直す話になるため。

### 作る場所

| 何 | どこ |
|---|---|
| 一覧・サンプル・生成と検査の道具 | `family-mruby-apps` (別リポジトリ) |
| 店の画面 (ブラウザ) | `fmruby-core/wasm/web/` |
| 店のアプリ (実機) | `fmruby-core/flash/app/tool/` |
| 文書 | `fmruby-core/doc/app-distribution/` (ここ) |

### ライセンス

`family-mruby-apps` は **MIT**。本体 3 リポジトリ (GPL-3.0) には揃えない。
根拠と、作者リポジトリへ散らす段での切り替え方は spec.md 11.1。

本体の GPL-3.0 がアプリに及ばないことは fmruby-core の README に明記済み
(「Your apps」の節)。**投稿しようとする人が最初に詰まる場所**なので、店を
開ける前に片付けた。

### 検証の道具

- ブラウザ版: `web_up` / `web_input` / `web_screenshot` / `web_fs`
- Linux sim: `sim_up` / `sim_app` / `sim_screenshot` (toml 解析は実機と同じ C)
- Modern 実機: `tab5_fs` / `tab5_app` / `tab5_screenshot`
- Retro 実機: 遠隔操作の口が無いのでユーザに依頼する

| **P1-B** | 実機側の前提の確認 | sim / ブラウザ / 実機で置いて動かす。**sim・ブラウザ済、Retro 実機はユーザ** |

### やらないこと

署名、発行者の信頼、権限、隔離、審査。配布物は作者が書いた Ruby がそのまま
動くものであり、入れる操作は「そのコードを信じる」ことと同義である
(spec.md 11)。この点は店の画面に明記する。

## P1 — 置き場・サンプル・自動検査

**P1 の本当の狙いは Web 側ではなく、spec.md が置いている 2 つの前提を実地で
確かめることである。**

1. `.app.toml` に配布用の鍵を足しても、実機の toml 解析器は**未知の鍵を黙って
   無視する**ので壊れない。
2. `required_heap_kb_*` を**省略したときの既定** (普通のアプリ扱い) が、
   今の挙動と変わらない。

この 2 つが崩れると、方針の「ファームウェアを変更しない」が成り立たなくなる。
先に確かめる。

### 作るもの

```
family-mruby-apps/
├─ apps/
│  ├─ hello_store/     1 ファイル。コメント埋め込み toml。配布鍵は最小
│  ├─ paint_pad/       別ファイルの .app.toml。配布鍵を全部書く。3 環境
│  └─ wide_only/       app_env = ["modern","web"]、app_min_width = 400
├─ tools/registry.rb   .app.toml を歩いて registry.json を作る
├─ tools/validate.rb   spec.md 5.1 の検査
├─ Rakefile            registry / validate
├─ registry.json       生成物。コミットする
├─ .github/workflows/ci.yml
├─ LICENSE
└─ README.md
```

サンプルは `flash/app` から複製しない。**複製すると同じアプリの写しが 2 つ
できて必ず片方が腐る**ため、店用に小さく書き下ろす。3 本は品揃えではなく、
形式を一通り踏むための検体である。

| サンプル | 何を試すか |
|---|---|
| `hello_store` | 1 ファイル配布、コメント埋め込み toml、配布鍵の省略 |
| `paint_pad` | 別ファイルの `.app.toml`、配布鍵を全部書く、320x240 で動く |
| `wide_only` | 環境と画面の判定で**弾かれる**側 (Retro に入らないことを確かめる) |

### 一覧の生成

`rake registry` が `apps/*/[^/]*.app.toml` を読んで `registry.json` を作る。
**生成物はコミットする**。CI は書き戻さず、「生成し直して差分が出たら落とす」
検証だけを行う。CI に書き込み権限を与えないため、および raw から取る先が
常に main の実体であるため。

### 受け入れ条件

前提の確認 (これが主目的):

- [ ] 配布鍵を足した `paint_pad.app.toml` を `flash/app/usr/paint_pad/` へ手で
      置き、sim で起動する。**警告なく起動し、窓の大きさと表示名が toml の
      とおりになる**こと。
- [ ] 同じものをブラウザ版へ `web_fs` で置き、起動すること。
- [ ] `required_heap_kb_*` を省略した `hello_store` が、今のアプリと同じに
      起動すること (`large_memory` を書かないので普通のプールに入る)。
- [ ] ログに未知の鍵に関する警告が出ていないこと (`sim_screenshot` ではなく
      `docker logs fmruby_core` で確かめる)。

道具の確認:

- [ ] `rake registry` が 3 本すべてを載せた `registry.json` を作る。
- [ ] `rake validate` が、わざと壊した 4 通り (`app_id` 重複 / 必須鍵の欠落 /
      本体ファイル不在 / `app_env` の綴り誤り) をすべて落とす。
- [ ] CI が PR でこれを実行し、`registry.json` が古いと落ちる。

ライセンスの確認:

- [ ] `LICENSE` (MIT) があり、README に「ここに出すことは MIT で公開すること
      への同意である」と書いてある。
- [ ] `rake validate` が、SPDX 表に無い `app_license` を落とす。

配信の確認:

- [ ] `curl -I https://raw.githubusercontent.com/family-mruby/family-mruby-apps/main/registry.json`
      が 200 で、`access-control-allow-origin` と
      `cross-origin-resource-policy` を返す (spec.md 6 の前提の実地確認)。

ユーザに依頼する確認:

- [ ] Retro 実機で `paint_pad` が起動する (遠隔操作の口が無いため)。

### 決めておくこと

- **`.app.rb` の構文検査は P1 ではやらない**。picoruby を CI で建てる手間に
  見合わない。代わりに `Regexp` リテラルなど実機で落ちる書き方の文字列検査を
  入れ、本物の構文検査は後の段へ回す。

## P2b — `?app=<id>` の残り半分 (未着手)

ページはアプリを入れられるが**起動できない**。ブラウザに debug server が
無く、`startup_app` のような設定も無い (report/p2.md)。

要るのは desktop の 10 行ほど: 起動時に `FmrbApp.config("startup_app")` を
読み、あれば `spawn_app` する。ページ側は `--fmrb-conf=startup_app=...` を
渡すだけ (道は既にある)。**実機にも効く機能**なので独立させた。

**desktop は Spinel で生成されるので、足したコードが生成を通ることを別に
確かめる**。基底クラスに ivar を 1 個足しただけで壊れた例がある。

## P2 — ブラウザ版の店 (完了)

一覧を読んで並べ、選んだものを `/flash/app/usr/<id>/` へ置いて起動する。
取得はページ (JavaScript) が行う。ブラウザ版に `Net::HTTP` は無い。

ページに足すのは `?app=<id>` の受け口 1 つ。既に `?autostart=1` `?theme=`
`?drive=1` がある (`wasm/web/main.js`)。

一覧の行には**小さな画面の写しを出す**。ページなので `<img>` を並べるだけで
済む (spec.md 10.2)。

受け入れ: 一覧から `hello_store` を選んで起動でき、**再読み込みしても残る**
こと (`/flash/app/usr` は永続化の対象)。`wide_only` は環境の判定で「未確認」
と出ること。写しが 3 本とも出ること。

## P3 — 実機の店アプリ

`flash/app/tool/appstore.app.rb`。手順は spec.md 9.2、面の分け方は 13.2。

**1 本のアプリが 2 つの面を持つ。**

| 面 | 中身 |
|---|---|
| 探す | `registry.json` の一覧、絞り込み、取ってくる |
| 入れたもの | 導入済み・版・入れた日・**新しい版の有無**・更新・削除・取得の進み具合 |

自動更新はしない (spec.md 13.1)。新しい版があることは、ユーザがこの面を
開いたときに分かればよい。

一番の落とし穴は、**入れただけではランチャーに出ない**こと (起動時の走査は
`/var/cache/launcher_index` を無条件に信じる)。導入の最後にこのファイルを
消し、右クリック再走査か次回起動で出ると表示する (spec.md 9.3)。

### 一覧に絵を出す

実機でも一覧の行に **32x24** の写しを出す。ただし**見えている行の分だけ、
見えたときに読み込み、一度読んだら残す**。スプライト 1 枚を描画側へ渡すのに
約 160 ms かかるため、20 件を一度に並べると 3.2 秒待つことになる (spec.md 10.2)。

Retro では絵つきの行が 6 行、文字だけなら 16 行見える。**6 行で browsing が
つらいと感じたら、一覧は文字だけにして詳細に 1 枚だけ出す形へ落とす。**
その判断は実機で触ってから report/p3.md に書く。

### 一覧の部品をどうするか

`FmrbUI` には `Label` `Button` `Toggle` `Stepper` `Enum` `Scrollbar`
`TextField` があるが、**スクロールする一覧が無い**。店には両方の面で要る。

**まず店アプリの中に書き、汎用に切り出せそうなら `FmrbUI::List` へ引き上げる。**
先に汎用部品を作らないのは、1 行の描き方がアプリごとに違い、そこを外に
出す形を決めるのが難しいため。

引き上げるときは**ブロックを持たせない**。`List.new(...) { |i, x, y, w| ... }`
のように受け取ったブロックを後で呼ぶ形は、Spinel が外側のローカル変数の
捕捉で黙って壊す形そのものである。`Widget` は既に `draw` / `hit?` /
`active?` をメソッドで持つ作りなので、**継承して `draw_row` を上書きする**
形にすれば既存の型に沿い、かつ Spinel でも安全になる。

受け入れ: Modern 実機で一覧から入れ、右クリック再走査で現れ、起動する。
「入れたもの」の面で版が古いことが分かり、更新すると入れ替わる。手を入れた
写しは触られず `.new` が隣に置かれる (spec.md 13.4)。
`required_heap_kb_esp32` が large を超える検体を断ること。

## P4 / P5

束 (複数ファイルと素材)、`app_version` の比較と入れ替え、アイコンの二重生成、
絞り込み、Web Serial での書き込み。着手時に切り出す。

## 決めたこと (2026-09-02)

| | 決定 |
|---|---|
| 自動更新 | **しない**。店アプリの「入れたもの」の面で気づける形にする (spec.md 13) |
| 手を入れた写し | `sha256` の三分岐で守る。指紋は `registry.json` から無料で得られる |
| 配布の範囲 | **中央リポジトリだけ**。作者リポジトリへ散らす案は採らない (spec.md 12.1) |
| ライセンス | apps は MIT。本体の GPL-3.0 はアプリに及ばないと README に明記済み |
| 画面 | Retro 320x240 と Modern 426x240。**店の画面は 1 つの作りで両方に収まる** |
| 必要ヒープの計測 | 手順を文書にするだけ。CI での自動計測はやらない |
| 一覧の絵 | 作者は PNG を 1 枚。実機用の 32x24 BMP は CI が作る。生成は全部 Ruby |
| 配布の形 | **`.app.toml` は必須**。埋め込み記述だけのアプリはランチャーに出ない (spec.md 3.3) |
