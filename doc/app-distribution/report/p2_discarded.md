## `?app=<id>` を分けた理由

**受け皿が無い。** ページは機械のファイルを書けるが、**アプリを起動する手段を
持たない**。ブラウザに debug server は無く (実機の `/app/launch` にあたる
ものが無い)、`startup_app` のような設定も無い (`page_settings_wasm.c` が
受けるのは解像度と配色だけ)。

代わりに**できる半分だけを実機能として入れた**: `?install=<id>` で、開いた
だけでそのアプリが入る。入ったあとは「Reload to use it」を出す。

残り半分 (起動) に要るものは分かっている。`FmrbApp.config(key)` で設定を
読め (`launcher.rb:343`)、`spawn_app(name)` で起動でき (`launcher.rb:785`)、
ページから機械へ設定を渡す道もある (`--fmrb-conf=`)。**desktop に
「起動時に `startup_app` を読んで spawn する」を足すだけ**で、実機にも効く。
ただし desktop は Spinel で生成されるので、足したコードが生成を通ることを
別に確かめる必要がある。独立したフェーズとして切る。

## 踏んだこと

### 絵が出ないのは COEP ではなく `loading="lazy"` だった

最初、スクリーンショットの枠が全部黒かった。COEP を疑ったが、**`crossorigin` を外しても
絵は出た** — つまり `raw.githubusercontent.com` が CORP を返すので素の
`<img>` で通る、という spec.md 6 節の記述は正しい。原因は
`loading="lazy"` の方だった。

`crossorigin="anonymous"` は残した。**GitHub Pages は CORP を返さない**ので、
将来そちらから絵を出すときはこれが要る。両方で動く書き方にしておく。

### 見出しに書いた結果が消える

導入の結果を見出し (`store-state`) に書いていたが、直後の再描画が
「3 apps」で上書きしていた。**壊れた `sha256` を弾いているのに、弾いた
理由が画面に出ない**という一番良くない形になっていた。

結果は行に書き、行は作り直されるので、`Map` に覚えて再描画のたびに
書き戻す形にした。

### `?registry=` がファイル名を捨てていた

`registry.noweb.json` を指したのに `registry.json` を読んでいた。基準 URL を
作るときにファイル名を落としていたのが原因で、**判定が効いていないように
見えた**が、実際は判定にかける中身が違っていた。

ディレクトリでもファイルでも受けるようにした。

### 撮影の待ち方

ページの絵は canvas の外なので `web_screenshot` では写らない。headless
Chrome の `--screenshot` を使ったが、**`--holdload` では画像の読み込みが
間に合わず黒いまま写る**。`--virtual-time-budget=20000` にすると全部
写った。「絵が出ない」を実装の不具合と読み違えたのはこれが 2 度目
(1 度目は sim の move の間引き、report/p1b.md)。

### ページの DOM は既存の道具で押せない

`web_input` は canvas に注入する道具で、店のボタンは DOM。既存の駆動路
(ページが開発サーバに命令を取りに行く形) にも DOM を押す命令は無い。

**そのため `?install=` が検証の道でもある**。Install / Update / Remove の
ボタン自体は、同じ関数を呼ぶ 3 行の配線で、その関数は `?install=` と
入れ直しで通してある。ボタンを実際に押す確認はユーザに残る。

### 前のセッションの残置物

ブラウザの `/flash/app/usr` に `hello.app.toml` / `hello2.*` が残っていて、
ランチャーに「HelloUsr」として出ていた。自分のアプリが出ていないと
一瞬読み違えたが、**一覧が日本語名で並び順の別の頁にあっただけ**だった。
残置物は別セッションのものなので消していない。
