## 作り

- **2 つの面**を切替 (`Find` / `Installed`)。320x240 に一覧を 2 つ置けないため。
- **導入済みの版は入っている `.app.toml` から読む。** 別の台帳を持たない
  (spec.md 13.3)。行頭の印が `=` (最新) と `^` (新しい版あり)。
- **取得は `on_update` で進める**状態機械。ファイルを全部受け取ってから
  書くので、途中で失敗しても半端なアプリが残らない。
- `required_heap_kb` がこの機械の通常プールを超えるとき、`large_memory = 1`
  を `.app.toml` に書き足してから置く (spec.md 8.4)。

## 掘り当てたバグ: 「wasm32 なら Regexp がある」

ブラウザで一覧が読めず `uninitialized constant Regexp`。

`picoruby-json` に wasm 向けの最適化があり、`RUBY_DESCRIPTION` に `wasm32` が
入っていれば Regexp の速い経路を使う。**wasm32 であることと Regexp を持って
いることは別**で、この機械のブラウザ版は正規表現エンジンを積んでいない。

**発火が遅い。** ビルドも起動も通り、何かが JSON を解析した瞬間に、その環境
でだけ出る。`use_regexp?` に `Object.const_defined?(:Regexp)` の確認を足して
直した (`lib/patch/picoruby-json/`)。上流 PR 候補にも記録した。

P2 の `String#length` と同じ形をしている: **環境か内容に依存して初めて出る
ので、まず別のものを疑ってしまう。**

## 詰まったこと

### FmrbUI の flush は部品より広く塗る

一覧の 1 行目が消えていた。`clear_user_area → draw_list → flush` の順だと、
`flush` がボタンの下 10px ほどまで塗り、そこに重なった行が消える。
**`flush` を先に、自前の描画を後に**。ボタンとの間隔も 2px では足りず、
8px 空けた。

### 選択の見せ方は塗りつぶしでは無理

行の高さが 11px しかないので、帯を塗って反転色で書く形は読めなかった
(実際、選択行だけ文字が出ないように見えた)。**行頭に `>` を置く**形に
変えたら解決した。狭い画面では印の方が強い。

### テーマ色の名前

`theme_highlight` は無い。`theme_bg` / `theme_fg` / `theme_accent` /
`theme_border` / `theme_fg_light` が正 (`fmrb-app.rb:174`)。

### 束ねる前に stage する

`rake wasm:web` は **git の index を読む**ので、新しいアプリを
`git add` しないとブラウザ版に入らない。追加したのに出てこないときの
最初の疑い。

## 積み残し

- **sha256 を検証していない。** この機械に digest が無い (`picoruby-marshal`
  はあるが digest 系の gem は無い)。今は**大きさだけ**を照合している。
  spec.md 11.2 が sha256 を「最初の版で持つもの」に挙げているので、
  ここは仕様との差。SHA-256 を C で足すのは独立した作業。
- **一覧にスクリーンショットを出していない。** 32x24 の BMP を出すには、取得 → ファイルへ
  書き出し → 描画側へ転送 (1 枚 160ms) が要る。段を分けた。
- **環境で弾かれる側を実測していない。** sim は modern なので、3 本とも入る。
  `wide_only` を Retro で断ることの確認は Retro 実機か、Retro 構成の sim で。
- **Retro 実機**はユーザに依頼する。
