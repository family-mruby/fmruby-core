# 実機 (NARYA v4) での確認 (2026-09-02)

> 状態: 完了 | 一覧の取得・写真・sha256 の照合・導入・起動まで実機で通った。
> **`task_stack_kb` が実機では高くつく**ことが分かり、サンプルを直した。

対象は NARYA v4 (ESP32-P4 + HDMI、Modern)。Retro ではないので、**文字だけの
一覧の確認は残っている**。

## 通ったこと

| | 結果 |
|---|---|
| ブート | crash マーカー 0、健全 |
| WiFi | 接続 (`Associated with AP`、`fmruby.local`) |
| 一覧の取得 | **`3 apps - modern`**。日本語を含む registry が落ちた |
| 写真 | 3 本とも一覧に出た |
| `sha256` の照合 | **実機で照合できた** (注記に "size checked only" が付かない) |
| 導入 | `/app/usr/paint_pad/` に 2 ファイル |
| 入れたアプリの起動 | 動き、線が引けた |

**日本語を含む `registry.json` (2858 バイト) が実機で落ちた**のが、P2 で直した
`Content-Length` を文字数で数えるバグの実機での確認になる。直す前は 1 本も
落とせなかったはずのもの。

## 見つけたこと: `task_stack_kb` は内蔵 RAM の取り合い

`paint_pad` が**実機で起動を拒否された**。

```
W: [Paint Pad] refused: largest internal block 31744 < 40960 needed
```

`task_stack_kb = 32` を書いていたので `need = 40960`。WiFi と BLE が両方
上がった NARYA v4 では、**その大きさの連続領域がもう無い**。

- 起動直後: `largest=229376`
- WiFi + BLE 起動後: `largest=114688`
- 店 (32KB) を起動した後: `largest=31744`

**しかも店を止めても 36864 までしか戻らなかった** (断片化)。

`paint_pad` は窓に線を引くだけのアプリで、32KB を必要としていない。私が雛形
から写しただけだった。**外したら既定 16KB で問題なく動いた** — 店を動かした
ままでも。

### 配布の設計に返ること

`task_stack_kb` は「大きくしておけば安心」ではない。**内蔵 RAM は基板で
一番乏しく、抱えた分だけ次のアプリが入らなくなる。** 配るアプリが余分に
要求すると、忙しい機械では起動しない。

`family-mruby-apps` の README にこの実測をそのまま書いた。サンプルは最初に
真似されるものなので、雛形から写した 32KB をサンプルが持っていること自体が
害だった。

## 踏んだこと

### raw の配信は数分遅れる

サンプルを直して push したあと、店から入れ直しても**古い manifest が入った**。
`raw.githubusercontent.com` がまだ前の版を配っていた (registry も toml も
揃って古いので、大きさも `sha256` も一致して導入は成功する)。

切り分けには `tab5_fs` で端末の manifest を直接置き換えた。**店の取得元が
CDN である以上、直した瞬間には反映されない**ことは覚えておく。

### 別セッションの掴みでポートが開けなかった

`/dev/ttyACM0` が別の MCP サーバの掴みで塞がっていた。実体を見ると
**26 時間前に死んだ捕捉の記録**で、ポートを開いているプロセスは無かった
(`lsof` で 0 件、最終書き込みが前日)。`dev-ttyACM0.lock` を `.stale` に
退避して開いた。

### 実機の storage に検証用の写真が混ざった

`flash/cache/app/appstore/*.png` が storage 像に入った。sim で店を動かした
ときに書かれたもので、**配布物のツリーに検証の副産物が残っていた**。害は
無い (中身は正しいサムネイル) が、`flash/` は「git 追跡分 = 配布してよい
もの」という不変条件があるので、消しておく。

## 残り

- **Retro (NARYA v3) での確認**。文字だけの一覧が 320x240 で見やすいか、
  `wide_only` が断られるか。遠隔操作の口が無いのでユーザに依頼する。
- 店自身の `task_stack_kb = 32` も見直す価値がある。断片化した状態では店
  自体が起動できなくなる (再起動で戻る)。JSON の解析とアプリ本体の翻訳が
  どれだけ要るかを測ってから決める。
