# R2 の指示: 変えるコマンド・スイッチ・印

先に読む: `doc/remote_shell/plan.md` (7 章が正)、`report/r0.md`、`report/r1.md` (R1 で作った物とメソッドの形)。

## 作る物

0. **先にする下ごしらえ (R1 で見つかった 2 つ。親の決定)**
   - **転送のアプリの台本を 64 KB の上限から離す**。`transfer.app.rb` は上限 (`MAX_SCRIPT_FILE_SIZE`) まで残り 57 バイト。
     動きを変えずに、まとまり (`TransferInbox` など) を `flash/usr/share/transfer/` の別のファイルへ出して require する
     (上限は上げない)。残りを 8 KB 以上にする。別コミットにし、転送の今の試験と `rake regress` が通ること。VM の使用量が
     始める前より増えないこと (測って report に書く)。
   - **確かめられた接続でだけ入れる**。`open` と各呼び出しは、転送のアプリの `certified?` (tls/ のルータ、ブラウザ版は
     door の印) が真のときだけ受ける。そうでない接続では、呼び手の名前を騙れるため。sim・開発の確認用に、
     `receive.toml` の持ち主の部分の `rshell_uncertified = true` (手で書くときだけ。受け取りのアプリの画面には出さない)
     があれば、確かめられない接続でも受ける。断る理由は呼び手に返す。
   - 切の端末には `rshell` を公開しない今の形 (呼び手には `no_object`) はそのままでよい。

1. **変えるコマンド** (`flash/usr/share/transfer/rshell.rb`。`exec_write` だけが受ける。`exec_read` に来たら断る)。
   - `cp SRC DST`・`mv SRC DST`・`rm PATH` (`-r` でフォルダ)・`mkdir PATH`。鍵の場所 (R1 の判定) は、元にも先にも
     できない。大きいファイルの `cp` は少しずつ写す (全部をメモリに読まない)。読み取り専用の場所は理由を返す。
     `mv` で先に同じ名前があるときは断る (上書きは `-f`)。
   - `kill PID|名前`・`open PATH` (アプリを起こす。`.app.rb`・`.app.wasm`)。カーネルへ頼み、「頼んだ」と返す。結果
     (止まった・起きた・断られた) が届いたら、続き (`more`) で返す。届かないまま 5 秒で「返事なし」。カーネルと話す形は
     シェルの `cmd_kill`・`spawn_app`・`cmd_ps` (`main/ruby/default_app/shell/shell_commands.rb`) と同じにする (読むだけ。
     シェルは変えない)。転送のアプリ自身とカーネル・デスクトップは `kill` できない。
   - `put` で使う: `/home/inbox` (SD は `/mnt/sd/inbox`) から先への `mv` が、上の決まりで通ること。
   - 補完: `kill` は動いているアプリの名前、`open` はアプリのパス。
2. **スイッチ** (受け取りのアプリ `flash/app/tool/receiving.app.rb` と `flash/usr/share/transfer/receive_conf.rb`)。
   - 「リモートシェル: on / off」を、今の 2 つのスイッチ (受け取り・送り) と同じ並びに足す (`FmrbReceiveConf.set_rshell_enabled`、
     `tell_transfer`)。既定は off。320x240 の画面に収める (今の行の高さの決まりのまま。収まらないときは止まって報告)。
   - 入ってよい相手の一覧 (種類 `rshell`): console が配った分は「from the console」として見せる。手で足す・消すも、
     ほかの種類と同じにする。
   - on にしたとき、何ができるようになるかを 1〜2 行の注意書きで出す (日本語・英語)。「この端末のファイルを、許した相手が
     遠くから見たり変えたりできます」の意味。
   - シェルの `areceive` には足さない (シェルは変えない)。
3. **入られている間の印** (デスクトップ `main/ruby/kernel/system_desktop.app.rb`・`system_desktop/taskbar.rb`、カーネル
   `main/ruby/kernel/fmrb_kernel.rb`)。
   - セッションが開いている間だけ、メニューバーの右 (かなの指示器の並び) に小さい印を 1 つ出す。開いた・閉じた・時間切れを、
     転送のアプリがカーネル経由でデスクトップへ知らせる (今あるメッセージの中継の形を使う。新しい通信の型を増やすなら
     最小限)。右側の幅 (`TASKBAR_RIGHT_RESERVE`) とセルの位置を直す。Retro (320 幅) でタスクバーの見た目が変わらないこと
     (印が無いときの幅は今と同じにする)。
   - 印の見た目は仮でよい (文字 2 つ程度か 10 px の絵)。色はテーマの色から選ぶ (0x01 は使わない)。印を押して切る操作は
     作らない (未確定 4)。
   - デスクトップ・カーネルは Spinel。型が絞れない呼び出しで黙って 0 になる罠に注意し、生成 C を確かめる。
4. **回帰の場面**: `regress:run` に「転送のアプリが動いている」場面を足す下ごしらえ (場面の定義だけ。基準の作り直しは
   親がする)。場面の足し方は `doc/regression/usage.md`。難しければ止まらず、残件に書く。
5. 試験: R1 の試験に、変えるコマンド・鍵の線引き (元と先)・`exec_read` で断ること・スイッチの読み書き
   (`receive_conf`) を足す。

## 触ってよい範囲

上の 1〜5 のファイルとその試験・生成物。シェル・`vendor/`・`lib/upstream/`・sdkconfig・ほかのリポジトリは触らない。
ブランチは `remote-shell`。コミットしてよい。push しない。

## 確認

- `rake regress` (落ちたものだけ見る。描画の記録の基準が変わるなら、変化を report に書いて別コミット)。足した試験。
- sim: `rake clean` → `rake build:linux` → 受け取りのアプリでスイッチを on にし (画面を撮る)、PC の asterism の CLI から
  `open` → `exec_write` で `mkdir`・`cp`・`mv`・`rm`、`kill`・`open` と続きの結果、鍵の場所への書き込みの断り、
  `exec_read` に `rm` を渡したときの断りを確かめる。入っている間の印と、`close`・時間切れで消えることを画面で撮る
  (時間切れは、確認の間だけ短い値で確かめてよい。値は戻す)。スイッチが off のとき、転送のアプリが (受け取り・送りも
  off なら) 終わること。
- Retro の sim (320x240) でメニューバーが今までどおりであること。
- **ESP32 のビルドはしない**。重い道具 (`regress:run`・`size`・`screens`) も流さない。

## 止まる条件

- 利用者から見た動き (仕様) が変わる直し方を選ぶ必要が出たとき。7 章と食い違う事実が出たとき。
- 範囲の外を変える必要が出たとき。受け取りのアプリの画面に収まらないとき。
- 内蔵 RAM の静的な増分が出るとき (カーネル・デスクトップに大きな表や状態を足す形になるとき)。

## report (`doc/remote_shell/report/r2.md`)

変えるコマンドの答えの形、`kill`・`open` の結果の届き方、印の知らせ方、撮った画面、測った数、見立てと違った点、
撤回した仮説、残件。実在の値を書かない。終わったら sim を止める。
