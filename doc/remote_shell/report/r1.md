## 2. メソッドの引数と答えの形 (R3 で console が読む)

どれも `caller: :from`。断り (スイッチが切・一覧に無い・別のセッション・番号違い) は例外で、呼び手には
`raised: ArgumentError: <理由>` が届く。スイッチが切のときは公開そのものが無く、`no_object` (`no object rshell exposed by <node>/transfer`) になる。

| メソッド | 答え |
|---|---|
| `open()` | `{"id", "cwd", "version" => {"os", "board", "rshell" => 1}, "commands" => {名前 => "read"/"write"}, "out_max" => 8192, "total_max" => 65536, "idle_ms" => 300000}` |
| `exec_read(id, line)` / `exec_write(id, line)` | `{"out", "code", "cwd", "more" => 次の pos か nil, "cut" => 64 KB で切ったか}`。code は 0 成功・1 失敗・2 使い方の誤り・126 変えるコマンドを exec_read で・127 無いコマンド (この版の変えるコマンドも 127) |
| `more(id, pos)` | `{"out", "more", "cut"}`。pos は前の答えの `more`。同じ pos を聞き直してよい |
| `complete(id, line, pos)` | `{"word" => 置き換える語の始まり (文字数), "items" => [語の全体の候補], "cut"}`。pos は文字数、nil か範囲外は行末。候補は `\ ` 付きの打てる形、フォルダは末尾 `/`、200 まで |
| `read(id, path, pos, len)` | `{"data", "pos", "size" => ファイル全体}`。len は 1〜8192 |
| `close(id)` | true (違う番号は false) |

`object info` には各メソッドの引数の名前と説明が出る (`RShell::METHODS`)。

## 5. 見立てと違った点

- **アプリの台本は 64 KB まで** (`main/app/fmrb_app.c` の `MAX_SCRIPT_FILE_SIZE`)。`transfer.app.rb` は始める前に
  65,002 バイトで残り 534 バイトだった。最初の形 (67,381 バイト) は読み込みで断られ、転送のアプリが起きなかった。
  呼ぶ側の作りを `rshell.rb` に寄せ (`Door#switch`)、`receive.toml` の例を繰り返していた注釈を短くして 65,479 バイト
  (残り 57 バイト) に収めた。試験で大きさを見張る。**R2 で転送のアプリに何か足すと、もう入らない**。
- ON の増分は r0 の見当 (ソース 20〜25 KB) より大きい約 89 KB。ソースは約 30 KB。mruby の irep と文字列の分。
  P4 の large プールは 2 MB で、転送のアプリは GC の後で約 1 MB を使うので収まるが、R5 の `regress:run` で見る。
- 切の端末でも +1,376 バイト増える (0 ではない)。転送のアプリに足した数行と `receive_conf.rb` の `rshell_enabled?` の分。
  0 にするには、スイッチの読みを別のファイルへ出すしかない (下の残件)。
- `File#read(n)` はバイト数で読む (文字数ではない)。picoruby の `seek` は無いので、離れた位置は頭から読み飛ばす。
  続けて読む `more`・`read` は開いた File を持ち越すので読み直さない。

## 6. 撤回した仮説

- 「スイッチが切でも `rshell` を公開し、理由つきで断る」は採らなかった。切の端末に何も足さない (公開の表にも出ない) 方を
  取り、切のときは gem の `no_object` が理由になる。console (R3) は `no_object` を「リモートシェルが切」と読む。
  R2 の受け入れ条件 (「呼び出しは理由つきで断られる」) の言い方と合わせて、親が確かめてほしい。
- 鍵の判定は devctl と同じ「SECRET と PASSWORD だけ」ではなく、`secret_path?` は plain 以外を全部 true にした
  (`/home/asterism/config.toml` と `/home/asterism` そのものも)。計画 3 章 4 の「/home/asterism は読めない」に合わせた。

## 7. 残件

- R2: 変えるコマンド、`open` の補完をアプリのパス・`kill` を動いているアプリに、入られている間の印、受け取りのアプリの
  スイッチ。`transfer.app.rb` が 64 KB の際にあるので、R2 の前に `TransferInbox` を別のファイルに出すか、台本の上限を
  上げるかを決める (どちらも R1 の触ってよい範囲の外)。
- 切の +1,376 バイトを 0 にするなら、`rshell` の結線ごと別ファイルにする (その場合も `check_receiving` の数行は残る)。
- 許可の確認は転送の今の作りに沿い、ノードの名前を一覧と照らすだけ。証明書の無いルータでは名前を騙れる
  (`policy_set` のような `certified?` の縛りは入れていない)。R2 で入れるか決める。
- `areceive` の表示と `HAND_KINDS` に `rshell` は入れていない (シェルの出力が変わるので R2 の受け取りのアプリと一緒に)。
- `ps` はサービスの子の行を出さない (シェルは答えを後で受けて出す)。
- バイナリのファイル (最初の 4 KB に NUL) は `cat` で断る (`not text`)。取り出しは R4 の `get` (`read`)。
- ESP32 のビルド・実機・重い回帰はしていない (親の検収)。
