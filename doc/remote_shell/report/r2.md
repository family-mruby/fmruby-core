## 2. 答えの形

- 変えるコマンドの答えは R1 と同じ `{"out", "code", "cwd", "more", "cut"}`。成功は 1 行で何をしたかを返す
  (`cp: /home/rs/a.txt -> /home/rs/d1/a.txt (6 bytes)`、`mv: A -> B`)。`mkdir`・`rm` の成功は空。失敗は code 1 と理由の行。
- 断りの文: 鍵 `kept from the remote shell (keys and passwords)`、読み取り専用 `read-only here`、
  先にある `already there (-f to write over it)`、中身のあるフォルダ `a directory with things in it (rm -r)`。
- 鍵の線引き: 元・先のどちらかが `secret_path?` なら断る。`rm`・`mv` の元と `cp`・`mv` の先は、さらに鍵を含むフォルダ
  (`/`・`/home`・`/etc`・`/home/asterism`、`/flash/...` も) を断る (C の `fmrb_path_contains_secret` と同じ決まりを Ruby に書いた)。
  `rm -r` は再帰を使わずスタックで深い方から消す。
- `mv` は名前の付け替えが通らないとき (SD と /home の間)、ファイルなら写してから元を消す。`put` の `/home/inbox`・SD の inbox
  からの `mv` はこれで通る (ホストの試験で確認。sim には SD が無い)。
- `kill`・`open` の答えは `{"out" => "kill: asked the kernel to end PID 6 (Kamon)\n", "code" => 0, "more" => 44, "wait" => true}`。
  console は `more(id, 44)` を呼び、結果が来るまでは `{"out" => "", "more" => 44, "wait" => true, "code" => nil}`、
  来たら `{"out" => "kill: PID 6 (Kamon) ended\n", "more" => nil, "wait" => false, "code" => 0}`。5 秒来なければ
  `no answer from the kernel in 5 s (ps)` か `was asked to end and has not in 5 s (ps)` (code 1)。

## 3. kill・open の結果の届き方

- kill: カーネルへ `{"cmd" => "kill", "pid"}` (シェルと同じ)。`kill_result` の ok が偽なら「断られた」、真なら待ち続け、
  `app/died` (転送のアプリが前から購読している) の pid で「終わった」。転送のアプリ自身・system・kernel の型は端末の側で先に断る。
  名前が 2 つ以上当たるときは PID を求める。
- open: カーネルへ `{"cmd" => "spawn", "app_name"}`。`spawn_result` の app が同じパスなら「起きた (PID)」。失敗は今まで
  デスクトップにだけ行っていた `spawn_failed` を転送のアプリにも送るようにした (カーネルの変更はこの 1 か所)。
  受けるのは `.app.rb`・`.app.wasm` だけ。
- 転送のアプリの `on_control` が `kill_result`・`spawn_result`・`spawn_failed` を、`app_ended` が死んだ pid を `Door#note` へ渡す。

## 4. 印の知らせ方

`Door` がセッションを作ったとき (置き換えでは出し直さない) と消したとき (close・時間切れ・スイッチ切・アプリの終わり) に
`tell_kernel({"cmd" => "rshell_state", "on"})`。カーネルは転送のアプリからだけ受け、`@rshell_open` を持ってデスクトップへ
同じ形で渡す。転送のアプリが知らせずに終わったら (`note_move_exit`) カーネルが下ろす。デスクトップは `@rshell_on` が変わったら
`draw_foreground`。新しい通信の型は増やしていない (今の APP_CONTROL の cmd を 1 つ)。

## 5. 確認 (sim、Retro 320x240)

- `rake regress`: host 38 suites と 310 runs が通る (下ごしらえの後と最後の 2 回)。`rake regress:transfer:quick`: 下ごしらえの後と最後に ok。
  `rake regress:spinel`: 6 programs, 0 failed (デスクトップ・カーネルを Spinel で生成。生成 C で `rshell_pad` が `sp_int`、
  `msg["on"] == true` が `sp_poly_eq(..., sp_box_bool(1))` になっているのを見た)。
- sim: `rake clean` → `rake build:linux` → 受け取りのアプリでスイッチを on → 転送のアプリが起き `rshell` を公開。
  PC の CLI (`--node` で一覧の名前) から `open` → `mkdir`・`cp`・`mv`・`cp` の重ね (断り)・`rm` (中身ありは断り、`-r` で消える)、
  鍵への `cp`・`mv`・`mkdir`、`rm -r /home` の断り、`exec_read` の `rm` が 126、一覧に無いノードの断り。
  `kill Kamon` → more で `ended`、`open` → `started (PID 6)`、アプリの枠が埋まった状態の `open` → `not started (No free app slot. ...)`。
  `kill 2` (デスクトップ)・`kill Transfer` の断り。補完 `kill ` → `["Kamon", "Receiving"]`、`open /app/demo/ka` → `["/app/demo/kamon.app.rb"]`。
  `close` で印が消え、時間切れ (確認の間だけ `IDLE_MS = 8000`、戻した) で消えた。スイッチを off にすると
  `the remote shell is off; the transfer app ends` で終わった (受け取り・送りも off)。`rshell_uncertified` を消すと、
  tcp のルータからの `open` は `takes the remote shell only over a checked connection` で断られた。エディタを開いて 1 打鍵。
- Retro のメニューバー: 変更の前と後の起動画面の上 13 行の差は時計の数字 (x 284〜312) だけ。
- 撮った画面 (どれも sim のもの): 受け取りのアプリで on にした所 (注意書きと「console から」の行)、印が出た所、
  印とタスクバーのアイコン (R K M S) とアプリの起動の失敗のダイアログ、close の後、時間切れの後。

## 6. 測った数

| 項目 | 数 |
|---|---|
| 転送のアプリのプール (切、起動の終わりで GC の後、sim) | 分ける前 1,004,888 → 分けた後 963,448 バイト (**-41,440**) |
| 転送のアプリの台本 | 65,479 → 45,691 バイト (上限 65,536 まで 19,845) |
| ON で公開した直後のプール (GC なし) | 1,184,264 バイト (R1 と同じ測り方ではないので参考) |
| 1 回の呼び出し | 測っていない (R1 の 45〜48 ms から変えていない) |

内蔵 RAM: カーネルに `@rshell_open` (bool の ivar) を 1 つ足した。Spinel はこれを struct の欄と、`civ_FmrbKernelImpl_*` の
静的な 1 バイトにする。後者は `SP_TU_BSS` (= `EXT_RAM_BSS_ATTR`、PSRAM)。デスクトップは定数を足していない (セルの幅は
数字のまま書いた。最初の形の `RSHELL_CELL_W` は生成 C で静的な欄になったのでやめた)。`regress:size` は流していない。

## 7. 見立てと違った点

- 台本を分けたら、転送のアプリのプールが 41 KB 減った (増えないことだけを見込んでいた)。1 本の大きい台本のコンパイルの
  後に残る分が、2 本に分かれて小さくなったと見ている (中身は見ていない)。
- `open` の失敗はカーネルから頼み手に届いていなかった (デスクトップのダイアログにだけ)。シェルの `open` も同じで、
  失敗は画面のダイアログでしか分からない。カーネルを 1 か所直した (転送のアプリにだけ送る)。
- 端末の側の `kill` が失敗の理由を返せるのは、カーネルの `kill_result` の ok=false (suspended・queue full ほか) と、
  端末の側の事前の確かめだけ。「頼んだが終わらない」は 5 秒で打ち切る。
- 受け取りのアプリのアイコンは Retro のタスクバーに出ていなかった (前から。R2 とは関係なし)。アプリを 4 つ足した画面では出た。

## 8. 撤回した仮説・選んだこと (親に確かめてほしい)

- **`cp` も先にファイルがあると断る** (`-f` で上書き)。指示は `mv` だけだったが、間違えて消すのを防ぐ側に揃えた。シェルの `cp` は
  黙って上書きする。仕様として違ってよいか。
- **`open` はアプリ (`.app.rb`・`.app.wasm`) だけ**。R1 の表の説明「ファイルを関連付けのアプリで開く」は外した (指示どおり)。
- `mv` はフォルダも名前の付け替えで動かす (ストレージをまたぐフォルダは断る)。
- `rm -f` は受けるが何もしない (`-r` と並べて打たれることが多いため)。
- `rshell` の一覧は受け取りのアプリからだけ変えられる (`allow`・`deny` の `all_kinds`)。シェルの `areceive allow rshell ...` は
  今までどおり「not a kind」。
- 受け取りのアプリの種類の名前は「シェル」(Shell) にした (4 つの種類を 1 行に並べるため短くした。長い名前で収まるかは試していない)。

## 9. 残件

- `regress:run` の `running_transfer` の基準 (親)。ON の場面 (`receive.toml` を置いて rshell を入れる) は足していない:
  sim の /home は flash/home (開発者のもの) なので、fixtures から置いて消す仕組みが要る。
- ESP32 のビルド・実機・`regress:size`・`regress:run`・`regress:screens` はしていない。
- `kill` の時間切れの文は ESP32 で 5 秒が足りるか (delay_ms の件とは関係なし。`Machine.board_millis` で数える)。
- 大きいファイルの `cp` は 1 回の呼び出しの中で全部写す (8 KB ずつで、メモリは 8 KB まで)。数 MB だと呼び手の期限
  (CLI は 2 秒) を越えうる。R4 の `get`・`put` の大きさと合わせて、呼び出しを分けるかを決める。
- `ps` はサービスの子の行を出さない (R1 から)。`kill` はサービスの名前を受けない。
- 印を押して切る操作は作っていない (未確定 4)。
