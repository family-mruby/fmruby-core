# R4 ファイルの出し入れ (get・put) と大きい cp

> 2026-11-27。指示は instruction_r4.md。コミットは fmruby-core が
> `feat(transfer): the remote shell's writes for put and a long cp a piece at a time`、asterism-console が
> `feat(terminal): get and put files in the remote shell, a long cp's progress` と
> `docs(terminal): get, put and the long cp in the remote shell; report on R4` (console の報告は docs/remote_shell_r4.md)。

## 1. したこと

| 物 | 中身 |
|---|---|
| 端末 `rshell.rb` | `write_begin`・`write_chunk`・`write_end`・`write_cancel`・`stop` を足した。PROTO を 3 に。`read` は R1 のまま (バイナリもそのまま運べた) |
| 端末 大きい cp・mv | 64 KB を超えるファイルの `cp` と、付け替えが通らない `mv` は「頼んだ」(`wait`) で答え、転送のアプリの周期で 1 回 30 ms まで写す。`more` は写している間 `progress` を返す。写し先は隠しの `.part` で、写し終えて名前を付ける |
| 端末 `transfer.app.rb` | `Door#tick` が真 (写している・2 秒以内に呼ばれた) の間は周期を 2 ms に (2 行) |
| console | `get <ファイル>`・`put [<フォルダかファイル>]`、ドラッグ&ドロップ、y/N、記録 (`terminal_commands.files`)、一時の置き場 (`TerminalFiles`)、大きい cp の進み具合と Ctrl-C。詳細は console の docs/remote_shell_r4.md |
| 試験 | `test/rshell/run.rb` 215 → 267 件。console 722 → 739 runs |

## 2. メソッドの形 (端末)

| メソッド | 答え・動き |
|---|---|
| `write_begin(id, path, size, overwrite)` | `{"path" (畳んだパス), "size", "pos" => 0, "piece" => 8192}`。`<フォルダ>/.<名前>.part` を開く。断り (例外): 鍵・鍵を含むフォルダ・読み取り専用・フォルダがある・フォルダが無い・同じ名前 (`overwrite` が真でなければ `already there (overwrite to write over it)`)・空きが足りない (上書きは元の大きさを足して見る)・size が整数でない |
| `write_chunk(id, pos, data)` | 今の位置 (整数)。pos が今より先なら受けず今の位置を返す、全部が前なら読み飛ばす、重なりは後ろだけ書く。8 KB を超える片・size を超える片は断る (後者は `.part` を消す) |
| `write_end(id)` | `{"path", "size"}`。全部来ていなければ断る (`.part` は残す)。ファイルの大きさを確かめて付け替え (失敗したら先を消してもう一度) |
| `write_cancel(id)` | true。`.part` を消す。`close`・別の `write_begin`・60 秒片が来ない (`WRITE_IDLE_MS`) でも消す |
| `stop(id)` | true。写している cp を止め、写した分を消す (`... stopped (what was copied is deleted)`、code 1)。kill・open の待ちはやめる |
| `more` (写している間) | `{"out" => "", "wait" => true, "progress" => {"done", "total"}, ...}`。終わると `cp: A -> B (N bytes)` |

- `open` の `commands` に `get`・`put` は入れていない。console の ACL と汎用の `call` の塞ぎは `transfer/rshell` 全体なので、
  足したメソッドも同じに守られる (ルータの deny `no_rshell_calls`、`CallPermission.reserved?`)。
- 別のコマンドが来たら写している cp は止める (`another command came`)。

## 3. 通した結果

sim (tcp、`rshell_uncertified`、Retro) と、ネイティブ版 (tls/ のルータ、証明書つき、console の配る一覧) の 2 つ。
console はブラウザ (Playwright の Chromium) から、見るだけの人と変えるまでの人で。

| 項目 | 結果 |
|---|---|
| get (sim) | テキスト・かな 86 KB・PNG・1 MB の乱数を落とし、4 つとも SHA-256 が元と一致。落とした後は置き場が空 |
| get (tls、ネイティブ版) | PNG・1 MB が一致 |
| get の断り | フォルダ (`not a file`)・`/home/asterism/receive.toml` (`kept from the remote shell`)・上限超え (試験) |
| put (sim) | 4 つ (テキスト・かな・PNG・1 MB) を一度に選んで置き、全部一致。ドロップで 2 つを `put d2` の先に。1 つを `put renamed.txt` で別の名前に (試験) |
| 同じ名前の y/N | `... is there already (written over). Go on? (y/N)`。n は何も送らず、y は同じ upload で上書き |
| 本体の領域 | `put /usr/` は system's area の y/N |
| 見るだけの人の put | `put: changes the machine; you may only read ...` |
| 鍵の場所への put | `put /home/asterism/` は端末が `kept from the remote shell` で断る |
| put の途中の Ctrl-C | 6 MB の 2.5 MB で止め、`write_cancel`。端末に `.part` は残らなかった |
| 大きい cp | 4 MB・64 MB とも期限切れにならず一致。sim は速すぎて進み具合が出ないので、確認の間だけ写す量を落として (512 B・1 ms、戻した) `30.1 MB / 64.0 MB` の行と Ctrl-C で `.part` が消えることを見た |
| 補完 | `g` → `get `、`get o` → `one.bin`、`p` → `ps put pwd` |
| 記録 | Call log に get・put の行。`files` に各ファイルのパス・大きさ・結果 |
| **put (tls、ネイティブ版)** | **通らない** (4 章 1) |

## 4. 測った数

| 項目 | 数 |
|---|---|
| 1 MB の get (sim、bridge が受けてから終わるまで) | 425〜434 ms (ページで Enter から次のプロンプトまで 600〜700 ms) |
| 1 MB の put (sim、端末へ書く分) | 635〜734 ms (console へ上げる分を含めてページで 0.8〜1.1 s) |
| 1 MB の get (tls、ネイティブ版) | 440〜535 ms |
| 1 MB の put (tls、1792 バイトずつ、試しの台本) | 1.8 s |
| 64 MB の cp (sim、30 ms ずつ) | 0.6 s ほど (ホストのファイルシステム) |
| 1 回の read・write_chunk | 約 3〜5 ms (sim、同じ PC のルータ。r1 の 46 ms は CLI の接続込み) |

転送のアプリの VM: `rshell.rb` は 45.9 → 約 57 KB。ON のときの増分は測っていない (R5 の `regress:run` で見る)。
公開した直後のプール (GC なし) は sim で 1,237,224 バイト (R2 の 1,184,264 から +52 KB、測り方は同じではない)。

## 5. 見立てと違った点・止まった所

1. **tls/ のルータ越しのネイティブ版で、端末へ向かう 2 KB 前後より大きい呼び出しが届かない** (止まる条件「1 回の呼び出しで
   運べない」に当たる)。`write_chunk` の data が 1950 バイトまでは通り、2000 バイトからは端末の TLS が
   `TLS: the connection failed: -0x004e (NET - Sending information through the socket failed)` で切れて繋ぎ直し、呼び出しは
   答えられない。zenoh-pico が分けて受ける大きさ (`Z_BATCH_UNICAST_SIZE` 2048) を超えた所。tcp (sim) では 8 KB が通る。
   端末から出る 8 KB の答え (get) は TLS でも通る。原因は picoruby-asterism-zenoh の posix の TLS の口
   (`ports/posix/zp_tls_posix.c`、触らないものの範囲) と見ている。ESP32 の口 (`zp_tls_esp32.c`) は試していない。
   転送の `Asterism::Transfer` の片 (3072〜3840) も同じ道なら、ネイティブ版への tls のファイル送りも通らない見込み (未確認)。
   **直し方は決めずに残した**: (a) gem の TLS の口を直す、(b) 端末が `write_begin` で返す `piece` を 1792 などに下げる
   (console は端末の言う片で送るので console は変えなくてよい。決定の「8 KB まで」の内側)。(b) は 1 行だが原因を隠すので選ばなかった。
2. sim のファイルの読み書きは速く、1 MB の get・put は 0.5 秒前後で終わる。呼び出しを並べる (窓) 必要は無かった。
   実機の flash の書き込みの速さは見ていない。
3. 大きい cp は sim では一瞬で終わり、進み具合の行は確認用に遅くしたときしか出ない。実機では出る見込み。
4. 上書きの有無は、書き始める前に console が `stat` (exec_read) で見る形にした (端末に確かめるだけのメソッドは足していない)。
