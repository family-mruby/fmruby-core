# R0 調査の結果

> 2026-11-26。読むだけの調査 2 本 (端末の側・console の側) と、その結果を受けた決定。計画への反映は plan.md 7 章。

## 1. 見立てと違った点

| 見立て (計画の初版) | 実際 | 決めたこと |
|---|---|---|
| console に「見るだけの人 / 起こせる人」の 2 段がある | 人の区別は admin かどうかだけ。読むコマンドはサインインした人なら誰でも、call は Call permissions (node/app/object/method の表) で許されていれば誰でも | **人ごとに許す** (ユーザ決定): 利用者ごとに「なし / 見るだけ / 変えるまで」の列を足す |
| 端末のスイッチは Config | 受け取りの ON/OFF は Config に無く、受け取りのアプリ (`flash/app/tool/receiving.app.rb`) とシェルの `areceive` が `/home/asterism/receive.toml` を書く | **受け取りのアプリに足す** (ユーザ決定)。`receive.toml` に `rshell_enabled = true` |
| 新しい画面なしのアプリ | console が一覧を配る先 (`policy_set`) も、ルータの ACL が守る鍵 (`asterism/<node>/transfer/**`) も、転送のアプリのもの。別のアプリにすると一覧が届かず、ブラウザ版の共有の接続では呼んだ相手を騙れる。ON の間の内蔵 RAM (タスクのスタック 16 KB) と TLS の接続も 1 本増える | **転送のアプリに足す**。オブジェクトは `<node>/transfer/rshell`。ソースは別のファイルにし、ON のときだけ読む |
| 1 回の出力 64 KB | 1 回の呼び出しで運べるのは 16 KB まで (zenoh-pico の `Z_FRAG_MAX_SIZE`。超えると黙って落ち、呼び手は期限切れ) | 1 回の答えは 8 KB、続きは `more`。1 コマンドの合計の上限は 64 KB |
| シェルのコマンドを切り出して使う | シェルはファームに焼いたバイトコードで、/usr/share のアプリから require できない。`resolve_virtual_path` は `..` を畳まない (鍵の守りに使えない)。引用符を扱わない。Tab はパスだけでコマンドの名前を補わない | 要るコマンドだけ別のファイルに書く (約 600 行)。パスの正規化・引用符・コマンドの名前の補完は新しく作る。シェルには触らない |
| 鍵の線引きは Ruby で | C に既にある (`main/kernel/fmrb_secret_path.c` の `fmrb_path_classify`。`..`・`/flash/` の別名・`.part` まで見る)。Ruby からは呼べない | C の判定を Ruby に出して使う (sig も足す)。devctl と同じ決まりになる |
| `get` は転送に乗せる | 乗るが、端末の行に「console へ送ってよい」の印が要り、受けたファイルは admin しか落とせず、console に溜まる | `get` は console が `rshell` の `read(id, path, pos, len)` で取りに来る形にする (許可が 1 か所、切れても続きから)。`put` は今の転送 (/home/inbox に置く) の後に `mv` |
| `ps`・`kill`・`open` はすぐ返る | `kill`・`open` の結果はカーネルから後で届く。公開したメソッドは答えを後に延ばせない | 「頼んだ」と返し、結果は続き (`more`) で取る |
| メニューバーにアプリが印を出せる | 汎用の仕組みは無い。印はデスクトップの固定のセル | デスクトップにセルを 1 つ足し、カーネル経由で知らせる (R2) |

## 2. 数

- VM プール (`components/fmrb_common/include/fmrb_mem_config.h`): ESP32-P4 は通常 1 MB、large 2 MB が 2 つ。sim は 1.5 MB と 3 MB が 2 つ。
  ブラウザ版は large が枠ごと。転送のアプリは large を 1 つ持つので、転送 + 麻雀で large は埋まる (今もそう)。転送のアプリに
  足せば、この数は変わらない。足すソースは約 20〜25 KB で、2 MB のプールの中の増分は R1 で測る。
- `regress:run` の基準に、転送のアプリが動く場面が無い。R2 で足す。
- 転送の `CALL_BYTES = 4096`・`PIECE_MAX = 3840` は、上限を 16 KB に上げる前の値のまま (今回は触らない)。
- 記録が古い所: `doc/reference/app_memory.md` の「Modern の large は 1 つ」(今は 2 つ)。R5 で直す。

## 3. console の側の作り (要点)

- Terminal は、ブラウザが 1 行を `POST /terminal/commands` で送り、bridge (`lib/bridge/terminal.rb`) が行を取って CLI を流し、
  出力を ActionCable で返す。ソケットはブラウザ向きの片方向。
- 「入っている」状態は bridge のメモリ (ページごと。セッションの番号はブラウザに渡さない) に置き、Rails が読めるように
  `TerminalSession` に端末の名前を 1 列写す。ページを閉じたときの片付けは今の `sync`・`close` に乗る。
- Tab の入れ方 (1 つなら入れる、複数なら共通の頭まで + 一覧) は既にある。足りないのは空白のある名前の引用。
- 許可を配る仕組みは `ReceiverLists` の種類 (file・checkpoint) に `rshell` を足せばそのまま広がる。ルータの ACL
  (`lib/relay/cloud_config.rb` の `sender_keys`) には `rshell` の呼び出しの鍵の行を別に足す。
- Ctrl+C が効くのは呼び出しと呼び出しの間 (端末で走っている 1 回の実行は止まらない)。
- 見当: console だけで 800〜1,000 行。

## 4. 残した判断

- コマンドの表 (どれが見る・どれが変える) の置き場: 端末が `open` の答えで返す。console は表を持たず、端末の答えで
  `exec_read`・`exec_write` を選ぶ。端末の側でも `exec_read` に変えるコマンドが来たら断る (2 重)。gem に client を置く
  (手元の CLI から入る) のは R6。
