# R3 console と本物の端末の通し

> 2026-11-26。console の側 (asterism-console のブランチ remote-shell、報告は docs/remote_shell_r3.md) を、端末の偽物でなく
> sim とネイティブ版の端末を相手に通した。直しのコミットは fmruby-core が
> `fix(transfer): cat's 64 KB cut no longer sends a broken character`、asterism-console が
> `fix(bridge): the receivers' lists go out on the bridge's connection` と
> `fix(terminal): a machine with its remote shell off may look absent; the stand-in as the real one`。

## 1. 通し方 (再現の手順)

2 つの道で通した。sim の zenoh-pico は TLS が入っていない (`Z_FEATURE_LINK_TLS` がホストのビルドでだけ 1。sim の
転送のアプリは `connect: TLS is not built in on this platform` で繋がらない) ので、**tls の道はネイティブ版**で通した。

### 1.1 sim (tcp、確認用の抜け道)

1. fmruby-core で `rake clean` → `rake build:linux`、`sim_up` (Retro 320x240)。sim のノード名は `<node>` (設定なしの既定。
   /home/asterism/config.toml を置かないと、ルータは compose の zenohd `tcp/zenohd:7447`)。
2. `flash/home/asterism/receive.toml` を手で置く (sim の /home は flash/home):
   ```
   rshell_enabled = true
   rshell_uncertified = true
   [rshell]
   from = ["console"]
   ```
   試験用のファイルは `flash/home/rs/` (`a.txt`・405 KB の base64 `big.txt`・かな 109 KB の `kana.txt`・`my file.txt`・
   `my dir/inside.txt`・`d1/`)。終わったら両方消した。
3. console: 開発用の DB (`storage/development*.sqlite3` と `storage/relay/generated/router_watch.json`) を tar で退避し、
   `bin/rails runner` で試験の利用者を 3 人 (リモートシェル なし / 見るだけ / 変えるまで、admin でない) 作った。
   `env -u ASTERISM_CREDENTIALS CONSOLE_EXTRA_HOST=host.docker.internal bin/rails server -b 0.0.0.0 -p 3471` と
   `env -u ASTERISM_CREDENTIALS bin/bridge` (既定の `tcp/127.0.0.1:7447` = sim の zenohd)。
4. ブラウザ: `script/headless/` の Playwright のイメージと node_modules を使い、scratchpad に置いた小さな台本
   (ログイン → /terminal → 行を打って次のプロンプトを待つ・Tab・Ctrl+C・画面と xterm の中身を出す) で動かした。
   コンテナは `--add-host=host.docker.internal:host-gateway`。

### 1.2 ネイティブ版 (tls/ のルータ、確かめられた接続)

1. scratchpad に使い捨ての CA (`Relay::CertAuthority`) を作り、ルータ (`zenohd-cloud`、名前に `localhost`・`r3tls`)・
   `console`・`<node>` の証明書を出す。開発用の DB に `<node>` の行 (client、`rshell_from_console`、上の証明書を
   `RelayCertificate.record!`) を足し、`Relay::CloudConfig` で DB の行からルータの設定 (ACL つき) を作る。
2. ルータは `eclipse/zenoh:1.10.2` をその設定で起こす (`-p 127.0.0.1:7448:7447`)。
3. bridge は `ASTERISM_ROUTER=tls/localhost:7448 ASTERISM_TLS_CA/CERT/KEY=...` (bridge は `ASTERISM_CREDENTIALS` を
   読まない。`lib/bridge/runner.rb` の TLS の環境変数)。
4. `rake native:mruby` → `rake native:core`、`~/.local/share/family-mruby-dev/home/asterism/` に `config.toml`
   (`router = "tls/localhost:7448"`、`node`)・`<node>` の .tar・`receive.toml` (`rshell_enabled = true` だけ。抜け道も
   手書きの一覧も無し) を置き、`native_up`。console の配る一覧で入れることを確かめた。終わったら消した。

## 2. 通った事

| 項目 | 結果 |
|---|---|
| `remote` | 一覧に `<node>` が出る。切 (転送のアプリなし) の後は「No machine has its remote shell on the network now ...」 |
| `remote <node>` → 見るコマンド | `pwd`・`ls`・`ls -l`・`cd`・`cat`・`cat "my file.txt"`・`stat`・`ps`・`df`・`free`・`ver`・`help` が端末のとおり |
| 大きいファイル | `cat big.txt` が 64 KB で切れ、最後に `(the output is cut at 64 KB)`。表示された行は全部元のファイルの中身 |
| かな | `cat kana.txt` の各行が正しい。**切れ目の 1 文字が壊れていた** (3 章 1、直した) |
| Tab | `c` → `cat cd cp` の一覧、`ve` → `ver `、`cat /home/r` → `/home/rs/` → フォルダの中の一覧 (`my\ dir/` の形)、`my` → `my\ `、`f` → `my\ file.txt `、`my\ d` → `my\ dir/` → `inside.txt`、`kill ` → `Kamon `、`open /app/demo/ka` → `kamon.app.rb` |
| 変えるまでの人 | `mkdir`・`cp` (重ねは断り)・`mv`・`rm` (中身ありは断り、`-r` で消える)。鍵の場所への `cp`・`mkdir`、`rm -r /home` は理由つきで断り |
| `kill`・`open` | `open /app/demo/kamon.app.rb` → 「asked」の後に `started (PID 6)`。`kill 6` → `ended`。同名 2 つの `kill Kamon` は PID を求める。`kill Transfer`・`kill 2` は断り |
| 本体の領域 | `mkdir /usr/r3tmp` で y/N。n は「(not sent)」、y で作られ、`rm /usr/r3tmp` も y/N の後に消えた。Call log に asked と confirmed の行 |
| 見るだけの人 | `rm`・`mkdir` は「changes the machine; you may only read ...」。`get` は「not in this version of the console」、無いコマンドは「not a command of this remote shell」 |
| なしの人 | `remote`・`remote <node>` とも「you may not use the remote shell」 |
| 入れない理由 | 一覧に無い: 「does not let this console in (tick ...)」+ 端末の文。スイッチが切 (手で書き換えた直後): 「the remote shell is off on `<node>`」。いないノード: 「not on the network now」。別の呼び手が入っている (tls の道で別のノードが先に open): 「someone else is in `<node>` now」 |
| 印 | 入っている間メニューバーに「RS」。`exit` で消えた。ページを閉じたときは bridge が約 27 秒後に `left <node> (the page was closed)` で close し、消えた |
| Call log | 「remote shell `<node>`」の印、read / write / open / close、終了の値、出力の頭、ms が残る |
| tls の道 (ネイティブ版) | console の配る一覧 (`[managed.rshell] from = ["console"]`) が端末に書かれ、抜け道なしで入れた (`ver`・`ls`・Tab・`mkdir`・`rm`・`ps`)。印を外すと一覧が `[]` で届き、「does not let this console in」で断られた |
| ルータの ACL | `rw asterism/**` を持つ別のメンバー (証明書つき) は、端末の手書きの一覧に入れても `transfer/rshell` の `open` が届かない (`no_rshell_calls`)。その deny だけを外したルータでは入れた |

## 3. 見つけた食い違いと直し

1. **端末: 64 KB の切れ目で壊れた文字** (fmruby-core)。`cat` の片が 65534 で終わり、次の文字が 3 バイトのとき、最後の
   呼び出しの片がその文字の頭 2 バイトだけになり、`utf8_whole` が 0 を返した後の「壊れた並びは送る」の分岐で 2 バイトが
   送られていた (決定 5 の「UTF-8 の境目で切る」に反する)。上限のところではその頭を落とすようにした。ホストの試験に
   その並びのかな (pieces が 65534 で終わる) を足した (`test/rshell/run.rb`、直す前は 2 件落ちる)。
2. **console: 配る一覧がどの端末にも届いていなかった** (asterism-console、本筋の外だが通しを止めていた)。
   `Bridge::Receivers` が `Asterism["<node>/transfer/inbox"]` (モジュール全体の接続) で `policy_set` を呼んでいたが、
   asterism 0.14 (protocol 2、接続をオブジェクトに) でこれが無くなり、毎回 `NoMethodError: undefined method '[]' for
   module Asterism` で失敗していた。試験は呼び出しを差し替えていたので見えなかった。bridge の接続を渡すようにし、
   既定の呼び出しを通る試験を足した。**console 0.4.0 以降のリリース (VPS のものを含む) は、受け取り・checkpoint の
   一覧も端末に届いていない見込み** (main にも同じ直しが要る。親の判断)。
3. **console: 切の端末が「いない」とだけ言われる**。スイッチが全部切の Family mruby の端末は Asterism に何も出さない
   (転送のアプリが動かない) ので、console からは「いない」と区別できない。決定 15 の「切か、端末がいない」に合わせ、
   理由の文に「リモートシェルが切のこともある」を足した (docs/terminal.md の表も)。
4. **偽物を本物に合わせた**: コマンドの表を本物の 18 語に、`more` の答えに `"wait" => false`・`"code" => nil`。

## 4. 速さ (1 行の応答)

- ブラウザで Enter から次のプロンプトまで (台本の待ちの粒度を含む): 見るコマンドで 200〜400 ms、`cat` 64 KB で約 700 ms、
  `open`・`kill` (カーネルの返事を待つ) で約 500 ms。
- Call log の ms (bridge が受けてから終わるまで): 1 行 105〜120 ms、`kill`・`open` 325〜445 ms、`cat` 64 KB 440 ms。
- 端末への 1 回の呼び出しは r1 の 46 ms のまま (同じ PC のルータ)。体感で遅れは気にならない。

## 5. 決めずに残した事 (仕様に触れるので、親に)

- ページを閉じたときの close は bridge が約 27 秒後に行う (R3 の作り: トークンの期限)。その間、同じ利用者が新しいページで
  `remote <node>` すると「you are in `<node>` on another Terminal page」で断られる。閉じて開き直す使い方では待たされる。
- `kill ` の Tab は同じ名前のアプリが 2 つあっても候補は 1 つ (`Kamon`) で、入れた後の `kill Kamon` は PID を求められる。
- 端末の `head -3` は受けない (`head -n 3` だけ)。手元のシェルの癖とは違う。
- `cd` の Tab はファイルも出す (フォルダだけにしない)。
- 「someone else is in」の文に、端末の文として先に入っている呼び手のノード名が出る。

## 6. 通らなかった事・しなかった事

- **sim での tls の道** (sim の zenoh-pico に TLS が無い)。tls の道はネイティブ版 (Modern、同じ転送のアプリ) で通した。
  sim は `rshell_uncertified = true` と手書きの `[rshell] from` で通した。sim では配る一覧は端末が理由つきで断る
  (「takes no list from console over a connection without certificates」) ところまで確かめた。
- Ctrl+D と、長い出力の途中の Ctrl+C は本物では試していない (R3 が偽物で確認済み)。
- `get`・`put` は R4。ESP32 のビルド・実機・重い回帰はしていない。

## 7. 確認

- fmruby-core: `rake regress` (host 38 suites、310 runs) が通る。`rake rshell:test` 215 件。
- asterism-console: `env -u ASTERISM_CREDENTIALS bin/rails test` 722 runs、0 failures。
- 片付け: sim・ネイティブ版・ルータのコンテナ・Rails・bridge を止め、flash/home の試験の物とネイティブ版の
  /home/asterism・/home/rs を消し、console の開発用の DB を退避した物に戻した。
- 撮った画面は scratchpad (リポジトリの外) に置いた。

## 8. 残件

- 3 章 2 の直しを main とリリース (console の版) へ。VPS の console は今、配る一覧を送れていない見込み。
- R4 (`get`・`put`)、R5 (Tab5・P4-Nano・ブラウザ版、VPS の console から)。
- sim で tls の道を通すなら、sim の asterism-zenoh にネイティブ版と同じ `Z_FEATURE_LINK_TLS=1` と Mbed TLS の設定が要る
  (今回は触っていない)。
- 5 章の小さな仕様の点。
