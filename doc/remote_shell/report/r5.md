## 1. 通し方 (ブラウザ版、確かめられた接続の道)

**抜け道 (`rshell_uncertified`・手書きの `[rshell] from`) は使っていない**。T8 の手元の通しと同じく console の
`deploy/local/rehearse` (deploy/vps の compose + nginx の container、自己署名の `*.localtest`) を作業中の木から立て、
ブラウザ版のページを door 経由で利用者の証明書でつないだ。

1. fmruby-core: `source ~/emsdk/emsdk_env.sh; rake spinel:gen && rake wasm:mruby && rake wasm:web && rake wasm:dist`。
2. console: `deploy/local/rehearse prepare` → `build` (gem は rubygems の asterism 0.14.0) → `bootstrap`。
   `bin/rails runner` で試験の利用者を 3 人 (Terminal を使う「変えるまで」の人・「見るだけ」の人・ページの持ち主。
   持ち主には handle と「Remote shell from the console」の印) 作り、`bin/asterism setup --from-update` で持ち主の
   ブラウザの証明書 (`wasm-<handle>`) とルータの設定を作った。生成された ACL で、持ち主のブラウザの subject に
   自分の `transfer/**` の rw (印が受け手の行と同じ扱いにする) と共有の `no_rshell_calls` が入ることを確かめた。
3. `PLAY_DIST=wasm/build/dist deploy/local/rehearse up`。ページは `https://play.localtest/` から、持ち主の pass
   (`BrowserPass.issue!` + `PassLink.url`) の付いたリンクで開いた。
4. ページの操作 (クリック・ファイル・画面・再読み込み): ページの `?drive=1` は同じ origin の `drive/cmd` を取りに来るので、
   確認の間だけ play.localtest の nginx に `location /drive/` を足し (scratchpad の上書きの compose ファイル。リポジトリは
   変えていない)、手元の `rake wasm:serve` (port 8006) へ渡した。ブラウザはホストの Playwright の Chromium を
   `--headless=new --ignore-certificate-errors --host-resolver-rules="MAP play.localtest:443 127.0.0.1:18443, MAP router.localtest:7443 127.0.0.1:17443"`
   で起こし、`ruby tools/fmrb_web.rb` (MCP の web_* と同じ道) で動かした。
5. console の Terminal: Playwright のコンテナを `asterism-rehearsal_web` に置き、R4 の台本 (ログイン → /terminal → 行・Tab・
   ファイル選択・ダウンロード) を `https://asterism.localtest/` に向けた。

door のログ: `#1 open from ...: GET /, as wasm-kid with its certificate (pass 2)`。受け取りのアプリでスイッチを入れると、
bridge の配る一覧が `[managed.rshell] from = ["console"]` で端末の receive.toml に書かれた。

## 3. ブラウザ版だけの違い

1. **ページが開いている間しかいない**。ページを閉じると `remote` の一覧から消え、`remote <node>` は
   「not on the network now ... or its remote shell is off ...」。入っている途中で閉じると、次の行は
   「did not answer exec_read in 10 s」で断られ (実際はすぐ返る)、Terminal はセッションに残ったまま (`exit` で出る)。
2. **再読み込みしたページは console から開き直すまで入れない**。pass は 1 つのページ (読み込みごとの鍵) に結び付く
   (wasm/web/main.js の G1.5b の決まり) ので、読み込み直したページは door に入れず、ネットワークに出ない。
   console の「Launch Web Studio」から開き直すと入れる。ファイルとスイッチ (receive.toml) は残る。
3. **`df` は出る**。値はブラウザの見積もり (`navigator.storage.estimate()` の空き、1 割引き。今回の headless では
   `9216 MB /home`) で、本当の空きではない。`/tmp` は 8064 KB。
4. **速さは遅くない**。手元 (同じ PC の door・ルータ) で、1 行は Enter から次のプロンプトまで 200〜400 ms (sim と同じ)、
   1 MB + 27 B の `put` が 875 ms、1 MB の `get` が 914 ms (sim は 0.8〜1.1 s・600〜700 ms)。SHA の照合は console の側
   (ブラウザ版は書くだけ) なので、ブラウザ版の SHA の遅さは効かない。
5. ブラウザ版の `free` はホストのメモリ (`heap: 62 MB free of 256 MB`)。

## 4. 未確定 1 (Terminal の一覧でブラウザ版をどう見せるか) の今の見え方と案

今: `remote` の一覧は `wasm-<handle>` を台帳の端末と同じ 1 行で出す。閉じたページは一覧から消え、`remote` で入ろうと
すると端末と同じ「not on the network now」。ブラウザ版だと分かる手掛かりは名前の頭 (`wasm-`) だけ。

案 (決めていない):
- (a) 一覧の行に印を付ける: `wasm-kid  (a browser: only while its page is open)`。console は `User` の handle から
  ブラウザのノードを知っている (`Relay::BrowserNode.base`) ので、console だけで足せる。
- (b) 閉じたページへの断りをブラウザ用の文に: 「`wasm-kid` is a user's browser; it is there only while its page is open
  (a reloaded page joins after it is opened from the console again)」。
- (c) 印の付いた利用者のブラウザで、今ページが開いていないものも一覧に薄く出す (`wasm-kid  (page closed)`)。
- (d) 入った直後の 1 行に「files are the browser's own (/home stays across reloads)」を出す。
- 今のままでも使えるので、(a)+(b) が小さく効くと見ている。

## 5. 見つけて直した事

- **console: 端末の断りで名前が 2 度出る** (`wasm-kid: wasm-kid: /home/asterism/receive.toml: kept from the remote shell`)。
  `Terminal::Remote.explain` が端末の文の頭に名前を付け、Terminal の行の断りがもう一度付けていた。`put` だけは外して
  いた。共通の所で外すようにし、試験に「名前は 1 度」を足した (直す前は落ちる)。sim でも同じだったはず
  (R4 の報告には文の全体が無い)。

## 6. console 0.4.5 の準備 (B)

- CHANGELOG の Unreleased を `## 0.4.5` にし、「What an update needs」を今までの版の形 (`./update.sh 0.4.5` だけで済む、
  マイグレーション 2 つ、ルータの設定は更新の setup が書いて起こし直す、nginx は変えない、`.env` の
  `ASTERISM_RSHELL_FILE_MAX_BYTES`・`ASTERISM_RSHELL_FILE_KEEP_SECONDS`、Users と Members/Browsers での選び方と Apply、
  端末に要る版 (リモートシェルの入ったファーム。`ver` が `remote shell: 3`、まだリリースに無い)) で書いた。
  docs/install.md に「From 0.4.4 to 0.4.5」(戻し方を含む)。VERSION と compose の既定を 0.4.5。
- **受け取りの一覧が 0.4.0 から届いていなかった直し**を、利用者向けに太字の項で書いた。配り直しはコードで確かめた:
  `Bridge::Receivers` は送った記録 (`@last`) をメモリにしか持たないので、更新で bridge が起き直すと、その時に転送の
  アプリがネットワークにいる端末全部へ送り直し、いない端末へは転送のアプリが現れた時 (受け取り・送信・リモートシェルの
  どれかを入れた時) に送る。一覧の中身 (digest) も `rshell` が足されて変わる。手でする事は無い。Members の行が古い
  エラーのままなら、その端末は更新の後にネットワークに出ていない。
- 印「Remote shell from the console」を付けたら Apply が要る (台帳の行・ブラウザに転送の鍵が付く) ことを足した。
- **Gemfile.lock**: asterism 0.14.1 は rubygems に無い (`gem list -r asterism` は 0.14.0 まで。0.14.1 は asterism の
  リポジトリのタグだけ、差は ROS の橋だけ)。なので 0.14.0 のまま (変更は捨てた)。`git archive v0.14.0` を scratchpad に
  出して `ASTERISM_DIR` に指し、`env -u ASTERISM_CREDENTIALS bin/rails test` が 739 runs・0 failures。既定の
  `../asterism` (0.14.1) で流すと Bundler が lock を 0.14.1 に書き換えるので、試験の後に lock を戻す必要がある。
- **更新の手順**: 特別な手順は要らない。`update.sh` の setup (`--from-update`) がマイグレーションとルータの設定
  (`no_rshell_calls`) を書いて起こし直し、`env.example` の新しい設定は update.sh が「.env に無い設定」として並べる。
  `put` の upload は nginx の `client_max_body_size 300m` (Caddy は 300MB) で通る (1 回の `put` は 16 MB × 16 = 256 MB まで)。
- docs/terminal.md: 節の見出しの段の名前 (R3・R4) を版 (0.4.5) に、ブラウザ版の見え方を 1 項足した。
- 気付いた事 (変えていない): `deploy/vps/env.example` の `CONSOLE_VERSION=0.3.12` が古いまま (今までのリリースも
  変えていない。update.sh が書き換えるので更新には効かないが、新しく入れる人が写すと古い版を引く)。

## 7. 文書 (C)

- **置き場は `flash/usr/share/doc/remote_shell.md`・`remote_shell_ja.md`**。理由: リモートシェルを入れる・切るのは
  端末の持ち主で、その人が端末の上で読む案内は今 `/usr/share/doc/` に英語と日本語の対で置いている (wifi・display・
  kanji)。`/home` の案内 (`home*.md`) の一覧にも足した。doc/reference は開発者向けなので選ばなかった。console を使う
  側の説明は console の docs/terminal.md にある。
- 中身: 受け取りのアプリの「Remote shell」の意味と入れる人の条件 (シェルの一覧の「console から」・console の人ごとの
  許可・確かめられた接続)、「RS」の印と消える時 (exit・5 分)、見られる事・変えられる事・できない事、本体の領域、
  鍵の場所 (`/home/asterism`・`wifi.toml`・`secrets.toml` と、それを含むフォルダ)、切り方 (スイッチ・ブラウザ版はページを閉じる)。
- F1 のヘルプと sig: アプリから呼ぶ API (`FmrbReceiveConf.rshell_enabled?` ほか・`FmrbFile.secret_path?`) は R1・R2 で
  sig に入っており、今回足す所は無かった (変えていない)。
- doc/reference/app_memory.md: Modern・sim の large のプールを 2 つ (2 つ目は初めて使う時に取る)、ホストの版は枠ごと、
  転送のアプリが 1 つを持つことに直した (6 章の「同時に 1 本」も)。
