# Console から端末に入るリモートシェル

> 状態: 進行中 | 更新: 2026-11-26 | asterism-console の Terminal から、Asterism 越しに Family mruby の端末 (Tab5・P4-Nano・ブラウザ版) に入り、行ごとのコマンドでファイルの確認・出し入れとアプリの一覧・起動・停止をする。遠くにいる利用者のサポート用。段は R0〜R6、R0・R1 済 (端末の見るコマンドと補完、sim で確認)・R2 に着手

## 1. 目的

- 人に渡した端末のサポートを、相手の家の LAN に入らずにできるようにする。今の WiFi の遠隔操作 (devctl・リモート
  デスクトップ) は同じ LAN の中だけで、NAT の内側の端末には届かない。Asterism はルータ経由なので届く。
- 操作する側は **asterism-console の Terminal**。ブラウザがあればどこからでも入れ、console のログイン・権限・記録の
  下で動く。PC に gem や証明書を入れなくてよい。
- できる事は、ファイルの一覧・中身の確認・出し入れ (SCP に当たる)・削除や名前の変更、動いているアプリの一覧・停止・
  起動。
- doc/console_terminal の VT4 (端末の Shell に console から入る) と、doc/remote_guard の G3 (遠隔の操作の正式な経路を
  Asterism の認証の上に置く) の、最初の実装に当たる。

## 2. 今あるもの (2026-11-26)

| もの | 中身 | この計画での使い方 |
|---|---|---|
| console の Terminal (VT1・VT2 済) | asterism gem の CLI のコマンドを bridge の中で動かし xterm.js に流す。見るだけ / 何かを起こすの 2 段の権限、Call log への記録 | ここに「端末に入る」を足す |
| Asterism のファイル転送 (T0〜T8 済) | 再送つき・SHA-256 の照合。端末は転送のアプリ (画面なし) が受ける。console の Files ページ | ファイルの出し入れの中身に使う |
| 端末のシェル (`main/ruby/default_app/shell*`) | Window に結び付いたアプリ。コマンドの実装 (`ShellCommandsMixin`、約 2,100 行) は画面への出力・less・エディタの起動と一体 | そのままは使えない。画面なしで動くコマンドの実行部を別に持つ (R0 で切り出し方を決める) |
| 受け取りの許可 (`receive.toml`) | 持ち主が Config で ON、送ってよい相手は console の Members の表が端末へ配る | 同じ 2 重の形をリモートシェルにも使う |
| WiFi の遠隔操作の線引き (remote_guard G1・G2) | 鍵 (wifi.toml・secrets.toml・/home/asterism) は読めない | 鍵の扱いを揃える |

## 3. 方針 (決定 2026-11-26 ユーザ)

1. **行ごとのコマンド**。Terminal で端末に入るとプロンプトがその端末に替わり、1 行打つごとに端末で実行して結果の
   文字が返る。1 文字ごとの対話・全画面 (less・エディタ・irb) は無い。1 往復が VPS 経由で数十〜百ミリ秒台かかるので、
   この形なら遅れが気にならず、端末の側は画面なしで軽く動く。
   **Tab の補完は効かせる** (ユーザ 2026-11-26): コマンドの名前と、端末の中のファイル・フォルダの名前。Tab を押した
   ときだけ端末に聞くので、行ごとの形のまま足せる。
2. **できる範囲は 2 段**。console の今の権限 (見るだけ / 何かを起こす) と同じ分け方にする。
   - 見る: `pwd`・`cd`・`ls`・`cat`・`head`・`tail`・`stat`・`df` (空き容量)・`free` (メモリ)・`ps`・`ver`。
   - 変える: `cp`・`mv`・`rm`・`mkdir`・`get`・`put` (ファイルの出し入れ)・`kill`・`open` (アプリの起動)。
   - **任意の Ruby の実行 (`run`・irb) は最初の版に入れない**。
3. **入られる側の許可は 2 重**。端末の Config に「リモートシェル」(既定は切) を足し、持ち主が ON にする (閉じるまで
   残る)。入ってよい人は console の権限の表で決める。入られている間は端末の画面 (メニューバー) に印を出す。
4. **触れる場所は、鍵のほか全部**。鍵の 3 か所 (wifi.toml・secrets.toml・/home/asterism) は読めず、書けない。
   ほかは本体の領域 (/usr・/etc など) も含めて読み書きできる。本体の設定を遠くから直せる代わりに、誤って消すと起動
   しなくなる恐れがあるので、本体の領域への `rm`・`mv`・上書きは Terminal の側で一度確かめる (仮決め 3)。
5. **新しい通信の仕組みを作らない**。端末がオブジェクトを公開し、console がそのメソッドを呼ぶ。長い出力は続きを
   取りに行く形で分ける。ファイルの中身は今のファイル転送で運ぶ。
6. **console は OSS として配る前提を崩さない**。作者の環境 (アドレス・ノード名) を焼き込まない。違いは設定で吸収する。
7. **内蔵 RAM を増やさない**。端末の側は PSRAM (VM プール) の中で動かし、切のときは何も常駐させない。

## 4. 作る物の形

```
ブラウザ ── console (Terminal) ── bridge ══ Zenoh (ルータ) ══ 端末 <node>/<アプリ>/rshell
            権限・記録                 call exec("ls /home")        許可の確認 → 実行 → 文字を返す
```

- **端末の側**: 画面なしで動く部分が、オブジェクト `rshell` を公開する。
  - `open()` → セッションの番号と、今いる場所・端末の版。許可の確認 (ON か、呼んだノードが許されているか) はここと
    各呼び出しで行う。
  - `exec(id, line)` → `{"out" => 文字, "code" => 終了の値, "cwd" => 今いる場所, "more" => 続きの印}`。
  - `more(id, pos)` → 長い出力の続き (`cat` の大きいファイルなど)。上限を超える分は切って、その事を返す。
  - `complete(id, line, pos)` → 補完の候補 (`{"word" => 置き換える語の始まり, "items" => [候補...]}`)。フォルダは末尾に
    `/` を付ける。端末のシェルの Tab (`handle_tab`) と同じ決まり: 行の先頭はコマンドの名前、`open`・`kill` は
    アプリの名前、ほかはパス。鍵の場所の中身は候補に出さない。候補が多いときは数で切る。
  - `close(id)`。一定時間呼ばれなければ自分で閉じる (印も消える)。
  - 同時に入れるのは 1 セッション (仮決め 2)。
- **console の側**: Terminal に `remote <node>` (仮の名前) を足す。入るとプロンプトが `<node>:/home$` の形に替わり、
  打った行を bridge が `exec` に渡す。`exit` で戻る。Tab は `complete` を呼び、候補が 1 つなら入力に入れ、
  複数なら共通の頭まで入れて一覧を出す (手元のシェルと同じ動き)。Terminal の今の補完の仕組み (`__complete`) に、
  入っている間は端末へ聞く道を足す。
  - 見るコマンドは「見るだけ」の権限、変えるコマンドは「何かを起こす」権限 (Call permissions の表) で分ける。
    どちらに当たるかは console と端末の両方で確かめる (console を直さずに端末を呼ぶ道を残さない)。
  - 打った行と結果の要約を Call log に残す (だれ・いつ・どの端末・何を)。
  - `get <端末のパス>` はブラウザにファイルを落とす。`put` はブラウザで選んだファイルを端末の今いる場所へ置く。
    中身はファイル転送に乗せる (Files ページの仕組みを使う)。
- **許可の置き場**: `/home/asterism/` の下の設定 (受け取りの `receive.toml` と同じ作り: 持ち主が書く部分に ON/OFF、
  console が配る部分に入ってよいノード)。置き場と名前は R0 で決める。

## 6. 受け入れ条件

- R1: sim で `call <node>/.../rshell exec` に `ls /home`・`cat <ファイル>`・`ps` を渡すと、端末のシェルで打ったのと同じ
  中身が返る。鍵の 3 か所は `cat` でも `ls` の中身でも読めず、理由が返る。大きいファイルの `cat` が続きを取れて、
  上限で切れる。`complete` が、コマンドの名前・パスの途中・フォルダの中の候補を返す。変えるコマンドはまだ無い (知らないコマンドとして断る)。`rake regress` が通る。
- R2: Config が切のとき、端末にリモートシェルの部分が常駐せず、呼び出しは理由つきで断られる。ON にすると入れ、
  許されていないノードからは断られる。`rm`・`mv`・`cp`・`mkdir`・`kill`・`open` が効き、鍵の場所には書けない。
  入られている間だけメニューバーに印が出て、閉じる・時間切れで消える。内蔵 RAM の静的な増分 0。
- R3: ブラウザの Terminal で端末に入り、`ls`・`cd`・`cat`・`ps` が打てる。Tab でコマンドの名前とファイル名が補完され
  (候補 1 つは入力に入り、複数は一覧が出る)、空白のある名前も打てる形で入る。「見るだけ」の人は変えるコマンドを理由つきで
  断られる。打った行が Call log に残る。`exit`・ページを閉じる、でセッションが端末に残らない。
- R4: 端末のファイルをブラウザに落とせ、ブラウザのファイルを端末に置ける。内容が元と一致する (SHA-256)。
- R5: Tab5 か P4-Nano と、ブラウザ版で、VPS の console から入って上の操作が通る。リモートシェルを切のままにした
  端末の `regress:run`・`regress:size` の数が、始める前と変わらない (ON のときの増分は report に書く)。
- どの段も、console の既存の試験と asterism gem の試験が通る。gem の振る舞いを変えたら版を上げる。

## 7. R0 の後の決定 (2026-11-26。経緯は report/r0.md。上の章と食い違う所はここが正)

1. **端末の側は転送のアプリに足す**。オブジェクトは `<node>/transfer/rshell`。ソースは別のファイル
   (`flash/usr/share/transfer/rshell.rb`) で、ON のときだけ読む。console が一覧を配る先とルータの ACL が転送のアプリの
   ものなので、別のアプリにしない。
2. **スイッチは受け取りのアプリ** (ユーザ決定。3 章 3 の「Config」を変える)。`/home/asterism/receive.toml` の持ち主の部分に
   `rshell_enabled = true`。鍵の場所の下なので、リモートシェル自身からは書き換えられない。カーネルが転送のアプリを
   起こす条件に、このキーを足す。入ってよい console は、console が配る部分の種類 `rshell`。
3. **console では人ごとに許す** (ユーザ決定)。利用者ごとに「リモートシェル: なし / 見るだけ / 変えるまで」を admin が選ぶ。
   Terminal の今の決まり (読むのは誰でも) には乗せない。
4. **メソッド**: `open`・`exec_read(id, line)`・`exec_write(id, line)`・`more(id, pos)`・`complete(id, line, pos)`・
   `read(id, path, pos, len)`・`close(id)`。`exec_read` に変えるコマンドが来たら端末が断る。コマンドの表 (見る・変える) は
   端末が `open` の答えで返し、console はそれでどちらを呼ぶか決める。
5. **1 回の答えは 8 KB**、続きは `more`。1 コマンドの出力の合計は 64 KB まで (超える分は切って、その事を返す)。
   文字の切れ目は UTF-8 の境目。
6. **`get` は console が `read` で取りに来る**。`put` は今の転送で /home/inbox に置いた後、`exec_write` の `mv`。
7. **鍵の判定は C の `fmrb_path_classify` を Ruby に出して使う** (devctl と同じ決まり)。パスは `.`・`..` を畳んでから見る。
8. **コマンドは新しく書く** (シェルには触らない)。引用符 (`"a b"`・`a\ b`) を読む。Tab は、行の先頭はコマンドの名前、
   `open` はアプリのパス、`kill` は動いているアプリ、ほかはパス。
9. `kill`・`open` は「頼んだ」と返し、結果は続きで取る。Ctrl+C は呼び出しと呼び出しの間で効く。
10. 同時に入れるのは 1 セッション。呼ばれないまま 5 分で閉じる。
11. 本体の領域 (/home・/app・/mnt/sd・/tmp の外) への `rm`・`mv`・上書きは、console (bridge) が一度確かめる。
12. Terminal のコマンドの名前は `remote <node>`・`exit` (gem の表の外の語で、console が先に読む)。
13. 入られている間の印は、デスクトップにセルを 1 つ足し、カーネル経由で知らせる。
14. `regress:run` に転送のアプリが動く場面を足す (R2)。
15. (R1 の後) 切の端末には `rshell` を公開しない。呼び手に届く理由は gem の `no_object` で、console が「切か、端末が
    いない」と言い換える。
16. (R1 の後) 確かめられた接続 (tls/ のルータ、ブラウザ版は door の印) でだけ入れる。開発の確認用に、手で書く
    `rshell_uncertified = true` で外せる。
17. (R1 の後) 鍵の判定 `FmrbFile.secret_path?` は `/home/asterism` のフォルダ自体と、その中の全部を鍵として扱う。
18. (R1 の後) ON のときの転送のアプリの VM の増分は約 89 KB (sim)。切のときは +1.4 KB。転送のアプリの台本は 64 KB の
    上限に近いので、R2 でまとまりを別のファイルへ出す。

## 8. 未確定事項

1. ブラウザ版の相手の見分け方。ブラウザ版は利用者ごとの証明書でルータが名前を確かめる (T8)。開いている間しか
   入れないことと、ブラウザの中のファイル (IndexedDB) だけが相手になることを、Terminal の一覧でどう見せるか。
2. Files ページに「端末の中を見て選ぶ」画面を足すか (R4 で決める。Terminal の `get`・`put` だけで足りるか)。
3. 端末の側にも記録を残すか (だれがいつ入り、何を変えたか。持ち主が端末で見られる形)。flash への書き込みが増える。
4. 入られている間の印の見た目と、持ち主がその場で切る操作 (印を押すと切れる、など)。
5. リリースのビルドへの入れ方 (既定は切で入れるか、選べるビルドにするか)。remote_guard の G3 と合わせて決める。

## 9. ほかの計画とのつながり

- doc/console_terminal/plan.md: VT4 の一部を、この計画が受け持つ。
- doc/remote_guard/plan.md: G3 (Asterism に寄せる) の最初の実装。素の HTTP の口の扱いは remote_guard の側で決める。
- doc/asterism_file_transfer/plan.md: `get`・`put` の中身。受け取りの許可の作り (`receive.toml`) を手本にする。

- memory: Asterism は信頼できるメンバーだけの網。console は OSS で各自が導入する。
