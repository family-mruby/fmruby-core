# H0 報告: AtomS3R の確認と、H1 の設計の案

> 状態: 完了 (検収待ち) | 更新: 2026-10-12 | instruction_h0.md の記録。AtomS3R の flash 8 MB を全部保存し (sha256 つき、戻して照合済み)、公式の回路図と実物でピンの割り当てを照合した。**画面の制御 IC はこの個体では GC9107** (資料は ST7735。ライブラリは ID を読んで両方を扱う)、**RGB LED は載っていない** (LP5562 の R/G/B は配線なし、W が背光)、システムの I2C は SDA=G45 / SCL=G0。I2C の機器 (LP5562・BMI270・BMM150)、BMI270 の割り込み線 (G16)、ボタンの待機時の値は試しのファームで確かめた。H1 は Modern の描画の経路 (display_p4 + CPU の合成) を S3 で動かす案。sdkconfig の defaults・区画の表・system_conf のキーは案だけで、決めることを 8 章に並べた。止まる条件には当たらなかった

## 1. 結果の要約

- **保存**: 端末に入っていた 8 MB を全部読み出した。sha256 は
  `fc86ad91933fda4a7595214acf52e076dd9bf6ffd53d2c5160ccbb0966a32ecb`。試しのファームを焼いたあと、この像を書き戻して
  全域の照合 (verify_flash) が一致し、元のファームで起動することまで確かめた。**端末は受け取ったときと同じ状態に戻してある**。
- **入っていたのは M5Stack の出荷時のファームではなかった**。Family mruby の fmruby-core (ATOM_DISPLAY 構成、
  2026-03-25 のビルド、IDF v5.5.1) が入っていた。区画は今の `partitions_n8r8.csv` と同じ (factory 3M・storage 4900K)。
  M5Stack の出荷時のファームが要るなら、M5Stack の配布物から取り直す (この保存はそれの代わりにならない)。
- **ピン**: 公式の回路図で全部の線を追い、資料の表との食い違いを 4 件見つけた (3 章)。H1 を左右する割り当て (画面の SPI、
  背光、システムの I2C、ボタン) は回路図と実物で決まった。決まらなかったのはボタンを押したときの変化・赤外線・底面と Grove の
  線の導通で、どれも H1 の作りは左右しない。
- **H1 の描画**: Retro の描画の子マイコンの代わりに、Modern とブラウザ版が使っている端末の中で描く経路
  (`display_p4_task.cpp` + `display_backend_cpu.cpp` + `display_blend_cpu.c`) を S3 で動かすのがよい。128x128 なら
  PSRAM は 100 KB 程度で足りる。ただし今は「P4 である」(`FMRB_HW_MODERN`) と「描画を端末の中で行う」が同じ印で
  分岐しているので、後者を表す一般の印を足す必要がある (5.1)。
- **flash**: 今の Retro のファームは約 4.3 MB で、8 MB に「ファーム + 今の storage の木 (約 3.5 MB)」は入らない。
  外すための既存のビルドの選択肢は少ない (5.5)。区画の大きさと、何を外すかはユーザが決める (8 章)。

## 2. 出荷時の flash の保存と戻し方

### 2.1 置き場所

| 場所 | 中身 |
|---|---|
| `/home/kishima/fmrb/device_backup/atoms3r/` (どのリポジトリの外。消えない場所として作った) | `atoms3r_factory_8MB.bin`、`.sha256`、元のファームの起動ログ、試しのファームのログ |
| この作業の scratchpad の `h0/` | 同じ像と、1 MB ごとの断片、試しのファームの一式 |

- 像は 8,388,608 バイト、sha256 は上のとおり。コミットしない。ログには端末固有の値 (MAC) が出ているので、これもリポジトリに入れない。
- 読み出しは、921600 bps で 8 MB を一度に読むと途中で `Corrupt data` で止まった。既定の速度で 1 MB ずつ読むと 8 回とも
  1 回で通った (esptool は断片ごとに MD5 を照合する)。合わせて約 13 分。

### 2.2 戻し方

ビルド用の docker の像の esptool で、ポートを明示して書く。ポートを開くとチップはリセットされる。

```
docker run --rm --device /dev/ttyACM1 -v /home/kishima/fmrb/device_backup/atoms3r:/out \
  ghcr.io/family-mruby/fmruby-esp32-build:v5.5.4 bash -lc ". /opt/esp/idf/export.sh >/dev/null 2>&1; \
  esptool.py --chip esp32s3 --port /dev/ttyACM1 write_flash --flash_mode keep --flash_size keep 0x0 /out/atoms3r_factory_8MB.bin && \
  esptool.py --chip esp32s3 --port /dev/ttyACM1 verify_flash 0x0 /out/atoms3r_factory_8MB.bin"
```

- 2026-10-12 にこの手順で書き戻し、`verify OK (digest matched)` を確認した (書き込み約 1 分、照合を含め数分)。
- AtomS3R の USB の ID は Tab5 と同じ `303a:1001`。`/dev/ttyACM*` の番号は繋ぎ方で変わるので、書く前に
  `/sys/class/tty/ttyACM*/device/../idProduct` などで確かめる。

### 2.3 元のファームの起動の様子 (記録)

- ROM → 2nd stage → app。bootloader が QIO・80 MHz に切り替えて起動する (像の見出しは DIO、bootloader が QIO を有効にする)。
- Octal PSRAM を検出: 製造元 AP、第 3 世代、64 Mbit (8 MB)、3 V、80 MHz。メモリ試験は約 0.4 秒。
- 起動の直後の内蔵 RAM の空き (heap_init): 243 KiB + 21 KiB + 32 KiB (DRAM) + RTC 7 KiB。
- M5GFX の自動判別が `board_M5AtomS3R (GC9107)` を出した。画面の ID を SPI で読んで判別しているので、画面の SPI の線
  (CS=G14、SCK=G15、MOSI=G21、DC=G42、RST=G48) が正しい証拠になる (3 章の「実物」の印の根拠)。
- ATOM_DISPLAY 向けなので HDMI の相手 (Atom Display) を探して失敗し、I2C キーボードを Grove の線 (G2/G1) で探して NACK を
  出し続ける。カーネルは起動し、デスクトップを spawn するところまでは進む。

コード、**実** = 実物で確かめた (方法は 3.2)。

### 3.2 実物での確かめ方

ESP-IDF の最小の試しのファーム (Family mruby ではない。scratchpad の `h0/probe/`) を焼き、USB-Serial/JTAG に結果を出した。

| 確かめたこと | 方法 | 結果 |
|---|---|---|
| チップ・flash・PSRAM | `esp_chip_info` / `esp_flash_get_size` / `esp_psram_get_size` | rev v0.2、flash 8 MB (QIO で起動)、PSRAM 8 MB (Octal で起動) |
| 素の IDF の内蔵 RAM | `heap_caps_get_free_size(INTERNAL)` | 空き 381,595 B、最大の塊 286,720 B (WiFi・BLE なし) |
| システムの I2C | SDA=G45 / SCL=G0 で 0x08〜0x77 を走査 | **0x30、0x68 の 2 個だけ** |
| BMI270 | 0x00 を読む | 0x24 |
| BMI270 INT1 = G16 | INT1 を出力にして active の向きだけを反転 (割り込みは何も割り当てない) | active-high で G16=0、active-low で G16=1。線が G16 につながっている |
| BMM150 | BMI270 の補助 I2C を手動で使い、BMM150 の電源ビットを入れて 0x40 を読む | 0x32 |
| LP5562 | 有効化・内部クロック・I2C 制御に設定し、W の PWM を 0x00/0xFF/0x40/0xC0 と書いて読み戻す | 全部読み戻せた。R/G/B も書けるが回路図では出力が配線されていない |
| Grove | G2/G1 に内部プルアップで走査 | 0 件 (何も繋いでいない) |
| ボタン | G41 を 20 秒見る | 待機時 1、変化 0 回 (誰も押していない) |
| 画面の SPI | 元のファームの M5GFX が ID を読んだ記録 (2.3) | GC9107 を認識 |

- 背光の明るさが目で見て変わるか、緑の LED がどう光るか、ボタンを押したときの値は、人の目と指が要るので**ユーザの確認待ち**。

### 3.3 資料どうしの食い違い

1. **画面の制御 IC**: 製品の文書は ST7735。この個体は GC9107 (実物の ID)。公式のライブラリは製造の時期で両方あるものとして
   ID で選んでいる。H1 は ID を読んで選ぶ形にする (どちらかに決め打ちしない)。
2. **RGB LED**: 製品の文書と plan.md は「RGB LED (LP5562)」。回路図では LP5562 の R/G/B 出力 (LED_R/G/B) は相手の無い線で、
   **RGB LED は載っていない**。LP5562 は W 出力で画面の背光を駆動するためにある。plan.md の H4 の「LED を Asterism の
   オブジェクトにする」は、背光の明るさか、別の LED (後付け) のどちらかに読み替える必要がある。
3. **ピンの表の重複**: 製品の文書の表はセルが結合されていて、読み方によって列がずれる。ずれて読むと G0 が「画面の CS」と
   「システムの I2C の SCL」の両方に、G48 が「背光」と「画面のリセット」の両方に、G21 が「DC」と「MOSI」の両方に出てくる
   (plan.md の「重複」はこれ)。回路図とライブラリは一致していて、正しいのは 3.1 の表 (CS=G14、SCK=G15、MOSI=G21、
   DC=G42、RST=G48、背光は LP5562 の W、SCL=G0)。
4. **表に無いもの**: BMI270 の INT1 (G16)、BMM150 の番地 (0x10)、PMS150G と緑の LED。PMS150G は SCL (= G0) と
   ESP_EN と緑の LED につながっている。G0 の Low を見て緑を点ける、あるいはリセットの補助をするものと読めるが、中身は
   資料に無い。システムの I2C の通信のたびに緑の LED が明滅するかもしれない (目で確かめる)。

## 4. `fmrb_pin_assign.h` の ATOMS3R の分岐の案

組み込まない (H1 で入れる)。全部の分岐が同じマクロの名前を持つ決まり (ヘッダの冒頭のコメント) に合わせ、既存の名前は全部定義する。
新しい名前 (画面の SPI、IMU の割り込み、赤外線) は案。

```c
// ============================================================
// Pin assignments for M5Stack AtomS3R (ESP32-S3-PICO-1-N8R8, headless S3)
// Checked against the board schematic and on the device (doc/headless_s3/report/h0.md).
// No WROVER, no SD slot, no USB host: the USB-C port is the S3's own
// USB-Serial-JTAG (console + flashing).
// ============================================================
#elif defined(FMRB_HW_ATOMS3R)

// Restricted pins
#define FMRB_PIN_RESTRICTED_BOOT    GPIO_NUM_NC  // GPIO0 is the system I2C SCL (see below)
#define FMRB_PIN_RESTRICTED_JTAG    GPIO_NUM_NC  // GPIO3 is not bonded out
#define FMRB_PIN_RESTRICTED_USB_DN  GPIO_NUM_19  // USB-Serial-JTAG console
#define FMRB_PIN_RESTRICTED_USB_DP  GPIO_NUM_20
#define FMRB_PIN_RESTRICTED_PSRAM0  GPIO_NUM_35  // in-package octal PSRAM (33-37)
#define FMRB_PIN_RESTRICTED_PSRAM1  GPIO_NUM_36
#define FMRB_PIN_RESTRICTED_PSRAM2  GPIO_NUM_37
#define FMRB_PIN_RESTRICTED_STRAP1  GPIO_NUM_NC  // GPIO45 is the system I2C SDA; VDD_SPI fixed by eFuse
#define FMRB_PIN_RESTRICTED_STRAP2  GPIO_NUM_46  // strap, not bonded out

// System I2C: LP5562 (0x30, LCD backlight on its W output) + BMI270 (0x68,
// BMM150 behind its aux port). 2.2K pull-ups on the board.
#define FMRB_PIN_I2C1_SDA      GPIO_NUM_45
#define FMRB_PIN_I2C1_SCL      GPIO_NUM_0
// Grove (HY2.0-4P): connector pin 1 = GPIO1, pin 2 = GPIO2. No pull-ups.
#define FMRB_PIN_I2C2_SDA      GPIO_NUM_2
#define FMRB_PIN_I2C2_SCL      GPIO_NUM_1

// LCD: GC9107 or ST7735S (lot-dependent, told apart by the panel ID),
// 128x128, 3-wire SPI (no MISO).
#define FMRB_PIN_LCD_SPI_MOSI  GPIO_NUM_21
#define FMRB_PIN_LCD_SPI_SCLK  GPIO_NUM_15
#define FMRB_PIN_LCD_SPI_CS    GPIO_NUM_14
#define FMRB_PIN_LCD_SPI_DC    GPIO_NUM_42
#define FMRB_PIN_LCD_SPI_RST   GPIO_NUM_48
#define FMRB_PIN_LCD_BACKLIGHT GPIO_NUM_NC   // LP5562 W channel, not a GPIO

#define FMRB_PIN_IMU_INT       GPIO_NUM_16   // BMI270 INT1
#define FMRB_PIN_IR_TX         GPIO_NUM_47
#define FMRB_PIN_BUTTON_ENTER  GPIO_NUM_41   // active low, 10K pull-up

// Bottom headers (not claimed by the system): 1x5 = 3V3, G5, G6, G7, G8;
// 1x4 = G39, G38, 5V, GND.

// Not on this board
#define FMRB_PIN_SD_CS         GPIO_NUM_NC
#define FMRB_PIN_SD_MOSI       GPIO_NUM_NC
#define FMRB_PIN_SD_SCLK       GPIO_NUM_NC
#define FMRB_PIN_SD_MISO       GPIO_NUM_NC
#define FMRB_PIN_SD_DETECT     GPIO_NUM_NC
#define FMRB_PIN_GFX_SPI_MOSI  GPIO_NUM_NC
#define FMRB_PIN_GFX_SPI_MISO  GPIO_NUM_NC
#define FMRB_PIN_GFX_SPI_SCLK  GPIO_NUM_NC
#define FMRB_PIN_GFX_SPI_CS    GPIO_NUM_NC
#define FMRB_PIN_GFX_SPI_INTR  GPIO_NUM_NC
#define FMRB_PIN_GFX_UART_TX   GPIO_NUM_NC
#define FMRB_PIN_GFX_UART_RX   GPIO_NUM_NC
#define FMRB_PIN_GFX_UART_RTS  GPIO_NUM_NC
#define FMRB_PIN_GFX_UART_CTS  GPIO_NUM_NC
#define FMRB_PIN_USB_POWER     GPIO_NUM_NC
#define FMRB_PIN_STATUS_LED    GPIO_NUM_NC   // the green LED is driven by a helper MCU
#define FMRB_PIN_ERROR_LED     GPIO_NUM_NC
#define FMRB_PIN_WROVER_RESET  GPIO_NUM_NC
#define FMRB_PIN_BUTTON_UP     GPIO_NUM_NC
#define FMRB_PIN_BUTTON_DOWN   GPIO_NUM_NC
#define FMRB_PIN_KBD_I2C_SDA   GPIO_NUM_NC
#define FMRB_PIN_KBD_I2C_SCL   GPIO_NUM_NC
#define FMRB_PIN_KBD_INT       GPIO_NUM_NC
#define FMRB_PIN_TOUCH_I2C_SDA GPIO_NUM_NC
#define FMRB_PIN_TOUCH_I2C_SCL GPIO_NUM_NC
#define FMRB_PIN_TOUCH_INT     GPIO_NUM_NC
```

- 置く場所は Retro (N16R8) の既定の分岐 (`#elif !defined(FMRB_HW_ATOM_DISPLAY)`) より前。そうしないと Retro の分岐に吸われる。
- **G0 を RESTRICTED_BOOT にしない**理由: 制限のピンは pin manager が `SYSTEM_EXCLUSIVE` にするので、アプリが I2C の unit 1
  (システムの I2C) を開くときに衝突しうる。G0 はこの端末ではシステムの I2C として常に使うピンで、strap の役目はプルアップで
  満たされている。G45 も同じ。
- Octal PSRAM は G33〜G37 の 5 本を使うが、マクロの枠は 3 つ (Retro の N16R8 も同じく 35〜37 だけ)。G33/G34 は外に
  出ていないので実害はない。枠を増やすかは別件。
- 画面の SPI のピンを新しい名前にするか、既存の `FMRB_PIN_GFX_SPI_*` (Retro の子マイコンへの SPI) を流用するかは決めること
  (8 章)。意味が違うので新しい名前を勧める。

## 5. H1 の設計の案

### 5.1 描画: 端末の中で描く経路を S3 で使う

**今の形**

| 端末 | 描画の経路 |
|---|---|
| Retro (N16R8) | GFX のコマンドを UART で子マイコン (WROVER) へ送り、向こうで描く |
| Modern (P4) | 同じコマンドを `fmrb_hal_link_local.c` (プロセス内の Message Buffer) で `display_p4_task.cpp` に渡し、canvas (RGB332 の LGFX_Sprite、PSRAM) を合成して RGB565 の framebuffer にし、PPA で拡大して画面へ |
| ブラウザ版 | P4 と同じ `display_p4_task.cpp` を使い、合成は `display_blend_cpu.c` (IDF に依存しない C)、出力は `display_backend_wasm.cpp` |
| ATOM_DISPLAY (中断中) | `m5gfx_task.cpp`。Atom Display の FPGA の裏画面を canvas に使う作りで、小さい内蔵画面には使えない |

**案**: AtomS3R は P4・ブラウザ版と同じ `display_p4_task.cpp` を使い、合成は CPU の backend (`display_backend_cpu.cpp` +
`display_blend_cpu.c`)、出力は LovyanGFX の SPI の画面 (GC9107 / ST7735S)。ブラウザ版がこの組み合わせ (PPA なし・CPU の合成)
が動くことを既に示している。`m5gfx_task.cpp` は使わない。

- **色の形**: コマンドは RGB332、canvas は RGB332 の sprite、framebuffer は RGB565 (今のまま)。画面へは framebuffer の
  RGB565 をそのまま送る。今の framebuffer は「PPA の並び (バイトを入れ替えない RGB565)」で、SPI の画面は上位バイトが先なので、
  送るときに入れ替える (LovyanGFX の `pushImage` の色の形を `rgb565_nonswapped` と指定すれば中で入れ替える)。
- **送り**: 128x128x2 = 32 KB。SPI 40 MHz で約 6.5 ms/枚 (ライブラリの既定の速さ)。拡大は 1 倍 (`display_scale_for` が 1 を返す)。
  cursor の小さい塗り (`present_patch`) はそのまま使える。
- **メモリ**: framebuffer 32 KB、canvas 1 枚につき 16 KB x 2 (committed と作業用)。デスクトップを出さない単一アプリなら canvas は
  1〜2 枚で、PSRAM は合わせて 100 KB 程度。全画面の高解像度 (640x360、460 KB) は使われたときだけ確保される作りなので、
  128x128 の端末では使わない設定にする (アプリが要求しても断る)。表示の task の stack は内蔵 RAM に 16 KB
  (`FMRB_DISPLAY_P4_TASK_STACK_SIZE`)。代わりに Retro の UART の link の task と USB host の task が無くなる。差し引きは H1 で測る。
- **背光**: LP5562 はシステムの I2C (G45/G0) にあり、BMI270 と同じ線。P4 では「表示の driver が内部の I2C を持ち、アプリの
  unit 1 の I2C は表示の driver の直列化された I2C の窓口を通す」作り (`hw_proxy_i2c.c` の `HW_PROXY_I2C_MEDIATED_*`) が既に
  あるので、それをそのまま使う。ただしこの分岐は今 `CONFIG_IDF_TARGET_ESP32P4` で書かれている。
- **画面のクラス**: `lgfx_tab5.hpp` / `lgfx_naryav4.hpp` と同じ並びで `lgfx_atoms3r.hpp` を作る。ID を読んで GC9107 か
  ST7735S を選ぶ (ライブラリの自動判別の処理と同じ)。背光は自前の ILight で、上の I2C の窓口から LP5562 の W に書く
  (ライブラリの自動判別をそのまま使うと、ライブラリが自分の I2C の driver で同じ線を掴み、BMI270 を使うアプリと衝突する)。
- **起動の画面**: `draw_boot_screen` は 1280x720 向けの文字の並び (「CPU: ESP32-P4」など) を直接画面に書いている。
  128x128 では文字が収まらない。起動の速さの要件 (長い黒画面で隠さない) を守るため、小さい画面向けの数行の版を画面の
  大きさで選ぶ形にする (端末の名前ではなく画面の大きさで分ける)。

**直す必要のある分岐 (今は「P4」と「描画を端末の中で行う」が同じ印)**

| 場所 | 今の条件 | 必要なこと |
|---|---|---|
| `components/fmrb_hal/CMakeLists.txt` | local link は ATOM_DISPLAY か esp32p4 | ATOMS3R も local link に |
| `main/CMakeLists.txt` | `display_p4/*` は esp32p4 の枝の中 | 端末の中で描く構成なら S3 でも入れる。PPA の backend は P4 だけ |
| `display_p4_task.cpp` | `#ifndef FMRB_PLATFORM_WASM` で `driver/ppa.h`・`esp_cache_private.h`・Tab5 の I2C を入れる | PPA の部分を「PPA がある」印で分ける。Tab5 の I2C の定義は `!FMRB_HW_NARYAV4` で書かれているので、Tab5 の印で分ける |
| `display_p4_task.cpp` の JPEG (EXPORT_FRAME) と `display_p4_video.cpp` | P4 の JPEG のハードウェア | ブラウザ版の `rd_encoder_stub.c` / `display_video_wasm.c` と同じく、無い端末向けの空の実装を使う |
| `main/boot/boot.c` | `FMRB_HW_MODERN` で display を起動、`#else` で `reset_wrover()`、`#ifndef FMRB_HW_ATOM_DISPLAY` で USB host | 端末の中で描く構成なら display を起動し、WROVER のリセットはしない。USB host は無い |
| `hw_proxy_i2c.c` | `CONFIG_IDF_TARGET_ESP32P4` で unit 1 を表示の driver に回す | 「表示の driver が I2C1 を持つ」端末で回す |
| `fmrb_hw_defines.cmake` | S3 は ATOM_DISPLAY か Narya v3 | `FMRB_HW_ATOMS3R` と、WiFi あり (`FMRB_HAS_WIFI`) |
| `rakelib/build.rake` と `cmake/check_storage_inputs.cmake` | 端末の表 (2 か所で同じ表) | ATOMS3R の行 (sdkconfig / system_conf) |
| `fmrb_rtc.c` | NARYA v4 は RTC が無いので読まない | AtomS3R も RTC が無い (0x32 に機器が無いことは走査で確認済み) |

- 印の名前は案: `FMRB_HAS_LOCAL_DISPLAY` (描画を端末の中で行う。P4 2 機種・AtomS3R)、`FMRB_HAS_PPA` (P4 だけ)。
  どちらも「ヘッドレス専用」ではなく、端末の性質を表す一般の印。今 `FMRB_HW_MODERN` で書いてある分岐のうち、描画に
  関わるものだけを前者に置き換える。

### 5.2 区画の表 (8 MB)

| 区画 | 今の n8r8 | 今の n16r8 (Retro) | 案 A (勧める) | 案 B |
|---|---|---|---|---|
| nvs | 24K @0x9000 | 24K | 24K | 24K |
| phy_init | 4K | 4K | 4K | 4K |
| factory | 3M | 6M | **5M** (0x10000〜0x510000) | 4608K (0x10000〜0x490000) |
| storage | 4900K | 5M | **3008K** (0x510000〜0x800000) | 3520K (0x490000〜0x800000) |

- ファームの大きさの見込み: 今の Retro のファームは 6M の区画で空き 28% (Spinel の上流取り込みの後の実測) なので約 4.3 MB。
  zenoh と Asterism で +100 KB 前後 (P4 の実測の増分から)。代わりに USB host と HID、UART の link が抜け、描画の側
  (display_p4、LovyanGFX の一部、fonts) が入る。差し引きは H1 で `idf.py size-components` で測る。
- storage の木は今 3.5 MB (`flash/` の du。`app` 1.5M、`usr` 1.4M、`help` 440K)。**案 A では今の木が丸ごとは入らない**。
  案 B なら木はほぼ入るが、ファームの空きが 5% 前後しか残らず、H3 (zenoh) で溢れる見込み。
- どちらにしても、storage に積むものを端末ごとに絞る仕組みが要る。今あるのは「Retro の像からサービスを抜く」1 か所だけ
  (トップの CMakeLists の storage_staging)。これを一般化して「端末ごとに像から抜く一覧」(例: `config/storage_exclude_<端末>.txt`)
  にするのが案。ヘッドレス専用の分岐ではなく、Retro のサービスの除外もこの一覧に移せる形。
- 区画の表を変えた端末は、app だけの書き込みでは更新できない (全体の書き込み、/home が消える)。既存の表と同じ注記を付ける。

### 5.3 `sdkconfig.defaults.atoms3r` の案 (Retro の n16r8 との差分)

n8r8 は ATOM_DISPLAY 向けで止まっているので、生きている n16r8 を元にする。**ファイルは作っていない**。

```diff
-CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="config/partitions_n16r8.csv"
-CONFIG_PARTITION_TABLE_FILENAME="config/partitions_n16r8.csv"
+CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="config/partitions_atoms3r.csv"
+CONFIG_PARTITION_TABLE_FILENAME="config/partitions_atoms3r.csv"

-CONFIG_ESPTOOLPY_FLASHSIZE="16MB"
-CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y
+CONFIG_ESPTOOLPY_FLASHSIZE="8MB"
+CONFIG_ESPTOOLPY_FLASHSIZE_8MB=y
 # flash: QIO / 80m のまま (実物は GD の quad、3.3 V。QIO 80 MHz で起動することを確認済み)
 # PSRAM: SPIRAM_MODE_OCT / SPEED_80M のまま (実物は Octal、AP の 3 V、80 MHz で起動することを確認済み)

+# Console on the S3's own USB-Serial-JTAG (the only USB port; no USB-UART bridge).
+CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y

-# USB Hub Support
-CONFIG_USB_HOST_HUBS_SUPPORTED=y
+# (no USB host: the OTG PHY is the console's)

 # BT: 8 章の決めごと 3 による。残すなら n16r8 と同じ。外すなら
+# CONFIG_BT_ENABLED=n
```

- `CONFIG_SPI_MASTER_ISR_IN_IRAM=y` は画面の SPI にも効くので残す。`FATFS_LFN` は SD が無いので効かないが、無害なので揃えて残す。
- USB-Serial/JTAG をコンソールにすると、Retro の UART0 の前提 (シリアルの MCP ツールの読み方) は Tab5 と同じ扱い (ポートを
  開くとリセット) になる。2 章のとおり実際に開くたびにリセットがかかった。

### 5.4 system_conf の案 (全端末で使えるキー)

新しいキーは 2 つ。どちらも既存の `startup_app` と組み合わせる。

```toml
# What the machine runs at boot. "desktop" (default) is the ordinary desktop,
# launcher and windows; "app" runs startup_app alone, full screen, with no
# desktop -- for a machine that exists to run one thing. Any machine can be
# set this way; a board without a usable screen is set this way by default.
boot_mode = "desktop"
startup_app = ""
# boot_mode = "app": how many times an app that dies is started again before
# the machine gives up and shows why (on the screen and on the serial log).
# 0 = never restart.
startup_app_retries = 3
```

- 名前の流儀: 既存のキーは `snake_case`、真偽は `*_auto_start`、数は単位を接尾 (`app_spawn_margin_kb`)。`boot_mode` を
  文字列にしたのは、後で H5 の「小さい画面向けのデスクトップ」を `boot_mode = "mini_desktop"` のように同じキーで足せるため。
  真偽 (`desktop = false`) より拡げやすい。
- 中身: カーネル (`fmrb_kernel.rb`) が `system/desktop` を spawn する所で `boot_mode` を見て、`"app"` なら `startup_app` を
  全画面で spawn し、HID の宛先をそのアプリにする。死んだら、サービスホストの再 spawn の勘定 (`note_service_host_death`) と
  同じ形で数え、`startup_app_retries` を超えたら止めて、表示の側に理由を 1 枚描く。
- AtomS3R の `system_conf_atoms3r.toml` の値の案: `display_width = 128`、`display_height = 128`、`display_margin_x/y = 0`、
  `default_user_app_width/height = 128`、`display_mode = "spi_lcd"` (新しい値。今の `display_mode` はログに出すだけで分岐には
  使われていない)、`boot_mode = "app"`、`boot_splash = false`、`ble_auto_start = false`、`wifi_auto_start = true` (H2 から)、
  `language = "en"`、`audio_mute = true`、`[[shortcuts]]` と `[[launcher_exclude]]` は無し。
- 試しのアプリの置き場: 単一アプリの既定は `/home/app/main.app.rb` のような /home の下が自然だが、/home は空で出荷する決まり
  なので、H1 の試しのアプリは `/usr/share/samples/` かファームに同梱のものにする。

### 5.5 外すもの

| もの | 既存の選択肢 | 外せるか |
|---|---|---|
| デスクトップ・ランチャー | `boot_mode = "app"` (案) | 実行時に動かさないだけ。ファームには残る |
| 起動のロゴと音 | `boot_splash = false` | 外せる (実行時) |
| 音 (APU) | 選択肢なし | ブラウザ版の `audio_backend_wasm.c` と同じ形の「音を出さない backend」を使い、APU の task を起動しない (コードは残る) |
| 遠隔デスクトップ (Modern) | S3 にはもともと入らない | — |
| 開発用の遠隔操作 (`/fs/*`・`/app/*`) | `FMRB_DEV_REMOTE_CTL` | H2 で使うので**残す** |
| FFT の Spinel 版 | `FMRB_FFT_SPINEL=0` | 外せる |
| SpinelHello・raycast の gem | 無し (常に入る) | 外せない |
| Lua・BASIC・MicroPython | 無し (`main/CMakeLists.txt` の REQUIRES に常に入る) | 外せない |
| 日本語のフォント・ヘルプ・サンプル・ランチャーの絵 | 無し (`flash/` を丸ごと像にする) | 外せない (5.2 の一覧の案) |
| USB host・HID | ATOM_DISPLAY の分岐で抜いていた | ATOMS3R の分岐で抜く (ボードの事情なので許される範囲) |

- **既存の選択肢で外せるものはほとんど無い**。言語を外すには、全端末で使える一般のビルドの選択肢 (例: `FMRB_LANG_LUA` /
  `FMRB_LANG_BASIC` / `FMRB_LANG_MICROPYTHON`、既定 ON) を足すことになる。これは「外すための専用の分岐を増やさない」の
  解釈に関わるので、ユーザが決める (8 章)。どれだけ減るかは H1 の最初のビルドで `idf.py size-components` で測ってから決めるのがよい。

### 5.6 ボード固有として書くもの

ボード固有として書くのは次だけに収まる見込み。

- `fmrb_pin_assign.h` の ATOMS3R の分岐 (4 章)
- `lgfx_atoms3r.hpp` (画面の SPI と ID での選択、LP5562 の背光)
- `config/sdkconfig.defaults.atoms3r`、`config/partitions_atoms3r.csv`、`config/system_conf_atoms3r.toml`、端末の表の 1 行
- `fmrb_hw_defines.cmake` の印 (`FMRB_HW_ATOMS3R` と、それが持つ一般の性質の印)

それ以外 (local link、端末の中で描く経路、I2C の窓口、単一アプリの起動、storage の除外の一覧、言語の選択肢) は一般の印や設定と
して書く。**ボタンを入力にする仕組み** (G41 を何のキーにするか) は H1 には要らない。H4 で Asterism のオブジェクトにするか、
一般の「GPIO のボタンをキーとして扱う」設定にするかを決める。

### 5.7 H1 の段の分け方と、各段で測るもの

| 段 | 内容 | 測るもの |
|---|---|---|
| H1a | 構成だけを作る: `FMRB_HW_TARGET=ATOMS3R`、区画・sdkconfig・system_conf、pin の分岐、local link、USB host なし、RTC なし。表示の task は動かすが画面は無し (ブラウザ版の「画面の無い LGFX_Device」と同じ) で、カーネルの版の確認に答えるだけ | USB-Serial/JTAG にログが出る、起動の時間、`M1|` 行の内蔵 RAM、`idf.py size-components` とファームの空き、Retro と Tab5 のビルドが通る |
| H1b | 画面: `lgfx_atoms3r.hpp`、CPU の backend、RGB565 の送り、LP5562 の背光、小さい起動の画面 | 電源を入れてから最初の画素までの時間、present 1 回の時間、試しのアプリの描画 (ユーザの目視) |
| H1c | 単一アプリ: `boot_mode` と `startup_app_retries`。sim と Retro / Tab5 でも同じ設定が効くことを確かめる | 試しのアプリが全画面で動く、わざと落ちるアプリで 3 回起動し直して止まり、理由が画面とログに出る |
| H1d | 外す: 8 章で決まったものを外し、storage の除外の一覧を入れる | flash の残り (ファームと storage)、内蔵 RAM の残り (WiFi はまだ上げない。H2 の基準値) |

- 画面の無い H1a を先に置くのは、描画が無くてもカーネルが起動しログが出るところで、区画・コンソール・PSRAM・内蔵 RAM の
  問題を描画の問題と分けるため。
- 共通の部分 (local link の条件、`display_p4_task.cpp` の分岐、`hw_proxy_i2c.c`、boot.c) を変えるので、各段で Retro (N16R8) と
  Tab5 のビルド、Tab5 の起動を確かめる (既存の端末の内蔵 RAM を増やさない)。

## 6. 端末の状態

- 2026-10-12 の終わりの時点で、AtomS3R (`/dev/ttyACM1`) は**受け取ったときの 8 MB を書き戻した状態** (全域の照合が一致し、
  元のファームで起動した)。試しのファームは残っていない。
- P4-Nano (`/dev/ttyACM0`) には触っていない。

## 7. 気づき

- AtomS3R の USB-Serial/JTAG も Tab5 と同じく、ポートを開くとチップがリセットされる (`rst:0x15 USB_UART_CHIP_RESET`)。
  シリアルは開きっぱなしで使う運用がこの端末にも当てはまる。
- esptool の `read_flash` は USB-Serial/JTAG で高い速度を指定すると途中で壊れる。既定の速度で区切って読むと安定した。
- 素の IDF (WiFi・BLE なし) の内蔵 RAM の空きは 381,595 B。今の Retro の構成から何がどれだけ使うかを H1a で比べる基準にする。
- システムの I2C の SCL が G0 (BOOT の strap) なので、I2C の機器が SCL を Low に保持したままリセットされると、ダウンロード
  モードで止まる可能性がある (プルアップは 2.2 kΩ)。起こったら、この理由を先に疑う。

## 8. ユーザが決めること

1. **区画の大きさ**: 案 A (factory 5M・storage 3008K、storage の木を絞る) か 案 B (4608K・3520K、木はほぼそのまま、ファームの
   空きは 5% 前後)。勧めは A。
2. **storage を端末ごとに絞る仕組み**: 端末ごとの除外の一覧 (5.2) を一般の仕組みとして足してよいか。何を外すか
   (ヘルプ・サンプルのアプリ・日本語のフォントなど)。
3. **BLE**: AtomS3R のファームに BLE (NimBLE) を残すか (最初の WiFi の設定にだけ使う道を残す) か、外すか
   (`CONFIG_BT_ENABLED=n`。flash と内蔵 RAM が浮くが、`ble_task` がビルドに常に入っているので、外すにはビルドの条件も要る)。
   WiFi の最初の設定を USB のシリアルで入れるなら外せる。
4. **言語を外す一般のビルドの選択肢** (`FMRB_LANG_*`) を足してよいか。plan.md の「アプリの言語: mruby を基本に、余裕があれば
   MicroPython」と合わせ、どれを AtomS3R で外すか。決めるのは H1a の `size-components` の後でもよい。
5. **system_conf のキー**: `boot_mode = "desktop" | "app"` と `startup_app_retries` (5.4) でよいか。名前の別案は
   `desktop = false` / `startup_app_restart_limit`。
6. **印の名前**: `FMRB_HAS_LOCAL_DISPLAY` / `FMRB_HAS_PPA` (5.1) と、`FMRB_HW_FAMILY` の扱い (AtomS3R は "retro" か
   "modern" か、別の値か。フォントの有無やサービスホストの可否がこの値で決まっている。描画の経路は Modern と同じ、チップは
   Retro と同じ)。
7. **画面の SPI のピンの名前**: 新しい `FMRB_PIN_LCD_SPI_*` を足すか、既存の `FMRB_PIN_GFX_SPI_*` を流用するか (勧めは新しい名前)。
8. **H4 の「LED」**: RGB LED は載っていない (3.3 の 2)。H4 で公開するのは背光の明るさにするか、Grove や底面に LED を足す前提にするか。
9. **目で確かめること** (H1 の前でも後でもよい): ボタンを押したときに G41 が Low になること、背光の明るさが LP5562 の W で
   変わること、緑の LED がシステムの I2C の通信で明滅するか。
