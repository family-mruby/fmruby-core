# H1 報告: 構成 ATOMS3R でビルドして起動する

> 状態: 完了 (検収待ち、画面の目視はユーザ) | 更新: 2026-10-12 | instruction_h1.md の記録。`FMRB_HW_TARGET=ATOMS3R` で AtomS3R が起動し、128x128 の画面 (GC9107) に端末の中で描いた絵を出し、`boot_mode = "app"` で 1 本のアプリだけを全画面で動かす。落ちたアプリは 3 回まで起動し直し、それでも落ちたら止めて理由を画面とログに出す (端末と sim の両方で確認)。**ただし標準の構成 (Spinel のエディタ) のままでは factory 5M に 211 KB 入らない**。既存の選択肢 `FMRB_APP_ENGINE_EDITOR=mruby` と `FMRB_FFT_SPINEL=0` を付けてビルドすると入り、空きは 4%。何を外すか (フォント・言語・エンジン) は 8 章でユーザが決める

## 1. 結果の要約

- **起動**: 電源 (リセット) から app_main まで約 1.42 秒 (bootloader と PSRAM の試験 0.4 秒を含む)。そこから画面の初期化が終わって起動の画面が出るまで +0.30 秒 (**最初の画素は約 1.7 秒**)、アプリが自分の画面を作るまで +0.77 秒 (**アプリの最初の絵は約 2.2 秒**)。
- **描画**: present 1 回 (CPU の合成 + SPI で 128x128x2 = 32 KB を送る) は平均 10 ms、最大 16 ms。
- **内蔵 RAM**: 起動の直後 329,908 B 空き。カーネル・試しのアプリ・debugd が立った後 214,888 B (最大の塊 172,032 B)、定常の `IRAM free:` は 213,824 B。PSRAM は静的な VM プール (約 6.6 MB) を取った残りが 1.45 MB。
- **flash**: ファームは 4,906 KB (5M の区画の残り 228 KB、4%。エディタを mruby、Spinel の FFT なしで)。storage は約 2.0 MB を使い、3008K の区画の残りは約 0.9 MB。
- **共通の部分**: Retro (NARYAv3) と Tab5 のビルドが通り、静的な内蔵 RAM は Retro が変化なし、Tab5 が 8 B 減。Linux の sim は標準の構成 (Spinel のカーネルとエディタ) でデスクトップが出て、エディタを開いて 1 打鍵できる。wasm もビルドが通り、node で動かしてデスクトップまで起動する。
- **画面の見た目はまだ誰も見ていない**。ログでは画面の制御 IC を GC9107 と判別し、LovyanGFX の初期化は成功している。色・向き・ずれ・背光はユーザの目で確かめる (7 章)。

## 2. 段ごとの作り

### 2.1 H1a: 構成の骨組み

| 置いたもの | 中身 |
|---|---|
| `fmrb_pin_assign.h` | ATOMS3R の分岐 (report/h0.md 4 章の案どおり)。Retro の既定の分岐より前に置く。画面のピンは新しい `FMRB_PIN_LCD_SPI_*` |
| `config/sdkconfig.defaults.atoms3r` | n16r8 との差分は承認済みの案どおり: 区画の表、flash 8MB、コンソールを USB-Serial-JTAG に、USB host なし、`CONFIG_BT_ENABLED=n` |
| `config/partitions_atoms3r.csv` | A 案: factory 5M (0x10000) + storage 3008K (0x510000) |
| `config/system_conf_atoms3r.toml` | 128x128、余白 0、`display_mode = "spi_direct"` (既存の値)、`boot_mode = "app"`、`startup_app = "/app/test/atoms3r_hello.app.rb"`、`ble_auto_start = false`、`wifi_auto_start = false` (WiFi は H2)、`boot_splash = false`、`audio_mute = true` |
| 端末の表 | `rakelib/build.rake`、`cmake/check_storage_inputs.cmake`、`tool/spinel/gen_const_rb.rb` に ATOMS3R の行 |
| `fmrb_hw_defines.cmake` | `FMRB_HW_ATOMS3R`、`FMRB_HW_FAMILY_MINI`、`FMRB_HAS_LOCAL_DISPLAY`、`FMRB_HAS_WIFI` |

- `FmrbConst::BOARD` は `"atoms3r"`、`FmrbConst::HW_FAMILY` は `"mini"` (mruby の const.c と Spinel の生成の両方)。
- 区画の表を新しくしたので、この端末は app だけの書き込みでは更新できない (全体の書き込みで /home が消える)。区画の表の注記に書いた。

**描画の経路**: P4 と同じ `display_p4_task.cpp` + local link を S3 で動かす。PPA の backend は入れず、CPU の backend (`display_backend_cpu.cpp` + `display_blend_cpu.c`) だけを入れる。H1a の時点では画面の driver が無く、panel の無い `LGFX_Device` で合成だけを回した (ブラウザ版と同じ形)。CPU の backend は panel の無い device では何もしないようにした。

### 2.2 H1b: 画面

- `main/drivers/display_p4/lgfx_atoms3r.hpp` (新規、ボード固有): LovyanGFX を `fmrb_pin_assign.h` から直接設定する。3 線式 SPI (SPI3)、M5GFX と同じ手順で panel ID を読み (8 MHz、だめなら 100 kHz で読み直し)、GC9107 と ST7735S のどちらかを選んで offset などを設定する。この個体は ID `0xff079100` で GC9107。動作の速さは書き込み 40 MHz。
- 背光は LP5562 の W 出力。LovyanGFX の I2C (I2C_NUM_1、G45/G0、400 kHz) で書く。LovyanGFX がこの I2C をレジスタの水準で使うので、Tab5 と同じく、他の利用者は表示の task の直列化された I2C の窓口を通す。アプリの I2C unit 1 は `hw_proxy_i2c.c` がこの窓口に回す (条件を `CONFIG_IDF_TARGET_ESP32P4` から `FMRB_HAS_LOCAL_DISPLAY` に変えた)。
- 色: framebuffer は今までどおり RGB565 (PPA の並び)。CPU の backend の `pushRotateZoom` が倍率 1 で画面へ送る (LovyanGFX が色の形を変換する)。
- 起動の画面: 幅 320 未満の画面は小さい版 (6x8 の字で「Family mruby」・版・ビルドの日時・チップと大きさ・PSRAM の空き・Starting...)。端末の名前ではなく画面の大きさで選ぶ。選んだ印は外部 RAM に置いた (Tab5 の内蔵 RAM を動かさない)。
- 試しのアプリ `flash/app/test/atoms3r_hello.app.rb`: 外周 1 画素の白枠、四隅に色の印 (左上 赤、右上 緑、左下 青、右下 黄)、8 色の帯、大きさ、0.5 秒ごとに進む数。どの大きさの画面でも描ける。

### 2.3 H1c: 単一アプリ

system_conf の新しいキー (全端末):

```toml
boot_mode = "desktop"     # "desktop" (既定) | "app"
startup_app = ""          # 既存
startup_app_retries = 3   # boot_mode = "app" のときの起動し直しの回数 (0 = しない)
```

- C のカーネルが読み、`fmrb_system_config_t` に `boot_mode` と `startup_app_retries` (既存の詰め物の中に収まり、大きさは変わらない)、パスは外部 RAM の静的な領域に置く。
- `boot_mode = "app"` のとき、カーネル (`fmrb_kernel.rb`) はデスクトップを spawn せず、`startup_app` を自分で起動して全画面にし、キーボードを渡す。全画面の大きさはデスクトップの窓から読んでいたので、デスクトップが無いときは画面の大きさから余白を引いた値を C から聞く。
- 頼まれずに終わった (例外・コンパイルの失敗・spawn の失敗) ときは 1 秒後に起動し直す。`startup_app_retries` 回を超えたら止め、アプリが最後に出したエラーをログと画面に出す。画面はカーネルが z=255 の canvas を 1 枚作り、普通の link のコマンドで描く (`fmrb_kernel_show_halt`)。端末の中の画面・WROVER・sim のどれでも同じに出る。
- 頼まれて終わった (kill、`FmrbApp#stop`) ときは起動し直さない。H2 の「止めて差し替える」開発の流れを邪魔しないため。
- 新しいカーネルの呼び出し (`_boot_mode`、`_startup_app_retries`、`_startup_app`、`_screen_width`、`_screen_height`、`_show_halt`) は mruby の binding と Spinel の FFI の両方に置いた。
- 全端末の `config/system_conf_*.toml` の `startup_app` の隣に、2 つのキーを既定値で説明つきで書いた。

### 2.4 H1d: 外すもの

- **保存領域に入れないファイルの一覧** (一般の仕組み): `config/storage_exclude_<端末の小文字>.txt`。1 行に storage の根からのパス、`#` 以降は注釈。トップの `CMakeLists.txt` が像を作る前に staging から消す。一覧の無い端末は今までどおり全部入る。絶対パスと `..` は拒む。Retro のサービスを抜く既存の処理はそのまま (この一覧に移すこともできる)。
- AtomS3R の一覧: `help`、`usr/share/backgrounds`、`usr/share/icon`、`usr/share/samples`、`usr/share/sounds`、`usr/share/music`、`cache/launcher`、`app/game`、`app/demo`、`app/debug`。外したのはデスクトップ・エディタ・音の出力だけが使うもの。`usr/share/asterism` (H3 で使う) と `app/test` は残した。
- 外さないと入らなかった: 全部入れると 3008K の像の作成が失敗する (storage の木は 4 KB の塊で数えて約 3.5 MB)。
- **既存のビルドの選択肢**: `FMRB_FFT_SPINEL=0` (45 KB) と `FMRB_APP_ENGINE_EDITOR=mruby` (Spinel のエディタ 475 KB の代わりに mruby のエディタのバイトコード) で、ファームが 5M に入った。

## 3. 実測

### 3.1 起動 (最後の像、`boot_mode = "app"`、試しのアプリ)

| 時点 | 時刻 (リセットから) |
|---|---|
| app_main | 約 1.42 s |
| 画面の初期化が終わる (起動の画面が出る、最初の画素) | 約 1.72 s |
| カーネルが ready | 約 1.84 s |
| アプリが canvas を作る (`App started`) | 約 2.19 s |
| アプリの最初の絵 | 約 2.2 s |

- 合成と送り出し: `render: 10 frames/5s avg=10ms max=11ms` (試しのアプリは 0.5 秒ごとに present)。H1a の panel なしでは合成だけで平均 2 ms だったので、SPI の送り出しが約 8 ms (32 KB を 40 MHz で送る計算は 6.5 ms)。

## 5. 単一アプリの起動し直しの振る舞い (端末で実測)

`startup_app = "/app/test/crash_soon.app.rb"` (起動の 2 秒後にわざと例外を出す) で焼いた。

| 時刻 | できごと |
|---|---|
| 44.98 | Single-app boot 開始 |
| 47.46 | 1 回目の例外 → 47.49 「died (1/4); starting it again in 1000 ms」 |
| 48.52 | 2 回目の起動 → 50.99 例外 |
| 52.03 | 3 回目の起動 → 54.51 例外 |
| 55.85 | 4 回目の起動 → 58.03 例外 |
| 58.05 | 「giving up. /app/test/crash_soon.app.rb failed 4 times. crash_soon: failing on purpose (RuntimeError)」、停止の canvas (z=255) を作る |

- 3 回起動し直し、4 回目に落ちたところで止まる (`startup_app_retries = 3`)。理由はアプリの最後のエラーの 1 行目と backtrace の先頭 (エラーの記録の長さで途中で切れる)。
- sim の停止の画面 (426x240) は、暗い赤の地に白で「STOPPED」、理由、「Reset to try again.」。端末の 128x128 では 21 桁で折り返す (目視はユーザ)。
- 起動し直すたびに canvas の z が 1 つずつ上がる (2, 3, 4, 5)。前の canvas は消えている。

## 6. 言語を外す選択肢について (数字だけ、作っていない)

- 言語の 3 つで約 380 KB、日本語のフォントで約 1,080 KB、Spinel のエディタで 475 KB。
- 今 5M に入れるには、どれか (今回は既存の選択肢でエディタの Spinel 版と FFT) を外す必要がある。H3 (zenoh と Asterism、P4 の実測で +100 KB 前後) を入れると、今の 4% (228 KB) では足りなくなる見込みが高い。
- いちばん効くのは日本語のフォント (1 MB)。128x128 で efontJA 16 を使う場面は少ない。ただ「フォントを外すビルドの選択肢」は既存に無く、新しい選択肢の名前と、外したときの `set_font(:ja, 12/16)` の振る舞い (misaki 8 に落とすか) を決める必要がある。言語の選択肢 (`FMRB_LANG_*`) も同じく新しい名前が要る。

## 7. ユーザに確かめてほしいこと (AtomS3R、今の像)

今の像は `startup_app = "/app/test/atoms3r_hello.app.rb"` で焼いてある。電源を入れ直す (またはリセットボタン) と次が見えるはず。

1. **起動の画面**: 電源から約 1.7 秒で、黒地に白の小さい字 (「Family mruby」、版、日時、`esp32s3 128x128`、PSRAM の空き、Starting...) が出る。字が欠けずに読めるか。
2. **試しのアプリ** (約 2.2 秒で切り替わる):
   - 外周の 1 画素の白枠が 4 辺とも見えるか (ずれ・切れが無いか。GC9107 は縦の offset 32 を入れている)。

   - ボタン側を下にしたとき画面の上下が自然か (向きの好み)。

## 8. 決めてほしいこと

1. **5M に入れる方法** (標準の構成のままでは 211 KB 溢れる):
   - a) 今回のまま、ATOMS3R のビルドでは `FMRB_APP_ENGINE_EDITOR=mruby FMRB_FFT_SPINEL=0` を付ける (既存の選択肢。今は手で付けている。端末の表に既定として持たせるなら、その形を決める)。
   - b) 日本語のフォントを外す選択肢を作る (約 1 MB 浮く。名前と、外したときの `set_font` の振る舞いを決める)。
   - c) 言語を外す選択肢 (`FMRB_LANG_*`、合わせて約 380 KB)。
   - H3 の zenoh を考えると、a だけでは足りない見込み。
2. 停止の画面の文言と色 (今は「STOPPED」、理由、「Reset to try again.」、暗い赤)。
3. `boot_mode = "app"` で、頼まれて止まった後 (kill など) の画面。今は何も描かず黒のまま。

## 9. H2 への申し送り

- WiFi はまだ上げていない (`wifi_auto_start = false`)。H2 で true にし、`config/wifi.toml` を焼く。S3 の radio の起動の流れ (boot.c の Retro と同じ) にそのまま乗る。BLE は無いので排他の判断は要らない。
- 開発の流れ (put → 起動し直し): `/app/kill` は「頼まれた停止」なので単一アプリの起動し直しは働かない。そのあと `/app/launch` で別のアプリを起動すると、それは単一アプリとしては扱われない (落ちても起動し直さない)。H2 で「差し替えた startup_app を起動し直す」入口が要るか決める。
- 停止の canvas は z=255 で残るので、止まった後に `/app/launch` で起動したアプリはその下に隠れる。H2 で launch の前に消すか決める。
- 内蔵 RAM の基準値 (WiFi なし): 定常 213,824 B。H2 の WiFi・H3 の zenoh はここから比べる。
- flash の基準値: 残り 228 KB (4%、エディタ mruby・FFT なし)。H3 の前に 8 章の 1 を決める。
- シリアル: AtomS3R も Tab5 と同じく、ポートを開くとリセットがかかる (`rst:0x15`)。MCP の `serial_start` は `port: /dev/ttyACM1` で使えた。MCP の `flash` は端末とポートを選べないので、ビルドの docker の esptool で `--port /dev/ttyACM1` を付けて書いた (460800 bps、全体で約 1 分)。
- SD は無いが、今までの S3 は SD の SPI バスを NC のピンで立てていた (SPI3 を取ってしまう)。ピンが NC なら立てないように直した。
- `FMRB_PIN_STATUS_LED` が無いので status_led の task は何も光らせない (heartbeat の task 自体は動く)。

## 10. 端末の状態

- AtomS3R (`/dev/ttyACM1`): H1 の最後の像 (feature/headless-h1、`boot_mode = "app"`、試しのアプリ)。区画は ATOMS3R の表 (factory 5M + storage 3008K)。出荷時の中身に戻すときは report/h0.md 2.2 の手順。
- P4-Nano (`/dev/ttyACM0`) には触っていない。
- `build/` は Linux の標準の構成 (x86-64)。wasm の libmruby とコアは作り直してある。
