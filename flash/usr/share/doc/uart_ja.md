# シリアル (UART)

端子につないだシリアルの機器 (LoRa の無線・GPS・ほかのマイコンなど) と、
アプリから文字やバイトをやりとりできます。試すだけなら、メニューの
「シリアルターミナル」で番号とピンと速さを選んで Open を押し、下の欄に
打った 1 行を Enter で送れます。届いた文字は真ん中に並びます。

## つなぎ方

- **TX と RX は相手と交差させます**: こちらの TX を相手の RX に、こちらの
  RX を相手の TX につなぎます。
- **GND を必ずつなぎます** (2 台の基準をそろえるため)。
- 信号は **3.3 V** です。5 V の信号の機器 (古い Arduino など) を直接
  つなぐと端末を壊すことがあるので、レベル変換を挟んでください。
- 速さ (ボー) は相手と同じにします。よく使うのは 9600 と 115200 です。

## 機種ごとの番号と端子

番号は UART の番号 (UART1 なら 1) です。下の表の端子は例で、ほかの
空いているピンも選べます。

| 機種 | アプリが開ける番号 | 端子の例 (TX・RX) |
|---|---|---|
| Tab5 | 1・2・3・4 | Grove の G53・G54 |
| NARYA v4 (P4-Nano) | 1・2・3・4 | 拡張のピンヘッダの空いているピン |
| AtomS3R | 1・2 | Grove の 2・1 |
| StickS3 | 1・2 | Grove の 9・10 |
| NARYA v3 | 2 | GROVE 2 の 47・48 |

- UART0 (コンソール) と、NARYA v3 の UART1 (描画側とのつながり) は本体が
  使っているので開けません。
- 画面・SD・無線・音などに使っているピンは選べません。理由が出ます。
- Linux sim では UART2 だけが開け、書いた物がそのまま届きます (相手の
  いない試し用)。ブラウザ版・PC 版には UART がありません。

## アプリの書き方

```ruby
class Hello < FmrbApp
  def on_create
    # 番号とピンは例 (Tab5 の Grove)
    @u = UART.new(unit: 1, txd_pin: 53,
      rxd_pin: 54, baudrate: 115200)
    @u.puts "hello"
  end

  def on_update
    line = @u.gets       # 待たない
    Log.info(line) if line
    50
  end
end
```

- 読む側 (`gets`・`read`・`getbyte`) は待ちません。まだ届いていなければ
  nil を返すので、`on_update` の中で毎回呼びます。
- アプリが終わると、開いた UART は本体が閉じます。
- 開けないときは IOError (使用中・本体のピンなど) か ArgumentError (番号や
  ピンが無いなど) になり、理由の文が付きます。
- 詳しくはエディタで `UART` にカーソルを置いて F1 を押してください。

## シリアルの MIDI 出力と同時には使えません

MIDI のアプリで出力先を serial にすると、MIDI は UART2 と TX のピン
(Grove の 1 本目) を、再起動するまで持ち続けます。その後は同じ番号や
ピンを UART で開けません ("used by the MIDI serial output")。UART を
使うときは、MIDI の serial 出力を使う前か、再起動した後にしてください。
逆に UART で Grove を使っている間は、MIDI の serial 出力が開きません。

## うまくいかないとき

- **何も届かない**: TX と RX が交差しているか、GND をつないだか、速さが
  相手と同じかを確かめます。
- **文字化けする**: 速さか形式 (データ 8 ビット・パリティ無し・ストップ
  1 ビットが普通) が相手と違います。
- **"in use by another app"**: ほかのアプリが同じ番号を開いています。
  そのアプリを閉じてください。
- **"used by the system"**: 本体が使っている番号かピンです。別のものを
  選んでください。
- **捨てたバイトが出る** (シリアルターミナルの「あふれて捨てたバイト」、
  `dropped`): 読むのが追いついていません。もっと頻繁に読むか、
  `rx_buffer_size:` を大きく (16384 まで) してください。
